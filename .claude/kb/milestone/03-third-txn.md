## 六　GPU：批量派活，与 GPU 上判对错

- **原话**：「判断对错也可以在 gpu 上判断吧 不行吗？如果不行 那么本机的 5090 提供 16 gpu 我感觉就够用了」「gpu 的实现放里程碑 3 吧」（用户 2026-09-28）。
- **仓里已有的**：里程碑二「增补 4」第四项落了单元两道校验和上 GPU、与 CPU 逐个对拍（`crates/singlefs-checker-tier/src/gpu_unit_checks.rs`，特性 `gpu`），跑法由配置的 `ENABLE_GPU` 定；判对错仍是 CPU 上的池级 checker（`crates/singlefs-checker`）。今天 GPU 逐状态派一次活（建缓冲、提交、映射、等），单机 CPU+GPU 在固定脚本展开到 18 的 393338 个状态上 184 状态/秒，纯 CPU 3300 状态/秒（`records/2026-09-28-里程碑三崩溃放量剪枝与GPU调度.md` 第三节「分片与 GPU 跑通」那一行）：只证功能，不算加速。
- **开工前要先定的**：① 批量派活——一批状态的单元一次送上卡、一次读回，批多大按显存与状态数定；② GPU 上判对错——池级 checker 的 WGSL 版（选根、走树、扫 journal 环、比版本表、48 条不变量），与 CPU 版逐状态对拍、不一致判红；它是第二个 checker 实现，与 D13（验证路线） 已定项 5「池级 checker 与实现的依赖闭包不相交」同一口径下再定它与 CPU 版共不共享常量模块；③ 校验和那一截本机 5090 一张卡够，多卡与双机的分工沿用「增补 4」第四项按空闲显存分。
