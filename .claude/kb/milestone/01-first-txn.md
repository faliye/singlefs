## 步 0　脚手架

**现状（2026-09-14 开工）**：根 `Cargo.toml` workspace（排除 `research/`）+ 四个 crate：`crates/singlefs-format`（格式常量，带 `format-const:` 注与 `// placeholder:` 占位）、`crates/singlefs-core`（地址 newtype、块设备 trait 与文件后端）、`crates/singlefs-harness`（录制器与流的条数闸）、`crates/singlefs-checker`（骨架：判定宽度的「探到 / 声明」两态）。门禁多一道阶段「格式常量文件里的占位」（`.claude/gate.d/53-format-const-placeholders.sh`，样本在 fixtures），27 号阶段的常量同步扩到 `crates/`。验收三条：录制器条数闸的自证（`stream_count_gate_rejects_a_stream_that_lost_one_write`）、两种地址类型混用编译不过（`address` 模块的 `compile_fail` 文档测试）、占位计数的门禁——都在。镜像默认 4 GiB（`TEST_IMAGE_DEFAULT_BYTES`，C323（镜像大小全仓没有条款） 的占位），用户 2026-09-14 说虚拟盘可扩到 200–500 GB。

**设想实现**：一个 `crates/` workspace，三个 crate：核心（事务层）、checker、harness。
一个块设备抽象，接 N 个镜像文件；一个录制器包装在它外面，把每个写请求与屏障记成一条流。
一个格式常量文件，第一个事务要写的每个宽度都在里面，占位的常量带占位标记与分项号。

**预想的细节**：
- 设备抽象只暴露读、写、屏障、FUA 写、探测 `physical_block_size` 五个动作，不暴露介质是什么。
- 镜像文件默认两个，放 `${TMPDIR:-/tmp}`，大小预想 **4 GiB**（2026-09-14 起：D23（journal 的角色与格式） 已定项 19 ③ 定「环 ≤ 设备容量 ÷ 4」，1 GiB 装不下默认的 768 MiB 环）。**预想**：`physical_block_size` 按参数给，默认 512（与 [layout/01-first-txn.md](../layout/01-first-txn.md) 零那一节同口径；4096 作为第二档在步 7 另跑）。
- 录制器每条记：设备号、偏移、长度、内容哈希、是不是屏障、是不是 FUA。流落到文件，给步 7 用。
- 地址全部 newtype：设备号、设备内 16 KiB 槽号、代号 `txg`、`jsn`、树 ID、inode 号。
- 常量文件里每个常量一行注释：值来自哪条分项，是不是占位。

**验收标准**：
- 录制器自证：喂一个少发一条写的假设备，比对条数判红。
- 两种地址类型混用的代码编译不过（一个 compile-fail 测试）。
- 门禁多一道阶段：数出常量文件里还有几个占位，每个占位都指得到分项号，指不到判红。

**写出的字节**：无（这一步不写新的盘上字节）。

**会碰到的决策点**：无格式决策；工程约定见 [verification-build.md](../verification-build.md)「待定案」第 5 问。

## 步 1　mkfs

**现状（2026-09-14 开工，验收五条全过）**：`crates/singlefs-core` 的 `make_filesystem` 吃两块设备，按字节表零的 m1–m4 写出实例表单元第 0 片（槽 50176）、树表单元第 0 版（槽 50178）、三个区域各自槽 0 的第 0 代根记录（FUA）、每盘两个世代号 1 的超级块槽；几何越界（环 > 容量 / 4、根环或单元区越过盘尾、区域归属指到不存在的盘）在写任何字节之前拒绝。编码在 `bytes` / `checksum` / `pointer` / `unit` / `superblock` / `root_record` / `root_ring` 六个模块，每个偏移用 `assert_position` 钉在字段表上；checker（`crates/singlefs-checker`）另写按位 CRC-32C 与三种槽 / 单元的解析，只与实现共享常量模块。验收（`crates/singlefs-harness/tests/first_transaction_step_one_mkfs.rs`）：同参数两次 mkfs 逐字节相同；三个区域的槽 0 解出同一份第 0 代根、改坏一槽一字节只判那一槽；每盘两槽校验和过且世代号 1、改坏一槽择另一槽；根记录两条指针指到的单元头自检过且位置条目里的整单元校验和对得上；录制流段序列 `4+1+1+1+4`、种类串与八那一节 mkfs 那一行逐字相同、13 次操作。镜像准备（journal 环与根环区域全 0）靠新建的稀疏镜像，真设备上要显式写 0 的那一半还没做。

**设想实现**：`mkfs` 吃两个镜像文件，写出一个能被挂载、但一个文件都没有的池：每盘一份超级块、
三个根环区域、一条两盘镜像的 journal 环、实例表单元第一片、一个空的树表单元，
然后把第 0 代根记录种进全部三个区域。

- 超级块每盘两个槽轮换。**预想**的字段：magic、格式版本、三张 feature bitmap、fsid、本盘设备号、设备数、
  节点与单元与落点粒度三个尺寸、根环参数（区域数 3、素数步长、每区槽数、区域起点）、journal 几何（起点、长度、记录尺寸）、

  两盘上三个区域必有一盘背两个（E87（固定结构的放置） 逐字），归属由 mkfs 逐区域写进超级块（D2（RAID 条带策略） 已定项 7）。

## 步 2　分配一个数据单元，写一个小文件的数据

**现状（2026-09-14 开工，验收三条全过）**：`crates/singlefs-core` 的 `allocator` 模块——每盘一张单元区空闲图（已分配位、每段已用槽数、空闲 run 数三样增量维护，运行时不扫盘）、用户数据落点政策（起点最小、偶数槽、两槽都空、不在开放段）、提交内生块从开放段 bump（容器按 32768 对齐档）、政策函数复算比对计数（第一个事务恒 0）、分配记录 20 字节编码；`unit::build_data_unit` 按字节表二写码 1（头 105 + 预留 29，载荷从 134 起，载荷 CRC 罩 [105, 32768)）；`pointer::DataPointer` 88 字节。验收（`crates/singlefs-harness/tests/first_transaction_step_two_data_unit.rs`）：3000 字节文件写到 t1@50180 两盘各一份，读回头自检过、载荷 CRC 对、前 3000 字节等于文件内容、之后全 0；改坏载荷 / 补齐区 / 头任一字节各判红、flags 非 0 拒收；内存里恰好两条分配记录、槽号等于录制流里两次写的偏移 ÷ 16384；记账增量：已分配 5 槽、空闲 run 2 段。

**设想实现**：内存里一个分配器，从两盘各拿一个 32 KiB 数据单元的落点；把文件内容装成一个自描述的数据单元，
写到两盘各一份；在内存里记下分配记录与记账增量。这一步还没有任何树落盘。

**预想的细节**：
- 落点粒度 16 KiB 槽，一个数据单元占两个连续槽（D3（空间分配） 已定项 7、D4（校验和位置） 已定项 5）。落点政策已定：用户数据不进聚簇段，取已选设备内槽号最小、过准入合取、不在 `R` 保护期内的空槽（D3（空间分配） 已定项 8）；第一版不做分配器提示（D14（双轨（大小文件 / 持久临时）） 已定项 2）；提交内生块（步 3 的树节点、步 5 的树表单元）从聚簇段分配（D3（空间分配） 已定项 5）。落点：两盘各自的槽 50180–50181——单元区从 50176 起、mkfs 占 50176–50178、开放段是最低的 64 槽对齐全空段 [50240, 50304)，不在开放段里的最低 32768 对齐空槽对是 50180（D3（空间分配） 已定项 10）；E142（第一个事务的干跑） 第六次跑对过之前仍标预想。
- 分配时同时算一遍政策函数（最低空槽、排除 bump 的开放段与 `R`）并与实际落点比对，不一致就计数、非 0 判红（C146（无空段时的回落政策全仓无定义） 第 ② 条；第一个事务恒 0，口径在 [verification-build.md](../verification-build.md) 事务层第一版「运行时计数与准入自证」表）。
- 单元头按 `DATA_UNIT_HEADER_BYTES`（D18（块里携带什么信息） 已定项 7）：magic、格式版本、单元类型标签 1、flag 0、
  extent 声明长度 = 文件字节数、头校验和、五元组、诞生代号、fsid、写序、载荷 CRC、nonce 与 MAC 预留位。
  五元组里树 ID 取 11（引用它的 extent 树，D8（核心索引结构） 已定项 11 从 11 起编号）、对象 ID 取分配到的 inode 号、锚点偏移 0；诞生代号 = 发布它的 checkpoint_txg，暖机后是 3（D16（发布语义） 已定项 6）；含 29 字节预留位的头 134，载荷从 134 起（D18（块里携带什么信息） 已定项 16，2026-09-14 预留 28 → 29）。
- 载荷 = 文件字节，之后补 0 到单元末尾，补齐参与校验和（I-2.3（补齐字节为零且参与校验和））。
- 整个单元落一列，两盘各一份，位置条目两条（D2（RAID 条带策略） 已定项 10、已定项 6 的 `w ≥ 2`）。
- 分配记录两条（每盘一条）：key = 设备 4 + 槽号 6，value = 跨度 2（最高位是已释放标志）+ 分配代 8（D3（空间分配） 已定项 7 / 已定项 11）。
- 第一版不加密，位置条目里那 4 字节校验和取 CRC32C 罩整个单元（D4（校验和位置） 已定项 8），MAC 16 字节留位全 0。

**验收标准**：
- 从两盘各读回那个单元：头自检过、载荷 CRC 对、前 N 字节等于文件内容、之后全 0。
- 改坏载荷任一字节，CRC 判红；改坏头任一字节，头校验和判红。
- 内存里这一步新增恰好两条分配记录（mkfs 的两个单元另有分配代 0 的四条，字节表五那 20 条里的头四条），槽号与录制器流里的写偏移对得上。

**写出的字节**：[layout/01-first-txn.md](../layout/01-first-txn.md)「二、数据这一侧」；分配记录与记账增量在「五、空间记账与分配」。
