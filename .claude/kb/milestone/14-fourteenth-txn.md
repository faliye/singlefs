**口径**：规划文件，2026-10-12 提前建档，是草案。用户定了七到十，问「你可能漏了的 你觉得怎么排里程碑比较好」，主 agent 建议把十一到十五接在后面，原则是动盘上格式的都排在格式冻结之前、冻结排在对外之前（`records/2026-10-11-里程碑五打包与决策进度列.md` 第七节）；用户同日要求「写在 /home/fy5090/code/singlefs/.claude/kb/milestone 中吧 提前写上」，再定这个次序：「这个可以 做的时候还要调整」。**它不要求正确**：每项开工前回来改。前提是里程碑三到十三的出口全部达成，尤其是里程碑四的只读快照、deadlist 与 GC（[04-fourth-txn.md](04-fourth-txn.md)）；前面的里程碑收口时少了哪一样，这份文件按缺的那一样重排。

**读法**：每项三格——「仓里已有的」写这一项在仓里压着哪些条款、欠账、代码（2026-10-12 现查的，带出处）；「作业点」一张表：编号、做什么、压着的条款与欠账、验收（每条先证会红）、依赖；「开工前要先定的」列还没定、开工前要走三方或问用户的问题。凡写「推的」的是主 agent 没量过的判断。作业点的编号写成「项·点」（一·1、二·3），只在这份文件里用。欠账号都是建档那天还开着的，开工前逐条现查。
