# 里程碑「小文件打包」：作业点、验收与次序

**口径**：规划文件，2026-10-11 按用户定案建档（原话「我认为里程碑5 需要做小文件打包」；主 agent 建议打包排在并发之前、并发改成里程碑六，用户定「可以，那就这样排」），是草案。**它不要求正确**：每项开工前回来改。做的是 D27（小数据打包容器）：13 项已定，形态是后台整理把 ≤ 4 KiB 的对象搬进共享容器、写路径一个字节不改、容器是一个新单元类。前提是里程碑三（[03-third-txn.md](03-third-txn.md)）与里程碑四（[04-fourth-txn.md](04-fourth-txn.md)）的出口全部达成：搬迁与回收搭 D26（后台整理与放置回收） 的常驻整理与区域扫描（里程碑四出口 2），容器坏了靠 D2（RAID 条带策略） 已定项 6 的两份副本；前面两个里程碑收口时少了哪一样，这份文件按缺的那一样重排。

**读法**：每项四格——「原话」照录用户口述；「仓里已有的」写这一项在仓里压着哪些条款、欠账、代码（2026-10-11 现查的，带出处）；「作业点」一张表：编号、做什么、压着的条款与欠账、验收（每条先证会红）、依赖；「开工前要先定的」列还没定、开工前要走三方或问用户的问题。凡写「推的」的是主 agent 没量过的判断。作业点的编号写成「项·点」（一·1、二·3），只在这份文件里用。

**不加新事务种类**：打包是后台整理的一种搬迁（D27（小数据打包容器） 已定项 1、6），走里程碑四 GC 落地的那套意图机制与区域扫描，不新增 `CommitStep` 成员；仍是一个事务层（`.claude/rules/fs-design.md`「一个事务层，所有结构共用」）。

**与写路径打包的分界**：写路径上把几个文件塞进一个单元、或内联进索引节点，是 D14（双轨（大小文件 / 持久临时）） 已定项 3 判否的（判据是原子性：多个文件共享一个原子单位），这份文件不碰那条「否」。
