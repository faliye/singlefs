## 四　コールドリードと RefFS の size 非展開

- **リポジトリ内の既存要素**（2026-10-22 時点確認）: K12 の上限（N の上限は ⌈N ÷ ペイロード⌉ × ペイロードが u64 をオーバーフローしないこと、`research/prompts/m4-trunc-r1-main-verification.md` K12）内の大きな size（例：2⁴⁰ バイト。ディスク上では数ユニットしか占めない）へ正当に伸ばした後、コア層のコールドウォーク `walk_to_file` とコールドリカバリ `recover` は内容全体を 1 本のベクタとして返し、穴を size まで 0 で埋める（`crates/singlefs-core/src/recovery.rs` の `content_padded_with_the_hole_up_to_the_size`）。参照実装 RefFS は切り詰めを内容全体の `resize` として適用し（`crates/singlefs-reference-filesystem/src/lib.rs` の切り詰め箇所 `truncated.resize(`）、プロセスが中止する。コア層の `mount.rs` と `mounted_session.rs` は `recover(&` も `walk_to_file(` も一切呼ばず、コールドリードの呼び出し元は checker 層、harness 層、`recovery.rs` 自身にあるため、マウント経路は影響を受けない。ランダム履歴の切り詰め先は高々現在の size に 4 ペイロードを足した値まで（`crates/singlefs-harness/src/history.rs` の `new_size_in_bytes`）で、三方の突き合わせは大きく伸ばす場合に当たらない。ユーザーは 2026-10-22 に、この版は変えず、この最適化マイルストーンで扱うと決定した。発言ママ："这个没必要管就按照现在的方式读。 之后会优化 没有必要现在优化。 肯定不可能现在这种方式冷读", "现在这个样子冷读肯定是不行的 放到后面的优化里程碑里面"（判定 `research/prompts/m4-validate-code-r1-main-verification.md` 第 4 節 2 行目と「用户定案」の節）。未済の検査：C878 (コールドリードと RefFS が size 全体のメモリを確保する)。
