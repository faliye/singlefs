# 里程碑「目录与 POSIX 面」：作业点、验收与次序

**口径**：规划文件，2026-10-12 按用户定案提前建档（原话「POSIX 去历程杯9 FUSE 去里程碑10」；同日要求「写在 /home/fy5090/code/singlefs/.claude/kb/milestone 中吧 提前写上」），是草案。**它不要求正确**：每项开工前回来改。目录由用户定往里程碑四之后去做（[04-fourth-txn.md](04-fourth-txn.md)「不在出口」照录了原话），落在这一份。前提是里程碑三到十的出口全部达成（十是 [10-tenth-txn.md](10-tenth-txn.md)）；前面的里程碑收口时少了哪一样，这份文件按缺的那一样重排。

**读法**：每项三格——「仓里已有的」写这一项在仓里压着哪些条款、欠账、代码（2026-10-12 现查的，带出处）；「作业点」一张表：编号、做什么、压着的条款与欠账、验收（每条先证会红）、依赖；「开工前要先定的」列还没定、开工前要走三方或问用户的问题。凡写「推的」的是主 agent 没量过的判断。作业点的编号写成「项·点」（一·1、二·3），只在这份文件里用。欠账号都是建档那天还开着的，开工前逐条现查。

**新事务有几种**：建目录、删目录、改名、硬链接这类操作各是一种新事务（`.claude/rules/fs-design.md`「从事务开始，不从功能开始」），走同一个事务层与同一套意图机制，不新开发布路径；新增的提交步骤进共享的 `CommitStep` 枚举。

- **仓里已有的**：全仓没有一条管目录结构的决策。相关的已定条款：D8（核心索引结构） 已定项 3「key = `(locality_id, inode, offset)`，`locality_id` 创建时从父目录继承、改名时故意不更新」；D8（核心索引结构） 已定项 5 接受墓碑、可能修改无界数量 extent 的操作先写意图再分批推进；D14（双轨（大小文件 / 持久临时）） 已定项 2 第一版不做分配器提示（重开条件三条）；D14（双轨（大小文件 / 持久临时）） 已定项 3 内联阈值 0。欠账：C109（哪些树的 key 死亡要写墓碑）、C527（改名覆盖借错删除规则的一半）、C2（无界操作做成单事务）（删大目录那一格还欠）、C115（inode 属性的溢出路线无落点）。
