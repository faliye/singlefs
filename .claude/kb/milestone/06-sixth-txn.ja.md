## 六　GPU パッキング移転

- **原話**：ユーザー 2026-10-20：「マイルストーン4 では gpu gc を行う。したがってマイルストーン7 のパッキング移転を gpu で実装できるかを議論する。マイルストーン7 にこの項目を入れ、マイルストーン4 のマルチ分岐処理機構を参照して、拡張可能なほかのインターフェースとフィールドを確保する。」
- **リポジトリ内の既存要素**（2026-10-20 調査）：バックグラウンドタスクの GPU スイッチ、カード選択、VRAM 上限、エラー時に降格しないこと、二つの GPU カーネルの比較による再検証は D26 (バックグラウンド整理と配置回収) 確定項目 13 で確定しており、一組のパラメータが全バックグラウンドタスクを管轄する（ユーザー 2026-10-20 決定、原文は変更履歴）；マイルストーン四七・1 は GC 一バッチ分の移動の壁時計を測定中（E185 (GC 1バッチ移行のウォールクロック内訳)、問題票 `git show 59ce5a86550d:research/prompts/m4-gpugc-measure-forks.md` の四行はすべて未決）で、七・2 の制御インターフェースはコードにある（`crates/singlefs-core/src/background_compute.rs` の `BackgroundComputeBackend`、`BackgroundTask`；マウントパラメータには `background_gpu_wait_limit` と `background_gc_cpu_compensation_threshold` もある、`.claude/kb/mount-parameters.md` 参照；2026-11-16 確認）。D24 (バックグラウンド重処理の GPU オフロード要否) 確定項目 2 の三つのハード制約は GPU にオフロードするあらゆる作業を縛る；パッキング移転は D24 (バックグラウンド重処理の GPU オフロード要否) の三候補には入らず、D26 (バックグラウンド整理と配置回収) 確定項目 13 が管轄する。master にパッキングコンテナのコードはない（`crates/` に対する `grep -rln 'PackingContainer\|packing_container'` は 0 件；`crates/singlefs-core/src/unit.rs` にはコード 1、2、3 のみ）；プロダクト側の GPU 依存はオプションのクレートにだけある（`wgpu` は `crates/singlefs-background-gpu`、`crates/singlefs-mount-runtime` と検証クレート、テストクレートの `Cargo.toml` にあり、コア層 `crates/singlefs-core` にはない；2026-11-16 確認）。D27 (小データパッキングコンテナ) 確定項目 6 は一トランザクション一マッピングリーフで、コストはマッピング書き込みが支配的と定める；確定項目 13 の 36 クラスを同時に開いたコンテナは合計 1.15 MiB；E21 (GPUオフロードの純収支) は転送の下限が ≥ 64 MiB のバッチを要すると測定したため、GPU モードは多数のマッピングリーフにまたがってバッチを蓄積する必要がある。
- **GPU に載せられるか**（メイン agent の判断、推論、未測定）：載せられる。形態は GPU ガベージコレクションと同じ——GPU は計算だけを担い、マッピングリーフの COW とトランザクションのパブリッシュは CPU に残り、トランザクション層は一つのまま（`.claude/rules/fs-design.md`「一つのトランザクション層をすべての構造が共有する」）。パッキング移転の一バッチは次の段に分かれる：

| 段 | 内容 | GPU に載せるか（推論） |
|---|---|---|
| 転送元検証 | 転送元オブジェクトを読み、転送元ユニットのチェックサムを検証 | 可：帯域律速で、GC の転送元ユニット検証と同形；E21 (GPUオフロードの純収支) は純スキャンで壁時計の純利益 0.78× と測定しており、D26 (バックグラウンド整理と配置回収) 確定項目 13 第 7 条の節約できたホスト CPU 時間で数えて初めて割に合う可能性がある |
| クラス割り当て | オブジェクトのサイズで 36 クラスのいずれかに入れ、スロット番号を決める | 可。ただし計算量が小さく、これ単独では節約は少ない |
| コンテナ組み立て | スロット幅までパディング、コンテナのバイト列を組み立て、コンテナ全体のチェックサムを計算（MAC は暗号化有効時のみ実行経路がある、D27 (小データパッキングコンテナ) 確定項目 7） | 可：組み立てたバイト列はディスクへ書くため戻す必要があり、「往復」の転送下限の側に入る |
| マッピング更新とパブリッシュ | キー順にマッピングリーフを COW し、トランザクションのパブリッシュを通す | 載せない：ツリー操作とパブリッシュはトランザクション層であり、一バッチ内でバックエンドは変えない |
| 再暗号化 | 暗号化有効時、オブジェクトを移すと新しい AAD の下で暗号文を再計算する（C240 (運搬時再暗号化コスト未計算)） | 余地のみ：暗号化は最初の実行可能版に入らない（D9 (暗号化) 確定項目 10）；この段はインターフェースにタスク種別を一つ残すだけ |

- **マイルストーン四のマルチ分岐機構にならって残す余地**：

| マイルストーン四七・3 の機構 | パッキング移転の接続方法 | 残す拡張の余地 |
|---|---|---|
| 計算バックエンド `background_compute`（`cpu` / `gpu`、既定 `cpu`） | この一つのパラメータを共用：`gpu` にするとパッキングと GC がそろって GPU で動き、パッキング用のパラメータは別に設けない | バックエンドは閉じた列挙型で網羅的な `match`、ワイルドカード腕は書かない；バックエンドを一つ足すときは列挙子を一つ足すだけで、コンパイラがすべての箇所の補完を強制する |

| マウント中に切り替え、次のバッチから有効、一バッチ内では変えない | 同じ：一度に全バックグラウンドタスクを切り替え、各タスクはそれぞれ自分の次のバッチから有効 | 制御インターフェースのスイッチは一つだけで、タスク種別では指定しない |

| 二つの独立した GPU カーネルがそれぞれ一回計算して比較（カード一枚でも走る）、確認済みは CPU に渡してビットマップを更新、連続して不確定のものは CPU が判定；GPU と CPU の二つの実装 | 同じ（D26 (バックグラウンド整理と配置回収) 確定項目 13 第 8 条、D24 (バックグラウンド重処理の GPU オフロード要否) 確定項目 2 第 3 条） | CPU 参照と GPU パスをタスク種別ごとに一組、突き合わせテストは種別ごとに一つ、毎回走らせる |
| 分岐をテストで強制的に通せる、実行時にどちらを通ったか見える | 同じ（`.claude/rules/fs-design.md` 五つのハード要件） | 観測カウンタは「タスク種別 × バックエンド」ごとに記録 |

  余地を残すのは三か所のみ：タスク種別とバックエンドの二つの列挙型、制御インターフェース、メモリ内の観測カウンタ；マウントパラメータは D26 (バックグラウンド整理と配置回収) 確定項目 13 の一組だけで、パッキング用には足さない。ディスク上には一ビットも足さない：パッキングのインテントにもコンテナヘッダにも、どのバックエンドを通ったかは記録しない（D24 (バックグラウンド重処理の GPU オフロード要否) 確定項目 2 第 1 条；D26 (バックグラウンド整理と配置回収) 確定項目 13 第 1 条）。プレースホルダーコードは書かない：拡張の余地は列挙型とパラメータの形に置き、コードは二つのタスク種別（GC とパッキング）と二つのバックエンド（`cpu` と `gpu`）だけを書く（`.claude/singlefs-ai-sop/rules/code-discipline.md`「不要なコードは削除する」；マイルストーン四「最適化項目：出口対象外、参入条件登録済み」節と同じやり方）。
