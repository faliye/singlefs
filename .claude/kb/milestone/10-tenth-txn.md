## 一　会话与对外接口

- **仓里已有的**：`O_DIRECT` 后端是 `crates/singlefs-core/src/block_device.rs` 的 `DirectInputOutputBlockDevice`（物理块大小经 sysfs 探测或声明），全仓只有 checker 档的两个装置二进制用它（`new_pool_file_creation_on_device`、`new_pool_file_creation_device_log_check`），跑在 QEMU 的 virtio 盘上（`crates/singlefs-checker-tier/src/on_device_modes.rs` 的 `direct` 模式）；挂着之后的发布由 `crates/singlefs-core/src/mounted_session.rs` 那一层接；core 里没有独占打开（`grep -n 'O_EXCL\|flock\|lock_exclusive' crates/singlefs-core/src/*.rs` 零命中），也没有给应用用的二进制或命令行。C618（删完之后不能再建带数据的文件） 的去向原写目录与 POSIX 那个里程碑，这一份要多文件就提前到这里。

## 三　多租户隔离

- **原话**：「5 还有权限的问题，因为使用O_DIRECT  所以需要设计权限」「换句话 叫做多租户隔离 可能比较合适」确认「对 我们要 Linux 的权限模型自己判权限 在 o_direct 模式下」（用户 2026-10-12）。
- **仓里已有的**：inode 记录的盘上形态在偏移 24 留了 mode / uid / gid / nlink 各 4 字节（D8（核心索引结构） 已定项 6 的字段表）；`crates/singlefs-core/src/records.rs` 的 `InodeRecord` 只带 inode、对象出生代、nlink、size、改动计数、写时刻；写盘时 mode 写死 `0o100644`、uid 与 gid 写死 0，读时跳过这三格（`InodeRecord` 的写与解析，`crates/singlefs-core/src/records.rs` 现查）。属性怎么扩展挂在 C115（inode 属性的溢出路线无落点），原排在里程碑十一一·2（属性与扩展属性的落点）。空间统计按 `.claude/rules/fs-design.md`「记账是事务的副产品，不是事后的遍历」落第一格，按租户的配额同样要在提交时增量维护。
- **作业点**：

| # | 做什么 | 压着的条款与欠账 | 验收 | 依赖 |
|---|---|---|---|---|
| 三·1 | 设计轮（与一·1 同轮）：身份怎么取（推的：持盘进程经 Unix 套接字取对端进程的 uid、gid 与附加组）；mode、uid、gid 落在 inode 记录偏移 24 已留的那几格；判法与 Linux 内核对普通文件的判法逐条对齐到哪一层（属主 / 属组 / 其他三档 rwx 与 root 之外，setuid / setgid / sticky 位、POSIX ACL、能力位 `CAP_DAC_OVERRIDE` 这类认不认）；列举（按 inode 号枚举）要不要也按权限过滤；裸盘本身由 Linux 设备节点的权限管（持盘进程以哪个用户跑、盘归哪个组）；按 uid 的配额在提交时增量维护 | D8（核心索引结构） 已定项 6；C115（inode 属性的溢出路线无落点）；D5（快照 / 空间记账机制） 的统计量表；D16（发布语义） 已定项 1「准入」 | 三方判决落 `research/prompts/`，定案写回 kb；有实验才有决策 | 段 0 |
| 三·2 | 实现：inode 记录读写 mode、uid、gid（不再写死 `0o100644` 与 0）；建文件时属主取调用者；chmod、chown、改配额各是一种走同一个事务层的事务（`.claude/rules/fs-design.md`「从事务开始，不从功能开始」）；会话入口按调用者的 uid、gid、附加组与文件的 mode 判读、写、截断、删、列举；按 uid 的空间配额在提交时增量维护、准入按它拒 | 三·1 的定案 | 每条新测试先证会红；模型对拍按多个 uid 交错的历史逐项相同 | 三·1；一·2 |
| 三·3 | 越权用例与对拍：照 Linux 权限的每一档越权各一条（没有写位的写、没有读位的读、改别人文件的 mode、非 root 改属主、写满自己的配额之后再写），全部被拒；同一组（uid、gid、附加组、mode、操作）在 ext4 上经内核判的结果与 singlefs 判的逐项相同；chmod、chown 中途崩溃的流接进崩溃放量；崩溃流里按 uid 的配额账与 checker 遍历算的逐 uid 相等 | `.claude/rules/fs-design.md`「记账是事务的副产品，不是事后的遍历」（运行时与 checker 用不同的算法） | 越权用例全拒、对拍逐项相同；去掉入口那道判，越权用例必红 | 三·2 |

- **开工前要先定的**：
  1. 能直接打开裸盘的进程绕得过任何文件级的判（它能读盘上每个字节），所以只靠权限位的隔离要求租户不直接碰盘：多会话只能是「一个持盘进程服务多个客户端会话」那一种。要让租户各自直接开盘，就得靠按租户分密钥的加密，加密在里程碑十五（[15-fifteenth-txn.md](15-fifteenth-txn.md)）。两条路选哪条，决定一·1 的多会话形态（推的，没量过）。
  2. 判法对齐 Linux 到哪一层：只做 rwx 与 root，还是 setuid / setgid / sticky 位、POSIX ACL、能力位一起做。

**不在出口**：经内核 VFS 访问（FUSE 在里程碑十二 [12-twelfth-txn.md](12-twelfth-txn.md)）、目录与名字（里程碑十一 [11-eleventh-txn.md](11-eleventh-txn.md)）、两台机器共享一块盘。
