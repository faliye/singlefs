**計測条件**：計画文書。2026-10-01 にユーザーとメイン agent の対話に基づき作成された草案である。**正確であることは要求されない**：各作業点の着工前に立ち戻って改訂する。前提としてマイルストーン三（[03-third-txn.md](03-third-txn.md)）の出口がすべて達成されていること；マイルストーン三の収束時に欠落項目があれば、本ファイルはその欠落に応じて再編される。元の項目六（並行コミット）はマイルストーン六「並行読み書きと並行コミット」（[06-sixth-txn.md](06-sixth-txn.md)）に移管され、本ファイルおよびマイルストーン五「小ファイルパッキング」（[05-fifth-txn.md](05-fifth-txn.md)）の後に配置された（ユーザーが 2026-10-11 に決定：「マイルストーン4と5の順序を入れ替えればよい」、同日さらにパッキングを並行の前に配置と決定）；本ファイルは直列コミット前提で設計する。

**読み方**：各項目は四枠構成とする——「原話」はユーザーの口述を忠実に記録；「リポジトリ内の既存要素」は当該項目がリポジトリ内でどの条項、未済の検査、コードを担っているかを記述（2026-10-01 時点で調査、出所付き）；「作業点」は表：番号、作業内容、担う条項と未済の検査、受入（各条項はまず赤になることを実証）、依存；「着工前の確定事項」は未確定であり着工前に三者合意またはユーザーへの確認を要する問題を列挙。「推論」とあるものはメイン agent が未計測の判断である。作業点番号は「項目·点」（一·1、二·3）と表記し、本ファイル内でのみ使用する。

**新規トランザクションは二種類**：スナップショット作成 / スナップショット削除（項目一）、および GC 移動（項目二）。GC は新規の `CommitStep` メンバーを追加せず、インテントを単調述語として記述し（D26 (バックグラウンド整理と配置回収) 確定項目 2）、マイルストーン三で着地した削除のインテント機構を踏襲する。

1. 中央マッピング：各パブリッシュ済みコード 1 / コード 3 ユニット → その配置先（デバイス、スロット）。ユニットヘッダ内に中央マッピングキーの全入力が存在（`crates/singlefs-core/src/records.rs` の `:347`、`:359` の二つのキー規則が読み出すフィールド）、同一キーの複数バージョンは C113 (スキャン再構築時の複数版ユニットの現行バージョン判定に入力がない) 決定 P2 に従い現行を選択（ユニット書き込み順序 (インスタンスコード, トランザクション番号) ＋ インスタンス表パブリッシュ済み述語、`crates/singlefs-checker/src/walk.rs` の `PublishedPredicate` および `scanned_content_units` で既に計算済み）。
2. 各 inode のデータユニット集合（extent ツリーのリーフ内容）：コード 1 ユニットヘッダのオブジェクトキー（`ScannedContentUnit.object_key`）からマージし、I-1.8 (マージ後バージョンの全順序) の全順序キーに従い現行を取得；走査方向が extent ツリーから読み出した (inode, オフセット) → データユニットと項目ごとに比較。
3. inode レコード集合：inode リーフコンテナ（コード 3、パッキングレコード種別 2）の現行バージョンから各レコードをデコード；走査方向が inode ツリーから読み出したものと項目ごとに比較。
割り当てレコードツリー、会計ツリーは派生状態であり（D21 (権威状態と派生状態の境界) 確定項目 5）、第一版では再構築・比較を行わない（負債は C122 (割り当てレコードのポイント削除後のエントリ数計測条件)、C413 (断片化度と完全空セグメント統計に不変条件がない) に計上）；deadlist / livelist 等はスナップショット着地後、C301 (deadlist と livelist の状態区別が未記述) の確定後に比較。

**入力と禁止領域**：入力は `ImageReader`（`crates/singlefs-checker/src/image.rs`）のデバイス、ジオメトリ、候補スロットのみ；インスタンス表行は最新ルートから読み出す（パブリッシュ済み述語に必要、現在の I-1.8 (マージ後バージョンの全順序) の走査と同一の情報源。これは再構築側がルートを読み出すことが許される唯一の箇所であり、関数ドキュメントに明記）；ツリーテーブルは読まず、いかなるツリーノード（コード 2）も読まない。スキャン方向と走査方向が共有するのはフォーマット解析のみ（D13 (検証ルート) 確定項目 12）：再構築コードは `singlefs_format` 定数および checker 内のユニットヘッダデコード関数（`unit_header_of` 一族）の呼び出しのみが許可され、ツリー走査関数（`walk_*`、`IndexNodeCache`）の呼び出しは禁止；この規則は単体テストで固定（再構築モジュールの `use` リストとホワイトリストを項目ごとに突き合わせ、C410 (checker の二方向が何を共有しているかの検査がない) の必ず赤になる形態）。
