## III. Multi-Tenant Isolation

- **Verbatim**: "5 also has permission issues, because using O_DIRECT requires designing permissions" "in other words calling it multi-tenant isolation might be more appropriate" confirming "Yes, we want Linux permission model to judge permissions ourselves in o_direct mode" (User 2026-10-12).
- **Existing in repo**: On-disk format of inode records reserves 4 bytes each for mode / uid / gid / nlink at offset 24 (field table in settled item 6 of D8 (core index structure)); `InodeRecord` in `crates/singlefs-core/src/records.rs` only carries inode, object birth generation, nlink, size, change count, write timestamp; writing to disk hardcodes mode to `0o100644`, uid and gid to 0, reading skips these three slots (writing and parsing of `InodeRecord`, checked in `crates/singlefs-core/src/records.rs`). How attributes are extended is linked to C115 (overflow path of inode attributes lacks placement), originally ordered in Milestone 11 I·2 (placement of attributes and extended attributes). Space accounting follows `.claude/rules/fs-design.md` "accounting is a byproduct of transactions, not post-hoc traversal" falling in first slot; per-tenant quotas must likewise be maintained incrementally upon commit.
- **Work items**:

| # | Description | Backing clauses and owed checks | Acceptance | Dependencies |
|---|---|---|---|---|
| III·1 | Design round (same round as I·1): how identity is obtained (inferred: disk-holding process obtains uid, gid, and supplementary groups of peer process via Unix socket); mode, uid, gid fall in slots reserved at offset 24 of inode records; how far alignment goes with Linux kernel judgments for regular files (beyond owner / group / others rwx tiers and root, whether setuid / setgid / sticky bits, POSIX ACLs, capabilities like `CAP_DAC_OVERRIDE` are recognized); whether listing (enumeration by inode number) filters by permission; raw disk itself governed by Linux device node permissions (which user disk-holding process runs as, which group disk belongs to); per-uid quotas maintained incrementally upon commit | Settled item 6 of D8 (core index structure); C115 (overflow path of inode attributes lacks placement); metric table in D5 (snapshot / space accounting mechanism); settled item 1 of D16 (publish semantics) "acceptance"; C71 (unrecognized metric tags silently ignored) (quota per uid is the first new statistical dimension planned, attribution inferred, verify before starting work) | Three-party verdict filed in `research/prompts/`, settlements written back to kb; decisions require experiments | Stage 0 |
| III·2 | Implementation: inode records read and write mode, uid, gid (no longer hardcoding `0o100644` and 0); owner takes caller upon file creation; chmod, chown, quota modification are separate transactions traversing same transaction layer (`.claude/rules/fs-design.md` "start from transactions, not from features"); session entry judges read, write, truncate, delete, listing per caller uid, gid, supplementary groups and file mode; per-uid space quotas maintained incrementally upon commit, acceptance rejects accordingly | Settlement of III·1 | Each new test proven to turn red first; differential testing against model matches item by item across interleaved multi-uid history | III·1; I·2 |
| III·3 | Unauthorized access test cases and differential testing: one test case per permission tier in Linux (writing without write bit, reading without read bit, modifying another file's mode, non-root changing owner, writing after exhausting own quota), all rejected; identical tuple (uid, gid, supplementary groups, mode, operation) judged via kernel on ext4 matches singlefs judgment item by item; streams crashing mid-chmod or chown connect to crash amplification; per-uid quota ledger in crash streams equals per-uid calculated by checker traversal | `.claude/rules/fs-design.md` "accounting is a byproduct of transactions, not post-hoc traversal" (runtime and checker use different algorithms) | Unauthorized access cases all rejected, differential testing matches item by item; removing entry check causes unauthorized test cases to turn red | III·2 |

- **Must be settled before starting work**:
  1. Processes capable of directly opening raw disks bypass any file-level judgment (able to read every byte on disk); hence isolation based solely on permission bits requires tenants not to touch disks directly: multiple sessions can only take the form of "single disk-holding process serving multiple client sessions". To allow tenants to open disks directly, encryption partitioning keys by tenant is required, with encryption in Milestone 15 ([15-fifteenth-txn.md](15-fifteenth-txn.md)). Choosing between the two determines multi-session form in I·1 (inferred, unmeasured).
  2. How far alignment with Linux goes: implementing rwx and root only, or including setuid / setgid / sticky bits, POSIX ACLs, and capabilities together.

**Not in exits**: Access via kernel VFS (FUSE in Milestone 12 [12-twelfth-txn.md](12-twelfth-txn.md)), directories and names (Milestone 11 [11-eleventh-txn.md](11-eleventh-txn.md)), two machines sharing a single disk.
