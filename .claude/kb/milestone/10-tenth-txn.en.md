## I. Sessions and External Interfaces

- **Existing in repo**: `O_DIRECT` backend is `DirectInputOutputBlockDevice` in `crates/singlefs-core/src/block_device.rs` (physical block size probed or declared via sysfs); repo-wide only two apparatus binaries in the verification crate use it (`new_pool_file_creation_on_device`, `new_pool_file_creation_device_log_check`), running on virtio disk in QEMU (`direct` mode of `crates/singlefs-verification/src/on_device_modes.rs`); publish after mounting is handled by `crates/singlefs-core/src/mounted_session.rs` layer; core lacks exclusive open (`grep -n 'O_EXCL\|flock\|lock_exclusive' crates/singlefs-core/src/*.rs` yields zero hits), and lacks binaries or CLI for application use. Multiple files (C618 (unable to create files with data after deletion)) belong to Milestone 5 "X. Multiple Files". The background runtime `MountedRuntime` started at mount holds one lock inside the process; there is no cross-process exclusive open (C833 (Writable mount has no exclusive open), checked 2026-11-16).
