### IV·1 Problem Statement (Written by main agent 2026-10-13, per crates/ status)

**Problem**: Read-only scan rebuild — without reading root ring or tree table, reconstruct "index" purely from unit headers scanned from unit area, comparing item-by-item against index read from latest root by traversal direction, with zero divergence. No writeback to disk (rescue writeback not in exit criteria).

**What to rebuild** (three derived tables in first version, all computed on the fly from scanned unit headers and payloads):
1. Central mapping: each published code 1 / code 3 unit → its placement (device, slot). Unit header contains all inputs for central mapping key (fields read by key rules `:347`, `:359` in `crates/singlefs-core/src/records.rs`), multiple versions of same key choose current version per C113 (current version judgment for multi-version unit during scan rebuild lacks input) settlement P2 (unit write order (instance code, transaction number) + instance table published predicate, `PublishedPredicate` and `scanned_content_units` in `crates/singlefs-checker/src/walk.rs` already computed to this step).
2.
