# マイルストーン「実ディスク上の O_DIRECT セッション」: 作業項目、受入、順序

[中文](10-tenth-txn.md) · [English](10-tenth-txn.en.md) · **日本語**

**計測条件**: 計画文書。2026-10-12 にユーザー決定に基づき前倒し作成（発言ママ「我计划 目录与 POSIX 面 这个里程碑前， 先增加一个 o_direct 挂载里程碑。先实现通过o_direct 挂载。」；同日メイン agent の質問への回答: 「ユーザースペースライブラリが物理 NVMe を O_DIRECT で開き（QEMU を経由せず）、リカバリを行い、セッションを長期保持し、外部へは inode 番号によるファイル API またはコマンドラインを提供；カーネル VFS には入らない」「つまりカーネル VFS をバイパスする方法を提供するということ」）、草案である。**正確であることは要求されない**: 各項目の着工前に見直して改訂する。前提条件は、マイルストーン3から9の出口がすべて達成されていることである（マイルストーン9は [09-ninth-txn.md](09-ninth-txn.md)）；先行するマイルストーンの完了時に不足がある場合、本書はその不足項目に応じて再編する。

**読み方**: 各項目三つの区分——「リポジトリ内の既存要素」はその項目がリポジトリ内でどの条項、未済の検査、コードに基づいているかを記述（2026-10-12 時点確認、出典付き）；「作業項目」は一覧表: 番号、作業内容、根拠条項と未済の検査、受入（各条項が事前に赤となることを証明）、依存関係；「着工前の要確定事項」は未確定で着工前に三者検討またはユーザーへの確認が必要な問題を列挙。「推論」と書かれた箇所はメイン agent が測定していない判断である。作業項目の番号は「項目・点」（一・1、二・1）と表記し、本ファイル内でのみ使用する。

**カーネル VFS へは入らない**: アプリケーションは本書が提供するライブラリ API またはコマンドライン経由で直接 singlefs にアクセスし、カーネル VFS をバイパスする；D17 (実装階層とサードパーティパイプライン) の確定項目 5「初版は純粋なユーザースペースライブラリであり、マウントしない……2つのバックエンド: 通常ファイルと `O_DIRECT` で開かれた生デバイス」と同方向であり、再開しない。カーネル経由のアクセス（FUSE）はマイルストーン12（[12-twelfth-txn.md](12-twelfth-txn.md)）。**新規トランザクション種別の追加なし**: セッション内の操作はすべて既存のトランザクションへ還元される。

## 一　セッションと対外インターフェース

## 三　マルチテナント隔離

- **発言ママ**: 「5 还有权限的问题，因为使用O_DIRECT  所以需要设计权限」「换句话 叫做多租户隔离 可能比较合适」確認「对 我们要 Linux 的权限模型自己判权限 在 o_direct 模式下」（ユーザー 2026-10-12）。
- **リポジトリ内の既存要素**: inode レコードのディスク上形態はオフセット 24 に mode / uid / gid / nlink 各4バイトを予約（D8 (コアインデックス構造) の確定項目 6 のフィールド表）；`crates/singlefs-core/src/records.rs` の `InodeRecord` は inode、オブジェクト誕生世代、nlink、size、改変カウント、書き込み時刻のみを保持；ディスク書き込み時に mode は `0o100644`、uid と gid は 0 にハードコードされ、読み出し時にこれら3スロットをスキップ（`crates/singlefs-core/src/records.rs` の `InodeRecord` の書き込みと解析を参照）。属性拡張手法は C115 (inode 属性のオーバーフロー経路の配置先欠落) に付随し、元々はマイルストーン11の一・2（属性と拡張属性の配置先）に配置。空間統計は `.claude/rules/fs-design.md`「会計はトランザクションの副産物であり事後走査ではない」に基づき第1スロットに配置、テナント別クォータも同様にコミット時に増分維持が必須。

- **着工前の要確定事項**:
