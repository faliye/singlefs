# 避坑清单

**现有 COW 文件系统上已被证实的设计失误。用法：每做一个设计决定，回来对一遍这张表。**

目前条目主要取自 btrfs——不是针对它，而是因为它的失败模式记录得最完整、
社区讨论最公开、可考证。别的实现有同类教训一样收进来。

坑的描述来自公开资料与各自的官方文档，**未在本工程验证**。
"对策"一栏链接到 [decisions.md](decisions.md) 的对应决策。

| # | 坑 | 根因 | 对策 |
|---|---|---|---|
| 1 | ENOSPC 荒谬（`df` 有空间但写不进、删文件也报没空间） | 两级分配 + chunk 分类僵化 | ✅ D3 不分类 |
| 2 | RAID5/6 write hole，至今不建议生产使用 | 定宽条带需 read-modify-write | ✅ D2 变宽全条带 |
| 3 | extent tree + backref 是复杂度黑洞与 bug 集中区 | 反向索引是长出来的，不是设计的 | ✅ D1 day-1 设计 |
| 4 | fsync 走特例化的 log tree，独立 bug 源 | 第二套事务机制 | ✅ 统一事务层（.claude/rules/fs-design.md） |
| 5 | 所有数据挤在同一棵树、同一 key 空间、同一把锁 | 单一索引结构 | ⏸ D8 按访问模式分结构 |
| 6 | RAID 级别只能整盘设，做不到按文件设 | profile 绑在 chunk 上 | ⏸ 候选：指针内联多副本 |
| 7 | qgroup 又慢又常年记错（+76% 提交时间 / +1347% 事务等待 / −25% 写吞吐） | 记账是后补的，且依赖反向索引遍历 | ✅ D5 birth txg 增量记账 |
| 8 | `nodatacow` 是逃生舱不是解法（关 COW = 同时丢校验和与快照一致性） | 随机写碎片化没有真答案 | ⏸ D10 未决 |
| 9 | degraded 挂载会写出单副本 chunk，越救越糟 | 降级行为没有设计 | ⏸ 未决：降级语义需显式定义 |
| 10 | `btrfs check --repair` 社区自己劝你别用 | 可重建性不是设计目标 | ✅ 自描述块 + checker day-1 |
| 11 | 没有原生加密 | 从未进入格式，现在塞不进去 | ✅ D9 半定，四样格式字段 day-1 预留 |
| 12 | `df` 输出对用户没有意义 | 实现细节泄漏给用户 | ⏸ 未决：空间语义要面向用户设计 |
| 13 | 原生加密与 send/recv 复制路径长期互相踩（openzfs/zfs#12014 自 2021-05 开着，2025 年仍在修） | 认证结构为了 raw send 而变形：MAC 不能做成 Merkle 树，改用聚合 MAC + objset 层双根 | ⏸ D9：密文复制的语义要在格式层定，不做成事后功能 |
| 14 | nonce 绑物理位置 → 搬一个块就要重新加密，后台整理离不开密钥，多副本还字节不同 | 加密与数据可移动性没有一起设计 | ✅ D9 硬要求：nonce 跟逻辑身份走，存在指针里 |
| 15 | per-directory 加密逼着文件大小留明文（fsck 要用），filenames / xattr / inline extent 跟着各留一堆缺口 | 加密粒度细于校验粒度 | ✅ D9：整卷加密，不做 per-directory |
| 16 | 换用户密钥不使旧的被包裹主密钥失效，可被取证恢复 | 换钥只重新包裹主密钥，不重新加密数据 | ⏸ D9 未答项：换钥能保证什么要写给用户看，不能让人以为等于重新加密 |

## 优势

**同样来自现有实现，但这些已被验证有效，值得直接沿用。**

| 项 | 说明 |
|---|---|
| 元数据节点头自描述 | 节点头带自身逻辑地址、generation、level、所属树、fsid。这是 btrfs-rec 能在树全烂时靠全盘扫描重建的唯一原因 |
| feature bit 分三档 | `incompat` / `compat_ro` / `compat`，演进通道设计正确 |
| 单设备与多设备同一套代码路径 | 不为单盘开特例，减少一整类只在多盘下才暴露的 bug |
