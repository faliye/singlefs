# 設計決定記録

[中文](decisions.md) · [English](decisions.en.md) · **日本語**

各決定の状態は3種類のみです: **決定済み（已定）** / **半決定（半定）**（方向性は決定、詳細は未定）/ **未決定（待定）**。
これは各決定本文の先頭行 `## D<n> 略称 —— 状態` に記述され、そこが唯一の権威ある記録です。
本文の構成（各決定項目は定案 / 射程 / 根拠 / 欠の4ブロックで構成され、根拠はポインタのみ記述、実験があって初めて決定が成立）については `.claude/rules/format-evolution.md`「決定本文は現状のみ記述し根拠はポインタとする；決定と実験の双方向登録」を参照してください（門番 doc-experiments の decision-links スロットで判定）。
決定を覆す場合は本文を直接修正します。修正前・修正後および根拠は [decisions-history.md](decisions-history.md) 内の該当する `## D<n>（略称）` 節に記録し、構成形式は `.claude/rules/changelog-format.md` に従います。decisions.md および各決定本文末尾の「履歴バージョン」には誘導文のみを置き、詳細な変更履歴は記載しません。

## 決定インデックス

**各決定の本文は `decisions/` 配下に独立したファイルとして存在します。** 決定インデックス表はナビゲーション + 一言の結論を提供し、**登録簿ではありません**——
番号の登録簿は各本文ファイル内の `## D<n> 略称 —— 状態` 見出し行です。

⚠️ **「結論」列は一律200字以内**とし、その決定が**何を定めたか**を記述します。なぜ定めたかや何が不足しているかは記述しません。
上限は門番段階「決定インデックス結論列の幅」（`.claude/gate.d/doc-decisions.sh` の decision-summary-width スロット）で判定されます。上限値の権威ある記録は「「結論」列は一律 N 字以内」という文中の N であり、門番はそこから読み取ります。
詳細や根拠は本文に記載します。分項は各本文の「決定済み項目」/「未定項目」の2つの小節に状態ごとに収められ、通し番号で採番され並べ替えられません。

⚠️ **「状態」列には分項のカウントが記載されます**（例: `決定済み 6 項目 / 未定 0 項目`）。決定がいくつの項目に分かれ、そのうち未定が何件あるかが一目で把握できます——3態の単語ではこの問いに答えられないため、この列には配置されません。
分項のない決定のセルには `分項なし · 全体決定済み` と記載されます。
この列は各本文の2つの小節の射影であり、`.claude/scripts/gen-decision-items.py` により自動生成されます（**手動編集禁止**）。

⚠️ **「進捗」列（末尾列）には実装カウントが記載されます**（例: `実装済み 3 項目 / 未実装 1 項目`、対象外がある場合は ` / 対象なし 2 項目`、分項なしの場合は `対象なし`）。
これは各分項インデックス行末尾の標準マーク `**進捗：実装済み。**` / `**進捗：未実装。**` / `**進捗：未実装。**` の射影であり、
自動生成され、**手動編集禁止**です。分項リスト内では各項目が `—— 決定済み · 実装済み` のように記述されます。3つの値の判定基準:
**実装済み** = `crates/` 内に該当コードが存在する（ソースが「D<n>（略称） 決定済み項目 k」を名指ししている、または該当構造とパスが確認できる）；
**未実装** = 該当項目が管轄するパスや構造が `crates/` 内に未存在、または存在してもそれに準拠していない；
**対象なし** = 取り下げられた番号、判定基準や境界に関する項目、プロセスや他決定の管理のみでコード形態を持たない項目。
進捗を修正する場合は該当行のマークを修正し、`--write` を実行します。門番 doc-decisions の kb-shape スロットがマークの有無と妥当性を検証し、進捗列との一致を確認します；decision-items-sync スロットが生成器の出力と完全一致するか比較します。

```bash
bash .claude/gate.d/doc-decisions.sh --write   # 状態列、進捗列、分項リストを一括再生成
```

門番は2つの異なる経路で検証します: decision-items-sync スロットが生成器出力とインデックス表を逐字比較します；
kb-shape スロット（第7段落）が**本文を独自に数え直して比較**します——生成器が誤認した場合、decision-items-sync は両側同時に誤るため、kb-shape のみが赤（不合格）になります。
