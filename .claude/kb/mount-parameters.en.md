# Mount Parameter Table

[中文](mount-parameters.md) · **English** · [日本語](mount-parameters.ja.md)

Mount parameters are parameters the caller gives at each mount and that can be changed without rebuilding anything. The whole repository has two kinds, listed one parameter per row in the mount parameter table of `mount-parameters.md`:

| Kind | Stored on disk? | Source |
|---|---|---|
| The background compute and GC cadence set (including the three compaction watermarks and the batch size) | Not stored: lives only in memory, is not written to system configuration, does not occupy a feature bit, and is supplied separately at each mount | D26 (Background Compaction and Placement Reclamation) settled item 13 rule 1; for the watermarks and the batch size, D26 (Background Compaction and Placement Reclamation) settled item 1 |
| System runtime configuration (36 bytes; the ones in use are T_time with 4 bytes and T_dirty with 8 bytes, and the 24 bytes of compaction watermarks are an all-zero reservation) | Stored: lives in the system configuration slot, mkfs writes the defaults, and each mount can reset them and write them back to disk | D22 (Synthesizing Unit Atomicity) settled item 26 |

**Where parameters are given**: today the background compute set has only a library function entry and no command line (once there is a command line it takes the form `--background-compute=gpu`, D26 (Background Compaction and Placement Reclamation) settled item 13 rule 1): mounting goes through `mount_writable_with_background_compute_settings_the_gc_cpu_compensation_threshold_and_compaction_parameters` (`crates/singlefs-core/src/mount.rs:9741`, together with the three watermarks and the batch size, `CompactionMountParameters`), and switching while mounted goes through `switch_background_compute_with_the_gc_cpu_compensation_threshold_from_the_next_batch` (`crates/singlefs-core/src/mounted_session.rs:3181`). The background runtime started at mount gathers these, together with the compaction period and the GC write bandwidth limit, into one `RuntimeParameters` (`crates/singlefs-mount-runtime/src/lib.rs:65`) and computes from the period the `CompactionPacing` it hands to the background entry of the core layer. System runtime configuration has no mount entry, and the code writes only the built-in defaults (C422 (Mount option channel nonexistent)).

**Not here**: mkfs parameters (journal ring length, unit size, placement granularity, devs, node size: the first two tiers of D22 (Synthesizing Unit Atomicity) settled item 26) need a rebuild when changed and are not mount parameters. The unit write retry budget `T_retry` of D16 (Publish Semantics) settled item 5 is a named adjustable parameter, but the clause does not say whether it is a mount parameter and the code does not have it either, so it is not listed.

**The three compaction watermarks are not stored on disk, and the 24 bytes in the system configuration are an all-zero reservation**: the three watermarks of D26 (Background Compaction and Placement Reclamation) settled item 1 are three quantities, completely empty cluster segment count, fragmentation metric and unreclaimable bytes, crossing any one of which starts a run, and stopping takes the `R` local predicate and does not rely on watermarks; all three are mount parameters and are not stored on disk. In the system configuration field table (`layout/01-first-txn.md` "I. Seeded by mkfs (Present on Disk Before New-Pool File Creation)") these 24 bytes are called compaction watermark reservation, always all 0, with the bytes unchanged. In the code these 24 bytes are the three reserved words of the system runtime configuration (`reserved_runtime_words` at `crates/singlefs-core/src/system_configuration.rs:370`), always written as 0; the three watermarks are `CompactionWatermarks` at `crates/singlefs-core/src/compaction_plan.rs:1671`.
