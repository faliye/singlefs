## E40 反向链挡不挡得住残留记录 —— 已跑（2026-08-29，N=5 轮字节一致）

**它问的是**：D23（journal 的角色与格式） 未定项 8 的方向定案「记录头加一条反向链
（前一条记录的 hash）」，**能不能真的把上一条时间线的残留记录挡在合法前缀之外**。

⚠️ **方向已定不等于有效性已证。** E33（上一条时间线的残留） 实测过那个漏洞成立
（N=5 轮字节一致）：残留记录校验和完好、`jsn` 恰好等于 expected，
I-8.3（重放前缀严格连续）、在飞记录数上限、`checkpoint_txg` 三条闸逐条核实都不触发。
**本实验测的是补丁，不是漏洞。**

### 要测什么、判据、失败条款

- **测什么**：在 E33（上一条时间线的残留） 那套模型上加一条反向链字段，重跑同样的
  「空洞 → 恢复 → 少量续写 → 再崩」序列，看重放前缀里还会不会出现属于已丢弃时间线的记录。
- **判据**：
  - **有效性**：加了反向链之后，属于旧时间线的记录被接受进前缀的次数必须为 **0**。
  - **不误杀**：同一条时间线内的合法前缀必须**一条不少**地被接受
    （否则它是靠「什么都不接受」拿到的 0）。
  - **宽度**：扫 hash 截断宽度（32 / 64 / 128 位），找到「误接受率仍为 0」的最小宽度，
    并给出该宽度下的碰撞概率算术。
- **阳性对照**：把反向链字段整个关掉，误接受次数必须回到 E33（上一条时间线的残留） 那个非零值——
  否则「0」分不清是反向链有效还是模型根本没造出残留。
- **失败条款**：若在任一参数组合下加了反向链仍有误接受，方向定案不成立，
  **如实记录并退回 D23（journal 的角色与格式） 未定项 8**。
- ⚠️ **必须带绝对值断言**：造出来的残留记录条数要由构造直接算出，
  不许从被测代码读回来——否则「误接受 0」可能只是因为一条残留都没造出来。

### 口径要求

⚠️ **必须覆盖 E33（上一条时间线的残留） 没覆盖的那两个组合**：
那一轮四个组合只覆盖了 2 / 4，本实验要把四个都跑到，否则补丁的射程与漏洞的射程对不上。

### 实测（2026-08-29，N=5 轮逐字节一致；8 条变异全部被抓、0 个盲区）

#### 功能：开链的 16 个格子残留全 0，且不误杀

2 种槽位映射 × 2 种续写策略 × 开/关链 × 4 档宽度：

| | 结果 |
|---|---|
| **有效性** | 开链的 **16 个格子全部** `replayed_stale = 0` |
| **不误杀** | 同 16 个格子全部 `lost_own = 0`，前缀恰为 `20 落定 + 3 新写 = 23` —— **不是靠什么都不接受拿到的 0** |
| **阳性对照** | 关链且从前缀末续写的 8 个格子全部 `replayed_stale = 6` —— 残留确实造出来了 |

#### 宽度：8 位不够，16 位边缘，32 位起才干净

**碰撞是概率事件，一轮试验量不出概率** ⇒ 每档跑 **200 万轮独立试验**
（每轮换一个种子，判「残留有没有骗过反向链」）：

| 宽度 | 误接受 / 200 万轮 | 折合 ppm | 理论 2⁻ⁿ | 记录头 84 → | 头增长 |
|---|---|---|---|---|---|
| **8 位** | **7 922** | 3 961 | 3 906 | 85 字节 | +1.19% |
| **16 位** | **33** | 16 | 15.3 | 86 字节 | +2.38% |
| **32 位** | **0** | 0 | 0.0005 | 88 字节 | +4.76% |
| 64 位 | 0 | 0 | ~0 | 92 字节 | +9.52% |

**实测逐档贴住理论值 2⁻ⁿ**（3961 vs 3906、16 vs 15.3）⇒ 这条曲线是可外推的，不是巧合。

⇒ **读法**：8 位每 256 次「空洞 → 恢复 → 续写 → 再崩」就放进去一条别的时间线的记录，
**太少**；16 位是每 6.5 万次一条；32 位在 200 万轮里一次都没有，且理论上是每 43 亿次一条。
**买 32 位只要 4 字节、记录头涨 4.76%**，按 `.claude/rules/fs-design.md`
「不为省空间牺牲自包含」，这个价钱不该省。

#### 独立复现了 E37（槽位映射那一维） 的结论

本实验的模型独立重写，**没用 E33（上一条时间线的残留） / E37（槽位映射那一维） 的代码**。
把槽位与序号解耦、并按 jbd2 的做法在恢复时把写头退回断点位置之后，
解耦那一支的 `replayed_stale` 与 `jsn` 取模那一支**逐格相等（都是 6）**
⇒ **仅仅解耦并不免疫**，与 E37（槽位映射那一维） 的结论一致。这是一次免费的交叉核对。

#### 三处是被断言与变异打出来的，不是 review 看出来的

1. **绝对值断言先红**：按「造了 8 条残留就该重放 8 条」写，实测 **6**。
   新时间线写的 3 条盖掉了空洞那一格加其后 2 条残留
   ⇒ **活下来的残留 = `stale − (new_after − 1)`**。**模型没错，是断言少算了覆盖。**
2. **解耦臂必须把写头退回断点**：不退回的话新记录写在残留后面，顺序扫描根本走不到
   ⇒ 量出来的会是「新记录全丢」（`lost_own = 3`）而不是「残留被重放」。
   ⚠️ **一个模型缺陷会伪装成一个结论。**
3. **摘掉「序号必须等于 expected」时九个测试一个都没红**——别的臂读到的记录序号本来就等于 expected，
   那条闸在它们身上是冗余的。补了一条用「解耦 + 跳过断点续写」造出
   「校验和完好但序号对不上」的测试之后被抓。

⚠️ **哈希本身要能被证明在随种子变。** 种子必须放在**最前**并配终混：
放末尾且直接截低位时，FNV-1a 的低字节演化对每个输入字节是**双射**
⇒ 两端追加同样的种子字节，低字节相等与否**与种子无关**
⇒ 8 位那档跑出 **0 次误接受**（理论 7 813 次）。
**那不是「8 位够用」，那是没量到东西。**
守它的是断言 `the_measured_false_accept_rate_tracks_two_to_the_minus_n`
（实测必须贴住 2⁻ⁿ）与变异 `M8_退回第一版哈希`。
⚠️ **同类的第二个坑**：种子做成全局静态时，并行跑的单测会互相踩，
「8 位该出几百次」实测 3 次。**种子是参数，不是全局。**

**口径**：64 槽环、20 条落定、第 21 条是空洞、其后 8 条残留、新时间线续写 3 条；
宽度那一段每档 200 万轮独立试验。记录头 84 字节取自 E24（journal 几何) 逐字列出的 11 个字段。
代码 `research/e7-index-bench/src/bin/e40_back_chain.rs`
（`cargo run --release --bin e40_back_chain`），
原始输出 `research/results/e40-back-chain-2026-08-29.out`，
变异表 `research/mutations/e40_back_chain.tsv`。
**13 个单测，8 条变异逐条命中、0 个盲区。**

### ⚠️ 它答不了的

- **误接受率是「每次事故一次机会」的概率，不是「每秒」的频率。** 分母是
  「空洞 → 恢复 → 少量续写 → 再崩」这个序列发生的次数，本实验不回答它多久发生一次。
  ⇒ 从 ppm 推「多久出一次事」要另外给那个频率。
- **它只测了一种碰撞形态**：新时间线最后一条的 hash 撞上第一条活着的残留记录里存的 prev_hash。
  真实实现里还有别的比对点（例如 checker 反向遍历），本实验没覆盖。
- **它不回答 hash 算法选哪个。** 模型用的是 FNV-1a + splitmix64 终混，
  实测贴住 2⁻ⁿ 说明它在这个规模上够随机，**但那不等于它适合做格式里的那个字段**。

无。E33（上一条时间线的残留） 的模型已在仓里，加一个字段即可。
