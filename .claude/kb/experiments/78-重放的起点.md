## E78 重放的起点 —— 已跑（2026-09-02，计数模型，16 单测 / 9 条变异全抓）：**陈旧 tail × 块重用叠加后，全环扫描式恢复在健康镜像上自我中止；出路是根带水位或盲放加尾删**

D23（journal 的角色与格式）已定项 3 定了全环扫描式恢复，E24（恢复算法：先信 tail 会不会丢记录）
逼出重放幂等，当时的结论是「陈旧 tail 只是多做功」。**E24（恢复算法：先信 tail 会不会丢记录）没建模块重用**：
I-7.4（近 K 代块未被复用）只扣最近 K 代（K ≤ 根环深度，几十个量级），
而环里的记录数以千计——陈旧 tail 与最新根之间的记录，其点名块可以已被**合法**释放并复用。
E77（发布的持久顺序）又刚证明重放施加前必须验证点名单元。两条已定要求叠在一起怎么收场，
E78（重放的起点）拿四条恢复算法各跑一遍。

### 判据（跑前写死，写在源码头部，跑完没改）

1. 失配数钉闭式 `max(0, M − L − PIN − tail)`，并与独立的重分配追踪器逐格相等；
   手算锚点 (M=13,tail=8)⇒0、(M=23,tail=16)⇒2。对不上作废。
2. 阳性对照：闭式 > 0 的格上中止臂必须中止。不中止说明模型没判别力，作废。
3. 撕裂判别力：torn 场景下水位臂、尾删臂必须旗标 1 且终态 = M；跳过臂必须旗标 0（静默吞掉）。
4. 终态审计（不共享恢复代码）：宣称完成的恢复终态必须与真值逐格相等，不等该算法出局。

### 实测（L=4 对象轮转 COW，环 64 槽；主格 M=23 / PIN=1 / tail=16，失配闭式 = 2）

| 算法 | 健康镜像 | 撕裂镜像（记录在、单元没落） |
|---|---|---|
| **中止臂**：从 tail 重放 + 施加时验证 + 失配即中止 | **中止**——把陈旧失配当损坏，**健康镜像判恢复失败** | 同样中止（在撞到撕裂之前先撞陈旧失配） |
| **跳过臂**：从 tail 重放 + 施加时验证 + 失配跳过 | 完成，悄悄跳过恰 2 条 | 完成，但**旗标 0**——撕裂与陈旧同一个计数器，分不开 |
| **水位臂**：根带 jsn 水位，只放 > 水位的 | 完成，重放 0 条 | 完成，**旗标 1**（水位外失配落在在飞窗口内 ⇒ 判撕裂） |
| **尾删臂**：盲放全前缀 + 收尾走读 + 尾删重试 | 完成，0 轮重试 | 完成，恰 1 轮尾删，**旗标 1**，窗口内其余 7 条保住 |

边界格证实这是**只在 tail 足够陈旧时咬人的 bug 形状**：窗口 < L + PIN 时（tail 刚推进过）
四条算法全部干净完成——测试常绿不代表没事。PIN 加大失配单调减少（PIN 1→2 时 2→1）。

### 三条结论

1. **「全环扫描 + 断号即止 + 幂等」三件套不闭合。** I-8.4（重放幂等）管「同一条记录重复施加」，
   管不到「旧记录的点名块已被复用」——后者在施加时验证下是**校验失配**，不是无害重放。
   中止臂（把失配当损坏）在健康镜像上自我中止，是**可用性故障**；跳过臂保住可用性，
   代价是撕裂判别力归零。
2. **恢复需要一个「重放下界」，而它今天没有落点。** 水位臂那条出路要根记录带一个 jsn 水位字段
   （D23（journal 的角色与格式）已定项 9 的宽度是 10 字节）——⚠️ 若「每次发布都推进
   checkpoint_txg」成立，记录头现有的 `checkpoint_txg` 就能当水位；若一个 txg 罩多次发布，
   同 txg 记录与根之间无法排序，必须另立字段。**这取决于一条没人写死的等式**，
   落点 [checks-owed.md](../checks-owed.md) C85（发布计数器的四个等号没写死）。
3. **尾删臂那条出路不要新格式字段**，代价是盲放全窗口 + 至多在飞窗口那么多轮尾删；
   它的正确性有一条构造前提（窗口内被复用块的对象必有更晚记录），本模型证明该前提由
   COW 重写的构造自动成立（有单测钉住）。**水位臂与尾删臂都过全部判据，选哪条是决策——已定（2026-09-02）：取水位臂，权威记录在 D23（journal 的角色与格式）已定项 14。**

### 失败条款（跑前写死）

判据 1、2 全命中（闭式 == 追踪器，四格全对；中止臂在闭式 > 0 的格上确实中止）。未触发作废。
