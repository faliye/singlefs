## E122 按目录聚在一起买到什么 —— 已跑（2026-09-07，纯计数模型，10 单测 / 12 条变异全部被抓）

<!-- doc-lint:not-numbers M1 M2 M3 M4 M5 M6 M7 M8 M9 M10 M11 M12 -->

**问的是** D8（核心索引结构） 已定项 3 那张表里「分配器（把子目录的数据放到父目录附近）」一行的收益。
那一行的唯一依据逐字标着「⚠️ **未核实**——kb 内无出处无口径，要用先补」，
而 D14（双轨（大小文件 / 持久临时）） 未定项 2 一轮三方论证之后用户定「**先补收益数据再定**」。

**结论一句话**：**两格收益都挂在交错度上**——`arrival` 的连续段数 = 对象总数 ÷ 交错步长，
`stride = 每目录文件数`（不交错）时两条臂的落点序列逐格相同，**遍历与回收两个量因此也逐格相同**。
只有在**交错**负载上 `grouped` 才买到东西：`stride ≤ 8` 时删掉一个目录，
`grouped` 腾得出整段（段长 32 槽时 2 个、64 槽时 1 个、128 槽时 0 个），
而 `arrival` 与 `random` 一个都腾不出来。

### 模型建在哪几条已定条款上

| 条款 | 用到的那一句 |
|---|---|
| D14（双轨（大小文件 / 持久临时）） 已定项 3 + D4（校验和位置） 已定项 2 | 内联阈值 0、小文件补齐到 32 KiB ⇒ **每个小文件各占一个整单元** ⇒ 聚集只改变单元**之间**的相邻性。⚠️ **口径（2026-09-09 收窄）**：D27（小数据打包容器） 未定项 1 / 2 定了 ≤ 4 KiB 的对象在写完之后由后台整理搬进共享容器 ⇒ **稳态下 ≤ 4 KiB 那一档并非「各占一个整单元」**，E122（按目录聚在一起买到什么） 的模型只对 **> 4 KiB** 的对象成立，以及对 ≤ 4 KiB 对象**在被整理搬走之前**的那段时间成立（那段时间有多长由 D27（小数据打包容器） 已定项 6 的迟滞 `K` 定，而 `K` 没有数，见 C202（打包巡回的空转开销与迟滞 K 都没有数））|
| D3（空间分配） 已定项 7 | 落点粒度 16384 ⇒ 一个 32 KiB 数据单元占 **2 个槽** |
| D3（空间分配） 已定项 5 | 聚簇段是「运行时分配器政策不是格式位……盘上没有任何字段声明它」⇒ **段长是参数，不是格式常量**，扫 32 / 64 / 128 槽 |

### 三条臂

| 臂 | 落点怎么定 |
|---|---|
| `grouped` | 同一父目录下的对象在盘上连续 |
| `arrival` | 按创建到达顺序；目录之间的交错程度由 `stride` 定（一个目录连着放几个再换下一个）|
| `random` | 确定性 LCG 伪随机。**判别力下界，不是候选** |

### 实测（16 个目录 × 每目录 32 个文件 = 512 个对象）

| `stride` | `grouped` 总段数 | `arrival` 总段数 | `random` 总段数 |
|---|---|---|---|
| 1（完全轮转） | 16 | **512** | 484 |
| 2 | 16 | 256 | 484 |
| 4 | 16 | 128 | 484 |
| 8 | 16 | 64 | 484 |
| 32（= 每目录文件数，不交错） | 16 | **16** | 484 |

⇒ **闭式**：`arrival` 总段数 = 512 ÷ `stride`（源码 `walk_runs_are_pinned_to_absolute_values` 逐格钉住，并断言 `段数 × stride ≡ 512`）。

**删掉一个目录之后腾出的全空段数**（⚠️ **这一格同样带 `stride` 口径**，
产物里 `arrival` 每一行都带 `stride`，此前这张表把它脱掉了，2026-09-09 补回）：

| 段长（槽） | `grouped`（各 `stride`） | `arrival`，`stride ≤ 8` | `arrival`，`stride = 32`（不交错） | `random` |
|---|---|---|---|---|
| 32 | **2** | 0 | **2** | 0 |
| 64 | **1** | 0 | **1** | 0 |
| 128 | 0 | 0 | 0 | 0 |

⇒ **不交错时 `arrival` 与 `grouped` 在回收这一格上也逐格相同**，产物逐行：

```
E7RESULT name=walk arm=grouped stride=32 total_runs=16 worst_dir_runs=1 empty_segs_at_32=2 empty_segs_at_64=1 empty_segs_at_128=0
E7RESULT name=walk arm=arrival stride=32 total_runs=16 worst_dir_runs=1 empty_segs_at_32=2 empty_segs_at_64=1 empty_segs_at_128=0
```

这与阳性对照那一行是同一件事（`stride = 32` 时两条臂的落点序列**完全相同**）——
落点序列相同，任何从落点算出来的量都必然相同。
装置里的断言范围一直是对的（`empty_segments_are_pinned_to_absolute_values` 写死 `stride = 2`，
断言消息逐字「arrival **交错之后**一个整段都空不出来（段长 {sg}）」），
**脱掉口径的是正文**。

### 三条对照的判定

| 对照 | 判据 | 实测 |
|---|---|---|
| 阳性（逐臂） | 不交错时 `arrival` 逐格等于 `grouped` | `stride = 32` 时两条臂的落点序列**完全相同** |
| 阴性 | 每目录 0 个文件 | 三条臂总段数都是 0 |
| 判别力 | 三条臂至少一格不同 | `stride = 2`：16 / 256 / 484 |

### 跑前登记的一处参数标反了，留档不改

判据 3 登记的是「`stride = 1` 时 `arrival` 必须逐格等于 `grouped`」，
而 `stride` 的语义是「一个目录连着放几个再换下一个」⇒ **`stride = 1` 是完全轮转、交错最厉害那一格**，
`stride = 每目录文件数` 才是没有交错。判据的**意思**没变，错的是主 agent 登记时给参数贴的标签。
两个值都留在源码 `positive_control_on_every_arm_without_interleave` 里。

### 变异测试逼出的一条真盲区与一条取样点不敏感

| 变异 | 三分 | 处置 |
|---|---|---|
| `M11_目录数与文件数对调`（改 `main` 里的规模） | **真盲区**：单测各自硬写 16 / 32，没有任何东西钉住产物实际用的那组参数 | 把规模提成常量 `DIRECTORY_COUNT` / `FILES_PER_DIRECTORY` 并在 `geometry_and_workload_constants_are_pinned` 钉住 |
| `M10_random不去重`（把去重条件短路成恒真） | **取样点不敏感**：LCG 的模是 2⁶⁴，而 512 是 2 的幂 ⇒ `x % 512` 恰好走满周期、永不碰撞，去重成了死逻辑 | 补一个非 2 的幂的取样点（15 × 32 = 480，当场碰撞 172 次），见 `random_deduplication_needs_a_non_power_of_two_size` |

### 它对 D14（双轨（大小文件 / 持久临时）） 未定项 2 说了什么

1. **遍历那一半的收益不是「聚集 vs 不聚集」，是「交错 vs 不交错」**：
   负载本来就一个目录写完再写下一个时，分配器什么都不做也拿到同样的结果。
   ⇒ 这一格的收益取决于**目标负载的交错度**，而 D25（目标负载优先级） 的负载表里没有这一维。
2. **回收那一半也是「交错 vs 不交错」，不是「聚集独有」**（2026-09-09 改正）。
   此前这一条写的是「回收那一半是只有聚集才买得到的」，而同一份留存产物里
   `arm=arrival stride=32` 那一行的 `empty_segs` 是 2 / 1 / 0，与 `grouped` 逐格相同
   ⇒ 原写法与产物矛盾，已按产物改正。它的大小另外还取决于段长与目录规模的比值——
   段长 128 槽、目录只占 64 槽时收益归零。
   ⚠️ **这处矛盾门禁看不见**：E122（按目录聚在一起买到什么） 的复跑与留存产物逐字节一致、全绿
   （2026-09-09 现跑复核），而对不上的是**正文与产物**，不是产物与产物。
   落点 [checks-owed.md](../checks-owed.md) C233（结论点名的独有收益在自己产物里有反例）。
3. 两格都**不含**「疑似短命」那一半：那一格在 D25（目标负载优先级） 全文出现 0 次，是空白。
4. **合起来**：E122（按目录聚在一起买到什么） 证明的是「**在交错负载上**，按目录聚比按到达序放
   在遍历与回收两个量上都更好」，**不是**「按目录聚有一份与负载无关的正收益」。
   D25（目标负载优先级） 没有交错度这一维（`grep -n "交错"` 现查 0 命中，2026-09-09），
   ⚠️ 但这句话**不能读成「D25（目标负载优先级） 里没有交错负载」**——
   它的负载表有 `multistream 多流并发` 一行，权重「次」，那是一条实质交错的负载。

### 它答不了的

纯计数模型：没有真实 I/O、没有寻道时间、没有页缓存、没有崩溃点重放。
「连续段数」是**代理指标不是挂钟**——它假设一次连续读比两次便宜，便宜多少这里不答。
不建模目录树的形状（只有一层）、不建模文件大小分布（每个对象恒一个单元）。
确定性模型，**跑 N 轮说明的是没有隐藏状态，不是统计上稳定**。
