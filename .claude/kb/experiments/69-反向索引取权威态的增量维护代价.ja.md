### 一字一句読まれた定義 (印象に基づかないモデリング)

D21 (権威状態と派生状態の境界)「自己完結性が逆マッピングの半分を O(1) にする」の一字一句：

> ユニット自身が「自分が誰に属するか」を保持 ⇒ 「この物理位置にどのオブジェクトが存在するか」はその単一ユニットを読むだけで判明し、逆インデックスツリーは不要。
> ⚠️ **しかし半分のみである。** 共有 (スナップショット / reflink / 重複排除) の下では、1つのユニットが**複数の**参照者を持つことがあり、
> 固定長ユニットヘッダには列挙しきれない。⇒ **逆インデックスは依然として必要であるが、その責務は狭まる**：
> 「すべての逆引きクエリに応答する」から「共有されている部分に応答する」へと狭まる。

⇒ **被試験対象は「共有されている部分」のみを記録し**、逆マッピング全体ではない。
同節により、D21 (権威状態と派生状態の境界) 確定項目 1 には：派生の場合 ⇒ インデックス再構築完了まで balance / GC は実行不能；権威の場合 ⇒ コミットに伴い増分保守を行う、とも明記されている。

### 計測対象

2つの腕、同一の負荷：

| 腕 | 内容 |
|---|---|
| **甲 権威状態** | 逆インデックスエントリをトランザクションコミットに伴い**増分保守**。コストはコミットパスに発生 |
| **乙 派生状態** | 保守しない；必要時に**ユニット自己記述ヘッダの全ディスク走査により再構築**。コストは balance / GC 前のウィンドウに発生 |

3つの計測量：

1. **甲のコミットコスト**：各トランザクションが追加で書き込むエントリ数。**本トランザクションで新規追加された共有参照数に比例しなければならず**、
   ディスク容量や総オブジェクト数に依存してはならない——さもなければ全走査に退行し、それはまさに
   `.claude/rules/fs-design.md` 第 1 格で固く禁じられている事態である (「遅いのではなく、問われた瞬間に答えが存在しない」)。
2. **乙の再構築コスト**：全ディスク走査で読み出す必要のあるユニット数。**ディスク上の総ユニット数に比例しなければならない。**
3. **乙の可用性ウィンドウ**：再構築中に balance / GC が停止する期間 (ユニット数換算)。

### 判定基準 (実行前ハードコード)

| # | 判定基準 |
|---|---|
| 1 | **共有なし負荷において、両腕のエントリ数は正確に 0 でなければならない。** D21 (権威状態と派生状態の境界) 確定項目 1 で論証済み：スナップショットなし、reflink なし、重複排除なし ⇒ 共有ユニットは皆無 ⇒ エントリ数は 0。非ゼロなら「共有部分のみ記録」に沿ってモデリングされていない |
| 2 | **陽性対照**：共有追加後 (スナップショット + reflink)、甲のエントリ数は **> 0** であり、**独立計算された共有参照数と等しくなければならない** (閉形式算術、**被試験コードからの読み戻しは禁止**) |
| 3 | **甲のトランザクションあたりコストはディスク容量に依存しない**：2段階のディスク容量 (総ユニット数比 10 倍) を走査し、甲のトランザクションあたり追加書き込みは**セル単位で一致**しなければならない |
| 4 | **乙の再構築コストは総ユニット数に線形**：同2段階において、乙が読み出すユニット数は当該段階の総ユニット数に**正確に一致**しなければならない |
| 5 | **絶対値アサーション** (両腕の同時誤りを防ぐ)：甲の総エントリ数と乙が再構築したエントリ数は、**双方が同一の閉形式で算出された共有参照数と等しくなければならず**、その閉形式は負荷パラメータから独立して導出される |
| 6 | **同一負荷下で両腕が再構築したマッピングはエントリ単位で一致しなければならない**——不一致なら少なくとも一方が誤っており、コストを論じる前に修正を要する |

### 何をもって失敗とするか (実行前ハードコード、実行後変更禁止)

| 条項 | トリガー時の判定 |
|---|---|
| 共有なし負荷でいずれかの腕のエントリ数 ≠ 0 | 「共有部分のみ記録」に沿って構築されておらず、**ラウンド全体無効** |
| 陽性対照下で甲のエントリ数に変化なし | 共有の計算が一切行われておらず、**ラウンド全体無効** |
| 両腕が**すべての**計測量において一致 | 当該次元に差異がなく、**ラウンド全体無効** |
| **甲のトランザクションあたりコストがディスク容量に伴い変化** | **忠実に記録。** 「権威状態は増分保守可能」という前提が本モデルで不成立であることを示し、ユーザー方針の再検討を要する |
| **甲のコストがトランザクション自体に対して無視可能 (< 1%)** | **忠実に記録。** 本項目に元来悩む必要がなく、直接権威状態を採用可能であることを示す |
| 両腕が再構築したマッピングがエントリ単位で不一致 | 実装を先に修正、**2026-08-31 の実行は無効**——正当性が確立される前のコスト値に意味はない |

なし。純粋なカウントモデルであり、ファイルシステムや QEMU に依存しない。

### 本実験で答えられない半面

1. **実負荷における共有参照の密度にローカルな根拠がない** (スナップショット頻度、reflink 利用率、重複排除ヒット率が未測定)
   ⇒ 結論は「共有参照あたりどれだけのコストか」のみ記述し、**「総コストがいくらか」とは記述しない**。
   E43 (拡張ポイントバイト上限) における需要側の欠落、E40 (暗号文チェックサムビット幅) における破損率の欠落と同型である。
2. **逆インデックスの具体的構造が未定** (D1 (データ可動性 / 逆インデックス) は必要性のみ言及、形態は未定) ——
   汎用的な「物理位置 → 参照者集合」btree としてモデリング、**構造を変更すれば数値は変わる**。
3. **実時間を測定しない**：カウントモデルであり、エントリ数と読み出しユニット数を計測、所要時間ではない。
4. ⚠️ **乙側は「再構築の読み出し量」のみをモデル化し、「再構築中の balance / GC 停止」の影響をモデル化していない**——
   立案時に計測量 3 としたが、実際には未実施。D21 (権威状態と派生状態の境界) 確定項目 1 にその影響が明記されているが、
   **依然としてカバレッジゼロである。**
