### How Harm Is Calculated (Each Item Must Have Mechanistic Derivation, No Direct Assignments)

- **`blocks_freed_while_referenced`**:
  D5 (snapshot / space accounting mechanism) verbatim "destroying snapshot merges its deadlist **into the next newer side**,
  filtering reclaimable entries by `birth > prev(S).txg`". A snapshot invisible to writer causes "next newer side" to be identified as
  the newer one ⇒ filtering `prev` is larger ⇒ **more blocks pass "freed directly"** ⇒ blocks born within invisible window are erroneously released.
  With `BLOCKS_BORN_PER_GENERATION` blocks born per generation and invisible window of `W_GENS` generations ⇒ erroneously freed blocks = `BLOCKS_BORN_PER_GENERATION × W_GENS`, closed form.
- **`rdonly_violations`**: When unknown bit takes `RDONLY` semantics, writer writes to read-only tree once every published generation
  ⇒ = flagged read-only tree count × generations actually published.
- **`dead_revived`**: When unknown bit takes `DEAD` semantics, writer treats half-deleted tree as alive ⇒ = flagged DEAD tree count (one-time).
- **`writable_gens`**: Generations writer actually published (`ReadOnly` is 0, others `G`).
- **`rows_lost` / `rows_written_per_gen`**: Same measurement basis as E112 (legacy writer encountering unknown trees).

### Selection Method (Locked Before Run, Lexicographical Order, No Changes After Run)

**"Minimum silence" was used by E112 (legacy writer encountering unknown trees) and invalidated by adversarial round** — it does not price severity,
nor does it price "unmountable". E113 (unknown trees: saturated (padding) arm set) adopts **lexicographical order**, reasoned by project's value hierarchy "correctness > availability > economy":

1. `blocks_freed_while_referenced == 0` (data loss, one-vote veto)
2. `rdonly_violations + dead_revived == 0` (violating semantics)
3. `rows_lost == 0`
4. `silent` minimum
5. `writable_gens` maximum
6. `rows_written_per_gen` minimum

**This order was written down before run, unchanged after run.** If no cell passes gate 1,
conclusion is "all five flags policies lose data", recorded truthfully.

### Conclusion (Cross-Checked Against Acceptance Clause Locked Before Run)

Written before run: "Adversarial round inclines toward `PerBit`; if lexicographical winner is not it, change conclusion."
**Winner is not `PerBit`, but `RejectEntry`** ⇒ conclusion altered per clause.

`PerBit` lost because it is a **conditional policy**: when bit unregistered it equals `ReadOnly`, unable to publish a single generation;
when all bits registered it equals `Skip`, which loses 192 blocks at Gate 1.
**It possesses no third behavior of its own** — two tiers each degrade to an existing arm.

⇒ **Flags unknown bits take `RejectEntry` (entry EIO)**. This is simultaneously the tier **already settled**
by this project for two other flags fields (D18 (information carried in a block) "reject without exception", D8 (core index structure) "entry EIO",
landing as I-9.7 (records three segments constantly zero)) ⇒ three flags fields merge into single policy, requiring no explanation of why they differ.

⚠️ **Why `RejectEntry` avoids data loss relies on ④ entry self-contained length**: entry EIOs but **position remains**
⇒ writer knows "there is a tree there I cannot read" ⇒ refrains from deadlist merge across it.
Without length field, next entry cannot be located, breaking this derivation.

⚠️ **`Exempt` in accounting dimension did not win cleanly**: it won only at Gate 6 (17 rows written per gen vs `Carry`'s 19),
while **its true cost is not on this balance** — exempting a tree from K-generation point deletion modifies D5 (snapshot / space accounting mechanism) settled item 2,
an established settled clause. ⇒ **Accounting dimension must be settled separately**: `Carry` touches no settled clauses, writing 2 extra rows per generation;
`Exempt` saves those 2 rows at cost of altering D5 (snapshot / space accounting mechanism) settled item 2. Placement recorded in C693 (arguments to re-derive after K generations withdrawal) (merged from former C160 (true cost of accounting arm not on balance) on 2026-10-11).

⚠️ **`Skip` losing 192 blocks is not "more likely", but "mechanistically will"**: D5 (snapshot / space accounting mechanism)
"merge into next newer side + `birth > prev(S).txg` filtering" necessarily mistakes neighbors under invisible snapshot;
value `BLOCKS_BORN_PER_GENERATION × invisible_window_generations` is closed form, zeroing when `invisible_window_generations = 0` (negative control).
