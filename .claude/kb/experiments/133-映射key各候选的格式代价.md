### 它答不了的

- **不判输赢**，也不给「谁更好」的排序。
- 只算格式宽度、扇出与层数门槛；**不算 CPU、缓存、I/O**（那是 E128（指针带出生 (树, txg) 之后的点查代价） 那一类）。
- 映射树按码 1 的 key 算；码 2 / 码 3 条目按 ⌈N / 119⌉ 估。**逻辑身份族给不出码 2 的定宽 key**（它的码 2 key 带 key 区间下界，宽随树变），产物里报 `n/a`。
- 码 2 头的增量**不回灌进扇出**：扇出式里的节点头 64 与 D18（块里携带什么信息） 的码 2 三档头不是同一个口径，头宽只照报。
- D27（小数据打包容器） 的槽只报增量：槽带哪些字段 D27（小数据打包容器） 已定项 3 自陈「仍未写死」。⚠️ **增量的基线是 E114（小数据打包容器的总账） `pack` 臂的假设**（槽已有五元组 33 + 写序 10），D27（小数据打包容器） 正文里槽只写了五元组；按那个基线的数与两条新臂在 E134（映射 key 格式代价·槽基线与两条新臂）。
- 记账树叶条目取 D5（快照 / 空间记账机制） 已定项 5 的 30；按 D8（核心索引结构） 已定项 7 的 seq 住 value 是 34，两个口径各臂同值，只动记账树门槛的绝对值。
- 根记录两条指针都按「指向码 2 / 3」那一种算；实例表单元那一条今天由根记录直接持有物理指针，要不要带 key 取决于 C248（树表单元的自举豁免没写过） 那一类豁免。

### 变异

19 条全部被抓。起初的三条漏网按 `.claude/rules/mutation-sampling.md` 三分：
节点头 64 与 76 互换（两条）是**取样点不敏感**——已登记的 196 / 164 / 175 / 201 / 267 / 236 在两个口径下恰好同值，补了会分叉的取样点（`slotgen12` 的 inode 内部条目 111 字节、`k3` 的映射叶条目 48 字节）；
映射内部扇出错用叶条目宽是**真盲区**，补了逐臂钉绝对值的断言。拆出两种指针之后另加两条（extent 内部条目错用指向码 1 的指针、逻辑身份最强形态把指向节点的指针也加宽），都被抓。
