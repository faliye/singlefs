## E59 (バッファメッセージはユニットのみから再計算可能か) —— 実行済み (2026-08-31)

[中文](59-缓冲消息能不能只从单元重算.md) · [English](59-缓冲消息能不能只从单元重算.en.md) · **日本語**

D11 (インデックスノード内のメッセージバッファ要否) 確定項目 4 (確定前の原問題) に回答する。文面は逐語的に以下の通りである：

> バッファ内の当該メッセージはユニットのみから再計算可能か。
> 可能 ⇒ バッファは純粋な派生態にとどまる；不可能 ⇒ 権威態へと昇格し、
> D21 (権威態と派生態の分界) の「権威態 = ユニット + 会計 + ルート」を拡張しなければならない。

**これは D11 (インデックスノード内のメッセージバッファ要否) 確定項目 1 (残す) の後に残された唯一の死活的前置条件である。**

### 判定基準 (実行前固定)

甲アーム (ユニットのみから) の4クラスのメッセージの不一致数：すべて 0 ⇒ **再計算可能**；一部クラス > 0 ⇒ **クラス別に分解**；
全クラス > 0 ⇒ **再計算不可能**；陳腐化レプリカ不可視時に全 0、可視時に > 0 ⇒ 結論は**その前提に条件付けられる**とし、前提を個別列挙する。

### 失敗条件 (実行前固定、実行後変更禁止)

### 結果 (2026-08-31、5 ラウンドでバイト単位一致)：判定基準「クラス別に分解」

7アーム、3組の負荷 (256 / 4096 / 16384 オブジェクト、各々 25% の上書き、12.5% の削除を含む)。
「16384 オブジェクト、4096 上書き、2048 削除、16 ツリー」の組：

| アーム | 判別不能レプリカ | マッピング誤り | 復活した削除済みキー | 逆インデックス不足 | 会計誤りのツリー | 不一致合計 |
|---|---|---|---|---|---|---|
| **甲 ユニットのみから** (確定項目 4 の文面上の問題) | **4096** | 0 | **2048** | 0 | **16** | **2064** |
| **庚 ユニットのみから + アロケータによる低位アドレス再利用** | **4096** | **4096** | **2048** | **4096** | **16** | **10256** |
| 乙 ユニット + 会計 | 0 | 0 | 0 | 0 | 0 | **0** |
| 丙 ユニット + 系譜書き換えシーケンス番号 | 0 | 0 | **2048** | 0 | **16** | **2064** |
| 丁 シーケンス番号 + 明示的墓石ユニット (完全対照) | 0 | 0 | 0 | 0 | 0 | **0** |
| 戊 陳腐化レプリカ読み取り不可 | 0 | 0 | 0 | 0 | 0 | **0** |
| 己 ヘッダ全消去 (陰性対照) | 0 | 不足 14336 | 0 | **14336** | **16** | 28688 |

⇒ **クラス別に分解され、かつ4クラスは並列関係にない**：

| メッセージクラス | ユニットのみから再計算可能か | どこで阻害されるか |
|---|---|---|
| **マッピングクラス** (論理 ID → 配置先) | **条件付き成立** | 同一キーに複数の可読レプリカが存在する場合、ヘッダ内のいかなるフィールドもどれが現行値かを判別できない。判別不能数は**上書き回数にちょうど等しい** |
| **逆インデックスクラス** | マッピングクラスと同様 | マッピングクラスの対極であり、項目ごとに運命を共にする |
| **墓石クラス** (削除) | **不成立、かつ条件なし** | 削除はディスク上に**ユニットを一切残さない** ⇒ スキャンは削除済みキーを必然的に復活させ、復活数は**削除回数にちょうど等しい** |
| **会計クラス** (各ツリーの生存ユニット数) | **墓石クラスに連動して誤る** | 「どのユニットが生存しているか」から導出されるため、前段が誤れば必ず誤り、実測ですべてのツリーが過大計上された |

### 3つの決定的な絶対値 (アーム間相対比較ではない)

1. **現行値を判別できないキー数 = 上書き回数** (64 / 1024 / 4096、セル単位で一致)。
2. **復活したキー数 = 削除回数** (32 / 512 / 2048)、**かつ丙アーム (シーケンス番号あり) でも1件も減らない**——
   系譜書き換えシーケンス番号は上書きの枠を解決できるが、削除の枠は解決できない。
3. ヘッダ全消去時の不足件数 = 生存キー総数 (224 / 3584 / 14336)。

### 甲アームの「マッピング誤り = 0」は偶然であり、庚アームがそれを打破した

甲アームのマッピングクラスは1件の誤りもなかった——**しかし再構築側は自身が正しいことを認識できていない** (判別不能なレプリカは依然として 4096 件存在する)。
これが正しかったのは、モデル内の割り当てが単調増加方向に進み、「物理アドレス順にスキャンしてアドレス最大値を取る」ことが偶然「最新の版を取る」ことと等価であったからに過ぎない。

**いかなる確定条項もこの保証を与えていない**：D3 (領域割り当て) は割り当てが単調増加することを規定しておらず、
COW アロケータが解放された空間を再利用するのは常態である。庚アームは1点のみを変更した——上書きがより低位のアドレスに配置される——
同一の再構築コードは**項目ごとにことごとく誤り**、誤り件数は上書き回数と完全に一致した。

⚠️ ⇒ **「甲アームのマッピングクラスが 0 であること」を「マッピングクラスはユニットのみから再計算可能である」根拠として引用してはならない。**
引用可能な文言は：**誰も定めていないアロケータの性質に依存している**、ということである。

### 乙アーム：閉合させているのはユニットではなく、会計である

ユニット + 会計のアームでは4クラスすべてが 0 となった、**なぜなら「この配置先がまだ生存しているか」こそが会計が記録している内容だからである**。
D21 (権威態と派生態の分界) は権威態 = ユニット + **会計** + ルート と定めている ⇒ 会計はインデックスと共に喪失することはない。

⚠️ **ただしこのアームの前提はリポジトリ内で確定していない**：会計が**配置先ごと**に「生存しているか否か」を回答できると仮定している。
D3 (領域割り当て) も D5 (スナップショット・領域台帳機構) もこの粒度を定めていない——
D5 (スナップショット・領域台帳機構) が記録するのは**集合に関する**使用量であり、「ある配置先が現行バージョンに属しているか否か」ではない。
⇒ 乙アームが提示しているのは**答えの形状**であって答えではない：これを利用するには、まず会計の粒度を確定させる必要がある。

### D11 (インデックスノード内のメッセージバッファ要否) 確定項目 1 に対して何を示したか

確定項目 1 (残す) は「既知の2つの未解決事項の上に下された裁決」と自ら述べており、そのうちの1つこそがコスト 2
(再構築可能性が「検出可能な到達不能」から「検出不能な陳腐化」へと退化すること、**推論であり定量化されていない**) である。

E59 (バッファメッセージはユニットのみから再計算可能か) はコスト 2 の**フェイルセーフ経路**に数値を付与したものであり、コスト 2 自体に数値を付与したわけではない：
測定したのは「バッファ喪失後にディスクから再計算可能か」であり、コスト 2 が問うているのは「再計算を誤った際に警告が発せられるか」である。
**両者は同一チェーンの前後の環であり、E59 (バッファメッセージはユニットのみから再計算可能か) は前段の環に触れたに過ぎない。**
後段の環は依然として未済の検査であり、帰属先は [checks-owed.md](../checks-owed.md) C52 (陳腐化ブロックの正当誤認) である。

### これで答えられない半分

1. **計数モデルは実装ではない**。ファイル操作はゼロであり、E54 (記帳の「世代」は何世代保持すべきか)、E57 (平文側フィールドセットの権威着地点) と同一の制約を持つ。
2. **Bε ツリーを再構築しない**：幾何は「ツリー全体のバッファが何件保持できるか」の算出 (常駐ウィンドウの画定) にのみ使用され、
   いかなるクラスのメッセージが再計算可能かどうかの判定には関与しない。メッセージが再計算可能か否かは、それが現時点でどのノードに存在するかとは無関係である。
3. **並行処理なし、クラッシュポイントなし**：再構築は静止したディスク上で行われる。真の再構築はクラッシュ後に実行されなければならず、
   その際にはさらに「リカバリ再生をどこまで進めるか」という問題が加わるが、E59 (バッファメッセージはユニットのみから再計算可能か) はこれにいかなる数値も提供していない。
4. **削除のモデル化は1形態のみ** (ディスク上に痕跡を残さない)。もし将来 D3 (領域割り当て) が「解放には意図ログの記録が必要」と定めた場合、
   その記録自体が墓石となるため、E59 (バッファメッセージはユニットのみから再計算可能か) の第3枠は再実行が必要となる。
5. **暗号化に触れていない**：A6 (AAD 期待値が平文側に由来しない) と再構築パスの衝突は D18 (ブロックに含める情報) 確定項目 5 が管轄し、
   E59 (バッファメッセージはユニットのみから再計算可能か) はヘッダが読み取れるものと仮定している。
6. **4クラスのメッセージは E59 (バッファメッセージはユニットのみから再計算可能か) が選定したものであり**、特定の確定条項が提示したリストではない。将来バッファが別クラスを収容する場合は、個別に再判定が必要である。

### ミューテーションテスト：16 件の破壊、16 件補足、盲点なし

「甲アームが会計を覗き見る」「庚アームが単調割り当てへ後退する」「シーケンス番号で最大値ではなく最小値を取る」「墓石を生存と誤読する」
「会計クラスを常に正解とする」「バッファ件数を1段階変更する」を含む。

⚠️ **第1ラウンドには真の盲点が1箇所存在した**：逆インデックスの列には `reverse_index_bad == map_wrong` という相互比較アサーションが1つあるのみであり、
しかもそれが甲アーム上で実行されていた——**双方の数値ともに 0 であり**、`0 == 0` は何も証明していなかった。欠落分岐のカウントを `+= 0` に変更しても、
単体テストは1つも赤にならなかった。第1ラウンド後に3つのアームに各々絶対値を固定するよう改定した (0 / 上書き回数 / 生存キー総数)。
**これはまさに test-discipline.md の「複数アームの相互比較のみでは、全アームが一斉に誤ることを検出できない」形態であり**、
人手による確認ではなくミューテーションテストによって補足された。

⚠️ **「盲点」から「デッドコード」と判明した別の項目**：比較器内の「同一の配置先が別のキーを指す」分岐は
いかなるミューテーションでも赤にできなかった——調査の結果、それは**到達不能**であった：配置先の所有者はその配置先自身のヘッダによって決定されるため、
両側が同一の配置先に対して異なるキーを出力することはあり得ない。解明後にアサーションとして記述し、モデルに自己矛盾が生じた場合は即座に爆発するようにした。
