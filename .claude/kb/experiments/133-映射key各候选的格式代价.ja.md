## E133 マッピングキー各候補のフォーマットコスト —— 実行済み (2026-09-11)

[中文](133-映射key各候选的格式代价.md) · [English](133-映射key各候选的格式代价.en.md) · **日本語**

**問われていること**：D19 (ブロックポインタ構造と幅予算) 確定項目 6 の 2 ラウンドにわたる三方論証で出現したすべてのマッピングキーについて、フォーマットに落とし込んだ際にそれぞれ何バイトを支払うか ——
2 種類のポインタ (コード 1 データユニットを指すもの、コード 2 / コード 3 を指すもの)、3 種類のユニットヘッダ、ルートレコード、ツリーテーブルエントリ、マッピングエントリ ——
およびそれらが extent ツリー、inode ツリー、会計ツリー、マッピングツリーのファンアウトと層数閾値をどのように変化させるか。
**数値を報告するのみで勝敗を判定しない**：`.claude/rules/fs-design.md` は逐字で「『誰がより節約しているか』はいかなる判定基準も構成しない」と明記している。その判定基準はすべて装置の突き合わせである。

**なぜ必要とされたか**：D19 (ブロックポインタ構造と幅予算) 確定項目 6 はユーザーの裁定に委ねる必要があり、提出前に各経路のコスト数値が必要であった；
E133 (マッピングキー各候補のフォーマットコスト) の前には、リポジトリ内にはポインタ +16 のみ計算した E128 (出生 (ツリー, txg) 付与ポインタのポイント検索コスト) と、key 33 / 40 の 2 階層のみ走査した E109 (位置権威3アームの実行時コスト) しか存在しなかった。

**実行前に事前固定**：`e133-preregistration.md` (装置の前に記述)。その「追記」節には正式実行前の 2 回の変更が記録されている：
① ミューテーションの感度サンプリング点を補充するため、**装置の作成者は正式実行前に独立した算術により各アームの数値をすでに確認していた**；
② 第 2 ラウンド三方論証の後に 4 アームを追加し、ポインタ増分を「コード 1 を指す / コード 2・3 を指す」の 2 量に分割した。判定基準は 1 文字も変更されていない。

```bash

# 装置を直接実行：
```

### これは計数モデルであり実装ではない

I/O なし、ランダムソースなし ⇒ N 回実行すれば必然的にバイト単位で一致する；根拠の強度は **16 件の単体テスト + 19 件のミューテーションが全数捕捉されたこと** に由来する。
単体テストでは各アームの幅、7 つのファンアウト、マッピングツリー層数をすべて絶対値として固定しており、期待値は独立した Python 算術から得られたものである (登録された元の量のみを使用し、装置の計算式は読み取らない)。

### 答えられないこと

- **勝敗を判定せず**、「誰がより優れているか」の順位付けも行わない。
- フォーマット幅、ファンアウト、層数閾値のみを計算；**CPU、キャッシュ、I/O は計算しない** (それらは E128 (出生 (ツリー, txg) 付与ポインタのポイント検索コスト) の種別に属する)。
- マッピングツリーはコード 1 の key で計算；コード 2 / コード 3 エントリは ⌈N / 119⌉ で見積もり。**論理識別子族はコード 2 の固定幅 key を提供できない** (そのコード 2 key は key 区間下限を含み、幅がツリー毎に変化する)、成果物内では `n/a` と報告。
- コード 2 ヘッダの増分は**ファンアウトに再投入されない**：ファンアウト計算式内のノードヘッダ 64 と D18 (ブロックに含める情報) のコード 2 の 3 階層ヘッダは同一の計測条件ではなく、ヘッダ幅はそのまま報告するのみ。
- D27 (小データパッキングコンテナ) のスロットは増分のみ報告：スロットがどのフィールドを持つかは D27 (小データパッキングコンテナ) 確定項目 3 が自白するように「依然として未確定」である。⚠️ **増分の基準は E114 (小データパッキングコンテナの総勘定元帳) `pack` アームの仮定** (スロットにすでに 5 つ組 33 + 書き込み順序 10 が存在) であり、D27 (小データパッキングコンテナ) 本文のスロットには 5 つ組しか書かれていない；その基準による数値と 2 つの新アームは E134 (マッピングキーフォーマットコスト：スロット基準と2新アーム) にある。
- 会計ツリーリーフエントリは D5 (スナップショット / 領域会計メカニズム) 確定項目 5 の 30 を採用；D8 (コアインデックス構造) 確定項目 7 の seq が value に常駐する場合は 34 となるが、両計測条件とも全アームで同値であり、会計ツリー閾値の絶対値のみを動かす。
- ルートレコードの 2 本のポインタはいずれも「コード 2 / 3 を指す」種類として計算；インスタンステーブルユニットの 1 本はルートレコードが直接物理ポインタを保持しており、key を持つ必要があるかどうかは C248 (ツリーテーブルユニットのブートストラップ免責が記述されていない) の種別の免責事項に依存する。

### ミューテーション

19 件全数捕捉。当初の 3 件の捕捉漏れは `.claude/rules/mutation-sampling.md` の三分法に従って分類：
ノードヘッダ 64 と 76 の相互入れ替え (2 件) は**サンプリング点非感度**であった —— 登録済みの 196 / 164 / 175 / 201 / 267 / 236 が 2 つの計測条件の下で偶然同値であったため、分岐するサンプリング点を補充 (`slotgen12` の inode 内部エントリ 111 バイト、`k3` のマッピングリーフエントリ 48 バイト)；
マッピング内部ファンアウトで誤ってリーフエントリ幅を用いた件は**真の盲点**であり、アーム毎に絶対値を固定するアサートを補充した。2 種類のポインタを分割した後、さらに 2 件追加 (extent 内部エントリで誤ってコード 1 を指すポインタを使用、論理識別子最強形態でノードポインタも拡幅)、いずれも捕捉された。
