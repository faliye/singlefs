## E25 リングと連鎖型で各々必要な予約プールのサイズ —— 実行済み (2026-08-29)

[中文](25-环与链各要多大保留池.md) · [English](25-环与链各要多大保留池.en.md) · **日本語**

**[checks-owed.md](../checks-owed.md) C30 (連鎖型予約プール定量化の未検証) を清算。**
[decisions.md](../decisions.md) D23 (journal の役割とフォーマット) で「定長リングを採用」と裁定した際、ある定量計算が用いられた——
連鎖型において予約プールは `ckpt_cost` から `ckpt_cost + 1 チェックポイントウィンドウ内の journal ブロック` へと増大する必要がある。
**この式は計算によって導出されたものであり、未検証であった。** E25 (リングと連鎖型で各々必要な予約プールのサイズ) はこれ operational なモデル化を行い、クラス別に走査した。

### 結論：デッドロックは予測通りのクラスで綺麗にゼロになり、両アームが個別に一致

容量 10 万ブロック、2 万回操作、100 操作ごとに 1 回のチェックポイント、`ckpt_cost = 64`、1 操作あたり 1 ブロック
⇒ 1 ウィンドウの journal ブロック = 100。初期占有率 99%。

| reserve | リングのチェックポイントデッドロック | 連鎖型のチェックポイントデッドロック |
|---|---|---|
| 0 / 32 | 95 | 120 |
| **64** | **0** | 120 |
| 100 / 128 | 0 | 120 |
| **164** | 0 | **0** |
| 256 / 512 | 0 | 0 |

⇒ **リングは `reserve = 64` でゼロになる** (= `ckpt_cost`)；
**連鎖型は `reserve = 164` でゼロになる** (= `ckpt_cost + ウィンドウ journal ブロック = 64 + 100`)。
D23 (journal の役割とフォーマット) で算出された計算式とビット単位で一致した。

**陰性対照**：初期占有率 95%（空き容量 5000 ブロック）の場合、**両アームとも一切デッドロックせず、いかなる reserve でもデッドロックしない**
⇒ 効果は真に容量逼迫に起因するものであり、モデリング上のアーティファクトではない。

### E19 (defer ウィンドウ下での擬似 ENOSPC) の結論に対する絞り込み

E19 (defer ウィンドウ下での擬似 ENOSPC) では「予約プールは通常割り当てにとって純粋な税である」と記述された。
**その命題には暗黙の前提が存在する：予約プールが既にデッドロックを回避できるほど十分大きいこと。その前提を外れると符号は反転する。**

| 区間 | reserve | 通常割り当て拒否回数 |
|---|---|---|
| デッドロック区間 | 0 | **9340** |
| 非デッドロック区間 | 64 | 756 |
| 非デッドロック区間 | 512 | 1204 |

デッドロック発生後は領域が一切回収されず、拒否回数はデッドロックに支配される ⇒ **過小な予約プールの方がかえって拒否回数が多くなる**。
これは E25 (リングと連鎖型で各々必要な予約プールのサイズ) のテスト初版が誤っていた際にその場で露見したものである（当初のアサーションは「予約プールが大きいほど拒否回数が増える」とし、0 と 512 を比較したため結果が逆転した）。2 つの区間にそれぞれ固定されたテストが存在する。

### 計測条件と既知の限界

- 純粋なカウントモデル。デバイスなし、ファイルシステムなし。**ウィンドウごとに正味のリークが不可欠**（モデルでは 8 ブロックを採用）、
  そうでなければチェックポイントが消費領域をすべて返却して空き領域が常に原点に戻り、実験で何も測定できなくなる——
  初版がまさにその状態であり、6 単体テスト中 3 つが赤であった。リーク自体は現実的である：
  D16 (パブリッシュセマンティクス) で確定済みの「チェックポイント内の解放はパブリッシュ前には割り当て可能集合に戻してはならない」および D22 (ユニット原子性の合成方法) のルートリング K 世代保持による拘束。
- **擬似 ENOSPC はモデル化しておらず**、チェックポイントのデッドロックと通常割り当ての拒否のみをモデル化した。
  両者の切り分けは E19 (defer ウィンドウ下での擬似 ENOSPC) を参照。
- コード `scripts/experiments/e25_journal_reserve.rs` (`cargo run --release --bin e25_journal_reserve`)、
  生の出力 `e25-journal-reserve-2026-08-29.out`。3 ラウンドでバイト単位一致。

**エンジニアリング品質**：7 個の単体テスト、**7 つのミューテーションをすべて捕捉**、3 ラウンドでバイト単位一致。
