## E127 分割統合下でのグループID保存要否 —— 実施済 (2026-09-13、決定論的モデル、17 単体テスト / 14 ミューテーション全捕捉)

[中文](127-分裂合并之下组身份要不要存.md) · [English](127-whether-to-store-group-identity-under-splits-and-merges.en.md) · **日本語**

**問題**：E95 (老化したノードレイアウトアーム) の実施後、D26 (バックグラウンド整理と配置回収) 確定項目 4 は**モデルの欠落**で停滞しており、「誰もその実験を実施していない」ことによる停滞ではなくなった。

E95 (老化したノードレイアウトアーム) で比較を制したアーム（ノードグループ）は、そのモデルにおいて**ディスク上フィールドを一切消費しない** ——
グループ ID は `key / g` で算出された。同一の関数に別タグを付与してポリシーアームとして登録すると、
**48 行の `runs_median` は逐字不変のまま回答行の 6 マスがすべて反転した**（同ドキュメントの「本実験で答えられないこと」第 4 項およびメイン agent の再実行）。
根本原因は同一箇所に記載されていた：E95 (老化したノードレイアウトアーム) のモデルにおいて key からオブジェクトへは**静的一対一対応であり分割統合が存在せず**、
その結果「key 区間によるグループ化」と「ノード数によるグループ化」が完全に同一の数値を算出し、
**「ノード数によるグループ化」のみがノードヘッダ内にグループ ID を保存する必要があった**。

E127 (分割統合下でのグループID保存要否) はその欠落を補完するものである：分割統合をモデルに導入し、これら 2 つのグループ化が**異なる数値を算出し得る**ようにした。

**結論（実施完了、実施前確定の判定基準 6 に基づく）**：6 つの等予算マスにおいて、ノード数によるグループ化は runs を key 区間グループ化の 0.8 倍以下に抑えたマスが**1 つも存在しなかった** ⇒ **モデル層は「グループ ID をフォーマットに含める必要はない」を支持**、同アームはポリシー層に後退し、D26 (バックグラウンド整理と配置回収) 確定項目 4 のバイト判定は再判定を要する（このステップは推論であり、第 5 ラウンド三者論証 `research/prompts/d26-r5-main-verification.md`）。第 1 回実行（W ∈ {8, 32, 128}、G ∈ {2, 8, 32}）では 6 マスの比率が 0.930 / 0.889 / 0.957 / 1.651 / 1.856 / 1.031 で両アームが 3 マスずつ勝利；**第 2 回実行で両 knob ファミリーを同一のノード幅（W ∈ {8, 16, 32, 64, 128, 256}、G ∈ {1, 2, 4, 8, 16, 32}）に補完した後は key 区間グループ化が 6 マス全勝**（1.004 / 1.043 / 1.072 / 1.116 / 1.108 / 1.134）—— 第 1 回実行で「ノード数グループ化がわずかに優位」であった 3 マスは key 区間グリッドが W = 16 を欠落させていたこと、「65%〜86% 優位」であった 2 マスはノード数グリッドが G = 4 を欠落させていたことによるものであり、逆推レッグのプローブが事前に算出し第 2 回実行でリポジトリに確定。失敗条件の行に従い「key 区間グループ化の全勝 ⇒ 正当な結果であり、グループ ID の保存は不要であるのみならず有害であると個別に特記」。

### 決定論的モデルであり、測定ではない

固定シード、I/O なし、ランダムソース以外の変動要因なし ⇒ N 回実行で 1 バイト違わず同一。根拠の強度は **17 個の単体テストで固定された絶対値 + 14 件のミューテーション全捕捉**に由来する：分割が中点で発生しない、分割されたノードが一律に分割元のグループに従う、統合閾値 < を ≤ に変更、退場ノードの隣接ペアを不計算、装置間照合表を 1 マス改変、ポリシーアームの整理バッチがダーティノードをスキップしない、2 つのグループ化アームがグループ全体を再配置しない、第 rank 番目の key が 1 乖離、分割時に未配置ノードの計上漏れ、ポリシーアームが予算を 1 つ余分に消費、ダーティ key がすべて位置 0 にマップ、挿入を行わない、判定基準 6 の閾値を 1.0 に変更 —— すべての項目でテストが赤判定となる。

### モデル

E93 (老化下の配置とフラグメンテーション度)/ E95 (老化したノードレイアウトアーム) のスロット位置、defer、断片化および等予算の計測条件を踏襲、
**変更点は 1 箇所のみ**：オブジェクトは固定長静的配列ではなく、分割統合を行う**ノード**に格納される。

| 要素 | 定義 |
|---|---|
| ノード | 各ノードは 1 物理スロットを占有；容量 `C` 個の key、`C` 超過で中点分割、`C/4` 未満で隣接ノードと統合 |
| 負荷 | E93 (老化下の配置とフラグメンテーション度) の 2 組の負荷（uniform / runs8）に加え、**挿入および削除を必須追加** —— 挿入削除がなければ分割統合が発生せず、実験対象が存在しなくなる |
| 断片化 | `F = runs / ノード数`、runs は**ノードの key 順**で物理連続ランを巡回（E93 (老化下の配置とフラグメンテーション度) と同型、単位をオブジェクトからノードへ変更） |

**3 本のアーム、等予算**（追加書き込み数 = チェックポイントごと `D × (X − 1)`、X は 1.5 / 3 / 5）：

| アーム | グループ決定手法 | ディスク上フィールド要否 |
|---|---|---|
| **key 区間グループ化** | グループ = 固定 key 区間 `[i·W, (i+1)·W)`、グループ内ノード数は分割統合に伴い変動 | **不要** —— アロケータが key から算出可能 |
| **ノード数グループ化** | グループ = ノード順で隣接する `G` 個のノード；ノード分割時に新ノードは分割元のグループ番号を継承、グループ満杯で新設 | **要** —— ノード順は key の関数ではなく、グループ番号はノードヘッダ内に保持するほかない |
| **ポリシーアーム（対照）** | E93 (老化下の配置とフラグメンテーション度) の `bump_compact(B)`、B = 予算 | 不要 |

### 判定基準（2026-09-10 実施前確定、実施後変更不可）

1. **手計算アンカー**：8 個の key、ノード容量 2、グループ幅 2：key を 1 つ挿入して分割を 1 回トリガー、2 つのグループ化アームのグループ分割を**手計算で確定**し、かつ分割後に**互いに異なる**こと —— アンカーで両アームが一致した場合、本モデルは弁別力を持たずラウンド全体を破棄。
2. **保存則**：増分 runs == 監査 runs（各サンプリング点）；ノード内 key 総数 == 生存 key 数；空スロット + 占有スロット == 総スロット数；defer されたスロットは当ラウンドで再利用不能。
3. **陽性対照のアーム別通過**：強制配置下で完全分離レイアウトは `runs == ノード数`、連続レイアウトは `runs == 1` を報告。
4. **分割統合が実際に発生**：各アームが当ラウンドの分割回数と統合回数を報告、**双方が > 0** であること、さもなくばラウンド全体を破棄（`.claude/singlefs-ai-sop/rules/test-discipline.md`「陰性結果を『コードが実行されなかった』ことと区別可能にしなければならない」）。
5. **装置間照合ゲート**：挿入削除を無効化しノード容量を 1 とした際、3 アームは E95 (老化したノードレイアウトアーム) 成果物の対応マスの `runs_median` を逐字再現しなければならない；不一致は不合格。
6. **回答すべき 1 問**：**いずれかの**等予算マスにおいて、「ノード数グループ化」が runs を「key 区間グループ化」の **0.8 倍以下**に抑えられるか（閾値は実施前確定）。可能 ⇒ グループ ID はノードヘッダに保存**必須**、D26 (バックグラウンド整理と配置回収) 確定項目 4 のフォーマット部分は具体的形態と幅を確定；不可能 ⇒ **モデル層は「グループ ID をフォーマットに含める必要はない」を支持**、同アームはポリシー層へ後退、D26 (バックグラウンド整理と配置回収) 確定項目 4 のバイト判定は再判定。
7. E10 (老化：構造的抗老化 vs 事後デフラグ) を代替しない；所要時間軸とデグレード判定基準は同実験に帰属。

### 本実験で答えられないこと

1. カウントモデル：所要時間軸なし、メッセージバッファバッチ集計なし、実機なし。
2. 分割統合規則は 1 つの選択肢（中点分割、`C/4` 統合）であり、D8 (コアインデックス構造) 確定規則ではない ——
   D8 (コアインデックス構造) は分割点と統合閾値を定めておらず、本項目は成果物内でモデル仮定と明記**必須**。
3. グループ ID が実際のフォーマットで何バイト占有するか、D11 (インデックスノード内のメッセージバッファ要否) の 665 件バッファと競合するか否かは計算外 ——
   E101 (ノードヘッダ予約ビットのコストと表現力) は「ノードグループのグループ数にはいかなる確定条項も上限を与えておらず、モデルは `UPPER_UNKNOWN` を報告」と逐字判定済であり、
   E127 (分割統合下でのグループID保存要否) もこのマスを解決しない。
4. 「保存すべきか否か」に回答するものであり、「何バイト保存すべきか」には答えない。
5. モデル仮定（実行後に確定した手法であり条項ではない）：中点分割（左 ⌊n/2⌋）；統合対象は右隣（なければ左隣）、統合後 > C で再分割；主グリッド幾何 8192 ノード、容量 8、初期ノードあたり 4 key、key 空間 65536（初期 key は偶数）、チェックポイントごと挿入 16 削除 16；ノード数グループ化のグループは分割時のみ新設し並べ替えない。分割統合規則を変更した場合は再実行を要する。
6. runs の単位はノード：ノード内の key の多寡は断片化に算入しない。
7. 幾何サンプリング点に対する判決の感度（第 5 ラウンド逆推レッグのプローブ、未リポジトリ化、`research/prompts/d26-r5-main-verification.md` 第 3 節）：挿入多削除少（挿入 20 削除 12）のとき「グループをノード順連続ブロックとして維持しグループ自身が分割統合する」グループ ID 保存アームが 4 マス全勝、最良 0.876 —— それでも 0.8 には届かず；容量 32 の段階では両族の比率が 0.999〜1.007 でモデルに弁別力なし。主グリッド幾何（容量 8、挿入 16 削除 16、ノード数が 8192 から 7398 に縮小）はいかなる確定条項も与えておらず、判定基準 6 はこの単一の幾何サンプリング点でのみ測定、C317 (判定が単一の幾何サンプリング点のみで測定され未検証)に記録。
