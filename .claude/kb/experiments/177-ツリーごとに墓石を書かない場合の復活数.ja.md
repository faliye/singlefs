### 実施内容

- **書込経路**：mkfs の2ユニット（インスタンス表50176は2スロット、ツリーテーブル50178は1スロット）、mkfs プロセス内の txg 1・2 のゼロユニットウォームアップと txg 3 の新規プールでのファイル作成、書き込み可能マウントの行書込（txg 4）とウォームアップ（txg 5）、以降はセッション経由で4種類の変更（上書き、順次書込、空 inode 作成、unlink）。各パブリッシュは `crates/` と同順序で、今回交換される全配置先を解放し、bump 順に配置先を取得し、root を記録する。書き換えるユニットも `crates/` の規則に従う：inode 葉コンテナは233件、空になれば永続化せず、右側から左へ移動するものをすべて書換え。extent ツリーは上段の root 兼葉と下段（1葉144ユニット）。割り当てレコードツリーはスロット番号で位置指定（葉が812スロットをカバー、ファンアウト169、4 GiB ディスク2台の root レベル2）し、書換え集合は `crates/` と同じ固定点に到達。会計ツリーと中央マッピングツリーは `code_two_tree.rs` と同じ分割・縮小規則（会計葉477件、マッピング葉294件）。`deleted_inodes` は最大1 key、墓石ツリーはコンテナ1つ815件で追加のみ、削除なし。
- **3幾何**：G-環 は `crates/` 製品経路に従い、1マウント内でリングによる回収（リング長24、閾値 max(F_有効, リング内の最古の有効 root)）。回収スロットの再割当時は W6 に従い割当記録を更新または削除。G-宽 は G-環 と同じ配置先規則だが交換されたスロットを返さず、ユニット領域の終端を設けない。G-紧 は最小スロット番号を取得しクラスタ化セグメントをモデル化せず、配置先を取れない場合は「保持中」のうち今回のパブリッシュが交換したもの以外をすべて返す。
- **読取方式**：R-U は読める各ユニットの全 key を読む（増分計数し、最後の走査は別の全走査参照経路と突き合わせ）。R-S は（誕生ツリー、コンテナ番号、コンテナ誕生世代）と（誕生ツリー、オブジェクト、オブジェクト誕生世代、アンカー）でグループ化し、最新の読めるバージョンを選択。extent、割当記録、マッピングは採用したユニットから再計算し、会計は各行の最大世代、`deleted_inodes` は nlink = 0 の記録を採用。R-G は R-S に加え、R-S が再構築した inode ツリーにオブジェクトの記録があるデータユニットだけを採用。
- **方式**：N は墓石なし。B は unlink インテント時にオブジェクト全体の墓石を書き、（オブジェクト、誕生世代）が一致する inode 記録、データユニット、extent 記録、`deleted_inodes` エントリを抑制。P は key の死亡ごとに死亡記録（モデル専用領域でスロット消費なし）を書き、死亡記録が供給元ユニット以上に新しければ採用しない。
- **登録で指定されず装置が読みを選んだ点**（実行員修訂2の確認5、メイン agent の承認対象）：割り当てレコードツリーはスロット番号ごとに1 key と数える（2ディスクの同スロット）。d は「以前のいずれかの版に存在し、走査時点の版にはない」ものを数える（死亡後に再誕生したものは数えない）。R-S/R-G では割り当てレコードツリーとマッピングツリーの正解値は当該版のデータユニットとパック済みコンテナを使うため、両方式の割り当てレコードツリーの2つの計測条件はセルごとに同じ。インスタンス表ユニットは両側とも比較しない。書き込み可能マウントの番号取得は2。G-紧 のディスク容量は G-宽 の「当該版の活スロット + 今回交換されたスロット」のピークの1.25倍。最後の点について登録原文の字面の読み（活スロットのみを数える）も実行し、履歴・書込経路ごとに `name=tight_literal_reading` を1行出力：102回中50回は収まる（空 inode 作成・削除28回はすべて、混合ランダム6/10、大ファイル16/64）。判定には含めない。実行員修訂2の「推論：51履歴は冒頭数回のパブリッシュで収まらなくなる」はこの102行によって覆された。「答えられないこと」参照。
- **陽性対照**：各履歴の最後の走査で、3方式・3読取方式・死亡のある各ツリーに死亡済み key を1件ずつ植える（PC1。B は墓石が指す場合と指さない場合に分け、P はさらに k の死亡記録を削除して1回測定）。活 key を含むユニットを1つ消す（PC2、期待値は別途記述した手計算関数で与える）。
- 装置内で実時間は測っていない。8スレッドでビルドを含め全成果物を実行（各履歴2回、全陽性対照を含む）して240秒のフォアグラウンド制限内に完了。
