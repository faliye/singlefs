## E54 记账的「代」要保留几代 —— 已跑（2026-08-30，N=5 轮字节一致，8 单测 / 6 条变异全抓）：**甲与丙不是两个候选**，真正要定的只有 K

**用户定案「需要代」（2026-08-30）之后，D5（快照 / 空间记账机制） 已定项 2 只剩甲与丙**：

| 候选 | 「代」取什么 |
|---|---|
| 甲 | checkpoint 号（D16（发布语义） 的 txg），**不丢** |
| 丙 | 只保留最近 K 代，K 取根环深度 |

E54（记账的「代」要保留几代）量两件事：**两者的 key 数量怎么长**，以及**丙的丢弃要不要遍历**——
后者是生死判据：`.claude/rules/fs-design.md` 第一格明令
「运行时决策路径不许遍历，且代价不许随盘容量增长」。

### 要测什么

| # | 量 |
|---|---|
| 1 | key 数量随 checkpoint 数的增长（甲 vs 丙），扫统计量数 × K × checkpoint 数 |
| 2 | **丢弃一代要触及多少条 key**，以及**它依不依赖盘容量** |
| 3 | 每个 checkpoint 的记账写放大（甲只写，丙写 + 删）|
| 4 | **甲与丙是不是同一条路**：甲配上一条增量丢弃规则之后，与丙的 key 数逐格相同吗 |

### 判据（跑前写死）

| # | 判据 |
|---|---|
| 1 | **丙的 key 数与 checkpoint 数无关**（斜率 0）；**甲的斜率 = 统计量数** |
| 2 | **丙的丢弃代价与盘容量无关**——判据是它出不出现在代价式里，出现即判违反 `.claude/rules/fs-design.md` 第一格 |
| 3 | 甲 + 增量丢弃 与 丙 的 key 数**逐格相同** ⇒ 记「它们是同一条路的两种说法」；不同 ⇒ 记差在哪 |
| 4 | K 的下界由**根最多能回退几代**给：E53（丢一整块盘之后根环还挂不挂得上） 实测最坏回退 **1**，E50（根环槽数的上下界） 给的槽总数是 N ⇒ 两个候选下界各算一次 |

### 怎样才算失败（跑前写死，跑完不许改）

| 条款 | 触发时怎么判 |
|---|---|
| **阳性对照**：K = ∞ 时丙必须退化成甲（斜率变成统计量数）| 不退化 ⇒ 模型没在按 K 算，**整轮作废** |
| **阴性对照**：统计量数 = 0 ⇒ 两者 key 数恒 0 | 非 0 ⇒ **整轮作废** |
| **丙的丢弃需要遍历** | **如实记录并淘汰丙**——那时它违反第一格，不管 key 数多好看 |
| 两者逐格相同 | **如实记录「不是两个候选」**，不许硬凑出差别 |

### 它答不了的那一半

1. **这是计数模型不是实现**，与 E50（根环槽数的上下界） / E52（两种多可写头机制的运营代价） 同一条限制：文件操作 0 处。
2. **统计量有多少个**是输入不是测量——本工程还没有统计量清单（D5（快照 / 空间记账机制） 未定项 1 也还开着）。
3. **不建模 write buffer 的合并**：同一 checkpoint 内对同一统计量的多次更新在缓冲里会合成一条，
   E54（记账的「代」要保留几代）按「每 checkpoint 每统计量一条」算，**是上界**。

### 前置

无。纯计数模型。

### 实测（2026-08-30，N=5 轮字节一致）

#### 结果一：**甲 + 一条增量丢弃规则 ≡ 丙，逐格相同**

扫遍 4 档统计量数 × 5 档 checkpoint 数 × 3 档 K（60 格）：
`a_with_discard` 与 `scheme_c` **每一格都相等**（`a_and_c_identical_with_discard=1`）。

⇒ **它们不是两个候选，是同一条路的两种说法**：
甲说的是「代取 checkpoint 号」，丙说的是「只留最近 K 代」——
而「代取什么」与「留几代」是**两个正交的问题**，此前被写成了一个二选一。
⇒ **要定的只有 K。**

#### 结果二：不丢的代价是无界的，丢的代价是常数

| | key 数（64 个统计量、100 万个 checkpoint） | 对 checkpoint 数的斜率 |
|---|---|---|
| 不丢（甲的字面形态） | **64 000 000** | **= 统计量数**（8 / 64 / 512 三档逐格验过） |
| 保留最近 K = 8 代 | **512** | **0** |

#### 结果三：丢弃是增量的，**满足 `.claude/rules/fs-design.md` 第一格**

丢一代触及的 key 数 = **统计量数**（K=8、64 个统计量、100 万 checkpoint 时是 **64**），
**与 checkpoint 数无关、与盘容量无关**（`discard_depends_on_capacity=0`）。

机制：`(统计量, 维度元组, 代)` 里「代」是 key 的一段，要丢的那一代**算得出来**（当前代 − K），
**不用找** ⇒ 是点删不是扫描。
⇒ **第一格那条「不许遍历、代价不许随盘容量增长」满足。**
代价是每 checkpoint 的记账写次数从 `统计量数` 变成 `统计量数 × 2`（一写一删）。

#### 结果四：K 的下界由「根最多能回退几代」给

| 来源 | 回退深度 | K 下界 | 64 个统计量下的 key 数 |
|---|---|---|---|
| E53（丢一整块盘之后根环还挂不挂得上） **实测**最坏回退 | 1 | **2** | **128** |
| E50（根环槽数的上下界） 的槽总数（保守：任何幸存槽都可能被选中） | 8 | **9** | **576** |

⇒ **两个下界差 4.5 倍，但都是常数，且都比不丢那条小五个数量级。**

#### 对照逐条判定

| 条款 | 判定 |
|---|---|
| **阳性对照**：K = ∞ ⇒ 丙退化成甲 | **通过**（两边都是 64 000 000）|
| **阴性对照**：统计量数 0 ⇒ 两者恒 0 | **通过** |
| 丙的丢弃需要遍历 ⇒ 淘汰丙 | **没有发生**：丢弃代价 = 统计量数，式子里没有盘容量 |
| 两者逐格相同 ⇒ 记「不是两个候选」 | **发生了，已如实记录** |

### 结论

1. **「代取什么」与「留几代」是两个正交问题**，此前被写成一个二选一。
   代取 checkpoint 号 + 一条增量丢弃规则，**就是**「只留最近 K 代」。
2. **丢弃满足第一格**：点删、代价 = 统计量数、与盘容量无关。
3. **K 的下界绑在「根最多能回退几代」上**：实测口径 K ≥ 2，保守口径 K ≥ 根环槽总数 + 1。
4. ⚠️ **key 数量的绝对值仍取决于统计量个数**，而那个数本工程还没有
   （D5（快照 / 空间记账机制） 未定项 1 也还开着）⇒ K 下界那张表里的 128 / 576 是**按 64 个统计量算的示例**，不是预测。
