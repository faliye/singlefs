## E35 多可写头两种形态 —— 已跑（2026-08-29，N=5 轮字节一致）

**它问的是**：D6（快照实现模型） 定案取多可写头之后，两种实现形态哪一种在写第一行代码之前就带着坑。

### 它攻的是两条已定项凑在一起

| 出处 | 逐字 |
|---|---|
| D8（核心索引结构） 已定项 3 | `key = (locality_id, inode, offset)` —— **三段，没有快照维** |
| D9（加密） 已定项 4 | nonce **现算**还是每 extent 存。取「现算」时，输入就是逻辑身份，也就是 key |

两个可写头各写一次同一个 `(locality, inode, offset)`：三段 key 下它们的逻辑身份
**逐字节相同** ⇒ 现算出**同一个 nonce** ⇒ 同密钥同 nonce 加两段不同明文
⇒ ChaCha20 的 keystream 复用。

⚠️ **这不是「MAC 会失配」那一类可检出的错，是机密性直接没了**，
而 I-6.1（nonce 不重用） 自陈这类事故「不会表现为任何读写错误」。

### 三条臂

| 臂 | key | 每头一棵树 | nonce 来源 |
|---|---|---|---|
| `key3_derived` | 三段（D8（核心索引结构） 已定） | 否 | 现算 |
| `key4_derived` | 四段（加快照维） | 否 | 现算 |
| `clone_per_head` | 三段 | **是** | 现算 |

⚠️ **`clone_per_head` 不是E35（多可写头两种形态）发明的**：D5（快照 / 空间记账机制）
「克隆 / 可写快照要加三条」一节写的就是它——每个可写头各持一份 `prev_snap_txg`
与一份 deadlist。**它是 D6（快照实现模型） 定案没有点名、而仓里现成躺着的另一条路。**

### 判据（两条，必须同时满足）

1. **不许出现 keystream 复用**：`keystream_reuse_pairs == 0`。
2. **两个头各自读得回自己写的那一份**：`own_reads_ok == 2`。

### 阳性对照

验「同密钥同 nonce 两段密文异或 == 两段明文异或」这条恒等式：
出事那条臂上**必须成立**（证明复用是真的），另外两条臂上**必须不成立**（证明度量分得开）。
⚠️ 这条计数**无条件对所有对判**，不套在「已经判定复用」的分支里——
套进去它只能等于复用数，就不再是独立佐证（变异 M5 实测：套进去改成恒真，一个测试都不红）。

### 怎样才算失败

- 三条臂的 `keystream_reuse_pairs` 全为 0 ⇒ 先查两个头的逻辑身份是不是真的构造成相同了
  （单测 `under_the_three_segment_key_the_two_heads_collide_on_one_slot` 判的就是这个），
  确认构造成立仍无差异，则本担忧不成立，**如实记录**。
- 异或恒等式在出事那条臂上不成立 ⇒ **整轮作废**，度量没在看 keystream。

### 实测（2026-08-29，N=5 轮逐字节一致；2 个可写头、64 字节明文、ChaCha20-Poly1305）

| 臂 | keystream 复用对数 | 异或恒等式成立 | 各头读回自己 | 判定 |
|---|---|---|---|---|
| `key3_derived`（D8（核心索引结构） 已定 + 现算） | **1** | **1** | **1 / 2** | ✗ |
| `key4_derived` | 0 | 0 | 2 / 2 | ✓ |
| `clone_per_head` | 0 | 0 | 2 / 2 | ✓ |

**三条结论**：

1. **出事那条臂上，加密只是第二层伤**。它的 `own_reads_ok = 1`——
   三段 key 下两个头**共用同一个 key 槽**，后写的覆盖先写的。
   ⚠️ **这一条独立于加密：就算一个字节都不加密，这条臂也已经错了。**
   构造自证：两个头算出的逻辑身份逐字段相同（单测直接比 `Ident`）。
2. **加密开启且 D9（加密） 已定项 4 取「现算」时，再叠一层 keystream 复用**：
   异或恒等式实测成立 ⇒ 两段密文异或**就是**两段明文异或。
   这不是推理，是用真 AEAD 跑出来的。
3. **两条出路都同时满足两条判据**：key 加一维快照，或每头一棵树（D5（快照 / 空间记账机制） 那条）。
   两者的差别不在正确性，在运营代价——E35（多可写头两种形态）只量了两个粗指标
   （删一个头要碰几个区间、点查比几个 key 分量），**不足以在两条之间做选择**。

**一条挡住自然辩解的**：「加个版本号就好了」不成立——
两个头各自都是**第一次**写那个位置，各自的版本号都是 1（单测钉死）。

### 口径与已知局限

- **只建模了 2 个可写头、1 个位置、1 次写**。真实负载下的复用对数会更多，E35（多可写头两种形态）不外推。
- **只量了两个运营指标，且都是构造给出的常数**，不是测出来的：
  「删一个头要碰几个区间」与「点查比几个 key 分量」。
  ⇒ **E35（多可写头两种形态）能判「哪条臂错」，不能判「两条对的臂里选哪条」。**
- **没有建模快照祖先过滤**：`key4_derived` 那条臂只放了两个平行的头，
  没有共享块、没有祖先链。共享块那一格由 E31（AAD 缺快照维） 覆盖。
- 代码 `research/e7-index-bench/src/bin/e35_head_forms.rs`
  （`cargo run --release --bin e35-head-forms`），
  原始输出 `research/results/e35-head-forms-2026-08-29.out`。
  7 个单测、**6 条变异全部被抓**（表在 `research/mutations/e35_head_forms.tsv`）。

**前置**：无。纯逻辑 + 现成的 AEAD 库。
