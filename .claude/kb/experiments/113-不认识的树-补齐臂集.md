### 臂集（5 × 3 = 15 格）

| flags 政策 | 含义 | 仓内出处 |
|---|---|---|
| `Ignore` | 忽略未知位，按已知语义继续解释 | 无先例，作阳性对照用 |
| `Skip` | 按「不认识这棵树」跳过该条目 | E112（旧写者遇到不认识的树） 定的那一档 |
| `RejectEntry` | 该条目 EIO，树不可用但**写者知道它在** | D18（块里携带什么信息） 与 D8（核心索引结构） 对另外两个 flags 字段已定的那一档 |
| `ReadOnly` | 只读挂载 | D15（格式冻结政策） 判定表的 compat_ro 那一档 |
| `PerBit` | 未登记的位 ⇒ `ReadOnly`；登记为 compat 的位 ⇒ `Skip` | 对抗轮给的候选 |

| 记账政策 | 含义 |
|---|---|
| `Carry` | 把不认识的记账行原样带到新代 |
| `NoCarry` | 不带 |
| `Exempt` | 不带，但**豁免那棵树的 K 代点删**（写代价 0，代价是改 D5（快照 / 空间记账机制） 已定项 2）|

### 伤害怎么算（每一项都要有机制推导，不许直接赋值）

- **`blocks_freed_while_referenced`（释放了仍被引用的块）**：
  D5（快照 / 空间记账机制） 逐字「销毁快照时把它的 deadlist **合并到下一个更新的那一侧**，
  并按 `birth > prev(S).txg` 过滤出可释放的条目」。一棵对写者隐形的快照使「下一个更新的那一侧」认成了
  更新的那个 ⇒ 过滤用的 `prev` 更大 ⇒ **更多块通过「可直接释放」** ⇒ 隐形窗口里出生的块被误释放。
  每代出生 `BLOCKS_BORN_PER_GENERATION` 块、隐形窗口 `W_GENS` 代 ⇒ 误释放数 = `BLOCKS_BORN_PER_GENERATION × W_GENS`，闭式。
- **`rdonly_violations`**：未知位取 `RDONLY` 语义时，写者每发布一代就往只读树里写一次
  ⇒ = 被置位的只读树数 × 实际发布代数。
- **`dead_revived`**：未知位取 `DEAD` 语义时，写者把半删的树当活的 ⇒ = 被置位的 DEAD 树数（一次性）。
- **`writable_gens`**：写者实际发布了几代（`ReadOnly` 为 0，其余为 `G`）。
- **`rows_lost` / `rows_written_per_gen`**：同 E112（旧写者遇到不认识的树） 的口径。

### 选法（跑前写死，字典序，不许跑完再改）

**「静默最少」这个选法 E112（旧写者遇到不认识的树） 用过，被对抗轮判为不成立**——它不给严重性定价，
也不给「挂不上」定价。E113（不认识的树·补齐臂集） 改成**字典序**，理由是本工程的价值次序是「正确 > 可用 > 便宜」：

1. `blocks_freed_while_referenced == 0`（丢数据，一票否决）
2. `rdonly_violations + dead_revived == 0`（违反语义）
3. `rows_lost == 0`
4. `silent` 最小
5. `writable_gens` 最大
6. `rows_written_per_gen` 最小

**这个次序在跑之前写下，跑完不许改。** 若跑出来没有任何一格过第 1 关，
结论是「五条 flags 政策全都会丢数据」，如实写。

### 失败条款（跑前写死）

| 条款 | 触发时怎么判 |
|---|---|
| **阳性对照，每条 flags 臂各一条**：`Ignore` 必须有 `rdonly_violations > 0`；`Skip` 必须有 `blocks_freed_while_referenced > 0`；`RejectEntry` / `ReadOnly` / `PerBit` 必须各自有一项代价 > 0（分别是 rows_lost、writable_gens=0、按档混合）| 任一条不成立 ⇒ 那一维没进模型，**整轮作废** |
| **阴性对照**：`W_GENS = 0`（没有隐形窗口）时 `blocks_freed_while_referenced` 必须 == 0 | 不成立 ⇒ 误释放这一维是硬编码的，**整轮作废** |
| **不许用筛子请人出场**：`ReadOnly` 与 `RejectEntry` 必须与其余臂在**同一个**字典序里比 | 代码里若还有 `if mount_ok` 这类筛子，**整轮作废** |
| **参数不许只取一个点**：`K`（D5（快照 / 空间记账机制） 已定项 2 至今**未定 K 的值**，E54（记账的「代」要保留几代） 逐字「真正要定的只有 K」）、`W_GENS`、`UNKNOWN_WRITABLE_HEAD_COUNT` 各扫一条曲线，**报「排名翻不翻」** | 任一参数下排名翻转而正文只报一个点 ⇒ 结论降级为「依赖参数」，并把翻转点写出来 |
| **反向接受条款**：若字典序的赢家不是 `PerBit` 或 `ReadOnly`，照实写，按赢家改结论 | 照实写 |

### 结论（与跑前写死的接受条款对照）

跑前写的是「对抗轮倾向 `PerBit`；若字典序赢家不是它，就改结论」。
**赢家不是 `PerBit`，是 `RejectEntry`** ⇒ 按那条条款改结论。

`PerBit` 输在它是个**条件政策**：位没登记时它就等于 `ReadOnly`，一代都发不出去；
位全登记过时它就等于 `Skip`，而 `Skip` 在第 1 关上丢 192 块。
**它没有自己的第三种行为**——两档各退化到一条已有的臂。

⇒ **flags 未知位取 `RejectEntry`（该条目 EIO）**。它同时是本工程对另外两个 flags 字段
**已经定过**的那一档（D18（块里携带什么信息）「一律拒收」、D8（核心索引结构）「该记录 EIO」，
落成 I-9.7（记录三段恒零））⇒ 三个 flags 字段并成一条政策，不用再解释它们为什么不同。

⚠️ **`RejectEntry` 为什么不丢数据，依赖 ④ 的条目自带长度**：条目 EIO 但**位置还在**
⇒ 写者知道「那儿有一棵树我读不了」⇒ 不做跨它的 deadlist 合并。
没有长度字段就定位不到下一条，这条推导不成立。

⚠️ **记账那一维的 `Exempt` 赢得不干净**：它只在第 6 关（每代写 17 行 vs `Carry` 的 19）赢，
而**它的真实代价不在这个天平上**——豁免一棵树的 K 代点删要改 D5（快照 / 空间记账机制） 已定项 2，
那是一条已定条款。⇒ **记账那一维要单独定**：`Carry` 不动任何已定条款、每代多 2 行；
`Exempt` 省那 2 行、代价是改 D5（快照 / 空间记账机制） 已定项 2。落点 C160（记账臂的真实代价不在天平上）。

⚠️ **`Skip` 的 192 块不是「更可能」，是「机制上会」**：D5（快照 / 空间记账机制） 的
「合并到下一个更新的那一侧 + `birth > prev(S).txg` 过滤」在隐形快照下必然认错邻居；
数值 `BLOCKS_BORN_PER_GENERATION × invisible_window_generations` 是闭式，`invisible_window_generations = 0` 时归零（阴性对照）。
