## E96 混合架构的一致性 —— 已跑（2026-09-03，10 单测 / 12 条变异全抓）：单元头只有五元组时快照读会静默读到新版本，头带块 birth 则恒 0；释放必须经映射不经提示；搬迁三步截断不新增错读

**问题**：D26（后台整理与放置回收）「六个未定项的论证材料」推荐的位置权威形态是
**混合架构**——树指针里的位置条目（D19（块指针的结构与宽度预算）已定项 1）降为**提示**，
「逻辑身份 → 落点」的中央映射（D9（加密）已定项 5 在加密侧已定的形态）无条件存在并作**权威**；
读走提示、验单元头、失配回映射；整理只改映射，快照树与 deadlist 不动。
用户问：它在一致性上有没有问题。E94（搬共享落点的触碰面）只量了代价，没量一致性。

跑前能想到的四处危险，做成四个判据：
提示过期后落到**被复用的槽**上（单元头五元组——D18（块里携带什么信息）已定项 3——
没有块的 birth，同一 (inode, offset) 的新旧版本五元组相同）；
释放路径误把提示当权威；搬迁事务中途崩溃；映射与占用表的守恒。

### 模型

沿用 E94（搬共享落点的触碰面）的持久 COW 树（L=4096、F=16）、快照轮换与销毁级联，加：

| 部件 | 模型 |
|---|---|
| 叶条目 | (版本, 落点提示)；提示只在该条目被重写时刷新，整理不改它 |
| 中央映射 | 版本 → 落点，权威；整理只改这里 |
| 单元头 | 两臂：`hdr_key`（只有五元组 ⇒ 建模为 key）/ `hdr_birth`（五元组 + 块 birth ⇒ 建模为 (key, birth)） |
| 读路径 | 提示优先：提示槽的占用者单元头与要读的版本匹配就返回；否则回映射多一跳 |
| 释放 | 销毁快照时 deadlist 条目按映射解落点（正解）；另算「按提示解落点」会误放几次（负臂，只计数不施加） |
| 分配 | 两臂：`alloc_lowest`（最低空槽）/ `alloc_lifo`（最近回空的先复用）——都不针对 key |
| 整理 | 扫描游标起取 N=64 个占用槽搬到新槽，扫完一圈回头 |
| defer | 某一轮释放的槽要到下一轮才可复用（D16（发布语义）新规则 2） |

负载：每轮 64 次更新 + 一批整理 + 轮末读全部根的全部 key，200 轮，每 8 轮立快照、保留 4 个；
两组：`uniform`（均匀随机 key）与 `adversarial`（一半更新打刚被搬走的 key——
让「同 key 新版本复用旧槽」这个危险可达，E31（AAD 缺快照维）那类对照的形态）。

### 判据（跑前写死 2026-09-03）与判定

| # | 判据 | 判定 |
|---|---|---|
| 1 | 手算锚点：快照 → 搬 key 3（槽 3 → 8）→ 更新 key 3 复用槽 3 → 读快照 key 3：`hdr_key` 错读 1、`hdr_birth` 错读 0 多跳 1 | **通过**（单测） |
| 2 | 守恒：被引用的每个版本 `占用者(映射(v)) == v`，映射与占用互为反函数 | **通过**（40 个配置 × 200 轮逐轮审计） |
| 3 | 阳性对照：踩坏映射 ⇒ 审计红；对调占用 ⇒ 错读计数能响 | **通过**（单测，含只有反向核对能抓的构造） |
| 4 | `hdr_key` 错读数恰等于独立扫描的「提示槽被同 key 另一版本占用」数；`hdr_birth` 恒 0 | **通过**（逐轮相等；`hdr_birth` 40 × 200 轮恒 0） |
| 5 | 按提示解落点的误放数 > 0；按映射恒 0 | **通过** |
| 6 | 搬迁三步各截断一次：**不新增**错读、守恒恒成立 | **通过**（8 个配置各三步，差值恒 0；口径澄清见修订记录） |
| 7 | 多跳率随轮数（只报数） | 见实测 |

### 实测（5 种子）

#### 1. 单元头只有五元组：快照读会静默读到新版本（判据 4）

| 单元头 | 分配 | 负载 | 200 轮错读总数（5 种子） | 第 200 轮的错读 |
|---|---|---|---|---|
| `hdr_key` | 最低空槽 | 均匀 | **65 / 0 / 72 / 0 / 69** | 0 |
| `hdr_key` | LIFO | 均匀 | 66 / 48 / 40 / 128 / 57 | 0 |
| `hdr_key` | 最低空槽 | 对抗 | 4052 / 3925 / 3992 / 4503 / 4326 | 22–31 |
| `hdr_key` | LIFO | 对抗 | 4581–5259 | 17–23 |
| `hdr_birth` | 任意 | 任意 | **0（20 个运行全部）** | 0 |

- **均匀随机负载、最低空槽分配——最不利于复现的那一格——也出错读**（5 种子里 3 个非零）。
  每一次都是快照读拿到同一 (inode, offset) 的**新**内容而没有任何报错：提示槽被同 key
  新版本复用，五元组逐字相同，读路径认为提示命中。
- 对抗负载下每轮末有约 20 条这样的条目活着（`wrong_last`），200 轮累计四五千次。
- 头带块 birth 后，同样的负载、同样的提示、同样的复用，**一次错读都没有**——
  失配全部回映射（多跳率见第 3 条）。
- E85（单元头的字段表）早已量出「已定字段集判不了块 birth」，E31（AAD 缺快照维）
  量出五元组对快照维是瞎的；E96（混合架构的一致性）把这两条接到整理上：
  **位置提示 + 五元组头 = 整理之后快照静默读错**。

#### 2. 释放必须经映射，不经提示（判据 5）

| 负载 | 200 轮里按提示解落点会误放（放掉别的版本正占的槽） | 按映射 |
|---|---|---|
| 均匀 | 4861–5123 次 | **0** |
| 对抗 | 6003–6158 次 | **0** |

deadlist 条目带的提示是 kill 那一刻叶里的值，此后整理一搬就过期；销毁快照时若拿它当落点，
放掉的是别人的槽。⇒ **任何释放路径都不许把提示当权威**——这是混合架构的一条硬规则。

#### 3. 提示过期的读代价（判据 7）

| 负载 | 第 100 轮多跳率 活根 / 快照根 | 第 200 轮 活根 / 快照根 |
|---|---|---|
| 均匀 | 约 30% / 37% | 29–31% / 35–37% |
| 对抗 | 约 15–16% / 25% | 19–21% / 27–30% |

活根的提示只在该 key 被重写时刷新，快照的永不刷新；200 轮里整理游标把占用区扫过约一遍
⇒ 三成读要多一跳。**这是混合架构的读代价的形状**：与整理搬过多少、快照多老成正比，
不与快照数 K 成正比（E94（搬共享落点的触碰面）里指针权威的代价才随 K 走）。

#### 4. 搬迁中途崩溃不新增错读（判据 6）

一次搬迁 = ① 写新副本 → ② 发布映射 → ③ defer 放旧槽。8 个配置各在三步之后截断并恢复
（① 之后未发布的分配回滚；② 之后旧槽由 defer 放）：**错读差值恒 0、守恒恒成立**。
机制：② 之前映射仍指旧副本、旧副本还在；② 之后提示落到旧槽时占用者仍是同一个版本，
读到的还是它自己——两边都没有「映射指着不存在的东西」的窗口。

### 模型修订记录（全部发生在正式轮入库之前，判据 1–5、7 未动）

1. **整理批次从「槽号最低的 64 个」改为扫描游标**：初版目的地又取最低空槽，等于在盘底原地打转，
   200 轮把多跳率抬到 95%——那是伪影不是混合架构的读代价。
2. **判据 6 的口径澄清为差值**：`hdr_key` 臂的世界里本来就有提示落到同 key 复用槽的错读，
   截断前后按绝对 0 判会把它们算到崩溃头上；改为「截断不新增错读」（`hdr_birth` 下差值 0 即绝对 0）。
3. **加了分配政策维**：最低空槽下对抗负载 24 轮也造不出同 key 复用（旧槽前面总有更低的空槽），
   加 LIFO（最近回空先复用，不少分配器的形态、不针对 key）让危险在规模上可达；
   入库轮两种政策都报，均匀负载 + 最低空槽那一格照样非零。

### 它答不了的

1. 位置条目里那个 32 位密文校验和（D19（块指针的结构与宽度预算）已定项 2）也能概率性检出复用，
   模型没建它——它只把 `hdr_key` 臂的错读从「必然」变成「2⁻³² 概率」，量纲不同，另算。
2. 无耗时轴：多跳率是次数占比，不是延迟。
3. 加密侧（映射层明文、MAC 不覆盖位置）的篡改面不在模型里。
4. 映射层自身的持久与重建（C34（明文映射层的态别三处打架）、E28（明文映射层能不能只靠单元自描述重建））按已有结论引用，不重验。
5. 活根提示的刷新政策只有「随重写刷新」一种；「读失配时顺手刷提示」那种会改快照树以外的叶，没建臂。
6. 绝对计数不能搬去扇出 119 加消息缓冲的树（与 E94（搬共享落点的触碰面）同一条限制）。
