## E93 老化下的放置与碎片度 —— 已跑（2026-09-03，14 单测 / 11 条变异全抓）：碎片度可 O(1) 增量维护；聚簇段没有整理喂空段就不自持；邻居重写有天花板，整理随预算持续走低

**问题**：D26（后台整理与放置回收）未定项 1 缺两样前置——「不整理会退化多少」的量，
和一个碎片度的可计算定义（`.claude/rules/fs-design.md` 硬要求 1：判据必须显式、可计算、写下来）；
未定项 4 要判「结构抗老化要不要动节点布局」；已定项 6（2026-09-03 用户定案取持久化）要观测量本身。
E10（老化：结构抗老化 vs 事后整理）欠文件系统，今天跑不了；
E93（老化下的放置与碎片度）在计数模型层先把放置政策这一半量出来。

⚠️ **E93（老化下的放置与碎片度）不代替 E10（老化：结构抗老化 vs 事后整理）**：
D26（后台整理与放置回收）主结论里「两条腿可有一条降级」的判据归
E10（老化：结构抗老化 vs 事后整理）自己写死的那条（③ 达到 ② 的水平），E93（老化下的放置与碎片度）不碰那个判定。

### 模型

L 个定宽对象按 key 序排队（可读作 D8（核心索引结构）已定项 2 的 16 KiB 索引叶，
也可读作 D4（校验和位置）已定项 7 的 32 KiB 数据单元——两类都定宽，模型不区分，
读作哪类只影响「runs 多 ⇒ 谁的扫描慢」的解释），设备 S 个槽，填充率 L/S。
初始按 key 序连续写入（顺序创建的形态）。每个 checkpoint 按负载脏掉一批对象，
COW 重写到新槽；旧槽进 defer，下一个 checkpoint 才可复用
（D16（发布语义）新规则 2 的模型化）。

**碎片度的候选定义（被验证对象）**：`F = runs / L`，
runs = 按 key 序遍历全部对象时的物理连续段数。要求它**可增量维护**：
对象从槽 a 挪到槽 b 时，只有它与 key 相邻两个对象的邻接关系变化 ⇒ O(1) 更新；
审计路径全扫重算，与增量路径不共享代码（`.claude/rules/fs-design.md` 第一格 + 第二格的分工）。

四条臂（放置政策）× 两组负载（均匀随机单点重写 / 成段重写，段长 8）：

| 臂 | 政策 |
|---|---|
| first_fit | 最低空槽优先（对照：经典老化形态） |
| bump_seg | 同 checkpoint 的脏对象按 key 排序后连续写进聚簇段；无空段时回落 first_fit 并计数。D3（空间分配）已定项 5 只定了提交内生块聚簇，把它推广到全部 COW 写是候选政策，不是已定条款 |
| bump_neighbor(R) | bump_seg + 写路径邻居重写：每个脏 key 段向两侧各多重写 ≤ R 个干净邻居——「结构抗老化」的无格式改动候选形态 |
| bump_compact(B) | bump_seg + 每 checkpoint 预算 B 个对象的按 key 序轮转整理——D26（后台整理与放置回收）腿一的模型化 |

### 判据（跑前写死 2026-09-03，跑完没改）

1. **手算锚点**：8 对象小场景，脚本化重写后 runs 按手算钉死（绝对值断言）。
2. **守恒**：每个采样点、每条臂、每个种子上，增量 runs == 全扫重算 runs；
   占用槽数恒 == L；空槽 + 占用 == S；defer 的槽本 checkpoint 不可复用。
3. **测量的阳性对照，四条臂都过闸**：经测试专用的强制放置开关（绕过政策）把对象放成
   全隔离布局，每条臂的测量管道必须报 runs == L；放回 key 序连续布局必须报 runs == 1。
4. **老化负载够不够狠**：first_fit × 均匀随机负载跑到期末 runs ≥ L/4——
   E10（老化：结构抗老化 vs 事后整理）的作废条款同形：没测出退化只说明负载不够狠。
5. **要回答的三问（只报数，不判降级）**：
   a. first_fit 与 bump_seg 的 runs 轨迹——「不整理会退化多少」的模型层答案；
   b. bump_seg 的空段供给在稳态耗不耗尽（回落次数轨迹）——聚簇段政策没有整理时自持不自持；
   c. 额外写预算相近的格子上，bump_neighbor 与 bump_compact 谁的 runs 低、比值多少。
6. 确定性模型带种子 RNG：5 种子说明的是无隐藏状态与种子敏感度，不是统计稳定
   （`.claude/singlefs-ai-sop/rules/test-discipline.md` 确定性实验条款）。

### 实测（L=8192、S=10240（填充 80%）、段长 G=64、每 checkpoint 脏 D=64、T=2000 轮、5 种子取中位）

#### 1. 不整理会退化多少：两组负载都冲到饱和，且很快

| 臂 | 均匀随机 runs（占 L） | 成段重写 runs（占 L） | 额外写 |
|---|---|---|---|
| first_fit | **8186（99.9%）** | 7997（97.6%） | 0 |
| bump_seg | **8186（99.9%）** | 7312（89.3%） | 0 |

轨迹：first_fit × 均匀随机在 **t=500（每对象平均重写约 3.9 次）就到 8184**，此后平台。
⇒ 模型层的「不整理」不是缓慢退化，是**几百个 checkpoint 内冲顶**。

#### 2. 聚簇段政策没有整理喂空段就不自持（判据 5b）

bump_seg 的回落率（分配走不进聚簇段的占比）五个种子全部 **91.8%–93.8%**：
散布的释放几乎永远凑不齐一个全空段。整理预算是唯一把它压下来的力量——
bump_cp_b32 / b128 / b256（均匀随机）的回落率分别约 88% / 73% / 50%。
⇒ **「聚簇段分配」这个政策骑在整理身上**；E81（提交的固定点）指望的提交内生块聚簇，
稳态下同样要有人清出空段。

#### 3. 邻居重写有天花板；整理随预算持续走低（判据 5c）

| 臂 | 均匀随机 runs（额外写倍数） | 成段重写 runs（额外写倍数） |
|---|---|---|
| bump_nb_r1 | 5497（2.98×） | 5181（1.25×） |
| bump_nb_r2 | **5460（4.92×）** | 5111（1.50×） |
| bump_cp_b32 | 7502（1.50×） | 6073（1.50×） |
| bump_cp_b128 | 6095（3.00×） | 3922（3.00×） |
| bump_cp_b256 | 4791（5.00×） | **1339（5.00×）** |

- **等预算格互有胜负**：均匀随机 3× 档邻居胜（5497 vs 6095），5× 档整理胜（4791 vs 5460）；
  成段重写 1.5× 档邻居胜（5111 vs 6073）。
- **邻居重写饱和**：R 从 1 提到 2，均匀随机只从 5497 挪到 5460（预算却从 3× 涨到 4.9×）——
  簇被后续重写打散的速度跟上了成簇速度，稳态卡在 F ≈ 66%。
  且它的预算受负载几何封顶：成段负载下 R=2 只花得出 1.5×，**想多花也没处花**。
- **整理不饱和**：预算 5× 的整理把成段负载压到 F ≈ 10–21%（五种子 713–880 起伏，如实报），
  且轨迹随时间还在下行。

#### 4. 碎片度定义成立（判据 2）

增量 O(1) 维护的 runs 与全扫审计在**全部臂 × 负载 × 种子 × 采样点**逐点相等；
审计的判别力单测验证（绕过增量路径直接踩坏布局，两条路径必须分叉）。
⇒ `F = runs / L` 满足 `.claude/rules/fs-design.md` 第一格（提交时增量维护、被问到那一刻有答案）
且审计路径独立（第二格），可作 D26（后台整理与放置回收）未定项 1 的碎片度定义候选与
已定项 6 的观测量。

### 模型修订记录（全部发生在正式轮入库之前，判据未动）

1. **邻居臂的分配路径修过一次**：初版簇在段耗尽后逐槽 first_fit 回落，写出的「簇」物理不连续——
   那是给邻居重写立稻草人（`.claude/singlefs-ai-sop/rules/evidence-discipline.md` 明令）。
   修订后邻居臂与整理批次按「开放段 → 新空段 → 空槽连续 run → 逐槽回落（计数）」整段放置。
   修订前整理在等预算格全胜；修订后互有胜负——**这一改动改变了结论方向，所以记在这里**。
2. **first_fit 加了保留区守卫**：开放段里未 bump 到的槽对 first_fit 与 run 搜索都是保留区，
   偷走会双重分配（变异 M7/M11 双向验证）。入库轮的输出在守卫前后逐字节相同
   ⇒ 该窗口在本参数下没被踩到，守卫是防御不是改数。

### 它答不了的

1. 计数模型：无真实 I/O、无 CPU、无缓存。「runs 少 ⇒ 扫描快」是结构量到耗时的外推，
   耗时那一半归 E10（老化：结构抗老化 vs 事后整理）。
2. 对象定宽：变长 extent 的碎片形态没建模。
3. 两组负载是端点不是分布：真实老化负载（git checkout 类）落在哪没有依据。
   D11（索引节点要不要留消息缓冲区）已定的消息缓冲会把叶子重写攒成批 ⇒ 真实脏集比
   均匀随机更接近成段那一档，但攒批统计本身没建模。
4. 触发阈值取多少不归 E93（老化下的放置与碎片度）——它只交付碎片度定义、
   增量可维护性证据与退化轨迹。
5. 节点布局侧的抗老化形态（动格式那条路）没有臂——邻居重写臂的天花板不构成
   「动格式也没用」的证据。
6. 没有条带、没有崩溃 / 重做、不分元数据与数据、填充率只取 80% 一个点
   （三方论证反推腿指出，2026-09-03）：D2（RAID 条带策略）已定项 11 的部分条带钉住、
   D8（核心索引结构）已定项 5 的意图重做、D3（空间分配）已定项 5 那批提交内生块
   能不能进聚簇段，都在模型之外。回落率是全部分配的口径，**不能**当作提交内生块的聚簇成功率。
