### 判据（跑前写死，跑完不许改）

1. **绝对值断言**：每一档记录宽度下，一个 16 KiB 叶装得下的记录数必须恰好等于
   `(16384 − 节点头) / 记录宽`，树高必须由叶扇出与内部扇出两级各自算出。**不许只做臂间互比。**
2. **态别判据（E98（inode 记录与 inode 树的几何） 的核心）**：对每个字段判「能不能只从权威态（单元 + 记账 + 根）重算出来」，
   **数得出不能重算的字段数**。不能重算的字段数 > 0 ⇒ inode 记录不是派生态，
   按 D21（权威态与派生态的分界） 的判据它要么住单元、要么权威态扩项——**两条路都要报出来，不替它选。**
3. **`locality_id` 对照的判别力**：造一批对象，让记录里的 `locality_id` 与 extent key 的首段不一致，
   数「读成空洞而 checker 判绿」的对象数。**带对照臂必须全抓，不带对照臂必须全漏**——
   两个数都要是绝对值，不许只说「带对照更好」。
4. **改动计数的排序力**：同一个 checkpoint 内对同一个 inode 改 k 次，数「排不出先后」的对数。
   取 `checkpoint_txg` 时该数必然 > 0（同号）⇒ **要么加窗口内序号，要么另有排序来源**，如实报。
5. **爆炸半径**：「扫描单位是节点不是记录」⇒ 丢一个叶节点丢多少条 inode 记录。绝对值。

#### 判据 1 / 5：几何与爆炸半径

记录 140 字节（身份段 24 + 属性段 84 + 预留 32）。
**三档节点头（58 / 67 / 76）上叶扇出恒 116** ⇒ 结论不依赖节点头。
内部扇出 243（key = inode 8 + 子指针 59）；1e6 个 inode 树高 3、1e9 树高 4。

**丢一个容器永久损失几条**（2026-09-04 补测，第一、二版只在 btree 那条线上发这个数，
两种形态从没被并排比过 ⇒ 反向接受条款在结构上碰不到）：

| 形态 | 一个容器装几条 | **永久损失** | 要不要冗余 / 可检出条款 |
|---|---|---|---|
| 住索引节点的 value | 116 | **116** | 要 |
| 打包进共享单元 | 233 | **233** | 要 |
| 阳性对照：假设 14 个字段全都算得回来 | — | **0** | 不要 |

⚠️ **两种形态的永久损失都不是 0**，而 E29（坏一个节点的爆炸半径） 实测索引节点的永久损失**恒 0**
——靠的正是「索引可从单元重建」，inode 记录不满足那个前提。
⇒ **反向接受条款那句「爆炸半径否掉住单元」评价不了**（没人设过阈值）；
这一维真正暴露的是：**无论选哪个形态，都要一条冗余 / 可检出条款**，打包形态的永久损失恰好是另一种的 **2.00 倍**。

⚠️ **头判别位撤回**：D6（快照实现模型） 已定项 1 定「每头一棵自己的树」，
D8（核心索引结构） 已定项 3 的注逐字「两个头不再落进同一个 key 槽」⇒ 这一位**没有对象**。
两条臂都量了：带 2 字节判别位时内部扇出 236，不带是 243——**白付 7 格**。

#### 判据 3 / 4：两条对照的判别力

`locality_id` 对照（100 万对象、1000 个不一致）：**带对照臂抓 1000、静默 0；
不带对照臂抓 0、静默读空洞 1000**。阴性对照（零个不一致）两臂都是 0。

改动计数取 `checkpoint_txg`：同一 checkpoint 内改 8 次 ⇒ **28 对**排不出先后（C(8,2)）；
改 64 次 ⇒ 2016 对。配 8 位窗口内序号之后归零，而 300 次时 8 位又不够。
⇒ **改动计数单靠 checkpoint_txg 排不了同窗口内的两个版本。**
