### 判据（跑前写死，跑完不许改）

1. **单次更新的绝对值**：一次发布只改一条记录，两侧各自「写出的节点 / 单元数 × 大小 × w」，N ∈ {1e4, 1e6, 1e8}、节点头 58 / 67 / 76 逐格；树高由叶扇出与内部扇出两级各自算出。
2. **批量更新**：k ∈ {1, 10, 100, 1000} 条均匀散开，每层碰到的节点数按 L × (1 − (1 − 1/L)^k)；另报全落同一容器 / 同一叶的聚簇格。
3. **stat 的读代价**：住索引叶 = 树高次节点读；打包 = inode 树高 + 容器索引树高次节点读 + 1 次 32 KiB 单元读。**第三臂「叶即容器」（2026-09-05，D8（核心索引结构） 已定项 6 第一轮论证后加）**：inode 树的叶就是码 3 容器、内部节点就是容器索引，条目 = 分隔 key 8 + 身份引用 26（出生树 8 + 打包记录类型 2 + 容器号 8 + 容器出生代 8，与别的树引用容器的那 26 字节同一段）+ 子指针 59 = 93（扇出 175；基础头三档 58 / 67 / 76 是 E73（节点 key 区间的扇出代价） 的不带区间下界，inode 树内部节点带 16 字节 key 区间后是 74 / 83 / 92，扇出仍 175，头到 109 才掉一格）⇒ 写 = 碰到的容器 + 内部层碰到的节点，读 = 内部层次数 + 1 次 32 KiB 单元读。
4. **爆炸半径**：沿用 E98（inode 记录与 inode 树的几何） 口径，两侧各一个数。
5. **判先前估算**：「≈ 3 倍」按判据 1 的单次更新比核，≥ 3 成立，< 3 作废并如实写。

### 失败条款（跑前写死）

**它对 D8（核心索引结构） 已定项 6 说了什么**：路 ① 在写上不是 3 倍而是 1.25–1.85 倍（取决于 N 与批量），
在读上是 2.25–2.5 倍字节、多一次单元读；容器索引树比 inode 树矮，抵掉了一部分容器比叶大的代价。
第三臂把容器索引并进 inode 树自己的内部节点之后，单次写不变、批量写多不到 0.2%、读降到 1.25–1.5 倍——是 D8（核心索引结构） 已定项 6 第三版起取的形态。
容器数 ⌈n/233⌉ 是新建树的值，删除后不合并时填充率没有下界（1e6 顺序创建再删 90% 不合并 = 9.98 倍空间放大）。单次 stat 多出的那 16 KiB 按路径深度累乘：命名树的 value 只有 inode 号（D8（核心索引结构） 已定项 3），路径每个分量各查一次 inode 树，d 层深的路径多付 d 次。
这些数只回答代价，不回答态别与恢复那一半（那在三方论证里判）。

### 它答不了的

纯算术：没有 btree 实现、没有 I/O、没有缓存、没有崩溃点重放，文件操作 0 处。不答挂钟。
更新均匀散开是选定的场景点，真实负载的局部性只用聚簇格给一个上界；打包侧的容器每次发布重写一次那笔账（C105（打包容器按发布频率重写的写放大））
在这里体现为「k 条更新落在几个容器」，没有单独建模。
