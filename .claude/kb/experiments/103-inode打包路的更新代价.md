### 判据（跑前写死，跑完不许改）

1. **单次更新的绝对值**：一次发布只改一条记录，两侧各自「写出的节点 / 单元数 × 大小 × w」，N ∈ {1e4, 1e6, 1e8}、节点头 58 / 67 / 76 逐格；树高由叶扇出与内部扇出两级各自算出。
2. **批量更新**：k ∈ {1, 10, 100, 1000} 条均匀散开，每层碰到的节点数按 L × (1 − (1 − 1/L)^k)；另报全落同一容器 / 同一叶的聚簇格。
3. **stat 的读代价**：住索引叶 = 树高次节点读；打包 = inode 树高 + 容器索引树高次节点读 + 1 次 32 KiB 单元读。
4. **爆炸半径**：沿用 E98（inode 记录与 inode 树的几何） 口径，两侧各一个数。
5. **判先前估算**：「≈ 3 倍」按判据 1 的单次更新比核，≥ 3 成立，< 3 作废并如实写。

### 失败条款（跑前写死）

| 条款 | 触发时怎么判 |
|---|---|
| 阳性对照：打包侧容器取 16384 且不计索引，必须与住索引叶的叶那一层同代价 | 不等 ⇒ 两条臂不在同一把尺子上，整轮作废 |
| 阴性对照：k = 0 ⇒ 两侧结构字节恰 0 | 不为 0 ⇒ 平凡输入就错，整轮作废 |
| 饱和对照：k 远大于层内节点数 ⇒ 碰到的节点数收敛到该层节点数（差 < 0.5%） | 不收敛 ⇒ 批量模型错，整轮作废 |
| **反向接受条款**：单次更新比 < 3 | 结论是「第二轮正推腿的 3 倍估算作废」，D8（核心索引结构） 未定项 6 那句改成实测数 |

### 实测（2026-09-04，纯算术，N=5 轮逐字节一致，10 单测 / 8 条变异全抓）

**口径与复跑**：代码 `research/e7-index-bench/src/bin/e103_inode_update_cost.rs`（`cargo run --release --bin e103-inode-update-cost`），
产物 `research/results/e103-inode-update-cost-2026-09-04.out`（68 行，收尾 `emitted=68`），
变异表 `research/mutations/e103_inode_update_cost.tsv`
（`bash research/scripts/mutate.sh e103-inode-update-cost research/e7-index-bench/src/bin/e103_inode_update_cost.rs research/mutations/e103_inode_update_cost.tsv`，
记录 `research/results/e103-mutate-2026-09-04.log`），已挂 `research/scripts/replay.sh`。

**几何（头 58，1e6 个 inode）**：住索引叶 8621 叶 → 36 → 1（高 3）；打包 4292 个容器，容器索引 23 叶 → 1（高 2；条目 26 + 59 = 85，扇出 192），
inode 树按身份引用时叶扇出 466（条目 8 + 27）、高 3。

| 判据 | 数（头 58） |
|---|---|
| 1 单次更新 | 1e4：65536 对 98304（**1.5 倍**）；1e6：98304 对 131072（**1.33 倍**）；1e8：131072 对 163840（**1.25 倍**）。住索引叶那侧是「树高个节点」，打包那侧是「一个 32 KiB 容器 + 容器索引树高个节点」，后者的索引树矮一到两层 |
| 2 批量散开 | 1e6：k = 100 是 1.65 倍、k = 1000 是 1.84 倍（打包侧每条更新的边际代价趋向一个 32 KiB 容器，住索引叶趋向一片 16 KiB 叶）；1e4 k = 1000 已进入全量重写区，**0.99 倍**——两侧存的是同一批 140 字节记录，全部重写时字节相同；聚簇格（k 条全落同一容器 / 同一叶）恒等于单次更新的比 |
| 3 stat 读 | 1e4：2 次对 4 次（2.5 倍字节）；1e6：3 次对 6 次（49152 对 114688，**2.33 倍**）；1e8：4 次对 8 次（2.25 倍）。多出来的是容器索引的树高次节点读加一次 32 KiB 单元读 |
| 4 爆炸半径 | 116 对 233（E98（inode 记录与 inode 树的几何） 口径不变） |
| 5 先前估算 | 「≈ 3 倍」= (32768 + 16384) / 16384，**只数了叶子**；实测单次更新 1.25–1.5 ⇒ **作废**。三档节点头同向，比值都落在 [1.25, 2) |

**它对 D8（核心索引结构） 未定项 6 说了什么**：路 ① 在写上不是 3 倍而是 1.25–1.85 倍（取决于 N 与批量），
在读上是 2.25–2.5 倍字节、多一次单元读；容器索引树比 inode 树矮，抵掉了一部分容器比叶大的代价。
这些数只回答「路 ① 比住索引叶贵多少」，不回答路 ① 与路 ②（权威态扩项）哪个该选。

### 它答不了的

纯算术：没有 btree 实现、没有 I/O、没有缓存、没有崩溃点重放，文件操作 0 处。不答挂钟。
更新均匀散开是选定的场景点，真实负载的局部性只用聚簇格给一个上界；打包侧的容器每次发布重写一次那笔账（C105（打包容器按发布频率重写的写放大））
在这里体现为「k 条更新落在几个容器」，没有单独建模。
