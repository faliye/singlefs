## E163 GPUマルチカードによるユニットチェックサム計算 —— 実施済み（2026-09-27）

[中文](163-GPU多卡算单元校验和.md) · [English](163-gpu-multi-card-unit-checksum-computation.en.md) · **日本語**

実行前登録 `e163-preregistration.md`、課題票 `m2-gpu-multicard-r1-forks.md`（M1、M2、M3）。装置は独立に手書きしたモデルで、`crates/` とコードを共有しない: `scripts/experiment-apparatus/e163_gpu_multicard_crc32c.rs`、bin `e163-gpu-multicard-crc32c`、既定では有効にならないフィーチャ `e163-gpu` に紐づく（`wgpu = "=30.0.1"` は `vulkan`/`wgsl`/`std` のみ有効、`pollster = "=1.0.1"`）。ゲート checker-tier-research-build-and-replay の research-unit-tests のセルはこれをコンパイルしない。10 件の単体テストはすべて成功（`cargo test --release --features e163-gpu --bin e163-gpu-multicard-crc32c`）。

### このセクションで行ったこと

- **アーム C**: ビット単位・反射型の CRC-32C 参照実装（多項式 0x82f63b78、初期値 0xFFFFFFFF、出力反転）。ソースは `e163_gpu_multicard_crc32c.rs` の `crc32c_reference`。
- **アーム G**: WGSL コンピュートシェーダ。ユニットごとに 1 呼び出しで、同じ CRC-32C をビット単位で計算する。バイトは `array<u32>` から `(word >> 8*(k%4)) & 0xFF` で取り出す。ソースは `e163_gpu_multicard_crc32c.rs` に埋め込まれた文字列 `COMPUTE_SHADER_SOURCE`。
- バッチ: N = 2560 ユニット × 32768 バイト、シード `0xE163092700000001`、ユニット内容 = splitmix64 で埋めたもの。
- R1（M1）: 本機の NVIDIA ディスクリート GPU カード 2 枚（RTX 5090、RTX 5060 Ti）がそれぞれ 1280 ユニットを計算する。
- R2（M2）: 各 512 ユニットの 5 シャード。シャード 0–1 は本機の 2 枚、シャード 2–4 は別の 3 枚搭載機（RTX 5080、RTX 5060 Ti × 2）。同一バイナリの sha256 は両端で同一、往復ファイルの sha256 も両端で同一。
- F1、F2（M3）: R1 の 2 シャード構成に対して、それぞれ 1 ビット反転（2 か所）と結果 1 件の欠落（1 か所）を注入する。
- PC-A（毎回の実行冒頭で、各カードとアーム C がすべて計算する）: 実行前登録の第 7 節 B 類の 8 個のアンカー（ASCII "123456789"、空文字列、32×00/32×FF、昇順/降順、32768×00/32768×FF）を、コマンドで検証済みの期待値と 1 つずつ照合する。

### 成果物から一行ずつ書き写した結果

成果物: `e163-gpu-multicard-crc32c-2026-09-27-r1.out`（M1）、`e163-gpu-multicard-crc32c-2026-09-27-r2.out`（M2）、`e163-gpu-multicard-crc32c-2026-09-27-f1.out`、`e163-gpu-multicard-crc32c-2026-09-27-f2.out`（M3）。

M1（R1、本機の 2 枚）:
```
MERGE_INPUT_HEADER seed=0xE163092700000001 unit_count=2560
MERGE total_units=2560 shards=2
MERGE matched_count=2560
MERGE mismatched_count=0 mismatched_global_unit_identifiers=[]
MERGE missing_count=0 missing_global_unit_identifiers=[]
MERGE duplicated_count=0 duplicated_global_unit_identifiers=[]
MERGE all_reference_values_distinct=true
```
2 枚とも `anchors_cpu_match=true anchors_gpu_match=true sentinel_and_gid_ok=true record_count=1280`（各 1 回）。**M1 の判定は「できる」**: Q1 本機の 2 枚とも起動できる（`nvidia-smi -L` が 2 行、`probe` も 2 枚と報告）、Q2 各シャードの不一致数が 0、Q3 マージ後のカバー数が 2560。

M2（R2、二台構成 5 枚）: 別機の `--probe` は終了コード 0 で、NVIDIA ディスクリート GPU カード 3 枚を報告した（Q4 通過）。本機の 2 シャード（0、1）と別機の 2 シャード（3、4、RTX 5060 Ti × 2）はいずれも成功し、`anchors_cpu_match=true anchors_gpu_match=true sentinel_and_gid_ok=true`、往復ファイル（シャード 3、4 の結果ファイル）の sha256 は両端で 1 つずつ一致、件数は各 512（Q6 通過）。**別機の 3 枚目（RTX 5080、シャード 2、ユニット 1024–1535）は 2 回とも GPU コンテキストを作れなかった**: `request_device` が `RequestDeviceError { inner: Core(Device(OutOfMemory)) }` で失敗。当時このカードの `nvidia-smi` のメモリ余裕は 141 MiB しかなかった（ローカルサービスに使い切られており、登録は「ローカルモデルを止めない」としている）。4 シャード（0、1、3、4）をマージした結果:
```
MERGE total_units=2560 shards=4
MERGE matched_count=2048
MERGE mismatched_count=0 mismatched_global_unit_identifiers=[]
MERGE missing_count=512 missing_global_unit_identifiers=[1024, ..., 1535]
```
カバー数 2048 < 2560 で失敗条項 2 が発動する（Q5/Q7 の閾値は通らない）。**M2 の判定は「できない」（2026-09-27 のビデオメモリ条件下で）**: 二台構成のマルチカード協調そのものが成り立たないのではなく（5 枚中 3 枚が全て成功し、マシン間転送、バイナリコピー、sha256 照合、マージはすべて正しかった）、そのうち 1 枚が当時 wgpu のデバイスコンテキストを確保するだけのビデオメモリを持っていなかった。登録は「ローカルモデルを止めない、構成を変えて再試行しない」と定めているので、この観測は登録の計測条件では「できない」であり、反転条件はそのカードがビデオメモリを空けることである。

M3（F1、F2、いずれも R1 の 2 シャード構成上）:
```
# F1
MERGE mismatched_count=2 mismatched_global_unit_identifiers=[100, 1381]
# F2
MERGE missing_count=1 missing_global_unit_identifiers=[1480]
```
F1 が注入した 2 つのグローバルユニット（100、1381）は報告された不一致集合と 1 つずつ一致し、過剰報告はない。F2 が落としたユニット（1480）は報告された欠落集合と 1 つずつ一致する。**M3 の判定は「赤になる」**: 2 種類の故障をそれぞれ 1 回注入し、照合はどちらも正直に報告した。

### 判定行の名指し（第 4 ステップ 4c）

4 つの成果物で `grep -n 'name=verdict'` は 0 行ヒットした。この装置は `name=verdict` 形式の判定行を書かず、判定は `MERGE ...` 系列のフィールドが直接与える。各成果物で「通らなかった」ことを意味するフィールドを 1 つずつ名指しする:

- `-r1.out`: `mismatched_count=0`、`missing_count=0`、`duplicated_count=0`（いずれも違反類のカウントで値は 0 のため名指ししない。`all_reference_values_distinct=true` は真偽値の真で名指ししない）。**false / not_run のフィールドはない。**
- `-r2.out`: `r2-shard2-failure.out` の段落にある失敗は wgpu の**原文エラー**（`RequestDeviceError`）であり、本装置が書いた判定フィールドではない。登録は「起動できないカードは wgpu の原文エラーを報告する」ことを認めている。マージ部分の `missing_count=512` は、名前が「欠落」を意味する整数カウントで、かつ非 0 なので**名指しする**: ビデオメモリ不足でシャード 2 の結果がまったく出なかったことの直接の結果で、登録の想定内（失敗条項 2 の発動）。
- `-f1.out`: `mismatched_count=2` は、名前が「不一致」を意味する整数カウントで非 0 なので**名指しする**: F1 が意図的に注入した 2 つのビット反転で、照合が正直に報告したものであり、登録の想定内（Q8 通過）。
- `-f2.out`: `missing_count=1` は、名前が「欠落」を意味する整数カウントで非 0 なので**名指しする**: F2 が意図的に落とした 1 件で、登録の想定内（Q9 通過）。

判定行の名指しは計 3 件（`missing_count=512`、`mismatched_count=2`、`missing_count=1`）で、すべて登録の想定内の意図的な注入か既知の環境制約であり、`false` / `not_run` のフィールドはない。

### cargo test がハングする実際のバグの修正（本題外、再実行時に踏み直さないよう本ページに記録）

既定の並列度で `cargo test --release --features e163-gpu --bin e163-gpu-multicard-crc32c` を初めて実行したとき、出力なしで 39 分間ハングした（メイン agent が発見し調査を指示）: GPU を必要とする 3 件の単体テストがそれぞれ `wgpu::Instance` を作り、すべて同じカード（列挙順で 0 番）を選ぶ。既定で並列に走るテストスレッドが同じ物理カード上で同時に `Device` を作り、ディスパッチし、`device.poll(Wait)` を呼び、衝突したあと GPU 側のどこかのブロッキング呼び出しで固まり、エラーもタイムアウトも出ない。修正: この 3 件のテストにプロセス内の `static GPU_TEST_MUTEX: std::sync::Mutex<()>` を追加して GPU へのアクセスを直列化した。修正後、時間制限付きで 4 回実行し、10 項目すべて成功、0.73–1.53 秒。この修正は最終ソースに入っており、未対応事項ではない。

### 経路と結論の登録

| # | 経路 | 計算方法 | ソースの配置先 | 読んだ共用項目 |
|---|---|---|---|---|
| 1 | CPU 参照 | ビット単位・反射型の CRC-32C、初期値 0xFFFFFFFF、出力反転（関数本体は :43 で終わる） | `scripts/experiment-apparatus/e163_gpu_multicard_crc32c.rs:30` `fn crc32c_reference` | D18 (ブロックに含める情報)の確定項目 17 の 4 つのパラメータ（Rust 側の定数、独立に宣言） |
| 2 | GPU シェーダ | WGSL コンピュートシェーダがユニットごとにビット単位で同じ CRC-32C を計算し、バイトは `(word >> 8*(k%4)) & 0xFF` で取り出す（シェーダソースは :273 で終わる） | `scripts/experiment-apparatus/e163_gpu_multicard_crc32c.rs:216` `const COMPUTE_SHADER_SOURCE` | D18 (ブロックに含める情報)の確定項目 17 の 4 つのパラメータ（WGSL 側は定数を別に書き、経路 1 を参照しない） |

経路をまたぐアサーション: 単体テスト `gpu_matches_cpu_reference_on_anchor_vectors` は、2 つの経路の 8 個のアンカー上の出力をそれぞれ `EXPECTED_ANCHOR_VALUES`（登録の第 7 節 B 類。2 経路の相互比較ではない）と 1 つずつ照合する。`merge` サブコマンドの `compare_reference_and_shards` は、GPU の結果を CPU がその場で計算した参照とユニット単位で照合する（2560 個の値、バッチ全体を走査し、抽出点ではない）。結論「R1 の全 2560 ユニットについて、アーム C とアーム G は 1 つずつ同一」は全称であり、X の取りうる値はこのバッチの全 2560 個を走査したものである。

⚠️ 2 つの経路が共有しているのは、「D18（ブロックが運ぶ情報）の確定項目 17 の 4 つのパラメータ値そのものが正しい」という 1 つの前提である。kb のこの 4 つの値自体が誤って書かれていれば、独立した 2 つの実装は同じ誤った値でそれぞれ 1 つずつ書き、健全な入力では互いに一致し続ける（D13 (検証ルート)の確定項目 5 が警告する類の偽の赤）。ミューテーション「アーム C とシェーダを同じ誤った多項式に同時変更する」がこれを示している。相互比較系のテストはすべて緑で、`EXPECTED_ANCHOR_VALUES` に対する絶対値の検査だけが捕捉する。この検査（`crc32c_reference_matches_prereg_anchor_vectors`、`gpu_matches_cpu_reference_on_anchor_vectors`）は欠かせない。

### 答えられないこと

- ビデオメモリが十分にあるとき、二台構成 5 枚がすべて成功するか: 今回唯一失敗したカード（RTX 5080）はビデオメモリの余裕が 141 MiB しかなく、これはローカルサービスの占有によるもので、本装置や wgpu/Vulkan 経路自体の制限ではない。ビデオメモリを空けたあとの再実行はしていない。
- 速度、スループット、マルチカードの CPU に対する利得: 登録は「できるかどうかだけを問い、速度の閾値は設けず、所要時間は報告するだけで判定しない」と定めている。所要時間の数値は成果物にあるが判定基準はない。
- ユニット長、ディスパッチ粒度、バッチサイズへの感度: N=2560、1 回のディスパッチ 128 ユニット（シェーダは実際には 64 個ずつの組で動く。ワークグループサイズを参照）、32768 バイトのユニットでしか実行していない。登録の第 8 節は「幾何感度なし」と明記している。
