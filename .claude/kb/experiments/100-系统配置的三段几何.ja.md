### 判定基準（実行前固定、実行後変更禁止）

1. **収まるか否かは絶対値として計算せよ**：3段のバイト数の合計 vs スロット幅（`physical_block_size` の検出から得られる 512 / 4096 の2段階）。**「収まる / 何バイト超過か」をセルごとに報告せよ、「不足する可能性がある」と述べるにとどめることを禁ず。**
2. **デバイス表はここで唯一規模に伴い増大する要素である**：デバイス数 1 / 2 / 8 / 64 / 256 × エントリ幅 24 / 40 / 64 をスキャンし、**最初にスロットから溢れるセルをカウントせよ**。これは絶対値であり、トレンドではない。
3. **打開策アーム**：デバイス表をスロット外へ移動（システム構成にはデバイス表ユニットを指すポインタを1つのみ格納、D22 (ユニット原子性の合成方法) 確定項目 7 のツリーテーブルユニット間接層と同形態）、3段のバイト数は**デバイス数と無関係な定数**となり、2段階のスロット幅で常に収まらなければならない。
4. **原子性判定基準**：`.claude/rules/fs-design.md` の「使用を誤ったときマウント不能にできるか」はここでは**1スロットは厳密に1セクタでなければならない**という形態を取る。3段が1セクタを超える場合、スロットローテーションは原子的ではなくなる ⇒ **モデルは「複数セクタにまたがるスロットが断裂点において何種類の読み取り可能だが不一致な状態を持つか」をカウントせよ**、絶対値。
5. **ブートストラップ順序**：第1段のフィールドは**デバイス表を読み取る前に**解決できなければならない。モデルは「パーサが先頭 N バイトのみを読み取る」として判定し、N を段階的に増大させ、「fsid を判定可能 / dev id を判定可能 / feature bits を判定可能」となるためにそれぞれ第何バイトまで読み取る必要があるかを報告。

### 失敗条項（実行前固定）

| 条項 | トリガー時の判定方法 |
|---|---|
| **陽性対照**：デバイス表をスロット内に残し、デバイス数を 64 とした場合、512 バイトスロット上で必ず溢れと判定；移動後は溢れなしと判定 | 不成立 ⇒ スロット幅という次元がモデルに入っておらず、**ラウンド全体を無効とする** |
| **陰性対照**：デバイス数 1、エントリ幅 24、4096 スロットの場合、必ず収まると判定 | 溢れと判定 ⇒ モデルが最も緩やかなセルで既にエラーを起こしており、ラウンド全体を無効とする |

### 実測（2026-09-03、純算術、N=5 ラウンドでバイト単位で一致、9単体テスト / 6件ミューテーション全検出）

**計測条件と再実行**：コード `scripts/experiments/e100_system_configuration_slot.rs`、成果物 `research/results/e100-system-configuration-slot-2026-09-03.out`（127行、末尾 `emitted=127`）、ミューテーション表 `scripts/mutation/tables/e100_system_configuration_slot.tsv`、`scripts/experiments/replay.sh` に組み込み済み。

#### 判定基準 1：各段の絶対バイト数

| 段 | バイト | 内訳で最大のもの |
|---|---|---|
| 一 ブートストラップヘッダ | **162** | **feature bit 96**（D15 (フォーマット凍結ポリシー) 逐字：3つのビットマップが各 256 ビット）|
| 一 の D9 (暗号化) 予約 | 24 | MAC 16 + nonce 水位 8（D9 (暗号化) 確定項目 8 + D15 (フォーマット凍結ポリシー) 損切り規則）|
| 二 幾何（デバイス表を除く）| 127 | ツリーテーブルユニットポインタ 59 |
| 三 調整可能値 | 36 | — |
| **四 実行時水位** | 12 | journal tail 8 + インスタンスコード 4 |

固定オーバーヘッド合計 **361 バイト**。⚠️ **第4の分類は今回新たに追加されたものである** —— 3段軸（誰が変更可能か）は tail スロットのような「チェックポイントごとに1回変更」されるフィールドを収容できず、それは不変でも、mkfs 読み取り専用でも、手動調整可能な値でもない。

#### 判定基準 2 + 3 + 4：デバイス表をスロット内に残すと収まらず、移動すれば恒等的に収まる

512 バイトスロット、24 バイトデバイス表エントリ、D9 (暗号化) 予約を含む：

| デバイス表 | 1 台 | 2 台 | 8 台 | 64 台 | 256 台 |
|---|---|---|---|---|---|
| **スロット内に残す** | 385 ✓ | 409 ✓ | **553 ✗ 溢れ 41** | 1897 ✗ 溢れ 1385 | 6505 ✗ 溢れ 5993 |
| **間接層を経由** | **420 ✓** | 420 ✓ | 420 ✓ | 420 ✓ | 420 ✓ |

⇒ **512 バイトスロット上において、デバイス表インラインの上限はエントリ幅に連動する**：24 バイトエントリで **6 台**、40 バイトで **3 台**、64 バイトで **2 台**（`361 + デバイス数 × エントリ幅 ≤ 512`、単体テスト `criterion2_inline_device_table_overflows_a_512_byte_slot_early` で固定）。
⚠️ **E100 (システム構成の3段幾何) 判定基準 2 のスキャンセットは {1, 2, 8, 64, 256} のみであり、3–7 台は未実行** ⇒ 表からは上限を読み取れず、「2台は収まり、8台は収まらない」ことのみが読み取れる。**上限は計算によって算出されたものであり、スキャンされたものではない。**

**セクタにまたがるスロットは原子的ではない**（D20 (耐荷重面：ユニットの原子性と自己完結性) 系 3：断裂判定幅 = `physical_block_size`）：n セクタにまたがるとき `2ⁿ − 2` 種の読み取り可能だが不一致な状態が存在する —— 8 台で **2 種**、64 台で **14 種**、256 台で **8190 種**。間接層を経由する場合は恒等的に **0**。

⚠️ **これはルートレコードが既に踏み抜いて否定されたのと同一の形状である**：C78 (ルートレコードにフィールド表がない)（2026-10-11 に C66 (フォーマット級の空白に分項番号がない) に統合済み、原文は git 履歴内）は E79 (ルートレコードの容量) の際の「512 バイトスロットには 6 ツリーしか収まらず、7 ツリーで 43 バイト溢れる ⇒ **間接層は構造的に不可避**」を逐字的に記録している。

#### 判定基準 5：ブートストラップ順序

第1段が宣言順序に従って配置されている場合、パーサは第 **4** バイトまで読み取って初めて magic を判定でき、第 **6** バイトでフォーマットバージョン、第 **102** バイトで feature bits、第 **118** バイトで fsid、第 **122** バイトで自ディスクの dev id を判定できる。

### それが答えられないこと

純算術：mkfs なし、マウントなし、実機デバイスなし、ファイル操作 0 箇所。
**「ディスク追加時にデバイス表をどのように変更するか」のトランザクション形態には答えない** —— それはクラッシュポイント再生の役割である；E100 (システム構成の3段幾何) は「それが原子的スロット内にあるか否か」および「ない場合に何通りの断裂読み取りモードが存在するか」のみを答える。
