### Measured Results (1 Million Leaves, 40-Byte Pointers, Byte-identical across Three Rounds)

**Crossover Point (proportion of affected entries at which range rebuild starts saving more)**:

| Node | Contiguous Entries | Scattered Entries |
|---|---|---|
| 4 KiB | **1000‰** (cost-effective only when modifying all) | **10‰** |
| 16 KiB | **1000‰** | **3‰** |

**Two Conclusions**:

1. **Crossover point is determined by "layout" and "node size"**, differing by more than two orders of magnitude between the two:
   under contiguous layout, item-by-item shares leaves and spines, remaining cheaper all the way to 100%; under scattered layout, nothing is shared, so whole-segment rebuild is warranted at 0.3–1%.
2. **Larger nodes yield earlier crossover points for scattered entries** (10‰ → 3‰): larger fanout ⇒ relatively fewer nodes in whole-segment rebuild.

⚠️ **E30 (Write Amplification Half of the Crossover Point) cannot be used to falsify the document statement "approx 1% for HDDs, approx 10% for SSDs"**:
that statement refers to the crossover point in **elapsed time**, where media affects time rather than write amplification.
E30 (Write Amplification Half of the Crossover Point) counts nodes only, **saying not a single word about the media dimension**.
What can be stated is: **under the write amplification measurement basis, independent variables of the crossover point are layout and node size, not media.**

### Measurement Basis and Known Limitations

- Pure counting, counting **written node tallies**, not time nor I/O count.
- Item-by-item modification assumes entry distributions fall only into the two extremes of "completely contiguous" and "completely scattered", **whereas actual distribution lies in between**.
- Code `scripts/experiments/e30_range_rebuild.rs` (`cargo run --release --bin e30_range_rebuild`),
  raw output `e30-range-rebuild-2026-08-29.out`. Three rounds byte-identical.
- 8 unit tests; mutation table `scripts/mutation/tables/e30_range_rebuild.tsv` catches all 7 mutations
  (reconstructed and committed 2026-09-03—the earlier 3-row table was deleted by a concurrent workflow, leaving only text in the body, isomorphic to C43 (Nobody judges whether named artifacts still exist);
  an added unit test pins scattered leaf count ceiling, where K exceeding leaf count was previously present only in output files). ⚠️ One modeling mistake caught by tests on the spot:
  first version confused "K **entries**" with "K **leaves**", so contiguous layout at 100% touched only 1/fanout of leaves,
  causing crossover point never to appear.
