## E128 出生 (ツリー, txg) 付与ポインタのポイント検索コスト —— 実施済 (2026-09-10、15 単体テスト / 14 ミューテーション全捕捉；**記帳のペアは4ラウンド同方向、inodeのペアは4ラウンド不安定**)

[中文](128-指针带出生树txg之后的点查代价.md) · [English](128-指针带出生树txg之后的点查代价.en.md) · **日本語**

**答える対象は D19（ブロックポインタ構造と幅予算） 確定項目 7 の未済の負債である**：候補甲がポインタヘッダを 31 → 47 に拡張し、
連動して inode ツリー内部エントリを 93 → 109、記帳ツリー内部エントリを 81 → 97 に拡大するが、**このステップが 1 回のポイント検索の CPU 時間をどれほど増加させるか**。
ユーザー決定はそのマスを「暫定未確定、別ラウンドで検証」と判定し、理由は逐字的に
「甲の 1 つの代償（E20（ポインタ肥大化のCPUキャッシュコスト） の実測で 16 KiB ノード上の 67 バイトエントリが 2.22 倍）が
**いかなる検証脚の資料にも一度も含まれていなかった**」であった。
E128（出生 (ツリー, txg) 付与ポインタのポイント検索コスト） は**コストのみを提示し、判定は行わない** —— 判定は三者検証を経る必要がある
（`.claude/rules/three-way-inference.md`）。

### なぜ別番号を立項し、E20 にアームを追加しなかったのか

E20（ポインタ肥大化のCPUキャッシュコスト） の判定基準は 2026-08-29 に確定済、成果物は保管済、`replay.sh` に登録済であり、
E95（ノード配置のエージングアーム） のアーム欠落時に E127（分割統合下でのグループID保存要否） を別立項したのと同一の理由である。

**さらに E20（ポインタ肥大化のCPUキャッシュコスト） はこの項目を測定していない**：その階層は 16 / 24 / 32 / 40 / 67 / 111 であり、
本プロジェクトの実際の 2 組である 93 → 109 および 81 → 97 は**1 つも含まれていない**。
67 と 111 の 2 つの比率で代用することは、別の量の数値でこの問いに答えることに等しい。

### 判定基準、閾値、破棄条件（いかなる測定コードの記述前にも確定済）

原本 `e128-preregistration.md`、実施後一字一句変更なし。4 箇条：
① 6 本のアームそれぞれの陽性対照（L1 階層が DRAM 階層より ≥ 2 倍高速）、いずれか 1 マスでも不合格ならラウンド全体を破棄；
② **装置間照合ゲート** —— `xdev_67` と `xdev_111` は E20（ポインタ肥大化のCPUキャッシュコスト） 保管成果物の 2 数値に回帰しなければならない（誤差 ≤ 15%）；
③ 絶対値アサート、スロット数とツリー深度を階層ごとに固定し「6 アーム同時の誤り」を防止；
④ 5 ラウンド実行、「甲が低速」と主張するには 5 ラウンドすべて低速、「低速でない」と主張するには 5 ラウンドすべて低速でないことが必要であり、いずれも満たさなければ「不安定」と記録。

⚠️ **「どれほど低速なら受容可能か」の閾値は実施前に意図的に設けていない**：その数値は判定に属し実験に属さない
（`.claude/singlefs-ai-sop/rules/test-discipline.md`「失敗条件は結論を反証不能にしてはならない」）。
⚠️ **逆の結果を受容することを実施前に明記**：原本逐字「もし `inode_jia` が `inode_bing` より**高速**、または差が **< 2%** の場合：
『**甲のこのキャッシュ代償は 16 KiB ノード上では成立しない**』と記録する……**これは受容すべき結果であり、回避すべき結果ではない**」。
**実測はまさにこのマスであった。**

`published_fanouts_come_out_of_the_same_header_constant` で固定。

### 実測（成果物 `e128-pointer-birth-cost-2026-09-10.out`、134 行、`emitted=134`）

**結論 1：inode ツリーのペア（93 → 109）は不安定であり、E128（出生 (ツリー, txg) 付与ポインタのポイント検索コスト） はこのマスに回答できない。**
**4 回の全ラウンド**を実行し、先頭 3 ラウンドは「甲は一切低速化せず」と判定、第 4 ラウンドは「甲は全ラウンドで低速化」と判定し、方向が反転した。
**ラウンド別推移表**（再実行で再反転した際はこの表に行を追加）：

| ラウンド | 成果物 | inode 比率 | 判決 |
|---|---|---|---|
| 1 | 未保管（`tree_per_level` 削除前のソースコード） | 0.9686 | `0/5 jia_never_slower` |
| 2 | 未保管（`replay.sh` 検証ラウンド、第 1 ラウンドと同ソース） | 0.9655 | `0/5 jia_never_slower` |
| 3 | `e128-pointer-birth-cost-2026-09-10.out` | 0.9764 | `0/5 jia_never_slower` |
| **4** | `e128-pointer-birth-cost-2026-09-10-rerun4.out` | **1.0885** | **`5/5 jia_slower_every_round`** |

⇒ `.claude/singlefs-ai-sop/rules/test-discipline.md`「『合格』と言うなら全ラウンド合格、『失敗』と言うなら全ラウンド失敗でなければならない……いずれも満たさない場合は『不安定』と事実通り記録し、結論を出してはならない」に従い —— **このマスは「不安定」と記録し結論を出さない。**

第 3 ラウンドと第 4 ラウンドの成果物逐字記録：

```

E7RESULT name=verdict pair=inode bing_median=612.09 jia_median=667.30 ratio_median=1.0885 ratio_min=1.0283 ratio_max=1.1017 rounds_jia_slower=5/5 verdict=jia_slower_every_round
```

⚠️ **未検証の候補説明、記録するが採信はしない**：第 4 ラウンドでマシン全体が低速化 —— 装置間照合ゲートの 2 段階が E20（ポインタ肥大化のCPUキャッシュコスト） の基準より 4.9% および 5.9% 高く
（前 3 ラウンドは −2.4% 〜 +2.6%）、`inode_jia` のワーキングセット（929 MB）が `inode_bing`（790 MB）より大きく、
ローカルで当時別セッションがビルドを実行中であった。**これは単なる候補である**：E128（出生 (ツリー, txg) 付与ポインタのポイント検索コスト） は当時のマシン負荷を記録しておらず、
「マシン全体の低速化により大ワーキングセット側がより大きな不利益を被った」という言明は**証明も反証も不能**である。配置先 C252（E128 の inode ペアが不安定、装置が負荷を隔離していない）に記録。

⚠️ **この反転はバイト単位の照合により捕捉されたものであり、区間アサートによるものではない**：`replay.sh` の `strip_timing` は意図的に `verdict=`
および `rounds_jia_slower=` の 2 フィールドを**消去しない**（これらは結論であって計測時間ではない）⇒ 判決の反転は構造比較ステップで赤判定となった。
仮にこれらを一括消去していた場合、第 4 ラウンドは「時間のみ相違、構造一致、宣言適合」として緑判定で素通りしていた。

**結論 2：記帳ツリーのペア（81 → 97）は 4 ラウンド同方向であり、甲は全ラウンドで低速化**、比率は 1.0179 / 1.0454 / 1.0210 / 1.0357。
⇒ 同一の規律に基づきこの条項は**成立する**：4 ラウンドすべて同一方向を判定。成果物逐字（第 3 ラウンド）：

```

```

**結論 3：装置間照合ゲートは 4 ラウンドすべて合格**、4 ラウンドの偏差は −2.4% / +2.6%、−1.9% / +3.0%、−0.2% / +1.4%、**+4.9% / +5.9%**。
⚠️ **合格したが、同時に「第 4 ラウンドでマシン全体が低速化」を記録した唯一の要素である** —— 15% の許容誤差はこのマスに対して十分に広く、
5〜6% の全体ドリフトを素通りさせ、そのドリフトは inode ペアの反転と同ラウンドで発生した。成果物逐字（第 3 ラウンド）：

### ⚠️ 第 3 ラウンド成果物に非単調性が 1 箇所存在、説明なしに事実通り提示

第 3 ラウンドにおいて、同一 16 KiB ノード、同一ツリー深度 4 のとき、93 バイトエントリ（586.89 ns）は **109 バイト（572.95 ns）
および 111 バイト（555.26 ns）の双方より低速であった**；**第 4 ラウンドでこの非単調性は消失した**（612.09 対 667.30）。E20（ポインタ肥大化のCPUキャッシュコスト） の列は 67 → 111 の間で単調増加していたが、ここではそうではない。
未検証の仮説として、ノードの 16384 アライメント、エントリのストライド、キャッシュのアソシアティビティの相互作用が挙げられる。
⚠️ **ラウンドを跨いで再現しないため、E20（ポインタ肥大化のCPUキャッシュコスト） の 8 KiB の異常とは性質が異なる** ——
あちらは 6 ラウンド安定していたが、こちらは 4 ラウンド中 3 回出現し第 4 ラウンドで消失した。**両者を並列引用することは禁止される。**

### 本モデルは E20 の手書き複製であり、装置間照合ゲートで担保

`Tree` / `generate_lookup_keys` / `bench` の 3 セクションは `e20_fanout.rs` と同源であり、統合されていない。
理由は E20（ポインタ肥大化のCPUキャッシュコスト） のミューテーション表が**原文一致**でファイルを改変するためであり、
それら 3 セクションを移動すると E20（ポインタ肥大化のCPUキャッシュコスト） の保管済 5 件のミューテーション証明が即座に不一致となる。
代償は手作業複製であり、下支えは装置間照合ゲートである。⚠️ **ゲートは DRAM 階層の 2 点のみを固定**しており、他階層での複製漏れには無反応であり、
配置先 C249（2つのポイント検索モデルが同一のレイアウトコードを手作業複製、ゲートは2点のみ固定）に記録。

### 計測条件と再実行

純 CPU / メモリ実験、配列として展開された暗黙的 B ツリー、ノード内二分探索、エントリ幅によるストライド、
エントリの第 2 の 8 バイトに子ノード番号を格納（依存ロードチェーンを形成）。**key 数を固定、ワーキングセットは非固定** ——
エントリ幅拡大 ⇒ ワーキングセット拡大 ⇒ キャッシュ溢れ、これこそが測定対象である。
ローカルのコアあたり L1d 48 KiB、L2 1 MiB、L3 32 MiB、キャッシュライン 64 バイト。
ワーキングセットは 2¹¹ / 2¹⁵ / 2¹⁹ / 2²³ keys の 4 階層、階層ごとに 5 ラウンド、ラウンドごとに 3 回の最小値を採用、`iters = 2000000`。

コード `scripts/experiments/e128_pointer_birth_cost.rs`
（`cargo run --release --bin e128-pointer-birth-cost -- 2000000`）、
生出力 `e128-pointer-birth-cost-2026-09-10.out`（第 3 ラウンド、保管済）
および `e128-pointer-birth-cost-2026-09-10-rerun4.out`（第 4 ラウンド、方向反転版）。
前 2 ラウンドは `tree_per_level` 削除前のソースで実行、**成果物は未保管**。

```bash
bash scripts/experiments/replay.sh E128
```

⚠️ **E128（出生 (ツリー, txg) 付与ポインタのポイント検索コスト） の再実行は断続的に赤判定となるが、これは意図的でありノイズではない。**
inode ペアの `verdict=` はバイト単位の構造比較に参加しており、本質的に不安定であるため ⇒ **方向が反転するたびに赤判定となる**。
赤判定時に行うべきことは許容誤差を広げることでは**なく**：新実行の比率と判決を **E128（出生 (ツリー, txg) 付与ポインタのポイント検索コスト）
「結論 1」のラウンド別推移表に追加し**（4 ラウンドが 5、6 ラウンドへ……）、保管成果物を差し替えるか否かを判断することである。
**毎回の赤判定は新たな観測である** —— 「不安定」と記録された実験にとって、これこそが再実行のあるべき挙動である。
逆にこれら 2 フィールドを消去して恒久的に緑判定とすることは、何も証明しない版を作成することになる。

`replay.sh` の区間アサートが固定するのは**4 ラウンドで安定しているもの**である：装置間照合ゲートの両マスが `ok=true`；
記帳ペアの比率が (1.00, 1.10) に収まること。**inode ペアの方向は固定しない** —— 4 ラウンド中 3 ラウンドがある方向、1 ラウンドが逆方向であり、
どちらを固定しても不安定な観測をアサートとして固定することになる。⚠️ 構造比較ステップは依然として `verdict=` および
`rounds_jia_slower=` を逐字比較する（`strip_timing` は意図的にこれらを消去しない）⇒ **判決が再反転すれば、再実行は依然として赤判定となる。**
