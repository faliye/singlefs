## E79 Capacity of Root Record —— Run (2026-09-02; 2026-09-06 recomputed per position entry 14, pure arithmetic, 8 unit tests / 6 mutations caught): **512-byte root slot only holds 6 trees (still 6 trees with watermark removed); 7 common-sense trees explode by 43 bytes; per-head trees rapidly puncture flat form**

[中文](79-根记录的容量.md) · **English** · [日本語](79-根记录的容量.ja.md)

New-pool file creation immediately requires writing to the root slot, yet **the field table for root records has never been settled anywhere in the repository** (grep confirmed: only a single mention in I-7.2 (Latest Root Fully Traversable) "starting from checkpoint tree root pointer" touches upon its content). Three settled clauses elevate this omission into a capacity problem: slot width = `physical_block_size` (D22 (How Unit Atomicity is Synthesized) settled item 2, measured at 512 on this machine); tree table opened day-1 (D15 (Format Freeze Policy) settled item 2); one dedicated tree per head (D6 (Snapshot Implementation Model) settled item 1). E79 (Capacity of Root Record) lays out the arithmetic.

### Measurement Basis (Field Widths Are Inputs, Not Conclusions; All Have Citations)

Fixed header 76 bytes (magic 4 + fsid 16 + flags 4 + publish generation 8 + checkpoint_txg 8 + tree count 4 + self-witnessing checksum 32, with checksum width matching `header_csum` from E23 (Journal Geometry)); carrying jsn watermark (E78 (Starting Point for Replay) resolution B) +10 = 86. 67 bytes per tree (tree_id 8 + pointer header 31 + position entry 14 × 2 replicas; position entry width per D19 (Block Pointer Structure & Width Budget) settled item 4, remaining byte-by-byte table per D21 (Boundary Between Authoritative and Derived States), 2 replicas per D2 (RAID Striping Strategy) settled item 9 v1 2 disks).

### Actual Run (Criteria: All Numbers Pinned by Manual Anchors; Reports Numbers Without Judging Selection)

| Form | 512 Slot | 4096 Slot |
|---|---|---|
| Flat, with watermark | **6 trees** | 59 trees |
| Flat, without watermark | **6 trees** | 60 trees |

- **7 common-sense trees (extent / inode / dirent / reverse index / free / accounting / allocation record) + watermark = 555 bytes, exceeding 512 by 43 bytes.** The v1 minimal tree set (accounting + allocation record + data extent = 3 trees) fits.
- **What crushes flat form is entry width, not watermark**: the 512 slot holds 6 trees with watermark, and **remains 6 trees even with watermark removed**—the watermark displaces zero trees at this slot width.
- **Per-head trees rapidly puncture flat form**: 7 base trees + 8 writable heads = 15 trees, which neither form can fit in a 512 slot; 4096 slot cap is 59 trees with watermark / 60 trees without (tops out at just 52 heads).
- **Indirect layer** (root slot holds only a single pointer to a "tree table unit"): 16 KiB tree table unit holds **243** trees (calculated with current header width 68 for index node class per D18 (Information Carried in a Block) settled item 7: (16384−68−32)/67 = 16284/67 = 243).
  ⚠️ **The three tiers 68 / 77 / 86 are no longer identically valued across cells**: they are **243 / 242 / 242** respectively, differing in capacity by one tree—the statement "capacity is not determined by tier" at entry width 61 does not hold at 67.
  The cost is **one additional 16 KiB unit COW per publish**—calculated against 14 blocks per fsync per D25 (Target Workload Priority), this is **+7.1%**. When trees exceed 243, embed another level, with a two-level ceiling of 243² ≈ 59k trees.
  ⚠️ **2026-09-13**: This set of 243 is calculated with legacy entry width 67 (tree ID 8 + root pointer 59); D22 (How Unit Atomicity is Synthesized) settled item 7 changed to calculate at 112 trees/level using 145-byte entries from D8 (Core Index Structure) settled item 8; the 243 here is obsolete, and adding a tier re-run is owed in C148 (Widening Tree Table Entries Compresses Indirect Threshold to Two Levels) (formerly C157 (Tree Table Capacity Calculated Under Different Entry Widths in Two Places), merged 2026-10-11).

### Conclusion

Root record **flat form cannot accommodate what this design itself has settled** (open tree table × per-head tree × 512 slot); an indirect layer is structurally unavoidable, with a cost of +7.1% blocks/publish.
**Field table settled (2026-09-02): permanently adopt indirect layer, authoritative record in D22 (How Unit Atomicity is Synthesized) settled item 7**; remaining owed check (reverse verification tooling) see [checks-owed.md](../checks-owed.md) C66 (Format-Level Blank Lacks Item Number) (formerly C78 (Root Record Lacks Field Table), merged 2026-10-11).

### What It Cannot Answer

tree_id width is not settled in the repository (taking 8 bytes is an assumption; narrowing by one or two bytes does not change the order of magnitude); crash consistency of the tree table unit itself is governed by barrier conclusions in E77 (Persistent Order of Publishes); "which trees are hot enough to justify inlining into the root slot (hybrid form)" was not modeled.
