## E60 加盘之后不搬数据的代价 —— 已跑（2026-08-31，N=5 种子，10 单测 / 5 条变异全抓）：**不搬的代价不是慢，是新盘的 60% 买不到**

D2（RAID 条带策略） 已定项 4 c（2026-08-31 用户定案）定了「不搬数据，新数据优先落新盘」，
用户同时要求「测一下性能，性能差也可以搬」。

### 要测什么

| # | 量 |
|---|---|
| 1 | 加盘之后**还能写进去多少用户数据**（三条分配策略各一次） |
| 2 | **物理格 / 数据格**（parity 开销） |
| 3 | **搁浅容量**：再也凑不出宽度 ≥ 2 的条带时，剩下多少空闲格 |
| 4 | 搬平的**一次性搬动量**——那是不搬省下来的东西，不报出来就是只算了一边的账 |

### 判据（跑前写死，跑完没改）

| # | 判据 |
|---|---|
| 1 | 三臂按「写下同样多的用户数据各消耗多少物理格」比 |
| 2 | 甲相对丙**高 ≥ 10%** ⇒ 判「不搬的代价显著」，D2（RAID 条带策略） 已定项 4 c 要重开 |
| 3 | 高 **< 10%** ⇒ 判「代价不显著，维持不搬」。**这句写在跑之前：反过来的结果接受** |
| 4 | 丙的搬动量必须一并报出 |
| 5 | 各臂的搁浅容量必须报出 |

### 怎样才算失败（跑前写死）

| 条款 | 触发时怎么判 |
|---|---|
| **守恒**：各设备已用格增量之和 ≠ 记账的物理格数 | **整轮作废** |
| **阳性对照，对每一条臂都跑**：新盘容量 0（等于没加盘）⇒ 四臂都退化成 4 盘池的数、丙搬动量为 0 | 任一臂不满足 ⇒ **整轮作废** |
| **阴性对照**：加盘时旧盘也空（没有不均衡）⇒ 丙搬动量 0 | 非 0 ⇒ **整轮作废** |
| 5 个种子结论方向不一致 | 报「不稳定」，不下结论 |

### 模型

4 块旧盘各 1000 格、加盘前填到 90%，新盘 1000 格空。一条条带在参与的每块盘上各占一格，
`w` 格里 1 格 parity、`w−1` 格数据（D2（RAID 条带策略） 主结论：全条带写、永不 read-modify-write）。
写入 payload 每次 1..8 格随机（5 个种子）。写到再也凑不出 `w ≥ 2` 的条带为止。

| 臂 | 策略 |
|---|---|
| 甲 | **不搬 + 优先新盘**：窄条带（宽度 2 或 3）落在剩余空间最多的那几块盘上 |
| 乙 | **不搬 + 不偏向**：每条条带用上所有还有空闲的盘 |
| 丙 | **搬平后全宽**：注水法搬平，再按乙写 |

### 实测（2026-08-31，N=5 种子）

#### 结果一：一条与分配策略无关的算术上界

**不搬数据时，新盘最多只能吸收「其余盘剩余空闲之和」那么多格。**
机制：一条有冗余的条带至少要两块盘各出一格 ⇒ 新盘每写一格，就要有另一块盘同时出一格。

4 盘各 1000 格、填到 90% ⇒ 其余空闲 400 格 ⇒ **新盘 1000 格里 600 格永远用不上（60%）**。
旧盘越满这个比例越糟：填到 95% 时是 80%，填到 99% 时是 96%。

⚠️ **甲不是稻草人臂**：窄条带 w=2 **恰好打到这个上界**（新盘吸收 400 = 4 × 100，一格不多一格不少）
⇒ 它是**不搬情况下最优的策略**，不是随手挑的差形态。

#### 结果二：三臂逐格

| 臂 | 加盘后还写得进去的用户数据（格） | 物理/数据 | 平均宽度 | 搁浅（全在新盘） | 一次性搬动 |
|---|---|---|---|---|---|
| 甲 窄条带 w=2 | **400**（5 个种子全部相同） | **2.000** | 2.0 | **600** | 0 |
| 甲 窄条带 w=3 | 358–362 | 1.657–1.676 | 3.0 | **800** | 0 |
| 乙 全宽不偏向 | 294–302 | 1.656–1.701 | 5.0 | **900** | 0 |
| 丙 搬平后全宽 | **819–837** | 1.673–1.709 | 5.0 | **0** | **720** |

⇒ **丙比最好的不搬策略多写进去 2.05–2.09 倍的用户数据**，代价是一次性搬 720 格
（旧盘已用量 3600 格的 20%）。

#### 结果三：按跑前写死的判据判，两条甲判反了

| 臂 | 物理/数据 相对丙 | 判据 2 / 3 判定 |
|---|---|---|
| 甲 w=2 | **+18.3%** | 判「代价显著」⇒ 已定项 4 c 要重开 |
| 甲 w=3 | **−2.0%** | 判「代价不显著」⇒ 维持不搬 |

⚠️ **判据 1–3 只盯了 parity 开销这一维，而决定性的是搁浅容量那一维**（判据 5 只要求报出、没设阈值）。
按 `.claude/singlefs-ai-sop/rules/test-discipline.md`「不许回头改判据——改了就是新实验」，
这里**如实并列**：判据判出的是分裂结果，而判据没覆盖的那一维给出的是 2 倍差距。
**要把搁浅当判据，得另立实验。**

#### 对照逐条判定

| 条款 | 判定 |
|---|---|
| 守恒（物理格数 = 条带占用之和） | **通过**，三臂各自成立 |
| **阳性对照，四条臂都跑**：新盘容量 0 | **通过**，四臂全部退化成 4 盘池、丙搬动量 0 |
| 阴性对照：均衡池 ⇒ 搬动量 0 | **通过** |
| 5 个种子方向一致 | **一致**：搁浅与数据量的排序在 5 个种子上完全相同 |

#### 变异测试：5 条，最后全抓，但有一条第一次没抓到

| # | 变异 | 结果 |
|---|---|---|
| M1 | 上界改成整块新盘 | 抓到 |
| M2 | 窄条带不截宽 | 抓到 |
| M3 | 条带按 `w` 格计数据（不扣 parity） | 抓到 |
| M4 | 搬平不夹容量 | 抓到（**这条是真 bug，第一次跑阳性对照时就红了**：新盘容量 0 时它搬了 200 格） |
| M5 | 选盘那一步的宽度下界放开到 1 | **第一次没抓到** |

⚠️ **M5 值得单记**：`no_arm_emits_width_one` 判的是跑完之后的最小宽度，
而 `run()` 里还有第二道同样的 `set.len() < 2` 闸，**把选盘那一步的错误吃掉了**——
两道闸都对时看不出来，删掉一道也看不出来。补了一条**直接钉在选盘那一步**的测试
（`choose_refuses_width_one`）之后才红。

### 它答不了的那一半

1. **这是分配层的计数模型，不是吞吐测量**：没有文件系统、没有块设备、文件操作 0 处。
   它给的是物理格消耗、条带宽度、搁浅容量，**不是 MB/s**。真吞吐要等事务层 + QEMU。
2. **不建模读**：「新数据集中在少数盘上 ⇒ 读并行度低」这一维只由平均宽度间接反映，没有直接量。
3. 不建模碎片、不建模后台整理（D3（空间分配） 第 2 条那条常驻整理管碎片，不管盘间均衡）。
4. **填充率是输入不是测量**：90% 是设的，不是本工程实测的典型值。
