## E41 ルートリングスロット幾何 2×4×256 —— 実行済み（2026-08-30、N=5 ラウンドでバイト完全一致）：ティア分離判定赤、スロット幅 256 < アトミック幅

[中文](41-根环槽几何2x4x256.md) · [English](41-根环槽几何2x4x256.en.md) · **日本語**

**問い**: D22 (ユニット原子性の合成手法) 確定項目 2 の候補形態（逐字: 「**2 領域 × 4 スロット × 256 バイト = 2048 バイト**」）が成立するか。

⚠️ **E34 (ルートリングスロット幾何) との役割分担**: E34 (ルートリングスロット幾何) が問うのは**スロット幅とデバイスマッピングユニットの関係**（メカニズム推論であり、ホスト側の `io_min == physical_block_size == 512` では反証不能、かつ2つのクラウド脚が未済）；**E41 (ルートリングスロット幾何 2×4×256) が問うのは、その具体的なパラメータの組み合わせがクラッシュとブロック再利用という2つの制約下で十分であるか**という、モデル化可能な半分である。

### 測定対象、判定基準、失敗条項

- **測定対象**: `2 領域 × 4 スロット × 256 バイト` でルートリングをモデル化し、fsync レートとチェックポイント間隔をスイープして、以下の3点を測定する:
  1. **1周の所要時間**（= 8 スロット ÷ ルート発行頻度）；
  2. **ブロック再利用遅延**: I-7.4 (直近 K 世代のブロック未再利用) は直近 K 世代のルートが参照するブロックの再利用を禁じており、K とスロット数は同源である ⇒ 1周の所要時間が再利用遅延の上限となる；
  3. **1回の断裂書き込みで破壊されるスロット数**（`スロット幅 / アトミック幅` で算出、ホストの 512 およびアレイで一般的な 4096 / 65536 の3段階）。
- **判定基準**:
  - **幾何学的充足性**: 1周の所要時間 **≥** 最悪ブロック再利用遅延要件（D22 (ユニット原子性の合成手法) 確定項目 2 自らが記述したもの）。
  - **断裂分離**: 1回の書き込みで破壊されるスロット数が **1** でなければならない。
    ⚠️ ホスト側の `physical_block_size = 512` に対し候補スロット幅は 256 ⇒ **この項目は赤判定となる想定**であり、それこそが測定すべき事項であって実装バグではない。
- **陽性対照**: スロット幅を `max(physical_block_size, io_min)` に設定し各スロットが1ユニットを排他占有するようにした場合、「1回の書き込みで破壊されるスロット数」が 1 に低下すること——そうでなければモデルがユニット単位で計算しておらず、ラウンド全体が無効となる。
- **失敗条項**: すべてのパラメータ組み合わせで2つの判定基準を満たした場合、候補形態は成立とし**ありのままに記録**；断裂の基準のみ満たさない場合、結論は「スロット幅を引き上げるべき」であり「ルートリング形態の誤り」ではない——**両者を混同してはならない**。
- ⚠️ **絶対値アサーションの義務付け**: 「1回の書き込みで破壊されるスロット数」は `(スロット幅, ユニット幅, 開始オフセット)` から直接算出；「1周の所要時間」は `(スロット数, ルート発行頻度)` から直接算出。いずれも被テストコードから読み戻してはならない。

### ⚠️ 回避不能な前提

D22 (ユニット原子性の合成手法) 確定項目 2 は自ら本項が「ディスク先頭と末尾の障害ドメインが独立であること」に依存していると明記しているが、**ホスト側にその根拠は存在しない**（ZFS の 4-label 設計も同一の仮定に基づいている）。E41 (ルートリングスロット幾何 2×4×256) は**この仮定を検証せず**、それが成立するという前提の下でのみ幾何を計算する。

### 前提

なし。純粋な計数モデル。

### 実測（2026-08-30）

| 量 | 値 |
|---|---|
| 候補形態 | 2 領域 × 4 スロット × 256 バイト = **8 スロット / 2048 バイト** |
| 1周（fsync 毎にルート発行）| **8 回の操作**；チェックポイント毎にルート発行（E16 (ジャーナルの役割：WAL vs インテントログ) 実測で20万回操作あたり200回ルート発行）⇒ **8000 回** |
| 断裂: スロット幅 256、判定幅 512 / 4096 | **2 / 16** スロットを破壊 |
| 陽性対照: スロット幅を 512 に引き上げ（ホスト `physical_block_size = io_min = 512`）| **1** スロットを破壊 |
| しかしスロット幅 512 は 4096 判定幅上で | 再び **8** スロット破壊となる |
| **非アライメント**: 512 幅スロットが 256 オフセット | **2** アトミックユニットを跨ぐ ⇒ リスクスロット数 **2** |
| **2048 バイトのリング全体が単一の `io_min` に収まるか** | 512 には収まらない；**4096 および 65536 には収まる** |
| スロット幅を判定幅まで引き上げるコスト: リング総バイト数 | 512 段階で **4096**（候補の2倍）、4096 段階で **32768**（16倍）|

**4つの結論**:

1. **候補スロット幅 256 を却下**: 512 および 4096 の両判定幅において分離を達成できない（2 / 16 スロットを破壊）。立案時に赤判定が予測されており、赤になったことは**実装バグではない**。
2. **「2 領域 × 4 スロット」という次元は E41 (ルートリングスロット幾何 2×4×256) では網羅率ゼロ**: モデル内で `REGIONS` は乗算にのみ寄与し、**領域間隔および障害ドメイン**という2つの入力が存在せず、それこそが「2」という数値の唯一の根拠である。
   ⇒ **「形態が破綻しなかった」のは根拠の不在であり、陰性結果ではない。**
3. **断裂分離には当時「ルートスロットは判定幅に整列する」という要件が未済であった**:
   [invariants/02-根环.md](../../../crates/singlefs-checker/invariants/02-根环.md) の I-7 (ルートリング) クラスには当時この条項が存在しなかった（現行は I-7.5 (ルートスロットの判定幅整列)、実装済み、プールレベル checker がスロット単位で判定）。陽性対照の「512 に引き上げれば 1 に低下する」はこれを暗黙に前提としており、半スロットずらすと再び 2 に戻ることが実測された。
4. **真にリング全体を一撃で破壊するメカニズムは断裂ではなく、デバイス内部の RMW である**:
   2048 バイトのリングは**単一の 4096 または 65536 の `io_min` に収まる**。
   これに対処する手段はスロット幅の引き上げ（断裂への対処）ではなく、**2つの領域の間隔を ≥ `io_min` に引き離すこと**である。

⚠️ **数値の不整合が1箇所修正された（あのラウンドで演繹脚が指摘し、メイン agent がコードを現物確認）**:
修正前は判定幅の欄に 65536 が含まれていたが、**64 KiB は `io_min` の規模であり、`physical_block_size` の規模ではない**——
`block/blk-settings.c` の `blk_stack_limits` 内の `t->physical_block_size = max(t->physical_block_size,`（メンバディスクの `physical_block_size` の最大値を取得）および `drivers/md/raid0.c`、`raid5.c`（いずれも `lim.io_min = mddev->chunk_sectors << 9`）で確認。
一方、D20 (荷重受け面: ユニットの原子性と自己完结性) 系３では「自己証拠ユニットのアトミック幅 = ランタイムに検出された `physical_block_size`」と決定されている。
⇒ 修正前にこれに基づき導出された「1回の書き込みで 256 スロットが破壊され全証拠が消失する」は**不成立であり削除された**；対応する真のメカニズムは結論 4 にあり、コストもその「256倍」ではない。

### 「1周で足りるか」: 判定不能なのは存在すべきでない要件であるため

成果物 `reuse_requirement_source=none`——kb 内に「最悪ブロック再利用遅延要件」という数値は存在しない。
しかし**下限は明記されている**: I-7.3 (リング健全性) は「最大世代番号のほかにより古い世代のレコードが少なくとも1つ存在する」ことを要求し、D22 (ユニット原子性の合成手法) は逐字で「K はランタイムポリシーでなければならない（**下限 ≥ 2**）」と定める。8 ≥ 2。
そして D22 (ユニット原子性の合成手法) の同一箇所で「**ルートリングを『K 世代ロールバック可能』と解釈してはならない**」と明命している
⇒ 「N 世代ロールバック必須」という形式の要件は、D22 (ユニット原子性の合成手法) 自身の定義によればそもそも存在してはならない。
**欠落しているのはデータではなく、その要件自体が存在しないのである。**

⚠️ **ついでに kb 内の矛盾が1箇所発見された**: I-7.4 (直近 K 世代のブロック未再利用) の括弧注には「**K = ルートリング深度**」とあり、
D22 (ユニット原子性の合成手法) は逐字で「K はランタイムポリシーでなければならず（下限 ≥ 2）、**フォーマット定数であってはならない**」とし、「『ルートリング深度 = ブロック再利用遅延』は『深度はフォーマットフィールドであるから K もフォーマットフィールドである』と誤実装されやすい」と明記している。
ルートリング深度はフォーマット量（スロット数）である ⇒ **両記述は文字通りには同時に成立し得ない**。
⚠️ **この矛盾は 2026-09-13 に解消された**: I-7.4 (直近 K 世代のブロック未再利用) は「K 世代」をロールバック候補集合（インスタンス表に基づき依然有効 ∧ txg ≥ F_有効）に変更し、ブロック再利用の境界は D16 (パブリッシュセマンティクス) 確定項目 1 により `max(F_有効, リング内最古有効ルート)` として与えられた ⇒ K という量が2箇所で別々に定義されることはなくなった。
本モデルにおいて `cycle_ops` と `reuse_delay_ops` が同一関数を2回呼び出しているのは、まさにこの混同の可視的形態である——**したがって本モデルにおいて「1周 ≥ 要件」という判定基準は自己比較にすぎない**。

### 三者論証の状況

| 脚 | 立場 | 独自の成果 | 判決 |
|---|---|---|---|
| クラウド A | 順方向推論 | 「スロット幅 = 判定幅ですでに分離を達成しており、これを超えても安全性は買えずバイトを浪費するのみ」；候補の 8 スロットは自身が算出した要件と**等しいのであって余量があるわけではない**と指摘 | 候補不成立 |
| クラウド B | 演繹的反論 | **3箇所の越境をすべて的中**: ① 65536 は `io_min` であり `physical_block_size` ではない；② それに基づき導出された「256倍のコスト」は誤った処方箋に対する値付けである；③ 断裂の半分は E43 (拡張ポイントのバイト上限) と同日、同一クレート、同一の1行の式であり、**独立した検証脚を構成しない**。さらに領域次元のカバレッジ欠落と整列要件の欠如を指摘 | 全面的絞り込み |
| ローカル | 反例探索 | K はチェックポイント間隔（1000）に等しくあるべきと主張 | 却下 |

**メイン agent の判決**: 演繹脚の3点（越境についてはカーネルソースを行単位で現物確認）＋順方向推論脚の「等号で十分」を採用。
**ローカル脚の「K = チェックポイント間隔」は不成立**: D22 (ユニット原子性の合成手法) はルートリングを K 世代ロールバック可能と解釈することを明示的に禁じており、
かつ E19 (deferウィンドウ下の疑似ENOSPC) は K を**コスト側**に位置づけており（遅延世代数が大きいほど擬似 ENOSPC を引き起こしやすい）、これは K に対する上限圧力であって下限要件ではない。

  E41 (ルートリングスロット幾何 2×4×256) は**決定論的計数モデル**であり（実 I/O なし、並行性なし、ランダム源なし、システムクロック入力なし）、同一バイナリを5回実行すればバイト単位で同一となるのは必然である ⇒ N=1 と N=5 が提供する情報量は同等である。
  `.claude/singlefs-ai-sop/rules/test-discipline.md` の「単一の観測はカウントしない」は**本質的にばらつきを伴う**観測を対象としている。
  **この N=5 をもって実ストレステスト水準の根拠強度を偽装してはならない。**
- ⚠️ **陽性対照が不完全**: 「スロット幅を 512 に引き上げる」に対してのみ実施されており、
  **開始オフセットの次元には反例のみが存在し、独立した陽性対照がない**。
- ⚠️ **ミューテーションテストにより3つの真の盲点を特定し修正済み**: ① スロットがアトミックユニットより広い場合に破壊スロット数が **0** と計算される；② 逆算で切り上げを行わない場合に「必要なスロット数が **0**」と算出される；③ 開始オフセットで剰余を取らない場合、リング内の第8スロットが9個のアトミックユニットに接触すると計算される。
- ⚠️ **等価ミューテーションを1点記録**（`>=` を `>` に変更）: 全入力で同一値 ⇒ **これを捕捉できないことは盲点ではない**；テストとして記述して文書化し、挙動を変更するものに差し替えた。
- **断裂の半分は独立した検証パスを構成しない**: E43 (拡張ポイントのバイト上限) が同日に同一の1行の式を用いて同様の数値を計算している。
  E41 (ルートリングスロット幾何 2×4×256) の**純粋な増分は「1周 / 逆算」および「整列 / `io_min` スパン」の各次元にある**。
- **ホスト幾何の現物確認**（2026-08-30、`/sys/block/nvme0n1/queue/`）:
  `physical_block_size = logical_block_size = minimum_io_size = 512`。4096 の段階は**推算**である。
- **E41 (ルートリングスロット幾何 2×4×256) は「ディスク先頭と末尾の障害ドメインが独立であること」を検証せず**、`io_min` 内部の RMW メカニズムも検証していない（E34 (ルートリングスロット幾何) 主張2、未実行）。
