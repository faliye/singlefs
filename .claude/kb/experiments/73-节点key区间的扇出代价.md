## E73 节点 key 区间的扇出代价 —— 已跑（2026-09-01，纯算术，8 单测 / 8 条变异全抓）：**扇出最多掉 1 格（0.33%），树高一层没涨**

D18（块里携带什么信息） 已定项 2 定了记账树的节点带 key 区间，并自陈
「扇出下降多少、写放大动没动，一次都没量过；D8（核心索引结构） 已定项 2 的 16 KiB 是在**没有**这两个字段的前提下选的」。

### 判据（跑前写死，跑完没改）

1. **绝对值断言**：扇出恰好等于 `(节点大小 − 节点头) / 条目宽度`，两条臂各自算得出，
   不许只比两条臂的比值。
2. 若树高因此涨一层，判「16 KiB 这个取值要跟着重开」。
3. key 区间买到的那件事（一个节点单独捡起来能自证覆盖哪一段）要有一条**能失败的检查**：
   拿一个孤立节点判它该覆盖哪一段，不带区间的那条臂必须判不出来。

### 失败条款（跑前写死）

| 条款 | 判定 |
|---|---|
| **阳性对照**：把 key 区间字段撑到节点大小的一半，扇出必须塌掉 | **通过**（301 → 150）|
| 只测记账树，结论带「只对记账树成立」的口径，**不许外推** | 已带 |

### 实测

#### 判据 1：扇出最多掉 1 格

记账树 key = `(统计量, 树 ID, 设备, 代)` = **22 字节**；条目 = key + 子指针 32 = **54 字节**。
带区间的节点头多两个 key 字段（`min_key` + `max_key`）= **+44 字节**。

| 基础节点头 | 带区间的头 | 带区间扇出 | 不带区间扇出 | 差 |
|---|---|---|---|---|
| 32 | 76 | **302** | **302** | **0** |
| 64 | 108 | **301** | 302 | **1** |
| 128 | 172 | **300** | 301 | **1** |

⇒ **代价最多是 1 格，相对 0.33%。** 基础头 32 那一档**代价恰好为 0**——
44 字节整个被整数除法的余量吸收掉了。

⚠️ **三档的射程已被 D18（块里携带什么信息）已定项 7 收窄（2026-09-02 定案，2026-09-03 补注）**：
该定案给索引节点头定了字段集合——共同明文前缀 42 字节（magic 4 + 格式版本 2 + flags 2 +
声明长度 2 + 头校验和 32）+ 类身份段（树 ID + 层级 + 该树已定携带的 key 区间 +
诞生代号 8 + fsid 8）。⇒ **基础节点头 ≥ 58 字节（42 + 8 + 8，树 ID 与层级的宽度仍随实现定）**
⇒ **32 那一档不可达**，「32 档代价恰好为 0」指向一个该定案之后不存在的档。
**结论不变**：按 58 / 67 / 76 三个下界各重算，不带区间扇出恒 302、带区间恒 301，
差仍是 1 格；树高仍不涨 ⇒ D8（核心索引结构）已定项 2 的 16 KiB 不重开。
⚠️ **仍未定的是宽度不是字段**：E73（节点 key 区间的扇出代价）跑时「节点头基础字节仓里一处都没定过」
这句话，在字段集合那一半已经不成立；宽度那一半仍没定（树 ID、层级、key 各段），
欠账与 E71（记账 key 的条目数与宽度）/ E74（分配记录的条目数与整理开销）同一笔。

#### 判据 2：树高一层都没涨 ⇒ D8（核心索引结构） 已定项 2 的 16 KiB **不需要重开**

条目数取 E71（记账 key 的条目数与宽度） 量过的记账树规模，3 档基础头 × 4 档条目数共 12 格：

| 条目数 | 带区间树高 | 不带区间树高 |
|---|---|---|
| 4 075（E71（记账 key 的条目数与宽度） 窄读臂）| 2 | 2 |
| 59 200（宽读臂）| 3 | 3 |
| 115 200（上界臂）| 3 | 3 |
| 1 000 000 | 3 | 3 |

**12 格全部 `grew=0`。** ⇒ 判据 2 的重开条件**没有触发**。

#### 写放大：没动

COW 下改一条 key 要重写的节点数 = 树高，两条臂**逐格相同**（2 / 3 / 3）。
⚠️ 这是**结构口径**，不是字节吞吐——后者要真设备。

#### 判据 3：孤立节点自证覆盖区间

| 臂 | 孤立节点答得出它该覆盖哪一段吗 |
|---|---|
| **带区间** | **答得出**（`100..200`）|
| 不带区间 | **答不出**（区间只在父节点的 keypointer 里，父没了就没了）|

⇒ D18（块里携带什么信息） 已定项 2 逐字说它买到的那件事**有了一条会失败的检查**，
而不是一句断言。这条检查由变异 M6 证明会红（把不带区间的臂改成也能自证，它当场判红）。

### 结论：这是一笔便宜的自包含

`.claude/rules/fs-design.md`「不为省空间牺牲自包含」逐字要求
「遇到『这个字段能不能省掉』这类权衡，默认答案是**不省**——除非有实测证明省下来的那部分是瓶颈」。
⇒ **实测的结论是省下来的那部分远不是瓶颈**：0 到 1 格扇出、树高不变、写放大不变，
而买到的是「一个节点单独捡起来能自证覆盖哪一段」。

### 它答不了的那一半

1. 纯算术 + 一个孤立节点的判定模型：没有 btree 实现、没有分裂合并、没有 write buffer，
   文件操作 0 处。
2. **节点头的基础字节数跑时仓里一处都没定过** ⇒ 跑的时候它是**参数**，按 32 / 64 / 128
   三档各算一次；三档结论一致（掉 0 或 1 格），但**基础头若长到几百字节，这个结论要重算**。
   ⚠️ **字段集合那一半 2026-09-02 已定**（D18（块里携带什么信息）已定项 7 ⇒ 基础头 ≥ 58、
   32 档不可达），重算见实测段的射程注；**宽度那一半仍没定**。
3. **key 各段宽度同样没定过**（与 E71（记账 key 的条目数与宽度） 同一笔欠账）：22 字节是假设。
   key 变宽会同时抬高条目宽度与区间字段，两侧同向，**净效应没扫过**。
4. **只对记账树成立。** dirent 树那一格按 D18（块里携带什么信息） 已定项 2 推迟——
   它的分隔 key 是文件名，宽度分布完全不同，**不许外推**。
5. 「一个节点单独捡起来自证」这件事的**价值**没量：它买到的是重建路径上少一步，
   而重建路径本身还不存在。
