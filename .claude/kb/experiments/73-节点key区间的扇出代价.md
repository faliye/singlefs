## E73 节点 key 区间的扇出代价 —— 未跑（依赖索引节点实现）

**背景**：D18（块里携带什么信息） 已定项 2 定了记账树的节点带 key 区间。
节点头多两个 key 字段会挤掉载荷，而 D8（核心索引结构） 已定项 2 的 16 KiB 是在**没有**这两个字段的前提下选的。

**测什么**：同一棵记账树，带 / 不带 key 区间两条臂，量扇出、树高、点查的节点读次数、写放大。

**判据（跑前写死）**：
1. **绝对值断言**：扇出必须恰好等于 `(节点大小 − 节点头) / 条目宽度`，两条臂各自算得出，
   不许只比两条臂的比值。
2. 若树高因此涨一层，判「16 KiB 这个取值要跟着重开」——那是 D8（核心索引结构） 已定项 2 自己写的重开条件的同类。
3. key 区间买到的那件事（一个节点单独捡起来能自证覆盖哪一段）要有一条**能失败的检查**：
   拿一个孤立节点判它该覆盖哪一段，不带区间的那条臂必须判不出来。

**怎样才算失败**：
- **阳性对照**：把 key 区间字段撑到节点大小的一半，扇出必须塌掉；没塌说明字段根本没进节点头。
- 只测记账树不测别的 keyspace 是**合法的**——dirent 树那一格按 D18（块里携带什么信息） 已定项 2 推迟；
  但结论一律带「只对记账树成立」的口径，不许外推。
