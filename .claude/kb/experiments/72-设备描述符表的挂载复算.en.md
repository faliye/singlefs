## E72 Mount-Time Recalculation of Device Descriptor Table — Run (2026-09-02, **Real Heterogeneous Loop Pool**, N=5 Rounds × 2 Invocations Consistent in Verdict): **All Four Comparison Items Can Be Forced Red; Out-of-Table Quantities Not Judged Red**

[中文](72-设备描述符表的挂载复算.md) · **English** · [日本語](72-设备描述符表的挂载复算.ja.md)

D12 (Target Media) settled item 3 settled device-level geometric quantities in the device descriptor table of system configuration,
D12 (Target Media) settled item 4 settled comparison rules and verbatim required "**every single item must be able to be forced into the 'mismatch' branch by testing** —
a comparison item that never turns red and having no comparison item at all look identical in mount logs".

### Criteria (Hardcoded Before Run, Unchanged After Run)

1. **Absolute value assertion**: Byte size of table must exactly equal `device count × per-device entry width`, forbidden to look only at trends.
2. Recalculation time must be **linear** with device count; superlinearity judged as "O(device²) comparisons crept into recalculation".
3. **Every single comparison item must be able to be forced into the 'mismatch' branch.**

### Failure Clauses (Hardcoded Before Run)

| Clause | Verdict |
|---|---|
| **Positive control**: Corrupting geometric field of one device, recalculation must judge red | **Passed** (all four judged red individually; see "Criterion 3 + Positive Control: Four Comparison Items Forced Red One by One") |
| **If all comparison items tested only on homogeneous pool, entire round aborted** | **Not triggered**: All scenarios run on **real heterogeneous pool** (`pbs_mix=4096,512`) |

### Measurement

#### Criterion 3 + Positive Control: Four Comparison Items Forced Red One by One

Pool consists of 4 real loop devices, using `losetup --sector-size` to create **mixed `physical_block_size` of 512 and 4096**.
"Corruption" executed entirely through **genuine mechanisms** — remounting with changed sector-size, `truncate` changing capacity, swapping device order, altering layout bit in table.

| Scenario | How Corrupted | pbs | Capacity | Identity | Layout | Disposal |
|---|---|---|---|---|---|---|
| Negative control: nothing modified | — | ok | ok | ok | ok | **allow** |
| Forced pbs mismatch | Remount disk 1 with 4096 → 512 | **mismatch** | ok | ok | ok | **refuse_rw** |
| Forced capacity reduction | `truncate` to half and remount | ok | **shrunk** | ok | ok | **refuse** |
| Forced capacity expansion | `truncate` to double and remount | ok | **grown** | ok | ok | **allow_and_note** |
| Forced identity mismatch | Swap order of two disks, leave table untouched | ok | ok | **mismatch** | ok | **refuse** |
| Forced unrecognized layout bit | Change layout bit of a disk in table to 2 | ok | ok | ok | **mismatch** | **refuse** |
| **Quantity outside table changed** | Change readahead via `blockdev --setra` | ok | ok | ok | ok | **allow** |

⇒ **Four comparison items each individually forced red, and only that item turned red each time** —
mutual isolation demonstrates they indeed judge their respective quantities, not a generic "something is wrong".
⇒ **Disposal matches D12 (Target Media) settled item 4 cell-by-cell**: pbs is `refuse_rw` (refuse **writable** mount, not refuse mount),
capacity expansion is `allow_and_note` (allow and log), remainder is `refuse`.

⚠️ **The last row is the second most important row in this table**: D12 (Target Media) settled item 4 verbatim wrote
"Not in list: rotational speed, queue depth, `io_opt`, discard support ... comparing them merely manufactures false-red unmountable failures".
After altering readahead, recalculation **allows as before** ⇒ **the 'do not compare' rule also carries discriminative power**, not mere posturing.

#### Criterion 1: Table Byte Size

| Device Count | Entry Count | 24 B/entry | **40 B/entry** | 64 B/entry |
|---|---|---|---|---|
| 2 | 2 | 48 | **80** | 128 |
| 4 | 4 | 96 | **160** | 256 |
| 8 | 8 | 192 | **320** | 512 |

⇒ Exactly `device count × entry width`, holds across all three width tiers.
⚠️ **Entry width has not been settled in repo** ⇒ 40 bytes (dev_uuid 16 + pbs 4 + lbs 4 + capacity 8 + layout bit 8) is an **assumption**;
other two tiers reported alongside, **forbidden to treat byte counts of any single tier as conclusions**.

#### Criterion 2: Recalculation Time Is Linear, No O(device²)

| Device Count | Total Recalculation Time | Per Device |
|---|---|---|
| 2 | 26.0 ms | 13.02 ms |
| 4 | 50.5 ms | 12.63 ms |
| 8 | 99.8 ms | 12.48 ms |

⇒ Per-device time is **flat or slightly decreasing** (fixed overhead amortized) ⇒ **linear, Criterion 2 holds**, no quadratic term.

⚠️ **That 12.5 ms is harness overhead, not a prediction of mount elapsed time.** It is overwhelmingly the process startup cost of two `sudo`
invocations per device (`blockdev --getsize64` and `losetup -O BACK-FILE`).
**The linearity conclusion holds; absolute values must not be extrapolated to real mount path.**

### What It Cannot Answer

1. **Mount path itself does not exist** (no system configuration, no implementation) ⇒ what was implemented here is the **rule** of D12 (Target Media) settled item 4,
   verifying **whether each comparison item in the rule carries discriminative power**, **not** "whether mount code of this project is correct".
   Once code is written, it must be re-verified against identical scenarios.
2. **Heterogeneity achieved only on `physical_block_size` dimension** (512 / 4096).
   A true heterogeneous pool also has differing media types, stripe geometries, and layouts — those require QEMU
   (E15 (Whether Simulation of Heterogeneous Device Geometry Holds) already proved guest-distinguishable heterogeneous geometries can be synthesized), which was not done in the round yielding E72 (Mount-Time Recalculation of Device Descriptor Table).
3. **Device identity uses backing file name as proxy**, not genuine UUID — a true implementation writes an identity field on device and reads it back.
   Mismatch path was verified, but **how identity field itself lands on disk was unverified**.
4. **Table entry width and dev_uuid width are assumptions** (same owed check as E71 (Entry Count and Width of Accounting Keys) / E73 (Fanout Cost of Node Key Interval)).
5. **Did not verify "table itself corrupted"**: table checksum, table spanning atomic unit, consistency between table and root were untouched.
6. **Path where multiple comparison items mismatch simultaneously was not traversed**: each scenario corrupted only one item.
   The precedence order of "which is stricter" in disposal function (`refuse` stricter than `refuse_rw`) was written correctly per D12 (Target Media) settled item 4,
   **yet has not been tested by any scenario** — testing requires synthesizing compound scenarios such as "pbs changed and capacity shrunk simultaneously".
