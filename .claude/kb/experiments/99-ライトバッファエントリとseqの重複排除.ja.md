## E99 ライトバッファエントリとseqの重複排除 —— 実行済み（2026-09-03、純カウント、12単体テスト / 10件ミューテーション全検出）：**会計ツリーの key には既に世代が存在 ⇒ seq は4バイトのウィンドウ内シーケンス番号で十分；seq 内に再度 txg を配置することは重複会計である**

[中文](99-writebuffer条目与seq的去重.md) · [English](99-deduplication-of-write-buffer-entries-and-seq.en.md) · **日本語**

**これが答えるべきは D8 (コアインデックス構造) 確定項目 7（write buffer エントリが自前で保持する `seq`）である**：どれだけの幅か、どこに配置されるか、マウントをまたいで単調か。当該項目は「新規プールでのファイル作成のバイト変更：**はい**」と判定した。

### 判定基準（実行前固定、実行後変更禁止）

1. **ビット幅会計は計算によって算出せよ、推測を禁ず**：`seq = (checkpoint_txg, ウィンドウ内シーケンス番号)` の2つのセグメントがそれぞれ何ビットを占め、合計何バイトとなるかは、**絶対値でなければならない**。`checkpoint_txg` が 64 ビットである（D22 (ユニット原子性の合成手法) 確定項目 7）と定められている以上、**8バイトには1ビットも残らない** ⇒ モデルは「ウィンドウ内シーケンス番号の使用可能ビット数 = 0」という事実を報告しなければならず、曖昧に誤魔化してはならない。
2. **重複排除の決定論性**：4本のアームがそれぞれ同一の一連の更新を実行 —— ① seq なし；② ウォールクロック；③ マウントごとにゼロクリアされるカウンタ；④ `(checkpoint_txg, ウィンドウシーケンス番号)` —— **「勝者の選択誤り」の回数をカウントする**。各アームとも絶対値が必要であり、アーム間の相対比較のみを行うことは許されない。
3. **マウント間単調性**：更新シーケンスの中間に1回マウントを挿入し、判定基準 2 を再実行。アーム ③ のエラー数は必ず**増加**し、アーム ④ は恒等的に 0 でなければならない。
4. **切り捨てのコスト**：ウィンドウビットを捻出するために `checkpoint_txg` を `w` ビットに切り捨てた場合、ラップアラウンド後に同一の更新シーケンス内で「勝者の選択誤り」が発生する回数はいくつか？E44 (シーケンス番号ビット幅の実機測定とコスト) の 2785 パブリッシュ/秒に基づきラップアラウンド期間を提示せよ。
5. **ウィンドウ内シーケンス番号に必要な幅**：1回のパブリッシュウィンドウ内で同一 key が最大何回書き込まれるかが、ウィンドウセグメントのビット幅下限を決定する。D16 (パブリッシュセマンティクス) 確定項目 5 の `T_dirty` = 2 GiB と D5 (スナップショット / 空間会計メカニズム) 確定項目 5 の 30 バイトエントリから逆算せよ。

### 失敗条項（実行前固定）

| 条項 | トリガー時の判定方法 |
|---|---|
| **陽性対照、全アームで実行**：seq なしのアーム ① は最多のエラーを出さなければならず、マウント挿入後のアーム ③ は挿入なし時よりもさらにエラーを出さなければならない | 不成立 ⇒ 重複排除モデルが接続されておらず、**ラウンド全体を無効とする** |
| **陰性対照**：更新シーケンスを同一 key が1回のみ書き込まれるように変更した場合、4アームのエラー数はすべて 0 でなければならない | 0 でない ⇒ モデルが曖昧性のない入力において既にエラーを起こしており、ラウンド全体を無効とする |
| **逆受入条項**：判定基準 1 が 8 バイトでは収まらないと計算し、かつ判定基準 4 が切り捨てにより > 0 の選択誤りをもたらすと計算した場合 | 結論は「**8バイトでは不足、seq を拡幅せよ**」であり、ありのまま記述し、**ウィンドウセグメントを無理に 0 ビットに押し込めて帳尻を合わせてはならない** |

### 実測（2026-09-03、純カウント、N=5 ラウンドでバイト単位で一致、12単体テスト / 10件ミューテーション全検出 + 2件等価ミューテーション保存）

**計測条件と再実行**：コード `scripts/experiment-apparatus/e99_writebuffer_sequence.rs`、成果物 `e99-writebuffer-seq-2026-09-03.out`（37行、末尾 `emitted=37`）、ミューテーション表 `scripts/mutation/tables/e99_writebuffer_sequence.tsv`、`scripts/experiment-apparatus/replay.sh` に組み込み済み。

#### 判定基準 1 + 5：**8 バイトには収まらず、12 バイトで十分**

| seq 幅 | `checkpoint_txg` が 64 ビットを占有した後にウィンドウシーケンス番号に残るビット数 |
|---|---|
| 8 バイト | **0 ビット** |
| 10 バイト | 16 ビット |
| **12 バイト** | **32 ビット** |

ウィンドウシーケンス番号の要求下限：1パブリッシュウィンドウで最大 **71 582 788** 件の会計エントリを収容
(`T_dirty` 2 GiB ÷ D5 (スナップショット / 空間会計メカニズム) 確定項目 5 の 30 バイトエントリ）⇒ **少なくとも 27 ビット**。
⇒ seq が `checkpoint_txg` を**自前で保持**する必要がある場合、8 バイトも 10 バイトも不足し、12 バイトで十分である。

#### 判定基準 6（第2ラウンド補足）：会計ツリーの key には**既に世代が存在**し、seq が txg を重複して保持する必要はない

D5 (スナップショット / 空間会計メカニズム) 確定項目 5 は key = `(統計量タグ 2, ツリー ID 8, デバイス 4, **世代 8**)` と逐字的に定め、
D16 (パブリッシュセマンティクス) 確定項目 6 は「世代 = チェックポイント番号」と定め、D5 (スナップショット / 空間会計メカニズム) 確定項目 2 の付帯条項は
「会計エントリの**パブリッシュ間マージはもはや実行不能**（世代が key に入った）」と逐字的に補足している。

⇒ **同一 key の重複排除対象エントリは必然的に同一のパブリッシュウィンドウに属する** ⇒ seq はウィンドウ内シーケンス番号のみを必要とする：

| key 形態 | 必要な seq 幅 | txg は key 内に既存のセグメントの重複か |
|---|---|---|
| 会計ツリー（key が世代を含む）| **4 バイト** | **はい** |
| 逆インデックス / LRU（key レイアウトはリポジトリ内で未定）| **適用外** | 判定不能 |

⚠️ **12 バイトという数値は重複会計である** —— key 内に既に存在する「世代 8」を seq 内で再度書き写したものである。
⚠️ **この条項は key 内に世代を含むツリーにのみ成立する**。他の2つのツリーの key レイアウトは未定であり、モデルは「適用外」と報告し、外挿しない。
⚠️ これにより、判定基準 2 / 3 のマウント間の表は**会計ツリー上では射程外となる**：同一 key のエントリは key 構造上マウントをまたいで共存することはあり得ない。その表は「もし key に世代がなかったらどうなるか」に答えるものであり、他の2つのツリーにとっては依然として意義を持つ。

#### 判定基準 2 + 3：`checkpoint_txg` から派生したアームのみがマウントをまたいでも依然として正しい

1000 個の key、それぞれ 8 回の更新、key 順ソート後に到着順序が破棄される：

| アーム | マウント挿入なし（選択誤り / 未定義）| 1回マウント挿入（選択誤り / 未定義）|
|---|---|---|
| seq なし | 0 / **1000** | 0 / **1000** |
| ウォールクロック | 0 / 0 | **1000** / 0 |
| マウントごとにゼロクリアされるカウンタ | 0 / 0 | 0 / **1000** |
| **`txg + ウィンドウシーケンス番号`** | **0 / 0** | **0 / 0** |

⚠️ **「選択誤り」と「未定義」は分けてカウントせよ** —— D8 (コアインデックス構造) write buffer ハード要件 3 は
「不安定ソートを使用する場合、同一 key エントリの**相対順序は未定義**」と逐字的に述べており、モデルが実装に代わって一方を選択することは許されない。
陰性対照：同一 key を1回のみ書き込んだ場合、4アームすべて 0 / 0。

#### 判定基準 4：「世代」切り捨てのコスト —— それが衝突するのは**キーの同一性**であり、順序付けではない

世代は D5 (スナップショット / 空間会計メカニズム) 確定項目 5 により key に組み込まれた ⇒ これを切り捨てると、ラップアラウンドした2つのチェックポイントが
**同一の key に崩落し**、エントリが誤ってマージされる。可算な違反（2026-09-04 補足測定、
第1・第2版ではラップアラウンド期間を印字したのみで、その数値はいかなる違反カウントにも接続されていなかった）：

| 世代セグメントビット幅 | 1000 回パブリッシュ | 10 万回 | 1000 万回 |
|---|---|---|---|
| 8 ビット | **1464** ペア | 19 481 280 ペア | 195 307 500 032 ペア |
| 16 ビット | 0 | 34 464 ペア | **757 947 392** ペア |
| 32 ビット | 0 | 0 | 0 |
| 48 ビット（確定下限）| 0 | 0 | **0** |

ラップアラウンド期間（E44 (シーケンス番号ビット幅の実機測定とコスト) の 2785 パブリッシュ/秒に基づく）：32 ビット保持 ⇒ **17 日**
(D5 (スナップショット / 空間会計メカニズム) 確定項目 2 付帯条項の「32 ビットで 17.8 日」と同値）；
48 ビット保持 ⇒ **3204 年**（E44 (シーケンス番号ビット幅の実機測定とコスト) の「48 ビットで 3202 年持続」と同オーダー）。

### それが答えられないこと

純カウントモデル：write buffer 実装なし、本物の flush なし、並行性なし、クラッシュポイント再生なし、ファイル操作 0 箇所。
**「write buffer がディスクに永続化されるか否か」には答えない** —— それはリポジトリ内に記述のない前提条件であり、E99 (ライトバッファエントリとseqの重複排除) は「永続化される」と「永続化されない」の2通りの読み方でそれぞれ影響を報告し、代わって決定しない。
