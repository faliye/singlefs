## E67 1つのストライプはどのディスク群にまたがるか —— 実行済み (2026-08-31、N=5 シード + 偏向ラウンド、単体テスト 9 件 / ミューテーション 4 件中 3 件捕捉、1 件無効)：**オブジェクト作成時に最も空いている組を1つ選び以後固定**が両ラウンドで最善

[中文](67-一条条带参与哪几块盘.md) · [English](67-which-disks-a-stripe-spans.en.md) · **日本語**

D2 (RAID ストライプ方針) 確定項目 6 で何列用いるか (上限 4) を定めたが、どのディスク群を選ぶかは定めていなかった。E67 (1つのストライプはどのディスク群にまたがるか) が計測したのは「どれだけ失われるか」ではなく——
**予想データ損失割合は幅によって決定される** (`(w−1)/C(D,2)`、選定方法によらず、E67 (1つのストライプはどのディスク群にまたがるか) 実測で四腕すべてセルごとに等しい) ——
**損失がどのように分布するか**である：少数のオブジェクトに集中するのか、各オブジェクトに広く分散するのか。

### 判定基準 (実行前ハードコード、実行後未改変)

1. 各腕の「2ディスク同時故障後の健全オブジェクト割合」の差 ≥ 10 パーセントポイント ⇒ この次元が選定を決定；< 10pp ⇒ 均等度による決定に変更。
2. **保存則**：各腕の予想データ損失割合は互いに等しくなければならない (差 ≤ 1%)。等しくない ⇒ 当該ラウンド全体を無効化。
3. ディスク間使用量の極差が単一ディスク使用量の 5% を超える腕は**足切り** (早期の ENOSPC を引き起こす、E60 (ディスク追加後にデータ移動を行わないコスト) で座礁コストは計測済み)。

### 何をもって失敗とするか (実行前ハードコード)

| 条項 | 判定 |
|---|---|
| **陽性対照、全腕で実行**：`w = デバイス数` (フル幅) ⇒ 健全割合は**すべて 0** でなければならない | **合格**、五腕すべて 0 |
| **陰性対照**：幅 2、単一ストライプオブジェクト ⇒ 健全割合 = `1 − C(2,2)/C(8,2)` = 27/28 | **合格** |
| 失敗ペアは全 `C(8,2)=28` ペアを**全数検査**し、サンプリングしない | サンプリング誤差なし |

### 実測 (8 ディスク、幅 4、512 オブジェクト；四ラウンドの負荷)

| 腕 | 均等 (オブジェクトあたり 8 ストライプ) | 偏向 (16 オブジェクト中 1 つが 64 ストライプ占有) |
|---|---|---|
| | 健全割合 / ディスク間極差 | 健全割合 / ディスク間極差の割合 |
| 甲 オブジェクト番号で1組に拘束 | **78.6%** / 0 | 78.6% / **88.7%** ← 判定基準 3 で足切り |
| 乙 ストライプごとにローテーション | 14.3% / 0 | 74.6% / **31.9%** ← 足切り |
| 丙 ストライプごとに最も空いた 4 台を選択 | 57.1% / 0 | 77.2% / 0 |
| 丁 ストライプごとにランダム | 14.1% / 4.5% | 73.7% / **6.4%** ← 足切り |
| **戊 オブジェクト作成時に最も空いた組を選び、以後固定** | **78.6%** / **0** | **78.6%** / **0** |

| 己 オブジェクト作成時に組を選び、**組内ディスク満杯で再選定** | 78.6% / 0 | **78.4%** / **0** |

予想データ損失割合：**六腕すべて 107142 ppm** (= 3/28 = `(w−1)/C(D,2)`) ⇒ 判定基準 2 の保存則成立。

⚠️ **ラウンド間での健全割合の比較は不可**：偏向ラウンドでは大半のオブジェクトが 1 ストライプしか持たず、元来健全を維持しやすい。**同一ラウンド内でのみ比較する。**

#### 第 3 ラウンド (2026-08-31 補足)：異機種容量下で「組内満杯だがプールには空きがある」事態が起きるか

ローカル脚からの反例の文面：各ディスクは同容量である必要はない (D2 (RAID ストライプ方針) 確定項目 2) ⇒ 組拘束によりオブジェクトが 4 台の小容量ディスクに縛り付けられ、
他所に空きがあるのに書き込めなくなる懸念。異機種容量の 1 ラウンドを追加実行 (3000 スロットのディスク 4 台 + 900 スロットのディスク 4 台、総容量 15600 < 要求 16384)：

| 腕 | 満杯ディスクに配置されたストライプ数 (少ないほど良い) |
|---|---|
| 甲 オブジェクト番号で組拘束 | 2012 |
| 乙 ローテーション | 2009 |
| 丁 ランダム | **2277** |
| 丙 ストライプごとに最空きを選択 | **1148** |
| 戊 オブジェクト作成時に組選択 | **1148** |
| 己 組選択 + 組内満杯で再選定 | **1148** |

⇒ **反例は顕在化せず**：戊は空き領域に基づいて組を選択するため、小容量ディスクが満杯に近づくと選ばれなくなる ⇒ ストライプごとに最空きを選ぶ手法と**セル単位で一致**。
問題となったのは残容量を考慮しない「オブジェクト番号で組拘束」(甲) のような拘束方式である。
⚠️ 六腕すべてで 4 台のディスクが容量超過した——総要求が元より総容量を超過しており、**このラウンドは横並びの比較にのみ用い、絶対値として読んではならない**。

#### 第 4 ラウンド (2026-08-31 補足)：ディスク追加 + 確定項目 4 c のリバランス後、健全割合はどれだけ残るか

クラウド両脚が同一箇所を指摘：組を作成した後にディスクが追加され、リバランスでデータ移動が生じた場合 ⇒ 組の整合性が保たれるか。
**移動粒度が唯一の独立変数である。** 8 台配置後に 9 台目を追加し、新ディスクが 1/9 を取得するまで移動させ、
全 `C(9,2)=36` ペアの故障ディスクを全数検査：

| 移動粒度 | 移動スロット数 | 健全割合 |
|---|---|---|
| **オブジェクト全体を新しい組に再配置** | 1824 | **83.3%** ＝ `1 − C(4,2)/C(9,2)` の理論値、**1スロットも欠損なし** |
| ストライプごとに移動 | 1820 | **75.0%** |

⇒ **オブジェクト全体移動により組拘束の利益が完全に維持され**、ディスク数が増加したため健全割合は 78.6% から 83.3% へと上昇した。
ストライプごとの移動では 8.3 パーセントポイント低下——**判定基準 1 の 10pp ラインを下回っており**、忠実に記録；
これ以上の低下に至らなかったのは本ラウンドで 11% のスロットしか移動していないためであり、移動量が増えるほど低下は顕著となる。

⚠️ **第 1 版のストライプごと腕はモデル化を誤っていた**：先頭 N 個を順次走査したが、配列内でストライプがオブジェクトごとに局所化していたため
⇒ オブジェクト全体移動と等価となり、両腕が同一値を出力した (83.3% vs 83.3%)。全オブジェクトに歩進分散するよう修正した後に分離した。

### 判定基準の個別判定

| # | 判定 |
|---|---|
| 1 | **均等ラウンドで成立** (甲 78.6 vs 丙 57.1、差 21.4pp ⇒ この次元が決定)；**偏向ラウンドでは不成立** (戊 78.6 vs 丙 77.2、差 1.4pp ⇒ 均等度で決定に変更)。二ラウンドで結論が異なり、**忠実に並記** |
| 2 | **成立**、五腕すべてセルごとに等しい |
| 3 | **甲・乙・丁を足切り**；丙と戊のみが両ラウンドで極差 0 を達成 |

⇒ **戊は両ラウンドで最高の健全割合を達成し、かつ両ラウンドで極差 0 となった唯一の腕である。**

### なぜ組拘束が勝つのか：メカニズム

一対のディスクが同時故障した際、組拘束されたオブジェクトは組全体が被災するか (当該オブジェクトの複数ストライプが一括して損傷)、あるいは1スロットも失われないかのいずれかとなる。
**被災する確率は `C(4,2)/C(8,2) = 6/28`** ⇒ 健全割合は正確に `22/28 = 78.6%` (単体テストで固定)。
ストライプごとに組を変更すると各ストライプで独立にサイコロが振られ、8 ストライプ中 1 つでも被災すれば当該オブジェクトは健全ではなくなる
⇒ ローテーション腕では `4/28 = 14.3%` しか残らない (リング距離 4 の 4 対のディスクはどのウィンドウにも該当せず、独立算術、単体テストで固定)。

⇒ **等しく 10.7% のデータが失われる条件下で、組拘束は 78.6% のオブジェクトを無傷に保ち、ローテーションでは 85.7% のオブジェクトでブロック欠損が発生する。**

### 本実験で答えられない半面

1. **カウントモデル**：ファイルシステムなし、ブロックデバイスなし、ファイル操作は 0 箇所。
2. **単一オブジェクトのスループットをモデル化していない**：組拘束はオブジェクトを 4 台のディスクに固定する ⇒ 当該オブジェクトの並列度上限は 4 であり、8 ではない。
   E67 (1つのストライプはどのディスク群にまたがるか) ではこの次元を計測しておらず、これは組拘束の既知のコストである。
3. 3 ディスク同時故障をモデル化しておらず、再構築ウィンドウをモデル化しておらず、オブジェクト削除後の組回収をモデル化していない。
4. 偏向形態 (16 分の 1 のオブジェクトが 64 ストライプを占有) は仮定されたものであり、本プロジェクトで実測された分布ではない。

なし。純粋なカウントモデル。
