### 判定基準（実行前固定、実行後変更禁止）

1. **カバレッジ**：4箇所のリストおよび確定項目 8 で使用される 15 個のクラス名は、登録表の下で厳密に1つのコードにマッピングされなければならない；未マッピング、1名複数コード、未登録コードへのマッピングの3つの数値はすべて厳密に 0 でなければならない。陽性対照：D9 (暗号化) 確定項目 6 の行の名前のみを登録表とした場合、墓標は必ず未登録コードに着地しなければならない。
2. **ドメイン分離**：2つのクラスの AAD 標準エンコーディングが同一になり得る ⇔ タグが同一（または双方が持たない）かつボディが等長（AEAD 暗黙的認証 assoclen）。陽性対照：データユニットのボディと等幅の合成クラスはタグなしで厳密に 1 ペア衝突、タグありで 0 ペア衝突；陰性対照：単一クラスは恒等的に 0。
3. **容量とダウンストリーム数値**：cap(h, r) = (32768 − h) / r。cap(103, 56) = 583、cap(103, 140) = 233 を固定（パックヘッダ 93 時も同値）、それぞれが成立するヘッダ幅の閉区間を算出、両端でそれぞれ 1 バイト増加すると 1 スロット減少しなければならない。⚠️ 判定基準固定時のパックヘッダは 76 であった；第1ラウンドで2本のクラウドレッグがそれぞれ独立に頭部チェックサムがヘッダのみを保護しユニット全体チェックサムが親ポインタにあることを指摘し、逆推レッグはさらに誕生世代がロード世代でないことを指摘し、第2版で 48 バイト（ヘッダ 90）へ変更；第2ラウンドで不認識リーダーにレコード幅が必要であることとタグの暗号文側複製が必要であることが指摘され第3版でレコード幅 2 とタグ 1 を復元、ヘッダ 93。**判定基準の形式は未変更、固定数値も未変更**、h が 76 から 93 に変更されたのみ。
4. **特定力**：5つ組は N 件収容されたユニットについて N − 1 件を特定不能；パッククラス識別子セグメント + パース列挙は厳密に 0。
5. **固定幅パースと混在**：レコード数 × レコード幅 + ヘッダ > 宣言長であれば破損判定；2種の幅の混在を第1種に従ってパースした誤分類数は gcd により独立算出；非混在は恒等的に 0。
6. **未登録コードの2段階ポリシー**：k 個の未登録ユニットクラス —— incompat は静黙見逃し 0 かつマウント拒否、「スキップ」は厳密に k 個を見逃す；m 個の未登録レコードタイプコンテナ —— 検証可能は厳密に m、適用レコードは厳密に 0、読み取り専用、回収禁止。
7. **値域ヘッドルーム**：256 − 7 = 249。

### 第2回における `crates/` との突き合わせ（登録第11節停止条項、成果物実行前に実施）

装置は `crates/` をインポートせず、突き合わせは `crates/` の当該行を読み取り、定数を Python コマンドで抽出して装置ソース内のローカル定数と比較、不一致項目数 0：

純算術、ファイル操作 0 箇所。AAD の暗号学的モデルは構築せず（ドメイン分離は「エンコーディングが同一になり得るか」のみで判定、MAC は判定せず）、スキャナは実行せず、パック記録ユニットが通常パスでどのようにインデックス付けされるかは判定せず、D8 (コアインデックス構造) 確定項目 6 がどのアプローチを採用するかには答えず、パックユニットが1つのスナップショット世代内で複数回パブリッシュされた際に何回書き込まれるかには答えない（それは E83 (墓石の粒度) の書き込み増幅計測条件の役割である）。

第2回において追加で答えられないこと：

- 読み方乙（レコード領域起点 136）のみを測定。読み方甲（原点 107）は h = 107 の感度サンプリング点として現れるのみ（墓標容量 816）であり、甲に従って別途判定基準を設けてはいない。
- 「P8 の書き換え成立」が答えるのは：コード 3 の予約ビットを含むヘッダ末端 136 が墓標 40 バイト容量 815 および inode 容量 233 を kb 登録値から乖離させず、かつ 136 が [129, 148] 内に位置することである。E83 (墓石の粒度)、E84 (パックされた墓石の固定量) 本文内の 583 という数値が 40 バイト下でどうなるかには答えない：583 は 56 バイト下の数値であり、40 バイト下ではもはや下流の数値ではない；E83 (墓石の粒度) の再実行はそれ自身の第2回登録に帰属し、E84 (パックされた墓石の固定量) 装置は 583 を固定記述（`scripts/experiment-apparatus/e84_tombstone_pinning.rs`）しており、ゲート code-source-discipline の format-constants セルはバインドできずメイン agent に引き渡される。
- `crates/` との突き合わせは定数と破損判定条件を読み取ったものであり、`crates/` のコードを実行していない；登録表、AAD および2段階ポリシーは `crates/` と突き合わせていない（幅に依存しない）；装置は「墓標 → コード 3」のみをモデル化しており、第2段階登録表が登録するパック記録タイプには 1〜5 が存在する。
- `RecordTypeOutcome.records_applied` が恒等的に 0 である構造は未変更（`.claude/gate.d/experiment-constant-reading-lag.tsv` の C60 (一定読み出し値に故障注入自己検証がない) に登録）、今回の再実行では実際の書き込みを補足していない。
