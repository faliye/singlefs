## E59 缓冲消息能不能只从单元重算 —— 已跑（2026-08-31）

它答 D11（索引节点要不要留消息缓冲区） 已定项 4（定案前的原问题），逐字是：

> 缓冲里那条消息能不能只从单元重算出来。
> 能 ⇒ 缓冲仍是纯派生态；不能 ⇒ 它已晋升为权威态，
> D21（权威态与派生态的分界） 的「权威态 = 单元 + 记账 + 根」必须扩项。

**这是 D11（索引节点要不要留消息缓冲区） 已定项 1（留）之后剩下的唯一生死前置。**

### 判据（跑前写死）

甲臂（只从单元）四类消息的分歧数：全 0 ⇒ **能重算**；部分类 > 0 ⇒ **按类拆**；
全类 > 0 ⇒ **不能重算**；陈旧副本不可见时全 0、可见时 > 0 ⇒ 结论**条件于那条前提**，前提要单列。

### 怎样才算失败（跑前写死，跑完不许改）

| 条款 | 落地情况 |
|---|---|
| 扫到的单元数 ≠ 独立算出的应有数 ⇒ 整轮作废 | 7 条臂 × 3 组负载**逐格相等** |
| 丁臂（序号 + 显式墓碑单元）任一类 ≠ 0 ⇒ 整轮作废 | 四类全 0 |
| 往任一臂注入 k 处破坏、报出的 `map_wrong` 不多 k ⇒ 比较器无判别力，整轮作废 | 7 条臂各注 1 / 5 / 17 处，逐条报出 |
| 驻留容量算出来是 0 ⇒ 整轮作废 | 1024 / 8192 / 32768 叶给出 6650 / 46550 / 186200 条 |
| 结论方向与 D11（索引节点要不要留消息缓冲区） 已定项 1 相左 ⇒ 如实记录 | 见「它对已定项 1 说了什么」 |

### 结果（2026-08-31，5 轮逐字节一致）：判据「按类拆」

七条臂，三组负载（256 / 4096 / 16384 个对象，各带 25% 覆写、12.5% 删除）。
「16384 对象、4096 覆写、2048 删除、16 棵树」那一组：

| 臂 | 分不出的副本 | 映射错 | 复活的已删 key | 反向索引缺 | 记账错的树 | 合计分歧 |
|---|---|---|---|---|---|---|
| **甲 只从单元**（已定项 4 的字面问题） | **4096** | 0 | **2048** | 0 | **16** | **2064** |
| **庚 只从单元 + 分配器复用低地址** | **4096** | **4096** | **2048** | **4096** | **16** | **10256** |
| 乙 单元 + 记账 | 0 | 0 | 0 | 0 | 0 | **0** |
| 丙 单元 + 谱系重写序号 | 0 | 0 | **2048** | 0 | **16** | **2064** |
| 丁 序号 + 显式墓碑单元（全对照） | 0 | 0 | 0 | 0 | 0 | **0** |
| 戊 陈旧副本不可读 | 0 | 0 | 0 | 0 | 0 | **0** |
| 己 头全抹掉（阴性对照） | 0 | 缺 14336 | 0 | **14336** | **16** | 28688 |

⇒ **按类拆，而且四类不是并列关系**：

| 消息类 | 只从单元重算得出来吗 | 卡在哪 |
|---|---|---|
| **映射类**（逻辑身份 → 落点） | **条件成立** | 同一个 key 有多份可读副本时，头里没有任何字段能分出哪份是现行值。分不出的数**恰好等于覆写次数** |
| **反向索引类** | 同映射类 | 它是映射类的另一头，逐条同生同死 |
| **墓碑类**（删除） | **不成立，且没有条件** | 删除在盘上**不留任何单元**⇒ 扫描恒把已删的 key 复活，复活数**恰好等于删除次数** |
| **记账类**（每棵树的活单元数） | **跟着墓碑类一起错** | 它是从「哪些单元是活的」推出来的，前一格错了它必错，实测每棵树都被顶高 |

### 三条判决性的绝对值（不是臂间互比）

1. **分不出现行值的 key 数 = 覆写次数**（64 / 1024 / 4096，逐格相等）。
2. **复活的 key 数 = 删除次数**（32 / 512 / 2048），**且丙臂（有序号）一条不少**——
   谱系重写序号买到的是覆写那一格，买不到删除这一格。
3. 头全抹掉时缺的条数 = 活 key 总数（224 / 3584 / 14336）。

### 甲臂那个「映射错 = 0」是运气，庚臂把它拆了

甲臂的映射类一条没错——**而重建方并不知道自己是对的**（分不出的副本仍是 4096 条）。
它对，只是因为模型里分配是单调向前的，「按物理地址扫、取地址最大的一份」恰好等于「取最新的一份」。

**没有任何已定条款给这个保证**：D3（空间分配） 没有定分配单调向前，
而 COW 分配器复用释放出来的空间是常态。庚臂只改一件事——覆写落到更低的地址——
同一段重建代码**逐条赌错**，错的处数恰好等于覆写次数。

⚠️ ⇒ **「甲臂映射类为 0」不许被引用为「映射类可以只从单元重算」。**
可引用的那一句是：**它取决于一条谁都没定过的分配器性质。**

### 乙臂：闭合它的不是单元，是记账

单元 + 记账那一臂四类全 0，**因为「这个落点还活着吗」正是记账记的东西**。
D21（权威态与派生态的分界） 已定权威态 = 单元 + **记账** + 根 ⇒ 记账不会跟着索引一起丢。

⚠️ **但这一臂的前提仓里没定**：它假设记账能**逐落点**回答「活没活」。
D3（空间分配） 与 D5（快照 / 空间记账机制） 都没有定这个粒度——
D5（快照 / 空间记账机制） 记的是**关于集合的**用量，不是「某个落点此刻属不属于现行版本」。
⇒ 乙臂给出的是**答案的形状**，不是答案：要用它，得先定记账的粒度。

### 它对 D11（索引节点要不要留消息缓冲区） 已定项 1 说了什么

已定项 1（留）自陈是「在两个已知未决之上做的裁决」，其中之一正是代价 2
（可重建性从「可检出的不可达」退化成「检不出的陈旧」，**至今是推理、没有量化**）。

E59（缓冲消息能不能只从单元重算） 给代价 2 的**兜底路径**量了一个数，不是给代价 2 本身量数：
它测的是「缓冲丢了之后能不能从盘上重算回来」，而代价 2 问的是「重算错了有没有人报警」。
**两者是同一条链的前后两环，E59（缓冲消息能不能只从单元重算） 只碰了前一环。**
后一环仍然欠着，落点是 [checks-owed.md](../checks-owed.md) C52（陈旧当成合法）。

### 它答不了的那一半

1. **计数模型不是实现**，零文件操作，与 E54（记账的「代」要保留几代）、E57（明文侧字段集的权威落点） 同一条限制。
2. **不重建 Bε 树**：几何只用来算「全树缓冲能扣住多少条」（划驻留窗口），
   不参与任何一类消息可不可重算的判定。一条消息能不能重算与它此刻躺在哪个节点无关。
3. **没有并发、没有崩溃点**：重建发生在一个静止的盘上。真正的重建要在崩溃之后跑，
   那时还多一层「journal 重放到哪」的问题，E59（缓冲消息能不能只从单元重算） 一个数都没给它。
4. **删除的建模只有一种形态**（盘上不留痕迹）。若 D3（空间分配） 将来定了「释放要写意图记录」，
   那条记录本身就是墓碑，E59（缓冲消息能不能只从单元重算） 的第三格要重跑。
5. **没碰加密**：A6（AAD 期望值不来自明文侧） 与重建路径的冲突由 D18（块里携带什么信息） 未定项 5 管，
   E59（缓冲消息能不能只从单元重算） 假设头读得出来。
6. **四类消息是 E59（缓冲消息能不能只从单元重算） 选的**，不是某条已定条款给的清单。缓冲将来若装别的类，要各自再判一次。

### 变异测试：16 条破坏，16 条被抓，无盲区

含「甲臂偷看记账」「庚臂退回单调分配」「序号取最小而不是最大」「墓碑读成活的」
「记账类永远算对」「缓冲条数改一档」。

⚠️ **第一轮有一条真盲区**：反向索引那一列只有一条 `backref_bad == map_wrong` 的互比断言，
而它跑在甲臂上——**两个数都是 0**，`0 == 0` 什么也没证明。把缺条那一支的计数改成 `+= 0`，
一个测试都没红。现在改成三条臂各钉一个绝对值（0 / 覆写次数 / 活 key 总数）。
**这正是 test-discipline.md「只让多条臂互相比，测不出所有臂一起错」的形态**，
而它这次是被变异测试抓出来的，不是被人看出来的。

⚠️ **另有一条从「盲区」查成「死代码」**：比较器里「同一个落点指向别的 key」那一支
任何变异都打不红——查下去它**不可达**：落点的主人由那个落点自己的头说了算，
两侧不可能对同一个落点给出不同的 key。现在写成断言，模型自相矛盾就炸。
