## E93 老化下の配置とフラグメンテーション度 —— 実行済み（2026-09-03、14単体テスト / 11件ミューテーション全検出）：フラグメンテーション度は O(1) で増分維持可能；クラスタセグメントは空セグメントを供給する整理がなければ自己持続しない；近傍書き換えには天井があり、整理は予算に伴い持続的に低下する

[中文](93-老化下的放置与碎片度.md) · [English](93-老化下的放置与碎片度.en.md) · **日本語**

**問題**：D26 (バックグラウンド整理と配置回収) 確定項目 1 は2つの前提を欠いている ——「整理しないとどれだけ退化するか」の量、
およびフラグメンテーション度の計算可能な定義（`.claude/rules/fs-design.md` ハード要件 1：判定基準は明示的、計算可能、記述されていなければならない）；
確定項目 4 は「構造的抗老化のためにノードレイアウトに手を加える必要があるか」を判定する必要がある；確定項目 6（ユーザー決定により永続化を採用）は観測量自体を必要とする。
E10 (老化：構造的抗老化 vs 事後整理) はファイルシステムに未済があり実行できない；
E93 (老化下の配置とフラグメンテーション度) はカウントモデル層においてまず配置ポリシーの半分を定量化する。

⚠️ **E93 (老化下の配置とフラグメンテーション度) は E10 (老化：構造的抗老化 vs 事後整理) を代替しない**：
D26 (バックグラウンド整理と配置回収) 主結論における「2本のアームのうち1本をデグレード可能」という判定基準は
E10 (老化：構造的抗老化 vs 事後整理) 自身が固定した条項（③ が ② の水準に達する）に属し、E93 (老化下の配置とフラグメンテーション度) はその判定には触れない。

### モデル

L 個の固定幅オブジェクトが key 順に整列（D8 (コアインデックス構造) 確定項目 2 の 16 KiB インデックスリーフとも読め、
D4 (チェックサム位置) 確定項目 7 の 32 KiB データユニットとも読める —— 両タイプとも固定幅であり、モデルは区別しない；
どちらと読むかは「runs が多い ⇒ 誰のスキャンが遅いか」の解釈にのみ影響する）、デバイスには S 個のスロット、充填率 L/S。
初期状態は key 順に連続書き込み（順次作成の形態）。各チェックポイントでワークロードに応じてオブジェクトのバッチをダーティ化し、
COW で新しいスロットに書き換える；古いスロットは defer に入り、次のチェックポイントで初めて再利用可能となる
(D16 (パブリッシュセマンティクス) 確定項目 15 のモデル化）。

**フラグメンテーション度の候補定義（検証対象）**：`F = runs / L`、
runs = 全オブジェクトを key 順に巡回したときの物理的連続セグメント数。これが**増分維持可能**であることを要求：
オブジェクトがスロット a からスロット b に移動したとき、key 上隣接する2つのオブジェクトとの隣接関係のみが変化する ⇒ O(1) 更新；
監査パスのフルスキャン再計算は増分パスとコードを共有しない（`.claude/rules/fs-design.md` 第1ボックス + 第2ボックスの役割分担）。

4つのアーム（配置ポリシー）× 2組のワークロード（一様ランダム単一ポイント書き換え / セグメント書き換え、セグメント長 8）：

| アーム | ポリシー |
|---|---|
| first_fit | 最低空きスロット優先（対照：古典的老化形態） |
| bump_seg | 同一チェックポイント内のダーティオブジェクトを key 順にソート後、クラスタセグメントに連続書き込み；空きセグメントがない場合は first_fit にフォールバックしてカウント。D3 (領域割り当て) 確定項目 5 はコミット内生ブロックのクラスタ化のみを確定しており、これをすべての COW 書き込みに一般化することは候補ポリシーであり、確定項目ではない |
| bump_neighbor(R) | bump_seg + 書き込みパス近傍書き換え：各ダーティ key セグメントの両側それぞれ最大 R 個のクリーンな近傍を追加で書き換える —— フォーマット変更を伴わない「構造的抗老化」の候補形態 |
| bump_compact(B) | bump_seg + 各チェックポイントで B 個のオブジェクトを予算とした key 順ラウンドロビン整理 —— D26 (バックグラウンド整理と配置回収) 第1レグのモデル化 |

### 判定基準（2026-09-03 実行前固定、実行後未変更）

1. **手計算アンカー**：8オブジェクトの小規模シナリオ、スクリプト化された書き換え後の runs を手計算通りに固定（絶対値アサーション）。
2. **保存則**：すべてのサンプリング点、すべてのアーム、すべてのシードにおいて、増分 runs == フルスキャン再計算 runs；
   占有スロット数は常に == L；空きスロット + 占有 == S；defer されたスロットは本チェックポイントで再利用不可。
3. **測定の陽性対照、4つのアームすべてがゲート通過**：テスト専用の強制配置スイッチ（ポリシーをバイパス）によりオブジェクトを
   完全隔離レイアウトに配置した場合、各アームの測定パイプラインは runs == L を報告しなければならない；key 順連続レイアウトに戻した場合は runs == 1 を報告しなければならない。
4. **老化ワークロードが十分に過酷であるか**：first_fit × 一様ランダムワークロードが終期まで実行されたとき runs ≥ L/4 ——
   E10 (老化：構造的抗老化 vs 事後整理) の失効条項と同形：劣化が測定されなかった場合はワークロードが不十分であったことを示すにすぎない。
5. **回答すべき3つの問い（数値報告のみ、デグレード判定なし）**：
   a. first_fit と bump_seg の runs 軌跡 ——「整理しないとどれだけ退化するか」のモデル層の回答；
   b. bump_seg の空きセグメント供給が定常状態で枯渇するか否か（フォールバック回数軌跡）—— クラスタセグメントポリシーが整理なしで自己持続するか否か；
   c. 追加書き込み予算が近いセルにおいて、bump_neighbor と bump_compact のどちらの runs が低いか、その比率。
6. シード付き RNG を伴う決定論的モデル：5つのシードは隠蔽状態の不存在とシード感度を示すものであり、統計的安定性を示すものではない
   (`.claude/singlefs-ai-sop/rules/test-discipline.md` 決定論的実験条項）。

### 失敗条項（実行前固定）と判定

| 条項 | 判定 |
|---|---|
| 陽性対照（判定基準 3）がいずれかのアームで不的中 | **合格**：7つのアーム構成すべて scatter_runs=8192、compact_runs=1 |
| 判定基準 4 不的中 | **合格**：first_fit × 一様ランダムの5シード終期 runs 8182–8188（≥ L/4 = 2048） |
| bump_neighbor が first_fit より良くない | トリガーされず（first_fit より良好、ただし実測第3項の天井を参照） |
| bump_compact が bump_seg より良くない | トリガーされず |

### 実測（L=8192、S=10240（充填率 80%）、セグメント長 G=64、チェックポイントごとのダーティ D=64、T=2000 ラウンド、5シードの中央値）

#### 1. 整理しないとどれだけ退化するか：両ワークロードとも急速に飽和に達する

| アーム | 一様ランダム runs（L に占める割合） | セグメント書き換え runs（L に占める割合） | 追加書き込み |
|---|---|---|---|
| first_fit | **8186（99.9%）** | 7997（97.6%） | 0 |
| bump_seg | **8186（99.9%）** | 7312（89.3%） | 0 |

軌跡：first_fit × 一様ランダムは **t=500（各オブジェクト平均約 3.9 回書き換え）で 8184 に達し**、その後プラトー。
⇒ モデル層における「非整理」は緩やかな退化ではなく、**数百チェックポイント以内にピークへ急上昇する**。

#### 2. クラスタセグメントポリシーは整理が空きセグメントを供給しなければ自己持続しない（判定基準 5b）

bump_seg のフォールバック率（割り当てがクラスタセグメントに入らない比率）は5シードすべてで **91.8%–93.8%**：
散乱した解放はほぼ永遠に完全な空きセグメントを構成できない。整理予算がこれを押し下げる唯一の力である ——
bump_cp_b32 / b128 / b256（一様ランダム）のフォールバック率はそれぞれ約 88% / 73% / 50%。
⇒ **「クラスタセグメント割り当て」というポリシーは整理に乗っかっている**；E81 (コミットの不動点) が期待するコミット内生ブロックのクラスタ化も、
定常状態では同様に誰かが空きセグメントを一掃する必要がある。

#### 3. 近傍書き換えには天井がある；整理は予算に伴い持続的に低下する（判定基準 5c）

| アーム | 一様ランダム runs（追加書き込み倍率） | セグメント書き換え runs（追加書き込み倍率） |
|---|---|---|
| bump_nb_r1 | 5497（2.98×） | 5181（1.25×） |
| bump_nb_r2 | **5460（4.92×）** | 5111（1.50×） |
| bump_cp_b32 | 7502（1.50×） | 6073（1.50×） |
| bump_cp_b128 | 6095（3.00×） | 3922（3.00×） |
| bump_cp_b256 | 4791（5.00×） | **1339（5.00×）** |

- **同等予算セルでは一長一短**：一様ランダムの 3× 帯では近傍が勝利（5497 vs 6095）、5× 帯では整理が勝利（4791 vs 5460）；
  セグメント書き換えの 1.5× 帯では近傍が勝利（5111 vs 6073）。
- **近傍書き換えの飽和**：R を 1 から 2 に引き上げても、一様ランダムは 5497 から 5460 にわずかに動くのみ（予算は 3× から 4.9× に増大）——
  後続の書き換えによってクラスタが崩される速度がクラスタ形成速度に追いつき、定常状態は F ≈ 66% で膠着する。
  またその予算はワークロード幾何によって上限が制限される：セグメントワークロード下では R=2 でも 1.5× しか消費できず、**さらに使おうとしても使い道がない**。
- **整理はセグメントワークロードを F ≈ 11.5–21.1% に抑え込む**（5シードの `f_pct` 個別値：16.35 / 20.39 / 21.12 / 11.52 / 13.04、
  対応する `runs_final` は 1339 / 1670 / 1730 / 944 / 1068、中央値 1339）。
  ⚠️ **軌跡は上昇傾向であり下降傾向ではない**：成果物内のその行をそのまま書き出すと
  `E7RESULT name=traj arm=bump_cp_b256 load=runs8 seed=0 runs=0:1,500:914,1000:1147,1500:1202,2000:1339`
  —— 914 から 1339 へ単調増加している。**「整理は飽和せず、軌跡は時間とともに下降傾向にある」という記述は 2026-09-06 に撤回された**：
  同一成果物の同一行と矛盾し、方向を逆にするとダウンストリームが問題を過小評価することになる
  (D26 (バックグラウンド整理と配置回収) 確定項目 1 の停止条件はこの記述の上に成り立っている）。

#### 4. フラグメンテーション度の定義成立（判定基準 2）

増分 O(1) で維持された runs とフルスキャン監査は、**すべてのアーム × ワークロード × シード × サンプリング点**で点ごとに一致；
監査の判別力は単体テストで検証済み（増分パスをバイパスしてレイアウトを直接破壊した場合、2つのパスが分岐しなければならない）。
⇒ `F = runs / L` は `.claude/rules/fs-design.md` 第1ボックス（コミット時に増分維持され、問い合わせられた瞬間に回答を持つ）を満たし、
かつ監査パスが独立している（第2ボックス）ため、D26 (バックグラウンド整理と配置回収) 確定項目 1 のフラグメンテーション度定義候補および
確定項目 6 の観測量として採用できる。

### モデル改訂記録（すべて正式ラウンド登録前に発生、判定基準は未変更）

1. **近傍アームの割り当てパスを1回修正**：初版のクラスタはセグメント枯渇後にスロットごとに first_fit へフォールバックし、書き出された「クラスタ」が物理的に不連続であった ——
   それは近傍書き換えに対して藁人形を立てる行為であった（`.claude/singlefs-ai-sop/rules/evidence-discipline.md` の明令）。
   改訂後、近傍アームと整理バッチは「オープンセグメント → 新規空きセグメント → 空きスロット連続 run → スロットごとフォールバック（カウント）」に従いセグメント全体で配置する。
   改訂前は整理が同等予算セルで全勝していたが、改訂後は一長一短となった —— **この変更は結論の方向を変えたため、ここに記録する**。
2. **first_fit に予約領域ガードを追加**：オープンセグメント内で bump されていないスロットは first_fit および run 検索にとって予約領域であり、
   これを奪うと二重割り当てが発生する（ミューテーション M7/M11 の双方向検証）。登録ラウンドの出力はガードの前後でバイト単位で一致した
   ⇒ このウィンドウは本パラメータ下で踏まれず、ガードは防御であり数値を改ざんするものではない。

### それが答えられないこと

1. カウントモデル：実際の I/O なし、CPU なし、キャッシュなし。「runs が少ない ⇒ スキャンが速い」は構造量からレイテンシへの外挿であり、
   レイテンシの半分は E10 (老化：構造的抗老化 vs 事後整理) に属する。
2. オブジェクト固定幅：可変長 extent のフラグメンテーション形態はモデル化されていない。
3. 2組のワークロードは端点であり分布ではない：実際の老化ワークロード（git checkout 系）がどこに位置するかについての根拠はない。
   D11 (インデックスノードにメッセージバッファを残すか) で確定したメッセージバッファはリーフの書き換えをバッチ化する ⇒ 実際のダーティセットは
   一様ランダムよりもセグメントのティアに近いが、バッチ化の統計自体はモデル化されていない。
4. トリガー閾値をいくつにするかは E93 (老化下の配置とフラグメンテーション度) には帰属しない —— フラグメンテーション度の定義、
   増分維持可能性の根拠、退化軌跡を届けるのみである。
5. ノードレイアウト側の抗老化形態（フォーマット変更のアプローチ）にはアームがない —— 近傍書き換えアームの天井は
   「フォーマット変更も無駄である」ことの根拠を構成しない。
6. ストライピングなし、クラッシュ / リドゥなし、メタデータとデータの区別なし、充填率は 80% の1点のみ
   （三者論証逆推論レグが指摘、2026-09-03）：D2 (RAID ストライピング戦略) 確定項目 11 の一部ストライプ固定、
   D8 (コアインデックス構造) 確定項目 5 の意図リドゥ、D3 (領域割り当て) 確定項目 5 のコミット内生ブロック群が
   クラスタセグメントに入れるか否かは、すべてモデル外である。フォールバック率は全割り当ての計測条件であり、コミット内生ブロックのクラスタ化成功率とみなすことは**できない**。
