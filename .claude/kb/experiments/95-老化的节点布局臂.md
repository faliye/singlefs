## E95 老化的节点布局臂 —— 已跑（2026-09-09，纯算术，20 单测 / 20 条变异全抓）

**问题**：D26（后台整理与放置回收）未定项 4 问「结构抗老化取什么形态」，
而 E93（老化下的放置与碎片度）只有政策臂（聚簇放置、邻居重写、整理），
**没有一条动节点布局的臂**——所以「政策形态够不够」在模型层无从比较，
未定项 4 的字节判定（改第一个事务的字节：是）也就翻不动
（2026-09-03 三方论证，正推腿与反推腿同一判决）。
E95（老化的节点布局臂）就是补那条臂。

### 模型

沿用 E93（老化下的放置与碎片度）的对象 / 槽位模型与两组负载，
加两条**格式级**候选臂，与政策臂在同一套负载、同一组额外写预算下比：

| 臂 | 动格式的哪一处 | 机制 |
|---|---|---|
| 节点组 | 节点头带组身份（G 个 key 相邻的 16 KiB 节点构成一个放置与重写单元） | 重写以组为单位：组内任一节点脏就整组重落一段——BetrFS 大节点效应的显式化，节点大小仍是 D8（核心索引结构）已定项 2 的 16 KiB |
| 代际分离 | 节点头带老化代（自上次重写以来的 checkpoint 数分档） | 放置按代分区：热的与冷的不混段，整理只清热区——日志结构清理里的按龄分离 |
| 政策臂（对照） | 不动格式 | E93（老化下的放置与碎片度）的 bump_compact(B) 与 bump_neighbor(R) 原样复用 |

**格式臂要给它最有利的实现**（`.claude/singlefs-ai-sop/rules/evidence-discipline.md`
稻草人条款）：组身份与老化代都当作零成本可读，放置器对它们的利用取最优。

### 判据（跑前写死 2026-09-03，跑完不许改）

1. **手算锚点**：8 对象、组大小 2：脏一个对象整组重落，runs 按手算钉死。
2. **守恒**：与 E93（老化下的放置与碎片度）同一套（增量 runs == 审计、占用恒等、defer 不可复用）。
3. **阳性对照每臂都过闸**：强制放置开关下全隔离布局报 runs == L，连续布局报 runs == 1。
4. **等预算比较**：额外写倍数取 1.5× / 3× / 5× 三档，每档每臂各报 runs 中位（5 种子）。
5. **要回答的一问**：最有利实现的格式臂，在**任一**等预算格上能不能把 runs 压到
   政策臂的一半以下。能 ⇒ 「政策够」被推翻，D26（后台整理与放置回收）未定项 4 的格式部分要真定形态；
   不能 ⇒ 模型层支持「不动格式」，字节判定翻转的证据链补上一环（耗时轴仍归
   E10（老化：结构抗老化 vs 事后整理））。
6. 不代替 E10（老化：结构抗老化 vs 事后整理）；降级判据仍归它。

### 失败条款（跑前写死）

| 格式臂在所有格都不如政策臂 | **合法结果，如实记**——那是「不动格式」的证据，不是实现坏了 |

### 口径

原始输出 `research/results/e95-node-layout-arms-2026-09-09.out`。
变异表 `research/mutations/e95_node_layout_arms.tsv`。复跑：

```bash
cargo run --release --bin e95-node-layout-arms          # research/ 下跑
cd research && bash scripts/replay.sh E95               # 与入库产物逐字节比对
```

配置逐字取 E93（老化下的放置与碎片度）那一套：`l=8192 s=10240 g=64 d=64 t=2000 seeds=5`。

**「额外写倍数 X」的口径是 2026-09-09 跑它那一轮定的**（判据 4 原文只写「1.5× / 3× / 5× 三档」，没写怎么花）：
每 checkpoint 允许的额外写数 = `D × (X − 1)`，四条臂逐轮花同一个数，
花了多少报在产物的 `budget_spent_pct` 列里。1.5 / 3 / 5 ⇒ extra = 32 / 128 / 256。
⚠️ 这个口径与 E93（老化下的放置与碎片度）对得上：它的 bump_cp_b32 / b128 / b256
逐字报 `write_amp=1.500` / `3.000` / `5.000`。

**跨装置闸**：E95（老化的节点布局臂）把 E93（老化下的放置与碎片度）的模型抄了一份，
所以断言里钉死了 E93（老化下的放置与碎片度）入库产物的 14 个 `aging_median`，对不上判红
（`.claude/singlefs-ai-sop/rules/show-me-test.md`「坑在建模口径上，检查要立在装置之间」）。
14 个逐个复现，一个不差。

**确定性模型**：同一个二进制跑四遍逐字节一致。按
`.claude/singlefs-ai-sop/rules/test-discipline.md`，这只说明没有隐藏状态，**不说明统计上稳定**。

**按判据 5 的字面：能。** runs8 三格全中，uniform 三格全不中（1.15 / 1.38 / 1.40 倍，一格都没到两倍）。

⚠️ **而这个「能」不成立——判据 5 量的不是它要量的那件事**
（2026-09-10 反推腿实测，主 agent 读源码 + **自己在 scratchpad 副本上复跑一遍**坐实：
只改 tag 前缀与家族标签两行、机制与随机源一个字不动，**48 行 `runs_median` 逐字不变，
六格答案行全部从 `true` 翻成 `false`**；探针产物未留存）。
产物里「格式 / 政策」这个分界**是一个写死的标签**：`Arm::family()` 按 enum 变体硬写
（`e95_node_layout_arms.rs:108-113`），判决行按 tag 前缀过滤
（`:953` 的 `starts_with("pol_")` 与 `:959` 的 `starts_with("fmt_")`）。
反推腿把**同一个函数** `step_node_group` 原样注册成一条政策臂（对齐 key 窗口重写，盘上零字节，
组大小是运行时旋钮），**24 个格的数字逐字不变，而答案行当场从 `true` 翻成 `false`、六格全 false**，
14 个跨装置 median 一个不差。
⇒ **被判成「格式臂」的那条臂，在这个模型里不消费任何盘上字段**（`:683` 逐字 `dirty.iter().map(|&k| k / g)`），
它归哪个家族只取决于提交它的人给它起了什么名字。

⇒ **E95（老化的节点布局臂） 2026-09-09 这一次既推翻不了「政策够」，也确立不了它。**
唯一真读盘上状态的那条格式臂是代际分离（`:726`、`:743` 读 `last_write` 与 `obj_gen`），
而它六格里只赢一格、从未过半 ⇒ **只看它，判据 5 = 不能。**

**代际分离那条格式臂六格里赢一格**：`budget=256 load=uniform` 逐字是
`name=grid budget=256 arm=fmt_gensep_256_1024 load=uniform runs_median=4347`，
同格最好的政策臂是 `pol_compact ... runs_median=4791` ⇒ 低 9.3%，但离一半差得远；
另外五格全输，最接近的一格是 `budget=256 arm=fmt_gensep_256_1024 load=runs8 runs_median=1343`
对同格政策臂 1339（输 4）。**它在任何一格都没赢过节点组臂。**
按失败条款那是**合法结果，如实记**。
⚠️ 这一段 2026-09-10 改过一次：初稿写「输了每一格」「打平」，两处都与产物对不上
（`.claude/singlefs-ai-sop/rules/evidence-discipline.md`「引产物就整行抄」，正推腿打中、主 agent 复算坐实）。

### 它答不了的（跑前写死 2026-09-03）

1. 计数模型：无耗时轴、无消息缓冲攒批统计、无真机。
2. 两条格式臂是候选不是穷举：别的节点布局形态若被提出，要加臂重跑。
3. 组身份与老化代在真格式里各占几字节、与 D11（索引节点要不要留消息缓冲区）的 665 条缓冲抢不抢，模型不算。

### 它答不了的（跑完之后才看出来的，2026-09-09 三处 + 2026-09-10 三处）

**这几处不是判据，是射程注**：判据 5 的字面结论不受它们影响，
**但「这份结果能不能拿去改决策」受**。

4. **赢的那个机制，在这个模型里不需要任何格式位。**
   `fmt_group_gN` 的组是 `key / N` 算出来的——模型里 key 到对象是静态一一对应、没有节点分裂合并，
   所以放置器不查任何盘上字段就知道组身份。而模型那一节注册的臂逐字是
   「节点头带组身份（G 个 key **相邻的 16 KiB 节点**构成一个放置与重写单元）」：
   **按节点数分组**才要存字段，**按 key 区间分组**不要。
   ⇒ 量到的是「固定边界的整组重落 打赢 滑动窗口与轮转整理」，
   **不是**「节点头里那个组身份字段是必需的」。要分辨这两者，得有一个带分裂合并的模型。
5. **runs8 那一列的赢面与组大小对齐有关**：负载的重写段长逐字是 8，赢得最多的臂是 `fmt_group_g8`；
   而同一条臂在 uniform 上（7558 / 5797 / 3669）反被 `fmt_group_g2` 压着。
   ⇒ 组大小要按负载的局部性挑，挑错就没有收益。
6. **结论在预算轴上不单调，而登记的三档没覆盖到转折点。**
   跑完之后在 scratchpad 副本上加了一档 extra = 512（write_amp 9×）探针（**产物未留存**，
   不进判据、不进复跑）：uniform 上 `pol_compact=1037` 反超 `fmt_group_g2=2545`，
   runs8 上 `pol_compact=195` 反超 `fmt_group_g8=401` 与 `fmt_group_g32=230`。
   ⇒ **格式臂的优势落在 1.5×–5× 这一段，预算再大就翻过去了**；转折点在 5× 与 9× 之间，没测。
   ⚠️ 2026-09-10 反推腿独立复现了 512 那一档的四个数（逐字相同），并往上外推到 1024：
   `pol_compact` 报 576 / 102，**赢过全部六条格式臂**，翻面随预算单调加深。

7. **组大小那三个取样点（2 / 8 / 32）低估了节点组臂，而不是高估。**
   反推腿扫了 g ∈ {1,2,4,8,16,32,64} × 段长 ∈ {1,2,4,8,16,32}：最优 g **跟着预算走**，
   不是跟着负载段长走 ⇒ 第 5 条那个「与组大小对齐有关」的说法**按它写的形态不成立**。
   实测差距：`budget=128 load=runs8` 的真最优是 g16 = 522，而登记的三点栅格报 904（低 1.73 倍）。

8. **`fallback_pct` 不能当赢面的佐证。**（正文「结果」一节引过它）
   反推腿实测：把代际分离臂的回落计数口径对齐之后，18 个格的回落率从 55.7–89.8 全部变成 0.0，
   而 `runs_median` **18 格逐字不变**——因为 `len == 1` 时 `find_free_run(1)` 与 `alloc_first_fit`
   返回同一个槽，只有后者计数。⇒ 那一列量的是「走了哪条代码路径」，不是「放置好不好」。

9. **跨装置闸只罩住共享底座，罩不住新加的两条臂。**
   `step_node_group` / `step_gen_sep` / `place_gen_run` / `extend_neighbors_budgeted`
   在 `run_e93_arm` 里出现 **0 次** ⇒ 14 个 median 全对，只证明 Sim / dirty_set / place_run 这套底座与
   E93（老化下的放置与碎片度） 同源，对新臂一个字都没说。`pol_neighbor` 同样在闸外，
   而它正是 `budget=32 load=runs8` 那个决胜格的对手。
