## E95 老化的节点布局臂 —— 未跑（判据已注册 2026-09-03）

**问题**：D26（后台整理与放置回收）未定项 4 问「结构抗老化取什么形态」，
而 E93（老化下的放置与碎片度）只有政策臂（聚簇放置、邻居重写、整理），
**没有一条动节点布局的臂**——所以「政策形态够不够」在模型层无从比较，
未定项 4 的字节判定（改第一个事务的字节：是）也就翻不动
（2026-09-03 三方论证，正推腿与反推腿同一判决）。
E95（老化的节点布局臂）就是补那条臂。

### 模型

沿用 E93（老化下的放置与碎片度）的对象 / 槽位模型与两组负载，
加两条**格式级**候选臂，与政策臂在同一套负载、同一组额外写预算下比：

| 臂 | 动格式的哪一处 | 机制 |
|---|---|---|
| 节点组 | 节点头带组身份（G 个 key 相邻的 16 KiB 节点构成一个放置与重写单元） | 重写以组为单位：组内任一节点脏就整组重落一段——BetrFS 大节点效应的显式化，节点大小仍是 D8（核心索引结构）已定项 2 的 16 KiB |
| 代际分离 | 节点头带老化代（自上次重写以来的 checkpoint 数分档） | 放置按代分区：热的与冷的不混段，整理只清热区——日志结构清理里的按龄分离 |
| 政策臂（对照） | 不动格式 | E93（老化下的放置与碎片度）的 bump_compact(B) 与 bump_neighbor(R) 原样复用 |

**格式臂要给它最有利的实现**（`.claude/singlefs-ai-sop/rules/evidence-discipline.md`
稻草人条款）：组身份与老化代都当作零成本可读，放置器对它们的利用取最优。

### 判据（跑前写死 2026-09-03，跑完不许改）

1. **手算锚点**：8 对象、组大小 2：脏一个对象整组重落，runs 按手算钉死。
2. **守恒**：与 E93（老化下的放置与碎片度）同一套（增量 runs == 审计、占用恒等、defer 不可复用）。
3. **阳性对照每臂都过闸**：强制放置开关下全隔离布局报 runs == L、连续布局报 runs == 1。
4. **等预算比较**：额外写倍数取 1.5× / 3× / 5× 三档，每档每臂各报 runs 中位（5 种子）。
5. **要回答的一问**：最有利实现的格式臂，在**任一**等预算格上能不能把 runs 压到
   政策臂的一半以下。能 ⇒ 「政策够」被推翻，D26（后台整理与放置回收）未定项 4 的格式部分要真定形态；
   不能 ⇒ 模型层支持「不动格式」，字节判定翻转的证据链补上一环（耗时轴仍归
   E10（老化：结构抗老化 vs 事后整理））。
6. 不代替 E10（老化：结构抗老化 vs 事后整理）；降级判据仍归它。

| 条款 | 判定 |

| 判据 3 任一臂不中 | 整轮作废 |
| 格式臂在所有格都不如政策臂 | **合法结果，如实记**——那是「不动格式」的证据，不是实现坏了 |
| 格式臂全胜 | **合法结果，如实记**——那是 D26（后台整理与放置回收）未定项 4 要真定形态的证据 |

### 它答不了的

1. 计数模型：无耗时轴、无消息缓冲攒批统计、无真机。
2. 两条格式臂是候选不是穷举：别的节点布局形态若被提出，要加臂重跑。
3. 组身份与老化代在真格式里各占几字节、与 D11（索引节点要不要留消息缓冲区）的 665 条缓冲抢不抢，模型不算。
