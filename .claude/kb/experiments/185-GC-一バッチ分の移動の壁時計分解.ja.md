### 何をしたか

1. 計時ラッパーデバイス：メモリディスク（`SparseBlockDevice`）または実ディスク（ext4 上の `O_DIRECT` イメージファイル、`DirectInputOutputBlockDevice`）を包み、`BlockDevice` のあらゆる呼び出しの前後でそれぞれ一回 `Instant` と自スレッドの `clock_gettime(CLOCK_THREAD_CPUTIME_ID)` を読み（CPU 読み値が壁時計読み値を包む）、呼び出しの種類ごとに壁時計、CPU、ディスク待ち（壁時計から CPU を引いたもの）、回数、バイトを累計する。読み出しは「この計時窓での最初の書き込みの前 / 後」で分け、最初の書き込みの前の読み出しはさらに三つの欄に分ける：R のディスクの R に落ちたもので、移動元スロット上の再読み出しを除いたものはスキャン読み出しへ。このバッチの移動元スロット上（二つのディスクの同番号スロット）のもので、R のディスクの各スロットの最初の読み出しを除いた残りは解放前ディスク読み出し照合へ（`release_check_read_bytes`、登録第十二節 12.5）。その他はその他へ。書き込みは「このバッチの移動先に落ちたもの / その他」に分ける。陽性対照の注入（`write_at` のたびに 2 ms 眠る、またはスレッド CPU 時計で 2 ms スピンする）もここにある。
2. プール作成：harness の既定パラメータで 4 GiB のメモリディスク二台を mkfs、最初のファイル、書き込み可能マウント。P + 64 個の空 inode を作り、先頭の P 個はそれぞれデータユニットを一つずつ順次書き込む。全体が今回書いた段はスロット順に 4 つごとに 3 つ（f = 0.25）か 1 つ（f = 0.75）を上書きし、混在する段は今回書いたユニットをすべて上書きする。余分に作った空 inode で最上位の段を埋める。さらに「F を受入上限まで上げて inode を一つ作る」を、上書きされた古い配置先がすべて解放されるまで繰り返す。**上書きの順序（改法甲、装置 `overwrite_order_of`、第 2131 行）**：f = 0.75 は従来どおりすべて古いスロット番号の昇順。f = 0.25 は三つのグループを順に行うように変えた：① 「段の 32 ユニットすべてが今回書いたもの」である段に入っていないユニット（混在する段の全部と、レシピの累積で名指しされたもの）、グループ内は古いスロット番号の昇順。② 全体が今回書いた段で上書きするユニットのうち、スロット番号が最大の段を除いたもの、古いスロット番号の昇順。③ スロット番号が最大の全体が今回書いた段で上書きする 24 個、古いスロット番号の昇順。どのユニットを上書きするか、何回書くか、書く内容は変えず、順序だけを変える。機構（登録第七節「推した予測」）：上書きは一回ごとに一回のパブリッシュでルートを一本書き、ルートリングは 24 本、古い配置先はその上書きのパブリッシュで解放済みと記録される。そのため上書きの 25 回目からはどのコピーも 24 回前に開いた穴に落ち、最後の 24 回の上書きが開けた穴（スロット番号が最大の段の 24 個）は作成が終わった時点でまだ空いていて、その段には生きたスロットが 16 個残り、すべて今回書いたものになる。
3. 幾何照合：コピー上で書き込み可能マウントし、セッションが発行する段階の選段ループ（`choose_region` と「先にスキャン」を交互に）を再生し、greedy がどの段を選ぶかを見る。その段が全部今回書いたデータユニットで生きたスロット = 64f なら greedy を使う。そうでないがその段が全部今回書いたデータユニットなら、それらをレシピに併合して作り直す（最大三回）。他のユニットを含むなら登録済みのフォールバック（テスト専用の強制選段でスロット番号最小の f 段を名指し）に進む。プール作成後に段ごとの構成（`name=segment_composition`、N11）、作れた段の数の二経路の並記（`name=segment_composition_summary` の `counts_agree`）、上書きのコピーの落ち先（`name=overwrite_landing`、N12）を出力する。これらの行は各点の最初のプール作成でだけ出力し、第 2–5 ラウンドの作り直しでは出力しない。
4. 一つのインテントを測る：書き込み可能マウント（`mount_writable_with_compaction_switches`、製品スイッチはバッチサイズをテスト専用の `ForcedForTests(K)` に替えるだけ）、各呼び出しの前にセッションの「経過したパブリッシュ数」を 1000 に設定し（パブリッシュ予算が 1 に落ちる）、`run_compaction` を一回ずつ、最後のバッチがインテントを消すまで呼ぶ。各呼び出しの前後で `Instant` とスレッド CPU 時計を読み（壁時計読み値が CPU 読み値を包み、デバイス呼び出しの層とは逆）、戻った後に計時窓の外で、出された版から発行・バッチ・最後のバッチのどれかを判定する。各インテントの前後には計時窓の外で校正（読み値 1、N15）とスレッドとマシンの読み値（読み値 3–N9、`name=intent_machine_readings`）も一回ずつ取る：校正比が > 1.10 のインテントは無効にし、無効にした後は 10 秒ごとに校正して二回続けて ≤ 1.10 になってから測り直す。一回の待ちは最大 300 秒、一つの段の累計は最大 600 秒（改訂 R2-1、R2-2）。各段の最初に校正の基準（読み値 2、21 回）と倍の作業の自己検査（R2-3）を行い、段の最後にもう一度基準を取る（R2-4）。段の最初、各標本点の最初、段の最後にそれぞれ `name=machine_state`（N10）を一行出す。
5. 第二段の再生：呼び出しの前にこの版の割り当てレコード、マッピングエントリ（セッションの非公開の取り方を別に書いたもの）、固定と隔離のスロットを取り、スキャンが読んだユニットのバイトを取る。三つの段（甲 読まれた各ユニットのユニット全体の CRC-32C（もう一つの子項目は解放前ディスク読み出し照合の複製のユニット全体の CRC-32C で、複製のバイトは呼び出しの前に二つのディスクの同番号スロットから一部ずつ読む）、乙 `scan_region` 全体、丙 発行段階での `choose_region` の各回）は、再生のたびにまず計時なしで一回ウォームアップしてから計時して一回走らせ、5 回の再生の中央値を取る。飽和スループットは 1、16、N スレッドで各 2 秒。丙段の判定（変更六）：各ラウンドでそのラウンドの有効なインテントの発行行ですでに計算された `choose_share_per_batch` を取り、元の閾値（10%）で判定し、五ラウンドを一行の `name=choose_judgement` にまとめる（`name=stage_judgement` 行は従来どおり出し、その丙段のマスは `not_run` のまま）。
6. 第三段（引き継ぎ、今回は実行しない）：各カードでプール作成時に書いた本物のデータユニット一つ（32768 バイト）を使い、n を 1 から 16384 段まで取り、`GpuCard::crc32c_of_ranges` を一回捨ててから 5 回計って中央値を取り、各段の CRC が CPU と同じこと、どの回も PCIe リンクのピークより速くないことを照合する。最小二乗で a、b を当てはめ、第一段の B_批 で φ と n* を計算し、第二段の 16 スレッド飽和スループットで D24 (バックグラウンド重処理の GPU オフロード要否) 確定項目 3 の形の比（Q9）を計算する。
7. 単点チェック（`geometry-check` サブコマンド、変更二）：プールを作って幾何を照合するだけで、`name=geometry_attempt`、`name=geometry`、`name=segment_composition`、`name=segment_composition_summary`、`name=overwrite_landing`、`name=pool` の各行と最終行を出し、測定はしない。`--overwrite-order slot-order` は第 1 回再実行の版どおりに作る（すべて古いスロット番号の昇順、コピーの落ち先は数えない）。

### 計測条件

- CPU 時間は自スレッドの `clock_gettime(CLOCK_THREAD_CPUTIME_ID)` の二回の読み値の差（登録第一節、第十二節 12.2 で改訂。元の schedstat の読み方は実行中のスレッドに対して約 1 ms に一回しか進まない、実測値は 12.2）。`wall-clock`、`stage-split`、`foreground-fsync` は実行の最初に自スレッドで 1 ms スピンしながらこの時計を連続して読み、進んだ回数が 100 回に届かなければ停止して 3 で終わる（成果物の行 `name=clock_resolution_check`）。デバイス呼び出しの層では CPU 読み値が壁時計読み値を包み、ディスク待ち = 壁時計 − CPU で、純粋に CPU のデバイス呼び出しでは負になりうる（時計を読む手間の分）。一回の `run_compaction` 呼び出しの層では壁時計読み値が CPU 読み値を包む。このように入れ子にすると、二つの時計が同じ速さで進むとき「壁時計 ≥ CPU + ディスク待ち」が時計を読む順序のせいで崩れることはない。
- 一バッチの壁時計は、その一回の `run_compaction` 呼び出し（呼び出し末尾の discard を含む）を包む `Instant`。discard、バリア、ゼロ書き込みは呼び出しの種類ごとに別に列挙する。
- 実ディスクアーム：各測定の前に、前回の測定で変わった 4 MiB ブロックを起点のコピーから作業コピーへ書き戻し、イメージ全体のブロック要約（4 MiB ごとのブロックの SHA-256 をつないでもう一度 SHA-256 を取ったもの）が起点のコピーと同じことを照合する。メモリアームはラウンドごとに同じレシピで作り直し、二つのディスクのブロック要約が最初に作ったものと同じことを照合する。マウント時の journal レコードのオフセットのヒントは、ユニット領域の前に書いたセクタをそのまま写し（メモリディスクと同じ答え方）、`O_DIRECT` イメージ上でリング全体をスロットごとに読み通すことはしない。計時窓の中では写さない。
- デバイス：メモリアームは harness の疎メモリディスク。実ディスクアームは二台目の NVMe 一台（型番 CT2000T500SSD8、論理ブロック 512、`research/results/e185-r2-inputs-wall-clock-2026-10-23.txt` 第 22–26 行）上の ext4 にある二つのイメージファイルで、バリアは `fdatasync`、結論は「二台目のそのディスク上の ext4 にある `O_DIRECT` イメージファイル」とだけ言う（再実行登録第一節「実ディスク」）。元の登録が書いた本機のディスクは使っていない。
- バッチ：一回の呼び出しでユニットを移動したもの（セッションの `observations.batches_published` と同じ計測条件）。発行は別に列挙し、バッチに数えない。
- Q4 の `rises` は最初のバッチの壁時計の比が > 1（5 ラウンド中央値、かつ各ラウンド > 1）であることだけを求める。今回の 12 対の中央値は 1.015102–1.074115 で上がり方は小さく、判定基準はどれだけ上がったかを見ない。
- Q7 の「一バッチの CPU」はそのインテントのバッチ CPU の中央値を取る（元の登録以来の装置の読み方で、登録第六節「丙段はどう読み値を得るか」に固定）。丙段の値は発行の一回の `name=stage` 行の `choose_share_per_batch` で、各ラウンドはそのラウンドの有効なインテントの一つを取るので、`name=choose_judgement` の各マスには値が 5 つしかない。
- 第一行の陽性対照（登録第五節の陽性対照表第 1 行、CPU アームのディスク待ちの一文は第十二節 12.9 どおり）：標本点 f = 0.75、P = 1024、K = 8、`write_at` のたびに 2 ms 眠る（ディスクアーム）か、スレッド CPU 時計で 2 ms スピンする（CPU アーム）。増分はすべて対照各ラウンドの中央値 − ベースライン各ラウンドの中央値。ディスクアーム：インテント全体のディスク待ち増分が書き込み呼び出し回数 × 2 ms の [1.0, 1.5] 倍に収まり、CPU の変化が ±10% 以内（変更なし）。CPU アームは二つの文をそれぞれ報告する：CPU 増分が書き込み呼び出し回数 × 2 ms の ±10% に収まる（変更なし）。書き込み呼び出し（注入がある種類の呼び出し）のディスク待ち増分の絶対値 ≤ 書き込み呼び出し回数 × 2 ms × 10%（12.9 の新しい判定法、分母は注入量）。元の判定基準「インテント全体のディスク待ちのベースラインに対する変化が ±10% 以内」は計算して報告するが（`wait_change`、`wait_clause_under_the_original_criterion_holds`）、判定には使わない。対照点の各ラウンドで、各デバイスアームはベースライン、ディスクアームの対照、CPU アームの対照を続けて一回ずつ測り、順序はラウンド番号で回す（第 1、4 ラウンド ベースライン → ディスクアーム → CPU アーム、第 2、5 ラウンド ディスクアーム → CPU アーム → ベースライン、第 3 ラウンド CPU アーム → ベースライン → ディスクアーム）、ラウンド数 5。ラウンド番号で対にした増分の中央値は別に報告し、判定しない。
