### 何を測るか

- **状態**: 一回のマウントの中で、セッションの二回のユーザー変更の間の時点(`publish_user_change` が返った後)。書き込み可能マウントができた直後も一つの状態に数える。コア層の公開入口だけを経由して作る: mkfs、書き込み可能マウント、`MountedSession::publish_user_change`、正常アンマウント、録画ストリームの切り詰めで作るクラッシュ、デバイス呼び出しへのエラー注入。
- **T(この時点で書き込める最大バイト数)**: この状態のコピーの上で、`UserChange::SequentialWrite` が最初のファイルを n × 32634 バイトの内容で丸ごと置き換え、セッション(空き不足のためにセッションが押す F の引き上げを含む)を通して成功する最大の n に 32634 を掛けた値。T は拒否の理由が空き不足のときだけ有効で、他の理由で拒否された状態では T を「取得不能」と記録する。
- **過大報告と過小報告**: 候補 c が状態で X_c バイトを報告するとき、⌈X_c ÷ 32634⌉ > T ÷ 32634 であれば過大報告で、過大報告量は X_c − T。過小報告は T − X_c(> 0 のとき)。
- **幾何**(既定のリング 768 MiB、io_min 4096): G既定(4 GiB が 2 枚、S = 8)、G不等大(4 GiB と 3 GiB + 33 スロット)、G狭(3 GiB + 33 スロットが 2 枚)。幾何の感度のために G既定-S4 と G既定-S16 も取る。
- **履歴族**(各族は確定した 1 本のスクリプトで、シードは登録第五節に固定): HF 満杯、HO 上書き、HU 削除してから書き込み、HM 複数回マウント、HC 放棄されたルートと純解放、HL 長時間マウント。

### 判定基準(登録第六節、実行前に固定)

- Q1: 各 F2 アーム、各幾何の格で過大報告となる状態の数。= 0 なら「過大報告なし」、≥ 1 なら「過大報告」と判定する。Q2、Q3 は過大報告の最大バイト数と過小報告の上界を報告する。Q4 は T が取得不能な状態の数で、その格の状態数の 10% を超えたらその格の Q1–Q3 は判定しない。
- Q5: F5 の R2 の残差が 0 でない状態の数。固定ビット族と、放棄されたルート・純解放族に分け、両族とも = 0 なら「R2 は書ける」と判定する。Q6 は残差を「固定かつ隔離」のスロット数と並べて報告する。Q7: R3 の残差が 0 でない状態の数。≥ 1 なら「未済の検査の行の原式は到達可能な状態で偽」と判定する。
- Q8–Q11(第二段): F6 の各格(F が有効、F が無効)で、各アームの再試行した 1 回の書き込みが成功した例数。K0、K2、K3 が解放した後のクラッシュ窓で「上書きされた」クラッシュ状態の数(2 枚とも、ディスク 0 のみ残る、ディスク 1 のみ残るを分けて報告)。K3 が余分に押した空パブリッシュの回数。2 種類の格がそれぞれ何例作れたか。
- Q12: F8 で各幾何の格の各ディスクについて「セグメント内で閉じている空スロット − リング窓」のピーク、正になる状態の数、期末値。ピーク > 0 なら「S1 は到達可能な状態で過大報告する」と判定する。Q13 は閉じている空スロット自体のピークを報告する。
- 陽性対照: 各 F2 アームで max(X_c, T) + 32634 を別に計算し、それが過大報告と判定されなければならない。過大報告と既知の W0(複製数で割らず、コミット量を引かない)は T > 0 の状態で過大報告と判定されなければならない。X = 0 は過大報告と判定してはならない。F5 の R2 は、固定項を外したもの、重なり項を外したものが、それぞれ対応する状態で残差が 0 でなければならない。F8 のカウンタは、mkfs 後にディスク 0 で開いているセグメント [50240, 50304) の中の閉じた空スロットをちょうど 52 と数えなければならない。どれか一つでも当たらなければ、その段は無効とする。
- 改訂 1: T が journal レコード上限(既定のリング 65536 件)で切り詰められた状態は下界 L を記録し、候補が必要とするユニット数 ≤ L なら「過大報告はない」と報告し、> L なら「未確定」と報告して、どちらも過大報告数に入れない。改訂 4 はこれを、判定が変わる格だけで下界を絞り込む形に改め、第一段を 29 分割で実行してからマージするものとした。判定は一字も変わらない。

### 失敗条項(登録第十節)

- X1: F2 の候補が同じ幾何の格ですべて過大報告する: その格は識別できないアームに当たったものとし、アームの判定には使わない。
- X2: ある F2 アームが、向きの逆な二つの幾何の格で、一方では過大報告し他方では過大報告しない: 「不安定」と記録する。
- X3: Q5 がいずれかの族で ≥ 1: R2 の二項の式は書けない。
- X4: K2 または K3 が解放した後のクラッシュ窓で、リカバリが選ぶルートが参照するユニットを上書きする: そのアームは脱落する。
- X5: K0(書き込み失敗が返ったらすぐ解放する)でさえ上書きしなかった: F6 は Q8 と Q10 だけで提出する。
- X6: F が無効な格が作れない: F6 のその半分は足りないままで、「到達不能」とは推論しない。
- X7: Q12 がいずれかの幾何の格のいずれかのディスクでピーク > 0: S1 はこの履歴で過大報告する。
- 第十節の「条項が誤っている可能性」の項: 被検条項自身の拠り所(第七節 A1 から A4)が実装と合わないとき、その拠り所に関わる量は止めて差し戻し、装置の故障として無効にはしない。

### 計測条件

- 単位: スロットは 16 KiB。データユニットは 2 スロットで、各ディスクに 1 部ずつ置く。データユニットのペイロードは 32634 バイト(32768 − ヘッダ 134)。`df` の候補の値は常にバイトに換算して報告する。
- T の探査は状態のコピーの上で行い、デバイスはコピーオンライトのオーバーレイで、最初のデータユニットの書き込みが届いたらブロックデバイスエラーを返し、通過として記録する。この近道は、まず HF 族で全体書き込みと項目ごとに同じ判定になることを確かめてから使い、異なれば段全体を全体書き込みに切り替える(登録 5.1、改訂 2)。
- セッションにはオフセット付きの上書き書き込みの入口がないため、F8 の十分条件にある「オフセット付き上書き」は HL(丸ごと置き換え書き込みの長時間マウント)で代用する。「大きなファイルの局所上書きで、他のユニットを残す」ことで生じるセグメント内の空洞は覆えない(改訂 3.4)。
- 第一段の履歴では、F を引き上げる一連の処理はすべて丸ごと発行して丸ごと解放するため、固定の勘定 H は常に 0 で、固定ビットの半分は第二段に属する(改訂 3.5)。
