**第4区間は H7 を補完し、Q9 を完全な軌跡に拡張し、第3区間の発見①のスロットごとの根因を解明して、3つ目の読みが明確な敗北を追加**：G12（両シャドウ会計）はロールバック族 H4d2/H4dNm2/H5早/H5晚/H6/H7 の全12セルで I-3.1 が事前登録の「方式内の読み」と「今日の読み」の両方で不合格。根因は2層：① G12 の述語は「破棄 root の参照を保護する」責務を会計第1項へ直接取り込み（登録第5節 G12 主述語の「r が破棄された」分岐）、I-3.1 の「候補集合専用」定義と設計上整合しない。甲-T1 は独立シャドウ会計に全面的に委ねる。② 区間近似自体の偽陽性が重なる。破棄された時間線で既に交換されたスロットでも、区間 `[割当世代,解放世代)` に blocking root がかつて存在したため、root が現在別のスロットを指していても占有中と判定される。Q10 はこれを測るもので、本区間の手動確認は具体的反例を先に示したが、網羅はしていない。**同じく「敗北」のみ記録し、脱落の要否は判定せず G12 の定義も修正しない**。診断証拠（スロットごとの `actually_referenced_by`）は事前登録第12節第4区間、元の行は「成果物の数値」末尾を参照。

**第5区間で Q6b/Q7/Q10 と Q8 の一部を補完し、2つの新たな明確な結論**：Q7（合法状態での G27 の判別力）は実行した全720（族、セル、方式）行で0。G27 の「会計第1項 − 第5項 == 最新 root の走査参照」チェックは E153 の合法状態（L1、クラッシュ分岐を除く）で偽陽性なし。Q8 の判別力行列 B1a/B1b/B2/Bk1/Bk2（120の基底・方式組合せ中48が基底で既に不合格、72が判定可能）は登録 P5 に例外なく一致：B1a は4チェックすべて検出不能、B1b/B2 は G27 のみ、Bk1 は4つすべて、Bk2 は I-5.2 のみ検出。Q6b の2上界はロールバックを含む6族、全5方式、サンプル数が正の全360（族、セル、方式）行で**隔離スロット数に超過された**（上界が負になったことはない）。登録 F4「条項が誤りの可能性、メイン agent に渡す」と記録し、合わせるためにシャドウ会計定義を変えない。⚠️ 2026-09-17 にメイン agent が指示した読取専用確認（`alloc-basis-r3-forks-verify-e153.md` 第1節）では、装置の代理値（root 自身の参照集合の大きさ）は会計第1項 − 第5項に等しく、第1項には等しくないことが判明。各 root 永続化時の実際の第1項で再計算すると、4測定方式は依然毎回超過するが、ベースライン「今」は H4d2、H4dNm2 の672サンプルで一度も超えない。「5方式すべて超過」は4測定方式には成立するがベースラインには成立しない。超過の原因は元の式が数値差、隔離が集合差を用いるため。同じ確認で、登録は各 publish の回収ステップ前に条件付きで隔離集合を再計算するよう要求するが、装置の `recompute_shadow` は allocator 再構築時のみ呼ばれ、1回のマウント内で隔離がクリアされず、ロールバック族の隔離と過剰保持の軌跡が大きめになることも判明。Q10 は実行した全履歴で0。「G12×G28 が候補 root のツリーを別途読まず区間から推論する」支持者形態はこの履歴群では反証されなかった（第4区間で見つけた G12 **主述語**の相違とは別。実施内容8参照）。
