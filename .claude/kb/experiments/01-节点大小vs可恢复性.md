## E1 节点大小 vs 可恢复性 —— 部分已跑（爆炸半径那一半由 E30（坏一个节点的爆炸半径）还清，且判据被它纠正；恢复时间那一半仍欠 checker）

**产物**：爆炸半径那一半的原始输出在 `research/results/e30-blast-radius-2026-08-29.out`，
复跑 `cargo run --release --bin e30_blast_radius`（正文在 E30（坏一个节点的爆炸半径））。
⚠️ **恢复时间那一半没有产物，因为它一次都没跑过**——前置是 mkfs、checker、定点破坏工具。


**背景**：大节点省 seek、树更浅（bcachefs 用 128K–256K），
但**一个坏节点损失的范围随节点大小线性放大**，与本工程的可重建性目标直接冲突。
两边都要量，不能只挑一边说话。

**自变量**：节点大小 16K / 32K / 64K / 128K / 256K。

**测什么**

| 指标 | 口径 |
|---|---|
| 单节点损坏的爆炸半径 | 随机破坏 1 个元数据块后，**变得不可达的 key 数**（不是字节数——字节数会被节点大小本身带偏） |
| 全盘扫描重建的成功率 | 破坏 K 个节点后，靠自描述块头全盘扫描能重建出的 key 占比 |
| **可达但值陈旧或错误的 key 数** | 把重建出的 keyspace 与模型（那个理想文件系统 HashMap）逐 key 比对，**与「不可达」分开报两个数** |
| 查找代价 | 一次点查平均读多少个块；树高 |
| 元数据总量 | 同一份数据集下的元数据字节数 |

**判据**：在「全盘扫描重建成功率 ≥ 目标线」的前提下，取查找代价最低的那个节点大小。
目标线本身要先定——**这一步不能等实验结果出来再定**。

**怎样才算失败**：如果各档之间爆炸半径没有可分辨的差异，
说明破坏注入的方式不对（比如只破坏了叶子、或者破坏点没落在被引用的节点上），
**整轮作废重做**，不许拿「看起来差不多」当结论。

⚠️ **「可达但值陈旧」这一列不是锦上添花，是这个实验的判别力缺口。**
纯路由的内部节点丢了，损失的只是路由，叶子自带块头，扫描重建是**幂等**的；
而一旦内部节点里存了别处没有第二份的数据（例如消息缓冲区里还没下刷的更新），
丢了它损失的就是**数据**，重建出来的树可以块头对、校验和对、Merkle 链对——
**I-1（块自描述）.x 与 I-2（校验和）.x 全绿，内容却是旧的**。
[invariants.md](../invariants.md) 里现有的不变量没有一条能检出这一类。
不加这一列，E1（节点大小 vs 可恢复性） 会对「内部节点存数据」这类设计报出一个漂亮的重建成功率，
而那个数字什么也没保证。

**前置**：D8（核心索引结构） 定案、mkfs、checker、以及一个能定点破坏镜像的工具。

**顺带要产出的**：一条 mkfs 用的确定性选取规则——
输入设备特性（旋转 vs SSD、容量、擦除块/zone 大小），输出节点大小。
同样输入必须得到同样输出，且 mkfs 要打印出选取理由。
**测试一律显式钉死取值，不许用自动值**（见 decisions.md D8（核心索引结构））。
