## E33 Two Block Pinning Rules — Run (2026-08-29 Rerun After Reimplementation, N=5 Rounds Byte-identical)

[中文](33-两条钉块规则扣的不是同一批.md) · **English** · [日本語](33-两条钉块规则扣的不是同一批.ja.md)

**What it asks**: Whether the two "recently freed blocks forbidden from reuse" rules in the repository pin the same batch of blocks,
and how much space adjusting root ring depth K can actually free up.

⚠️ **Origin identical to E31 (AAD Lacks Snapshot Dimension) and E32 (Residuals from Previous Timeline)**: During adversarial verification,

**The main agent deleted code, mutation table, artifacts, and that `[[bin]]` registration** (unreviewed, unproven to fail red),
retaining only premises verified personally. **Disposition identical to E31 (AAD Lacks Snapshot Dimension) and E32 (Residuals from Previous Timeline):
delete code, retain design, rewrite a compliant implementation and run.**

### Verified Premises (Audited 2026-08-29)

The repository **indeed has two mutually distinct block pinning rules**, and their dimensions differ:

| Rule | Verbatim | Anchor |
|---|---|---|
| **Root Ring Rule** | "Blocks referenced by the most recent K generations of roots have physical extents not reallocated to other objects (K **≤** root ring depth, taking runtime effective value)" | [invariants/02-根环.md](../../../crates/singlefs-checker/invariants/02-根环.md) I-7.4 (Blocks freed in recent K generations not reused) |
| **Replay Window Rule** | "The true constraint is **the entire journal replay window**, not checkpoint boundaries" | D22 (Synthesizing Unit Atomicity) Settled Item 4 |

⚠️ **Their independent variables differ**: The root ring rule counts **root generations** (D23 (Journal Role & Format) Axis 1 takes Variant A ⇒ one generation per fsync),
while the replay window rule counts **fsync count since last checkpoint** (tail advances only after checkpoint persists).
⇒ **They do not pin the same batch of blocks, and nowhere in the repository had the two been computed together.**

### Assertion to Be Verified

The rationale of D22 (Synthesizing Unit Atomicity) includes this statement: "K must be a runtime policy... that would weld the **sole escape hatch** of ENOSPC deadlock
into the format: when disk is near full, the space most desperately needed for rescue is precisely the portion pinned by K".

**The assertion states**: If the set pinned by the replay window rule already contains (or mostly contains) the batch pinned by R1,
then the space bought by "adjusting K smaller can rescue" **is far smaller than implied by that rationale**—
the rescue space continues to be pinned by another rule that is outside the control of K.

⚠️ **Confirmed empirically**, quantified in "Measured Results". It depends on two unwritten matters handled in that section's measurement basis.

### What Is Measured, Criteria, Failure Clauses

- **What is measured**: Under given fsync rate and checkpoint interval, block set pinned by root ring rule, block set pinned by replay window rule, and **their union**;
  then sweep K to see how **union** changes with K.
- **Criterion**: `Space freed by reducing K = union(K) − union(K−1)`. If this difference is near 0 under realistic parameters, assertion holds.
- **Positive control**: Turn off replay window rule completely; space freed by reducing K must be significantly non-zero—
  otherwise "no space freed" cannot distinguish rule overlap from model not pinning blocks at all.
- **Failure clauses**: If across all parameter combinations the difference is significantly non-zero, assertion is invalid, **record truthfully**.
- ⚠️ **Must carry absolute assertions**: Sizes of both sets must be directly calculated by construction, not read back from tested code.

### Measured Results (2026-08-29, N=5 Rounds Byte-identical; 8 Blocks Freed per fsync, Taking Coarse Granularity Settled in D25 (Target Workload Priority))

⚠️ **Both readings were evaluated**, because the two repo statements differ by 1, and conclusions must not depend on this off-by-one:

| Reading | Origin | fsyncs Pinned by Root Ring |
|---|---|---|
| `invariant_i74` | Decidable form of I-7.4 (Blocks freed in recent K generations not reused) "blocks **referenced by** recent K generations of roots" | **K − 1** |
| `d22_prose` | D22 (Synthesizing Unit Atomicity) prose "retaining K generations of roots ⇒ space freed in recent K transactions forbidden from reuse" | **K** |

Derivation of `invariant_i74`: Block b freed at fsync t ⇒ generation t root no longer references it, generation t−1 root still references it
⇒ the K generations `{now−K+1 … now}` on the ring cover only **K−1** values of t.

**Primary Results (Checkpoint Interval 1000)**:

| K | Helpful Phases (I-7.4 (Blocks freed in recent K generations not reused) Reading) | Helpful Phases (Prose Reading) | Freed at Phase 0 | Total Pinned at Phase 0 |
|---|---|---|---|---|
| 2 | **0 / 1000** | **0 / 1000** | 0 | — |
| 4 | **2 / 1000** | **3 / 1000** | 16 | 24 / 32 |
| 8 | 6 / 1000 | 7 / 1000 | 48 | 56 / 64 |
| 16 | 14 / 1000 | 15 / 1000 | 112 | 120 / 128 |

**Positive control passed** (checkpoint interval = 1, replay window collapses to 1 slot ⇒ K becomes sole constraint):
Same K = 4 frees **16 blocks**, and that is the sole phase of that cycle ⇒ **metric indeed moves**.

**Three Readings**:

1. **"Helpful phases" = `root_ring(K) − 1`, independent of checkpoint interval.**
   Mechanism: The root ring rule pins more than the replay window rule only when `phase + 1 < root_ring(K)`,
   meaning **only in the few fsyncs immediately following checkpoint completion**.
   ⇒ At interval 1000 and K = 4, this escape hatch exists for only **0.2–0.3%** of a cycle.
2. ⚠️ **Phrasing like "250-fold difference" is forbidden** (struck down by tripartite debate counter-agent, updated in E33 (Two Block Pinning Rules)).
   That compared `max_freed` existing only at Phase 0 against whole-cycle average `mean_pinned_by_window`,
   which is a **cross-phase comparison**; the multiple also scales linearly with interval (~250× at interval 1000, only ~2× at interval 8),
   while interval itself is admitted as an arbitrary scenario point, not a measurement.
   **Same-phase comparison yields the opposite conclusion**: at Phase 0, root ring accounts for the bulk of pinned space (16 / 24 to 16 / 32).
   ⇒ **What is load-bearing is phase count, not the multiple.**
3. **The statement "sole escape hatch" collapsed, and none of three agents could rescue it**:
   Resolution of D23 (Journal Role & Format) Deadlock 2 is settled as **reserve pool** (`reserve ≥ ckpt_cost`);
   E19 (False ENOSPC Under Defer Window) empirically showed reserving 64 blocks reduced deadlocks from 199 to 0,
   reproduced by E25 (Reserve Pool Sizes for Ring vs Chained Log) with negative controls.

⚠️ **E33 (Two Block Pinning Rules) does not overturn the conclusion of D22 (Synthesizing Unit Atomicity) that "K is a runtime policy"**—
retaining extra root generations is pure availability gain, and a format constant would weld it shut. **What fell was that specific rationale.**
⚠️ **That conclusion itself changed form on 2026-09-13**: I-7.4 (Blocks freed in recent K generations not reused) verbatim "former 'K is runtime policy, floor ≥ 2' voided",
block reuse bound changed to `max(F_effective, oldest valid root on ring)` (D16 (Publish Semantics) Settled Item 1); E33 (Two Block Pinning Rules) disproving that rationale remains unaffected.

### Measurement Basis and Known Limitations

- **Pure arithmetic model**, both rules converted into "fsync count". **Does not model realistic allocation/release sequences**.
- **Releasing 8 blocks per fsync** taken from coarse granularity settled in D25 (Target Workload Priority). It is a scale factor:
  changing it scales all absolute values proportionally, **while the phase count conclusion does not depend on it**.
- **Checkpoint interval 1000** comes from modeling parameter of E23 (Journal Geometry);
  ⚠️ that figure is admitted as a **chosen scenario point, not a measurement**. Phase count conclusion is independent of it.
- **Does not model retention outside replay window** (ENOSPC admission reserve, uncompleted pending intent allocations),
  which would only make the other side larger, **preserving conclusion direction**.
- 9 unit tests, **all 6 mutations caught** (table in `scripts/mutation/tables/e33_pin_rules.tsv`),
  one specifically pinning "both readings must yield different numbers"—
  without it, merging both branches into one left zero tests red.

**Prerequisites**: None. Pure counting model.
