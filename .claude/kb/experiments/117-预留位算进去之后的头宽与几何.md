## E117 预留位算进去之后的头宽与几何 —— 已跑（2026-09-07，纯算术，12 单测 / 12 条变异全部被抓）

**问的是**：D18（块里携带什么信息） 已定项 7 的字段表算出数据单元头 105 字节，
**而同一节那句「v1 就预留 nonce 代号与 MAC 的字段位」里的两个位在表外**。
把它们算进去之后三类单元的头各多宽，下游几何各变多少。

**它答的是** C193（加密开启时的单元头有多大，全仓没算过），也是
D18（块里携带什么信息） 已定项 14 定案前用户要的那个数
（2026-09-07 用户：「取甲，但先把头宽算清楚再定」）。

### 三条臂

| 臂 | 预留位 | 是什么 |
|---|---|---|
| `bare` | 0 | 今天四个下游实验用的口径 |
| `resv12` | 12 + 16 = 28 | 已定项 14 **臂甲**：nonce 代号 = 完整 96 位 nonce，MAC 满 128 位 |
| `resv4` | 4 + 16 = 20 | **判别力对照臂，不是候选**——代号若只有 4 字节 |

### 逐字贴进源码的条款

| 条款 | 用到的那一句 |
|---|---|
| D18（块里携带什么信息） 已定项 7 | 「v1 就预留 nonce 代号与 MAC 的字段位」，理由「不预留则开加密成了布局变更」 |
| D9（加密） 已定项 2 | MAC 满 128 位不截断 ⇒ 预留的 MAC 位 16 字节 |
| D9（加密） 已定项 4 | 「指针头部为每个逻辑 extent 存一份 **96 位** nonce」⇒ 完整 nonce 12 字节 |
| D18（块里携带什么信息） 已定项 7 补注 | E73（节点 key 区间的扇出代价） 三档下界 58 / 67 / 76 各加写序 10 成 68 / 77 / 86 |
| D19（块指针的结构与宽度预算） 已定项 4 | 指针 59 ⇒ 内部条目宽 22 + 59 = 81（E73（节点 key 区间的扇出代价） 自己用的是 22 + 32 = 54） |

### 跑前写死的判据与失败条款

1. 头宽闭式：每类头 = 表内字段 + 预留位，逐类钉绝对值。
2. 码 2 扇出 = `(16384 − 头) / 条目宽`，条目宽取 54 与 81 两个，逐格钉绝对值。
3. 码 3 每容器记录数 = `(32768 − 头) / 140`，逐格钉绝对值。
4. 码 1 净荷 = `32768 − 头`，逐格钉绝对值。
5. **判别力**：`resv12` 与 `resv4` 必须至少在一格上不同。全格相同 ⇒ 判「取样点不敏感」
   （`.claude/rules/mutation-sampling.md` 第三类），去找跨整数边界的取样点，
   **不许记成「预留位不影响几何」**。
6. **阳性对照逐臂跑**：头强制为 0 时扇出 = 单元 / 条目宽、记录数 = 32768 / 140。
7. **阴性对照**：条目宽 > 可用字节 ⇒ 返回 0。

**失败条款**：判据 5 不成立时不许改判据，按第三类补取样点。

### 实测

| 臂 | 码 1 头 | 码 3 头 | 码 1 净荷 | 码 2 三档头 | 扇出（条目 54） | 扇出（条目 81） | 码 3 每容器记录数 |
|---|---|---|---|---|---|---|---|
| `bare` | 105 | 103 | 32663 | 68 / 77 / 86 | 302 / 301 / 301 | 201 / 201 / 201 | 233 |
| **`resv12`（臂甲）** | **133** | **131** | 32635 | 96 / 105 / 114 | 301 / 301 / 301 | 201 / 200 / 200 | **233** |
| `resv4` | 125 | 123 | 32643 | 88 / 97 / 106 | 301 / 301 / 301 | 201 / 201 / 200 | 233 |

⇒ **臂甲的几何代价是扇出各掉 0–1 格，码 3 的每容器记录数一格都不掉。**

### 三条对照的判定

| 对照 | 判据 | 实测 |
|---|---|---|
| 阳性（逐臂） | 头为 0 时扇出 = 闭式值 | 三条臂都给 303 / 202 / 234 |
| 判别力 | `resv12` 与 `resv4` 至少一格不同 | **满足**：条目宽 81 的第二档，`resv12` 给 200、`resv4` 给 201（产物 `cells_differing=1`）|
| 阴性 | 条目宽 > 可用字节 | 0 |

⚠️ **判别力那一格不在 E73（节点 key 区间的扇出代价） 自己的条目宽上**：条目宽 54 时两条臂逐格相同，
向下取整把那 8 字节差吃掉了。按 `.claude/rules/mutation-sampling.md` 这是**取样点不敏感**，
不是「预留位不影响几何」——留档在单测 `t10`，判别力由 `t09` 那一格承担。

### 跑前登记的一个值判否，留档不改

判据 2 跑前登记的是「`bare` 三档全是 302」，**实测 302 / 301 / 301**——
第二档 `(16384 − 77) / 54 = 301.05` 就已经掉一格。
登记那个值是主 agent 手算时只算了第一档就外推的；**第二次改判时又只改了第三档，还是没算第二档**。
两次错在同一个毛病：**拿一个取样点当三个**。
E73（节点 key 区间的扇出代价） 自己的说法是「三档结论一致（掉 0 或 1 格）」，与实测不冲突；
冲突的是本实验跑前那句更强的登记。两个值都留在源码 `t03` 里，跑前那个不许改成对的。

### 它答不了的

纯算术，没有 I/O、没有崩溃点重放。不答「E73（节点 key 区间的扇出代价） 的子指针宽度 32
该不该改成 59」——那是 C89（单元头收口的遗留重算） 的账，这里只把两个宽度都摆出来。
不重算 E97（记账与分配记录的条目编码）/ E98（inode 记录与 inode 树的几何）/
E103（inode 打包路 ① 的更新代价） 的内部模型，只报它们承重的几何数在新头宽下是多少。
**跑 N 轮说明的是没有隐藏状态，不是统计上稳定**——它是确定性模型。
