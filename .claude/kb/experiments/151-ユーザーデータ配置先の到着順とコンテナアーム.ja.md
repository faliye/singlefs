### モデル

E93 のスロット / defer / runs の計測条件を使用し、ノード骨格は E127 (分割統合下でのグループID保存要否)に従うが分割・マージはしない。単一オブジェクトノードに 1 key、コンテナに連続 ≤ 7 key。メンバーがダーティになるとコピーオンライトで単一オブジェクトとして移動し、残る 2 片は同じスロットに残る（runs は同じコンテナと扱う）。全メンバー移動後にスロットが defer に入る。runs は key 順に数える。到着順は一様置換（E93 の昇順ダーティ集合を同じ乱数生成器で再シャッフル）とリクエスト単位（連続 key の列を 1 リクエストとし、リクエスト間を同じ生成器でシャッフル、内部は key 順。D16 確定項目 5 の「1 書き込み要求をユニットごとに複数トランザクションに分割し各自番号取得」に従う）。完全空クラスタセグメントは期末値のほか、初期 (S − L) / G = 32 個を使い切るラウンド、その後のピーク、正となるラウンド数を記録。内生ブロックのフォールバックは別計数。各 checkpoint で key 順に ≤ 64 key を走査し、連続 7 個の「単一オブジェクト、前回書き込みから ≥ K」の key をコンテナに入れ bump 配置。内生ブロックは checkpoint ごとに bump セグメントから M 個確保し、次ラウンドに defer に入る。

### 答えられないこと

1. 計数モデル：時間軸も実機もなく、オブジェクトは固定幅ですべて ≤ 4 KiB の区分。
2. パッキング規則は仮定（checkpoint ごとに ≤ 64 key 走査、容量 7、key 順、前回書き込みからのヒステリシス）。D27 確定項目 6 の「1 トランザクション 1 マッピングリーフ」とレート制限はモデル化しない。コンテナの書き込み増幅は「コンテナ 1 件につき 1 書き込み」で数え、バイト単位ではない。
3. コミット内生ブロックはセグメントを占有するだけで木を作らず runs に入らず、寿命は 1 checkpoint（割り当てた次の checkpoint 冒頭に defer）。M の 3 段階は同じ bump セグメントから割り当て、ユーザーデータと同じオープンセグメントを奪い合う。first_fit の内生ブロックフォールバック 0 はこの寿命仮定の下限であり、実際のツリーノードはより長寿命。
4. D14 確定項目 2 のヒントアームは 1〜3 回目では構築せず、4 / 5 回目はディレクトリ単位の 2 アーム（`directory_hint`、`directory_home`）のみ。拡張子別、上位層が明示するヒントは構築していない。E122 (ディレクトリ集約で何が得られるか)の `grouped` はディレクトリ初期条件でありアームではない（第 7 項）。
5. 判定の幾何サンプル点への感度は巡回予算の一次元だけを走査した（C317 (判定が一つの幾何サンプル点でしか計測されていないことへの検査がない)：L / S / セグメント長 / D はすべて E93 (老化下の配置とフラグメンテーション度) の一つの幾何のままで、走査していない。`PACK_SWEEP_PER_CHECKPOINT = 64` と `DIRTY_PER_CHECKPOINT = 64` が等しいという次元は、3 回目の実行で 64 / 256 / 1024 を走査した。結論 4）。
6. 「リクエスト内ユニットを key 昇順に発行」は arrival_by_request の前提で、実行時は推論で条項ではなかった。現在は D16 確定項目 5 の分割規律に含まれる（C319 は返済済み、返済済み負債表参照）。逆推レッグコピーではリクエストはグループ到着するが内部が無順序の場合 8117 で、一様置換との差は 0.8%。
7. ディレクトリ形状は 1 種のみ（連続 32 key、初期連続、t = 0 では 5 アームがセルごとに一致。E122 の `grouped` はこの初期条件でアームではない）。ディレクトリ間の交互作成や追加・削除はない。2 負荷はディレクトリ形状が同じで連続書き換えかだけが異なる（runs8 は要求の 78% が同一ディレクトリに入りヒントに有利、uniform は各ディレクトリ各ラウンド 0.25 回で減数に有利）。ディレクトリ局所性の 3 量は期末に 1 回測り軌跡ではない。H9 の「≤ 3 セグメント」は固定ホームアームの定義（ホーム + 溢出 + 1 フォールバック）と同義反復で、メンバー追従アームにのみ判別力がある。内生ブロックのフォールバックは溢出数の関数（5 回目）であり方針の性質ではない。
8. 整理アームの `R` はユーザーノードのみを移し、`R` の内生ブロックは移さない（次ラウンドに自力解放）。毎ラウンド 1 インテントで予算と水位は設けない。`R` 解放後は保護せず、次ラウンドに最小空きスロットのユーザーデータが消費する。この半分は D26 確定項目 1 に属する。
9. 逆推レッグコピーの「コンテナ自体も最小空きスロット」のアーム（runs8 K = 16 M = 9 の期末空セグメント 73）は登録装置に入っていない。登録済み container_firstfit はパッキング前の配置のみ変更。
