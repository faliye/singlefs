## E99 write buffer 条目与 seq 的去重 —— 已跑（2026-09-03，纯计数，12 单测 / 10 条变异全抓）：**记账树的 key 里已经有代 ⇒ seq 只要 4 字节的窗口内序号；在 seq 里再放一份 txg 是重复计账**

**它要答的是 D8（核心索引结构） 未定项 7（write buffer 条目自带的 `seq`）**：多宽、住哪、跨挂载单不单调。
该项判过「改第一个事务的字节：**是**」。

### 判据（跑前写死，跑完不许改）

1. **位宽账要算得出，不许估**：`seq = (checkpoint_txg, 窗口内序号)` 的两段各占几位、
   合起来几字节，**必须是绝对值**。给定 `checkpoint_txg` 是 64 位（D22（单元原子性怎么合成） 已定项 7），
   **8 字节一个位都不剩** ⇒ 模型要报出「窗口内序号可用位数 = 0」这个事实，而不是含糊过去。
2. **去重确定性**：四条臂各跑同一串更新——① 无 seq；② 墙上时钟；③ 每次挂载归零的计数器；
   ④ `(checkpoint_txg, 窗口序号)`——**数「选错胜者」的次数**。每条臂都要绝对值，不许只做臂间互比。
3. **跨挂载单调性**：在更新串中间插一次挂载，重跑判据 2。臂 ③ 的错误数必须**上升**，臂 ④ 必须恒 0。
4. **截断的代价**：若把 `checkpoint_txg` 截到 `w` 位以腾出窗口位，回绕之后同一串更新里
   「选错胜者」的次数是多少？按 E44（序号位宽的本机实测与代价） 的 2785 发布/秒给回绕期。
5. **窗口内序号要多宽**：一次发布窗口内同一个 key 最多被写几次，决定窗口段的位宽下界。
   按 D16（发布语义） 已定项 5 的 `T_dirty` = 2 GiB 与 D5（快照 / 空间记账机制） 已定项 5 的 30 字节条目反解。

### 失败条款（跑前写死）

| 条款 | 触发时怎么判 |
|---|---|
| **阳性对照，每条臂都跑**：臂 ① 无 seq 必须错得最多，臂 ③ 在插挂载之后必须比不插时更错 | 不成立 ⇒ 去重模型没接上，**整轮作废** |
| **阴性对照**：把更新串改成同 key 只写一次，四条臂的错误数必须全为 0 | 不为 0 ⇒ 模型在无歧义输入上就已经出错，整轮作废 |
| **反向接受条款**：若判据 1 算出 8 字节装不下，而判据 4 算出截断会带来 > 0 的选错 | 结论是「**8 字节不够，seq 要加宽**」，如实写，**不许把窗口段压到 0 位硬凑** |

### 实测（2026-09-03，纯计数，N=5 轮逐字节一致，12 单测 / 10 条变异全抓 + 2 条等价变异留档）

**口径与复跑**：代码 `research/e7-index-bench/src/bin/e99_writebuffer_seq.rs`，
产物 `research/results/e99-writebuffer-seq-2026-09-03.out`（37 行，收尾 `emitted=37`），
变异表 `research/mutations/e99_writebuffer_seq.tsv`，已挂 `research/scripts/replay.sh`。

#### 判据 1 + 5：**8 字节装不下，12 字节才够**

| seq 宽 | `checkpoint_txg` 占 64 位之后剩给窗口序号 |
|---|---|
| 8 字节 | **0 位** |
| 10 字节 | 16 位 |
| **12 字节** | **32 位** |

窗口序号的需求下界：一个发布窗口最多装 **71 582 788** 条记账条目
（`T_dirty` 2 GiB ÷ D5（快照 / 空间记账机制） 已定项 5 的 30 字节条目）⇒ **至少 27 位**。
⇒ 若 seq 要**自己带一份** `checkpoint_txg`，8 与 10 字节都不够，12 字节够。

#### 判据 6（第二轮补）：记账树的 key 里**已经有代**，seq 不必重复携带 txg

D5（快照 / 空间记账机制） 已定项 5 逐字定 key = `(统计量标签 2, 树 ID 8, 设备 4, **代 8**)`，
D16（发布语义） 已定项 6 定「代 = checkpoint 号」，D5（快照 / 空间记账机制） 已定项 2 的骑手条款
逐字补「记账条目的**跨发布合并不再可行**（代进了 key）」。

⇒ **同一个 key 的待去重条目必然同属一个发布窗口** ⇒ seq 只需要窗口内序号：

| key 形态 | 需要的 seq 宽 | txg 是不是 key 里已有段的重复 |
|---|---|---|
| 记账树（key 含代）| **4 字节** | **是** |
| 反向索引 / LRU（key 布局仓里没定）| **不适用** | 判不出来 |

⚠️ **12 字节那个数是重复计账**——它把 key 里已有的「代 8」在 seq 里又抄了一遍。
⚠️ **这一条只对 key 里含代的树成立**，另两棵树的 key 布局没定，模型报「不适用」，不外推。
⚠️ 由此，判据 2 / 3 那张跨挂载的表**在记账树上射程之外**：同一个 key 的条目按 key 结构
不可能跨挂载并存。那张表回答的是「若 key 里没有代会怎样」，对另两棵树仍有意义。

#### 判据 2 + 3：只有从 `checkpoint_txg` 派生的那条臂跨挂载还对

1000 个 key、每个 8 次更新、按 key 排序之后到达顺序被丢掉：

| 臂 | 不插挂载（选错 / 未定义）| 插一次挂载（选错 / 未定义）|
|---|---|---|
| 无 seq | 0 / **1000** | 0 / **1000** |
| 墙上时钟 | 0 / 0 | **1000** / 0 |
| 每次挂载归零的计数器 | 0 / 0 | 0 / **1000** |
| **`txg + 窗口序号`** | **0 / 0** | **0 / 0** |

⚠️ **「选错」与「未定义」要分开数**——D8（核心索引结构） write buffer 硬要求 3 逐字说
「用不稳定排序时同 key 条目的**相对次序未定义**」，模型不许替实现挑一边。
阴性对照：同 key 只写一次时四条臂全部 0 / 0。

#### 判据 4：截断「代」的代价——它撞的是**键的同一性**，不是排序

代按 D5（快照 / 空间记账机制） 已定项 5 进了 key ⇒ 截断它之后，回绕的两个 checkpoint
**塌成同一个 key**，条目被错误合并。可数的违例（2026-09-04 补测，
第一、二版只打印回绕期、那个数从没接到任何违例计数上）：

| 代段位宽 | 1000 次发布 | 10 万次 | 一千万次 |
|---|---|---|---|
| 8 位 | **1464** 对 | 19 481 280 对 | 195 307 500 032 对 |
| 16 位 | 0 | 34 464 对 | **757 947 392** 对 |
| 32 位 | 0 | 0 | 0 |
| 48 位（已定下界）| 0 | 0 | **0** |

回绕期（按 E44（序号位宽的本机实测与代价） 的 2785 发布/秒）：保留 32 位 ⇒ **17 天**
（与 D5（快照 / 空间记账机制） 已定项 2 骑手条款的「32 位 17.8 天」同一个数）；
保留 48 位 ⇒ **3204 年**（与 E44（序号位宽的本机实测与代价） 的「48 位撑 3202 年」同量级）。

### 它答不了的

纯计数模型：没有 write buffer 实现、没有真 flush、没有并发、没有崩溃点重放，文件操作 0 处。
**不答「write buffer 落不落盘」**——那是一条仓里没写过的前置，E99（write buffer 条目与 seq 的去重） 按「落盘」与「不落盘」
两种读法各报一次影响，不替它定。
