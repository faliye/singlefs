## E95 老化したノードレイアウトアーム —— 実行済み（2026-09-09、純算術、20単体テスト / 20件ミューテーション全検出）

[中文](95-老化的节点布局臂.md) · [English](95-老化的节点布局臂.en.md) · **日本語**

**問題**：D26 (バックグラウンド整理と配置回収) 確定項目 4 は「構造的抗老化はどのような形態を取るか」を問い、
一方 E93 (老化下の配置とフラグメンテーション度) にはポリシーアーム（クラスタ配置、近傍書き換え、整理）のみが存在し、
**ノードレイアウトに手を加えるアームが1つも存在しなかった** —— したがって「ポリシー形態で十分か」をモデル層で比較することができず、
確定項目 4 のバイト判定（新規プールでのファイル作成のバイト変更：はい）を覆すこともできなかった
(2026-09-03 三者論証、順推論レグと逆推論レグで同一判定）。
E95 (老化したノードレイアウトアーム) はまさにそのアームを補うものである。

### モデル

E93 (老化下の配置とフラグメンテーション度) のオブジェクト / スロットモデルと2組のワークロードを踏襲し、
2本の**フォーマット級**候補アームを追加し、ポリシーアームと同一のワークロード、同一の追加書き込み予算セットの下で比較する：

| アーム | フォーマットのどこに手を加えるか | 機構 |
|---|---|---|
| ノードグループ | ノードヘッダがグループ識別子を保持（key 上隣接する G 個の 16 KiB ノードが1つの配置・書き換えユニットを構成） | 書き換えはグループ単位：グループ内のいずれかのノードがダーティになればグループ全体を1つのセグメントに再配置 —— BetrFS の大ノード効果の明示化、ノードサイズは依然として D8 (コアインデックス構造) 確定項目 2 の 16 KiB |
| 世代分離 | ノードヘッダが老化世代を保持（前回の書き換え以降のチェックポイント数で階層化） | 配置を世代ごとに区分：ホットとコールドを同一セグメントに混在させず、整理はホット領域のみを清掃 —— ログ構造クリーニングにおける年齢別分離 |
| ポリシーアーム（対照） | フォーマット不変 | E93 (老化下の配置とフラグメンテーション度) の bump_compact(B) および bump_neighbor(R) をそのまま再利用 |

**フォーマットアームには最も有利な実装を与える**（`.claude/singlefs-ai-sop/rules/evidence-discipline.md`
藁人形条項）：グループ識別子と老化世代はともにゼロコストで読み取り可能とみなし、配置器はそれらを最適に利用する。

### 判定基準（2026-09-03 実行前固定、実行後変更禁止）

1. **手計算アンカー**：8オブジェクト、グループサイズ 2：1つのオブジェクトがダーティになればグループ全体を再配置、runs を手計算通りに固定。
2. **保存則**：E93 (老化下の配置とフラグメンテーション度) と同一セット（増分 runs == 監査、占有恒等、defer スロット再利用不可）。
3. **陽性対照が各アームでゲート通過**：強制配置スイッチ下で完全隔離レイアウトは runs == L を報告、連続レイアウトは runs == 1 を報告。
4. **同等予算比較**：追加書き込み倍率は 1.5× / 3× / 5× の3段階を取り、各段階各アームの中央値 runs（5シード）を報告。
5. **回答すべき1つの問い**：最も有利な実装のフォーマットアームが、**いずれかの**同等予算セルにおいて runs をポリシーアームの半分以下に抑え込めるか。可能 ⇒「ポリシーで十分」は覆り、D26 (バックグラウンド整理と配置回収) 確定項目 4 のフォーマット部分は真の形態を確定しなければならない；不可能 ⇒ モデル層は「フォーマット不変」を支持し、バイト判定反転の証拠チェーンに1つの環が補われる（レイテンシ軸は依然として E10 (老化：構造的抗老化 vs 事後整理) に帰属）。
6. E10 (老化：構造的抗老化 vs 事後整理) を代替しない；デグレード判定基準は依然としてそれに帰属する。

### それが答えられないこと（2026-09-03 実行前固定）

1. カウントモデル：レイテンシ軸なし、メッセージバッファのバッチ化統計なし、実機なし。
2. 2本のフォーマットアームは候補であり網羅ではない：他のノードレイアウト形態が提案された場合、アームを追加して再実行する必要がある。
3. グループ識別子と老化世代が実際のフォーマットで何バイトを占めるか、D11 (インデックスノードにメッセージバッファを残すか) の 665 エントリのバッファと領域を取り合うかはモデルは計算しない。

### それが答えられないこと（実行後に判明したもの、2026-09-09 に3点 + 2026-09-10 に3点）

**これらは判定基準ではなく射程注釈である**：判定基準 5 の字面通りの結論はこれらに影響されないが、
**「この結果を用いて決定を変更できるか」は影響を受ける**。

4. **勝利した機構は、このモデル内ではいかなるフォーマットビットも必要としない。**
   `fmt_group_gN` のグループは `key / N` で計算されている —— モデル内では key からオブジェクトへは静的1対1対応であり、ノードの分裂合併がないため、配置器はいかなるディスク上フィールドを照会せずともグループ識別子を把握できる。一方モデルの節で登録されたアームは逐字的に
   「ノードヘッダがグループ識別子を保持（key 上**隣接する G 個の 16 KiB ノード**が1つの配置・書き換えユニットを構成）」である：
   **ノード数によるグループ化**を行って初めてフィールドを保存する必要が生じ、**key 区間によるグループ化**では不要である。
   ⇒ 測定されたのは「固定境界のグループ全体再配置が スライディングウィンドウとラウンドロビン整理に勝利する」ことであり、
   「ノードヘッダ内のそのグループ識別子フィールドが必須である」こと**ではない**。両者を弁別するには、分裂合併を伴うモデルが必要である。
5. **runs8 列の勝ち分はグループサイズとの整列に関係している**：ワークロードの書き換えセグメント長は逐字的に 8 であり、最も多く勝利したアームは `fmt_group_g8` である；
   一方同一アームは uniform 上では（7558 / 5797 / 3669）逆に `fmt_group_g2` に抑え込まれている。
   ⇒ グループサイズはワークロードの局所性に合わせて選択する必要があり、選択を誤れば利益はない。
6. **結論は予算軸上で単調ではなく、登録された3段階は変曲点をカバーしていない。**
   実行完了後、scratchpad コピー上で extra = 512（write_amp 9×）のプローブを追加（**成果物は未保存**、
   判定基準に含めず、再実行にも含めず）：uniform 上で `pol_compact=1037` が `fmt_group_g2=2545` を逆転、
   runs8 上で `pol_compact=195` が `fmt_group_g8=401` および `fmt_group_g32=230` を逆転。
   ⇒ **フォーマットアームの優位性は 1.5×–5× の区間に位置し、予算がさらに大きくなれば逆転する**；変曲点は 5× と 9× の間にあり、未測定である。
   ⚠️ 2026-09-10 逆推論レグが 512 の段階の4つの数値を独立再現（字面通り一致）、さらに 1024 へと上方外挿：
   `pol_compact` は 576 / 102 を報告し、**6本すべてのフォーマットアームに勝利**、逆転は予算に伴い単調に深化する。
7. **グループサイズの3つのサンプリング点（2 / 8 / 32）はノードグループアームを過大評価したのではなく、過小評価した。**
   逆推論レグが g ∈ {1,2,4,8,16,32,64} × セグメント長 ∈ {1,2,4,8,16,32} をスキャン：最適 g は**予算に連動**し、
   ワークロードセグメント長には連動しない ⇒ 第5項の「グループサイズとの整列に関係している」という説明は**記述された形態では成立しない**。
   実測の格差：`budget=128 load=runs8` の真の最適は g16 = 522 であるのに対し、登録された3点グリッドは 904 を報告（1.73倍劣る）。
8. **`fallback_pct` は勝ち分の傍証としては使えない。**（本文「結果」節で引用）
   逆推論レグの実測：世代分離アームのフォールバックカウント計測条件を整列させた後、18セルのフォールバック率は 55.7–89.8 からすべて 0.0 に変化し、
   一方 `runs_median` は **18セルで字面通り不変** —— `run_length_in_slots == 1` のとき `find_free_run(1)` と `allocate_first_fit` が
   同一のスロットを返し、後者のみがカウントするためである。⇒ その列が測定しているのは「どのコードパスを通ったか」であり、「配置の良否」ではない。
9. **クロスハーネスゲートは共有基盤のみを保護し、新規追加された2本のアームを保護できない。**
   `step_node_group` / `step_generation_separation` / `place_generation_run` / `extend_neighbors_budgeted` は
   `run_e93_arm` 内に **0 回**出現 ⇒ 14 個の median がすべて一致することは、Sim / dirty_set / place_run の基盤が
   E93 (老化下の配置とフラグメンテーション度) と同源であることを証明するのみで、新アームについては一字も語っていない。`pol_neighbor` も同様にゲート外にあり、
   まさにそれが `budget=32 load=runs8` という決戦セルの対戦相手である。
