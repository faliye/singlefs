## E127 Whether to Store Group Identity Under Splits and Merges —— Run (2026-09-13, deterministic model, 17 unit tests / 14 mutations caught)

[中文](127-分裂合并之下组身份要不要存.md) · **English** · [日本語](127-分裂合并之下组身份要不要存.ja.md)

**Problem**: After running E95 (Aged Node Layout Arms), D26 (background compaction and placement reclamation) settled item 4 was blocked on a **modeling gap**, no longer blocked on "nobody has run that experiment".

The arm winning the comparison in E95 (Aged Node Layout Arms) (node grouping) **consumed zero on-disk fields** in its model ——
group identity was calculated via `key / g`. Registering that identical function under a different tag as a policy arm,
**all 48 rows of `runs_median` were verbatim unchanged while the six verdict cells flipped completely** (item 4 of "What It Cannot Answer" in that document and main agent replay).
The root cause lay in the identical spot: in the model of E95 (Aged Node Layout Arms), keys mapped to objects in **a static one-to-one manner without splits and merges**,
causing "grouping by key interval" and "grouping by node count" to produce identical numbers,
**whereas only "grouping by node count" requires storing a group identity in node header**.

E127 (Whether to Store Group Identity Under Splits and Merges) repairs that gap: introducing splits and merges into the model so that these two groupings **can potentially** yield different numbers.

**Conclusion (Run completed, per criterion 6 hardcoded before run)**: Across six equal-budget cells, grouping by node count **did not suppress runs below 0.8x of key interval grouping on a single cell** ⇒ **model layer supports 'group identity does not need to enter format'**, that arm retreats to policy tier, and byte judgment of D26 (background compaction and placement reclamation) settled item 4 requires re-adjudication (this step is a deduction, fifth round tripartite review `research/prompts/d26-r5-main-verification.md`). First run (W ∈ {8, 32, 128}, G ∈ {2, 8, 32}) had six cell ratios 0.930 / 0.889 / 0.957 / 1.651 / 1.856 / 1.031, each arm winning three cells; **second run supplemented both knob families into identical node widths (W ∈ {8, 16, 32, 64, 128, 256}, G ∈ {1, 2, 4, 8, 16, 32}), after which key interval grouping swept all six cells** (1.004 / 1.043 / 1.072 / 1.116 / 1.108 / 1.134) —— in the first run, the three cells where "grouping by node count was slightly better" resulted from key interval grid omitting W = 16, and the two cells where it was "65%–86% better" resulted from node count grid omitting G = 4, as first deduced by counter-deduction probe and confirmed in repository by the second run. Per failure clause row: "Key interval grouping sweeps all ⇒ valid result, with a separate note: storing group identity is not only unnecessary, but harmful."

### This Is a Deterministic Model, Not Measurement

Fixed seed, zero I/O, zero variations outside random source ⇒ running N times gives byte-for-byte identical output. Evidence strength derives from **pinned absolute values in 17 unit tests + all 14 mutations caught**: splitting not at midpoint, split-off node always following splitting party's group, merge threshold changed from < to ≤, retired node adjacency pairs uncounted, cross-apparatus table modified by one cell, policy arm compaction batch not skipping dirty nodes, both grouping arms never relocating whole groups, rank-th key off by one, splitting forgetting to account unplaced nodes, policy arm spending one extra budget, dirty keys all mapped to location 0, not inserting, criterion 6 threshold changed to 1.0 —— every single mutation has failing tests.

### Model

Inherits slot, defer, fragmentation, and equal-budget measurement basis of E93 (Placement and Fragmentation under Aging) / E95 (Aged Node Layout Arms),
**with only one change**: objects are no longer fixed-length static arrays, but housed inside **nodes** that undergo splitting and merging.

| Component | Definition |
|---|---|
| Node | Each node occupies one physical slot; capacity `C` keys, splits from midpoint when exceeding `C`, merges with neighbor when below `C/4` |
| Workload | Beyond the two workloads of E93 (Placement and Fragmentation under Aging) (uniform / runs8), **must add inserts and deletes** —— without inserts and deletes there are no splits or merges, leaving the experiment with zero objects |
| Fragmentation | `F = runs / node_count`, runs traverse physical contiguous runs in **node key order** (identical pattern to E93 (Placement and Fragmentation under Aging), only switching unit from object to node) |

**Three arms, equal budget** (extra write count = per checkpoint `D × (X − 1)`, X takes 1.5 / 3 / 5):

| Arm | How Group Is Determined | Whether On-Disk Fields Are Needed |
|---|---|---|
| **Key interval grouping** | Group = fixed key interval `[i·W, (i+1)·W)`, node count in a group floats with splits and merges | **No** —— allocator computes directly from key |
| **Node count grouping** | Group = `G` adjacent nodes in node order; on node split new node inherits splitting party's group number, opening new group when full | **Yes** —— node order is not a function of key, group number must live in node header |
| **Policy arm (control)** | `bump_compact(B)` of E93 (Placement and Fragmentation under Aging), B = budget | No |

### Criteria (Hardcoded Before Run 2026-09-10, Never Modified After)

1. **Manual calculation anchor**: 8 keys, node capacity 2, group width 2: inserting one key triggers one split, group partitions of both grouping arms **hardcoded by manual calculation**, and must be **mutually distinct** after split —— if both arms are identical on anchor, the model lacks discriminative power, entire round invalidated.
2. **Conservation**: incremental runs == audit runs (per sampling point); total keys in nodes == live keys; free slots + occupied slots == total slots; deferred slots cannot be reused in current round.
3. **Positive control passes gate on every arm**: under forced placement, fully isolated layout reports `runs == node_count`, contiguous layout reports `runs == 1`.
4. **Splits and merges truly occurred**: each arm reports split count and merge count for this round, **both must be > 0**, otherwise entire round invalidated (`.claude/singlefs-ai-sop/rules/test-discipline.md` "Negative results must be distinguishable from 'code was never reached'").
5. **Cross-apparatus gate**: disabling inserts/deletes and setting node capacity to 1, the three arms must reproduce verbatim the `runs_median` of corresponding cells in E95 (Aged Node Layout Arms) committed artifact; mismatch judged red.
6. **Question to answer**: on **any** equal-budget cell, can "grouping by node count" suppress runs below **0.8x** of "grouping by key interval" (threshold hardcoded before run)? Yes ⇒ group identity **must** be stored in node header, format portion of D26 (background compaction and placement reclamation) settled item 4 must settle concrete shape and width; No ⇒ **model layer supports 'group identity does not need to enter format'**, that arm retreats to policy tier, and byte judgment of D26 (background compaction and placement reclamation) settled item 4 requires re-adjudication.
7. Does not substitute for E10 (Aging: Structural Aging Resistance vs Post-Hoc Compaction); time axis and degradation criteria remain under it.

**Swept ranges** (strawman clause): Second run unified both families into identical node widths 1 / 2 / 4 / 8 / 16 / 32 —— key interval width W ∈ {8, 16, 32, 64, 128, 256} (initially 4 keys per node, stride 2 ⇒ W = 8 is 1 node wide), node count grouping G ∈ {1, 2, 4, 8, 16, 32}; across six cells best knob for key interval was W = 16 / 16 / 16 / 32 / 32 / 64, best knob for node count grouping was G = 2 / 2 / 2 / 4 / 4 / 8. First run only swept W ∈ {8, 32, 128}, G ∈ {2, 8, 32}; being on different grids, each omitted one tier in opposite directions.

**Why splits and merges separated the two arms**: Group identity in node count grouping follows the node —— split-off nodes inherit the splitting party's group, opening a new group when full, while merges shrink groups; after 2000 checkpoints group members are no longer contiguous in key order, and relocating whole groups places nodes non-adjacent in key order together. Key interval grouping always partitions by initial key, relocating nodes that are adjacent in key order. Under large budgets (128 / runs8, 256) key interval grouping wins by large margins, demonstrating that runs (physical contiguous segments counted in key order) specifically reward "placing adjacently in key order", while group identity in node count grouping drifts further from key order with age.

### What It Cannot Answer

1. Counting model: no time axis, no message buffer batching statistics, no real hardware.
2. Split and merge rules represent one choice (midpoint split, `C/4` merge), not rules settled by D8 (Core Index Structure) ——
   D8 (Core Index Structure) did not settle split point and merge threshold, so this **must** be labeled as a model assumption in artifact.
3. How many bytes group identity occupies in real format, and whether it contends with 665 buffered messages of D11 (Whether to Reserve Message Buffer in Index Nodes), model does not calculate ——
   E101 (Cost and Expressiveness of Reserving Space in Node Header) verbatim ruled "number of node groups has no upper bound from any settled clause, model reports `UPPER_UNKNOWN`",
   nor does E127 (Whether to Store Group Identity Under Splits and Merges) resolve this cell.
4. It answers "whether to store", not "how wide to store".
5. Model assumptions (choices settled only after running, not clauses): midpoint split (left ⌊n/2⌋); merge target is right neighbor (left neighbor if no right), split again if > C after merge; main grid geometry 8192 nodes, capacity 8, initial 4 keys per node, key space 65536 (initial keys even), insert 16 delete 16 per checkpoint; groups in node count grouping only open new groups upon split, never rearranging. Changing split/merge rules requires re-running.
6. Unit of runs is nodes: key count inside a node does not enter fragmentation.
7. Sensitivity of verdict to geometric sampling points (fifth round counter-deduction probe, uncommitted, `research/prompts/d26-r5-main-verification.md` Section 3): when inserting more and deleting less (insert 20 delete 12), a store-group-identity arm where "groups maintain node-order contiguous blocks and split/merge themselves" won all four cells, best 0.876 —— still unable to reach 0.8; at capacity 32 ratio of both families was 0.999–1.007, model lacking discriminative power. Main grid geometry (capacity 8, insert 16 delete 16, node count contracting from 8192 to 7398) is not given by any settled clause; criterion 6 was measured at only this single geometric sampling point, recorded as C317 (verdict measured at only one geometric sampling point without verification).
