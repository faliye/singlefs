## E125 シーケンシャルゾーン書き込みポインタ上方で読めるデータ —— 実施済(2026-09-09、5 ラウンド 1 バイト違わず一致、6 件のミューテーションがそれぞれ赤判定となることを証明済）

[中文](125-顺序区写指针之上读到什么.md) · [English](125-what-is-read-above-write-pointer-in-sequential-zone.en.md) · **日本語**

**答える対象は D22 (ユニット原子性の合成手法) 未定項目 6 の甲問である**：「アドレッシングヒントのみ」アームの第 2 の脱出口
（WP で候補セットを限定せず、ゾーン全体のスキャンに変更）が成立するか否か。同アームの当該ラウンドで逆推レッグに突かれた第 1 点は逐字的に以下であった：

> WP で候補セットを限定するか（**WP が新世代選択に参入し、「アドレッシングヒントのみ」アームの前半と後半が自己矛盾**）、
> ゾーン全体をスキャンするか（**本プロジェクトが書き込んでいない WP 上方のバイト列を読み出すことになり**、ユニット全体チェックサムを通過しない ⇒ 破損と判定されるが実際は未書き込み）。

**当該ラウンドでは観測値がゼロであった。** しかし観測は取得可能である：ローカル環境に `null_blk` が存在し（`modinfo` 逐字的に `zoned` / `zone_size` /
`zone_capacity` / `zone_nr_conv` / `zone_max_open` / `zone_full` あり）、`/usr/sbin/blkzone` が存在する。
E125 (シーケンシャルゾーン書き込みポインタ上方で読めるデータ) はその観測値を取得しに行ったものである。

### 判定基準（実施前確定、実施後変更不可）

1. **WP 上方で何が読み出されるか。** 空のシーケンシャルゾーン内にルートスロット幅のレコードを N 個追記後、`[wp, zone_end)` を読み出す。
   結果は以下の 3 種のいずれかのみであり、**被テストアームへの影響は実施前に確定**：

   | 観測結果 | 「アドレッシングヒントのみ」アームへの影響 |
   |---|---|
   | ① 読み出し成功かつ**全ゼロ** | ゾーン全体スキャンの脱出口で**バイト列を読み出し可能**。⚠️ 「全ゼロ」と「破損」を分離するルールを別途設ける必要があるが、そのルールの入力はゼロ値自体で足り、WP である必要はない ⇒ 同アームの**この半分は成立** |
   | ② 読み出し成功かつ**非ゼロ** | 脱出口は非ゼロゴミデータと破損を分離する新ルールを支払う必要があり、**E125 (シーケンシャルゾーン書き込みポインタ上方で読めるデータ) は最初の非ゼロバイトのオフセットと値を報告**し、そのルールの入力が WP に限定されるか否かを判定する |
   | ③ **読み出し失敗** | 脱出口は**不成立**（errno の絶対値を報告）⇒ シーケンシャルゾーン上で WP なしには「全候補」を限定不能 ⇒ 同アームは**脱落** |

2. **ゾーンリセット後に何が読み出されるか、および書き込んだバイト列が残存するか。** `BLKRESETZONE` 後にゾーン全体を再読み出しし、同様に判定基準 1 で三分；
   **「リセット前に書き込んだ N 個のレコードのシグネチャバイトが発見可能か否か」を別途報告** —— これは
   「ゾーンリセット後に、本プロジェクトが書き込んだバイト列にかつて存在した痕跡が残存するか」に回答する。
3. **`zone_full` により「WP が認識コミット点に先行」状態を構築可能か。** `zone_full=1` で null_blk を起動し、
   `blkzone report` における各ゾーンの `wp` と `start + capacity` の関係を**絶対値**で報告。
4. **ゾーン境界アライメント（装置間照合）。** `zone_size` の絶対値を報告し、`8191 × chunk mod zone_size` を計算、
   chunk は E48 (ルートリング幾何の実行可能点) でスイープされた 3 段階を採用。**結果は 2026-09-09 ラウンドでメイン agent が再計算した 9 マスとマスごとに一致しなければならない**
   （9 マスすべて割り切れず）。不一致の場合は不合格と判定 —— 2 箇所で同一の量に対して異なる数値を算出したことを意味する。
5. **通常ゾーン。** `zone_nr_conv=k` のとき先頭 k 個のゾーンの `type` と残りのゾーンの `type` を**絶対値**で報告、
   かつ通常ゾーンの総バイト数を報告 —— これは「一律通常ゾーン配置」アームが要求する
   「通常ゾーンが `{0, P·chunk, 2P·chunk}` の 3 点をカバーするか」が実現可能か否かを決定する。

### 失敗条件（実施前確定）

| 条件 | 発動時の判定 |
|---|---|
| **陽性対照**：空ゾーンに M 個書き込み後、`blkzone report` が報告する `wp` が `start + M × レコード幅` と等しくなければならない | 不等 ⇒ **観測装置自体が誤っており、ラウンド全体を破棄**（「WP 意味論の想定との乖離」と「自身の書き込み誤り」を区別不能） |
| **陰性対照**：空ゾーンの `wp` は `start` と等しく、`cond` は EMPTY でなければならない | 不成立 ⇒ ラウンド全体を破棄 |
| **逆受容条件**：判定基準 1 で ①（全ゼロ）が得られた場合 | 「ゾーン全体スキャンの脱出口でバイト列を読み出し可能」と事実通り記録し、**被テストアームに有利だからといって判定基準 2 をスキップすることは禁止** —— リセット後のマスこそがより困難な半分である |
| **逆受容条件 2**：判定基準 3 で「WP 先行」が構築不能な場合 | 「`zone_full` ではこの状態を構築不能」と事実通り記録し、「その状態をどう構築するか」を新たに未決事項として立項、**計測条件を変更して他の状態をそれと強弁することは禁止** |
| null_blk の挙動が実際の ZNS ディスクと異なる場合 | **E125 (シーケンシャルゾーン書き込みポインタ上方で読めるデータ) は null_blk の挙動にのみ回答**し、本文の各数値は [tooling.md](../tooling.md) の計測条件を付与しなければならない。⚠️ **「zoned デバイス上ではこうなる」と記述することは禁止** |

### 実行方法（root 権限要、2026-09-09 ラウンドでは取得不能であった）

```bash
# 判定基準 1/2/4/5：4 ゾーン、各 64 MiB、先頭 1 つが通常ゾーンの null_blk
sudo modprobe null_blk nr_devices=0
# 残りの幾何は configfs 経由（モジュールパラメータはグローバルのため、デバイスごとの幾何は configfs 経由を要する）
# 判定基準 3：別インスタンスを起動、zone_full=1
sudo modprobe null_blk zoned=1 zone_size=64 zone_full=1 nr_devices=1
sudo blkzone report /dev/nullb0
```

⚠️ **対象デバイスは必ず変数から取得し事前に `lsblk` で確認すること**（`.claude/singlefs-ai-sop/rules/command-safety.md`）、
**ローカル唯一の実ブロックデバイス `nvme0n1` には 1 バイトたりとも触れてはならない**。

### 本実験で答えられないこと

**実 ZNS ディスクの挙動には答えない** —— ローカルに実 zoned ディスクは存在しない。
**クラッシュ意味論には答えない**：`zone_full` が作成するのは「WP がすでに末尾にある」という静的状態であり、
「書き込み途中でクラッシュ」ではない —— 「書き込み途中でクラッシュ」にはクラッシュポイント再生ハーネスが依然として必要である。
**「一律通常ゾーン配置」アームが成立するか否かにも答えない**：判定基準 5 は通常ゾーンの規模を報告するのみであり、
「この規模でその 3 点をカバーするのに十分か」は推論であり別途三者検証を要する。

### 実測結果(2026-09-09)

装置：`null_blk` メモリバックエンドの host-managed zoned デバイス、4 ゾーン × 64 MiB、ゾーン 0 が通常ゾーン、ゾーン 1〜3 がシーケンシャルゾーン、
`physical_block_size` = `logical_block_size` = 4096（⇒ D22 (ユニット原子性の合成手法) 確定項目 2 のスロット幅は本装置上で 4096）。
**5 ラウンド 1 バイト違わず一致**、両対照とも通過：陽性対照 `wp_bytes=32768 expect_bytes=32768`、
陰性対照 `wptr=0x000000 zcond=1`。

| 判定基準 | 実測 | 実施前確定のどのマスに該当するか |
|---|---|---|
| 1 WP 上方で何が読めるか | `outcome=read_ok rc=0 bytes_got=67076096 distinct=1 uniform_byte=0xff first_nonzero_off=0 first_nonzero_val=0xff` | **②（読み出し成功かつ非ゼロ）** |
| 2 ゾーンリセット後 | `wp_bytes=0 zcond=1 uniform_byte=0xff marker_found_at=-1` | リセットによりゾーンは EMPTY に戻り、**シグネチャバイトは 1 つも回収不能** |
| 3 `zone_full` による WP 先行構築 | `committed_bytes=0 wp_bytes=67108864 lead_constructed=yes`（4 ゾーンすべて `wp_eq_cap=yes zcond=14`） | **構築可能** |
| 4 ゾーン境界アライメント（装置間照合） | 9 マス `divides=no`、商 7.999023 / 3.999512 / 1.999756 / 63.992188 / 31.996094 / 15.998047 / 511.937500 / 255.968750 / 127.984375 | **D22 (ユニット原子性の合成手法) 本文の表とマスごとに一致** |
| 5 通常ゾーン | `types=1222 conv_zones=1 conv_bytes=67108864`；3 段階 chunk の `p1_inside=no p2_inside=no` | 通常ゾーン 64 MiB、`{P·chunk, 2P·chunk}` に届かず |

**判定基準 1 は ② に該当し、② の実施前確定の影響は以下であった**：「脱出口は非ゼロゴミデータと破損を分離する新ルールを支払う必要があり、
E125 (シーケンシャルゾーン書き込みポインタ上方で読めるデータ) は最初の非ゼロバイトのオフセットと値を報告し、そのルールの入力が WP に限定されるか否かを判定する」。
報告された値：オフセット 0、値 `0xff`、かつ WP 上方の 67 076 096 バイトで `distinct=1`（この 1 種のバイト値のみ存在）。

⚠️ **判定基準 1 以外で最も価値の高いマスは判定基準 5 が副次的に捉えた対照である**：
**同一デバイス上で、未書き込みの通常ゾーンから読み出されるのは全 `0x00` であり、未書き込みのシーケンシャルゾーンから読み出されるのは全 `0xff` である**
（`crit5_conv_unwritten distinct=1 uniform_byte=0x00`）。
⇒ 「未書き込みパターン」は**単一デバイス内部**ですら同一の定数ではない。

### 判定基準外の 2 点、本装置ではなくカーネルドキュメントに由来

実行後にローカルの `~/code/fs-refs/linux-6.17/Documentation/filesystems/zonefs.rst` を調査したところ、
D22 (ユニット原子性の合成手法) 未定項目 6 に直接関係する 2 文が存在、逐字引用（**外部ドキュメント、本プロジェクト内未検証**）：

1. 236〜242 行：「the partial failure of a multi-BIO large write operation will cause the zone
   write pointer to advance partially, even though the entire write operation will be reported as
   failed to the user」⇒ **WP のコミット点先行はクラッシュを待つ必要がなく**、失敗と報告された 1 回の巨大書き込みで足りる。
2. 330〜332 行：「the write pointer of read-only zones is defined as invalib by the ZBC and ZAC
   standards, making it impossible to discover the amount of data that has been written to the zone」
   （`invalib` は上流原文の綴り、そのまま転記）⇒ **ゾーンが一度読み取り専用に遷移すると、WP は標準上無効となる**。

⚠️ **外部標準の項目は別途再調査を実施**：2026-09-09 に NVMe ZNS 公開資料を調査したところ、
「reading in this area is handled the same way as when reading unwritten blocks」、
未書き込みブロック読み出しの挙動は Identify Namespace の `DLFEAT` により選択され（全 0 / 全 1 / 報告なし）、
かつ `NSFEAT` の 1 ビットがセットされている場合コントローラは**未書き込みブロック読み出しに対して直接エラーを返却可能**である（Deallocated or Unwritten Logical Block error）。
⇒ **「WP 上方の読み出しが必ず成功し必ず 0xff を返す」は成立せず**、本装置の挙動であって標準の保証ではない。
出典：nvmexpress.org の ZNS Command Set 仕様および zonedstorage.io、**本プロジェクト内未検証**。

**本物の回転ディスク、本物の 4Kn ディスク、本物の zoned ディスクは存在せず**、関連数値はすべてシミュレーションによるものであり、
引用時はこの計測条件を付与しなければならない」。⇒ E125 (シーケンシャルゾーン書き込みポインタ上方で読めるデータ) が報告する各数値は `null_blk` の挙動にすぎない。

⚠️ **E125 (シーケンシャルゾーン書き込みポインタ上方で読めるデータ) は `scripts/experiment-apparatus/replay.sh` に含まれておらず、これは明示的な除外であって登録漏れではない**：
再実行装置が実行するのは `cargo run --bin <名前>` であるが、E125 (シーケンシャルゾーン書き込みポインタ上方で読めるデータ) はシェルプローブであり、
root、`modprobe null_blk`、configfs デバイスの作成と破棄を要する ⇒ **2026-09-09 のハーネスでは接続不能であった**。
⇒ その再現性は 2 点に依存する：`e125-zoned-wp-rounds-2026-09-09.out`（5 ラウンド別 sha256、
`distinct_hashes=1`）とそれら 6 件のミューテーションである。**「replay に未収録」であること自体を明記しなければならない** ——
明記しなければ、後続の者が `replay.sh` の全合格を見て収録済みの全実験が再実行されたと誤認することになる。

**6 件のミューテーションがそれぞれ赤判定となることを証明済**（ベースライン緑判定）：
`slot_width_not_4096`（期待スロット幅を 512 に変更）、`crit4_unexpected_divides`（P を 2 のべき乗 8192 に変更、
装置間照合が直ちに赤判定）、`neg_control_cond_not_empty`、`zone_bytes_not_64MiB`、
`pos_control_wp_absolute`（M を 8 から 7 に変更）、`slot_width_not_4096:512`（スロット幅が pbs を採用しない）。

⚠️ **そのうち 1 件はミューテーションテストが炙り出した真の欠陥であり、事実通り記録**：陽性対照はもともと
`WPB == M × SLOT` という 1 つの**相互比較**アサートしか持たず、`M` が書き込みと期待値の両方を駆動していたため ⇒ `M` を 8 から 7 に変更しても
**一切の反応がなかった**。`.claude/singlefs-ai-sop/rules/test-discipline.md`「相互比較アサートを 1 つ記述するごとに、
傍らに絶対値を固定するアサートを配置しなければならない」に従い `WPB == 32768` と `ZBYTES − WPB == 67076096` の 2 つの絶対値アサートを補完し、
同一のミューテーションが即座に捕捉された。**これこそが当該規則が防ごうとする形態であり、E125 (シーケンシャルゾーン書き込みポインタ上方で読めるデータ) の 2026-09-09 の実行において実際に 1 回発生した。**
