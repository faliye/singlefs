D23 (journalの役割とフォーマット) 決定済み項目 8 で幅 32 ビットを決定し、決定済み項目 10 で適用範囲（直前レコードのヘッダ全体、
うち 32 バイトの `header_csum` はハッシュ入力から除外）を決定済み。**不足していたのは、どの関数を用いてそのバイト列を 32 ビットに圧縮するかのみ。**

⚠️ **これは「どれでも適当に選べばよい」問題ではない**：E51 (逆方向チェーンの衝突機会は何回あるか) が「32 ビットで十分」と判定した前提は
**誤受容率 = 2⁻ⁿ** であり、その曲線は**チェーン値の均一性を条件**としている。
E40 (暗号文チェックサムのビット幅) の実測により、**切り詰められた CRC は短い CRC と同等ではない**ことが判明済み（全幅 CRC32C は単一ビット反転で漏れ 0 件、
8 ビットに切り詰めると 3212 ppm に悪化）⇒ チェーン値に「より広い幅の CRC を 32 ビットに切り詰めたもの」を採用した場合、その曲線は適用できない。

### 計測対象

**比較される二つのレコードヘッダにおいて、差異がどこに位置するかには構造が存在し、ランダムではない。**
二つのタイムラインのレコードヘッダは magic / version / algo_type / record_length において構造上同一であり、
差異は `jsn`（32 ビットのインスタンス識別子を含む）、`checkpoint_txg`、`tail_lsn`、`nonce` に集中する。
⇒ 真に問われるべきは「ランダム入力下で衝突率が 2⁻³² であるか否か」ではなく、
**「差異が特定のウィンドウ内に制限された場合、各レグの衝突数はいくつか」**である。

三本のレグ：

| レグ | 内容 | 含まれる理由 |
|---|---|---|
| 甲 | **完全 32 ビット CRC32C** | D19 (ブロックポインタの構造と幅予算) 決定済み項目 2 で決定済みの暗号文チェックサムと同一の関数 |
| 乙 | **32 ビットに切り詰めた SHA-256** | 「32 ビットに切り詰めた暗号学的ハッシュ」の候補、**まずその切り詰めが均一であることを証明する必要がある** |
| 丙 | **下位 32 ビットに切り詰めた CRC-64**（陽性対照） | E40 (暗号文チェックサムのビット幅) で切り詰め CRC が劣化することを確証済み。劣化が検出できない場合 ⇒ 判定基準に弁別力がない |

**中核手法：CRC は GF(2) 上の線形写像であるため、ウィンドウ内の衝突数は網羅的列挙を行わずに厳密に計算可能。**
差異が w ビットのウィンドウ内に制限される場合 ⇒ それらの差異は w 次元の線形部分空間を構成；
CRC はそれを GF(2)³² へ線形に写像する。**衝突数が厳密に 0 ⟺ 当該線形写像のランク = w。**
⇒ w 個の基底ベクトルの像を計算してランクを求めるだけで、全 2^w 個の差異を列挙したことと同等となる。
甲・丙の双方に適用可能（切り詰めも依然として線形）；**乙には適用不能**——暗号学的ハッシュは非線形であり、サンプリングしか行えない。
**「ランクによる判定が可能か否か」自体が一つの結論**であり、実装の詳細ではない。

### 判定基準（実行前に固定）

| # | 判定基準 |
|---|---|
| 1 | **ランク判定基準**：各 32 ビットウィンドウのオフセットに対し、差異空間の像のランクが必ず = 32 ⇒ 当該ウィンドウ内の衝突数は**厳密に 0** |
| 2 | **陽性対照は必ず失敗すること**：丙（切り詰め CRC-64）は少なくとも一つのウィンドウでランク < 32 となること。**至る所でフルランクの場合 ⇒ ランク判定基準でレグの区別がつかず、ラウンド全体が無効** |
| 3 | **絶対値アサーション**（三レグ共通の誤りを防止）：`CRC32C("123456789") == 0xE3069283`；`SHA-256("abc")` の先頭 4 バイト `== 0xBA7816BF`；CRC-64/XZ の標準テストベクタ。三件をそれぞれ独立に固定し、**被テストコードから読み戻すことを禁止** |
| 4 | **非線形レグのサンプリング**：乙は誕生日法でサンプリングし、衝突数と 2⁻³² の期待値の比が [0.5, 2] 内に収まること |
| 5 | **ヘッダ長スキャン**：86 / 95 / 99 の三段（当時の現行値、D23 (journalの役割とフォーマット) 決定済み項目 7 で 9 バイト追加後、さらに逆方向チェーン 4 バイト追加後）。**結論がヘッダ長に依存して変化しないこと**——変化した場合は条件付き命題として記述 |
| 6 | **同一元比較は恒等であること**：同一入力に対する二回の評価はビット単位で一致し、衝突機会のカウントは 0（E51 (逆方向チェーンの衝突機会は何回あるか) 判定基準 1 と同型） |

### 何をもって失敗とみなすか（実行前に固定、実行後の変更禁止）

| 条項 | トリガー時の判定 |
|---|---|
| 陽性対照（丙）が至る所でフルランク | 判定基準に弁別力がなく、**ラウンド全体が無効** |
| **甲でランク < 32 となるウィンドウが存在** | **ありのまま記録。** E61 (逆方向チェーンハッシュアルゴリズムの均一性) は CRC32C がより優れていると予断しない——その場合、この用途において暗号学的ハッシュより優位でないことを示す |
| 乙のサンプリング衝突比が [0.5, 2] を逸脱 | ありのまま記録し、「切り詰めの均一性が証明されなかった」旨を明記 |
| 三段のヘッダ長で異なる結論 | ありのまま並記し、結論を条件付き命題として記述、**特定の一段のみを選んで報告することを禁止** |
| 甲と丙が同一のランクスペクトルを出力 | この次元が無効化されており、**ラウンド全体が無効** |

### 答申できない半面

1. **インスタンス識別子自体の分布**。ランク判定基準が答えるのは「差異がウィンドウ内に収まる場合の衝突が厳密に 0 であること」であり、
   「インスタンス識別子が偶然再利用されるか否か」には答えられない——それは D23 (journalの役割とフォーマット) 決定済み項目 9 の管轄。
2. **ハードウェアアクセラレーションのコストは未計測**。CRC32C には SSE4.2 命令があり、SHA-256 には SHA-NI があり、双方とも高速であるが、
   **E61 (逆方向チェーンハッシュアルゴリズムの均一性) ではサイクル数を一切計測しない**——均一性のみに答える。
3. **同一関数の共用による共通モード故障の有無**：甲は D19 (ブロックポインタの構造と幅予算) 決定済み項目 2 の暗号文チェックサムと同一の関数であるが、
   双方がカバーするバイト列と用途は異なるものの、「同一関数であること」自体のリスクは C48 (複数の検証パスが同一の前提を共用) に帰属し、
   E61 (逆方向チェーンハッシュアルゴリズムの均一性) ではこれに答えない。

なし。純粋な算術処理であり、ファイルシステムや QEMU に依存しない。

### 実測（2026-08-31）

#### 計測一：ランクスペクトル——甲は全ウィンドウでフルランク、丙は半分未満

⚠️ **三段のヘッダ幅は 2026-08-31 実行時の 86 / 95 / 99 に準拠**；現行ヘッダは **487**（D23 (journalの役割とフォーマット) 決定済み項目 4：十フィールド 78 + 決定済み増分三件 17 + 本パブリッシュ内シーケンス番号 4 + 新規ルートセグメント 364 + fsid 8 + MAC 16）。甲は三段すべてでフルランク、丙は三段すべてで非フルランク ⇒ 結論は段位に非依存；**ソースコードと成果物は旧段位で固定されているため、引用前に再実行すること**。

| レグ | ヘッダ 86 | ヘッダ 95 | ヘッダ 99 | 最悪ランク | 最悪ウィンドウの衝突数 |
|---|---|---|---|---|---|
| **甲 完全 CRC32C** | **401 / 401** | **473 / 473** | **505 / 505** | **32** | **0** |
| 丙 CRC-64 を 32 に切り詰め（陽性対照）| 193 / 401（48.1%）| 226 / 473（47.8%）| 237 / 505（46.9%）| **28** | **15** |

⇒ **甲は可変領域内の任意の 32 ビットウィンドウにおいて、非ゼロの差異による衝突が一件も発生しない——これは計算によって導かれた 0 であり、未検出の 0 ではない。**
フルランクは当該ウィンドウ内の全 2³² 個の差異を列挙したことと同値。

### 口径と再実行

- コード `scripts/experiments/e61_chain_hash.rs`
  （`cargo run --release --bin e61-chain-hash`）。
- 成果物 `e61-chain-hash-2026-08-31.out`（24 行、終端行 `emitted=24`）。
- ⚠️ **三回連続でバイト完全一致であるが、それは「隠蔽された状態が存在しないこと」を証明するのみであり、統計的安定性ではない**：
  E61 (逆方向チェーンハッシュアルゴリズムの均一性) は決定論的モデル（I/O なし、並行性なし、クロック入力なし）であり、同一のバイナリを三回実行すれば必然的に同一
  ⇒ N=1 と N=3 の情報量は等価。**本物の高負荷テストと同等の証拠強度であると偽装してはならない。**

  再利用は被テスト対象とその正当性証拠の間でコードを共有することを意味する。それぞれ判定基準 3 の標準テストベクタにより固定。
