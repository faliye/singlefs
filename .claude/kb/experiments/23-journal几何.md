## E23 journal 几何 —— 已跑（2026-08-29）

**测的是**：定长环 vs 链式，以及 tail 存哪。

**测 [decisions.md](../decisions.md) D23（journal 的角色与格式） 已定项 2（定长环还是链式）与已定项 3（tail 位置）。**
两项**不正交，必须一起量**：tail 的权威位置决定空间什么时候能回收，
而「空间什么时候能回收」正是环与链的分水岭。分开量会各自得出一个漂亮答案。

### 结论

1. **已定项 3：两条臂的代价差是 21 : 500，方向一边倒。**

   | tail 形态 | 稳态额外写 | 空闲期崩溃后要重放 |
   |---|---|---|
   | `tail_sb`（jbd2：住 journal 超级块、原地覆盖、FUA） | **21 块**（= checkpoint 次数） | **0** |
   | `tail_inline`（XFS：内联在每条记录头的 `tail_lsn`） | **0** | **500 块**（pbs=4096）/ 63 块（pbs=512） |

   20000 次 fsync、每 1000 次一个 checkpoint。`tail_sb` 的稳态开销是 **0.105%**
   （21 / 20000），换来空闲崩溃后重放量归零。
   **机制**：`tail_inline` 只能搭记录的便车推进——不写记录就推不动 tail；
   `tail_sb` 可以在 checkpoint 完成时单独写一次。空闲期崩溃时两者因此分开。
   ⚠️ 换屏障口径结论不变：21 次额外 FUA 对 20000 次 fsync 的 40000 次持久点是 0.05%。

2. **已定项 2：环与链在除一项之外的每个指标上完全相同，那一项是分配次数。**

   | | 定长环 | 链式 |
   |---|---|---|
   | 稳态写块数 | 相同 | 相同 |
   | **向分配器要块** | **0 次** | **每个 journal 块一次**（20000 次 fsync ⇒ 20000 次） |
   | 死锁 3（单条操作大于环） | 存在，需要几何不变量 | 不存在 |

   ⇒ **链式把 journal 写路径变成一条分配路径**，于是它进入 D23（journal 的角色与格式） 死锁 2 的环
   （checkpoint → COW 写新节点 → 要分配 → 盘满 → 发不出根）。
   环的 0 次分配正是「journal 不可能被 COW 覆盖」在模型里的形态。
   **链式用「消掉死锁 3」换「加重死锁 2」，而死锁 2 是 COW 独有、且已经最难的那个。**

3. **环大小的下界 = checkpoint 间隔 × 每次 fsync 的记录块数，而它随原子宽度放大 8 倍。**

   | pbs | 环 ≥ 多少块才不强制 checkpoint | 峰值占用 |
   |---|---|---|
   | 512 | **256** | 125 块 |
   | 4096 | **1024** | 1000 块 |

   环太小时代价是断崖式的（pbs=4096、每次 fsync 点名 1 项）：

   | 环大小 | 强制 checkpoint 次数 | `tail_sb` 的 tail 写 |
   |---|---|---|
   | 4 块 | **4980**（每 4 次操作一次） | 5000 |
   | 16 块 | 1240 | 1260 |
   | 64 块 | 300 | 320 |
   | 256 块 | 60 | 80 |
   | 1024 块 | **0** | 20 |

   ⇒ **已定项 2、3、4 三者耦合**：原子宽度（已定项 4）决定记录占几块，
   记录占几块决定环要多大（已定项 2），环太小则把 `tail_sb` 的写放大 250 倍（已定项 3）。
   **任何一项单独定都会定错。**

### 口径与已知局限（不许无视）

- **纯计数模型，不碰设备。** 数的是**块**，不是字节也不是屏障——
  [checks-owed.md](../checks-owed.md) C27（块数口径定格式参数） / C26（屏障数从没量过） 两笔口径欠账同样适用于E23（journal 几何）。
- **没有建模 checkpoint 本身的代价。** 强制 checkpoint 的真实代价是写全部脏祖先
  （见 E16（journal 的角色：WAL vs 意图日志）），E23（journal 几何）只数了它发生几次。
- **重放量只按块算，没算重放时的随机读**。链式重放要沿指针逐块跳，
  环式可以顺序预读——这一层E23（journal 几何）够不着。
- 代码 `research/e7-index-bench/src/bin/e23_journal_geom.rs`（`cargo run --release --bin e23_journal_geom`），
  原始输出 `research/results/e23-journal-geom-2026-08-29.out`。三轮字节一致。

### 08-29 那一轮踩的两个坑，都由变异测试抓出来

1. **`pbs` 那一维原本是死代码。** 第一版按「每条记录占几块」算，
   而 `pbs ≤ BLOCK` 时「先对齐到 pbs 再向上取整到 4096」是**恒等操作**，
   512 与 4096 给出完全相同的块数。变异测试把对齐整个删掉，**8 个测试一个都没红**。
   ⇒ 改成按字节累计、最后折一次块，打包这件事才出现（512 扇区下 8 条记录挤一块）。
2. **测试把 `84` / `56` 抄成了自己的字面量**，于是改常量时一个都不红。
   ⇒ 断言一律走常量。

### 还有一个坑不是变异测试抓的，是数字自相矛盾

第一次跑出来 `rec_blocks=2500` 而 `allocs=20000`——打包在记录块数里生效了、在分配次数里没有。
原因是**跑的是旧二进制**：`cargo test` 只构建测试宿主，不重建 release bin。
⇒ 改完模型后必须 `cargo build --release --bin` 再跑，
或者让结果行带一个能与构建对上的标记。
