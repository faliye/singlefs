**問うているのは** D8（コアインデックス構造） 確定項目 3 の表における「アロケータ（サブディレクトリのデータを親ディレクトリ近傍に配置）」の行の利益である。
その行の唯一の根拠には逐字的に「⚠️ **未検証** —— kb 内に出典・計測条件なし、利用時は要補完」と付記されており、
D14（大小ファイル・永続/一時デュアルトラック） 確定項目 2 の三者検証を経てユーザーは「**まず利益データを補完してから確定せよ**」と定めた。

**結論を一行脈で**：**2 つの利益マスはともに交錯度に依存する** —— `arrival` の連続ラン数は総オブジェクト数 ÷ 交錯ストライドであり、
`stride = ディレクトリあたりファイル数`（交錯なし）のとき両アームの配置先シーケンスはマスごとに一致し、**したがってトラバーサルおよび回収の 2 つの測定値もマスごとに一致する**。
**交錯した**負荷においてのみ `grouped` は利益を獲得する：`stride ≤ 8` のとき 1 つのディレクトリを削除すると、
`grouped` はセグメント全体を解放できるが（セグメント長 32 スロット時 2 個、64 スロット時 1 個、128 スロット時 0 個）、
`arrival` および `random` は 1 つも解放できない。

### 3 本のアーム

| アーム | 配置先決定手法 |
|---|---|
| `grouped` | 同一親ディレクトリ配下のオブジェクトがディスク上で連続 |
| `arrival` | 作成到達順；ディレクトリ間の交錯度は `stride` で決定（1 つのディレクトリをいくつか連続配置した後に次へ切り替え） |
| `random` | 決定論的 LCG 擬似乱数。**識別力下界であり候補ではない** |

### 実測（16 ディレクトリ × ディレクトリあたり 32 ファイル = 512 オブジェクト）

| `stride` | `grouped` 総ラン数 | `arrival` 総ラン数 | `random` 総ラン数 |
|---|---|---|---|
| 1（完全ラウンドロビン） | 16 | **512** | 484 |
| 2 | 16 | 256 | 484 |
| 4 | 16 | 128 | 484 |
| 8 | 16 | 64 | 484 |
| 32（= ディレクトリあたりファイル数、交錯なし） | 16 | **16** | 484 |

⇒ **閉形式**：`arrival` 総ラン数 = 512 ÷ `stride`（ソースコード `walk_runs_are_pinned_to_absolute_values` でマスごとに固定、`ラン数 × stride ≡ 512` をアサート）。

**1 ディレクトリ削除後に解放された完全空セグメント数**（⚠️ **このマスも同様に `stride` の計測条件を伴う**。
成果物内で `arrival` の各行は `stride` を保持しており、この表は一時それを脱落させていたが 2026-09-09 に補完）：

| セグメント長（スロット） | `grouped`（各 `stride`） | `arrival`、`stride ≤ 8` | `arrival`、`stride = 32`（交錯なし） | `random` |
|---|---|---|---|---|
| 32 | **2** | 0 | **2** | 0 |
| 64 | **1** | 0 | **1** | 0 |
| 128 | 0 | 0 | 0 | 0 |

⇒ **交錯なしのとき `arrival` と `grouped` は回収のマスにおいてもマスごとに一致する**。成果物の行ごとの記録：

```
E7RESULT name=walk arm=grouped stride=32 total_runs=16 worst_dir_runs=1 empty_segs_at_32=2 empty_segs_at_64=1 empty_segs_at_128=0
E7RESULT name=walk arm=arrival stride=32 total_runs=16 worst_dir_runs=1 empty_segs_at_32=2 empty_segs_at_64=1 empty_segs_at_128=0
```

これは陽性対照の行と同一の事象である（`stride = 32` のとき両アームの配置先シーケンスは**完全に同一**） ——
配置先シーケンスが同一であれば、配置先から算出される任意の量は必然的に同一となる。
装置内のアサート範囲は常に正しかった（`empty_segments_are_pinned_to_absolute_values` は `stride = 2` をハードコード、
アサートメッセージは逐字的に「arrival **交錯後**はセグメント全体が 1 つも空かない（セグメント長 {sg}）」）、
**計測条件を脱落させていたのは本文側である**。

### 3 つの対照の判定

| 対照 | 判定基準 | 実測 |
|---|---|---|
| 陽性（アーム別） | 交錯なしのとき `arrival` は `grouped` とマスごとに一致 | `stride = 32` のとき両アームの配置先シーケンスは**完全に同一** |
| 陰性 | ディレクトリあたり 0 ファイル | 3 アームとも総ラン数は 0 |
| 識別力 | 3 アームが少なくとも 1 マスで異なる | `stride = 2`：16 / 256 / 484 |

### 実施前登録のパラメータ 1 箇所に逆ラベル、記録は改ざんせず維持

判定基準 3 で登録されたのは「`stride = 1` のとき `arrival` は `grouped` とマスごとに等しくなければならない」であったが、
`stride` の意味論は「1 つのディレクトリをいくつか連続配置した後に次へ切り替え」である ⇒ **`stride = 1` は完全ラウンドロビンであり最も激しく交錯するマス**であり、
`stride = ディレクトリあたりファイル数` こそが交錯なしである。判定基準の**意図**は不変であり、誤っていたのはメイン agent が登録時にパラメータへ付与したラベルであった。
両値ともソースコード `positive_control_on_every_arm_without_interleave` 内に保持されている。

### D14（大小ファイル・永続/一時デュアルトラック） 確定項目 2 に対する言明

1. **トラバーサルの利益は「集約 vs 非集約」ではなく「交錯 vs 非交錯」である**：
   負荷がもともと 1 つのディレクトリを書き終えてから次を書く場合、アロケータが何もしなくても同様の結果が得られる。
   ⇒ このマスの利益は**対象負荷の交錯度**に依存し、D25（対象ワークロードの優先順位） の負荷表にはこの次元が存在しない。
2. **回収の利益も同様に「交錯 vs 非交錯」であり、「集約固有」ではない**（2026-09-09 訂正）。
   2026-09-09 以前はこの条項は「回収の利益は集約によってのみ獲得可能」と記述されていたが、同一の保存成果物内で
   `arm=arrival stride=32` の行の `empty_segs` は 2 / 1 / 0 であり、`grouped` とマスごとに一致する
   ⇒ 旧記述は成果物と矛盾しており、成果物に従い訂正した。その規模はさらにセグメント長とディレクトリ規模の比率に依存する ——
   セグメント長 128 スロット、ディレクトリが 64 スロットしか占有しない場合、利益はゼロに帰着する。
   ⚠️ **この矛盾はゲートには不可視であった**：E122（ディレクトリ集約で何が得られるか） の再実行は保存成果物と 1 バイト違わず一致し完全合格であった（2026-09-09 再実行確認済）が、
   矛盾していたのは**本文と成果物**であり、成果物間ではない。
   [checks-owed.md](../checks-owed.md) C233（結論が名指しした固有利益に自身の成果物内で反例が存在）に記録。
3. 両マスとも「短命の疑い」側を**包含しない**：そのマスは D25（対象ワークロードの優先順位） 全文に 0 回しか出現せず空白である。
4. **統合すると**：E122（ディレクトリ集約で何が得られるか） が証明したのは「**交錯した負荷において**、ディレクトリ単位の集約は到達順配置よりもトラバーサル・回収の両測定値で優れている」ということであり、
   「ディレクトリ集約に負荷と無関係な正の利益が存在する」ということでは**ない**。
   D25（対象ワークロードの優先順位） には交錯度の次元が存在しない（`grep -n "交错"` 現行 0 ヒット、2026-09-09）、
   ⚠️ しかしこの言明を**「D25（対象ワークロードの優先順位） に交錯負荷が存在しない」と解釈してはならない** ——
   その負荷表には重み「次」の `multistream マルチストリーム並行` の行が存在し、実質的な交錯負荷である。

### 本実験で答えられないこと

純カウントモデル：実際の I/O なし、シーク時間なし、ページキャッシュなし、クラッシュポイント再生なし。
「連続ラン数」は**プロキシ指標であり実時間ではない** —— 1 回の連続読み出しが 2 回より安価であると仮定するが、どれほど安価かには答えない。
ディレクトリツリーの形状をモデル化していない（1 階層のみ）、ファイルサイズ分布をモデル化していない（各オブジェクト一定 1 ユニット）。
決定論的モデルであり、**N ラウンド実行は隠蔽された状態が存在しないことを示すものであり、統計的安定性を示すものではない**。
