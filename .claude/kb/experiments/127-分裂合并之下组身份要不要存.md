## E127 分裂合并之下组身份要不要存 —— 未跑（判据已注册 2026-09-10）

**问题**：E95（老化的节点布局臂） 跑完之后，D26（后台整理与放置回收）未定项 4 卡在一处**模型缺口**上，不再卡在「没人跑那个实验」上。

E95（老化的节点布局臂）里赢下比较的那条臂（节点组）在它的模型里**不消费任何盘上字段**——
组身份是 `key / g` 算出来的。把同一个函数换个 tag 注册成政策臂，
**48 行 `runs_median` 逐字不变而答案行六格全部翻面**（那一篇的「它答不了的」第 4 条与主 agent 的复跑）。
根因写在同一处：E95（老化的节点布局臂）的模型里 key 到对象是**静态一一对应、没有分裂合并**，
于是「按 key 区间分组」与「按节点数分组」出的数完全一样，
**而只有后者要在节点头里存一个组身份**。

E127（分裂合并之下组身份要不要存）就是补那个缺口：把分裂合并放进模型，让这两种分组**有可能**出不同的数。

### 模型

沿用 E93（老化下的放置与碎片度）/ E95（老化的节点布局臂）的槽位、defer、碎片度与等预算口径，
**改动只有一处**：对象不再是定长静态数组，而是装在会分裂合并的**节点**里。

| 件 | 取法 |
|---|---|
| 节点 | 每个节点占一个物理槽；容量 `C` 条 key，超过 `C` 从中点分裂，低于 `C/4` 与相邻节点合并 |
| 负载 | 在 E93（老化下的放置与碎片度）两组负载（uniform / runs8）之外，**必须加插入与删除**——不插不删就不分裂不合并，整个实验没有对象 |
| 碎片度 | `F = runs / 节点数`，runs 按**节点的 key 序**遍历物理连续段（口径与 E93（老化下的放置与碎片度）同型，只是单位从对象换成节点） |

**三条臂，等预算**（额外写数 = 每 checkpoint `D × (X − 1)`，X 取 1.5 / 3 / 5）：

| 臂 | 组怎么定 | 要不要盘上字段 |
|---|---|---|
| **key 区间分组** | 组 = 固定的 key 区间 `[i·W, (i+1)·W)`，一个组里的节点数随分裂合并浮动 | **不要**——放置器从 key 算得出 |
| **节点数分组** | 组 = 按节点序相邻的 `G` 个节点；节点分裂时新节点继承分裂方的组号，组满了另开新组 | **要**——节点序不是 key 的函数，组号只能存在节点头里 |
| **政策臂（对照）** | E93（老化下的放置与碎片度）的 bump_compact(B)，B = 预算 | 不要 |

### 判据（跑前写死 2026-09-10，跑完不许改）

1. **手算锚点**：8 个 key、节点容量 2、组宽 2：插一个 key 触发一次分裂，两条分组臂的组划分**手算写死**，
   且必须在分裂之后**互不相同**——两条臂在锚点上就相同的话，这个模型没有分辨力，整轮作废。
2. **守恒**：增量 runs == 审计 runs（每采样点）；节点里的 key 总数 == 活 key 数；空槽 + 占用槽 == 总槽数；
   defer 的槽本轮不可复用。
3. **阳性对照每臂都过闸**：强制放置下全隔离布局报 `runs == 节点数`，连续布局报 `runs == 1`。
4. **分裂合并真的发生了**：每条臂报出本轮的分裂次数与合并次数，**两者都必须 > 0**，否则整轮作废
   （`.claude/singlefs-ai-sop/rules/test-discipline.md`「阴性结果要能和『代码没跑到』分开」）。
5. **跨装置闸**：把插删关掉、节点容量设为 1 时，三条臂必须逐字复现
   E95（老化的节点布局臂）入库产物里对应格的 `runs_median`；对不上判红。
6. **要回答的一问**：在**任一**等预算格上，「节点数分组」能不能把 runs 压到「key 区间分组」的
   **0.8 倍以下**（阈值跑前写死）。
   能 ⇒ 组身份**必须**存进节点头，D26（后台整理与放置回收）未定项 4 的格式部分要真定形态与宽度；
   不能 ⇒ **模型层支持「组身份不必进格式」**，那条臂退回政策层，
   D26（后台整理与放置回收）未定项 4 的字节判定要重判。
7. 不代替 E10（老化：结构抗老化 vs 事后整理）；耗时轴与降级判据仍归它。

### 失败条款（跑前写死）

| 条款 | 判定 |
|---|---|
| 判据 1 / 3 / 4 / 5 任一不中 | **整轮作废**——分辨力、测量、机制、跨装置一致性，缺一样，产出那份输出的那次运行就什么也没证明 |
| 两条分组臂在所有格都打平 | **合法结果，如实记**——那是「组身份不必进格式」的证据，不是实现坏了 |
| 「节点数分组」全胜 | **合法结果，如实记**——那是要真定格式形态的证据 |
| 「key 区间分组」全胜 | **合法结果，如实记**，且要单独记一句：那说明存组身份不但不必要，还有害 |

⚠️ **两条分组臂都要给最有利的实现**（`.claude/singlefs-ai-sop/rules/evidence-discipline.md` 稻草人条款）：
组宽 `W` 与组大小 `G` 各自扫一组取值、每格取最好的那个，扫的范围要写进产物。

### 它答不了的

1. 计数模型：无耗时轴、无消息缓冲攒批统计、无真机。
2. 分裂合并的规则是一种取法（中点分裂、`C/4` 合并），不是 D8（核心索引结构）已定的规则——
   D8（核心索引结构）今天没有定分裂点与合并阈值，所以这一条**必须**在产物里标成模型假设。
3. 组身份在真格式里占几字节、与 D11（索引节点要不要留消息缓冲区）的 665 条缓冲抢不抢，模型不算——
   E101（节点头留位的代价与表达力）逐字判过「节点组的组数没有任何已定条款给上界，模型报 `UPPER_UNKNOWN`」，
   E127（分裂合并之下组身份要不要存）也不解这一格。
4. 它回答的是「要不要存」，不是「存多宽」。
