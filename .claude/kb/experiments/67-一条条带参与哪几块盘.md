## E67 一条条带参与哪几块盘 —— 已跑（2026-08-31，N=5 种子 + 倾斜轮，9 单测 / 4 条变异全抓）：**建对象时按最空选一组、之后固定**两轮都最好

D2（RAID 条带策略） 已定项 6 定了用几列（上界 4），没定选哪几块。E67（一条条带参与哪几块盘） 量的不是「丢多少」——
**期望丢数据比例由宽度定死**（`(w−1)/C(D,2)`，与选法无关，E67（一条条带参与哪几块盘） 实测四臂逐格相等）——
而是**损失怎么分布**：集中在少数对象上，还是弥散到每个对象上。

### 判据（跑前写死，跑完没改）

1. 各臂「两盘同坏后完好对象比例」差 ≥ 10 个百分点 ⇒ 这一维决定选型；< 10pp ⇒ 改由均衡度决定。
2. **守恒**：各臂期望丢数据比例必须彼此相等（差 ≤ 1%）。不等 ⇒ 整轮作废。
3. 盘间使用量极差超过单盘用量 5% 的臂**淘汰**（会提前 ENOSPC，E60（加盘之后不搬数据的代价） 已量过搁浅的代价）。

### 怎样才算失败（跑前写死）

| 条款 | 判定 |
|---|---|
| **阳性对照，对每一条臂都跑**：`w = 设备数`（全宽）⇒ 完好比例必须**全部为 0** | **通过**，五臂全 0 |
| **阴性对照**：宽度 2、单条带对象 ⇒ 完好比例 = `1 − C(2,2)/C(8,2)` = 27/28 | **通过** |
| 失败对**穷举**全部 `C(8,2)=28` 对，不抽样 | 没有采样误差 |

### 实测（8 盘、宽度 4、512 个对象；四轮负载）

| 臂 | 均匀（每对象 8 条带） | 倾斜（每 16 个对象里 1 个占 64 条带） |
|---|---|---|
| | 完好比例 / 盘间极差 | 完好比例 / 盘间极差占比 |
| 甲 按对象号绑一组 | **78.6%** / 0 | 78.6% / **88.7%** ← 判据 3 淘汰 |
| 乙 每条带轮转 | 14.3% / 0 | 74.6% / **31.9%** ← 淘汰 |
| 丙 每条带取最空的 4 块 | 57.1% / 0 | 77.2% / 0 |
| 丁 每条带随机 | 14.1% / 4.5% | 73.7% / **6.4%** ← 淘汰 |
| **戊 建对象时按最空选一组、之后固定** | **78.6%** / **0** | **78.6%** / **0** |

| 己 建对象时选组、**组内有盘满了就重选** | 78.6% / 0 | **78.4%** / **0** |

期望丢数据比例：**六臂全部 107142 ppm**（= 3/28 = `(w−1)/C(D,2)`）⇒ 判据 2 守恒成立。

⚠️ **跨轮次不能比完好比例**：倾斜轮里大多数对象只有 1 条带，本来就更容易完好。**只在同一轮内比。**

#### 第三轮（2026-08-31 补）：异构容量下会不会「组内满而池里还有空间」

本地腿的反例逐字是：各盘不必等大（D2（RAID 条带策略） 已定项 2）⇒ 绑组可能把对象钉在四块小盘上，
写不进去而别处有空间。补跑一轮异构容量（4 块 3000 格 + 4 块 900 格，总容量 15600 < 需求 16384）：

| 臂 | 落到已满盘上的条带数（越低越好） |
|---|---|
| 甲 按对象号绑组 | 2012 |
| 乙 轮转 | 2009 |
| 丁 随机 | **2277** |
| 丙 每条带取最空 | **1148** |
| 戊 建对象时选组 | **1148** |
| 己 选组 + 组内满就重选 | **1148** |

⇒ **反例没有兑现**：戊按剩余空间选组，小盘一旦偏满就不再被选中 ⇒ 与逐条带选最空**逐格相同**。
栽跟头的是「按对象号绑组」（甲）那种不看剩余空间的绑法。
⚠️ 六臂都有 4 块盘超容量——总需求本来就超过总容量，**这一轮只能横比，不能当绝对值读**。

#### 第四轮（2026-08-31 补）：加盘 + 已定项 4 c 的重平衡之后，完好比例还剩多少

两条云端腿指到同一处：组开出来之后加了盘，重平衡要搬数据 ⇒ 组还成不成立。
**搬迁粒度是唯一的自变量。** 8 盘放好之后加第 9 块，搬到新盘拿到 1/9 为止，
再对全部 `C(9,2)=36` 对失败盘穷举：

| 搬迁粒度 | 搬动格数 | 完好比例 |
|---|---|---|
| **整个对象重落一组** | 1824 | **83.3%** ＝ `1 − C(4,2)/C(9,2)` 的理论值，**一格没丢** |
| 逐条带搬 | 1820 | **75.0%** |

⇒ **整对象搬把绑组的收益完整保住**，而且因为盘变多了完好比例还从 78.6% 升到 83.3%。
逐条带搬掉 8.3 个百分点——**低于判据 1 那条 10pp 的线**，如实记；
它没掉更多只是因为这一轮只搬了 11% 的格，搬得越多掉得越狠。

⚠️ **第一版的逐条带臂建模错了**：按顺序扫前 N 条，而条带在数组里按对象聚在一起
⇒ 它等价于整对象搬，两臂给出同一个数（83.3% vs 83.3%）。改成按步长散布到所有对象之后才分开。

### 判据逐条判定

| # | 判定 |
|---|---|
| 1 | **均匀轮成立**（甲 78.6 vs 丙 57.1，差 21.4pp ⇒ 这一维决定）；**倾斜轮不成立**（戊 78.6 vs 丙 77.2，差 1.4pp ⇒ 改由均衡度决定）。两轮结论不同，**如实并列** |
| 2 | **成立**，五臂逐格相等 |
| 3 | **淘汰甲、乙、丁**；只有丙与戊两轮都是极差 0 |

⇒ **戊是唯一在两轮里都拿到最高完好比例、且两轮极差都为 0 的臂。**

### 为什么绑组会赢：机制

一对盘同坏时，绑组的对象要么整组被打中（该对象多条带一起损）、要么一格不丢。
**打中的概率是 `C(4,2)/C(8,2) = 6/28`** ⇒ 完好比例恰好 `22/28 = 78.6%`（单测钉死）。
每条带换一组则每条带独立掷骰，8 条带里只要有一条被打中该对象就不完好
⇒ 轮转臂只剩 `4/28 = 14.3%`（环距为 4 的那 4 对盘一个窗口都不落，独立算术，单测钉死）。

⇒ **同样丢 10.7% 的数据，绑组让 78.6% 的对象毫发无损，轮转让 85.7% 的对象都缺块。**

### 它答不了的那一半

1. **计数模型**：没有文件系统、没有块设备，文件操作 0 处。
2. **不建模单对象吞吐**：绑组把一个对象钉在 4 块盘上 ⇒ 该对象的并行度上限是 4，不是 8。
   E67（一条条带参与哪几块盘） 没量这一维，而它正是绑组的已知代价。
3. 不建模三盘同坏、不建模重建窗口、不建模对象删除后的组回收。
4. 倾斜形态（16 分之 1 的对象占 64 条带）是设的，不是本工程实测的分布。
