## E60 (ディスク追加後にデータ移動を行わないコスト) —— 実行済み (2026-08-31、N=5 シード、10 単体テスト / 5 ミューテーション全捕捉)：データ移動を行わないコストは低速化ではなく、新ディスクの 60% が購入不能になることにある

[中文](60-加盘之后不搬数据的代价.md) · [English](60-加盘之后不搬数据的代价.en.md) · **日本語**

D2 (RAIDストライプポリシー) 確定項目 4 c (ユーザー決定事項) は「データ移動は行わず、新規データは新ディスクに優先配置する」と定めたが、
ユーザーは同時に「性能を測定し、性能が悪ければ移動してもよい」と指示した。

### 何を計測するか

| # | 計測対象 |
|---|---|
| 1 | ディスク追加後に**あとどれだけのユーザーデータを書き込めるか** (3つの割り当て戦略で各1回) |
| 2 | **物理セル / データセル** (パリティオーバーヘッド) |
| 3 | **座礁容量**：幅 ≥ 2 のストライプを構成できなくなった時点で、残存する空きセル数 |
| 4 | 平坦化のための**一括移動量**——データ移動を行わないことで節約されるものであり、これを報告しなければ片方の会計しか計算していないことになる |

### 判定基準 (実行前固定、実行後変更なし)

| # | 判定基準 |
|---|---|
| 1 | 3アームを「同量のユーザーデータを書き込む際に消費される物理セル数」で比較 |
| 2 | 甲が丙に対して **≥ 10% 高い** ⇒「データ移動を行わないコストは顕著」と判定し、D2 (RAIDストライプポリシー) 確定項目 4 c を再審理 |
| 3 | 高い幅が **< 10%** ⇒「コストは軽微、データ移動なしを維持」と判定。**この文言は実行前に記述：逆の結果も許容** |
| 4 | 丙の移動量を必ず併せて報告 |
| 5 | 各アームの座礁容量を必ず報告 |

### 失敗条件 (実行前固定)

| 条項 | トリガー時の判定 |
|---|---|
| **保存則**：各デバイスの使用済みセル増分の合計 ≠ 会計上の物理セル数 | **ラウンド全体を無効化** |
| **陽性対照、全アームに対して実行**：新ディスク容量 0 (ディスク未追加と等価) ⇒ 4アームすべてが4ディスクプールの数値に縮退、丙の移動量は 0 | いずれかのアームで不成立 ⇒ **ラウンド全体を無効化** |
| **陰性対照**：ディスク追加時に旧ディスクも空 (不均衡なし) ⇒ 丙の移動量は 0 | 0 以外 ⇒ **ラウンド全体を無効化** |
| 5つのシードで結論の方向性が不一致 | 「不安定」と報告し、結論を出さない |

### モデル

旧ディスク4台各1000セル、ディスク追加前に90%まで充填、新ディスクは1000セル空。1本のストライプは参加する各ディスク上で1セルずつ占有し、
`w` セルのうち1セルがパリティ、`w−1` セルがデータ (D2 (RAIDストライプポリシー) 主結論：フルストライプ書き込み、リード・モディファイ・ライトは一切行わない)。
書き込みペイロードは毎回 1..8 セルのランダム (5シード)。`w ≥ 2` のストライプが構成できなくなるまで書き込む。

| アーム | 戦略 |
|---|---|
| 甲 | **移動なし + 新ディスク優先**：狭いストライプ (幅 2 または 3) を空き領域が最も多いディスク群に配置 |
| 乙 | **移動なし + 偏向なし**：各ストライプは空きがあるすべてのディスクを使用 |
| 丙 | **平坦化後フル幅**：注水法で平坦化後に乙と同様に書き込み |

### 実測値 (2026-08-31、N=5 シード)

#### 結果1：割り当て戦略と無関係な算術的上界

**データを移動しない場合、新ディスクは最大でも「他ディスクの残余空き領域の合計」と同数のセルしか吸収できない。**
メカニズム：冗長性のあるストライプは少なくとも2台のディスクが各1セルを提供する必要がある ⇒ 新ディスクに1セル書き込む毎に、別のディスクが同時に1セルを提供しなければならない。

4台のディスク各1000セル、90%充填 ⇒ 他の空き領域は計400セル ⇒ **新ディスクの1000セルのうち600セルは永久に使用不能 (60%)**。
旧ディスクが満杯に近いほどこの比率は悪化する：95%充填で 80%、99%充填で 96% が座礁。

⚠️ **甲は藁人形アームではない**：狭いストライプ w=2 は**この上界にちょうど到達する** (新ディスク吸収量 400 = 4 × 100、1セルも過不足なし)
⇒ これは**移動なし条件下での最適戦略**であり、適当に選んだ劣悪な形態ではない。

#### 結果2：3アームのセル単位結果

| アーム | ディスク追加後になお書き込めたユーザーデータ (セル) | 物理/データ | 平均幅 | 座礁 (すべて新ディスク上) | 一括移動量 |
|---|---|---|---|---|---|
| 甲 狭いストライプ w=2 | **400** (5シードすべて同一) | **2.000** | 2.0 | **600** | 0 |
| 甲 狭いストライプ w=3 | 358–362 | 1.657–1.676 | 3.0 | **800** | 0 |
| 乙 フル幅偏向なし | 294–302 | 1.656–1.701 | 5.0 | **900** | 0 |
| 丙 平坦化後フル幅 | **819–837** | 1.673–1.709 | 5.0 | **0** | **720** |

⇒ **丙は最良の移動なし戦略と比較して 2.05–2.09 倍のユーザーデータを書き込める**。その代償は一括して 720 セルを移動することである
(旧ディスク使用量 3600 セルの 20%)。

#### 結果3：実行前固定の判定基準による判定、2つの甲で判定が分裂

| アーム | 丙に対する 物理/データ 比率 | 判定基準 2 / 3 による判定 |
|---|---|---|
| 甲 w=2 | **+18.3%** | 「コスト顕著」と判定 ⇒ 確定項目 4 c を再審理 |
| 甲 w=3 | **−2.0%** | 「コスト軽微」と判定 ⇒ データ移動なしを維持 |

⚠️ **判定基準 1–3 はパリティオーバーヘッドの次元のみを注視しており、決定的なのは座礁容量の次元であった** (判定基準 5 は報告を要求したのみで閾値を設けず)。
`.claude/singlefs-ai-sop/rules/test-discipline.md` の「後から判定基準を変更してはならない——変更した場合は新規実験となる」に従い、
ここでは**ありのまま並列**する：判定基準が下したのは分裂した結果であり、判定基準が網羅しなかった次元が2倍の格差を示している。
**座礁容量を判定基準に据えるには、別途実験を立ち上げる必要がある。**

#### 対照の項目別判定

| 条項 | 判定 |
|---|---|
| 保存則 (物理セル数 = ストライプ占有の合計) | **合格**、3アームそれぞれで成立 |
| **陽性対照、全4アームで実行**：新ディスク容量 0 | **合格**、全4アームが4ディスクプールに縮退、丙の移動量 0 |
| 陰性対照：均衡プール ⇒ 移動量 0 | **合格** |
| 5シードで方向性一致 | **一致**：座礁容量およびデータ量の順位は5シードすべてで完全に同一 |

#### ミューテーションテスト：5項目、最終的に全捕捉、ただし初回で捕捉漏れが1件存在

| # | ミューテーション | 結果 |
|---|---|---|
| M1 | 上界を新ディスク全体に変更 | 捕捉 |
| M2 | 狭いストライプの幅クリップを解除 | 捕捉 |
| M3 | ストライプが `w` セルをデータとして計上 (パリティを差し引かない) | 捕捉 |
| M4 | 平坦化が容量をクランプしない | 捕捉 (**真のバグであり、初回陽性対照実行時に赤判定となった**：新ディスク容量 0 の際に 200 セル移動した) |
| M5 | ディスク選択ステップの幅下限を 1 に緩和 | **初回捕捉漏れ** |

⚠️ **M5 は特記に値する**：`no_arm_emits_width_one` は実行完了後の最小幅を判定するが、
`run()` 内には全く同一の `stripe_devices.len() < 2` という第2のゲートが存在し、**ディスク選択ステップの誤りを握り潰していた**——
両方のゲートが正しい状態では不可視であり、片方を削除しても不可視であった。ディスク選択ステップに**直接固定されたテスト**
(`choose_refuses_width_one`) を追加して初めて赤判定となった。

### これで答えられない半分

1. **これは割り当て層の計数モデルであり、スループット測定ではない**：ファイルシステムなし、ブロックデバイスなし、ファイル操作 0 箇所。
   提示しているのは物理セル消費、ストライプ幅、座礁容量であり、**MB/s ではない**。真のスループットはトランザクション層 + QEMU を待つ必要がある。
2. **読み取りをモデル化していない**：「新規データが少数のディスクに集中する ⇒ 読み取り並列度が低下する」という次元は平均幅を通じて間接的に反映されるのみで、直接計測はしていない。
3. 断片化をモデル化しておらず、バックグラウンド整理もモデル化していない (D3 (領域割り当て) 確定項目 14 の常駐整理は断片化を管轄し、ディスク間均衡は管轄外)。
4. **充填率は入力値であり測定値ではない**：90% は設定値であり、当プロジェクトの実測典型値ではない。

### 前置条件

なし。純粋な割り当て層計数モデル。
