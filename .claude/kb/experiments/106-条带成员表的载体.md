## E106 条带成员表的载体 —— 已跑（2026-09-06，纯算术模型，15 单测 / 11 条变异全抓）：**成员表住码 3 打包记录（臂甲）时，稳态下一次单盘失效重建不出来的格数恒 0（8 盘、4096 单元、5 种子 × 6 档容器容量，容器占落点 0.17%–50%），而池刚建好那一格恒 1——条带表只有一个容器时它落在自己描述的那条条带里，容器所在盘一坏就无论按什么顺序都解不开，五个种子全中；同一格上臂甲镜（容器镜像）与臂乙（parity 自证）都是 0。代价（口径当日换过一次，见正文）：臂甲 1544 ppm、臂乙（每单元预留 128 字节恒零区）2511 ppm、臂甲镜 3088 ppm，均按 16 TiB / 90% 占用 / 单元 32768**

**它验的是** D2（RAID 条带策略） 已定项 12（parity 列的位置与发现机制）的一格：成员表放在哪，
决定「一次单盘失效之后，坏盘上的格还能不能重建」。提案 P4 自陈的弱点是自举——
条带记录容器自己也落在条带里，丢了要先重建容器，而重建容器又要成员表。
**那句话是估的，E106（条带成员表的载体） 把它变成量出来的**，而且量出来的形态与那句话说的**不一样**：
不是「成对互指」，是**自指**，落在 `w ≥ 3` 的第一条条带上（2026-09-06 反推腿第五节给的那条历史，
先做成模型里必须报非 0 的世界再改规则）。

### 判据（跑前写死，跑完没改）

1. **阳性对照**：臂丙的不可解格数必须恰等于坏盘上的活格数（另行独立数出来）。对不上说明度量分不出差别，**整轮作废**。
2. 臂乙与臂甲镜恒 0，且这是结构性的。
3. 臂甲按种子钉死绝对值。**两种结果都接受**：全 0 ⇒ 提案 P4 那个担心不成立；非 0 ⇒ 那条自举链是实的。这句话写在跑之前。
4. **阴性对照**：不失效 ⇒ 四条臂全 0。
5. 代价按 16 TiB / 90% 填充 / 单元 32768 算，报 ppm 绝对值；单元数必须等于 E97（记账与分配记录的条目编码） 已入库的 483 183 820。
6. 不动点迭代必须证明真的在动，否则那个循环等于没跑。

### 实测（2026-09-06，产物 `research/results/e106-stripe-member-table-2026-09-12.out`，65 行、`emitted=65`；2026-09-12 随码 3 头 107 重生成，与留在 results/ 的上一版 `e106-stripe-member-table-2026-09-06.out` 只差 config 行，变异复跑 `research/results/e106-mutate-2026-09-12.log` 11 条全抓）

| 臂 | 5 个种子上的不可解格数 | 代价（16 TiB / 90%） |
|---|---|---|
| 甲 | **0 / 0 / 0 / 0 / 0**（坏盘上分别丢 682 / 695 / 726 / 680 / 712 格） | 828 789 个容器 ⇒ 少装 828 789 个数据格 = 27 157 757 952 字节 = **1544 ppm** |
| 甲镜 | 0（结构性：镜像容器丢不掉） | **3088 ppm**（恰好 2 倍） |
| 乙 | 0（结构性：parity 自证，无依赖边） | 128 × 345 131 300 = 44 176 806 400 字节 = **2511 ppm** |
| 丙 | 682 / 695 / 726 / 680 / 712，**逐格等于坏盘上的活格数** | 0 |

⚠️ **2026-09-06 当日在这里挂过一句「几个 ppm 不含 parity 格」的注，那句是错的，已撤回**：
`483 183 820` 不是数据格数，是**被占用的落点总数**（含数据格、parity 格与容器），
`828 789 = ⌈483 183 820 / 583⌉` 因此已经是「一格一条、含 parity 格」——与 D2（RAID 条带策略）
已定项 12 定的口径一致，不用重算。挂那句注时依据的是 E111（条带表的 key 与它的几何） 第一版，
而 E111（条带表的 key 与它的几何） 第一版把这个数读成数据格数、再往上加 parity，摆出了 16 TiB 盘的 135%
（经过记在本文件的「历史版本」2026-09-06（其二））。

**自指那一格（`name=first_stripe`，4 盘、`w = 4`、池刚建好、条带表只有一个容器）**：
五个种子上 `self_referential=true`、`lost=1`、**`unsolvable=1`**——那条条带的四条记录全住在它自己的一个成员里，
容器所在盘一坏，`P4` 那句「条带里只要还有一个成员的记录活着就解得开」为假。
臂甲镜在同一格上是 0（镜像的两份在两块不同盘）。⇒ **臂甲的失败不是罕见摆放，是开池第一条 `w ≥ 3` 条带。**

**代价的口径当日换过一次（第二轮攻击腿 5.5 打中）**：第一版报的是「元数据自己占多少字节」，
而它先取 `483 183 820` 当**数据格数**，再往上加 parity 格与容器 ⇒ 往一块声称 90% 填充的 16 TiB 盘里
摆了 **126.3%** 的格（落点 678 085 686 对槽总数 536 870 912）。当时那条钉绝对值的断言只钉了数据格数，
**对真正喂进成本式的那个量不设防**——正是「钉绝对值的断言钉在不承重的量上」这个形状。
现行口径：**483 183 820 是被占用的落点总数（含数据格、parity 格与容器）**，
各臂在这个固定占用下装得下多少数据格，代价 = 相对臂丙少装的那部分。
换口径也把排序换了：旧读法「甲 2166 < 乙 3516 < 甲镜 4333」，自洽读法「甲 1544 < 乙 2511 < 甲镜 3088」。

⚠️ **这个自洽口径 2026-09-06 当日被 E111（条带表的 key 与它的几何） 第一版反向「纠正」过一次，那次是错的**：
它把 483 183 820 读回成数据格数、再往上加 parity（`w = 3` 得 724 775 730 格 = 16 TiB 盘的 135%），
据此把 D2（RAID 条带策略） 已定项 12 的代价行改成 4631 ppm。E111（条带表的 key 与它的几何） 修好之后
报 **54 315 515 904 字节 / 3087 ppm**，与本实验臂甲镜的 `cost_bytes` **逐位相同**——
两个实验用互不相同的算法算同一个量而落到同一个数。
⚠️ **这个交叉校验今天没有任何检查在做**，是靠人去对才发现的：账记
[checks-owed.md](../checks-owed.md) C155（跨实验同量无交叉断言）。

**加盘窗口那一格：预言的退化没复现（如实记）**。第二轮攻击腿 5.3 预言臂甲在加盘窗口会退化成阳性对照臂丙——
理由是 D2（RAID 条带策略） 已定项 8 的「取最空的」是确定性且全局同步的规则，新盘最空 ⇒ 每条新条带都取它、
容器也堆在它上面 ⇒ 容器与它描述的格正相关，而「稳态恒 0」的承重点正是那个独立性。
按那条规则建模（`name=add_disk`：8 盘、其余盘预填 4096 槽、最后一块是空盘、放置改成「取最空的」）之后
**臂甲仍是 0**（新盘上丢 1643 格），臂丙同格 1639 全丢。**没复现的原因钉成了断言**：
一次攒批的 w−1 个单元被摊到 w−1 个**不同的列**上 ⇒ 一条条带在同一块盘上至多一个格，
容器与它描述的格因此仍落在不同盘上（实测 10 个容器落在 [0,7,2,3,7,5,7,0,1,7]，只有 4 个在新盘）。
⇒ **这条预言在「容器与数据同一次攒批」这个写入形态下不成立**；它要成立得靠别的形态。

**一个纯算术的观察（不靠模型）**：容器**单独一次发布**写出时，
D2（RAID 条带策略） 已定项 6 的公式给 `w = clamp(1 + 1, 2, 4) = 2`，
而 w = 2 的 parity 就是逐字节相同的第二副本（D9（加密））⇒ **那次写自动是镜像**
⇒ 臂甲在这个写入形态下退化成臂甲镜、自举那条边消失。
⇒ 臂甲与臂甲镜的差别只在「容器与数据同批」这一种写入形态上才存在。

**容器容量灵敏度扫描**（臂甲，容量 583 → 64 → 16 → 8 → 4 → 2，容器占落点比例 0.17% → 1.57% → 6.25% → 12.5% → 25% → 50%）：
**30 格里不可解数全部是 0**。不动点迭代确实在动——`solved_after_first` 在 30 格里有 12 格非 0（最大 3），
即第一轮解不开、后面几轮解开的格确实存在，只是从没有解不开的。

**为什么恒 0（机制，不是运气）**：一个丢失的格有 `w` 条独立的路可走——它那条条带的每个成员各有一条记录，
任一条记录所在的容器只要可读或已重建，成员表就到手。要不可解，得 `w` 条路同时落进「坏盘上且自己也不可解」的容器里。
按 key =(设备, 槽号) 排序装容器 ⇒ 坏盘上那些落点的记录聚在一起，而**要用的恰恰是活盘上兄弟成员的记录**，
它们的 key 落在别的容器区间里，物理落点又是独立随机的。

**但「随机摆放下解不开的概率极低」不等于「解不开这件事不会发生」**：
手工摆的死锁（两条条带，各自的成员记录全住对方那个容器，两个容器都在坏盘上）度量报 **2**，
把其中一个容器搬到活盘上就回 0；而**自指那一格根本不用手工摆**——按模型自己的建池顺序就是它。
⇒ **臂甲的可解性是概率性的、且在开池那一刻恒为假；臂甲镜与臂乙的是结构性的。**
这条区别不靠这次的数字，靠依赖图的形状：臂甲的依赖图有边，另两条没有。

### 变异测试：11 条全抓

「不可解判定只看第一轮」「阳性对照臂也走求解」「容器不动点忽略自己」「记录容量按整单元算」
「镜像臂也发 parity 格」「成员表只看自己那一条」「代价漏掉 parity 落点」
「镜像副本当成两个容器」「自指那格换一块没坏的盘」「占用当成数据格数」「闭式条带数少算一轮」。
⚠️ 后两条是补的：第一版模型把臂甲镜的两份镜像当成**两个**容器，于是「任一副本可读」这条判不出来，
自指那一格上臂甲镜误报 2。改成逻辑容器（一个容器多份副本）之后归 0。

### 钉绝对值的断言（不做臂间互比）

`unit_count_matches_e97`（483 183 820、16 TiB = 17 592 186 044 416）、
`records_per_container_is_pinned`（583，且 107 + 56 × 583 + 13 = 32768）、
`positive_control_unsolvable_count_equals_lost_count`（臂丙逐种子等于坏盘活格数且 > 0）、
`deadlock_is_reachable_by_construction`（手工死锁报 2，搬走一个容器回 0）、
`cost_absolute`（数据格 345 131 300、甲少装 27 157 757 952 字节、甲镜 = 2 × 甲、三条 ppm 各自钉死）、
`occupancy_is_self_consistent`（各臂摆进去的落点数 ≤ 槽总数 536 870 912，且填满占用）、
`closed_form_matches_loop`（闭式条带数与逐条带循环在 0–2000 及三个大值上逐格相等）、
`lone_container_publish_is_mirrored_by_the_width_formula`（clamp(1+1,2,4) = 2）、
`add_disk_window_leaves_pooled_container_arm_solvable`（加盘窗口实得 0，并钉住「一条条带在同一块盘上至多一个格」）、
`first_stripe_self_reference_is_unsolvable`（五个种子上自指成立、不可解数 == 坏盘上的格数、臂甲镜同格为 0）、
`container_fixpoint_accounts_for_itself`（容器自己也要一条记录）。

### 它不答什么

挂钟；真实分配器的落点分布（**取均匀随机是建模选择，不是实测**）；多盘同坏（`w = 3` 只容一格）；
修复的写放大（E80（条带的部分释放） 量过那一格）；**加密开启后臂甲的记录读不读得到**——
那是正推腿打中的那一格，属于判据问题不是算术问题，模型里没有这一维。
**稳态那一格的落点分布取均匀随机，`w` 只跑了 3 / 4 两档**；
**代价那三个数只在「所有单元都参与 `w ≥ 3` 条带」这个假设下成立**；第一版 `w` 恒 2 时臂甲恒 0 字节、臂乙照付。
