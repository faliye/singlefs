## E96 ハイブリッドアーキテクチャの一致性 —— 実行済み（2026-09-03、10単体テスト / 12件ミューテーション全検出）：ユニットヘッダが5つ組のみのときスナップショット読み取りは新バージョンを静黙に読み取る、ヘッダにブロック birth を持つと恒等的に 0；解放はヒントではなくマッピングを経由しなければならない；移動の3段階切り捨ては誤読み取りを新規増加させない

[中文](96-混合架构的一致性.md) · [English](96-混合架构的一致性.en.md) · **日本語**

**問題**：D26 (バックグラウンド整理と配置回収) 当該節の6つの未確定項目の論証資料が推奨した位置権威形態は
**ハイブリッドアーキテクチャ**であった —— ツリーポインタ内の位置エントリ（D19 (ブロックポインタの構造と幅予算) 確定項目 1）を**ヒント**に降格させ、
「論理識別子 → 配置先」の中央マッピング（D9 (暗号化) 確定項目 5 が暗号化側で確定した形態）を無条件に存在させて**権威**とする；
読み取りはヒントを辿り、ユニットヘッダを検証し、不一致時はマッピングへ戻る；整理はマッピングのみを変更し、スナップショットツリーと deadlist は動かさない。
ユーザーからの問い：一致性において問題はないか。E94 (共有配置先移動の接触面) はコストのみを測定し、一致性は測定していなかった。

実行前に想定された4つの危険を4つの判定基準とした：
ヒントの期限切れ後に**再利用されたスロット**に着地する（ユニットヘッダの5つ組 —— D18 (ブロックに含める情報) 確定項目 3 ——
にはブロックの birth がなく、同一の (inode, offset) の新旧バージョンで5つ組が一致する）；
解放パスが誤ってヒントを権威とみなす；移動トランザクションの中途クラッシュ；マッピングと占有表の保存則。

### モデル

E94 (共有配置先移動の接触面) の永続 COW ツリー（L=4096、F=16）、スナップショットローテーションおよび破棄カスケードを踏襲し、以下を追加：

| 部品 | モデル |
|---|---|
| リーフエントリ | (バージョン, 配置先ヒント)；ヒントは当該エントリが書き換えられたときのみリフレッシュされ、整理はこれを変更しない |
| 中央マッピング | バージョン → 配置先、権威；整理はここでのみ変更 |
| ユニットヘッダ | 2アーム：`hdr_key`（5つ組のみ ⇒ key としてモデル化）/ `hdr_birth`（5つ組 + ブロック birth ⇒ (key, birth) としてモデル化） |
| 読み取りパス | ヒント優先：ヒント先スロットの占有者ユニットヘッダが読み取り対象バージョンと一致すれば復帰；そうでなければマッピングへ戻り1ホップ追加 |
| 解放 | スナップショット破棄時、deadlist エントリはマッピングに従って配置先を解決（正解）；別途「ヒントに従って配置先を解決」した場合の誤解放回数を計算（ネガティブアーム、カウントのみで適用せず） |
| 割り当て | 2アーム：`alloc_lowest`（最低空きスロット）/ `alloc_lifo`（直近に解放されたものを優先再利用）—— いずれも key を対象としない |
| 整理 | スキャンカーソルから N=64 個の占有スロットを取得して新スロットへ移動、1周スキャン後に先頭へ戻る |
| defer | あるラウンドで解放されたスロットは次のラウンドまで再利用不可（D16 (パブリッシュセマンティクス) 確定項目 15） |

ワークロード：毎ラウンド 64 回の更新 + 1バッチの整理 + ラウンド終了時に全ルートの全 key を読み取り、200 ラウンド、8ラウンドごとにスナップショット作成、4個保持；
2組：`uniform`（一様ランダム key）と `adversarial`（更新の半分を移動直後の key に集中 ——
「同一 key の新バージョンが旧スロットを再利用する」危険を到達可能とする、E31 (AAD にスナップショット次元が欠落) 系統の対照形態）。

### 判定基準（2026-09-03 実行前固定）と判定

| # | 判定基準 | 判定 |
|---|---|---|
| 1 | 手計算アンカー：スナップショット → key 3 を移動（スロット 3 → 8）→ key 3 を更新してスロット 3 を再利用 → スナップショットの key 3 を読み取り：`hdr_key` の誤読み取り 1、`hdr_birth` の誤読み取り 0 で追加ホップ 1 | **合格**（単体テスト） |
| 2 | 保存則：参照されている各バージョン `占有者(マッピング(v)) == v`、マッピングと占有は互いに逆関数 | **合格**（40構成 × 200ラウンドをラウンドごとに監査） |
| 3 | 陽性対照：マッピングを破壊 ⇒ 監査が赤判定；占有を入れ替え ⇒ 誤読み取りカウントが反応 | **合格**（単体テスト、逆方向照合でのみ検出可能な構成を含む） |
| 4 | `hdr_key` の誤読み取り数は独立スキャンした「ヒント先スロットが同一 key の別バージョンに占有されている」数と厳密に一致；`hdr_birth` は恒等的に 0 | **合格**（ラウンドごとに一致；`hdr_birth` は 40 × 200 ラウンドで恒等的に 0） |
| 5 | ヒントに従って配置先を解決した場合の誤解放数 > 0；マッピングに従う場合は恒等的に 0 | **合格** |
| 6 | 移動の3段階で各1回切り捨て：誤読み取りを**新規増加させず**、保存則が常に成立 | **合格**（8構成各3段階、差分は恒等的に 0；計測条件の明確化は改訂記録を参照） |
| 7 | ラウンドに伴う追加ホップ率（数値報告のみ） | 実測を参照 |

### 実測（5シード）

#### 1. ユニットヘッダが5つ組のみ：スナップショット読み取りは新バージョンを静黙に読み取る（判定基準 4）

| ユニットヘッダ | 割り当て | ワークロード | 200ラウンドの誤読み取り総数（5シード） | 第200ラウンドの誤読み取り |
|---|---|---|---|---|
| `hdr_key` | 最低空きスロット | 一様 | **65 / 0 / 72 / 0 / 69** | 0 |
| `hdr_key` | LIFO | 一様 | 66 / 48 / 40 / 128 / 57 | 0 |
| `hdr_key` | 最低空きスロット | 敵対的 | 4052 / 3925 / 3992 / 4503 / 4326 | 22–31 |
| `hdr_key` | LIFO | 敵対的 | 4581–5259 | 17–23 |
| `hdr_birth` | 任意 | 任意 | **0（全20実行）** | 0 |

- **一様ランダムワークロード、最低空きスロット割り当て —— 再現に最も不利なセル —— でも誤読み取りが発生**（5シード中3シードが非ゼロ）。毎回エラー報告なくスナップショット読み取りが同一 (inode, offset) の**新しい**コンテンツを取得：ヒント先スロットが同一 key の新バージョンによって再利用され、5つ組が字面通り一致し、読み取りパスがヒント的中と判断。
- 敵対的ワークロード下では各ラウンド末に約20個のそのようなエントリが生存（`wrong_last`）、200ラウンド累計で4〜5千回。
- ヘッダにブロック birth を付与すると、同一のワークロード、同一のヒント、同一の再利用において、**誤読み取りは1回も発生しなかった** —— 不一致はすべてマッピングへ戻る（追加ホップ率は第3項を参照）。
- E85 (ユニットヘッダのフィールド表) は「確定フィールドセットはブロック birth を判定できない」と既に測定しており、E31 (AAD にスナップショット次元が欠落) は5つ組がスナップショット次元に対して盲目であることを測定済み；E96 (ハイブリッドアーキテクチャの一致性) はこの2つを整理へと接続した：**位置ヒント + 5つ組ヘッダ = 整理後にスナップショットが静黙に誤読み取りを起こす**。

#### 2. 解放はヒントではなくマッピングを経由しなければならない（判定基準 5）

| ワークロード | 200ラウンドでヒントに従って配置先を解決した際の誤解放（他バージョンが占有中のスロットを解放） | マッピング経由 |
|---|---|---|
| 一様 | 4861–5123 回 | **0** |
| 敵対的 | 6003–6158 回 | **0** |

deadlist エントリが保持するヒントは kill の瞬間にリーフにあった値であり、その後に整理が移動させれば期限切れとなる；スナップショット破棄時にそれを配置先として扱うと、他人のスロットを解放してしまう。⇒ **いかなる解放パスもヒントを権威とみなしてはならない** —— これはハイブリッドアーキテクチャの厳格な規則である。

#### 3. 期限切れヒントの読み取りコスト（判定基準 7）

| ワークロード | 第100ラウンド追加ホップ率 有効ルート / スナップショットルート | 第200ラウンド 有効ルート / スナップショットルート |
|---|---|---|
| 一様 | 約 30% / 37% | 29–31% / 35–37% |
| 敵対的 | 約 15–16% / 25% | 19–21% / 27–30% |

有効ルートのヒントは当該 key が書き換えられたときのみリフレッシュされ、スナップショットのものは永久にリフレッシュされない；200ラウンドで整理カーソルは占有領域を約1周スキャン ⇒ 3割の読み取りが1ホップ追加を要する。**これがハイブリッドアーキテクチャにおける読み取りコストの形状である**：整理がどれだけ移動したか、スナップショットがどれだけ古いかに比例し、スナップショット数 K には比例しない（E94 (共有配置先移動の接触面) ではポインタ権威のコストが K に連動していた）。

#### 4. 移動中途のクラッシュは誤読み取りを新規増加させない（判定基準 6）

1回の移動 = ① 新レプリカ書き込み → ② マッピングパブリッシュ → ③ defer で旧スロット解放。8構成が3段階の各段階後に切り捨ててリカバリ（① の後の未パブリッシュ割り当てはロールバック；② の後の旧スロットは defer が解放）：**誤読み取りの差分は恒等的に 0、保存則は常に成立**。機構：② の前はマッピングは依然として旧レプリカを指し旧レプリカは健在；② の後はヒントが旧スロットに着地した際も占有者は依然として同一バージョンであり、読み取られるのはそれ自身である —— 双方案とも「マッピングが存在しないものを指す」ウィンドウは存在しない。

### モデル改訂記録（すべて正式ラウンド登録前に発生、判定基準 1–5、7 は未変更）

1. **整理バッチを「スロット番号最小の64個」からスキャンカーソルに変更**：初版の移動先が再び最低空きスロットを取ったためディスク底で空回りし、200ラウンドで追加ホップ率を95%まで引き上げた —— それはアーティファクトでありハイブリッドアーキテクチャの読み取りコストではない。
2. **判定基準 6 の計測条件を差分として明確化**：`hdr_key` アームの世界には元々同一 key 再利用スロットに着地する誤読み取りが存在し、切り捨て前後を絶対値 0 で判定するとそれらをクラッシュのせいにすることになる；「切り捨てが誤読み取りを新規増加させない」に変更（`hdr_birth` 下では差分 0 即ち絶対値 0）。
3. **割り当てポリシー次元を追加**：最低空きスロット下では敵対的ワークロードでも24ラウンドで同一 key 再利用を作れなかった（旧スロットの前方に常にさらに低い空きスロットが存在するため）、LIFO（直近解放分を優先再利用、多数のアロケータの形態、key を対象としない）を追加して危険を規模的に到達可能とした；登録ラウンドでは両ポリシーを報告し、一様ワークロード + 最低空きスロットセルも同様に非ゼロとなった。

### それが答えられないこと

1. 位置エントリ内の 32 ビット暗号文チェックサム（D19 (ブロックポインタの構造と幅予算) 確定項目 2）も確率的に再利用を検出可能であるが、モデルは構築していない —— それは `hdr_key` アームの誤読み取りを「必然」から「2⁻³² の確率」に変えるのみであり、次元が異なるため別途計算する。
2. レイテンシ軸なし：追加ホップ率は回数比率であり、遅延ではない。
3. 暗号化側（マッピング層平文、MAC が位置をカバーしない）の改ざん面はモデル外。
4. マッピング層自体の永続化と再構築（C34 (平文マッピング層の状態に関する3つの対立)、E28 (平文マッピング層はユニットの自己記述のみで再構築可能か)）は既存の結論を引用し、再検証しない。
5. 有効ルートヒントのリフレッシュポリシーは「書き換えに伴うリフレッシュ」の1種のみ；「読み取り不一致時にヒントを併せて更新する」ようなスナップショットツリー外のリーフを変更する形態はアームを構築していない。
6. 絶対カウントはファンアウト 119 にメッセージバッファを加えたツリーには流用できない（E94 (共有配置先移動の接触面) と同一の制限）。
