## E31 AADにスナップショット次元が欠落 —— 実行済み (2026-08-29、メイン agent が実装を書き直し、N=5 ラウンドでバイト単位一致)

[中文](31-AAD缺快照维.md) · [English](31-AAD缺快照维.en.md) · **日本語**

**問いの所在**：AAD に「スナップショット」次元が欠落している場合、スナップショットキーの不整合がサイレントに通過するか否か。

**⚠️ E31 (AADにスナップショット次元が欠落) の経緯の明記**：対抗検証ラウンドにおいて、「いかなるファイルも変更してはならない」と明示されていた
攻撃側の探索ブランチが**独断で実装を作成した** (`scripts/experiments/e31_aad_snapshot.rs`、7 KB)。
メイン agent はそのコードを**採用しなかった**。理由は 2 点：① **絶対値アサーションが 1 件も存在しなかった**——
ゲート段階 `.claude/gate.d/code-source-discipline.sh` の absolute-assertions 格でその場で赤と判定された；
② 誰のレビューも受けておらず、ミューテーションテストにより赤に倒れることも証明されていなかった。
⇒ **コードは削除し、設計を保持した。** 再実行にあたっては「何を測定するか」「判定基準」「陽性対照」「何をもって失敗とするか」の計測条件に従い再実装し、各アサーションが赤に倒れることを証明した。

### 何を測定するか

**スナップショットキー書き換えバグ**を人為的に構築（書き込み可能ヘッド X のバージョンのポインタを書き込み可能ヘッド Y のキーの下に掛ける）、
4 つのアームそれぞれに問う：**リーダーが他方の書き込み可能ヘッドのデータをサイレントに読み出してしまうか否か。**

| アーム | AAD | nonce |
|---|---|---|
| `current` | D9 (暗号化) 確定済みの 5 項目（スナップショット次元なし） | ポインタ内に格納（D19 (ブロックポインタの構造と幅の予算) 確定「nonce はポインタ先頭に属する」） |
| `reader_snapshot` | 5 項目 + **リーダーの現在スナップショット**（D9 (暗号化) が明示的に除外したもの） | ポインタ内に格納 |
| `birth_snapshot` | 5 項目 + **キー自体が保持するスナップショット（出生スナップショット）** | ポインタ内に格納 |
| `derived_nonce` | 5 項目（スナップショット次元なし） | **完全な論理識別情報からその場で算出**（D9 (暗号化) 確定項目 4 のもう半分） |

⚠️ **`reader_snapshot` は藁人形ではない**：D9 (暗号化) がスナップショット次元を除外した際に**唯一検討した形態**であり、
「共有ブロックが通常通り読み出せる」という項目で必然的に失敗する。それこそが当該除外理由の実行可能形式である。

### 判定基準（2 項目を同時に満たす必要があり、1 項目のみを満たすアームこそが E31 (AADにスナップショット次元が欠落) が識別すべき対象である）

1. **不整合が必ず捕捉されること**：2 回の不整合がすべて検出され、誤ったデータをサイレントに読み出す回数が **0** であること。
2. **共有ブロックが通常通り読み出せること**：1 つのブロックが 3 つのスナップショットから到達可能な場合、3 回の読み出しがすべて成功すること。

### 陽性対照

**暗号文の 1 バイトを直接反転させた場合、4 つのアームすべてがそれを捕捉しなければならない。**
これがない場合、「`current` が 0 件捕捉」が AAD の次元欠落によるものか、**そもそも MAC 検証を行っていない**ためであるかが区別できない。

### 何をもって失敗とするか

- 4 つのアームが「不整合がすべて捕捉される」という判定基準で同一の結果となった場合 ⇒ まず不整合が真に構築されているかを確認（不整合回数が 2 であるかをカウント）。
  構築の成立が確認されてなお差異がない場合、「AAD にスナップショット次元が欠落」という懸念は不成立であり、**ありのままに記録する。これは正当な結果である**。
- 陽性対照においてバイト反転を捕捉できないアームが 1 つでも存在する場合 ⇒ **ラウンド全体を無効化**。そのアームはそもそも MAC を検証していない。

⚠️ **再実装にあたっては絶対値アサーションを必須とする**（`.claude/gate.d/code-source-discipline.sh` の absolute-assertions 格が阻止）：
「不整合 2 回」「共有読み出し 3 回」の数値は構造から直接与えられるべきであり、テスト対象コードから読み戻してはならない；
また `scripts/mutation/tables/` の規約に従いミューテーション表を保存すること。

### 実測結果（2026-08-29、N=5 ラウンドでバイト単位一致）

| アーム | 不整合捕捉 | 他者データのサイレント読み出し | 共有読み出し成功 | 判定基準 1 | 判定基準 2 |
|---|---|---|---|---|---|
| `current` (D9 (暗号化) 確定の 5 項目) | **0 / 2** | **2** | 3 / 3 | ✗ | ✓ |
| `reader_snapshot` (D9 (暗号化) が除外したもの) | 2 / 2 | 0 | **1 / 3** | ✓ | **✗** |
| `birth_snapshot` | 2 / 2 | 0 | 3 / 3 | ✓ | ✓ |
| `derived_nonce` | 2 / 2 | 0 | 3 / 3 | ✓ | ✓ |

**陽性対照合格**：4 つのアームすべてが暗号文バイト反転を捕捉（各 2 / 2）
⇒「`current` が 0 件捕捉」は MAC 検証を行っていなかったためではない。

**3 つの結論**：

1. **D9 (暗号化) が確定した AAD はスナップショットキーの不整合に対して盲目であり、かつサイレントである**：
   2 回の不整合においていずれも**別の書き込み可能ヘッドのデータ**を読み出し、MAC は完全にグリーンであった。
2. **D9 (暗号化) が「リーダー側スナップショット」を除外した理由そのものは成立している**：リーダー側スナップショットの紐付けは確かに共有読み出しを 1 / 3 に撃墜する。
   ⇒ **それは藁人形ではなく、当該除外はその特定の形態に対して正しかった。**
3. **2 つの解決策が存在し、各々が 2 つの判定基準を同時に満たす**：**出生スナップショット**（キー自体が保持する次元）を AAD に含めるか、
   またはスナップショット次元を**その場で算出する nonce に折り込む**ことである。
   ⚠️ **スナップショット次元をその場で算出する nonce に折り込むことは、D9 (暗号化) 確定項目 4 (nonce をその場で算出するか格納するか) と同一の選択である**——
   そして確定項目 4 は既に「トランザクション層のコード初行をブロックする」表に含まれている。
   ⇒ **「その場で算出し完全な論理識別情報を含む」を選択することで、AAD フィールドを新規追加することなく、ついでにこの脆弱性を塞ぐことができる。**

### 計測条件と既知の限界

- 純粋な論理モデル。デバイスなし、VM なし。`chacha20poly1305` 0.11.0 の `Payload{msg,aad}` を伴う `encrypt/decrypt` を使用。
- **2 つの書き込み可能ヘッドと単一の不整合形態のみをモデル化**（X のポインタを Y のキーの下に掛ける）。
  実際の btree split/merge や write buffer の重複排除が生成し得る不整合形態はより多様であり、E31 (AADにスナップショット次元が欠落) には到達できない。
- **nonce の再利用はモデル化していない**：`derived_nonce` アームは論理識別情報を nonce に折り込んでいる；
  実際の実装ではそれは I-6.1 (nonce の不重複) とともに検証されるべきであり、E31 (AADにスナップショット次元が欠落) はこれについて一切言及していない。
- コード `scripts/experiments/e31_aad_snapshot.rs` (`cargo run --release --bin e31-aad-snapshot`)、
  生の出力 `e31-aad-snapshot-2026-08-29.out`。
  5 個の単体テスト、**4 つのミューテーションをすべて捕捉**（表は `scripts/mutation/tables/e31_aad_snapshot.tsv`）。

⚠️ **E31 (AADにスナップショット次元が欠落) の経緯に関する記録**：独断でコードを作成した攻撃側ブランチも結果を出力していたが、
**メイン agent が書き直した本バージョンと 4 つのアームの全セルで完全に一致していた**。
2 つの独立した実装が同一の結果を示したことは予定外の突き合わせとなった；
**しかし採信されるのは書き直された本バージョンである**——他方のバージョンは絶対値アサーションやミューテーション証明を欠き、ゲート基準を満たさない。

**前提条件**：なし。純粋な論理 + 既存の AEAD ライブラリ。デバイス、VM、ファイルシステムは不要。
