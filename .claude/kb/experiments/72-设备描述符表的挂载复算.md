## E72 设备描述符表的挂载复算 —— 已跑（2026-09-02，**真异构 loop 池**，N=5 轮 × 2 次调用判决一致）：**四条比对项全部能被强制判红，表外的量不判红**

D12（目标介质） 已定项 3 把设备级几何量定在超级块的设备描述符表里，
D12（目标介质） 已定项 4 定了比对规则并逐字要求「**每一条都要能被测试强制走进『对不上』那条分支**——
一条不会红的比对项与没有这条比对项，在挂载日志里长得一模一样」。

### 判据（跑前写死，跑完没改）

1. **绝对值断言**：表的字节数恰好等于 `设备数 × 每设备条目宽度`，不许只看趋势。
2. 复算耗时随设备数**线性**；出现超线性判「复算里混进了 O(设备²) 的比对」。
3. **每一条比对项都要能被强制走进「对不上」那条分支。**

### 失败条款（跑前写死）

| 条款 | 判定 |
|---|---|
| **阳性对照**：改坏其中一台设备的几何字段，复算必须判红 | **通过**（四条各自判红，逐格见「判据 3 + 阳性对照：四条比对项逐条被强制判红」）|
| **若所有比对项都只在同构池上验过，整轮作废** | **未触发**：全部场景跑在**真异构池**上（`pbs_mix=4096,512`）|

### 实测

#### 判据 3 + 阳性对照：四条比对项逐条被强制判红

池子是 4 台真 loop 设备，`losetup --sector-size` 造出 **`physical_block_size` 512 与 4096 混合**。
「改坏」全部用**真手段**——换 sector-size 重挂、`truncate` 改容量、换设备顺序、改表里的布局位。

| 场景 | 怎么改坏的 | pbs | 容量 | 身份 | 布局 | 处置 |
|---|---|---|---|---|---|---|
| 阴性对照：什么都不改 | — | ok | ok | ok | ok | **allow** |
| 强制 pbs 对不上 | 1 号盘 4096 → 512 重挂 | **mismatch** | ok | ok | ok | **refuse_rw** |
| 强制容量变小 | `truncate` 到一半再重挂 | ok | **shrunk** | ok | ok | **refuse** |
| 强制容量变大 | `truncate` 到两倍再重挂 | ok | **grown** | ok | ok | **allow_and_note** |
| 强制身份错配 | 交换两台盘的顺序，表不动 | ok | ok | **mismatch** | ok | **refuse** |
| 强制布局位不认识 | 表里某台的 layout 位改成 2 | ok | ok | ok | **mismatch** | **refuse** |
| **表外的量变了** | `blockdev --setra` 改预读 | ok | ok | ok | ok | **allow** |

⇒ **四条比对项各自被单独强制判红，且每次只有那一条红**——
互不串味说明它们判的确实是各自那个量，不是一条笼统的「有什么不对」。
⇒ **处置也逐格符合 D12（目标介质） 已定项 4**：pbs 是 `refuse_rw`（拒绝**可写**挂载，不是拒绝挂载）、
容量变大是 `allow_and_note`（放行并记），其余是 `refuse`。

⚠️ **最后一行是这张表里第二重要的一行**：D12（目标介质） 已定项 4 逐字写着
「不在清单里的：转速、队列深度、`io_opt`、discard 支持……比对它们只会制造无法挂载的假红」。
改预读之后复算**照样放行** ⇒ **那条「不比」的规则也有判别力**，不是一句态度。

#### 判据 1：表的字节数

| 设备数 | 条目数 | 24 B/条 | **40 B/条** | 64 B/条 |
|---|---|---|---|---|
| 2 | 2 | 48 | **80** | 128 |
| 4 | 4 | 96 | **160** | 256 |
| 8 | 8 | 192 | **320** | 512 |

⇒ 恰好 `设备数 × 条目宽度`，三档宽度都成立。
⚠️ **条目宽度仓里没定过** ⇒ 40 字节（dev_uuid 16 + pbs 4 + lbs 4 + 容量 8 + 布局位 8）是**假设**，
另外两档一并报出，**不许把某一档的字节数当结论**。

#### 判据 2：复算耗时线性，没有 O(设备²)

| 设备数 | 复算总耗时 | 每设备 |
|---|---|---|
| 2 | 26.0 ms | 13.02 ms |
| 4 | 50.5 ms | 12.63 ms |
| 8 | 99.8 ms | 12.48 ms |

⇒ 每设备耗时**平坦甚至微降**（固定开销被摊薄）⇒ **线性，判据 2 成立**，没有二次项。

⚠️ **那个 12.5 ms 是 harness 开销，不是挂载耗时的预测。** 它绝大部分是每台设备两次
`sudo`（`blockdev --getsize64` 与 `losetup -O BACK-FILE`）的进程启动代价。
**线性这个结论成立，绝对值不许外推到真实挂载路径。**

### 它答不了的那一半

1. **挂载路径本身不存在**（没有超级块、没有实现）⇒ 这里实现的是 D12（目标介质） 已定项 4 那条**规则**，
   验的是**规则里每一条比对项有没有判别力**，**不是**「本工程的挂载代码对不对」。
   代码写出来之后要拿同一组场景再验一遍。
2. **异构只做到了 `physical_block_size` 这一维**（512 / 4096）。
   真正的异构池还有介质类型、条带几何、布局不同——那些要 QEMU
   （E15（异构设备几何的模拟是否成立） 已证明造得出宾能分辨的异构几何），产出 E72（设备描述符表的挂载复算）这份正文的那一轮没做。
3. **设备身份用 backing 文件名当代理**，不是真的 UUID——真实现要在设备上写一个身份字段并回读。
   错配这条路径验到了，**身份字段本身怎么落盘没验**。
4. **表的条目宽度、dev_uuid 宽度都是假设**（与 E71（记账 key 的条目数与宽度） / E73（节点 key 区间的扇出代价） 同一笔欠账）。
5. **没有验「表本身坏了」**：表的校验和、表跨原子单元、表与根的一致性，一条都没碰。
6. **多条比对项同时对不上这条路径没被走到**：每个场景只改坏一条。
   处置函数里「谁更严」的次序（`refuse` 严于 `refuse_rw`）是照 D12（目标介质） 已定项 4 写对的，
   **但它没有被任何场景验过**——要验得再造「pbs 变了且容量同时变小」这类组合场景。

### 前置

要 `sudo`（口令走 `.env`，2026-09-02 已具备）。异构靠 `losetup --sector-size`，不需要 QEMU。

### 口径与复跑

- 脚本 `research/scripts/e72-devtable-probe.sh`（`bash research/scripts/e72-devtable-probe.sh`，要 `sudo`），
  原始输出 `research/results/e72-devtable-probe-2026-09-02.out`（40 行，收尾行 `emitted=40`）。
- 4 台 16 MiB loop 设备，偶数号 `--sector-size 512`、奇数号 `4096`；镜像落 `TMPDIR`，
  EXIT 按字面量名字 `losetup -d`。
- ⚠️ **复跑不是逐字节比对**：含耗时字段 ⇒ 每次不同。
  **判据是七个场景的处置模式**（四条各自判红、表外的量放行、阴性对照放行），
  两次完整调用共 10 轮一致。
