### ⚠️ Two Measurement Bases; Conclusions False Without Documenting Them

#### 1. "Payload Only Half Landed" Constructed as **Residual Bytes**, Not Short Buffer

If constructed as short buffer, **length check alone stops it without reading a single byte of checksum** —
attributing it to "payload checksum caught it" credits length check's achievement to checksum.
Journal is fixed-length ring (D23 (Journal Role and Format) settled item 2); unlanded half consists of **residual bytes from previous revolution**, not holes.

Short buffer arm was run separately and **faithfully noted as intercepted by length check**:
`header_csum=pass, payload_csum=not_reached` — verdict is three-state, not two-state.

#### 2. **Digest Function** of `header_csum` Unsettled in D23 (Journal Role and Format); Settled Width and Coverage Only

Settled item 13 settled CRC32C for **payload**; algorithm for the 32-byte header field was not settled anywhere.
⇒ Four-row verdict evaluated **once each for CRC32C and FNV-1a**,
**all 8 cells yielded identical verdicts** ⇒ conclusion is artifact of coverage range, not function selection.
(CRC32C implementation pinned by public test vector: `crc32c("123456789") = 0xE3069283`.)

### Measurement: Why Candidate A Was Rejected, Measured Numerically

D23 (Journal Role and Format) settled item 13 verbatim stated reason for rejecting Candidate A was
"would lose discriminative capability for 'header landed but tail unlanded'". **That statement now has numbers**:

| Construction | Candidate B `distinguishable` | Candidate A `distinguishable` |
|---|---|---|
| Entire record landed intact on disk | 0 (both pass, inherently should be identical) | 0 |
| **Header landed, payload only half landed** | **1** | **0** |
| Header corrupted by one byte | **1** | **0** |
| Payload corrupted by one byte | **1** | **0** |

Candidate A has only one checksum, both columns **structurally incapable of differing** ⇒ outputs 0 on every row.
⇒ **That was not "Candidate A fell slightly short", but that Candidate A's type signature cannot answer the question of "header landed but tail unlanded".**

### Consequential Requirement Pinned: `header_csum` Must Cover the 4 Bytes of `payload_csum`

Payload checksum is **a field inside header**. If `header_csum` does not cover it,
modifying payload checksum itself is silent — payload altered, checksum altered to new value, both pass.
⇒ Field placement settled as `payload_csum` **before** `header_csum` (offset 59, header checksum at 63),
pinned by a unit test: altering one byte of `payload_csum`, `header_csum` must judge red.

### What It Cannot Answer

1. **This is a record codec model**, lacking journal implementation, block layer, and crash-point replay, 0 file operations.
   It verifies "whether coverage of these two fields can discriminate these four constructions",
   **not** "whether real power loss creates row 2 half-landed records" — that requires crash-point replay, not yet in repo.
2. **When residual bytes happen to match real payload, row 2 degenerates**, which is inherent collision surface of checksums, not a coverage issue.
   Three residual values (0x00 / 0xEE / 0xFF) yielded identical verdicts, yet this **does not constitute measurement of collision rate**.
3. Header modeled as 95 bytes (78 + three settled pending-landing increments); field placement arranged by E76 (Discriminative Power of Payload Checksum);
   **concrete offsets of header fields never settled anywhere in repo**.
