### 这是确定性模型，不是测量

fsid、时间戳都是固定参数，没有 I/O、没有随机源 ⇒ 跑 N 遍逐字节一样。证据强度来自 **16 个单测里钉死的绝对值 + 16 条变异全部被抓**：
根记录改回 242、摘掉第二道屏障、oracle 不计走读失败、读单元不验校验和、32 字节校验和少罩一字节、指向码 1 的指针改 83、
mkfs 只种两个区域、载荷校验和挪出头校验和覆盖、码 2 映射 key 丢出生树、实例表跨度改 1、已分配字节少一槽、枚举漏掉空子集、
FUA 不切段、根槽恒写区域 0、树 ID 水位不高于最大树 ID、只读第一条位置条目——每一条都有测试红。

### 被测对象与臂

装置照 [first-txn-layout.md](../first-txn-layout.md) 零到七各节写字节：两块 512 槽的盘、超级块槽 0 / 4096、根环 1 / 4 / 7 MiB 各 8 槽、
journal 环 16 MiB 起 64 MiB、单元区从槽 5120 起按字节表的分配顺序。持久顺序照 D16（发布语义） 已定项 7；崩溃状态集合照 D13（验证路线） 已定项 4
（屏障切段、段内任意整写子集、没持久的位置放旧字节、镜像双写按设备各算）；恢复照 D23（journal 的角色与格式） 已定项 14 的口径
（全环扫描不先信 tail、jsn 严格连续、只施加 (实例代号, checkpoint_txg) 高于根水位的记录、提交标记齐全、施加前逐项验证点名单元）；
oracle 照 E77（发布的持久顺序） 判据 1（根槽已持久而恢复不是新态或走读失败即违例；根槽未持久时新旧两态都合法）。

### 它答不了的

1. 层 0 只枚举段内整写子集（D13（验证路线） 已定项 4），撕裂态并进「没持久」；真实 FLUSH / FUA 是否生效归 C6（块层语义假设写错）。
2. 只有一次发布、一条记录：环回绕、多记录前缀、实例切换、回退行一个都碰不到；判据 6 的「journal 不承重」只对第一个事务、且只对「施加 = 验证」这一读法成立。
3. 装置自取的预想值（码 2 头宽、映射 key 补齐、根记录字段序、SHA-256、反向链首值、出生序号计数）对不对，由 gap 行交给决策，装置不判。
4. 主臂里根槽持久的状态只有 4 个，且都是前两段全持久之后的——oracle 对主臂的判别力只由阳性对照证明，主臂自己没有一个「险些出事」的状态。
5. 装置是一份代码写 mkfs、事务、恢复三边，不是 D13（验证路线） 已定项 5 要的「实现与 checker 各写一份」；它证明的是字节表写得出、读得回，不是任何一条不变量。
