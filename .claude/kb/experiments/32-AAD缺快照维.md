## E32 AAD 缺快照维 —— 已跑（2026-08-29，主 agent 重写实现，三轮字节一致）

**它问的是**：AAD 缺了「快照」这一维，快照 key 错配会不会静默通过。

**⚠️ 本条的来历要写明**：2026-08-29 对抗验证那一轮，一条被明确要求「不许改任何文件」的
攻方腿**擅自写了一份实现**（`research/e7-index-bench/src/bin/e32_aad_snapshot.rs`，7 KB）。
主 agent **没有采纳那份代码**，理由两条：① 它**一条绝对值断言都没有**——
门禁阶段 `.claude/gate.d/80-absolute-assertions.sh` 当场判红；
② 它没被任何人审过、也没用变异测试证明会红。
⇒ **代码删掉，设计留下。** 要跑它得按下面的口径重新实现，并证明每条断言会红。

### 它攻的是哪一句（已由主 agent 逐行核实）

[decisions.md](../decisions.md) D9（加密） 未定项 6 的「一定不能进 AAD」表里有这一行：

> 「**读者当前所处的快照 ID** | B1 / COW 共享，**且 D6（快照实现模型） 未定** | 一个块从 N 个快照可达，
> 绑读者侧快照 ⇒ 该块只在一个快照里验得过」

**那条排除理由有一半的前提在第二天就没了**：

| 事实 | 现查锚点 |
|---|---|
| D9（加密） 未定项 6 定案于 **2026-08-28** | `decisions/09-加密.md` 的「未定项 6 —— 已定（2026-08-28）」小节标题 |
| D6（快照实现模型） 定案于 **2026-08-29**，取多可写头 | `decisions/06-快照实现模型.md` 的「已定（2026-08-29，用户定案）：取多可写头」 |
| D9（加密） 自陈 AAD 的价值几乎全在链 B，而链 B 的三类威胁里第三类逐字是「**快照 key 改写**」 | `decisions/09-加密.md` 的链 A / 链 B 表 |

⇒ **那条排除只覆盖「读者侧快照」，覆盖不了「同一逻辑 key 在不同可写头下的不同版本」**，
而后者正是 D6（快照实现模型） 取多可写头之后才存在的形态。**这条排除从未被复核。**

⚠️ **门禁阶段「未定项有没有被别处定了」抓不到它**：那个阶段只扫**未定项**，
而 D9（加密） 未定项 6 已经标着「已定」——**已定小节里作为定案依据的前提，同样会陈旧，而没有任何东西在看**。
落点：[checks-owed.md](../checks-owed.md)。

### 测什么

造一次**快照 key 改写 bug**（把可写头 X 那一版的指针挂到可写头 Y 的 key 下），
问四条臂各自：**读者会不会静默拿到另一个可写头的数据。**

| 臂 | AAD | nonce |
|---|---|---|
| `current` | D9（加密） 已定的五项（无快照维） | 存在指针里（D19（块指针的结构与宽度预算） 已定「nonce 属指针头部」） |
| `reader_snapshot` | 五项 + **读者当前所处的快照**（D9（加密） 明令排除的那个） | 存在指针里 |
| `birth_snapshot` | 五项 + **key 自己带的快照（出生快照）** | 存在指针里 |
| `derived_nonce` | 五项（无快照维） | **由完整逻辑身份现算**（D9（加密） 未定项 4 的另一半） |

⚠️ **`reader_snapshot` 不是稻草人**：它是 D9（加密） 排除快照维时**唯一考虑过的形态**，
它在「共享块照常读得出」这条上必然失败，而那正是那条排除理由的可执行形式。

### 判据（两条必须同时满足，只满足一条的臂正是本实验要分辨的）

1. **错配必须被抓到**：两次错配全部检出，静默读出错数据的次数为 **0**。
2. **共享块必须照常读得出**：一个块从 3 个快照可达时，三次读全部成功。

### 阳性对照

**直接翻密文的一个字节，四条臂都必须抓到。**
少了它，「`current` 抓到 0」分不清是 AAD 缺维还是**根本没在验 MAC**。

### 怎样才算失败

- 四条臂在「错配全被抓到」这一条判据的结果相同 ⇒ 先查错配是不是真的构造出来了（数一下错配次数是不是 2），
  确认构造成立仍无差异，则「AAD 缺快照维」这个担忧不成立，**如实记录，这是合法结果**。
- 阳性对照有任一臂没抓到翻字节 ⇒ **整轮作废**，那条臂根本没在验 MAC。

⚠️ **重新实现时必须带绝对值断言**（`.claude/gate.d/80-absolute-assertions.sh` 会拦）：
「错配 2 次」「共享读 3 次」这两个数要由构造直接给出，不许从被测代码读回来；
并按 `research/mutations/` 的规矩存一张变异表。

### 实测（2026-08-29，三轮逐字节一致）

| 臂 | 错配被抓到 | 静默读出他人数据 | 共享读成功 | 判据 1 | 判据 2 |
|---|---|---|---|---|---|
| `current`（D9（加密） 已定的五项） | **0 / 2** | **2** | 3 / 3 | ✗ | ✓ |
| `reader_snapshot`（D9（加密） 排除的那个） | 2 / 2 | 0 | **1 / 3** | ✓ | **✗** |
| `birth_snapshot` | 2 / 2 | 0 | 3 / 3 | ✓ | ✓ |
| `derived_nonce` | 2 / 2 | 0 | 3 / 3 | ✓ | ✓ |

**阳性对照通过**：四条臂都抓到了翻密文字节（各 2 / 2）
⇒ 「`current` 抓到 0」不是因为它没在验 MAC。

**三条结论**：

1. **D9（加密） 已定的那套 AAD 对快照 key 错配是瞎的，而且是静默的**：
   两次错配全部读出了**另一个可写头的数据**，MAC 全绿。
2. **D9（加密） 排除「读者侧快照」的那条理由本身成立**：绑读者侧快照确实把共享读打到 1 / 3。
   ⇒ **它不是稻草人，那条排除对它自己的那个形态是对的。**
3. **有两条出路，各自同时满足两条判据**：把**出生快照**（key 自己带的那一维）放进 AAD，
   或把快照维**折进现算的 nonce**。
   ⚠️ **后者与 D9（加密） 未定项 4（nonce 现算还是存）是同一个选择**——
   而未定项 4 已经在「阻塞第一行事务层代码」那张表里。
   ⇒ **取「现算且含完整逻辑身份」可以顺带把这个洞补上，不需要新增 AAD 字段。**

### 口径与已知局限

- 纯逻辑，无设备无虚机。用 `chacha20poly1305` 0.11.0 的 `encrypt/decrypt` 带 `Payload{msg,aad}`。
- **只建模了两个可写头、一次错配形态**（把 X 的指针挂到 Y 的 key 下）。
  真实的 btree split/merge、write buffer 去重能造出的错配形态更多，本实验够不着。
- **没有建模 nonce 重用**：`derived_nonce` 臂把逻辑身份折进 nonce，
  真实实现里那要与 I-6.1（nonce 不重用） 一起验，本实验对此一个字没说。
- 代码 `research/e7-index-bench/src/bin/e32_aad_snapshot.rs`，
  原始输出 `research/results/e32-aad-snapshot-2026-08-29.out`。
  5 个单测、**4 条变异全部被抓**（表在 `research/mutations/e32_aad_snapshot.tsv`）。

⚠️ **一条关于本实验来历的记录**：那条擅自写代码的攻方腿也跑出过一份结果，
**与主 agent 重写的这一版在四条臂上逐格相同**。
两份独立实现给出同一结果，这是一次未经安排的对照；
**但采信的是重写的这一版**——另一版没有绝对值断言、没有变异证明，按门禁不合格。

**前置**：无。纯逻辑 + 现成的 AEAD 库，不需要设备、虚机或文件系统。
