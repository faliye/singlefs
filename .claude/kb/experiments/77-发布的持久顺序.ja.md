## E77 発行の永続順序 —— 実行済み (2026-09-02、クラッシュ部分集合全数検査モデル、単体テスト 18 件 / ミューテーション 8 件全捕捉)：**必要なバリアは正確に1本 (ルートスロット直前)、かつ再生適用前に指定ユニットの検証が必須**

[中文](77-发布的持久顺序.md) · [English](77-发布的持久顺序.en.md) · **日本語**

1回のパブリッシュは3種類のエンティティを書き込む：COW ユニット、journal レコード、ルートスロット。それらの間の永続化順序はリポジトリ全体でわずか2文の演繹にとどまり
(D25 (対象ワークロード優先度) は「これは演繹であり実測ではない」と告白；D23 (journal の役割とフォーマット)「既にディスクに書き込まれた」
は発行済みか永続化済みかを明示せず)、レコードとルートスロット間、ユニットとレコード間の順序は**カバレッジゼロ**であった (grep にて確認)。
E77 (発行の永続順序) は4種のバリア配置下における全クラッシュ部分集合を全数検査した。

### 判定基準 (実行前ソースコード先頭にハードコード、実行後未改変)

1. 違反 = ルートスロットが永続化済みだがリカバリ ≠ 新状態または走査失敗；あるいは一部のトランザクションのみ復元；あるいはチェックサム失敗ユニットの接合。
   ルートスロット未永続化時は新旧両状態ともに正当 (fsync 未復帰)。
2. クラッシュ状態数は閉形式と一致しなければならない (b_all 72 / b_ur 79 / b_rs 513 / b_none 1024)、計数ミスはラウンド全体を無効化。
3. 陽性対照：指定ユニットを検証しない再生 (naive) は b_rs において違反が正確に 63 (= 2⁶ − 1) でなければならず、赤とならない場合は無効化。
4. どのバリアが必要かは数値によって決定され、予断を持たない。

### 実測 (モデル：6 ユニット + 同一トランザクションのレコード 3 件 (末尾にコミットマーカー) + 1 ルートスロット；セグメント内任意部分集合永続化)

| 腕 (バリア配置) | 状態数 | 違反 (検証付き再生) | 違反 (naive 再生) | レコードストリームの空洞 |
|---|---|---|---|---|
| b_all [ユニット][レコード][ルートスロット] | 72 | **0** | 0 | 0 |
| b_ur [ユニット][レコード+ルートスロット] | 79 | **0** | 0 | **7** |
| b_rs [ユニット+レコード][ルートスロット] | 513 | **0** | **63** | 0 |
| b_none [完全自由] | 1024 | **504** | 567 | 448 |

3つの結論、それぞれが閉形式で固定：

1. **データ整合性に必要なバリアは1本のみ：ルートスロットの直前** (b_rs 違反 0、b_none 違反 504 = ルートスロットが存在しユニットが欠落する
   全組み合わせ)。これは D25 (対象ワークロード優先度) の「fsync ごとに 2 つの永続化ポイント」という演繹をモデルレベルで実証：
   ルートスロット前の 1 回の FLUSH + ルートスロット自体の FUA で十分である。
2. **ユニットとレコードの間にバリアは不要、ただし再生適用前に指定ユニットを項目ごとに検証することが前提**——検証を除去 (naive) すると、
   b_rs 上で即座に 63 箇所の無音接合が発生。⇒ **「レコードが指定する各項目がチェックサムを自前で保持する」(D23 (journal の役割とフォーマット)
   確定項目 17) は単なる飾りではなく、本バリアを省略可能とするための交換条件である**；リカバリパスは実際にそれを検証しなければならない。
3. **レコード → ルートスロットの順序が担保するのはレコードストリームの完全性であり、データではない**：b_ur のデータ違反は 0 であるが、7 状態において
   「ルートスロットが存在するのにレコードが欠落」が発生——レコード照合器と逆方向チェーン (D23 (journal の役割とフォーマット) 確定項目 8) の入力に
   それらの状態で空洞が生じる。このために第2のバリアを支払うべきかは決定事項であり実験ではない。

### 失敗条項 (実行前ハードコード)

判定基準 2、3 ともに合致 (状態数は腕ごとに閉形式と一致；naive は正確に 63)。無効化条項は未トリガー。

### 本実験で答えられない点

純粋な全数列挙モデルであり、ファイル操作は 0 箇所。次の点には回答しない：実デバイスで FLUSH が有効に機能するか (C6 (ブロック層セマンティクスの仮定記述誤り) の射程)、
FUA と FLUSH のコスト、複数発行の交錯とリングラップアラウンド (E78 (再生の起点) の射程)。
「セグメント内任意部分集合永続化」はブロック層のコミットメントの下限モデルである (D20 (耐荷重面：ユニットの原子性と自己完結性)：
「ブロック層は bio が断裂しないことを一切約束したことがない」)。

### 計測条件と再実行

- コード `scripts/experiments/e77_publish_order.rs`
  (`cargo run --release --bin e77-publish-order`)、
  生出力 `e77-publish-order-2026-09-02.out` (12 行、末尾行 `emitted=12`)。
- ランダム性のない全数列挙、5ラウンドで同一 md5。**単体テスト 18 件、ミューテーション 8 件が1件ずつ捕捉、死角 0 件**、
  ミューテーション表 `scripts/mutation/tables/e77_publish_order.tsv`
  (`bash scripts/mutation/mutate.sh e77-publish-order scripts/experiments/e77_publish_order.rs scripts/mutation/tables/e77_publish_order.tsv`)。
- ⚠️ ミューテーションテストによりモデル自体の2つの死角が相次いで検出され修正済み：リカバリ関数の「成功」が自己申告であった点
  (監査と監査対象の同源)、走査の完備性が監査のフォールバックにより覆い隠されていた点——双方が「まず赤となることを証明する」手法により補完された。
