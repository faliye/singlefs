### 世界与臂

计数模型，零文件操作，没有并发。「盘」是落点 → 单元的映射，分配器按 FIFO 复用释放空间（复用即把旧头盖掉，默认概率 50%，靶子世界按需关掉）；释放的落点要再等 2 次发布才进可分配集合（defer 窗口，回退用）。实例表行是三段 (实例代号, 所选根的 txg T_pub, 从所选根的 tail 起连续重放施加的最大事务号 W)：崩溃行 = (i, 所选根 txg, W)——恢复恒选最新可读的根，所以通常是在飞 txg − 1，最新根的槽坏了就退一格；回退行 = (r_old, T_old, 0)，中间实例 = (i, 0, 0)。谓词按单元类分（第七版 P2）：数据单元 b ≤ T_pub ∨ n ≤ W；容器只在 checkpoint 的固定点写出，b ≤ T_pub。W 是前缀：记录按事务号顺序追加，一个事务在发出单元写之后失败即实例切换，号更大的记录一条都不追加。
真值由生成器在每个根发布那一刻记下，不经过任何重建代码。码 3 容器的头里只有出生树，模型不给重建多于头里有的信息（写者树 = 出生树）。

| 世界 | 造什么 |

| crash_clean | 在飞 txg 里三个事务全部被抛弃、一个都没被重放（整个 txg 烧得掉的那一格） |

| rollback | 四个对象、覆写两个、再建三个并发布，然后管理员回退到上一个根（第三版的定义：不施加该根之后的记录、实例代号 +1、写回退行 (r_old, T_old, ∞)），再建一个对象；模型带 2 次发布的 defer 窗口，回退时丢掉被抛弃时间线的 defer |

| merge | 六个 inode 分两片叶，删到左半剩一条、右半剩一条触发合并（右退役），再删掉从右半吸收来的那条 |
| mixed / mixed_gate_v1 | 60 轮随机：覆写 / 删除 / 快照 / 克隆（≤ 4 头）/ 崩溃（15% 每轮，其中 20% 连崩）/ 回收 / scrub 全开 |

臂：`oracle`（真值 alloc 当 `live`，阳性对照）、`full`（P1–P6 全上）、九条消融 `no_wseq` / `no_watermark` / `no_ancestry` / `no_death_wseq` / `no_retire` / `tie_unit_wins`（写序相等时单元赢而不是墓碑赢）/ `inst_only`（头里只有 4 字节实例代号、没有计数器，水位只能说「实例 i 发布到了 txg T、在飞 txg 有没有被部分重放」）/ `no_replica_merge`（不先把同一逻辑版本的副本归并成一个候选）/ `wseq_meta_only`（第四轮的对立臂 B：写序只上码 3 容器，数据单元头只有诞生代号，数据单元按「诞生代号 ≤ 根 txg」判已发布、同 key 多版按诞生代号择新）。

第三轮之后模型按第四版规则重建了三样：**副本归并**（同 key、写者树、诞生代号、写序的多份可读单元先归并成一个候选，bcachefs 的 cookie 合并是同一步）；**回退**（管理员回退 = 一次恢复：实例代号 +1、写回退行 (r_old, T_old, ∞) 与中间实例的 (i, 0, 0)、第一个新根的 txg 压过根环里全部根、被抛弃的根留在环里、defer 与分配记录从旧根重载）；**清扫准入按规则不按真值**（分配记录条目释放时不删而改成「已释放 + 释放代」，清扫只清释放代 ≤ 根环最旧根 txg 的落点，孤儿按实例表判未发布才清，清扫水位只推进到根环最旧根的 txg；真值版本只留作单测对照：规则清掉的 ⊆ 真值清掉的，且从不碰根环任一根引用的落点）。

### 判据（跑前写死，写在提案 P8，跑完没改）

1. 全规则臂对全部根、全部种子：错版本 = 复活 = 判死实活 = 歧义 = 0；任一非 0 ⇒ 提案不完整，记下是哪一类世界。
2. 每条消融臂在它的靶子世界上 > 0，数值钉闭式，闭式由生成器独立计数。
3. 神谕臂恒 0；扫到的单元数 ≠ 生成器记的（写出 − 被盖掉 − 被抹掉）⇒ 整轮作废；注入 k 处破坏必须报出恰 k。
4. 全规则臂非 0 而消融臂也非 0 ⇒ 缺的构件不在六个之内，提案回到靶子重画。

- 第四轮的对立臂 B（`wseq_meta_only`）：数据单元头里没有实例代号与事务号，实例表的上限对它没有输入 ⇒ 崩溃 / 回退各世界的数据孤儿全部复活（与 no_watermark 逐格相同），同 txg 世界歧义 4 + 复活 1；不崩溃、不回退、没有同 txg 多版的世界上 0。单测 `arm_b_residual_is_pinned` 钉住崩溃世界的复活数 = 被抛弃单元数 × 根数、同 txg 的歧义 = (覆写次数 − 1) + 两对。

### 它答不了的

**模型比提案宽松的地方（第二、三、五轮反推腿逐处点名，这些格子上「全规则臂 0」不构成证据）**：事务级失败只建了「发出单元写之后失败 ⇒ 实例结束」一种，没有单副本失败换落点重试（写序不变，对判定无影响）、取号后写单元前的作废只留洞不建；容器按事务写不按固定点写（比实物多出中间版本，写序 n 取事务号；判定只用实例代号与诞生代号，择版本取写序最大者等价于取固定点那一版，多出来的版本不改结论——第七版 I-1.8（归并后版本全序） 对码 3 的全序键 (诞生代号, 实例代号) 在模型里没有单独建）；恢复选非最新根只建了「之后的记录不可重放」那一格，不建「记录可重放、跨两个 checkpoint 重放」；模型没有设备、没有写失败、没有超级块 ⇒ 失败表两支的判别子（探针写）、收敛论证（取号全或无）、实例切换整条路径、可写挂载的过半独占与取号全或无一格都没建；墓碑回收门在模型里是**按 key** 判的，而 D18（块里携带什么信息） 已定项 10 问的是「还有没有根引用那个死掉的版本」——两者在「先删后重建」上就分岔（同一个 key 既有 kill 记录、又被本头引用着新版本）⇒ **模型分不出这条门的新旧量词**，那条变异抓不住、已从表里删掉（第八轮反推腿 14.1）；模型没有 journal ⇒ 回退行不许被覆盖与重放下界遇回退行截断这两条规则实现了但没有能分辨它们的世界（C124（回退行与重放下界没有会红的检查））；码 3 的择新键是 (诞生代号, 实例代号, 事务号) 三元——第八轮反推腿 8.1 指出二元键押在一句没有可判红形态的前提上（「一个实例在一个 checkpoint 只有一个固定点」，而失败表自己写着固定点会「收敛不了」即会迭代），第九版把规则也改成三元，模型与规则由此是同一个键；清扫在两次发布之间跑，没有在飞 overlay；行回收的「全部设备在线」与清扫准入的「头可读」在模型里恒真（没有设备概念、没有损坏注入，第六轮 Sonnet 审计点名）；清扫瞬间完成（准入已按第四版规则建，但整轮一次做完、没有可续做的中途状态）；实例表永久、不会坏、没有载体；一个事务恒等于一个计数器，不建跨多条记录的事务，也不建 checkpoint 切分等齐事务那一步；回退最多退两代、根环深度取 4；副本恒逐字节相同，不建载荷撕裂；码 3 的头里只有出生树这一处是严格的；臂 B 只建了「数据单元头没有写序」这一格，不建码 2 节点、也不建 extent 叶仍在时顺着 extent 树到达数据的路径——它量的是 extent 叶丢失时数据单元靠自己的头能不能判，不是完整的臂 B。

计数模型，文件操作 0 处。不回答：写序进头之后各实验常量怎么变（C89（单元头收口的遗留重算） 形态的重算）；实例水位表住记账树时与 D5（快照 / 空间记账机制） 已定项 2 的 K 代点删怎么共存（模型里它是一张永久的表）；
