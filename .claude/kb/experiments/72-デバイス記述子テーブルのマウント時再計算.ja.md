## E72 デバイス記述子テーブルのマウント時再計算 —— 実行済み (2026-09-02、**真の異種 loop プール**、N=5 ラウンド × 2 回呼び出しで判定一致)：**4つの比較項目すべてで強制的に赤と判定可能、表外の計測量は赤と判定せず**

[中文](72-设备描述符表的挂载复算.md) · [English](72-mount-time-recalculation-of-device-descriptor-table.en.md) · **日本語**

D12 (対象メディア) 確定項目 3 はデバイスレベルの幾何学的数値をシステム構成のデバイス記述子テーブルに定め、
D12 (対象メディア) 確定項目 4 は照合規則を定め「**すべての項目がテストによって強制的に『不一致』分岐に入り得ること**——
決して赤にならない照合項目と照合項目が存在しないことは、マウントログ上まったく同一に見える」と一字一句要求している。

### 判定基準 (実行前ハードコード、実行後未改変)

1. **絶対値アサーション**：テーブルのバイト数は正確に `デバイス数 × デバイスあたりエントリ幅` に等しくなければならず、傾向の観察のみで済ませてはならない。
2. 再計算所要時間はデバイス数に対して**線形**；超線形が現れた場合は「再計算に O(デバイス²) の照合が混入した」と判定。
3. **すべての比較項目が強制的に「不一致」分岐に入り得ること。**

### 失敗条項 (実行前ハードコード)

| 条項 | 判定 |
|---|---|
| **陽性対照**：1台のデバイスの幾何フィールドを改ざんした場合、再計算は赤と判定しなければならない | **合格** (4項目それぞれ個別に赤と判定、「判定基準 3 + 陽性対照：4つの比較項目が1項目ずつ強制的に赤と判定」を参照) |
| **全比較項目が同種プールでのみ検証されていた場合、ラウンド全体を無効化** | **未トリガー**：全シナリオが**真の異種プール** (`pbs_mix=4096,512`) 上で実行 |

### 実測

#### 判定基準 3 + 陽性対照：4つの比較項目が1項目ずつ強制的に赤と判定

プールは4台の真の loop デバイスであり、`losetup --sector-size` により **`physical_block_size` 512 と 4096 の混在** を構築。
「改ざん」はすべて**実質的手段**で実施——セクタサイズ変更再マウント、`truncate` による容量変更、デバイス順序入替、テーブル内レイアウトビット変更。

| シナリオ | 改ざん方法 | pbs | 容量 | 識別情報 | レイアウト | 処置 |
|---|---|---|---|---|---|---|
| 陰性対照：一切変更なし | — | ok | ok | ok | ok | **allow** |
| 強制 pbs 不一致 | 1号ディスク 4096 → 512 再マウント | **mismatch** | ok | ok | ok | **refuse_rw** |
| 強制容量縮小 | `truncate` で半減後に再マウント | ok | **shrunk** | ok | ok | **refuse** |
| 強制容量拡大 | `truncate` で倍増後に再マウント | ok | **grown** | ok | ok | **allow_and_note** |
| 強制識別情報不一致 | 2台のディスク順序を入替、テーブル不変 | ok | ok | **mismatch** | ok | **refuse** |
| 強制未認識レイアウトビット | テーブル内特定ディスクの layout ビットを 2 に変更 | ok | ok | ok | **mismatch** | **refuse** |
| **表外の計測量が変化** | `blockdev --setra` で先読み変更 | ok | ok | ok | ok | **allow** |

⇒ **4つの比較項目がそれぞれ単独で強制的に赤と判定され、かつ各回でその項目のみが赤となった**——
相互の干渉がないことは、これらが包括的な「何かがおかしい」ではなく、それぞれの計測量を確実に判定していることを示す。
⇒ **処置もセル単位で D12 (対象メディア) 確定項目 4 に合致**：pbs は `refuse_rw` (**書き込み可能**マウントを拒否し、マウント自体は拒否しない)、
容量拡大は `allow_and_note` (許可して記録)、残りは `refuse`。

⚠️ **最終行は本表において2番目に重要な行である**：D12 (対象メディア) 確定項目 4 は
「目録外のもの：回転数、キュー深度、`io_opt`、discard サポート……これらを照合することはマウント不能という偽陽性の赤を生むだけである」と明記。
先読み変更後も再計算は**同様に通過** ⇒ **「照合しない」規則も判別力を有しており**、単なる姿勢表明ではない。

#### 判定基準 1：テーブルのバイト数

| デバイス数 | エントリ数 | 24 B/エントリ | **40 B/エントリ** | 64 B/エントリ |
|---|---|---|---|---|
| 2 | 2 | 48 | **80** | 128 |
| 4 | 4 | 96 | **160** | 256 |
| 8 | 8 | 192 | **320** | 512 |

⇒ 正確に `デバイス数 × エントリ幅` となり、3段階の幅すべてで成立。
⚠️ **エントリ幅はリポジトリ内で未定** ⇒ 40 バイト (dev_uuid 16 + pbs 4 + lbs 4 + 容量 8 + レイアウトビット 8) は**仮定**であり、
他の2段階も併せて提示し、**特定の段階のバイト数を結論としてはならない**。

#### 判定基準 2：再計算所要時間は線形、O(デバイス²) なし

| デバイス数 | 再計算総所要時間 | デバイスあたり |
|---|---|---|
| 2 | 26.0 ms | 13.02 ms |
| 4 | 50.5 ms | 12.63 ms |
| 8 | 99.8 ms | 12.48 ms |

⇒ デバイスあたり所要時間は**平坦ないし微減** (固定オーバーヘッドの償却) ⇒ **線形であり、判定基準 2 は成立**、二次項は存在しない。

⚠️ **その 12.5 ms は harness のオーバーヘッドであり、マウント所要時間の予測値ではない。** その大半はデバイスあたり2回の
`sudo` (`blockdev --getsize64` および `losetup -O BACK-FILE`) によるプロセス起動コストである。
**線形という結論は成立するが、絶対値を実マウントパスに外挿してはならない。**

### 本実験で答えられない半面

1. **マウントパス自体が存在しない** (システム構成なし、実装なし) ⇒ ここで実装されたのは D12 (対象メディア) 確定項目 4 の**規則**であり、
   検証されたのは**規則内の各照合項目に判別力があるか**であって、「本プロジェクトのマウントコードが正しいか」**ではない**。
   コード実装後に同一のシナリオ群を用いて再検証を要する。
2. **異機種性は `physical_block_size` の次元のみ** (512 / 4096)。
   真の異種プールにはメディア種別、ストライプ幾何、レイアウトの差異も存在する——それらには QEMU を要し
   (E15 (異種デバイス幾何シミュレーションの成立性) でゲストが識別可能な異種幾何が作成可能と証明済み)、E72 (デバイス記述子テーブルのマウント時再計算) 本文を産出したラウンドでは未実施。
3. **デバイス識別情報は backing ファイル名を代理として使用**し、真の UUID ではない——真の実装はデバイス上に識別フィールドを書き込み読み戻す。
   不一致パスは検証されたが、**識別フィールド自体のディスク配置方法は未検証**。
4. **テーブルのエントリ幅、dev_uuid 幅は仮定** (E71 (記帳キーのエントリ数と幅) / E73 (ノードキー区間のファンアウトコスト) と同一の未済の検査)。
5. **「テーブル自体の破損」は未検証**：テーブルのチェックサム、テーブルの原子ユニットまたぎ、テーブルとルートの整合性は一切触れていない。
6. **複数照合項目が同時に不一致となるパスは未通過**：各シナリオで1項目のみ改ざん。
   処置関数における優先順位 (`refuse` は `refuse_rw` より厳格) は D12 (対象メディア) 確定項目 4 に沿って正しく記述されているが、
   **いかなるシナリオでも未検証**——「pbs 変化かつ容量縮小」等の複合シナリオを構築して検証を要する。

### 前提条件

`sudo` を要する (パスワードは `.env` 経由、準備済み)。異種環境は `losetup --sector-size` に依存し、QEMU は不要。

### 計測条件と再実行

- スクリプト `scripts/devices/e72-devtable-probe.sh` (`bash scripts/devices/e72-devtable-probe.sh`、`sudo` 要)、
  生出力 `e72-devtable-probe-2026-09-02.out` (40 行、末尾行 `emitted=40`)。
- 16 MiB の loop デバイス 4 台、偶数番号 `--sector-size 512`、奇数番号 `4096`；イメージは `TMPDIR` に配置、
  EXIT 時にリテラル名で `losetup -d`。
- ⚠️ **再実行はバイト単位の突合ではない**：所要時間フィールドを含むため ⇒ 実行ごとに異なる。
  **判定基準は7つのシナリオの処置パターン** (4項目それぞれ赤と判定、表外の計測量は許可、陰性対照は許可) であり、
  2回の完全呼び出し計 10 ラウンドで一致。
