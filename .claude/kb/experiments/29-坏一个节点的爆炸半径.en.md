## E29 Blast Radius of a Single Failed Node — Run (2026-08-29)

[中文](29-坏一个节点的爆炸半径.md) · **English** · [日本語](29-坏一个节点的爆炸半径.ja.md)

**Clears the modelable half among [experiments.md](../experiments.md) E1 (Node Size vs Recoverability).**

### First Correct the Criteria of E1 (Node Size vs Recoverability): It Contradicts D21 (Boundary Between Authoritative and Derived States)

E29 (Blast Radius of a Single Failed Node) originally stated "the blast radius of a single failed node scales linearly with node size, **directly conflicting with the rebuildability goal of this project**",
using the criterion "full disk scan rebuild **success rate** ≥ target line".
However, D21 (Boundary Between Authoritative and Derived States) settled that **indexes are derived state, and "losing them is merely slow"**.
⇒ Indexes can be rebuilt from unit self-description (E28 (Can Plaintext Mapping Layer Rebuild Solely from Unit Self-description) empirically confirmed on metadata side)
⇒ **A corrupted index node causes zero permanent loss, only rebuild time. "Success rate" measures the wrong thing; rebuild cost should be measured instead.**

### Measured Results (16 Million Leaves, 40-Byte Pointers, Byte-identical across Three Rounds)

| Node | Fanout | Tree Height | Re-scanned on Level 1 Node Failure | Re-scanned on Root Failure | Permanent Loss from Corrupted Index | Permanent Loss from Corrupted Unit |
|---|---|---|---|---|---|---|
| 2 KiB | 49 | 5 | **49** | All 16,777,216 | **0** | 1 |
| 4 KiB | 100 | 4 | **100** | All | **0** | 1 |
| 16 KiB | 408 | 3 | **408** | All | **0** | 1 |
| 64 KiB | 1636 | 3 | **1636** | All | **0** | 1 |

**Three Conclusions**:

1. **Permanent loss from corrupted index is constant 0**, independent of node size—a direct corollary of D21 (Boundary Between Authoritative and Derived States), holding in the model.
2. **Loss from corrupted unit is also independent of node size** (a unit is a unit)
   ⇒ **the "loss range scales linearly with node size" in E29 (Blast Radius of a Single Failed Node) original text cannot possibly refer to data**.
3. **What truly scales with node size is re-scanning cost**: re-scan volume for Level 1 nodes **exactly equals fanout**,
   surging 33× from 49 at 2 KiB to 1636 at 64 KiB. **Root failure always requires full disk scan**, independent of node size.

⇒ **Node size trades "recovery time", not "data safety".** The target line of E29 (Blast Radius of a Single Failed Node) should be placed on recovery time.

### Measurement Basis and Known Limitations

- Pure arithmetic model. **Does not model how much I/O scanning a unit requires**, only counting unit tallies.
- **Premised on index rebuildability**, which did not hold on data blocks on 2026-08-29 (measured in E28 (Can Plaintext Mapping Layer Rebuild Solely from Unit Self-description)).
- Code `scripts/experiments/e29_blast_radius.rs` (`cargo run --release --bin e29_blast_radius`),
  raw output `e29-blast-radius-2026-08-29.out`. Three rounds byte-identical.
- 7 unit tests, all 6 mutations caught. ⚠️ One fanout blind spot caught by mutation testing:
  six tests all routed through the same fanout function, so dividing the formula by 2 turned zero tests red—added an absolute assertion with independent arithmetic.
