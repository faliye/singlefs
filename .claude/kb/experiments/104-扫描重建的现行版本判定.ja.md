### 世界と腕

カウントモデル、ファイル操作ゼロ、並行性なし。「ディスク」は配置先 → ユニットのマップであり、アロケータは FIFO で解放領域を再利用（再利用時は古いヘッダを上書き、デフォルト確率 50%、標的世界では必要に応じて無効化）；解放された配置先はさらに 2 回のパブリッシュを待ってから割り当て可能集合に入る（ロールバック用 defer ウィンドウ）。インスタンス表の行は 3 つのセグメント (インスタンスコード, 選択されたルートの txg T_pub, 選択されたルートの tail から連続再生適用された最大トランザクション番号 W)：クラッシュ行 = (i, 選択されたルート txg, W) —— リカバリは常に読み取り可能な最新ルートを選択するため、通常はインフライト txg − 1、最新ルートのスロット破損時は 1 段後退；ロールバック行 = (r_old, T_old, 0)、中間インスタンス = (i, 0, 0)。述語はユニット分類ごとに分かれる (第 7 版 P2)：データユニット b ≤ T_pub ∨ n ≤ W；コンテナはチェックポイントの固定点でのみ書き出され、b ≤ T_pub。W はプレフィックス：レコードはトランザクション番号順に追加され、ユニット書き込み発行後にトランザクションが失敗した場合はインスタンス切り替えとなり、より大きな番号のレコードは 1 件も追加されない。
真値は各ルートがパブリッシュされた瞬間にジェネレータによって記録され、再構築コードを一切通過しない。コード 3 コンテナのヘッダには誕生木のみが存在し、モデルは再構築に対してヘッダにある以上の情報を与えない (書き手木 = 誕生木)。

第 3 ラウンド以降、モデルは第 4 版のルールに従い 3 要素を再構築した：**レプリカマージ**（同一キー、書き手木、誕生世代、書き込み順序を持つ複数の読み取り可能ユニットを事前に 1 つの候補にマージ、bcachefs の cookie マージと同一ステップ）；**ロールバック**（管理者ロールバック = 1 回のリカバリ：インスタンスコード +1、ロールバック行 (r_old, T_old, ∞) と中間インスタンスの (i, 0, 0) を書き込み、最初の新規ルートの txg はルートリング内の全ルートを上書き、放棄されたルートはリング内に残留、defer と割り当てレコードは古いルートからリロード）；**スクラブ受入は真値ではなくルールに従う**（割り当てレコードのエントリは解放時に削除せず「解放済み＋解放世代」に変更、スクラブは解放世代 ≤ ルートリング最古ルート txg の配置先のみを消去、孤児はインスタンス表により未パブリッシュと判定された場合のみ消去、スクラブ水位はルートリング最古ルートの txg までのみ前進；真値版は単体テストの対照としてのみ保持：ルールで消去されたもの ⊆ 真値で消去されたもの、かつルートリングの任意のルートが参照する配置先には一切触れない）。

### 判定基準 (実行前に確定、提案 P8 に記載、実行後の変更なし)

1. 全ルール腕は全ルート、全シードにおいて：バージョンの誤り = 復活 = 死者判定だが実際は生存 = 曖昧性 = 0；いずれかが非 0 ⇒ 提案は不完全、どの世界クラスであるかを記録。
2. 各切除腕はその標的世界において > 0、数値は閉形式に固定、閉形式はジェネレータが独立カウント。
3. 神託腕は恒常的に 0；スキャンされたユニット数 ≠ ジェネレータ記録 (書き出し − 上書き − 抹消) ⇒ ラウンド全体を無効化；k 箇所の破壊注入に対して正確に k 箇所を報告しなければならない。
4. 全ルール腕が非 0 であり切除腕も非 0 ⇒ 不足している構成要素が 6 要素の範囲外、提案を標的に戻して再設計。

### 実測 (2026-09-05、5 ラウンド同一 md5、成果物 830 行、`emitted=830`)
