## E56 Message Buffer Gains vs Epsilon — Run (2026-08-31 Round 4, N=5; Rounds 1–3 Aborted Due to Harness Defects)

[中文](56-消息缓冲的收益vsε.md) · **English** · [日本語](56-消息缓冲的收益vsε.ja.md)

**Asks directly about the figure in D11 (Message Buffers in Index Nodes): on 16 KiB nodes pinned by D8 (Core Index Structure) settled item 2,
how much marginal gain remains for reserving a message buffer inside internal nodes, relative to D8 (Core Index Structure) current direction (log-structured nodes + write buffer frontend).**

### Why the 3.22× of E7 (Offline Index Harness) Cannot Answer This Question

In the Bε arm of E7 (Offline Index Harness), **buffer capacity and fanout were two mutually independent free parameters**—
in `scripts/experiments/e7_index.rs`, `message_buffer_capacity = 200` (constant), `FANOUT = 32` (constant);
internal nodes only held messages, **holding no pivots**, and the two never competed for the same node bytes.
In real Bε internal nodes, however, they **must compete for the same node bytes**: more pivots yield larger fanout, shorter tree, and cheaper queries;
more buffer allows one flush to amortize across more messages and cheaper updates. **This tension is the entire mechanism of Bε; E7 (Offline Index Harness) decoupled it.**

⇒ Two consequences, both being reasons why E7 (Offline Index Harness) figures cannot be used directly to settle D11 (Message Buffers in Index Nodes):

| Consequence | Explanation |
|---|---|
| **Node size scan across three tiers in E7 (Offline Index Harness) is not comparable** | Buffer fixed at 200 items × 16 bytes = 3200 bytes, while nodes grew from 4 KiB to 64 KiB ⇒ buffer fraction fell steadily across **0.78 / 0.195 / 0.049**. In that table, "node size" and "ε" are two variables changing simultaneously |
| **3.22× is "a single point on a particular ε"** | It is not "Bε gain at 16 KiB", but "gain when ε≈0.20, fanout 32, and internal nodes are 99% empty" |

### Why Run

D8 (Core Index Structure) settled item 2 (2026-08-30 user settlement) pinned nodes to a **16 KiB constant** ⇒
the "node size target line" required by D11 (Message Buffers in Index Nodes) prerequisite 4 has a value.
Gains thus collapse from a family of numbers into a single curve: **given 16 KiB, gain is purely a function of ε.**

### What to Measure

**Sole independent variable ε = proportion of internal node bytes allocated to message buffer.** All others derived from it:

| Quantity | Formula | Source |
|---|---|---|
| Node bytes `S` | 16384 | D8 (Core Index Structure) settled item 2 |
| Pivot item `P` | 8 (key) + 40 (pointer header) = **48 bytes** | D19 (Block Pointer Structure & Width Budget); E20 (CPU Cache Cost of Wider Pointers) also uses 40-byte header |
| Message item `M` | 8 (key) + 8 (value) = **16 bytes** | Same measurement basis as E7 (Offline Index Harness), making numbers across two experiments comparable |
| Fanout `F(ε)` | `floor(S × (1−ε) / P)` | |
| Buffer capacity `B(ε)` | `floor(S × ε / M)` | |
| Internal levels `H(ε)` | Levels required bottom-up to converge to single root per `F` | Small fanout ⇒ tall tree ⇒ expensive queries; **this is the cost side of ε** |

**Measuring four metrics**: update io/op, update bytes/op, **hot key** point lookup reads/op, and **cold key** point lookup reads/op.

⚠️ **The cold key column is the cell E7 (Offline Index Harness) confessed it did not measure**: in E7 (Offline Index Harness), query and update shared the same distribution,
so recently updated keys had high probability of residing in cached root/internal buffers, skipping leaf reads;
**point lookup column was thus counterintuitively favorable to Bε**. E56 (Message Buffer Gains vs Epsilon) sets aside a distinct column for "keys never touched during update phase".

### Analytical Predictions Hardcoded Before Run

One flush pushes `B` messages to at most `min(B, F)` children ⇒ **each message pays `min(1, F/B)` node touches per level**,
summing across `H` levels:

> **`touch_per_op = H(ε) × min(1, F(ε)/B(ε))`**

From this, two **written before run and falsifiable** predictions were derived:

| # | Prediction | Falsifying It Means |
|---|---|---|
| 1 | Crossover point `B = F` is at **ε = 0.25** (`S·ε/M = S·(1−ε)/P` ⇒ `ε = M/(M+P) = 16/64`). **When ε < 0.25, amortization factor < 1, i.e., message buffer amortizes nothing**, where Bε pays `H` touches per op, worse than 1.5755 of D8 (Core Index Structure) current direction | Either model not computing geometrically, or analysis flawed. **Must investigate both thoroughly before adopting any numbers** |
| 2 | When ε > 0.25, amortization factor `= 3ε/(1−ε)`, cost `= H×(1−ε)/(3ε)`; if ε continues rising, `F` shrinks, `H` grows, **cost does not decrease monotonically** | Either model not computing geometrically, or analysis flawed. **Must investigate both thoroughly before adopting any numbers** |

⚠️ **Prediction 1 and D11 (Message Buffers in Index Nodes) text "if this project takes 16K–32K, messages carried per flush approaches 1, and the gain mechanism of message buffers naturally vanishes at that node size" agree in direction but differ in measurement basis**:
that sentence tied "messages approaching 1" to **node size**, whereas the analytical formula ties it to **ε**—at 16 KiB, when ε is 0.9, amortization factor is 27; when ε is 0.2, it is 0.75.
**What E56 (Message Buffer Gains vs Epsilon) must judge is precisely which of these two bases is correct.**

#### Verdict: Prediction 1 Falsified Empirically, and Variable in D11 (Message Buffers in Index Nodes) Statement Was Also Wrong

| Assertion | Verdict | Basis |
|---|---|---|
| D11 (Message Buffers in Index Nodes) "gain mechanism vanishes naturally at 16K–32K" | **Overthrown** | Gain is a function of ε; at 16 KiB, ε=0.5 gives 2.42×, ε=0.9 gives 17.06×. Node size only determines resolution of ε |
| Prediction 1 "crossover at ε=0.25 (where B=F); when ε<0.25, amortization factor < 1 ⇒ Bε worse" | **Overthrown** | Actual crossover is at **ε≈0.15** (1.01×). Amortization is a **continuous** `(1−e^(−x))/x`; zero amortization occurs at x→0, not x=1; at ε=0.25, amortization factor is already 1−e^(−1)=0.632 |
| Prediction 2 "when ε>0.25, cost ∝ (1−ε)/ε and non-monotonic (H increases)" | **Direction holds, mechanism half wrong** | Across 1024 leaves, tree height is constantly 2 for ε≤0.9, cost decreasing monotonically; tree height increase appears only at ε≥0.8 with 8192 leaves |

**Why it went wrong**: `H×min(1, F/B)` treated amortization as an on/off **switch** of "whether there is enough to amortize", whereas it is a continuous quantity;
furthermore, it omitted the fact that "D8 (Core Index Structure) current direction is itself a point on the same curve"—
write buffer 512 items amortized across 1024 leaves, x=0.5; **it is not a 'no-batching' baseline**,
so where Bε catches up with it is determined by the ratio of their x values, not by B=F.

**Corrected formula comes from forward leg blind prediction** (which had seen no empirical data):

> **`io/op = 2(1 − e^(−x))/x`**, x = messages per flush ÷ children count of node
> Arm A is x→0 (limit 2), Arm B is x = 512/1024 = 0.5 (closed form 1.5739, empirical 1.5737),
> Arm C is x = B/F = 3ε/(1−ε). Break-even point at x=0.5 ⇒ **ε = 1/7 ≈ 0.143** (empirical falls at 0.15).

⇒ **"Whether to retain message buffers" is actually "what x to select"**, and D8 (Core Index Structure) current direction already lies on this curve.
This is pinned in unit test `all_three_arms_lie_on_one_flush_curve`, forbidden to exist only in prose.

#### Steady-State Usable Zone: Criterion Is "Total Buffer Capacity ÷ Workload", Computable Before Run

**In a buffered structure, total buffer capacity can exceed the entire workload**—at that point, what is measured is "cost of stuffing messages into buffer",
not steady-state write amplification; accounts have not come due. Capacity is directly computed from geometry: `Σ node_count_per_level × B`. This project defines **≤25% as usable**.

| | ε≤0.5 | ε=0.65 | ε=0.8 | ε=0.9 | ε=0.95 |
|---|---|---|---|---|---|
| 1024 leaves | ≤2.0% | 3.3% | 7.0% | 14.7% | **32.1% unusable** |
| 8192 leaves | ≤12.8% | 23.3% | **50.8% unusable** | **115.1% unusable** | **249.8% unusable** |

⚠️ **Forbidden to use post-hoc "net residual increase" as criterion**: that quantity is primarily **phase noise**, not net filling.
Parent distributes uniformly to all children ⇒ children fill synchronously, flush synchronously; one snapshot catches the same phase,
amplitude roughly equal to total buffer capacity. In actual measurement on 8192 leaves, ε=0.9, residual jumped from 41,445 to 153,950 (56% difference of workload),
whereas at same configuration ε=0.5 differed by only 1.2%. Placement in [checks-owed.md](../checks-owed.md) C54 (Sampling Before Amortized Structure Reaches Steady State).

### First Two Rounds Aborted: Adversarial Validation Identified Three Silent Defects in Harness (2026-08-31)

**Bε arm io/op across first two rounds was completely aborted and rerun.** Both defects shared the same signature—
**a path quietly doing or computing less at boundaries, making results appear cheaper**, hitting only the Bε arm,
so **invisible when comparing the three arms against one another** (`.claude/singlefs-ai-sop/rules/test-discipline.md`
"merely comparing multiple arms cannot detect 'all arms wrong together'").

| # | Defect | How Detected | Remediation |
|---|---|---|---|
| 1 | `push_down` pushed entire batch of messages into internal buffer at once, while `Node::push` **did nothing** when full ⇒ **messages silently dropped** when buffer filled precisely. Keys in internal buffer stem from entire subtree, duplication rate ~0.09%, compaction vacates almost no slots | **Blind prediction of forward leg**: stated "leaf compaction should trigger 0 times", while measured 15,092–24,290 times. Tracing showed compaction of **internal buffer** was being counted, the exact crime scene of dropped messages | Changed to "flush immediately when full"; internal buffer no longer compacts (emptying handled by flush; compaction belongs only to leaves). Added conservation gate: `messages landing on leaves + buffer residuals == operations`; violation exits with code 7, aborting round |
| 2 | `drain_all` counted residuals while pushing ⇒ missed cases where "upper level draining pushes message into lower level, which overflows immediately and flushes directly to leaf", undercounting residuals | **Conservation gate added for Defect 1 failed on first real run**: `landed_update=199869 residual=109 landed_total=200000`, 22 short | Count residuals before modifying |
