# 欠的检查清单

**本文件放「已经知道要拦什么、但现在还拦不了」的检查。**

与 [invariants.md](invariants.md) 的分界：不变量是**对着一个镜像**可判定的性质，
checker 是它的可执行形式；本文件放的是**代码路径的要求**——
它们对着镜像判不出来，只能由门禁在跑的时候拦。

**写进来的门槛**：说得出「拦什么」「怎么拦会红」「现在缺什么前置」。
三样缺一样就是还没想清楚，先别写
（`singlefs-ai-sop/rules/sop-first.md`：写不出下一步就别加那条检查）。

| # | 要拦什么 | 怎么拦（会红的形态） | 前置 | 出处 |
|---|---|---|---|---|
| C1 | 把「续做未完成的意图」做成可选的修复通道，而不是每次恢复都跑的常规路径 | 崩溃点重放里，任一含未完成意图的镜像正常挂载后没跑续做即判红；恢复路径里不许存在「跳过续做」的分支 | 事务层、意图日志、崩溃点重放 harness | [decisions.md](decisions.md) D8 规则 2 |
| C2 | 无界操作被做成单个事务 | 对 truncate 大文件 / 删大目录量一遍「单个事务的写入量 vs 对象规模」，斜率不为 0 判红 | 事务层、块层写记录 | [decisions.md](decisions.md) D8 硬要求 |
| C3 | 读重试次数没有小的硬上限 | 加密开启且用截断 MAC 时，读路径的重试上限必须是编译期常量且不超过约定值；取不到该常量或超限判红 | 加密实现、读路径 | [decisions.md](decisions.md) D9 硬要求 3 |
| C5 | 形式验证的 `Z3 timeout` 被当成通过 | 门禁的 crash refinement 阶段必须有**三种**结果（证明 / 反例 / timeout），timeout 一律判红。现在 `gate.sh` 的 `record` 只有 PASS/FAIL 两态 | crash refinement 阶段存在 | 读 `singlefs-ai-sop/scripts/gate.sh` 确认只有两态；`show-me-test.md`「门禁不许假装通过」 |
| C6 | 块层重排 / FLUSH / FUA 的语义假设本身写错 | 在 QEMU 里用真实 virtio-blk + 写缓存策略跑，**故意去掉一次 FUA**，崩溃测试必须变红；不红说明重排模型没判别力 | QEMU 负载、崩溃点重放 | 三类验证路线共享这份假设，共享的东西没有第二条路径能查 |
| C7 | 「返回正确但过期的块」这一类错误没有任何检查 | 需要一个**会返回该地址历史版本**的设备模型（不是随机损坏），在它上面 D4 的 Merkle 必须报错 | 设备模型（现成工具没有，必须自造）、checker | D4 正文把「能检测读到正确但过期的块」列为 Merkle 的首要收益，而目前无手段验证它 |
| C8 | 门禁挂钟悄悄膨胀到没人愿意本地跑 | `gate.sh` 打印每阶段耗时并把总时长做成可回归的数，中位数超阈值判红；同时统计带跳过标记的提交比例 | 无（纯欠工） | `.claude/rules/fs-design.md`：门禁运行时长本身是设计约束，而「本地先跑一遍」是整套设计的支点 |
| C4 | 项目本地规则（`.claude/rules/*.md`）与项目 `CLAUDE.md` 的引用清单不一致 | 门禁比对 `.claude/rules/` 下的文件集合与 CLAUDE.md 里 `@.claude/rules/` 引用集合，任一侧多出一项即判红 | 无（现在就能做，只是还没做） | 实测：`manifest.sh` 只覆盖 SOP 包自己的 `CLAUDE.md + rules/`，项目本地那一份没有任何检查在看 |

> ⚠️ C3 不是强化项。截断 MAC 的安全论证整个押在「伪造尝试次数有界」上，
> 而那个界来自读重试上限——上限没钉死，80 位 MAC 的论证不成立。

**状态**：C1–C8 全部未实现。C1–C3 等事务层，C5 等形式验证阶段，C6 等崩溃点重放，C7 等自造设备模型；
