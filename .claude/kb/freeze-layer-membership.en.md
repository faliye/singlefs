# Freeze Layer Membership Registry

[中文](freeze-layer-membership.md) · **English** · [日本語](freeze-layer-membership.ja.md)

One row per **structure**: which layer or independent freeze component of settled item 7 of D15 (Format Freeze Policy) its bytes belong to, whether it is authoritative state or derived state, whether it withdraws from the freeze, and the sub-item serving as basis.

**Scope**: Governs the ledger of "which structure lands in which cell." How each sub-item is defined authoritatively is recorded in that sub-item; this table only references it without repeating the details. Granularity is taken at structure level, not field level—settled item 10 of D21 (Boundary Between Authoritative and Derived States) verbatim rejected "applying criteria at field granularity."

**Withdrawal from freeze is judged by structure, not by layer**: Scope of settled item 7 of D15 (Format Freeze Policy) verbatim states "Four-layer diagram is not rearranged: settled item 10 of D21 changed state classification to structure-by-structure; in Layer 4, Code 2 nodes of accounting tree are authoritative state, while internal nodes of other trees are derived state; no layer is pure, so the unit of freeze withdrawal is a structure, not a layer."

**Correspondence between state classification and freeze withdrawal** is given by the table in settled item 9 of D21: Authoritative state: "Losing it loses data. Participates in format freeze, permanent contract"; Derived state: "Losing it is merely slow. **Does not participate in format freeze**." Therefore, derived state withdraws from freeze, while authoritative state does not; for rows where state classification is undecidable, if freeze withdrawal has an independent basis it is stated, otherwise it is left undecidable.

**Layer values have only eight options**: `Layer 1`, `Layer 2`, `Layer 3`, `Layer 4`, `Component 1`, `Component 2`, `Component 3`, and `No governing clause` reserved for rows where scope of settled item 7 of D15 verbatim notes "which layer tree table units and instance table units land in has no clause yet."

## Where Each of the Eleven Undecidable Rows Is Blocked

State classification for these eleven rows cannot be governed by any settled sub-item. Marking them undecidable is not an evasion, but because two sentences in settled items 9 and 10 of D21 give conflicting answers for the same structure, or neither sentence reaches it.

| Structure | Where it is blocked |
|---|---|
| System configuration slot (Code 18) | Authoritative state list in settled item 9 of D21 is "Unit + Accounting + Root", explicitly stating "authoritative state list has three items, no expansion"; system configuration is not among the three. Conversely, recomputability criterion in settled item 10 judges it into authoritative state—geometry and fsid reside solely in system configuration; if non-reconstructible, reader reads with wrong geometry, yielding incorrect answer. Scope of settled item 22 of D22 defers state classification to D21: "governs axis of 'what is paid when modified', not state classification (authoritative/derived in settled item 9 of D21)", but three items in item 9 cannot accommodate it. Freeze withdrawal cell is unaffected: Layer 1 of settled item 7 of D15 verbatim names system configuration ⇒ does not withdraw |
| Journal record format (Code 17) | Same collision: journal records are neither units, nor accounting, nor roots, not accommodated by three items in item 9; settled item 4 of D21 groups them with root slots as "self-describing units", but self-describing unit class lacks state classification clause. Freeze withdrawal cell provided verbatim by independent freeze component 3 of settled item 7 of D15 ⇒ does not withdraw |
| Livelist shared tree (tree ID 65541) key encoding and Code 2 node internal layout two rows | Livelist is an event stream: settled item 3 of D6 verbatim states "adopts ZFS livelist event stream form; FREE recorded the moment block is killed." Events are history; scanning only observes current state ⇒ non-reconstructible. Under semantic criterion of settled item 10 of D21, one must ask "when non-reconstructible, does reader receive conservative or incorrect answer", which no sub-item has answered—falling back to full tree traversal is conservative, while omitting or double-counting a FREE is incorrect answer; both readings can be constructed |
| Sparse side-table tree (tree ID 65542) key encoding and Code 2 node internal layout two rows | Sparse side-table holds reference counts of shared blocks (settled item 6 of D5, entry = central mapping key 27 + count 4). Counts can be recomputed via traversal from authoritative state, pointing to derived state; but consumer is release decision, falling under first cell of `.claude/rules/fs-design.md` "must have answer the moment asked", which points to authoritative state per accounting derivation. Both derivations hold; no sub-item has adjudicated this cell |
| Deadlist tree (tree ID 65543) key encoding and Code 2 node internal layout two rows | Deadlist records "in which generation this block died"; settled item 5 of D26 verbatim states "deadlist entries recorded by version identity—key takes central mapping key." Same gap as livelist: death is historical event unobservable by scanning; no sub-item has answered whether reader gets conservative or incorrect answer when non-reconstructible |
| Logged_ops tree (tree ID 65547) key encoding and Code 2 node internal layout two rows | Zero root registered in first file version publish, writing zero entries; field table settled (settled item 2 of D26 (Background Compaction and Placement Reclamation)), rollback target version and state classification deferred to compaction landing (settled item 5 of D8, C364). Intents split into commitment and hint kinds; which kind a tree holds and whether recomputable from elsewhere is unstated in any settled sub-item |
| Container index | Has no landing location, recorded in C103. Settled item 6 of D8 verbatim "container index is internal nodes of this tree" holds only for inode tree; container indexes for tombstone and lineage containers are dedicated trees (settled item 24 of D18 (Information Carried in a Block)); container index for retirement record containers is retirement tree (tree ID 65548, settled item 11 of D18 (Information Carried in a Block)); where container index for stripe membership table lives has no clause ⇒ both layer and state classification undecidable |

## Three Criteria Judged by Gate

The freeze-layer-membership slot in `.claude/gate.d/doc-decisions.sh` judges the three criteria specified in "How to intercept" column of C45:

| # | What is judged | Where list comes from |
|---|---|---|
| 1 | Every layer and every structure has a row in the table; missing one turns red | Layers and components freshly read from settled item 7 of D15; trees freshly read from `TREE_IDENTIFIER_*` constants in `crates/singlefs-format/src/lib.rs`; unit classes freshly read from registry table in settled item 11 of D18 (Information Carried in a Block). None copied as second copy in script |
| 2 | Rows marked "withdraws" must have derived state classification; writing authoritative state turns red | Table itself |
| 3 | Sub-items named in basis column must exist in KB and be settled items | Freshly read from `.claude/kb/decisions/` |

**What the gate cannot manage**: Whether state classification for a row is correct, whether rationale for undecidable rows holds, and whether the table missed a structure already in the repo but unmentioned in the three lists. These three rely on human review.
