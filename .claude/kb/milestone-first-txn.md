## 步 0　脚手架

**设想实现**：一个 `crates/` workspace，三个 crate：核心（事务层）、checker、harness。
一个块设备抽象，接 N 个镜像文件；一个录制器包装在它外面，把每个写请求与屏障记成一条流。
一个格式常量文件，第一个事务要写的每个宽度都在里面，占位的常量带占位标记与分项号。

**预想的细节**：
- 设备抽象只暴露读、写、屏障、FUA 写、探测 `physical_block_size` 五个动作，不暴露介质是什么。
- 镜像文件默认两个，放 `${TMPDIR:-/tmp}`，大小预想 1 GiB。**预想**：`physical_block_size` 按参数给，默认 4096。
- 录制器每条记：设备号、偏移、长度、内容哈希、是不是屏障、是不是 FUA。流落到文件，给步 7 用。
- 地址全部 newtype：设备号、设备内 16 KiB 槽号、代号 `txg`、`jsn`、树 ID、inode 号。
- 常量文件里每个常量一行注释：值来自哪条分项，是不是占位。

**验收标准**：
- 录制器自证：喂一个少发一条写的假设备，比对条数判红。
- 两种地址类型混用的代码编译不过（一个 compile-fail 测试）。
- 门禁多一道阶段：数出常量文件里还有几个占位，每个占位都指得到分项号，指不到判红。

**写出的字节**：无（这一步不写新的盘上字节）。

**会碰到的决策点**：无格式决策；工程约定见 [verification-build.md](verification-build.md)「待定案」第 5 问。

## 步 1　mkfs

**设想实现**：`mkfs` 吃两个镜像文件，写出一个能被挂载、但一个文件都没有的池：每盘一份超级块、
三个根环区域、一条两盘镜像的 journal 环、实例表单元第一片、一个空的树表单元，
然后把第 0 代根记录种进全部三个区域。

**预想的细节**：
- 槽宽 = 探测到的 `physical_block_size`，超级块槽与根环槽都是（D20（承重面：单元的原子性与自包含）、D22（单元原子性怎么合成） 已定项 2）。
- 超级块每盘两个槽轮换。**预想**的字段：magic、格式版本、三张 feature bitmap、fsid、本盘设备号、设备数、
  节点与单元与落点粒度三个尺寸、根环参数（区域数 3、素数步长、每区槽数、区域起点）、journal 几何（起点、长度、记录尺寸）、
  两个 tail 槽、槽世代号、整单元校验和。字段表整个是占位（D22（单元原子性怎么合成） 未定项 9），只装 mkfs 必需的。
- 根环三个区域落在 `1 MiB + r × P × chunk`。**预想**：P = 3、`chunk` = 1 MiB、每区 8 槽、槽距 4096；区域 0 / 1 / 2 归盘 0 / 1 / 0——
  两盘上三个区域必有一盘背两个（E87（固定结构的放置） 逐字），归属由 mkfs 逐区域写进超级块（D2（RAID 条带策略） 已定项 7）。
- journal 环两盘镜像，记录 4 KiB（D23（journal 的角色与格式） 已定项 12）。**预想**：环长 64 MiB，mkfs 把整环写 0。
- 实例表单元：码 3 打包记录类型 4，只有一条「无下一片」记录。树表单元：码 2 索引节点，0 条条目。
- 第 0 代根记录 194 字节（D22（单元原子性怎么合成） 已定项 7）：实例代号 1、`checkpoint_txg` 0、树表单元指针、
  实例表单元指针、树 ID 水位、自证校验和。写进三个区域各自的槽 0，一共三份、不镜像，最后一道屏障加 FUA。
- 这些固定单元的落点**预想**写死在设备头部固定偏移，两盘各一份。

**验收标准**：
- 同参数跑两次 mkfs，两个镜像逐字节相同。
- checker 骨架从三个区域的槽 0 各自解析出同一份第 0 代根记录；改坏其中一个槽的一个字节，那个槽判无效、其余两个仍一致。
- 每盘两个超级块槽校验和都过、世代号相同；改坏一个槽，挂载选另一个。
- 根记录里两条指针指到的单元，头自检都过。
- 录制器流的最后两条是屏障与 FUA 写。

**写出的字节**：[first-txn-layout.md](first-txn-layout.md)「零、盘面地图与第一个事务的写清单」「一、mkfs 已经种下的」，第 0 代根记录与树表单元第 0 版在「七、发布」。

**会碰到的决策点**：D22（单元原子性怎么合成） 未定项 9；D2（RAID 条带策略） 未定项 15（槽距与槽宽，C212（固定结构的写小于 io_min））；
C241（树表归谁，两条用户定案说反话）；C217（P 大于设备数这条约束的理由没了而约束还在）；超级块槽轮换字段的宽度（D22（单元原子性怎么合成） 已定三只定了形态）。

## 步 2　分配一个数据单元，写一个小文件的数据

**设想实现**：内存里一个分配器，从两盘各拿一个 32 KiB 数据单元的落点；把文件内容装成一个自描述的数据单元，
写到两盘各一份；在内存里记下分配记录与记账增量。这一步还没有任何树落盘。

**预想的细节**：
- 落点粒度 16 KiB 槽，一个数据单元占两个连续槽（D3（空间分配） 已定项 7、D4（校验和位置） 已定项 5）。**预想**落点：两盘各自的槽 5124–5125。
  **预想**的政策：最低空槽优先（D3（空间分配） 未定项 8 占位）。
- 单元头按 `DATA_UNIT_HEADER_BYTES`（D18（块里携带什么信息） 已定项 7）：magic、格式版本、单元类型标签 1、flag 0、
  extent 声明长度 = 文件字节数、头校验和、五元组、诞生代号、fsid、写序、载荷 CRC、nonce 与 MAC 预留位。
  **预想**：五元组里树 ID 取 1（第一版唯一的可写头）、对象 ID 取分配到的 inode 号、锚点偏移 0；诞生代号取 1。
- 载荷 = 文件字节，之后补 0 到单元末尾，补齐参与校验和（I-2.3（补齐字节为零且参与校验和））。
- 整个单元落一列，两盘各一份，位置条目两条（D2（RAID 条带策略） 已定项 10、已定项 6 的 `w ≥ 2`）。
- 分配记录两条（每盘一条）：key = 设备 4 + 槽号 6 + 跨度 2，value = 分配代（D3（空间分配） 已定项 7）。
- **预想**：第一版不加密，位置条目里那 4 字节校验和取 CRC32C 罩整个单元，MAC 16 字节留位全 0。

**验收标准**：
- 从两盘各读回那个单元：头自检过、载荷 CRC 对、前 N 字节等于文件内容、之后全 0。
- 改坏载荷任一字节，CRC 判红；改坏头任一字节，头校验和判红。
- 内存里恰好两条分配记录，槽号与录制器流里的写偏移对得上。

**写出的字节**：[first-txn-layout.md](first-txn-layout.md)「二、数据这一侧」；分配记录与记账增量在「五、空间记账与分配」。

**会碰到的决策点**：整单元校验和在无加密下用哪个字段、多宽（要核 D4（校验和位置） 已定项 1 与 D19（块指针的结构与宽度预算） 已定项 2）；D3（空间分配） 未定项 8。

## 步 3　inode 树与其余几棵树

**设想实现**：一个按 keyspace 参数化的 btree，节点 16 KiB。用它建五棵树：extent 树（树 ID 1）、inode 树（2）、分配树（3）、记账树（4）、
以及步 4 的映射树（5），树 ID 是**预想**。第一个事务里每棵树都只有一个根加至多一个叶。inode 树按已定的形态：码 2 根、码 3 叶、一条定长 140 记录。

**预想的细节**：
- 码 2 节点头取三档头之一（D18（块里携带什么信息） 已定项 7；**预想**取带 key 区间那一档），字段：共同前缀、树 ID、
  层级、key 区间、诞生代号、fsid、写序 4、载荷 CRC 4、预留 2。基础字节数**预想**先取三档头的数。
- inode 树根：层级 1，key 区间 [ino, ino]，一条 93 字节条目 = 分隔 key 8 + 身份引用 26 + 子指针 59（D8（核心索引结构） 已定项 6）。
- inode 树叶：32 KiB 码 3 容器，头 107 字节（D18（块里携带什么信息） 已定项 11）：标签 3、出生树、打包记录类型 2、容器号 1、
  容器出生代、记录数 1、记录宽 140、诞生代号、fsid、载荷校验和、写序、出生序号。一条 inode 记录按 D8（核心索引结构） 已定项 6 的偏移表填。
  **预想**：第一个文件的 inode 号取 1，`locality_id` 0，mode 常规文件，size = 文件字节数。
- extent 树：**预想**只有一个叶节点，一条 83 字节记录 = key 24（`locality_id`, inode, offset）+ 指向数据单元的指针 59。
- 分配树：一个叶节点，装步 2 的两条分配记录，再加这一步自己写出的节点各一条。
- 记账树：一个叶节点，装「inode 号水位」一行（key 22 + value 8 + seq 4，seq 住 value，D8（核心索引结构） 已定项 7）
  与已分配字节各一行。**预想**：统计量标签值与设备段取值先按常量文件里的占位表。
- 父指针里的校验和与子单元一致（Merkle，D4（校验和位置） 已定项 1）。

**验收标准**：
- 每棵树：根节点头自检过，key 区间与条目一致，父指针校验和等于子单元算出来的。
- 从 inode 树按 inode 号查到那条记录，逐字段回读等于写入。
- 从 extent 树按 (inode, 0) 查到指针，指针解引用到步 2 那个单元。
- 变异：把叶容器头里记录宽改成 139，头合法性判红；把子节点改坏一字节，父指针校验和判红。

**写出的字节**：[first-txn-layout.md](first-txn-layout.md)「四、文件元数据（inode）」「四·二、extent 树」「五、空间记账与分配」，指针在「三、指向数据单元的指针」。

**会碰到的决策点**：D18（块里携带什么信息） 已定项 7 索引节点类的基础字节数；C108（扩展点归属对打包记录单元无判定）；
C71（不认识的统计量标签静默忽略）；C117（不带设备维的统计量的设备段没有取值）；D26（后台整理与放置回收） 未定项 4 占位为今天的节点布局；
D5（快照 / 空间记账机制） 未定项 6（稀疏旁表，第一个事务没有释放、不写它，但记账树的 key 布局要给它留位置）。

## 步 4　中央映射

**设想实现**：映射树，每写出一个数据单元就插一条「逻辑身份 → 位置」条目。解引用先按父指针里的位置提示读，
校验和不对再查映射；释放判定一律走映射（D19（块指针的结构与宽度预算） 已定项 5）。第一个事务里没有释放，
这一步只把入口建起来。

**预想的细节**：
- key 形态是 D19（块指针的结构与宽度预算） 已定项 6（2026-09-11 用户定案：按类复用写序键）：码 1 的 key = 类标签 1 + 出生树 8 + 出生 txg 8 + 写序 10 = 27 字节；
  value = 位置条目 14 × 2。指针带出生树、出生 txg 与写序才凑得出 key：指向码 1 的指针 85、指向码 2 / 码 3 的指针 83（D19（块指针的结构与宽度预算） 已定项 7、已定项 8，2026-09-12 用户定案）。
- 映射装码 1、码 2、码 3（D19（块指针的结构与宽度预算） 已定项 8，2026-09-12 用户定案）；映射树自己的节点、树表单元、实例表单元不进（自举豁免）。
- 映射树的根**预想**挂在树表单元里，与别的树同形（C196（中央映射树的根住哪全仓无条款） 占位）。

**验收标准**：
- 按步 2 那个单元的逻辑身份查映射，得到的位置等于 extent 树指针里的位置提示。
- 把位置提示改坏，解引用经映射仍读到正确内容。
- 映射树自己的节点不在映射里。
- 变异：删掉映射条目，释放判定路径报「不在映射」而不是按提示释放。

**写出的字节**：[first-txn-layout.md](first-txn-layout.md)「三·二、中央映射条目」。

**会碰到的决策点**：D19（块指针的结构与宽度预算） 已定项 7、D19（块指针的结构与宽度预算） 已定项 8（D19（块指针的结构与宽度预算） 已定项 6 带的四条收严要守）；C196（中央映射树的根住哪全仓无条款）；
映射条目走不走 write buffer。

## 步 5　一次发布

**设想实现**：事务状态机加一个封闭的 `CommitStep` 枚举，穷尽 `match` 没有通配臂。一次发布把步 2 到步 4 写出的全部单元、
一份新的树表单元、一条 journal 记录、一条根记录按已定的持久顺序落盘：单元与节点 → 屏障 → journal 记录 → 屏障 → 根槽 FUA
（D16（发布语义） 已定项 7）。`checkpoint_txg` 从 0 变 1（D16（发布语义） 已定项 6）。

**预想的细节**：
- `CommitStep` **预想**五个臂：写单元、屏障、写记录、屏障、FUA 写根槽。状态机每前进一步都经过录制器。
- 树表单元 COW 出新版本，装五条树表条目（inode、extent、分配、记账、映射），每条 121 字节（D8（核心索引结构） 已定项 8）。
- journal 记录 4 KiB。头**预想**取 78 加三笔已定增量（事务号 8 + 提交标记 1、反向链 4、载荷校验和 4）= 95，
  字段：magic、类型、`jsn`、实例代号、事务号、提交标记、点名项数、反向链 CRC32C、载荷校验和、头校验和；
  点名项每条 56 字节，每个新写单元一条。两盘各写一份。
- 根记录写到区域 `txg mod 3` 的下一个槽，FUA，一道写。**预想**：第一版每次发布都是 checkpoint，发布后再更新超级块的 tail 槽。
- 第一版串行提交（D13（验证路线） 已定项 2），defer 窗口占位 8 秒（D16（发布语义） 未定项 1）且这一步用不到。

**验收标准**：
- 录制器流的顺序恰是：若干单元写 → 屏障 → 记录写 × 2 → 屏障 → 一条 FUA 根槽写；FUA 只有一道。
- 根槽读回自证校验和过，`checkpoint_txg` = 1，`jsn` = 1。
- 记录的点名项数等于这次新写的单元数；反向链指向 mkfs 那条空环状态。
- 变异：摘掉第二道屏障，步 7 的 harness 用例判红（E77（发布的持久顺序） 那两条）；`CommitStep` 少写一个臂，编译不过。

**写出的字节**：[first-txn-layout.md](first-txn-layout.md)「六、journal」「七、发布」；整个事务的写清单（21 条写请求）在「零、盘面地图与第一个事务的写清单」。

**会碰到的决策点**：C94（登记的格式常量与后来的定案对不上）（记录头登记值取哪个数）；
C199（实例代号递增与 jsn 断号即止互相矛盾）；D16（发布语义） 已定项 3（journal 记录格式是四层之外的独立冻结组件；冻它之前 C199（实例代号递增与 jsn 断号即止互相矛盾） 要先还）；
D6（快照实现模型） 未定项 2（销毁可写头的第二个结构要不要 day-1 进树表，预想惰性、第一个事务不写）；
D16（发布语义） 未定项 1（若取动态回退下界，根记录多 8 字节的 F，194 → 202）。

## 步 6　读回来：冷启动恢复

**设想实现**：进程退出后重开两个镜像，走完整的挂载路径读出那个文件：择超级块、择根、扫 journal、
取前缀、重放、沿树走到数据单元、验校验和、返回内容。不许沿进程内的指针热读。

**预想的细节**：
- 择超级块：每盘两槽，校验和过且世代号大的那个；各盘的 fsid 与设备数要互相对得上。
- 择根：读三个区域全部槽，逐个验自证校验和，取 (实例代号, `checkpoint_txg`) 最大的，平局按实例代号（D22（单元原子性怎么合成） 已定项 7）。
- journal：全环扫描、不先信 tail（D23（journal 的角色与格式） 已定项 3）；前缀按五条口径取，缺一不可（D23（journal 的角色与格式） 已定项 14）。
  第一版的重放**预想**只验点名单元存在且校验和对，不改镜像。
- 读路径：根记录 → 树表单元 → inode 树 → inode 记录 → extent 树 → 指针 → 映射校验 → 数据单元 → 校验和 → 前 size 字节。

**验收标准**：
- 读回内容与写入逐字节相同。
- 改坏最新那个根槽一个字节：择回第 0 代根，报文件不存在，不崩溃、不返回坏数据。
- 改坏 journal 记录一个字节：前缀在它之前截断，恢复仍完成。
- 改坏数据单元一个字节：报校验和错误，不返回数据。
- 改坏 tail 槽让它指向陈旧位置：恢复结果与 tail 正确时相同。

**写出的字节**：无（这一步只读，不写新的盘上字节）。

**会碰到的决策点**：C199（实例代号递增与 jsn 断号即止互相矛盾）；C113（扫描重建时多版单元的现行版本判定无输入） 定案 P2 的回退行口径在第一个事务上是空的，要有一条测试证明它被跑到。

## 步 7　层 0 崩溃点重放

**设想实现**：harness 拿步 5 的录制流，按 D13（验证路线） 已定项 4 枚举崩溃状态：屏障切段、段内任意整写子集、
撕裂态并进「没持久」、没持久的位置放旧字节、镜像双写按设备各算。对每个状态生成镜像，跑步 6 的恢复、
checker 已实现的不变量、记录核对器，三样都要绿。

**预想的细节**：
- 第一个事务的写数按 [first-txn-layout.md](first-txn-layout.md) 的写清单是 21 条（单元 8 × 2 盘 + 记录 × 2 + 根槽 1 + 超级块 2）；单元段内任意子集是指数量，
  层 0 全量枚举能不能跑完要先量；跑不完就按 D13（验证路线）「崩溃点重放要分三层」进层 1，但里程碑出口要求层 0 全量。
- checker 第一版两个方向：从根槽下去、全盘扫描；每条已实现的不变量报成立 / 不成立 / 不适用。
- 记录核对器吃 (崩溃前镜像, 记录流, 崩溃后镜像)，判「根在案而记录缺席」那类状态。

**验收标准**：
- 全部崩溃状态零红，并报出枚举了多少个状态、是不是全量。
- [verification-build.md](verification-build.md) 点名的七条 harness 自证用例先红后绿。
- 阴性结果要能和「代码没跑到」分开：每条不变量至少一个崩溃状态上真被评估过。

**写出的字节**：无（这一步只生成崩溃镜像并读，不定义新的盘上字节）。

**会碰到的决策点**：D13（验证路线） 已定项 4 的枚举规模；checker 与实现允许共享什么（D13（验证路线） 已定项 5）在代码里怎么落。
