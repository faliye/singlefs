2026-08-30 起，每条决策的分项只有一套编号、按状态分住「已定项」与「未定项」两节
（见 [decisions-history.md](decisions-history.md) 2026-08-30（其二十四）那一条）。那一次把全仓的分项引用同步改写了，

### 2026-09-04：E98（inode 记录与 inode 树的几何）与 E99（write buffer 条目与 seq 的去重）各修一处「反向接受条款碰不到」

两处都是第二轮三方论证挑出来的**同一类毛病**：跑前写死的反向接受条款，在代码里**没有对应的输入**，
于是它永远不会触发——而一条永远不触发的失败条款，与没有这条条款在产物里长得一模一样。

| 实验 | 曾经 | 现在 |
|---|---|---|
| E98（inode 记录与 inode 树的几何） | 只在 btree 那条几何线上发 `records_lost_per_leaf`，打包臂的 233 只以 `records_per_container` 的身份出现，两个数**从没并排比过** ⇒ 条款里「住单元被爆炸半径否掉」评价不了 | 两种形态各报一个**永久损失**（116 / 233），并报 `needs_redundancy_clause`。结论：**两种形态都不是 0** ⇒ 那句条款仍评价不了（没人设过阈值），但这一维暴露出「无论选哪个都要一条冗余 / 可检出条款」 |
| E99（write buffer 条目与 seq 的去重） | 判据 4 只打印回绕期，那个数**从没接到任何违例计数上** ⇒ 条款里「截断带来 > 0 的选错」在代码里从没产生过一个数 | 按 D5（快照 / 空间记账机制） 已定项 5 的 key 结构接上——代进了 key，截断它撞的是**键的同一性**：16 位、一千万次发布之后 **757 947 392** 对本属不同 checkpoint 的条目塌成同一个 key；48 位恒 0 |

**E99（write buffer 条目与 seq 的去重） 记下一条等价变异**：把「无 seq」那条臂从 `None` 换成「所有条目同一个常数序号」，
在扫过的全部输入上与原式同结果——两种写法都让同 key 的条目全部并列，而并列在模型里判「胜者未定义」。
**这不算盲区，是等价**，等价性写成单测留档，变异表那一条换成一个真会改行为的（把墙钟压成常数）。

**一处方法论收获**：E99（write buffer 条目与 seq 的去重） 第一版把「选错胜者」和「胜者未定义」混成一个数，于是
「每次挂载归零的计数器」那条臂只错一半——那一半是被 tie-break 规则救回来的，不是它对。
D8（核心索引结构） write buffer 硬要求 3 逐字说「用不稳定排序时同 key 条目的**相对次序未定义**」
⇒ **模型不许替实现挑一边**，两个数分开报之后那条臂的错误率从「一半」变成「全部未定义」。
