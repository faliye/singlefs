# Bytes Written by New-Pool File Creation

[中文](01-first-txn.md) · **English** · [日本語](01-first-txn.ja.md)

**This is the table owed by C66 (format-level blank lacks sub-item number).** It lists every section to be written to disk for the first runnable objective "correctly commit one transaction"
(see project `CLAUDE.md`), with every field pointing to a settled or unsettled decision item.

**It serves two purposes.** First, reverse checking: if a field points to no item, it represents a **format-level blank**—
it blocks the first line of code, yet is absent from the unsettled item list of any decision, meaning during the gate phase
"has every unsettled item been judged on whether it modifies new-pool file creation bytes" cannot say a single word about it.
C66 (format-level blank lacks sub-item number) accounted for debt precisely because five such blanks existed at the time.
Second, supplying values to the milestone: each step of [01-first-txn.md](../milestone/01-first-txn.md) writes "what is added on disk",
whose byte widths, values, and placements follow this table, without the milestone copying another version.

**Measurement basis**: New-pool file creation refers to "writing a small file and publishing once after mkfs". It excludes snapshots, excludes reflinks,
excludes encryption (D9 (Encryption) settled item 10 settles that encryption does not enter the first version), excludes compression, excludes directory trees
(the first runnable objective does not require directories, see project `CLAUDE.md`).
Widths are universally **initial values**, adjustable during coding; adjusting them requires returning to update this table.

**Every row provides concrete numbers, divided into two types**: rows whose "Pointing" column points to a settled item have their widths and values settled by that item;
rows pointing to an unsettled item have widths and values as **anticipated**—adopted tentatively during coding, revised once the item is settled, editing the body text directly, with history tracked via git.
The "Value in new-pool file creation" column records the actual values left on disk by this mkfs plus one publish;
rows marked "mkfs random" are quantities that differ on every mkfs, and rows marked "anticipated" have no clause in the repository settling them.

**Form of hooking with milestones and decision indices** (gate stage "hooking three new-pool file creation documents together" judges red):
Below each section heading, one line states which milestone step it belongs to; each milestone step states which section here contains its written bytes;
every unsettled item in [decisions.md](../decisions.md) judged "changes new-pool file creation bytes: yes"
must occupy one row in the "Remaining Blanks" table here and one row in the milestone's "Decision points encountered".
