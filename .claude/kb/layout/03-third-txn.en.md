# Bytes Written by Deletion (On-Disk Patterns Newly Appearing After New-Pool File Creation and Overwrite)

[中文](03-third-txn.md) · **English** · [日本語](03-third-txn.ja.md)

**Registry table for Section III.6 of milestone "Deletion and Repeated COW"** ([03-third-txn.md](../milestone/03-third-txn.md)), established 2026-10-01. Each byte segment of new-pool file creation is in [layout/01-first-txn.md](01-first-txn.md), and newly written patterns of overwrite, release, rollback and reuse are in [layout/02-second-txn.md](02-second-txn.md); here we only register newly appearing patterns of deletion (single-file unlink) and lineage records of administrator rollback. Widths and placements of identical fields follow layout/01-first-txn.md without duplicate copying. Each row points to a decision item; those pointing to no item are marked as "format-level blanks". Deletion is already implemented: `publish_unlink_intent` (intent), `publish_unlink_step` (batch), and `walk_the_deletion_queue_until_it_is_empty` (drain) in `crates/singlefs-core/src/transaction.rs`; mount resumption in `continue_the_deletion_queue_until_it_is_empty` in `crates/singlefs-core/src/mount.rs`; `crates/singlefs-harness/tests/unlink_single_file_publishes.rs` pins rewritten role sets across intent, intermediate batch, and final batch publishes. On-disk bytes were verified field-by-field against E142 (New-Pool File Creation Dry Run) patterns by E172 (Dry Run of Bytes Written by Deletion), validating the version prior to adding the retirement tree: tr@0, tr cells and label 6 retirement items introduced by the retirement tree were not verified (C775 (E172 apparatus lacks retirement items)); cells marked "inferred, pending dry-run verification" in the segment sequence table remain inferred.

## 4. Segment Sequence

Deletion publishes (intent, non-final batches, final batch, mount resumption batches) and administrator rollback all follow normal publish shape: [units × 2 disks] barrier [journal records × 2 disks] barrier [root FUA] [system configuration slots × 2 disks] barrier ("normal publish (new-pool file creation)" row in segment sequence table of [layout/01-first-txn.md](01-first-txn.md)). For unit count column where harness test cases pin rewritten role sets, cases are cited; unpinned rows marked inferred. Segment strings (across two disks) are all inferred, verified by III.6 dry run. Role names follow `TransactionUnit::tag`: t2 extent tree root, t2lower@level.seq extent lower leaf, t3 inode leaf container (leftmost), t4 inode tree root, t5 allocation record tree root, t5@level.disk.seq nodes beneath allocation record root, t6 accounting tree root, t7 mapping tree, t8 tree table, td `deleted_inodes` root, tt@leaf_seq tombstone container, tt tombstone tree root, tr@leaf_seq retirement container, tr retirement tree root.
