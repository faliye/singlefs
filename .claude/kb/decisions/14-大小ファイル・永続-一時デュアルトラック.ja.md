## D14 大小ファイル・永続/一時デュアルトラック —— 確定

[中文](14-双轨大小文件-持久临时.md) · [English](14-dual-track-large-small-files-persistent-transient.en.md) · **日本語**

D14 (大小ファイル・永続/一時デュアルトラック) は「オブジェクト別の軌道分割」がどの層に位置づけられるかを管轄する：大小ファイルおよび永続/一時の2軸における軌道分割は、アロケータヒントと小ファイルの inode へのインライン化の2層のみに位置づけられ、フォーマットレベルの第2軌道は設けない（確定項目 6）。第1版ではこれら2層はいずれも空である：アロケータヒントは実装せず（確定項目 2）、インライン閾値は 0 とする（確定項目 3）。D14 (大小ファイル・永続/一時デュアルトラック) は文献や他社の結末を根拠とすることを禁じ、自前の演繹と検証を行わなければならない。管轄外：1つの割り当てユニットより小さいオブジェクトの領域節約方法は D27 (小データパッキングコンテナ) に属する——書き込みパスは通常通りパディングし（D4 (チェックサム配置位置) 確定項目 1 / 5：ユニットはヘッダ込み 32 KiB、4 KiB のファイルは 32 KiB を占有）、バックグラウンド整理が ≤ 4 KiB のオブジェクトを共有コンテナへ移動する。これは新たなユニット種別を追加するものであり、新たな軌道を追加するものではない；割り当てユニット自体の大きさは D12 (対象メディア) / D19 (ブロックポインタ構造と幅予算) のパラメータであり、空間利用率のみで決定することはできない（E20 (ポインタ肥大化によるCPUキャッシュコスト) は小ノードにおけるポインタ幅の CPU キャッシュコストが倍増近くに達することを計測）；1割り当てユニット以上のオブジェクトは問題を構成しない；永続/一時が D11 (インデックスノード内のメッセージバッファ要否) の判定基準となり得るかは D14 (大小ファイル・永続/一時デュアルトラック) 確定項目 4 に属する。

#### 確定項目 2：アロケータヒントの判定基準の定式化

**定案**：5つの文——

1. **第1版はアロケータヒントを実装しない**：ユーザーデータの配置先はすべて D3 (領域割り当て) 確定項目 8（選択されたデバイス内でスロット番号が最小、受入合取を通過、`R` 保護期間外の空きスロット）に従い、アロケータはオブジェクトに関するいかなるヒントも読み取らない；判定基準欄は「なし」と記し、3つの小文（ディスク非保存、割り当てごとに再判定可能、ゼロフォーマットビット）および5つのハード要件は空振りとなる。
2. **3つの独立した理由、性能上の利益数値には依拠しない**：① D8 (コアインデックス構造) 確定項目 3 は逐字的に「第1版にはディレクトリが存在しない」としており、`locality_id` は第1版で 0 をとる ⇒ ディレクトリに基づく判定基準は第1版では入力が存在せず、実装の有無にかかわらず書き出されるバイトは同一である；② 現行条項下では判定基準セットが解を持たない——「ディスク非保存」の文はオンディスクフィールドから導出される一切の判定基準（拡張子テーブル、親ディレクトリ、`locality_id`）を失格とし、残る到達順 / パブリッシュバッチ（アーム庚）の配置先は D3 (領域割り当て) 確定項目 8 第1文によって固められている；③ 「将来は作成時に1回継承し以後は変更しない形のみ採用可能」というメカニズム上の制約と「割り当てごとに再判定可能」という小文が相互排他である（同一分項内の2文）。そのため本セルは「性能データを待つ」状態ではなく、判定基準自体をまず収束させる必要がある。
3. **3つの再開条件、それぞれ検証可能**：㈠ 第1版の後にディレクトリが実在し、D8 (コアインデックス構造) 確定項目 3 の「親ディレクトリがない場合に何をとるか」が確定したとき；㈡ 「ディスク非保存」の文自体が再開または射程を縮小したとき（縮小前はディレクトリ別 / 拡張子別の判定基準は測定不要）；㈢ D3 (領域割り当て) 確定項目 8 第1文が再開したとき（第1版の配置先を一意に決定しており、いかなるヒントもこれと両立し得ない）。再開時には整理先側も同時に判定する（ホーム固定は整理先側を構造上最も散らばらせ、D26 (バックグラウンド整理と配置回収) 確定項目 5 ② の 370 倍の最悪ケースに陥る）。
4. **「ホーム固定 + N₀留保」は候補とせず、測定済み手がかりとして登録**：E151 (ユーザーデータ配置先の到達順序とコンテナアーム) の第4/5回実行——ホーム固定のディレクトリヒントは各ディレクトリを2セグメント以内に収めるが（ディレクトリ走査セグメント数は減数アームの 54%–55%）、uniform 上でコミット内生ブロックのために末尾24セグメントを留保すると0に戻り、局所性は1段階も低下しない；runs8 上では「セグメントの留保」と「各ディレクトリ ≤ 3セグメント」を同時に達成できるオーバーフローセグメント数は存在しなかった——局所性と完全空きセグメントの供給は同一のセグメント群を奪い合う。メンバーに追従するヒントは老化下で減数アームとほぼ同等に散乱する（97%–99%）。
5. **E122 (ディレクトリ集約で何が得られるか) の3アームの減数アームに対するマッピング**：`grouped`（同一ディレクトリ連続）は E151 (ユーザーデータ配置先の到達順序とコンテナアーム) の初期条件であり、どのアームにも対応しない；`arrival` は E151 (ユーザーデータ配置先の到達順序とコンテナアーム) の均一置換アームに対応；`random` は対応なし。E122 (ディレクトリ集約で何が得られるか) の2つの利益セルは老化下の uniform で 0 に帰着し、runs8 では 12 / 256 のみが残存する（1つのディレクトリのみを収容する 32 スロットブロック）。

新規プールでのファイル作成のバイト変更：否——アロケータヒントはゼロフォーマットビットであり、新規プールでのファイル作成の配置先値は D3 (領域割り当て) 確定項目 8 が与える。

#### 確定項目 3：インライン閾値の設定

**定案**：インライン閾値 0、すなわちインライン化しない。**小ファイルは一律に独立データ extent を経由し**（D4 (チェックサム配置位置) 確定項目 2 に従い 32 KiB にパディング）、**インデックスノードにはインライン化せず、1バイトもインライン化しない。**

**判定基準は原子性であり、性能ではない。** インライン化により**複数ファイルのデータが同一インデックスノード内に密集する** ⇒ あるファイルの書き込みが同一ノード上の他のファイルの原子単位を巻き込む。これは E66 (パディング後に小ファイルがどう配置されるか) で失格となった `pack` アーム（複数小ファイルが1つのデータユニットを共有）と**同一形状の結合**であり、単にコンテナを変更したにすぎない。原子性は以後本項目の判定基準そのものであり、単なる今回の値の選定理由にとどまらない：**今後インライン閾値を引き上げるいかなる提案も、まず「複数ファイルが1つの原子単位を共有する」という関門に答えなければならず**、性能数値はこれに答えることができない。

書き込みパス上の**複数ファイルにまたがる末尾パッキング**も同様に**否**と判定する：2つのファイルが1つのユニットを共有 ⇒ 一方を書き込むにはユニット全体を COW しなければならない ⇒ **他方のファイルのポインタも変更が必要となり**、**D20 (荷重受け面: ユニットの原子性と自己完結性) の「ユニットの自己完結性」が即座に破綻する**。インライン閾値の引き上げは本質的に末尾パッキングであり、コンテナがベアブロックではなく btree の葉であるにすぎない ⇒ 本項目に帰着し、本項目は 0 をとる ⇒ そのパスは有効化しない。

**射程**：

- パック記録ユニットに対する本関門の回答（D8 (コアインデックス構造) 確定項目 6）：inode レコードを Code 3 葉コンテナにパッキングすることは 233 個のオブジェクトが 1 つの 32 KiB ユニットを共有することであり、形状はインライン化と同一であるが、回答は性能数値ではない——D18 (ブロックに含める情報) 確定項目 11 に登録されたパック記録ユニットクラスはまさに「複数オブジェクトが1つの自己記述ユニットを共有する」ために設けられたものであり、固有の識別情報（誕生ツリー、種別、コンテナ番号、誕生世代）とペイロードチェックサムを持ち、あるオブジェクトのレコードは他オブジェクトによる自己証明に依存しない；COW 下であるオブジェクトの更新は新版コンテナを書き出し旧版は変更しないため、パブリッシュ単位で原子性が保たれ、別オブジェクトを断裂させない；ファイルデータは依然としてインライン化しない。残る2点はコスト（E103 (inodeパッキング経路1の更新コスト) の実測で単一更新 1.25–1.5 倍）と爆発半径（C100 (inode コンテナの喪失は恒久的な損失なのに、それを覆う冗長性の条項がない)）であり、いずれも未済の検査として計上済み。
- データ側のバックグラウンドパッキングコンテナに対する本関門の回答は D27 (小データパッキングコンテナ) 確定項目 10 の射程内にある：「外部移動」の形態ではあるオブジェクトを書き込んでもコンテナをまったく COW しないため、複数ファイル末尾パッキングの「否」の理由は届かない；その「否」自体は不変である。
- コストの承知の上での受容（E66 (パディング後に小ファイルがどう配置されるか) および E68 (インライン化閾値の選定) ページで計測、本項目の根拠ではない）：空間的には 512 B のファイルが **64 倍**（32 KiB にパディング）、1 KiB が 32 倍を占有；ポイント読み出しはインライン化より遅く、桁数は未確定——E66 (パディング後に小ファイルがどう配置されるか) の非対称会計では 16.6%、対称会計では 54.5%（葉ミス）から 100%（葉ヒット）；キャッシュ上は E68 (インライン化閾値の選定) の読み出しモデルで 16 MiB 以上のキャッシュ階層においてインライン化が 10% 良好；承知の上で放棄したパスが節約可能であったデータバイト数は E8 (大容量と小容量ファイルで書き込みパスを分けるべきか) の陽性対照を参照（4096 個の 64 B ファイルにおいて、非分流アームは実質 16 MiB、インラインアームは 0 バイト）。
- 見返りとして得られる利益：メタデータワーキングセットが膨張しない（インライン化はファイルあたり 64 B → 89 B、葉数 1.40×）；さらに**閾値横断移行パスが完全に消滅する**——閾値が 0 であれば「インライン → extent」のステップは存在せず、E8 (大容量と小容量ファイルで書き込みパスを分けるべきか) に記録された「閾値は適格な分岐変数ではない」という制約はもはや適用されない（これは「追記書き込みが操作途中で閾値をまたぐこと」を阻止するものであった）。初回書き込みも RMW を経由し、新スロットの残留物を一度読む（D4 (チェックサム配置位置) 確定項目 3 の射程、C385 (初回書き込みに読み戻しが要るかについて 2 つの確定項目が逆のことを言う) はユーザーが 2026-10-26 に「初回書き込みも読み戻す」と決定）ので、書き込み側は「初回書き込みで RMW 不要」という利益を数えない。

**根拠**：

- 実験なし：判定基準は原子性（複数ファイルが1つの原子単位を共有）であり、構造的判断であって性能数値はこれに答えられない；コストと見返りの2欄は、この決定が性能上の大きな代償を払わずに済むことを示すにすぎず、根拠ではない。
- ユーザー決定：原文は変更履歴にある。
- ユーザー決定 2026-10-26：C385 (初回書き込みに読み戻しが要るかについて 2 つの確定項目が逆のことを言う)「初回書き込みも読み戻す」。見返りの欄から「初回書き込みで RMW 不要」という利益を外す（原文は変更履歴；判決 `research/prompts/m4-partial-write-r1-main-verification.md` の決定振り返り表）。

#### 確定項目 4：「永続/一時」は D11 (インデックスノード内のメッセージバッファ要否) に欠けていた判定基準か

**定案**：否、不成立と判定。当該判定基準は `linkat` / `fsync` / スナップショット / `rename` により操作スコープ外から非同期に反転される（参考1） ⇒ .claude/rules/fs-design.md ハード要件 5「分岐変数は操作途中で変更されてはならない」に抵触し、**適格な分岐変数ではない**。

**射程**：1つの候補を排除したにすぎず、D11 (インデックスノード内のメッセージバッファ要否) の問題自体に回答したわけではない；その問題は D11 (インデックスノード内のメッセージバッファ要否) 確定項目 6 で回答された：レイアウト軸は分岐せず、ツリー軸は「フラッシュ待ちメッセージが権威態のみから再計算可能か」で分岐する。

**根拠**：

- 実験なし：操作スコープ外からの反転は POSIX セマンティクスからの演繹である——参考1に列挙された各エントリポイントはいずれも POSIX が O(1) または原子性を保証する操作であり、演繹 D-3（マルチ軌道互換判定基準）の非対称な結論も同一の事実を述べており、測定可能な量はない。
- ユーザー決定：原文は変更履歴にある。

**未済の検査**：なし。

#### 確定項目 5：確定·対象なし·番号廃止

**定案**：対象なし、この番号はもはや使用しない。元の課題：インライン → extent の有界トランザクションのクラッシュセマンティクス。確定項目 3 がインライン閾値を 0 に定めた後、「インライン → extent」のステップは存在しない ⇒ 本項目は「根拠不足」ではなく**対象なし**である。D9 (暗号化) 確定項目 7 / 9 の先例に従い、適切な処置は**確定に変更し対象なしを明記すること**であり、番号はリサイクルせずそのまま保持する。新規プールでのファイル作成のバイト変更：対象なし。

**射程**：将来インライン閾値が 0 から非 0 に変更された場合、本セルは**即座に未定に復帰する**：その時点で「インライン → extent」が再び出現し、そのクラッシュセマンティクスは依然として誰も検証していない状態となる。

**根拠**：

- 実験なし：測定対象が存在せず、閾値 0 の場合このステップは存在しない。

**未済の検査**：なし。

#### 確定項目 6：軌道分割が位置づけられる層

**定案**：軌道分割は**これら2層のみに位置づけられ、フォーマットレベルの第2軌道は設けない**——第2の検証セマンティクス、第2の台帳、第2のリカバリセマンティクスは設けない。

| 層 | 役割 | なぜ負債を負わないか |
|---|---|---|
| **アロケータヒント** | 小ファイルのブロックをまとめる；短命の疑いがあるデータを一括解放が見込まれる領域に配置する | ディスク非保存、割り当てごとに再判定可能、**ゼロフォーマットビット**。本層の根拠はこれら3つの小文のみであり、判定基準は3文すべてを満たさなければならない（確定項目 2） |
| **小ファイルの inode へのインライン化** | inode の残余空間に収まる小データを直接インライン化 | **移行規模は構造上制限される**（≤ inode 残余空間）、「インライン → extent」は有界トランザクションであり、無界操作に対する D8 (コアインデックス構造) のインテントログ要件をトリガーせず、per-inode で1ビットあれば十分 |

v1 はフォーマットレベルの第2軌道を含まず、ビットも予約しない；v2 で実装する場合は incompat を経由して新たなレイアウトを開始する——D15 (フォーマット凍結ポリシー) 凍結前リスト第7項「v1 が本機能を含まないことを明示する」の分岐に従い、パディング幅は 0 とする。

将来のあらゆるマルチ軌道提案は day-1 マルチ軌道互換判定基準（演繹 D-3（マルチ軌道互換判定基準））に従って判定する。**最強の形態は「軌道はコミットメントを削減するのみで、エンコーディングは変更しない」である**：軌道フィールドは耐久性のコミットメントを引き下げるのみで、バイトレイアウトを決して変更しない；判定可能形式（採用された場合、その時点で [invariants/README.md](../../../crates/singlefs-checker/invariants/README.md) に新設）：**任意のポインタの track フィールドを 0 にマスクした後も、単一軌道パーサーによってバイト単位で解析可能であり続け、チェックサム / MAC / nonce / birth txg / 逆インデックスセマンティクスは1文字も変更されない。** この形態下では inode の軌道は**保存されず**、その全 extent 軌道から計算される下限となる ⇒ 混合状態は生来的に正当であり、「移行」は2ビットの反転に縮退し、ポインタを書き換える本来のトランザクションに統合され、**データ移動なし、再エンコーディングなし、MAC 再計算なし**となる。

| # | 4つの判定基準（すべて設計時定数） | 判定方法 |
|---|---|---|
| 1 | **軌道フィールドはコミットメントを削減するのみで、エンコーディングは変更しない** | 0 にマスク後も単一軌道パーサーによりバイト単位で解析可能。不変条件として記述され、チェッカー判定可能、かつ赤となることを証明可能（2軌道の幅が不揃いなイメージを構築） |
| 2 | **削減される各コミットメントは、当該ポインタ自身のフィールドのみを読み取る述語として記述可能** | 述語実装シグネチャを `fn(&Pointer) -> bool` に固定、引数が1つでも多ければ赤と判定 |
| 3 | **軌道はオブジェクト作成時に確定し、以後は不変** | 軌道を変更可能な全エントリポイントを列挙し、集合が空でなければならない |
| 4 | **D12 (対象メディア) および D6 (スナップショット実装モデル) が確定** | track は nonce 担持体、スナップショット ID、locality_id と**同一のソート権**を競合する |

**判定基準 3 に判定可能性の全重量が存在する**：「誕生時に確定し以後は不変」という耐久性軌道は取消不能な宣言であり、**歴史的帰納に依拠することなく、永続/一時軸を自動的に失格とする。** 本プロジェクトにはすでに4基準すべてを満たす day-1 マルチ軌道が存在する：D9 (暗号化) に予約された「データ/メタデータ書き込みごとのアルゴリズム種別フィールド」——コミットメントを削減するのみでエンコーディングを変更せず（旧データは各フィールドに従い復号）、述語はその書き込み自身のみを読み取り、**書き込まれた瞬間に固定される**。ここから非対称な結論が得られる：day-1 マルチ軌道は**大/小軸**には顕著に寄与するが（反転は操作自体により引き起こされ、同一トランザクションに統合可能）、**永続/一時軸**には一切寄与しない（反転は操作スコープ外から生じる）。**day-1 が購入するものの正確な表現は：フォーマットは反転を生き延びることができるが、操作は生き延びることができない。**

| 演繹 | 略称 | 何を演繹するか | 現状 |
|---|---|---|---|
| D-1 | 反転エントリの網羅 | 「オブジェクト → 軌道」マッピングを変更可能な全エントリポイントを網羅（判定基準は `.claude/rules/fs-design.md` ハード要件 5 による）：各システムコール / 内部イベントごとに1行、何を変更するか、変更が原子的一貫性を有するか、途中で失敗した操作をどう収拾するか、禁止可能かを明記；既知のエントリポイントとして少なくとも `linkat` / `rename` / `fsync` / スナップショット取得 / ハードリンク / mmap ダーティページライトバック / クォータ精算 / `truncate` / `fallocate` が存在 | 網羅表は未演繹、網羅性の証明も未完了 |
| D-2 | 6つの省略項目の逐次演繹 | 6つの「省略」（スナップショット可視性、deadlist 会計、Merkle ツリー連鎖、nonce、リカバリコミットメント、逆インデックス）について「1つのイメージを見るだけで判定可能か」を逐次演繹；判定不能 ⇒ オンディスクの事実が必要 ⇒ 新たな負債を開くのではなく、D12 (対象メディア) で受容済みのフォーマット分岐予算に落とし込む | 検証の半分（各「省略」の個別計測、反転移行の傾き）は E11 (デュアルトラック：恩恵と反転コスト、自前計測) に属し、未実行：確定項目 6 はフォーマットレベルの第2軌道を設けないため、2つの軌道は実装されず、v2 でフォーマットレベル第2軌道が提案された場合にのみ実行が必要 |
| D-3 | マルチ軌道互換判定基準 | 歴史的帰納に依存しない、day-1 マルチ軌道互換の判定基準 | 演繹完了、4つの判定基準と非対称な結論を定案に記述 |

**射程**：

- アロケータヒントの層は「予測を誤っても局所性を失うのみ」を撤回した：誤予測は直接 ENOSPC に至り（受入不等式が「回収不能」を利用可能領域に算入、D28 (マウント時コミットメント量) 確定項目 1、元 D3 (領域割り当て) 確定項目 4）、必然的に支払わなければならない移動バイトとなる（D26 (バックグラウンド整理と配置回収) 確定項目 1 の停止述語）。D3 (領域割り当て) 確定項目 5 は計測済みの先例である；したがって本層は3つの小文のみが残り、依然として成立するか否かは D14 (大小ファイル・永続/一時デュアルトラック) 確定項目 2 が答える。
- インライン化の層における「移行規模は構造上制限される」が制限するのは**移行の規模**であり、**判定基準の安定性**ではない（追記書き込みが操作途中で閾値をまたぐ）；後者は確定項目 3 により解消された——インライン閾値を 0 とするため、またぐべき閾値が存在しない。
- 演繹 D-3（マルチ軌道互換判定基準）の判定基準に従って6つの「省略」を再計算：真に安価になるのは **deadlist の1点のみ**である（I-3.1 (割り当て済み統計が一致する) がスカラー等式から「軌道別バケット化ベクトル等式 + スカラー収縮」へ変化し、判別力が**純増**、「総数は一致するが分類が誤っている」というクラス全体を検出可能）；他の2点は「0バイト節約だが拒否権が消滅」（逆インデックス）および「小幅に安価化」（リカバリコミットメント）；残る3点（スナップショット可視性、Merkle、nonce）は純節約が 0 である。⚠️ 最初の3点を成立させるメカニズムは、まさに「一時軌道に何も節約させないこと」である——本設計は利益を削除することによってコストを相殺した。

**根拠**：

- 根拠2（自前演繹）：唯一の取消不能な宣言は、反転エントリポイントを禁止することによって得られたものであり、安定した変数を設計できたわけではない——`O_TMPFILE | O_EXCL`（`man 2 open`：「Specifying O_EXCL in conjunction with O_TMPFILE **prevents a temporary file from being linked into the filesystem**」、代償としてこのファイルは永久に名前を持つことができない）および独立サブボリューム / マウントポイント（境界を越えた `rename` は `EXDEV` を返し、per-file ではない）；隔離された後では「一時ファイルが透過的に高速パスを取る」という当初の要求はもはや存在せず、O_TMPFILE が表現するのは「この名前がまだ存在しない」ことであって、「このデータが一時的である」ことではない。
- 演繹 D-3（マルチ軌道互換判定基準）：`linkat` は POSIX 下で O(1) である；1 TB の一時 extent を持つオブジェクトが `linkat` によりディレクトリツリーにリンクされた場合、即座の再ラベリングは O(N) のメタデータ書き換えとなり O(1) のコミットメントが無効化され、遅延再ラベリングは「未再ラベリング」というインフライト派生態を導入し D11 (インデックスノード内のメッセージバッファ要否) 確定項目 3 / 5 のような排空契約や陳腐化検出メカニズムを欠き、インテントログによる再ラベリングはリターン後かつ再ラベリング完了前にクラッシュが発生した際に正常にリンクされたファイルのデータをリカバリ時に破棄することになる——病根はレトロフィットにあるのではなく、「コミットメントの反転が操作スコープ外から生じること」にある。
- E8 (大容量と小容量ファイルで書き込みパスを分けるべきか)：インライン化の層の利益はすべて ≤ 閾値に集中し、コストは読み出し側に生じ、追記書き込みは操作途中で閾値をまたぐ——「移行規模は構造上制限される」は規模のみに答えている。
- 他ファイルシステムの記録（参考1、3、4、5：両軸において操作期間中に安定した分岐変数は存在せず、6つの省略項目のうち純粋な振る舞い分岐に属するものは0、検証直積16倍、歴史上いかなるファイルシステムもフォーマットレベルの一時軌道のパブリッシュに成功していない）は、**D14 (大小ファイル・永続/一時デュアルトラック) の支持または否定に用いてはならない**；これらを残す唯一の目的は D-1（反転エントリの網羅） / D-2（6つの省略項目の逐次演繹）のチェックリストとすることである。原文は変更履歴にある。
