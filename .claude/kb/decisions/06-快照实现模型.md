## D6 快照实现模型 —— 已定

D6（快照实现模型） 管快照与可写头在盘上用什么机制实现：做不做多可写头、取哪条机制、销毁一个可写头要什么结构、那个结构的条目宽与建树时机、把可写头退回到快照态提不提供，以及采纳一个快照实现模型要过哪几条判据。不管的：快照的空间记账（`birth` txg、deadlist、稀疏旁表、统计量清单）在 D5（快照 / 空间记账机制）；索引树的 key 布局、树表条目字段表与树的种类码在 D8（核心索引结构）；中央映射 key 的宽度与编码在 D19（块指针的结构与宽度预算）；管理员按发布回退在 D23（journal 的角色与格式） 已定项 14；快照点与 checkpoint 边界的对齐在 D16（发布语义）。

#### 已定项 1：多可写头取每头一棵自己的树

**定案**：取 ②——**每头一棵自己的树**，接受它那一侧的代价（一张引用计数旁表 + 每头 3 条固定元数据），换掉 ①-前缀 那一侧的「读路径恒定多走 H−1 次树下降」。候选 ①（bcachefs 的**快照 ID 进 key 低位**）其实是两支——低位与前缀，两支删一个头的代价整个不同（全扫对范围操作）；低位那一支被前缀那一支**严格支配**，先出局。

**射程**：管多可写头取哪条机制，不管每头各自的记账（D5（快照 / 空间记账机制））、也不管销毁一个头要什么结构（已定项 3）。② **破 D5（快照 / 空间记账机制） 前提 3**（每块至多一个活引用）——引用计数旁表正是为此而要的；② 可不可接受取决于旁表装不装得下缓存。①-前缀 的「H 次下降」是最朴素形态的上界，跳表 / 位图 / 祖先集合缓存都可能把它压下去，没人建过模型。这条定案**在实装测试阶段可以被推翻**（与 `.claude/rules/format-evolution.md`「第一个外部用户出现前磁盘格式是软的」同向），但推翻的纪律不变：当场改正文、把推翻依据写进当月的 `decisions-history/<年-月>.md`，不许悄悄改。

#### 已定项 2：livelist 条目 36 字节一宽，共享树 day-1 注册进树表

**定案**：① 条目 key = 头的树 ID 8 + 中央映射 key **27（定宽）**（D19（块指针的结构与宽度预算） 已定项 6 的码 1 形态；码 2 / 码 3 的 25 字节 key **末尾补零到 27**，D19（块指针的结构与宽度预算） 已定项 10）+ 事件类型 1 字节（ALLOC / FREE 单独占一个字节，不折进类标签），共 **36 字节一宽**，value 为空；② 那棵共享树 **day-1 注册进树表**，第一个事务多一条 200 字节的树表条目（D8（核心索引结构） 已定项 8 的条目宽）、根指针为零。改第一个事务的字节：**是**——树表里 livelist 那一条条目的宽度；条目本身第一个事务一条都不写。

**射程**：管条目的 key 与宽度、以及那棵共享树什么时候建，不管条目什么时候写（已定项 3 定 FREE 在块被杀掉那一刻就记）。条目身份必须是中央映射 key、不许是位置条目——D19（块指针的结构与宽度预算） 已定项 5 规则 1 逐字「释放一律经映射，不经提示」，按位置条目记的旧形态因此作废。每次 FREE 预付 36 字节，它进不进「解开自己需要多少」那条条款仍欠。两处改动（条目从「36 / 34 两宽」回到「36 一宽」、树表条目加宽）都是用户弹窗定案、没有走三方论证，可推翻。

**依据**：

- E146（livelist 条目按映射 key 定身份之后的宽度与代价）：按映射 key 定身份之后四种候选形态的条目宽、叶与内部扇出、树高，以及每次 FREE 的预付量——36 字节一宽这一档树高与 35 字节形态全同。
- E132（livelist 载体·按真实树数与内部扇出重算）：那 21 个规模格就是判树高的栅格；树表条目 200、每层 81 棵重跑之后门槛与点查深度都在它那里。
- 用户定案（条目 36 一宽、共享树 day-1 注册），原话在变更史。

**欠**：C260（livelist 条目的预付没算进解开自己那个量）；C267（一个可写头在树表里没有一个能被指到的对象）。

#### 已定项 3：销毁可写头的第二个结构——要，ZFS 事件流形态，一棵共享树

**定案**：三件一起定。

1. **要**。销毁一个可写头要一个盘上的第二个结构，形态取 D5（快照 / 空间记账机制） 逐字的 ZFS livelist——ALLOC / FREE 配对、按 birth txg 分组、可增量、可 condense，**必须带 condense**。另三条候选都已出局：走遍历给不出写意图那一刻准入要的待删占用；复用稀疏旁表罩不到引用计数为 1 的块；功能缺失要撤一条已被下游消费的前提。
2. **FREE 在块被杀掉那一刻就记**，按出生晚于克隆时刻过滤，不等块真正被放。另一种做法下，打过快照又删掉快照的头会把同一个块放两次。
3. **载体取一棵共享树**，key 以头的树 ID 打头。每头一棵树并不更简单——它多出四样独有机制（头到 livelist 的链接、每次克隆建树、快照不带走 livelist、拆树），而共享树按头前缀删，走的是 D8（核心索引结构） 已定项 5 早就要求的范围删，逐字「范围删除直接丢弃整个节点，不用插 N 个墓碑」。每头一棵树换到的是点查浅 1–2 层、各头互不干扰。

**射程**：管这个结构要不要、什么形态、住哪，不管条目的 key 与宽度（已定项 2）。连带与代价：点查比每头一棵树深 1–2 层，所有头的条目住在一棵树里；树表第二层门槛共享树 39 头、每头一棵树 27 头；批前预留要的「这个头的 livelist 有多少条」不按前缀范围数、要一个每头计数器，而它只能住头的树表条目预留仅剩的 8 字节；用户最初那句「用空间换复杂度」对这一格不成立——共享树的 livelist 反而多占字节，换到的是更少的机制。靠 D5（快照 / 空间记账机制） 同日补的两条：还有自己活快照的可写头不许销毁；分叉点闸的 `children` 数克隆。本机 ZFS 源码 `dsl_dataset.c` 就在杀块路径上记 FREE——线索、未在本项目验证。⚠️ 门槛与点查深度的数取 E132（livelist 载体·按真实树数与内部扇出重算），它改正的是 E131（livelist 的两条载体，数值与代价）——后者按每头一棵数据树、没有池级树算，报的头数不能再引。

**依据**：

- E130（每头一份 livelist 过不过有界销毁）：验过 livelist 形态过已定项 8 的判据 5（有界销毁），条件是必须带 condense。
- E132（livelist 载体·按真实树数与内部扇出重算）：两条载体在真实树数与真实内部扇出下的树表层数门槛与点查深度。
- 用户定案（三件一起定，按第三轮对抗改正后的口径重判后取共享树），原话在变更史；三轮对抗的经过见 [decisions-history.md](../decisions-history.md) 与 [2026-09-10-D6项2三轮对抗.md](../../../records/2026-09-10-D6项2三轮对抗.md)。

**欠**：C271（livelist 的 FREE 在什么时刻记没有定义）；C267（一个可写头在树表里没有一个能被指到的对象）。

#### 已定项 4：把可写头退回到快照态，第一版不提供

**定案**：第一版没有「把一个可写头退回到它某个快照的状态」这个操作（ZFS 的 `rollback` 那一类）。要回到某个快照的状态，从那个快照克隆一个新的可写头（D5（快照 / 空间记账机制）「克隆 / 可写快照要加三条」，已定项 1 的每头一棵树下这是现成的动作），旧头照常按已定项 3 销毁。

**射程**：管第一版提不提供这个操作，不管以后怎么做。D23（journal 的角色与格式） 已定项 14 的管理员回退是全池按发布回退、载体是根环，不是这个操作。这样一来人类尺度的「退回旧状态」只剩克隆这一条，加上管理员回退；要收窄根环给管理员回退的那条承诺之前，先回来重看这一项。以后要做这个操作再立分项，那时要答：回退后原头的那些代怎么办、记账怎么跟、与实例代号 / 回退行怎么共存。

**依据**：无实验：C223（把可写头退回到快照态这个动作全仓没有定义） 立账时写明二选一——在这里定义这个操作，或写明第一版不提供并说明替代，而且写下「第一版不含」同样算还清；这是一次功能取舍，第一版没有这个操作、也就没有可量的量。用户定案取后者，原话在变更史。

**欠**：C223（把可写头退回到快照态这个动作全仓没有定义）。

#### 已定项 5：做多可写头，代价按「付查找」那条付

**定案**：**做多可写头，且付查找**——每删一个快照付 O(N) 次反向索引查找，换到的是多可写头加**不丢不漏**。另两条路都不取：不做多可写头（O(1) 保住、恒为 0 查找，但放弃这个功能）；做而拒绝付（多可写头 + O(1)，但**回收率归零**，不可用）。

**射程**：管做不做与代价怎么付，不管取哪条机制（已定项 1）。**销毁快照落在 `.claude/rules/fs-design.md` 三格纪律的第三格**（后台、可续做、非决策路径——无戒律）⇒ O(N) 遍历在这里是本工程纪律明确允许的。⚠️ 这句豁免的主语是**销毁快照**，被豁免的量是「每删快照 O(N) 次反向索引查找」；**它不覆盖销毁一个可写头**——D5（快照 / 空间记账机制） 逐字把销毁快照定义成「把它的 deadlist **合并到下一个更新的那一侧**……**不做全盘扫描**」，而销毁一个可写头要释放的是 `birth > origin.txg` 那批「散落全树」的块，两者不是同一条路径。也不构成「因此可写头那条路径必须有盘上结构」——第三格的理由列逐字是「它们走『写意图 → 分批 → 可续做』」，那是前置条件，落在已定项 2 上判。⚠️ 「归属原创建者」（btrfs squota 的机制）不能拿来做释放判定：squota 只管配额归属、不参与存活判定，两者不许互相引用。btrfs 那组 backref resolution 的数不适合直接搬来——本工程设计里没有那个东西（[prior-art.md](../prior-art.md) 已标为「只能当定性证据」）。

**依据**：

- E26（三种记账模型的查找代价与精度）：三种记账模型删一个快照要的反向索引查找次数逐档已量，付查找那条臂的 log-log 斜率说明付出的不是「贵一点」，是从常数掉进 O(N)；同一份产物里「归属原创建者」在多可写头 + 70% 共享下误放全部可写头，而误放是数据丢失方向。
- E18（D5 在多分叉 / 多可写头下是否报废）：「做而拒绝付」那条臂的泄漏率与「根本不记 death」逐位相同——它用「一块都不回收」换零数据丢失，不可用是实测判定的，不是推的。
- 用户定案「我坚持这是未来」——这是一次产品方向判断，不是从代价推出来的；取「付查找」那条的理由是 `.claude/rules/fs-design.md`「判据写不出来时，先只做一条，而且先做慢而正确的那条」。原话在变更史。

**欠**：C35（多可写头的 O(N) 没有优化过）。

#### 已定项 6：多可写头打掉的是 D5（快照 / 空间记账机制） 的 O(1) 性质，不是正确性

**定案**：D5（快照 / 空间记账机制） 那句「D6（快照实现模型） 若取多可写头候选，O(1) 性质失效」**已经被触发**。要读准的是：失效的是 **O(1) 性质，不是正确性**——数据丢失方向结构性为零（可证，不只是实测），失效表现为过判带来的空间泄漏与归属错。

**射程**：管「失效的是哪一半」，不管怎么把 O(N) 拉回去（已定项 10）。具体反例：主线 txg=10 建可写快照 X；在 X 里于 txg=30 写一个块（birth=30）；主线 txg=35 建快照 Y。按 D5（快照 / 空间记账机制） 的条件 `30 ≤ 35 < death` → 判「Y 引用它」，**而 Y 根本看不见它**（那个 key 挂在 X 的分支上）⇒ 过判 ⇒ 空间泄漏 + 归属错，**而 I-3.1（已分配统计对得上） 全绿**（块仍被恰好一处引用，总账平）——这正是已定项 8 条件 1 要挡的那个形状。

**依据**：

- E18（D5 在多分叉 / 多可写头下是否报废）：失效形态是「无界泄漏 + 回收率归零」，不是数据丢失；泄漏率与「根本不记 death」逐位相同。
- 用户定案随已定项 5 一起给，原话在变更史。

**欠**：C35（多可写头的 O(N) 没有优化过）。

#### 已定项 7：跨快照的部分覆盖第一版不产生 sub-unit 分片

**定案**：第一版**不产生分片**。D4（校验和位置） 已定项 3 的整单元读—改—写 + 已定项 7 的 extent 恒 = 单元 ⇒ 跨快照的部分覆盖走**整单元 COW**——快照留住旧的整单元、活版本写出一个全新的整单元，两边偏移都是 0，没有 sub-unit 共享。

**射程**：管第一版会不会出现跨快照的 sub-unit 分片，不管切分特性开了之后怎么办。D9（加密） 已定项 12 第 2 项「extent 距原始 extent 起点偏移」是为**切分**留的位，而切分是预留特性、第一版关闭 ⇒ 这一格第一版的代价是整单元 COW 的写放大，不是分片。「读路径恒定的祖先过滤开销」那一格在已定项 1 取 ② 之后不再存在，也从来没有重新记过账。

**依据**：无实验：这一格是从 D4（校验和位置） 已定项 3 / 已定项 7 与 D9（加密） 已定项 12 三条已定条款直接推出来的，第一版根本没有 sub-unit 共享这个对象，没有可量的量；要量得等切分特性开线，那时另立分项、另立实验。

**欠**：无。

#### 已定项 8：快照实现模型的九条判据

**定案**：**一个快照实现模型可以被采纳，当且仅当它同时满足这九条。** 这九条从机制与方法论推得，**不从任何决策的地位推得**——不许用「本候选破掉 D5（快照 / 空间记账机制） 的前提 ⇒ 采纳它则 D5（快照 / 空间记账机制） 失效」去否候选，那是条件句「D6（快照实现模型） → ¬D5（快照 / 空间记账机制）」，反着读就闭合成循环。

| # | 条件 | 依据 |
|---|---|---|
| 1 | **单一谓词**：存在唯一一个「S 引用 b」的谓词，**同时**驱动读可见性与空间回收 | 两个分歧方向后果不对称：可见集合大于记账集合 ⇒ **数据丢失**；反向 ⇒ 泄漏 + 归属错，而 I-3.1（已分配统计对得上） 构造上看不见。D5（快照 / 空间记账机制） 的保守默认纪律**只兜住后者** |
| 2 | **决策路径增量 + 独立审计**：进入准入控制 / ENOSPC / defer 判定的记账量提交时增量维护、代价不随盘容量增长；且有一条**与运行时不共享判定代码**的独立重算路径 | D3（空间分配） 的准入控制；C12（增量语义共用） 与它在 bcachefs 已发生的同源失效 |
| 3 | **边界对齐 + 完整视图**：快照点落在 checkpoint 边界、钉在本 checkpoint 全部数据变更之后；不存在「部分可见」或「用户可见但未发布」的快照 | D16（发布语义） 已定项 14。`birth` 分辨率只到 checkpoint ⇒ 块无法表达「我生在快照点之前还是之后」，`birth == S.txg`（数据丢失）与 `death == S.txg`（泄漏）**同时失去确定答案** |
| 4 | **有界创建**：单个 checkpoint 内原子完成，代价不随规模增长，且**不触碰任何已发布块的字节** | D8（核心索引结构）「无界必分批」× D16（发布语义）「快照点不许跨 checkpoint 边界」互斥。第二条腿来自 D9（加密）：触碰已发布块要重加密 ⇒ 新 nonce + MAC 变 ⇒ 沿引用改写到根 |
| 5 | **有界销毁**：可分批、可续做，每批最坏空间需求有界且可在批前预留 | D3（空间分配）「释放空间不需要申请空间」。⚠️ D5（快照 / 空间记账机制） 在这一格是用「分叉点快照不许销毁」这条功能缺失回避掉的，不是满足 |
| 6 | **不开第二套事务层**：不引入绕过 journal 的发布路径，不给提交协议增加结构性步骤 | 崩溃点的定义域就是事务层状态机 ⇒ 两套是**叉积**；且 D16（发布语义） 把崩溃语义定义成「根 + journal 任意前缀」，两个 journal 之间没有全序 ⇒ 规范本身无定义 |
| 7 | **可扫描重建**：快照集合与可见性判定的输入，能在只有「所有块 + 其自描述头」的条件下重建 | D13（验证路线） 已定项 12 的扫描式 checker 与 I-6.1（nonce 不重用） 阶段 ② 都建立在它上面 |
| 8 | **小规模可判**：正确性差异能在层 0 冒烟档规模上**被强制触发**，且有直接构造该状态的测试开关 | `.claude/rules/fs-design.md` 硬要求 2「进不去就等于没测」 |
| 9 | **标识不回收 + 布局无关**：**已发布的**快照标识单调不回收，位宽写进格式并声明生命周期内创建总数上界 | 回收一个快照 ID 会让盘上遗留的旧 key 在新快照里**变成可见**，与 C11（feature bit 跳号） 同型。布局无关那半来自 D12（目标介质） 与避坑第 13 条 |

**射程**：管候选进不进得了门，不管已经采纳的那条机制怎么演进。⚠️ **条件 9 的「已发布的」那四个字**限定的是射程：理由句的动词是「变成可见」，而可见性作用在**树里的 key** 上；从没发布成的 checkpoint 留下的孤儿单元不在任何树里，判它们的两道闸（已发布谓词、择新键）与孤儿回收条件都不看树 ID ⇒ 未发布过的标识被重发不落在这条判据的射程里。九条里有判别力的是 1、4、5、8，其余五条两侧对称或两侧都满足。

**依据**：

- E26（三种记账模型的查找代价与精度）：条件 1 的两个分歧方向后果不对称是量出来的——「归属原创建者」这个谓词在多可写头 + 70% 共享下误放全部可写头，而误放是数据丢失方向。
- E18（D5 在多分叉 / 多可写头下是否报废）：反方向（记账集合大于可见集合）的后果是无界泄漏 + 回收率归零，而 I-3.1（已分配统计对得上） 全绿——条件 1 那句「I-3.1（已分配统计对得上） 构造上看不见」的可数证据。
- 2026-08-26 三方论证：九条判据由那一轮定出，经过在变更史。

**欠**：C12（增量语义共用）：条件 2 要的「与运行时不共享判定代码的独立重算路径」今天没有会红的检查。

#### 已定项 9：六条假戒律不许用来否候选

**定案**：这张表里的六条被**故意排除**在已定项 8 的九条判据之外。用它们否候选，等于用一条本来就可以改的决策去否掉一个可能更好的模型。

| 不许用 | 为什么 |
|---|---|
| 「永不事后遍历」 | 它只约束**运行时决策路径**，且已在三处豁免：I-3.1（已分配统计对得上） 全盘遍历、D8（核心索引结构） 的意图分批、D13（验证路线） 已定项 8 的代际增量 scrub |
| 「I-3.1（已分配统计对得上） 是唯一手段」 | 已被 I-3.5（引用区间的精确性）「两条都必须有」与 C12（增量语义共用） 的已知盲区双向证伪 |
| 「必须是 birth txg + deadlist」 | 那是 D5（快照 / 空间记账机制） 的**实例**，判据只要求条件 1 的谓词一致性 |
| 「格式上多一个分支」 | 冻结前当期成本为零（`.claude/rules/format-evolution.md` 明说这条自由「要用足」），且本工程已经花过格式分支：D12（目标介质） |
| 「分隔 key 敏感」 | **敏感性是编码的函数，不是 btree 的性质**：把 dirent 的 name 分量换成 hash，D8（核心索引结构） 依赖的两件事都不受影响。⚠️ 此条为推理，未在本工程验证，也未核算 hash 编码在 readdir 顺序与冲突处理上的代价 |

**射程**：管这六条不许当否决理由，不管它们本身对不对——「永不事后遍历」在运行时决策路径上照样成立，这一项只禁止拿它去否快照实现模型的候选。

**依据**：无实验：六条各自的反例是已定条款与已有豁免（三处遍历豁免、I-3.5（引用区间的精确性） 的「两条都必须有」、格式冻结前的自由、夜间档），不是可量的量；要量的那一条（hash 编码在 readdir 顺序与冲突处理上的代价）本项自陈没算过，要用它先立实验。2026-08-26 三方论证定下这张表，经过在变更史。

**欠**：无。

#### 已定项 10：那条 O(N) 模型层已有优化，两笔限度还清之前实现按付查找走

**定案**：D5（快照 / 空间记账机制） 的「与上一个快照比 txg」本质是**链上的区间标号**；树上的推广是**嵌套区间标号**（preorder / postorder），把「子树里还有没有活快照」从遍历变成一次区间包含判定，再配一个**删除前沿**（每块记它在哪几个分支上被删了的极小反链，在「继承没发生」的那一步提交时就地记下——记账是事务的副产品）。这条路**模型层已验**。**两笔限度还清之前，实现仍按已定项 5 的付查找走。**

**射程**：管这条优化今天的地位（模型层已验、实现不换），不管什么时候换过去。两笔限度：① 树增长时标号要 order-maintenance / list-labeling 增量维护，成熟解法存在但本工程未验；② 事务层与真实反向索引上的实装复验含崩溃点重放，一步没走。「树还是 DAG」这一问由已定项 1 解掉——每头一棵树、克隆自单一 origin、无合并操作 ⇒ 谱系是树，不必碰 DAG 那档难度。

**依据**：

- E89（嵌套区间标号与删除前沿）：三条判据全中——候选臂全格子误放漏放恒 0（对着独立真值）；固定树上扩 extent 时付查找基线的反向查找随规模长而候选恒 0，前沿上界跟分支数走；Linear 拓扑下前沿退化回 D5（快照 / 空间记账机制） 的常数形态。前沿退化那条限度也由它量过，没超反链上界。
- E26（三种记账模型的查找代价与精度）：付查找基线那条 O(N) 就是它量出来的，是这条优化要拉回去的对象。

**欠**：C35（多可写头的 O(N) 没有优化过）：两笔限度（增量标号维护、事务层与真实反向索引上的实装复验含崩溃点重放）都记在它名下。
