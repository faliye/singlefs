## D6 快照实现模型 —— 待定（**不是低优先：它是 D5（快照 / 空间记账机制） 的隐藏前置**）

候选之一是 bcachefs 的「快照 ID 进 key 低位」：快照 ID 自成一棵树，
查找时按祖先关系过滤，不 clone 任何树，创建 O(1)，可有百万级快照。

代价：删快照要遍历所有带快照的 btree；读路径有恒定的祖先过滤开销；
写路径要处理 whiteout 和跨快照的部分覆盖分片。

⚠️ **这个候选的真实代价里有一条是 D5（快照 / 空间记账机制） 的 O(1) 性质（E18（D5 在多分叉 / 多可写头下是否报废） 实测，2026-08-28 第二轮）。**
多可写头之下 D5（快照 / 空间记账机制） 按其正文定义的 `death` 规则
**不会判死实活（数据丢失恒为零，可证）**，但**回收能力归零**——
8 个可写头档它与「根本不记 death」逐位相同，泄漏率 29.40%。
而要维护「最后一个活引用」需要每块的分支覆盖信息 = **引用计数**，正是 D5（快照 / 空间记账机制） 想省掉的。
⇒ **评估本候选时必须把「D5（快照 / 空间记账机制） 退化为引用计数」算进它的代价**；

**那个代价已量**（[experiments.md](../experiments.md) E27（三种记账模型的查找代价与精度），
2026-08-29，三轮字节一致，64 个快照 × 每快照 8 个 extent）：

| 拓扑 | 共享率 | 本决策所依赖的记账形态的反向索引查找 | 精确引用计数的查找 |
|---|---|---|---|
| 单向线性 | 0 / 30 / 70% | **0 / 0 / 0** | 8 / 10 / 28 |
| 多可写头 | 0 / 30 / 70% | **0 / 3 / 13** | 8 / 12 / 23 |

三条读法：

1. **D5（快照 / 空间记账机制） 的 O(1) 优势在单向线性下与共享率无关**——
   共享 70% 时仍是零查找。那才是它真正买到的东西。
2. **多可写头下这个优势按共享率退化**，共享 70% 时已经付到引用计数的一半多。
   **它破的是 O(1) 性质，不是正确性**——与 E18（D5 在多分叉 / 多可写头下是否报废）同结论。
3. **付了查找就不丢也不漏**：两条臂在全部六格里误放与漏放都是 0。
   ⇒ 多可写头下**不泄漏，只要肯付那些查找**；E18（D5 在多分叉 / 多可写头下是否报废）量到的 29.40% 泄漏是「拒绝付」的变体。

⚠️ **btrfs 那组数（提交时间 +76%、事务等待 +1347%、写吞吐 −25%）不适合直接搬来**：
btrfs qgroup 慢的根源是它自己的 backref resolution，本工程的设计里没有那个东西；
[prior-art.md](../prior-art.md) 已把它标为「不可当作本工程的性能预期，只能当作定性证据」。

⚠️ **「归属原创建者」（btrfs squota 的机制）不能直接拿来做释放判定**：
E27（三种记账模型的查找代价与精度）实测它在多可写头 + 70% 共享下**误放全部 8 个**，
而误放是数据丢失方向。squota 本身只管配额归属、不参与存活判定，算错只是配额不准——
**两者不许互相引用**。
但**这是泄漏方向，不是数据丢失方向**，权重比数据丢失方向低一个量级。

⚠️ **这三条代价里有两条要重新记账（2026-08-26）：**

1. **「删快照要遍历」这一笔，D5（快照 / 空间记账机制） 侧同样欠着，而且已被记为「已付」。**
   D5（快照 / 空间记账机制） 正文自陈：「**不承认它（livelist），本决策『永不事后遍历』这条核心性质
   在这条路径上就是假的**」——要释放的是 `birth > origin.txg` 的那批块，散落全树。
   **同一笔账在 D5（快照 / 空间记账机制） 侧记成「已接受的代价」，在本决策侧记成「否决理由」，这是不对称记账。**
   另见 D8（核心索引结构） 已定的布局规则：「同一快照的 key 带同一 snapshot 前缀 →
   删快照**有机会变成范围操作**」，而范围删除「直接丢弃整个节点，根本不用插 N 个墓碑」。
2. **「跨快照的部分覆盖分片」这一笔已经被 D9（加密）预付了。**
   D9（加密）day-1 预留字段第 2 项「extent 的**距原始 extent 起点偏移**」，
   立项理由正是「extent 被切分后重写时无法既不重用 nonce 又不重算」。
   ⇒ **这条代价对本决策不是新增的，是一个已经花掉的格式位。**

**注意它和 D-写路径优先的耦合**：这个选择会显著改变提交路径的复杂度，
即"第一段代码长什么样"。真要采用就得早定；不采用则可以一直拖。

现状：**不作为默认方案，仅作候选。**

### 快照实现模型的戒律：九条判据（2026-08-26 三方论证）

**这九条是判候选用的，不依赖任何一条决策的既有地位。**
**不许用「本候选破掉 D5（快照 / 空间记账机制） 的三条前提 ⇒ 采纳它则 D5（快照 / 空间记账机制） 失效」那种形状去否它**——
那是条件句「D6（快照实现模型） → ¬D5（快照 / 空间记账机制）」，把它读成「D5（快照 / 空间记账机制） 已定 ⇒ ¬D6（快照实现模型）」就闭合成了循环。
**这九条从机制与方法论推得，不从任何决策的地位推得。**

> **一个快照实现模型可以被采纳，当且仅当它同时满足这九条。**

| # | 条件 | 依据 |
|---|---|---|
| 1 | **单一谓词**：存在唯一一个「S 引用 b」的谓词，**同时**驱动读可见性与空间回收，两者在代码上是同一个定义 | 两个分歧方向后果不对称：可见集合大于记账集合 ⇒ 可见的块被判可释放 ⇒ **数据丢失**，且空间一旦复用就退化成「校验和不匹配、原因不明」；反向 ⇒ 泄漏 + 归属错，而 **I-3.1（已分配统计对得上） 构造上看不见**。D5（快照 / 空间记账机制） 的保守默认纪律**只兜住后者** |
| 2 | **决策路径增量 + 独立审计**：进入准入控制 / ENOSPC / defer 窗口判定的一切记账量，提交时增量维护、代价不随盘容量增长；且存在至少一条**与运行时不共享判定代码**的独立重算路径 | D3（空间分配） 准入控制「进门前先算」+「释放空间本身不需要申请空间」；[checks-owed.md](../checks-owed.md) C12（增量语义共用） 与它在 bcachefs 已发生的同源失效 |
| 3 | **边界对齐 + 完整视图**：快照点落在 checkpoint 边界、钉在本 checkpoint 全部数据变更之后；不存在「部分可见」的快照；不存在「用户可见但未发布」的快照 | D16（发布语义） 新规则 1 与「根 + journal 任意前缀」。`birth` 的分辨率只到 checkpoint，**块无法表达「我生在快照点之前还是之后」** ⇒ D5（快照 / 空间记账机制） 边界表里 `birth == S.txg`（数据丢失）与 `death == S.txg`（泄漏）**同时失去确定答案** |
| 4 | **有界创建**：在单个 checkpoint 内原子完成，代价不随文件系统规模增长，且**不触碰任何已发布块的字节** | D8（核心索引结构）「无界必分批」× D16（发布语义）「快照点不许跨 checkpoint 边界」**互斥** ⇒ 创建不许无界。第二条独立的腿来自 D9（加密）的 MAC / nonce / 密文校验和：触碰已发布块要重新加密 ⇒ 新 nonce + MAC 变 ⇒ 沿引用改写路径到根 |
| 5 | **有界销毁**：可分批、可续做，每批最坏空间需求有界且可在批前预留 | D3（空间分配）「释放空间不需要申请空间」+ 准入控制形态。⚠️ **D5（快照 / 空间记账机制） 在这一格是用「分叉点快照不许销毁」这条用户可见的功能缺失回避掉的，不是满足**；本决策候选侧的对应答案从未被要求给出——**这一格两边的账都还没合** |
| 6 | **不开第二套事务层**：不引入绕过 journal 的发布路径，不给提交协议增加结构性步骤 | 崩溃点的定义域就是事务层状态机 ⇒ 两套是**叉积**不是两倍；且 **D16（发布语义） 把崩溃语义定义成「根 + journal 任意前缀」，两个 journal 之间没有全序，「任意前缀」失去指称对象——规范本身无定义** |
| 7 | **可扫描重建**：快照集合与可见性判定的输入，能在只有「所有块 + 其自描述头」的条件下重建（可靠冗余达成，但必须显式说明冗余在哪） | 「元数据块必须自描述」的第二条腿：D13（验证路线） 的扫描式 checker 方向与 I-6.1（nonce 不重用） 阶段 ② 都建立在它上面，**没有自描述，第二个方向在物理上不存在** |
| 8 | **小规模可判**：正确性差异能在层 0 冒烟档规模（小镜像、少快照、写请求数两位数）上**被强制触发**，且有直接构造该状态的测试开关 | `.claude/rules/fs-design.md` 硬要求 2「进不去就等于没测」 |
| 9 | **标识不回收 + 布局无关**：快照标识单调不回收，位宽写进格式并声明**生命周期内创建总数**上界；可见性与生命周期语义不依赖任何布局参数 | 回收一个快照 ID 会让盘上遗留的带该 ID 的旧 key 在新快照里**变成可见**——与 C11（feature bit 跳号） 拦 feature bit 位号回收的失效同型。布局无关那半来自 D12（目标介质） + 避坑第 13 条（ZFS raw send 因认证结构变形而长期出 bug） |

#### 被**故意排除**在判据之外的六条（假戒律）

用它们否候选，等于用一条本来就可以改的决策去否掉一个可能更好的模型。

| 不许用 | 为什么 |
|---|---|
| 「永不事后遍历」 | 它只约束**运行时决策路径**。本工程已在三处豁免它：I-3.1（已分配统计对得上） 全盘遍历、D8（核心索引结构） 的意图分批、D13（验证路线） 的代际增量 scrub。**一条被三次豁免的规则，判据不在它自己写的那个量上** |
| 「I-3.1（已分配统计对得上） 是唯一手段」 | 已被 I-3.5（引用区间的精确性）「两条都必须有」与 C12（增量语义共用） 的已知盲区双向证伪 |
| 「必须是 birth txg + deadlist」 | 那是 D5（快照 / 空间记账机制） 的**实例**，判据只要求条件 1 的谓词一致性 |
| 「格式上多一个分支」 | 冻结前当期成本为零（D12（目标介质） 债表第 6 项自陈；`.claude/rules/format-evolution.md` 明说这条自由「**要用足**」）。而且本工程已经花过格式分支：D12（目标介质） |
| 「分隔 key 敏感」 | **敏感性是编码的函数，不是 btree 的性质**。把 dirent 的 name 分量换成 name 的 hash，D8（核心索引结构） 依赖它的两件事都不受影响（范围删除靠 `parent_inode` 前缀、点查靠精确键）。⚠️ 此条为**推理，未在本工程验证**，也未核算 hash 编码在 readdir 顺序与冲突处理上的代价 |
| 「总验证量太大 / 门禁跑不完」 | D13（验证路线） 已把无界验证量放进夜间档，**挂钟只约束快速档**——那一半已收进条件 8 |

#### 这套判据对本决策候选的判别力

**九条里有判别力的是 1、4、5、8，其余五条两侧对称或两侧都满足。**

其中条件 1 上，「快照 ID 进 key 低位」这个候选**目前给不出 O(1) 局部可判定的归属谓词**：
「谁覆盖了我」不在块自己或它的直接父指针里，它散落在整个数据树里同逻辑 key 的其它版本上；
要算归属必须按剥掉快照后缀的逻辑 key 分组、配合快照树的祖先关系全局重建。
**那是一次全局重建，而 [invariants.md](../invariants.md) 明写只有 I-3.1（已分配统计对得上） 才准全盘遍历**，
且该重建的算法骨架与遍历式方向高度雷同，**两条本该独立的路径独立性打折**。

⚠️ **这是「戒律排除该候选的现有形态」，不是「D5（快照 / 空间记账机制） 排除它」。**
该候选若要成立，路径是明确的：**先给出一种让归属判据重新局部化的格式设计**
（例如显式的反向覆盖记录），并证明它能增量维护、能崩溃恢复。
而那个反向记录在多可写头、多分叉下**不是一个标量而是一个变长集合**，这一层从没人回答过。

#### 顺带揪出 D5（快照 / 空间记账机制） 欠的一条格式要求

扫描式 checker 在 D5（快照 / 空间记账机制） 形态下能成立，靠三条：`birth` 内联在指针里 ✓、
deadlist 自身是可扫描的自描述树 ✓、**快照列表必须是可枚举的持久结构** ✓（[invariants.md](../invariants.md) I-3.7（活快照可枚举），checker 未实现）。
**第三条至今没有被写成格式要求**（全文只有一处顺带提及「查快照列表」）。
拿不到全部根的 txg 列表，扫描式 checker 的归属判定就做不了。

### 它为什么是 D5（快照 / 空间记账机制） 的隐藏前置（2026-08-26）

D5（快照 / 空间记账机制） 的机制成立依赖四条前提，其中三条被本候选直接破掉：

| D5（快照 / 空间记账机制） 的前提 | 「快照 ID 进 key 低位」下 |
|---|---|
| 快照 = 一个已发布过的根，「被 S 引用」= 从 S 的根可达 | **破**。只有一棵树，可见性由快照 ID 树上的祖先关系决定，快照根本不是一个根 |
| 快照按 txg 全序，只有一个可写头 | **破**。该模型的卖点就是廉价的**可写**快照 ⇒ 多个可写头 |
| 一个块的死亡是一个事件（一个标量） | **破**。在分支 Y 上删 key 是插一个 whiteout，块在分支 X 上仍活着 ⇒ death 变成快照树上的一个函数 |

**具体反例**：主线 txg=10 建可写快照 X；在 X 里于 txg=30 写一个块（birth=30）；
主线 txg=35 建快照 Y。用 D5（快照 / 空间记账机制） 的条件：`30 ≤ 35 < death` → 判「Y 引用它」。
**事实是 Y 根本看不见它**（那个 key 挂在 X 的分支上）。方向是**过判 ⇒ 空间泄漏 + 归属错，
而 I-3.1（已分配统计对得上） 全绿**（块仍被恰好一处引用，总账平）。

⇒ **本候选一旦采纳，D5（快照 / 空间记账机制） 的 birth txg + deadlist 机制失效**，
必须换成「per-extent 引用计数 + 提交时触发器维护」那一套，
checker 侧换成「全量遍历重建计数」。

**所以本决策的定级从「低优先」改为「D5（快照 / 空间记账机制） 的隐藏前置」。**
本决策正文原有的理由（会显著改变提交路径复杂度）仍然成立，但那不是最硬的理由——
最硬的是：**它决定 D5（快照 / 空间记账机制） 这条已定决策还成不成立。**

⚠️ **顺带一条 kb 精度修正**：D5（快照 / 空间记账机制） 用 bcachefs「记账由触发器在 key 提交时维护、不靠遍历」
来做独立印证。**那条印证成立的层次是「增量维护 + 遍历校验」这个模式，不是
「birth txg + deadlist」这个机制**——bcachefs 没有 deadlist。已在 D5（快照 / 空间记账机制） 正文加限定。
