## D5 快照 / 空间记账机制 —— 已定（正确性成立；**O(1) 性质已因 D6（快照实现模型） 取多可写头而失效**，退化为每删快照 O(N) 次反向索引查找）

**采用 ZFS 的 birth txg + deadlist 模型。**

- 每个块自带**诞生代号**（birth txg）。
- 删除时，把块的代号和**活头记录的 `prev_snap_txg`**（上一个快照的代号）比：
  `birth > prev_snap_txg` → **直接释放**；否则 → 追加进**活头自己的 deadlist**。
- 建快照时，把**活头的 deadlist 整个交接给新快照**，活头换一个空的。
- 销毁快照时，把它的 deadlist **合并到下一个更新的那一侧**，并按
  `birth > prev(S).txg` 过滤出可释放的条目。不做全盘扫描。

**引用区间的充要条件**（本决策的可判定形式）：

> **块 b 被快照 S 引用 ⟺ `birth(b) ≤ S.txg < death(b)`**，左闭右开。

三个量的定义各有一处容易差一，必须钉死：

| 量 | 定义 | **不是**什么 |
|---|---|---|
| `birth(b)` | 块被**发布**的那个 checkpoint 号 | 不是写请求发出时所在的开放 txg——崩溃后该号会被重发 |
| `death(b)` | 最后一个活引用被摘掉、**且该摘除被发布**的 checkpoint 号；仍在活树里则为 ∞ | **不是** `rm` 返回的时刻（D8（核心索引结构） 走意图分批），**也不是**空间变得可再分配的时刻（见 D16（发布语义） 新规则 2） |
| `S.txg` | **S 捕获的最后一个已发布 txg** | 不是「创建操作所在的 txg」 |

`S.txg` 必须取第二种定义，理由是机制性的：`birth` 的分辨率只到 checkpoint，
若取「创建操作所在 txg」，条件会随「快照点放在 checkpoint 头还是尾」在
`birth ≤ S.txg` 与 `birth < S.txg` 之间跳。**定义要选那个让不变量不随实现位置摆动的。**

**三个边界，取错的后果不对称**：

| 边界 | 判定 | 取错的后果 |
|---|---|---|
| `birth == S.txg` | S **引用**它 | 写成 `birth < S.txg` → 判为「比快照新」→ 立即释放 → **数据丢失** |
| `death == S.txg` | S **不引用** | 写成 `S.txg ≤ death` → 挂在不需要它的快照上 → **空间泄漏 + 归属错** |
| `birth == death` | 任何快照都不引用，可立即释放 | 记账上对，但**物理空间不许在本 checkpoint 内复用**，见 D16（发布语义） 新规则 2 |

⚠️ **「三个边界，取错的后果不对称」那张表读起来像三处独立的笔误，实际不是**（[experiments.md](../experiments.md)
E28（D5 三条可建模的风险路径）实测，2026-08-29）：把右边界写成 `S.txg ≤ death`
**同时命中两行**——`death == S.txg` 与 `birth == death` 两格都会被判成「引用」。
⇒ **一个笔误造成两处泄漏，不是一处。** 两种取错的失败方向确实相反
（写严左边界只造成数据丢失 1 处、写闭右边界只造成泄漏 2 处，零交叉），
那一半正文说对了。

⚠️ **保守默认纪律：判据的任何一个输入取不到或不确定时，默认必须是「进 deadlist」。**
泄漏可被 **I-3.6（deadlist 紧界）** 检出（⚠️ **不是 I-3.1（已分配统计对得上）**——invariants.md 明写「归属错误对它不可见……总账依然平」）、可回收、伤害有上界；
而丢失不可逆，且一旦空间被复用就退化成「校验和不匹配、原因不明」——**连归因都没了**。

### 那个「条件」是 O(1) 条件，不是正确性条件（E18（D5 在多分叉 / 多可写头下是否报废） 实测，2026-08-28 第二轮）

`birth(b) ≤ R.txg < death(b)` 这个谓词，**只在 txg 全序（单向线性历史）时等价于可达性**。
[experiments.md](../experiments.md) E18（D5 在多分叉 / 多可写头下是否报废） 实测：

| 历史形状 | 判死实活（数据丢失） | 判活实死（泄漏） | 「永不记 death」的泄漏 |
|---|---|---|---|
| 线性（阳性对照） | **0** | **0** | — |
| 一次分叉 | **0** | 8.19% | 8.44% |
| 8 个可写头 | **0** | **29.40%** | **29.40%（逐位相同）** |

**按本决策定义表里的 `death`（「最后一个活引用被摘掉」），分叉下判死实活恒为零**——
truth 为真 ⇒ 块在该根的链上没死 ⇒ 不满足「所有分支都删过」⇒ `death = ∞`
⇒ 区间判定必为真。**这是可证的，不只是实测。**

⚠️ **但代价是回收能力归零。** E18（D5 在多分叉 / 多可写头下是否报废） 实测：8 个可写头档，正确的规则与
「**根本不记 death**」**逐位相同**（泄漏率均为 29.40%）——
它用「一块都不回收」换来零数据丢失。
而要维护「是不是最后一个活引用」，需要的正是每块的分支覆盖信息 = **引用计数**，
**正是本决策想省掉的那个东西**。

⇒ **本决策标题里那个条件是 O(1) 条件，不是正确性条件**：
D6（快照实现模型） 若取多可写头候选，本决策的失效形态是**无界泄漏 + 记账退化到引用计数**。
**泄漏可被 [invariants.md](../invariants.md) **I-3.6（deadlist 紧界）** 检出（⚠️ **不是 I-3.1（已分配统计对得上）**——invariants.md 明写「归属错误对它不可见……总账依然平」，抓泄漏方向的是 I-3.6（deadlist 紧界））、可回收、伤害有上界，
而数据丢失不可逆**——两者在 D6（快照实现模型） 的候选评估里权重差一个量级。

### 级联方向：并到更新的那一侧（约定 B）

**依据（机制，不是照抄）：两种约定的差别是「改写已发布快照 deadlist 的频率」，不是「改不改写」。**

- 另一种约定（删除时挂给更老的快照）：**每一次 kill** 都要往一个已发布快照的 deadlist 里追加。
- 约定 B：kill 只追加到**活头自己的**结构；已发布快照的 deadlist **只在销毁级联时**被改写一次。

⚠️ **约定 B 并没有做到「快照的 deadlist 永不改写」**——销毁级联的目标
`dsl_deadlist_merge(&ds_next->ds_deadlist, ...)` 里，`ds_next` 本身就是一个快照。
本决策采用约定 B 的理由是**例外更少**（从「每次 kill」降到「只在销毁时」），
不是「没有例外」。对一个把「已发布的根不可变」当作根本前提的工程，
少一个数量级的例外仍然值得，但这个前提在这条路径上**确有例外，必须写明**。

ZFS 实现的是约定 B（2026-08-26 现查 `module/zfs/dsl_destroy.c`）：
`/* Merge our deadlist into next's and free it. */` 配 `dsl_deadlist_merge(&ds_next->ds_deadlist, ...)`。

### 本决策只覆盖四条前提，越过任何一条它就失效

1. **线性历史**（无分叉）；2. **单一可写头**；3. **每个块在活树里至多一个活引用**；
4. **快照点与 checkpoint 边界对齐**（见 D16（发布语义） 新规则 1）。

**前提 3 与 reflink / dedup / 块克隆机制上不相容。** 有第二个活引用时，
摘掉其中一个不构成 death，而判据只看 `birth` 与 `prev_snap_txg`，
两个引用的 birth 完全相同 ⇒ **第一次摘除就判「立即释放」⇒ 另一个引用悬空 ⇒ 数据丢失**。
这不是假想：ZFS 二十年没有 reflink，直到 2023 年的 block cloning 才补，
而且补的方式是**另加一张带引用计数的表**，不是扩展 birth/death。
⚠️ **任何引入「同一块的第二个活引用」的特性，必须先重开本决策。**

**但重开不等于推翻——本工程自己量过了**（[experiments.md](../experiments.md) E12（攒批的顺序追加 vs 不攒批的随机页读改写），N=5 轮、五个不同种子、每档 200000 次删除，
并有块层独立读数校验）：

**20 万次删除一共触发多少次设备 I/O（中位，五个不同种子）**

| | 计数器表装得进缓存 | 2× 缓存 | 8× 缓存 |
|---|---|---|---|
| **本决策（时间序推导）** | **2** | **2** | **2** |
| **全域引用计数** | 512 | ~200,208 | ~350,042 |
| **本决策 + 稀疏旁表**（clone 率 1‰） | 508 | ~1,956 | ~3,466 |

**这组数经过块层独立校验**：每臂前后读一次虚机内 `/sys/block/vda/stat`（内核自己数的，
与被测程序的计数器不共享代码、采样或工具），**九个格子比值全部 1.00**——
由此确认 O_DIRECT 真的绕过了缓存、块层没有合并或拆分请求、没有预读。

三条读法：

1. **转折是陡的。** 计数器表一旦装不下缓存，引用计数从「几乎免费」跳到约 1 次设备 I/O 每删除。
   **而本决策这一侧完全不动**——它没有计数器可查，这正是它的全部价值。
2. **装得下时引用计数几乎免费**（那 256 次读写是一次性冷启动填充）。
   **这是合法结果，不是实现 bug**——它说明本决策的优势条件是「计数器表装不下缓存」，
   而不是无条件成立。
3. **所以正确形态是「本决策为主 + 稀疏旁表为辅」**（ZFS 的 BRT 形态），
   不是把本决策换成全域引用计数。1‰ clone 率下稀疏旁表把代价压回 0.0172，约 100 倍。

⚠️ **外推边界**：E12（攒批的顺序追加 vs 不攒批的随机页读改写） 的探测用的是**内存全域位图、每块 1 bit**——真实文件系统上
≈ 128 MB/TB，**本实验高估了旁表在大盘上的表现**。**换成真正的稀疏结构必须重测。**

⚠️ **局部性这一条已经量出来了，不再只是标注**：把删除序列从均匀随机换成顺序，
引用计数的 8× 档从 174,998 次 I/O 掉到 **391 次（448 倍）**。
**引用计数的代价高度依赖访问局部性**——真实负载有局部性时，本决策的优势会显著小于
E12（攒批的顺序追加 vs 不攒批的随机页读改写） 主表里那个数量级。这一条必须与主结论一起引用。

⚠️ **这套测量本身做过故障注入**：摘掉 `O_DIRECT` 后块层读数归零而程序计数器不变，
证明「块层与程序计数器比值 1.00」这条校验有判别力、不是摆设。详见 E12（攒批的顺序追加 vs 不攒批的随机页读改写）。
另外 E12（攒批的顺序追加 vs 不攒批的随机页读改写） **不回答** checker 代价与崩溃一致性——那两笔账不在它射程内。
⚠️ **[checks-owed.md](../checks-owed.md) C12（增量语义共用） 那类盲区对本决策同样成立**：
本决策的记账（空间统计、快照用量）也是靠一串 `+=` 增量维护出来的——
**C12（增量语义共用） 关心的是「记账是不是靠增量维护」，与生命周期判定用 birth txg 还是引用计数无关。**

**克隆 / 可写快照要加三条**（前提 1、2 被越过时）：

1. 每个可写头各持一份 `prev_snap_txg` 与一份 deadlist，
   **新克隆的 `prev_snap_txg` 必须初始化为 origin 快照的 txg**——
   置 0 的话，克隆里删一个继承来的老块会算出「立即释放」而 origin 还引用着它，**数据丢失**。
2. **分叉点快照不许销毁**（约定 B 的「并到更新那一侧」在分叉点没有唯一的 next）。
   判据是 O(1) 的子计数：`children > 1` → 拒绝。ZFS 就是这么做的
   （`dsl_destroy_snapshot_check_impl`：`/* Can't delete a branch point. */`）。
3. **销毁一个可写头需要第二个结构**（ZFS 的 livelist 形态：ALLOC/FREE 配对、
   按 birth txg 分组、可增量、可 condense）。**不承认它，本决策「永不事后遍历」
   这条核心性质在这条路径上就是假的**——要释放的是 `birth > origin.txg` 的那批块，散落全树。

### 运行时判定是 O(1)，而且这个 O(1) 要证

```
判定(ptr):
    birth = ptr.birth              // 指针内联字段，零次额外 I/O
    p     = head.prev_snap_txg     // 活头头部一个标量，常驻内存
    if birth > p:  立即释放 → 进 defer 队列（不是直接进空闲表，见 D16 新规则 2）
    else:          追加进 head.deadlist
```

**归约证明**：设删除发生在 checkpoint `d`，P 为此刻最新的快照。
(⇐) 若 `birth ≤ P.txg`：P 已发布 ⇒ `P.txg < d = death` ⇒ `birth ≤ P.txg < death`，∃S 引用它。
(⇒) 若 ∃S：`birth ≤ S.txg < d`，则 S 在删除时已存在 ⇒ `S.txg ≤ P.txg` ⇒ `birth ≤ P.txg`。∎

**归约只用了两件事**：txg 全序（所以「比最新的老」蕴含「比所有的老」），
以及**判定必须发生在死亡那一刻**（所以未来的快照被 `death < S.txg` 自动排除）。
⚠️ **这两条哪一条破了，O(1) 就没了**——D6（快照实现模型） 的候选破第一条，D8（核心索引结构） 的分批删除破第二条。

**销毁快照的代价是 O(deadlist 条目数 + 桶数)，不是 O(全盘)**，
前提是 deadlist **按 birth txg 分桶、桶边界 = 快照 txg**，否则销毁时的过滤退化成全表扫描。

### 与 D8（核心索引结构） 分批删除的交互：待删除结构算作活引用

D8（核心索引结构） 已定无界删除走「写意图 → 分批 → 可续做」，于是**判定发生在物理批次那一刻，
而逻辑死亡早得多**——归约的第二个前提被破。**本决策取的处置是：
待删除结构（意图 key、删除中队列）算作活引用**，于是 `death` = 物理批次的 checkpoint，
判定天然发生在死亡那一刻，**O(1) 保住，且不需要新增任何不变量**。

代价是一个用户可见的现象：`rm` 返回之后建的快照会**钉住**那批尚未释放的 extent，
`df` 要等快照死了才回来。这一条已被 [invariants.md](../invariants.md) I-3.4（可用空间扣待删占用） 与 I-4.7（删除中 inode 有账） 部分覆盖，
且 D8（核心索引结构） 正文已经点名过「我删了一大堆 `df` 却不动」这类现象。

**另一条路（把待删除结构算作已死）会破坏 O(1)**：
正确的 deadlist 属于「逻辑死亡之后建的第一个快照」，
而那个快照在写意图时还不存在，无法预存，只能在批次执行时查快照列表。

**核心性质：记账是增量维护出来的，不是事后遍历出来的。** 这是本决策的全部价值。

**独立印证（2026-08-26）**：bcachefs 的记账「由触发器在 key 提交时维护，
不靠遍历 btree」，而其 `check_allocations` 用全量遍历重建记账，
以此分辨「计数器过期」和「key 真的还在」。
这与 [invariants.md](../invariants.md) 的 I-3.1（已分配统计对得上） 是同一个设计。

⚠️ **这条印证成立的层次是「增量维护 + 遍历校验」这个模式，不是「birth txg + deadlist」
这个机制**——**bcachefs 没有 deadlist**。不许把它读成机制层的印证。
另见 [prior-art.md](../prior-art.md) 7.11：bcachefs 那套遍历校验**与运行时共用同一段加减代码**，
因此抓不到「语义本身写错」——本工程不许照搬那个形态。

以及判定发生在死亡那一刻。**它是证明，不是测量。**

⚠️ **本决策目前没有针对它自己的实测。** [experiments.md](../experiments.md) E12（攒批的顺序追加 vs 不攒批的随机页读改写）

销毁快照的级联合并（按 birth 分桶的开销）、崩溃重放、以及 defer 队列的持久化代价。
稳态 kill 路径不在其中，因为**那条路径本来就没人怀疑**。

### 第二依据（别家记录，口径要看清）

btrfs qgroup 走 extent refcount + 反向索引遍历，代价是提交时间 +76%、
事务等待 +1347%、写吞吐 −25%（数据来自 btrfs 官方，见 [prior-art.md](../prior-art.md)）。
btrfs 自己另出了 squota（不算全局 refcount，只归属原创建者）。

⚠️ **这组数字的口径是「qgroup 走反向索引」，不是「纯引用计数」**，
拿它直接支撑本决策会夸大。**它只能作为旁证。**
比它硬的是本决策引用的 [experiments.md](../experiments.md) E12（攒批的顺序追加 vs 不攒批的随机页读改写），但**两者量的都是「全域引用计数有多贵」，不是本决策自己的机制对不对**——
本决策自己的实测仍然欠着，见「本决策的依据：机制推导（尚无本决策自己的实测）」。

**与 D9（加密）的连锁**：birth txg **不能**当加密 nonce——同一事务里的块共享它，nonce 会重复。

### 未定项

**计数器的载体形态。** ⚠️ **阻塞第一行事务层代码**（2026-08-29 对抗验证补入）：
第一个事务必须落一次记账（D21（权威态与派生态的分界） 权威态 = 单元 + 记账 + 根，
且 `.claude/rules/fs-design.md` 要求提交时增量维护），而本项答的是「记账记录长什么样」——
**它与 D22（单元原子性怎么合成） 未定项 3（记账结构是不是 COW）是同一格的两半，缺任一半那几十个字节都写不出来。**
bcachefs 2024 年把计数器做成 btree 里的 key
（tagged union，加新统计维度不用改格式），是个值得采用的形态，但与 D8（核心索引结构） 耦合，等 D8（核心索引结构） 定。
