## D10 True Answer to Random Writes / Fragmentation —— Settled

[中文](10-随机写-碎片化的真答案.md) · **English** · [日本語](10-随机写-碎片化的真答案.ja.md)

D10 (True Answer to Random Writes / Fragmentation) governs one thing: where to place our bet on random writes on databases and VM images—the shared soft underbelly of COW. What it does not govern: the form, triggering, transactions, and accounting of that answer, all of which reside in D26 (Background Compaction and Placement Reclamation)—what the two legs of fragmentation are, how compaction starts and stops, what form structural anti-aging takes, and how reclamation divides into two tracks are all items in that decision; whether message buffers remain resides in D11 (Message Buffers in Index Nodes); when node formats freeze resides in D15 (Format Freeze Policy) and D8 (Core Index Structure).

#### Settled Item 1: The answer to fragmentation is given by this project itself, not bet on device interfaces

**Settled**: **The answer to fragmentation is given by this project itself.** Candidate B (structural anti-aging) and "in-house placement and reclamation" two legs are **superimposed**, not an either-or choice; NVMe FDP / ZNS is demoted to "use-if-available acceleration". **The authoritative text is in D26 (Background Compaction and Placement Reclamation)**—basis, form, all sub-items, and ramifications are over there; D10 (True Answer to Random Writes / Fragmentation) records only the single sentence on "where the answer is placed".

**Scope**: Governs where the answer is placed, not what the answer looks like. btrfs's `nodatacow`—disabling COW at the expense of losing both checksums and snapshot consistency—is the kind of trade this item rejects; this project does not accept dodging issues with configuration toggles. D26 (Background Compaction and Placement Reclamation) Settled Item 7 settles that reclamation divides into two tracks (delegated to the disk when disk FTL is good enough, without building an FTL in the software layer); this is opposite in direction to Candidate C: Candidate C hands placement and GC to the **host**, while Settled Item 7 leaves reclamation in the **disk**'s own FTL. "Superposition" is the current settled item, not final; degradation verdict relies on the exact rule written in E10 (Aging: Structural Resistance vs Post-hoc Compaction), which has not run.

**Basis**:

- E93 (Placement and Fragmentation Under Aging): Clustered segment policy is not self-sustaining without compaction feeding empty segments, neighbor rewrites have a ceiling, while compaction steadily declines with budget—the in-house leg bears load, not an optional acceleration; this is the measurable half of "the answer is given by this project itself".
- User decision (2026-09-01): Betting the answer to fragmentation on device interfaces is unreliable—on devices without FDP / ZNS support, it is equivalent to having no answer, and D12 (Target Media) settled not capping media classes in advance => those are not corner cases, but mainstream media. Original words in changelog.

**Owed**: None.

#### Settled Item 2: Respective status of the three candidates

**Settled**: The respective status of the three candidates is:

| Candidate | Mechanism | Status |
|---|---|---|
| **A: Absorb small writes into index message layer** | Bε-tree internal node message buffers: small writes do not land on data blocks, buffered in tree first and flushed in batches | **Not adopted as answer to D10 (True Answer to Random Writes / Fragmentation).** ⚠️ What is abandoned is "taking message layer absorption as the answer to this item", not "not implementing message buffers"—D11 (Message Buffers in Index Nodes) Settled Item 1 settled "retain", which is ε amortisation for update paths, a separate benefit from random write absorption |
| **B: Structural anti-aging** | Enable the index itself to preserve scan locality after aging, reducing post-hoc compaction burden | **Adopted**; form settled by D26 (Background Compaction and Placement Reclamation) Settled Item 4: do not store group identity in node header, do not alter index node internal layout, placement group computed solely from key |
| **C: Hand over to device** | NVMe FDP / ZNS hands data placement and GC responsibility to host, reducing device-side write amplification | **Demoted to acceleration**: used if FDP / ZNS is available; absence does not affect whether the answer holds |

**Scope**: These three candidates originated from the 2026-08-26 literature survey. Governs the respective status of the three candidates, not how B's form is implemented (D26 (Background Compaction and Placement Reclamation) Settled Item 4), nor whether message buffers are retained (D11 (Message Buffers in Index Nodes)). Existing evidence and unknowns for the three candidates (BetrFS FAST 2018 4-byte random write microbenchmark, FAST 2017 aging comparison, NVM Express and SNIA public materials) are research, detailed citations in [prior-art.md](../prior-art.md) 7.1 and 7.2, not verified in this project; per .claude/singlefs-ai-sop/rules/evidence-discipline.md, others' approaches are clues, not evidence, used only to raise hypotheses and indicate which paths to benchmark.

**Basis**:

- E127 (Whether to Store Group Identity Under Splits and Merges): Candidate B's arm requiring on-disk fields (node-count grouping) did not bring runs below 0.8x of the field-free arm across six equal-budget cells => B adopted, but in the form of "group computed solely from key", not adding fields to node headers.
- User decision (2026-09-01 settled B adopted, C demoted to acceleration; 2026-09-13 settled B's form along with D26 (Background Compaction and Placement Reclamation) Settled Item 4), original words in changelog.

**Owed**: None.

#### Settled Item 3: This item no longer blocks D8 (Core Index Structure) node format freeze

**Settled**: **Does not block.** Neither leg alters the internal layout of index nodes: Candidate B's form was settled by D26 (Background Compaction and Placement Reclamation) Settled Item 4 as **not entering format** (no group identity stored, no alteration to node internal layout; modifying new-pool file creation bytes: no), and the in-house layer is non-format-level.

**Scope**: Governs the freeze cell, not other ramifications. **There is only one exception**: if the in-house layer adds steps to the closed `CommitStep` enum in D13 (Verification Route) Settled Item 10, that is another matter—**the criterion remains that enum**, and D26 (Background Compaction and Placement Reclamation) Settled Item 2 already settled that compaction does not add `CommitStep` members.

**Basis**: No experiments: this item is read directly from two settled clauses—D26 (Background Compaction and Placement Reclamation) Settled Item 4 verdicts "not entering format, modifying new-pool file creation bytes: no", and D26 (Background Compaction and Placement Reclamation) Settled Item 2 verdicts "does not add `CommitStep` members"; "whether it blocks freeze" is the logical consequence of these two verdicts, carrying no measurable quantities of its own. Experimental basis for each resides in D26 (Background Compaction and Placement Reclamation).

**Owed**: None.
