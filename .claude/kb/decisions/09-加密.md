## D9 加密 —— 半定（方向与九项已定；明文侧字段集一项未定）

调查见 [prior-art.md](../prior-art.md) 第六节。

### 方向

**整卷 AEAD，加密边界与校验和边界重合：D4（校验和位置） 那个内联进指针的字段，
在加密开启时就是 MAC。除超级块**与已定项 5 已定留明文的那一层**（逻辑身份 → 物理地址映射 + 反向索引）
外全部加密，元数据留最小明文头。**

依据：

1. **AEAD 的位置已经由 D4（校验和位置） 腾出来了。** 块层加密（LUKS）做不了认证，
   是因为它没地方放 MAC 和 nonce 而不破坏块对齐；fscrypt 不认证，给的理由也是密文膨胀。
2. **不做 per-directory / per-subvolume 加密。** bcachefs 拒绝它的理由在本工程更重：
   fsck 需要文件大小 ⇒ 大小得明文；而本工程的 checker 要靠全盘遍历验记账
   （I-3.1（已分配统计对得上）），有一部分子卷锁着就等于那部分记账验不了。
3. **不为「无 key 也能后台维护」把元数据挪到明文。** ZFS 选了那条路，代价是间接块全明文
   （池结构、文件大小、文件洞、快照结构都泄漏），认证退化成 SHA512 聚合而不是 MAC 树，
   并且要在 objset 层维护 portable / local 两个根 MAC——[prior-art.md](../prior-art.md) 6.4
   记的那串 send/recv 损坏 bug 就长在这套复杂度上。**这条同时压住已定项 5 的第二个候选**
   （索引内部节点留明文）：那是同一条路，在本工程还更糟，因为内部节点的分隔 key 带语义。

### 格式必须 day-1 预留的四样

| # | 字段 | 不留会怎样 |
|---|---|---|
| 1 | 指针里的 MAC + nonce 空间 | 事后加等于改指针宽度，全格式重来 |
| 2 | extent 的「距原始 extent 起点偏移」 | extent 被切分后重写时无法既不重用 nonce 又不重算（[prior-art.md](../prior-art.md) 6.3）。⚠️ 宽度预算已由 D19（块指针的结构与宽度预算） 收窄：值域由**最大 extent 尺寸**封顶、不由文件尺寸封顶（现役实现 7–13 位），D21（权威态与派生态的分界） 的逐字节表按 **2 字节** 计 |
| 3 | 超级块的 KDF 标识 + 主密钥槽 + 加密类型 | 换不了 KDF，也没法在既有文件系统上开加密 |
| 4 | 每个数据/元数据写的算法类型字段 | 换不了算法；bcachefs 把加密做成一种校验和类型，新数据用新算法、老数据按各自字段解 |

⚠️ **这四样在多布局下共用不共用，权威记录在 D12（目标介质） 已定项 2**（2026-08-31 用户定案）：
第 1、2、3 项**必须全布局共用**，第 4 项**可以各布局各异**。不在 D9（加密） 记第二份。

### 三条现在就能定死的硬要求（与最终选型无关）

1. **nonce 不许由物理位置派生**，否则 balance / copygc 搬一个块就要重新加密（要改 MAC、要密钥），
   多副本还会因此字节不同，D2（RAID 条带策略） 的 parity 直接算不成。**nonce 跟逻辑身份走并存在指针里。**
2. **顺序固定为 压缩 → 加密 → MAC。** 反过来不可能（密文压不动）。
   由此密文长度泄漏明文可压缩性（Kelsey, FSE 2002），写进已知泄漏清单，不装作没有。
3. **若采用截断 MAC，读重试次数上限必须是写死的小常数，并且有检查。**
   bcachefs 的 80 位 MAC 安全论证整个押在「MAC 对不上就判设备坏、很快停用」上——
   **那是一条实现行为，不是密码学性质**。（D9（加密）已定项 2 取满 128 位，此条因此不承重。）

### 已定项 1（2026-08-26）：指针里额外存一份密文的非密钥校验和

即指针里有两个完整性字段：MAC（要密钥，认证）+ 密文校验和（不要密钥，查损坏）。
ZFS 同形态（`include/sys/spa.h:242-246`，2026-08-29 逐字现查 master `58d73c9`）：
「The MAC occupies **half of the checksum space** ... the checksum is used to detect
on-disk corruption **whether or not the encryption key is loaded**」
⇒ **所有读路径都用它，不是只有 scrub 用。**
依据：可重建性与常驻后台整理是硬承诺（D1（数据可移动性 / 反向索引）、D3（空间分配）），
而「未解锁就完全瞎」会让这两条在最需要的时候（盘开始坏、人不在）失效。
代价是指针变大，且**无密钥只做检测与搬运，不做判定谁是好副本**——
攻击者能造出校验和自洽的块骗过无密钥的一侧。

### 已定项 2（2026-08-28）：MAC 取满 128 位，不截断

| # | 证据 | 强度 |
|---|---|---|
| 1 | **Linux 的 `chachapoly_setauthsize` 要求 authsize 恰为 16 字节**，否则 `-EINVAL`（`crypto/chacha20poly1305.c`）；`crypto_gcm_check_authsize` 只接受 4/8/12/13/14/15/16 字节，**10 字节直接 `-EINVAL`**（`include/crypto/gcm.h`） | 硬：接口层拒绝 |
| 2 | **SP 800-38D §5.2.1.2 逐字**（本机 PDF 核实）：「t may be any one of the following five values: **128, 120, 112, 104, or 96** ... An implementation **shall not** support values for t that are different from the seven choices」——**80 不在其中** | 硬：标准正文 |
| 2b | RFC 8439 §4 原文「Tag truncation **MUST NOT** be done.」（本机 `rfc8439.txt:1483-1484` 逐字核实） | 中，性质见 D9（加密）「截断 Poly1305 的危险性」 |
| 3 | **零个现役实现钉死过跨请求的伪造尝试上限**：dm-integrity 的 `number_of_mismatches` 只自增与输出、**从不与任何阈值比较**；dm-verity 的上限只用来压日志；bcachefs 的重试计数是栈上局部变量、每请求归零；全内核 `MaxInvalids` **0 命中** | 硬：现查 |
| 4 | 已定项 1 已让密文校验和独立承担无密钥侧的损坏检测 ⇒ **MAC 的职责只剩认证**，截断省下的 8 字节买不到任何检测能力 | 硬：本工程自身设计 |
| 5 | 空间代价 **8 字节 / CRC 项**（48 位塞不进 padding，必须整体升级布局），4 KiB extent 摊 **+0.195%**、64 KiB 摊 +0.012% | 硬 |
| 6 | OpenZFS 面对同一个冲突选择**保满 128 位 MAC**（`include/sys/zio.h:121` `ZIO_DATA_MAC_LEN 16`），宁可付「加密块最多 2 副本」也不动 MAC | 中：同行取舍 |

⚠️ **唯一支持 80 位的现役数据点是 bcachefs 的默认值，而它站不住**：
80 位是 `bch_extent_crc64` 位域的余量（type:3 + sizes:27 + nonce:10 + types:8 + csum_hi:16 = 64，
加 csum_lo:64 恰为 80），是**布局挤出来的数字，不是安全论证的产物**；
它靠**绕开内核 AEAD 接口**手动调 chacha+poly1305 再 `memcpy` 截断做到
（`fs/bcachefs/` 对 `crypto_aead|setauthsize` **0 命中**，截断在 `checksum.c:160`）；
而**它自己的元数据仍恒用 128 位**。

#### 截断 Poly1305 的危险性：论据存在，但走的不是 GCM 那条路

**⚠️ 不许引用的一条**：Ferguson 2005 的短 tag 惨案**不能外推到 Poly1305**——
那个攻击的病根是 GHASH 在 GF(2¹²⁸) 上的线性结构，Poly1305 在素域 2¹³⁰−5 上、掩码是模加不是 XOR，
**那条 bit-forcing 路径没有对应物**。⚠️ 这一条本身是**推理**：查不到任何权威来源明写它免疫。

| # | 结论仍成立的依据 | 等级 |
|---|---|---|
| 1 | **Wegman-Carter 类 MAC 的伪造界是 `fℓ/2^τ`，不是 `f/2^τ`**（多一个随消息长度线性增长的 ℓ 因子）⇒ 截断到 t 位并不给你 2⁻ᵗ。这把 Poly1305 与 GHASH 放在同一档，理由是 ℓ 因子而非密钥泄漏 | 通用界，有公开表述 |
| 2 | **一次成功伪造在 Poly1305 上同样暴露 r。** DJB *Cryptography in NaCl* §9 逐字（2026-08-28 本机抽 PDF 复核）：「the attacker can then, by **polynomial root-finding**, easily determine ClampP(r) and s ... allowing the attacker to generate "re-forgeries" ... under the same nonce」 | **逐字核实** |
| 3 | 文献公认的安全截断办法是两级哈希 / 额外子密钥（Nyberg-Gilbert-Robshaw 2005 的 two-stage、DJB 自己说的 "safely truncated after an appropriate **twist**"、GCM-SST 的子密钥 Q）——**Poly1305 这三样一样都没有** | 二手转述，未逐字复核 |

⇒ 「因为每 nonce 新鲜导出 (r,s) 所以截断不泄漏 r」**是错的**：新鲜的 r 只把泄漏关进单个 nonce，
不改变「一次成功伪造就暴露 r」，而截断恰恰拆掉了 DJB 说的第一道防线（伪造根本成功不了，>100 位）。

⚠️ **RFC 8439 那条 MUST NOT 的性质要写准**：它是**未经分析的保守禁止**——
来龙去脉可完整还原（2015-08-07 CFRG 列表提问 → 同日两封推测性回复（一封自陈 "I presume"）
→ 2016-11-14 提议写进 bis → 2017-01-30 `-01` 加入，此后一字未改），中间没有任何密码分析；
且它不被普遍执行（BoringSSL 的 `aead_chacha20_poly1305_init` **只有上界没有下界**，
`tag_len = 1` 被接受，2026-08-28 现拉 master 核实；OpenSSL 同样放行到 1 字节）。
⚠️ 但「那条禁令没做过分析」**推不出**「截断没事」——「结论仍成立的依据」那三条独立于它成立。

#### 「MAC 长度取决于读重试上限」不成立

1. **零个现役实现做到过**（证据 3）。最接近的是 bcachefs 的 extent 投毒，但它**默认关闭**、
   自陈 "unsafe without read fua support"、且是 **per-extent 的，而安全上限必须是 per-key 全局的**。
2. **标准对付「尝试次数无界」的手段是把 tag 留满**：RFC 8439 §4 的答案是
   "This is hard if the attacker has to try all **2^128** possible tags one by one."

**这条判据还引错了文档**（2026-08-28 从本机 NIST PDF 逐条核实）：`MaxInvalids` 在
**SP 800-38B（CMAC）里命中 2 次、在 SP 800-38D（GCM）里命中 0 次**；38D 附录 C 那一列的标题是
"**Maximum Invocations** of the Authenticated Decryption Function"——计的是全部解密调用（含成功的）。
⇒ [checks-owed.md](../checks-owed.md) 的 C3（读重试无硬上限） 可以销账，
**理由是「前提口径错了」，不是「已拦住」**。

### 已定项 3（2026-08-27）：运行时按 CPU 特性选，格式里不钉死

**盘上记算法类型，运行时按有没有 AES-NI 挑默认值。** 两种算法都必须实现。
依据（E6（加密算法选型） 实测，2026-08-31 重测，QEMU 两档 CPU 特性，单核 256 MiB，
N=5 取最好值，单位 MiB/s，原始输出 `research/results/e6-units-2026-08-31.out`）：

| 单元 | 有 AES-NI | 屏蔽 AES-NI |
|---|---|---|
| 4 KiB | AES 3656.13 / ChaCha 1192.00 ⇒ **AES 快 3.07 倍** | AES 244.74 / ChaCha 1195.08 ⇒ **ChaCha 快 4.88 倍** |
| 64 KiB | AES 4117.34 / ChaCha 1582.12 ⇒ AES 快 2.60 倍 | AES 249.31 / ChaCha 1585.14 ⇒ **ChaCha 快 6.36 倍** |

**反转是真的，幅度 2.59–6.47 倍**（八格全扫，最小值在 16 KiB 有 NI 档、最大值在 256 KiB 屏蔽档），
所以「挑一个写进格式」在另一类机器上必然选错。
⚠️ 这条决定的是默认值怎么选，**格式侧没有新增**。

**由此得到一条硬要求：加密路径必须能并行。** 无 AES-NI 时 AES-256-GCM 单核只有 244.74 MiB/s，
低于任何现代 NVMe 的顺序带宽（本机 nvme0n1 3.6 T，其顺序带宽未单独实测——这一步按介质类别推）。
E17（write buffer 合并上限） 确认了瓶颈的位置：同一台机器上 write buffer 单线程合并等效
42.2 GB/s 用户写带宽，而加密单核 3.83–4.41 GB/s（有 AES-NI）/ 0.257 GB/s（无）
⇒ **D8（核心索引结构） 那条「合并是关键路径」的担忧在方向上不成立，D9（加密） 已定项 3才是真的。**
⚠️ 它与 D13（验证路线） 已定项 2「事务层承不承诺串行提交」直接对撞，**两处叠加的后果尚未评估**。

### 已定项 4（2026-08-29，用户定案）：nonce 每 extent 存，不现算

**指针头部为每个逻辑 extent 存一份 96 位 nonce。** 不采用 bcachefs 那种由 `bversion` 现算的形态。

**依据**：nonce 是写出那一刻就该被钉死的东西。现算把「这个密文该配哪个 nonce」变成一条**推导**，
推导的每个输入（bversion、per-crc 偏移、extent 切分历史）都是后来可能被改动的量；存下来则一次写入、此后只读。
并列的第二条依据是 `.claude/rules/fs-design.md` 的**不为省空间牺牲自包含**。

| 买到 | 付出 |
|---|---|
| ① 解密不依赖任何**别处**的字段仍然正确 ⇒ 单元自包含（D20（承重面：单元的原子性与自包含））在加密开启时也成立；② I-6.1（nonce 不重用） 变成**对着镜像可判定**的性质——扫一遍全部指针头部即可 | **12 字节 / 逻辑 extent**；不加密时是留位（D19（块指针的结构与宽度预算） 已定项 3）|

⚠️ **它没有解掉 extent 切分那一格**：day-1 预留第 2 项仍然必需——切分后的 N 个子 extent
**共享同一份密文、同一个 nonce、同一个 MAC**，存下来的那份 nonce 是「原始 extent 的」，
子 extent 靠偏移找回它。**存 nonce 不等于每个子 extent 各存一个。**

### 已定项 5（2026-08-26）：取第三个候选，性能优先

**把「一个块的物理地址的权威记录点」移出加密结构**，让无密钥的一侧能搬块
（明文的逻辑身份 → 物理地址映射层 + 明文反向索引）。三个候选：

| 候选 | 无密钥能做到 | 代价 |
|---|---|---|
| 只做 scrub | 检测损坏、报告坏块 | 搬不动任何东西，碎片和坏盘疏散仍要密钥 |
| 索引内部节点留明文 | 能搬、能疏散 | **内部节点带分隔 key，dirent 树的分隔 key 就是文件名**——泄漏面比 ZFS 大得多（ZFS 的间接块是纯指针数组，没有 key）|
| **反向索引 + bucket 代号留明文（取这条）** | 能搬 | 泄漏物理布局与引用关系 |

**依据（用户定案）**：这是一笔**互斥取舍**——无密钥搬运要求「位置」能在无密钥下被改写，
而「被 MAC 覆盖」要求它不能。两者不可兼得时**性能优先**，因为 D3（空间分配） 的
「常驻、自动、用户无需知道的后台整理」是硬承诺。

**瓶颈的准确位置**：不是 MAC 的位置，是**「一个块的物理地址的权威记录点在不在密文里」**。
把 MAC 挪到块自己的明文头（bcachefs 对 btree 节点就是这么做的，`extents_format.h`
一行注释直说 `/* Btree pointers don't carry around checksums: */`）**只松一格，门还锁着**：
元数据块可以原样搬（MAC 覆盖块自己的字节、nonce 不由物理位置派生），
但父指针里的**地址字段**仍要改，而父节点的载荷是密文。

**明确失去什么，不许含糊**：

| 失去 | 具体是什么 |
|---|---|
| 「哪个块该出现在这个位置」的密钥保护 | 位置移出 MAC 覆盖范围后攻击者可以**重排块**。块内容仍被 MAC 认证（改内容仍会被发现），但**换位置不会** |
| D4（校验和位置）「检测读到正确但过期的块」的抗篡改性 | 可以用父指针里的明文期望代号补回**检测**能力（形态同 bcachefs `bch_btree_ptr_v2` 的 `seq`，纯整数比较），但代号是明文，**攻击者可以连块头带代号一起伪造** |

⚠️ **这条使 D9（加密）方向第 3 点被部分推翻**：本工程也接受了一个明文间接层。
**差别在于范围**：ZFS 是整个间接块明文（池结构、文件大小、文件洞、快照结构全泄漏），
本工程只把逻辑身份 → 物理地址这一层扁平映射放明文，**不暴露 btree 内部节点的分隔 key**。
**这个范围差异是D9（加密） 已定项 5成立的全部依据，守不住就等于走了 ZFS 那条路。**

⚠️ **「无密钥后台整理瘫痪」这一句是推理，不是引文**（2026-08-26 专项检索 bcachefs
Principles of Operation 全文、官网 Encryption 与 FAQ、`bcachefs.5` 手册源码、Kent 的历次公告，
**没有任何一手材料用散文明说** copygc / rebalance / scrub / fsck 在无密钥时不能跑）。
推论建立在五条可核事实上：除超级块外全部加密且认证；主密钥挂载时解密并缓存至卸载；
未解锁挂载直接失败（`Required key not available`）；离线 `bcachefs dump` 必须先 `remove-passphrase`；
拒绝 per-directory 加密的理由之一是「fsck 需要文件大小」。

⚠️ **一条必须同时记下的冲突：代号失效不能当搬运机制。**
本项括号里那句「靠代号失效，不必逐条改引用」按 D1（数据可移动性 / 反向索引） 已核实的事实不成立——
bump gen 的语义是「这份数据没了」，**对唯一副本就是丢数据**；它只管失效不管搬运。
搬运仍要逐条改引用，而那正是明文反向索引存在的理由。
**本项定案方向不受影响，被推翻的是它顺带写的那个省力办法。**

### 已定项 6（2026-08-28）：AEAD 的关联数据绑逻辑身份，物理位置一律不进

**AAD = `(单元类型标签, 树 ID, 对象 ID, 对象出生代, 锚点偏移)`，定长定序的规范编码。
物理落点、设备 ID、以及任何明文侧字段，一律不进。**

⚠️ **fsid 不在 AAD 里，它是密钥派生的输入**（已定项 8 定案）：跨卷绑定发生在密钥层，
另一个卷的密文在本卷的派生密钥下**根本解不开**，比 AAD 逐单元失配更早、更彻底；
**不是字段，就不受 A6（AAD 期望值不来自明文侧） 约束**。

| 字段 | 为什么必须在里面 | 谁提供期望值 |
|---|---|---|
| **单元类型标签**（数据 extent / btree 节点 / 记账单元 / 根记录） | 不同单元类的字段集合不同。没有域分隔时两类单元的 AAD 可序列化成同一串字节 ⇒ **类型混淆变成一次合法的 MAC 通过** | 读者的查找路径 |
| **树 ID** | D8（核心索引结构） 是多 keyspace，对象号在不同 keyspace 里各自编号、**必然碰撞** | 查找路径 |
| **对象 ID（inode）** | 同一棵树里文件 A 的 offset 0 与文件 B 的 offset 0 除对象号外全同。指针挂错对象 ⇒ 读 A 得 B | 查找路径 |
| **对象出生代（inode generation）** | inode 号复用后旧文件与新文件的 `(树, 对象, 偏移)` 完全相同。⚠️ 它是 I-6.1（nonce 不重用） 失效时（崩溃窗口 / nonce 水位回滚）的**第二道闸**，I-6.1（nonce 不重用） 成立时与 nonce 冗余 | 密文侧 |
| **锚点偏移** = 该 extent 首次写出时的对象内起始偏移，读者现算 `key.offset − ptr.extent_off` | 同一文件内两个 extent 互换，对数据库文件 / VM 镜像就是一次真实破坏 | 查找路径 + 密文侧 `extent_off` |

**独立佐证**（2026-08-29 本机内核树逐行现查）：ext4 的 inode 校验种子是
`(fsid, 对象 ID, 对象出生代)` 三件套，但**三项进入的层次不同**——
`s_csum_seed = ext4_chksum(~0, es->s_uuid, ...)` 在**挂载时算一次**（`fs/ext4/super.c:4725`），
逐对象校验只喂 `inum` 与 `gen`（`fs/ext4/ialloc.c:1301`），**`s_uuid` 一次也没进过逐对象输入**。
⚠️ 这条佐证的重合点是「哪三项」，不是「在哪一层」；按层次读，它支持的形状正是已定项 8 采纳的那个。
⚠️ 折进种子的形态**只能验证一个猜测，不能反解身份** ⇒ 它**不能**被当作已经补上了
D20（承重面：单元的原子性与自包含） 的承重面洞（数据块零自描述），那个洞仍要靠 D18（块里携带什么信息） 已定项 3 的显式字段补。

#### 一定不能进 AAD 的，以及各自撞的是哪一条

| 字段 | 撞哪条 | 机制 |
|---|---|---|
| **物理落点 / 设备 ID** | **A7（含义待查） + D19（块指针的结构与宽度预算），以及已定项 5，两条互相独立** | D2（RAID 条带策略） 已定「N 个副本是同一份密文写 N 遍、共用一个 nonce」，D19（块指针的结构与宽度预算） 已定「MAC 每逻辑 extent 一份、落点每物理位置一份」⇒ 落点进 AAD ⇒ N 个副本 N 个 AAD ⇒ 要 N 个 MAC ⇒ 当场推翻 D19（块指针的结构与宽度预算） 的分段结构。**第二条独立路径**：已定项 5 要求无密钥能搬块，搬块要重算 MAC ⇒ 要密钥 |
| **extent 距原始起点偏移** | **day-1 预留第 2 项** | 切分后 N 个子 extent 共享同一份密文、nonce、MAC；该字段逐指针不同 ⇒ N 个 AAD 对 1 个 MAC ⇒ **切分后 N−1 个子 extent 全部验不过**——失配成为正常操作的必然结果 |
| **`locality_id`** | **D8（核心索引结构） 已定项 3 逐字**：「`locality_id` 是提示，不是正确性的一部分——它可以是错的、可以过期」 | 让声明为「可以是错的」的字段承重 |
| **任何明文侧字段**（明文头 flags / 长度 / nonce 代号、明文映射层条目、反向索引、位置条目里的密文校验和）| 期望值来源判据 | 期望值由被读对象自己提供，攻击者可同时改两边，AEAD 对此零保护 |
| **读者当前所处的快照 ID** | COW 共享 | 一个块从 N 个快照可达，绑读者侧快照 ⇒ 该块只在一个快照里验得过。⚠️ 这条排除的后半个前提（「且 D6（快照实现模型） 未定」）在第二天就没了，见「AAD 缺快照维」 |
| **引用计数 / 记账量 / deadlist 归属 / 当前 txg** | D5（快照 / 空间记账机制） | 全是集合属性，块不被重写就会变 ⇒ 每变一次要重新加密一次 |
| **父节点物理地址** | D18（块里携带什么信息） 否决清单 | 时序上不可能：COW 是子先写父后写，子块下笔时那个值还不存在 |

**不必要但零成本的两项：算法类型、密钥代号。** 可以放，但**必须记成「无成本的冗余」**：
它们住在密文侧、攻击者改不了，用错必然失配。特别地——**算法类型够不着最危险的那一格**：
字段标为「未加密」时读者根本不跑 MAC，而 AAD 是 MAC **之内**的东西；
那一格的防线是 I-6.4（无未加密块） 加超级块的加密声明。
**单元长度不必进 AAD**：AEAD 构造已隐式认证它（`crypto/chacha20poly1305.c:184-185`
收尾喂 `tail.assoclen` / `tail.cryptlen`，2026-08-28 现查）。

#### 期望值来源：D9（加密）最硬的一条

> **AAD 每个字段的期望值只许来自 ① 读者的查找路径，或 ② 已被上一级 MAC 认证的密文侧字段。
> 一律不许来自明文侧，也不许从指针里读回来。**

两条腿从不同方向各自撞到它，且都判「这条不成立则三条命题全部崩塌」。
机制：从明文侧取期望值 ⇒ 攻击者控制 AAD 的输入，AAD 从防线变成自由变量；
从指针里读回来 ⇒ checker 验的是「指针自洽」，**逻辑身份 ↔ 指针**那一环完全没查。

#### AAD 真正买到的是哪一环——不是「MAC 会失配」

```
逻辑身份 q  ──链 B──  指针（头部：nonce / MAC）  ──链 A──  盘上的密文 C
                                        ↑
                            明文映射层（攻击者可控）在这里
```

| 链 | 由什么保证 | 主要威胁是谁 |
|---|---|---|
| **链 A：指针 ↔ 密文块** | **nonce**（在密文侧指针头里，I-6.1（nonce 不重用） 保证全盘唯一；tag 是 nonce 的函数）⇒ **不需要 AAD** | 攻击者（改明文映射）|
| **链 B：逻辑身份 ↔ 指针** | **只有 AAD**。nonce 只说「这块配这个指针」，不说「这个指针该挂在哪个 key 下」 | **本工程自己的实现 bug**——btree split/merge、write buffer 的 seq 去重、快照 key 改写 |

⇒ 「MAC 会失配」只回答了链 A；AAD 的价值几乎全在链 B，而链 B 的主要威胁是自家代码
（E17（write buffer 合并上限） 实测漏掉 `seq` 就是这一类）。

#### 三条命题的适用范围

| 命题 | 判决 | 收窄到什么范围 |
|---|---|---|
| 1 骗不过 checker | **对有密钥的 checker 成立** | **对无密钥 scrub 完全不成立**：密文校验和在明文侧，攻击者搬块时连校验和一起改成自洽即可。这是已定项 1 逐字接受过的范围，此处提升为明写 |
| 2 不能提权 | **在两条被单独关掉之后才成立** | ①「就近修复」：制造权威树与明文映射冲突后，若修复路径以明文侧为准去改权威侧，攻击被转成数据销毁；② **明文超级块里的 nonce 水位可回滚**（A2（超级块是明文））⇒ 写者重用 nonce ⇒ ChaCha20 下两段明文直接 XOR，**AAD 对它零作用** |
| 3 读不出他人旧数据 | **在单卷、非整根回滚、非块级克隆的范围内成立** | 挡住重排的主力是**密文侧的 nonce，不是 AAD**；AAD 的净增只有 I-6.1（nonce 不重用） 失效时的降级保护与抓链 B 的实现 bug。跨卷那一格已移交密钥派生层（已定项 8）|

**两格 AAD 补不上**：**整根回滚**（被回滚到的旧根每个 (nonce, AAD, 密文) 三元组都是真的——
任何「这是上一版」的判定都需要 AEAD 之外的见证者）；
**块级克隆**（克隆卷与原卷 fsid 相同、密钥相同、nonce 空间从同一点分叉 ⇒ 分叉后两卷可能对不同内容发同一个 nonce，
**这是一次 nonce 重用事件，AAD 里放什么都修不好**，要修只能在 mkfs / 克隆时换密钥域）。

**现役同行的口径**（2026-08-28 本机逐字现查）：fscrypt 明写不保证——「fscrypt is not
guaranteed to protect confidentiality or authenticity if an attacker is able to manipulate
the filesystem offline prior to an authorized user later accessing the filesystem」；
dm-verity 的根哈希来自外部信任锚，自陈「This hash should be trusted as there is no other
authenticity beyond this point」。⇒ **「防不住整卷回滚」不是本工程独有的短板，但必须像它们一样写在明面上。**

#### ⚠️ AAD 缺快照维：一条排除理由的前提在第二天就没了（2026-08-29）

D9（加密） 已定项 6 定案于 2026-08-28，而排除「读者当前所处的快照 ID」的理由**有一半逐字是「且 D6（快照实现模型） 未定」**，
**D6（快照实现模型） 在 2026-08-29 定了取多可写头**，那条排除从未被复核。
⚠️ 门禁阶段「未定项有没有被别处定了」抓不到它——那个阶段只扫**未定项**，而本项已标「已定」
⇒ **已定小节里作为定案依据的前提同样会陈旧，而没有任何东西在看**（落点 [checks-owed.md](../checks-owed.md)）。

**已实测**（E31（AAD 缺快照维），2026-08-29，三轮字节一致）：

| 臂 | 错配被抓到 | 静默读出他人数据 | 共享读成功 |
|---|---|---|---|
| **D9（加密） 已定项 6 已定的五项（无快照维）** | **0 / 2** | **2** | 3 / 3 |
| 五项 + 读者当前所处的快照 | 2 / 2 | 0 | **1 / 3** |
| 五项 + **出生快照** | 2 / 2 | 0 | 3 / 3 |
| 五项 + **nonce 现算含快照** | 2 / 2 | 0 | 3 / 3 |

1. **D9（加密） 已定项 6 已定的 AAD 对快照 key 错配是瞎的，而且是静默的**——两次错配全部读出**另一个可写头的数据**，
   MAC 全绿；而「快照 key 改写」正是链 B 那张表里点名的三类实现 bug 之一。
2. **排除「读者侧快照」的理由本身没错**（绑它把共享读打到 1 / 3）。
   **倒下的是「排除了读者侧快照 ⇒ 快照这一维整个不进 AAD」这个跳步。**
3. **两条出路**：绑**出生快照**（key 自己带的那一维），或把快照维**折进现算的 nonce**。
   ⚠️ 后者是已定项 4 的一个取值，而已定项 4 已定「每 extent 存，不现算」
   ⇒ **本工程只剩「绑出生快照」这一条出路，那张字段表要重开一次。**

#### 连带要新增 / 改写的不变量与检查

| ID | 内容 | 性质 |
|---|---|---|
| I-6.3（MAC 与密文匹配） | 改写：AAD 的每个字段由 checker **从权威树的 key 现算**，不许从指针或明文侧读取 | 现有条目口径不足 |
| I-6.9（密文过而 MAC 败判身份错配） | 新增：密文校验和通过而 MAC 失配 ⇒ 判红并归类为「身份错配」，**不许归类为损坏、不许触发副本修复或投毒** | 堵命题 2 的「就近修复」 |
| I-6.10（明文映射层可重建） | 新增：checker 从权威侧重建的明文映射层与反向索引，与盘上明文副本逐条相同；差异一律判红，**不许就地修复** | 「明文映射是派生态」的可判定形式 |
| I-6.2（明文头字段白名单） | 补注：白名单里每一项都只是提示，**必须在密文侧有权威副本，读者取密文侧那一份** | 期望值来源判据的可判定形式 |
| I-6.1（nonce 不重用） | 补注：它是**抗 bug 检查，不是抗攻击检查**——阶段 ② 靠明文头 magic 枚举，攻击者抹掉 magic 即可让块隐身 | 措辞修正 |

**格式必须 day-1 提供的三样**（少一样 checker 就履行不了「连带要新增 / 改写的不变量与检查」那张表）：
① **单元类型标签在权威侧显式**，不许靠「它在哪棵树里」推；
② **反向索引条目的身份口径 == AAD 口径 == 权威树 key 口径，同一份定义**（三份口径就是三份定义）；
③ **btree 节点的逻辑身份要有定义**（候选：树 ID + 层 + 谱系重写序号）——
AAD 的字段清单只覆盖数据 extent ⇒ **D18（块里携带什么信息） 未定项 1 从「强候选」升级为元数据侧 AAD 的前置。**

且在「extent 距原始起点偏移」一项上判反了）。
主 agent 自核的承重外部事实（不采信任何一条腿的转述）：`crypto/chacha20poly1305.c:184-185`、
`fs/ext4/super.c:4725` 与 `fs/ext4/ialloc.c:1301-1303`、`Documentation/filesystems/fscrypt.rst`
的威胁模型段、D8（核心索引结构） 的「`locality_id` 是提示」——四条全部逐行现查过。

### 已定项 7（2026-08-29）：取甲，且「或回收块」这半句撤销

**问题**：已定项 5 那句「无密钥侧的 GC 能搬块**或回收块**」与 D21（权威态与派生态的分界） 直接冲突——
记账是权威态且加密 ⇒ **无密钥写不了记账** ⇒ 无密钥侧没有安全手段真正完成「把空间标记为可分配」。

**先纠正岔路本身**：甲的原文写「不触碰加密记账」，按字面**连搬都搬不了**——搬运也要一个目的地，
而目的地的空闲判定同样只能来自明文侧。⇒ 真正的岔路是「**无密钥侧的空闲判定从谁那里来**」。

**免疫别名 ⟺ 明文侧的空闲集在任意时刻是权威空闲集的子集。** 两条达成路径：

| 路径 | 判定 |
|---|---|
| 无密钥侧自己算 | **不可能。** 明文映射的补集不是空闲集——差集里有 journal 环、根环、journal 重放窗口内不得重用的已释放块、ENOSPC 准入预留、待删意图未完成占用。明文反向索引补不上：它只回答「被共享的那部分」，且看不见来自加密结构的引用 |
| **密钥侧签发让渡区** | **可行。** 上锁前由密钥侧签发一段被主密钥派生 MAC 覆盖的**让渡区 A**（外加预授权的**可回收集合 E**：已疏散的源头可并入 A）。无密钥侧只许在 A∪E 内分配 |

⇒ 乙的字面形态（权威的明文空闲表）必然可能造别名；去掉「把占改成空」这条能力之后它就不是空闲表，
是**租约凭据**——A 在权威记账里整体记为「已分配」，删掉不丢信息 ⇒ 派生态，不与 D21（权威态与派生态的分界） 冲突。
⇒ **定案：取甲，撤销「或回收块」，改为「只在密钥侧签发的让渡区内分配，并在明文映射里标死」。**

**甲的代价与「锁盘整理瘫痪」是两件事**：定案之后搬运恢复，甲只放弃「净空闲增长」，
而**锁盘期的净回收没有消费者**（挂载需要密钥 ⇒ 无用户写 ⇒ 唯一消费空间的是搬运工自己，其需求正是 A）。
真正停摆的是三样：快照销毁 / 删除意图续做（要写 deadlist 与记账）、准入预留数更新、
**疏散能力上限 = 上锁那一刻签发的 A∪E**（近满卷上的换盘与缩容仍做不成）。

**命题 4′（可判定形态）**：设 S 为上锁瞬间的权威状态，A∪E 为密钥侧签发、被主密钥派生 MAC 覆盖的让渡区。
(a) 锁盘期无密钥侧发出的全部写请求落点 W ⊆ A∪E；
(b) (A∪E) 与 {S 的单元 / 根环 / journal 环 / 准入预留 / 重放窗口内待重用} 交集为空；
(c) A 的 MAC 无密钥不可伪造，解锁时验签失败即整批搬运结果不予采信。
三条都可判：(a) 是块层写请求 trace 的集合包含判定，**不需要任何「空闲」语义**；
(b) 与 I-3.1（已分配统计对得上） / I-5.1（物理范围不重叠） 共用同一趟全盘遍历；(c) 一次验签。
**判别力自证**：目的地改成「A 外第一个看起来空的位置」⇒ (a) 必须红；摘掉 A 的 MAC 覆盖 ⇒ (c) 必须红。
落点：[checks-owed.md](../checks-owed.md) C23（无密钥侧回收造别名）。

⚠️ **这条定案压在一个仓内三处互相打架的地基上**：「明文映射层到底是权威态还是派生态」——
已定项 5 定案说它是权威（物理地址的权威记录点）；D21（权威态与派生态的分界） 的分类表说索引是派生；
I-6.10（明文映射层可重建） 预设它是派生且重建源存在。**若第一条成立，第三条不可能成立。**
**本定案采用的读法：明文映射层是派生态，重建源是单元自描述**——
搬运可逆正是因为承重面住在单元自身（D20（承重面：单元的原子性与自包含）），
逐字节搬运不动它，只脏一个派生索引；回收不可逆是因为它销毁承重面本身。
⇒ 已定项 5 那句「权威记录点」措辞不准，**挪出去的是快速查找路径，不是权威**。
⚠️ **未满足的前置**：数据块目前零自描述（D18（块里携带什么信息） 已定项 3）
⇒ 对数据块而言重建源今天不存在，**本定案对元数据单元成立，对数据块欠那一项**。

**腿况**：云端 A（正推）——岔路本身 misframed、让渡区构造、命题 4′、三处打架的地基；
云端 B（反推）——「靠代号失效」与 D1（数据可移动性 / 反向索引） 冲突、D21（权威态与派生态的分界） 未定项 1 是未经确认的前提、
「密钥回来即可补做」全仓无定义；本地（找反例）——补做步骤要解密记账、更新、重加密、写回，**可被中途打断**，全仓无人定义过。
**两条云端腿独立撞到同一个根**（明文映射层的态别未定），主 agent 逐行核实三处原文后采纳。

### 已定项 8（2026-08-29）：fsid 进 KDF，超级块因 nonce 水位而必须认证，整卷回滚宣布不防

| 子问题 | 定案 |
|---|---|
| 1 超级块被认证吗 | **要认证，但理由不是 fsid。** fsid 移进 KDF 后它与 A6（AAD 期望值不来自明文侧） 的矛盾自动消失；逼出认证需求的是 nonce 水位 |
| 2 nonce 水位住哪 | **不许住在裸明文超级块里**，必须落在一个被主密钥派生 MAC 覆盖的字段上——无密钥侧不许写它 |
| 3 整卷回滚 | **宣布为已知不防的范围**，与 fscrypt 同口径。防它需要 AEAD 之外的见证者，本工程不引入 |

#### 前提编号（A 系列）

**这几个编号在本仓没有定义处，只有引用**（2026-08-29 现查：全仓 grep 无定义行）。
简称按引用处的原话反推；反推不出来的一条显式标为待查，不猜。

| 前提 | 简称 | 内容（来源：D9（加密）引用处的原话） |
|---|---|---|
| A2 | 超级块是明文 | 引用处原话：超级块是明文 |
| A6 | AAD 期望值不来自明文侧 | AAD 每个字段的期望值一律不许来自明文侧 |

**子问题 1**：先前 A6（AAD 期望值不来自明文侧） 与 fsid 那一行（期望值来自挂载时的超级块，
而超级块按 A2（超级块是明文） 是明文）**在同一份决策里直接打架**。
**解法不是给超级块加认证去救 fsid，是把 fsid 挪出 AAD**：另一个卷的密文搬进本卷 ⇒ 派生密钥不同 ⇒ **解不开**；
攻击者改明文 fsid ⇒ 全卷解不开，是拒绝服务而非机密性突破，且**立刻可见**。
**现役先例**：ext4 把 `s_uuid` 折进 `s_csum_seed`（挂载时算一次），逐对象校验只喂 `inum` 与 `gen`
⇒ 「卷身份进派生层、对象身份进逐单元层」是现役做法。

**子问题 2**：I-6.5（nonce 水位单调） 的水位若住在裸明文超级块里，把它回滚就是**密钥被绕过**
（写者重用 nonce，ChaCha20 下两段明文直接 XOR，AAD 里放什么都修不好）。
**有逐字对应的现役演示**（2026-08-29 本机内核树现查）：dm-integrity 的 `recalc_sector` 文档原文
「an attacker could modify the volume, set recalc_sector to zero, and the kernel would not
detect the modification.」，上游的处置是带密钥时默认禁掉那条路径，要开必须显式加
`legacy_recalculate`（`drivers/md/dm-integrity.c:395`）。⇒ **本工程取同一形状。**

**子问题 3**：D22（单元原子性怎么合成） 已写下「任何『这是上一版』的判定都需要外部见证者，
这是定义性的，不是工程限制」。本项只把它对超级块的形态写明：**MAC 给完整性，不给新鲜性**——
一个被重放的、真实的旧超级块每一位都是合法的，验签必过。

**腿况**：三条腿给了三个不同的答案。云端 A（正推）找出 A6（AAD 期望值不来自明文侧） 与 fsid 行的内部矛盾
（本次定案的起点）；云端 B（反推）指出 nonce 若绑 checkpoint / 代号则**没有攻击者也会撞**
（D5（快照 / 空间记账机制） 说崩溃后 checkpoint 号重发，D22（单元原子性怎么合成） 说回退 K 代是正常路径）；
本地腿独有产出 **fsid 该进 KDF 而不是 AAD**——两条云端腿都没提出，而它是唯一不需要修改
A6（AAD 期望值不来自明文侧） 的解。**分歧点**（云端 A 判「必须认证超级块（为了 fsid）」vs 本地判「不必」）
**不靠投票解决，靠查 ext4 把 uuid 放在哪一层**：查完两条腿都对了一半——认证要做，但理由是 nonce 水位不是 fsid。
⚠️ **本地腿在这条未定项定案之前作废了三轮**，三轮都被字词损坏检查判红，而**那三轮在子问题 2 上给的是相反的答案**
（都说「水位放进 root ring 就拿到了新鲜性」，与 D22（单元原子性怎么合成） 已定的「新鲜性需要外部见证者」冲突）
⇒ **作废损坏轮不只是洁癖，那三轮的结论本身也是错的**。诱因已查明：提示里的 `**粗体**:` 模式诱发损坏。

**还没定的**：超级块的 MAC 具体覆盖哪些字段、算法与密钥怎么定，属格式细节，
**留到 D18（块里携带什么信息） 自包含轴一起定**。

### 与其他决策的连锁

| 决策 | 连锁点 |
|---|---|
| D1（数据可移动性 / 反向索引） | 数据可移动是硬需求 → nonce 不许绑物理位置。**bucket generation 只管失效不管搬运** |
| D2（RAID 条带策略） | parity 对**密文**算；多副本必须字节相同，即同一份密文写 N 遍，不是加密 N 次 |
| D3（空间分配） | 无密钥能验不能搬：scrub 可做，搬运要读写索引，见已定项 5 |
| D4（校验和位置） | 加密开启时该字段就是 MAC，两者是同一个字段的两种取值 |
| D5（快照 / 空间记账机制） | **birth txg 不能当 nonce**——同一个事务里的块共享它，nonce 会重复 |
| D8（核心索引结构） | extent key 要留 version number 与偏移字段；btree 节点明文头的字段集合要一起定 |
