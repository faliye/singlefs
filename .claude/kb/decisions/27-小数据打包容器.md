## D27 小数据打包容器 —— 半定（两项已定、七项未定）

**2026-09-07 用户定案：采纳小数据打包容器，形态取后台整理，界线 ≤ 4 KiB。**

小对象补齐到整单元的浪费（D4（校验和位置） 已定项 2：512 B 占 64 倍、1 KiB 占 32 倍、4 KiB 占 8 倍）
由**后台整理把多个小对象搬进一个共享容器**来收，**写路径一个字节都不改**。
前置是 D25（目标负载优先级） 2026-09-07 加的 smallfile 那一行——在它之前，这条路没有分母。

⚠️ **它不是 D14（双轨（大小文件 / 持久临时）） 说的「格式级第二轨」**：不新开第二套校验语义、
第二本账、第二套恢复语义——容器仍是一个走同一套整单元校验、同一本账、同一套恢复路径的单元。
它新增的是**一个单元类**，不是一条轨道。
⚠️ **它也不推翻 D14（双轨（大小文件 / 持久临时）） 已定项 3**：内联阈值仍是 0，
文件数据一个字节都不内联进索引节点；容器是数据侧的载体，不是索引节点。

#### 已定项 1（2026-09-07，用户定案 + E114（小数据打包容器的总账））：形态取后台整理，写路径不改

**写入时一律照现行规则独立成单元（D4（校验和位置） 已定项 2 的补齐行为不变）；
对象写完之后，由 D26（后台整理与放置回收） 的常驻整理把它搬进共享容器。**

**为什么不取在线打包**（写路径直接进容器，即 2026-09-07 提案的原形态）——两条，都由
E114（小数据打包容器的总账） 实测：

| 在线形态的毛病 | 实测 |
|---|---|
| 收益挂在一个本工程定义不了的量上 | 收益 = `m / ⌈m/cap⌉`，`m` 是一次发布落多少个小对象。`m` = 1（每写一个小文件就 fsync）时**总账为负**——数据侧持平而元数据侧还多付容器索引与活槽记账 |
| 判据在操作中途会变 | 界线是写路径的分支变量，追加写会跨过它 ⇒ 撞 `.claude/rules/fs-design.md` 硬要求 5，与 E8（大文件与小文件是否该走不同写路径） 量到的「4 KiB 文件分 8 次追加 vs 一次写完，判据落在阈值两侧」同形 |

**后台整理形态把这两条一起解掉**：容器数 = ⌈N / 容器容量⌉，**与发布节奏无关**
（E114（小数据打包容器的总账） 有一条断言守着这一点：六个 `m` 值下占用逐字节相同）；
判据变成「这个**已经写完**的对象多大」，分支变量在操作期间不存在 ⇒ 硬要求 5 自动满足。

**代价，知情接受**：

| 代价 | 量 |
|---|---|
| 对象落盘两次 | 写字节 = 现行 × (1 + 1/容器容量)：512 B 档 1.0172、1 KiB 档 1.0333、**4 KiB 档 1.1429** |
| 整理跑完之前一点空间都没省 | 峰值占用 = 现行的补齐占用 |
| 故障域 | 一个容器不可读 = 该容器里全部对象一起丢（4 KiB 档 7 个）。⚠️ 与 C100（inode 容器丢失是永久损失而没有任何冗余条款覆盖它） 同形，**数据侧更重**——索引可从单元重建，用户数据没有上游 |
| 整理自己的字节 | E114（小数据打包容器的总账）：1 KiB / `m` = 30 / 覆写 30% 那格整理一次 218 497 024 字节，占同格省下的 10% |

#### 已定项 2（2026-09-07，用户定案 + E114（小数据打包容器的总账））：界线 ≤ 4 KiB

**只有 ≤ 4096 字节的对象进容器**，更大的照现行规则独立成单元。

**依据是 E114（小数据打包容器的总账） 的收益随对象大小的塌陷**（后台整理形态，容器头 103、每槽全额自描述 47）：

| 对象大小 | 一个容器装几个 | 空间收益 | 写字节比 |
|---|---|---|---|
| 512 B | 58 | 52.33× | 1.0172 |
| 1 KiB | 30 | 28.40× | 1.0333 |
| **4 KiB（界线）** | **7** | **6.91×** | **1.1429** |
| 8 KiB | 3 | 2.98× | 1.3333 |
| 16 KiB | 1 | **1.00×（纯亏：白写两次，一点不省）** | 2.0000 |

⚠️ **16 KiB 那一格是硬边界，不是取舍**：容器装不下第二个对象 ⇒ 空间一点不省，而写字节整整翻倍。
界线取 4 KiB 是在「覆盖面」与「收益」之间取的一点，8 KiB 那一档（2.98×）仍为正但已明显塌陷。

### 未定项

3. **容器占单元类登记表哪个码，类身份段带哪些字段。** 改第一个事务的字节：**否**（2026-09-07，依据：已定项 1 定的后台整理形态下，第一个事务只写独立单元，容器由后台整理产生，[first-txn-layout.md](../first-txn-layout.md) 不含容器）。 **状态：未定。**
   D18（块里携带什么信息） 已定项 11 的登记表码 4–15 是「保留给将来的内容类」，新增一类占一个 incompat 位。
   ⚠️ **不许用「声明长度 = 0 + flags 位」表达容器身份**：flags 偏移 7 那 8 位第一版恒 0、非 0 一律拒收，
   且类型标签是 AAD 的域分隔子（D9（加密） 已定项 6，day-1 永久契约）。
4. **容器索引住哪、key 怎么编。** 改第一个事务的字节：**否**（2026-09-07，依据同未定项 3）。 **状态：未定。**
   与 C103（容器索引无落点） 是姊妹问题——那一条覆盖打包记录类型 1（墓碑），数据侧的容器索引全仓无落点。
5. **每容器活槽计数住哪。** 改第一个事务的字节：**否**（2026-09-07，依据同未定项 3）。 **状态：未定。**
   D5（快照 / 空间记账机制） 已定项 5 的记账 key 是 `(统计量标签 2, 树 ID 8, 设备 4, 代 8)`，**没有容器这一维**
   ⇒ 活槽计数装不进现行记账，只能住容器索引的 value 或另开结构。
   而「容器全空可以释放」这个判定是生命周期判定，落在 `.claude/rules/fs-design.md` 记账纪律第一格
   （运行时决策路径，不许遍历）。
6. **整理的触发判据与批量。** 改第一个事务的字节：**否**（2026-09-07，依据同未定项 3）。 **状态：未定。**
   前置是 D26（后台整理与放置回收） 未定项 4（结构抗老化取什么形态）。
   ⚠️ 批量决定收益兑现的延迟：整理跑完之前峰值占用等于现行。
7. **slot 的 nonce 与 MAC 载体。** 改第一个事务的字节：**否**（2026-09-07，依据同未定项 3；但它是 day-1 加密契约的一部分，**必须在加密开机之前定死**）。 **状态：未定。**
   两条路：整容器一份 MAC，或每槽各自 nonce 与 MAC（则 D19（块指针的结构与宽度预算） 已定项 3
   「MAC 与 nonce 恒定占位的定宽槽位」与 D9（加密） 已定项 4「指针头部为每个逻辑 extent 存一份」都要改）。
   ⚠️ **这一格与 C68（不变量白名单与已定条款打架） 挂着的 nonce 归属那半是同一个洞。**
   ⚠️ **射程只到「住哪」**：拿什么身份进 AAD 是未定项 9，两项耦合但不同——
   载体解决「N 份还是 1 份」，AAD 解决「那一份绑的是谁」。
8. **装载纪律在数据侧取哪几条。** 改第一个事务的字节：**否**（2026-09-07，依据同未定项 3）。 **状态：未定。**
   D18（块里携带什么信息） 已定项 11 给码 3 定了四条（一容器一种打包记录类型 / 一个代际 / 一棵树 / 记录定宽）。
   数据侧至少两条要重判：**记录定宽**（小对象天然变长 ⇒ 要槽目录，码 3 没有过这东西）与
   **一容器一棵树**（跨树容器算不清这 32768 字节记给哪棵树，D5（快照 / 空间记账机制） 记账 key 带树维）。

9. **容器的 AAD 组成与域分隔子。** 改第一个事务的字节：**否**（2026-09-07，依据同未定项 3：第一个事务不写容器；但它是 D9（加密） 已定项 6 逐字「day-1 永久契约」的一部分，**必须在加密开机之前定死**，此后改一次就是一次格式断裂）。 **状态：未定。**

   **问题的形状**：D9（加密） 已定项 6 定的 AAD 是 `(单元类型标签, 树 ID, 对象 ID, 对象出生代, 锚点偏移)`，
   而一个容器里住着 N 个对象——**这五项里有三项逐对象不同**（对象 ID、对象出生代、锚点偏移）。

   | 取法 | 后果 |
   |---|---|
   | AAD 绑**对象**身份 + 整容器一份 MAC | N 个 AAD 对 1 个 MAC ⇒ **N−1 个对象验不过**。这正是 D9（加密） 已定项 6 排除 extent 切分时用的那条机制，逐字「失配成为正常操作的必然结果 ⇒ 排除」 |
   | AAD 绑**容器**身份（照码 3 的做法：出生树 + 打包记录类型 + 容器号 + 容器出生代） | 一份 AAD 对一份 MAC，自洽；代价是**对象身份不再进 AAD** ⇒ 一个对象连同它的槽被整体搬到另一个容器时，AAD 变了，要重新加密 |
   | 每槽各自 nonce 与 MAC + AAD 绑对象身份 | 自洽，且搬运不必重算；代价是未定项 7 那三条已定条款都要改 |

   ⚠️ **不许用「第一版恒 X 所以放进去无害」重新论证**——D9（加密） 已定项 6 对 extent 距起点偏移那一格
   点过这个陷阱，逐字「恒 0 是第一版的运行时事实，不是格式契约」。
   ⚠️ **与未定项 6（整理的触发与批量）耦合**：后台整理会搬对象，若 AAD 绑容器身份，
   每一次搬运都是一次重新加密——那笔代价 E114（小数据打包容器的总账） 没算过。
