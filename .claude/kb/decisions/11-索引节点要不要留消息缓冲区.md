## D11 索引节点要不要留消息缓冲区 —— 已定

D11（索引节点要不要留消息缓冲区） 管索引节点的磁盘格式里留不留一块消息缓冲区，让小写先攒在内部节点里、批量下刷，而不是每次都改到叶子（Bε-tree 形态），即 D10（随机写 / 碎片化的真答案） 候选 A 的具体形态；它的实质是「一个 key 的权威值，允不允许暂时不在它的最终位置上」，是与「空间怎么记账」同级的心智模型（`.claude/rules/format-evolution.md`「概念模型要慢」）。管留不留、ε 取多少、按什么分支、陈旧怎么检出、缓冲能不能重算、重建前排空。不管的：节点大小归 D8（核心索引结构） 已定项 2；write buffer 前端与节点消息缓冲区的衔接归 D8（核心索引结构） 已定项 12；消息缓冲区在冻结政策里落 D15（格式冻结政策） 第 4 层（索引节点内部布局）。第一版全部树 ε = 0（已定项 7）。

#### 已定项 1：留不留消息缓冲区

**定案**：留。索引节点的磁盘格式里留一块消息缓冲区，缓冲住内部节点里；把消息做成独立的一棵树（`pending_ops`）这条出路已否。第一版全部树 ε = 0、不启用（已定项 7）。

**射程**：这条定案是在两个已知未决之上做的裁决，不是它们消失了：代价 2（可重建性从「可检出的不可达」退化成「检不出的陈旧」）至今是推理、没有量化；`.claude/rules/fs-design.md` 的格式分支判据判它是负改善——消息缓冲买不到「用错了→挂不上」，同一条规则明写「判据里不许出现『这样更快』」⇒ 收益数不构成该判据下的通过理由。它朝 [pitfalls.md](../pitfalls.md) 第 10 条那个根因（可重建性不是设计目标）走了一步，所以已定项 3（陈旧的可检出机制）不是可选项。代价 1（checker 对增量 Δ 形态的判别力归零）在本工程不成立，因为 D8（核心索引结构） 已定项 1 取幂等完整值；若某一类账做不到幂等，那一类必须另有一条与运行时不共享判定代码的独立重算路径（C12（增量语义共用））。

**依据**：

- E56（消息缓冲的收益 vs ε）：16 KiB 节点上收益是 ε 的强函数，在四个树规模上都显著；节点大小只决定 ε 的分辨率，不决定收益有没有。
- E14（I-3.1 的判别力：幂等完整值 vs 增量 Δ）：代价 1 只在增量 Δ 形态下成立，幂等完整值形态下 checker 独立重算抓得到语义写错——取幂等完整值之后它不挡「留」。
- 用户定案，日期与经过在变更史；「消息独立成树」被否的论证也在变更史。

**欠**：C52（陈旧当成合法）：代价 2 的兜底检查；C349（重组时节点消息缓冲区怎么搬没有条款）：塌缩、再平衡时节点缓冲里的消息怎么搬。

#### 已定项 2：ε 取多少

**定案**：ε = 0.65 是将来值，不是第一版的取值（已定项 7）：扇出 F = 119，缓冲 B = 665 条，两者争同一块 16 KiB 节点字节。要开、开多少，等 E56（消息缓冲的收益 vs ε） 按今天的 pivot 与消息宽重跑之后再定。

**射程**：ε 可逆，「留不留」不可逆：按 D21（权威态与派生态的分界） 索引是派生态 ⇒ 改 ε = 重建索引，不换格式，所以已定项 2 将来可以按已定项 3（陈旧的可检出机制）的结果上下调，已定项 1 不行。唯一把 ε 往下压的力量是代价 2 的暴露面，而它没有数。将来值 0.65、扇出 119、缓冲 665 条出自 E56（消息缓冲的收益 vs ε） 的 pivot 48 与消息宽 16，这两项输入今天都不成立（C351（ε 0.65 的两项输入作废而数还留在正文里））。

**依据**：

- E56（消息缓冲的收益 vs ε）：ε = 0.65 在四个树规模上逐档压过 ε = 0.5，点查代价只多几个百分点；树高是 (叶数, 扇出) 的因变量，多付一层没有决定性代价。
- 用户定案，日期与经过在变更史。

**欠**：C351（ε 0.65 的两项输入作废而数还留在正文里）：E56（消息缓冲的收益 vs ε） 按今天的 pivot 与消息宽重跑，重跑之前正文里的 0.65 / 119 / 665 一律带「将来值」。

#### 已定项 3：陈旧的可检出机制

**定案**：代价 2（可重建性从「可检出的不可达」退化成「检不出的陈旧」）有兜底，不是无解。检出机制骑在已定项 4 的两个重算源上，不需要第三样东西：

| 问的是 | 谁回答 |
|---|---|
| 这个落点是不是现行版本 | **单元自带的写序 + 实例表 + 祖先表**（C113（扫描重建时多版单元的现行版本判定无输入） 定案 P2 / P3：写序 (实例代号, 事务号) 结合实例表判「发布了没有」，祖先表判「对这棵树可不可见」，可见候选里写序最大者是现行版本）|
| 这个 key 是不是已经死了 | **墓碑单元**（已定删除要写单元）|

**检测逻辑不许复用消息生成或应用的那段代码。** 否则重犯 bcachefs 那个形状——抓得到应用过程出偏差，抓不到语义本身写错。

**射程**：定的是「检得出」，欠的是「证明它检得出」。记账逐落点答不出「这个落点活没活」（D3（空间分配） 已定项 1 逐字说记账树答不了单个落点），所以现行版本那一问不交给记账。

**依据**：

- E104（扫描重建的现行版本判定）：写序、实例表行、祖先表、死亡写序、容器退役记录、清扫门全上时，全规则臂在全部世界与种子上判对现行版本、不复活已删 key，每一样消融都在靶子世界上判错——这组输入够用且每一样都承重。
- E14（I-3.1 的判别力：幂等完整值 vs 增量 Δ）：checker 拿运行时那个累加函数重放时是在和自己比，语义写错一条都抓不到——检测逻辑不许复用那段代码。
- 用户定案，日期与经过在变更史。

**欠**：C52（陈旧当成合法）：造一份「缓冲消息丢失、对应叶子留着旧值」的镜像，注入 N 次必须抓到 N 次（判据看故障注入率，不看抽样通过率）；把检测机制关掉，同一份镜像必须由红转绿。

#### 已定项 4：缓冲里那条消息能不能只从单元重算出来

**定案**：能，源是「单元（带写序）+ 实例表 + 祖先表 + 墓碑单元」⇒ **缓冲仍是纯派生态，D21（权威态与派生态的分界） 的「权威态 = 单元 + 记账 + 根」不扩项**（实例表单元与树表单元一样是根的间接层，权威态没有多一项）。单元自带的写序判发布性（实例表给上限），祖先表判树轴可见性，墓碑单元判 key 死亡。

**射程**：它不是「只从单元」——那个更窄的问法答案是不能；成立的是从**权威态**重算。记账逐落点答不出活没活（D3（空间分配） 已定项 1），这一半由写序、实例表、祖先表的机制替代（C113（扫描重建时多版单元的现行版本判定无输入） 定案）。

**依据**：

- E59（缓冲消息能不能只从单元重算）：只从单元重算时覆写分不出现行值、删除会复活、记账跟着错；单元 + 记账、序号 + 墓碑单元两臂四类全对——「只从单元」不成立，从权威态成立。
- E104（扫描重建的现行版本判定）：E59（缓冲消息能不能只从单元重算） 乙臂里当神谕用的记账换成写序 + 实例表 + 祖先表的机制之后仍判全对——源里的记账可以由这组机制替代。
- 用户定案，日期与经过在变更史。

**欠**：无。

#### 已定项 5：索引重建之前的排空契约

**定案**：**任何一次索引重建（改 ε、改节点大小、损坏恢复）之前，各层缓冲（节点内的消息缓冲区；write buffer 前端是内存里的结构，重建不清它、读的次序里它照旧排在树前面，C161（缓冲两级并存而衔接没定） 第三轮写明）必须先排空，且这一步由重建入口强制执行，不靠调用者自觉。**

**射程**：只管重建入口；write buffer 前端不在「各层缓冲」之内，重建不清它。

**依据**：

- E56（消息缓冲的收益 vs ε）：排空后的更新优势只比不排空时低一点——排空本身很便宜；贵的是「忘了排空」没有任何东西会报警，所以判据落在「谁来强制」而不是「记得排空」。
- 用户定案，日期与经过在变更史。

**欠**：C390（索引重建入口不强制排空）：会红的检查要等重建路径与 checker 存在，今天写不出来。

#### 已定项 6：ε 是单一取值还是按布局分支

**定案**：**布局轴不分支，全部布局共用同一个 ε**（将来值 0.65，E56（消息缓冲的收益 vs ε） 按今天的宽度重跑之前不定，见已定项 2；第一版 ε = 0，已定项 7）。树轴另有分支，分支变量是已定项 4 那条谓词：**这棵树待下刷的消息能不能只从权威态（单元 + 记账 + 墓碑单元）重算**——能 ⇒ 留缓冲、ε 取已定项 2 的将来值 0.65；不能 ⇒ 内部节点不留消息缓冲区、ε = 0。走 write buffer 前端的树（记账 / 反向索引 / LRU）另是一个分支变量：ε 恒 0、不留节点缓冲，前端在发布前直接排空到叶（D8（核心索引结构） 已定项 12）。

**射程**：今天只有 inode 树落在「不能」这一边：inode 属性更新在到达叶（码 3 打包记录单元）之前没有权威态载体，缓冲进派生态节点就撞 D21（权威态与派生态的分界） 已定项 4 的硬约束 6。extent / dirent / 反向索引判能；记账树按 D21（权威态与派生态的分界） 已定项 10「离线可由遍历重算」判能，但 E59（缓冲消息能不能只从单元重算） 那一列是神谕、未实测（C113（扫描重建时多版单元的现行版本判定无输入））。分支变量按树恒定，过 `.claude/rules/fs-design.md` 五条硬要求（判据显式、建一棵 inode 树就在这条分支上、E103（inode 打包路 ① 的更新代价） 与崩溃点重放各自验、节点布局可观测、操作中途不变）；它落 D15（格式冻结政策） 第 4 层（派生态），不是格式分支。将来要按布局分支，先给出一个合格的分支变量（显式、可计算、且不在操作中途改变），再按 `.claude/rules/fs-design.md` 的五条硬要求逐条过。

**依据**：

- D14（双轨（大小文件 / 持久临时）） 已定项 4 已把唯一的候选布局分支变量（持久 / 临时）判为不成立（会被 `linkat` / `fsync` / 快照从操作范围之外翻转，撞 `.claude/rules/fs-design.md` 硬要求 5），而同一份规则写着判据写不出来时先只做一条；这条便宜，因为可逆（改 ε = 重建索引，不换格式）。
- E98（inode 记录与 inode 树的几何）：inode 记录的字段大多不能只从权威态重算——inode 树落在「不能」这一边。
- E59（缓冲消息能不能只从单元重算）：单元 + 记账那一臂映射、反向索引、墓碑三类全对——extent / dirent / 反向索引落在「能」这一边。
- 用户定案，日期与经过在变更史。

**欠**：无。

#### 已定项 7：另四棵树与树表单元的 ε；高度为 1 的树；第一版要不要全树 ε = 0

**定案**：第一版全部树 ε = 0（含 extent 与记账），高度为 1 的树根就是叶、不留缓冲；D8（核心索引结构） 已定项 6「根恒码 2」只管 inode 树。已定项 2 的 0.65 保留为将来值：E56（消息缓冲的收益 vs ε） 按今天的 pivot（105–117）与消息宽（34–109）重跑之后再定要不要开、开多少。

**射程**：它不动已定项 1——「留不留」不可逆，ε 可逆。D11（索引节点要不要留消息缓冲区） 已定项 1 / 已定项 2 / 已定项 6 里的 0.65、扇出 119、缓冲 665 条是 write buffer 前端启用之后的将来值，不是第一版的取值；要开、开多少等 E56（消息缓冲的收益 vs ε） 重跑。

**依据**：无实验：第一版不开缓冲是取舍，不是可量的量——那个将来值今天没有数撑（它的两项输入已作废，C351（ε 0.65 的两项输入作废而数还留在正文里）），ε 可逆而「留不留」不可逆，先取 ε = 0 不动已定项 1。写代码前的总审核（`records/2026-09-13-总审核.md` 的 D11（索引节点要不要留消息缓冲区） 两节）推荐这一臂，用户定案，日期与经过在变更史。

**欠**：C351（ε 0.65 的两项输入作废而数还留在正文里）。
