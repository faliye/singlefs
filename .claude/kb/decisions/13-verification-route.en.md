## D13 Verification Route —— Settled

[中文](13-验证路线.md) · **English** · [日本語](13-検証ルート.ja.md)

D13 (Verification Route) governs how this project verifies correctness: employing all three off-the-shelf approaches—writing a custom reference implementation for differential testing, bounded exhaustive crash testing, and crash refinement formal verification (survey in [prior-art.md](../prior-art.md) Section 7.4)—without slavishly copying them, designing bespoke verification methods tailored to four characteristics unique to this project (COW issuing a new root per transaction, Merkle self-verification, nonce uniqueness for full-volume AEAD, and lack of reference implementation). It settles how oracles are divided, which two items are custom-developed, how crash-point replay is tiered and sampled, how the crash state set is defined, and what is shared between checker and implementation. Out of scope: what each invariant specifies in [invariants/README.md](../../../crates/singlefs-checker/invariants/README.md); how the three verification approaches land and what blocks what in [verification-build.md](../verification-build.md); where commit steps are registered, how structural equivalence classes are partitioned, and how many exist belong to D17 (Implementation Layering & Third-Party Pipeline) settled item 2.

**Scope**: Marginal value of refinement exists only in dimensions unattainable by crash-point replay enumeration—payload bytes, record counts / segment counts / txg counts (including ring wraparound), remnants of previous timeline, slot counts and device counts; crash-point dimension is already fully enumerated by crash-point replay. "Checksum passed" in model is boolean flag, **must not be read as refinement verifying integrity**—isomorphic to D4 (Checksum Location) line in settled item 14 "must not read as verifying Merkle", and same informed acceptance regarding CRC32C collision probability as D13 (Verification Route) settled item 4. D13 (Verification Route) settled item 4 is `Crash` on left of refinement (enumeration domain of model layer), not `Spec` on right; treating it as spec makes refinement trivially true. Formalization of I-6.5 (nonce watermark monotonic) withdrawn; reopened once D18 (Information Carried in a Block) settled item 14 settles and nonce allocation rules (monotonic counter + pre-allocated watermark, persisted before use) are established as settled item—when reopened, its sole true advantage is that nonces are invisible to POSIX, its spec structurally incapable of sharing origin with model of O1 (In-Memory Model Differential Testing (HashMap Ideal File System)), immune to Conflict 2 (D13 (Verification Route) settled item 13).

Premises and domains for M1–M4: semantic layer hinges solely on "same (instance, counter) corresponds to unique content across all timelines", guaranteed by verbatim re-issue in D23 (Journal Role & Format) settled item 14 "failure handling of this version"; re-checked when root slot write failure advancing `checkpoint_txg` lands; premise domain takes legal history family of E165 (Bounded Exhaustive Recovery Replay and Mutation Kill Bound) (arbitrary landed subset of history written by legal writer, newer root slots may be unreadable). In M2 "remaining fields equal chosen root", root reconstructed from records has unmount marker `NotWrittenByTheUnmountSequence` (D22 (Synthesizing Unit Atomicity) settled item 7 "other roots write 0"), which may differ from chosen root marker, hence "except unmount marker". M3 monotonicity corollary holds only under serial commit, fault-free crash states. M4 together with root selection eliminates confirmed complete publishes discarded by recovery under complete premises: fault-free crash states (enumeration domain of settled item 4), chosen root per D22 (Synthesizing Unit Atomicity) settled item 7, chain not straddling instance boundaries (D23 (Journal Role & Format) settled item 14 note 1), new instance roots written across two disks before any fsync returns (warm-up of D16 (Publish Semantics) settled item 8); not eliminated in faulty domain—in-flight bound truncates complete publishes, missing copy on dead disk prevents application (C519 (Recovery loses newly confirmed version when entire disk lost)).

Scope of mount transparency: applies only to fault-free crash states resulting in successful writable mount. Rejected writable mounts judged not for transparency, but legality of refusal: refusal legal ⇔ reason in D23 (Journal Role & Format) settled item 14 list, recalculation holds on crash image (the refusal reason "system configuration unreadable again after the read phase has judged" carries the rewrite exception: on the D23 (Journal Role & Format) settled item 14 list this refusal holds only when some disk has not a single self-verified system configuration and also fails the rewrite gate of D22 (Synthesizing Unit Atomicity) settled item 8; the judge recomputes only the "not a single one" half and does not recompute the five conditions of the rewrite gate; a disk state the rewrite gate lets through is not refused when it mounts and is judged by the crash-point replay observer (settled item 6); the slot self-verification judgment reads the pool-level checker's per-disk counts, not the core layer's parsing, implemented in the implementation batch), on-disk bytes identical, and read-only read in allowed set; unlisted reasons reported red per crash injection phase 2. #### Settled Item 2: Serial Commit First

**Settlement**: Transaction layer commits to serial commit first—implementing `.claude/rules/fs-design.md` rule "when criteria cannot be written, implement only one path, and **implement the slow but correct path first**"; serialization is the explicit default of this project, not an arbitrary pick. Concurrency opens only past the intersection, never promised before it. Future concurrent commit constraint: records appended in transaction number order, fsync for transaction N must wait before return until transactions < N are all appended ∨ invalidated ∨ confirmed instance switch or read-only transition (invalidation is in-memory state of commit pipeline, visible to concurrent successors); this rule idles under serial commit.

**Scope**: Serial ceiling is ~11,000 entries per checkpoint (intersection where single-thread merge time catches up to one device sync, formula in C58 (serial commit ceiling reached with no alarm)): below intersection device sync is bottleneck and serialization suffers no penalty; above intersection single-thread merge becomes ceiling with zero safety margin. Settled item 2 does not decide record header field list or alter bytes written by new-pool file creation; it dictates performance ceiling and scope of crash refinement. Concurrent commit will affect crash semantics: "prefix" is total order concept; under concurrency, a prefix may contain complete transaction B alongside truncated transaction A; record header already carries transaction boundary fields (D23 (Journal Role & Format) settled item 7: transaction number 8 + commit marker 1).

- E42 (Number of Records per Transaction): Under serialization, multi-record transactions can still be split by prefix—record header field list dictated by whether transaction produces exactly one journal record, not serial vs concurrent.

#### Settled Item 3: RefFS Taken to the Extreme, Handling Persistence and Crash Semantics Itself

**Settlement**: Refuses functional-only memory model, building a reference implementation (RefFS) handling persistence and crash semantics itself, elevating RefFS from "reserve candidate" to **active commitment**. "Taken to the extreme" means semantic level: RefFS operates in memory strictly via POSIX operations, defining what counts as persisted after each fsync and which POSIX states are permissible after crash, having no on-disk format; disk-writing and disk-recovering tier (effort approximating building another file system) is rejected. RefFS and implementation forbidden from sharing crash-point enumeration code: "three-oracle collusion test" (settled item 6) guards against shared misunderstanding, most critically "whether RefFS and implementation share identical flawed understanding of crash semantics".

Crash semantics (serial commit, fault-free crash states):

1. **fsync**: Upon successful return of fsync, all operations carried by the publish awaited by this fsync must be present (under serialization, all operations whose number acquisition succeeded before the call began, counted in units); read by state index, raising lower bound lo of allowed set to end of that publish. Errored fsync does not raise lo, operations of errored publish optionally present; subsequent operations judged against state read on next recovery.
2. **Drop rule: prefix by publish boundary**. When crash occurs during operation hi, recovery permits reading {S_j : j = lo, or j is end of an explicit publish; lo ≤ j ≤ hi}, where S_j is state resulting from applying first j operations after previous recovery, and S_0 is content read on previous recovery. Dropping arbitrary subsets is excluded under serial commit (incompatible with D16 (Publish Semantics) settled item 12), reopened under concurrency.
3. **Raising lo**: Successful publish calls, fsync, and rollback all raise lo (D16 (Publish Semantics) settled item 7: rollback and fsync share return condition); rollback counts as confirmed publish, its index marking publish end.
4. **Rollback**: Rollback is an operation in RefFS; post-rollback content equals content following m-th confirmed publish across entire history; m passed in by caller from root reported by implementation, RefFS does not judge whether target selection is correct. m covers every root-writing entry point (publish call, rollback, write row and warm-up, raise F, unmount), mapping to active version when written, active version including that read on recovery and restarted.
5. **Attribution of crash moment**: Operation index hi where crash occurs is attributed by "which step issued the barrier cutting current segment", not by first intercepted write; used only by RefFS, O1 (In-Memory Model Differential Testing (HashMap Ideal File System)) crash judge untouched.
6. **Post-recovery**: Following each recovery, RefFS first verifies that read state lies within allowed set, then advances from that state as starting point.

**Scope**: Settles ambition level and form of RefFS, not scheduling; must not be read as "building RefFS before implementation"—RefFS is verification vehicle, not milestone (`.claude/rules/format-evolution.md` "start from writing, not reading"). Explicit publish points take only publish calls and fsync in history: until automated batch accumulation lands, RefFS interfaces only with explicit publish points; automated publishes outside RefFS scope, belonging to settled item 1 M2 and record checker; recoveries discarding newest root cause RefFS to restart from read content without judging that step. Faulty crash states (lying devices, whole disk loss C519 (Recovery loses newly confirmed version when entire disk lost)) inapplicable. Independence: RefFS reads no recording streams, calls no segmentation or state planning, but its (lo, hi) shares origin with inputs to O1 (In-Memory Model Differential Testing (HashMap Ideal File System)) crash judge disk-level lower bound criterion, logged under C191 (homology counter covers only single pair). #### Settled Item 4: Crash-Point Replay Enumerates Full Write Subsets Only

**Settlement**: The crash state set to be enumerated by crash-point replay is defined as: recorded write request stream is segmented **by device**—a write is ordered before subsequent writes only by subsequent barriers on its own disk (or FUA writes on its disk); current segment closes only when every disk with writes in the segment is released by its own barrier or FUA; if any disk has unreleased writes, that barrier (or FUA) does not close segment, and writes before and after belong to same segment. A crash state is "preceding segments all persisted, each write in current segment takes one of its states in arbitrary combination, subsequent segments all non-persisted"; enumeration unit is **one full write**. FUA writes release only their own disk: grouped in same segment with preceding unseparated writes on that disk, writes on other disks not persisted thereby. A write takes two states (persisted / non-persisted); **in-place overwrites** (non-unit writes longer than a sector covering pre-existing content, such as system configuration slot writes and journal writes overwriting old records) take a third state "neither new nor old readable", enumerated in both full run and quick tier; third-state images cover entire write range, differing bytes split with first half new bytes and second half old bytes (torn by byte, not sector); torn states of other writes collapsed into "write non-persisted". In "non-persisted" positions, images retain **pre-crash old bytes at that position**, not zeroes, and these images (including third-state) are concretely generated and fed to checker and record checker, never treated as mere counters. Mirrored writes (w ≥ 2 of D2 (RAID Stripe Policy) settled item 6, journal mirroring of D22 (Synthesizing Unit Atomicity) settled item 8) counted as distinct writes per **device**, harness state counts computed via closed form per write stream. **Adjacent barriers on same disk collapsed into one**: when recording stream contains consecutive barriers on a disk without intervening writes (barriers on other disks do not count as writes), second barrier omitted (`push` in `crates/singlefs-harness/src/lib.rs`), independent model recording identically; lacking intervening writes, segment produces zero crash states, merging affecting only operation count and kind string without altering crash state set.

**Scope**: Defines enumeration domain at model layer. Whether FLUSH / FUA take effect on real devices as advertised belongs to C6 (Wrong Block Layer Semantic Assumptions Written), verified in QEMU with real devices. Segmenting by device yields states unreachable in practice (writes released on other disks remain combinable in segment when one disk unreleased), without missing reachable states. Tearing falls into two categories: writes outside in-place overwrites (unit writes, sub-sector writes, writes over empty ranges) differ from "non-persisted" solely by CRC32C collision probability (32-bit, D19 (Block Pointer Structure & Width Budget) settled item 2, D23 (Journal Role & Format) settled item 11), an **informed acceptance**; tear granularity excluded from model, consistent with D20 (Load-Bearing Surface: Unit Atomicity & Self-Containment) "units with parent pointers depend on no width"; in-place overwrite tears lose old content as well, whereas "non-persisted" retains complete old content, representing distinct states, hence enumerated separately. Crash-point replay sectors take 512 bytes; system configuration slot writes are sole source of third-state on both crash replay streams. Known corner case: third-state old bytes take version where "writes prior to this write fully landed", combinations where earlier overlapping writes in same segment failed to land contain extra bytes (such combination occurs zero times across both streams); multi-sector root slot writes over old content do not support third state in first version (harness assertion; pools built with 512-byte physical blocks, unreachable). Device tearing writes to match checksum collisions excluded from model. D13 (Verification Route) settled item 5 orthogonal: one defines enumeration domain, other defines crate boundaries.

**Basis**:

#### Settled Item 8: Two Custom-Developed Mechanisms: Merkle Root Chain Diff and Generational Incremental Scrub

**Settlement**: Two mechanisms unavailable off-the-shelf and custom-developed for this project:

**1. Merkle root chain diff —— Leverage unique to COW + new root per transaction.**
Historical roots physically exist prior to reclamation, forming replayable chain. Recursively comparing "subtree pointer + checksum/MAC" across adjacent root generations,
**directly skipping identical pointers without descending**, with complexity proportional strictly to actual modifications between generations.
Detects error class undetectable by traversal checker: **in-place writes self-consistent after synchronous tampering**—
a write bypassing COW modifying block in-place while synchronously updating checksum appears self-consistent in isolation (I-2.1 (Checksum Matches Content) all green),
whereas root chain diff exposes contradiction: **lacking COW, no new allocation should occur; parent pointer should remain unchanged, yet checksum altered**.
⚠️ **Must pair with negative control**: running same check post-normal COW commit must be all green, avoiding flagging normal updates as tampering.

**2. Generational incremental scrub.** Leveraging I-1.2 (block header write order published) and D5 (Snapshot / Space Accounting Mechanism) birth txg
to maintain "generation watermark scanned in previous scrub", traversing only blocks with `birth generation > watermark`—
checksum chains of older subtrees remain self-consistent if unaltered. **Enables "verifying current change completely on every commit" within wall-clock constraints without sampling.**

**Scope**: Re-located replicas retain original `birth`, permanently falling below watermark, invisible to generational incremental scrub. Neither root chain diff (`grep -rn 根链 crates` yields 0 hits) nor generational scrub (`grep -rn scrub crates` yields 0 hits) exists in `crates/`.

**Basis**:
- No experiment: Both rely on structural properties of COW new root per transaction and birth txg; neither implemented, lacking measurable quantities.
