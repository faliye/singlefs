#### 已定项 3：内联阈值取多少

**定案**：内联阈值 0，即不内联。**小文件一律走独立数据 extent**（按 D4（校验和位置） 已定项 2 补齐到 32 KiB），**不内联进索引节点，一个字节都不内联。**

**判据是原子性，不是性能。** 内联让**多个文件的数据挤在同一个索引节点里** ⇒ 一个文件的写牵动同节点上其他文件的原子单位。这与 E66（补齐之后小文件怎么落） 判出局的 `pack` 臂（多个小文件共享一个数据单元）**是同一个形状的耦合**，只是换了个容器。原子性从此是这一项的判据本身，不只是这一次的取值理由：**今后任何抬高内联阈值的提议，都要先答「多个文件共享一个原子单位」这一关**，性能数字答不了它。

写路径上的**跨文件尾部打包**同样判**否**：两个文件共享一个单元 ⇒ 写其中一个要 COW 整个单元 ⇒ **另一个文件的指针也得改**，**D20（承重面：单元的原子性与自包含） 的「单元自包含」当场破掉**。抬高内联阈值本质上就是尾部打包，只是容器是 btree 叶子而不是裸块 ⇒ 化归这一项，这一项取 0 ⇒ 那条路当前不启用。

**射程**：

- 这一关对打包记录单元的答案（D8（核心索引结构） 已定项 6）：inode 记录打包进码 3 叶容器是 233 个对象共享一个 32 KiB 单元，形状与内联相同，答案不是性能数——D18（块里携带什么信息） 已定项 11 登记的打包记录单元这一类正是为「多个对象共享一个自描述单元」而立，它有自己的身份（出生树、类型、容器号、出生代）与载荷校验和，一个对象的记录不靠别的对象自证；COW 下一个对象的更新写出新版容器、旧版不动，原子性按发布，不会撕另一个对象；文件数据仍不内联。剩下的两笔是代价（E103（inode 打包路 ① 的更新代价） 实测单次更新 1.25–1.5 倍）与爆炸半径（C100（inode 容器丢失是永久损失而没有任何冗余条款覆盖它）），都已立账。
- 这一关对数据侧后台打包容器的答案在 D27（小数据打包容器） 已定项 10 的射程里：「搬出去」这个形态下写其中一个对象根本不 COW 容器，跨文件尾部打包那条「否」的理由够不到它；那条「否」本身不动。
- 代价，知情接受（量在 E66（补齐之后小文件怎么落） 与 E68（内联阈值取多少） 页上，不是这一项的依据）：空间上 512 B 文件占 **64 倍**（补齐到 32 KiB），1 KiB 占 32 倍；点读比内联慢，量级未定——E66（补齐之后小文件怎么落） 的不对称记账给 16.6%，对称记账给 54.5%（叶不命中）到 100%（叶命中）；缓存上 E68（内联阈值取多少） 的读模型说 16 MiB 及以上缓存档内联好 10%；知情放弃的那条路能省的数据字节见 E8（大文件与小文件是否该走不同写路径） 的阳性对照（4096 个 64 B 文件，不分流臂实付 16 MiB，内联臂 0 字节）。
- 换回来的：写侧快 **一个数量级**（E66（补齐之后小文件怎么落） 设备侧：独立 extent 首次写不必 RMW，25.0 μs vs 内联 247.8 μs）——这一句与 D4（校验和位置） 已定项 3「首次写不设例外」说反话，没判，欠在 C385（首次写要不要读回，两条已定项说反话）；元数据工作集不涨（内联会让每文件 64 B → 89 B、叶数 1.40×）；以及**跨阈值迁移这条路径整个消失**——阈值为 0 就没有「内联 → extent」这一步，E8（大文件与小文件是否该走不同写路径） 记的「阈值不是合格的分支变量」这条约束因此不再适用（它拦的是「追加写在操作中途跨过阈值」）。

#### 已定项 6：分轨只落在两层，不做格式级第二轨

**定案**：分轨**只落在这两层，不做格式级第二轨**——不做第二套校验语义、第二本账、第二套恢复语义。

|---|---|---|

将来任何一条多轨提议按 day-1 多轨兼容的可判据判（推导 D-3（多轨兼容可判据））。**最强形态是「轨道只减承诺、不改编码」**：轨道字段只降低耐久性承诺，绝不改变任何字节布局；可判定形式（若采纳，届时在 [invariants.md](../invariants.md) 新开一条）：**把任一指针的 track 字段抹成 0 之后，它必须仍能被单轨解析器逐字节解析，且校验和 / MAC / nonce / birth txg / 反向索引语义一字不变。** 在这个形态下 inode 的轨道**不存**，是其全部 extent 轨道算出来的下确界 ⇒ 混合态天生合法，「迁移」退化成翻两个位、与那次本来就要重写指针的事务合并，**没有数据搬运、没有重新编码、没有重算 MAC**。

| 3 | **轨道在对象创建时确定，此后永不改变** | 枚举全部能改变轨道的入口，集合必须为空 |
| 4 | **D12（目标介质） 与 D6（快照实现模型） 已定** | track 要与 nonce 载体、快照 ID、locality_id 抢**同一段排序权** |

**判据 3 是可判定性的全部重量所在**：一条「出生即定、此后不变」的耐久性轨道就是不可撤销的声明，**它自动把持久/临时轴判出局，而不是靠历史归纳。** 本工程已经有一条满足全部四条的 day-1 多轨：D9（加密） 预留的「每个数据/元数据写的算法类型字段」——只减承诺不改编码（老数据按各自字段解）、谓词只读该写自身、**写下去那一刻就定死**。由此得到一条不对称结论：day-1 多轨对**大/小轴**帮助显著（翻转由操作自己引起，可以并进同一个事务），对**持久/临时轴**帮助为零（翻转来自操作范围之外）。**day-1 买到的准确表述是：格式能在翻转中存活，操作不能。**

|---|---|---|---|

**射程**：

- 分配器提示那一层撤回过「猜错只损失局部性」：猜错直接进 ENOSPC（准入不等式把「不可回收」算进可用空间，D28（挂载期承诺量） 已定项 1，原住 D3（空间分配） 已定项 4）、变成必须付的搬运字节（D26（后台整理与放置回收） 已定项 1 的停机谓词），D3（空间分配） 已定项 5 是量过的先例；所以那一层只剩三个分句，是否仍然成立由 D14（双轨（大小文件 / 持久临时）） 已定项 2 答。
- 内联那一层的「迁移规模按构造有界」有界的是**迁移的规模**，不是**判据的稳定性**（追加写会在操作中途跨过阈值）；后者由已定项 3 消解——内联阈值取 0，没有阈值可跨。
- 按推导 D-3（多轨兼容可判据） 的可判据重算六样「少做」：真正变便宜的只有 **deadlist 一样**（I-3.1（已分配统计对得上） 从标量等式变成「按轨道分箱的向量等式 + 标量收缩」，判别力**净增**，能检出「总数对但归类错」这一整类）；另外两样是「省 0 字节但否决权消失」（反向索引）与「小幅变便宜」（恢复承诺）；其余三样（快照可见性、Merkle、nonce）净省为 0。⚠️ 使前三样成立的机制，恰恰是「让临时轨什么也不省」——这个设计用删掉收益的方式消掉了成本。

**依据**：

- 依据二（自推）：唯二不可撤销的声明，是靠禁掉翻转入口换来的，不是设计出了稳定的变量——`O_TMPFILE | O_EXCL`（`man 2 open`：「Specifying O_EXCL in conjunction with O_TMPFILE **prevents a temporary file from being linked into the filesystem**」，代价是这个文件永远不能有名字）与独立子卷 / 挂载点（跨边界 `rename` 返回 `EXDEV`，不是 per-file 的）；围起来之后「临时文件透明地走快路径」这个最初的诉求已经不在了，O_TMPFILE 表达的是「这个名字还不存在」，不是「这份数据是临时的」。
- 推导 D-3（多轨兼容可判据）：`linkat` 在 POSIX 下是 O(1)；一个带 1 TB 临时 extent 的对象被 `linkat` 挂进目录树，急切重标是 O(N) 元数据重写而 O(1) 承诺照样作废，惰性重标引入「尚未重标」这个在途派生状态而没有 D11（索引节点要不要留消息缓冲区） 已定项 3 / 5 那样的排空契约与陈旧可检出机制，意图日志重标在崩溃落在返回之后、重标完成之前时恢复丢弃一个已被成功 link 的文件的数据——病根不在 retrofit，在「承诺翻转来自操作范围之外」。
- E8（大文件与小文件是否该走不同写路径）：内联那一层的收益全集中在 ≤ 阈值、代价在读侧，追加写会在操作中途跨过阈值——「迁移规模按构造有界」只答了规模。
- 别家的记录（参考一、三、四、五：两条轴上都不存在操作期间稳定的分支变量、六样少做零样落在纯行为分支里、验证叉积 16 倍、历史上没有任何文件系统成功发布过格式级临时轨）**不许用来支撑或否定 D14（双轨（大小文件 / 持久临时））**；它们留着只有一个用处——当作 D-1（穷举翻转入口） / D-2（六样少做逐样推） 的检查清单，原文在变更史。
- 用户定案：原话在变更史。
