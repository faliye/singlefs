## D14 双轨（大小文件 / 持久临时）—— 半定（两层已采纳、格式级第二轨不采纳，四项未定）

**2026-08-26 用户定案：本决策不许拿文献或别家结局当依据，要自己推导和验证。**

### 采纳的两层（依据是机制推导，不是文献）

**采纳分轨，不追求万能方案**（`.claude/rules/fs-design.md`）。
但分轨**只落在下面两层，不做格式级第二轨**——不做第二套校验语义、第二本账、第二套恢复语义。
在推导 D-1（穷举翻转入口） / D-2（六样少做逐样推） 与 [experiments.md](../experiments.md) E11（双轨：收益与翻转代价，自己量） 给出结论之前，这两层维持采纳，
因为它们的依据**不依赖任何别家实现**。

| 层 | 做什么 | 为什么它不欠债 |
|---|---|---|
| **分配器提示** | 把小文件的块放到一起；把疑似短命的数据放进预期会整片释放的区域 | 不落盘、猜错只损失局部性、每次分配都可以重新判、**零格式位**。它连「分支」都不算——是同一条路径上的一个启发式参数。F2FS 的冷热分离就活在这一层：判据是 superblock 里一张文件名后缀表（`mkfs.f2fs -e/-E`），它只决定块进哪个 log，不改格式、不改校验、不改恢复语义 |
| **小文件内联进 inode** | 小到能塞进 inode 剩余空间的数据直接内联 | **迁移规模按构造有界**（≤ inode 剩余空间），「内联 → extent」是**一个有界事务**，不触发 D8（核心索引结构） 对无界操作的意图日志要求，不产生混合态 inode，per-inode 一个位就够 |

### 内联这一条已经被 E8（大文件与小文件是否该走不同写路径） 实测过，结论要写进来

[experiments.md](../experiments.md) E8（大文件与小文件是否该走不同写路径） 层 A（2026-08-28）给了三样东西：

**1. 交叉点不是文件大小的某个自然刻度，就是内联阈值本身。**
收益全部集中在 ≤ 阈值（该轮取 3584 B）：64 B 与 1 KiB 档省 **2.9–94.6 倍**写放大；
**4 KiB 及以上四条臂逐格相同（1.00），一档收益都没有。**

**2. 内联的代价在读侧，而且很大。** 1 KiB 档内联把每条 inode 记录撑到约 1152 字节，
每叶装得下的记录数塌下来：设备读次数 **47 → 293（6.2 倍）**，每文件元数据 692 → 1644 字节。
⇒ **写放大与读次数在这一档上方向相反，只看写放大会选错。**

**3. 追加写会在操作中途跨过阈值 ⇒ 阈值不是合格的分支变量。**
4 KiB 文件分 8 次追加时，前 7 次的累计大小都在阈值以下，内联臂因此仍拿到 **6.96 倍**收益；
而同样的 4 KiB 文件**一次写完**时收益恰好 **1.00**。
**同一个文件大小、两个写形态，判据落在阈值两侧。**
⇒ **`.claude/rules/fs-design.md` 硬要求 5 被这条分支违反**，
除非另设跨阈值迁移路径并**单独验它的崩溃语义**。

⚠️ **这一条收窄了「采纳的两层」表里「小文件内联进 inode」那条依据。**
那条依据说「迁移规模按构造有界」——**有界的是迁移的规模，不是判据的稳定性**。
两者是不同的问题：前者管「迁移这个事务大不大」，后者管「什么时候决定要不要迁移」。
**本决策只答了前者，后者未答。**

### 「小文件占满盘」这件事，已解决与未解决的分界

| 区间 | 状态 |
|---|---|
| **≤ 内联阈值** | **已解决**：内联进 inode，数据字节为 0（E8（大文件与小文件是否该走不同写路径） 阳性对照实测：4096 个 64 B 文件，不分流臂实付 16 MiB，内联臂 0 字节） |
| **内联阈值 ~ 一个分配单元** | **未解决，且是主要痛处**。按 D19（块指针的结构与宽度预算） 的模型几何（16 KiB 单元），一个 4 KiB 文件占 16 KiB，浪费 4×，而内联够不着它（E8（大文件与小文件是否该走不同写路径） 实测该档收益 1.00） |
| **≥ 一个分配单元** | 不构成问题 |

**中间那段的三条候选，判据各不相同**：

| 候选 | 判 |
|---|---|
| **抬高内联阈值** | **可行，且不需要新机制**——它本质上就是尾部打包，只是**容器是 btree 叶子而不是裸块**，而索引树本来就在把变长记录打包进节点。代价曲线 E8（大文件与小文件是否该走不同写路径） 已量出（读侧 6.2 倍）。⇒ 问题化归为未定项 2「阈值取多少」 |
| **跨文件尾部打包**（多个文件共享一个物理单元） | **否**。两个文件共享一个单元 ⇒ 写其中一个要 COW 整个单元 ⇒ **另一个文件的指针也得改**。COW 下这是跨对象写放大，且一个对象的写路径要去改另一个对象的元数据，**D20（承重面：单元的原子性与自包含） 承重面的「单元自包含」当场破掉**。⚠️ 旁证（2026-08-28 现查 Linux 7.2.0）：Linux 里唯一做 tail-packing 的是 **erofs，而它是只读的**（`fs/erofs/super.c:658` 无条件置 `SB_RDONLY`）；可写的几家都只做 inline（btrfs `BTRFS_DEFAULT_MAX_INLINE = 2048`，`fs/btrfs/fs.h:352`）。**这是旁证不是证明**——它说明「可写 + 尾部打包」没人做成，不说明做不成 |
| **减小分配单元** | 是 D12（目标介质） / D19（块指针的结构与宽度预算） 的参数，不是新机制。⚠️ 代价已由 E20（指针变宽的 CPU 缓存代价） 量出（指针宽度在小节点上的 CPU 缓存代价接近翻倍），**不能只按空间利用率定** |

### 推导 D-3（多轨兼容可判据）：day-1 多轨兼容的可判据（不依赖任何历史归纳）

**问题**：如果 day-1 就把多轨设计进格式（per-extent 轨道字段、混合态天生合法、
feature bit 预留够），那六样的账要重算成什么样？

**最强形态是「轨道只减承诺、不改编码」**：轨道字段只降低耐久性承诺，
绝不改变任何字节布局。可判定形式（若采纳，届时在 [invariants.md](../invariants.md) 新开一条，编号按「只往上加」的规矩现取）：
**把任一指针的 track 字段抹成 0 之后，它必须仍能被单轨解析器逐字节解析，
且校验和 / MAC / nonce / birth txg / 反向索引语义一字不变。**

在这个形态下，inode 的轨道**不存**，是其全部 extent 轨道算出来的下确界——
于是混合态天生合法，「迁移」退化成翻两个位，与那次本来就要重写指针的事务合并，
**没有数据搬运、没有重新编码、没有重算 MAC**。

**重算结果**：六样里真正变便宜的只有 **deadlist 一样**（I-3.1（已分配统计对得上） 从标量等式变成
「按轨道分箱的向量等式 + 标量收缩」，判别力**净增**，能检出「总数对但归类错」这一整类）。
另外两样是「省 0 字节但否决权消失」（反向索引：等宽等语义则临时块照常进反向索引，
与 D1（数据可移动性 / 反向索引） 的冲突消失）与「小幅变便宜」（恢复承诺可降为既有 keyspace 的新 key 变体）。
**其余三样（快照可见性、Merkle、nonce）净省为 0。**

⚠️ **使前三样成立的机制，恰恰是「让临时轨什么也不省」——这个设计用删掉收益的方式消掉了成本。**

**四条判据（全部是设计期常量，无一是操作期间会变的量）**：

| # | 判据 | 怎么判 |
|---|---|---|
| 1 | **轨道字段只减承诺、不改编码** | 抹成 0 后仍可被单轨解析器逐字节解析。写成不变量，checker 可判，且能证明会红（构造一个两轨不等宽的镜像） |
| 2 | **每一条被减掉的承诺，都能写成只读该指针自身字段的谓词** | 把谓词实现签名钉成 `fn(&Pointer) -> bool`，多一个入参即判红 |
| 3 | **轨道在对象创建时确定，此后永不改变** | 枚举全部能改变轨道的入口，集合必须为空 |
| 4 | **D12（目标介质） 与 D6（快照实现模型） 已定** | track 要与 nonce 载体、快照 ID、locality_id 抢**同一段排序权**；在它们定型前给 track 分配排序权，等于替它们做主 |

**判据 3 是可判定性的全部重量所在，也是它自洽的地方：**
一条「出生即定、此后不变」的耐久性轨道，就是不可撤销的声明。
**判据 3 自动把持久/临时轴判出局，而不是靠历史归纳。**

**这条判据不是空的——本工程已经有一条满足全部四条的 day-1 多轨：
D9（加密）预留的「每个数据/元数据写的算法类型字段」。**
它只减承诺不改编码（老数据按各自字段解）、谓词只读该写自身、
**写下去那一刻就定死、此后永不改变**、且已随 D9（加密）定案。
**它成立正是因为满足判据 3；而耐久性轴无法满足。**

**由此得到一条不对称结论**：day-1 多轨对**大/小轴**帮助显著
（翻转由操作自己引起，可以并进同一个事务），对**持久/临时轴**帮助为零（翻转来自操作范围之外）。
而大/小轴本决策**已经采纳**（有界内联 + 分配器提示）。

**day-1 买到的准确表述是：格式能在翻转中存活，操作不能。**
`linkat` 在 POSIX 下是 O(1)；一个带 1 TB 临时 extent 的对象被 `linkat` 挂进目录树，
三条出路各自的结局是：急切重标 = O(N) 元数据重写、**O(1) 承诺照样作废**；
惰性重标 = 引入「尚未重标」这个在途派生状态，**正是 D11（索引节点要不要留消息缓冲区） 被否掉的那个东西换了个地方**；
意图日志重标 = `linkat` 变成发起一个无界操作，**崩溃落在返回之后、重标完成之前
⇒ 恢复丢弃一个已被成功 link 的文件的数据**。

⚠️ **最后这条的形状与 D14（双轨（大小文件 / 持久临时）） 参考里那条 btrfs 内核 commit 逐字相同
（`write()` 返回成功之后数据丢失）——从零设计、格式全新，走到了同一个坑。
因为病根不在 retrofit，在「承诺翻转来自操作范围之外」。**
这是用自己的推导得到的结论，不是照抄别家结局。

### 不采纳格式级第二轨：一条依据、四条参考

**口径**：本节只有**依据二**参与判断，它是自推的、不依赖任何别家实现。
标为**参考**的四条是别家的记录，本工程未验证，**不许用来支撑或否定本决策**
（本决策开头已定：不许拿文献或别家结局当依据）。
它们留着只有一个用处——**当作推导 D-1（穷举翻转入口）/D-2（六样少做逐样推） 的检查清单，看自己有没有漏掉某个入口或某样代价**。
编号在依据与参考之间连续，不重排。

**参考一（待自推验证）：两条轴上都不存在「操作期间稳定的分支变量」。**

`.claude/rules/fs-design.md` 硬要求 5 要求分支变量在操作期间不变，
D8（核心索引结构） 已经列举过合格的输入：介质类型、受影响 key 是否连续、操作开始时的规模估计——
共同性质是「在操作外部，且操作本身不改变它」。

- **大/小轴**：`open(O_CREAT)` 时 size=0，**每个文件出生都是小文件**，判据在做决定的那一刻永远返回同一个答案；
  `truncate` 让阈值**双向可穿**；「大小」还是 `i_size` / 已分配块数 / extent 条数三个互相矛盾的候选
  （`ftruncate(fd, 1TB)` 后是「i_size 大、分配 0」，`PUNCH_HOLE` 后反向）。
- **持久/临时轴**：它比「中途改变」更糟——分支变量会被**操作范围之外的第三方异步翻转**。
  已枚举的入口：`linkat`（O_TMPFILE 挂进目录树）、`fsync`、**快照捕获**（一次操作把整个子卷内每个文件的分类同时翻转）、
  `rename` 到持久路径、硬链接把持久文件挂进临时目录、mmap 脏页在翻转后回写、配额。
  **每一个入口都是 POSIX 已经承诺为 O(1) 或原子的操作**，把轨道迁移挂上去等于把这些承诺作废。

**依据二：唯二不可撤销的声明，是靠禁掉翻转入口换来的，不是设计出了稳定的变量。**

| 声明 | 为什么不可撤销 | 代价 |
|---|---|---|
| `O_TMPFILE \| O_EXCL` | `man 2 open` 原文：「Specifying O_EXCL in conjunction with O_TMPFILE **prevents a temporary file from being linked into the filesystem**」 | 这个文件**永远不能有名字**，只能靠 fd 传递 |
| 独立子卷 / 挂载点 | 跨边界 `rename` 返回 `EXDEV`，内核替你拒绝翻转 | **不是 per-file 的**，而且它就是 tmpfs 已经是的东西 |

围起来之后，「临时文件透明地走快路径」这个最初的诉求已经不在了。
另外 `man 2 open` 明写 O_TMPFILE 的两个主要用途之一就是**变成永久文件**
（写好后用 `linkat` 原子地挂进文件系统）——**它表达的是「这个名字还不存在」，不是「这份数据是临时的」。**

**参考三（D12（目标介质） 定案后必须重算）：要少做的六样，零样落在纯行为分支里。**

判定标准是「这件事能不能只看一个镜像判出来」，判不出来就必须有盘上事实。

⚠️ **本表的判定基于「不为多轨预留格式字段」这个前提，该前提正在被重新审视**——
若 day-1 就把多轨设计进格式（per-extent 轨道字段、混合态 inode 天生合法、
feature bit 预留够），这张表要重算。重算的前置是格式冻结政策（见 D15（格式冻结政策））。

| 要少做的 | 判定（在「不预留」前提下） | 机制 |
|---|---|---|
| 快照可见性 | 格式 | 挂载时必须知道哪些对象不被快照捕获，这知识只能来自盘 |
| deadlist 记账 | 格式 | 释放块时判「进不进 deadlist」，判据必须来自块自己（D5（快照 / 空间记账机制） 就是这么设计的）。若临时块单开一本账，I-3.1（已分配统计对得上） 就从**一条对照**退化成两条各自对账，**唯一那条独立对照消失**——与 D11（索引节点要不要留消息缓冲区） 否掉「消息独立成树」是同一个论证 |
| Merkle 链 | 格式或白省 | 只有两种实现：指针宽度不同 = 两种指针格式 = 永久分支；宽度相同、字段标为无效 = **一个字节都没省**，只省 CPU |
| nonce | **绝对少不了** | I-6.1（nonce 不重用） 的 checker 阶段 ② 要全盘扫描已分配区间、靠明文头识别「这是不是一个 singlefs 块」。一个不带标准明文头的临时块，会让阶段 ② **分辨不出它是不是本文件系统的块**——检查全绿而判别力为零 |
| 恢复承诺 | 格式 | 挂载时要知道哪些 inode 可以直接丢，而 `.claude/rules/fs-design.md` 明写「任何要事后扫一遍才能算出来的记账设计一律否决」⇒ 必须有一棵持久的临时对象树 ⇒ 新 keyspace ⇒ 进格式 |
| 反向索引 | 格式，且违反 D1（数据可移动性 / 反向索引） | 临时块不进反向索引 ⇒ balance / copygc **搬不动它** ⇒ 它是永久碎片源，缩容与移除设备会卡在它上面 |

**参考四（D12（目标介质） 定案后必须重算）：验证叉积 16 倍。**

已在册的配置维度：D8（核心索引结构） 范围重建/逐项修改（2）× D2（RAID 条带策略） 条带宽度（3）× D12（目标介质） 若定成两者都一等（2）× D9（加密）加密开关（2）= **24**。
加双轨（迁移路径本身也是分支）：大/小 4 档 + 持久/临时 4 档 → **24 × 4 × 4 = 384，16 倍**。
⚠️ 这个比值是纯组合推算；具体挂钟依赖尚不存在的实现，无法量。
而 [checks-owed.md](../checks-owed.md) 的 C8（门禁范围判不出来）状态是「零前置的纯欠工」——**现在没有任何东西在拦这个膨胀**。

**参考五（不作依据）：历史上没有任何文件系统成功发布过格式级临时轨。**

⚠️ **这一条是「无证据」，不是「有反证」，因此列为参考而非依据。**
本参考所列的每一个案例都是**往既有格式上补**的：btrfs 的 nodatacow 是补的、
XFS realtime 的 reflink 与 rmap 是后来才加的、ZFS 的 `special_small_blocks`
是 2019 年加进 2005 年定的格式、ext4 的 `data=writeback` 继承自 ext3。
**它们承载的结论是「retrofit 很贵」，不是「从零设计也不行」。**
本工程没有它们的历史包袱，这条差异必须写明，不能拿它们的结局直接外推。

| 实现 | 原文与结局 |
|---|---|
| btrfs `chattr +C` | 跨阈值迁移的历史答案是**宣布为未定义**：`chattr(1)` 原文「If it is set on a file which already has data blocks, **it is undefined when the blocks assigned to the file will be fully stable**」 |
| btrfs `nodatacow` | 第二轨要付的是丢掉校验和：`man 5 btrfs` 原文「**Nodatacow implies nodatasum, and disables compression**」。且它被快照压倒——NOCOW 文件只要引用数 > 1，写它仍然 CoW；社区的规避办法是「放进单独子卷并且不对它做快照」 |
| btrfs NOCOW 的数据丢失 bug | 内核 commit「fix unexpected failure of nocow buffered writes after snapshotting when low on space」（backport 到 4.14 / 4.18 stable）：空间不足时 nocow 写**不预留空间**就返回成功，建快照强制此前的写回退到 COW，回退因无预留而 ENOSPC ⇒ **`write()` 返回成功之后数据丢失**。修法不是「处理翻转」，是新增 `snapshot_force_cow` 让已开始的写按旧轨走完、新的写提前失败——正是硬要求 5 的内容，用一个 stable backport 学回来 |
| ext4 `data=writeback` | `man 5 ext4` 原文：收益是「This is **rumoured** to be the highest-throughput option」，代价是「**can allow old data to appear in files after a crash**」。**内核手册无法把收益写成事实，却把代价写成事实**；且它是挂载全局的，ext4 二十年没能把 data 模式做成 per-file |
| XFS realtime subvolume | 格式级第二轨的三十年账单：**quota 从来不支持带 realtime volume 的文件系统**（即使一个 realtime 文件都没有）；reflink 与 rmap 直到 Linux 6.13 / 6.14（2025）才落到 realtime 设备。**它缺的恰好是 D1（数据可移动性 / 反向索引） 反向索引与 D5（快照 / 空间记账机制）/D6（快照实现模型） 快照，两条都是本工程 day-1 硬承诺** |
| ZFS `special_small_blocks` | 按大小分轨的现役实现，三个毛病：改阈值**不追溯**（盘上同时躺着按每一个历史阈值放置的数据且无法分辨）；special vdev 写满后**静默回落**（硬要求 4「走错分支是性能悬崖，而悬崖不报错」的现役实例）；判据是**压缩后**大小，与 `recordsize` 耦合 |
| Windows `FILE_ATTRIBUTE_TEMPORARY` | **唯一一个主流的 per-file 临时声明**，而它整个关在页缓存层（「a hint to the **cache manager**」），**一个字节的盘上格式都没动**，并要求应用配上不可撤销的 `FILE_FLAG_DELETE_ON_CLOSE` |

口径：man page 为本机 2026-08-26 现查并逐字核对；其余为公开记录，**未在本工程验证**。

### 与「AI 协同不需要过度抽象」这条前提的关系

**这条前提本身成立，本决策不依赖推翻它。**
`.claude/rules/fs-design.md` 已经接受它——被解除的那条成本（一个维护者要把整套装进脑子里）确实被解除了。
本决策的那一条依据与四条参考**没有一条依赖「人记不住」或「代码太多读不完」**，
全部落在那四样明写**没有被解除**的成本上：验证是组合的、格式分支是永久的、门禁挂钟是真的、罕见分支会腐坏。

### 未定项

1. **参考三在「day-1 多轨兼容」前提下要重算。** 用户提出：那六样之所以贵，
   可能只是因为历史实现都在往既有格式上补。这一条的前置是 D15（格式冻结政策）——
   多轨能不能 day-1 预留，取决于「什么时候冻结、冻结后怎么加东西」有没有答案。
2. **分配器提示的判据写成什么。** F2FS 用 superblock 里的后缀表，本工程用什么？
   判据必须显式、可计算、写下来（硬要求 1），且要能被测试强制进入（硬要求 2）。
3. **内联阈值取多少**，以及内联 → extent 那个有界事务的崩溃语义。
4. **「持久/临时」是不是 D11（索引节点要不要留消息缓冲区） 缺的那个判据** —— **判为不成立**：
   该判据会被 `linkat` / `fsync` / 快照 / `rename` 从操作范围之外异步翻转（参考一）。
   D11（索引节点要不要留消息缓冲区） 仍然缺一个合格的分支变量。
