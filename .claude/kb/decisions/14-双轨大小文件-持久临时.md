## D14 双轨（大小文件 / 持久临时）—— 半定（两层已采纳、格式级第二轨不采纳，三项未定）

**2026-08-26 用户定案：D14（双轨（大小文件 / 持久临时））不许拿文献或别家结局当依据，要自己推导和验证。**
理由：那批依据的口径问题已经暴露过一次——所举案例全部是往既有格式上补的，
承载的是「retrofit 很贵」，不是「从零设计也不行」。
再叠一层：**D12（目标介质） 已定多种介质各自一套布局**，本工程已接受「多套格式分支」这个形态，
所以「格式分支永久」这条成本对 D14（双轨（大小文件 / 持久临时））的边际增量必须重算，不能沿用。

### 拆成两半：可穷举的推导 + 要自己量的实验

| 推导 | 简称 | 推的是什么 |
|---|---|---|
| D-1 | 穷举翻转入口 | 穷举所有能改变「对象 → 轨道」映射的入口 |
| D-2 | 六样少做逐样推 | 六样「少做」逐样推「能不能只看一个镜像判出来」 |
| D-3 | 多轨兼容可判据 | day-1 多轨兼容的可判据，不依赖任何历史归纳 |

**D-1（穷举翻转入口）** 的判据来自 `.claude/rules/fs-design.md` 硬要求 5（分支变量不许在操作中途改变）。
要产出一张**穷举表**：每一个能改变该映射的系统调用 / 内部事件各一行，写清它改的是什么、
改动是否原子、正在进行的操作怎么收场、能不能禁掉它。已知至少有：`linkat` / `rename` / `fsync` /
快照捕获 / 硬链接 / mmap 脏页回写 / 配额结算 / `truncate` / `fallocate`——**这张表必须自己推完并证明穷尽。**

**D-2（六样少做逐样推）** 是定义推导：判不出来 ⇒ 必须有盘上事实 ⇒ 落进 D12（目标介质） 已接受的格式分支预算里，
而不是新开一笔债。**验证这一半见 E11（双轨：收益与翻转代价，自己量）。**

### 采纳的两层（依据是机制推导，不是文献）

分轨**只落在这两层，不做格式级第二轨**——不做第二套校验语义、第二本账、第二套恢复语义。

| 层 | 做什么 | 为什么它不欠债 |
|---|---|---|
| **分配器提示** | 把小文件的块放到一起；把疑似短命的数据放进预期会整片释放的区域 | 不落盘、猜错只损失局部性、每次分配都可以重新判、**零格式位**。F2FS 的冷热分离就活在这一层：判据是 superblock 里一张文件名后缀表（`mkfs.f2fs -e/-E`），只决定块进哪个 log |
| **小文件内联进 inode** | 小到能塞进 inode 剩余空间的数据直接内联 | **迁移规模按构造有界**（≤ inode 剩余空间），「内联 → extent」是一个有界事务，不触发 D8（核心索引结构） 对无界操作的意图日志要求，per-inode 一个位就够 |

**E8（大文件与小文件是否该走不同写路径） 层 A（2026-08-28）给了三样**：

1. **交叉点不是文件大小的某个自然刻度，就是内联阈值本身**：收益全集中在 ≤ 阈值（该轮 3584 B），
   64 B 与 1 KiB 档省 **2.9–94.6 倍**写放大；**4 KiB 及以上四条臂逐格相同（1.00）**。
2. **内联的代价在读侧，而且很大**：1 KiB 档内联把每条 inode 记录撑到约 1152 字节，
   设备读次数 **47 → 293（6.2 倍）**，每文件元数据 692 → 1644 字节
   ⇒ **写放大与读次数在这一档上方向相反，只看写放大会选错。**
3. **追加写会在操作中途跨过阈值 ⇒ 阈值不是合格的分支变量**：4 KiB 文件分 8 次追加时内联臂拿到 **6.96 倍**，
   一次写完时恰好 **1.00**——**同一个文件大小、两个写形态，判据落在阈值两侧**
   ⇒ 硬要求 5 被这条分支违反，除非另设跨阈值迁移路径并**单独验它的崩溃语义**。

⚠️ **这收窄了「小文件内联进 inode」那条依据**：「迁移规模按构造有界」有界的是**迁移的规模**，
不是**判据的稳定性**。**D14（双轨（大小文件 / 持久临时））只答了前者，后者未答。**

### 「小文件占满盘」的分界

| 区间 | 状态 |
|---|---|
| **≤ 内联阈值** | **已解决**：内联进 inode，数据字节为 0（E8（大文件与小文件是否该走不同写路径） 阳性对照：4096 个 64 B 文件，不分流臂实付 16 MiB，内联臂 0 字节）|
| **内联阈值 ~ 一个分配单元** | **未解决，且是主要痛处**：按 D19（块指针的结构与宽度预算） 的模型几何（16 KiB 单元），一个 4 KiB 文件占 16 KiB，浪费 4×，而内联够不着它 |
| **≥ 一个分配单元** | 不构成问题 |

| 中间那段的候选 | 判 |
|---|---|
| **抬高内联阈值** | **可行，且不需要新机制**——它本质上就是尾部打包，只是**容器是 btree 叶子而不是裸块**。代价曲线 E8（大文件与小文件是否该走不同写路径） 已量出（读侧 6.2 倍）⇒ 问题化归为未定项 3 |
| **跨文件尾部打包** | **否**：两个文件共享一个单元 ⇒ 写其中一个要 COW 整个单元 ⇒ **另一个文件的指针也得改**，**D20（承重面：单元的原子性与自包含） 的「单元自包含」当场破掉**。旁证（2026-08-28 现查 Linux 7.2.0）：Linux 里唯一做 tail-packing 的是 **erofs，而它是只读的**（`fs/erofs/super.c:658` 无条件置 `SB_RDONLY`）；可写的几家都只做 inline（btrfs `BTRFS_DEFAULT_MAX_INLINE = 2048`）。**这是旁证不是证明** |
| **减小分配单元** | 是 D12（目标介质） / D19（块指针的结构与宽度预算） 的参数，不是新机制。⚠️ 代价已由 E20（指针变宽的 CPU 缓存代价） 量出（指针宽度在小节点上的 CPU 缓存代价接近翻倍），**不能只按空间利用率定** |

### 推导 D-3（多轨兼容可判据）：day-1 多轨兼容的可判据

**最强形态是「轨道只减承诺、不改编码」**：轨道字段只降低耐久性承诺，绝不改变任何字节布局。
可判定形式（若采纳，届时在 [invariants.md](../invariants.md) 新开一条）：
**把任一指针的 track 字段抹成 0 之后，它必须仍能被单轨解析器逐字节解析，
且校验和 / MAC / nonce / birth txg / 反向索引语义一字不变。**
在这个形态下 inode 的轨道**不存**，是其全部 extent 轨道算出来的下确界 ⇒ 混合态天生合法，
「迁移」退化成翻两个位、与那次本来就要重写指针的事务合并，**没有数据搬运、没有重新编码、没有重算 MAC**。

**重算结果**：六样里真正变便宜的只有 **deadlist 一样**（I-3.1（已分配统计对得上） 从标量等式变成
「按轨道分箱的向量等式 + 标量收缩」，判别力**净增**，能检出「总数对但归类错」这一整类）；
另外两样是「省 0 字节但否决权消失」（反向索引）与「小幅变便宜」（恢复承诺）；
**其余三样（快照可见性、Merkle、nonce）净省为 0。**
⚠️ **使前三样成立的机制，恰恰是「让临时轨什么也不省」——这个设计用删掉收益的方式消掉了成本。**

| # | 四条判据（全部是设计期常量） | 怎么判 |
|---|---|---|
| 1 | **轨道字段只减承诺、不改编码** | 抹成 0 后仍可被单轨解析器逐字节解析。写成不变量，checker 可判，且能证明会红（构造一个两轨不等宽的镜像）|
| 2 | **每一条被减掉的承诺，都能写成只读该指针自身字段的谓词** | 把谓词实现签名钉成 `fn(&Pointer) -> bool`，多一个入参即判红 |
| 3 | **轨道在对象创建时确定，此后永不改变** | 枚举全部能改变轨道的入口，集合必须为空 |
| 4 | **D12（目标介质） 与 D6（快照实现模型） 已定** | track 要与 nonce 载体、快照 ID、locality_id 抢**同一段排序权** |

**判据 3 是可判定性的全部重量所在**：一条「出生即定、此后不变」的耐久性轨道就是不可撤销的声明。
**它自动把持久/临时轴判出局，而不是靠历史归纳。**
**本工程已经有一条满足全部四条的 day-1 多轨：D9（加密） 预留的「每个数据/元数据写的算法类型字段」**——
只减承诺不改编码（老数据按各自字段解）、谓词只读该写自身、**写下去那一刻就定死**。

**由此得到一条不对称结论**：day-1 多轨对**大/小轴**帮助显著（翻转由操作自己引起，可以并进同一个事务），
对**持久/临时轴**帮助为零（翻转来自操作范围之外）。**day-1 买到的准确表述是：格式能在翻转中存活，操作不能。**
`linkat` 在 POSIX 下是 O(1)；一个带 1 TB 临时 extent 的对象被 `linkat` 挂进目录树，三条出路的结局是：
急切重标 = O(N) 元数据重写、**O(1) 承诺照样作废**；惰性重标 = 引入「尚未重标」这个在途派生状态，
**正是 D11（索引节点要不要留消息缓冲区） 被否掉的那个东西换了个地方**；
意图日志重标 = `linkat` 变成发起一个无界操作，**崩溃落在返回之后、重标完成之前 ⇒ 恢复丢弃一个已被成功 link 的文件的数据**。
⚠️ **最后这条的形状与参考五里那条 btrfs 内核 commit 逐字相同（`write()` 返回成功之后数据丢失）——
从零设计、格式全新，走到了同一个坑。因为病根不在 retrofit，在「承诺翻转来自操作范围之外」。**

### 不采纳格式级第二轨：一条依据、四条参考

**口径**：只有**依据二**参与判断，它是自推的。标为**参考**的四条是别家的记录，本工程未验证，
**不许用来支撑或否定 D14（双轨（大小文件 / 持久临时））**；它们留着只有一个用处——**当作 D-1（穷举翻转入口） / D-2（六样少做逐样推） 的检查清单**。
编号在依据与参考之间连续，不重排。

**参考一（待自推验证）：两条轴上都不存在「操作期间稳定的分支变量」。**
大/小轴：`open(O_CREAT)` 时 size=0，**每个文件出生都是小文件**；`truncate` 让阈值**双向可穿**；
「大小」还是 `i_size` / 已分配块数 / extent 条数三个互相矛盾的候选。
持久/临时轴：比「中途改变」更糟——分支变量会被**操作范围之外的第三方异步翻转**
（`linkat` / `fsync` / 快照捕获 / `rename` / 硬链接 / mmap 脏页回写 / 配额），
**每一个入口都是 POSIX 已经承诺为 O(1) 或原子的操作**。

**依据二：唯二不可撤销的声明，是靠禁掉翻转入口换来的，不是设计出了稳定的变量。**

| 声明 | 为什么不可撤销 | 代价 |
|---|---|---|
| `O_TMPFILE \| O_EXCL` | `man 2 open` 原文：「Specifying O_EXCL in conjunction with O_TMPFILE **prevents a temporary file from being linked into the filesystem**」 | 这个文件**永远不能有名字**，只能靠 fd 传递 |
| 独立子卷 / 挂载点 | 跨边界 `rename` 返回 `EXDEV`，内核替你拒绝翻转 | **不是 per-file 的**，而且它就是 tmpfs 已经是的东西 |

围起来之后，「临时文件透明地走快路径」这个最初的诉求已经不在了。
`man 2 open` 还明写 O_TMPFILE 的两个主要用途之一就是**变成永久文件**——
**它表达的是「这个名字还不存在」，不是「这份数据是临时的」。**

**参考三（D12（目标介质） 定案后必须重算）：要少做的六样，零样落在纯行为分支里。**
判定标准是「这件事能不能只看一个镜像判出来」，判不出来就必须有盘上事实。
⚠️ D14（双轨（大小文件 / 持久临时））基于「不为多轨预留格式字段」这个前提，前置是 D15（格式冻结政策）。

| 要少做的 | 判定 | 机制 |
|---|---|---|
| 快照可见性 | 格式 | 挂载时必须知道哪些对象不被快照捕获，这知识只能来自盘 |
| deadlist 记账 | 格式 | 若临时块单开一本账，I-3.1（已分配统计对得上） 就从**一条对照**退化成两条各自对账，**唯一那条独立对照消失**——与 D11（索引节点要不要留消息缓冲区） 否掉「消息独立成树」是同一个论证 |
| Merkle 链 | 格式或白省 | 只有两种实现：指针宽度不同 = 两种指针格式 = 永久分支；宽度相同、字段标为无效 = **一个字节都没省**，只省 CPU |
| nonce | **绝对少不了** | I-6.1（nonce 不重用） 的 checker 阶段 ② 靠明文头识别「这是不是一个 singlefs 块」。不带标准明文头的临时块会让阶段 ② **分辨不出它是不是D14（双轨（大小文件 / 持久临时））系统的块**——检查全绿而判别力为零 |
| 恢复承诺 | 格式 | 挂载时要知道哪些 inode 可以直接丢，而「任何要事后扫一遍才能算出来的记账设计一律否决」⇒ 必须有一棵持久的临时对象树 ⇒ 新 keyspace |
| 反向索引 | 格式，且违反 D1（数据可移动性 / 反向索引） | 临时块不进反向索引 ⇒ balance / copygc **搬不动它** ⇒ 永久碎片源 |

**参考四（D12（目标介质） 定案后必须重算）：验证叉积 16 倍。**
已在册的维度：D8（核心索引结构） 范围重建/逐项修改（2）× D2（RAID 条带策略） 条带宽度（3）×
D12（目标介质） 两者都一等（2）× D9（加密） 开关（2）= **24**；加双轨（大/小 4 档 + 持久/临时 4 档）
→ **24 × 4 × 4 = 384，16 倍**。⚠️ 纯组合推算，具体挂钟依赖尚不存在的实现。
而 C8（门禁范围判不出来） 状态是「零前置的纯欠工」——**现在没有任何东西在拦这个膨胀**。

**参考五（不作依据）：历史上没有任何文件系统成功发布过格式级临时轨。**
⚠️ **这是「无证据」，不是「有反证」。** 每个案例都是**往既有格式上补**的
（btrfs 的 nodatacow、XFS realtime 的 reflink 与 rmap、ZFS 2019 年的 `special_small_blocks`、
ext4 继承自 ext3 的 `data=writeback`），**承载的结论是「retrofit 很贵」**。

| 实现 | 原文与结局 |
|---|---|
| btrfs `chattr +C` | 跨阈值迁移的历史答案是**宣布为未定义**：`chattr(1)`「it is **undefined** when the blocks assigned to the file will be fully stable」|
| btrfs `nodatacow` | 第二轨要付的是丢掉校验和：`man 5 btrfs`「**Nodatacow implies nodatasum, and disables compression**」；且被快照压倒——引用数 > 1 时写它仍然 CoW |
| btrfs NOCOW 的数据丢失 bug | 内核 commit「fix unexpected failure of nocow buffered writes after snapshotting when low on space」（backport 到 4.14 / 4.18 stable）：**`write()` 返回成功之后数据丢失**。修法是新增 `snapshot_force_cow` 让已开始的写按旧轨走完——正是硬要求 5 的内容 |
| ext4 `data=writeback` | `man 5 ext4`：收益是「This is **rumoured** to be the highest-throughput option」，代价是「**can allow old data to appear in files after a crash**」——**手册无法把收益写成事实，却把代价写成事实** |
| XFS realtime subvolume | 三十年账单：**quota 从来不支持带 realtime volume 的文件系统**；reflink 与 rmap 直到 Linux 6.13 / 6.14（2025）才落到 realtime 设备。**它缺的恰好是 D1（数据可移动性 / 反向索引） 与 D5（快照 / 空间记账机制）/D6（快照实现模型），两条都是本工程 day-1 硬承诺** |
| ZFS `special_small_blocks` | 三个毛病：改阈值**不追溯**；special vdev 写满后**静默回落**（硬要求 4「悬崖不报错」的现役实例）；判据是**压缩后**大小 |
| Windows `FILE_ATTRIBUTE_TEMPORARY` | **唯一一个主流的 per-file 临时声明**，而它整个关在页缓存层（「a hint to the **cache manager**」），**一个字节的盘上格式都没动** |

口径：man page 为本机 2026-08-26 现查并逐字核对；其余为公开记录，**未在本工程验证**。
