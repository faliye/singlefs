## D1 数据可移动性 / 反向索引 —— 已定

D1（数据可移动性 / 反向索引） 管**判据这一格**：要不要能回答「这个物理块被谁引用」、什么数据可以进单元的自包含段、要不要预留扩展点、什么进自包段什么进扩展点、自包不可变数据带几条指向以及旧版怎么断开。不管的：实际进了哪几个字段、各多宽、按单元类怎么分，在 D18（块里携带什么信息）；扩展点的字节形态（配额上限、哪几类单元带、指向宽度与「为空」怎么编码）在 D21（权威态与派生态的分界） 已定项 2 / 3 / 4；多引用者那一半的清单与计数在 D21（权威态与派生态的分界） 已定项 6 与 D5（快照 / 空间记账机制） 已定项 6。

### 已定项

**D1（数据可移动性 / 反向索引）的分项只有一套编号**，不重排。

|---|---|---|

| 2 | **反向索引算不算自包含数据** | 算——反向映射的主体就在单元里，不需要一棵反向索引树 **状态：已定。** |

#### 已定项 1：身份值等特有的不可变数据都可以进自包含段

**定案**：**单元数据自包含。** 凡是「这个单元特有的、**不可变的**」数据——身份值是其中一类——都可以进自包含段，默认答案是**放**，不为省空间裁字段（`.claude/rules/fs-design.md`「不为省空间牺牲自包含」）。

**射程**：管什么**可以**进，不管实际进了哪几个（D18（块里携带什么信息））。⚠️ **判据落在「不可变」这三个字上，这比既有的禁放清单更根本**：D18（块里携带什么信息） 已定项 3 禁止物理落点 / 设备 ID 进块头，理由写的是「物理位置一律不进 AAD ⇒ 放进块头就是一个不被认证、可无声篡改的字段」；而按本项的判据，**物理落点根本就不是不可变数据**——块会被搬（D1（数据可移动性 / 反向索引） 存在的理由正是要能搬）⇒ 它连门都进不来。两条理由同向，本项这条是上位的那条。⚠️ **有一类是不可变的、却仍然不许进**：文件名与 btree 内部节点的分隔 key。它挡在门外的理由**不是可变性，是泄漏面**——D9（加密） 已定项 5 的射程逐字：「索引内部节点留明文」这个候选不取，因为内部节点带分隔 key、dirent 树的分隔 key 就是文件名，泄漏面比 ZFS 大得多（ZFS 的间接块是纯指针数组，没有 key）。**所以那一条禁令要单独留着，不能被本项覆盖掉。**

**依据**：无实验：这一项定的是「什么可以进」这条判据本身，不是任何一个字段要不要加——字段各自的字节账在 D18（块里携带什么信息） 与 D21（权威态与派生态的分界） 那边各自量；判据的取向来自 `.claude/rules/fs-design.md`「不为省空间牺牲自包含」，那条规则明写它管的是已经论证过有用的字段该不该为省空间而砍。用户定案，原话在变更史。

**欠**：无。

#### 已定项 2：反向索引是自包含数据

**定案**：**反向映射的主体就在单元里**——单元自带「我属于谁」⇒「这个物理位置上是哪个对象」只读那一个单元就答得出，不需要一棵反向索引树。⇒ 「反向索引取权威态」不是给权威态清单加第四项，而是**认下它已经在第一项（单元）里**。

**射程**：**只有一半。** 共享（快照 / reflink / 去重）之下一个单元可以有**多个**引用者，而定长的单元头列不下 ⇒ 剩下那一半不在本项：清单那一半由 D21（权威态与派生态的分界） 已定项 6 定（位置权威取混合之后搬迁不问引用者，不需要任何新结构），计数那一半归 D5（快照 / 空间记账机制） 已定项 6 的稀疏旁表。本项也不定单元头里那条指向长什么样，那在已定项 5。

**依据**：无实验：这一项是从「单元自描述」这条格式纪律直接读出来的结论——单元头里已经有「我属于谁」，它不新增任何盘上字段，也不改任何一个宽度，没有可量的量；要量的是多引用者那一半的代价，那已经不在本项射程内。用户定案，原话在变更史。

**欠**：无。

#### 已定项 3：预留可自定义的扩展点，要么为空要么是一个指向

**定案**：**每个单元预留一个可自定义的扩展点**，语义**二选一**：**要么为空，要么是一个指向**。⇒ **扩展点里不内联数据**。这条把 D21（权威态与派生态的分界） 已定项 3 的语义收口了：那一项此前只定了「指向不许与核心层的主字段重合」「长度可以不用指定」，没说过「除了指向还能不能装别的」——现在说了，不能。

**射程**：管扩展点的**语义**，不管它的字节形态。字节形态的权威记录在 D21（权威态与派生态的分界），本项不复述：上限由挂载时那组判定算出（已定项 2）、哪几类单元带（已定项 4：数据单元带、索引节点条件带、自证单元不带）、每个指向 7 字节那一档与它曾欠的三样（宽度与单位、「为空」怎么编码、外部调研）由已定项 3 全部定完（配额内字节偏移 + 1，全零即空）。⚠️ 「一个指向」是语义；D21（权威态与派生态的分界） 已定项 3 的「128 字节配额挂 18 个」是容量算术、不是个数条款——扩展点里只放一个 7 字节指向，配额的其余空间是它指向的目标区。

**依据**：

- E43（扩展点字节上限）：按「里面放一个指向」这个形态量四条拒绝理由的门槛，核心层这一侧付得起、形态本身不被任何一条判定否掉；按字节计的指向落在下界区间最便宜那一档，而按比例定上限在大单元上夹不住任何东西。
- 用户定案，原话在变更史。

**欠**：无。

#### 已定项 4：按「随版本变不变」分自包段与扩展点

**定案**：**判据一句**——一个字段**随版本变不变**。不变的进自包段，**每版可以不同的进扩展点**。

**射程**：管怎么分，不管分进去之后怎么表达（已定项 3 定的形态）。两条不冲突：可变的东西按本项归扩展点，而在扩展点里一律表达成**指向**——要放一个可变的**值**，就放一个指向那个值的指向。⚠️ **「可改」不是原地改**：单元不可变（已定项 1 那条判据的另一半）⇒ 动扩展点一个字节就等于写一个新单元，**「频繁可改」的准确意思是「每版可以不同」**，不是「同一个单元被改来改去」。⚠️ **不许拿「扩展点在整单元的校验 / 认证覆盖内」当理由**：那条与「无密钥的一侧要能搬」互斥，而 D9（加密） 已定项 5 定了无密钥侧只做 scrub、不搬之后，这条互斥理由不再承重；扩展点里放物理指向的正当理由只剩一句，写在 D18（块里携带什么信息） 已定项 3 的射程段——**造不出静默误读**。⚠️ 「要么为空」说的是它**允许**为空；**第一版里它就是空的**——D21（权威态与派生态的分界） 已定项 3 逐字「本工程今天一条开线方的线都没有 ⇒ 扩展点内一个字节都没有」。本项与已定项 1 是同一条判据的两面：已定项 1 说「特有的**不可变**数据可以进自包段」，本项说「随版本变的那些别进自包段，进扩展点」，两条合起来才是完整的分界。

**依据**：无实验：这一项定的是一条二分判据（随版本变不变），它不决定任何字段的宽度、也不新增盘上字节——扩展点的字节账由 D21（权威态与派生态的分界） 已定项 2 / 3 消费，本项没有自己要量的量。用户定案，原话在变更史。

**欠**：无。

#### 已定项 5：自包不可变数据带唯一一条指向，旧版由树断开

**定案**：**自包不可变数据带唯一一条指向**——「我属于谁」，五元组（树 ID / 对象 ID / 对象出生代 / 锚点偏移）。**「唯一」说的是链唯一**：每一个新的数据单元都起一条唯一的链，新数据生成 ⇒ 断开旧链 ⇒ 完成新链接。**新版写成即旧版断开，而断开由树完成**——树的指针改指新单元；**不去改旧单元**（它不可变，改它既撞 COW 也撞 D2（RAID 条带策略）「不诱发设备 RMW」那条）。两条独立的射程声明：**fs 不隐式保留旧版本**（除非有人**显式**建了快照，否则旧版本按周期释放）；**备份不是 fs 的事**（用户要备份就是拷贝数据的问题，与 COW 无关，这一句挡掉的是一整类功能蔓延）。

**射程**：⚠️ **它指的是出生所有者，不是「当前所有引用者」。** 共享之下一个单元可以有多个引用者而定长的单元头列不下，多引用者那一半由已定项 2 的后半句承接、落点 D21（权威态与派生态的分界） 已定项 6；**不加这句限定，本项会被读成「本工程不支持共享」**。⚠️ **必须带「隐式」两个字**——快照本身就是「长久保留旧版本」，D5（快照 / 空间记账机制） 的 deadlist 整套机制存在的理由就是它；去掉「隐式」就与 D5（快照 / 空间记账机制） / D6（快照实现模型） 直接打架。⚠️ **「到期」的口径**（两条已定的闸，缺一条这句就变成错的）：被快照引用的落点按 D3（空间分配） 已定项 7 进 deadlist 不进 defer、快照销毁时才释放；近 K 代不许复用（I-7.4（近 K 代块未被复用），K ≤ 根环深度）⇒ 「按周期释放」的准确读法是**「没有任何根（含快照）引用、且已过 K 代」的那些**。

**依据**：无实验：本项定的是「几条指向、谁来断开」这条结构判据，五元组各段实际多宽、进不进头由 D18（块里携带什么信息） 的字段表定并在那边量；「唯一一条」本身不产生可量的量。用户定案，原话在变更史。

**欠**：无。

#### 已定项 6：已撤回·此编号不再使用

**定案**：已撤回，此编号不再使用。原题：扩展点里的代数据是一个深 5 的栈、到期由 gc 整批释放。三方论证三腿一致判它买不到东西且**结构性违规**——撞 D21（权威态与派生态的分界） 硬约束 5「指向不许指向核心层的对象」，并且正好造出 C21（扩展点指向逃出记账） 拿来自证判别力的那个反例。

**射程**：2026-09-06 当日立、当日撤。**编号不回收**——盘上没有字节，但仓里有引用它的历史条目，回收会让那些引用悬空。撤回前的论证只留在变更史，不是现行设计；撤回的理由若将来失效，被撤回的结论也不自动回来（`.claude/singlefs-ai-sop/rules/evidence-discipline.md`「撤回的理由失效，不等于被撤回的结论自动回来」）。

**依据**：无实验：立与撤在同一天，三腿一致判它结构性违规，按已定条款就能判出来，没有跑过也不需要跑任何可量的量。撤回依据全文在 [decisions-history.md](../decisions-history.md)。

**欠**：无。

#### 已定项 7：要反向索引，且 day-1 就设计进格式

**定案**：**要。且 day-1 就设计进格式，不许后补。** balance / defrag / 缩容 / 移除设备 / 纠删码都要求能回答「这个物理块被谁引用」。

**射程**：管要不要与什么时候进格式，不管它长什么样（已定项 2 定主体在单元里、已定项 5 定那条指向）。现役对照只当线索、不当证据（`.claude/singlefs-ai-sop/rules/evidence-discipline.md`：别的项目怎么做是线索不是证据）：btrfs 选了要但是**后长出来的**，成了它最复杂、bug 最多的部分；ZFS 选了不要，换来简单，代价是二十年不能缩容不能碎片整理。本工程要解决的正是缩容与整理，所以选要——但必须是设计出来的，不是补出来的。**bucket generation 替代不了它**：它只对缓存副本成立、只管「失效」不管「搬运」、绕回处理是一次全索引遍历，而 bcachefs 自己已经改用 backpointers。其中两条（bucket gen 只对缓存数据成立、gen 绕回已被 backpointers 取代）的原文在 [prior-art.md](../prior-art.md) 7.10；另两条（只管失效不管搬运、绕回处理是一次全索引遍历）来自 2026-08-26 现查 Linux 6.17 `fs/bcachefs/` 的 `buckets.c` 与 `alloc_background.h`，逐条出处在变更史。四条都未在本项目验证。bucket generation 可作为「缓存副本回收」的优化并入，但它对 D9（加密） 已定项 5 无效——已定项 5 今天是「只做 scrub，不搬」，「无密钥能不能搬」这一问本身已经没有对象。

**依据**：无实验：这一项是产品方向的取舍（要不要这个能力、什么时候进格式），可量的量在它的下游——扩展点的字节账在 D21（权威态与派生态的分界） 那边量、单元头字段的字节账在 D18（块里携带什么信息） 那边量；外部调研按规则只提假设、不进论证。用户定案，原话在变更史。

**欠**：无。

#### 已定项 8：与 D18（块里携带什么信息） 的边界

**定案**：两边各写一句、不许写乱。**D1（数据可移动性 / 反向索引） 定判据**——什么可以进自包段、什么进扩展点；**D18（块里携带什么信息） 定字段表**——实际进了哪几个字段、各多宽、按单元类怎么分。**判据变了 D18（块里携带什么信息） 的字段表跟着改；字段表怎么排不回头改判据。**

**射程**：管这两条决策之间的分工，不管第三条。扩展点的**字节形态**既不在本项也不在 D18（块里携带什么信息），在 D21（权威态与派生态的分界） 已定项 2 / 3 / 4。

**依据**：无实验：这是一条分工条款，定的是哪条决策说了算，不产生任何盘上字节，也没有可量的量；它要防的是同一件事在两处各写一半、然后互相引用对方的半句。用户定案，原话在变更史。

**欠**：无。
