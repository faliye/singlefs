## D23 journal 的角色与格式 —— 半定（角色、环、tail、记录头、事务边界、反向链含宽度与覆盖字段、序号位宽十项已定；A/B/C 三条可逆性要求待落实；hash 算法未定）

**方向已定：journal 记录承载「指针层的目标态」，不是逻辑意图，也不是全量物理重做。**
单元由 COW 写到各自最终位置并自带校验和（D22（单元原子性怎么合成） 分界线里「COW + D4（校验和位置） 够」那一类），
journal 只记「哪些子树根换到了哪个块 + 新根」。

**由此得到一条写路径的硬顺序：分配先于 journal。**
journal 记录不是「事务的全部」，是「**已经写到盘上的东西的发布指令**」。

依据（2026-08-28 三方论证，主 agent 裁决）：

| 判据 | 逻辑意图 | 全量物理重做 | **指针层目标态** |
|---|---|---|---|
| 幂等（I-4.4（意图只描述目标态）「只描述目标状态」） | 只有写成目标态才幂等 | 天然幂等 | **天然幂等** |
| 重放要不要分配器 | **要** | 不要 | **不要** |
| 记录大小（D16（发布语义）「小、顺序写」） | 小 | **大**（要带全部字节） | **小** |
| D13（验证路线） 的 O2（独立解析器 + checker） 能做什么 | **退化**成跑一遍不变量检查 | 逐字节比对 | **逐字节比对** |

### 逻辑意图被 D13（验证路线） 的 O2（独立解析器 + checker） 决定性否掉

**O2（独立解析器 + checker） 明令不许调用被测 crate 任何代码**（D13（验证路线））。而逻辑意图的重放要重新实现
分配器 + 树操作 + 校验和 + 记账，**约等于第二个文件系统**。

**现役实现证实这条成本是真的**：ZFS 的 ZIL 是逻辑意图日志，
其 on-disk 规范逐字写着「**When replaying the transaction the VOP layer is called again.
To do this we reopen the object and pass it's vnode.**」——
**它靠「把主写路径再调一遍」回避了独立实现的成本，而这条路线对本工程是关闭的。**

**第二条否决理由**：逻辑重放要新分配块，而分配决定不在记录里
⇒ 被测 crate 与 O2（独立解析器 + checker） 会把同一条意图落到**不同的物理块**上
⇒ O2（独立解析器 + checker） 从「独立算出同一个答案再比对」退化成「独立跑一遍不变量检查」，
**而后者已经是 checker 在做的事**，O2（独立解析器 + checker） 的增量价值大幅缩水。

⇒ **D23（journal 的角色与格式）与 D13（验证路线） 的 O2（独立解析器 + checker） 互相挟持，两者要一起定，不能分开定。**

### 世代号：记录粒度的全局单调号，不是 D5（快照 / 空间记账机制） 的 txg

**D5（快照 / 空间记账机制） 是「一个 checkpoint 一个 txg 号」** ⇒ 同一 checkpoint 窗口内的多条 journal 记录
**共享同一个 txg**，彼此分不出先后，D22（单元原子性怎么合成） 要求的「被实际检查的世代号」就失去意义。

⇒ 记录头要**两个**计数字段，职责不同、不可合并：

| 字段 | 粒度 | 用途 |
|---|---|---|
| `jsn` | **每条记录**，全局单调，u64 | D22（单元原子性怎么合成） 要求②的世代号；前缀判定靠它 |
| `checkpoint_txg` | 每个 checkpoint | 归属哪个 checkpoint，供 D5（快照 / 空间记账机制） 的 birth/death 记账 |

⚠️ **64 位不是「买到新能力」，是买到「免掉回绕比较」**：jbd2 的 tid 是 **32 位且会回绕**，
靠 `tid_gt` 的有符号差比较。回绕比较正是 O2（独立解析器 + checker） 最容易实现得不一样的地方。

⚠️ **「用 txg 就不需要 cycle」只对轴①成立**，见 D22（单元原子性怎么合成） 那两个正交轴的表。

### 前缀判定：严格连续、断号即止，且必须限定在「在飞窗口」内

只用「`jsn` > 上次已应用」过滤**不够**：若序列里有空洞（5849 写成、5850 没写、5851 写成），
「>」会把 5851 错接到 5849 后面，**破坏因果序**。⇒ 判据是 `jsn == expected`，不等即止。

⚠️ **一条已实测的缺口：上一条时间线的残留**（E32（上一条时间线的残留） 实测，
2026-08-29，N=5 轮字节一致；三方论证六条腿齐跑，一条打中射程）。

断号即止在**那一次**恢复里是对的（前缀停在 5849）。**没写明的是下一步**：
恢复之后接着写时，5851 那个槽里还躺着上一条时间线的记录，
**校验和是好的、`jsn` 恰好等于 expected** ⇒ 第二次崩溃后的恢复把它接上去重放。

**已核实的前提**（2026-08-29 现查，主 agent 自核）：

| # | 事实 | 怎么查的 |
|---|---|---|
| 1 | 记录头 11 个字段里**没有任何一项标识时间线** | 读 [experiments.md](../experiments.md) E23（journal 几何) 的字段表 |
| 2 | `decisions/` 与 [invariants.md](../invariants.md) 里**没有任何一条规则管残留记录** | 全仓 grep，零命中 |

**实测结果**：在 `slot = jsn % 槽数` 这一支上，
`重放的残留条数 = max(0, 残留条数 − (恢复后新写条数 − 1))`，
最坏格（恢复后只写成一条就再崩）**残留全数被重放**。
两条自然实现（接前缀末 / 跳过空洞）**各违反一条判据且方向相反**
——前者重放已丢弃时间线，后者把新写的记录全丢。

**三条现有的闸逐条核实都不触发**：I-8.3（重放前缀严格连续） 要求的正是
`jsn == expected`（残留满足它，是通行证不是闸）；在飞记录数上限判的是
**校验和失败**算撕裂还是算损坏，而残留的校验和**是好的**；
`checkpoint_txg` 在同一个 checkpoint 窗口内一模一样。

⚠️ **「必然」要按槽位映射收窄（三方论证的反推腿打中，主 agent 现查坐实）**：
E32（上一条时间线的残留） 固定了一个**D23（journal 的角色与格式）从未定过的自由度**——槽位映射取 `jsn % 槽数`。
现役 jbd2 把槽位与序号**解耦**：恢复收尾时号跳过断点、位置回退到断点
（`fs/jbd2/recovery.c:318-321` 逐字：
`j_transaction_sequence = ++info.end_transaction; j_head = info.head_block;`，
注释「Restart the log at the next transaction ID,
thus invalidating any existing commit records in the log」）。
⇒ **`slot = jsn % n` 让「残留恰好落在下一个要读的槽、号恰好等于 expected」由构造必然发生；
位置与序号解耦时它退化成巧合。**
⇒ 正确表述是「**在 D23（journal 的角色与格式）唯一测过的那种槽位映射下必然重放**」。
**「缺口在规范里」这个判定不变**——因为 D23（journal 的角色与格式）从没定过槽位怎么映射。

⚠️ **tail 推进不是第三条出路**（两条独立的腿各自推了一遍，结论一致）：D23（journal 的角色与格式）已定项 3 已定「恢复不许先信 tail 再往前走」，
且 tail 只在 checkpoint 持久之后前移、而残留按定义**从未被应用**
⇒ `tail ≤ min(残留 jsn)` 恒成立。补上 checkpoint 推进的建模不改结论。

⚠️ **重放幂等也救不了**：D23（journal 的角色与格式）已定项 3 逼出的那条硬要求逐字是
「**同一条记录**被重放两次与重放一次，结果相同」——它是自反的。
残留是**另一条**记录，而且它点名的那些单元在被丢弃之后可能已被新时间线重分配。

**出路有三条，代价各不相同**（前两条已实测，第三条未测）：

⚠️ **「槽位与序号解耦」不在这张表里**——它被 E36（槽位映射那一维） 实测判掉，理由见「前缀判定：严格连续、断号即止，且必须限定在「在飞窗口」内」后文。

| 出路 | 花记录头字节吗 | 对 zoned 那个等价类成立吗 | 状态 |
|---|---|---|---|
| 每条记录带**前一条的 hash**（反向链） | **要** | 成立 | 实测两条判据全过 |
| 恢复时**物理作废**残留槽 | 不要 | **不成立**——要求原地覆写，zoned 只能追加 | 实测两条判据全过 |
| 序号高位带**日志实例代号**（每次恢复递增） | 要，**且要改一条已定的前缀规则** | 成立 | 已测，见下 |

⚠️ **「槽位与序号解耦」这条出路已被实测判掉**（E36（槽位映射那一维），
2026-08-29，N=5 轮字节一致，8 单测 / 7 条变异全抓）：

**解耦的是写侧位置，而恢复走的是读侧顺序**——新时间线从断点位置接着写，
它后面那个位置**仍然**是残留序列的下一条。
实测：新旧记录**等长**时，解耦那一支与按序号那一支**逐格相同**（残留 7 条时全数重放）。

真正打散对齐的是**记录长度不同**（新记录多占 1 位 ⇒ 残留整体错位 ⇒ 全部挡住），
⚠️ **而那是巧合不是保证**：同一条臂把长度改回等长，7 条残留全部回来。
⇒ 它给不出 `.claude/rules/fs-design.md` 硬要求 1 要的那种「显式、可计算」的判据。

**阳性对照**：按序号那一栏逐格复现 E32（上一条时间线的残留） 的式子
——两份独立写的模型对上了。

⇒ **剩下的出路是三条**：反向链、恢复时物理作废残留槽（zoned 做不到）、
序号高位带日志实例代号（**仍未测**）。

⚠️ **「日志实例代号」这条出路的代价比此前记的重**（E37（日志实例代号） 实测，
2026-08-29，N=5 轮字节一致，7 单测 / 6 条变异全抓）：

**只加字段不够。** 代号一加，新记录的 `jsn` 就与旧前缀**不连续**，
而 D23（journal 的角色与格式）已定的判据是 `jsn == expected`、不等即止 ⇒ **新写的记录全丢**——
与 `skip_hole` 同病（实测：残留挡住了 0 条重放，但新写的全部丢失）。
⇒ **它还要改一条已定的前缀规则**：恢复必须接受「代号 +1 且计数器接着走」。
改完之后两条判据才同时满足。

⚠️ **而且它的正确性全押在「代号不许回滚」上**：实测把代号回滚一格，
它逐格退回 baseline（残留 7 条全数重放）。
**那与 D9（加密） 已定项 8 对 nonce 水位的要求同型**——
D9（加密） 逐字要求水位「不许住在裸明文超级块里……必须落在一个被 MAC 覆盖的字段上」。
**代号需要同一份保护，而 D23（journal 的角色与格式）一个字都没写过。**

⚠️ **代号住哪儿本身是个循环**：住 journal 记录里 ⇒ 恢复要先读记录才知道代号，
而读记录正需要代号来判；住超级块 ⇒ 落进「代号不许回滚」那个要求。

⚠️ **反向链这个字段 D23（journal 的角色与格式）早就提过**（「三条给格式的现查警示」第 3 条，XFS `h_prev_block` 形态），
但**理由记的是**「让 O2（独立解析器 + checker） 能用不同的遍历复核前缀边界」——
**同一个字段两个理由，仓里只记了一个**，而只按验证独立性记，它会在省字节的权衡里第一个被砍。
⚠️ **且那个类比要收窄**：现查本机 7.2.0 树，`h_prev_block` 只在写入侧被赋值
（`fs/xfs/xfs_log.c:2703`），**恢复侧的 `xlog_valid_rec_header()` 不比对它**
⇒ XFS 并没有把它当链式校验用。**D23（journal 的角色与格式）引它时只能引「字段形态」，不能引「现役这么防」。**

⚠️ **XFS 真正用来分辨「这是哪一圈」的是 cycle，而那是精确机制不是概率机制**
（2026-08-30 现查本机 7.2.0 树）：`xlog_rec_header.h_cycle`（`__be32`）记这条记录属于第几圈，
且每个 512 B 基本块的头 4 字节都被换成该圈的 cycle 号、原字节存进 `h_cycle_data[]`；
恢复用 `xlog_find_head()` **二分找 cycle 的跃变点**（`first_half_cycle` / `last_half_cycle`）来定头。
⇒ 上一圈的残留记录带的是**小一号的 cycle**，判定是「不等就是旧的」，**没有碰撞概率**。

⚠️ **jbd2 那条同样是精确的**：恢复收尾 `j_transaction_sequence = ++info.end_transaction`，
注释逐字「Restart the log at the next transaction ID, thus invalidating any existing
commit records in the log」——号跳过断点，残留在**号**上就对不上。
E39（反向链挡不挡得住残留记录） 实测这一支：`resume=SkipHole` 且**不开链**时 `replayed_stale = 0`。

⇒ **两个现役实现都用精确判据分辨时间线，没有一个用 hash 链。**
D23（journal 的角色与格式）若只靠反向链，是在用**概率**手段做一件别人用**精确**手段做的事——
这不构成否决（反向链另外买到 O2（独立解析器 + checker） 的遍历独立性，那是别人没有的），
但**「宽度取多少」这个问题本身只在「反向链是唯一判据」时才存在**。

⚠️ **链宽不随文件变大而需要变宽。** 误接受概率的分母是
「空洞 → 恢复 → 续写 → 再崩」这个事故序列发生的次数，与文件大小、池容量、记录总数都无关：
一次事故里链只在**一个接缝**上被考验（现行时间线内部的比对由构造必然相等，
接缝之后的残留段彼此本来就成链）。
**随文件变大而受压的是另外两个字段**：序号计数器（E37（日志实例代号） 取的 48 位 = 每实例 2.8×10¹⁴ 条记录）
与环的几何（I-8.1（环几何够大）「环 ≥ F × 最坏事务占用」，而最坏事务随单次 fsync 的规模走）。

判据、失败条款与要扫的参数组合见 [experiments.md](../experiments.md) E32（上一条时间线的残留）；
欠的检查见 [checks-owed.md](../checks-owed.md) C42（残留记录冒充合法前缀）。

⚠️ **还要一个显式的在飞记录数上限。**
XFS 只在最后 `XLOG_MAX_ICLOGS` 条记录内把 CRC 失败**当作撕裂**（理由逐字：
「only a certain number of log records can be written out at one time」）；
**窗口之外的 CRC 失败是 `-EFSCORRUPTED`，拒绝挂载，不是截断前缀**。
没有这个上限，「前缀有效性单调」判不出来，O2（独立解析器 + checker） 也复现不了同一个判定。

### 三个死锁，两个落在格式上、事后补不进去

| # | 环 | 现役破法（逐字核实，Linux 7.2.0 本地树） | 对本工程 |
|---|---|---|---|
| 1 | journal 满 → checkpoint → 发根 → **发根要不要写 journal** | jbd2 `fs/jbd2/transaction.c`：「The commit code assumes that it can get enough log space **without forcing a checkpoint**. This is \*critical\* for correctness: a checkpoint of a buffer which is also associated with a committing transaction creates a **deadlock**」 | **D16（发布语义） 那句措辞必须显式裁一个读法**，见下 |
| 2 | **COW 独有**：checkpoint → COW 写新节点 → 要分配 → 盘满 → 发不出根 | jbd2/XFS **没有**这个环，因为它们**原地写**、回家不需要新空间。btrfs 有，用 `global_block_rsv`（`fs/btrfs/block-rsv.c`）按 extent/csum/root 树大小动态定尺 | **保留池治这一条**，`reserve ≥ ckpt_cost` 即可（E19（defer 窗口下的假性 ENOSPC） 实测，见 D23（journal 的角色与格式）「死锁 2 与假性 ENOSPC 是两种故障，要分治」）。⚠️ **D22（单元原子性怎么合成） 的 K 加重它**：盘快满时最该救命的空间正是被 K 扣住的 ⇒ **K 必须是运行时策略，不能是格式常量** |
| 3 | 单条操作大于环 | XFS `fs/xfs/libxfs/xfs_log_rlimit.c`：「no single transaction can be larger than half size of the log… **dead loop situation**」；`XFS_MIN_LOG_FACTOR = 3`（`libxfs/xfs_log_format.h:42`），**mkfs 时算、mount 时校验** | 需要等价的几何不变量：**任一操作的最坏 journal 占用 ≤ 环大小 / F，F ≥ 2** |

**死锁 3 推出一条依赖关系**：
**D8（核心索引结构） 的意图分批机制不是「删大文件的便利设施」，
它是 journal 满死锁的必要条件之一**——算不下的操作必须能拆成若干个各自合法的事务。

### 死锁 2 与假性 ENOSPC 是两种故障，要分治（E19（defer 窗口下的假性 ENOSPC） **建模层**实测，2026-08-28 第二轮）

| 故障 | 谁治得了 | 数字 |
|---|---|---|
| **checkpoint 卡死**（D23（journal 的角色与格式）死锁 2） | **保留池**，且 `reserve ≥ ckpt_cost` 就够 | 预留 **64 块**（恰等于一次 checkpoint 的开销）把卡死次数从 **199 打到 0** |
| **假性 ENOSPC** | **只有准入**。保留池反而加重它 | 预留 0 → 16384 块，假性 ENOSPC 从 3150 涨到 **7246**，每档增量恰为 `reserve / 文件块数` |

**机制**：保留池是给 checkpoint 开的一道地板，对**普通分配**是纯税。
而假性 ENOSPC 的成因是「defer 窗口与根环 K 扣住的量超过剩余空间」，
**那不在保留池的射程内**——btrfs 的 `global_block_rsv` 防的是普通分配吃光空间。

**假性 ENOSPC 的破法是一条可计算的准入规则**
（E19（defer 窗口下的假性 ENOSPC） 跨 6 档填充率 × 6 档延迟共 36 格，预测与实测逐格一致）：

> **剩余空间必须 > 每 checkpoint 搅动量 × (延迟代数 + 1) + 一次 checkpoint 的开销**

⇒ 不许把盘填到 `容量 − 搅动量 × (延迟+1) − checkpoint 开销` 以上。
这与 `.claude/rules/fs-design.md`「准入控制要在进门前先算最坏情况」同构——
**「最坏情况」里必须含 defer 窗口与 K 扣住的那一块。**

⚠️ **搅动量在真实负载里是变量，E19（defer 窗口下的假性 ENOSPC）把它当常数。** 怎么估它是真机压测那一半的问题。

### 措辞必须显式裁一个读法：D16（发布语义）

> 「没有任何操作可以绕过 journal 直接发根。」
⚠️ **这句话的读法已由 D23（journal 的角色与格式） 裁定为「甲」**（语义效果必须经 journal，发根本身不是一条追加）。

| 读法 | 含义 | 结果 |
|---|---|---|
| **甲（D23（journal 的角色与格式）采用）** | 任何最终反映到根里的**语义效果**必须先经由 journal；**发根这个动作本身不是一条 journal 追加** | 与 jbd2/XFS 的破法②（释放空间的路径消耗零日志空间）相容 |
| 乙（字面） | 发根也要走 journal ⇒ 发根要追加记录 ⇒ journal 满时发不出根 | **环闭合，死锁** |

⇒ **采用读法甲**，且它与 D22（单元原子性怎么合成） 兼容：**根环是 journal 之外的固定 K 槽，发根 = 覆写根环的一个槽，不是追加。**
checkpoint 不是「操作」，是 journal 机制本身的一部分；普通用户操作仍然只能进 journal。

### 三条给格式的现查警示

1. **校验和覆盖的字节范围必须是显式的盘上常量，绝不能由语言的 `sizeof(struct)` 推出。**
   XFS 因为用了 `sizeof`，i386 与其他架构算出不同 CRC，至今背着 `XLOG_REC_SIZE` /
   `XLOG_REC_SIZE_OTHER` 两个常量和两遍校验的兼容疤。
   ⚠️ **这正是 D13（验证路线） 的 O2（独立解析器 + checker） 能抓、而单一实现抓不住的错误类型**——独立解析器不会碰巧复制同一个 `sizeof`。
2. **记录自述长度必须先做边界检查，再用于校验和计算。**
   ZFS 的 ZILOG2 从块内读 `zc_nused` 决定校验范围，读之前先 `if (size < nused) return ECKSUM`。
3. **加一条反向链**（XFS 的 `h_prev_block` 形态）。
   它让 O2（独立解析器 + checker） 能用**与正向扫描完全不同的遍历**复核同一个前缀边界——
   正合 `.claude/singlefs-ai-sop/rules/evidence-discipline.md`「校验的两条路径不许共享同一段代码」。

   #### 重测与攻击轮的结果：**维持原定案**，而理由换了

   ⚠️ **2026-08-30 那次「跨多条把环顶大 12 倍」的推翻，本身也被推翻了。**
   E45（事务跨多条记录的环占用） 把 I-8.2（记录头不跨原子单元）
   实现成了「整条记录起于单元边界」，而I-8.2（记录头不跨原子单元）逐字只要求**头**落在一个单元内。
   按字面规则，12 条一项记录（每条 153 字节、共 1836 字节）**全部装进同一个 4096 单元**，
   一条都没违反 ⇒ **那个倍数从 12× 塌到 1.00×**。
   ⚠️ E45（事务跨多条记录的环占用） 声称的「三条互不共享代码的验证路径」也不成立：
   两条是同一规范的两种写法、共享那条错规则，第三条只锚定两个与结论无关的常量。
   **三条一致是因为三条共享了同一个错前提。**

   #### 现役实现两个都走「跨多条 + 边界标记」（2026-08-30 现查本机 7.2.0 树，已做成断言）

   | 实现 | 逐字 |
   |---|---|
   | **XFS** | `XLOG_START_TRANS` / `XLOG_COMMIT_TRANS` / `XLOG_CONTINUE_TRANS` / `XLOG_END_TRANS`；注释逐字「If a single region can not fit into the remainder of the current active in-core log, it is **split up into multiple regions**. Each partial region will be marked with a `XLOG_CONTINUE_TRANS` until the last one, which gets marked with `XLOG_END_TRANS`」 |
   | **jbd2** | 一个事务由多个 descriptor block + 多个 data block + 一个 commit block 拼成（`fs/jbd2/commit.c` 的 `jbd2_journal_get_descriptor_buffer`），事务边界靠 commit block 标记 |

   ⇒ **两个现役实现都是「跨多条 + 显式边界标记」，与本项定案的形态一致。**
   **没有任何现役实现走「一事务恰一条记录」。**

   #### ⚠️ 一条物理事实，它反过来支持本定案

   `header_csum`（32 字节）**只覆盖记录头**（E23（journal 几何) 字段表逐字：
   「头落尾没落可区分的前提」），而记录**载荷没有任何已定义的独立校验和**
   ⇒ **一条跨多个原子单元的大记录，载荷完整不完整今天判不了。**
   E42（一事务几条记录） 与 E45（事务跨多条记录的环占用） 都把「记录」当成不可再分的原子单位来枚举撕裂，
   **那个假设只在记录整体落在一个原子单元内时才有物理依据**
   ⇒ 「一事务一条就不需要丢尾巴逻辑」这个推论**前提没有被证明**，
   而「一事务一条」恰恰把记录做大到必然跨多个单元。

   #### 仍然欠的两笔，2026-08-30 各调研了一轮

   **第一笔：记录载荷的完整性怎么判。** `header_csum` 只覆盖头，载荷没有已定义的校验和。
   现役三家的做法（现查本机 7.2.0 树与固定点 bcachefs 树）：

   | 实现 | 校验和覆盖什么 | 存在哪 | 与本工程的**已知差异**（不写差异就是搬运，不是论证） |
   |---|---|---|---|
   | **XFS** | **头 + 扩展 cycle 数据 + 全部载荷**，`xlog_cksum()` 末尾逐字 `crc = crc32c(crc, dp, size)` | 头里的 `h_crc` | 它**不需要**「头落尾没落可区分」——定位日志头靠 cycle 号二分，不靠头在不在 |
   | **bcachefs** | **整条变长 entry**（`csum_vstruct(..., j)`），`csum` 是 `struct jset` 的**第一个字段** | entry 开头 | 它的 journal 是加密的，校验和与 nonce 同源；本工程的 journal 加不加密未定 |
   | **jbd2** | **每个数据块各自一个校验和**，种子里折进事务号（`jbd2_block_tag_csum_set`：先 `chksum(seed, seq)` 再 `chksum(csum, 块内容)`）；描述块与提交块**另有**覆盖整块的校验和 | 校验和住在**指向该块的 tag 里** | 它的「块」是文件系统块，本工程的「点名项」是指针层目标态，粒度不同 |

   ⚠️ **三家都覆盖载荷，没有一家是「只覆盖头」。** 本工程的 `header_csum` 是那个异类，
   而 E23（journal 几何) 给它的理由（「头落尾没落可区分的前提」）**是三家都不需要的一个目的**——
   它们定位日志头各有别的办法（XFS 的 cycle、jbd2 的序号 + 提交块、bcachefs 的 `seq` / `last_seq`）。

   ⇒ **四个候选，按本工程已定的东西排**：

   | 候选 | 形态 | 它买到什么 / 付什么 |
   |---|---|---|
   | 甲 | 一个校验和覆盖整条记录（XFS / bcachefs 形态） | 载荷可判；**失去「头落尾没落」的可分辨性** |
   | 乙 | `header_csum` 保持只覆盖头，**另加一个覆盖点名项数组的校验和** | 两件事都能判；多一个字段 |
   | 丙 | **每个点名项自带它所指目标的校验和** —— **这正是 D4（校验和位置） 已定的形态**（校验和内联进指针），而记录承载的就是「指针层的目标态」⇒ **本工程可能已经有了它** | 粒度最细；但它判的是**目标块**在不在，**不判点名项自己有没有落盘** |
   | 丁 | 丙 + `named_count`（头里已有，4 字节）⇒ 数够不够 | 需要论证「读到的项是不是垃圾」怎么判 |

   ⚠️ **丙这一格要小心**：D4（校验和位置） 的校验和证明的是「指向的那个单元完好」，
   **不证明「这条点名项本身完整落盘」**。两者不是同一件事，
   而「载荷完整性」问的是后者。⇒ **本笔仍然未定**，但候选集与判据现在写下来了。

   **第二笔：跨多条那一臂每条装几项。** 现役两家都是**塞满一个定长记录**，
   不是「每项一条」（现查，已做成断言）：

   | 实现 | 每条装多少 |
   |---|---|
   | **XFS** | 装满当前 iclog 的剩余空间，装不下才 `XLOG_CONTINUE_TRANS` 续到下一条。iclog 尺寸 `XLOG_MIN_RECORD_BSIZE` 16 KiB / 默认 `XLOG_BIG_RECORD_BSIZE` **32 KiB** / `XLOG_MAX_RECORD_BSIZE` 256 KiB，在飞条数 `XLOG_MAX_ICLOGS = 8` |
   | **jbd2** | 一个描述块塞满 tag 为止（`space_left = descriptor->b_size − …`，循环到 `space_left < tag_bytes + 16 + csum_size`）⇒ **一个块** |

   ⇒ **E45（事务跨多条记录的环占用） 拿「每项一条」当这条臂的代表，确认是稻草人。**
   按「塞满一个定长记录」算：4096 字节的记录装 `(4096 − 99) / 56 = 71` 项，
   32 KiB 的记录装 583 项 ⇒ **目标负载那个 12 项事务在两条臂下都只占一条记录，字节数完全相同。**
   ⚠️ **记录尺寸本身仍未定**，它是一个新的格式参数（XFS 把它写进超级块的 `h_size`）。

   #### 定案带来的三条义务（用户定案：算法要增强）

   1. **格式**：记录头要加**事务号**与**提交标记**（当时 84 字节，已定项 9 之后 86；两个字段合计 9 字节）。

9. **序号与实例代号的位宽划分（2026-08-30，用户定案）：实例代号 32 位 + 计数器 48 位，两个字段共 10 字节。** **状态：已定。**

   | 哪一半 | 实测怎么说 | 处置 |
   |---|---|---|
   | **计数器 48 位** | 记录数就是 fsync 数（D23（journal 的角色与格式）已定项 1 轴一已定「每次 fsync 发根」）。本机 fsync 率 **2785 次/秒**（KINGSTON SNV3S4000G 消费级 NVMe + ext4 + O_DIRECT，阳性对照通过：不 fdatasync 快 32.1 倍）⇒ 48 位撑 **3202 年** | **不加宽**——「48 位不够」那条推理的前提在本机不成立 |

   **一格都不多占单元**；要到 16 字节才在 512 单元下多占一格。
   ⇒ 取 10 字节买到「代号用不完」，**盘上一个字节都不多花**。

   本来就要改前缀规则（恢复必须接受「代号 +1 且计数器接着走」），挤不挤在一起都要改。

   ② 代号那一档的「每天崩 10 次」是**取的场景点，不是测量**。

   #### 已定项 9 的两条欠账

   1. **代号住哪儿、谁保护它。** 住 journal 记录里是循环（恢复要先读记录才知道代号，而读记录正需要代号来判）；
      住超级块则落进「不许回滚」那个要求 ⇒ 与 D9（加密） 已定项 8 的 nonce 水位**同一个载体问题**，
      两者应当一起定，不许各定各的。
   2. **记录头从 84 变 86，两处算术要跟着动**（都是算术，不是实测）：

      E43（扩展点字节上限） 的自证单元上界 428 / 4012 → **426 / 4010**。

10. **`prev_hash` 覆盖哪些字段（2026-08-30，用户定案）：覆盖前一条记录的整个记录头，其中含 `jsn`。** **状态：已定。**

    `jsn` 已定为「实例代号 32 位 + 计数器 48 位」（D23（journal 的角色与格式）已定项 9）
    ⇒ **实例代号在链值的输入里** ⇒ 两条时间线的链值构造性不同，
    误接受率回到 2⁻ⁿ 那条曲线上，E51（反向链的碰撞机会有多少次） 判的「32 位够用」因此成立。

    ⚠️ **取「整个记录头」而不是「只取 jsn」的理由**：多覆盖的字段**一个字节都不多花**
    （hash 的输入长度不进盘），而少覆盖一个字段就多一条「这个字段被改了链还对得上」的缝。
    ⚠️ **一条实现纪律**：`header_csum` 那 32 字节**自己不能进 hash 输入**（它是头的一部分而又依赖头），
    要么在算 `prev_hash` 时把它当零、要么显式排除——**两种都行，但必须写死一种并落成不变量**。

    **链值必须有一个「两条时间线保证不同」的输入**，否则误接受率是 **100%，与位宽无关**：
    若 `prev_hash` 取前一条的 `header_csum`，两条竞争记录的 magic / 类型 / `jsn`（都等于 expected）/
    `checkpoint_txg`（E32（上一条时间线的残留） 已核实同一窗口内一模一样）在点名项数相同、加密关闭时**构造性相等**。
    **自然的选择是 D23（journal 的角色与格式）已定项 9 已定的 32 位实例代号。**
    ⚠️ 它与已定项 8 的宽度定案是两件事：宽度答「碰撞概率多大」，本项答「有没有东西可碰」。
    发现经过：2026-08-30 三方论证的反推腿读 E39（反向链挡不挡得住残留记录） 源码时指出——

### 已定项 2（2026-08-29）：取定长环，但理由不是「链式进入死锁 2」

**取定长环。** ⚠️ **候选理由「链式把 journal 写路径变成分配路径，于是进入死锁 2」被三条腿一致判为过强**，D23（journal 的角色与格式）不采用它。链式的增量是有界可算的，抬保留池就断开——它不是一个真环。

真正判掉链式的是三条，都不经过死锁 2：

#### ① 保留池必须涨一个量级，而涨保留池已被实测会加重假性 ENOSPC

链式下 journal 块本身要分配 ⇒ 保留池必须从 `ckpt_cost` 涨到
`ckpt_cost + 一个 checkpoint 窗口内的 journal 块`：

| 原子宽度 | 窗口内 journal 块 | 保留池 | 倍数 |
|---|---|---|---|
| 512 | 125 | 64 → 189 块 | 3.0× |
| 4096 | 1000 | 64 → 1064 块 | **16.6×** |

（`ckpt_cost = 64 块` 由 [experiments.md](../experiments.md) E19（defer 窗口下的假性 ENOSPC）实测；
窗口内 journal 块由 E23（journal 几何）的每记录块数 × checkpoint 间隔算出。）

**这条式子已实测**（[experiments.md](../experiments.md) E25（环与链各要多大保留池），
2026-08-29，三轮字节一致）：checkpoint 卡死次数**恰好**在预测的那一档归零——
环在 `reserve = 64`（= `ckpt_cost`），链在 `reserve = 164`（= `64 + 100`）。
阴性对照：盘只用 95% 时两条臂任何 reserve 都不卡，效应确实来自空间紧张。

⚠️ **同时收窄了 E19（defer 窗口下的假性 ENOSPC）的一句话**：「保留池对普通分配是纯税」
有一个隐含前提——**保留池已经大到不卡死**。前提之外符号是反的：
`reserve = 0` 时普通分配被拒 9340 次，`reserve = 64` 时只有 756 次，
因为卡死之后空间根本不回收。

而 E19（defer 窗口下的假性 ENOSPC）同时实测：**保留池对普通分配是纯税**，预留 0 → 16384 块时假性 ENOSPC 从 3150 涨到 7246。
⇒ **链式不是把代价变成死锁，是把它变成假性 ENOSPC**——而 E19（defer 窗口下的假性 ENOSPC）已定「假性 ENOSPC 只有准入治得了，保留池反而加重它」。

#### ② 前缀判定与空间归属被绑死

| | 定长环 | 链式 |
|---|---|---|
| 「有效前缀到哪」决定什么 | **只决定重放哪些记录** | 还决定**哪些块分配器可以发出去** |

链式下 D23（journal 的角色与格式）的前缀规则与 D21（权威态与派生态的分界）的记账权威
是两个独立判定，却必须逐块一致——不一致就是静默泄漏或双分配。
断号即止的截断点之后的链块要么泄漏、要么被重发而重放仍指着它。
**ZFS 为此需要 mount 期 claim 加 `zh_claim_txg`**（D22（单元原子性怎么合成）已记录）。

#### ③ 死锁 3 不是被消掉，是从静态判据换成动态判据 —— 这条是决定性的

| | 判据 | 什么时候算得出 |
|---|---|---|
| 定长环 | 最坏操作 ≤ 环大小 / F，F ≥ 2 | **mkfs 时算、mount 时校验**（同 XFS `XFS_MIN_LOG_FACTOR`） |
| 链式 | 最坏操作 ≤ **当前空闲** | 算不出——**当前空闲在操作中途会变** |

`.claude/rules/fs-design.md` 硬要求 5 逐字写着：
「**只在操作期间不会变的输入上分支**……「当前填充率」会在操作中途越过阈值，**那是危险的分支变量**」。
⇒ **链式把一条可判定的几何不变量，换成了本工程明令不许用的运行期变量。**
这不是权衡，是撞上已定的硬要求。

⚠️ **但环这一侧的欠账也要写明，不许说成已完成**：那条几何不变量**今天不存在**——
既不在 [invariants.md](../invariants.md)，也不在 [checks-owed.md](../checks-owed.md)。D23（journal 的角色与格式）正文此前写的是「**需要**等价的几何不变量」，那是要求不是事实。
已登记为欠检查，见 [checks-owed.md](../checks-owed.md)。

### 已定项 3（2026-08-29）：tail 住超级块槽，但改 jbd2 两处

**取超级块形态**（tail 的权威副本住在一个固定位置，不内联在记录头），**并改两处**：

| # | 改动 | 为什么 |
|---|---|---|
| 1 | **不许单副本原地覆写**，改 ≥2 槽轮换 + 代号 + 先逐个验证全部候选再择新 | D22（单元原子性怎么合成）已对根定过同一条纪律：一次撕裂会抹掉唯一见证者。轮换不增写数，仍是 21 块 |
| 2 | **只在 checkpoint 持久之后写一次，不上 fsync 路径** | 稳态开销因此是每 checkpoint 一次，不是每 fsync 一次 |

#### 原地覆写与 COW 不冲突，理由有三条

1. **自证单元这一类早就存在**，不是为 tail 新开的：发根本身就是覆写根环的一个槽。
   tail 与根槽、journal 记录头同类，都归 D22（单元原子性怎么合成）已定三管。
2. **COW 对没有父的单元买不到东西**：COW 的防护来自父指针里的校验和。
   给 tail 造一个父，那个父要提交，而提交正是 journal 要办的事——循环原样成立。
3. **tail 语义上是派生态**：权威判定仍是 `jsn` 连续前缀 + `checkpoint_txg`。

#### 由此逼出一条硬要求：恢复不许先信 tail 再往前走

**必须先全环扫描、逐条验证，再择最长合法前缀。**

理由是机制性的：tail 陈旧时，`[tail_陈旧, tail_真实)` 这段已经被新一圈记录写掉了
⇒ 从陈旧 tail 起往前走，**第一条就 `jsn != expected`** ⇒ 断号即止
⇒ 连 `tail_真实` 之后仍然需要的记录也不重放。**那是数据丢失方向，不是「多做功」方向。**

⇒ 「陈旧 tail 只让恢复多做功」这句话**只在全环扫描式恢复下成立**。
本要求与 D22（单元原子性怎么合成）对根槽的「先逐个验证全部候选、再择新」是同一条纪律。

**已实测**（[experiments.md](../experiments.md) E24（恢复算法：先信 tail 会不会丢记录），2026-08-29，
环 64 块，三轮字节一致）：

| 窗口内写入条数 | 先信 tail 漏 | 全环扫描漏 | 全环扫描多重放 |
|---|---|---|---|
| 1 / 5 / 20 / 63 | **1 / 5 / 20 / 63**（全漏） | **0 / 0 / 0 / 0** | 63 / 59 / 44 / 1 |
| 100（超过环 64） | 100 | **36**（= 100 − 64） | 0 |

⇒ **先信 tail 漏掉的条数恰等于窗口内写入的条数——它一条都恢复不出来**，不是漏一部分。

#### 由 E24（恢复算法：先信 tail 会不会丢记录）逼出的第二条要求：重放必须幂等

E24（恢复算法：先信 tail 会不会丢记录） 同时测出一件**不在预期内**的事：全环扫描不丢，但它把**陈旧 tail 以来的记录全部重放一遍**
（多重放条数 = 环槽数 − 窗口内新记录数；窗口为空时仍重放满环 64 条）。
机制：全环扫描只知道**陈旧的**持久 tail，于是把环里 tail 之上能找到的全重放。

⇒ **「陈旧 tail 只是多做功」这句话有一个前提：重放必须幂等。**
没有幂等，陈旧 tail 就从「多做功」变成「重复施加已生效的记录」。
**本工程从未定过重放幂等这条要求**，现在把它立为 D23（journal 的角色与格式）的一条硬要求：

> **每条 journal 记录的重放必须幂等**——同一条记录被重放两次与重放一次，结果相同。

这与 D23（journal 的角色与格式）已定的「记录承载指针层的**目标态**，不是逻辑意图」是相容的：
目标态天然幂等（把指针写成某个值，写两次结果一样），而逻辑意图不是
（「计数加一」执行两次结果不同）。**这条一致性是事后核实的，不是设计时就想到的。**

#### 第三条：恢复算法救不了几何

E24（恢复算法：先信 tail 会不会丢记录）测到窗口撑爆环时（100 条 > 64 槽）**两条臂一起丢**，全环扫描漏 36 条。
⇒ 环大小 ≥ 窗口是 [checks-owed.md](../checks-owed.md) C28（环几何不变量未实现）的职责，
**不是恢复算法的**。两者不许互相顶替。

### 已定项 2 与 3 耦合：选链等于把已定项 3 的自由度一起交掉

| | 定长环 | 链式 |
|---|---|---|
| tail 答错的后果 | **只是多做功**（可降级） | **泄漏或双分配**（承重，见已定项 2 的理由 ②） |
| 因此 tail 必须 | 可以是派生态 | **必须是权威态**，且要 tail-before-reuse 硬序、FUA 落在关键路径 |

**内联 tail + 链式是最坏格**：内联只能搭记录便车推进，链式下空闲期不写记录
⇒ 不只是多重放，是 journal 块一直回收不了，空转变成空间泄漏。

### 这两项的证据强度：三处要写明的降级

1. ⚠️ **E23（journal 几何）的「500 块重放」是建模参数，不是测量。**
   代码里 `idle_after = n − 500` 是选定的场景点，`tailing` 就是它之后的记录数。
   真实重放量 ∈ [0, checkpoint 间隔]，取决于崩溃落在窗口哪个位置。
   **方向性结论（内联形态空闲崩溃后重放非零、超级块形态恒为零）站得住，数字不代表典型值。**
2. ⚠️ **「21 : 500」这个比不成立。** 21 是稳态**无条件**付（系统永不崩溃也照付），
   500 只在崩溃真的发生时才兑现。正确的问法是「一次额外写对设备寿命的代价
   与一次最多一个 checkpoint 间隔的顺序重放读，哪个贵」——**E23（journal 几何）没有建模这一维**。
3. ⚠️ **屏障口径下超级块形态是多付的，不是少付**：每 checkpoint 一次额外 FUA，
   20000 次 fsync 里 21 次，占 40000 个持久点的 **0.05%**。方向与块数口径相反，量级仍可忽略。

### 已定项 2 / 3 / 4 的代价已量出，且三者耦合

纯计数模型，20000 次 fsync，每 1000 次一个 checkpoint。**数的是块，不是字节也不是屏障**
（[checks-owed.md](../checks-owed.md) C27（块数口径定格式参数）与 C26（屏障数从没量过）同样适用）。

#### 已定项 3：两条臂差 21 : 500，方向一边倒

| tail 形态 | 稳态额外写 | 空闲期崩溃后要重放 |
|---|---|---|
| jbd2 形态（住 journal 超级块、原地覆盖、FUA） | **21 块**（= checkpoint 次数，占 20000 次 fsync 的 **0.105%**） | **0** |
| XFS 形态（内联在每条记录头的 `tail_lsn`） | **0** | **500 块**（原子宽度 4096）/ 63 块（512） |

**机制**：内联形态只能搭记录的便车推进——不写记录就推不动 tail；
超级块形态可以在 checkpoint 完成时单独写一次。空闲期崩溃时两者因此分开。
⚠️ 换屏障口径结论不变：21 次额外 FUA 对 20000 次 fsync 的 40000 个持久点是 0.05%。

#### 已定项 2：除一项外每个指标都相同，那一项是分配次数

| | 定长环 | 链式 |
|---|---|---|
| 稳态写块数 | 相同 | 相同 |
| **向分配器要块** | **0 次** | **每个 journal 块一次**（20000 次 fsync ⇒ 20000 次） |
| 死锁 3（单条操作大于环） | 存在，需要几何不变量 | 不存在 |

⇒ **链式把 journal 写路径变成一条分配路径**，于是它进入 D23（journal 的角色与格式）死锁 2 的环
（checkpoint → COW 写新节点 → 要分配 → 盘满 → 发不出根）。
环的 0 次分配正是「journal 不可能被 COW 覆盖」在模型里的形态。
**链式用「消掉死锁 3」换「加重死锁 2」，而死锁 2 是 COW 独有、且已经最难的那个。**

#### 已定项 4：头部 86 字节，装得下；但 512 这个数不由本工程定

头部字段合计 **86 字节**（magic 4 + 类型 2 + 算法类型 1 + 填充 1 + 自述长度 4 +
点名项数 4 + `jsn` **10** + `checkpoint_txg` 8 + `tail_lsn` 8 + nonce 12 + 头部校验和 32），
占 512 扇区的 17%，其后还余 **426 字节**（装得下 7 个点名项，每项 56 字节）。
⚠️ `jsn` 的 10 字节 = 实例代号 32 位 + 计数器 48 位，由 D23（journal 的角色与格式）已定项 9 定案；
**点名项容量与 `jsn` 占 8 字节那一版相同，都是 7 项**（E44（序号位宽的本机实测与代价） 实测：
8 / 10 / 12 字节三档在 512 与 4096 单元下容量都不变）。

**对齐代价**（要求「记录头完整落在一个原子单元内」）：

| 原子宽度 | 点名 1 项（140 B） | 点名 10 项（644 B） | 点名 100 项（5684 B） |
|---|---|---|---|
| 512 | 512 B（3.7×） | 1024 B（1.6×） | 6144 B（1.1×） |
| 4096 | **4096 B（29.3×）** | 4096 B（6.4×） | 8192 B（1.4×） |

不对齐、多条记录挤同一个原子单元则空间不浪费，**但除第一条外都判不了撕裂**。

#### 三者耦合：任何一项单独定都会定错

原子宽度（已定项 4）决定一条记录占几块 → 决定环要多大（已定项 2）→
环太小把超级块形态的 tail 写放大（已定项 3）。

| 原子宽度 | 环 ≥ 多少块才不强制 checkpoint | 峰值占用 |
|---|---|---|
| 512 | **256** | 125 块 |
| 4096 | **1024** | 1000 块 |

环太小时代价是断崖式的（原子宽度 4096、每次 fsync 点名 1 项）：

| 环大小 | 强制 checkpoint 次数 | 超级块形态的 tail 写 |
|---|---|---|
| 4 块 | **4980**（每 4 次操作一次） | 5000 |
| 64 块 | 300 | 320 |
| 256 块 | 60 | 80 |
| 1024 块 | **0** | 20 |

⇒ **环大小的下界 = checkpoint 间隔 × 每次 fsync 的记录块数**，
这是死锁 3 那条几何不变量的具体形态；它随原子宽度放大 8 倍。

### 已定项 1（2026-08-28）：轴一定了之后，轴二只剩一个合法值

**取甲：每次 fsync 写脏叶 + 全部祖先 + 根槽 + 一条记录。祖先不延后。**

#### 第一依据是结构性的：两根轴不正交

**延后祖先 ⇒ 新根不可能自洽 ⇒ 发不出一个反映本次 fsync 的根。**
COW 下，要让本次 fsync 的叶从根可达，整条脊柱必须已在盘上；
而「自洽」是 [invariants.md](../invariants.md) I-7（根环） 类的要求（从代号最大的根递归校验能走完权威态）。

⇒ 2×2 只有三格可实现：

| | 不延后祖先 | 延后祖先 |
|---|---|---|
| **每次 fsync 发根** | **甲** | **不存在** |
| 只在 checkpoint 发根 | `wal_full` | 乙 / 丙 |

⇒ **轴一已定的「每次 fsync 发根」单独就把乙与丙一起判掉了**，
且轴一那四条依据（环截断不了 / 多一条挂载期重放路径 / journal 进验证链 / 屏障一个没省）
对乙**逐条原样成立**，不需要重新论证。

**实测佐证**（[experiments.md](../experiments.md) E16（journal 的角色：WAL vs 意图日志））：`wal_leaf` 在 20 万次操作里发根
**200 次 = checkpoint 次数**，不是 fsync 次数。它从来就没在 fsync 时发过根。

⚠️ **一处措辞要精确**：轴一依据 2 说的「发根时重放不施加任何东西」只对 **journal redo** 成立。
甲下恢复期仍有「续做未完成意图」这条常规路径（[checks-owed.md](../checks-owed.md) C1（意图续做做成常规路径））。
正确说法是「**甲下 redo 为空**」，不是「甲下恢复无动作」。

#### 三条被降级的依据，逐条写明降到哪

定案给出的三条理由，三方论证打中两条半。**它们仍然写在这里，因为定案是在它们之上做的裁决，不是它们消失了。**

| 原依据 | 判决 | 依据 |
|---|---|---|
| ① 乙毁掉 D13（验证路线） 的 O2（独立解析器 + checker） 逐字节比对，而本工程没有 oracle | **暂不作为承重**，因为它依赖一处本仓自身的矛盾，见 D23（journal 的角色与格式）「一处本仓自相矛盾：O2（独立解析器 + checker） 到底是什么」 | — |
| ② 按 `fs-design.md` 的格式分支判据，乙买不到「用错了变成挂不上」 | **射程用错，撤下** | D18（块里携带什么信息） 逐字：「⚠️ **判据 2 不是** `.claude/rules/fs-design.md` 那条「能不能把用错了变成挂不上」……**两条判据射程不同，不许互相替代**」。乙不是与甲并存的分支，是二选一的另一套编码 |
| ③ 乙的收益形状不好——不 fsync 时为 0，与组提交是替代品 | **「替代品」那一半已被实测推翻**；③ 只剩「不发布时为 0」，降级为「奖金上界」，不作为否决理由 | **两条腿独立打中，随后补测坐实**：见下 |

**③ 的「替代品」那一半是错的，2026-08-28 补测（[experiments.md](../experiments.md) E16（journal 的角色：WAL vs 意图日志） 多流负载）**：

| 负载 | fsync 每次 | fsync 每 10 次 | 攒批把差距怎么了 |
|---|---|---|---|
| seq | 1.54× | **1.05×** | 几乎吃光 |
| rand | 1.71× | 1.33× | 吃掉一半 |
| metaheavy | 2.31× | 1.63× | 吃掉一部分 |
| **multistream**（16 条流各在自己子树里推进） | 3.40× | **3.71×** | **不降反升** |

**机制：攒批只在被攒的操作共享祖先时才帮到甲。** 流不共享脊柱时，
攒 10 个操作就是 10 条互不相交的脊柱都要写，甲一分钱没省，而乙照样全延后。

⚠️ **适用范围有界，且这个界是先算后测出来的**（56 格扫描，见 E16（journal 的角色：WAL vs 意图日志））：
甲每批 ≈ `批 + min(流数,批)×树高 + 2`，乙 ≈ `批 + 1`
⇒ **比值在「批 ≈ 流数」处见顶，批超过流数之后单调塌向 1**（128 流时批 200 已降到 2.89）。

> **「与组提交是替代品」只在「批大小 ≤ 并发流数」时是错的；
> 批大于流数时它是对的。**

⚠️ **这不改变定案**——轴二是被轴一**结构性**排除的（延后祖先 ⇒ 新根不可能自洽 ⇒ 发不出根），
与收益多少无关。改的是依据 ③ 的强度，不是结论。

**③ 还有一条必须同时写下的反向读法**：乙的收益只在单流同步写上存在，
而**那恰是数据库与虚拟机镜像**——D10（随机写 / 碎片化的真答案） 已把「数据库和虚拟机镜像上的随机写」记为
COW 文件系统的共同软肋。所以 ③ 只能说「乙的奖金有界」，
**不能说「乙的收益不值一提」**。

⚠️ **本工程从未定过目标负载优先级。** 用「那不是主要负载」去否掉 1.3–2.3×，
等于替一个未定项做主。这一条本身是个缺口，记在这里。

#### 一条不依赖 O2（独立解析器 + checker） 的代价

**乙下崩溃后的镜像必须先重放才判得了恢复结果**，于是 checker 的输入只有两个来源：

| 路 | 撞什么 |
|---|---|
| 用**被测实现**去重放，再让 checker 判 | 违反 `.claude/singlefs-ai-sop/rules/evidence-discipline.md`「两条路径不许共享同一段代码」——checker 的输入由被测代码生产 |
| 让 **O2（独立解析器 + checker） 自己重放** | O2（独立解析器 + checker） 要实现分配器 ⇒ C3（读重试无硬上限）①（第二实现的成本） 那笔「第二个文件系统」的成本原样回来 |

⇒ **C3（读重试无硬上限）①（第二实现的成本） 对乙的力度不弱，只是付款点转移了**：不在「重放要不要分配器」，在「谁来生产 checker 的输入」。
⇒ **「C3（读重试无硬上限）①（第二实现的成本） 对 `wal_leaf` 力度明显弱于对逻辑意图」不成立。**

#### 记录头的类型字段：不是期权，是已经欠着的债

D23（journal 的角色与格式） 自身已经有**两种**记录——fsync 记录（点名的每项自带校验和）与 checkpoint 记录（明写不需要）。
⇒ **类型字段现在就是必需的，与轴二日后重不重开无关。**
把它写成「为轴二留的期权」会让人以为付了钱、买到了轴二的可逆性——**它一分钱也没买到那个。**

**真正让轴二可逆的是四项，缺一不可**（三条腿独立指出其中的长度字段）：

⚠️ **D23（journal 的角色与格式） 已定项 1的本地腿曾用过一份带字词损坏的输出**（`batchinggroup` / `monotfree`，
2026-08-29 补上拼接检测后回扫才发现）。已按 `.claude/rules/three-way-inference.md`
作废重跑，干净那轮**结论未变**，并第三次独立指出长度字段。


| # | 预留什么 | 为什么 |
|---|---|---|
| A | 记录头**类型字段** + **未知类型 ⇒ 拒绝挂载**，且该政策由**超级块 incompat 位**承载 | 光有字段而政策是「跳过不认识的记录」，失败模式是**静默漏放一条发布指令**，比没有字段更糟 |
| B | 记录**自述长度**，且**先边界检查再算校验和** | 类型字段只说「这是什么」，不说「这有多长」。丙的记录长度正比于树高，装不进按甲的尺寸钉死的预算 |
| C | **journal 几何进超级块**（环大小、最大记录字节、在飞记录数上限），**不许是代码常量** | 换轴二 ⇒ 最坏记录尺寸变 ⇒ 死锁 3 的几何不变量要跟着变。焊进代码就只能重建文件系统 |
| D | 项的大小**由记录类型决定** | D9（加密）已定 MAC 满 128 位不截断，丙的项更宽 |

⚠️ **A 与 B 本来就欠着**（B 是 D23（journal 的角色与格式）「三条给格式的现查警示」第 2 条）。
把它们记成「为轴二付的钱」是重复记账。

#### 丙（E22（记录点名祖先落点））的地位跟着变了

**丙也被轴一排除**——它同样不写祖先内容，同样发不出自洽的根。
⇒ [experiments.md](../experiments.md) E22（记录点名祖先落点） **只在轴一被重开时才有意义**，
它不再是「轴二的第三个候选」。

#### 重开轴二的可判据

⚠️ **这是设计期判据，不是运行期开关。** `.claude/rules/fs-design.md` 硬要求 5
「分支变量不许在操作中途改变」——把「延不延后」做成按负载切换的运行时分支，
会让崩溃语义在一次操作中途改变，当场违规。**轴二只能整体切换，且走 incompat 位。**

<!-- doc-lint:registry name-col=2 -->

| 闸 | 简称 | 判什么 | 现在测得了吗 |
|---|---|---|---|
| G23.0 | 轴一被重开 | 轴一被重开（否则后面几条不必看） | — |
| G23.1 | 祖先链占比达标 | 单流同步写（QD=1、单线程）的 fsync 服务时间里，「写祖先链 + 根槽」占比 ≥ X%，**X 在实验注册时声明，不许事后定** | **不能**，E16（journal 的角色：WAL vs 意图日志） 口径明写只算块数不算时间。前置：事务层 + 真机 harness |
| G23.2 | 甲丙差不收敛 | 攒批变大时，甲与丙的差**不**收敛 | **已答（对乙），但有界**：E16（journal 的角色：WAL vs 意图日志） 多流负载上攒批 1 → 10 时 3.40× → **3.71×**，不收敛反而扩大；**而这只在「批 ≤ 流数」时成立**——56 格扫描显示峰值落在批 ≈ 流数，16 流那一行批 50 已降到 1.99、批 200 降到 1.24。⚠️ 丙尚未测 |
| G23.3 | 四项盘上齐备 | 第 A–D 四项在盘上齐备 | **能，现在就该定** |

**反向判据（D23（journal 的角色与格式）必须自带）**：若 O2（独立解析器 + checker） 上线后，累计 N 次全量验证里
「O2（独立解析器 + checker） 抓到而 checker + O1（内存模型对拍（HashMap 理想文件系统）） + 崩溃点重放三者都没抓到」的事件数仍为 **0**
（N 在上线时先声明），则依据①的增量价值实测为零，轴二应当重开评估。
没有这一条，依据①就是不可证伪的。

#### O2（独立解析器 + checker） 是什么：已由 D13（验证路线） 定案

**D13（验证路线） 2026-08-29 定案：O2（独立解析器 + checker） 是一元谓词 `P(镜像)`，只判单个镜像，
永不判 identity；D23（journal 的角色与格式）此前三处写的「独立算出同一个答案再比对」「逐字节比对」都是加宽了入参。**
⇒ 那件事归 D13（验证路线） 命名的**记录核对器**（入参 `(崩溃前镜像, 记录流, 崩溃后镜像)`）。

⇒ 由此 **C3（读重试无硬上限）②（落点不确定使核对退化） 的主语要换成记录核对器**，
其实质（逻辑意图记录不点名盘上对象 ⇒ 核对从句法变成语义 ⇒ 第二实现的成本原样搬到核对侧）仍然成立，
但它是 C3（读重试无硬上限）①（第二实现的成本） 的一条封堵，**不是独立的第二条理由**。
⚠️ **不改变本次定案**——第一依据是结构性的，完全不经过 O2（独立解析器 + checker）。
同理，D23（journal 的角色与格式）「反向判据」那条按字面恒为 0（O2（独立解析器 + checker） 就是 checker），
其主语同样应为**记录核对器**。

### 已定项 1 定案的三方论证腿况

- **正推腿**给出了本次定案的第一依据（轴一 ⇒ 轴二），并抓到「C3（读重试无硬上限）①（第二实现的成本） 力度对乙较弱」是错的、
  以及 D13（验证路线）/D23（journal 的角色与格式） 关于 O2（独立解析器 + checker） 的矛盾。
- **反推腿**独立打中依据 ③（E16（journal 的角色：WAL vs 意图日志） 的「每 10 次」档乙仍领先 1.33×，没归零），
  指出本工程从未定过目标负载，并证明 E16（journal 的角色：WAL vs 意图日志） 从未建模并发 ⇒ 「不 fsync」不等于「组提交在场」。
- **本地腿（改用英文提示之后，输出判绿：1078 词零复读零替换字符）**
  独立打中同一条 ③，并独立指出「类型字段不含长度」这条缺口。
  它提出「让 O2（独立解析器 + checker） 用确定性分配器就能恢复逐字节比对」——**主 agent 判它不成立**：
  确定性分配器要求 O2（独立解析器 + checker） 重新实现分配器状态（自由空间图依赖全部历史），那正是 C3（读重试无硬上限）①（第二实现的成本） 的成本；
  且它会剥夺实现按介质优化分配的自由，与 D12（目标介质）、D3（空间分配） 冲突。
