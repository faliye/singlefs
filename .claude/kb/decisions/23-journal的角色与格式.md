## D23 journal 的角色与格式 —— 半定（形态、角色、环与 tail 已定，两项未定）

**方向已定：journal 记录承载「指针层的目标态」，不是逻辑意图，也不是全量物理重做。**
单元由 COW 写到各自最终位置并自带校验和（D22（单元原子性怎么合成） 分界线里「COW + D4（校验和位置） 够」那一类），
journal 只记「哪些子树根换到了哪个块 + 新根」。

**由此得到一条写路径的硬顺序：分配先于 journal。**
journal 记录不是「事务的全部」，是「**已经写到盘上的东西的发布指令**」。

依据（2026-08-28 三方论证，主 agent 裁决）：

| 判据 | 逻辑意图 | 全量物理重做 | **指针层目标态** |
|---|---|---|---|
| 幂等（I-4.4（意图只描述目标态）「只描述目标状态」） | 只有写成目标态才幂等 | 天然幂等 | **天然幂等** |
| 重放要不要分配器 | **要** | 不要 | **不要** |
| 记录大小（D16（发布语义）「小、顺序写」） | 小 | **大**（要带全部字节） | **小** |
| D13（验证路线） 的 O2（独立解析器 + checker） 能做什么 | **退化**成跑一遍不变量检查 | 逐字节比对 | **逐字节比对** |

### 逻辑意图被 D13（验证路线） 的 O2（独立解析器 + checker） 决定性否掉

**O2（独立解析器 + checker） 明令不许调用被测 crate 任何代码**（D13（验证路线））。而逻辑意图的重放要重新实现
分配器 + 树操作 + 校验和 + 记账，**约等于第二个文件系统**。

**现役实现证实这条成本是真的**：ZFS 的 ZIL 是逻辑意图日志，
其 on-disk 规范逐字写着「**When replaying the transaction the VOP layer is called again.
To do this we reopen the object and pass it's vnode.**」——
**它靠「把主写路径再调一遍」回避了独立实现的成本，而这条路线对本工程是关闭的。**

**第二条否决理由**：逻辑重放要新分配块，而分配决定不在记录里
⇒ 被测 crate 与 O2（独立解析器 + checker） 会把同一条意图落到**不同的物理块**上
⇒ O2（独立解析器 + checker） 从「独立算出同一个答案再比对」退化成「独立跑一遍不变量检查」，
**而后者已经是 checker 在做的事**，O2（独立解析器 + checker） 的增量价值大幅缩水。

⇒ **本决策与 D13（验证路线） 的 O2（独立解析器 + checker） 互相挟持，两者要一起定，不能分开定。**

### 世代号：记录粒度的全局单调号，不是 D5（快照 / 空间记账机制） 的 txg

**D5（快照 / 空间记账机制） 是「一个 checkpoint 一个 txg 号」** ⇒ 同一 checkpoint 窗口内的多条 journal 记录
**共享同一个 txg**，彼此分不出先后，D22（单元原子性怎么合成） 要求的「被实际检查的世代号」就失去意义。

⇒ 记录头要**两个**计数字段，职责不同、不可合并：

| 字段 | 粒度 | 用途 |
|---|---|---|
| `jsn` | **每条记录**，全局单调，u64 | D22（单元原子性怎么合成） 要求②的世代号；前缀判定靠它 |
| `checkpoint_txg` | 每个 checkpoint | 归属哪个 checkpoint，供 D5（快照 / 空间记账机制） 的 birth/death 记账 |

⚠️ **64 位不是「买到新能力」，是买到「免掉回绕比较」**：jbd2 的 tid 是 **32 位且会回绕**，
靠 `tid_gt` 的有符号差比较。回绕比较正是 O2（独立解析器 + checker） 最容易实现得不一样的地方。

⚠️ **「用 txg 就不需要 cycle」只对轴①成立**，见 D22（单元原子性怎么合成） 那两个正交轴的表。

### 前缀判定：严格连续、断号即止，且必须限定在「在飞窗口」内

只用「`jsn` > 上次已应用」过滤**不够**：若序列里有空洞（5849 写成、5850 没写、5851 写成），
「>」会把 5851 错接到 5849 后面，**破坏因果序**。⇒ 判据是 `jsn == expected`，不等即止。

⚠️ **还要一个显式的在飞记录数上限。**
XFS 只在最后 `XLOG_MAX_ICLOGS` 条记录内把 CRC 失败**当作撕裂**（理由逐字：
「only a certain number of log records can be written out at one time」）；
**窗口之外的 CRC 失败是 `-EFSCORRUPTED`，拒绝挂载，不是截断前缀**。
没有这个上限，「前缀有效性单调」判不出来，O2（独立解析器 + checker） 也复现不了同一个判定。

### 三个死锁，两个落在格式上、事后补不进去

| # | 环 | 现役破法（逐字核实，Linux 7.2.0 本地树） | 对本工程 |
|---|---|---|---|
| 1 | journal 满 → checkpoint → 发根 → **发根要不要写 journal** | jbd2 `fs/jbd2/transaction.c`：「The commit code assumes that it can get enough log space **without forcing a checkpoint**. This is \*critical\* for correctness: a checkpoint of a buffer which is also associated with a committing transaction creates a **deadlock**」 | **D16（发布语义） 那句措辞必须显式裁一个读法**，见下 |
| 2 | **COW 独有**：checkpoint → COW 写新节点 → 要分配 → 盘满 → 发不出根 | jbd2/XFS **没有**这个环，因为它们**原地写**、回家不需要新空间。btrfs 有，用 `global_block_rsv`（`fs/btrfs/block-rsv.c`）按 extent/csum/root 树大小动态定尺 | **保留池治这一条**，`reserve ≥ ckpt_cost` 即可（E19（defer 窗口下的假性 ENOSPC） 实测，见本决策「死锁 2 与假性 ENOSPC 是两种故障，要分治」）。⚠️ **D22（单元原子性怎么合成） 的 K 加重它**：盘快满时最该救命的空间正是被 K 扣住的 ⇒ **K 必须是运行时策略，不能是格式常量** |
| 3 | 单条操作大于环 | XFS `fs/xfs/libxfs/xfs_log_rlimit.c`：「no single transaction can be larger than half size of the log… **dead loop situation**」；`XFS_MIN_LOG_FACTOR = 3`（`libxfs/xfs_log_format.h:42`），**mkfs 时算、mount 时校验** | 需要等价的几何不变量：**任一操作的最坏 journal 占用 ≤ 环大小 / F，F ≥ 2** |

**死锁 3 推出一条依赖关系**：
**D8（核心索引结构） 的意图分批机制不是「删大文件的便利设施」，
它是 journal 满死锁的必要条件之一**——算不下的操作必须能拆成若干个各自合法的事务。

### 死锁 2 与假性 ENOSPC 是两种故障，要分治（E19（defer 窗口下的假性 ENOSPC） **建模层**实测，2026-08-28 第二轮）

| 故障 | 谁治得了 | 数字 |
|---|---|---|
| **checkpoint 卡死**（本决策死锁 2） | **保留池**，且 `reserve ≥ ckpt_cost` 就够 | 预留 **64 块**（恰等于一次 checkpoint 的开销）把卡死次数从 **199 打到 0** |
| **假性 ENOSPC** | **只有准入**。保留池反而加重它 | 预留 0 → 16384 块，假性 ENOSPC 从 3150 涨到 **7246**，每档增量恰为 `reserve / 文件块数` |

**机制**：保留池是给 checkpoint 开的一道地板，对**普通分配**是纯税。
而假性 ENOSPC 的成因是「defer 窗口与根环 K 扣住的量超过剩余空间」，
**那不在保留池的射程内**——btrfs 的 `global_block_rsv` 防的是普通分配吃光空间。

**假性 ENOSPC 的破法是一条可计算的准入规则**
（E19（defer 窗口下的假性 ENOSPC） 跨 6 档填充率 × 6 档延迟共 36 格，预测与实测逐格一致）：

> **剩余空间必须 > 每 checkpoint 搅动量 × (延迟代数 + 1) + 一次 checkpoint 的开销**

⇒ 不许把盘填到 `容量 − 搅动量 × (延迟+1) − checkpoint 开销` 以上。
这与 `.claude/rules/fs-design.md`「准入控制要在进门前先算最坏情况」同构——
**「最坏情况」里必须含 defer 窗口与 K 扣住的那一块。**

⚠️ **搅动量在真实负载里是变量，本实验把它当常数。** 怎么估它是真机压测那一半的问题。

### 措辞必须显式裁一个读法：D16（发布语义）

> 「没有任何操作可以绕过 journal 直接发根。」
⚠️ **这句话的读法已由 D23（journal 的角色与格式） 裁定为「甲」**（语义效果必须经 journal，发根本身不是一条追加）。

| 读法 | 含义 | 结果 |
|---|---|---|
| **甲（本决策采用）** | 任何最终反映到根里的**语义效果**必须先经由 journal；**发根这个动作本身不是一条 journal 追加** | 与 jbd2/XFS 的破法②（释放空间的路径消耗零日志空间）相容 |
| 乙（字面） | 发根也要走 journal ⇒ 发根要追加记录 ⇒ journal 满时发不出根 | **环闭合，死锁** |

⇒ **采用读法甲**，且它与 D22（单元原子性怎么合成） 兼容：**根环是 journal 之外的固定 K 槽，发根 = 覆写根环的一个槽，不是追加。**
checkpoint 不是「操作」，是 journal 机制本身的一部分；普通用户操作仍然只能进 journal。

### 三条给格式的现查警示

1. **校验和覆盖的字节范围必须是显式的盘上常量，绝不能由语言的 `sizeof(struct)` 推出。**
   XFS 因为用了 `sizeof`，i386 与其他架构算出不同 CRC，至今背着 `XLOG_REC_SIZE` /
   `XLOG_REC_SIZE_OTHER` 两个常量和两遍校验的兼容疤。
   ⚠️ **这正是 D13（验证路线） 的 O2（独立解析器 + checker） 能抓、而单一实现抓不住的错误类型**——独立解析器不会碰巧复制同一个 `sizeof`。
2. **记录自述长度必须先做边界检查，再用于校验和计算。**
   ZFS 的 ZILOG2 从块内读 `zc_nused` 决定校验范围，读之前先 `if (size < nused) return ECKSUM`。
3. **加一条反向链**（XFS 的 `h_prev_block` 形态）。
   它让 O2（独立解析器 + checker） 能用**与正向扫描完全不同的遍历**复核同一个前缀边界——
   正合 `.claude/singlefs-ai-sop/rules/evidence-discipline.md`「校验的两条路径不许共享同一段代码」。

### 未定项

1. **journal 的角色本身 —— 已定，见本决策「未定项 1 —— 已定（2026-08-28）：轴一定了之后，轴二只剩一个合法值」。**
   轴一（每次 fsync 发不发根）与轴二（祖先落盘延不延后）**不正交**：轴一取「发根」之后轴二只剩一个合法值。**取甲。**
2. **journal 是定长环还是链式**（D22（单元原子性怎么合成） 已证链式是可行的另一条路，代价是 mount 时 claim）。
   **代价已量**，见本决策「未定项 2 / 3 / 4 的代价已量出，且三者耦合」与 [experiments.md](../experiments.md) E24（journal 几何）。
3. **tail 位置存在哪、谁是权威、什么时候必须持久。**
   现役两家都有而本工程从没问过：jbd2 写在 journal superblock，固定位置、原地覆盖、
   **`REQ_FUA`**，且必须在环空间重用**之前**落盘（注释原文：「as soon as we update j_tail,
   next transaction can start reusing journal space」）；XFS 写在每条记录头的 `h_tail_lsn` 里。
   **代价已量**，见本决策「未定项 2 / 3 / 4 的代价已量出，且三者耦合」与 [experiments.md](../experiments.md) E24（journal 几何）。
4. **记录头能不能被约束在单个 512 扇区内。**
   能 ⇒ 「头落尾没落」与「头也没落」可区分，是否接受前者成为一个**可以做的选择**；
   不能 ⇒ 这个选项不存在。jbd2 有一条 `jbd2_commit_block_csum_verify_partial()`
   显式接受「只有头部有效、其余为零」的 commit block。
   ⚠️ 这是**读侧**约束，与 D22（单元原子性怎么合成） 未定项 5（不发小于映射单元的写，**写侧**）是两条，都要满足。
   ⚠️ **512 这个数不由本工程定**：D2（RAID 条带策略） 已定 `physical_block_size` 是**设备承诺的掉电原子宽度**，
   设备不声明 NAWUPF 时它塌到逻辑块大小。⇒ 本项的正确形态是「记录头必须完整落在一个
   `physical_block_size` 单元内」这条不变量，不是把 512 焊进格式。
   **代价已量**，见下节与 [experiments.md](../experiments.md) E24（journal 几何）。
5. **O2（独立解析器 + checker） 到底是什么 —— 已定（2026-08-29），权威记录在 D13（验证路线）。**
   **O2（独立解析器 + checker） 是一元谓词，只判单个镜像**，不是「逐字节比对」——那是二元关系，需要第二个入参。
   ⇒ 本决策的第二条否决理由（「落点不确定使核对退化」）按字面是空的，
   **改写为「核对从句法变成语义」，且它不是独立的第二条理由，是第一条的一条封堵**。
   ⇒ **「否掉逻辑意图日志」这个结论不动**，第一条理由独立成立。
   ⇒ 本决策的反向判据主语改成**记录核对器**（原主语按字面恒为 0，不可证伪）。
   逐条依据见 D13（验证路线）「O2（独立解析器 + checker） 判的是**一个**镜像：定案」。
6. **目标负载优先级 —— 已移出本决策，见 D25（目标负载优先级）。** 它跨 D8（核心索引结构） / D10（随机写 / 碎片化的真答案） / D23（journal 的角色与格式），不是 journal 的问题；
   留在这里会被当成 journal 细节。**它不阻塞 D23（journal 的角色与格式） 任何一项**：轴二是被轴一结构性排除的，
   目标负载只影响依据 ③ 的强度，不影响结论。

### 未定项 2 —— 已定（2026-08-29）：取定长环，但理由不是「链式进入死锁 2」

**取定长环。** ⚠️ **候选理由「链式把 journal 写路径变成分配路径，于是进入死锁 2」被三条腿一致判为过强**，
本决策不采用它。链式的增量是有界可算的，抬保留池就断开——它不是一个真环。

真正判掉链式的是三条，都不经过死锁 2：

#### ① 保留池必须涨一个量级，而涨保留池已被实测会加重假性 ENOSPC

链式下 journal 块本身要分配 ⇒ 保留池必须从 `ckpt_cost` 涨到
`ckpt_cost + 一个 checkpoint 窗口内的 journal 块`：

| 原子宽度 | 窗口内 journal 块 | 保留池 | 倍数 |
|---|---|---|---|
| 512 | 125 | 64 → 189 块 | 3.0× |
| 4096 | 1000 | 64 → 1064 块 | **16.6×** |

（`ckpt_cost = 64 块` 由 [experiments.md](../experiments.md) E19（defer 窗口下的假性 ENOSPC）实测；
窗口内 journal 块由 E24（journal 几何）的每记录块数 × checkpoint 间隔算出。）

而 E19（defer 窗口下的假性 ENOSPC）同时实测：**保留池对普通分配是纯税**，预留 0 → 16384 块时假性 ENOSPC 从 3150 涨到 7246。
⇒ **链式不是把代价变成死锁，是把它变成假性 ENOSPC**——而 E19（defer 窗口下的假性 ENOSPC）已定「假性 ENOSPC 只有准入治得了，保留池反而加重它」。

#### ② 前缀判定与空间归属被绑死

| | 定长环 | 链式 |
|---|---|---|
| 「有效前缀到哪」决定什么 | **只决定重放哪些记录** | 还决定**哪些块分配器可以发出去** |

链式下 D23（journal 的角色与格式）的前缀规则与 D21（权威态与派生态的分界）的记账权威
是两个独立判定，却必须逐块一致——不一致就是静默泄漏或双分配。
断号即止的截断点之后的链块要么泄漏、要么被重发而重放仍指着它。
**ZFS 为此需要 mount 期 claim 加 `zh_claim_txg`**（D22（单元原子性怎么合成）已记录）。

#### ③ 死锁 3 不是被消掉，是从静态判据换成动态判据 —— 这条是决定性的

| | 判据 | 什么时候算得出 |
|---|---|---|
| 定长环 | 最坏操作 ≤ 环大小 / F，F ≥ 2 | **mkfs 时算、mount 时校验**（同 XFS `XFS_MIN_LOG_FACTOR`） |
| 链式 | 最坏操作 ≤ **当前空闲** | 算不出——**当前空闲在操作中途会变** |

`.claude/rules/fs-design.md` 硬要求 5 逐字写着：
「**只在操作期间不会变的输入上分支**……「当前填充率」会在操作中途越过阈值，**那是危险的分支变量**」。
⇒ **链式把一条可判定的几何不变量，换成了本工程明令不许用的运行期变量。**
这不是权衡，是撞上已定的硬要求。

⚠️ **但环这一侧的欠账也要写明，不许说成已完成**：那条几何不变量**今天不存在**——
既不在 [invariants.md](../invariants.md)，也不在 [checks-owed.md](../checks-owed.md)。
本决策正文此前写的是「**需要**等价的几何不变量」，那是要求不是事实。
已登记为欠检查，见 [checks-owed.md](../checks-owed.md)。

### 未定项 3 —— 已定（2026-08-29）：tail 住超级块槽，但改 jbd2 两处

**取超级块形态**（tail 的权威副本住在一个固定位置，不内联在记录头），**并改两处**：

| # | 改动 | 为什么 |
|---|---|---|
| 1 | **不许单副本原地覆写**，改 ≥2 槽轮换 + 代号 + 先逐个验证全部候选再择新 | D22（单元原子性怎么合成）已对根定过同一条纪律：一次撕裂会抹掉唯一见证者。轮换不增写数，仍是 21 块 |
| 2 | **只在 checkpoint 持久之后写一次，不上 fsync 路径** | 稳态开销因此是每 checkpoint 一次，不是每 fsync 一次 |

#### 原地覆写与 COW 不冲突，理由有三条

1. **自证单元这一类早就存在**，不是为 tail 新开的：发根本身就是覆写根环的一个槽。
   tail 与根槽、journal 记录头同类，都归 D22（单元原子性怎么合成）已定三管。
2. **COW 对没有父的单元买不到东西**：COW 的防护来自父指针里的校验和。
   给 tail 造一个父，那个父要提交，而提交正是 journal 要办的事——循环原样成立。
3. **tail 语义上是派生态**：权威判定仍是 `jsn` 连续前缀 + `checkpoint_txg`。

#### 由此逼出一条硬要求：恢复不许先信 tail 再往前走

**必须先全环扫描、逐条验证，再择最长合法前缀。**

理由是机制性的：tail 陈旧时，`[tail_陈旧, tail_真实)` 这段已经被新一圈记录写掉了
⇒ 从陈旧 tail 起往前走，**第一条就 `jsn != expected`** ⇒ 断号即止
⇒ 连 `tail_真实` 之后仍然需要的记录也不重放。**那是数据丢失方向，不是「多做功」方向。**

⇒ 「陈旧 tail 只让恢复多做功」这句话**只在全环扫描式恢复下成立**。
本要求与 D22（单元原子性怎么合成）对根槽的「先逐个验证全部候选、再择新」是同一条纪律。

### 未定项 2 与 3 耦合：选链等于把未定项 3 的自由度一起交掉

| | 定长环 | 链式 |
|---|---|---|
| tail 答错的后果 | **只是多做功**（可降级） | **泄漏或双分配**（承重，见未定项 2 的理由 ②） |
| 因此 tail 必须 | 可以是派生态 | **必须是权威态**，且要 tail-before-reuse 硬序、FUA 落在关键路径 |

**内联 tail + 链式是最坏格**：内联只能搭记录便车推进，链式下空闲期不写记录
⇒ 不只是多重放，是 journal 块一直回收不了，空转变成空间泄漏。

### 这两项的证据强度：三处要写明的降级

1. ⚠️ **E24（journal 几何）的「500 块重放」是建模参数，不是测量。**
   代码里 `idle_after = n − 500` 是选定的场景点，`tailing` 就是它之后的记录数。
   真实重放量 ∈ [0, checkpoint 间隔]，取决于崩溃落在窗口哪个位置。
   **方向性结论（内联形态空闲崩溃后重放非零、超级块形态恒为零）站得住，数字不代表典型值。**
2. ⚠️ **「21 : 500」这个比不成立。** 21 是稳态**无条件**付（系统永不崩溃也照付），
   500 只在崩溃真的发生时才兑现。正确的问法是「一次额外写对设备寿命的代价
   与一次最多一个 checkpoint 间隔的顺序重放读，哪个贵」——**E24（journal 几何）没有建模这一维**。
3. ⚠️ **屏障口径下超级块形态是多付的，不是少付**：每 checkpoint 一次额外 FUA，
   20000 次 fsync 里 21 次，占 40000 个持久点的 **0.05%**。方向与块数口径相反，量级仍可忽略。

### 未定项 2 / 3 / 4 的代价已量出，且三者耦合

**2026-08-29，[experiments.md](../experiments.md) E24（journal 几何）。**
纯计数模型，20000 次 fsync，每 1000 次一个 checkpoint。**数的是块，不是字节也不是屏障**
（[checks-owed.md](../checks-owed.md) C27（块数口径定格式参数）与 C26（屏障数从没量过）同样适用）。
**三项都还没定**——本节给的是代价，不是判决；定它们要走
[three-way-inference.md](../../rules/three-way-inference.md) 的三方论证。

#### 未定项 3：两条臂差 21 : 500，方向一边倒

| tail 形态 | 稳态额外写 | 空闲期崩溃后要重放 |
|---|---|---|
| jbd2 形态（住 journal 超级块、原地覆盖、FUA） | **21 块**（= checkpoint 次数，占 20000 次 fsync 的 **0.105%**） | **0** |
| XFS 形态（内联在每条记录头的 `tail_lsn`） | **0** | **500 块**（原子宽度 4096）/ 63 块（512） |

**机制**：内联形态只能搭记录的便车推进——不写记录就推不动 tail；
超级块形态可以在 checkpoint 完成时单独写一次。空闲期崩溃时两者因此分开。
⚠️ 换屏障口径结论不变：21 次额外 FUA 对 20000 次 fsync 的 40000 个持久点是 0.05%。

#### 未定项 2：除一项外每个指标都相同，那一项是分配次数

| | 定长环 | 链式 |
|---|---|---|
| 稳态写块数 | 相同 | 相同 |
| **向分配器要块** | **0 次** | **每个 journal 块一次**（20000 次 fsync ⇒ 20000 次） |
| 死锁 3（单条操作大于环） | 存在，需要几何不变量 | 不存在 |

⇒ **链式把 journal 写路径变成一条分配路径**，于是它进入本决策死锁 2 的环
（checkpoint → COW 写新节点 → 要分配 → 盘满 → 发不出根）。
环的 0 次分配正是「journal 不可能被 COW 覆盖」在模型里的形态。
**链式用「消掉死锁 3」换「加重死锁 2」，而死锁 2 是 COW 独有、且已经最难的那个。**

#### 未定项 4：头部 84 字节，装得下；但 512 这个数不由本工程定

头部字段合计 **84 字节**（magic 4 + 类型 2 + 算法类型 1 + 填充 1 + 自述长度 4 +
点名项数 4 + `jsn` 8 + `checkpoint_txg` 8 + `tail_lsn` 8 + nonce 12 + 头部校验和 32），
占 512 扇区的 16%，其后还余 428 字节（装得下 7 个点名项，每项 56 字节）。

**对齐代价**（要求「记录头完整落在一个原子单元内」）：

| 原子宽度 | 点名 1 项（140 B） | 点名 10 项（644 B） | 点名 100 项（5684 B） |
|---|---|---|---|
| 512 | 512 B（3.7×） | 1024 B（1.6×） | 6144 B（1.1×） |
| 4096 | **4096 B（29.3×）** | 4096 B（6.4×） | 8192 B（1.4×） |

不对齐、多条记录挤同一个原子单元则空间不浪费，**但除第一条外都判不了撕裂**。

#### 三者耦合：任何一项单独定都会定错

原子宽度（未定项 4）决定一条记录占几块 → 决定环要多大（未定项 2）→
环太小把超级块形态的 tail 写放大（未定项 3）。

| 原子宽度 | 环 ≥ 多少块才不强制 checkpoint | 峰值占用 |
|---|---|---|
| 512 | **256** | 125 块 |
| 4096 | **1024** | 1000 块 |

环太小时代价是断崖式的（原子宽度 4096、每次 fsync 点名 1 项）：

| 环大小 | 强制 checkpoint 次数 | 超级块形态的 tail 写 |
|---|---|---|
| 4 块 | **4980**（每 4 次操作一次） | 5000 |
| 64 块 | 300 | 320 |
| 256 块 | 60 | 80 |
| 1024 块 | **0** | 20 |

⇒ **环大小的下界 = checkpoint 间隔 × 每次 fsync 的记录块数**，
这是死锁 3 那条几何不变量的具体形态；它随原子宽度放大 8 倍。

### 未定项 1 —— 已定（2026-08-28）：轴一定了之后，轴二只剩一个合法值

**取甲：每次 fsync 写脏叶 + 全部祖先 + 根槽 + 一条记录。祖先不延后。**

#### 第一依据是结构性的：两根轴不正交

**延后祖先 ⇒ 新根不可能自洽 ⇒ 发不出一个反映本次 fsync 的根。**
COW 下，要让本次 fsync 的叶从根可达，整条脊柱必须已在盘上；
而「自洽」是 [invariants.md](../invariants.md) I-7（根环） 类的要求（从代号最大的根递归校验能走完权威态）。

⇒ 2×2 只有三格可实现：

| | 不延后祖先 | 延后祖先 |
|---|---|---|
| **每次 fsync 发根** | **甲** | **不存在** |
| 只在 checkpoint 发根 | `wal_full` | 乙 / 丙 |

⇒ **轴一已定的「每次 fsync 发根」单独就把乙与丙一起判掉了**，
且轴一那四条依据（环截断不了 / 多一条挂载期重放路径 / journal 进验证链 / 屏障一个没省）
对乙**逐条原样成立**，不需要重新论证。

**实测佐证**（[experiments.md](../experiments.md) E16（journal 的角色：WAL vs 意图日志））：`wal_leaf` 在 20 万次操作里发根
**200 次 = checkpoint 次数**，不是 fsync 次数。它从来就没在 fsync 时发过根。

⚠️ **一处措辞要精确**：轴一依据 2 说的「发根时重放不施加任何东西」只对 **journal redo** 成立。
甲下恢复期仍有「续做未完成意图」这条常规路径（[checks-owed.md](../checks-owed.md) C1（意图续做做成常规路径））。
正确说法是「**甲下 redo 为空**」，不是「甲下恢复无动作」。

#### 三条被降级的依据，逐条写明降到哪

定案给出的三条理由，三方论证打中两条半。**它们仍然写在这里，因为定案是在它们之上做的裁决，不是它们消失了。**

| 原依据 | 判决 | 依据 |
|---|---|---|
| ① 乙毁掉 D13（验证路线） 的 O2（独立解析器 + checker） 逐字节比对，而本工程没有 oracle | **暂不作为承重**，因为它依赖一处本仓自身的矛盾，见本决策「一处本仓自相矛盾：O2（独立解析器 + checker） 到底是什么」 | — |
| ② 按 `fs-design.md` 的格式分支判据，乙买不到「用错了变成挂不上」 | **射程用错，撤下** | D18（块里携带什么信息） 逐字：「⚠️ **判据 2 不是** `.claude/rules/fs-design.md` 那条「能不能把用错了变成挂不上」……**两条判据射程不同，不许互相替代**」。乙不是与甲并存的分支，是二选一的另一套编码 |
| ③ 乙的收益形状不好——不 fsync 时为 0，与组提交是替代品 | **「替代品」那一半已被实测推翻**；③ 只剩「不发布时为 0」，降级为「奖金上界」，不作为否决理由 | **两条腿独立打中，随后补测坐实**：见下 |

**③ 的「替代品」那一半是错的，2026-08-28 补测（[experiments.md](../experiments.md) E16（journal 的角色：WAL vs 意图日志） 多流负载）**：

| 负载 | fsync 每次 | fsync 每 10 次 | 攒批把差距怎么了 |
|---|---|---|---|
| seq | 1.54× | **1.05×** | 几乎吃光 |
| rand | 1.71× | 1.33× | 吃掉一半 |
| metaheavy | 2.31× | 1.63× | 吃掉一部分 |
| **multistream**（16 条流各在自己子树里推进） | 3.40× | **3.71×** | **不降反升** |

**机制：攒批只在被攒的操作共享祖先时才帮到甲。** 流不共享脊柱时，
攒 10 个操作就是 10 条互不相交的脊柱都要写，甲一分钱没省，而乙照样全延后。

⚠️ **适用范围有界，且这个界是先算后测出来的**（56 格扫描，见 E16（journal 的角色：WAL vs 意图日志））：
甲每批 ≈ `批 + min(流数,批)×树高 + 2`，乙 ≈ `批 + 1`
⇒ **比值在「批 ≈ 流数」处见顶，批超过流数之后单调塌向 1**（128 流时批 200 已降到 2.89）。

> **「与组提交是替代品」只在「批大小 ≤ 并发流数」时是错的；
> 批大于流数时它是对的。**

⚠️ **这不改变定案**——轴二是被轴一**结构性**排除的（延后祖先 ⇒ 新根不可能自洽 ⇒ 发不出根），
与收益多少无关。改的是依据 ③ 的强度，不是结论。

**③ 还有一条必须同时写下的反向读法**：乙的收益只在单流同步写上存在，
而**那恰是数据库与虚拟机镜像**——D10（随机写 / 碎片化的真答案） 已把「数据库和虚拟机镜像上的随机写」记为
COW 文件系统的共同软肋。所以 ③ 只能说「乙的奖金有界」，
**不能说「乙的收益不值一提」**。

⚠️ **本工程从未定过目标负载优先级。** 用「那不是主要负载」去否掉 1.3–2.3×，
等于替一个未定项做主。这一条本身是个缺口，记在这里。

#### 一条不依赖 O2（独立解析器 + checker） 的代价

**乙下崩溃后的镜像必须先重放才判得了恢复结果**，于是 checker 的输入只有两个来源：

| 路 | 撞什么 |
|---|---|
| 用**被测实现**去重放，再让 checker 判 | 违反 `.claude/singlefs-ai-sop/rules/evidence-discipline.md`「两条路径不许共享同一段代码」——checker 的输入由被测代码生产 |
| 让 **O2（独立解析器 + checker） 自己重放** | O2（独立解析器 + checker） 要实现分配器 ⇒ C3（读重试无硬上限）①（第二实现的成本） 那笔「第二个文件系统」的成本原样回来 |

⇒ **C3（读重试无硬上限）①（第二实现的成本） 对乙的力度不弱，只是付款点转移了**：不在「重放要不要分配器」，在「谁来生产 checker 的输入」。
⇒ **「C3（读重试无硬上限）①（第二实现的成本） 对 `wal_leaf` 力度明显弱于对逻辑意图」不成立。**

#### 记录头的类型字段：不是期权，是已经欠着的债

D23（journal 的角色与格式） 自身已经有**两种**记录——fsync 记录（点名的每项自带校验和）与 checkpoint 记录（明写不需要）。
⇒ **类型字段现在就是必需的，与轴二日后重不重开无关。**
把它写成「为轴二留的期权」会让人以为付了钱、买到了轴二的可逆性——**它一分钱也没买到那个。**

**真正让轴二可逆的是四项，缺一不可**（三条腿独立指出其中的长度字段）：

⚠️ **本条的本地腿曾用过一份带字词损坏的输出**（`batchinggroup` / `monotfree`，
2026-08-29 补上拼接检测后回扫才发现）。已按 `.claude/rules/three-way-inference.md`
作废重跑，干净那轮**结论未变**，并第三次独立指出长度字段。


| # | 预留什么 | 为什么 |
|---|---|---|
| A | 记录头**类型字段** + **未知类型 ⇒ 拒绝挂载**，且该政策由**超级块 incompat 位**承载 | 光有字段而政策是「跳过不认识的记录」，失败模式是**静默漏放一条发布指令**，比没有字段更糟 |

#### 重开轴二的可判据

⚠️ **这是设计期判据，不是运行期开关。** `.claude/rules/fs-design.md` 硬要求 5

会让崩溃语义在一次操作中途改变，当场违规。**轴二只能整体切换，且走 incompat 位。**

#### 一处本仓自相矛盾：O2（独立解析器 + checker） 到底是什么

**这一条比轴二本身更要紧，因为 C3（读重试无硬上限）②（落点不确定使核对退化） 整个建立在它上面。**

| 出处 | 说 O2（独立解析器 + checker） 是什么 |
|---|---|
| **D13（验证路线） 表格逐字** | 「独立格式解析器 + checker」，判「磁盘字节是否满足 I-1（块自描述）~I-6（加密不变量）」，**验不到什么**：「只判结构自洽：一个块被覆盖成另一份**合法**内容，Merkle 链照样自洽、记账照样对」 |
| **D23（journal 的角色与格式） 三处** | 「独立算出同一个答案再比对」「逐字节比对」 |

**后者严格强于前者，而 D13（验证路线） 明写 O2（独立解析器 + checker） 不具备它。**

⇒ 两条推论，都不舒服：

1. **若 D13（验证路线） 的读法为准**：O2（独立解析器 + checker） 从来就不是逐字节比对器 ⇒ **C3（读重试无硬上限）②（落点不确定使核对退化） 没有可退化的东西 ⇒ 它是空的**，
   而否掉逻辑意图日志的就只剩 C3（读重试无硬上限）①（第二实现的成本）。
2. **若 D23（journal 的角色与格式） 的读法为准**：O2（独立解析器 + checker） 要独立算出同一份物理镜像 ⇒ **它必须自己实现分配器** ⇒
   那正是 C3（读重试无硬上限）①（第二实现的成本） 判为「约等于第二个文件系统」的成本。

⇒ **C3（读重试无硬上限）①（第二实现的成本） 与 C3（读重试无硬上限）②（落点不确定使核对退化） 不能同时按字面成立。** 这一项落进本决策的未定项 5。
⚠️ **它不改变本次定案**——第一依据是结构性的，完全不经过 O2（独立解析器 + checker）。

### 未定项 1 定案的三方论证腿况

- **正推腿**给出了本次定案的第一依据（轴一 ⇒ 轴二），并抓到「C3（读重试无硬上限）①（第二实现的成本） 力度对乙较弱」是错的、
  以及 D13（验证路线）/D23（journal 的角色与格式） 关于 O2（独立解析器 + checker） 的矛盾。
- **反推腿**独立打中依据 ③（E16（journal 的角色：WAL vs 意图日志） 的「每 10 次」档乙仍领先 1.33×，没归零），
  指出本工程从未定过目标负载，并证明 E16（journal 的角色：WAL vs 意图日志） 从未建模并发 ⇒ 「不 fsync」不等于「组提交在场」。
- **本地腿（本轮起改用英文提示，输出判绿：1078 词零复读零替换字符）**
  独立打中同一条 ③，并独立指出「类型字段不含长度」这条缺口。
  它提出「让 O2（独立解析器 + checker） 用确定性分配器就能恢复逐字节比对」——**主 agent 判它不成立**：
