# 不变量清单

**checker 是本文件的可执行形式。** 本文件每加一条，checker 就要加一个检查。
两者不同步的 commit 一律不收（见 [CLAUDE.md](../../CLAUDE.md) 第三节）。

每条不变量必须写成**可判定**的形式——能对着一个镜像回答"成立/不成立"。
写不成可判定形式的，说明还没想清楚，不许进本文件。

> 退役的编号留一行说明去向，比留一个无解释的空档安全。

## I-6 类：加密（依赖 D9，推荐方向已给、四项未答）

**这些检查在加密未开启时应当整类跳过并显式报告为「不适用」，不许静默通过。**

| ID | 不变量 | checker 状态 |
|---|---|---|
| I-6.1 | 加密开启时，全盘任意两个**已写出**的块（不论当前是否仍被引用），其 (密钥代号, nonce) 二元组不相同 | 未实现 |
| I-6.2 | 加密开启时，任一元数据块的明文头字段集合 ⊆ 格式白名单（magic / 格式版本 / flags / **nonce 代号** / 长度 / MAC） | 未实现 |
| I-6.3 | 加密开启时，任一被引用的块，其 MAC 与密文及关联数据匹配（需要密钥在场） | 未实现 |
| I-6.4 | 超级块声明加密时，不存在算法类型字段标为「未加密」的数据块或元数据块 | 未实现 |
| I-6.5 | 记录在案的 nonce 水位 > 全盘出现过的最大 nonce（崩溃后不重用的可判定形式） | 未实现 |
| I-6.6 | 任一指针记录的 MAC 长度与超级块声明的一致 | 未实现 |
| I-6.7 | 同一份数据的多个副本，其指针记录的 nonce 相同（nonce 未绑物理位置的可判定形式） | 未实现 |
| I-6.8 | 加密开启时，任一被引用的块，其指针记录的密文校验和与盘上密文匹配（**不需要密钥**） | 未实现 |

> ⚠️ **I-6.1 只在「不论是否被引用」这个范围下才有判别力。** nonce 重用最危险的一批数据
> 恰恰是崩溃遗留的孤儿块——已写盘、未进树、因而不被引用。
> 把检查范围写成「被引用的块」，等于在设计上排除掉最该查的那一批。
> 因此 checker 必须两阶段：① 遍历树可达块；② **额外全盘扫描已分配物理区间**，
> 靠块的明文头识别「这是一个已写出的 singlefs 块」并取出其 nonce 纳入去重集合。
>
> ⚠️ **阶段 ② 对 D9 未答项 4（nonce 载体）提出一条硬约束：nonce 的代号部分必须放在明文头，
> 无密钥可读，不能整体埋进密文。** 埋进密文的话 checker 没有密钥就连「这块用过哪个 nonce」
> 都判断不出来，I-6.1 的阶段 ② 与 [experiments.md](experiments.md) E5 的判据③一起失效。
> I-6.2 白名单里那一项因此写作「nonce 代号」而不是含糊的「序号」。
>
> ⚠️ I-6.1 与 I-6.5 是**唯一能把「nonce 重用」这类灾难变成可检出事实的检查**。
> nonce 重用在 ChaCha20 这类流密码下直接泄漏明文，而它不会表现为任何读写错误——
> 没有这两条检查，它永远不会被发现。验证手段见 [experiments.md](experiments.md) E5。
