# 不变量清单

**checker 是本文件的可执行形式。** 本文件每加一条，checker 就要加一个检查。
两者不同步的 commit 一律不收（见 [CLAUDE.md](../../CLAUDE.md) 第三节）。

每条不变量必须写成**可判定**的形式——能对着一个镜像回答"成立/不成立"。
写不成可判定形式的，说明还没想清楚，不许进本文件。

## I-3 类：空间记账（依赖 D5）

| ID | 不变量 | checker 状态 |
|---|---|---|
| I-3.1 | 已分配空间统计 == 实际遍历所有引用得到的和 | 未实现 |
| I-3.2 | **此编号不再使用**——它写成「≤ 引用它的**最新**快照的代号」，方向反了：紧的约束是最**旧**的那个。旧写法被 I-3.5 的子判据 ② 严格蕴含，且检不出任何一类真实错误 | 不适用 |
| I-3.3 | **此编号不再使用**——「所属快照」未定义，而两种归属约定给出不同的比较符。由 I-3.6 取代 | 不适用 |
| I-3.5 | **引用区间的精确性**。**内容**：对任一块 b 与任一根 R（快照根或活头根），**「b 从 R 可达」这个可达性谓词，必须等于记账所用的那个谓词**——两者是同一个定义，不是两份。**当前形态下该谓词的表达式**是 `birth(b) ≤ R.txg < death(b)`（[decisions.md](decisions.md) D5 形态）；**换快照模型时表达式要重写，内容不变**。可判定形式（与 I-3.1 共用同一趟全盘遍历）：按 txg 升序枚举全部快照根与活头得 `Reach(b)`，则 ① `Reach(b)` 在 txg 序上**连续无洞**；② 设 R_first 为最早者，`birth(b) ≤ R_first.txg`，且若存在更早的根 R_prev 则 `birth(b) > R_prev.txg`（**双侧夹死，off-by-one 无处可藏**）；③ 若 b 不被活头引用，则 b **恰好**出现在一个 deadlist 中，且该 deadlist 的归属区间 = `(Reach(b) 中最晚者.txg, 其下一个根.txg]`；④ 若 b 被活头引用，则 b 不出现在任何 deadlist 中 | 未实现 |
| I-3.6 | 任一 deadlist(S) 中的块满足 `birth ≤ prev(S).txg`（约定 B 下的紧界）。判别力：抓「kill 时该走直接释放却进了 deadlist」这一类（泄漏方向） | 未实现 |
| I-3.4 | 可用空间统计已扣除「待删除但意图未完成」占用的空间 | 未实现 |
| I-3.7 | 盘上存在一个可枚举的持久结构，其元素恰为当前全部活快照（既不多也不少） | 未实现 |

> ⚠️ **I-3.5 与 I-3.1 正交，两条都必须有。** I-3.1 是标量总账（已分配 == 遍历和），
> 而**归属错误对它不可见**——块被挂到错的 deadlist 上时，它仍然被恰好一处引用，总账依然平。
> 要检出归属错，必须有**按快照分箱的向量等式**。
> 这与 [decisions.md](decisions.md) D14 推导 D-3 里「标量等式 → 按轨道分箱的向量等式，
> 判别力净增」是同一个形状。
>
> ⚠️ **数据丢失方向只在空间被重新分配之前可检出。** 该进 deadlist 却被释放的块，
> 一旦其空间被复用，症状就退化成 I-2.1 校验和不匹配，即「损坏，原因不明」。
> **所以这类检查必须在崩溃点重放 harness 里紧跟着删除动作跑，不能只在夜间全量跑。**
>
> ⚠️ I-3.1 是**唯一允许全盘遍历的记账检查**——它是 checker，不是运行时路径。
> 运行时记账必须增量维护（D5），checker 才用遍历来验证增量维护有没有出错。
> 这条对照关系是本工程验证记账正确性的核心手段。

## I-5 类：分配器

| ID | 不变量 | checker 状态 |
|---|---|---|
| I-5.1 | 不存在被两个不同引用同时占用的物理范围（除非是显式的多副本） | 未实现 |
| I-5.2 | 空闲空间统计 == 总空间 − 已分配空间 | 未实现 |

> ⚠️ **I-3.1 与 I-5.2 的等式在 zoned 布局上有一个已知缺口（[decisions.md](decisions.md) D12 定了多布局之后才出现）。**
> zoned 设备上一个 zone 里只要还有一块活数据就不能 reset ⇒
> **一个活快照钉住的物理空间是 zone 粒度，而它引用的块数是块粒度**。
> 于是「已分配 == 遍历所有引用得到的和」在那套布局上不成立，
> 除非把「已分配」明确定义为「被引用」，**并另立一个「不可回收」量**。
>
> 连带一条对用户可见的要求：**报给用户的「这个快照占了多少」不许被定义成引用块数之和**——
> 那个数在 zoned 上会**系统性地低于**删掉该快照真正能拿回的空间，
> 而 [pitfalls.md](pitfalls.md) 第 12 条骂的正是这类「`df` 输出对用户没有意义」。
>
> **本缺口尚未有对应条目**，补它需要先定义「不可回收空间」这个量。

## I-6 类：加密（依赖 D9，推荐方向已给、四项未答）

**这些检查在加密未开启时应当整类跳过并显式报告为「不适用」，不许静默通过。**

| ID | 不变量 | checker 状态 |
|---|---|---|
| I-6.1 | 加密开启时，全盘任意两个**已写出**的块（不论当前是否仍被引用），其 (密钥代号, nonce) 二元组不相同 | 未实现 |
| I-6.2 | 加密开启时，任一元数据块的明文头字段集合 ⊆ 格式白名单（magic / 格式版本 / flags / **nonce 代号** / 长度 / MAC） | 未实现 |
| I-6.3 | 加密开启时，任一被引用的块，其 MAC 与密文及关联数据匹配（需要密钥在场） | 未实现 |
| I-6.4 | 超级块声明加密时，不存在算法类型字段标为「未加密」的数据块或元数据块 | 未实现 |
| I-6.5 | 记录在案的 nonce 水位 > 全盘出现过的最大 nonce（崩溃后不重用的可判定形式） | 未实现 |
| I-6.6 | 任一指针记录的 MAC 长度与超级块声明的一致 | 未实现 |
| I-6.7 | 同一份数据的多个副本，其指针记录的 nonce 相同（nonce 未绑物理位置的可判定形式） | 未实现 |
| I-6.8 | 加密开启时，任一被引用的块，其指针记录的密文校验和与盘上密文匹配（**不需要密钥**） | 未实现 |

> ⚠️ **I-6.1 只在「不论是否被引用」这个范围下才有判别力。** nonce 重用最危险的一批数据
> 恰恰是崩溃遗留的孤儿块——已写盘、未进树、因而不被引用。
> 把检查范围写成「被引用的块」，等于在设计上排除掉最该查的那一批。
> 因此 checker 必须两阶段：① 遍历树可达块；② **额外全盘扫描已分配物理区间**，
> 靠块的明文头识别「这是一个已写出的 singlefs 块」并取出其 nonce 纳入去重集合。
>
> ⚠️ **阶段 ② 对 D9 未答项 4（nonce 载体）提出一条硬约束：nonce 的代号部分必须放在明文头，
> 无密钥可读，不能整体埋进密文。** 埋进密文的话 checker 没有密钥就连「这块用过哪个 nonce」
> 都判断不出来，I-6.1 的阶段 ② 与 [experiments.md](experiments.md) E5 的判据③一起失效。
> I-6.2 白名单里那一项因此写作「nonce 代号」而不是含糊的「序号」。
>
> ⚠️ I-6.1 与 I-6.5 是**唯一能把「nonce 重用」这类灾难变成可检出事实的检查**。
> nonce 重用在 ChaCha20 这类流密码下直接泄漏明文，而它不会表现为任何读写错误——
> 没有这两条检查，它永远不会被发现。验证手段见 [experiments.md](experiments.md) E5。
