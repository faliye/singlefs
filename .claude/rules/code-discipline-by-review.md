# 编码纪律：machine-first 的实施细则（靠 review 的那一半）

与 `.claude/singlefs-ai-sop/rules/code-discipline.md` 同射程，只写上游没写的。

## 错误：能恢复的写进类型，破坏不变量的就断言

- 能恢复的失败（I/O 错、盘上数据损坏、资源不够）走 `Result`，失败写进返回类型。错误枚举的成员按调用方要做的决定分，不按底层原因逐个展开：底层几十种系统错误挂在一个成员（例「其它 I/O 错」）里当 source 带着；判据是调用方有没有因此失去该有的决定。
- 库代码的公开边界不用 `anyhow`、`Box<dyn Error>` 这类统一错误类型，也不在每一层把底层失败重新展开成成员；测试和命令行工具可以用。
- 不变量被破坏是 bug，用断言，不带着坏状态往下跑、不往盘上写。
- 不写 `unwrap()`，写 `expect`，消息写清依赖哪条不变量：`expect("journal 头在 open() 里验过；这里是 None 说明验证被跳过了")`。

## 函数与嵌套：按「能单独验证」切，按路径数限

- 一个函数一个能单独验证的契约；长度按这个定，不按行数或屏幕高度：一件事三百行可以，两件事挤在二十行里要拆。
- 嵌套层数不设限，限路径数：路径数说得出、而且有限；每一层的迭代对象有名字、有类型，不写 `a[i][j][k][l]`。不带提前出口的循环嵌套几乎不加路径（`break`、`continue`、`?` 各添一条），独立条件的嵌套按指数加。
- 路径数超了就拆；没超不等于好验。循环另写清迭代次数的上界、跨轮携带的状态与它的不变量（写成断言）、每一个提前出口。「只有一条路径」不拿来给难验的算法辩护。
- 参数不按个数限，每个有名字、有类型；几个参数本身构成一个带不变量的概念时才收成一个类型，不为缩短签名凑结构体。
- 结果放进返回类型，不用 `&mut` 输出参数。
- 副作用挤到边上，核心写成纯函数，带 I/O 的外壳越薄越好，外壳靠项目自己的装置验；既查又改的函数，名字把两件事都说出来。
- 提前返回随便用。

## 逐条审过的流行做法

每一条照 `.claude/rules/machine-first.md`「遇到一条通行准则，走这个流程」审过，处置只有六种：废弃、放宽、改写、留下、交给工具、降为建议。设计与流程层面的准则在 `.claude/rules/machine-first.md`「放宽的（人脑带宽的产物）」「留下的（与谁读代码无关）」。

### 整体理念

- 改写「代码读的次数比写的多，要为读的人优化」：为机器验证和信息量优化，人的注意力照 `.claude/rules/machine-first.md`「推论：人的注意力该花在哪」。
- 改写「KISS」：简单指控制流路径少、要验的状态少、每条路径都写明，不指行数少。
- 留下「别写聪明的代码」「YAGNI」（用不到的代码不写）、「最小惊讶」（名字和类型带够信息，让模型猜对行为）、「关注点分离、高内聚低耦合」（边界清楚、契约明确，每一块能单独验证）。
- 废弃「约定优于配置」：不靠隐式的默认行为，要的值都写出来。
- 放宽「文件、模块不要太长」：模块按契约切，不按行数切。

### 命名

- 写法在 `.claude/singlefs-ai-sop/rules/code-discipline.md`「名字：光看名字，就说得出它是什么、做什么」与「类型：让非法状态写不出来」的：废弃「名字要短、离声明越近越短」「循环计数叫 `i`、临时变量叫 `tmp`」「泛型参数用 `T`、`U`，生命周期用 `'a`」「大家都认得的缩写可以用」「匈牙利命名、`m_` 前缀、接口名加 `I`」（含义不同就是不同的 newtype，类型表达不了的单位写进名字）、「模块名别在类型名里重复」、「测试函数叫 `test_<被测函数>`」；留下并加硬「名字要搜得到」（一个语义概念全仓一个名字）；留下「布尔名以 `is_`、`has_` 开头」；改写「同名遮蔽是惯用法」（含义不变可以遮蔽，换了含义就换名字，含义无关的由 clippy 拦）。
- 留下「名字要念得出来」：要的是不歧义、搜得到。
- 留下「不用 `Manager`、`Helper`、`Data`、`Info` 这类噪音词」：删掉它名字没少说什么，就不用它。
- 留下 Rust API 指南 C-GETTER（取值方法不加 `get_`）与 C-CONV（`as_` 借用到借用、约定几乎无开销；`to_` 约定有开销，多半产出新值，也有 `to_str` 这种借用出借用的；`into_` 消费所有权；以 C-CONV 那张表为准，实现兑现名字所说的那一类开销）。
- 留下「类型用名词、方法用动词」与 Rust 的大小写约定。

### 函数

- 写法在「函数与嵌套：按「能单独验证」切，按路径数限」的：改写「函数要短：一两屏，最好不到 20 行」（按一件能单独验证的事切，不按行数）；留下「只做一件事」；放宽「参数最多三个」；留下「不用输出参数」「函数没有副作用；函数式核心、命令式外壳」「查询与修改分开」；废弃「单一出口」；放宽「嵌套不超过三层」。
- 放宽「每个函数只有一个抽象层次」：不强求，要紧的是契约清楚、路径数有限。
- 废弃「从上往下读」：不要求函数按调用顺序排。
- 留下「不用标志参数」：换成枚举（`.claude/singlefs-ai-sop/rules/code-discipline.md`「类型：让非法状态写不出来」）。
- 改写「圈复杂度不超过某个数」：穷举 `match` 的臂数不算，限彼此独立的条件（`.claude/singlefs-ai-sop/rules/code-discipline.md`「分支：穷举写全，不写通配臂」）。

### 类型、数据与封装

- 写法在 `.claude/singlefs-ai-sop/rules/code-discipline.md`「类型：让非法状态写不出来」与「注释、断言、常量、重复」的：留下并加硬「用值对象代替基本类型」；留下「让非法状态写不出来」「解析，而不是校验」「魔法数字要起名」；改写「字段私有，配上 getter / setter」「能 derive `Default` 就 derive」「字段多就上 builder」；我们自己的结构体上废弃 `..Default::default()`；会丢值的方向废弃 `as`（由 clippy 拦）。
- 留下「默认不可变」「不用全局可变状态；不用单例」。例外只有一种：进程级、建好之后只读的外部句柄（GPU 实例这类，建一次代价大、重复建会出错的），可以用 `OnceLock` 在整个进程里建一次；声明处上方写一行注释，说它是哪一种外部句柄、为什么要整个进程只建一次。建好之后还会被改的状态不在例外里。
- 废弃「别用 typedef 给结构体换个名字」：newtype 照用，包的是含义，不是藏结构。

### 分支与抽象

- 写法在 `.claude/singlefs-ai-sop/rules/code-discipline.md`「分支：穷举写全，不写通配臂」的：封闭集合上废弃「用多态替换条件分支」「开闭原则」（加一种情形，让编译器逼着把每一处旧代码过一遍）与 `default:` / `_ =>` 兜底；改写「依赖倒置」（至少两个真实现才抽 trait，对拍用的模型算一个）。
- 留下「单一职责」（一块只有一个能单独验证的契约）、「接口隔离」（trait 往小里切）。
- 留下「里氏替换」：trait 的契约对每个实现都成立，契约测试对每个实现都跑（`.claude/rules/test-discipline.md`「阳性对照必须对**每一条**被测的臂都跑」）。
- 放宽「迪米特法则」：模块内部随便链；跨模块不许穿过别人的内部。
- 改写「设计模式：工厂、策略、访问者」：策略、访问者在封闭集合上写成 `match`，不为模式多加一层。
- 放宽「DRY」：重复要生成，不许手抄（`.claude/singlefs-ai-sop/rules/code-discipline.md`「注释、断言、常量、重复」）。留下「三次重复之后再抽象」：重复先交给生成器，不抽成吃掉穷尽性检查的通用路径。

### 错误处理

- 写法在「错误：能恢复的写进类型，破坏不变量的就断言」的：留下「快速失败」；改写「库代码不 panic，一律返回 `Result`」「错误码还是异常」；库代码的公开边界上废弃 `anyhow`、`Box<dyn Error>`；废弃「确定不会失败时用 `unwrap()`」。
- 改写「防御式编程：处处检查参数」：边界上查一次，换成带证明的类型，往里不重复查（`.claude/singlefs-ai-sop/rules/code-discipline.md`「类型：让非法状态写不出来」）。

### 注释与文档

- 写法在 `.claude/singlefs-ai-sop/rules/code-discipline.md`「注释、断言、常量、重复」的：改写「多写注释」「注释是失败，好代码不需要注释」（「是什么」交给名字和类型，「为什么这样」照写）、「每个公开项都写文档注释」「`TODO` 注释」；留下 `// SAFETY:`（由 clippy 拦）；废弃「注释掉的代码留着以后用」。
- 废弃「在注释里记改动历史和作者」：照 `.claude/agent-common.md`「写」一节「代码与脚本的注释、说明只写现状，不写历史」。

### 格式

- 交给工具「每行不超过 80 列」：`rustfmt` 的默认值说了算；名字长了就换行，不为行宽缩名字。
- 交给工具「竖向留白、相关的挨着放」：不手调。
- 废弃「8 格缩进，逼人少嵌套」：层数不限。

### 测试代码

- 废弃「一个测试只写一个断言」：一个测试一个场景；断言可以多条，每条的消息写清期望什么。
- 改写「覆盖率达到某个比例」：拿路径数和变异清单说话（`.claude/rules/test-discipline.md`「变异测试证明的是断言会红，不是覆盖」）。
- 改写「依赖一律 mock」：优先用对拍的模型和真实实现。
- 改写「测试金字塔」：单元测试是快速反馈；准入靠 `.claude/singlefs-ai-sop/rules/show-me-test.md`「最终判据由项目定」。
- 放宽「测试代码也要 DRY」：每个测试自己读得出场景；搭建可以抽成辅助函数，断言不藏进去。
- 废弃「不稳定的测试多跑几次就过」：照 `.claude/rules/test-discipline.md`「单次观测不算数」如实说不稳定，不重跑到绿。
- 留下「先写测试」：先看着它红（`.claude/rules/show-me-test-by-review.md`「新增的测试必须先证明它会红」）。

### 改动方式

- 改写「童子军规则」：顺手的整理单独提交，不混进功能提交。
- 留下「不容忍破窗」，由门禁落实：编译器和 clippy 的警告按错误处理。
- 「避免过早优化」降为建议。

## 一处改动，改全相关的代码与配置

- 改一个行为、删一个功能、换一种做法时，依赖它的代码、测试、文档、登记表与配置一起改；本地配置（不进版本库的文件、程序运行时写进系统的设置）同样算。
- 动手前按旧名字、旧路径、旧取值全仓搜一遍，再查本地配置与运行时状态；删掉一段改过系统状态的代码时，同一次把它留下的状态清掉并回读。
- 改完按同一份清单再搜一遍，旧的只剩说这次改动本身的那几处。

没有检查判，靠改的人现查。
