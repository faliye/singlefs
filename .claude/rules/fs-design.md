# 设计纪律

具体的设计决策记在 `.claude/kb/decisions.md`。本文只写**跨决策生效的纪律**。

**这是 singlefs 的项目本地规则**，不在共享 SOP 里。
共享规则在 `.claude/singlefs-ai-sop/rules/`。

## 从事务开始，不从功能开始

任何新功能都是「一种新的事务」。
**没有事务层的功能实现一律不收。**

第一个可运行目标不是「能创建文件」，是「能正确提交一个事务」——
哪怕它只能分配块、写入、提交，没有目录、没有树、性能烂到底。

## 记账是事务的副产品，不是事后的遍历

**线划在「谁消费这个数」，不划在「用什么机制算出来」。**

| 消费者 | 允不允许遍历 |
|---|---|
| **运行时决策路径**（分配、ENOSPC 准入、defer 窗口、生命周期判定） | **不许**，且代价不许随盘容量增长 |
| **checker / 审计** | **必须**遍历 |
| **后台、可续做、非决策路径**（销毁快照、整理、scrub） | **无戒律** |

**空间统计与配额落在第一格**：必须在事务提交时增量维护出来。

⚠️ **一个量落不落在第一格，按这一格自己的判据判：「被问到那一刻有没有答案」，不按名词清单判。**
「快照用量」按这条判的结果、将来做 per-snapshot 配额时怎么办，
见 `.claude/kb/decisions/05-快照-空间记账机制.md` D5（快照 / 空间记账机制） 已定项 4 统计量表第 8、9 行。

⚠️ **被禁止的不是「遍历」，是两件事**：
「在需要答案的那一刻还没有答案」，以及「审计与被审计用同一段代码」。
**运行时与 checker 必须用不同的算法。**

⚠️ **别拿第一格的禁令去否第三格的设计。**

## 元数据块必须自描述

任何一个块单独捡起来，都要能回答「我是谁、我属于谁、我是第几代」。

## 不是单元的盘上空间，核心层对它零覆盖

要在盘上开一块新空间时，先问「它是不是单元」。
不是 ⇒ 校验和 / MAC、扫描重建认领、checker 遍历、不变量这几样一条都不给你，
要么逐条补齐各自的替代品，要么把它做成单元。
⚠️ **「是单元」说的是格式形态，D21（权威态与派生态的分界） 已定项 17 第 5 条「扩展点里的指向不许指向核心层的对象」里的
「核心层的对象」说的是可达性身份**：
一块空间可以既是单元、又不从任何根独立可达（生命周期绑在宿主上）。

## 不为省空间牺牲自包含

**自描述数据宁可写大一点。** 遇到「这个字段能不能省掉 / 能不能压窄 / 能不能现算」这类权衡，
默认答案是**不省**——除非有实测证明省下来的那部分是瓶颈。

⚠️ **「比谁省」不构成任何判据。**
「我们比 X 省 / 比 X 费」这类比较**不许出现在任何判据里**，
只许用来驳「我们很奢侈」这个前提。

⚠️ **这条不是「随便加字段」**。它管的是**已经论证过有用**的字段该不该为省空间而砍，
不管「要不要加这个字段」——后者仍然要各自给理由。

⚠️ **它也不推翻「格式上吝啬分支」**。

## 加密是可选的运算，不是可选的格式

可选的是 AAD 那道**运算**（加密关着就不算），不是**格式**：指针里的 MAC / nonce / 算法类型、单元头里的 nonce / MAC 预留、inode 条目里那份出生树，所有卷都照留，也不许挪去装别的字段。这与 D19（块指针的结构与宽度预算） 已定项 3「定宽，不加密时留位」是同一件事。

**判据表怎么写**：依据来自 D9（加密） / AAD / MAC 的，标成「只在加密开启时有执行路径」，不拿它当非加密一侧的理由——加密不进第一个可运行版本（D9（加密） 已定项 10），非加密一侧要有自己的理由（本地互证、自包含）。
不要提议「不加密的卷省掉加密预留位」「把预留位挪作他用」。

## feature bit 分三档，且预留空位

`incompat`（不认识不许挂）/ `compat_ro`（不认识只读挂）/ `compat`（不认识随便）。每档 256 位，分出去的位登记在 D15（格式冻结政策） 已定项 4 那张表（位号的唯一登记位），记账在 `.claude/kb/feature-bits.md`，没分出去的都是预留空位。

## 不同地址空间必须是不同的 Rust 类型

逻辑地址、物理地址、设备内偏移、代号、inode 号——一律 newtype，**混用必须编译不过**。

## 一个事务层，所有结构共用

不许为某个路径（如 fsync）开第二套事务机制。

**它约束的是「结构」，不是「字节完全相同的落盘代码」。** 精确形态：
**一个共享的事务抽象状态机 + 一个封闭的提交步骤枚举**，
「这一步具体怎么落盘」按结构等价类分派。介质各自一条实现管道是允许的；
**绕开状态机的第二条发布路径不允许**。见 [decisions.md](../kb/decisions.md) D17（实现分层与第三方管道） 与 D13（验证路线）。

**提交协议归本工程独占，不是可以外包的部分。**
一条第三方管道要引入新的结构性提交步骤，必须往本仓的共享枚举发 diff，
不许在自己的黑盒里发明。

## 借用式条款要把被借规则的每个参数都绑死

「X 同 Y」「X = 一次 Y」这种借用式条款，Y 的每一个参数在 X 上都要有定义。

**写借用式条款时，把被借规则的参数逐个列出来，在 X 上各写一句它取什么**；写不出来就别借，把 X 自己的规则写全。审一条借用式条款时同样逐个参数问一遍。门禁不判「同」「= 一次」后面借的是哪条规则、它有哪些参数。

# 不追求万能方案：分支是可以的，但要还对债

**不硬造万能方案，显式分支**：不同规模、不同介质、不同安全要求走不同实现。

## 分支的三条约束

1. **只在操作期间不会变的输入上分支。** 设备类型稳定，可以；
   「当前填充率」会在操作中途越过阈值，那是危险的分支变量。

2. **行为上放开分支，格式上吝啬分支。**
   ⚠️ 第一个外部用户出现之前格式是软的（`.claude/rules/format-evolution.md`）：评估候选时，一处格式改动的代价只算这一次要同步的东西（字节表、`crates/singlefs-checker/invariants/`、checker、装置、产物重跑），不算永久兼容负担，不拿「进了格式就删不掉」给候选设限；真正要慎重的是概念模型（决策正文）。

3. **门禁的范围必须可判定——挂钟本身不是约束。**
   单次改动只碰一条分支时，只重跑那一条；语料总量再大也不构成成本。
   「这次 diff 到底碰了哪几条」判得出 ⇒ 只跑受影响的那些；判不出 ⇒ 全跑。
   ⚠️ **「我只动了一条」是需要被证明的断言，不是事实。**
   落点：[checks-owed.md](../kb/checks-owed.md) C8（门禁范围判不出来）与 C19（介质判定渗进事务层）。

## 五条硬要求

1. **切换判据必须显式、可计算、写下来。**
   不许是「凭感觉」，也不许是埋在代码里的魔数。
2. **每条分支必须能被测试强制进入。**
   留一个只供测试使用的开关，能无视判据直接走指定分支。
   **进不去就等于没测**——靠碰运气覆盖到的分支，等于没有覆盖。
3. **每条分支单独验，包括崩溃点重放。**
   「另一条分支测过了」不算。
4. **分支必须可观测**：运行时能看出走了哪一条。
5. **分支变量不许在操作中途改变。** 判据见「分支的三条约束」第 1 条（只在操作期间不会变的输入上分支）。

**判据写不出来时，先只做一条，而且先做慢而正确的那条。**

## 这两条教条在格式层的形态

`.claude/singlefs-ai-sop/rules/machine-first.md` 的两条推论——**穷举的显式分支**、
**用类型让非法状态无法表示**——代码上照用，代码示例见那一篇。
**格式层也照用，判据见「格式分支的判据」。**

### 格式层的「让非法状态无法表示」，形态是 incompat feature bit

```rust
// ✗ 一套布局 + 参数
struct SystemConfiguration { node_size: u32, /* ... */ }
```

```rust
// ✓ 布局身份进 incompat 位：不认识就挂不上
// （示意写法：位号与名字以 D15（格式冻结政策） 已定项 4 与 .claude/kb/feature-bits.md 为准，别照抄这几个位号）
const INCOMPAT_LAYOUT_ROTATIONAL: u64 = 1 << 0;
const INCOMPAT_LAYOUT_SSD:        u64 = 1 << 1;
const INCOMPAT_LAYOUT_ZONED:      u64 = 1 << 2;

const SUPPORTED_INCOMPAT: u64 =
    INCOMPAT_LAYOUT_ROTATIONAL | INCOMPAT_LAYOUT_SSD | INCOMPAT_LAYOUT_ZONED;

fn mount(system_configuration: &SystemConfiguration) -> Result<Fs, MountError> {
    let unknown = system_configuration.incompat & !SUPPORTED_INCOMPAT;
    if unknown != 0 {
        // 拒绝挂载，而不是「尽力而为地猜」
        return Err(MountError::UnknownIncompat(unknown));
    }
    // ...
}
```

### 格式分支的判据

> **一条格式分支值不值得，看它能不能把「用错了」变成「挂不上」。**

| 能 | 值得 |
|---|---|
| **不能** | **不值得** |

「格式上吝啬分支」吝啬的对象不是分支数量，是**买不到失败模式改善的那些分支**。

⚠️ **判据里不许出现「这样更快」。**
拿性能去换永久的格式债，要单独立决策、单独给数字，不能挂在这条判据下面过。

### 一个已经成立的实例，和一个不成立的

| 实例 | 判定 |
|---|---|
| **D12（目标介质） 的介质分层布局** | **成立** |
| **D9（加密） 预留的「每个写的算法类型字段」** | **成立** |
| **「持久 / 临时」分轨** | **不成立**（见 [decisions.md](../kb/decisions.md) D14（双轨（大小文件 / 持久临时））） |

## 索引结构可以多样，事务层不许多样

按访问模式选索引结构是允许的、也是推荐的（反向索引写多读少、目录项点查、extent 范围查询）。
**唯一不许多样化的是事务层。**
