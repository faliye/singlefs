# 变异没被抓时，先分清是哪一类

变异测试的总纲在 `.claude/rules/test-discipline.md`「变异测试证明的是断言会红，不是覆盖」：被抓、等价变异（在所有输入上与原式同值，判定为等价的把等价性写成一条测试留档），常量断言写加法、不写减法（减法断言在变异下编译期溢出，记成第八类无效变异）。

这里共八类：第一至三类是变异没红的三种（「没红的三类，判据不同」那张表的三行），第四至八类各占一节。

## 没红的三类，判据不同

| 变异没红 | 是什么 | 怎么处置 |
|---|---|---|
| 断言压根没覆盖那段代码 | **真盲区** | 补断言 |
| 在**所有**输入上与原式同值 | **等价变异** | 把等价性写成一条测试留档，再换一个真会改行为的变异 |
| 在**我选的取样点上**恰好同值，换一个取样点就不同 | **取样点不敏感** | **补一个敏感的取样点**，不是留档 |

## 第三类不许当等价变异留档

取样点不敏感的变异不记成等价变异留档：补一个敏感的取样点。

## 第四类：取样点不敏感还有一种形态——它不判绿，它当场炸

取样点选窄了，单测全绿、变异也全抓，实验一跑起来就 panic。判据与第三类同，问句换一个方向：**单测取的那几个点，覆不覆盖实验自己会跑到的全部取值？**（`.claude/rules/test-discipline.md`「只让多条臂互相比，测不出「所有臂一起错」」管断言之间的盲区，这一条管取样点与实际取值域之间的盲区。）

## 第五类：两个口径算同一个量，而它们在基线那一臂上恰好同值

不经变异，出在两份算术之间：仓里对同一个物理量有两个口径，写新算术的人挑了一个，两个口径在他对答案的那一臂上恰好同值。

**判据：把一个数写进产物之前，问一句「这个量仓里是不是已经有人算过；算过的，他用的分母是不是我这个」。**
- 两个口径都在：不自己挑一个；要么按仓里那个算并注明出处，要么不报这个数，把这一格留给已有的欠账。
- 只在基线那一臂上对过账等于没对：对账对在被判的那一臂上。

## 第六类：跑前写死的判决只在一个几何 / 旋钮取样点上量过

对象是判决本身：一个实验跑前写死的判据（阈值、翻不翻面）只在装置取的那一个几何或旋钮上检验过，而那个几何 / 旋钮不是任何已定条款给的。

**判据**：每个带跑前判决的计数实验报一行「几何敏感性」：至少在一个方向相反的几何 / 旋钮取样点上重跑判决那一格，翻面记「不稳定」、不翻记两点；写「这是政策的性质」「是数不是取法」之前，把那条政策依赖的每个旋钮扫一遍。判别力自证：把判据阈值挪到两点之间，检查必须由绿转红。欠账在 [checks-owed.md](../kb/checks-owed.md) C317（判决只在一个几何取样点上量过没有检查）。

## 第七类：变异压根没跑——锚点在源码里不再唯一命中

变异表里一条的「原文」在对应源码里命中 0 次或多次（crates 那张表另算文件不在、读不了），那一条记**锚点失效**，按条判、不让整张表退出：
- `mutate.sh` 派活之前逐条核锚点，锚点失效的那一条打一行 `⚓`、不跑、不入判定库，别的条照跑；收尾「计数：」报「锚点失效 N 条」，N 不为 0 整轮退出码 3。
- 门禁 crates-mutation-replay 同样按行判：那一行记「锚点失效」、不跑、不入库、不复用，「计数：」报「锚点失效 N 行」，整道判红；别的行照判、照入库，选行（`--item`）与双机分片同样按行。

**判据：读 `mutate.sh` 的输出之前，先确认它跑完了整张表**：收尾没有「已还原，基线仍全绿」（全部复用时是「全部复用」那一行）就是中途退出，那一轮的「全抓」不算数；有这一行而退出码是 5（跑的时候源码被改过）同样不算数，改完重跑。锚点失效那一栏不为 0 的，那几条没跑过，不算进「全抓」：把原文改到今天源码里逐字存在、只出现一次的那一段，再单跑那几条。

门禁 code-source-discipline 的 mutation-tables 格不跑变异，只对每张表逐条做子串计数，命中不是 1 次判红并列出表名与条目名。

## 第八类：变异跑了但无效——替换编不过，那条行为零覆盖

替换之后编不过的变异记「无效变异」：不算被抓、也不算没抓到。一条无效变异等于它本要证明的那个行为零变异覆盖：换一条真会改行为的补上，实验页不按表里的条数写「N 条全抓」。

- 反斜杠转义这一种成因由门禁 code-source-discipline 的 mutation-tables 格静态判红：两侧变异表的原文与替换文里只有 `\n` 会被还原成换行，出现别的反斜杠转义判红。
- 跑起来才发现的编不过，门禁 crates-mutation-replay 单独报成「无效」，与「没红」分两栏、各带各的出路：无效先按「改了一个格式常量之后，要看「无效」那一栏有没有变多」列的来源分（编不过改那一行替换文，点名的名字认不出改那一行的测试名，测试进程被杀先查是谁杀的）；没红才去补一条会红的用例。读它的输出按两栏分开数，无效的条数不算进「全抓」。

## 改了一个格式常量之后，要看「无效」那一栏有没有变多

改完格式常量，重跑受影响的每张变异表，比对「抓到 / 无效 / 没红」三个数，不只看「没红」是不是 0；无效那一栏变多，等于有断言被关掉了。

`mutate.sh` 没有三数汇总行，按每条结果行开头的符号数（`[ ]` 里是变异名，不是结局）：`✅` 抓到、`⏭` 无效、`❌` 没红；`💥`（测试进程没跑完）、`⚠️`（报了失败却一个测试名都没抓到）、`⚓`（锚点失效）另列，几栏加起来等于表的条数。`⚠️`、`⚓` 不为 0 的整轮已判失败；`💥` 不判失败，照样单列、逐条交出去。收尾那行「计数：」报九栏：抓到、没红、无效、没跑完、抓名字有盲区、锚点失效六栏，后接判定库那一侧的现判、复用、拒算三栏，照原样另列。

门禁 crates-mutation-replay 照它自己收尾的「计数：」行（没有 `💥`、`⚠️` 两栏），每一条按这个次序判：
1. 点名的测试那一行是 `FAILED`，而 libtest 交出的它自己那一段输出（`---- <全名> stdout ----`）里、或所有段之外（不在任何一段里，归属不明）有一行行首是 `GPU_DEVICE_LOST ` 的行（形如 `GPU_DEVICE_LOST test=<当前线程名> card=<卡名> reason=<一句>`，`test=` 是 `main`、`unnamed-thread`、全名都算，不比对；红的是设备丢失、不是断言）：记「本次未跑」，走 `NOT_RUN_NO_GPU_ADAPTER` 同一路。
2. 那一行是 `FAILED`，它自己那一段里、所有段之外都没有行首 `GPU_DEVICE_LOST` 的行（标记行只在别的用例的那一段里、显存不够而红的同样）：记抓到。
3. 那一行是 `ok`（带不带 `GPU_DEVICE_LOST` 都照这一条往下判），输出里又有一行 `NOT_RUN_NO_GPU_ADAPTER` 点名它：记「本次未跑」。
4. 带 gpu 特性的行，那一行是 `ok`，它打的 `CRASH_POINT_REPLAY_GIVEN_STATES` 行里每一行的 `states_judged_by_the_gpu_here` 都是 0（给定状态整趟交 CPU 判）：记「本次未跑」。
5. 那一行出现了（跑了没红，或跑到它、跑完它之后进程被杀）：记没红。
6. 那一行没出现，而输出里有一行 `error:` 开头或 `could not compile`：记无效（替换文编不过，或测试进程在跑到点名的测试之前就被杀，尾巴带 `process didn't exit successfully` 与信号，或点名的名字认不出，名字里带 `$` 这类字符它按字面去找）。
7. 都没有：记「没跑到」，算没红。

「本次未跑」不算抓到、不算没红，另起「本次未跑：N 条」一行逐条报，不让整道判红。无效、没红都让整道判红；「锚点失效 N 行」不为 0 也让整道判红；基线不绿不在「计数：」那一行里，另起一行报（「基线：…基线不绿 N 行」），不为 0 同样让整道判红。`crates/mutations.tsv` 整表复跑与点名几行的 `--item` 什么时候跑、谁跑，照 `.claude/rules/verification.md`「一个门禁：两种跑法」。

## 判据

> **一条变异没被抓时，问一句：换一个取样点，它还同值吗？**

- 答不上来：去找一个会让它不同值的取样点，找得到就是取样点不敏感，补那一格。
- 确认在所有输入上同值，才是等价变异，照 `.claude/rules/test-discipline.md`「变异测试证明的是断言会红，不是覆盖」留档。

怎么找那个取样点：变异改的是出现在除法或取整里的常量，就去解「让两个式子跨过整数边界」的那个输入；改的是加法项，任何输入都敏感，那就是真盲区。

判据落在 `scripts/mutation/mutate.sh` 的输出上：它报「一个测试都没红」的条目，逐条照「没红的三类，判据不同」三分，不直接记成盲区或等价。
