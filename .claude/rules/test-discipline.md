# 测试纪律

## 单次观测不算数

跑至少 5 轮。说「通过」要每轮都通过，说「失败」要每轮都失败；两边都不满足就如实说「不稳定」，不下结论。

前提是观测本身有变化：真实 I/O、并发、时序、随机源至少占一样。一样都不占的是确定性模型，只能写「跑多少轮说明的都只是没有隐藏状态，不是统计上稳定」，证据强度靠变异测试和钉死绝对值的断言，不靠轮数。

## 读不到 ≠ 读到 0

指标读出来是空的，重试，而且这一轮作废，不当成 0 去算。

## 实验开跑之前，答案不许已经存在

- 不预设结论；设计阶段不参考任何已有结论：这个项目上一轮的结论、别处的定论、自己的直觉一概不看。
- 读定义，不读答案：被测对象的口径、参数、语义逐字读（`.claude/rules/evidence-discipline.md`「它定了没，和它到底怎么定义的，是两个问题」）；「上一轮测出来是某个值」「某某项目说这样更快」是答案，不读。
- 判据、阈值、作废条款都在跑之前写死，写完再去看已有结论。两边对不上就如实并列，不许回头改判据——改了就是新实验，重跑。
- 阳性对照的答案不放在被测的一方读得到的地方。被测的是会读仓的 agent 时，答案不写进它要跑的脚本、不写进同一个仓的记录；候选空间小又不加盐的短哈希算明文。盲测用的答案不进被测方能读的仓，或者换一段它没见过的历史；留在仓里的对照只当回归检查（防工具被改窄），不当盲测。

## 实验的失败条款不许让结论不可证伪

不把「没测出效应」一律写成实现有 bug。两个对照组都跑：

| 对照组 | 作用 | 测不出差异时怎么判 |
|---|---|---|
| **阳性对照**：效应在文献里确凿存在的那个基线 | 证明这套测量分得出差别 | **实现有问题，整轮作废** |
| **真实基线**：这个项目实际打算实现的那个方案 | 回答实验真正要问的问题 | **是个正当结果，如实记下来** |

每写一条失败条款，紧接着写一句「什么观测会让它触发」；写不出那句观测，这条条款要么前件写反了、要么写空了，都按没有条款算。

### 判据不写成合取，门槛不能是臂定义的同义反复

- 不把两个量合成一个 true / false：每个量各占一行、各报各的判定，合取留给人做。
- 门槛不能是被测臂的定义：写门槛之前把被测臂的定义并排放一遍，门槛能从定义直接推出来的，那一格不算判据。

## 阳性对照必须对**每一条**被测的臂都跑

对照那段循环遍历所有臂，不写成「拿第一条跑一下」；加臂时连对照那一段一起改。

## 只让多条臂互相比，测不出「所有臂一起错」

每写一条互比断言，旁边要有一条把绝对值钉死的断言：「三条臂的开销相等」不够，还要「开销正好等于某个数」，那个数另外算出来。写完一条互比断言就问「要是几条臂一起错了，谁会发现」，答不上来就补一条钉绝对值的。

## 端点不是轨迹：被条款当谓词输入的量，实验要报轨迹

一个量被某条条款当停机 / 起跑 / 准入谓词的输入时，至少报三样：吃光初始供给之后的峰值、为正的轮数、期末值；只报期末值的，正文里不写「从来」「恒」这类说轨迹的词。

## 实验要写清为哪个决定而量、量到哪算够

跑前登记除了「量什么」，还写这个量为哪个决定而量、它取什么值会让那个决定翻面、量到哪一步那个决定就能判；写不出这三样的量不登记。

- 选择与结论分开写：交选择的时候另写一份只有问题的清单，每个选择的候选、什么观测会让选择翻面、量到哪算够；它不带倾向、不带数，可以原样交给设计实验的一方。
- 登记里每个量对应清单的一行，对不上任何一行的不登记。
- 每段交回附一张表，逐行写「已够判 / 还差什么 / 剩下的量能不能让它翻面」；续派之前先点名还差的那几行，一行都不差就停。
- 「够判之后没跑」是合法结局，不是欠账，实验状态里写得出来。

## 变异测试证明的是断言会红，不是覆盖

变异只证明「凡是写了断言的代码都被变异测过」，不证明「结论涉及的每一处代码都测过」。不写「零盲区」，只写「<条数> 条变异全部被抓」；写完结论再问：这条结论的算术从哪来，那部分有断言盯着吗？

1. 常量断言写加法，不写减法：写 `assert_eq!(total_size_in_bytes, header_size_in_bytes + 240)`，不写 `assert_eq!(total_size_in_bytes - header_size_in_bytes, 240)`。
2. 等价变异不算盲区，但要分开记：在所有输入上都跟原式同值、判定为等价的，把等价性写成一条测试留档，再换一个真会改行为的变异补上。

变异没被抓时怎么分类，照 `.claude/rules/mutation-sampling.md`。

## 检查本身也可能是错的

- 下断言之前先确认这个检查分得出差别：验「没有非法块」的时候，同时确认扫描真的读到了块。写完一个检查就问：被测对象真坏了，它会不会红？答不上来就是还没写完。
- 比较前后两个值的核对（改前与改后、两次运行、两份清单），任一侧为空或取不到，整条判失败，不输出「相等」「不变」。
- 测试脚本与自证照 `.claude/rules/test-script-discipline.md`「测试脚本自己也要被测试证明有效」；自证每一格单跑与整份跑判定相同照它的「用例原子化：每一条都能单独跑」。

## 测试照真实的条件造，不虚构达不到的条件

- 测试里的资源、配置与规模照被测对象真会遇到的取值：从项目的配置或配置模板取，不另写一个真环境里不会出现的数。
- 用例要证明的行为是真环境里会发生的；真环境里达不到的条件（凑不齐的资源、不会出现的组合）不造成用例。
- 要验的条件造不出来，就写明「这一条测不到」，不拿一个造得出、真环境里不会有的条件顶替。

没有检查判，靠 review。

## 判资源够不够，先扣回本进程已经占着的

检查一份资源（显存、内存、句柄、磁盘配额）够不够时，读到的空闲量不含本进程自己已经占着的那一份：判之前把本进程（前面的用例或前面的一步）占着的加回去，或者只在进程开头、占用之前判一次。

没有检查判，靠 review。

## 阴性结果要能和「代码没跑到」分开

「没复现」不等于「没问题」：说「这条路径是对的」，要拿出读数证明那条路径真的跑过。

扫一批格、数某一支出了几次的探针，每个计数同时报那一支试了几次（分母）。分母是 0 的计数只写「装置走不到」，不写「没撞上」「没打中」，也不拿它撑结论；那一支的次数额度被别的格先用光，同样算分母是 0。
