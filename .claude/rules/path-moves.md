# 文件与目录的路径不在冻结范围内

**这是 singlefs 的项目本地规则**，不在共享 SOP 里。共享规则在 `.claude/singlefs-ai-sop/rules/`。

`.claude/singlefs-ai-sop/rules/evidence-discipline.md`「原样保存的证据不许事后改」冻结的是**内容**：发给模型的提示说了什么、腿答了什么、产物量到什么数。
**文件与目录的路径不在冻结范围内**（2026-09-17 用户定）：一个文件或目录搬了家、改了名，全仓指向它的地方一次改成新路径——`research/prompts/`、`research/results/`、`records/`、变更史与历史版本节、别的会话的记录都算，不留一处旧路径。

## 为什么

路径只是指向，不是被冻结的那句话本身。旧路径留在冻结材料里，读的人与脚本顺着它找不到文件，这份证据等于断了链；而冻结原本要保护的，正是「这份材料还对得上它当时说的东西」。
实测（2026-09-17）：两份字节布局表搬进 `.claude/kb/layout/` 时只改了现行文件，`research/prompts/` 下 200 多份材料仍指旧路径；E142（第一个事务的干跑） 装置源码里一条带路径的字符串改了，留存产物没改，门禁 87 号的逐字复跑因此对不上。

## 怎么做

1. 搬之前在 `research/scripts/path-moves.tsv` 登记一行：旧路径、新路径（都从仓库根写）、日期、依据。
2. 搬完跑 `python3 research/scripts/rewrite-moved-paths.py --apply`：Markdown 链接按每个文件自己的位置重算相对路径，其余写法（整条路径、`kb/` 起、文件名、不带 `.md` 的名字）按登记表改，改完回读。别的会话正在写的文件用 `--skip` 跳过，把旧路径与新路径的对照发给它自己改。
3. 说搬迁这件事本身的那一行保留旧路径：同一行里旧、新路径都在，或带「改前」「搬到」「搬进」「搬迁」「改名为」这类记变更的词——变更史里「改前：链接指向旧路径」照旧是真话。
4. 改写会让被改文件的 sha256 变：判决或核对表里记过的 sha256 对不上时，先对 `path-moves.tsv` 的日期；只差路径的不算证据被改。产物里带路径的，装置源码与留存产物一起改，复跑仍逐字相同。

## 按里程碑递增的文件放进同一个目录

同一类随里程碑一份一份长出来的 kb 文件（字节布局表之类）放进一个目录，文件名 `NN-简称.md` 与 `.claude/kb/milestone/` 同号，不在 kb 根目录下并排起 `first-…`、`second-…`（2026-09-17 用户定：两份字节布局表散在 kb 根目录，「明显要出现 third-txn-layout 之类的东西」；要的是放进一个文件夹，不是合成一份）。第一例是 `.claude/kb/layout/`（`01-first-txn.md`、`02-second-txn.md`）。新立这类文件时直接建目录；已经并排起了名的，按上面「怎么做」搬。

## 门禁管哪一半

`.claude/gate.d/64-moved-paths.sh` 用同一个脚本的 `--check` 查全仓不再出现登记过的旧路径，判别力样本在 `.claude/gate.d/fixtures/64-moved-paths.sh/`。
**它管不到的**：没登记的搬迁（登记表是它唯一的输入）；路径以外的改名（章节标题、编号、简称）不在这条规则里，照旧按冻结与 `kb-discipline.md` 办。
