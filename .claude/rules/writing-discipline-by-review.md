# 写作纪律（靠 review 的那一半）

## 先分清这份东西是给谁的

| 类别 | 谁在用 | 目标 | 规则 |
|---|---|---|---|
| **设计文档** | 人通读 | 让人同意并上手 | `.claude/singlefs-ai-sop/rules/design-doc-discipline.md` |
| **工程 kb** | 模型检索 | 让模型不编 | `.claude/singlefs-ai-sop/rules/kb-discipline.md` |
| **规则** | 执行 | 能变成会失败的检查 | `.claude/singlefs-ai-sop/rules/rules-discipline.md` |

动笔前先问：这份东西是给人从头读的，还是会被模型单条取出来看的。三类通用的只有一条：正文只写现状；历史放不放、放在哪照各自的规则（规则文件不留历史节：`.claude/singlefs-ai-sop/rules/rules-discipline.md`「5. 规则文件不留历史节」；kb 照 `.claude/rules/changelog-format.md`「只有决策与实验有历史，别的文件没有」）。

## 长度要配得上改动的重量

尺子：几行到几十行的改动，commit 正文最多两段，新增代码注释最多一行；写不下先查是不是在写不该写的东西。删到合适长度是写代码的人的事。

### 不丢内容的前提下，越短越好

- 正：删掉这句，读的人少知道了什么？说不上来就删；「读着更顺」「显得更周全」不算内容。
- 反：留着这句，读的人多知道什么？说得上来就不许删，短了也不行。
- 直接删的：同一句换个说法再说一遍、给没人质疑的结论加铺垫、判据正着说一遍再反着说一遍（`.claude/singlefs-ai-sop/rules/writing-discipline.md`「四类不许写」的「过度解释」）。

### 「越短越好」不是「越短越对」

拿不准时留着。证据、口径、下一步（`.claude/singlefs-ai-sop/rules/sop-first.md`「每一条拒绝都必须给出下一步」）一样不省。删过头的三种：

| 删成了什么 | 丢掉的是 |
|---|---|
| 「实测 3.26×」 | 口径：什么硬件、什么负载、块多大 |
| 「不合格」 | 下一步 |
| 「按某某决策办」 | 依据：为什么这么定 |

### 硬数据不算在长度里

给 review 用的、reviewer 拿过去自己就能验的实测数据不算长度。只贴能定胜负的那几个数，完整记录放 `.claude/kb/` 或 `records/`。

| 不算（该贴就贴） | 算（先删） |
|---|---|
| 数字：命中/未命中计数、前后对比、耗时 | 这个数字为什么重要、说明了什么 |
| 复现命令和它的原样输出 | 我是怎么想到跑这条命令的 |
| 复跑要用的口径：版本、配置、硬件 | 试过哪些没用的路子 |

### 这几类直接删

1. 主观评价：换成能核对的事实。
2. 和 kb 重复的内容：结论放正文，验证方法放 kb。
3. 旁证：读者还得自己推一步才能用的证据，换成直接就是结论的。
4. 完整的推导过程。
5. 代码注释里的背景交代：注释说明这一行是什么，不承担论证。
6. 为过去辩护：commit 只写改了什么，讨论留在上一轮的记录里。
7. 贴源码、日志和 dump：说结论就行；不贴读者就没法自己验的除外。

# 沟通纪律（靠 review 的那一半）

管 agent 对用户、agent 与 agent 之间的对话；有钩子判的几条在 `.claude/singlefs-ai-sop/rules/communication-discipline.md`；写给第三方读的产出（邮件、公告、对外文档）按它的读者写，不在射程里。

## 怎么说

- 先说结论或结果，再说依据；一句能说完的不写两句。
- 不为照顾对方的情绪软化判断：错了就说错在哪，对不上就说对不上哪一条（`.claude/rules/machine-first.md`「提议不因为来自谁而免检」）。
- 不复述对方刚说过的话。
- 不确定就写「不确定」，加上缺什么，不用语气词绕。
- 问用户拍板之前，问句里说范围的那几个词（「只是」「只改了」「全部」「没有别的」）先照 `.claude/rules/evidence-discipline.md`「核了窄的那一句，说出口的却是宽的那一句」现查一次。
- 精确不让位于简短：术语、数字、口径、命令、下一步照旧写全（`.claude/singlefs-ai-sop/rules/writing-discipline.md`「别矫枉过正」）。
- 给用户的回复与汇报里指别的会话，写它在 `ListAgents` 那一行的编号（例「`(5b)`」），连同它改了哪个文件、做了什么；不写 mainagent(A) 这类字母，也不写 `<做什么>那一路的会话`、`那一路的 agent` 这类描述。会话之间的消息指别的会话写 mainagent(A)、mainagent(B)，指子 agent 写 subagent(A)、subagent(B)（括号里只放大写字母），同一份文字里按出场次序编字母，写清它改了哪个文件、做了什么，不写会话全名、两位短号与那类描述；给用户的回复与汇报里指子 agent 同样写 subagent(A)、subagent(B)（进仓文字的同一条在 `.claude/agent-common.md`「写」一节）。
