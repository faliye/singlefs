# 项目 subagent 的共用约束

`.claude/agents/` 下每个定义开工前先读这一份；与定义冲突时以定义为准。
共用约束与各份定义只写怎么做：步骤、约束、判据、交付。「为什么」「实测」「经过」与带日期的记录写进 `records/2026-10-29-subagent拆分提案.md` 或 `.claude/kb/`，共用约束与定义里不写、也不留解释的尾巴；要用到那些内容时写成一条读取指令（「开工先读：`文件`「小节」」）。上游门禁的「规则纪律（项目本地）」阶段判这一条（规则：`.claude/rules/implementation-workflow.md`「改 agent 定义与共用约束，走同一条三步」）。

## 派发

- **简单任务不派发，自己直接改**，例如修改一下、查询一下、计划一下等，任务单一流程简单的任务。
- **派发任务要规划，尽量同类任务一起做，最大程度避免串行**。
- 只由主 agent 点名派发；你手里没有 Agent 工具，不派 subagent，也不从 Bash 里起 `claude` 会话（执行前拒，「执行前拒绝的写法」⑬）。
- 轮名、产出文件路径、草稿目录、这一轮的禁读清单都由主 agent 在派发提示里给。定义里写的路径只是形态（`<轮>`），不是实际路径。
- 输入缺一样就不开工，回复只写缺什么。
- **严格遵守文档中model和effort的设定**。
- **所有派发的subagent的effort不超过high**。如果需要超过那么弹窗告知。
- **任务连续三次派发失败，主agent自己做**。

## 规则怎么读

`.claude/agents/` 下的定义都开了 `omitClaudeMd`：项目 CLAUDE.md、它 `@` 的规则、用户级 CLAUDE.md 与主 agent 的私有记忆都不进你的上下文。

- 规则类文件（`.claude/rules/` 与 `.claude/singlefs-ai-sop/rules/` 下的 `.md`）一律整份读，不受读入大小的限制：定义「开工先读：」一行点名的是其中几个小节时，照样读全那份文件，点名的小节是这件活要照做的那几条。
- 「开工先读：」一行点名的别的文件，只读点名的那几个小节：先 `grep -n '^#' 文件` 找到小节的起止行，再按行读。点的是整份文件的，先看它的节标题，挑与这件活有关的节读。
  不整份读。
- 每个定义都照守、不再写进各自「开工先读：」一行的三处：跑命令照 `.claude/singlefs-ai-sop/rules/command-safety.md`「退不回去的操作，动手前先想一遍」「`pkill -f` / `killall` 一律禁用」两节；
  给人看的文字照 `.claude/singlefs-ai-sop/rules/writing-discipline.md`「文风要简单自然」一节；说外部状态之前现查（`.claude/singlefs-ai-sop/rules/verify-before-claiming.md` 开头一节）。
- 报告与进度记录里的时间只写日期，不写时刻，也不写时区（门禁 doc-text 的 clock-times 格判，Write / Edit 由 `.claude/hooks/write-guard.sh` 当场拒）；日期用 `TZ=Asia/Tokyo date +%F` 取，不用裸 `date`。
- 候选、臂、方案、判据、提问编号有了变体，起一个新名字（那一族里下一个没用过的号，或一个短的描述性名字），不在原名后面加撇号类角标（U+2032、U+2033、U+2034、U+02B9、U+02BA）；全仓由门禁 doc-text 的 prime-marks 格判，写法见 `.claude/rules/path-moves.md`「变体起新名字，不用角标」。
- 派发提示里没给、定义里也没写的项目事实（某份 kb 在哪、某条决策的原文），去仓里现查，不凭印象补。
- **找不到历史实验的数据、提示或产物，去 `git log` 里看。** 早于本轮的实验记录不留在工作区：
  这一轮提交之后由下一次提交删掉上一次那批，本轮的留着（门禁 doc-experiments 的 archive-past-rounds 格判这一条）。
  只写文件名、不写路径的引用当已归档的东西去查，不当坏链接。
  查法：`git log --all --diff-filter=D --name-only -- "*<文件名>*"` 找到删它的那次提交，
  `git show <提交>^:<路径>` 读当时的内容。**读到的是当时的数，不是结论**——
  拿它支撑新结论之前先重新跑一遍（`.claude/singlefs-ai-sop/rules/kb-discipline.md`「2. 每条带出处与状态」一节里「所有旧数据都只是参考」那一条）；
  要推翻早先的结论，按 `.claude/rules/three-way-inference.md` 重走一轮，不是拿旧文件对质。

## 写

- **不新建判定库**（核心策略，没有例外）：全仓只有一份判定库——prune-server 自己的那份 RocksDB（`.claude/rules/verification.md`「判定库只有一份」，判定库的内容、一族「接完」的三件与中转库都在那一节）。写测试、门禁、入口脚本、实验装置时，判定一律经 prune-server 的客户端写进那一份、按各族的键前缀；不许另开目录、TSV、sqlite 或另一份 RocksDB 存判定；并回即删的中转库与对临时服务起的自证库不算；自证与压测不写真服务；各族都只走服务，再写旧库算违例。改动里出现新的判定存放处，主 agent 打回。
- **所有任务都要多机可用，不许绑定某一台**（核心策略，没有例外；`.claude/rules/verification.md`「所有任务都要多机可用」）：没有一个任务是必须绑在一台机器上的。写测试、自证、门禁、入口脚本、实验装置、服务的控制命令时，派到两台里任何一台都要跑得起、判得对，判出来的结果两台都读得到（判定进那一份库，运行记录与产物放多机配置 `NFS_SHARED_ROOTS` 点名的共享根（两台同一绝对路径，不经 `~` 与 `$HOME` 取：第二台的家目录是另一个））；不读会改变判定结局的本机独有状态（许读的只有多机配置与 `~/.config/singlefs/` 下的私有名单与密钥）、不写死主机名与地址，环境只从多机配置 `multi-host.env` 读（没写就是没有，不补缺省）；一条测试自己的配置文件进仓或放共享根。派到某一台就红的是缺陷，当场修，不往统一任务服务里加只派一台的名单。

- 只写派发提示与定义「写范围」一节给的路径。写范围闸（项目 settings 里的 hook，表在 `.claude/hooks/agent-write-scope.tsv`）管 Write / Edit：目标不在表里你那几行模式内的，当场拒掉；Bash 里认得出目标的写（`scripts/kb/replace-once.py`、`replace-batch.py`、`insert-row.py` 的目标文件，`sed -i`、`tee`、`>`、`>>`、`cp`、`mv` 与 python 写文件）由 `.claude/hooks/bash-command-detector.sh` 照同一张表在执行前拒；目标的最终落点这一刻算不出的（命令替换、没赋过值或来源不明的变量、`while read` 与 `for f in $列表` 的循环变量、通配）同样执行前拒：备份原文件用 `python3 scripts/agents/copy-originals.py copy <草稿目录> <文件>…`，按文件写多份输出写成 `for 名字 in 写死的词` 或逐条写字面路径。被拒之后不换 Bash 或别的办法写过去，写进报告交回主 agent。没有项目定义的 agent（内置类型、定义已删的旧实例）两道都只许写工作根，落在仓里与仓外别处都拒。会话临时目录根 `/tmp/claude-<uid>/`（Claude Code 给各会话的临时目录与 scratchpad 都在它底下）不在任何子 agent 的写范围里：Write / Edit 写进去由写闸拒，没有项目定义的 agent 在 Bash 里写进去由检出钩子拒；草稿与报告写派发提示给的草稿目录。命令词由变量、命令替换拼出的（`$c`、`eval "$c"`）由项目代码闸照「认不出起什么的写法」拒，写成字面命令；钩子判不到的写法（`eval "$c"` 这种代码在变量里的、脚本文件里的写法、python / perl / ruby / tclsh 起的脚本文件里起的）全靠你守；`python3 -c` 与喂给 python 的字面代码这类命令行上写着的别的程序代码里起的命令（`os.system`、`subprocess` 这类），项目代码闸照命令判，写法认不出的照拒（怎样算认得出照「执行前拒绝的写法」一条里项目代码闸那一项）；`eval` 的字面代码照判，`xargs`、`find -exec`、`parallel` 接进来的落点照算不出拒，改成逐个写字面路径；定点写脚本的路径放在前面赋过值的变量里的，钩子照代入再认。
- tools 里有 Write / Edit 的：手写的改动一律用 Edit（旧串必须在文件里恰好命中一次，与 `replace-once.py` 同义；这一轮自己新建的文件可以 `replace_all`），新建文件用 Write（先 `ls` 确认不存在）；tools 里只有 Edit、没有 Write 的，新建文件照下一条「tools 里没有 Write」那样排他写；除了这种排他新建，Bash 里只许定义点名的写入工具自己写（`relabel-item.py`、`kb-scribe` 的 `replace-batch.py` 这类，「不做」一节「子 agent 不交任务」那一条许直接跑的），不用 python / sed 就地改仓内文件（执行前被拒，见「执行前拒绝的写法」⑧）。草稿目录里（仓副本、日志、自己的辅助脚本）用什么写都行。
- tools 里没有 Write 的（只有 Read / Bash、只有 Read / Edit / Bash，或另带 WebFetch、WebSearch 这类不写文件的工具）：新建文件一律排他，`set -o noclobber` 后 `cat > 文件 <<'EOF'`，文件已存在就停下报告；之后 `>>` 追加。
- 报告分段写，每一次写进文件的内容不超过 150 行（`.claude/rules/three-way-inference.md`「云端腿的报告要分段落盘」）；表格与代码块整块放进同一段，不从中间切。
- tools 里没有 Write、Edit 的，改已有文件只用定点替换：`scripts/kb/replace-once.py` 或 `scripts/kb/replace-batch.py`（先 `--dry-run`），不整份重写。
- 草稿放派发提示给的草稿目录，不放会话临时目录根 `/tmp/claude-<uid>/` 底下；用不上可以空着。
- tools 里有 Write / Edit 的，开工先认锁：派发提示里「草稿目录：」点名的目录，派发闸在里面建了写者锁（`.writer-lock`），你往这个目录的第一次 Write / Edit 由写闸认持锁者：主会话记录里找得到你的派发回执的，回执里的提示与时刻对得上锁才认你，对不上的拒，拒绝说明点名持锁者；回执还找不到的，先到先得，第一个写进这个目录的子 agent 是持锁者。被拒、拒绝说明点名了别的持锁者的，这个目录归那个子 agent：停下，已有的与没写完的写进报告交回主 agent，不换 Bash 或别的路径写进去（Bash 里的写闸看不见，同样不许写进别人持锁的目录）。子目录另派给别的子 agent 之后，父目录的持锁者不写那个子目录。
- 建仓副本或编译目录之前，先 `du -sh` 列出自己草稿目录下已有的副本与编译目录，用完的先删；仓副本只用 `python3 scripts/hosts/minimal-copy.py <仓根> <副本> --with-test-inputs` 建（直接跑、不经服务；拷哪些由它按闭包现算：path 依赖、编译期与运行期读的仓根文件、测试输入，算法在 `scripts/hosts/lib_repository_copy.py` 文件头），要门禁表的加 `--with-gate-tables`，要主 agent 在副本里交带 `--item` 的门禁与崩溃点重放入口、起仓里脚本的，逐条加 `--with scripts=<为什么>`、`--with .claude/scripts=<为什么>`、`--with .claude/singlefs-ai-sop=<为什么>`；不自己 `rsync`、`cp` 拷 `crates/` 与仓根条目，不手列清单；它拒了（闭包算不成、超阈值）照它的出路办。
- 副本、编译目录与运行目录里的中转库（并回服务那一份之后就该删的中转目录）用完就删，不留给以后的趟或别的任务复用：交回之前删掉自己认领、自己建的那几份（删之前 `du -sh` 记大小写进报告），完工清理闸判（「执行前拒绝的写法」那一条）。经服务跑的任务，编译目录由服务给，交任务的主 agent 用完 `task-server/task clean <号>` 删，谁都不自己 `rm`。要交给主 agent 接着用的副本（主 agent 照你报告里「要主 agent 跑的命令」在里面跑），在它所在那个认领目录的 `.deliverables` 里写一行「<相对路径> 交接 <主 agent 在里面跑什么>」；报告、补丁、打补丁前的备份照同一份文件写，写法在 `.claude/hooks/completion-cleanup-guard.sh` 文件头「要留的交付物」。
- 名字、注释、文档、输出文字都不用序数或位置代称，也不用缩写与「a / b / c」这类略列：不写 `layer0`、`stream_0`、`first_stream`、「层 0」「第一条流」「第一项」，写它是什么、做什么（`enumerate_crash_states`、「崩溃点重放」「新池新建文件流」「录入段」）；所有语言、所有文本一样。登记过的改名在 `.claude/kb/term-renames.md`，别处一律用新名。
- 在一份文件里新加函数、类、方法或 shell 函数之前，先在同一份文件里按这个名字搜一遍（`grep -nE '(def|class) <名>\b|^<名>\(\)|function <名>\b' <文件>`）；同一作用域里已经有这个名字的，换一个说出内容的名字，或者改用已有的那一个，不再定义第二份。
- 进仓的文字不写会话名与批次代号：会话不写全名（`singlefs-<两位>`），非写不可写两位短号，或写「别的会话」「<做什么>那一路的会话」；批次不写字母代号（`5a`、`9g`、`5g-rs`、`24c-1`、`SC02`），写那一批做了什么；调度记录依赖表的「第 N 批」批号照留。
- **里程碑 17 收尾之前不兼容任何旧东西，代码与格式尤其如此**：格式锁定之前没有旧盘、旧库、旧产物要认，旧逻辑一律不做特殊处理；不写、不留兼容旧代码、旧格式、旧字段、旧布局、旧写法的东西——认旧版本的分支、为旧镜像或旧库单开的拒绝分支与错误种类、旧布局号与旧版本号常量、迁移脚本与补旧行的子命令、只为旧行放宽的读法（`legacy_ok` 这类）、「新码接在最后、旧码不动」这类只为旧数据留的编号约束，以及造旧形态输入的测试与它们的变异行。格式、布局、编号、表的列改了，读者只认这一版：不是这一版的一律走同一条「认不得」的拒绝，出路写重建、换新目录或重跑，不按旧版本分别认、分别报；旧库、旧镜像、旧产物不迁移。`research/` 下的内容是当时的记录，豁免，不为这一条改，门禁与脚本里只为读它留的放宽照留。改的文件里碰到的兼容代码连同它的测试与变异行一并删掉；不在自己写范围里的，写进报告交回主 agent。
- **代码与脚本的注释、说明只写现状，不写历史**：管 `crates/`、`scripts/`、`task-server/`、`prune-server/`、`.claude/hooks/`、`.claude/gate.d/`、`.claude/scripts/` 下的注释（`//`、`///`、`//!`、`/* */`、`#`）、Python 文档串、脚本文件头（用法、判法、弄坏开关说明、退出码表）与这几处的 `README.md`；门禁样本目录 `.claude/gate.d/fixtures/`、上游副本 `.claude/singlefs-ai-sop/` 不管，kb、规则与定义、`records/`、`research/` 各有自己的规矩。只写这段代码此刻是什么、做什么、为什么非这样不可；不写日期（「用户 2026-10-26 定」）、谁定的与哪一轮打中的（「用户弹窗定案」「第二轮攻方腿」「三轮判决第三节」、批号）、改动经过（「此前」「原先」「起初」「最初」「后来改成」「改成了」「换成了」「修过」）、旧值与旧做法（「原为 148」「以前只认 --bin」）、弄坏开关说明里的「改前的样子」（写开关弄坏了什么、打开后哪一项该红）。要指依据，写现行登记位的编号与名字（决策分项、欠账号、不变量号、规则文件与小节标题）。判据：这句话放到这段代码第一次写下的那天去读还是真话，就是现状；「放回原来的值」「后来的写被拒」说的是运行时的先后，照写。历史的落点：改了什么、怎么证的红进 commit message；决策与实验的变更进 `.claude/kb/decisions-history.md`、`.claude/kb/experiments-history.md`；一轮的经过、量到的数与用户原话进 `records/`；三方打中了什么进 `research/prompts/<轮>-main-verification.md`。特殊缘由只三类：日期本身是数据（日期格式的说明与例子、测试输入里的日期、解析历史条目的代码讲它认的形态）、引外部文档或源码写读到它的那一天、绕开外部工具缺陷写从哪个版本起与修好后删哪一段；那一行的注释里写 `history-kept: <理由>`，理由至少 8 个字；「留着方便查来历」不算。路径与文件名里的日期是名字，照写。改存量照命中逐行改写，不整段删 `///` 或 `// SAFETY:`（`.claude/singlefs-ai-sop/scripts/comment-only-change.py` 把整段增删算改代码）。门禁 doc-text 的 `comment-history` 格全仓判，存量在只缩不涨的 `.claude/gate.d/comment-history-lag.tsv`，改净一个文件就删它那一行，新写的不许往里加。

## 报告

- 交回与报告在不影响正确性的前提下写简练：写结论、依据与没做什么，不写做事的经过、不复述派发提示与定义；下面几条要求的命令与原样输出、行号、推翻条件照样给，嫌长就放进报告文件、交回里指过去。
- 引规则与 kb 的条款优先写 `文件@小节标题`（标题逐字、不带井号，原文整行抄；`scripts/agents/cite-check.py` 认这种写法），不为一个行号再读一遍文件；引脚本、代码、产物写那份文件自己的行号，行号去原文件里现查，不从背景材料里数；没现查过的行号不写进报告，先写「行号待查」；行号用 `grep -n` 或 `awk 'NR==行号'` 现取，不从 `sed -n 'A,Bp'` 的输出里数偏移；贴的命令输出必须是这一次真跑出来的原样；引原文整行抄，不许摘句。
- 能用命令核的事实，贴命令与原样输出；输出不截断，嫌长先数。报告里的条数、阶段数、命中数用命令数出来，不手数。
- 报告里转述的数每个都标「量的」或「推的」，并写明是哪个量（哪个文件、哪份产物、源文件还是编出来的二进制）；收到的数没标的按「推的」办（`.claude/singlefs-ai-sop/rules/evidence-discipline.md`「进结论的每个数，先问它是量的还是拍的」）。
- 说「没有」「只有」「全仓」之前，把话缩到真核过的那个范围：核的是一个文件就只说这个文件（`.claude/singlefs-ai-sop/rules/verify-before-claiming.md`「核了窄的那一句，说出口的却是宽的那一句」）。
