# 项目 subagent 的共用约束

`.claude/agents/` 下每个定义开工前先读这一份；与定义冲突时以定义为准。
共用约束与各份定义只写怎么做：步骤、约束、判据、交付。「为什么」「实测」「经过」与带日期的记录写进 `records/2026-10-23-subagent拆分提案.md` 或 `.claude/kb/`，共用约束与定义里不写、也不留解释的尾巴；要用到那些内容时写成一条读取指令（「开工先读：`文件`「小节」」）。上游门禁的「规则纪律（项目本地）」阶段判这一条（规则：`.claude/rules/implementation-workflow.md`「改 agent 定义与共用约束，走同一条三步」）。

## 派发

- **简单任务不派发，自己直接改**，例如修改一下、查询一下、计划一下等，任务单一流程简单的任务。
- **派发任务要规划，尽量同类任务一起做，最大程度避免串行**。
- 只由主 agent 点名派发；你手里没有 Agent 工具，不派 subagent，也不从 Bash 里起 `claude` 会话（执行前拒，「执行前拒绝的写法」⑬）。
- 轮名、产出文件路径、草稿目录、这一轮的禁读清单都由主 agent 在派发提示里给。定义里写的路径只是形态（`<轮>`），不是实际路径。
- 输入缺一样就不开工，回复只写缺什么。
- **严格遵守文档中model和effort的设定**。
- **所有派发的subagent的effort不超过high**。如果需要超过那么弹窗告知。
- **任务连续三次派发失败，主agent自己做**。

## 规则怎么读

`.claude/agents/` 下的定义都开了 `omitClaudeMd`：项目 CLAUDE.md、它 `@` 的规则、用户级 CLAUDE.md 与主 agent 的私有记忆都不进你的上下文。

- 规则类文件（`.claude/rules/` 与 `.claude/singlefs-ai-sop/rules/` 下的 `.md`）一律整份读，不受读入大小的限制：定义「开工先读：」一行点名的是其中几个小节时，照样读全那份文件，点名的小节是这件活要照做的那几条。
- 「开工先读：」一行点名的别的文件，只读点名的那几个小节：先 `grep -n '^#' 文件` 找到小节的起止行，再按行读。点的是整份文件的，先看它的节标题，挑与这件活有关的节读。
  不整份读。
- 每个定义都照守、不再写进各自「开工先读：」一行的三处：跑命令照 `.claude/singlefs-ai-sop/rules/command-safety.md`「退不回去的操作，动手前先想一遍」「`pkill -f` / `killall` 一律禁用」两节；
  给人看的文字照 `.claude/singlefs-ai-sop/rules/writing-discipline.md`「文风要简单自然」一节；说外部状态之前现查（`.claude/singlefs-ai-sop/rules/verify-before-claiming.md` 开头一节）。
- 报告与进度记录里的时间只写日期，不写时刻，也不写时区（门禁 doc-text 的 clock-times 格判，Write / Edit 由 `.claude/hooks/write-guard.sh` 当场拒）；日期用 `TZ=Asia/Tokyo date +%F` 取，不用裸 `date`。
- 候选、臂、方案、判据、提问编号有了变体，起一个新名字（那一族里下一个没用过的号，或一个短的描述性名字），不在原名后面加撇号类角标（U+2032、U+2033、U+2034、U+02B9、U+02BA）；全仓由门禁 doc-text 的 prime-marks 格判，写法见 `.claude/rules/path-moves.md`「变体起新名字，不用角标」。
- 派发提示里没给、定义里也没写的项目事实（某份 kb 在哪、某条决策的原文），去仓里现查，不凭印象补。
- **找不到历史实验的数据、提示或产物，去 `git log` 里看。** 早于本轮的实验记录不留在工作区：
  这一轮提交之后由下一次提交删掉上一次那批，本轮的留着（门禁 doc-experiments 的 archive-past-rounds 格判这一条）。
  只写文件名、不写路径的引用当已归档的东西去查，不当坏链接。
  查法：`git log --all --diff-filter=D --name-only -- "*<文件名>*"` 找到删它的那次提交，
  `git show <提交>^:<路径>` 读当时的内容。**读到的是当时的数，不是结论**——
  拿它支撑新结论之前先重新跑一遍（`.claude/singlefs-ai-sop/rules/kb-discipline.md`「2. 每条带出处与状态」一节里「所有旧数据都只是参考」那一条）；
  要推翻早先的结论，按 `.claude/rules/three-way-inference.md` 重走一轮，不是拿旧文件对质。

## 写

- 只写派发提示与定义「写范围」一节给的路径。写范围闸（项目 settings 里的 hook，表在 `.claude/hooks/agent-write-scope.tsv`）管 Write / Edit：目标不在表里你那几行模式内的，当场拒掉；Bash 里认得出目标的写（`scripts/kb/replace-once.py`、`replace-batch.py`、`insert-row.py` 的目标文件，`sed -i`、`tee`、`>`、`>>`、`cp`、`mv` 与 python 写文件）由 `.claude/hooks/bash-command-detector.sh` 照同一张表在执行前拒；目标的最终落点这一刻算不出的（命令替换、没赋过值或来源不明的变量、`while read` 与 `for f in $列表` 的循环变量、通配）同样执行前拒：备份原文件用 `python3 scripts/agents/copy-originals.py copy <草稿目录> <文件>…`，按文件写多份输出写成 `for 名字 in 写死的词` 或逐条写字面路径。被拒之后不换 Bash 或别的办法写过去，写进报告交回主 agent。没有项目定义的 agent（内置类型、定义已删的旧实例）两道都只许写工作根，落在仓里与仓外别处都拒。钩子判不到的写法（变量里拼出来的命令、eval、脚本文件里的写法）全靠你守；定点写脚本的路径放在前面赋过值的变量里的，钩子照代入再认。
- tools 里有 Write / Edit 的：手写的改动一律用 Edit（旧串必须在文件里恰好命中一次，与 `replace-once.py` 同义；这一轮自己新建的文件可以 `replace_all`），新建文件用 Write（先 `ls` 确认不存在）；tools 里只有 Edit、没有 Write 的，新建文件照下一条「tools 里没有 Write」那样排他写；除了这种排他新建，Bash 里只许定义点名的脚本自己写（`relabel-item.py`、`kb-scribe` 的 `replace-batch.py`、门禁阶段的 `--write`、`mutate.sh`、`replay.sh`、cargo、跑产物的重定向），不用 python / sed 就地改仓内文件（执行前被拒，见「执行前拒绝的写法」⑧）。草稿目录里（仓副本、日志、自己的辅助脚本）用什么写都行。
- tools 里没有 Write 的（只有 Read / Bash、只有 Read / Edit / Bash，或另带 WebFetch、WebSearch 这类不写文件的工具）：新建文件一律排他，`set -o noclobber` 后 `cat > 文件 <<'EOF'`，文件已存在就停下报告；之后 `>>` 追加。
- 报告分段写，每一次写进文件的内容不超过 150 行（`.claude/rules/three-way-inference.md`「云端腿的报告要分段落盘」）；表格与代码块整块放进同一段，不从中间切。
- tools 里没有 Write、Edit 的，改已有文件只用定点替换：`scripts/kb/replace-once.py` 或 `scripts/kb/replace-batch.py`（先 `--dry-run`），不整份重写。
- 草稿放派发提示给的草稿目录，不放会话共用的暂存目录；用不上可以空着。
- tools 里有 Write / Edit 的，开工先认锁：派发提示里「草稿目录：」点名的目录，派发闸在里面建了写者锁（`.writer-lock`），你往这个目录的第一次 Write / Edit 由写闸认持锁者：主会话记录里找得到你的派发回执的，回执里的提示与时刻对得上锁才认你，对不上的拒，拒绝说明点名持锁者；回执还找不到的，先到先得，第一个写进这个目录的子 agent 是持锁者。被拒、拒绝说明点名了别的持锁者的，这个目录归那个子 agent：停下，已有的与没写完的写进报告交回主 agent，不换 Bash 或别的路径写进去（Bash 里的写闸看不见，同样不许写进别人持锁的目录）。子目录另派给别的子 agent 之后，父目录的持锁者不写那个子目录。
- 建仓副本或编译目录之前，先 `du -sh` 列出自己草稿目录下已有的副本与编译目录，用完的先删；副本只拷要编的（`crates/`、`Cargo.toml`、`Cargo.lock`、`.cargo`、`.claude/heavy-thread-default`，要门禁表的再加 `.claude/gate.d`），不拷 `research/`、`target` 这类大目录。
- 副本、编译目录与运行目录里的库拷贝用完就删，不留给以后的趟或别的任务复用：交回之前删掉自己认领、自己建的那几份（删之前 `du -sh` 记大小写进报告），完工清理闸判（「执行前拒绝的写法」那一条）。要交给主 agent 接着用的副本（主 agent 照你报告里「要主 agent 跑的命令」在里面跑），在它所在那个认领目录的 `.deliverables` 里写一行「<相对路径> 交接 <主 agent 在里面跑什么>」；报告、补丁、打补丁前的备份照同一份文件写，写法在 `.claude/hooks/completion-cleanup-guard.sh` 文件头「要留的交付物」。
- 名字、注释、文档、输出文字都不用序数或位置代称，也不用缩写与「a / b / c」这类略列：不写 `layer0`、`stream_0`、`first_stream`、「层 0」「第一条流」「第一项」，写它是什么、做什么（`enumerate_crash_states`、「崩溃点重放」「新池新建文件流」「录入段」）；所有语言、所有文本一样。登记过的改名在 `.claude/kb/term-renames.md`，别处一律用新名。
- 私有主机信息不进仓：本机的主机名与服务名，第二台的主机名与别名、IP、第二台上的路径，两台的服务单元名，清场脚本的内容，不写进 kb、records、research、规则、定义、代码注释与 commit message；进仓的文字写「本机」「第二台」，真实值只在仓根被 git 忽略的 `multi-host.env` 与 `~/.config/singlefs/` 里。贴原样输出、整行抄原话、冻结证据里遇到私有值的，把那个值换成「第二台」「本机」这类说法（写成 `〔本机主机名〕`、`〔第二台的主机名〕`），同一行注明换掉了什么；这一条优先于「贴原样输出」「整行抄」「证据不许事后改」。门禁 doc-text 的 `private-values` 格判新加的行。
- **进仓的文字只写本项目的东西**：记录、kb、判决、注释、commit message 不写本机与第二台上不归本项目的目录名、路径、别的工程与它们的占用；要说空间只说本项目自己的目录与总的可用量，别的写「其余不归 singlefs」。门禁 doc-text 的 `out-of-project-names` 格判新加的行（singlefs 自己的脚本读的仓外路径登记在 `.claude/out-of-project-paths`，只放行那条路径本身）。

## 不做

- 不做 git 写操作（`add`、`commit`、`stash`、`checkout`、`restore`、`reset`、`worktree`……），不提交，不推送。
- 不建、不改 `.claude/agents/`、`.claude/settings*.json`、`.claude/hooks/`、`.claude/rules/`、`.claude/singlefs-ai-sop/`，也不碰 `~/.claude/`。`tooling-writer` 例外：按它定义「写范围」一节改 `.claude/agents/`、`.claude/hooks/`、`.claude/rules/` 与 `.claude/settings.json` 的 `hooks` 一节；`.claude/singlefs-ai-sop/` 与 `~/.claude/` 它同样不碰。
- 不读派发提示给的禁读清单里的文件。
- 不编译 Rust、不跑 `gate.sh` 全量，除非定义明写要做。跑脚本、跑模型一律加 `nice -n 19`。

跑什么=…; 范围=…; 为什么=…'`，写法照 `.claude/hooks/run-scope-guard.sh` 文件头，没带的被它拒；跑法、谁跑、带 GPU 的怎么起在 `.claude/rules/verification.md`「两档：轻型与重型」），崩溃与变异两条不起，命令写进报告「要主 agent 跑的命令」一节，三条不带 `--quick` 的跑法是重型；harness 档照跑：自己动到的 `singlefs-harness` 与别的非 checker 档包的测试二进制（`SINGLEFS_RUN_SCOPE='种类=target; - 写进脚本文件、放进 `python3` 的 subprocess、`make` 这类间接起法同样算跑：自己写的验证链里不许出现重型测试的任何一步，checker 档包 `singlefs-checker-tier` 的测试二进制也不许。

## 门禁

- 扫仓的门禁阶段（本地与共享）与提交前的整轮门禁归主 agent，只在提交前由它照 `.claude/skills/gate/staged-gate.md` 跑的 `scripts/gate/gate-staged.sh`（它起的整轮 `gate.sh`）判，提交时的六道重阶段由它照 `.claude/skills/crash-test/commit-stages.md` 跑；子 agent 交回前不跑门禁阶段与各类 lint（gate-lint、shell-lint、preflight-lint、gate-overlap、doc-lint、rules-lint、hooks-registered；命名检查除外，见「命名检查交回前跑」）；脚本与钩子的 `--selftest` 和门禁样本档，`.claude/hooks/selftest-registry.tsv` 登记为 light 的，照钩子拒绝说明里写的起法改了谁就跑谁到绿；登记为 heavy 的、登记为 heavy-if-set 而命令里设了那个变量的、没登记的，归提交前，写明命令交主 agent；语法检查（`bash -n`、`python3 -m py_compile`）照做。
- **命名检查交回前跑**：改了代码或实验源码（`crates/`、`scripts/` 下的 `.rs`）的子 agent（`implementation-writer`、`experiment-runner`、`tooling-writer`）交回前，在主工作区（写仓根）或 git worktree 建的副本（写副本根）上跑两条：`SINGLEFS_RUN_SCOPE='种类=items; 跑什么=门禁 code-source-discipline.sh 的 vague-names、test-file-names、ordinal-names、data-names 四格; 范围=4 格; 为什么=交回前核自己改动里的命名' bash .claude/gate.d/code-source-discipline.sh --check vague-names,test-file-names,ordinal-names,data-names <根>` 与 `bash .claude/singlefs-ai-sop/scripts/naming-lint.sh <根>`（范围声明的写法照 `.claude/hooks/run-scope-guard.sh` 文件头）。在 rsync 拷的副本里改的，不在副本上跑：两条命令（`<根>` 填仓根）写进报告「要主 agent 跑的命令」一节，由主 agent 在补丁打进主工作区之后跑。只修命中在自己改动的文件里的；命中在别的文件里的，照「红了先看它点名的文件与行在不在这一轮的改动里」办。输出不重定向到 `.log`（`.claude/hooks/two-logs-guard.sh` 拒）；要落盘照「不做」一节读文件那一条的写法 `<命令> > <草稿目录>/<名>.txt 2>&1; echo rc=$?; tail -n 20 <草稿目录>/<名>.txt`，或经 `bash scripts/hosts/two-logs.sh <名> -- <命令>`；接管道（`| tail`、`| head`、`| grep`）、`|| true`、后面用 `;` 接别的命令而没紧跟 `echo rc=$?` 的，交回闸认不出它自己的退出码，不算跑过。跑了的，两条的命令与末尾原样输出贴进报告。
- 退出码 77 是「本次未跑」，不是通过。贴绿行时连它报的「查了多少项」一起贴；报「查了 0 项」或根本没报数的，按没判写。红了先看它点名的文件与行在不在这一轮的改动里；不在的不修，照写。

## 报告

- 交回与报告在不影响正确性的前提下写简练：写结论、依据与没做什么，不写做事的经过、不复述派发提示与定义；下面几条要求的命令与原样输出、行号、推翻条件照样给，嫌长就放进报告文件、交回里指过去。
- 引规则与 kb 的条款优先写 `文件@小节标题`（标题逐字、不带井号，原文整行抄；`scripts/agents/cite-check.py` 认这种写法），不为一个行号再读一遍文件；引脚本、代码、产物写那份文件自己的行号，行号去原文件里现查，不从背景材料里数；没现查过的行号不写进报告，先写「行号待查」；行号用 `grep -n` 或 `awk 'NR==行号'` 现取，不从 `sed -n 'A,Bp'` 的输出里数偏移；贴的命令输出必须是这一次真跑出来的原样；引原文整行抄，不许摘句。
- 能用命令核的事实，贴命令与原样输出；输出不截断，嫌长先数。报告里的条数、阶段数、命中数用命令数出来，不手数。
- 结论写「什么现象会推翻它」。
- 报告末尾有「没做什么」一节：跑不动的、没验的、按定义不归你的，照实列。
- 跑出来的产物先落盘进仓里该在的位置（实验产物与重跑日志进 `research/results/`，报告、提示与判决进 `research/prompts/`），再往下做。停机条款没过、按定义不写实验页、或者主 agent 还没定要不要留的，也要把草稿产物连同「为什么没入库」写进报告——它在哪个仓外路径（`~/.local/share/singlefs/work/` 或 `/tmp` 下）、跑了什么、为什么不入库。门禁 doc-experiments 的 evidence-in-repo 格判这一条的形式：装置或变异表改了而 `research/results/` 里没有一份不比它旧的产物、kb 与这一轮新写的提示里把 `/tmp` 路径当依据引用，都红。
- 定义点名的产出文件（跑前登记、腿的 output、样本、运行记录、实验页、代码与 kb 的改动）照定义写进文件。三方论证的云端腿，报告就是派发提示给的 `research/prompts/<轮>-*-output.md`：用 Bash 分段写进去，交回内容只写文件路径、`sha256sum` 与判定一览（照 `.claude/rules/three-way-inference.md`「云端腿的报告要分段落盘」办）。其余定义的「报告」全文写进报告文件：派发提示给了报告路径的写那里，没给的写草稿目录的 `result.md`（用 Bash 时 `set -o noclobber` 排他新建，之后 `>>` 分段追加）；交回只写结论、报告路径与 `sha256sum`，不超过 4000 字（交回正文闸拒超长的），主 agent 按路径存档。交回只调一次（第二次会被拒）。报告文件名里不带 report；没有别的形态要求的写 `result.md`，三方腿的报告名是 `research/prompts/<轮>-*-output.md`；子 agent 用 Write 建文件名以 REPORT、SUMMARY、FINDINGS、ANALYSIS 开头（不分大小写）的 `.md`，会被工具层当场拒，Bash 写的不拦。
- 干到一半收到主 agent 的消息：当成追加的输入并进这一轮做，报告里写明在哪一步收到、改了什么；与定义或原输入冲突的，停在那一处交回。
