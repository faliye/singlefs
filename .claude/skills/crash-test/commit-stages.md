# 提交时的六道重阶段：主 agent 照这一份跑

子 agent 不交这几道（`.claude/agent-common.md`「子 agent 不交任务」）。主 agent 跑的是 `.claude/rules/implementation-workflow.md`「三步，缺一步就不算做完」第 3 步与「不指定范围的只在提交时跑，指定范围的随时跑」里提交时跑的这六道门禁（文件是 `.claude/gate.d/<名>.sh`）：`crash-point-replay`（默认快档，`--full` 只在用户要求时）、qemu-device-streams、lkmm、crates-mutation-replay、formal-verification、broad-mutation（连同它前面起的广谱变异驱动，第 2b 步）。
开工先读：`.claude/skills/crash-test/SKILL.md`「判读纪律」；`.claude/rules/verification.md`「崩溃一致性只能靠崩溃点重放验证」「文件系统特有的反推缺口」；`.claude/singlefs-ai-sop/rules/test-discipline.md`「阴性结果要能和「代码没跑到」分开」。

## 跑之前定下来

- 这次改动的范围：`git diff --stat -- crates litmus` 原样，或提交区间。
- 这一次是提交时跑还是用户要求时跑（只在这两种时候跑；交给服务的命令不带 `SINGLEFS_HEAVY_TESTS` 前缀）。
- 门禁 `crash-point-replay` 跑哪一档：默认快档（两趟：`cargo test --release -p singlefs-verification --lib --tests`，再带 `tests/` 里 `cfg` 点到的特性一趟（feature-gated-tests 格），另有 product-gpu-real-card-tests 一格（产品 GPU 包带 `tests-on-a-real-gpu` 的真卡对拍，`--test-threads 1`，服务没交卡判红、测试找不到显卡报「本次未跑」、目标文件头声明的卡比服务交的多的不起、报「本次未跑」并照第 2d 步单交），加逐条核崩溃枚举用例的崩溃状态块（`SINGLEFS_CRASH_CASE_BLOCKS_QUERY=1` 只查库不判：每块在崩溃判定库里有单元键相同、不红的判定才算罩住；登记行第三列写了 `red-blocks=judged-by-test` 的用例照全量起、按 cargo test 退出码判、块那一行只核在不在、数对不对得上；`--full` 对这样的用例同一套判法，库里的红块不判），`.claude/rules/verification.md`），用户不另说就是它；用户要求全量时带 --full，在 HEAD + 暂存区的 worktree 里跑（照门禁 `crash-point-replay` 快档出路里那三行建）；要不读判定库、全部块现判从头跑的，加「--start-over」（现判的照键写回同一份库）。
- 要不要跑崩溃放量全量：只在用户要求「崩溃放量全量」时跑（里程碑收尾、动了崩溃点重放或判器的那一批，D13（验证路线） 已定项 9），在同门禁 `crash-point-replay` `--full` 那一棵 worktree 里跑；只跑几个分项的加 `--item <分项>`。
- 草稿目录。

## 监控行的三栏怎么数

监控行「这一趟 ✓ N ✗ M 本次未跑 K」的 N、M、K 数第 3、4 步抄下来的判定行，不另写 grep：

- 单位是一条判定：阶段汇总里的一格（「<格名>：绿 / 红（退出 N）/ 本次未跑」那一行）、门禁 `crash-point-replay` `--full` 逐条用例行里的一条用例、阶段自己逐项打的一项（一档、一份 litmus、一条变异行）；阶段没有逐项行的，整道阶段数一条，按它的退出码进栏。
- ✓：判定是绿的。`--full` 逐条用例行里「判绿」与「复用」（复用的是库里不红的判定）各数一条。
- ✗：判定是红的。一条判定的「✗」行连同紧跟的「→」数一条；格共用库打的汇总「✗ <阶段>：N 格里 M 格红」不数。
- 本次未跑：退出码 77 的格、项与阶段，报「本次未跑」的用例，加上「作废」（第 4 步：输出里读不到判定行）与「没跑成」（第 3 步：服务判出的结局）。这几种都没判出结果，只进这一栏，不进 ✓，也不进 ✗。
- 监控行里 ✗ 的逐条点名，本次未跑的 K 后面逐条点名是哪一条、属于 77、作废、没跑成里的哪一种。
- 三栏相加要等于这一趟数到的判定条数；对不上就回头重数，对上之前不抄这一行。
