## 五、重复作业：崩溃放量不是「两段」

用户定的形态：第一段 CPU 跑出数据存进 RocksDB；第二段从 RocksDB 取出来判，有 GPU 用 GPU、没有才 CPU；CPU 不许在一段任务里既跑数据又判一致。今天的代码与这条不一致，四处：

| # | 位置 | 事实 |
|---|---|---|
| 18 | `crates/singlefs-checker-tier/src/verdict_store.rs` 文件头的表；`crash_amplification.rs` 的 `record_crash_points_needing`（`store.record_path`、`store.record_block(&key, count)`） | 库里四张表只存判定块、判定向量、违例、恢复字；录入只写块键与状态数，**不存崩溃状态本身**。判的两条路 `check_blocks_where_until`（1649 行）与 `judge_my_blocks_on_gpu_cards`（2965 行）签名都收 `flow` 与 `plan`，状态在判的时候由 CPU 从流重算。所以「CPU 跑数据入库」这一段在实现里不存在，产数据与判定在同一个任务里 |
| 19 | `crash_amplification.rs:7667` `run_from_environment` | 一次调用顺序做完录入、第 ① 段判、第 ② 段事实表核对、对账、导入；环境变量表 `ENVIRONMENT_VARIABLES_READ_BY_A_RUN`（7524 行起）只有 `PLACEMENT_ONLY`，没有「只录」「只判」的开关，脚本层（`scripts/crash/crash-amplification-item.sh`）也就分不了段 |
| 20 | `crash_amplification.rs:7764–7831`、`8090–8129`，`CROSS_CHECK_SKIPPED_BY_THE_USER_ENVIRONMENT_VARIABLE`（9757 行） | 配了 GPU 时，`CrossCheckWanted::Run` 是默认：GPU 判一遍，**CPU 判器在同一趟并行把同一批状态再判一遍**（`check_the_cross_check_blocks_beside_the_library`），再比红项与恢复字；CPU 那一遍里单元校验和又上一张卡与 CPU 对拍（`ComputationRoutes.unit_checksums`）。只有用户当场给 `--cross-check-skipped-by-the-user` 才跳过（`scripts/crash/crash-point-replay.sh:22,68`）。来历是 `research/prompts/m3-crash-enumeration-merge-r3-main-verification.md:51` 的 J6「配了 GPU 时 CPU 判器同一批状态也判，同一趟并行……默认跑」。这是一条已判决的默认值，与用户今天的口径相反，改它要走决策变更，不只是改代码 |
| 21 | `.claude/gate.d/crash-point-replay-items.tsv`；`crates/singlefs-checker-tier/src/crash.rs:1388` | 合表里 7 项同时有第二列（崩溃点重放 `crash-case:`）与第三列（放量分项）：fixed-script-through-the-unmount、floor-raise、sigma、multi-record-publish、unlink-after…、tree-split-streams、position-addressed-trees。崩溃点重放引擎 `crash.rs` 对每个状态就地跑恢复、oracle、`check_pool_image`（全在 CPU、不进库），放量流水线再判同一条流。`crash-point-replay.sh:12` 自己写着「引擎合并之后由引擎那一路换成一套」，但两套今天并存；`test-script-discipline.md`「仓里已经并存两套判同一件事的，先合成一套，再跑它的剪枝跑或全量」 |

要落成用户的两段形态，至少四件事：录入段把状态（或重建它所需的最小输入）写进库；给 `run_from_environment` 加「只录 / 只判」两个入口并让分项驱动分两趟起；J6 的默认值改成「配了 GPU 只 GPU 判，CPU 对照由用户点名才跑」并记进决策变更史；崩溃点重放就地判那一路退役或并进引擎。第 20、21 两条是推论层面的改动，照 `.claude/rules/three-way-inference.md` 走三方再定。
