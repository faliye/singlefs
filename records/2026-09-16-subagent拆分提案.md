## 二、拆分判据

**1. 拆的理由不只是「专注」，更硬的是：好几条规则要求的本来就是隔离。**

| 规则要求 | 今天靠什么 | 拆开之后 |
|---|---|---|
| 三方的三条腿「不许读别的腿这一轮的产出」 | 腿今天已是用 Agent 工具分别派出的 subagent，各有上下文（`.claude/rules/three-way-inference.md` 第 32–33 行）；禁读靠提示里写一句 | 上下文同今天；读文件仍要靠定义禁止 |
| 实验的判据跑前写死，设计时不许参考已有结论（`test-discipline.md`） | 设计判据的人往往刚读完上一轮结论 | 设计员的上下文里没有那些结论，除非它自己去读，读了什么报告里要列出 |
| 判决由主 agent 做，主 agent 不再当一条推论（`three-way-inference.md`） | 主 agent 常顺手替腿做一段推导 | 分工写进定义 |
| 材料的小节清单逐节标抄 / 不抄：实测漏节都是写材料的人自己漏的，自查两遍没发现（`three-way-inference.md` 2026-09-09、09-10 两段） | 写正文的人自己标 | 标清单的是另一个上下文 |
| 回扫「输出不许截断」（`verify-before-claiming.md`） | 几百行命中灌进主线 | agent 吃下全文，交分好类的清单 |

**2. 按「谁判、谁做」切，不按代码模块切。** 判决、定案、和用户说话、提交留在主 agent（第三节），其余按活的形态分。

**3. 一个 agent 管一类会反复派出、判据固定的活**（上游 `agents/INDEX.md` 的定义）。一次性的活照旧临时写提示派 general-purpose。

**4. 分清观测类与推论类。** 观测类交的是可复核的结果（命令加原样输出），主 agent 抽查就能用；
推论类交的结论只算三方里的一票，主 agent 逐条现查才采纳。执行类（写代码、写 kb）交的是改动与自证记录。

**5. 每个定义写死四样**，对齐上游 `agents/INDEX.md` 的三条纪律：
**输入**（主 agent 必须给什么，缺一样就拒绝开工并说缺什么）、**写范围**（能写哪些路径）、**产出格式**、**没做什么**（跑不动的、没验的）。

**6. 调度平铺，不嵌套。** 主 agent 是唯一的派发者；有依赖的串行（材料员 → 三条腿 → 核查员），没依赖的并行（三条腿之间）；
agent 定义的 `tools` 里不给 Agent 工具。嵌套省下的只是主线上几次派发，换来的是：下层 agent 的提示与报告主 agent 看不到，
等于出现一条没人核的推论；写范围闸只挂在直接派出的那一层；撞限额时主 agent 只能续到自己派出的那一层。

## 五、写范围怎么拦：先有闸，再铺 agent

`sop-first.md`：规范和门禁先于实现。一个能写 kb 的 agent 越界写了 `crates/`，不该要等人翻 diff 才发现。

| 层 | 做什么 | 拦得住 | 拦不住 |
|---|---|---|---|

## 六、调度形态

- **平时**：主 agent 用 Agent 工具按名字派；一轮三方的次序是 主 agent 写正文 → `three-way-materials` → 三条腿同一条消息并行 → `three-way-verifier` → 主 agent 写判决。

- **限额**：撞周限额续同一个 agent（它的上下文还在），撞单次输出上限重派，照 `three-way-inference.md` 现有两条。
- **机器资源**：跑模型一律 `nice -n 19`；编译 Rust、QEMU、E152（按里程碑对比六家文件系统的文件性能） 这类重负载同一时刻只跑一个。第二批加一个取锁脚本（`flock`），`implementation-writer`、`experiment-runner`、`gate-triage` 开跑前取锁，取不到就报「在等谁」而不是硬跑。
