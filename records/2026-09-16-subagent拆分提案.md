## 二、拆分判据

**1. 拆的理由不只是「专注」，更硬的是：好几条规则要求的本来就是隔离。**

| 规则要求 | 今天靠什么 | 拆开之后 |
|---|---|---|
| 三方的三条腿「不许读别的腿这一轮的产出」 | 腿今天已是用 Agent 工具分别派出的 subagent，各有上下文（`.claude/rules/three-way-inference.md` 第 32–33 行）；禁读靠提示里写一句 | 上下文同今天；读文件仍要靠定义禁止 |
| 实验的判据跑前写死，设计时不许参考已有结论（`test-discipline.md`） | 设计判据的人往往刚读完上一轮结论 | 设计员的上下文里没有那些结论，除非它自己去读，读了什么报告里要列出 |
| 判决由主 agent 做，主 agent 不再当一条推论（`three-way-inference.md`） | 主 agent 常顺手替腿做一段推导 | 分工写进定义 |
| 材料的小节清单逐节标抄 / 不抄：实测漏节都是写材料的人自己漏的，自查两遍没发现（`three-way-inference.md` 2026-09-09、09-10 两段） | 写正文的人自己标 | 标清单的是另一个上下文 |
| 回扫「输出不许截断」（`verify-before-claiming.md`） | 几百行命中灌进主线 | agent 吃下全文，交分好类的清单 |

**2. 按「谁判、谁做」切，不按代码模块切。** 判决、定案、和用户说话、提交留在主 agent（第三节），其余按活的形态分。

**3. 一个 agent 管一类会反复派出、判据固定的活**（上游 `agents/INDEX.md` 的定义）。一次性的活照旧临时写提示派 general-purpose。

**4. 分清观测类与推论类。** 观测类交的是可复核的结果（命令加原样输出），主 agent 抽查就能用；
推论类交的结论只算三方里的一票，主 agent 逐条现查才采纳。执行类（写代码、写 kb）交的是改动与自证记录。

**5. 每个定义写死四样**，对齐上游 `agents/INDEX.md` 的三条纪律：
**输入**（主 agent 必须给什么，缺一样就拒绝开工并说缺什么）、**写范围**（能写哪些路径）、**产出格式**、**没做什么**（跑不动的、没验的）。

**6. 调度平铺，不嵌套。** 主 agent 是唯一的派发者；有依赖的串行（材料员 → 三条腿 → 核查员），没依赖的并行（三条腿之间）；
agent 定义的 `tools` 里不给 Agent 工具。嵌套省下的只是主线上几次派发，换来的是：下层 agent 的提示与报告主 agent 看不到，
等于出现一条没人核的推论；写范围闸只挂在直接派出的那一层；撞限额时主 agent 只能续到自己派出的那一层。

## 五、写范围怎么拦：先有闸，再铺 agent

`sop-first.md`：规范和门禁先于实现。一个能写 kb 的 agent 越界写了 `crates/`，不该要等人翻 diff 才发现。

| 层 | 做什么 | 拦得住 | 拦不住 |
|---|---|---|---|
| `tools` / `disallowedTools` | 观测类与推论类不给 Write / Edit | 用 Write / Edit 改仓里文件 | Bash 里的重定向 |
| agent 上挂的 PreToolUse hook | 新脚本 `.claude/hooks/agent-write-scope.sh <路径模式…>`：Write / Edit 的目标不在范围内就拒绝，并说该交给谁 | 执行类 agent 越界写 | Bash |
| 派发前后比一次 | 新脚本记派发前后的 `git status --porcelain` 与未跟踪文件，差集里有范围外的路径就报 | Bash 越界写 | 同一段时间里别的会话的改动也会进差集，只能报「疑似」 |

Bash 管不住这件事照实写进每个定义的「没做什么」。

**新门禁阶段**（号待定：2026-09-16 现查 59、62 空着，58 同日已被别的会话占用；号先到先得，落地时现查）判 `.claude/agents/*.md`：

| 判什么 | 判据 |
|---|---|
| frontmatter | 从第 1 行起；`name` 与文件名一致；`description` 非空 |
| 权限写明 | 必须显式写 `tools` 与 `model`，不许默认继承全部工具；`tools` 里不许有 Agent |
| 四样齐 | 正文有「输入」「写范围」「产出」「没做什么」四节 |
| 写范围一致 | 「写范围」列的路径模式与 hook 参数逐项相等 |
| 不抄规则 | 正文里不许出现与 `rules/*.md` 逐字相同的长行（阈值实测后定），规则只指路径 |
| 登记 | CLAUDE.md 的 agent 表与目录逐项相等（形态照 50 号） |
| 对抗过没有 | 这次改动里每个新增或改过的 `.claude/agents/*.md`，都要在同一次改动带来的某份 `research/prompts/*-main-verification.md` 里被按路径点名（形态照 56 号；对抗按第七节，每批一次）。⚠️ 只判形式：路径出现在判决里就算点名，那一次攻没攻这一版、用的是哪种形态，要人看 |

## 六、调度形态

- **平时**：主 agent 用 Agent 工具按名字派；一轮三方的次序是 主 agent 写正文 → `tw-materials` → 三条腿同一条消息并行 → `tw-verifier` → 主 agent 写判决。
- **固定流水可以存成工作流**：`tw-materials` 到 `tw-verifier` 那一段形态固定，可以写成 `.claude/workflows/three-way-round.js`，主 agent 在前后各做自己那一步。工作流要用户每次明说才跑，放第三批。
- **限额**：撞周限额续同一个 agent（它的上下文还在），撞单次输出上限重派，照 `three-way-inference.md` 现有两条。
- **机器资源**：跑模型一律 `nice -n 19`；编译 Rust、QEMU、E152（按里程碑对比六家文件系统的文件性能） 这类重负载同一时刻只跑一个。第二批加一个取锁脚本（`flock`），`impl-writer`、`exp-runner`、`gate-triage` 开跑前取锁，取不到就报「在等谁」而不是硬跑。
- **git**：所有 agent 不做任何 git 写操作；`isolation: worktree` 会建临时分支，与用户级约定「没有明确指令不许新建分支」冲突，不用。

## 十、这份提案没做的

- 自定义 agent 继承不继承规则、hook 挂在 agent 上按路径拦生不生效，都没实测，只测了 general-purpose 类型。
- 十五个的粒度没拿真活试过。族一的输入与产出是照 C143（inode 号水位在回退后会退回去重发） 第三轮与里程碑「第二个事务」代码第一轮两套提示归纳的，别的轮次可能有别的形态。
- 每派一次先付继承规则那一截 token（实测一次 137,814，含回答）。第一轮对抗攻方腿按提案原文算的下限：第一批逐个对抗至少 128 次派发、1764 万 token，按批合并 23 次；那一轮两条云端腿实际各用约 30 万 token，下限偏松。用户据此定 agent 落地不频繁对抗（第七节）；每批一次低成本对抗要多少，没算。算式与复算见 `research/prompts/agent-split-r1-main-verification.md` 第三节。
- 正反对抗只走了第一轮（判决 `research/prompts/agent-split-r1-main-verification.md`）：按跑前条款只改了事实，十一组设计上的打中与线索挂起到第二轮，第二、三轮没做。这份提案不确立也不推翻 `.claude/kb/decisions.md` 里的任何一句。
