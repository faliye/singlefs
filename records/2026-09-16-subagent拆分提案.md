## 二、拆分判据

**1. 拆的理由不只是「专注」，更硬的是：好几条规则要求的本来就是隔离。**

| 规则要求 | 今天靠什么 | 拆开之后 |
|---|---|---|
| 三方的三条腿「不许读别的腿这一轮的产出」 | 腿今天已是用 Agent 工具分别派出的 subagent，各有上下文（`.claude/rules/three-way-inference.md` 第 32–33 行）；禁读靠提示里写一句 | 上下文同今天；读文件仍要靠定义禁止 |
| 实验的判据跑前写死，设计时不许参考已有结论（`test-discipline.md`） | 设计判据的人往往刚读完上一轮结论 | 设计员的上下文里没有那些结论，除非它自己去读，读了什么报告里要列出 |
| 判决由主 agent 做，主 agent 不再当一条推论（`three-way-inference.md`） | 主 agent 常顺手替腿做一段推导 | 分工写进定义 |
| 材料的小节清单逐节标抄 / 不抄：实测漏节都是写材料的人自己漏的，自查两遍没发现（`three-way-inference.md` 2026-09-09、09-10 两段） | 写正文的人自己标 | 标清单的是另一个上下文 |
| 回扫「输出不许截断」（`verify-before-claiming.md`） | 几百行命中灌进主线 | agent 吃下全文，交分好类的清单 |

**2. 按「谁判、谁做」切，不按代码模块切。** 判决、定案、和用户说话、提交留在主 agent（第三节），其余按活的形态分。

**3. 一个 agent 管一类会反复派出、判据固定的活**（上游 `agents/INDEX.md` 的定义）。一次性的活照旧临时写提示派 general-purpose。

**4. 分清观测类与推论类。** 观测类交的是可复核的结果（命令加原样输出），主 agent 抽查就能用；
推论类交的结论只算三方里的一票，主 agent 逐条现查才采纳。执行类（写代码、写 kb）交的是改动与自证记录。

**5. 每个定义写死四样**，对齐上游 `agents/INDEX.md` 的三条纪律：
**输入**（主 agent 必须给什么，缺一样就拒绝开工并说缺什么）、**写范围**（能写哪些路径）、**产出格式**、**没做什么**（跑不动的、没验的）。

**6. 调度平铺，不嵌套。** 主 agent 是唯一的派发者；有依赖的串行（材料员 → 三条腿 → 核查员），没依赖的并行（三条腿之间）；
agent 定义的 `tools` 里不给 Agent 工具。嵌套省下的只是主线上几次派发，换来的是：下层 agent 的提示与报告主 agent 看不到，
等于出现一条没人核的推论；写范围闸只挂在直接派出的那一层；撞限额、被停或报错时，主 agent 只能处置（停掉、新开）自己派出的那一层。

## 五、写范围怎么拦：先有闸，再铺 agent

`sop-first.md`：规范和门禁先于实现。一个能写 kb 的 agent 越界写了 `crates/`，不该要等人翻 diff 才发现。

| 层 | 做什么 | 拦得住 | 拦不住 |
|---|---|---|---|

## 六、调度形态

- **平时**：主 agent 用 Agent 工具按名字派；一轮三方的次序是 主 agent 写正文 → `three-way-materials` → 三条腿同一条消息并行 → `three-way-verifier` → 主 agent 写判决。
- **固定流水可以存成工作流**：`three-way-materials` 到 `three-way-verifier` 那一段形态固定，可以写成 `.claude/workflows/three-way-round.js`，主 agent 在前后各做自己那一步。工作流要用户每次明说才跑，放第三批。
- **限额**：撞了限额、被停或报错的一律新开一条接着做，不续原来那条；新开的拿 `research/scripts/agent-handover.py` 从被中断那条的会话记录里抽的交接摘要接续，照 `three-way-inference.md`「撞了限额、被停或报错的腿」那一段。
- **机器资源**：跑模型一律 `nice -n 19`；编译 Rust、QEMU、E152（按里程碑对比六家文件系统的文件性能） 这类重负载同一时刻只跑一个。第二批加一个取锁脚本（`flock`），`implementation-writer`、`experiment-runner`、`gate-triage` 开跑前取锁，取不到就报「在等谁」而不是硬跑。
- **git**：所有 agent 不做任何 git 写操作；`isolation: worktree` 会建临时分支，与用户级约定「没有明确指令不许新建分支」冲突，不用。

## 二十五、Bash 检出 hook 的一处误报（2026-09-18）

`.claude/hooks/bash-command-detector.sh` 按整条命令串匹配「按模式找进程」这一类。实测撞到：执行员写报告时用 `cat >> report.md <<'EOF'`，heredoc 正文里引用了被禁的那个命令名（它正在记「主 agent 提醒我别用没超时的等待循环」这件事），检出记录因此报「用了按模式匹配的进程命令」，看门狗把主 agent 叫醒，现查是误报。

⇒ 判据只看命令串时，**写下这条禁令的行为本身会触发它**。要么把 heredoc 正文排除在匹配之外，要么让检出记录带上「命中的是命令位置还是数据」。2026-09-19 取前一种：前两种检出（按模式找进程、没超时的等待循环）也与第三种一样，先剥掉喂给非 shell 命令的 heredoc 正文，喂给 bash / sh 的照查；自检加四格，`BASH_COMMAND_DETECTOR_KEEP_HEREDOC_BODIES=1` 时判红。同一个坑 2026-09-18 在看门狗那一侧也撞过（第三十二节），那边先修了。引号里当数据写的命令名（`echo "…"`）仍会记一条。

## 二十六、这一阶段为什么收敛慢：两个可核的数（2026-09-18）

用户 2026-09-18 问「一个任务的时间被几十倍拉长，是决策数增加、流程繁琐，还是调度设计的问题」。拿这一轮的数回答，两条各管一半：

**一、分叉因子 ≈ 1.0（管项数会不会自己长）。** 这一轮派了 30 个 subagent，里程碑二收口表从立表时的 13 行涨到 43 行（+30 项），另立 3 笔欠账（C378、C379、C380）。**平均每个 agent 交回带出 1 项新发现**；主 agent 的默认策略是「发现即修」，于是每项又派 1 个 agent。这是分叉因子 1.0 的分支过程，期望队列长度不收敛——与决策数多少、流程繁不繁琐都无关，是策略本身的性质。三方有「第三轮之后停」、实验有「够判就停」，**阶段任务这一层没有对应的出口**。

**二、单位推论的墙钟 ×3（管每一项的单价）。** 一个推论的流水线从「正文 + 3 条腿 + 判决」变成「正文 → 材料员 → 3 条腿 → 核查员 → 判决」，新增的两段都在关键路径上：这一轮实测材料员 26 分钟、三条腿并行约 20 分钟、核查员 22 分钟、主 agent 判决与写回约 20 分钟 ≈ 1 小时 50 分。`crates/` 一处改动另加实现员（26–42 分钟）→ 代码三方 → 崩溃验证（层 0 全量一小时以上）。门禁从几个涨到 60 多个阶段，这一轮主 agent 被门禁打回改字至少 8 次。

**三、重复核实的成本**：同一个 agent 两次交回、数不一样，这一轮出现 4 次（E155 执行员、分配器实现员、回扫员、书记员），每次都要主 agent 去产物或代码现查才发现。⇒ 判决只许引产物与代码，agent 的结论句一律当线索。

**四、共享决策只能靠仓里的文件**：subagent 之间没有共享上下文，每次派发要把「今天实现长什么样、条款原文在哪、别人在改哪些文件、禁读什么」重写一遍（这一轮派发提示合计约 1.2 万字）；30 个 agent 3097 次调用、新输入 1009 万 token、读缓存 8.54 亿，大半是同一批文件在 30 个上下文里各读一遍。

## 三十六、`stage-mine.py` 对「两个会话改到同一行」只会整份拒绝（2026-09-20）

几个会话共写一个仓时，`research/scripts/stage-mine.py` 把工作区的改动按块切开、只暂存命中 `--match` 的块，
命中 `--foreign` 的块**让它整份拒绝**（「两个会话的改动挤在同一块里：换一个 `--split` 把它们切开，或者等对方先提交」）。

拒绝的判据对**改了已有行**那一类不够用：一行同时含我的改名与别人的改动时，它既命中 `--match` 又命中 `--foreign`，
换任何 `--split` 都切不开——那一行本来就只有一份。`checks-owed.md` 的 C313 行就是这个形态：
别人把一个测试名改了一个字符，而那一行里另有「系统配置」。

这一轮的绕法：按同样的块算法自己合一份索引内容，**命中 `--foreign` 的块保留索引原样**（而不是整份拒绝），
`git hash-object -w --stdin` 得到 blob、`git update-index --cacheinfo` 写进索引，工作区一个字节不动。

⇒ 欠的两件：① `stage-mine.py` 加一个「foreign 块按索引原样留下」的模式，把这一轮手写的脚本收进去；
② 它今天没有办法证明「暂存进去的就只有我的」——这一轮是另写一段逐行核对（把暂存 diff 的删除行套上改名，
与新增行做多重集相减，多出来的行数要为 0）才发现 `crates/` 下 40 份整份进了暂存区。这条核对该做成 `--verify`。

同一轮还踩到：`git reset HEAD -- .` 与 `git restore --staged` 会连带清掉别的会话排好的索引，
而被清的一方没有任何提示。`session-wrapup.md` 第 4 条只写了「暂存前先确认 `git diff --cached --name-only` 为空」，
没写「清索引之前也要看一眼里面有没有不是自己的」。

## 三十七、路径回写工具的三处失效，两处让绿门禁说了假话（2026-09-21）

全仓术语改名第二批（英文标识符与文件名）里，`research/scripts/rewrite-moved-paths.py` 连踩三次，形态各不相同：

| # | 它做了什么 | 怎么暴露的 | 它自己说什么 |
|---|---|---|---|
| 1 | 把 `research/e7-index-bench/Cargo.toml` 的 `path =` 升级成仓库根路径，而 Cargo 按 crate 根解析 ⇒ `src/bin/research/e7-index-bench/src/bin/…` | `cargo build` 报 can't find bin | ✓ 改写了 34 个文件，回读都没有旧路径 |
| 2 | 把 `research/scripts/replay.sh` 登记表第 4 列升级成仓库根路径，而那一列要 `results/` 底下的纯文件名 ⇒ `results/research/results/…` | `replay.sh` 报「对不上，127 行不同」——**看着像产物变了** | 同上 |
| 3 | 把一行含「搬到」二字的现状句当成「说搬迁这件事本身」跳过不改，旧路径留在正文里 | 主 agent 逐条分类全仓剩余旧名时才发现 | 同上 |

前两条是同一个病：**回写不保形**。它只认两种形状（Markdown 链接按文件自己的位置重算、其余按仓库根），不认「相对所在 crate 根」与「纯文件名」这两种，而位置的解析口径由读它的那个程序定，不由回写工具定。

第三条更隐蔽：**自检与被检共用同一条判据**。`remaining()` 调的是 `statement_line()`，跳过规则错了，两边一起错——凡是它误跳的行，它自己永远报不出来。这是 `.claude/singlefs-ai-sop/rules/evidence-discipline.md`「校验路径本身也要证明它会红」的一个实例：自检复用被测逻辑等于没自检。

三条共用一个更上层的毛病：**它的成功句报的是「回读都没有旧路径」，而那只证明旧路径消失，不证明新路径指得到东西**（`show-me-test.md`「成功那句里报的数，本身也要有东西钉住」）。

⇒ 欠账 [checks-owed.md](../.claude/kb/checks-owed.md) C428（路径回写的自检与被检共用同一条跳过规则）、C429（路径回写不保形，也不核新路径指不指得到）。第 2 条当天已做成会红的闸：`replay.sh` 在构建之前判登记表第 4 列带斜杠就退 2（放在构建之前，坏表不浪费十分钟编译；坏表退 2、真表退 0 双向证过）。
