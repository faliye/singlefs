# 树 ID 水位：三条臂在六根轴上重比（2026-09-06）

**为什么重做**：2026-09-06 定 ② 时只在「回退」一根轴上比过三条臂。
第三轮辩方腿逐字指出「原定案只在一根轴上比过三条臂，第二轮找到了第二根轴，却没有重比」。
材料 `research/prompts/tree-id-arm-recompare-material.md`（六根轴，每格出处逐字核过，
含跑前写死的接受条款）。

## 原否决理由是循环的

D8（核心索引结构） 已定项 8 正文逐字：「否掉的两条：放进记账或放进根记录，**回退之后都会退回去把号重发**
（D23（journal 的角色与格式） 已定项 14 逐字「全部记账统计量的现行值从 R_old 那棵账重新载入」）」。
**那条引用只覆盖记账，一个字也没说根记录。** 反推腿独立指出同一点。

而 D23（journal 的角色与格式） 已定项 14 自己就在用根记录臂要的那个装置：
「第一个新根的 checkpoint_txg = **根环里全部根记录 txg 的最大值 + 1**」——
是「全部」不是「候选」（候选集才排除被抛弃时间线的根），
且同条逐字「**回退深度 ≤ 根环深度**」⇒ 能被回退跨过的根都还在环里。

## 胜负手是轴 6，判定为「根本不是错误」

**轴 6 的问题**：某个 checkpoint 分配了树 ID 42、写出带 42 的单元头，根没写成就崩了；
丙-2 的水位随那个根一起丢 ⇒ 下次挂载重发 42，而盘上留着一批带 42 的孤儿单元。

正推腿给了五条独立依据，主 agent 逐条现查坐实其中三条：

1. `18-块里携带什么信息.md:697` 逐字「**作废一个 checkpoint 必须换实例代号**」⇒ 孤儿与活版的实例代号必不相等。
2. I-1.2（块头写序已发布） 逐字「**判不成已发布者必是未发布的撕裂事务垃圾或被抛弃时间线的残留**」。
3. 扫描重建两道闸（已发布谓词 + 择新键）**都不看树 ID**；即使第一道全失效，择新键里的实例代号仍判活的赢。
4. **决定性的一条**：孤儿与活版**共用五元组是这套设计的常态，不是树 ID 重发造出来的**。
   崩溃前后同一个逻辑块两次写出的五元组逐字段相同——树 ID 同树、对象 ID 同 inode、
   对象出生代在对象创建时固定、锚点偏移是文件内偏移。
   这正是 C113（扫描重建时多版单元的现行版本判定无输入） 的名字与定案 P1 给三类身份段统一加 10 字节写序要解决的东西。
   ⇒ **丙-2 只是把一个已被专门解决、且正在为常态承重的碰撞，从既有树扩到新建树。**
5. D6（快照实现模型） 判据 9 的理由句管不到孤儿：`06-快照实现模型.md:110` 的动词是
   「盘上遗留的旧 key 在新快照里**变成可见**」，而可见性作用在**树里的 key** 上，孤儿不在任何树里。

**回收侧也不看树 ID**：`03-空间分配.md:201` 逐字「孤儿（没有条目）要求头里的写序实例 < 当前实例
∧ 按实例表的已发布谓词判未发布」。

## 甲赢的那一格，价值是零

正推腿攻不破甲的中途预留（三条封死：水位永远先于使用落盘、过半独占打开使写入集合两两相交、
甲-2 那一项只会把 max 顶上去），**材料没写错，甲确实在轴 6 上赢**。
但按上一节，**它多盖住的那样东西价值为零**，而它为此付的价逐字出自 D8（核心索引结构） 已定项 8 与 C147（树 ID 水位的预留协议六件事没定）：

| | 甲 | 丙-2 |
|---|---|---|
| 挂载中途预留失败的出路 | **行为无定义**（C147（树 ID 水位的预留协议六件事没定） ㈠） | 不存在这个状态 |
| 树 ID 要不要进条目固定前缀 | **要，是第一个事务的格式级字节**（C147（树 ID 水位的预留协议六件事没定） ㈢） | 不存在（甲-2 消失） |
| 有没有现成不变量形态 | **一条都没有**（C147（树 ID 水位的预留协议六件事没定） ㈣） | I-7.7（超级块实例代号不低于根环） 同形可抄 |
| 「水位」两义 | 盘上是预留段上界（C147（树 ID 水位的预留协议六件事没定） ㈤） | 就是水位本身 |
| 消耗速率 | `K × 挂载次数`（C147（树 ID 水位的预留协议六件事没定） ㈥） | 无浪费 |
| 字节 | 超级块 420 → 428 | 根记录 186 → 194（余量 326 → 318）|
| 挂载时的读量 | 甲-2 要扫已发布树表（排序契约未定 ⇒ 今天无上界，二层封顶约 5.9 万棵） | 根环 R = 3，≤48 次小读 |
| 机制数 | **两套**（崩溃靠超级块、回退靠不动超级块） | **一个公式覆盖两格** |

⇒ **采纳丙-2 会当场关掉 C147（树 ID 水位的预留协议六件事没定） 的㈠㈢㈤㈥四件，㈣ 变成「抄 I-7.7（超级块实例代号不低于根环） 的形态」。**

## 丙-2 自己要付的两笔

1. **取值语义必须同时写死**（正推腿自陈这是它最不确定的一处，主 agent 认同这是采纳的前提）：
   「树 ID 水位 = `max(根环里全部根记录的该字段, 本次 checkpoint 发出的最高树 ID + 1)`，**每次发布重写**」。
   ⚠️ **若读成「本 checkpoint 发出的最高号」（不累计），树 ID 会随根轮出环被重发，
   而那时被重发的号属于*已发布*的树，D6（快照实现模型） 判据 9 正面命中** ⇒ 轴 6 的判定立刻不成立。
2. **丙-2 违反 D6（快照实现模型） 判据 9 的字面，不违反它的害处**：判据 9 逐字「快照标识单调不回收」，
   而孤儿场景下标识确实被回收了。补法是按判据 9 自己的理由句把射程收窄成
   「**已发布**的快照标识单调不回收」——**要动 D6（快照实现模型） 判据 9 的射程，要用户定案**，
   且立完要当场回扫 C143（inode 号水位在回退后会退回去重发）（回退抛弃的是已发布过的时间线，那条不会消失，只会变形）。

## 主 agent 的判决

**丙-2 应当取代甲，这条定案要重开——而这是用户定案，判决权不在这里。**
