## 三、逐题：现象、病根、定案、措施、状态

### 3.1 上游副本的 `CLAUDE.md` 被当成目录级 CLAUDE.md 注入

**现象与数。** 子 agent 用 Read 读 `.claude/singlefs-ai-sop/rules/` 下任何一份规则，Claude Code 就把副本里的 `CLAUDE.md` 与它 `@` 的 16 份规则全部作为附件塞进上下文。982 个里 406 个中招，注入前后上下文差中位 7.6 万 token（p25 6.7 万，p75 8.1 万）；之后各调中位 85 次、合计 42,927 次，每次带着它：约 33 亿读缓存，占子 agent 读缓存 11%，折算 3.3 亿（8%）。一份中位数实现员：第 1 次调用 1.06 万，第 4 次 2.7 万，第 5 次 10.5 万。定义开 `omitClaudeMd` 省下的 12 万起步，读一次规则就还回去大半。

**病根。** 那份 `CLAUDE.md` 是给在上游仓里干活的人读的；随 rsync 整目录拷进来。`records/2026-09-16-subagent拆分提案.md` 第三十一节 2026-09-18 记了，写「改法没评估」，没人动。

**定案。** P4 的 U4：副本不带 `CLAUDE.md`。

**措施与状态。**

| 措施 | 状态 |
|---|---|
| CLAUDE.md「规范从哪来」的 rsync 加 `--exclude CLAUDE.md`、diff 加 `--exclude=CLAUDE.md`，并写明为什么 | 已做 |

### 3.5 kb 写回两跳与 agent 合并

**现象与数。** 起草员 18 个（平均 2.1M 折算）交出旧串与新串，书记员 66 个（平均 1.8M、63 次 Bash、18 分钟）再执行一遍 `replace-batch.py` 与门禁 `--write`；两跳串在关键路径上约 40 分钟，合计 1.6 亿折算。实现员按活分：普通 123 个（平均 8.7M）、交补丁 17 个、「合入后验证」3 个（平均 14.3M，最贵的一种）、接调查 2 个；调查员 14 个（平均 1.3M）。

**病根。** 拆成两个 agent 的理由是「起草无写权限、闸在中间」，而闸是一个脚本，放在同一个 agent 的第 2 步照样拦；合入后验证做的是打补丁、编一次、逐个跑测试二进制，只有「改钉值」要判断。

**定案。** P2：书记与起草合并；调查员查到就修；合入后验证换脚本；实现员不与上游（三方判决、主 agent 聚簇）合，对抗独立性靠这条线。逐对论证：

| 候选 | 判断 | 理由 |
|---|---|---|
| 起草员 + 书记员 | 合 | 都读同一份判决与同一批 kb 文件，第二跳把第一跳读过的再读一遍 |
| 调查员 + 实现员 | 合，保留停点 | 14 次调查只有 2 次接了实现员；条款写了改法的直接改，没写的停下 |
| 实现员 + 合入后验证 | 不合，换脚本 | 前三步是 `apply-writer-patch.py` 加一条命令；红了才派实现员改钉值 |
| 实现员 + 三方判决 | 不合 | 「先定决策再写代码」与代码轮的对抗独立性 |
| 回扫员 + 书记员 | 不合 | 回扫交候选清单，要主 agent 判了才能写 |
| 设计员 + 执行员 | 不合 | 跑前登记先于代码、执行员看不到答案 |
