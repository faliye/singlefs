# 回扫员可靠性：从关键词回扫到事实表加逐行判

2026-09-18 一轮知识腐烂回扫里，四个按领域派的回扫员有两个报零处要改、一个只做了抽查；主 agent 定向搜出 25 处真腐烂，四份报告一处都没报。这份记录写这 25 处怎么被漏掉、改成了什么、改完实测抓得住多少。

## 漏在哪

| 环节 | 实测 |
|---|---|
| 关键词从哪来 | 派发提示给的是「做成的事」的新名字（`mount_writable`、两条流），腐烂的句子说的是旧说法（「层 0 只有第一个事务」「多次挂载的录制流」），按新名字搜不到 |
| 覆盖 | 回扫员自己挑载体、自己决定搜到哪；一份报告写「抽样得差不多了」就交回，没有东西拦 |
| 分领域派 | 欠账表的前置列不归任何一个领域，四个回扫员都没扫它 |
| 答案泄漏 | 阳性对照的 25 处明文写在工具源码里，一个回扫员读到后照抄成「要改」，其余 1740 行按载体类型套默认判定 |
| 组级放行 | 候选按退役片段分组时，一组 40–150 行里多数是碰巧共享几个字的噪声，回扫员写一句套话把整组放掉，含真腐烂的 37 组全被放掉，25 处判中 0 |
| 判的问题 | 回扫员在问「这笔欠账还清了没有」，而该问的是「这一行里描述现状的分句今天还是不是真话」；带日期的现状句被当成事件句 |

## 改成了什么

流程分两段，都由 `research/scripts/stale-candidates.py` 核形式，定义在 `.claude/agents/sweep.md` 第 7–11 步，调度在 `.claude/main-agent.md`：

1. 写事实表：`--changes` 列出这一阶段 kb 各文件历史版本节新加的每条变更记录（改名的文件按旧路径比）；回扫员把每件变了的事实写成「旧事实、新事实、检索词、出处」一行。`--check-facts` 判红四种：有变更记录没被任何一行罩住；检索词在基准那一版的现状句里零命中（照抄了新说法）；在结束那一版命中超过 150 行（太宽，用 `A&&B` 收窄）；标成「新立：」却在基准里有命中、或新事实写着落地 / 实现 / 还清。「只改措辞」的行只罩变更记录、不出候选。
2. 逐行判：候选表按组切段，一段一个回扫员，每一行都要判；`--check-report` 核每一行都有判定、判定是五种之一、理由不短于 8 个字。主 agent 交回后从「不相干」「事件句不改」里随机抽 20 行复判。
3. 阳性对照：`--benchmark` 用冻结的盲写事实表（`research/scripts/fixtures/stale-candidates-benchmark-facts.tsv`）在 `b1c8cef~1..00c9d4f` 上生成候选，已知腐烂只存哈希，工具罩住的不许少于 20 处；门禁 47 号每次跑。
