# 文件区间与尾部分批 Verus 补充

用户要求补充核心代码的 Verus 验证。本轮将两个可执行计算核放入 `crates/singlefs-replay-prefix/src/file_range_proofs.rs`，core 的三处入口直接调用：

- `truncate::next_truncation_step`：目标单元数以内不释放，每批释放不超过批大小，非最终批严格推进，恰好一批时结束。
- `unlink::next_unlink_step`：使用同一分批核，目标单元数为 0。
- `PartialWriteOfAFile::bytes_written_into`：返回精确交集、单元内偏移、请求内偏移和正长度；无交集返回 None。

增加两个可执行入口、一个无前提边界见证、两个分区引理，共 5 项 Verus 义务。分区引理分别证明释放尾区间与相邻单元内写字节的分区不重不漏。登记核、计数与 7 个必红变异，保留这些公共文件里本轮之前已有的 GC 修改。

新增运行时测试独立枚举小区间字节集、逐批释放单元集与批次数，另检查 u64 极值。既有 core 测试验证产品包装层。

范围：批大小大于 0 由 core 的 `UnlinkBatchSize` 保证；目标 size 到单元数的转换、单元端点乘加、unlink 的剩余 size 乘法、完整事务与 I/O 未进入本次证明。此次未运行全仓门禁，也未运行完整 proof 门禁的 MIR 比对。定向门禁的单元指纹遇到现有内存包装的 `sys-path-unfolded` 拒算，结果全部现判、未复用缓存，三项检查均退出 0。
