# 2026-09-06：D2 未定项 12（parity 列的位置与发现机制）三轮对抗

这是 D2 未定项 12 的建设记录。**三版提案，三轮对抗，全部被打穿**，
而这一格今天仍然是未定——但它从「三条没论证过的候选」变成了「三条边界 + 一个态别判定 + 一个结构选择 + 一条阻塞前置」。
决策正文在 `.claude/kb/decisions/02-RAID条带策略.md` 未定项 12；
新实验 E106（条带成员表的载体）（已跑）与 E107（条带表对主负载的写放大）（已建档未跑）；新账 C127（钉住状态在分配记录里没有落点） / C128（清扫准入对 parity 格两支都判不出）。

## 为什么打了三轮

用户口径：**一次打穿不算数，三轮里多数打穿才算**。第一轮反推腿判「第一版不该收」时我本来要照单收下，
被拦住之后补了第二、第三轮，每轮换攻击面。结果是：

| 轮 | 攻击面 | 结果 |
|---|---|---|
| 一 | 引理算术、释放路径钉住、加密、跨头 COW、自举、清扫 | 打穿；十一条命中里六条主 agent 逐字现查坐实 |
| 二 | 辩方复核第一轮的判决 + 全新面（几何再求值 / 快照销毁 / 崩溃点与回退 / `w` 的求值） | 辩方判「第一轮判重了」并给出四处补丁；攻击腿在新面上又打穿七条 |
| 三 | 攻第二轮自己给的那套修法（`w=2` 镜像链、parity 有条目、三段发布顺序）+ 主负载的写放大 | 打穿；攻击腿**撤回自己上一轮的四条主张** |

**多轮真的买到了东西**：第二轮的辩方推翻了第一轮的一条命中（跨头 COW），
理由是仓里早有「树 ID 取 0 = 全池 / 无归属」的成例、而一个根记录只有一张树表 ⇒ 池级的树不会每头分叉——
我现查 D5 已定项 4 与 D22 已定项 7 坐实。**这条要是没有第二轮，就会当成打穿记进正文。**

## 三条边界（这一轮真正的产出）

| 边界 | 它是哪几条已定条款的合取 |
|---|---|
| 成员表进不了任何单元的**头** | D18 已定项 3 的禁放清单（物理落点 / 设备 ID 不许进块头）；而 parity 格自己也放不下头——D18 已定项 6 定头必须在第 0 字节、已定项 9 定扫描器按 16384 步进，尾部的头永远探不到 |
| 进不了纯**指针 / 索引** | 索引是派生态（D21），扫描重建那一刻它正是丢掉的东西；C113 定案 P3 明写候选要答重建路径 |
| 进不了**密文** | D9 的明文豁免清单只有超级块与已定项 5 那一层；D3 第 4 条要求无密钥侧能搬，而修复与重建都是搬 |

**态别不再是开放问题**：按 D21 自己的判据「丢了就丢数据 / 丢了只是慢」——
这张表丢了会让重建做不成、让分配器判不出钉住（E80：单盘失效平均丢 9.8–13.0 个活单元，盘坏前零报错）
⇒ **权威态**，必须住在单元的载荷里。

## 打中已定条款自己的四处

这四处与「载体选谁」无关，选哪条候选都要还：

1. **钉住状态在分配记录里没有落点**（C127）：D2 已定项 11 规则 1 说「修复完成前不得复用」，
   而分配记录条目的 value 是「代 8 + 跨度 2（最高位已被已释放借走）」，没有任何一位表示钉住，
   分配准入也没有任何一条合取问条带 ⇒ 崩溃或重挂之后那条规则在**分配那一侧**拦不住。
2. **清扫准入对 parity 格两支都判不出**（C128）：共有合取要「头可读」，孤儿支要「头里的写序」，而 parity 格没有头。
   两个读法一个永久泄漏、一个静默清掉活 parity。
3. **「格 = 单元 = 32768」与元数据单元 16384 打架**：已当场改正文——格分两档、一条条带的全部格必须等宽、
   `w` 的「攒批后的写入量」按格宽分桶各算各的。
4. **「修复」一词在 D2 已定项 11 里有两个意思**：已补注收窄到「成员被释放」那一类；
   掉盘之后的重建是另一件事，降级期间 `w` 被可写设备数夹住 ⇒ 「整批重落**一条**新条带」按字面不可执行。

## 实验

**E106（条带成员表的载体）**（当日建档、当日跑、当日改三次）：
稳态下不可解格数恒 0，而**池刚建好那一格恒 1**——条带表只有一个容器时它落在自己描述的那条条带里。
那一格是第一轮反推腿给的可达历史，先做成模型里必须报非 0 的世界再动结论。
第二轮打中它的代价模型：往一块声称 90% 填充的盘里摆了 126.3% 的格；换成自洽口径后三条臂是 1544 / 2511 / 3088 ppm。
第二轮预言的「加盘窗口让臂甲退化成阳性对照」**建模之后没复现**，如实记 0 并把原因钉成断言。

**E107（条带表对主负载的写放大）**（建档未跑）：第三轮正推腿手算出「一次发布 332288 → 496128 字节、写放大 1.493×」，
**那是一份没有装置的算术**，只当假设。E107 要把它变成有断言、有变异、可复跑的东西，
并加一条丙臂——「`w` 恒 2 全镜像、不要条带表」，因为**未定项 12 的存废压在那个比较上**。

## 这一轮学到的

- **一次打穿不算数这条口径是对的。** 第二轮的辩方腿推翻了第一轮的一条命中，靠的是去查两条同类先例，
  而不是重新论证利弊。**分歧点要靠「去查能分辨它们的那个事实」解决**，不是靠第四个模型投票。
- **攻击腿撤回自己上一轮的方案，比它打中新东西更有价值。** 第三轮那条腿逐条撤回了它第二轮给的四条主张，
  每条都写明依据。一个只会加码的对手，给的是越来越复杂的补丁，不是越来越清楚的边界。
- **「这句话逐字是什么意思」经常就是全部争点。** 第三轮把「parity 有条目 ⇒ 走有条目那一支 ⇒ 无头不影响清扫」
  打穿，靠的只是原文里「**两支共有的**合取」那五个字——加条目换的是分支，共有合取一个字没动。
- **建模选择会替结论说话。** E106 第一版把落点分布取成均匀随机，而本工程的规则是确定性的「取最空的」；
  两条都建了，恒 0 都成立，但**只有把两条都跑了才知道**。
- **代价的口径比代价的数值更容易错。** 「元数据自己占多少字节」听着像个代价，
  而它把 parity 与容器加在 90% 之上 ⇒ 126.3%。钉绝对值的断言当时钉在了不承重的那个量上。
- **上游规则也会误判。** 一句讲盘上字节的话「已被 U9 覆盖」被 doc-lint 判成「就地标注被某条决策覆盖」。
  按规矩改上游并抬 VERSION（0.0.28 → 0.0.29），不在项目里就地改。
