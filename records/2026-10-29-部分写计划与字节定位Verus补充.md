# 部分写计划与字节定位 Verus 补充

用户要求继续增加核心代码的形式化验证。本轮从 143 条义务扩展到 150 条：新增模块 `partial_write_proofs.rs`，四个产品可执行函数、两个区间语义引理，以及字节定位函数中的一条 nonlinear_arith 子证明。

## 产品接入与性质

- `PartialWriteOfAFile::data_unit` 调用 `classify_partial_write_unit`。五个结果分别有充要契约：旧单元未被整块覆盖时读回、旧单元整块覆盖时免读、新单元部分覆盖时读残留、新单元整块覆盖时免读、未写到的新单元补零。core 穷尽匹配回原有公开枚举，原有名称及读回标记 API 不变。
- 两个引理证明在非空区间前提下，“整块覆盖”等价于每个单元字节都被写，“相交”等价于存在共同字节；相邻端点不能误算相交。
- `first_rewritten_unit` 调用 `first_unit_to_rewrite`，保证重写起点的精确位置：从已有单元内写则由写起点开始；从旧尾后写且旧尾不满则包括旧尾；否则从已有单元数开始。保留原有短路：写在已有单元内时不计算尾部声明长度。
- `data_units_after` 调用 `units_after_partial_write`，取已有单元数与覆盖写入终点所需单元数的最大值，不丢旧后缀且能容纳写入。
- `first_written_unit` 和 `last_written_unit` 调用 `unit_containing_byte`，分别定位首字节和 end - 1；证明 index × capacity <= byte < (index + 1) × capacity，包含 u64 极值。规格中的区间端点是数学整数，不等于保证端点本身能表示成 u64。

开发中修正了两处新增证明的乘法单调/交换引理衔接，以及普通 Rust 构建时不应导入被擦除 spec fn 的问题；最终整 crate 为 150 verified、0 errors（--no-cheating --rlimit 10）。没有新增可信假设或 external_body。

## 范围

输入的写区间、单元区间必须非空；构造后的计划字段须保持一致，端点乘加须不溢出。写入终点的非零条件来自非零长度及已有 checked_write_end 构造，正容量由产品格式提供。旧尾是否不满仍由 core 算，布尔值到真实文件状态的转换、实际设备读取/写入、完整事务与任意改写公开字段后的行为不在证明结论内。

## 回归

新增四个核测试：逐字节枚举且确认五类来源均出现、重写集合最小起点、写后计数的 u128 对照、字节定位的 u128 区间包含。新增一个 core 包装测试，遍历单元边界和不同旧单元数，用实际写字节集合核对首尾定位及公开枚举的读旧数据/读残留/补零标记。

最终 `cargo test -p singlefs-replay-prefix -p singlefs-core --lib --quiet` 为 core 370 passed、replay-prefix 25 passed，合计 395 项。此前仅验证计划函数时为 148 条义务，追加字节定位后才是 150；两次都直接验证整 replay-prefix crate，不把其它会话的 core 证明数算作本轮增量。
