# 2026-09-10：D26 未定项 4 与未定项 5 的定案推演——两项都仍未定，各换了一次挡路条

**用户要求**把 D26（后台整理与放置回收）的未定项 4（结构抗老化取什么形态）与未定项 5
（整理与记账的交互）做定案推演。**结果是两项都仍然未定。**
这份记录写清各自被什么挡着、这一轮把挡路条换成了什么，以及踩到的三处。

两项各走一轮三方论证，攻击面互不重复；每条判决由主 agent 逐条现查坐实，不采信任何一条腿的转述。

## 未定项 4：跑了那个挡着它的实验，实验没解开它，但换出了一条更准的挡路条

未定项 4 自 2026-09-01 起就挡在一件事上：E95（老化的节点布局臂）没跑。
那一篇自陈前置逐字「无。纯算术，可直接在 E93（老化下的放置与碎片度）的源码上加臂」——
也就是说，挡着一条格式级决策的，是一个当天就跑得出来、而没人跑的模型。

**这一轮把它跑了**（20 单测 / 20 条变异全抓，四轮逐字节一致，已注册进 `replay.sh`）。
跨装置闸把 E93 入库产物的 14 个 `aging_median` 逐个钉死，全部复现。

### 判据 5 的字面答案是「能」，而那个「能」被反推腿一次干预打掉

产物里「格式 / 政策」那个分界**是一个写死的标签**：`Arm::family()` 按 enum 变体硬写，
判决行按 tag 前缀 `pol_` / `fmt_` 过滤。反推腿把**同一个函数** `step_node_group`
原样注册成一条政策臂，**24 个格的数字逐字不变，而答案行当场从 `true` 翻成 `false`**。

⇒ 被判成「格式臂」的那条臂，在这个模型里不消费任何盘上字段（组身份是 `key / g` 算出来的）。
真读盘上状态的只有代际分离臂，而它六格里只赢一格、从未过半。

**⇒ E95 既推翻不了「政策够」，也确立不了它。** 挡路条换成
**「等一个带节点分裂合并的模型」**——静态 key → 对象的模型里，
「按 key 区间分组」与「按节点数分组」出的数完全一样，而只有后者要在节点头里存字段。

### 这一轮最值钱的一条：一个实验能把「谁给它起了什么名字」量成结论

E95 的判决行读起来像在比较两类机制，实际比较的是提交者贴的标签。
它通过了自己全部的判据：阳性对照每臂都跑、守恒逐点相等、跨装置闸 14 个数一个不差、
20 条变异全抓——**而它回答的那一问，问的不是它以为在问的那件事**。

⚠️ 这与 `.claude/singlefs-ai-sop/rules/show-me-test.md` 那张「能通过全部门禁、却仍然是错的」表
第一行同型（测试测的是实现，不是契约），只是这次落在实验的**分类轴**上：
臂间互比全部成立，绝对值断言全部成立，错的是把臂分进两个家族的那一步，而没有任何断言碰它。

### 顺带查出 E95 自己的四处射程限制（已写进那一篇）

| 处 | 是什么 |
|---|---|
| 组大小的三点栅格 | **低估**而不是高估节点组臂：`budget=128 load=runs8` 的真最优是 g16 = 522，登记的栅格报 904 |
| 预算轴 | 结论不单调：9× 上政策臂反超，16× 上政策臂赢过全部六条格式臂 |
| `fallback_pct` | 量的是走了哪条代码路径，不是放置好不好——对齐计数口径后 18 格回落率全变 0，而 `runs_median` 逐字不变 |
| 跨装置闸 | 只罩住 E93 那套共享底座，新加的两条臂在 `run_e93_arm` 里出现 0 次 |

### 本轮补上的一个真盲区

反推腿实测：把 `step_node_group` 里的组大小换成常量，**31 个测试一条都不红**，
而 g2 / g8 / g32 三行会逐字相同、判决行随之翻面。
根因是 18 条单测**全部直接调**那个函数，`Arm::NodeGroup { g }` 到函数之间那根线一点没测。
⇒ 补了两条 knob 接线测试与两条对应变异（M19 / M20），现在 20 条变异全抓。

## 未定项 5：挡路条写偏了两处，换出两笔无主的格式空白

③（deadlist 条目装什么）2026-09-08 起逐字挡在「指针带出生 (树, txg)」这笔未落地的格式代价上，
理由逐字是「凑那 33 字节要多读一次单元头，O(1) 就没了」。**这一轮判它两处写偏。**

### 一、跨头共享的块根本不走那条 O(1) 判定

D5（快照 / 空间记账机制）逐字写着「四条前提，越过任何一条它就失效」，
第 3 条逐字「每个块在活树里至多一个活引用」；同一段逐字记着这条重开条款
2026-08-30 已被 D6（快照实现模型）已定项 1 触发并收口，收口形态逐字是
「**D5 为主 + 稀疏旁表为辅（ZFS 的 BRT 形态）**」，末尾逐字「从备查变成必做」。

⇒ 「多读一次单元头，O(1) 就没了」把代价记在了一条**对这批块本来就不适用**的路径上。

### 二、「今天一个字节都没有」只对码 1 / 码 2 成立

码 3 那条边早就解掉了同一件事：D8（核心索引结构）已定项 6 的 26 字节身份引用逐字含
「出生树 8」，理由逐字就是「克隆头共享 origin 的叶」。

### 三、换出来的两笔，都不在 D26 名下

| 落点 | 是什么 |
|---|---|
| C236（稀疏旁表被定为必做却没有任何落点） | 一个被自己的决策定为**必做**的盘上结构，「旁表」二字在 checks-owed / first-txn-layout / invariants / verification-build 四个文件里各出现 **0 次**，而 D5 标「已定（分项 5，其中未定 0）」 |
| C237（码 1 / 码 2 的指针里没有出生 (树, txg) 的位置） | 三处消费者都要它，而已定的指针头部 31 字节逐字分解成四项、加满 |
| C238（位置条目从 11 变 14 之后「53」这个派生数没人回扫） | 顺带查出：E73 与 E74 逐字写「按 D22 已定项 7 的树表单元指针实宽 53 字节」，而那条分项今天写的是 59 |

### 候选「出生树由克隆祖先表 + birth txg 推导」三条腿各打中一处

本地腿两次抽样都给跨树 reflink / 去重的反例（主 agent 核：那类特性今天不存在、
引入它要先重开 D5 ⇒ 这条候选的真代价是**把它永久堵死**）；
正推腿判它破「不为省空间牺牲自包含」且推导是 O(克隆链深)；
反推腿指出 D5 逐字「崩溃后该号会被重发」⇒ txg → 出生树 这个映射不是单射。
