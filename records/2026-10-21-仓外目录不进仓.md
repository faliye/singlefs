# 仓外目录不进仓

## 课题与出口

用户要求：「提交的写内容的时候 让 书写员仅仅写本项目相关的 不要涉及其他的目录 这个也留下门禁」，例子是里程碑四 GPU 垃圾回收那份记录里列第二台根分区别的目录占用的那一句；随后补一句「singlefs 的没有问题 包括上游的 singlefs sop 都是可以的」。弹窗定：singlefs 自己会读的仓外依赖目录「登记了就放行」，只放行登记的那条路径本身，同一个目录名单独出现照样判红。

出口：

1. 进仓的文字只写本项目的东西，写进共用约束与主 agent 定义（写记录的是主 agent）。
2. 门禁 doc-text 加一格，判这次改动新加的行里不出现不归本项目的目录；本机的目录名由门禁现读，第二台的读私有名单 `~/.config/singlefs/out-of-project-names`（不进仓）；放行表登记 singlefs 自己读的仓外路径，每条要有仓里的脚本用到。
3. 现有文字里提到别的目录的地方改掉（冻结证据 `research/prompts/` 不改）。

## 依赖表

| 批次 | 任务 | 谁 | 依赖 | 输入齐没齐 |
|---|---|---|---|---|
| 1 | 记录与 kb 里已发现的几处改掉：本机与第二台根分区占用两句、一处本地模型名、一处别的工程的进程名、两处别的 agent 工具的路径、`tooling.md` 三语里本地模型网关的目录与密钥文件 | 主 agent | 无 | 齐 |
| 1 | 门禁一格、自证样本、放行表、共用约束与主 agent 定义各一句 | `tooling-writer` | 无 | 齐 |
| 2 | 照新格在全仓跑一遍的命中逐处改掉或登记放行 | 主 agent 或 `kb-scribe` | 批次 1 的门禁 | 等门禁 |

派发上限 1 个子 agent，截止批次 2。

## 过程

- 批次 1：主 agent 用 `scripts/kb/replace-once.py` 改了六处记录与 `tooling.md` 三语各三行，改完 `git grep` 这几个名字 0 命中。第二台家目录与仓的上一级目录的条目名列进私有名单（经 ssh 只读列，名单不进仓）。
- 批次 1 工具实现员交回补丁（`~/.local/share/singlefs/work/out-of-project-names-gate/scripts.patch`），主 agent `git apply` 打进主工作区（`apply-writer-patch.py` 只认 crates 补丁，报「补丁 没有」）。doc-text 样本档 51 个用例判得都对（新加 7 个），18 个弄坏开关逐个打开都退 1、判错的只落在新格的样本上。为跑样本档把 `doc-text.sh` 与 48 个新样本暂存了。
- 新格的单跑与 `--all-lines` 回扫按规矩归提交时；用户授权过所有操作、这一格只读文本，主 agent 带 `SINGLEFS_HEAVY_TESTS=user-request` 跑了回扫：「全仓 git 跟踪的 9365 份文本文件里 222 份有不归本项目的目录名或根下系统目录的占用，共 482 处」。用草稿目录里这一格判法的副本逐处列名字（只留本机）：`research/prompts/` 下冻结证据 92 份不改；其余命中大半是误报——相对链接里仓自己的 `../.claude`（163 处）、XDG 回退写法里后面紧跟 singlefs 一段的家目录路径、`$HOME` 与假家目录 `/home/u/` 没当成 `~` 认、Rust 注释里参数名 `` `code` `` 与子命令名 `` `models` `` 这类普通英文词进了反引号上下文。
- 批次 2（主 agent）：真该改的十几处改掉——两份记录里本地模型网关的目录、立项记录里另一个工程的路径、kani 工具目录、Claude Code 用户级配置文件、VSCode 服务端日志目录、NVIDIA 着色器缓存目录、`multi-host.env.example` 的 ssh 配置路径、`tooling.md` 三语的用户级可执行文件目录与 shell 启动文件。
- 批次 2（`tooling-writer`）：新格的三处误报修掉，放行表补两条有代码引到的（NVIDIA 着色器缓存目录、VSCode 服务端目录）。
- 批次 2 工具实现员交回第二份补丁（`~/.local/share/singlefs/work/out-of-project-names-gate-r2/scripts.patch`），主 agent `git apply` 打上：样本档 53 个用例判得都对，新加的 10 个弄坏开关逐个打开都退 1、判错的只落在两份新样本上。它交给主 agent 定的两句（`scripts/hosts/detached-run.sh` 出路句里的 XDG 状态目录、`.claude/hooks/bash-command-detector.sh` 文件头讲 dotglob 那一句）主 agent 判改句子，用 `replace-once.py` 改了；`records/2026-09-16-subagent拆分提案.md` 里最后一处反引号里的目录名改成放行的路径写法。
- 回扫（带 `SINGLEFS_HEAVY_TESTS=user-request`，依据同上）：「全仓 git 跟踪的 9530 份文本文件里 18 份有不归本项目的目录名或根下系统目录的占用，共 57 处」，18 份全在 `research/prompts/` 冻结证据里，其余 0 处。新格照常跑（判新加的行）另点名一份别的会话已提交的冻结证据 `git show 841b3beabb98:research/prompts/m4-segment-code-r2-sonnet-output.md` 的一行，不是这一轮的，提交时交那一轮的会话处理。
- 批次 2 第三份补丁（`~/.local/share/singlefs/work/out-of-project-names-gate-r3/scripts.patch`）修带容量上下文把放行路径底下的深层段当成家目录条目：样本档 55 个用例判得都对，新开关 `out-of-project-names-deep-segment-judged` 打开退 1、判错的只有两份新样本。新格照常跑（判新加的行）：「out-of-project-names：绿」。回扫：「全仓 git 跟踪的 9703 份文本文件里 17 份有不归本项目的目录名或根下系统目录的占用，共 56 处」，17 份全在 `research/prompts/` 冻结证据里。主 agent 删了草稿里记过真实目录名的中间文件。
