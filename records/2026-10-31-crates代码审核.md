## 读过并且对得上的

容器树、inode 树、已记录操作、删除 inode、谱系、墓碑、退役：暂存改动是 Verus 包装。`append_records_to_the_open_container`、inode 叶的借记录与吸收、已记录操作的 `to_bytes` / `parse`，可执行结果与 HEAD 相同。

字节、journal、记录、指针、单元、根记录、校验和：写侧交出的布局，读侧按同一字段表解得回。小端 1、2、4、6、8 字节往返成立，6 字节读回小于 2^48。码 1 载荷 CRC 罩 `[105, 32768)`，码 3 罩 `[107, 32768)`，码 2 罩 `[header_end, 16384)`。Journal 头校验和罩整条 4096 字节，载荷 CRC 只罩点名区。`record_offset`（`journal.rs:509`）对计数器 0 与环短于一条记录走 `checked_sub` / `checked_rem`，panic 条件写在 `requires` 里，调用点先判过。

两份把 CRC-32C 片段合成整段的函数（`checksum_kernels.rs:271` 的零字节矩阵、`checksum_kernels.rs:350` 的乘 x 的幂）用另一份 Castagnoli 实现核对过：两片长度各从 0 到 19 的全部组合，合成值与整段 CRC-32C 相同，两式彼此也相同。公开向量 CRC-32C(`123456789`) 是 `0xE3069283`。没有跑仓库里 1536 字节那条路。

区域记录在显存装不下时先交单元头一片、余下字节再切（`region_record_kernels.rs:589`）。切批（`memory_limit_and_chunks.rs:186`）把装不下一整条的输入切成单独成段放得下的片。同一条记录的两片要进同一段，输入缓冲按 4 字节向上取整之后会超过「单片刚好放下」的那一档显存或绑定上限，贪心装段装不到一起，不会走到「一段里同一个单元两片」那个断言。映射按落点切开时，落在片外的那一份位置改成片内那一份（`region_record_kernels.rs:533` 一带）；建表时两条位置相同只记一项（`region_record_kernels.rs:372`）。走映射的核用「第一份或第二份指着这条记录」判定（`region_record_kernel_walking_the_mapping.wgsl:388`），两份写成同一个落点不会被核拒掉。

`O_DIRECT` 后端的 `discard_at`（`block_device.rs:1217`）长度非 0 时交回 `Unsupported`，不改字节。调用方 `discard_the_segments_reusable_as_a_whole`（`mounted_session.rs:2988`）把这个结局记进 `unsupported`，不记成 `Applied`。文件后端仍是打洞。这是后端之间写明的差别，不是静默把「没丢掉」记成「丢掉了」。

截断字段：盘上 T = 0 且 N_w ≠ 0 时 `from_the_two_fields_on_disk`（`records.rs:161`）交回 `None`，与 spec 同一判法。

部分写与 unlink：`units_covering_size` 用 `(size - 1) / capacity + 1`，避开 `size + capacity - 1` 的中间和。`units_for_sequential_write` 在长度为 0 时仍是 1。`next_unlink_batch` 把 `next_tail_batch(..., desired = 0, ...)` 的留下的单元数交回去，最后一批留下 0。`size_after_an_unlink_batch` 乘不下就 `None`。`checked_write_end` 用 `checked_add`。

挂载读坏的根环槽：mkfs 种第 0 代根的那几个槽，最旧 txg 钉在第 0 代（`mount.rs:2994`），其余槽用公式在 `[0, first_txg)` 里落到该槽的最小 txg。注释写的是区域 1、区域 2 的槽 0 按公式要等 txg 1、txg 2 才被盖掉。

参照文件系统：`Truncate` 与 `WriteAtOffset`（`reference-filesystem` 的 `submit`）在没有文件时拒绝并保持模型不动；有文件时截短保留前缀、加长补 0，按偏移写时终点之前的洞补 0。偏移或终点装不进 `usize` 时是断言，注释写明调用方交的是实现已经做成的写。

## 仍在的规模代价

这三条在 `records/2026-10-11-singlefs-core严格审核.md` 里已经写过。现行号仍是这样，这次没有改它们。

1. 按槽找分配记录仍是线性扫描。`PoolAllocator::record_for`（`allocator.rs:2178`）在 `records` 上 `find`。发布路径对换下的角色、每块盘都会查。

2. 不改文件内容的发布仍会克隆第一个文件的全部数据单元字节。`carried_file_version_units`（`transaction.rs:14436`）对每个数据单元 `bytes.clone()`。

3. 发布与挂载仍整份克隆分配器。`transaction.rs:1837`、`transaction.rs:1942` 在发布前与预演各克隆一次；`mount.rs:4871`、`mount.rs:5293`、`mounted_session.rs:1574` 还有同样的克隆。

提示与映射都读不出的数据单元，重建时字节是空 `Vec`（`recovery.rs:3646`）。这是 D19（块指针的结构与宽度预算）已定项 5、用户定的 N2，注释写明挂载照常、读到那个文件才报错。不把它算成这次新发现的缺陷。

## 后台 GPU 与块设备

再对过一轮，同样没有确认缺陷。对过的字段包括：两份区域记录核的描述字（走表用第 10 字寄存器、二分用第 11 字）、头与载荷 CRC 和 key 偏移（码 1 的 43/75/91、码 2 的 42 与 key 区间之后、码 3 的 43/73/93/103）、分类次序（类标签、已死、可搬、key 与位置不符）及切片合并；校验和两份核的初值 `0xFFFFFFFF`、末尾取反与分片合成用的长度；活槽两份核的释放字只写 0 或 1、段界与相交长度。等提交的路径在 `poll` 得到完成之前不读回结果，超时不采用那一次的输出。`O_DIRECT` 的暂存区按 4096 对齐，请求按物理块对齐；文件后端打洞对不支持与被信号打断的分类与文档一致，打洞失败不改走逐块写 0 的那一支之外的字节。

## 格式常量扫描器

`verified_model.rs` 用 `assume_specification` 对 `singlefs-format` 的 `pub const`。下面三处是扫描器自己的边界。当前树上的规格写全路径，format 的 `pub const` 一行一条、右边是十进制字面量，这三处都不触发，也不会把现有字面量里的错值放过去。

1. `format_constant_definitions`（713–716 行）只看这一行里第一个 `const` 之前有没有单独的 `pub`。同一行写了两个 `const`，或 `pub` 与 `const` 分成两行，公开常量会被丢掉，同一行里后面那个非公开常量也可能被收成公开。

2. `read_specification`（763–770 行）只收以 `singlefs_format::` 开头的路径。末段不是 format 常量名的别名（924–934 行）既不核也不报。

3. `parse_integer_literal`（668–672 行）只剥小写 `0x`、`0o`、`0b`。大写进制前缀会被看成不是整数字面量。

## 证明与最满盘

`raise_floor_ceiling`（`gc_ring_interval_proofs.rs:1419`）是 `roots.len() - 1`。`compaction_relation`（同文件 1464–1465 行）要求整理那一份的这个下标比不整理那一份恰多整理发布数。最满盘在 `singlefs-core` 的 `background_compute.rs`：`of_the_fullest_device_of_the_allocator`（546 行）用 `u128` 交叉相乘比占比，容量为 0 的盘不参加；`is_the_allocated_share_above_the_threshold`（590 行）是已分配乘 100 大于容量乘阈值百分比。挂载坏槽、截断步、unlink 步、准入与整理计划这一路对过的执行核里，没有新确认的算错。

## 四个包里读完的

`ReadLoggingBlockDevice`（`read_tally.rs:207`）、`FaultInjectingBlockDevice`（`fault_injection.rs:1110`）、`RecordingBlockDevice`（`harness` 的 `lib.rs:439`）把普通读、读坏之后的重读、这一刻读盘、两份自证通知和 `discard_at` 都转给内层。`discard_at` 交回内层的结局。2026-10-24 记录里包装器把 discard 改成 `Unsupported`、把专用读改成普通读，现行这三层不是那样。

冷启动只收冷启动读回、不收空发布，在 `model.rs:8829`。

崩溃态 oracle（`crash.rs:920` 的 `classified_oracle_violation_for_the_version_table`）用 `(txg, 实例)` 比走到的根和盘上已持久的最新根，更旧就记恢复到旧态。版本表里没有的根报没有文件时，看比它旧的最新一项还有没有文件。原地覆写撕成新旧各一半（`crash.rs:2309`）：只差一个字节时交回旧字节，注释与切片一致。段内状态数是各次写的态数之积减 1，再另加全部持久那一个（`crash.rs:2483`）。

显存账借草稿区（`gpu_memory_ledger.rs:1308`）在一张卡都没借到时交回错误，那条路上没有先记上的借据。`decide_booking_by_priority`（270 行）先比空卡上限，再按表序找第一张此刻放得下的。

部分没判在崩溃点计数里进不适用、不进红项（`crash.rs:1664`）。池级 checker 交回的仍是 `PartiallyJudged`（`image.rs:728`）。计数把这两档并进同一格，是这段写明的。
