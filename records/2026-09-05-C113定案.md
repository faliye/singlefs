## 定下来的东西

- 每个单元的类身份段加 10 字节写序 = (实例代号 4, 事务号低 48 位)。码 1 取写出它的事务；码 2 / 3 只在 checkpoint 的固定点写出，取那次 checkpoint 里已分配的最大事务号。数据单元头 91 → 105（另加 4 字节载荷 CRC，C104 的码 1 那一半），打包记录单元头 93 → 103。
- 实例表 = 码 3 打包记录类型 4，由根记录直接持有（根记录 127 → 186）。行 (实例代号, 恢复所选根的 txg, 从它的 tail 起连续重放施加的最大事务号) 只在恢复、实例切换与回退时写；已发布谓词按单元类分——数据单元 b ≤ T_pub ∨ n ≤ W，容器 b ≤ T_pub。
- 失败表封闭（四格），处置按失败的性质分两支，判别子是**对目标设备的固定落点做一次探针写**：写得进去走实例切换（挂载内的一次恢复：新代号、写行、重发在飞 checkpoint），写不进去走转只读到下次挂载；连续切换越过 N_switch = 3 也转只读。分配失败按发生在哪里拆三支：前台用户数据返 ENOSPC、后台可续做暂停并记进意图、只有切换自己的预留拿不到才转只读。收敛靠的是切换的第一步就是取号、而取号是全或无的写；作废一个 checkpoint 必须换实例代号，否则重发的号会让孤儿判成已发布。记录按事务号顺序追加 ⇒ 行的 W 是精确的前缀，不需要第二种记录表达洞。
- 现行版本 = 副本归并 → 已发布 → 对该根可见（诞生代号 + 祖先表）→ 该类的择新键最大（码 1 取写序、码 3 取 (诞生代号, 实例代号, 事务号) 三元）→ 被死亡写序不小于它的墓碑压住即死。回退是 D23 已定项 14 的显式例外，候选集 = 根环里按实例表仍有效的根。
- 分配记录释放时不删、改写「已释放 + 释放代」；清扫准入两支共有三条合取，水位只推进到根环最旧根的 txg；扫描重建的产物今天永久只读。
- 对立臂（写序只上码 2 / 3、extent 叶改码 3）量了两个数之后按态别否掉：它让 extent 叶变成权威态，给「索引是派生态」开例外。

## 这一轮学到的

- **把「不会发生」写成机制之前先问它怎么持久化**：第四版的作废行挂在造出孤儿的那次发布上，恢复行的结构只表达得了前缀。第六版的答案不是再加一种记录，是让失败本身把后续记录截断，前缀就够了。
- **一个字段是不是必要，看它在哪条行里被读**：根记录的「最大已施加事务号」只被回退行读，而回退行的 W 恒 0——字段整个删掉，第五轮反推腿 3.1 的实例维问题随之消失。
- **模型的随机轨迹一变就会踩到新坑**：第六版改了行编码，mixed_w2 seed=5 的轨迹变了，神谕臂丢 1。追下去是重生取「最小 inode 号」当容器号与同 txg 退役的身份撞车——第一版起就在的设计漏洞，靠模型的第五轮才露头。
- **「量出来的」也能是挑出来的**：E105 三个取样点上的 1.25–1.5 被写成结论，同一份产物里就有 1.000。连续 N 上的区段分析写进实验，结论改成「由树高定」。
- **对立臂要按它自己的定义建**：`wseq_meta_only` 量的是叶恒丢的臂 B，实验正文写了、判决没带上。第六版把判决改成不依赖那个数的态别论证，第七版再把「开例外」改成 D21 自己的重算性判据——inode 叶本来就算不回来、extent 映射是被臂 B 改成算不回来的。
- **「在飞 txg − 1」与「所选根的 txg」平时相等，坏的那一格才分开**：模型恒选最新根，两种读法在模型里恒等，第六轮反推腿指出来之后才给模型加了「最新根的槽坏了」那个世界。口径要按定义写，不按常见情形写。
- **兜底不能建在刚失败的那个能力上**：第六轮嫌「转只读到下次挂载」的可用性代价大，第七版换成挂载内实例切换；第七轮指出切换要分配、要写单元、要重写整条实例表链，而触发它的一大类原因正是这些做不到了，唯一的终止出口挂在取号上——那是这类故障里唯一不会失败的一步。第八版分两支：换来的可用性留给瞬时失败，收敛性留给资源性失败。**一条兜底的价值不看它省了多少可用性，看它在最坏的触发原因上收不收敛。**
- **不许在别人的定案下面搭便车**：第七版用一个括号说过半规则「与 D2 已定项 9 同一取向、不是新口味」，现查那一项讲的是第一版跑几块盘，而「降级期间允许写还是只读」在 D2 正文里明写是未定的产品决策。第八版把它立成 D2 已定项 13，代价与收益都写在那里。
- **抓不住的变异要删掉、不要留着壮胆**：「回退行可被恢复覆盖」这条变异一个测试都没红。追下去发现它的害处是回退不持久，而 E104 量的是重建结果与真值的差——重放把真值一起改了，这个度量看不见它。删掉变异、立成 C124，比留一条永远绿的检查诚实。第八轮又指出这笔账记粗了：「行不许被覆盖」这一半今天就量得出（断言挡下次数与行的三段没变），只有「重放下界截断」要等崩溃点重放，于是拆成两笔、第一笔当天还清。
- **兜底的射程要跟着写**：第八版把「分配失败」整类路由到转只读，看着收敛，实际把释放空间的路一起关了——池一满就永久只读，而删除要写墓碑、重挂又被预留合取挡住。一条规则的收敛性和它的射程是两件事，前者成立不代表后者对。
- **改了规则要回头看模型跑的是不是这条**：D18 已定项 10 的回收门量词放宽到「根」之后，模型的门还只看快照；追下去发现模型那道门是按 key 判的、规则问的是「还有没有根引用那个死掉的版本」，两者根本分不出新旧量词。规则与被度量的东西不是同一个时，「全规则臂恒 0」不构成证据。
