# 单元地址换算与写交集 Verus 补充

用户要求在有效性审计之后继续增加。本轮针对审计中的单元端点换算缺口：把乘法、末端加法和按单元号求交加入正式验证，并接到 core 的两个实际入口。出口是三个新增函数的证明通过、实际调用接入、边界回归及定向负例通过。没有把公开计划字段不变量、枚举适配或完整事务扩进这一轮。

## 代码与契约

- `file_range_proofs::checked_unit_byte_range` 没有前提。成功时给出精确的 `index × capacity` 和 `start + capacity`，失败当且仅当完整单元数学终点超出 u64；零容量返回空区间，恰好到 u64::MAX 可表示。
- `checked_bytes_in_indexed_unit` 没有前提，把上述地址换算与已有 `bytes_in_unit` 组合。外层 None 只表示地址溢出；Some(None) 只表示可表示区间内没有共同字节；Some(Some(...)) 的两个偏移指向同一文件字节，正长度同时受请求和单元边界约束，返回区间恰好等于逐字节交集。
- `lemma_rounded_size_bounds_written_unit_addresses` 证明：正容量、按整单元取整后的 size 可表示、index 小于覆盖 size 所需单元数，则该单元完整地址可表示。通过乘法单调性和分配律把准入上界传给单元端点。
- 已有无前提边界见证增加精确最大端点、加法溢出、跨单元求交实例，并调用新引理，证明其前提至少有一个具体见证。
- core `PartialWriteOfAFile::data_unit` 使用已验证的地址换算；`bytes_written_into` 直接使用已验证的组合求交。地址无法表示时两处显式 panic，可表示输入的结果保持不变。

开发中修正了一处规格元组的 int/u64 类型不一致，并补上组合函数的量词衔接和见证的非空交集推导；没有降低规格、提高 rlimit、增加 assume 或 external_body。

## 验证结果

证明义务从 **150 增至 154**：两个 exec fn、一个 proof fn，以及该引理中的一条 nonlinear_arith 子证明。完整 replay-prefix 的正式 proof 门禁为 **138 个条目、154 verified、0 errors**，`--rlimit 10`；另直接以 `--no-cheating` 验证整 crate，结果相同。

产品构建的 **100 个 MIR 条目**与 Verus 构建整段逐字相同，没有路径规整。Verus 发布包、六个依赖包源码指纹及两侧 Rust 工具链核对通过。没有增加可信声明。

新增 8 个必红变异，分别破坏地址乘法、末端容量、最大端点准入、乘法溢出拒绝、请求端点顺序、单元号、交集内容和引理的取整准入前提。连同前两模块已有的 34 行，**42 行全部被真实 Verus 拒绝，落点与登记一致，0 行 rlimit 用尽**。新变异中两行实际错误数为 2 和 3，已实测回填；其余新增行为 1。错误数只是最近观测值，正式门禁按错误落点判。

这两个模块的 **17 处 requires** 的 false 注入均在插入位置被拒绝，未检出入口空真。新引理另有上面的无前提调用见证，两个新增 exec 函数没有 requires。

新增两个核测试，以 u128 运算核对两级溢出和最大端点，以实际枚举的字节集合核对求交；新增一个 core 边界测试，核对最后一个完整单元、无法表示的末单元以及乘法溢出的单元号。Rust 库回归为 **core 371 项、replay-prefix 27 项，共 398 项通过**。core 新边界测试在 release 构建也通过。

## 发布配置对照与范围

曾怀疑旧实现可能在 release 中回绕；实际对照没有支持这个说法：项目 `Cargo.toml` 已设置 `[profile.release] overflow-checks = true`，临时恢复旧算术后，相同 release 边界测试仍通过，因为原算术也会 panic。临时改动已在 finally 中还原。**本轮不宣称修复了现有发布配置下的回绕 bug**；增加的是被证明的地址检查、组合求交和显式的拒绝路径。

取整准入引理只管 size 覆盖的单元；size 之外保留的已有单元需要文件状态提供界限。core 的 expect、公开字段一致性、来源枚举转换、实际读写和完整事务仍未获得端到端证明。新增函数的地址失败有显式返回，core 对非法单元的 API 行为仍是 panic，没有改成静默空交集。

静态覆盖检查在本轮模块没有缺口，但仍报告上一轮记录的九处其它缺口（unlink 五个引理，core 的两个 block_device invariant 块、copy_bytes_into 和 crc32_castagnoli）。本轮没有宣称全仓门禁通过。

## 复现

本机固定副本 `/tmp/singlefs-indexed-write-review-ejb2j4wq`，第二台 `/tmp/singlefs-indexed-write-review-O0MnqzUD`。第二台用上一轮已核对的同一 Verus 发布包，经原有内存包装运行，保留本机资源队列。

正式命令为 `python3 scripts/gate/verus-proof-check.py proof . --threads 4 --jobs 4`，must-red-worlds 与 vacuity 以 list-items 精确点名上述两个模块。结果在 peer-proof.log、peer-must-red-worlds.log、peer-vacuity.log、peer-toolchain.log 和 peer-results.json，已取回本机副本。门禁判法单元指纹因已有 globals-lookup 拒算，全部现判，没有复用旧结论。

Rust 回归使用 `cargo test -j 2 -p singlefs-core -p singlefs-replay-prefix --lib --quiet`；release 指定测试 `partial_write_unit_addresses_reject_overflow_in_all_build_profiles`。发布配置的旧算术对照保存在 release-before-check.log，其通过结果按上文解释，没有伪称为检出错误。
