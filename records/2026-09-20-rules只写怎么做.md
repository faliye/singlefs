# 规则只写怎么做：立规矩、立门禁、回扫本仓七份

**起因**：用户指出 `.claude/rules/` 开始腐烂——正文里混进了「用户某天定」「实测（日期）」这类时间线与说明，
干扰模型读取与判断；并要求上游 SOP 立自检与对下游的约束门禁，严格检测。

## 立了什么

| 落点 | 内容 |
|---|---|
| `rules/rules-discipline.md`（上游，新） | 第四类文档的纪律：正文只写怎么做、做什么不做什么、推荐怎么做、什么规则在哪里；判据留下、论证删掉；搬出正文的东西不另立落点，共享规则的历史照旧进 `CHANGELOG.md` 一版一节；指向历史的链接要带劝阻句 |
| `scripts/rules-lint.sh`（上游，新） | 七条判据：记录小节、论证小节、带日期的行、解释性段落、解释性半句、词法说明、没带劝阻句的历史链接。判据从本仓 71 号门禁（agent 定义只写怎么做）移植并加了后两条 |
| `scripts/fixtures/rules-lint/`（上游，新） | 14 个判别力样本：每个红样本只犯一处，绿样本踩在四条豁免的边界上（「」里的日期、反引号里的阈值日期、表格行、排除清单生效） |
| `scripts/gate.sh`（上游） | 两个阶段：「规则纪律」扫上游自己的 `rules/`，「规则纪律（项目本地）」扫项目的 `.claude/rules/`。两个阶段都把 `CLAUDE.md` 一起扫——它和规则一样每次开工通读 |
| `.claude/rules-lint-exclude`（上游，新） | 上游自己 14 份规则还没回扫，逐个登记，改完一个删一行 |

**下游怎么被约束住**：项目装了这一版 SOP 之后跑 `gate.sh`，「规则纪律（项目本地）」阶段自动扫 `.claude/rules/` 与 `CLAUDE.md`，
不需要项目自己在 `.claude/gate.d/` 里接。项目要绕开它，只能改副本，而副本改了版本戳会对不上。

## 没做的与下一批

- **`skills/` 与 `agents/` 已纳入射程**：本仓 29 份（agent 定义 + skill 桩 + `CLAUDE.md`）一次过闸，
  零命中——71 号门禁（agent 定义只写怎么做）早就把那一半守住了。上游的 `skills/crash-test`、`skills/decide`、
  `agents/INDEX.md` 各有一两处，这一轮一并清了。
- **本仓 71 号门禁还没退化成调用共享脚本**：判据同源、两处定义，下一轮把它改成 `exec` 共享的 `rules-lint.sh`。
- **`rules-lint` 的判据只有中文词表**：en / ja 仓显式报未实现（退出码 77），不假装通过。要在别的语言上生效，
  先给它写一套词表并配判别力样本。

## 一处要记住的坑

派出去的四个 agent 里，两个给编号凭空补了分项号（`D17` 补成「D17（实现分层与第三方管道） 已定项 6」、
`D15` 补成「D15（格式冻结政策） 已定项 7」）——搬运的活被做成了改写。
`rules-sweep-audit.py` 抓不到这种（它只查「丢没丢」，不查「加没加」），是逐处读 diff 才发现的。
交搬运类的活出去时，验收要同时看「丢了什么」和「多了什么」。
