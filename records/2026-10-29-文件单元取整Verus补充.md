# 文件单元取整 Verus 补充

接用户“继续”，补齐上一轮明确未覆盖的 size 到单元数转换及截断整单元取整准入。

## 修改及证明含义

在 `file_range_proofs.rs` 增加三个产品函数与一个引理：

- `units_covering_size`：正容量下，零 size 返回 0；非零 size 通过 `(size - 1) / capacity + 1` 计算，避免 `size + capacity - 1` 的中间溢出。证明 count 不溢出、count × capacity 足够且少一个单元不够。
- `units_for_sequential_write`：零 size 返回 1，非零时沿用最小覆盖计数；core 的 `data_unit_count_of_a_sequential_write` 直接调用，读侧单元数核对与截断目标数量通过原有调用链共用。
- `rounded_size_fits`：覆盖计数乘容量的数学结果在 u64 内当且仅当放行；零 size 的准入按 0 个单元计算。core 的 `target_size_rounded_up_to_a_whole_data_unit_fits` 直接调用。
- `lemma_covering_units_are_monotone`：有序 size、正容量下单元数单调。

上述四个函数加一条 nonlinear_arith 子证明，新增 5 条 Verus 义务。本轮基线为 138，整 replay-prefix crate 实测 143 verified、0 errors（Verus 0.2026.09.20、--no-cheating --rlimit 10）。spec 中乘法是数学整数，不能误读为最后一个单元的结束地址必然能用 u64 表示；这正是独立取整准入核要检查的边界。调用方仍负责提供正容量，产品值来自数据单元格式。

## 回归与范围

新增两个核测试分别以逐字节触及的单元集合、u128 向上取整和乘积作参照；新增一个 core 包装层测试，钉住真实净荷容量 32634 对应的最大可表示整数倍及后一字节。

`cargo test -p singlefs-replay-prefix --lib --quiet`：21 passed。两 crate 联合 --lib 测试的 core 编译被共享工作区其他改动阻断：logged_operations.rs、pointer.rs、records.rs、root_record.rs 共 14 处找不到 every_byte_is_zero、copied_into_a_vector、copied_into_an_array、copy_bytes_into 等辅助函数。本轮没有修改这些文件。随后 bytes.rs 的并行修改解除编译问题，重新运行 `cargo test -p singlefs-core --lib --quiet` 得到 368 passed，包含新加的包装层边界测试；最终两个 crate 合计 389 项 Rust 测试通过。

继续沿用明确限定的验证范围：在临时副本 `/tmp/singlefs-unit-rounding-review-8944195w` 固定源码与门禁脚本，只在副本的 crate 登记、信任清单、trait impl 欠账清单保留 replay-prefix 范围，正式工作区不删其他 crate 的登记。定向检查覆盖整个 file_range_proofs 模块的新旧证明与反例。单元地址乘加、发布 I/O、完整 core 形式化门禁和 MIR 比对不在本轮通过结论内。

定向门禁结果：文件区间模块 13 个函数逐项证明通过（其中取整函数含额外 nonlinear_arith 义务）；10 处 requires（包含子证明前提）的 false 注入全部被拒绝，未检出入口空真；20 个新旧必红变异全部被拒绝且落在登记函数处，无仅因 rlimit 用尽而红的项。三个检查均现判、无缓存复用。

5 个新变异的实际证明错误数均为 2，已回填表中观测值，landing 不变。交回前核对本轮两份 core 调用文件、file_range_proofs.rs 与必红表均与验证副本一致，git diff --check 通过。
