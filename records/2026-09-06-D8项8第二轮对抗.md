## 命中一：② 只定了「住哪」，没定「什么时候写」——两条腿独立撞到

**本地腿逐字**：「The instance id mechanism increments once per mount while the tree ID counter
requires multiple increments per mount. ... This results in duplicate tree IDs.」
**找反例腿**独立构造出同一处的崩溃时序。

主 agent 现查坐实的三条：

| 现查 | 原文 |
|---|---|
| 实例代号取号一次、用在动单元之前 | `18-块里携带什么信息.md:697`：「再取新代号 = max(…) + 1 并写进那个集合里的每一份超级块、全或无……**之后才动任何单元**」 |
| 段四的同组字段 journal tail 是**滞后**写的 | `23-journal的角色与格式.md:777`：「**只在 checkpoint 持久之后写一次，不上 fsync 路径**」 |
| 超级块自己的更新协议还没定 | `22-单元原子性怎么合成.md:434`：「**有两处不在这条定案的射程里**：超级块自己的更新协议要写哪些字段」；D22（单元原子性怎么合成） 未定项 9 仍未定 |

⇒ **段四「运行时水位」里其实住着两类字段，判据是它落盘的时机相对于「用它」是先还是后**：

| 类 | 例 | 落盘时机 | 滞后了会怎样 |
|---|---|---|---|
| **完成标记** | journal tail | 可以在事后 | 有全环扫描 + 幂等重放兜底，滞后只是多扫一段 |
| **分配水位** | 实例代号、树 ID 水位 | **必须在用它之前** | 发出了一个没人记得的号 ⇒ 下次重发 |

实例代号是先落盘的，树 ID 水位被归进同一段却没继承那个时机。
而 ② 明确否掉了树 ID 的等价兜底（「挂载时从树表扫最大值 + 1」被回退打穿）
⇒ 它既没有先落盘、也没有兜底，**两头都不占**。

**这条打中的是 ② 的细则，不是 ② 本身**：住超级块、多副本取 max 仍然成立，
缺的是「什么时候写」。

## 命中二：① 的诞生 txg 在同一 checkpoint 窗口里不是单射

**找反例腿**：D16（发布语义） 允许攒批（`16-发布语义.md:65-66` 逐字「checkpoint → 同一窗口内的 K 批只走约一次」）
⇒ 同一个头在一个窗口里连建两个快照，两条树表条目的诞生 txg **相同**。
而 D5（快照 / 空间记账机制） 销毁时要「把它的 deadlist 合并到**下一个更新的那一侧**」（`05-快照-空间记账机制.md:9`）
⇒ 平局时没有判别子。同一类危险 D5（快照 / 空间记账机制） 已经在 reflink 那一格标过：
「两个引用的 birth 完全相同 ⇒ 第一次摘除就判『立即释放』⇒ 另一个引用悬空 ⇒ **数据丢失**」（`:80-82`）。

## 命中三：树 ID 水位缺第二路见证

实例代号有两路见证——I-7.7（超级块实例代号不低于根环） 逐字要求它「≥ 根环」里全部根记录的实例代号，
而根记录**带实例代号**（D22（单元原子性怎么合成） 已定项 7）。树 ID 水位没有对应的第二路：根记录不带它。
找反例腿指出了这处不对称但没把它构造成独立反例，主 agent 现查 I-7.7（超级块实例代号不低于根环） 与 D22（单元原子性怎么合成） 已定项 7 坐实不对称成立。
