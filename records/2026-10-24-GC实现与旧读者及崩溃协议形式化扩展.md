## 实现对应关系

- `singlefs-core::compaction_plan::choose_region` 负责从分配记录、扫描结果与排除集合形成核输入，实际选段调用 `choose_compaction_segment`。最小活槽数与平局取最早段直接由已经验证的同一段可执行代码决定。
- `plan_batch` 将扫描分类与映射 key 身份转换为核输入，调用 `plan_compaction_batch`，再将返回的下标转换为真实 key 与源落点。`CompactionBatchUnits` 保证批大小至少为一；输入的可搬 key 互异仍由普通 Rust 断言检查。
- 原选段与计划算法保留在 `#[cfg(test)]` 的独立参考实现中。选段同时比较参考、产品适配层和按形状直接构造的核输入；计划比较产品与独立 filter/take 算法，避免接核后只与自己对拍。
- `PoolAllocator::reclaim_released_records_up_to` 调用新核 `released_record_can_be_reclaimed`，契约精确描述 `released && generation <= floor`，没有改变复用门槛。
- 迁移 14 个产品变异锚点，避免原锚点留在仅供测试的参考算法上。变异仍由原产品测试判错。

以上把纯判定实现与证明合为同一份代码。输入转换、地址/跨度运算、分配记录与盘面的一致性仍是普通 Rust；其小域对拍不能替代一般输入上的精化证明。

## 新增协议与定理

新增核：[gc_crash_proofs.rs](../crates/singlefs-replay-prefix/src/gc_crash_proofs.rs)。状态包含持久字节表、当前映射、持久根映射及旧读者映射集合。逻辑 key 与地址为 u64，字节为任意序列；槽数、key 数和历史长度没有固定枚举上界。

| 步骤 | 允许条件及效果 |
| --- | --- |
| Write | 仅向当前根、持久根及全部读者都不引用的槽写任意字节，包括撕裂内容 |
| Relocate | key 存在，目的字节已经在持久表中且等于源字节，才更新当前映射 |
| Checkpoint | 将当前映射保存为持久根 |
| AcquireReader / ReleaseReader | 取得当前映射快照，或释放一个有效读者 |
| Reclaim | 仅删除所有根与读者都不引用的槽 |
| Crash | 当前映射恢复为持久根，进程内读者消失，持久字节保留 |

九条新增证明义务：

1. 不被映射引用的槽写入/删除保持该映射的所有读取。
2. 每种允许的步骤保持当前根、持久根和所有留存读者的逻辑读取。
3. 对任意有限合法历史，用历史前缀长度归纳，证明每个状态保持上述不变量；不是固定步数的有界枚举。
4. 崩溃恢复精确返回持久根且不改盘面，重复恢复幂等；Checkpoint 后的恢复返回保存时的当前映射。
5. 任意旧读者仍引用某槽时，禁止回收和覆盖该槽。
6. 目的字节与源不一致时，禁止发布搬迁映射。
7. 产品可执行释放代判定等价于其规格。
8. 在 `floor <= reader_txg < generation` 的前提下，该记录不能被回收。
9. 非空见证：真实构造一个 key、一字节数据、一个旧读者，依次复制、搬迁、保存根；旧读者存在时源槽不能回收，释放读者后才可回收，并验证崩溃分支。

新增 13 个必红负例：九条义务各一个入口假断言，以及忽略旧读者、把易失映射当恢复根、绕过目的字节核对、绕过释放代四个语义变异。所有核沿用 `--no-cheating --rlimit 10`，不引入 admit、assume 或 external_body。

## 与真实发布/恢复的连接边界

实际发布序列见 `transaction::persist_publish_writes`：单元写入 → Barrier → journal 写入 → Barrier → 根记录 FUA → 系统配置轮换 → Barrier。新模型的持久表表示屏障后可依赖的数据；Relocate/Checkpoint 表示完整记录被接受或根已经持久，不能把每次普通写入直接当成这两个原子步骤。

**本轮新增的是 GC 协议的完整步骤分类与任意有限历史安全证明，尚未完成整个文件系统产品的端到端崩溃恢复证明。** 下列条件必须保持显式，不能通过模型证明销账：

- 块设备屏障/FUA 的实现满足持久化契约；撕裂根、journal 和单元如何由真实校验及解析器拒绝。
- `recovery` 的择根、扫描、前缀重放与新状态转换的组合精化；旧核已证明各自的契约，但这里没有自动得到它们与设备状态的连接。
- 真实分配器算出的 floor 始终不超过所有受保护读者/根的版本，以及所有可读版本的引用均进入保护集合。新比较核及条件定理不能单独建立这些前提。
- 多槽 span、双盘副本、隔离、共享快照、不同逻辑版本之间的用户写入、错误重试与回退规则尚未全部纳入新模型。当前 GC 模型比较同一逻辑版本的搬迁前后；不能据此推出任意混合用户事务历史安全。
- 模型给出安全性，不保证恢复一定成功、设备最终响应或 GC 最终完成。

产品适配层现在会额外构造核输入向量，计划还会建立 key 身份表；语义回归已安排验证，性能影响未测量。
