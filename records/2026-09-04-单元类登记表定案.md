# 2026-09-04 单元类登记表定案：D18 的第 11 分项三轮对抗后收口

用户给的任务只有一句：D18 的第 11 分项（单元类型标签的值域，当时未定）是 inode 打包、墓碑、抗老化三条线的公共前置，
而且是唯一一条进 AAD 的，解决它。这一轮把它定成了 D18 已定项 11，配了一个计数模型（E102），
跑了三轮三方论证（九条腿，每轮换攻击面），落了一条决策、五条历史、三条新不变量、十一笔新欠账；随后按用户的两问补了依据追溯与一个实验（E103），并把五元组的拆分定了案。

## 问题长什么样

单元类型标签在仓里有六处互不相同的清单，没有一处是登记位；D18 已定项 8 在用一个不在任何清单里的值「墓碑」；
已定项 10 把墓碑载体改成打包共享单元之后，「五元组刚好够指认它」这句就破了——五元组只写得下一个对象 ID。
它进 AAD，AAD 组成是 day-1 永久契约，所以这一格不能拖。

## 怎么做的

1. 先写提案（登记表 + 打包记录单元独立成类 + 标签宽度与位置），同时建 E102 把「四处清单映不映得过去」「域分隔靠什么成立」
   「E83 / E84 / E98 的数会不会动」做成可钉绝对值的东西。E102 随提案改了三版常量，判据与钉的数一直没动。
2. 三轮三方论证。本地腿三轮闸都绿（英文提示）。每轮换攻击面：
   引用链与已定条款 / 反推 / 反例 → 实现与恢复 / 格式永久性 / 反例 → 落地与门禁可判性 / 改法复核 / 反例。
3. 每轮判决之后改提案再放下一轮。三版提案与九条腿的原样输出都在 `research/prompts/` 与 `research/results/`。

## 三轮各打掉了什么

第一版的骨架里有四处是错的：
「整单元头校验和罩全部记录」——头校验和只护头，整单元校验和住父指针，扫描期没有父指针（两条云端腿各自独立打中，E76 早就实测过同构的失败）；
「诞生代号同时就是装载代际」——E84 里一个代际跨十次发布，两者差一个倍数；
「记账单元由树 ID 分」与 D9 day-1 第 ① 条字面相反；
五元组的分字段宽度被当成已定事实写进背景材料，而它是 verification-build 第 8 问里「报给用户」的格。

第二版把打包单元的身份改成发布无关的（容器号, 容器出生代），加了载荷校验和；第二轮又打掉四处：
「多版容器取诞生代号高者」正是 D18 已定项 1 否掉的用途；载荷校验和的落点要求（头校验和覆盖范围全仓没定过）；
声明长度在两类单元里被写成了两种口径；compat_ro 对墓碑类不成立——跳过墓碑就让已删 key 复活。
还量出一笔账：fsync 交织的删除负载下，开放容器每次发布重写一次，比 E83 的单次批量口径贵约 50 倍。

第三版把择新规则改成按现行版本谓词判，第三轮反推腿又追到那个谓词的上游：它的输入是派生态的分配记录，
扫描重建那一刻拿不到；E59 乙臂里的「记账」在源码里是一个 `live: bool` 神谕，不是机制；
三条已定条款对同一个 E59 结果给了两种归因。这一格不是本项造的，但本项是第一个把它踩实的使用者，
立成最上游的一笔欠账 C113。同一轮还翻掉了「新增打包记录类型 compat_ro 为下限」（今天登记的两个类型都不满足它的限定，默认档改成 incompat），
并把头校验和的覆盖范围从绝对字节区间改成公式。

不采纳的一条：反推腿说容器索引独占 MAC 撞 D21 硬约束 6。MAC 由密钥、密文、AAD 重算得出，是派生值；
重算后的认证力等于对被扫载荷的信任，正是 D18 已定项 5 的降级语义，对容器索引与 extent 树里的数据指针一视同仁。

## 定下来的

登记表是唯一登记位：码 0 无效、1 数据单元、2 索引节点、3 打包记录单元、4–15 保留内容类、16–18 自证结构占位、19–31 保留自证、32–255 保留；
码 1–3 第一个镜像写出时冻结，16–18 加密开机时冻结，码用过不回收。标签住共同前缀偏移 6，偏移 7 是 8 个 flag 位（恒 0，非 0 拒收，赋义要 incompat）。
打包记录单元类身份段 51 字节、头 93；身份 =（出生树, 打包记录类型, 容器号, 容器出生代）；AAD 变体五项与数据单元五元组同构但树维取出生树。
四条装载纪律；容器索引是物理指针唯一持有者；第二级登记表（墓碑区间记录、inode 记录保留），新类型默认 incompat。
头校验和覆盖范围与声明长度口径由本项定。E83 / E84 / E98 的 583 / 233 在头 93 下不动。

## 留下的

十一笔新欠账 C103–C113，最重的三笔：容器索引无落点（C103）、扫描路径上码 1 / 2 的载荷完整性无自包含证据（C104）、
扫描重建时多版单元的现行版本判定无输入（C113）。五元组的分字段宽度（1 + 8 + 8 + 8 + 8）当日由用户定案。
inode 路 ① 的更新代价由 E103 实测：单次更新是住索引叶的 1.25 到 1.5 倍（两侧都算脏叶加全部祖先），批量散开 1.3 到 1.85 倍，全量重写相同，stat 读 2.25 到 2.5 倍字节；第二轮正推腿的「约 3 倍」只数了叶子，作废。数写回了 D8 第 6 分项 的比较表，路 ① 与路 ② 哪个该选仍未定。
