# CLAUDE.md 去冗余（2026-09-17）

**为什么有这一份**：用户 2026-09-17 要求解决项目 `CLAUDE.md` 的冗余。CLAUDE.md 每个会话、每次派 subagent 都整份进上下文（实测两次派发各 113,767 与 104,464 token，`records/2026-09-16-subagent拆分提案.md` 第十二节），而它 `@` 引进来的规则也是整份进同一个上下文；CLAUDE.md 里再复述规则，就是同一段话在同一个窗口里出现两次。CLAUDE.md 按设计纪律不留历史节，这次删了什么记在这里。

**结果**：176 行 → 97 行（`git diff --numstat`：删 112 行、加 33 行）。`@` 引用两张清单一行没动。

**第二步（同日，用户在做的过程中补了方向）**：「按照现在的逻辑 claude.md中不需要像以前那样什么都知道然后调度，它只需要知道什么时候调度哪一个agent就好了」。据此在开头加了「什么时候派哪个 agent」一节（留在主 agent 的活、八类活各派谁、按什么次序），事实表里只由某个 agent 用、且它的定义已经写了的四个脚本行挪出去。

**第四步（同日）**：用户定「写代码按活的形态分」，调度表「改 `crates/`」拆成两行：条款已定、改动有界的派 `implementation-writer`；探索性的、要用户边看边拍板的由主 agent 自己写（同一份计划第九、十六节）。
