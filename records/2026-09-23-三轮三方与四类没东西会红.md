## 二、四类「没有任何东西会红」

### 其一：条文与实现说反话，一天查出三例

- **回退候选集**（C493）：D23（journal 的角色与格式） 已定项 14 的候选集条文整段 `树表` 零命中，而实现拿 `tree_table_has_no_entries` 当第三条排除理由。
- **步骤种类**（X6）：D17（实现分层与第三方管道） 已定项 2 逐字列五种，而 `StepKind` 是六成员的封闭枚举、字节表也按六种写。第六种有用户 2026-09-19 的定案撑着，**只是没写回登记位**，而同一条分项第 3 条又写着「登记位只有一处」。
- **每区槽数 S**（C506）：D22（单元原子性怎么合成） 已定项 1 逐字写「具体取多少不是格式决策——格式承诺的是『S 是系统配置字段 + 挂载时判区间』」，而实现是编译期 `pub const`、全仓零区间判、零登记位。

三例里有两例的病根是同一个：**定案落不到登记位**。据此新立门禁 82 号（条文列的集合与代码里的枚举逐个对上），两个方向都自证过会红。

### 其二：检查在合法状态上误报，或在真洞上失声

- **I-3.1 误报**（Z3）：残留记录那条流 12 个状态合法而判红。判据错在 `walked` 只由根环里读得出的根贡献。四个候选改法里三个交不出「改完仍会红」那一半——其中两个被一份纯泄漏坏镜像当场打穿，改完连仓里原有那份坏镜像也一起哑。
- **记录核对器失声**（C507）：收口表登记的候选是「被更晚**已持久**的同位置写盖掉的不算缺席」，而落地的 `written_over_later` 只看有没有更晚的写压在同一段、不看那次写持没持久。更晚那次写没落盘的崩溃状态里，早先那个单元是真缺席，而检查一声不吭。当天收严完成，两半读数都量了。

⚠️ 还有一条更根本的：**层 0 段枚举根本产生不出记录核对器第二条判据要判的状态**——六条流上同时含根槽写与单元写的段都是 0 个，「单元写 + journal 记录同段」也全是 0。那句「两条判据恒 0」的断言因此是**结构上到不了**，不是语义上保证。

### 其三：装置与被测实现共用代码，一起错而逐格相等

攻方腿在副本上只改一个共用常量（`ROOT_RING_SLOTS_PER_REGION` 8 → 4），E156（alloc-basis 四条岔路的代价数） 的代价数整体平移（484 → 370、24 → 12、96 → 85），而 **26 行输出逐字不变**——其中包括装置里唯一那条钉绝对值的断言与三行 checker 判定。

`.claude/rules/implementation-first.md` 第 4 条末半句「装置的数与实现对不上时两边都查」**预设两边会对不上**；共用常量之后这个触发条件被消掉了。定义里那三条限制逐条挡不住：`use` 就是读、装置没改 core 与 checker、那一维上没有断言可红。

### 其四：闸自己认错了东西

- **点名闸认「提到」不认「判过」**（C508）：门禁 56 与 72 判「点名了没有」用的是整份判决的子串匹配。写判决时为了说明「这份共用文件里没有那一句」而提到某个路径，72 号当场把它算成「有去向」。
- **字词损坏闸的两处误判**（C505）：把 Rust 的双冒号路径记号当成标点粘死后词，把「实词加 ly」的副词拆成两半。两次都让整轮抽样作废重跑。
- **局部标号裸写没人拦**（C509）：轮内标号与决策内分支标号与编号同形，每份 kb 靠自己的白名单把它们从「编号要带简称」那条检查里摘出去 ⇒ 裸写不会有人说。仓里已经有一次跨轮撞车。

## 四、那条零故障历史走到底了

用户定案「走到底」之后，一条拒绝链整条打通：R2 → R1 → R4 → 三处写死的前提 → R8。端到端用例绿：建池 → 可写挂载 → 不写文件 → 正常退出 → 再可写挂载（写行）→ 写文件 → 冷启动读回来逐字节相同。30 条变异全抓、0 无效、0 没红。

**这一轮新打中的两处条款空白是崩溃注入判出来的、不是读代码推的**：

- **回退到无文件那一版之后诞生代怎么接**（C511）：拿掉排除之后注入当场判出 I-9.14（树表条目的诞生 txg 跨根不变） 跨根不一致加 I-9.10（对象出生代三处一致） 不符。机理是那之后只剩「再发一次第一个文件版本」一条路，而那一次走重新建树、重新发出生代。
- **树表 0 条那一版上被换下的实例表记在哪**（C512）：那次释放只住内存（这一版没有分配记录树），重开之后它成了空闲槽，而环里 txg 更低的候选根还指着它。**这是 R8 真实的依据**——2026-09-22 判决给它写的「零故障不可达」在 R1 修完之后不再成立。
