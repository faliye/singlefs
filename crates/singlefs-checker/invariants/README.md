# 不变量清单

**checker 是这份清单的可执行形式。** 这份清单每加一条，checker 就要加一个检查。
两者不同步的 commit 一律不收（见 [format-evolution.md](../../../.claude/rules/format-evolution.md)「硬约束」）。

这份清单按类拆成本目录下的 9 份文件，README.md 只放开头说明、状态、条数登记与「待补」；
每条不变量必须写成**可判定**的形式——能对着一个镜像回答"成立/不成立"。池级 checker 对一条不变量的判定有四种：成立、不成立、不适用（必须带理由，不许静默算成立）、部分没判（`InvariantVerdict::PartiallyJudged`，`crates/singlefs-checker/src/image.rs`）。部分没判是判到的那一部分都对得上、射程里另有一部分这张镜像上判不了，说明逐条列出没判到的是什么；它不是红，也不是成立：崩溃点重放与崩溃放量把它算成不红，崩溃点重放计数并进「不适用」那一格，GPU 判器只记违例位、它在那一侧与成立、不适用同是 0。报它的不止一条，逐条见各行（例：I-5.4（分配记录罩住的槽互不相交）、I-5.5（从 mkfs 水位建树那一版的 t1 落点）、I-9.28（全部可读根里同一树 ID 的诞生 txg 相同））。
写不成可判定形式的，说明还没想清楚，不许进这份清单。
