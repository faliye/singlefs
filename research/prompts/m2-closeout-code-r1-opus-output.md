## Z3　挂载入口的静默出错与坏盘

### Z3-A　挂着之后的入口认不出「换上去的空盘」

**条款**。只有可写挂载那一处写了逐盘核，`.claude/kb/decisions/18-块里携带什么信息.md:314`：「两个系统配置槽一份自证过的都没有（校验和过、fsid 与本池相同），即这块盘不」（原句接着是「可见」，那一段带内层引号，这里截在它前面）。挂着之后收盘表的入口（抬 F、准入抬 F、推一串、正常卸载、管理员回退、会话发布）怎么核盘表，kb 里没有条款。代码自己的文档说它们「照可写挂载同一套核」，快照 `mount.rs:2947-2956`。

**代码**。
- 这几个入口只调 `caller_inputs_agreeing_with_the_disk`（快照 `mount.rs:2957`）。它判三样：重复身份、择系统配置、参数与盘表比对。盘表那一项是 `device_table_disagreeing_with`（快照 `mount.rs:2806-2854`）：逐块盘取它自证过的系统配置槽，比本盘设备号（快照 `mount.rs:2831-2851`）。一块盘上一份本池 fsid 的自证槽都没有时，比对的集合是空的，这块盘一条不一致都报不出来。
- `DeviceTableDisagreement` 的文档把这一格交了出去，快照 mount.rs 第 368–369 行原文是：“一份自证过的槽都没有的盘不在这里报（可写挂载在取号之前的逐盘核里报 `SelectedVersionLackingOnDevice::NoSelfVerifiedSystemConfiguration`）”。接手的那道逐盘核（快照 `mount.rs:2709-2714`）只在可写挂载的 `establish_instance` 里调（快照 `mount.rs:3115`）。挂着之后的入口没有它。
- 会话发布只比身份，不读盘（快照 `mounted_session.rs:215`）。

**历史**（`opus_r1_z3_entries_with_a_substituted_device.rs`，4 条用例全过，`logs/run-z3a.log`）：
1. 两块 4 GiB 内存稀疏盘上 mkfs、取号、暖机、第一个文件（txg 3），会话里覆盖写两次（txg 4、5）。
2. 盘表 `[(盘0, 盘 0 的拷贝), (盘1, 一块全零的空盘)]`，调 `unmount`。
3. 原样输出：
   ```
   Z3A unmount_blank accepted=true outcome_is_err=false writes_dev0=28 writes_blank_dev1=28
   Z3A unmount_blank read_only_after chosen=(1,6) effective=(1,6) floor=5
   Z3A unmount_blank checker_violations_after=4 first=Some("I-2.1: 树表单元 在盘 1 槽 50284 的那一份与位置条目里的校验和对不上")
   Z3A unmount_blank writable_after err=WritableMountRefusedByDevicesWithoutTheSelectedVersion { selected_version: RollbackTarget { instance: InstanceGeneration(1), checkpoint_txg: CheckpointTxg(6) }, ...
   ```
   卸载报成功，空盘收到 28 次写（系统配置、单元、记录、区域 1 的根）。拿盘 0（卸载之后的样子）和没被碰过的真盘 1 再挂：只读挂载落在 (1, 6)，池级 checker 红 4 条（真盘 1 上没有这一串的那一份），可写挂载被逐盘核拒掉。用户拿到的是一次「做成了」的卸载，之后这个池的元数据只剩盘 0 一份，而且再也可写挂不上。
4. 同一个起点，`roll_back_by_a_forward_publish` 目标取现行那一版 (1, 5)：`rollback_blank_to_current ok=true err=None writes_blank_dev1=12`。目标取 (1, 3)：被复活集逐盘验拒了（`ResurrectedUnitCopyUnreadableOrMismatched ... device: DeviceIdentity(1)`）。这一次是那一判顺手挡住的，不是盘表核挡的。
5. 会话发布（`the_session_publishes_with_device_one_replaced_by_a_blank_disk`）：`Z3A session_blank ok=true err=None blank_written=true`。
6. 没打中的两形：
   - 别的池的盘 1（fsid 首字节翻转、mkfs 过）换上去，卸载被择系统配置拒：`Z3A unmount_foreign err=Recovery(SystemConfigurationsDisagree)`，一个写都没发。两块盘上各有一份自证过、fsid 不同的系统配置，择的那一步就对不上。
   - 空盘换上去后 `raise_rollback_floor` 被读根环那一判拒（`RollbackFloorCeilingRootRingSlotStillBadAfterOneReread { ring_slot: RootRingSlot { region: 1, slot: 0 } ...}`），是侧面挡住的。

**四问**。
- 分不分辨臂：这一轮是代码轮，没有臂。它分辨的是「挂着之后的入口带不带逐盘可见核」这两种实现。
- 系统当时看不看得到判别它的东西：看得到。入口第一步就读每块盘的两个系统配置槽（`device_table_disagreeing_with`），「一份自证过的都没有」就在它手里，可写挂载拿的也是这一个量。
- 满足判据的哪个分句：kb 里挂着之后的入口没有条款。按共用问句，它是「替没写的条款做了选择」：代码自称「照可写挂载同一套核」，实际只照了前三样，D18 已定项 11 那一行的「不可见」一支没带过来。今天没有会红的东西钉着：A1b 那组用例只造了「重复身份」「盘 0 的拷贝标成盘 1」「多一块盘」「换参数」四形，没有空盘这一形。
- 改法在打中的格上还中不中（跑前条款没给改法；下面是我提的，**只在我的模型上想过、没实现、被攻过零轮**）：

| 改法 | 卸载空盘 | 回退到现行那一版空盘 | 会话发布空盘 |
|---|---|---|---|
| 甲：`caller_inputs_agreeing_with_the_disk` 里，每块交进来的盘要有至少一份本池 fsid 的自证系统配置槽，没有就拒（与可写挂载逐盘核第一支同一判） | 修（推的） | 修（推的） | 不修：会话不调这个函数（推的） |
| 乙：甲，加上会话每次发布之前也读两槽核一遍（A1b 报告第 65 行提过、规格没写） | 修（推的） | 修（推的） | 修（推的）；代价是每次发布每块盘多读两槽（推的，没量） |

**推翻条件**：快照副本上 `unmount_with_device_one_replaced_by_a_blank_disk` 里 `accepted` 为 false，或空盘上的写数为 0。

## Z1　回退改成向前发布

### Z1Q-B　新根不引用的隔离单元：条款字面要释放，代码留着已分配

**两边原文**。
- D23 已定项 14 的表格，`.claude/kb/decisions/23-journal的角色与格式.md:379`：「cur 那一版的账里仍分配、而 new 不引用的落点，释放代 = new 的 txg」。
- D19 已定项 5 硬规则 1，`.claude/kb/decisions/19-块指针的结构与宽度预算.md:112`：「另一块盘上那一份对得上也一起留，各盘的账保持对称」。同一行前面说，任一份核出对不上，这个单元在每块盘上的分配记录都留在已分配、不改成已释放。

**代码**。回退只释放「现行那一版经映射引用的用户可见单元」里落点不在目标那一版里的那些（快照 `mount.rs:4143-4162`，`user_visible_units_through_the_mapping(current)` 在 `mount.rs:4144`）。隔离单元已经不被现行那一版引用，它的记录留在 cur 的账里、仍分配，不在这张表里，回退不动它。

**历史**（`rollback_to_a_version_not_referencing_a_quarantined_unit_leaves_it_allocated`）：
1. 第一个文件（txg 3）之后，把盘 1 上那一版数据单元的那一份写成 0xA5（静默坏块，一个故障）。
2. 覆盖写（txg 4）：换下的数据单元盘 1 那一份核不上，两份都留在已分配（隔离）。
3. 再覆盖写（txg 5），然后回退到 txg 4。
4. 原样输出：`Z1Q-B target_txg=4 rollback_txg=6 quarantined_slot=50180 record_before=Some((false, 3)) record_after=Some((false, 3)) released_user_visible_units=4`

字节上看得出的差异：回退那次发布（txg 6）的分配记录树里，两块盘槽 50180 那两条记录。代码是「已分配、分配代 3」；照 D23「释放」一格字面应是「已释放、释放代 6」。

**四问**。
- 分不分辨：分辨「照 D23 字面」与「照 D19 硬规则 1」两种读法。
- 看不看得到：回退那一刻看得到。那条记录在 cur 的账里仍分配，而 cur 的映射不引用它。
- 满足判据的哪个分句：D23 已定项 14「释放」一格的全句。它的字面没有给隔离单元开例外。第三轮判决 K1 说「多释放的孤儿 0 个」，那是在没有隔离单元的历史上量的。
- 改法：条款两处打架，要交主 agent 定用哪一句。我倾向在 D23「释放」一格补「隔离单元（D19 硬规则 1）除外」，代码不动（推的，被攻过零轮）。

### Z1Q-A　目标引用隔离单元：不进复活集、不逐盘验，回退做成

**原文**。D23 已定项 14「在任何写之前拒」一格，`.claude/kb/decisions/23-journal的角色与格式.md:383`：「cur 的账里仍分配的单元分配器不会发出去，不在逐盘验之内」。

**代码**。复活判定里，cur 的账里仍分配、分配代与目标那一版相同的，按「两版共用」处理（快照 `mount.rs:3841`），不进 `units_to_check_on_every_device`。逐盘验只读复活集（快照 `mount.rs:4129`）。

**历史**（`rollback_to_a_version_referencing_a_quarantined_unit_is_accepted_without_checking_its_copies`）：同上把 txg 3 那一版的数据单元盘 1 那一份写坏，覆盖写两次（txg 4、5），回退到 txg 3。原样输出：
```
Z1Q-A checker_violations_before_rollback=3 first=Some("I-2.1: 数据单元 在盘 1 槽 50180 的那一份与位置条目里的校验和对不上")
Z1Q-A quarantined_copies_at_overwrite=2 record_before_rollback=Some((false, 3))
Z1Q-A rollback_to_txg3 accepted=true err=None resurrected=Some(6)
Z1Q-A checker_violations_after=3 first=Some("I-2.1: 数据单元 在盘 1 槽 50180 的那一份与位置条目里的校验和对不上")
```
回退做成。新的现行版本引用的数据单元盘 1 那一份是坏的，只剩盘 0 一份好的。同一次回退里另外 6 份复活的单元都逐盘验过：同一种「一份坏」落在复活集上会被拒，落在隔离单元上照样放行。

**四问**。
- 看不看得到：看得到。那一判手里就有 cur 的账，隔离单元与「真正两版共用」的单元都是「仍分配、分配代相同」，只看账分不开；但逐盘读一次就分得开。
- 满足判据的哪个分句：「在任何写之前拒」一格的最后一句。代码兑现了字面；字面给的理由是「分配器不会发出去」，可逐盘验要挡的是「一块盘上那一份被盖掉」，隔离单元是已经核出一份坏的，这个理由罩不住它。
- 这一格与回退本身的关系：回退之前池级 checker 已经红在同一处（环里目标那条根引用着坏的那一份）。回退没造出新的坏，是把一份已知单拷贝的版本定成了现行版本、没拒。
- 改法（推的，被攻过零轮）：隔离单元（分配记录仍分配、而现行那一版映射不引用的）也进逐盘验。代价是多读几个单元。

### Z1 随机走（没打中）

`opus_r1_z1_rollback_walk_with_multi_unit_files_inodes_and_unmount.rs`。补 `history.rs` 生成器不走的三样：顺序写多单元文件（1–5 个数据单元）、建 inode、正常卸载。与覆盖写、管理员回退（目标取根环里最新 12 条之一，放开扫）、准入抬 F、进程退出、崩了再挂交错。
- 每一步之后跑池级 checker。冷恢复（`recover`，看 journal）读回的内容必须等于走到的那条根记下的内容。回退做成时，新根记下的内容是目标那一版的。
- 两种宽度并行，每批两件。第 2 批（种子 201..400，每段 60 步），`.rc` 2 份、两件都是 0：

| 宽度 | 步数 | 回退做成 | 其中目标是多单元文件 | checker 红的步 | 读回错 | 用时 |
|---|---|---|---|---|---|---|
| 4 GiB | 12000 | 2075 | 598 | 0 | 0 | 534 s |
| 单元区 384 槽 | 12000 | 2065 | 592 | 0 | 0 | 419 s |

- 拒绝的只有候选集那两种（`BelowEffectiveFloor` 423 / 433，`VersionWithoutFile` 190 / 190）。卸载 838 次、抬 F 做成 405 次，都没有别的错。

## Z5　验证装置

### 第三态的取法：字面还是选择（正文要连同答的那一句）

**原文**。D13 已定项 4（`.claude/kb/decisions/13-验证路线.md:71`）：
- 「不是单元写、长于一个扇区、罩住的范围里原来有东西的写，系统配置槽写与覆盖旧记录的 journal 写属于这一类」
- 「新旧不同的那一截前一半是新字节、后一半是旧字节（按字节撕，不按扇区）」

同一份文件 `.claude/kb/decisions/13-验证路线.md:73`：「两条层 0 流上取第三态的只有系统配置槽写」。

**代码**。快照 `crash.rs:1906`（单元写或不长于 512 字节就只取两态），`crash.rs:1951`（撕裂点取新旧不同那一截的中点）。

**判**：两样都是 D13 已定项 4 原文的字面后果，不是替它做的选择。但原文那一句是 2026-09-27 照实现写回的，「按字节撕」那一半 kb 自己记着被攻过零轮（同一份文件第 80 行）。所以「字面」只说明代码与条款一致，不说明条款经过攻击。

**别的撕裂点给不给不同的恢复结局**（`opus_r1_z5_torn_split_points_and_fua_release.rs`）：
- 流：一条真录出来的多挂载流，依次是 mkfs、第一个文件、覆盖写 4 次、崩了再挂、覆盖写 5 次、准入抬 F、回退、覆盖写、正常卸载、再挂、覆盖写。整条流 799 步、675 次写、92 段。
- 取第三态的写 62 次，全是系统配置槽写（4096 字节）。新旧不同那一截是 147..=469、147..=477 或 147..=481，只有 6–7 个字节不同。
- 在这一截里逐字节换撕裂点，前新后旧、前旧后新两个方向，一共 40312 个撕裂镜像。拿读者（`SystemConfiguration::parse_slot` 且 fsid 相同）判，能自证、又与新旧都不同的 0 个；中点那一个也是 0。原样输出：`Z5 split_points_tried=40312 self_verifying_other_than_old_and_new=0 midpoint_self_verifying=0`。
- 于是在这条流上，换撕裂点都落进「这一槽不可择」，恢复结局与中点相同。原因是整槽校验和罩着全部不同的字节。
- 不长于 512 字节的原地覆写在第一版流里只有根槽写（512 字节物理块）。按扇区原子的前提，它撕不开，模型里没有哪条可达历史会让它给出别的结局。物理块 4096 的池上根槽写会走到 harness 的断言，是 D13 已定项 4 自己记着的已知边角。
- 没罩住的：这条流 journal 环没转圈，覆盖旧记录的 journal 写一次都没有；一次写跨两个独立校验和结构的形，今天的写入口不发（系统配置、记录都是一写一个结构，读快照 `transaction.rs:280-326`）。

### FUA 只放行它那块盘（没打中）

**原文**，`.claude/kb/decisions/13-验证路线.md:71`：「一次写只被它自己那块盘上之后的屏障（或它那块盘上的 FUA 写）排在之后的写前面」。

**代码**。快照 `segments.rs:125` 起：FUA 把它那块盘从「没放行」里拿掉，这块盘上前面没被屏障隔开的普通写随它一起算放行。真设备上 FUA 只保证它自己持久，不替前面的普通写做持久（推的，属于块层语义，归 C6）。所以只要流里出现「普通写 A、同盘 FUA、段关、之后的写 C」，枚举就会漏掉「A 没落、C 落了」的状态。

**量**：同一条流里 29 次 FUA 写，「这块盘上一道屏障之后还有普通写」的 0 次（`Z5 fua_total=29 fua_with_unflushed_plain_writes_on_its_device=0`）。今天的发布顺序在根槽 FUA 之前总有一道全池屏障，这一形走不到。条款的模型与真设备语义在这一处不同，只是潜在的；将来谁在 FUA 前面插普通写，这一处会静默漏状态。今天没有会红的东西钉着「FUA 前面没有同盘未冲的普通写」（推的，没去找有没有这样的断言）。

## Z8　合并点（只读代码）

逐段读了几条路径的判定和写的先后：
