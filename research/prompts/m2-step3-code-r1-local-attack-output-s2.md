1a. In rebuild_from_records (F5), for a record marked released, mark_released (F4) increments deferred_slots but does not alter allocated_slots or free_slots. For a record marked allocated, mark_allocated increments allocated_slots and decrements free_slots. After a release followed by an allocation on the same slot, the device's free_slots equals unit_area_slots minus allocated_slots (which includes the released slot), while unit_area_slots minus (allocated_slots + deferred_slots) is lower by the deferred_slots value. For example, with unit_area_slots=100, allocate span=10 (allocated_slots=10, free_slots=90), then release span=10 (deferred_slots=10, allocated_slots=10, free_slots=90). Here free_slots=90 but 100 - (10+10)=80, differing by 10. Refuted by: evidence that mark_released modifies free_slots or allocated_slots.

1b. After a publish that releases a unit referenced only by an older root (not the newest), the checker's walk counts the unit as allocated (F16), but the allocator's allocated_slots still includes it (F4), while the accounting-tree's item 1 (F9) uses allocated_slots. However, if the unit is released and no longer referenced by any root, the checker's walk would not count it, but allocated_slots remains, causing item 1 to exceed the walk's sum. Sequence: mkfs, publish a file (allocating units), delete the file (releasing units), then restart. After restart, the allocator's allocated_slots includes released units, but the checker's walk (from all valid roots) does not count them, so item 1 in the accounting-tree would be higher. Refuted by: evidence that the bitmap is cleared for released slots in mark_released.

1c. At every publish (including warm-up), STATISTIC_INODE_WATERMARK is set to FIRST_INODE_NUMBER + 1 (F9). If prior publishes created more than one inode (e.g., FIRST_INODE_NUMBER=1, then created two inodes), the watermark should be 3. But the next publish resets it to 2. No invariant checks the watermark statistic, so this discards the correct value silently. Refuted by: evidence that STATISTIC_INODE_WATERMARK is computed from actual inodes instead of a fixed constant.
