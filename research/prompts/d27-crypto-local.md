You are reviewing a filesystem format proposal. Your stance is: find a concrete counterexample. Do not summarize, do not praise. Do not use any markdown emphasis such as bold or italics. Answer in English. Answer all three items, number them 1, 2, 3. Keep each item under 300 words.

Setting, all settled in this project. Disk is allocated in fixed 32768 byte units, each carrying a self describing header. Everything is copy on write: a unit is written whole to a new location and never modified in place. Encryption is AEAD: each encrypted region has a 96 bit nonce and a 128 bit authentication tag, and the tag is computed over associated data that identifies what the region is. The settled associated data is the tuple (unit class tag, tree id, object id, object birth generation, anchor offset). Physical location and device id are explicitly excluded from it. Nonce reuse is forbidden by an invariant. A separate settled rule says a scanner must be able to pick up any single unit off the raw disk and verify it without consulting anything outside that unit.

The proposal. A new unit class called a container holds several small objects, each in a slot. Objects up to 4096 bytes go into containers; larger ones keep their own unit. Containers are produced by a background compaction pass, not by the write path: an object is first written as its own unit, and later moved into a container. Each slot carries its own nonce, its own authentication tag, and its own identity tuple, so the associated data binds the object, not the container. The claimed benefits are that moving an object into a container needs no re-encryption, that corrupting one slot does not destroy the other objects in the container, and that the container verifies itself with no outside input.

Your task:

1. Attack the claim that moving an object needs no re-encryption. The object is written once as its own unit, then later copied into a slot of a container. If the ciphertext and the nonce are copied verbatim, the same nonce now exists in two places on disk at once, and after the original unit is freed it exists in one place again. Say whether this violates the nonce reuse rule, and construct a concrete sequence of operations where it causes a real failure, not merely an aesthetic problem. If it is safe, say exactly why, and name the property that makes it safe.

2. Attack the claim that one damaged slot does not destroy the others. Consider that the filesystem keeps old copies of units after crashes.
