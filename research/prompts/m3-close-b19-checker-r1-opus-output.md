## K3　C469 ②：I-8.7「从 1 起」算不算评估

攻的候选：实现员今天取的形（下称「只红记评估」：只在不成立时 `judge(…, false)`，成立不记）与另一形（下称「成立也记评估」）；另攻两形共用的「回绕」那一支。

### 打中一：回绕那一支把 ①② 已评估的成立整条压成不适用（两形都中，不分辨臂）

- 条文写「前一个计数器那一格坐着环转过一圈之后的记录（计数器大一个环长）时这个实例的第一条已被盖掉，报不适用（射程外，不判绿）」（`crates/singlefs-checker/invariants/03-journal.md:14`）。
- 实现把它记成射程里判不了：「TRANSACTION_NUMBERS_FROM_ONE_NOT_JUDGED_AS_THE_RING_WRAPPED_OVER_THE_FIRST_RECORD_OF_THE_INSTANCE,」（`crates/singlefs-checker/src/walk.rs:10887`），上一行调的是 `judgements.part_of_the_range_not_judged(`。
- 汇总的次序：「} else if let Some(reason) = self.part_of_the_range_not_judged.get(invariant) {」（`crates/singlefs-checker/src/image.rs:661`）排在 `evaluated > 0 ⇒ Holds` 之前；所以只要有一个实例的第一条被环盖掉、又没有违例，I-8.7 整条报不适用，不管 ①② 判过多少对、全成立。
- 已入库用例就钉着这一后果：`crates/singlefs-harness/tests/checker_known_bad_images.rs:2022` 那条用例的镜像是「A、B 两条记录（计数器 3、4）的事务号改成 5、6」（`crates/singlefs-harness/tests/checker_known_bad_images.rs:2056`）那一份同源的「发布 B 之后那份干净镜像」，上面 ① 至少有 A、B 一对非 0 号可比、成立；断言要求整条 `NotApplicable`。
- 后果（推的，没跑）：journal 环转过一圈之后，凡是最新实例自己写过非 0 记录、第一条又被盖掉的镜像，I-8.7 再也报不出成立；①② 的判别力还在（违例压过不适用），丢的是「判过且成立」这一记数。崩溃点重放、随机历史里凡是要求 I-8.7 真被评估过的断言，在回绕之后的状态上都会失败；K6 要新加的 1 MiB 环加大文件流正是会回绕的流。
- 字面矛盾：条文括注写「射程外」，射程外的东西不该影响这条不变量的判定；代码走的是「射程里有一部分判不了」，GPU 一侧注释也写「GPU 一律只记射程里判不了：两样都不置判到位」（`crates/singlefs-checker-tier/src/crash_judge_checker.wgsl:528`）。

四句：分不分辨臂——不分辨（两形都走这一支）；系统看不看得到——看得到（盖它的那条记录在盘上）；满足的是哪一句——条文「报不适用（射程外，不判绿）」被读成整条不适用；改法——两种：① 回绕那一支什么都不记（真射程外），①② 照常报成立，「从 1 起」那半句在这块盘上只是没有对象；② 保留整条不适用但把条文的「射程外」改成「射程里判不了」、写明整条降级的代价。只在我的推理上过、被攻过零轮。

### 打中二：「只红记评估」让不适用的理由句说假话

- 「只红记评估」形下，只有一条非 0 记录、「从 1 起」判了且成立的镜像，I-8.7 报不适用，理由是「环里没有哪个实例写出过两条非 0 事务号的记录：一对可比的号都凑不出来」——这一句对 ①② 是真的，对整条不是：这条不变量在这张镜像上有对象（第一条非 0 记录），判了，成立。`Judgements::not_applicable` 的文档注释说它记的是这个镜像上整条不适用：「这个镜像上整条不适用（例如第 0 代根下面没有记账树）。已经评估过的不改。」（`crates/singlefs-checker/src/image.rs:590`）。
- 代码注释自己写了这是实现员取的、条款没写：「// 只在不成立时记一次评估（判红）：成立时不单独把 I-8.7 从「一对可比的号都凑不出来」的不适用抬成成立，」（`crates/singlefs-checker/src/walk.rs:10907`）。
- 两形的判别力相同（坏镜像「第一条非 0 记录号是 5」两形都红，「从 1 起」恒成立的变异两形都抓得到），分开它们的只有「成立 / 不适用」的记数。所以选「只红记评估」的理由只剩「少改三处钉值」，那是代价不是依据。
- 反方向的不对称（推的）：同一个实现里回绕那一支把成立往下压成不适用（打中一），「只红记评估」又不肯把成立往上抬；两处合起来，I-8.7 的「成立」只在「环没转过、且有一对可比的非 0 号」这一窄格里出现。

结论：推荐「成立也记评估」，再按打中一的改法 ① 改回绕那一支；三处钉值随改（实现员点名的三份）。推翻它的观测：找到一处下游（崩溃点重放的评估计数、GPU 对拍）把「从 1 起成立」计成评估会在合法状态上误红。

### GPU 与 CPU（没打中，记一处不一致的写法）

CPU 把「前一格读不出」报部分没判（`partially_judged`，压过成立与不适用），把回绕报 `part_of_the_range_not_judged`；GPU 两样都只置 `part_not_judged`。按 `crates/singlefs-checker-tier/src/crash.rs` 第 1664 行那段注释（部分没判不红、不算评估过，计进不适用那一格），对拍时两种都并进不适用这一格，判定一致；只是 GPU 那一侧看不出 CPU 报的是哪一种。没跑对拍（checker 档，不归本腿）。

## K2　C740：实例表行的 W 等于那次挂载重放施加的最大事务号

攻的候选：① 判最新根实例表的每一行 / 只判挂载根自己那一行；② 期望值用「从给定根起、只取上一个实例的记录」那一份重放（`crates/singlefs-checker/src/walk.rs:11925` 的 `replay_the_next_mount_would_do` 已带 `chosen_root` 参数，换一个根就是那一份）；③ 读不出报部分没判还是不适用；④ T 那条根不在环里。

### 打中一：「给定根」在盘上认不出，同一张镜像上 W 合法地可取两种值

实现：行的 T 取恢复之后那一版、W 取扫环报告的最大施加事务号：「applied_transaction_high_water: journal.maximum_applied_transaction,」（`crates/singlefs-core/src/mount.rs:8914`）。行里没有记挂载择的那条根 c。

造的历史（推的）：实例 i 发到 txg T（T 那次发布带非 0 事务号 k），干净崩溃；挂载时 T 那一槽一时读不出（用户 2026-10-04 定读坏一个根槽的镜像算合法镜像，C698 那一行，`.claude/kb/checks-owed.md:422`），择根落到 c < T，重放把 (c, T] 的记录施加上来、恢复到 T，写行 (i, T, k)。读故障不留在盘上，镜像上 T 那条根读得出。对照的干净历史：同一段写，挂载时 T 读得出，直接择 T、一条记录都不施加，写行 (i, T, 0)。

- 期望值「从 T 那条根起重放」：干净历史对、读坏历史误红（期望 0，实得 k）。
- 期望值「从 T 之前最新的可读根起重放」：读坏历史对、干净历史误红（期望 k，实得 0）。
- 两条历史除行里的 W 与新实例根上的回收门槛 t、钉槽 p 之外，环里与 journal 里每一字节可以相同。t、p 只是半个见证：只在建账的发布上现算（I-7.18 那一行），p 只记钉值最小的那一槽，挂载时有两槽读坏、T 那一槽不是最小的那个，p 就不点名它。所以这一格基本是「判别子观测不到」：盘上一般分不开 c = T 与 c < T；p 恰好点名 T 那一槽时可以收严成只许 W = k（推的）。
- 照 C740 的判别力自证（「把 W 写成 0 的那张坏镜像必须红」），这张坏镜像只在一种盘面上和合法镜像分得开：行的 T 那条根从没落过槽（T 那一槽里坐着 txg 比 T 小的根）。b35 攻方「拿掉根槽写」那一形正是这种。T 那条根读得出、或被 txg 更大的根盖掉（转出环），W = 0 都可能合法。

我给的收窄形（只在我的推理上过、被攻过零轮）：W 落在一个集合里——T 那一槽坐着的根 txg ≥ T（T 本身或已转出环）时集合含 0；对 T 之前每条可读、按行有效的根 c，集合含 (c, T] 里实例 i 的记录的最大非 0 事务号；那一段记录读不全时这一格部分没判。T 那次发布带非 0 号时，各个 c 给的值都等于 T 那几条记录的号（事务号按计数器不减，I-8.7 ①），集合退化成 {0, k} 或 {k}；「W 写成 0」只在 T 从没落槽时红。

### 打中二：F2 退回那一支，「重放」字面与代码相撞

`crates/singlefs-core/src/mount.rs:8775` 写着「扫环报告里施加的那一截清零（新实例写的上一个实例那一行 W 取 0，与落在一条根上、一条记录都没施加时相同）。」：退回之后行是 (i, T_退, 0)，T_退 之上同实例的记录还在盘上、按前缀规则接得上。期望值若照 `replay_the_next_mount_would_do` 从 T_退 起算，会算出非 0、在合法镜像上误红。上面那个集合形含 0（T_退 是一条读得出的根），躲得过；照「从给定根起重放」的字面躲不过。

### 打中三：与 D23 已定项 14 注 4 字面不同

`.claude/kb/decisions/23-journal的角色与格式.md:374` 是「4. **切换时的 W 取被重发的那个 checkpoint 里的最大事务号**」，不是「重放施加的最大事务号」。今天实例切换只有预留的算法（`crates/singlefs-core/src/admission.rs:557` 的 `instance_switch_reserve_on_one_device`），切换本身没实现，所以今天没有可达盘面；条文要写明「挂载写的行」，或把注 4 那一支并进同一条，不然切换一实现就在合法盘面上红。

### ①④ 与 GPU

- 判每一行还是只判挂载根那一行：老行的记录多半已被环盖掉，老行的 T 那条根多半已转出环，按上面的集合形它们几乎都落进「含 0、判不出 0」或「部分没判」；判每一行不多抓什么，多一堆部分没判（推的）。我倾向只判最新实例写的那几行（上一个实例那一行与中间实例行 (i, 0, 0)，后者 W 恒 0 可以直接判），老行写明射程外。
- T 那条根不在环里：要分两种——那一槽坐着 txg 比 T 小的根（T 从没落槽，可判），坐着比 T 大的根或读不出（判不了，W = 0 也合法）。题面 ④ 只问「不在」，没分这两种。
- GPU：判器没有第二份重放；要跟上就得把「(c, T] 里最大非 0 号」放进扫描内核。没看到现成的落点，没攻 GPU 与 CPU 的一致。

## K8　C717：回退下界上限的单窗口盲带

攻的对象：C717 的要求本身——「造一张镜像：环上一个洞里留着有效根 X，窗口里非空有效根不足 4 个，F 抬到 X 与 W 之间；整环口径判它违例，要有一种判法把它判红」，前提是「F 越过环上洞里留着的一条有效根 X 时整环口径下违例」（`.claude/kb/checks-owed.md:433`）；连带攻任何只看根环的候选（整环、整环加洞里旧根、窗口加洞里旧根）。

### 打中：C717 要红的那张镜像由合法写者造得出

「整环口径下违例」只在抬 F 那一刻的环上成立；checker 看到的是后来的环。抬 F 那一刻环里撑着上限的第 4 新非空根，之后可以被盖掉，而洞里那条更旧的 X 留着——I-7.9 条文自己写了这一机理（「只判抬 F 的那一条，不在后来每张镜像上重算」，`crates/singlefs-checker/invariants/02-根环.md:16`），C717 把它反过来当违例的证据用了。

写死的一对历史（`research/prompts/m3-close-b19-checker-r1-opus-model/k8/k8_scripted_pair.py`，S = 4、R = 3、环长 12）：

1. 实例 1 发 txg 1（非空，状态 A）、2–8（空）、9–12。
2. txg 13 那次发布记录落了、根槽没落；恢复由记录施加出 13，实例 2 写行 (1, 13, ·)，第一条根 txg 14（空）。13 那一槽留着 txg 1 的根 X（洞）。

## K9　C764：新实例第一个 txg

实现：「checkpoint_txg_after_the_version(highest_ring_txg.max(highest_record_txg))」（`crates/singlefs-core/src/mount.rs:1408`），`records` 是环里全部自证过的记录，下一个计数器也从同一份 `records` 取最大 + 1（`crates/singlefs-core/src/mount.rs:8877` 那一行的上面几行）。条文要求「新实例（普通挂载、切换）的第一次发布的 checkpoint_txg ≥ max(根环里全部根记录的 txg, 环里全部自证通过的记录的 checkpoint_txg) + 1」（`.claude/kb/decisions/23-journal的角色与格式.md:373`）。

攻的候选：甲 照题面「新实例第一个根的 txg 大于环里读得出的别实例的每条根与记录」；乙 只比被抛弃的根与记录（C764 行的写法）；丙 「根与记录在挂载时都读不出」那一形不判。

### 打中一：「别实例」照字面会拿后来的实例去比

题面写「别实例」，C764 行写「被抛弃的根与记录」（`.claude/kb/checks-owed.md:473`），两处射程不同。若每个第一条根还在环里的实例都判一遍，实例 2 的第一条根（txg 10）对实例 3 的根（txg 20）照字面就红——合法镜像全红。要写成「实例代号比它小的实例」，或只判最新实例。比它小、又没被抛弃的根 txg ≤ 行的 T < 第一个 txg，自动成立；真有判别力的只有被抛弃的那部分，所以乙的射程是对的、甲的字面错。

### 打中二：丙的前件「挂载时读不出」盘上看不到，但计数器给了一个看得见的见证

- 读故障不留在盘上（I-7.19 行「读故障不留在盘上」那一句，`crates/singlefs-checker/invariants/02-根环.md:26`），所以「挂载时都读不出」这一形与「`first_txg_of_new_instance` 不看记录」的坏实现，在冲突那条记录上逐字节相同；照丙字面，checker 判不出该不该判。
- 但挂载的计数器与 txg 读的是同一份 `records`：第一条记录的计数器 c_new = 环里读得出的最大计数器 + 1。所以一条旧实例记录的计数器 < c_new 时，有一条计数器 = c_new − 1 的记录挂载时读得出；单故障下按 I-8.12（同实例 txg 不减）与计数器的时间序，那条记录的 txg 不小于前面那些，新实例的 txg 也就大过它们（推的）。反过来，旧实例记录的计数器 ≥ c_new，就说明挂载时没读到它（读到了，c_new 会更大）。
- 由此的候选丁（只在我的推理上过、被攻过零轮）：对被抛弃的、实例代号更小的记录，计数器 < 新实例在盘上最小计数器的，判 txg < 新实例第一个 txg；计数器 ≥ 它的不判、报部分没判。被抛弃的根：只在它那一次发布（同实例、txg ≥ 它）有一条计数器 < c_new 的记录在盘上时判，否则部分没判。
- 丁自己的洞（攻自己）：新实例的第一条记录没落盘（崩在第一次发布中间、子集持久），盘上新实例最小计数器 c' > c_new，计数器正好 = c_new、挂载时读不出的旧记录照旧坐在那一槽，丁会拿它去比、误红。要把门槛从「盘上最小计数器」降到「最小计数器 − 在飞上限」，代价是那一段不判。这一形要崩溃加读故障两样同时，与 C764 说的 1 037 260 张同一类，没量。
- 能抓的坏实现：「不看记录」与「改小那一句」的变异在没有读故障的历史上造出计数器 < c_new 而 txg ≥ 第一个 txg 的旧记录，丁会红（推的）。「不看根」的变异只在那条根的记录已被 journal 环盖掉时才与正确实现分得开，这时丁判不了，漏。

### 没打中

- 新实例第一条根被环转出之后，checker 拿到的是更晚的根，比的更松，不误红。
- 中间实例行 (i, 0, 0) 的实例写过的记录：它们按行全被抛弃，挂载读得到就进 `records`，丁照判；没找到误红的形。

## K4　C706：分配记录树根指针出生 txg 等于这一版 txg

攻的候选：「这一版写过分配记录时，分配记录树根指针的出生 txg 等于这一版的 txg」。

打中（判据循环，推的）：前件「这一版写过分配记录」盘上从哪读？那一版本身树表 0 条，没有别的树；能说明它写过记录的只有分配记录树自己（根的出生 txg = 这一版）。攻方那一形把根换成一棵合法的旧树，出生 txg 变成旧的，前件随之读成「没写过」，判据不判——正是要抓的那一形判不到。前件要从分配记录树之外取：① 上一版（按 txg 排的前一条可读有效根）走得到时，比两版各自引用的槽，这一版少引用了的就是这一版释放的，有释放就一定写过记录；② 这一版的 journal 记录新根段之外的点名项。上一版也是只在记录里的那一版、或读不出时，前件判不了、报部分没判。改成这样之后，条文落 I-5.4 那一行就不合适（I-5.4 判的是两棵记录树不相交），要另立一条。被攻过零轮。

## K7　C699 与 C698：取号跳过改认出生代号

打中前提（读代码，推的）：C699 要先量的前提是「「隔一条也是同一张实例表」是按「一个实例写行之后每一版照抄同一张实例表」推的，没量」（`crates/singlefs-checker/invariants/05-空间记账.md:8`）。实例表清扫在同一个实例里重写实例表：「把那一行删掉。」（`crates/singlefs-core/src/instance_table_sweep.rs:3`），文件头写可写挂载末尾「写行、暖机、抬 F、删除续做之后，交回之前」判一次，行数超过阈值就当场发清扫发布。所以：

- 清扫那一次发布之后，R 的实例表指针出生代号是清扫那一版的 txg，不是这个实例写行那一版。
- 同一实例里写行、暖机、抬 F、删除续做那几版 txg 都小于这个出生代号；按「行 + R 的实例表指针出生代号」认，它们落在出生代号之下，其中一槽读坏时照旧被认成取号跳过——C698 要修的那一类误认在这一段里留着。
- 量前提的装置要包含「行数超过清扫阈值」的历史；只量不清扫的历史会量出「照抄」成立。
- 改法候选（零轮）：出生代号改取「这个实例最早的、按行有效的根或记录的 txg」（实例代号在根记录与记录头里都有），不取实例表指针。

## K10　C70：跨统计量的和

打中（对象，推的）：

- 式子左边的可用(d) 不落盘：「已分配 = 分配记录树里落点之和」（`.claude/kb/decisions/05-快照-空间记账机制.md:17` 那一格「不含：已分配 = 分配记录树里落点之和」），准入读的是分配器此刻的计数；镜像上没有一个被维护的「可用」值可与右边比。等式在镜像上是定义式，判不出「两套 += 各自没错而互相对不上」。
- 题面划「挂载期承诺量、已承诺预留这类只住内存」判不出，轴分错了：checkpoint 保留池「按当时各记录树的高之和 + 记账节点现算」（`.claude/kb/decisions/28-挂载期承诺量.md:28` 那一句「**checkpoint 保留池**（第八项）：挂载期承诺量的池级成员，按当时各记录树的高之和 + 记账节点现算」），环窗口按几何与树高现算，镜像上都算得出；判不出的是没有落盘的左边。
