# 背景材料：C161（缓冲两级并存而衔接没定） 第三轮（2026-09-15）

<!-- doc-lint:not-numbers U1 U2 U3 U4 -->

这一轮论证的仍是开 write buffer 前端、ε > 0 的那一版两级怎么衔接，四条候选都不改第一个事务的字节。第二轮的判决在 `research/prompts/c161-r2-main-verification.md` 第四节：丙两轮都没被分辨臂的历史打中；甲-R4、乙-D 的最弱读法被「塌缩」打中（树变矮时孩子缓冲里的旧消息被当成新来的、并到根缓冲里新消息的后面），攻方腿的收严 T1、T2 被攻过零轮——D8（核心索引结构）、D11（索引节点要不要留消息缓冲区） 两份文件里「塌缩」「树变矮」「再平衡」「重分配」都是 0 次，缓冲在重组时怎么重分配全仓没写；乙 + 全池单调的最弱读法被「计数器不落盘」打中，收严 T3 被攻过零轮，消息在缓冲里的停留期没看到与总写次数无关的上界；乙-D、甲-R4 的陈旧检出要每条消息加一份发布号，与 D8（核心索引结构） 已定项 7 冲突；部分发布、排空跨两次发布、写入时算好的记账行三处不分辨臂，归 C80（记账更新必须原子地随根发布）；kb 里 fsync 发的是全量还是部分，三处说法不同。按多轮规则，这一轮派辩方腿复核第二轮判决 1–3，攻方腿攻 T1–T3、T6 与两轮都没建的面。

## 二、洞（C161 那一行整行在附录）

write buffer 前端 flush 之后条目落进哪一层、两级之间的下推与归并次序、发布点上排空到哪一层、崩溃后没排空的前端条目从哪恢复——全仓没有一句正文。重组（分裂、塌缩、再平衡）时节点缓冲里的消息怎么重分配，D8（核心索引结构） 与 D11（索引节点要不要留消息缓冲区） 也一句没有。

## 三、候选（按第二轮判决收严；T1–T6 都被攻过零轮）

- **甲-R4-T**：前端 flush 直落叶，不经内部节点的消息缓冲区；节点缓冲区只收不走前端的更新；flush 时清掉路径上比它旧的同 key 消息（路径按当前 pivot 走），落叶时比同一窗口的到达序，不走前端的写把前端里同 key 的条目逐出；读按「前端 → 根缓冲 → … → 叶」取第一条。T1：树变矮时先把根缓冲按下推规则推进孩子、再合并孩子（一般形式：重组不许改变任何 key 读出来的值）；T2：再平衡时缓冲里的消息随 key 搬走。
- **乙-D-T**：前端 flush 进根的缓冲区、逐层下推；一个缓冲区里同 key 至多一条，新来的替换旧的（单调统计量取最大）；跨层、同层都按位置定新旧，不读 seq。加 T1、T2。
- **乙-G-T**：乙字面（跨层看位置、同一层由 seq 定新旧），seq 全池单调；T3：写进前端时取号，计数器随发布落盘，seq 8 字节（记账条目 34 → 38）；加 T2。宽度的另一种形态（4 字节 + 每个节点在 A_max 次写之内至少下推一次）只作攻方腿可以试的变体，这一轮不当候选。
- **丙-T6**：一棵树只准一级——前端树 ε 恒 0、前端树上的写一律进前端；其余树按前提五的树轴；发布前把前端排空到叶，落叶比同一窗口的到达序。T6：前端树的写路径只暴露前端入口（类型层），加一条运行时断言「一次发布里前端树叶上的每一处改动都对得上一条这次排空的前端条目」；前提十六那个旧写者对前端树的写也走前端。
- **可选附件 T5（只给甲-R4-T、乙-D-T）**：每条消息带写进树那次发布的号，给陈旧检出一个盘上线索；与前提三「在 seq 里再放一份 txg 是把 key 里已有的段抄第二遍」冲突。
- **四条共用（不拿来判臂）**：T4——部分发布写出去的镜像 = 盘上原有的 + 发布集的改动；记账行在发布那一刻按发布集现算，前端不带写入时算好的完整值；发布集的前端条目在同一次发布里排空、按事务切（替换第一轮「前端按发布窗口打标签」那条按时间切的规则）；同 key 区间的冻结批次按到达序进树。fsync 按「全量发布」与「部分发布 + T4」两种读法各跑一遍。

## 五、失败条款、反向接受条款与事先的倾向

**反向接受条款**（每个改法写明它修的是哪一格）：

- 丙-T6 在 U1 或 U2 被一段分辨臂的历史打中 ⇒ 记一次；前两轮都没中，凑不成多数，照打中的形状补收严，连同这一次交用户。

- 三条臂被同一段历史一起打中 ⇒ 打中不分辨臂，病根另记，判臂只看分辨得出臂的格。
- 辩方腿推翻第二轮判决 1、2 或 3 ⇒ 照实记，两种判法一起交用户。
