# D18 未定项 11 的定案提案（2026-09-04，等三方论证核）

**要定的**：D18（块里携带什么信息）未定项 11——**单元类型标签的值域，以及打包共享单元算哪一类**。
它是三条线的公共前置：inode 记录打包（D8 未定项 6 路 ①）、墓碑打包（D18 已定项 8 / 10）、
抗老化留位（D26 未定项 4 / E101）。**提案是推论，按 `.claude/rules/three-way-inference.md`
走三方论证之后才进正文。** 下面是要被攻击的提案全文。

## 二、提案

### P1 值域只有一处登记位，四处清单全改成链过来

登记表住 D18 已定项 11。D9 已定项 6 那一行、D18 已定项 7 的字段表、D21 已定项 4、I-6.2
各自保留**自己那一维的判定**（AAD 变体 / 类身份段 / 扩展点 / 白名单），但**类的名字与码**一律取自登记表。
理由：kb-discipline 第 4 条「同一个事实只许有一处权威记录」；F1 说这个值域进 AAD，F2 说 AAD 组成是永久契约，
一个永久契约不能有四份互不相同的正本。

### P2 登记表（码 → 类是 day-1 冻结的部分；每类的类身份段 / AAD 变体各归自己的分项）

| 码 | 类 | 单元大小 / 对齐 | 头走哪张表 | 类身份段 | AAD 变体 | I-6.2 白名单 | 扩展点 | 认领之后怎么枚举内容 |
|---|---|---|---|---|---|---|---|---|
| 0 | **无效**（永不分配） | — | — | — | — | — | — | 见到即判损坏 |
| 1 | **数据单元** | 32768 / 32768 | D18 已定项 7 数据单元类 | 五元组 + 诞生代号 + fsid（91） | D9 已定项 6 的五项 | 数据单元类 | 带 | 载荷是用户数据，不枚举 |
| 2 | **索引节点** | 16384 / 16384 | D18 已定项 7 索引节点类 | 树 ID + 层级 + key 区间 + 诞生代号 + fsid | 归 D9 未定项 9 那一线 | 元数据类 | 条件带 | 按节点格式解条目 |

**F1 那四个名字怎么落**：数据 extent → 码 1；btree 节点 → 码 2；**记账单元 → 码 2**（记账树的节点走索引节点类头，
「它是记账」由树 ID 分，不另立类——D22 已定项 3 已定记账结构是 COW 挂父指针下的树，E73 按 16 KiB 节点量过它）；
根记录 → 码 16。**F7 的「墓碑」→ 码 3 + 记录类型 1。**

**自证单元为什么也占码**：F1 的值域里本来就有根记录；它们的头**不走** D18 已定项 7 的表（F4），
但一旦被 MAC 认证（D9 已定项 8 已定超级块要认证；journal 记录头已带 nonce 12 字节），
它们的 AAD 与单元的 AAD 就在同一个密钥域里，**域分隔子必须在同一个命名空间里才分得开**。
码只用作 AAD 首字节；头格式与 AAD 其余字段各归其决策。

### P3 标签的宽度与位置：1 字节，住 flags 的低字节；五元组首字节是它的冗余副本

- flags 2 字节里：**低字节 = 单元类型标签码（0–255）**，高字节 = 8 个 flag 位，第一版恒 0，
  不认识的位按 D15 的 compat 三档另判（本项不定它们的语义）。共同前缀 42 字节**一个字不动**。
- 数据单元五元组的首字节（F4 里那个「单元类型标签 1」）**必须等于** flags 低字节，不等 ⇒ 判损坏。
  F5 已经接受了这份冗余；本项只把「相等」写成不变量。
- AAD 的规范编码里，**标签码是第一个字节**，每一类都是。两类的 AAD 从第一个字节起就不同 ⇒ 不存在
  「两类序列化成同一串字节」——这就是 F1 要买的那件事，而且它不依赖各类字段集合的长度恰好不同。
- 256 个值，登记 7 个（0、1、2、3、16、17、18），余 249。

### P4 打包记录单元是独立的一类（码 3），不是数据单元，也不是索引节点

**为什么不是数据单元**：五元组的对象 ID 只写得下一个（问题的形状那一段）；而且它的载荷不是用户数据，
I-6.2 让数据单元类的五元组留明文是「知情泄漏面」，一个装着几百个对象 ID 的容器不能顺着那条豁免走。

**为什么不是索引节点**：它不是树的节点——没有层级、没有 key 区间、没有子指针，
装的是被别的树**指向**的记录容器；D21 硬约束 6 逐字「把一个算不出来的权威值放进一个可重建的容器里，
它就事实上晋升为权威态」，正是 E98 排除「inode 住索引节点 value」的依据。

**类身份段（初值 34 字节，头共 76）**：

| 字段 | 宽 | 为什么 |
|---|---|---|
| 树 ID | 8 | F18：对象号跨 keyspace 必然碰撞 ⇒ 一个打包单元**只装一棵树的记录**（第四条装载纪律，见 P5） |
| 记录类型 | 2 | 第二级登记表（P6）的码；一个单元只装一种 |
| 代内序号 | 4 | 同一棵树、同一代际里第几个打包单元；与诞生代号合起来是它的逻辑身份 |
| 记录数 | 2 | 解析用；≤ 583 |
| 记录宽 | 2 | 由记录类型登记表给，这里再抄一份——**它买到的是**：读者不认识记录类型时仍能验容器结构（记录数 × 记录宽 ≤ 声明长度 − 头）并整体跳过，这是 compat_ro 政策（P6）成立的前提，不是「宁可写大」 |
| 诞生代号 | 8 | D18 已定项 7 翻回头里的三条理由对它同样成立；**它同时就是装载代际**（F8：一个代际结束就关单元 ⇒ 一个单元恰属一个 checkpoint 窗口），不另设「装载代际」字段——E99 的教训是重复计账 |
| fsid | 8 | D18 已定项 7 同理 |

**AAD 变体**：（标签码 3, 树 ID, 记录类型, 诞生代号, 代内序号）。按 F2 判：这五个字段没有一个会「逐指针不同」
——一个打包单元只有一个身份、只被一处指向。按 F3：期望值来自指向它的那条查找路径（见 P7 的欠账）。

**记录级不再另带字段**：没有每条记录的类型标签、长度、校验和、活位。理由三条：
① 单元是 COW 一次写完不回写，整单元头校验和 / MAC 罩全部记录，撕裂的单元整个拒收——
「前 N 条合法、第 N+1 条撕裂」这种态在一个带整单元校验和的 COW 单元里不存在；
② 回收粒度 = 单元（F8），没有「就地标死一条记录」这种操作，活位没有对象；
③ 一个单元只装一种记录类型、记录定宽，类型与长度在单元头一份就够。
⇒ **C99 的形态改写**：记录是**解析**出来的不是**探针**发现的——认领规则（F6）跳过的是载荷内部的探针，
不跳过类解析器对已认领容器的枚举。

### P5 打包记录单元的四条装载纪律

1. 一个单元只装**一种记录类型**（不混装记录类型）。
2. 一个单元只装**一个代际**（F8 已定，此处引用）。
3. 一个单元只装**一棵树**的记录（P4 树 ID 那一行的理由）。
4. 记录**定宽**，宽度由记录类型登记表给；记录数 × 记录宽 ≤ 声明长度 − 76。

四条与 D2 写的粒度第 2 条「不让两个生命周期不同的对象共享同一个物理映射单元」同一条纪律，
只是把「生命周期」具体化成（类型, 代际, 树）三维。

### P6 记录类型是第二级登记表，新增记录类型不改 AAD 组成

| 记录类型码 | 记录 | 状态 | 宽 |
|---|---|---|---|
| 0 | 无效 | 永不分配 | — |
| 1 | 墓碑区间记录（D18 已定项 10） | 已定 | 56 是量级假设，字段表随 C84 |
| 2 | inode 记录 | **保留**，只在 D8 未定项 6 取路 ① 时启用 | E98 的 140 |
| 3–65535 | 保留 | | |

- 新增一个**单元类**（码 1–15 之外的新内容类）= 一个 **incompat** 位：读者解不了类身份段就重建不了、也读不了那些单元，
  失败模式只能是「挂不上」（fs-design.md 格式分支判据）。
- 新增一个**记录类型** = 一个 **compat_ro** 位（F13「新增记录类型 ⇒ compat_ro」那一行）：读者能验容器、
  按记录宽整体跳过，只读安全；不许回收它不认识的容器（写不安全）。
- **记录类型的码是 AAD 的一个字段的值，不是 AAD 组成**——按 F2 的判据，加记录类型不动组成，不是格式断裂。

### P7 它对三条下游各定了什么、各留下什么

| 下游 | 本项定的 | 仍归它自己的 |
|---|---|---|
| 墓碑（D18 已定项 8 / 10） | 「单元类型标签取『墓碑』」改写为「码 3 + 记录类型 1」；「那五个字段刚好够指认它」改写为「身份是 P4 的类身份段」 | 回收规则、C84 剩余 |
| inode 打包（D8 未定项 6 路 ①） | 若取路 ①：记录类型 2，容器不新增类、AAD 组成不变；E98 的 233 在头 ≤ 148 字节内不动 | 路 ① 还是路 ② 本身；C100 的冗余条款 |
| 抗老化（D26 未定项 4） | 类标签码与 flags 高字节**都不许**拿去当节点组 / 代际标签用——类标签是身份不是策略；任何抗老化标签只能是索引节点类身份段里自己的字段 | 形态与宽度（E101 判过留位翻不了） |

**一笔新欠账要立**：打包记录单元在**正常路径**怎么被找到（哪棵树指向它、那棵树的 key 是什么）全仓无落点；
按 F3，指向它的那条查找路径的 key 必须给得出（树 ID, 记录类型, 诞生代号, 代内序号）。本项只写下这条约束，不定那棵树。

### P8 对 E83 / E84 / E98 的数字：不动

打包类身份段头 76 字节：(32768 − 76) / 56 = 583（E83 / E84 的 583 在头 ∈ [65, 120] 内不动）；
(32768 − 76) / 140 = 233（E98 的 233 在头 ∈ (8, 148] 内不动）。三份实验的口径注要改字（从「属数据单元类、头 91」改成「码 3、头 76」），产物不改。
