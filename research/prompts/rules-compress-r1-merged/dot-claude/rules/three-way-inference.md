# 推论要三方独立论证

## 适用范围

**凡是「推论」，都要走三方。** 推论指设计判断、取舍结论，以及用来推翻或确立 `.claude/kb/decisions.md` 里某一条的依据。**不适用**：查一个事实（跑命令、读文件、看源码）、算术、本次对话里刚确认过的东西，那些是观测。⚠️ **从自己跑的实验里推出的结论同样走三方。** 读数是观测，「这个数说明了什么」被用来推翻或确立 `.claude/kb/decisions.md` 里某一句时是推论：**「数字是我自己跑的」不构成免走三方的理由。**

## 各条腿必须互不重复

一轮派两条推论腿，主 agent 的判决是第三方，不派本地模型的腿：云端攻方派 `three-way-attack`（Opus）；云端正推或云端辩方一轮一条（Sonnet），第一轮派 `three-way-forward`，已有一轮判决可复核时才派 `three-way-defense`。

**「不能重复」指的是各条腿要拿到不同的切入角，不是只换个模型名。** 正推腿与攻方腿分担 `.claude/rules/evidence-discipline.md`「所有结论要三次推导：正推 / 反推 / 校验」的正推与反推，校验由主 agent 判决时逐条现查；辩方腿替被判出局或被攻的一方辩护，复核已有的判决够不够得着、是不是同样打中所有替代方案。

## 引 kb 里的条目要整行抄，不许摘句——三处都管

**射程是三处，不止背景材料**：三方论证的背景材料；**一份 kb 文件引另一份里的条款**；**给用户或别的会话的转述**。

- **做法**：凡是引 kb 的条目（决策分项、挡路条、判据表格、不变量），**整条抄进去，连同它的 ⚠️ 与括注**。嫌长只有两条出路：整条放进末尾的附录、正文指过去，或只写指路不写数（「合计见 D22（单元原子性怎么合成） 已定项 7 的字段表」）；**不许在正文里给它做一个更短的版本**。
- **判据**：把引用处那一条与仓里那一条并排放，**有没有一个字是引用处没有的**？有就是摘句了。
- ⚠️ **另有两种漏引要防**：
  1. **只读结论句、不读它自己的射程句。** 引一条已定项之前，把它那一节从头读到下一个标题为止，开头的行一句都不许跳。
  2. **条款自己写了「引用时要连这句一起引」，而引用处没连。** 这类句子优先级高于「嫌长」。
- 材料与附录用脚本做，写材料、生成清单与附录之前先读 `.claude/skills/three-way/SKILL.md`「引 kb 里的条目要整行抄，不许摘句——三处都管」：
  - **别用手抄**（`scripts/kb/quote-kb.py`）；⚠️ **它保证「抄的没错」，不保证「该抄的都抄了」。** **用 `@标题` 取，不用 `:行区间` 取**。
  - **材料要带一张小节清单。** ⚠️ **射程按「这一轮要引的每个 kb 文件」算，不是「被判那一项所在的那一个文件」。** ⚠️ **清单要用 `scripts/kb/kb-sections.py` 生成，不要临时用 awk 抓标题行。** ⚠️ **机器生成的清单不许再过滤。**
  - ⚠️ **附录用 `scripts/kb/quote-kb.py --checklist 清单.md 出口.md 取法…` 抽，清单与附录由脚本绑住。** ⚠️ **正文没点名的枢纽条款，`--cited` 看不见。** ⚠️ **「不抄」的理由要能被核。**
  - ⚠️ **判据表也要照这条办：被判那一项自己交代过的问题，必须各占一格。**

**门禁拦不住这一条**，欠账 C192（摘句引用没有会红的形式）。

## 判决由主 agent 做，不由投票做

主 agent 的职责是**评判**，不是再当一条推论。

- **三方一致 → 继续。** **不一致 → 先核实，再讨论。** 核实指去查能分辨它们的那个事实，不再加一个模型来投票；分歧点写进结论。攻击结果主 agent 逐条现查再采纳，不照单全收。
- **腿要跑的都交主 agent**：照 `.claude/agent-common.md`「子 agent 不交任务」写进报告；要腿接着读输出的，新派同立场的腿，派发提示写一行「承接：<前一份报告的路径>」。腿报告里主 agent 还没复跑出的读数一律当「推的」。
- **一条腿在副本装置上量出来的数，要在入库的装置上重做一次才能引。** 副本上的数不进 kb：主 agent 把它做成入库装置的新一次跑（跑前登记写明核实哪条腿的哪句话），逐字段坐实了才引。
- **攻方腿自己提的收严，只在它自己的模型上量过，算「没被攻过」。** 可以写回，交用户时写明「被攻过零轮」，并给它自己的检查记一笔账。
- **腿提的、判决里标「零轮」的改法，写进产品代码之前先在探针里对它做 A/B。** 有这一改法与没有它两臂喂同一批输入，量它在被打中的那一支上换不换得到东西（写进或出路），换不到的撤回。A/B 读数由主 agent 经任务服务跑出，任务号写进判决「改法」一节那一条；实现员的派发提示引了零轮改法的，带一行「A/B 读数：<任务号>」（`.claude/hooks/runner-dispatch-guard.sh` 判这一行）。
- **攻方腿的装置把用户动作写死时，它报的「分辨臂」可能是装置造出来的。** 判一条臂「在同一段历史上不中」之前，把历史里由用户决定的那几步放开扫一遍，只固定前缀与故障；腿的模型只读导入、核对脚本与产物随判决一起入库。

## 多轮：一次打穿不算数，三轮里多数打穿才算

**开不开下一轮**：第一轮两条腿结论一致、没打中，就停，不开第二轮。有打中的或结论不收敛的，才开第二、三轮：打中的东西先挂起、不直接写进正文，同一个结论再攻两轮，三轮里多数打穿才算打穿；第一轮结论不一致、无法收敛的开第二轮，前两轮不一致、无法收敛的开第三轮。第三轮为最终轮，论证前两轮的结论和判定过程，交主 agent 判断。三轮各换一组攻击面，提示里明令不许重复已攻过的角度：第一轮过度外推与越位 / 内部矛盾与循环依赖 / 哪一条最脆弱；第二轮第一轮的修补本身 / 产生结论的方法 / 从未被看过的地方；第三轮「已定」项撑不撑得住 / 未定项清单的完整性 / 那一轮报出的数字能不能核。其中至少一轮派一条辩方腿复核已有的判决。攻击腿撤回自己先前给的方案，比它打中新东西更有价值。

**第三轮之后停，不开第四轮。** 腿提的收严、主 agent 判决里推的组合都算被攻过零轮；第三轮只攻前两轮站住的形态，这一轮里新冒出来的零轮形态不再为它开一轮，写进判决的交用户表、标「零轮」，要么登记实验量代价，要么另立一题。

**结论从一边翻到另一边时（两边互调），要三条互不共享前提的验证路径。** 一次算术复核不够；三条路径共用同一个前提时，逐格相等也不构成证据。

**岔路交用户定之前，每条路要有代价数。** 没有就先建一个计数模型实验（纯算术、钉绝对值断言、变异表、进 `replay.sh`，形态照 E109（位置权威三臂的运行时代价）、E110（条带表在连续发布下的期望写放大）），在两条臂真的不同的取样点上取样，跑完再交。

**用户叫停、不写判决的轮**，在 `research/prompts/abandoned-rounds.tsv` 登记一行收开工快照，每一行都要出处；写登记行之前，先读 `.claude/skills/three-way/SKILL.md`「用户叫停、不写判决的轮」。

**核查与判决由主 agent 做，不派子 agent 去核子 agent。** 腿交齐之后、写判决之前，主 agent 自己逐条核（命令在 `.claude/skills/three-way/SKILL.md`「核查与判决由主 agent 做，不派子 agent 去核子 agent」）：

1. 倒推出开工快照那一刻的树，在这棵树上核腿的引文。
2. 腿引的每一行产物，在产物文件里逐字找。
3. 判决要引的模型数，腿自己量出的读数不直接引，主 agent 在副本里复跑。
4. 核不动的在判决里写明是哪一条、为什么，不当核过。

**判决从骨架起笔**：开工快照记好之后用 `scripts/agents/verdict-skeleton.py <轮>` 起判决，「这一轮被判过的文件」一节逐个写这一轮判了它什么；起笔之前先读 `.claude/skills/three-way/SKILL.md`「判决从骨架起笔」。

### 交岔路时写岔路单，派实验时带上它

**每段交回对着岔路单判够不够。** 判决里要交用户的岔路另写一份 `research/prompts/<轮>-forks.md`，每条岔路一行，四列：候选（各自的定义）、翻面观测（量出什么数会让选择从一个候选换到另一个）、够判条件（量到哪一步这条岔路就能交用户定）、状态（开着 / 够判 / 用户已定）。只写问题与候选定义，不写倾向、不写已有的数，可以原样发给实验设计员。实验每段交回，主 agent 逐行更新状态；一行开着的都不剩就停，交岔路表，不再续派。

## 一条腿只抽一次样不算一次观测——否定结论尤其不算

模型的答复照 `.claude/rules/test-discipline.md`「单次观测不算数」办。⚠️ **两个方向的门槛不一样**：**打中了**（给出反例、指出矛盾）一次就值得去核，真伪由主 agent 现查坐实；**没打中**（「构造不出反例」「没发现问题」）**一次不算**。

- 拿一条腿的「没打中」支撑任何结论之前，用同一份提示再派一条同立场腿，报告写成 `<轮>-<模型>-s2-output.md`、模型目录写成 `<轮>-<模型>-s2-model/`，不盖掉第一条腿的；两次都没打中才记「没打中」。
- **几份样本一不一致，按每一格答的是哪件事判，不按行号、行标签、措辞、排版与作答次序判**：先按内容对到同一件事上再比，只有一份样本答到的那件事照只有一份样本办。对齐之后结论不同的格记「不稳定」：它不支撑「没打中」，也不算一致；格里任何一份样本给出的反例、矛盾与算出的数，照「打中了」当线索由主 agent 现查，判决里逐条写去向（现查坐实而采、现查推翻而不采、核不动），不整格写「不稳定不采」。

## 云端腿的报告要分段落盘

派云端腿的提示里写明：报告先写进派发提示给的 `research/prompts/<轮>-*-output.md`、最后才回复；**提示里还要写明分段写**：每一次工具调用写进文件的内容不超过 150 行，模型源码与报告都分段追加，第一段排他新建；**提示里还要写明：草稿与临时文件放腿自己的目录**；**提示里还要写明：引 kb 条款时写 kb 文件自己的行号。**

**中途停下、被停或报错的腿，新开一条接着做，不续原来那条。** **上下文多大不是停、不续的理由。** 写派云端腿的提示、接一条失败或停下的腿之前，先读 `.claude/skills/three-way/SKILL.md`「云端腿的报告要分段落盘」。
