# 准入铁律：Show me test（靠 review 的那一半）

## 新增的测试必须先证明它会红

- 先把被测代码改坏，看着测试变红，再改回来；证明不了会红的测试等于没写。
- 两样都要：把「改坏哪里、哪条断言红」做成存进仓里的变异行（`crates/mutations.tsv`）交给门禁反复复跑；变异行之外，commit message 里也写明怎么确认它会红（改坏了哪一行，看到哪个断言失败）。脚本查不了 commit message 那一样，写不出来就是没做。
- 设计论证同样照办：对抗轮打中的每一条，先在模型里做成一个必须报非 0 的世界，再改规则。

## 踩过的坑要做成会失败的检查，不要做成提醒句

形态与立的时机照 `.claude/singlefs-ai-sop/rules/sop-first.md`「推论」与「边界」：做成当场拒绝执行的检查，先记欠账、按批立，正在反复发生的当场立。

### 但要先问这个坑在哪一层：装置里，还是口径上

| 坑在哪 | 检查立在哪 |
|---|---|
| 一段代码的行为里 | 那段代码旁边 |
| **建模口径上**（同一个量该怎么算、边界算不算、单位是什么） | **立在装置之间**：两套装置算同一个量，就要有一条检查逼它们落到同一个数，对不上判红 |

- 判据：换一套装置从头把同一件事再做一遍，还会不会再踩一次；会，它就在口径层，检查跨装置立。
- 跨装置的检查要钉住「这个名字指的是哪个量」：两个量就登记两个名字，各钉各的值（`.claude/singlefs-ai-sop/rules/code-discipline.md`「名字：光看名字，就说得出它是什么、做什么」里「一个语义概念全仓一个名字」那一行）。

# 一条改动不同步铺满全仓时，排除的每一份都要登记

- 一个规范、一次操作、一次改动只铺了一部分文件时，没铺到的逐条登记进一张排除表，一行一条、`#` 后写为什么不铺；没有排除表就是全仓都要改。
- 判据不是「改起来麻烦」，是「改了这句话就成假的，或者改了某道闸就失效」：别家项目的术语与原文引文、某道检查自己的输入、工具自己的模式表、说这次改动本身的那句话，这几类登记，其余一律改。
- 排除表指向不存在的路径判红；表本身要能被一条命令读。
- 成功那句里报的数，本身也要有东西钉住；`gate-lint` 不管这一条，靠写阶段的人。

# 门禁能证明什么，不能证明什么

门禁证明的是证据要求被满足，不是代码语义正确。

## 能通过全部门禁、却仍然是错的

| 情形 | 门禁够不着的地方 |
|---|---|
| 测试测的是实现，不是契约 | 门禁只数有没有测试，不判测得对不对 |
| 声明本身写错了 | 声明与实测一致就判「符合」；没有对照组什么也没证明 |
| 不变量本身就是错的 | 检查会老老实实判一条错规矩，而且全绿 |
| 覆盖的不是出问题的那条路径 | 覆盖率不是正确性 |
| 正文引的数与它自己的产物对不上 | 复跑的区间断言只钉住结论落在哪一档，区间有多宽，正文就能漂多远 |
| 两套装置对同一个量算出不同的数 | 断言与变异只在一套装置内部生效 |
| 设计本身就错了 | 门禁够不着这一层 |

## 推论

1. **门禁绿不等于可以不看代码**：人去看测试测的是不是对的东西。
2. 语义对不对写在 `.claude/kb/decisions.md` 和 `crates/singlefs-checker/invariants` 下各类文件里，门禁只保证它们写下来了、实现了、和代码同步；它们本身写得对不对，靠人。
3. **门禁是下限，不是上限。**
4. 没实现的阶段一直列出来，`gate.sh` 每次都打印这份清单；项目阶段声明覆盖了某一项（`# gate-covers:`）的，那一项什么时候从清单里换下来照 `.claude/singlefs-ai-sop/rules/show-me-test.md`「最终判据由项目定」（这一轮跑过且通过）。
5. **交回的清单能被机器核全，不等于判对了**：子 agent 逐项判的活（回扫、复核），能做成检查的是「每一项都有判定、判定是认得的那几种、理由里引了那一项的原话」，拦得住「抽样够了」「整组放行」，拦不住判错。核全之后在全部判定种类里抽查复判，抽中判错的那一段重做、再抽。

## 不按来源分类，只看证据

不按来源分类，也不给哪一类单开规矩；只分带证据的提交和不带的。

## 跑批脚本不许把单轮的失败吞掉

跑批脚本不许把单轮的失败吞掉（`|| true` 那种），输出路径不跨轮复用。判据是这份输出能不能证明是这一轮产生的：跑之前删掉旧输出，跑完认一个本轮才会出现的完成标记。
