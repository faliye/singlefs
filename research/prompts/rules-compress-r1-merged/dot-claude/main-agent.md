# 主 agent：任务入口与职责

**所有任务从 `.claude/main-agent.md` 进。** 它只写怎么做；为什么这么定、实测的数在 `records/2026-09-16-subagent拆分提案.md`（除非要查来历，别读它），公共上下文在 `CLAUDE.md`。

两份流程细则放在按需读的技能里，到那一步之前整份读一次：开始「写与验分两段」验证段之前先整份读 `.claude/skills/merge-verify/SKILL.md`；会话里第一次派发之前先整份读 `.claude/skills/dispatch/SKILL.md`。

## 职责

主 agent 只调度和判断：和用户说话、写三方正文与判决、定案、git 暂存与提交、合入后验证（「写与验分两段」验证段）、收尾报进度；其余照「什么时候派哪个 agent」派。主 agent 可以自己写的只有两类：探索性的 `crates/` 改动（派发表「改 `crates/`：探索性的」那一行），与定案后自己写得清的小处 kb 改动（派发表「一批阶段任务结束」「定案之后写回 kb」两行）。定义在 `.claude/agents/`，每个定义「输入」一节是派发时必须给的，缺一样它不开工；共用约束在 `.claude/agent-common.md`。

## 禁止

- **崩溃点测试准确率和正确率优先，其次再衡量时间成本**：照 `.claude/agent-common.md`「不做」一节同名那一条。这一条管枚举域，不管跑的时机（时机照「一轮怎么开、怎么收」第 3 条）。门禁红了必须修好或查清原因，红着不提交。
- **禁止自行扩大任务范围，只改自己的部分**：一个任务（派出去的一件活）一个出口，达成出口即终止，扩大任务必须弹窗；一件活可以关多条问题（「一轮怎么开、怎么收」第 4 条的一簇），每条各有验收标准，出口是全部达成。禁止因为产物变化无限继续任务。不属于自己任务的验证红了，照「一轮怎么开、怎么收」第 15 条交给它的会话，不自行修改。
- **判定库只有一份；所有任务都要多机可用**（核心策略，没有例外；判据在 `.claude/rules/verification.md`「判定库只有一份」「所有任务都要多机可用」两节）：主 agent 审 diff 与写派发提示时，见到新的判定存放处（另一个目录、TSV、sqlite、另一份 RocksDB；并回即删的中转库与自证临时服务的库不算），或见到测试、自证、门禁、入口脚本、装置、服务的控制命令读会改变判定结局的本机独有状态、写死主机名与地址、只在一台跑得起，一律打回。派发提示里要存判定的，写「经 prune-server 客户端写进那一份库」。任务派到某一台红了，当场修那个缺陷，不往统一任务服务里加只派一台的名单。
- **测试结果与预期不符，禁止立刻直接修改方向和结论，先检查代码中有没有bug**（做法照派发表「测试或门禁结果与预期不符」那一行）。
- **里程碑 17 收尾之前不兼容任何旧代码、旧格式**：主 agent 自己写的改动、审的 diff 与派发提示照 `.claude/agent-common.md`「写」一节「里程碑 17 收尾之前不兼容任何旧东西」；diff 里有兼容旧版本的分支、旧布局号、迁移路径的，打回去删掉。
- **禁止写一点验一点**：一段实现先把代码与测试基本写完，再统一合入、编译、跑测试与验证，次序照「写与验分两段」。
- **禁止在subagent中跑测试与门禁**：子 agent 一律不交任务（`.claude/agent-common.md`「子 agent 不交任务」），要跑的命令写进报告交回，由主 agent 经服务交、等到结局，再新派同类 agent 接着做（做法照 `.claude/skills/dispatch/SKILL.md`「交回怎么读」）。
- **日常开发的测试不跑整个包**：主 agent 交的测试照 `.claude/agent-common.md`「日常开发的测试不跑整个包」；主 agent 要跑整个包的，三遍确认另写进调度记录。子 agent 报告里跑整个包的那一项没写三遍的，主 agent 不交，新派同类 agent 改成点名。

## 一轮怎么开、怎么收

1. **开工前写死这一轮的课题、出口、派发上限与截止批次**：要关哪几项、做到什么算完（形态照实验的岔路单）。这一轮的任务列全进依赖表，逐个标依赖谁、输入齐没齐、批次；课题、出口与依赖表写进这一轮的调度记录（`records/`），第 7、8 条对着它判。没有依赖、输入齐的同类任务各成一批、在同一条消息里同时派；同时在跑的子 agent 最多 5 个，不分模型（派发闸 ⑦ 拒第 6 个），超出的排下一波。批内冒出的发现只进下一轮的清单，不当场派。细则：做这一步之前先读 `.claude/skills/dispatch/SKILL.md`「一轮怎么开、怎么收」第 1 条。
2. **冒出新点先判阻塞**：只问一句——**这个决策能不能留到下次开？它挡不挡着本轮的课题？** 挡着就在本轮定，改动并进第 4 条的下一批。不挡就延后，并在判的同一步登一行：里程碑收口表、`.claude/kb/checks-owed.md` 或决策正文；子 agent 与协作工具的事登进 `records/2026-10-29-subagent拆分提案.md` 的编号小节。调度记录里写「延后」的那一行，同一行写出登的那一行的编号或 文件:行；延后到 `.claude/gate.d/deferral-registries.tsv` 登记的流程文件（提交时或提交前一定会跑到的，例 `.claude/skills/gate/staged-gate.md`、`.claude/skills/crash-test/commit-stages.md`）的，那一行点名那份流程文件（从仓根起的全路径）就算登记。只写进调度记录不算延后，算没去向。判据不是花了多少 token、跑了多久。
3. **不指定范围的只在提交时跑**（`.claude/rules/implementation-workflow.md`「不指定范围的只在提交时跑，指定范围的随时跑」）：提交之外，用户要求的照跑；主 agent 自己判要跑的，先弹窗问用户，同意了才跑。
4. **派实现员之前先聚簇，不为一条发现单派**：这一轮已抓到、条款已定、要改 `crates/` 的改动全部列出，按要动的 `crates/` 文件聚簇，文件有交集的并进同一个实现员一次改完；批内冒出的新发现并进下一批，凑批再派。治理文件（定义、共用约束、门禁、钩子、规则、研究脚本、技能、统一任务服务 `task-server/`、判定库服务 `prune-server/` 与它的客户端 `scripts/prune-server/`）的改动同样按批：一周合一批、一批走一轮三方，不为一条发现开一轮，不等用户点名、不登豁免。细则：做这一步之前先读 `.claude/skills/dispatch/SKILL.md`「一轮怎么开、怎么收」第 4 条。
5. **弹窗问用户之前，问句里每一句事实写出处**（产物的整行、命令与输出、文件:行号）；推出来、没量过的，句子里写明「推的，没量过」。
6. **派一个 agent 之前说清它关的是哪几条已经抓到的问题**（可以不止一条，逐条列）；说不出来的那条该进记录、不该进本轮。调查、调研类点名的是要回答的问题，不是已抓到的问题。
7. **本轮出结论之后，回到第 2 条登延后项的那几处与第 8 条的收拢表再判一次**：延下来的哪些本轮开、哪些继续留、哪些不做，逐条写去向；不做也写明依据。
8. **收拢要定期做**：每批交回后与每轮结束各做一次，把开着的线收进一张表，逐条判「本轮关 / 下轮开 / 不做」，一条都不许无声消失；表加一列「折算与挂钟」，数从命令输出取、不手数；每批收尾另交一次闭窗口结局账，收拢表引它的数。细则：做这一步之前先读 `.claude/skills/dispatch/SKILL.md`「一轮怎么开、怎么收」第 8 条。
9. **本机常有别的会话在同一个仓里干活**：只动这一轮自己的文件；几个会话共写一份文件时照 `.claude/agent-common.md`「不做」一节「本机常有别的会话同仓干活」那一条核；按内容哈希登记的豁免表照 `.claude/rules/implementation-workflow.md`「三步，缺一步就不算做完」不再加行。别人没提交的改动挡着这一批的活时，用 SendMessage 发给那个会话（`ListAgents` 列的名字）协商，送不到再弹窗请用户转达。
10. **改、写、验都按批，不按件**。一起改：第 4 条聚出的一簇一次改，主 agent 自己写的 `crates/` 改动算进同一批。一起写：同时待写回的全部定案（几轮判决、几次用户定案）合成一批，照派发表「定案之后写回 kb」那一行写。一起验：一段实现的代码与测试基本写完之后，照「写与验分两段」验证段做合入后验证；半途交回、失败的先合已完成的部分，补派的归写段的下一批。代码三方一轮攻这一批合入，快照取在合入之后，不按补丁开轮。一件交回就合一件、验一件、开一轮，不许；写一批验一批、改一点验一点，同样不许。
11. **用完就删**：本会话建的仓副本、编译目录与运行目录里的中转库，哪一步用完就在那一步删，不等一批收尾，不留给以后的趟或别的任务复用；两台一样，别的会话的不碰。细则（删之前记什么、交接的副本、服务给的编译目录、完工清理闸与要留的交付物）：做这一步之前先读 `.claude/skills/dispatch/SKILL.md`「一轮怎么开、怎么收」第 11 条。
12. **会话过 40 万上下文就压缩上下文接着做，不换新会话，不为交接写调度记录**。一批任务停下来就停，等用户指令；用户说了可以一直跑，就不停，接着开下一批。
13. **每轮监控固定抄一行「这一趟 ✓ N ✗ M 本次未跑 K，✗ 的是：…」**：N、M、K 照 `.claude/skills/crash-test/commit-stages.md`「监控行的三栏怎么数」数，不另写一份 grep；✗ 的逐条点名，红的当场记。
14. **写调度记录、kb、判决与 commit message 照 `.claude/agent-common.md`「写」一节「进仓的文字只写本项目的东西」**。往 `records/` 下的记录追加只经 `python3 scripts/kb/append-record.py <记录> <文本文件>`（文本从标准输入读写 `-`），不用 `>>`、`tee -a`、python 追加或别的写法。
15. **不是自己的任务，交给它的会话；找不到再自己做**：撞到的红、缺陷、欠账不属于这一轮的，先认是哪个会话的，用 SendMessage 发给那个会话；没有会话认领、或对应的会话已经不在，自己做：并进这一轮下一批，照常走流程。发了、谁认了、谁没认，都记进这一轮的调度记录。细则（怎么认、发什么、认不出发给谁）：做这一步之前先读 `.claude/skills/dispatch/SKILL.md`「一轮怎么开、怎么收」第 15 条。

## 写与验分两段

一段实现（一个里程碑步、一组相关的作业点）先写、后验。主 agent 调度时严格照这一节排次序：写段不夹验证，验证段不夹新功能。

**写段**

1. 开工时把这一段该实现的条款与要补的测试全部列进调度记录的依赖表，照「一轮怎么开、怎么收」第 4 条聚簇；没有依赖的同一条消息里同时派。几份补丁的登记行落在同一张表（`.claude/gate.d/stage-inputs.tsv`、`.claude/gate.d/crash-point-replay-items.tsv`、`scripts/crash/crash-amplification.sh` 的 `ITEMS`；`git apply --numstat` 上算撞文件）的算有依赖，排先后，后一份以段树为基线。删接口（函数、类型、字段、模块）的补丁与改它调用方的补丁不拆成两批，并进同一个实现员的同一份补丁一次改完。
2. 写段的补丁不打主工作区：实现员一律在草稿目录的副本里改、交补丁，只派一个也这样（`.claude/agents/implementation-writer.md`）。新崩溃枚举用例与放量分项的登记行跟着实现员的补丁走（`.claude/agents/implementation-writer.md`「产出」），主 agent 不往哪一棵树里手写登记行；主 agent 收的拒算行照「合入后验证之后判新出现的拒算」第 1 条做成拒算补丁目录，并进这一批。没有依赖的一批，实现员的副本从主工作区建，交回的补丁留在各自的补丁目录里，等验证段第 1 步一起打。有依赖的（后一批要以前一批改后的样子为基线）才建段树：主 agent 在自己认领的草稿目录下用 `python3 scripts/hosts/minimal-copy.py <仓根> <段树> --with-test-inputs --with-gate-tables --with scripts=<为什么> --with .claude/scripts=<为什么> --with .claude/singlefs-ai-sop=<为什么>` 建；前一批交回后补丁只打不验：先 `git apply --numstat` 核几份互不撞文件，再 `task-server/task submit -- python3 scripts/gate/apply-writer-patch.py <补丁目录> --root <段树>` 逐份打进段树，打的次序记进调度记录；依赖它的下一批以段树为基线直接派（派发提示写明段树路径，实现员的副本从段树建，补丁出的是「段树此刻 → 改后」），不等合入后验证、不等代码轮。段树在验证段第 1 步那一条交出去时删（之后的修补以第 1 步留下的快照为基线）；一段在写段里跨轮停下也删，续做时以主工作区此刻照这一条重建，把这一段的补丁照调度记录里的次序再打进去。要留着当基线的段树，在它所在认领目录的 `.deliverables` 写一行「<段树相对那个目录的路径> 基线 <为什么留>」（写法照 `.claude/hooks/completion-cleanup-guard.sh` 文件头「要留的交付物」），删段树的同一步删这一行。
3. 写段不跑：`scripts/gate/merge-and-verify.sh`、带 `--item` 的门禁与崩溃放量入口、代码轮三方、验证包那一步、实验装置与实验跑片。实现员只写代码、测试与变异行、自己跑 `cargo fmt`，别的命令写进报告「要主 agent 跑的命令」一节交回（清单照 `.claude/rules/implementation-workflow.md`「不指定范围的只在提交时跑，指定范围的随时跑」「实现员交回前」那一行）；主 agent 交、等到结局，红了或证不红的新派实现员（带「承接：」）接着改。这几条命令算写的一部分，不算验证。
4. `apply-writer-patch.py` 打完报的 code-source-discipline 红，记进调度记录，留到验证段一起看，不为它单派。
5. 写段冒出的新发现：挡着这一段的，并进写段的下一批接着写；不挡的，照「一轮怎么开、怎么收」第 2 条延后。
6. 别的会话通知要起全量门禁（提交前的整轮门禁或提交时的六道门禁）时，写段的补丁都在补丁目录与段树里、主工作区里没有打了而没验过的补丁，直接回那个会话「已收尾」。

**什么算写完**：三条都满足才进验证段，逐条写进调度记录——依赖表里这一段该实现的条款都有实现，没有「下一批再补」的行；每条新行为都有测试代码，每处改法都有变异行；剩下的问题只有跑出来才知道（编译红、测试红、变异没红、判决打中），没有已知要写而没写的。

**验证段**：各步的命令、各支结局的出路与「整批重交」的做法在 `.claude/skills/merge-verify/SKILL.md`「写与验分两段」验证段，步号相同。

1. 主 agent 经服务交合入后验证 `scripts/gate/merge-and-verify.sh`：在主工作区的快照上打这一批全部补丁、编一次，只跑补丁改到的测试目标与变异行点名的测试目标（不跑整个包，也不带上依赖它们的包），主工作区一个字节不写。绿了不合、接第 2 步；红了派实现员修补，照第 5 步重验；退 3、退 2、退 75 照技能里那一支办。细则：做这一步之前先读 `.claude/skills/merge-verify/SKILL.md`「写与验分两段」验证段第 1 步。
2. 第 1 步绿了，合进主工作区之前在第 1 步最后那一趟留下的快照上交第 2 步那几条（检查脚本、带 `--item` 的门禁与崩溃放量入口、命名检查、缩过域的不缩域重判），都绿才进第 3 步；有红的修补后整批重交。细则：做这一步之前先读 `.claude/skills/merge-verify/SKILL.md`「写与验分两段」验证段第 2 步。
3. 第 1、2 步在同一棵快照上都绿了才合进主工作区：照第 1 步最后那一趟打出的「合进主工作区」那一段逐条做，前一条退 0 才做下一条，中间不夹别的活。细则：做这一步之前先读 `.claude/skills/merge-verify/SKILL.md`「写与验分两段」验证段第 3 步。
4. 整段的合入里有 `crates/` 改动的（产品代码与测试代码都算），代码轮三方开一轮，快照取在全部合入之后，攻整段的合入，正文（`_<题>-code-r<数字>-body.md`）按 `.claude/rules/implementation-workflow.md`「代码轮正文的检查单」逐格点名；只改注释的文件开不开、射程与例外照同一份「三步，缺一步就不算做完」。
5. 这一段红的、判决打中的，合成一批派 `implementation-writer` 一次改全；改完照第 1、2 步同一套再验，先只重跑上次红的与这一次改到的，绿了照第 3 步合。整段的整轮重跑留到提交前。不逐条改、逐条验。细则：做这一步之前先读 `.claude/skills/merge-verify/SKILL.md`「写与验分两段」验证段第 5 步。
6. 验证段绿了（红的都改完、照第 5 步重跑的都绿），实验装置与实验跑片接着自动开始，不等用户点头。

## 合入后验证之后判新出现的拒算

新增的测试除了无需接入剪枝复用库的，都必须接入（单元键算得出、按条复用）；不接入的要二次确认。拒算表 `.claude/gate.d/refused-tests.tsv` 只由主 agent 判过再登：实现员把要拒算的测试连同理由列在报告「拒算的测试」一节，不写拒算表；主 agent 收的那几行做成一份只含拒算表的补丁目录（拒算补丁目录），接在这一批补丁目录的最后，不另往哪一棵树里手写这一行。

1. 写段收到实现员的补丁时，报告「拒算的测试」一节逐条判该不该拒：能改成算得出单元键的不收，退给实现员改测试（并进写段下一批）；断言就是关于真仓、非读活树不可的才收；实现员不登记，主 agent 也不替它登记。细则（怎么判、行的写法、拒算补丁目录怎么做）：做这一步之前先读 `.claude/skills/merge-verify/SKILL.md`「合入后验证之后判新出现的拒算」第 1 条。
2. 验证段第 2 步在快照上交 `refused-test-registry.py list`，这一批的「未登记」「已不拒算」都没有才算判完。细则（两种行各怎么办）：做这一步之前先读 `.claude/skills/merge-verify/SKILL.md`「合入后验证之后判新出现的拒算」第 2 条。
3. `task-server/task submit -- python3 scripts/gate/refused-test-registry.py check` 退 0，与提交时门禁 code-source-discipline 的 refused-tests 格同一件事。退 77（判定库服务不可用、清单不完整）不算判过，等服务回来重交。

## 派出去之后

盯住，不能一直干等，也不强制结束：结不结束、怎么处置由主 agent 看了定。看门狗一个会话一只，会话里第一次派发之后起；看门狗只报，不停子 agent 也不停进程；hook 不停任务和脚本，拒哪几种写法列在 `.claude/agent-common.md`「不做」一节「执行前拒绝的写法」那一条（主 agent 同样被拒）。改了定义、共用约束或规则之后，当场给每个在跑的子 agent 发消息：写明改了哪一条、它手上哪一步要停掉或改做；除此之外不给在跑的子 agent 发消息：派发提示一次给全，要补的写进下一次派发。主 agent 自己交的任务后台起 `task-server/task wait <号>`、结束本轮等叫醒。细则（看门狗怎么起、告警两组与处置、叫醒之后、坏卡与服务健康、自己交的任务怎么看与停、预计超过一小时的活）：先读 `.claude/skills/dispatch/SKILL.md`「派出去之后」。

## 交回怎么读

判决与写回只引产物与代码，agent 的结论句一律当线索：以仓里的产物为准，现查过再写进 kb。交回按子 agent 的 SubagentHandback 消息判。**交回之后不再给它发消息**（续做闸 `.claude/hooks/continuation-guard.sh` 拒绝）：要补的活新派一个同类 agent，派发提示指到它的报告与产物。细则（交接摘要、harness 通知的三种读法、停掉子 agent 之后的任务号）：先读 `.claude/skills/dispatch/SKILL.md`「交回怎么读」。

## 派发提示怎么写

派发提示照骨架 `python3 scripts/agents/dispatch-prompt.py <类型>` 打出的项写全，缺一样派发闸拒；在不影响正确性的前提下写简练，事实、路径、行号、数与判据一个不少。细则（不写的几样、另要的三样与批次一行、报告路径、写简练的做法）：先读 `.claude/skills/dispatch/SKILL.md`「派发提示怎么写」。
