**读法写死**：

1. **候选的名字**：整体独占记 A，分区记 P，乐观记 O；Q1 的三个候选依次记 Q1甲（准备并行、落盘串行）、Q1乙（一次发布装多个事务）、Q1丙（多次发布同时在飞）。每个量按「臂 × Q1 候选」逐格报，不跨 Q1 候选合并；某一格的判定只对那个 Q1 候选成立。
2. **「同一个落点」**：分配器发出的 `Placement`（用户数据落点与提交内生块落点，`crates/singlefs-core/src/allocator.rs:1377`、`:1431`，按「盘 × 起点槽号」计），再加 journal 环槽、根环槽这两种由计数推出的盘上位置。「同一个 inode 号」= inode 号水位发出的号（`crates/singlefs-core/src/transaction.rs:4839`）。树 ID、事务号、jsn 计数器、checkpoint_txg 的重复各占一行（Q-4 至 Q-7），与 Q-1 至 Q-3 同等判。
3. **「重复分配数」的口径**：一个调度跑完之后，对每一种资源里的每一个被发出的项（一个盘上的一个起点槽、一个号），数「最终持有它的已提交事务个数」，记 `持有数 − 1`（持有数 ≥ 1 时），再对全部项求和；一个调度的重复分配数就是这个和。报：全部调度上的合计、重复分配数 > 0 的调度个数、单个调度的最大值、调度总数。分母是「调度总数」，不是事务数。
4. **「调度」**：n 个事务各自是一串原子步（第五节逐臂写死），一个调度是这些步的一种全交错；冲突重算让一个事务回到它的第一步重来，重来的步也进交错。n 取 2 与 3（问题给的「两到三个」）。
5. **「冲突重算的次数」**：事务在提交那一步（或 P 按设备分区的核对那一步）判失败、回到第一步的次数；报全部调度上的合计、有重算的调度个数、单个调度的最大值、单个事务的最大值。
6. **「吞吐低于串行」在模型层的读法**：模型不计时，量不出吞吐。本登记只报一个同步轮次代理量 R_n（第六节 Q-9），它说的是「每轮能提交几个事务」，能判「不比串行多」，判不出「低于串行」（低于要把重算与校验的时间算进去，那是 Q1 在本机设备上的吞吐测量）。Q4 翻面观测的后一半因此在本登记里只能判到「不比串行多」，余下的写进第十一节「够判停机」。
7. **共享状态的清单**按 `crates/` 今天的实现列全，在第三节；主 agent 点名的六样之外，今天的实现里还有事务号、jsn 计数器、checkpoint_txg、反向链、会话的现行版本、冻结着的发布、系统配置槽世代号几样每次发布都会碰的状态，一并列出，各自标「本登记量 / 不量与为什么」。

### 5.1 模型的公共部分

- 盘数 D（默认 2）。每块盘一张用户数据空闲表：16 个「对」（起点槽 0、2、…、30），取「起点最小的空对」，各盘一致才给号（抽象 `allocator.rs:732`、`:1377`、`:159`）；不建聚簇段，提交内生块另放一个池。
- 提交内生块池：一个 64 槽的开放段，一个 bump 游标，每个节点 1 槽，每次发布 g = 2 个节点（抽象 `allocator.rs:1494`、`:1522`；对齐不建模）。
- 计数的初值：checkpoint_txg t0 = 5，jsn 计数器 c0 = 5，事务号已用最大 h0 = 1，inode 号水位 w0 = 2，树 ID 水位 19（初始态「有文件」）或 11（初始态「无文件」）。根环每区槽数 S（默认 4），根环槽 = (txg mod 3, (txg div 3) mod S)；journal 环槽数（默认 196608），环槽 = (计数器 − 1) mod 环槽数。
- BASE：一个「有没有文件」位与一个版本号；一次发布提交时置「有文件」、版本号加一。计划在视图里看到 BASE「无文件」才发八个树 ID（`transaction.rs:2390` 只在第一个文件版本那次发布）。
- 记账 ACC：每块盘「已分配对数」一个计数，每次提交按臂的写回规则改它。
- 事务形状：**同形** = 每个事务 1 个用户数据单元、建 1 个 inode、1 条记录；**不相交** = T1 只建 1 个 inode（0 个用户数据单元）、T2 只写 1 个用户数据单元（0 个 inode）、T3（n = 3 时）与 T2 同；**多 inode** = 每个事务 1 个用户数据单元、建 2 个 inode（只用于 P区 的预留不够那一格）。
- **Q1 候选决定每个事务自己碰哪些资源**（第三节第 2 条）：
  - Q1甲：事务碰 U、G、I、T、X、ACC、BASE；J / JS、TXG / RS 由一条串行管道按事务号发，不争用，不进交错（这几列在 Q1甲 下报「由串行管道发」，第七节甲给它们的串行值）。
  - Q1乙：事务碰 U、I、X、J / JS；全部事务提交进同一批之后，一个发布者一步发 TXG / RS、G、T、ACC、BASE（这一步排在全部事务之后，只一个，不进交错）。
  - Q1丙：事务碰全部资源 U、G、I、T、X、J / JS、TXG / RS、ACC、BASE。
- **调度**：每一步是原子的；一个调度是 n 个事务各自步序列的一种全交错，重算让事务回到它的第一步（重来的步也进交错）。枚举全部调度；调度数大到不能逐叶枚举的格（P设 D = 2，见第七节乙 7）按状态记忆化计数，结果必须与逐叶枚举在 n = 2 上逐项相等（第七节丙 3）。
- **重复数**：按第一节读法 3，逐资源记。

| **A**（整体独占，支持者的样子） | 一把提交锁罩住「从读共享状态、算这次要的全部号与槽、到写回」整段：今天 `&mut` 独占罩住的就是这一段，支持整体独占的人会把这一段整个放进锁里，不只是候选定义点名的四样 | 1 步 LOCKED：读共享态、按 Q1 候选算本事务碰的全部资源、写回 |
| **A字面**（整体独占，候选定义逐字） | 锁只罩候选定义点名的四样：分配器（U、G）、根环（TXG / RS）、journal 写指针（J / JS）、inode 号水位（I）；事务号 X、树 ID 水位 T、记账 ACC、BASE 不在锁里，锁外按读一份、写回一份做 | 3 步：SNAP_OUT（读锁外几样）、LOCKED_FOUR（锁内四样读、算、写回）、WB_OUT（锁外几样整份写回） |
| **P区**（分区，按区域，支持者的样子） | 用户数据空闲表与提交内生块池各切成 K 个区（默认 K = n，每区 16 ÷ K 下取整个对、64 ÷ K 下取整个槽）；事务开头一步原子地认领一个空闲区并预留号区间（I 预留 r_i 个，默认 r_i = 本事务要建的数；X 预留 1 个；Q1乙、Q1丙 下 J 预留 1 个；Q1丙 下 TXG 预留 1 个；视图里 BASE 无文件时 T 预留 8 个），之后在自己的区里不加任何同步地取落点，提交一步写回自己的区并释放它。区不够或号区间不够时多一步 FALLBACK：再原子地认领一个空闲区 / 再预留一段区间；没有空闲区时这一步不使能（等别人提交释放），全部活着的事务都不使能记一次「死锁」 | 2 步（不够时加 FALLBACK）：CLAIM、COMMIT |
| **P设**（分区，按设备，支持者的样子） | 每块盘的空闲表各一把锁；事务按盘号升序逐盘「取该盘最低空对并标占」，取完核对各盘是否一致（今天各盘不一致即拒，`allocator.rs:159`）；不一致就撤掉自己在各盘的标占、重算，重算上限 2，超过记「截断」。号区间与 P区 一样在 CLAIM 里预留；G 在 COMMIT 里从池级游标取（游标在 COMMIT 这一原子步里） | CLAIM、DEV_0 … DEV_{D−1}、CHECK、COMMIT |
| **O整**（乐观，整版校验） | 事务开头拷一份全部共享态并记下版本号；按拷贝算；提交一步里版本号没变就写回、版本号加一，变了就重算 | SNAP、COMMIT |
| **O读**（乐观，按读集校验，支持者的样子） | 支持乐观的人不会让事务号、jsn、txg 进拷贝：这几样在提交那一原子步里按当时的共享值发（排序器在提交点上）。提交只核本事务真读到的：它取的每个用户数据对在每块盘上仍空、G 的游标没动、I 的起点仍等于当前水位、发了 T 时 T 的起点仍等于当前树 ID 水位、Q1甲 与 Q1丙 下 BASE 版本号没变（这两个候选下一次发布要重写建在 BASE 上的树根，第三节第 2 条）；Q1乙 下 BASE 不进读集（批发布者合并） | SNAP、COMMIT |

「做完会怎样」只写一句、都由上表的步推得出：A 的全部资源在一个原子步里发，同一个号或槽不会发给两个事务；A字面 锁外几样在 SNAP_OUT 与 WB_OUT 之间可能被别人改；P区 在 K ≥ n、预留够用时各事务的区与号区间互不相交；O整 每次提交之前有别人提交过就重算；O读 只在读集被人改过时重算。

### 5.3 阳性对照（每条臂都跑，各自关掉自己那条臂的护栏；「必然重复分配的分法」）

### 5.4 真实基线

**S（串行，`crates/` 今天）**：n 个事务按下标一个接一个跑完（只有 1 个调度），每个事务从上一个提交的结果现算全部号与槽（`transaction.rs:3420`、`:4732`、`:4733`、`:4839`，`allocator.rs:732`）。重复数 0、重算 0，各号的值等于第七节甲。它是 D13 已定项 2 定案的形态（「事务层先承诺串行提交」），也是 R_n 的对照（R_n = n，第六节 Q-9）。

### 5.5 实现量与分段

格数：臂 6 + 阳性对照 6 + 基线 1；Q1 候选 3；形状 3（多 inode 只在 P区）；n 2；初始态 2；D 2；第八节的几何点另加。除 P设（D = 2）要记忆化计数外每格都在千万调度以内。要另写的子系统只有调度枚举器（逐叶 + 记忆化两种）与重复数计数器，没有检查器、崩溃枚举、坏镜像。

- **第一段**（补 Q4 的「重复分配数」与「冲突重算的次数」两半，补完 Q4 够判条件就齐）：第十一节停机条款的逐项对拍（第七节甲的锚点）→ 全部阳性对照与第七节乙的锚点 → 六条臂在默认几何（D = 2、S = 4、环槽 196608、K = n、r_i 够用）、同形与不相交、初始态两种、Q1 三个候选、n = 2、3 上的 Q-1 至 Q-9 → 第八节「几何敏感性」的第一个反向取样点（D = 1）。
- **第二段**（只在第一段交回后主 agent 判 Q4 还差时才跑）：第八节其余取样点（K = n − 1、多 inode 预留不够、S = 1、环槽 2）与附带量 Q-10。

## 八、轨迹与几何敏感性

### 轨迹

本模型里的「轮」：枚举时是调度里的一步（原子步的序号），Q-9 是同步轮次。被谓词消费的量与它们报的三样：

| 量 | 消费它的谓词 | 报的三样（每格对全部调度汇总） |
|---|---|---|
| 已提交事务之间的重复数（Q-1 至 Q-7 逐资源） | Q4 翻面观测「> 0」 | 每个调度上的峰值取最大、为正的步数合计、期末值合计（= Q-1 至 Q-7 报的合计）与期末值 > 0 的调度数 |
| inode 号水位余量 = 共享水位 − 已提交事务持有的最大 inode 号 − 1 | I-9.6（水位大于两处最大号，`transaction.rs:2576`、`:6262` 注释引它：水位与树里最大 key 的关系在盘上判） | 每个调度上的最小值取最小、为负的步数合计、期末值的最小值；为负说明共享水位退到了已发出的号之下，之后取号会重 |
| P区 在飞持有的区数、预留未用的 inode 号数 | P区 的 CLAIM 使能谓词（有没有空闲区） | 峰值、为正的步数、期末值（期末应为 0 区；预留未用的号期末值照报，它是号空洞，归属见第十一节） |
| Q-9 每一轮提交的事务数 | R_n = n 的判定 | 峰值、提交数 > 0 的轮数、最后一轮的提交数 |

只报期末值的格，正文不写「从来」「恒」。

### 几何敏感性（`mutation-sampling.md` 第六类）

默认取样点：D = 2、S = 4、环槽 196608、K = n、r_i = 本事务要建的数、形状同形、初始态有文件。每个带判定的格至少在一个方向相反的取样点上重跑判定那一格：翻面记「不稳定」，不翻记两点。

| 取样点 | 方向 | 预期它动哪几格（推的，不进判据） | 段 |
|---|---|---|---|
| D = 1 | 盘数从多到一 | P设 的不一致与截断应为 0（乙 7 已算）；别的臂的 U 列应不变 | 第一段 |
| 形状 不相交 | 事务之间的读集从全重叠到部分不重叠 | O读 在 Q1乙 下的 Q-8、Q-9 | 第一段 |

### 二、装置对登记含糊处取的读法

依据的单测读数：`research/e7-index-bench/src/bin/e166_parallel_commit_shared_state_partition.rs` 里 `positive_controls_and_partition_cells_match_the_independently_calculated_values` 等 21 个单测 2026-10-01 全绿（rustc 直编的测试二进制，报 `21 passed; 0 failed`），其中第七节乙组与甲组、丙组的 92 条锚点逐条与登记的值相等。下面三处读法都是这 92 条同时成立的唯一读法。

1. **U 一列（用户数据落点）的计数口径**：各盘空闲表同步变化的臂（A、A字面、P区、O整、O读与它们的阳性对照）按一个起点槽计一次，不乘盘数；P设 各盘表各自变化，按「盘 × 起点槽」计。读数：锚点「乙1 A去锁 n=2」观测 `schedules=6 U=4/4 G=8/4 I=4/4 X=4/4`，与第七节乙 1 逐字相等，而装置跑在默认盘数 2 上；乙 1 的 U = 4 / 4 在 D = 2 下只有按槽计一次成立（按「盘 × 槽」计，每个重复项在两块盘上各记一次，得 8 / 4）。第八节几何取样点 D = 1 的预期「别的臂的 U 列应不变」同样只有这个读法下成立。判据（> 0 即出局）不受这个读法影响（多乘一个盘数不改变「是不是 > 0」）。

import itertools
def rounds(types, order):
    # types: tuple of (u,m). conflict between a,b iff both u or both m (read-set overlap at commit time).
    remaining=list(range(len(types))); count=0
    while remaining:
        committed=[]
        for t in order(remaining):
            if not any((types[t][0] and types[c][0]) or (types[t][1] and types[c][1]) for c in committed):
                committed.append(t)
        remaining=[t for t in remaining if t not in committed]; count+=1
    return count
kinds=[(1,1),(1,0),(0,1)]
for n in range(2,8):
    diff=0
    for types in itertools.product(kinds,repeat=n):
        a=rounds(types,lambda r:r); b=rounds(types,lambda r:r[::-1])
        if a!=b: diff+=1; ex=(types,a,b)
