> **这一处代码的行为，是从哪条已定分项推出来的？推不出的那些，它是在替一条没写的条款做选择吗？如果是，这个选择今天有没有会红的东西钉着？**

三种结论，每格只能落一种：

| 结论 | 什么样 | 要交出什么 |

| **兑现了条款** | 行为是某条已定分项的字面后果 | 那条分项的**整段原文**，加从原文到这段代码的那一步 |
| **替没写的条款做了选择** | 不同实现会做出不同的、都说得通的选择 | 那个选择是什么、它影响哪些字节或哪条可达历史、今天有没有会红的东西钉着 |

## 三、六格（X1–X6）

### X1　挂载态整片读中央映射（线二）

`open_pool_for_read` 读一次映射树根就把整片条目解进挂载态，`central_mapping_lookup` 的签名里没有 `reader` ⇒ 查中央映射本身不发设备读。「提示过期的一次解引用发 3 次设备读」这个读数整个骑在它上面。**线二现状自陈这一格没有条款**：D19（块指针的结构与宽度预算） 已定项 5 只定了「映射是解引用的唯一入口」，没说要不要现场读。今天由「映射树根不是根兼叶就拒绝打开挂载态」挡着——那是实现自己选的。

### X2　树节点那一侧没有经映射的回退（线二）

树表、树根、inode 叶容器只按位置提示读，不经映射回退。线二现状写明「与冷走读今天同款，不是这一轮引入的」。要判：这是哪条分项的后果，还是两处都在替一条没写的条款做选择（C483（挂载态读映射与树节点回退都没有条款））。

### X3　inode 树根的 key 区间取分隔 key 的首尾（线三）

`inode_tree.rs` 跟 checker 今天的 `check_index_node_keys` 走，取分隔 key 的首尾、不取子树范围。口径的账在 C478（码 2 头的 key 区间是条目键区间还是子树覆盖区间）。要判：两种取法在盘上分不分得开、今天这一种有没有会红的东西钉着。

### X4　inode 记录 `blocks` 字段与建 inode 的固定值（线三）

`blocks` 改成结构体字段、文件版本填 64、没写过数据的填 0（账在 C480（inode 记录的 blocks 怎么算全仓没有条款））；没有目录时新建 inode 的 mode / uid / gid / nlink 写死 `0o100644` / 0 / 0 / 1。要判：写死的那四个值是不是也在替条款做选择。

### X5　一次发布只重写被改到的那几片叶容器（线三）

线三现状逐字「今天只有用例钉着，没有条款也没有不变量」。要判：它该不该是一条不变量；不该的话，用例钉住的是不是够。

### X6　mkfs 整环清零走的块设备动作与段序列的步骤种类（线四）

块设备抽象今天五个动作（读、写、屏障、FUA 写、探测），整环清零今天怎么落的、它在段序列登记表里算第几种步骤（登记表已从五种改成六种）。要判：第六种的引入是不是 D17（实现分层与第三方管道） 已定项 2「等价类按每段的步骤种类集合判」的后果，还是又一次替条款做选择。⚠️ 与它同族的两处已知缺口：C485（门禁 52 号不读活代码，段序列变了它照样绿）、C487（门禁 55 号拿活代码与不跟踪它的模型比）。

## 五、跑前写死的判据

1. **一格算「兑现了条款」，当且仅当抄出了那条分项的整段原文，而且从原文到这段代码的那一步不引用任何没有条款的取法。** 抄不出原文的一律算「推不出」。
2. **一格算「和条款说反话」，当且仅当指出了具体是哪个字节或哪条可达历史上看得出差异。** 只说「读起来不一致」不算。
3. **一格算「替没写的条款做了选择」，当且仅当说得出两个都说得通的不同选择，而且它们在盘上字节或可达历史上分得开。** 分不开的不立条款，登记成实现细节。
4. **本地攻方那张表，一格填 unknown 不算失败**，但 unknown 的格数要报出来；四列里只要有一列填不出判据来源的行号，那一行整行作废。

**什么观测会让这几条触发**：第 1 条在 X5 上大概率触发（线三现状自陈「没有条款也没有不变量」）；第 2 条在 X6 上有机会触发（段序列登记表已改成六种，而 D17（实现分层与第三方管道） 已定项 2 的原文只说按步骤种类集合判，没说种类表由谁定）；第 3 条在 X4 的四个写死值上触发；第 4 条在 `bin/` 那三个文件上大概率触发（它们多半一条变异都没有）。四条都写得出触发观测。
