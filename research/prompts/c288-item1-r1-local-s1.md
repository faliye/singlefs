1. Encryption. For layout A, type 3 header with encryption would have birth sequence at offset 103-106. The plaintext header ends at 69 (42 common prefix + 12 nonce + 16 MAC). Birth sequence is in ciphertext. Total header size would be 42 + 12 + 16 + (107 - 42) = 135, exceeding F5's fixed 131 size. For layout B, type 3 birth sequence at 103-106 causes same header size issue. For layout C, type 3 birth sequence at 103-106 causes same header size issue. For layout D, type 3 birth sequence at 81-84 is in ciphertext. Total header size 135 exceeds 131. All layouts place birth sequence in ciphertext, causing header size to exceed F5's fixed size.

2. Scan rebuild. All layouts have birth sequence within the header. For example, layout A type 2: birth sequence after write sequence, before payload CRC. Mapping key components (type tag, birth tree, birth txg, instance id, birth sequence) are all present in the header. Layout B type 2: birth sequence after reserved. All components present. Layout C type 2: birth sequence between payload CRC and reserved. All components present. Layout D type 2: birth sequence after birth generation. All components present. No case where components cannot be read from header alone.

3. Hidden ordering constraints. F3 fixes type 2 identity segment field order: tree id, level, key range, birth generation, fsid, write sequence, payload CRC, reserved. Layout A places birth sequence between write sequence and payload CRC, violating order. Layout C places birth sequence between payload CRC and reserved, violating order. Layout B places birth sequence after reserved, making reserved not last field, violating order. Layout D places birth sequence between birth generation and fsid, violating order. All layouts violate F3's fixed field order.

4. Allocation rule gap. The birth sequence offset does not depend on F9's missing allocation rules (initial value, step, renumbering). The offset is determined by layout design, not by how the birth sequence counter is incremented or reset. No case where offset depends on allocation rules.

Layout B: Adding F7 type tag copy for type 2 would move reserved and birth sequence if added before reserved. Widening reserved moves birth sequence. Layout C: Adding F7 type tag copy for type 2 would move birth sequence and reserved if added before birth sequence. Widening reserved moves birth sequence.
