## 二、Q1　I-3.1 整份改记读法加逐槽两判

### 先推一步：四判都成立时，记账还能藏什么

改记那一份四判（10532–10549）都成立时，同一块盘上有 W ⊆ E_class(θ_high) ⊆ E_class(t) ⊆ W ∪ Q ∪ U，且 |E_class(θ_high)| ≤ 记账 ≤ min(|E_class(t)|, |Ω ∪ U|)（E_class 是改记那一份，W 是遍历走到的槽，Q 是隔离豁免的槽，U 是已释放、释放代高于 t、没走到的槽）。U 与 Q 都按自述的记录算，改记不碰：「let still_deferred_outside_the_walk: BTreeSet<u64> = records_of_the_newest_root」（`crates/singlefs-checker/src/walk.rs:10421`）只取已释放的记录，「if record.is_released || referenced_start_slots.contains(&(record.device, record.slot)) {」（`crates/singlefs-checker/src/walk.rs:10197`）按自述跨度归组。所以记账在个数上一定落在改记那一份的 RCW 带里，按个数藏不住泄漏或漏数（推的）。剩下藏得住的只有记录一级的：E 按槽取并集，两条记录罩同一槽只算一次。

自述与改记两份 E 只在 I-3.18 判红的那几条记录的跨度上不同。窄记录改宽多出来的尾槽，要让两种读法判得不一样，它就不能在自述那一份 E(θ_high) 里；它若同时被另一条记录罩着，那条记录有两种：已释放、释放代不高于 t（已回收、条目不删，还没复用），它不在 E(t) 里，尾槽在写者眼里就是空闲的，正是 I-3.18 条文说的「可被重新分配」那个状态，不另算一样病；已释放、释放代在 (t, θ_high]，尾槽在写者眼里还在 defer、不许复用，却已经压着 X 的尾槽——这是下面打中的那一形（推的，模型 `i31_q1_sweep.py sweep 4` 把两种分开数，待跑）。

### 第 3 问　第 0 代根按 None 记、组合上界 4096

**None 会不会把该红的环落成部分没判：不会（推的，论证如下）。** 第 0 代根那一种只在「落点式的正 txg 认完了」时出现，而那时先推的一定是空着（9022），第 0 代根是同一槽的另一种。把同一组别的槽固定，记空着那一种的环为 V、它的上限为 c0，第 0 代根那一种为 V ∪ {G}（G 是 txg 0、最旧）。G 的指针是 None，它与它后面那一条 S1 都算空不空判不了；上沿把它们一律计入，计入的集合比 V 那一份只多不少（多 G，S1 原来没计入的话再多 S1），而 G、S1 是最旧的两条。逐种：V 计入 ≥ 4 条时第 4 新的那条不变，上沿 ≤ c0（G 只可能给它那块盘添一项 0）；V 计入 3 条时，S1 原来非空则第 4 新的是 G = 0，S1 原来是空的则第 4 新的是 S1、等于 c0 的「最旧有效根」；V 计入 ≤ 2 条时上沿取最旧有效根 0。所以第 0 代根那一种的上沿不高于 c0：V 判红（F > c0）时它也判红，不会因为 None 而落进两沿之间。真住户若是空着与第 0 代根以外的别的可能，它们照常各判。

**用「mkfs 树表 0 条」判得了。** 格式那一边写死了第 0 代根的树表：「| m2 | mkfs | 树表单元第 0 版（0 条条目） | 2 | 16384 | 50178 | — | 七 |」（`.claude/kb/layout/01-first-txn.md:59`），它的两棵用户可见树都没有，指针就是 ABSENT。池级 checker 不引实现，但这类格式常量它已另记一份：「const GENESIS_ROOT_INSTANCE: u32 = 0;」（`crates/singlefs-checker/src/walk.rs:8963`）。写者在抬 F 那一刻照读 m2（第 0 代根是有效根时 F = 0、环里最旧有效根是 0，m2 的释放代 ≥ 1 高于回收门槛，不会被复用，推的），读到的也是 ABSENT。按 ABSENT 记不引入误红，只会把一部分「两沿之间」改成成立：第四节第 4 问那张第 0 代根镜像上，今天部分没判，按 ABSENT 记成立（手算，模型 `q3_mirrors.py` 的 `genesis_known` 那几行，待跑）。
