Background (settled): code 1 units are data units written by the transaction itself before its journal record; their header carries a five-tuple identity, a birth checkpoint number and a 10 byte write sequence (instance id, transaction number). Code 3 units are packed record containers written only at the fixed point of a checkpoint, once per checkpoint per instance; their header carries a four-tuple identity, a birth checkpoint and the same write sequence field, whose transaction number is the largest allocated in that checkpoint. Every publish increments the checkpoint number. Persistent order per publish: units, barrier, journal records, barrier, root slot. The root ring keeps the last K roots; the region of a root is checkpoint number modulo R. Recovery picks the newest readable self-consistent root, then applies journal records after that root's tail in strictly consecutive journal sequence order, stopping at the first gap; the journal sequence number is the instance id in the high 32 bits and a counter in the low 48, so replay can never cross an instance boundary. Transaction numbers are per instance and monotonic; records are appended in transaction number order; the first release commits serially.

The eighth version:

P1 failure table, four cells, two branches. (1) failure before taking a number: nothing. (2) after taking a number, before any unit write was issued: burn the number. (3) after a unit write was issued: a single replica failure retries elsewhere with the same write sequence under a wall clock budget T_retry. (4) fixed point or publish stage failure. For cells 3 and 4 the handling depends on the nature of the failure. Transient failures (one I/O error, one root slot write failure, one non-converging fixed point) do an instance switch: a recovery inside the running mount that takes a new instance id, writes a row for the old instance, reissues the in-flight checkpoint, keeps transactions at or below W and redoes the ones above under the new write sequence. Resource and persistent failures (allocation failure, writable device count dropping below the w floor, the same root slot failing repeatedly, more than N_switch consecutive switches) turn the volume read-only until the next mount; that branch needs no allocation and writes no unit. The blocks an instance switch would need are reserved before the number is taken; if the reservation fails the read-only branch is taken. A root slot write failure advances the checkpoint number by one before reissuing, so the retry does not land on the same ring region.

P2 instance table rows are (instance id, T_pub, W). T_pub is the checkpoint number of the root the recovery chose. W is the largest transaction number of that same instance applied by this replay; because replay cannot cross an instance boundary, every instance other than the chosen root's has W = 0. Rollback writes (r_old, T_old, 0) with a rollback flag that later recoveries may not overwrite, plus (i, 0, 0) for intermediate instances; the replay lower bound also honours the rollback flag, applying that instance's records only up to the row's W. Published predicate for a unit (i, n) with birth b: if i is below the mounted instance, no row means published, a row means, for code 1, b at most T_pub or n at most W, and for code 3, b at most T_pub. If i equals the mounted instance, b at most the mounted root checkpoint. A row may be deleted only when one full sweep pass reached a verdict for every location in the pool with no unpublished unit of that instance among them, no read failed during that pass, all devices are online, and no root of that instance is in the ring. Writable mount admission: writable device count at or above the w floor, exclusive open of a majority of the pool's devices, instance table readable, switch reservation obtainable. The new instance id is max over the superblocks of that majority set and the ring roots, plus one, written to every superblock of that same majority set, all or nothing. Visible means exclusively opened and the superblock reads back. A device that missed a take-a-number is written off entirely when it returns and stays read-only until resync.

P3 current version: replica merge, then visibility by published plus birth at most the root's checkpoint plus an ancestry entry, then the largest per-class key: the write sequence for code 1, the pair (birth, instance id) for code 3. Dead if a visible tombstone names the key with a death write sequence at least the chosen version's.
