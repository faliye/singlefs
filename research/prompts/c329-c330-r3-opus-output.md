## 三、X2：主人行会不会被之后一次恢复的批量写盖掉

### 为什么跨恢复盖不到（推理，剧本在下面验）

1. 行只在一个实例的第一次发布里写（D18 第 879 行「只在恢复与回退时写、与第一个新根同一次发布」；P329″ ① ②）。
2. 实例 j 的每一个根指着的那一版表 = j 所选根那一版 + j 写的 [所选根的实例, j) ⇒ 里面只有 < j 的行（I-3.8（实例表行唯一且低于挂载根） 第 127 行「行的实例代号 < 挂载根实例」）。
3. 之后一次恢复选根 (s, T)，在 s 那一版上写 [s, 新实例) ⇒ 它写的实例与底版里已有的实例不相交 ⇒ 第 879 行「按实例代号唯一、后写覆盖」对上一次写出的行永远不触发。它只在同一次发布里两条规则写同一个实例时才触发——那正是 X3 的三格。
4. 能盖到主人实例 k（(k, 0, W_k) 或 (k, T, W_k)）的批量写，所选根实例 ≤ k；实例 ≤ k 的根都比切换实例 k+1 的重发旧，被照旧的单元住在 k+1 的重发里，不在那条时间线上 ⇒ 那一格该判未发布，(k, 0, 0) 判得对；k 自己是所选根实例时它得 (k, R 的 T_pub, 重放出的 W)，重放若施加了 k 失败那次的记录，被照旧的单元就在时间线上、判已发布也对。
