## 三、逐格判决

### S1　分配记录树的几何

**叶怎么划：主 agent 定，不交用户。** 攻方打中一处：叶边界与两槽单元错开、点查只看本叶、分配走回落，三样同时成立时同一次发布里的一个节点写掉数据单元的后半槽，根落盘的那个状态 checker 判红（`selftest.out` 第二组、`scan-rest.out` 的 `S1-Absent-NoLookBack-odd-fallback`）。两种改法同一批历史都 0 红：叶宽取偶数、叶边界按绝对槽号划；或点查回看前一片叶。定前一种：叶罩的槽段由绝对槽号直接算出，节点头里的 key 区间就是这一段，一个节点单独捡起来就判得出「我管的就是这一段」，checker 加一条「记录的末槽不越过它所在叶的末槽」逐节点可判；回看前一片叶要读别的节点，自证不了。今天的实现不会撞上（两槽单元都起在偶数槽，分配器用内存位图、不去树里点查）。被攻过零轮。

**缺席段：交用户（K1）。** 崩溃历史上「缺席 = 全空闲」与「写空叶」零对零。分得开的是写者漏掉一片叶的指针：缺席那一边挂载后点查把 16 个活槽全答成「空」，写空叶那一边 16 个全拒（`selftest.out` 的 `KNOWN_BAD_DROPPED_LEAF_POINTER`）；也就是缺席那一边违反 D21 已定项 11「损坏必须可检出」的运行时形态。代价：写空叶 mkfs 要写 532 / 10274 / 166158 个节点（4 GiB / 64 GiB / 1 TiB），缺席 8 / 8 / 10（`cost.out` 的 `mkfs_nodes`）；今天没有层 0 流覆盖 mkfs。

**层数（本地腿，两次抽样一致）**：叶 812 条、内部扇出 169（条目 96），4 GiB / 64 GiB / 1 TiB / 16 TiB 分别 3 / 3 / 4 / 4 层，写满时 264 / 5136 / 83078 / 1330154 个节点。

### S2　extent 树的形状

四个候选下段都一样：一个文件一棵按单元号按位置寻址的树（叶 144 个单元、内部扇出 147），洞就是缺席。差在上段：

| 候选 | 判定 | 依据 |
|---|---|---|
| 全局两段按 key（上段按 (locality, inode) 排） | **出局**：上段按 key 排就得分裂，与用户 2026-09-24 定的「派生树按 key 空间定形状、不分裂」相反 | 原型 `KTree::insert`；推的 |
| 每文件一棵、根住 inode 记录 | **出局候选**：86 字节根指针要住进已冻结、只剩 20 字节预留的权威态 inode 记录；重建一棵派生树要重写权威态容器 | 攻方附录第 7–10 段；推的，没跑 |
| 全局两段按位置 | **打中**（不是崩溃）：一次挂载里连续建小文件第 14625 次被拒，拒的时候两盘还空着十六万多槽（D3 已定项 9 第 1 条「df 报出的空闲 ≥ s，写 s 必须成功」） | `cost.out` 的 `manyfiles` |
| 全局两段按位置、单单元文件内联 | 唯一没被打中的：连续建 3 万个小文件不拒，其余代价与不内联的相同；崩溃历史没扫（用户取消），全量留给最后统一的层 0 | `cost.out` |

「一个文件至少一个节点」加「这次挂载开过的段不给用户数据」是假性 ENOSPC 的病根，每文件一棵与全局按 key 两个候选同样中。交用户（K2）。

### S3　节点格式与自描述

正推：树 ID、层级、诞生代号三样 D18 已定项 18 的码 2 头本来就带，不用改。key 区间：按位置寻址的树，节点头里写「按位置规定罩的那一段」，与 D18 已定项 2「子树覆盖区间」的字面在这类树上是同一段，写回时在 D18 已定项 2 射程里补一句按位置寻址的树怎么取；随 K1、K2 定案一起写。D21 已定项 11 在这套结构上靠两样兑现：节点头的四样自描述、checker 按位置独立算出每个节点该罩哪一段逐节点核（S1 那条「记录末槽不越过叶末槽」是其一）。

### S4　写序与层 0

所有候选都不多一道屏障、不多一段。第一个事务那条层 0 流里 18 写的那一段涨到 30 写（4 GiB）到 50 写（1 TiB 写空叶）。新写序三种要进层 0：长高多层（旧根与新根之间那一串位置 0 的节点同一次发布写）、矮下去多层（同一串一起释放）、内联与下段互换（只有内联那个候选有）。攻方原型自己在长高、矮下去上各写错一次，都是静默的洞或泄漏，只有全量 checker 的 I-3.1 那一半判得出：这两种写序的 checker 判定要随实现一起做。

**释放链：打中不分辨臂，另立一笔账（K3）。** 老化之后一次覆盖写要改的分配记录叶平均 13.38、最多 68 片，末条点名最多 76 > 67，ckpt_cost 的「Σ当前的高」在 3 万多次发布里一次都没兜住。S1 四个、S2 四个候选、4 GiB 到 1 TiB 都在同一量级，病根是共用前提「分配记录树给自己的节点记分配记录，且树多于一片叶」，不拿它判 S1、S2 的臂。末条超过 67 由用户 2026-09-24 定的「末条再跨记录」接住（实二十在做）；ckpt_cost 兜不住另是一件。攻方提的「分配记录树节点专区」在它的模型上把链叶压到最多 12 片、末条最多 20，崩溃模型 0 红，被攻过零轮，区本身在 1 TiB 铺满时要多大没量。

### S5　与别的结构的咬合

正推：中央映射（D19 已定项 5、8、12）三句都不动；回收（D3 已定项 7、C518）不动；记账的态别判据不动。准入：公式不动，分配记录树的高是 mkfs 参数的确定函数，extent 树的高按文件变，两棵不对称，随 K2 定案写进 D28 已定项 4 怎么读。挂载怎么读：推不出，交用户（K4）。
