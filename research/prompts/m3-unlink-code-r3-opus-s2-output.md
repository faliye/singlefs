### 装置

原型 `probe-s2`（`research/prompts/m3-unlink-code-r3-opus-s2-model/probe-s2/src/main.rs`）。每段历史在内存稀疏盘上造到卸载之前那一刻，录下卸载那一串的写流（带卸载入口），用 checker 档库的 `enumerate_layer0_selecting_versions_observing_each_state`（每一段都展开，与 `enumerate_layer0_versions` 同一个枚举域；观察者只记持久集合，枚举完再按 15 个线程并行判，状态一个不落）取全部崩溃状态。每个状态再分三种：两盘都在、丢盘 0、丢盘 1，各自：

1. `recover` 择根；
2. 那条根在卸载之前、没被写过的镜像上引用的落点（mount.rs 里 `placements_referenced_by_root` 与按映射现算那一份的并集，经 `patch-tree.py` 加的只读口子取），逐个比幸存盘上这一状态与卸载之前的字节——「被写掉」就是这一项不为 0；
3. `mount_read_only`、打开第一个文件、整份读回（用户看得到的那一层）；
4. 丢盘的两种另跑池级 checker（两盘都在的由枚举器自己跑）。

两臂：c1 = 冻结副本原样；held = 只把 mount.rs 第 2259 行改回 `HeldUntilFloorTakesEffect`（正文第五节点名的那一刀）。静态扫（`n1-scan`）不枚举，只算「S 上落下第一条带新 F 的根那一次发布（含）之前这一串重写的单元」与「S 单独恢复择到的根引用的落点」的交集（窗口交集），用来放开扫用户决定的那几步。

## 这条腿自己的限度

- 单盘镜像是两块盘里丢一块；三块盘以上、条带宽度不同的几何没造（第一版几何 R = 3、区域归属 0 / 1 / 0）。
- 静态扫的「窗口交集」按「幸存盘上落下第一条新根那一次发布（含）之前这一串重写的单元」算；它是枚举之前的筛子，打中的三段历史都用层 0 全量枚举逐字节坐实了，没打中的格只做了静态扫、没枚举。
- 族 0 的枚举里枚举器自带的 oracle 每个状态都报违例（例「走到实例 2 第 21 代根报没有文件」）：我给的版本表只收了读得出文件的根，删除中与删完的根不在表里，这是我装置的缺口，不是发现；判定只用了我自己逐状态判的那几样与枚举器的 checker 表。族 2 的两盘都在状态 oracle 0 违例。
- 只读挂载与读回只开了第一个文件；族 0 那几段历史里文件在删除中，读回本来就是「没有这个 inode」，用户看得到的差别只在 C 的只读挂载上。
- 卸载—再挂循环里第二次卸载没造：机理与第一次卸载相同（推的），没量。
- perdisk 只在 A、C 两段历史上全量枚举，B 没跑；perdisk 在准入那一格不变。
- 原型合计枚举 37 次、349428 个状态（探索 3 次、正式 9 次、三次复跑 7 + 9 + 9 次；每次一段历史、都不超过 12330 个），远在 10⁶ / 10⁷ 之内；崩溃状态没有缩、历史条数也没缩。取样与估时：先串行跑了 X 那一段（观察者在调用线程上逐状态判，8223 个状态 588 秒），之后把逐状态判挪到枚举之后 15 线程并行，一段 8223 个状态 26–128 秒、12330 个状态 110–120 秒，一次只跑一段（批里一件），不设限时。静态扫与 N2 不枚举崩溃状态。
