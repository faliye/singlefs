## 二、判据 4-1：登记表逐行对源码

判红条件逐字是「表里某一行的段序列与 E142（第一个事务的干跑） 源码或产物对不上」。**四行的段序列我一行都没打中**，先把核的过程写清楚，再写围着它的三处。

### 2.1 切段规则：源码怎么实现 FUA 边界

`research/e7-index-bench/src/bin/e142_first_transaction_dry_run.rs` 第 2384-2409 行 `fn split_into_segments`（整段抄自源码）：

```rust
fn split_into_segments(operations: &[RecordedOperation], fua_is_boundary: bool) -> (Vec<WriteRequest>, Vec<Vec<usize>>) {
    let mut writes = Vec::new();
    let mut segments: Vec<Vec<usize>> = Vec::new();
    let mut current: Vec<usize> = Vec::new();
    for operation in operations {
        match operation {
            RecordedOperation::Write(write) => {
                let is_fua = write.is_fua;
                writes.push(write.clone());
                current.push(writes.len() - 1);
                if fua_is_boundary && is_fua {
                    segments.push(std::mem::take(&mut current));
                }
            }
            RecordedOperation::Barrier => {
                if !current.is_empty() {
                    segments.push(std::mem::take(&mut current));
                }
            }
        }
    }
    if !current.is_empty() {
        segments.push(current);
    }
    (writes, segments)
}
```

两件事要从这段里读出来，两件都没写在条款里：

| # | 源码怎么做的 | 条款怎么说的 | 差在哪 |
|---|---|---|---|
| ① | FUA 写**先进当前段、再把当前段整个封口** | D13（验证路线） 已定项 4 的补句逐字「**带 FUA 的写自成一段，它之后的写不与它同段**」 | 「自成一段」与「封口当前段」**只在 FUA 写是它那一段的第一次写时相同**。今天三条有字节的路径里 FUA 写前面都紧挨着一道屏障，所以两种实现给同一个答案——这正是 `.claude/rules/mutation-sampling.md` 第三类「取样点不敏感」的形状。我用探针把 mkfs 的超级块写挪到三个根 FUA 之前（第五节变异 B），源码给出的段是 `[2 超级块 + 根 FUA 区域 0][根 FUA 1][根 FUA 2]`——**第一段里有两个非 FUA 写和它同段，按条款字面这是违规的** |
| ② | 屏障前面没有写时**不产生段**（第 2399 行 `if !current.is_empty()`） | 条款里一个字都没有 | 数值上无差别（2⁰ − 1 = 0），**但甲′的判据是按段序列同构比对**：`[0][2][1][2]` 与 `[2][1][2]` 是两个不同的向量。另一条线的装置若把空段记进去，两条线会被判成不同构，**而它们的崩溃状态集合逐个相同**。⇒ 甲′判据的一个假阳性口子，今天靠装置的一行实现细节堵着 |

第 ② 条正是提示里问的「暖机的第一道屏障前面没有写、算不算空段」：**算不算，源码答了（不算），条款没答。**

### 2.3 那句 ⚠️ 在三道接缝里有两道不成立

八的表下面那句 ⚠️ 逐字（`.claude/kb/layout/01-first-txn.md` 第 373 行）：

```markdown
⚠️ 相邻路径之间没有屏障：上一次发布的超级块槽写与下一次发布的单元写落在同一段（第一个事务的第四次跑里暖机第二次的 2 个超级块写与 16 个单元写合成 18 个写的一段），段序列按整条录制流切，不按路径切。
```

今天这条录制流有三道路径接缝，逐道核（源码行号在括号里）：

| 接缝 | 有没有屏障 | 依据 |
|---|---|---|
| mkfs → 暖机第一次 | **有两道** | `fn mkfs` 末尾 `pool.barrier();`（第 1674 行）；`fn warm_up` 每轮开头 `if parameters.barriers == BarrierPolicy::Settled { pool.barrier(); }`（第 1710-1712 行） |
| 暖机第一次 → 暖机第二次 | **有一道** | 同上，暖机第二轮开头那道 |
| 暖机第二次 → 第一个事务 | **没有** | `fn publish_first_file` 开头直接写单元，没有屏障（第 1941-1943 行才是它的第一道屏障，在 16 个单元写**之后**） |

⇒ **那句话举的例子是对的，话本身错了**：三道接缝里两道有屏障。
这不是措辞问题，它改数：按它字面读，mkfs 末尾那 2 个超级块写要与暖机第一次那 2 条空记录写合成一个 4 写的段，
而实测它们是两个各自独立的 2 写段（探针 `mkfs_segments=…+2`，产物 `segments=2+1+…` 的第一个 2 是暖机的记录段）。

**而且这句话不需要。** 八那四行**各自带着自己的屏障**（mkfs 行末有「屏障」、空发布行首有「屏障」），
把四行按今天的次序首尾相接，得到 `4,1,1,1,2 | 2,1,2 | 2,1,18 | 2,1,2`；去掉 mkfs 那一段（G19：不在枚举里）
正好是 `2+1+2+2+1+18+2+1+2`，与产物第 30 行逐字 `segments=2+1+2+2+1+18+2+1+2 states=262162` 相等。
⇒ 行是可组合的，那句 ⚠️ 是多写的一条错规则。

### 2.4 根槽写路径今天不是四条，是五条

D16（发布语义） 已定项 1 的「准入」那一行逐字（`.claude/kb/decisions/16-发布语义.md` 第 372 行）：


「推空发布抬 F」写一条 journal 记录、一个根槽、一个超级块槽——**它是一条根槽写路径**，而且是一条**已定项**定下来的路径，一次准入最多 8 次。

## 三、判据 4-2：今天是不是 1

判红条件逐字是「有腿按候选判据数出 ≥ 2（并说清为什么那是「线」而不是「路径」）」。

### 3.1 第一轮那个「逐路径读」，甲′把它堵死了

第一轮我给的读法 A 是「一条写路径一个集合，集合相等才同类」，那时今天数出 4。甲′的条款文本（材料第四节，整行抄）：

> 结构等价类：两条线同类 ⟺ 对最小封闭单元里的每一条根槽写路径（mkfs 种根、空发布、普通发布、实例切换 / 管理员回退），两条线录制流的段序列（段边界的位置 + 每段步骤种类的多重集）同构

「**两条线**同类 ⟺ 对每一条根槽写路径……**两条线**……同构」——量词是「对每一条路径，比两条线」，不是「对每一条路径各成一类」。
⇒ 读法 A 在这句文本下读不出来了。**这一条堵上了，我不再攻。**

### 3.2 但今天那个 1 是恒等式，不是观测

甲′的等价关系定义在**线**的集合上。今天那个集合只有一个元素（D12（目标介质） 已定项 5 的纯 SSD 线；E142（第一个事务的干跑） 产物第 66 行逐字 `feature_bits incompat_byte0=0x01 incompat_rest_zero=true` ⇒ 只有一个布局位置了 1）。
**一个单元素集合上的任何等价关系都恰好有 1 个类。**

⇒ 逐条问 `.claude/singlefs-ai-sop/rules/evidence-discipline.md`「什么现象会推翻它」：

| 想推翻「今天 = 1」，要看到什么 | 今天可不可能看到 |
|---|---|
| 两条线的某条路径段序列不同构 | **不可能**，只有一条线 |
| 某条路径的段序列有两个值 | 那也只是这一条线内部的事，甲′不按路径分类 |

### 7.2 真正挡在这里的是另一件事：zoned 上「线」可能不是携带段序列的那个对象

甲′把段序列挂在**线**上（「两条线同类 ⟺ …」）。D22（单元原子性怎么合成） 乙问的第三条臂「按区类型分支」逐字：

> **按区类型分支** | 分支：有常规区走「一律落常规区」臂，没有走「区对交替加区重置」臂 | **出局**。除了继承「区对交替加区重置」臂与 「一律落常规区」臂各自的问题，它自己还有三处，见下

它的第一处问题逐字：

> ① **分支谓词没有主语**——「有常规区」是每设备还是池级？池级读法的分支变量是「当时可写的设备集合」的一个谓词，而 D2（RAID 条带策略） 已定项 6 逐字「**掉盘不走已定项 4 b 的排空屏障**，它在写飞行中就变」⇒ 撞 `.claude/rules/fs-design.md` 硬要求 5

⇒ 这条臂已经出局，所以今天它不是 zoned 线的形态。但它点出的东西对甲′仍然成立：

⇒ 甲′要么把「线」的定义收严成「线 + 池几何」，要么按第三节的改法让判据对重数不敏感。**后者更简单，而且今天就能做。**

### 7.3 顺带核一条：zoned 上三个根 FUA 各自成段这件事本身就不成立

D22（单元原子性怎么合成） 乙问那条纯算术逐字结论：「**九格全部不整除**，而且是结构性的、不是取样出来的。⇒ 根环区域的起点落不到任何一个区边界上」。
⇒ zoned 线上根环区域这个对象本身要重新定义，mkfs 那一行的三段在 zoned 上没有对应物。
