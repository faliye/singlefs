1. During admission control for a new write operation that requires creating a new snapshot, the system must determine if sufficient space exists. The worst-case space calculation requires knowing the current exclusive and shared space usage of all existing snapshots to compute available space accurately. If the per-tree statistics are not maintained and the background scan is incomplete, the admission control uses stale or missing data. For example, if existing snapshots occupy 95% of the pool but the background scan has not updated the statistics, the system might incorrectly report 50% free space. This allows a write operation that exceeds actual available space, causing a failure when the operation attempts to allocate blocks beyond capacity. The runtime decision must be immediate, but a background scan cannot provide timely data, leading to incorrect space allocation decisions.

2. To compute exclusive space for a snapshot during a background pass, the system must traverse all blocks referenced by that snapshot’s tree and verify no other active trees reference them. However, concurrent writes modify block references. For instance, a block shared between two snapshots might be copied during a write to one snapshot, changing its reference count. If the background scan starts before the copy and finishes after, it may incorrectly count the block as exclusive to the original snapshot when it is now shared with the modified snapshot. Since block references change during traversal, the pass cannot produce a correct answer while writes occur. The mutable state during computation makes consistency impossible without blocking writes, which violates runtime constraints.

3. If the space usage data is only for human display, the loss is inaccurate or delayed reporting to users. For example, a user might see 10GB used by a snapshot when it is actually 12GB due to a pending background scan. However, no filesystem functionality breaks because runtime decisions (like admission control) rely on other metrics, not the displayed snapshot usage. The admission control computes space needs using real-time block references, not the stale snapshot statistics. Even if the number is unavailable, the filesystem continues normal operation—writes proceed based on actual free space calculations, and snapshot creation failures occur only when physical space is exhausted, not due to stale display data. The only impact is user-facing inaccuracies, which do not affect core system behavior.
