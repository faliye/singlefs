主 agent 给的问题，逐字：

读法写死：

1. **「撞上 135 片叶上限时的活 inode 数」**：同一条操作序列一条一条喂给一条臂，第一次有一次插入被拒（叶容器数会超过 135，`inode_tree.rs:258` 起那一格）时，**最后一个被接受的版本**里的记录条数。被拒那一条不算。插入只在最右叶满时新建一片，所以拒只发生在插入上，删除从不拒。
2. **「一次 unlink」只数最后一批那一次发布**（`transaction.rs:5114` 起：`FinalBatch` 只删一条记录、不与别的记录写同一次发布）。意图那次与中间各批是原地改一条记录，三条臂都只重写那一片（`write_records_into_leaf_containers` 的原地换那一支，`inode_tree.rs:211` 起），差为 0，不进比较；报告里写明这一点，不另量。合并、借都只在最后一批那次发布里做。
3. **「重写几片叶」两种记法都报，按旋钮处理，不是两种问法**（第八节）：
   - **位置记法**（`crates/` 今天的记法）：这次发布之后，凡是内容或身份变了的叶，加上第一个被摘掉的位置及其右边每一片留下的叶（位置左移，`inode_tree.rs:308` 起把它们全部列进重写清单）；
   - **内容记法**：只数内容变了、且这次发布之后还在的叶；被摘掉、退役的叶不算重写。
   两种记法下 M1 的数都与 `crates/` 的重写清单逐步对拍（位置记法就是那份清单的长度；内容记法 = 清单里内容真变了的那几片）。
4. **「多重写」= 同一条操作序列、同一段公共窗口上，两条臂每次 unlink 平均重写叶片数之差**（M2 − M1、M3 − M1，另报 M3 − M2）。公共窗口 = 从头到三条臂里最早一次插入被拒之前（不含被拒那一条）；三条臂在窗口里接受同一组操作，活 inode 集合逐步相同，只是分组不同。同时报单次 unlink 的最大值，不进判定。
5. 叶容器上限 233、根扇出 135、一次发布一个操作（建一个 inode 写一条记录、unlink 最后一批删一条）、inode 号从 1 起单调递增：照 `crates/` 今天的样子，不扫（理由见第八节）。
6. 根（码 2）在每一次最后一批发布里三条臂都重写（`inode_tree.rs:131` 起 `is_the_root_rewritten`：重写清单不空或摘了一片就重写），不进比较。

## 五、臂、阳性对照、真实基线

### 共同的部分（三条臂一样）

- 状态：按叶序排的叶容器表，每片 = 容器号 + 按号升序的记录号表（模型只存号，不存 140 字节记录）。
- 插入（建一个 inode）：号 = 上一个号 + 1，从 1 起；照 `inode_tree.rs:181` 的追加 / 末尾分裂（最右片不满就追加，满了就新建一片、容器号 = 这条的号）；新建之后片数 > 135 ⇒ 拒，树不变，这条臂在这条序列上到此为止（读法 1）。
- 删除（unlink 最后一批）：从装着它的那片里删掉那一条；那片删空 ⇒ 摘掉（三臂都是这样）。下面只写三条臂不同的那一步。
- 合并、借只在删除那次发布里做，插入那次不做。

### M1：只删空即摘（`crates/` 今天）

- 怎么做：删完那一条，那片还有记录就什么都不做；删空就摘。
- 做完会怎样：片数只在删空时减少，所以活数相同时片数 ≥ M2；每次删除内容记法至多重写 1 片（删空时 0 片），位置记法另加摘掉那片右边全部（照 `inode_tree.rs:309-311`）。推得出：两句都是这一步的直接结果。

### M2：只做左吸收右，合起来装得下就并（支持合并的人认的样子）

- 怎么做：删完那一条（记那片为 X，没删空），依次查 X 与右邻 R、左邻 L 与 X 两对（主取样点先查右边那一对，第八节扫「先查左边」）：哪一对两片记录数之和 ≤ 233，就让左边那片吸收右边那片——左片保留身份（容器号、出生代、出生树），记录接在后面，右片摘掉（退役）。并完之后，凡是因为这次并或摘而新相邻、或记录数变了的那片所在的每一对，再按同样规则查，直到没有一对装得下。X 删空时与 M1 一样摘掉，之后新相邻的 L、R 那一对同样查。
- 做完会怎样：每次发布之后任意相邻两片之和 ≥ 234（第四节推的那条，装置逐步断言），所以平均每片多于半满。推得出：规则就是「和 ≤ 233 就并、并到没有为止」，结论是它的不动点。
- 为什么这是支持者认的样子：岔路单原文就是「相邻两片合起来装得下就并」；合并只走左吸收右，守 D8「右吸收左会破记录号 ≥ 容器号」；不另设下限，不做「懒合并」（那是另一个候选，岔路单没列）。

### M3：照 D8 原文，左吸收右与左从右借都做（支持借的人认的样子）

- 怎么做：先照 M2 那一步并。这一次删除没有发生任何合并、X 没删空、X 的记录数 < 下限 f、X 有右邻 R 时，X 从 R 借：把 R 最小的 m 条移到 X 的末尾，两片都保留身份。主取样点 f = 117（= ⌈233 ÷ 2⌉，B 树常用的半满下限），m = ⌊(|R| − |X|) ÷ 2⌋（借到两片大致均分，B 树常用的再分配）；第八节扫 f = 59、m = f − |X|（借到刚好够下限）。借完之后 R 变少，R 与它右邻那一对照 M2 的规则查，装得下就并（R 吸收它右邻）。X 是最右那片时不借（右从左借违背 D8）。
- 做完会怎样：借过的那一对左片最大 key ≥ 右片容器号，I-9.4 第三句（左容器的最大 key < 右容器号）在那一版上为假——这就是 C536 那一句，岔路单 M3 的定义里写了「并改 I-9.4 的判据」，所以它不是 M3 的错，只计数当阳性对照。相邻两片之和 ≥ 234 照样成立（第四节）。推得出：借移的是 R 的最小 key，移过去之后 X 的最大 key 就是原来 R 的某条记录，≥ R 的容器号。

### 每段的预计挂钟（推的，没量过）

- 依据：模型每个操作至多在一片 233 条的表里插删一次、在至多 135 片里二分找片，按每操作 ≤ 1 µs 算；操作数上界按「被拒时活数 ≤ 31 455」推：W-R p = 0.55 约 3.1 × 10⁵，W-S (1000, 950) 约 1.2 × 10⁶，W-A 留 1/233 约 1.5 × 10⁷（低于 2 × 10⁷ 的封顶），22 条序列 × 7 个变体合计不到 2 × 10⁸ 个操作，单线程几分钟。对拍 bin 每次调 `crates/` 的纯函数要整份拷一次容器表（至多 135 × 233 条 × 48 字节 ≈ 1.44 MiB），按每次 0.1–0.3 ms 算，只跑到 M1 被拒为止，按序列分线程并行，十几分钟以内。研究工作区 release 构建（含 `singlefs-core`）几分钟。
- 第一段：构建、锚点、变异表、对拍、产物，合计 1 小时以内；第二段 15 分钟以内。两段都在 2 小时以内，不分片、不写续跑入口、不上多机。
- 模型按序列分线程并行时，合并结果按序列次序排、与单线程跑逐字相同（这组对拍进装置的单测）。每段整段跑两遍，两遍产物 sha256 相同才算（确定性模型，两遍只说明没有隐藏状态，不是统计上稳定）。
- 没有计时类的量，不涉及「在哪个进程里计时」。
## 六、报哪些量与各自的判据

### 负载序列（三条臂吃同一条）

序列由生成器单独产生，生成器自己维护活 inode 集合，不看任何一条臂的状态；一条臂某一步被拒就在那里停，别的臂照常往下吃。每条臂停下时报它吃过的操作流前缀的 sha256，三条臂在公共窗口内的前缀哈希必须相同（第十一节作废条款）。每条序列每条臂最多吃 2 × 10⁷ 个操作，到了还没被拒就报「未撞到」与那时的活数。

| 族 | 点 | 定义 |
|---|---|---|
| 随机插删 W-R | p = 0.55（主）、0.75、0.95；种子 1–5 | 伪随机源 splitmix64（种子即初值）；每一步取一个 53 位均匀数 u：活集合为空或 u < p ⇒ 插入；否则删活集合（插入时追加到末尾的 Vec）第 `next() mod 长度` 个，用 swap_remove 取出 |
| 按号顺序删 W-S | (A, D) = (1000, 500) 升序（主）、(1000, 950) 升序、(1000, 500) 降序 | 一轮 = 插入 A 条，再删活集合里最小的 D 个（升序，从小到大删）或最大的 D 个（降序，从大到小删）；一轮接一轮 |
| 隔号删 W-A | (留 1/2, A = 1000)（主）、(留 1/2, A = 2330)、(留 1/233, A = 2330)、(留 3/4, A = 1000) | 一轮 = 插入 A 条连号 b … b + A − 1，再按号升序删掉这一批里的一部分：留 1/s 的删 (n − b) mod s ≠ 0 的；留 3/4 的删 (n − b) mod 4 = 3 的 |

主取样点 = W-R p = 0.55（五个种子）、W-S (1000, 500) 升序、W-A (留 1/2, A = 1000)。三族的主取样点都跑到，就满足岔路单 M 那一行的够判条件。

## 八、轨迹与几何敏感性

### 轨迹（被谓词消费的量）

被条款当谓词输入的量是**叶容器片数**（`inode_tree.rs:258` 起的拒：片数 > 135）。每条序列、每条臂报：

- 片数：峰值、等于 135 的发布次数（贴着上限的轮数）、期末值（被拒前最后一版或封顶时）；
- 填充率（活数 ÷ (片数 × 233)）：最小值、被拒前最后一版的值；
- 累计重写差 S2(t) = Σ(M2 − M1)、S3(t) = Σ(M3 − M1)（两种记法各一条，t 走公共窗口里的最后一批）：峰值、单次差 > 0 的次数、期末值；
- M3 的 I-9.4 第三句为假的相邻对数：峰值、为正的发布次数、期末值（阳性对照，不进判定）。

只报期末值的量，正文不写「从来」「恒」。

import sys
CAP = 233
FANOUT = 135

class Tree:
    def __init__(self, arm, limit=True, floor=117, amount="balanced", prefer="right"):
        self.c = []  # list of [number, recs(list)]
        self.arm, self.limit, self.floor, self.amount, self.prefer = arm, limit, floor, amount, prefer
        self.merges = self.borrows = 0
    def insert(self, x):
        if self.c and x <= self.c[-1][1][-1]:
            raise ValueError("non-monotone")
        if self.c and len(self.c[-1][1]) < CAP:
            self.c[-1][1].append(x); grew = False
        else:
            self.c.append([x, [x]]); grew = True
        if self.limit and len(self.c) > FANOUT:
            self.c.pop(); return None  # refused (only a new container can overflow)
        return 1
    def find(self, x):
        for i, (n, r) in enumerate(self.c):
            if r and r[0] <= x <= r[-1] and x in r:
                return i
        raise KeyError(x)
    def remove(self, x):
        i = self.find(x)
        self.c[i][1].remove(x)
        content = set(); dropped_positions = []  # positions in the *before-drop* layout at time of drop
        ids_changed = set()
        def drop(j):
            dropped_positions.append(j); del self.c[j]
        if not self.c[i][1]:
            drop(i)
        else:
            ids_changed.add(self.c[i][0])
            if self.arm in ("M2", "M3"):
                merged = self.merge_loop(i, ids_changed, drop)
                if self.arm == "M3" and not merged:
                    j = self.index_of(ids_changed_hint := self.c_id_at(i))
                    self.maybe_borrow(j, ids_changed, drop)
        # final layout
        alive_ids = [n for n, _ in self.c]
        content = {alive_ids.index(n) for n in ids_changed if n in alive_ids}
        first_drop = min(dropped_positions) if dropped_positions else None
        shift = set(content)
        if first_drop is not None:
            shift |= set(range(first_drop, len(self.c)))
        return len(content), len(shift)

    def index_of(self, n): return [m for m, _ in self.c].index(n)

            k = self.index_of(cur)
            right = k + 1 < len(self.c) and self.fits(k, k + 1)
            left = k > 0 and self.fits(k - 1, k)
            order = [("r", right), ("l", left)] if self.prefer == "right" else [("l", left), ("r", right)]
            done = False
            for side, ok in order:
                if not ok: continue
                if side == "r":
                    self.absorb(k, ids_changed, drop)
                else:
                    self.absorb(k - 1, ids_changed, drop); cur = self.c[k - 1][0]
                merged = True; done = True; break
            if not done: return merged
    def maybe_borrow(self, k, ids_changed, drop):
        x = self.c[k][1]
        if len(x) >= self.floor or k + 1 >= len(self.c): return
        r = self.c[k + 1][1]
        m = (len(r) - len(x)) // 2 if self.amount == "balanced" else self.floor - len(x)
        assert m >= 1 and m < len(r)
        x.extend(r[:m]); del r[:m]
        ids_changed.add(self.c[k][0]); ids_changed.add(self.c[k + 1][0]); self.borrows += 1
        self.merge_loop(k + 1, ids_changed, drop)
    def i94_violations(self):
        return sum(1 for a, b in zip(self.c, self.c[1:]) if a[1][-1] >= b[0])
    def sums_ok(self):
        return all(len(a[1]) + len(b[1]) >= CAP + 1 for a, b in zip(self.c, self.c[1:]))

    while True:
        if t.insert(nxt) is None: return nxt
        nxt += 1
