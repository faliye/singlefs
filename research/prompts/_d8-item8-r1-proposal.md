# D8 未定项 8 第一版提案：树表条目

## P0 判据（这一版与调研稿的唯一区别，也是它的地基）

用户 2026-09-06 重申的那条原则，逐字是 D21（权威态与派生态的分界）的依据：
**「树是为了快查，而每个单元自带自包含信息——所以树是加速结构，不是事实来源。」**
加上 D21（权威态与派生态的分界）2026-09-05 补的判法：**态别按重算性判，不按「树」这个词判。**

⇒ 树表条目的判据收紧成**一句**：

> **一条树表条目里只许放两类东西：① 找到并解释这棵树所必需的；② 从这棵树自己重算不出来的值。
> 凡是能从这棵树自己重算出来的，一律不放**——放了就是同一事实的第二份正本，而两份可以互相矛盾。

⚠️ **树表单元本身不是快查结构**：D21（权威态与派生态的分界）2026-09-05 随 C113 定案把
「根记录 + 树表单元 + 实例表单元」划进「根」这一格，逐字「**不是索引，丢了就丢数据**」。
所以放进这里的第 ② 类是**权威**的，不是缓存。

## P1 字段表（97 字节）

|---|---|---|---|---|
| 0 | 条目长度 | 2 | ① | 不适用（自描述，让「以后加字段」落在 compat 那一行）|
| 2 | 树的种类 | 2 | ① | **算不出来**——码 2 的类身份段是「树 ID + 层级 + key 区间 + 诞生代号 + fsid + 写序」，没有种类 |
| 4 | flags（第 0 位 = 可写头）| 2 | ② | **不许算**——唯一能推出它的地方是记账里的 inode 号水位行，而 I-9.11（可写克隆头有水位行） 正是拿它去对那一行；从那里推等于让检查自己对自己 |
| 6 | 树 ID | 8 | ① | 身份，不适用。宽度**不是自由选择**：记账 key、码 3 出生树、五元组三处都已印死 8 |

**被判据挡在外面的**（每条都是「能从这棵树自己重算出来」）：
树的高度（根自己的头里就有）、条目数 / 用量（记账树已有带树维的第 8、9 项，放进来会让
I-5.2（空闲统计对得上） 那两条不共享的加减路径变成同源）、上次更新的 checkpoint（点不出消费者）、
write buffer 状态（运行时结构，崩溃后从 journal 重建）、条目宽 / 记录格式（种类那一段已经买到）。
**deadlist 的根不放但要立账**——它的载体形态没定之前放什么都是猜。

## P2 树 ID：单调不复用

三条独立理由（比 D8（核心索引结构）已定项 6 给 inode 号的那条更硬）：
树 ID 印在每个单元头里、树 ID 是 AAD 的一段（D9（加密）已定项 6）、记账行按 K 代点删。
保留区间：0 = 全池 / 无归属（D5（快照 / 空间记账机制）已定项 4 已占）、1–255 系统树、256 起动态、高位 256 个永不分配。
⚠️ **水位不能像 btrfs 那样挂载时扫树表算出来**——被抛弃 checkpoint 写出的单元不在已发布的树表里，
提议给 D5（快照 / 空间记账机制）已定项 4 加一项、取最大值合并。

## P3 种类：第二级登记表，且要把 D15 那一行拆开

照 D18（块里携带什么信息）已定项 11 的单元类登记表做成登记表。
**D15（格式冻结政策）判定表那一行要拆成两行**：加「已登记种类的树」是 compat；加「**新种类**」是 compat_ro。
⚠️ 依据要按用户那条原则重写：调研腿说「本工程一棵不认识的树是**解不开**不是看不见」，
但树是派生的 ⇒ 旧读者忽略一棵不认识的树只是慢，扫盘还能重建 ⇒ **compat 那一半站得住**；
真正要判的是「忽略它之后还能不能安全**写**」——那是 compat_ro 的问题。

## P4 预留：长度字段 + 16 字节，语义取「忽略」

**与单元头 flags 取的那一侧相反**（D18（块里携带什么信息）已定项 11：非 0 拒收）。
理由：拒收买不到 compat；而 btrfs 那条 `generation_v2` 的路本工程走不了——
它依赖「旧内核写坏新字段可容忍」，而树表单元是权威态。
