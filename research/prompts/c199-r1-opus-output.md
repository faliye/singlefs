## 〇、结论先行

1. **判据 2 对甲打中，而且比材料设想的便宜。** 材料只把恢复、回退、切换当成实例边界；D18（块里携带什么信息） 已定项 11 逐字「可写挂载的顺序：……再取新代号 = max(……) + 1 ……；只读挂载不取号」⇒ **每一次可写挂载都是一条实例边界**，干净重挂也算（核过的，附录 D18:760-898 那一段）。
   ⇒ 只要一个故障：新挂载的第一个根所在的那一个槽读不出（第一版里等价于掉 0 号盘），外加在这次挂载的第二次发布之前崩一次，甲就丢掉 fsync 已返回的事务。**同一个故障落在同一实例的任何别的根上，什么都不丢**（对照格 M0）。
   里程碑步 6 的验收条目「改坏最新那个根槽一个字节：择回第 0 代根，报文件不存在」（`milestone-first-txn.md:190`）就是这一格（M1）。失败条款第一条不触发（理由见第一节 E2）。
2. **乙按材料的字面，在最常见的那一格上等于甲。** 锚点写的是「上一条被施加记录的计数器 + 1」，而干净重挂之后的恢复一条记录都不施加 ⇒ 锚点不存在 ⇒ 不跨边界（M1、M2、M6 都丢）。锚点改成「链上前一条，施加与否都算」之后，判据 2 在 M0–M7 上一格都打不中。
3. **判据 5 打中乙（任何读法）与丙。** 最硬的一格是被抛弃的回退（M4）：回退的第一个根没持久就崩，下一次恢复把回退那条记录接上 ⇒ 回退生效。这与 D23（journal 的角色与格式） 已定项 14 逐字「回退与它的第一个新根同一次发布，之前没有持久效果，崩了就重做」冲突。
4. **判据 5 与判据 1 对任何「只读记录 + 所选根的表」的规则不能同时满足**（推的，模型给了两边各一格）：M4（回退的根从没持久）与 M5 去掉 X 的变体（回退的根持久过、回退已向管理员确认，之后槽坏）在环上逐条相同。甲在后者上把一次已确认的回退静默撤销（判据 1 打中甲，M5）；乙、丙在前者上让一次没确认的回退生效（判据 5）。出路不在前缀规则里，在于改判据 5 / 改 D23（journal 的角色与格式） 已定项 14 那一句（第六节）。
5. **乙的拒收机制是空的。** 只有「链上更大实例的根全都读不出」时才需要跨边界，而这些实例的行只住在它们自己的根所指的实例表版本里 ⇒ 所选根的表里对链上任何更大的实例**一行都没有**（模型每次跨越都打印 `row ... = None`）。材料倾向里的「W = 0 的行可以当拒收的依据」没有输入；五条口径的第五条（回退行截断）在它要管的那一格上同样没有输入（第三节 3.3）。
6. **丙不比「链尾锚」的乙多挡任何东西**：交接记录写的 (上一实例代号, 计数器) 是反向链已经绑住的那一对（D23（journal 的角色与格式） 已定项 10：`previous_hash` 覆盖前一条的整个记录头，其中含 `jsn`）。丙还要多一个记录类型、改第一个事务的字节。

## 三、判据 1 / 5 对乙

### 3.1 锚点从哪一条接：按字面读，乙在判据 2 上和甲一样丢

乙的原文：「要求它的计数器 = **上一条被施加记录**的计数器 + 1」。下面三格里，这个锚点要么不存在，要么不是链上的前一条：

| 格 | 锚点为什么对不上 | 模型行 |
|---|---|---|
| M1 | 第 0 代根没覆盖任何记录，这次恢复也一条没施加 | `name=M1_first_txn_after_mkfs rule=yi_literal final=[] expected=['X'] lost_acked=['X'] wrong_extra=[]` |
| M2 | 干净重挂后的恢复一条都不施加（(1,1) 已被根 (1,1) 覆盖） | `name=M2_clean_remount_first_root rule=yi_literal final=['A'] expected=['A', 'X'] lost_acked=['X'] wrong_extra=[]` |
| M6 | 实例 1 留下一条没有提交标记的尾巴 jsn (1,2)；恢复实例按 D23（journal 的角色与格式） 已定项 8 逐字「恢复之后从「前缀末 + 1」接着写」从 (2,3) 起写；而「上一条被施加」是 (1,1)，差 2 | `name=M6_uncommitted_tail rule=yi_literal final=['A'] expected=['A', 'X'] lost_acked=['X'] wrong_extra=[]` |

M6 正是任务里说的量纲错位。行的 W 和「被施加」都按事务号算（D23（journal 的角色与格式） 已定项 7「事务号按实例计数、从 1 起」），连续性却按记录计数器判。一个事务可以跨多条记录，号 > W 的事务（没提交的尾巴、C287（切换收养开放 checkpoint 的事务后再崩） 里的 a）的记录会夹在中间，于是「上一条被施加 + 1」接不上下一个实例的第一条。
⇒ 乙要改成「**链上前一条（施加与否都算）+ 1**；所选根一条都没覆盖时从 tail 接」。改完之后三格都过，例如 `name=M6_uncommitted_tail rule=yi_chain_end final=['A', 'X'] expected=['A', 'X'] lost_acked=[] wrong_extra=[]`。代号那一半要写成「更大」，不能照 E37（日志实例代号） 写成「恰好 +1」（E4）。

### 3.3 只看记录分不出「被抛弃」：M4 与 M5′ 在环上逐条相同

### 3.4 乙的拒收条款为什么是空的（E3 展开）

需要从实例 i 跨到 j，就意味着 j 以及更新的实例的根全都读不出（否则会选中它们）。i、j 的行由 j 以及之后的恢复 / 回退 / 切换写，住在它们各自第一个新根所指的表版本里 ⇒ 所选根的表里没有这些行。所选根自己那个实例的行也一样：写它的那次操作一定发生在它之后 ⇒ **所选根的表里永远没有所选根那个实例的行**（推的；模型每次跨越打印的 `row ... = None` 是这件事的具体实例）。由此两个后果：

1. 乙的「有行则按事务号到行的 W 为止」和「行的 W = 0 的实例……一条都不施加」，在需要它们的格子里没有输入 ⇒ 乙实际退化成「代号更大、计数器接得上就跨」。
2. 五条口径的第五条「所选根的实例在实例表里有回退行时，该实例的记录只施加到回退行的 W 为止」同理：回退行写在回退实例的第一个新根里，落回 R_old 的恢复读的是 R_old 自己的表（D18（块里携带什么信息） 已定项 11「它的现行版本由根记录持有的物理指针唯一确定」），里面没有回退行。C124（回退行与重放下界没有会红的检查）「仍欠的另一半」要造的那条历史，按今天的条文这条规则没有输入。E104（扫描重建的现行版本判定） 的 `rollback_row_protected` 世界之所以分得出它，是因为 E104 自陈「实例表永久、不会坏、没有载体」。

### 3.5 记下：乙把两笔已有的欠账放大

1. **固定点单元要重写多少。** 行给跨过的实例写 (j, 所选根 txg, W_j)，码 2 / 3 按 b ≤ T_pub 判 ⇒ j 在所选根之后发布过的每个 checkpoint 的固定点单元一律判未发布，恢复实例要把重放后仍被引用的那些全部重写（D18（块里携带什么信息） 已定项 11 逐字「所选根之后的固定点单元一律未发布，恢复实例重写它们」）。甲下这个集合最多是在飞的一两个 checkpoint；乙下是被跨过的若干实例的若干个 checkpoint。E104 的 `rewrite_inflight_containers` 只重写 `unit.birth == txg && unit.write_sequence.instance == previous_instance`，也就是一个 txg、一个实例。照这个实现，乙跨过的那些 checkpoint 里的容器被判未发布却仍被引用，清扫会抹掉它们（推的，没建模）。E104 自陈这一格没建（「不建「记录可重放、跨两个 checkpoint 重放」」）；同一实例内退格也会碰到这个问题，乙把它放大了。
2. **回退之后的中间实例行会被盖掉。** 设乙在一次恢复里先穿过一个被回退抛弃的中间实例 j（施加了它的记录），再遇到回退记录。回退记录是整体目标态，把状态改回 R_old，所以最终状态是对的。但恢复要按「属于 j 的、被这次重放施加的最大事务号」给 j 写行 (j, T_chosen, W_j > 0)，这会盖掉回退写下的 (j, 0, 0)——D18（块里携带什么信息） 只给回退行置 bit0（「回退行在 kind 0 记录的 flags 字节里置 bit0 标「回退」、**不许被后来的恢复覆盖**」），中间实例行没有这一位 ⇒ j 里号 ≤ W_j 的数据单元按谓词判已发布，扫描重建会复活它们。要的故障很多（回退之后、比 j 新的根全读不出），推的，没建模。
