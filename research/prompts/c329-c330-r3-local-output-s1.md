For example, if instance k never published a root and has kept transactions with write order W_k > 0, a recovery writing (k, 0, 0) would set W to 0. Code-1 units with n > 0 would then be unpublished, violating correctness. The owner row should receive the same protection as a rollback row to prevent this, as it is critical for maintaining published units during recovery.

2. Yes, the owner rule correctly picks the row and values in all cases. During a rollback publish, the instance table starts from the rollback target's version, so W is set to the kept transactions' row. In a warm-up empty publish, the switch uses the same logic for W, even if no transactions exist. After R takes effect, the chosen root's T_pub is set to its checkpoint, and the switch uses this to determine the owner row's values. The rule consistently applies regardless of publish context.

3. The instance table can grow indefinitely if root slots remain unreadable, as deletion requires all root ring slots to be readable. This affects the switch reserve because the reserve size is computed from rows read at mount. A larger instance table increases the required reserve size, potentially exceeding the fixed "one more switch" allocation, leading to failures during switches due to insufficient reserve space.

Failing check for owner row rule: If the system sets the owner row as (k, T_sel, 0) for an instance k that never published a root, but T_sel is incorrectly chosen (e.g., T_sel > 0), then code-1 units with n > 0 become unpublished. Proof: During switch, if the code assumes all instances with kept transactions published a root, it may set T_sel to a non-zero value, violating the requirement for (k, 0, W_k). Failing check for deletion condition: If the system deletes a row when a root ring slot is unreadable but incorrectly assumes it holds no root for the instance. Proof: A device failure leaves a root slot unreadable, yet the deletion check skips only checks readable slots. If the unreadable slot actually contains a root for the instance, deletion proceeds prematurely, leaving unpublished units.

It contradicts the rule that rows for i > i_now are corrupt because during a switch, new instance rows are written with i > i_now (current mounted root's instance), which F2 labels as corrupt, but these rows are necessary for the switch process and should not be marked corrupt.
