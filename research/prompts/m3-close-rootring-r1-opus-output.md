## X1　C743 错位读收进失败模型

### X1.1 读回的是什么：哪几种进模型

D17 已定项 1 今天的失败模型只有「核心层规定一个失败模型——扇区 512 原子、写可撕裂到扇区、屏障之间可重排」（`.claude/kb/decisions/17-实现分层与第三方管道.md:24`），读侧一个字都没有；C743 登记行自己写了「错位读不在那一行的故障分类里」（`.claude/kb/checks-owed.md:495`）。按读回的东西分：

| 读回的 | 落点公式判不判得出 | 进不进模型 | 理由 |
|---|---|---|---|
| 别的槽里一条自证得过的本池根（同盘别的区域，或别的盘别的区域） | 判得出：除 txg 0 之外每个 txg 只有一个合法槽（`crates/singlefs-core/src/root_ring.rs:114` 与下一行） | 进 | 这是 C743 那一形；不收的话重建分配器两遍并槽会把它记成「只有一遍自证过」的根 |
| 别的盘同偏移 | 用不上公式：区域起点在各自盘上是 1 / 4 / 7 MiB，第一版归属 0 / 1 / 0，盘 1 的 1 MiB、7 MiB 处不是根环 | 进，但落进已有的「读坏 / 全零」两类 | 读回的不是本池根，自证或 fsid 就挡掉 |
| 别的偏移的任意字节 | 同上 | 进，落进已有两类 | 整槽校验和加 fsid |
| 同一槽上一圈（或更早）的旧内容 | **判不出**：同一槽，公式给的就是这一槽 | 不进（写清不进） | 它是读回陈旧版本 / 丢写，不是错位；后果见下 |
| 第 0 代根的另一份（区域 r 槽 0 读回区域 r' 槽 0 的第 0 代根） | 带 I-7.17 例外时判不出 | 进，判为合法 | 读回的就是一份合法的第 0 代根，后果无害（下面 X1.2 末段） |

「同一槽旧内容」不进的后果（推的）：槽 X 真住着 t、读回 t − 3S。择根时 t 当没有，它的记录照 D23 已定项 15 施加回来；环里最旧有效根变低，回收门槛只会更保守；回退候选多一条 t − 3S，它引用的单元可能已复用，靠回退「在任何写之前拒」那几道核（分配代对不上）挡。条文要写明「陈旧读不在错位读之内，公式判不出」，否则读者以为公式罩住了它。

### X1.2 落点公式把合法根判成错位：第 0 代根（打中，前提量过）

用户这一支的字面是「读出的根 txg 照落点公式不该住这一槽的，一律按自证不过处置」，没带 I-7.17 那条例外「时只判 s == 0，不判 r」（`crates/singlefs-checker/invariants/02-根环.md:24`）。mkfs 在三个区域的槽 0 各写一份第 0 代根，core 自己已经知道裸公式只把它归到区域 0：「mkfs 在三个区域的槽 0 各写一份第 0 代根」（`crates/singlefs-core/src/mount.rs:3010`）。

历史（副本量过，`tests/rootring_attack_genesis_slots_after_one_power_loss.rs`）：384 槽小盘 mkfs → 第一次可写挂载崩在写行那次发布（txg 1）两条记录写之后、根槽写之前（一次断电，零读故障）→ 再可写挂载两次。`out/genesis.out` 原样（节选三行）：

```
GENESIS crash_before_row_root slot=(1,0) device=1 root=(inst 0, txg 0) formula_slot=(0,0) bare_formula_ok=false with_txg0_exception_ok=true
GENESIS second_mount effective_root=(inst 0, txg 0) row_publish_txg=2
GENESIS after_third_mount slot=(1,0) device=1 root=(inst 0, txg 0) formula_slot=(0,0) bare_formula_ok=false with_txg0_exception_ok=true
```

第二次挂载择到第 0 代根、txg 1 那条记录照 D23 已定项 14 注 1 不施加，新实例从 txg 2 起，txg 1 的槽（区域 1 槽 0，盘 1）一直留着第 0 代根，到 txg 25（S = 8，环长 24）才被写掉。裸公式在这一整圈里每次读都判它错位，带例外则判合法。

后果（推的，按今天的代码推）：重建分配器读到它归成读坏而不是全零的那一类（`BadAndNotAllZero`，`crates/singlefs-core/src/mount.rs:3108`），D16 已定项 1 「读坏的并进准入抬 F 的上限，读回全零的不并」（`.claude/kb/decisions/16-发布语义.md:39`），它在 (N − 3S, first_txg − 1] 里能住的最大 txg 按 `target_for_publish` 走出来是 1（`crates/singlefs-core/src/mount.rs:2873`），于是这一圈里准入抬 F 的上限被钉在 1；正确读法下它是一条空的有效根，上限照「第 4 新的非空有效根」走。窄盘上这一圈里非空根够 4 个之后，准入推空抬不动 F，提前报 ENOSPC。挂载本身挂得上，丢的是可用空间，不丢已确认的写。

另一份第 0 代根（区域 2 槽 0）在这段历史里 txg 2 就被写掉；若 txg 2 那次也崩在记录之后、根槽之前，同样留一圈。

带例外之后反过来的风险（推的，无害）：区域 r 槽 0 被读成区域 r' 槽 0 的第 0 代根，例外放行。槽 0 的第 0 代根只在环的第一圈或洞里活着；那时区域 0 槽 0 本来就住着一份第 0 代根，环里最旧有效根本来就是 0，回收门槛不变；它是空根，不进回退候选，不进「非空」。被它藏住的那条真根若是最新的，记录照施加回来。

别的合法根（推的，逐类核过）：洞里留着的上一圈旧根住在自己的槽；根槽写失败推进一格再发，新 txg 写新槽；新实例跳号仍按公式落槽；回绕按 `mod S`；S 是系统不可变配置。都不会被公式误判。

### X1.4 读错位进不进 checker

I-7.17 判的是盘上的位置，读错位不在盘上留痕，池级 checker 判不到它（推的）。它要进的是读故障注入那一族：harness 今天的注入只有「读回全零」「报读错」「乱字节」（`tests/common_unwitnessed_publish` 的 `DeviceReadingBackAllZeroOnRanges`、重建两遍那组用例的 e / z / g），没有「读回另一槽的字节」，新条目进了模型也没有会红的检查。它的后果——回收门槛被抬过真最旧有效根——在 X4 新不变量落盘之后由镜像上的上界判到（X5 第三条）。

## X2　C751 只读挂载在那一形照报失败

### X2.1 条件写成当下判得出的样子：两种读法

F2 今天在所选根的实例表读不出时「所选根的实例表读不出时只认与见证到的那一版恰好相等、读得出的那条根」（`.claude/kb/decisions/23-journal的角色与格式.md:398`；实现 `crates/singlefs-core/src/recovery.rs:6996`）。用户这一支要只读挂载在「退到的那一版之上还有读得出、没法按实例表判抛弃与否的根」时不退。表读不出时「没法判」有两种读法：

- **字面读法**：表读不出，(退到的那一版, 所选根) 里每条读得出的根都算没法判。
- **同实例可判读法**：实例表的行只写给比表的主人旧的实例（「行只落在 [这个根的实例, 新实例)」，`.claude/kb/decisions/23-journal的角色与格式.md:406`；可写挂载写行同样只写所选根那个实例与中间实例的行），所以与所选根同一个实例代号的根，在所选根的表里不会有它的行、按定义不被抛弃，表读不出也判得出；只有更旧实例的根没法判。

### X2.2 两份盘面上量（副本，`out/c751.out` 原样，k = 5 两行）

```
C751 registered_c751 kind=ow k=5 chosen=(1, 9) table_readable=false today rec=Fail ro=Ok(1,7) f2_fallback=Some((1, 7)) readable_roots_strictly_between=[(1, 8)] | literal_branch_ro_refuses=true same_instance_reading_ro_refuses=false newest_same_instance_root_between=Some((1, 8))
C751 pinned_656 kind=ow k=5 chosen=(2, 10) table_readable=false today rec=Ok(1,8) ro=Ok(1,8) f2_fallback=Some((1, 8)) readable_roots_strictly_between=[(1, 9)] | literal_branch_ro_refuses=true same_instance_reading_ro_refuses=true newest_same_instance_root_between=None
```

登记那一形（C751 登记行的造法：覆盖写 R，崩在 R 的根槽之后、轮换之前，读的那一刻 R 的单元、每块盘较新的系统配置槽、R 的实例表读回全零）四组（ow / sw3 × k = 3、5）都是：今天只读挂载落 Pm（越过读得出的已确认 P）。入库用例 `:656` 那一形两组（ow × k = 3、5）：今天恢复与只读挂载都落 P（`crates/singlefs-harness/tests/recovery_and_both_mounts_fall_back_to_the_version_the_system_configuration_witnessed.rs:674` 那一句断言），区间里读得出的是被 Row 那个实例抛弃了的旧实例 R。

| 读法 | 登记那一形 | `:656` 那一形 |
|---|---|---|
| 字面 | 只读照报失败（罩住了） | 只读从「退到 P、打得开」变成照报失败；恢复仍退到 P（条款只改只读）、可写本来就拒 ⇒ 三处分叉 |
| 同实例可判 | P 与 R 同实例 ⇒ 判得出 ⇒ 条件不成立 ⇒ 只读照旧落 Pm，**没罩住** | 旧实例的 R 没法判 ⇒ 只读照报失败，同字面读法 |

所以：用户这一支没有一种读法既罩住登记那一形、又不动 `:656` 的只读结局。`:656` 的盘面算这一形；断言要从 `mount_read_only(&devices).expect("只读挂载退回 P、打得开")` 改成只读照报打不开，而 P 在那份盘面上是对的版本——只读挂载丢了一份本来打得开、内容对的版本（挂不上本来挂得上的池，只读一侧）。

同实例可判读法另给出一条比「照报失败」更好的出路（我提的，只在我的模型上量过、被攻过零轮）：F2 在所选根的表读不出时，把「与所选根同实例、在区间里读得出的根」当不被抛弃收进候选、按 `F2_NEWEST` 取最新——登记那一形里它取到的就是已确认的 P（`newest_same_instance_root_between=Some((1, 8))`），三处都能落 P 而不是照报失败；`:656` 里同实例的根一条都没有（`None`），照旧只认恰好相等的 P，`:656` 的三处结局一个字不变。它不需要只读一处的例外，与 C755 的「三处同一套逻辑」不打架。没量的：这一改法在别的 F2 格上的结局；同实例的根被「记录读得出、根读不出」那一判（Y4）挡住的组合。

### X2.3 单故障加一次断电：没打中

条件要「退到的那一版之上有读得出、旧实例的根」，即环里有被抛弃（或可能被抛弃）的旧实例根，它只能来自一次「崩溃恢复落到旧根、新实例取号」的挂载；登记那一形另要 R 的单元、较新系统配置槽、实例表三样读回全零。一次断电只能让最后一次发布没轮换：之后的挂载落到哪版都不需要抛弃旧实例的根，除非那一刻再有读故障（第二样故障）且再断一次电写下新实例的根而没轮换（第二次断电）。所以在单故障加一次断电之内，这一条条件恒假，用户这一支在预算内不改任何结局（推的，没量）。推翻条件：一次断电、一样读故障下造出「所选根实例表读不出 ∧ 区间里有旧实例的可读根」的盘面。

### X2.4 F2 许可的其余格

字面读法只在「所选根表读不出」时生效，表读得出的各格（入库用例 `:177`、`:200`、`:223`、`:521`–`:552`、`:631` 那几形）一个都不动（推的：条件第一项为假）。表读不出的格里，入库用例只有 `:656` 一条，它被改。

（`out/union.out` 上按 `chosen=` 与 `rec=` / `ro=` / `rw=` 逐行比出来；`UNION_SUMMARY cells=100 mount_lost=38 read_only_lost=38` 是测试自己打的那一行。）`out/union.out` 原样两行：

没见证那 50 格：46 格统一之后退到 P（今天只读有 30 格打开 R；R 没确认，退到 P 在 F2 许可之内，不算越界）；4 格是共用的实例表，P 也建不出，统一之后照报失败，今天只读打开 R。

### X3.3 记录那一格：并集算不算记录（量过，副本）

R 已确认，只让 R 的末条记录两份读回全零（`out/record.out`，四组同形，原样一行）：


条款写的是「单元的并集」，记录不是单元；可建上一版没有记录顶着就建不出。并集算记录：恢复从今天的「落所选根、读回 R」变成照报失败，只读也挂不上——单故障上越界，并撞 D23 已定项 14 C366 那一条钉住的结局「只读挂载照常择 (实例 1, txg 4)」（`.claude/kb/decisions/23-journal的角色与格式.md:421`）。并集不算记录：恢复与只读落 R，可写挂载照 C554 乙「两条都读不出按真」另拒——三处仍不落同一版，「同一份盘面三处落同一版」在这一格做不到。条文要先定记录算不算。

### X3.4 不注读故障的崩溃态：没打中（推的）

统一之后恢复多读的是打开与建上一版读的那几类单元与所选那一版的末条记录。合法崩溃态上它们都在所选根的根槽之前持久（单元、记录、根的持久顺序，D16 已定项 7），撕裂只发生在屏障之间、根槽落盘之前的那几次写上，所选根引用的单元不在其内；由记录重建的那一版（D23 已定项 15）F2 本来就不退（`crates/singlefs-core/src/recovery.rs:6904` 那一判）。所以不注读故障时，恢复不会从「落所选根」变成「退回」。没量：我没有在 R 那次发布的崩溃枚举全集上跑统一之后的三处（限度第 2 条）。推翻条件：一个不注读故障的合法崩溃态，所选根的末条记录读不出、或建上一版读的某个单元读不出。

### X3.5 与 C754「重扫」一致吗

今天三处给 F2 判法的记录不是同一份：恢复走读失败之后重扫一遍（`crates/singlefs-core/src/recovery.rs:7124`），只读挂载用开头那一遍（`crates/singlefs-core/src/mounted_read.rs:628`），可写挂载用读阶段那一份（`crates/singlefs-core/src/mount.rs:8018` 那次调用传的 `records`）。系统配置落地补丁只在 F2 退了之后、F1 再判之前加了一次重扫（补丁里「判之前先重扫一遍 journal 环（C754，用户 2026-10-20 定「重扫」）」那几行），F2 自己的输入没动。于是一次瞬时读不出的计数器 = c_见证 的那条记录，在恢复的重扫里读得出、在两种挂载那一遍里读不出，恢复退到见证到的那一版、两种挂载照报失败（推的，没造盘面；要两样读故障，超出单故障）。统一的条文要写「三处在交 F2 之前都重扫」，不然触发统一了、判法的输入仍分叉。

### X3.6 崩溃点重放 oracle 与 GPU 判官

两者按恢复那一路判、挂载透明只判不带读故障的态。不注读故障时三处读通的集合相同（X3.4），统一不改它们的判决（推的）。注读故障的那一族（E165 r3 择根与重放合判）若照恢复那一路判，统一之后恢复多读的打开与建上一版那几类单元要一起进判官的「建得出」，否则判官放过的恢复结局两种挂载复现不了。

## X4　C773 回收门槛落盘

### X4.1 宽度、落点、要同步的（推的）

门槛是一个 txg，8 字节、小端，与 `rollback_floor` 同宽。根记录 457 → 465 字节，仍在一个 512 字节扇区里（D17 已定项 1 的扇区原子不受影响）；读者收的界「`physical_block_size` ∈ [根记录宽 457, 槽距]」（`.claude/kb/decisions/22-单元原子性怎么合成.md:341`）跟着改成 465。字段要落在根记录自证校验和罩住的那一段里，否则一次撕裂改了门槛、根照样自证过。要同步的：D22 已定项 7 字段表、`layout/01-first-txn.md` 字节表与 E142 干跑、core 与池级 checker 的根解析、GPU 判器的根解析。崩溃枚举不变：根槽仍是一次写，状态数不变。

### X4.2 字段的语义要钉的两点（读码，推的）

1. **「这次发布用的」是哪一次回收的门槛**：分配器在记下一条根之后才按新的 max(F_生效, 环里最旧有效根) 回收（`record_root_written_by_this_process`），记账「已分配」按位图数（`crates/singlefs-core/src/transaction.rs:12779`）。所以发布 T 的记账反映的是记下 T − 1 之后（写行那次是挂载重建时）那一次回收的门槛。字段若写成「记下 T 之后再算的那个」，释放代落在两次门槛之间的那截在 checker 上多算一截，合法盘面上 I-3.1 改式红。条文要写「建这次发布的记账之前最后一次回收用的门槛」。
2. **回收过的记录不离开分配记录树**：回收只把位图放开、记进 `reclaimed`（`crates/singlefs-core/src/allocator.rs:2429`、`crates/singlefs-core/src/allocator.rs:2434`），记录照旧是「已释放 + 释放代」，直到那一槽被再分配才改写。所以树里同时有释放代 ≤ 门槛（已回收、空闲）与 > 门槛（defer、算已分配）两种已释放记录，盘上门槛正是 checker 区分这两种的唯一依据——字段写对写错直接决定 I-3.1 改式红不红。一个进程里门槛只升不降（钉只在挂载那一刻产生，进程内重读只解钉），每次发布的值就是这个进程到此为止的最大值；跨挂载可以因新的钉变低，上一个进程回收过而没再分配的记录在新进程里重新算 defer，与字段一致。

### X4.3 新不变量「盘上门槛 ≤ max(F_生效, 环里最旧有效根)」：没打中（推的）

在合法盘面上找门槛高于 checker 现算值的一形，逐个来源排过：
- 挂载时读坏或全零的槽：钉在可能住过的最旧 txg，只会更低。
- 按实例表判抛弃：core 用挂载那一刻最新根的表，checker 用镜像上最新根的表；表只加行，抛弃只增不减，checker 那边有效根更少、最小值更高。
- F：core 回收用的 F 就是这条根带的 F（抬 F 先写系统配置再回收再发根），checker 的 F_生效 不低于最新根带的 F。
- 丢一块盘的镜像：checker 只看得见幸存盘上的根，最小值只会更高。
- 时间：环里最旧有效根随发布只升不降（只覆盖、不复活），F 只增；镜像总比写字段那一刻晚。
推翻条件：一个合法盘面（含读故障之后写下的），最新根带的门槛高于 checker 按镜像算的 max。我没造出来。反过来，读错位没修时（X1）重建两遍把别处的根记进一槽、真最旧有效根掉出表，门槛被抬高、真根引用的槽被回收——这一形在这条不变量上红，红得对。

### X4.4 I-3.1 改式加上界：判不出「门槛钉低不解开」（打中，判错的盘面，推的）

今天的 I-3.1：checker 自己算门槛 max(F_生效, 环里最旧有效根)，只把「F 之下的有效根引用着、释放代高于门槛」的槽并进遍历（`crates/singlefs-checker/src/walk.rs:8362`、`crates/singlefs-checker/src/walk.rs:18205`）。改式把「释放代大于盘上门槛的已释放槽」整个并进来，盘上门槛由写者给。

坏实现：写者把门槛钉得过低、一直不解开（比如进程内记根时漏了重读、写掉钉着的那一槽也不解钉，或干脆恒取 F），并如实写进字段。它的记账「已分配」= 引用 ∪ 释放代 > 过低门槛的全部已释放；改式按同一个门槛并，两边相等，绿；上界只管不高于，过低的门槛绿。今天的 I-3.1 在这一形上红（多出来的已释放槽没有有效根引用，记账多于遍历）——C773 登记的就是这一红，只是那一次钉是合法的。改式 + 上界把「合法的钉」与「钉住不放的泄漏」一起判绿。能补的下界只有「不低于这条根带的 F」，F 与环里最旧有效根之间的整段泄漏判不出。

我提的补法（只在推理里，被攻过零轮）：字段之外再记「挂载时钉着、这个进程还没解开的槽」（环最多 3 × 16 = 48 槽，6 字节位图），checker 按「未钉的槽里最旧有效根」与「钉着的槽可能住过的最旧 txg」现算出门槛、要求与字段**相等**，另判「钉着的槽不住着这个实例写过的根」。这样合法的钉照样绿、钉住不放的泄漏照样红。代价：根记录再多 6 字节（471），没量。

### X4.5 与 C684 打架

C684 那一形：一槽在最新根的账里还在 defer，只剩被抛弃根引用它——「原式不并（只剩被抛弃根引用它），另一式并」（`.claude/kb/checks-owed.md:447`），用户 2026-10-20 定「不并，记成已认的代价」（`research/prompts/_m3-close-rootring-r1-body.md:49`），即那一形 I-3.1 红、测试钉成例外。改式不看引用，只看释放代与盘上门槛：那一槽释放代高于门槛就并，那一形转绿——等于替 C684 选了「并」，钉成例外的那条测试与 `crates/mutations.tsv` 里 LR5 那一行（小世界等价）跟着失去对象。条文要二选一：写明 C773 改式取代 C684 的定案；或保留按引用并、只把门槛换成盘上门槛（那样 C773 那一形里 44 槽没有有效根引用，仍红，C773 没修到）。两条不能都照字面成立。

### X4.6 C773 那一形会不会转绿

按登记行的数推（没重跑那份调查的探针）：记账 302、遍历 258，差的 44 槽释放代全在 (21, 25]；盘上门槛 = 21 时改式并进这 44 槽，302 = 258 + 44，转绿；上界 21 ≤ 25，绿。

## 这条腿自己的限度

1. 统一之后的结局是在测试里按用户这一支现算的（`readers_on` 与 `unified_outcome`），core 没改；真实现可能多读或少读几类单元，格数会变，方向不变。
2. 崩溃状态没照崩溃点重放的枚举域取：每段历史只取了两个崩溃点（R 整次落盘、崩在 R 的根槽之后轮换之前），没调 `enumerate_crash_states`，经枚举函数跑的状态数是 0。打中的几格只需要一个反例；「不注读故障时不越界」（X3.4）那一句因此只是推的。
3. 「一样故障」照 C751、C755 登记行的数法：一个单元两份同时读回全零记一样。若失败模型按份数，X3.2 那 34 格是双故障。D19 已定项 5 与 D23 已定项 14 那几句的冲突是条文层的，不随故障怎么数而变。
4. X1.2 的后果（准入上限钉在 1、窄盘提前 ENOSPC）、X4.4、X4.5、X3.5 都是推的，没造盘面、没跑 checker。
5. 只量了 384 槽小盘一种几何、S = 8；第 0 代根留一圈的长度随 S 变（3S 次发布）。
6. 副本上的数，不是入库装置上的数。
