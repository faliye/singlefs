## 二、提案（第二版）

### P1 形态：inode 树 = 内部节点（码 2，派生态）+ 叶（码 3 打包记录单元，记录类型 2，权威态单元）

- **叶就是 D18 已定项 11 的码 3 容器**：一叶一个 32 KiB 打包记录单元，装 233 条 140 字节的 inode 记录（记录类型 2 由「保留」转「启用」，
  它是 day-1 类型、不需要位）。叶自带类身份段（稳定身份 = 出生树 + 类型 + 容器号 + 出生代）、记录数、载荷校验和（F20 的洞对它不存在）。
- **内部节点是普通码 2 索引节点，派生态**，条目 = 分隔 key 8 + 叶容器身份（容器号 8 + 出生代 8）+ 子指针 59 = 83 字节（扇出 196）。
  容器身份进条目，是为了 AAD 期望值来自查找路径（A6）。**容器索引就是这棵树的内部节点**，不另立树——D18 已定项 11
  「容器索引是物理指针唯一持有者、别的树按身份引用」在这里读作：物理指针只住 inode 树的内部节点；dirent 树引用的是 inode 号，不是容器。
- **D21 一个字不改**：叶是单元（权威态第一项），内部节点是索引（派生态）。承重面仍是单元（F21 的 D20 推论原样成立）。
  内部节点丢了从叶重建（叶容器的记录里有 inode 号 ⇒ 每叶的 key 范围可算）；叶丢了是丢数据，与数据单元同一格（C100 照旧）。
- **内部节点不缓冲 inode 更新**：更新直达叶容器（COW 叶 + 全部祖先，D23 甲）。这是对 D11 已定项 6 的一条按树例外：inode 树 ε = 0。
  理由 = 硬约束 6（F22 的四类重算源里没有 inode 类）。
- **不是路 ② 的那些代价**：内部节点布局不进冻结（派生态照旧）；迁移到另一条线时叶（单元）随单元格式走，内部节点按目标线重建；
  不写转换器。**进永久契约的只有记录格式（P5）**，它随码 3 的类身份段一起本来就在第 1 层。
- **与路 ①（第一版所指的形态）的区别**：没有「inode 树按身份引用 + 独立容器索引」那一层间接。F28：写逐格相同，读少一趟。

### P2 树的种类不进树表，不进本项

第一版 P2 撤回（树表随根一起丢，抢救时读不到；树表条目字段表全仓不存在）。本项不需要它：扫描重建靠码 3 头里的打包记录类型 2 + 出生树 ID
就知道这些容器属于哪棵 inode 树。**树 ID 的分配与编码规则全仓无落点**，立欠账（第一个事务要写三棵树的 ID，它挡在第一行代码前）。

### P3 叶不带 key 区间字段；内部节点照 D18 已定项 7

叶是码 3，类身份段里没有 key 区间，也不需要：叶的 key 范围由它装的记录算出（inode 号是记录首字段）。内部节点按 D18 已定项 7 索引节点类走，
key 区间那一格照 D18 已定项 2「dirent 推迟、不许外推」的口径**不在本项定**（内部节点是派生态，重建时从叶算范围）。

### P4 inode 树的 key：`(inode)` 8 字节；inode 号单调不复用；水位住记账

- key = inode 号（每头一棵树，头判别位没有对象，E98）。唯一性范围是 (树 ID, inode)：克隆头各自分配同号是两个对象，AAD 用出生树分。
- **inode 号单调不复用**（同 F24 对快照标识的戒律）：F23 的 `deleted_inodes` 后台回收窗口里，复用会让新旧对象的 extent key 三段逐字相同；
  不复用则 (树, inode) 永远唯一，同窗复用的出生代问题不存在。64 位按 1e9 次/秒分配也用不完。
- **下一个 inode 号是一个记账统计量**：key = (统计量类型「inode 号水位」, 树 ID, 设备 0, 代)，value = 下一个可用号（幂等完整值，F26）。
  它住权威态、随发布落盘、被问到那一刻有答案；不靠最右键查询（那在 `deleted_inodes` 窗口里给错答案）。

### P6 不变量

1. 身份对照：记录 inode == key，不等判红、EIO、不许静默修复。
2. locality 对照：记录 `locality_id` == 该对象每条 extent key 首段。**射程**：只在 extent 树未经重建时有判别力；重建后 extent key 首段由记录给出、两侧同源，不判红。
   要在重建后仍有判别力，需要 locality_id 在权威侧另有见证——那是六元组候选 `locality_id`（D18 已定项 3 待用户定案的提议），**不在本项定**。
   D9 已定项 6 排除 locality_id 进 AAD 的那行理由引的 D8 原文已改，理由要重写——随六元组那一格处理。
3. nlink：「nlink == dirent 条数」立成不变量，由 dirent keyspace 上线那个 compat 位（D15：新增一棵 keyspace ⇒ compat）门着——位未置不评估，置了零豁免；位是永久的、单调的，登记进 feature-bits。第一版的唯一文件取 inode 号 1（0 无效），nlink = 1，不进孤儿回收。

### P7 第一个事务写什么

inode 树：一片叶 = 一个码 3 容器（记录类型 2，容器号 1，容器出生代 = 本次发布的 checkpoint_txg，记录数 1，记录宽 140），一条记录（inode 1、出生代同上、
locality_id 0、nlink 1、改动计数同上、flags 0）；内部节点 0 个（一片叶时根就是叶）——**根直接指向叶容器时，树表条目里的指针指向一个码 3 单元**，
这要求树表条目 / 内部节点条目的指针能指向码 3（它们本来就指向单元，D19 的指针不分类）。记账树多一条统计量（inode 号水位 = 2）。
树 ID 的取值等树 ID 分配规则（P2 欠账）。
