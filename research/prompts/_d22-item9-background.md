# 背景材料：D22 未定项 9（超级块的字段表）的四条挡路

**每一条外部事实都由主 agent 于 2026-09-07 逐字现查过原文，来源写在每条后面。**

## 待验推论（三条，分别标 T1 / T2 / T3）

### T1：挡路条 ①（自举循环）不成立

登记的说法逐字是：「指针里的 dev id 要靠设备表才映射得到真实设备，而异构池下
『设备 N 用哪套布局』也在表里，撞 D12 已定项 3 逐字排除过的那条循环」。

T1 主张这条循环在超级块这一层已经被堵掉，理由三条已定条款：

1. **超级块骨架的解析不需要布局。** D12 已定项 2 把「超级块骨架、feature bit 编码、
   『设备 → 布局』表」归进**必须共用**桶，理由逐字：「超级块那一格靠的不是失败模式，
   是链条起点：解析规则要在读到那一层之前就在手上，而超级块**没有上一层**——
   想读它得先知道布局，想知道布局得先读它。」⇒ 全布局同一套骨架。
2. **dev id → 真实设备不查设备表。** 超级块每盘一份（D22 已定项 8），
   段一里有 `this_dev_id`（E100 源码 `SEC1`，4 字节，判据 5 实测「读到第 122 字节判得出本盘 dev id」）。
   挂载时手上已经握着一批块设备句柄（哪个句柄是哪台盘是**观测**，不是查表——
   D12 已定项 2 逐字：「扫的人知道自己在读哪个设备（那是观测）」）
   ⇒ 逐个读各盘超级块即可建出 dev id → 句柄，设备表不参与。
3. **读一个单元不需要条带几何。** D2 已定项 10（2026-09-01 用户定案）逐字：
   「一个 32768 字节的单元不切开、不横跨多列；位置条目每个副本一条。」
   位置条目是 (设备 ID 4, 物理偏移 6 = 16 KiB 槽号, 密文校验和 4)（D19 已定项 4）。
   ⇒ 寻址算术只用 dev → 句柄、槽号 × 落点粒度，不用条带宽度、不用布局。

### T2：挡路条 ④ 的答案由已定条款推得，不需要新决策

登记的说法逐字是：「节点大小 / 单元大小 / 落点粒度到底是池级还是每设备没定——
D12 已定项 2 把『各布局自己的节点布局、条带几何』明确归进『可以各异』桶」。

T2 主张：

- **单元大小两档（元数据 16384 / 数据 32768，D18 已定项 9）与落点粒度 16384（D3 已定项 7）
  必须全池统一。** 推导：D2 已定项 10 依据 2 逐字「格 = 单元 …… **一条条带的全部格必须等宽**，
  逐位异或才有定义」；D2 已定项 6 逐字「`w = clamp(攒批后的写入量 + 1, 2, 4)`，
  **再夹当时可写的设备数**」⇒ 任何一台可写的盘都可能被选进同一条条带
  ⇒ 格宽必须在全池所有盘上相等。
- **这与 D12 已定项 2 不冲突，因为那一桶写的是「节点布局」不是「节点大小」。**
  节点内部怎么排（bset 形态、D11 的消息缓冲区、ε）可以各异；节点占盘多少字节不行。
  旁证：D12 已定项 2 自己把 ε 与缓冲几何逐字排除在本项范围之外
  （「它们确实全布局一样，但那不是格式契约」）。

### T3：真正挡路的是 ③，而且它比登记的更宽

登记的说法逐字是「420 里至少 124 字节没有出处」。T3 主张问题不是「有字节没出处」，
而是**反过来也漏了：已定条款明文要求进超级块的字段，E100 的 24 字段表里没有**。
主 agent 已现查到三处：

| 已定条款逐字 | 出处 | 在 E100 的 24 字段里？ |
|---|---|---|
| 「上界 4 是**超级块声明的常量**，与设备数无关」 | D2 已定项 6 | **没有** |
| 「g 是**超级块声明常量**，初值 4；组不落盘」 | D2 已定项 8 | **没有** |
| 「区域 r 落在 `r × P × chunk`，**P 素数且 `P > devs`**」 | D22 已定项 2 | `ring_R_S` 只有 4 字节，装 R 与 S；**P 与 devs 没有** |
