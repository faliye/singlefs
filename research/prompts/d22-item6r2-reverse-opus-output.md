## H1（Q2b 前半）：`0xff` 是装置伪影，而且是**两行不同的 `memset`** 造出来的对照

**逐字**，`/home/fy5090/kbuild/linux-om/drivers/block/null_blk/main.c` 第 1250–1276 行（`null_transfer()` 起于 1250，`memset(..., 0xff, ...)` 在 1275）：

```c

	unsigned int len, unsigned int off, bool is_write, loff_t pos,
	bool is_fua)
{
	...
	p = kmap_local_page(page) + off;
	if (!is_write) {
		if (dev->zoned) {
			valid_len = null_zone_valid_read_len(nullb,
				pos >> SECTOR_SHIFT, len);
			if (valid_len && valid_len != len)
				valid_len -= pos & (SECTOR_SIZE - 1);
		}

		if (valid_len) {
			copy_from_nullb(nullb, p, pos, valid_len);

			memset(p + valid_len, 0xff, len);
```

```c
				sector_t sector, unsigned int len)

	    sector + nr_sectors <= zone->wp)
```

## H2（Q2b 后半）：标准允许哪几种「读未写块」——含「读失败」

**ZBC / ZAC 的 URSWRZ**（本机内核树现查，`drivers/scsi/sd_zbc.c` 第 412 行与第 440–450 行，逐字）：

```c
	/* Host-managed */
	sdkp->urswrz = buf[4] & 1;
	...
	/*
	 * Check for unconstrained reads: host-managed devices with
	 * constrained reads (drives failing read after write pointer)
	 * are not supported.
	 */
	if (!sdkp->urswrz) {
		if (sdkp->first_scan)
			sd_printk(KERN_NOTICE, sdkp,
			  "constrained reads devices are not supported\n");
		return -ENODEV;
	}
```

（`buf` 是 VPD page `0xb6`，见同函数第 396 行 `if (scsi_get_vpd_page(sdkp->device, 0xb6, buf, 64)) {`。）
⇒ **ZBC 明文存在一类「drives failing read after write pointer」的设备**，即 E125 判据 1 的 ③。

外部佐证（**未在本项目验证**）：[zonedstorage.io 的 Linux 概览](https://zonedstorage.io/docs/linux/overview)逐字
「The ZBC and ZAC standards define the *URSWRZ* bit, which determines whether a device will return an error when a read operation is directed at unwritten sectors of a sequential write required zone.」
以及「Linux supports only ZBC and ZAC host-managed hard disks that allow unrestricted read commands.」
⚠️ 该页另有一句「Linux supports only SMR hard disks that report that the URSWRZ bit is **not** set」，**与本机内核源码相反**（源码是 `if (!sdkp->urswrz) return -ENODEV;`，即要求 URSWRZ = 1）。
按 `.claude/singlefs-ai-sop/rules/evidence-discipline.md`「喂给多方论证的背景材料，本身要先核」，**以源码为准，该页那一句记为已核出错**。

**NVMe 的 DLFEAT**（Identify Namespace 字节 33，bits 2:0；外部出处，**未在本项目验证**）：
`000b` = 不保证返回什么 / `001b` = 全 `0x00` / `010b` = 全 `0xFF`。
内核只消费 `001b`，`drivers/nvme/host/core.c` 第 2498–2504 行逐字（注释起于 2499，`if` 在 2504）：

```c
	/*
	 * Only set the DEAC bit if the device guarantees that reads from
	 * deallocated data return zeroes.  While the DEAC bit does not
	 * require that, it must be a no-op if reads from deallocated data
	 * do not return zeroes.
	 */
	if ((id->dlfeat & 0x7) == 0x1 && (id->dlfeat & (1 << 3))) {
```

**⇒ 「读未写块」标准允许至少三种行为：全 0x00 / 全 0xFF / 不保证；ZBC 另外允许直接报错。**

**推翻候选 V 的哪一半**：推翻把 ② 读成「zoned 上就是这样」的余地。
V 措辞里没有这个越界（它写的是「本装置顺序区 `0xff`」），所以这条**不打中 V 本身**，
它打中的是**下游任何一个只读到 V 而没读到 E125 失败条款的人**。

⚠️ **这一条自己有反面，如实记**：Linux 把 URSWRZ = 0 的盘直接 `-ENODEV`（上引源码），
NVMe ZNS 侧读 WP 之上返回什么由 DLFEAT 决定而不是报错。
⇒ **在「本工程跑在 Linux 上」这个前提下，③ 这个结局到不了**。
所以 H2 **不足以**把 V 的「读得到字节」那一半打掉。真正打掉它的是 H3。
