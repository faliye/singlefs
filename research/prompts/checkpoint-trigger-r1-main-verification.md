## 一、逐格判定

### 判定一：I-8.1（环几何够大） 按盘上字段实例化之后恒真 —— 打中，这一轮最值钱的一格

`I-8.1（环几何够大）` 判据逐字：「`环大小 ≥ F × 任一事务的最坏 journal 占用`，F ≥ 2。最坏占用与 F 写进系统配置，mkfs 时算、mount 时复算比对」。

而盘上那个「最坏占用」字段是这么填的：

```
crates/singlefs-core/src/system_configuration.rs
            let in_flight_limit =
                journal_in_flight_record_limit(self.immutable.sizes.journal_ring_bytes);
            writer.put_u64(in_flight_limit * JOURNAL_RECORD_BYTES);

crates/singlefs-format/src/lib.rs
    ring_bytes / JOURNAL_RECORD_BYTES / JOURNAL_SAFETY_FACTOR
```

⇒ 最坏占用 = (环 ÷ 记录 ÷ F) × 记录 = **环 ÷ F**。代进判据：

```
环 ≥ F × (环 ÷ F)  ⇒  805306368 ≥ 3 × 268435456 = 805306368
判定：成立    余量 0 字节
```

**主 agent 用纯算术坐实、核查员独立复算一致**，并现查了那个式子的每个输入：里面**没有任何一项是「事务」或「一次操作要写多少字节」**。判据要的是「任一事务的最坏 journal 占用」（与环长无关的量，`C310（事务切分纪律与记录数口径打架）` 现查记着是 **12 KiB**），填进去的是环长的函数。

**判定：成立。** `I-8.1（环几何够大）` 今天状态是「未实现」；一旦照盘上这个字段实现，它就是一条**永远不会红的检查**——`.claude/singlefs-ai-sop/rules/show-me-test.md` 逐字「一条永远不红的检查与没有这条检查，在门禁输出里长得一模一样」。

### 判定二：「checkpoint」这个词指着两个量 —— 打中

`D16（发布语义）` 已定项 6 定案逐字：「每次发布把 checkpoint_txg 加一——**fsync 触发的发布也是发布，没有「小发布不记号」的例外**」。而已定项 2 的触发判据说「`now − 上次 checkpoint 的时刻 ≥ T_time`」。

攻方 K4-6 判三条条款钉住**读法甲**（checkpoint = 一次发布）。核查员核那三条引文：两条逐字准确，第三条（骑手条款 3）**结尾静默截断、漏了条款自带的「引用已定项 5 的下界时连这句一起引」那句**，判 ✗。

**判定：成立，但引文有一处截断。** 按读法甲，只要有 fsync 在跑，「上次 checkpoint 的时刻」每次都重置 ⇒ 增补 1 第二轮 I7 那条算式的前提（一个间隔跨 λ·T 个事务）**不成立**。

⇒ 这是 `.claude/singlefs-ai-sop/rules/kb-discipline.md` 第 5 条要防的形态：把文里的「checkpoint」换成它的定义句，两处读出来的不是同一个量。

### 判定三：第三支只是触发、不是节流 —— 打中，这是「甲不改」的直接理由

攻方 K2-1：第三支在「来得太快」那一类历史上与 `T_dirty` 的夹取重复（`T_dirty` 挂载时已经夹到环 ÷ F）；而在它唯一该救命的那一类——**发布停摆、开放 checkpoint 一直攒**（实例切换重做期间）——上是**空转**：触发了也发不出去。要让它有用就得升级成节流（挡住新事务进来），而那撞上另一条硬要求。

**判定：成立。** 第三支买不到它要买的东西。

### 判定四：第三支算得出来 —— 没打中（正推腿的结论成立，但不改变判决）

正推腿 K1：这个量 O(1) 增量维护得出来，`crates/singlefs-core/src/write_accounting.rs` 已有同构机制（按结构种类在写入口成功那一刻记账、`.since()` 求两次快照之差），落在 `.claude/rules/fs-design.md` 记账三格的第一格但不撞它的禁令（不需要遍历）。

⚠️ 它顺带给了一个写代码时会踩的坑：**直接借用 `write_accounting.rs` 的 `JournalRecord` 字节计数会被镜像盘数放大**（它按设备各计一次），要改用 `journal.rs` 的 `counter` 做纯算术。

**判定：算得出来这一点成立，但「算得出来」不等于「该加」**——判定三说它买不到东西。这条结论留给将来真要加节流时用。

### 判定五：触发判据今天在 crates/ 里零实现 —— 成立

```
crates/singlefs-core/src/system_configuration.rs
/// 也没有触发路径——T_time 与 T_dirty 的发布触发没实现，整理三水位恒 0 = 内置默认
```

主 agent 现查：两个阈值的**字段**在盘上（可调值段两行、读得出来），`grep -rn "T_time\|T_dirty"` 在 `crates/*/src/*.rs` 里只命中 `system_configuration.rs` 一个文件。本地攻方两份干净样本在这一格上判定一致。

**判定：成立。** ⇒ 这一轮不改任何代码；但按 `.claude/rules/format-evolution.md`「真正要慎重的是决策正文，不是 `.rs` 文件」，**条款该不该定清楚与今天有没有代码在跑是独立的两件事**。

### 判定六：三支之间不打架 —— 没打中

本地攻方两份干净样本四格全一致：三支都触发同一个动作、`T_dirty` 在 WAL 类下仍永不触发且定义不用改、第三支的阈值是派生量（既不走夹取也不走警告）、这个量今天在 `crates/` 里不存在。

## 二、写回的改法

**不加第三支。** 要做的是攻方提的三条（它自陈这三条「只在副本探针上推过、被攻过零轮」）：

| 改法 | 做什么 | 落点 |
|---|---|---|
| **A** | `I-8.1（环几何够大）` 那个字段**真算**：填「任一事务的最坏 journal 占用」（`C310（事务切分纪律与记录数口径打架）` 现查是 12 KiB），不填环 ÷ F；mount 时复算比对 | `crates/singlefs-core/src/system_configuration.rs` + `crates/singlefs-format/src/lib.rs`；要走代码三方 |
| **D** | `C425`、`C432（一个 checkpoint 间隔的 journal 占用没有条款）` 各补一句，覆盖「发布停摆期间的环占用」这一格 | `.claude/kb/checks-owed.md` |
| **E** | 把「checkpoint」在 `D16（发布语义）` 里写死成「一次发布」，与 `C245` 同缝 | `.claude/kb/decisions/16-发布语义.md` |

⚠️ **改法 A 与用户 2026-09-22 提的弹性环是同一格**：环长若从 mkfs 一次性参数改成「空间大就大、空间不足就缩」的弹性量，「能缩到多小」的下界正是 `I-8.1（环几何够大）` 该给的 `F × 12 KiB = 36 KiB`。今天那个字段填成环 ÷ F，判据恒真、**给不出任何下界**——缩环时没有东西拦得住。⇒ 改法 A 并进弹性环那一轮一起做。
