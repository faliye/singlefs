1. Device slots 0 to 7. Free slots are 0-3 and 5-7. Dirty objects: key 10 (size 3), key 11 (size 1), key 12 (size 1). Sorted by key: 10,11,12. Candidate B places key 10 in slots 0-2, key 11 in slot 3, key 12 in slot 5. When walking in key order, runs are 0-2 (key 10), slot 3 (key 11), slot 5 (key 12) for total 3 runs. If not sorted and placing key 10 in 5-7 first, then key 11 in 0 and key 12 in 1, runs are 5-7 (key 10) and 0-1 (key 11 and key 12) for total 2 runs. Step where it goes wrong is key 10 being placed in the smaller free segment (0-3) instead of the larger segment (5-7), causing unnecessary fragmentation.

2. Bump-seg falls back to first-fit 91.8 to 93.8 percent of the time. For the remaining 6.2 to 8.2 percent of allocations, bump-seg places objects contiguously. Since the fallback rate is over 90 percent, the effective behavior is identical to first-fit for the vast majority of allocations. Arithmetic: 93.8 percent fallback means only 6.2 percent of allocations use the sorted contiguous placement. For practical purposes, this is first-fit with extra bookkeeping.

3. First-fit is defined as lowest numbered free slot. But if two implementations have different interpretations of slot numbering (e.g., one counts slots from 0, another from 1), or if one considers the device as a linear array while another has a multi-segment structure where slot numbers reset per segment, the behavior differs. Example: device has two segments, segment A slots 0-3, segment B slots 0-3. First-fit implementation A treats all slots as 0-7, so lowest free slot is 0. Implementation B treats each segment independently, so lowest free slot in segment A is 0. If segment A has slot 0 free and segment B has slot 0 free, implementation A would use slot 0, implementation B would use segment A slot 0. But if the device is physically laid out as segment A (0-3) followed by segment B (4-7), implementation B might map segment B's slot 0 to physical slot 4, causing different behavior.

4. Defragmenter stops when fully empty segments grow by at least one. Construct a workload where every defragmentation attempt moves objects to fill existing empty segments but creates new fragmented holes. Example: device has 4 segments. Current state: 3 segments have 1 fully empty slot each, 1 segment is full. Defragmenter moves objects from full segment to the partially empty segments, but each move creates a new hole in the source segment. After moving, the source segment becomes fully empty but the destination segments now have holes. The count of fully empty segments remains the same. Candidate A (first-fit) is closest because it constantly fills low slots, creating fragmented scattered free space that defragmenter cannot consolidate.

5. Candidate C (arrival order) places consecutive writes in adjacent slots without sorting. Workload: keys 1, 100, 2, 101, 3, 102 written in that order. Physical placement: slots 0:1, 1:100, 2:2, 3:101, 4:3, 5:102. When walking in key order, objects are at 0 (1), 2 (2), 4 (3), 1 (100), 3 (101), 5 (102). Runs: 6. Candidate A first-fit would place them in 0,1,2,3,4,5 (sorted by key), runs: 1. Candidate B bump-seg would sort keys and place contiguously, runs: 1. Candidate C costs 5 more runs than A and B.
