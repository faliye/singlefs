1. There is a way to know which addresses to read without the write pointer: read the entire zone capacity. Unwritten data beyond the write pointer fails the checksum, so the candidate set can be determined by reading all blocks in the zone. Candidate R does not fail on this point.  
2. On a zoned block device, sequential write zones cannot be overwritten in place. Therefore, there is no fixed set of slot addresses for root records. Root records are written sequentially in the zone, and the concept of a ring of fixed slot addresses does not exist. Recovery cannot read a known set of positions because the positions are not fixed.  
3. The stale record situation can arise on an append-only zone that is not reset. Old records remain until the zone is reset, so a never-written slot in the current lap may contain a valid older record from a previous lap. This requires both checksum and generation number for correct recovery.  
4. Adding an index and count to each root record does not remove dependence on the write pointer. The write pointer is still needed to determine the range of addresses to read. Without it, the filesystem must read the entire zone, which is inefficient. Additionally, the count for the first record of a zone is known (0), but the dependence on the write pointer for addressing remains.  
5. A zone reset leaving the zone indistinguishable from never written is acceptable. The filesystem must start fresh when no valid root is found, regardless of whether the zone was reset or never written. This is expected behavior and does not make candidate R unsafe.
