# agent 定义两处改动 第一轮三方

日期：2026-09-21

## 课题

这一轮判两处 agent 定义的改动站不站得住。两处都已经写进文件、门禁 72 号点名要三方判决，判决没写之前不许提交。

**被判的改动一：`.claude/main-agent.md:43`，阶段同步的判定复核由抽样改成逐行全看。**

改前（原文逐字）：

> 交回齐了主 agent 跑 `stale-candidates.py --check-report 候选表 各份报告`，退出码 0 才往下，再从全部判定里随机抽 20 行（五种判定各至少 2 行，不够的全抽）自己复判，抽到判错的那一段重派，重派交回后对那一段再抽 20 行，抽不出判错为止

改后（原文逐字）：

> 交回齐了主 agent 跑 `stale-candidates.py --check-report 候选表 各份报告`，退出码 0 才往下，再**逐行全看**：每一条判定都对着载体今天的原文核一遍，不抽样、不按判定种类挑。判错的那一段重派，重派交回照样全看

**它压着的条款**：`.claude/singlefs-ai-sop/rules/show-me-test.md`「交回的清单能被机器核全，不等于判对了」那一条逐字写着「核全之后还要在**全部判定种类**里抽查复判，抽中判错的那一段重做、再抽」。改后的做法比那一条严，但**两条文本并存**：共享规则说抽查，项目本地的调度表说全看。

**改动的由来（观测，不是推论）**：2026-09-21 那一轮阶段同步，按原条款抽 20 行复判，抓到 `.claude/kb/decisions/06-快照实现模型.md:42` 一处判错；重派那一段之后再抽 22 行，一处都没抓到；改成逐行全看 138 行，确认没有第二处判错，另外看出两件抽样不会发现的事——候选表的原文列按 500 字截断（多处判定依据落在截断之外）、`.claude/kb/experiments/155-每次持久化的写量三种fsync形态与反事实上界.md` 的回看记录引的原句已被改过。

**被判的改动二：`.claude/agents/kb-scribe.md:20`，翻成未定的分项要判两句。**

改前（原文逐字）：「翻成未定的判一句改不改第一个事务的字节（31 号）」
改后（原文逐字）：「翻成未定的判两句（31 号两把尺都要，缺一句就红）：改不改第一个事务的字节、动不动格式」

**它压着的条款**：门禁 31 号同一轮改成两把尺（第二把判 D15（格式冻结政策） 已定项 1 要的「动不动格式」），定义里只说了第一把。

## 分工

| 腿 | 攻击面 |
|---|---|
| 云端攻方（Opus） | 改动一：**逐行全看这条规则本身会不会失效**。它要求主 agent 对每一条判定核一遍载体今天的原文——候选表可能几百行，上下文装不装得下？装不下时它会退化成什么（跳读、只看判定词、相信子 agent 的理由）？退化之后与抽样比，是更好还是更坏？另外：共享规则写抽查、本地调度表写全看，两条并存时执行的人照哪一条办，有没有一种读法能让人合规地只做抽查 |
| 云端正推（Sonnet） | 改动一与改动二：**从条款与实测推它们成不成立**。逐字读 `show-me-test.md` 那一条与 `.claude/main-agent.md` 改后那一句，判「本地更严」是不是这套规范允许的形态（那句话逐字住在 `.claude/singlefs-ai-sop/rules/show-me-test.md` 的「## 推论」第 3 条：「**门禁是下限，不是上限**（`rules/sop-first.md`）」——括注指回 `sop-first.md`，而 `sop-first.md` 全文没有这句的字面，引的时候别把出处记成后者）；改动二那边，逐字读 31 号改后的两把尺与 `.claude/rules/format-evolution.md` 改后的措辞，判三处（门禁、规则、agent 定义）说的是不是同一件事 |
| 本地攻方 | 改动二：**两把尺会不会被写定义的人混成一把**。给它 31 号两条正则、D15（格式冻结政策） 已定项 1 的三取值、以及 D2（RAID 条带策略） 未定项 21 那一行（第一把判「否」、第二把判「动」）的事实表，逐格填：哪几种写法会让一条分项在两把尺上拿到互相矛盾的判定、门禁现在拦不拦得住 |
