## 二、逐判据

记号：树 t 是活头 H 的 extent 树；快照 / 克隆的 txg 用 checkpoint 号；K = (类 2, 出生树, 诞生代号, 实例代号, 出生序号)。H 的 `previous_snapshot_txg` 写 `H.prev`。

### 判据 1：划分判不判得出 —— 两臂都红（按字面；核过原文，结论是推的）

**正推能给的最强判法**（我先替丙′ 写出来再攻）：对一个丢了的码 2 节点 X，若知道它的诞生代号 b 与持有它的头 H，则「X 被 H 的某个活快照或某个克隆 origin 引用」⟺ `b ≤ H.prev`。这一条我逐个情形核过是精确的（推的）：线性历史下 D5:176–178 的归约证明直接给出；克隆 C 的 `previous_snapshot_txg` 初值是 origin 的 txg（D5:151–152），C 里 `b ≤ C.prev` 的节点只能是从 origin 继承来的；`prev` 在销毁快照时按 D5:11 往回传；分叉点快照有克隆时不许销毁（D5:153–155）。两个方向都不漏。

**打中的地方：b 住在哪。** 这条判法要 b，而 b 的载体逐个是：

| 载体 | 态别 | 出处 |
|---|---|---|
| X 自己的头 | X 丢了就没了 | — |
| 父节点里指向 X 的节点指针 | 派生态（索引） | D19:131；D21:21 |
| 中央映射里 X 的条目（key 含出生 txg） | 派生态，丢了从单元扫描重建，而 X 不可读就重建不回它 | D19:202 |
| deadlist / livelist 里按 key 记的条目 | 态别全仓没写（第一轮已核）；**而且只在 X 被杀过（deadlist）或出生晚于克隆时刻（livelist）时才有** | D5:229；D6:232 |
| 树表条目里的根指针 | 权威态（「根」含树表单元） | D8:462；D21:10 |

⇒ 权威态里只有树表根指针带 b，只罩每棵树的根节点。**触发节点**（给判据 1 的触发观测）：

> H 于 txg 90 写出 X（第 1 层，诞生 90）与它的父 P（第 2 层）；txg 100 建快照 S（`H.prev = 100`）；txg 120 H 改写 P 下另一个孩子 ⇒ P COW 成 P_H（诞生 120），X 不动 ⇒ X 同时挂在 P_H（H）与 P（S）下。之后 X、P_H、P 与映射里 X 那一条都丢。
> X 仍在活头里、没被杀过 ⇒ 不在任何 deadlist（第一轮序列 2 同形）；H 不是克隆 ⇒ 不在 livelist。
> ⇒ 只凭单元 + 记账 + 根，X 的 b 与 K 都拿不到，`b ≤ H.prev` 判不了；X 被不被 S 引用，要读 P_H 或 P 或映射——三样都是派生态，而且都丢了。

**这一格判不出，后果是什么**（我推的）：R2 按定义只用在「抄不回」的格子上，也就是持有者全丢；而持有者全丢恰好就是 b 拿不到的时候。⇒ 在一个有活快照或有克隆血缘的头里，**R2 需要的那个前提（「只被活头引用」）永远判不出**。能判出「只被活头引用」的只剩两种：头根本没有快照、也不是克隆（从树表就读得出，推的）；或者重建器能拿出一个诞生晚于 `H.prev` 的现行数据单元落在 X 的 key 区间里——而 X 的 key 区间要从父节点的分隔 key 取，父节点也丢了。

**保守默认救得回吗**：能救正确性、救不回可写性。给丙′ 加一句「判不出一律按第二部分」是收严（多挡、不少挡）；加了之后没有错答案，但上面那个头里的每一格 R2 都转成只读——这正是失败条款 2 写的退化，只是范围是「有快照或克隆血缘的头」而不是全部。

⚠️ **另一种读法能避开它，但那是放宽，不是收严**：把划分从「旧节点」改成「重建产物」——凡是只挂进活头那棵树的新产物都算第一部分，只有要挂进快照 / 克隆 origin 那棵树的产物才受限。挂到哪棵树由重建器自己决定，所以按产物划分永远判得出（推的）。但它允许「给一个被快照共享的旧节点在活头里另造一份新身份的替身并持久化」，而丙′ 的字面禁止「被活快照引用的码 2 节点……重建……新发身份后持久化」⇒ 它比丙′ 多放行一格，按「只许收严」不能当丙′ 的收严用，要另开臂（第五节「丙‴」）。

**丁**：第一部分与丙′ 相同，同一格红；丁的第二部分另要「引用它的全部快照 / 克隆 origin」这个集合，持有者全丢时这个集合同样判不出（推的）。

### 判据 2：R1 抄回会不会抄错 —— 两臂都红（按最弱读法）

先说字面那一格：**「持有者之间 key 不一致」我找不到能给错答案的序列**（推的）。映射 key 就是节点身份：每个持有者都是按 key 指它，搬迁不改 key（D19:137），出生 txg 本身是 key 的一段，所以不存在「两个持有者给同一个节点报两个诞生代号」。C294（checks-owed.md:286）说的「指针 key 与被指单元头不等」是写路径的 bug 面，R1 从指针抄回反而会把单元头改成与指针一致，不会让它更坏。固定点里同一节点两版同 key（C163、C291 的「节点重写换号」还不是条款）会让映射的扫描重建挑错版本，那是丢节点之前就在的洞，不是 R1 造出来的。**这半格不红。**

**打中的是另一半：R1 抄回的诞生代号与重造出来的内容不配。** 背景材料第三节把 R1 写成「四段 key 与诞生代号……原样抄回……按搬迁处理」，没有写内容从哪来；丙′ 列的 R1 走不通只有两种（持有者全丢、要的是历史版本）。而「按搬迁处理」在仓里的依据是内容逐字节不变——D19:137「被搬单元逐字节不变、birth 不变」、D5:25–28「逻辑内容一个字节没变，只是物理位置换了」。节点丢了，内容只能重造；**内部节点的子项是码 2，而全仓没有码 2 的择版本规则**（D21:30「码 2 不进扫描重建的择版本规则」；D18:196–197 择新键那一行码 2 那一格「**不进规则**」），父节点丢了之后盘上同一 key 区间的哪一版码 2 是现行，判不出 ⇒ 子项只能从叶重造、新发身份。
