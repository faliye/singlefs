## 1. Q1：定口径

**先判「稳态占用收益」合不合法，答案是：不合法，独立于任何算术结果。**

`.claude/rules/fs-design.md` 逐字：

> 更强的一条：「比谁省」不构成任何判据。省空间从来不是本工程的目标，
> 所以「我们比 X 省 / 比 X 费」这类比较不许出现在任何判据里——
> 它可以用来驳「我们很奢侈」这个前提，仅此而已。

D27（小数据打包容器） 已定项 1 与已定项 2 采纳「后台整理」与「4 KiB 界线」，
两处用的**都是**「稳态占用收益倍数」（52.33× … 1.00×）——这正是「我们（打包形态）比（补齐形态）省」
这个句式的字面实例，`X` 不必是另一个项目，把它换成本工程自己的另一个候选形态，
句式与被否掉的 D21（权威态与派生态的分界） 那次推导（「本工程在 128 KiB 单元上比 ZFS 省」）
是**同一个语法**。规则原文没有把 `X` 限定成「外部系统」，「省空间从来不是本工程的目标」
这句本身就是无差别的。⇒ **稳态占用倍数不能作为『要不要采纳 D27』的判据**，
无论 Q2 算出来是正是负。

**规则自己留的口子**：「除非有实测证明省下来的那部分是瓶颈」。
这才是 D27 剩下的、唯一合法的收益说法：不是「打包更省」，
而是「**不打包是不是把 4 KiB 以下的对象堆成了一个真实的瓶颈**」——
比如 ENOSPC 提前撞墙、或者某个运行时判定的输入规模失控。
这件事至今没人测过：D25（目标负载优先级） 的 smallfile 那一行三列「未测」，
[checks-owed.md](../checks-owed.md) C174（smallfile 那一行的三列没测） 挂着账。

⇒ **本文选 (b) 一次性搬迁写作为可以诚实陈述的量**：它是一项工程成本（要写多少字节才能把
一批已经落盘的小对象搬进容器），不是一句「更省」的比较句，陈述它不违反上面那条硬要求。
(a) 稳态占用只作为计算 (c) 的输入使用，不单独作为判据陈述。
(c) 回本比是把 (a)（省下的空间）与 (b)（花掉的字节）放到同一把尺子上的诚实换算，
但它换算出来的仍然是「效率」，**不能替代「瓶颈论证」的举证责任**——即使回本比是正的，
也只回答了「这笔搬迁划不划算」，不回答「不搬会不会撞墙」，后者才是规则留的那个合法收益。

**独立于 Q2 的准入判断**：即使 (b)/(c) 全部对 D27 有利，`.claude/rules/fs-design.md`
的格式分支判据——「一条格式分支值不值得，看它能不能把『用错了』变成『挂不上』」——
D27 今天答不出来：不打包一个小对象不会造成任何静默误读，只是浪费空间；
打包也不把任何非法状态变成拒绝挂载。**它买不到安全性，只买效率**，
而效率被上面那条硬要求排除在判据之外。加上 D25（目标负载优先级） 那条独立举证的要求
（「一条永久的格式分支只服务次要负载，不许拿收益倍数顶替」，smallfile 权重「次」）
今天同样没有别的证成。⇒ **这一步的判断先于、且独立于下面的算术**：
D27 在「够不够格进格式」这一步，今天没有站得住的理由，Q2 判正判负都不改这个结论。

## 2. 反向条款（跑前写死，写在算之前）

1. **若任一（策略 × 对象大小）组合的「一次性搬迁写 ÷ 稳态省下的空间」≥ 1.0**，
   判该组合「搬迁永不回本，与对象能活多久无关」——这是比值本身给出的、不依赖任何
   生命周期假设的结论，不许因为换一个组合数字好看就放弃汇报这一条。
2. **若四个写分量里任何一个占总账 ≥ 10%**，判它「材料」，不许在结论里略去；
   只有 < 1% 的分量才能说「可以忽略」。
3. **若「按映射 key 序」与「按容器凑满序」两条策略在同一对象大小上给出的总账相差超过一个数量级**，
   判「D27（小数据打包容器） 未定项 6（整理的触发判据与批量）是这笔账的主导变量」，
   不许把其中一条当作代表数字挑着报。
4. **若中央映射迁移写单独一项就超过稳态省下的空间**，判「不需要算数据侧就已经回不了本」——
   这条比第 1 条更强，说明问题根本不出在数据侧的容器写放大上。

## 4. 回本期

**先说不能给什么**：「对象要活多久」需要一个把「省下的空间」换算成「每天值多少字节」的汇率，
而这个汇率不存在——D25（目标负载优先级） 的 smallfile 三列（叶/fsync、脊柱数、写放大）全部「未测」，
[checks-owed.md](../checks-owed.md) C174（smallfile 那一行的三列没测） 挂着账。没有到达率就没有「天」。

**能给的是一个与到达率无关的下界判断**：稳态省下的空间是「一次性冻结」的量（搬完立刻全额兑现，
不随时间累积），所以「一次性搬迁写」相对「稳态省下的空间」的比值，**在对象活到无穷久的极限下
仍然 ≥ 1** 就意味着这笔账永远回不了本——不需要知道对象具体活多久，因为连「活到永远」都不够本。
这是本文能负责任给出的唯一数：

`回本比 = 一次性搬迁写 ÷ 稳态省下的空间`，`稳态省下的空间 = 100000×32768 − containers×32768`：

| 对象大小 | 省下的空间（MiB） | 回本比（按映射 key 序） | 回本比（按容器凑满序，B=1） |
|---|---|---|---|
| 512 B | 3 071.09 | **4.01%** | **105.25%（不回本）** |
| 1 KiB | 3 020.81 | **7.41%** | **110.33%（不回本）** |
| 4 KiB | 2 678.56 | **33.92%** | **150.00%（不回本）** |
| 8 KiB | 2 083.25 | **100.79%（不回本）** | **250.00%（不回本）** |
| 16 KiB | 0 | ∞（不回本，省下的空间恒 0） | ∞（不回本） |

**新发现，比第二轮的结论更强**：

1. **8 KiB 档在「按映射 key 序」——已知代价最低的那条策略——下也回不了本**：
   一次性搬迁写（2 099.93 MiB）已经超过它永久省下的空间（2 083.25 MiB）。
   D27（小数据打包容器） 正文写 8 KiB「2.98× 仍为正」，那是**只算稳态占用比、完全没算搬迁成本**——
   把搬迁成本一并算上，8 KiB 这一档在两种策略下都不回本，**与对象能活多久无关**（反向条款第 1 条命中）。
2. **「按容器凑满序」在全部五档上都不回本**，包括此前从未在净收益表里出现过的 8 KiB / 16 KiB。
   这是第二轮「三档全负」结论的自然延伸，用「回本比 ≥ 1」这个更硬的判据重新表述：
   **不需要知道 f（覆写比例）或整理频率，光是把 N 个对象搬进容器这一次性动作本身就亏本**。
3. **只有 512 B / 1 KiB / 4 KiB 在「按映射 key 序」下有正的空间去谈回本**（4.01% / 7.41% / 33.92%）,
   而这条策略正是 D27（小数据打包容器） 未定项 6 尚未拍板的那一种；一旦整理批量拉不到「按 key 序」
   那种效率（现实中整理多半是按写入/到期顺序处理，不是按 key 排序处理），
   这三档同样会滑向「按容器凑满序」那一列的不回本区间。

### 钉绝对值的断言（每条都要能在变异测试里被抓到）

1. `cap(512)=58, cap(1024)=30, cap(4096)=7, cap(8192)=3, cap(16384)=1`（沿用 E114（小数据打包容器的总账），
   注意 `capacity()` 对容器头不敏感，**必须像 E114 已经做的那样补一个跨整数边界的取样点**
   ——见 `.claude/rules/mutation-sampling.md`，`16286` 那一档的手法原样搬过来，
   分配记录树与中央映射树各自的叶容量也要各配一个跨边界取样点，不能只在 SIZES 那五档上测）。
2. `total_leaves_map(N=100000, cap=267)=375`；`leaves(B=1) ≈ 99867`（容许 0.1% 误差）；
   `leaves(B=375)` 应显著低于 `leaves(B=1)`（判别力对照：换批量必须真的改变叶数，
   否则 `map_fillorder` 这条臂没有测出它本该测的那个变量）。
3. `leaves_alloc(512)=113, leaves_alloc(16384)=221`（本文 Component 3 表逐档钉死）。
4. `records_journal(512)=7, records_journal(16384)=9`。
5. **回本比**：`payback_ratio(8192, keyorder) > 1.0`、`payback_ratio(16384, keyorder)` 除以 0 的地方要判 `f64::INFINITY`
   而不是 panic 或悄悄给 0——这条防的正是「省下的空间恰好是 0」这种边界被静默吃掉。

### 失败条款（跑前写死，覆盖上面全部六条臂，不许有臂漏在射程外）

1. **阳性对照**：把 `cap` 强制设成 1（沿用 E114（小数据打包容器的总账） 的做法），
   `map_keyorder` 与 `map_fillorder` 的叶数都必须退化成 `pad` 对应的「每对象一条映射改写」，
   `alloc_migration` 同样要退化——**六条臂里只要有一条对不上就整轮作废**（这正是堵 C186 的地方：
   条款文字必须显式点名全部六个标识符，门禁阶段要能从这份清单里数出 6，数不出就判红）。
2. **判别力对照**：`map_fillorder(B=1)` 与 `map_fillorder(B=leaf数×10)` 的叶数必须相差超过 50%——
   证明这条臂真的对批量敏感，不是摆设。
3. **阴性对照**：N=0 时六条臂全部输出 0（`journal_migration` 的记录数在 N=0 时必须是 0 条，不是 1 条空记录）。
4. **回本比反向条款**（对应上面第 3 节的反向条款 1）：**任何一档 payback_ratio ≥ 1.0**，
   测试必须显式断言并打印该档「不回本，与生命周期无关」——不许只把数字打出来、让人自己去读表格判断；
   断言本身要能在变异测试里被抓（比如把某个分量写死成 0，回本比应该跟着掉出这条断言的范围）。
5. **格式常量出处**：仿 C187（源码里没在 kb 登记的格式常量，格式常量门禁看不见） 的做法，
   `map_keyorder` / `alloc_migration` 用到的「58 字节叶头」必须在源码注释里显式标「假设，来源：
   E97（记账与分配记录的条目编码） 的头 58 类比，非独立决策」——不许写成「格式常量，全部有出处」这种会被
   `.claude/gate.d/27-format-constants.sh` 放过的措辞，因为它确实没有独立出处。
