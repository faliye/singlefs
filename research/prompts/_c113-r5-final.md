## 三、定案

### P1 单元头带「写序」= (实例代号 4, 事务号低 48 位)

每个单元的类身份段加 10 字节写序 = 写出它的那个事务的 (实例代号, 事务号)。事务号是 D23 已定项 7 记录头里的 8 字节字段：按实例计数、从 1 起、高 16 位恒 0；提交标记 1 字节；记录头增量 9 与五处实验常量不动。jsn 按记录递增、事务号按事务递增，是两个计数；同一事务的全部记录共享事务号。
住类身份段不住共同前缀：码 1 与五元组、诞生代号同列（明文）；码 2 / 3 与诞生代号同待遇（加密开启后进密文）。

**取号纪律**：
1. **取号 = 事务被分配进某个 checkpoint 那一刻**，同时钉死它的 checkpoint 号，诞生代号由此写得出。checkpoint 的**切分只关闭成员资格**：触发之后不再分配事务进这个 checkpoint，已分配的事务把各自的单元写完；发布阶段等全部单元落盘（任何 COW checkpoint 都要等最慢的那次 I/O，ZFS 的 txg sync 同样等最慢的 vdev）。这是 D16 新规则 1「快照发布点钉在本 checkpoint 全部数据变更之后」的可执行形态。
2. **事务切分纪律**：一次写请求按单元切成若干事务各自取号（W1 不受影响，它们碰的 key 不同）⇒ 一个事务最多写一个单元的用户数据，切分延迟 ≤ 一个单元的写延迟。**与 ZFS 的差异**（现查 `zfs_vnops.c:780` 的循环）：ZFS 把一次 write() 切成每个记录块一个 dmu_tx、hold 在脏化完成时释放、I/O 在 sync 阶段；本工程的事务是应用可见的原子单元，切分纪律是让两者的 Δ 同量级的那一条。**D16 已定项 5 的上界口径由此改写**：崩溃最多丢的是 T_time + 一个单元的写延迟，不再恰是 5 s——这条动了用户定案，待用户复核。E70 的下界不受影响。在飞 checkpoint 深度 = 开放 + 发布中两个；并发 fsync 的返回时刻被同 checkpoint 的其他事务拖住是组提交固有的代价，记进 D25 的连锁。
3. 记录按事务号顺序追加；事务号 N 的 fsync 在返回前必须等 < N 的事务全部**已追加 ∨ 已作废 ∨ 已确定实例结束**（作废是提交管道的内存状态，对并发后继可见）。D13 已定项 2 第一版串行提交下这一条空转，是对将来并行提交的前置约束。
4. **失败表（封闭）**：① 取号之前失败 ⇒ 无事；② 取号之后、**尚未向设备发出任何单元写请求**时失败 ⇒ 号作废，不写单元不追加记录（事务号留洞无害）；③ 发出过任一单元写请求之后失败：单副本写失败 ⇒ 换落点重试、写序不变，重试有次数上界；事务级失败（准入中途拒绝、超过重试上界之外的可恢复错误）⇒ **写一条作废行 (i, n)**（P2 实例表 kind 2）与这个 checkpoint 同一次发布，该事务的单元由此判未发布；不可恢复的失败（全部副本失败、内部不变量破）⇒ 实例结束，转只读，下次挂载走恢复并写行。固定点收敛轮数超过声明上界不是失败事件（E81：收敛总会发生），是 C83 的读数。
5. **W1**：一个事务对一个逻辑 key 至多留一种净效果；未点名的单元允许原地重写或不点名；写序相等且不是副本时墓碑赢。

**10 字节买三件事**：同 key 已发布版本定序（诞生代号 + W1 够——`no_wseq` 臂只在同 txg 跨事务改同 key 时歧义）；分辨崩溃前后时间线（4 字节实例代号够——`inst_only` 臂在 crash_clean 世界 0）；在飞 txg 被部分重放时分开同实例同 txg 的已施加与被抛弃（**非要事务号不可**——`inst_only` 臂在 crash 世界复活 6）。第三格的发生频率未测。
**与唯一先例的差异**：bcachefs 两个字段（节点重写序 + journal_seq）且不给数据 extent 做扫描择版本；本工程一个字段、加在数据单元上，能做是因为 D18 已定项 3 让数据单元头带五元组。未在本项目验证。
**重开两句已定**：D18 已定项 1（射程条款重开）；D8 已定项 6「别的单元类都没有……不给容器单独加实例代号」。

### P2 实例表（码 3 打包记录类型 4）；实例代号

**实例表单元**：码 3 打包记录单元，打包记录类型 4，记录宽 64，三种记录按首字节 kind 分：
- kind 0 行记录：`kind 1 | 实例代号 4 | 发布上限 txg 8 | 事务号上限 8 | 预留 43`；
- kind 1 链指针记录（恒为一片的最后一条）：`kind 1 | 有无下一片 1 | 位置指针 59（无下一片时清零占位）| 预留 3`；
- kind 2 作废行：`kind 1 | 实例代号 4 | 事务号 8 | 预留 51`——该事务的单元判未发布。
四元组 (出生树 0, 类型 4, 容器号 = 片序号从 0 起, 出生代 0)；出生树 0 与 D5 给「全池 / 无归属」行的约定同一个数；不属于任何树、不进容器索引，由根记录直接持有物理指针（D18 已定项 11「容器索引是唯一持有者」加类型 4 例外）；I-1.1 加第三条臂、I-1.3 豁免行加类型 4；I-1.7 与 D18 已定项 11 的三处 93 改 103。一片 510 条记录（含链指针）；mkfs 写出一片空表（记录数 1：一条「无下一片」的链指针记录）。
根记录加两样：实例表单元指针 59、**最大已施加事务号 8**（这个根发布时该实例最后一条被施加记录的事务号；回退行的 W 取它）：127 → 194，512 槽余 318。COW 重写：每次写行重写整条链，代价 n × 32 KiB × w；非 zoned 上 n 由行回收压住，zoned 第一版不回收、链长无上界（第一版不跑 zoned，如实记）。
它属于 D21「根」那一格（根记录 + 树表单元 + 实例表单元 = 根的间接层）；载荷格式落进 D15 冻结组件 ①；类型 3 / 4 按 D15 默认档 incompat（冻结前零代价）。

**行怎么写**：实例表按实例代号唯一（kind 0），后写覆盖；kind 2 按 (实例代号, 事务号) 唯一。
- 任何非干净结束的实例在下次恢复写行：给 [所选根的实例, 新实例) 每个实例写 (i, 在飞 txg, 重放施加的最大事务号)，一条都没施加的写 (i, 在飞 txg, 0)；
- 回退：写 (r_old, T_old, R_old 根记录里的最大已施加事务号) 与中间实例的 (i, 0, 0)；
- 事务级失败：作废行 (i, n) 与这个 checkpoint 同一次发布；
- 全部与恢复 / 回退 / 这个 checkpoint 的根同一次发布写出。
**回收**：kind 0 行可删当且仅当清扫确认盘上不再有该实例超出上限的可读单元，且全部设备在线；kind 2 行同理按该事务的单元；zoned 第一版不回收。
**表不可读时**：① 正常挂载不受影响、可写，但记持久标记「实例表曾不可读」，此后扫描重建对那些实例里「诞生代号 == 某次重发代号」的多版只能记歧义——是把 C113 的一角重新暴露，不是兜住；② 扫描重建时读不到实例表 ⇒ 停在级 1。

**已发布谓词（全局）**：i_now = 挂载根的实例；单元写序 (i, n)、诞生代号 b：
- (i, n) 有作废行 ⇒ 未发布；
- i < i_now：无 kind 0 行 ⇒ 已发布；有行 (i, T, W) ⇒ b ≤ T ∧ n ≤ W；
- i == i_now：b ≤ 挂载根的 txg；
- i > i_now：判损坏。
**射程**：「无行 ⇒ 已发布」只对同一时间线成立。

**实例代号**：住超级块（E100 段四那 4 字节，这里补语义）。新代号 = max(全部可见超级块的代号, 根环里全部根记录的实例代号) + 1；每次可写挂载（含干净挂载、只读转可写）取一次新号并先写全部可见超级块再动任何单元；只读挂载不取号；从 1 起、0 无效；32 位按挂载次数够用。
- **射程**：取号那一刻两路见证不完整可见（部分盘或部分根环区域缺席）时不额外拦截，与整卷回滚同格，随 D9 已定项 8 宣布不防；I-7.6 只在 devs ≥ R 时让根环成为超级块之外的独立见证，第一版 (R = 3, devs = 2) 不成立，两路见证的失败域是同一对盘。
- **分叉盘**：第一版 2 盘、掉一块盘只能只读挂载（D2 已定项 9）、只读不取号 ⇒ 分叉在第一版不可达。盘数 ≥ 3 时降级可写挂载可达，「回归盘不是当前时间线的祖先」今天没有可判定的形式（根记录没有前驱字段），立成新欠账：候选判据是每盘超级块记「这块盘见过的最大 (实例代号, txg)」并要求它在当前根环里找得到对应的根；重同步的形态归 D2 / D22 / D26 未定；2 盘下整盘作废 = 整池只读直到重同步完成。

### P3 现行版本判定规则

输入：挂载根，根集 ℛ = 树表里的可写头 ∪ 快照列表（快照结构字段未定，按「只带 txg」假设），祖先表（P6），实例表，扫到的**码 1 与码 3** 单元，墓碑 / 退役记录。**码 2 不进规则**：它是派生态，扫到的旧码 2 节点一律垃圾，由重建重写。

**副本归并（先于择版本，只对码 1 / 3）**：同类身份段全部字段（含写序）的多份可读单元是同一逻辑版本的副本（D2 已定项 6 的 w = 2：parity 即第二副本、逐字节相同；P1 失败表 ③ 的重试同理），先归并成一个候选；成员载荷必须相同，码 3 由载荷校验和判、码 1 靠 C104 的载荷 CRC（由此从候选升为码 1 级 1 恢复的前置）；判不出哪份完好的记损坏、不择。w ≥ 3 时每个单元一份副本、parity 列不进归并。Current 返回一个版本与它全部副本的落点。

**回退的定义**（D23 已定项 14 的显式例外）：管理员带外从**回退候选集**里选一个旧根 R_old——候选集 = 根环里按实例表判仍然有效的根：(i, T) 可选 ⟺ 实例表无 i 的行，或有行 (i, Ti, Wi) 且 T ≤ Ti（被抛弃时间线的根一条都选不中）。回退 = 一次恢复：不施加 R_old 之后的任何记录；取新实例代号；写回退行；第一个新根的 checkpoint_txg = 根环里全部根记录 txg 的最大值 + 1；运行时的 defer 队列、分配器游标、全部记账统计量的现行值从 R_old 那棵账重新载入。回退与它的第一个新根同一次发布，之前没有持久效果，崩了就重做。回退深度 ≤ 根环深度 ≤ K。

逻辑 key 与写者树：码 1 = (对象 ID, 对象出生代, 锚点偏移)、写者树 = 五元组的树 ID；码 3 = 四元组、写者树 = 出生树（P6）。
```
Visible_R(u)  := 已发布(u) ∧ u.诞生代号 ≤ T_R ∧ ∃(a, c) ∈ anc(t_R): u.写者树 = a ∧ u.诞生代号 ≤ c
v*(R, k)      := Visible_R、key = k、归并之后的候选里写序最大者
Current_R(k)  := 若存在对 R 可见、指认 k、死亡写序 ≥ v*.写序 的墓碑记录 ⇒ 死；否则 v*
```
三步求值、类型 1 容器撕裂的因果同第三版。**派生量**：分配记录 = 各根 Current 的全部副本落点 ∪ 重建新写的索引落点 ∪ 固定结构；parity 列的落点不可重建（D2 未定项 12）；重建产物占新空间、晋升前只读。

### P4 垃圾清扫

**输入**：D3 已定项 7 的分配记录条目在落点释放时**不删**，改写成「已释放 + 释放代」——标志位放跨度段的余位（跨度段 2 字节第一版只用两个值），分配代那 8 字节不动、仍存完整 checkpoint 号；释放代写进代那一段；**条目留到该落点被重新分配时覆盖**（不点删：树按落点排序、代住 value，按代点删要扫全树，且点删所需的按代清单正是崩溃会丢的那份内存态）。条目数上界由此从「已分配落点数」变成「曾分配过的落点数」，仍以容量 / 16 KiB 为界；E74 / E97 按新口径重跑。它顺带把崩溃后 defer 队列内存态丢失那一格补上（分配器重启后照释放代判能不能复用）。
**准入（合取，全部来自运行时结构）**：条目标已释放 ∧ 释放代 ≤ 环里最旧根的 checkpoint_txg ∧ 头可读；孤儿（没有条目、也不在分配器在飞 overlay 里）：写序所属实例 < 当前实例 ∧ 按 P2 谓词未发布 ⇒ 清；当前实例的单元一律不碰。清扫水位只推进到「环里最旧根的 txg」。
清扫是与 D13 增量 scrub 不同的第二个 pass；水位只在整轮完成时推进；非 zoned 抹头，zoned 第一版不支持；`map_provenance = rebuilt` 未晋升期间禁止，晋升要级 2 见证者，今天不存在 ⇒ **扫描重建的产物今天永久只读；清扫、I-1.9、P5 的回收门在重建之后整套失效——C113 买到的是可读回，不是可续用。**
清扫水位与最近一次根销毁的代号是 D5 已定项 4 第 13 / 14 项，随每次发布重写（每次发布多两条记账写），取最大值，完备性理由「回收判定要它」。

## 五、对立臂的判决（重写）

**臂 B**：写序只上码 2 / 3；数据单元头不动；extent 树的叶改成码 3 打包记录单元；数据 extent 顺着重建出来的 extent 树到达。

**量出来的两个数**：
1. E104 `wseq_meta_only` 臂（数据单元只有诞生代号、容器带写序）：崩溃部分重放 / 连崩 / 回退各世界上**数据孤儿全部复活**（crash 6、crash_double 7、crash_clean 6、rollback 3、rollback_after_crash 6——与 `no_watermark` 在数据单元上逐格相同），同 txg 跨事务改同 key 歧义 4、复活 1；无崩溃无同 txg 多版的世界上 0。⇒ 臂 B 的残余不是第四轮反推腿估的「同 txg 那 2 个 key」，是**数据单元的整个第 (c) 类**：数据单元头里没有实例代号与事务号，实例表的上限对它们没有输入，任何一次崩溃或回退留下的数据孤儿在 extent 叶丢失时都判成已发布。
2. E105：extent 叶改码 3（记录 83 字节）单次更新与点查各 1.25×（1e8 条）/ 1.333×（1e6）/ 1.5×（1e4）字节，批量 1e6 上 1.44×（k = 10）到 1.78×（k = 1000）；三档节点头、窄记录（52 字节）逐格同一个数。

**判决：取臂 A（写序上全部三类）。** 两条腿都是量出来的：① 臂 B 让 extent 叶丢失时的数据重建退回 C113 定案前的处境（数据孤儿无判据），臂 A 不会；② 臂 B 把最热的树的每次更新贵 1.25–1.78×。D11 缓冲那一格两边都改了已定项 4 的源清单，不进判据；数据单元头 +10、墓碑 +10、I-6.2 数据类白名单加一项（写序与诞生代号同一类知情泄漏，登记进 C110 射程）是臂 A 的价钱，照实记。**bcachefs 不走 A 的已知差异**：它的数据 extent 头里没有逻辑 key。

**什么现象会推翻第五版**：第五轮给出一条 P3 判错的可达历史；D16 已定项 5 的上界口径用户不接受；E74 / E97 重跑后分配记录的条目数越过它们自己的判据。
