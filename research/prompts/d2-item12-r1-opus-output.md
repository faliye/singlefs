# D2 未定项 12 第一版提案：反推腿（云 B / opus）输出

**立场**：假设提案是错的，那我本该看到什么。全文的每一句「某条款说 X」都现查过原文，
文件名与行号写在句子里。做法是构造**可达的历史**——写哪些单元、宽度多少、落在哪块盘哪个槽、
第几次发布、崩在哪里——走完之后提案里某条规则给出错误答案或者判不出来。

**总判**：**第一版不该收。** 四条命中里有两条是形态错误（不是参数错）：
① 提案漏了**唯一一条已定条款直接管这一格**——`.claude/kb/decisions/02-RAID条带策略.md:250`

而 P1 条 d 引的 D9（加密）已定项 5 与 D3（空间分配）第 4 条正是「parity 对密文算」这条已定条款存在的理由。
另有两条可达历史让 P3 的清扫补丁分别走向**永久泄漏**与**静默清掉活 parity**。

P0 的方向（parity 格放不下自描述字节）**结论对、算术错、而且它给出的那条逃生口不可实现**；

## 二、攻 P0 的前提：「parity 必须逐字节覆盖成员的全部 S 字节」

### 2.1 我去查了「重建出来的那一格拿什么验证」

任务书给了两条可能推翻引理的路：**校验和只覆盖载荷**，或者**头可以由读者独立重算**。
两条我都查了，**两条都不成立**——引理的前提站得住，但站得住的理由**不是 P0 给的那个**。

**第一条路（校验和只覆盖载荷）——被三处已定条款堵死**：

- `.claude/kb/decisions/04-校验和位置.md:285` 逐字：「**单元恒 32768 字节，自描述头、声明长度、净荷、补齐全在这 32768 之内。**」
- `.claude/kb/invariants.md:106`（I-2.3 补齐字节为零且参与校验和）逐字：「校验和 / MAC 覆盖**整个单元含补齐**」
- `04-校验和位置.md:287-288` 逐字：「**被覆盖的那 32768 就是单元的全部**」

⇒ 父指针里那个校验和（`.claude/kb/decisions/19-块指针的结构与宽度预算.md:182`：位置条目 14 = 设备 ID 4 + 16 KiB 槽号 6 + **密文校验和 4**）
覆盖的是**含头的整单元**。要验一个重建出来的格，就得凑齐它全部 32768 字节，**头也在内**。

**第二条路（头可由读者独立重算）——被两个字段堵死**：

码 1 的头 105 字节（`18-块里携带什么信息.md:416-425`）逐字段过一遍，索引完好时读者手上有什么：

| 字段 | 宽 | 索引完好时读者算不算得出 |
|---|---|---|
| magic / 格式版本 / flags | 4 / 2 / 2 | 算得出（常量 + 类标签由指针上下文给，flag 位第一版恒 0） |
| 声明长度 | 2 | 算得出（extent key 带区间，D8 已定项 3） |
| 头校验和 | 32 | 头其余部分齐了就算得出 |
| 五元组 | 33 | 算得出——它就是读者走树走到这里用的那个逻辑身份 |
| 诞生代号 | 8 | 算得出：`18:445` 逐字「D5（快照 / 空间记账机制）kill 规则的输入正是**内联在指针里的 `ptr.birth`**」 |
| **写序（实例代号 4 + 事务号低 48 位）** | **10** | **算不出。**它记的是「写出它的那个事务」，指针里没有 |
| **载荷 CRC** | **4** | 从重建出来的载荷倒算得出，**但那样它就不再验证任何东西**（自己验自己） |

⇒ 引理的前提**成立**，理由是：**写序那 10 字节没有第二个落点**，
而少了它就凑不出整单元、对不上父指针那 4 字节密文校验和。
**P0 自己没给这个理由**——它给的是一段算术，而那段算术是错的。

### 2.2 P0 的算术错在哪：`w ≤ 2` 那个逃生口是空的

P0 写「`(w−1)·H ≤ H` 当且仅当 `w ≤ 2`」，这句话的字面含义是：**`w = 2` 时 parity 格放得下自描述头。**
**放不下。**

`.claude/kb/decisions/09-加密.md:506` 逐字：「parity 对**密文**算；**多副本必须字节相同，即同一份密文写 N 遍**，不是加密 N 次」。
`02-RAID条带策略.md:317` 逐字：「一个 32768 字节的单元不切开、不横跨多列；**位置条目每个副本一条**」。

⇒ `w = 2` 时那个所谓的 parity 格**就是第二份副本，必须与数据格逐字节相同**。
它的头是**数据单元的头**，不是 parity 的头。**没有任何 `w` 让 parity 格拥有自己的头。**

这不是挑字眼。P0 的算术把问题框成**容量**（「(w−1)·H 装不进 H」），
而真正的机制是**覆盖**（「parity 用掉的每一个字节，都是成员那一位置上再也重建不出来的字节」），
后者**根本不含 `w`**。框错的代价是可预见的：下一个人只要把成员表压小
（比如只存一个 8 字节条带号，40 → 8），就会认为 P0 的反对被回答了——
而覆盖那一侧一个字节都没改善。这正是 `.claude/singlefs-ai-sop/rules/kb-discipline.md`
第 5 条要拦的那种漂移：**判据换成定义句之后句子不通了，而没人看得出来。**

### 2.3 P0 给的逃生口（成员预留恒零区）不可实现

P0 说引理可以靠「成员单元预留一段值先验已知的 H 字节区（取恒零）」绕开。**这条路走不通，两处堵死：**

**堵点一（区在低位 ⇒ 与头撞车）**：`18-块里携带什么信息.md:380` 逐字：
「即每个块的**第 0 字节起是自描述头**，载荷紧随其后。」
恒零区若放在 `[0, H)`，那里已经是成员自己的头了，两者占同一段偏移，不可能同真。

**堵点二（区在高位 ⇒ 扫描器看不见 parity）**：把恒零区挪到尾部 `[S−H, S)`，
那么 parity 格的自述也必须落在尾部（parity 只能占成员恒零的那一段）。而
`18-块里携带什么信息.md:383-384` 逐字给了头必须在低位的判据：
「头必须落在扫描器能**预测**的位置上，而**块的起始是唯一不需要任何先验知识就能算出的位置**」；
`18:507-510`（已定项 9）定扫描器按池内最小单元大小步进，第一版 **16384**。
一个 32768 对齐的 parity 格，它的尾部在「落点 + 32256」——**不是 16384 的倍数，扫描器永远探不到**。

⇒ **parity 格不能自描述，这不是取舍，是三条已定条款的合取。**
P2 / P3 把它写成「显式记一条例外」，方向对；但它是**被逼出来的**，不是提案挑的。
提案该说的是「已定条款不留第二种可能」，而不是「我们选择记一条例外」。

### 2.4 真正杀死候选一的那条条款，P0 一个字没提

`18-块里携带什么信息.md:285-287`（D18 已定项 3「两条必须守住的线」）逐字：

> | 不许放 | 为什么 |
> | **物理落点 / 设备 ID** | D9（加密） 已定项 6 已定「物理位置一律不进 AAD」⇒ 放进块头就是一个**不被认证、可无声篡改**的字段。而物理地址的权威记录点按 D9（加密） 已定项 5 已定住在明文映射层 |

`02-RAID条带策略.md:250` 引用它时逐字读作「D18 已定项 3 的禁放清单也明令物理落点 / 设备 ID **不许进块头**」
——**仓自己的读法是「管所有块头」，不是只管码 1。**

⇒ **条带成员表是一张纯粹的「物理落点 + 设备 ID」表，它进不了任何单元的头。**
候选一（parity 单元的自描述头带条带成员表）死在这里，与 `w` 无关、与 H 无关、与恒零区无关。
**P0 那段算术是多余的**：它证的东西比这条已定条款弱，而且证错了。

**堵住的最小改动**：P0 整节删掉，换成两句——
（a）D18 已定项 3 禁物理落点进块头 ⇒ 成员表不能住任何头；
（b）D4 已定项 5 + I-2.3 + D19 已定项 4 ⇒ 重建出来的格要对父指针的整单元校验和，
而头里的写序 10 字节没有第二落点 ⇒ parity 必须覆盖成员全部 32768 字节 ⇒ parity 格自己不许占任何字节。

## 三、攻 Q2：分配器那一路

### 3.1 攻击 A：钉住这件事**没有落点**，而 P2 只答了释放那一侧

**历史**（4 盘 D0–D3，w = 4，格宽 32768 ⇒ 每格占两个 16 KiB 槽，位置条目记起始槽）：

1. **txg = 100**：发布条带 S1，四个成员 `(D0,槽200)=U_a`、`(D1,槽200)=U_b`、`(D2,槽200)=U_c`、`(D3,槽200)=P1`（parity）。
   按 P2 写四条条带记录，key 分别是这四个落点。
2. **txg = 140**：`U_a` 被 COW 覆写，旧格 `(D0,槽200)` 释放。分配器按 P1 条 a 查条带表得成员表，
   把整条 S1 钉住。**钉住这个状态写在哪里？**
   - `02-RAID条带策略.md:349-350` 只说它「计入**不可回收字节**统计量（D5 已定项 4 第 3 项）」，
     而 `.claude/kb/decisions/05-快照-空间记账机制.md:294` 那一行是**一个聚合统计量**，答不了单个落点；
   - `03-空间分配.md:203-206` 的分配记录条目 value = 「分配代或释放代 8 + 跨度段 2（**最高位借作已释放标志**）」，
     **没有任何一位表示「已释放但钉住」**。
   ⇒ 钉住只存在于内存，或者只存在于「去查条带表」这个动作里。
3. **txg = 141 … 140+K**：根环滚过 K 代，`(D0,槽200)` 的释放代 ≤ 根环最旧根的 checkpoint_txg。
4. **txg = 140+K+1**：分配器要一格。候选 `(D0,槽200)`。它按 `03-空间分配.md:201` 那条判：
   有条目 ∧ 已释放 ∧ 释放代够老 ∧ 不在在飞 overlay ⇒ **可分配**。
   **P2 没有在分配这一侧插入任何条带表查询**——P1 条 a 逐字只说「落点 → 成员表是查表」，
   触发点写的是「Q2 由分配器在**释放那一刻**问」。
5. `(D0,槽200)` 被复用写入 `U_x`（属于新条带 S2）。S1 的重建输入没了。
6. **D1 整盘失效** ⇒ `U_b` 丢失且重建不出来：XOR 要 `(D0,槽200)` 的原始字节，那里现在是 `U_x`。

**破的是哪句话**：`02-RAID条带策略.md:348` 逐字「**w ≥ 3 条带的成员被释放后，该格与整条带（含 parity）在修复完成前不得复用**」。
P2 买到了「释放时看得见兄弟」，**没买到「分配时判得出这一格被钉住」**——而后者才是那句话真正要拦的动作。

**这条历史的失败模式已经量过**：`research/results/e80-partial-stripe-2026-09-02.out` 的 `free_now` 臂，
uniform 负载五个种子逐行抄——
`seed=11 … loss_mean=11.1 loss_worst=26`、`seed=22 … loss_mean=13.0 loss_worst=32`、
`seed=33 … loss_mean=12.1 loss_worst=34`、`seed=44 … loss_mean=12.6 loss_worst=31`、
`seed=55 … loss_mean=9.8 loss_worst=24`（live=288）。
且 `.claude/kb/checks-owed.md:92`（C81）逐字「**盘坏之前无任何报错**」。

**堵住它的最小改动**（两条二选一，都要写进已定条款，P2 一条都没提）：
- (a) `03-空间分配.md:203-206` 那 2 字节跨度段里**再借一位「钉住」**（最高位已被已释放借走，次高位空着；
  第一版跨度值恒 1 或 2，位够），并把它写进 D3 已定项 1 的谓词。**零新增字节。**
  代价：分配记录是派生态（`21-权威态与派生态的分界.md:298-299`），这一位重建不出来 ⇒ 把矛盾推到 Q4，推不掉。
- (b) 分配准入加一条合取：「∧ 条带表[候选落点] 里没有活成员」。代价是**每次分配**多一次条带表点查
  加 w−1 次活性判定，而不是每次释放一次——这笔账 P1 条 a 的代价栏里没有。

### 3.2 攻击 B：条带表与条带的写落不落在同一次发布

P2 没写条带表挂在哪。两种可能都查过：

- **挂根下的 COW 树**（与分配记录同型，`03-空间分配.md:201` 逐字「分配记录是根下的 COW 树（D22 已定项 3），条目与根同一次发布」）
  ⇒ 记录与条带的写**原子**，崩在中间时两者一起不存在。**这一侧我构造不出崩溃窗口。**
- **不挂根下** ⇒ 它就不是任何已定的发布单位，直接撞 `.claude/rules/fs-design.md`「一个事务层，所有结构共用」。

⇒ **崩溃原子性这一路我没打中，挡住我的是 D22 已定项 3 + D3 已定项 7 那句「同一次发布里原子生效」。**
提案该做的是把「条带表是根下的 COW 树」明写出来（今天没写），而不是留白。

**但同一次发布这个性质本身造出另一条历史**（见第五节 P4 自举）：
条带表的容器**也是单元、也要落在条带里**，而它必须与它所描述的那批条带在**同一次发布**里写出
⇒ 分配器给它挑的落点，天然和它要记录的那批落点在同一个攒批窗口里。

### 3.3 攻击 C：P2 的载体让 Q2 在加密开启后**无密钥答不出来**——撞它自己的 P1 条 d

P1 条 d 逐字：「无密钥的一侧读得到（无密钥要能搬，修复与重建都是搬）」，出处写的是 D9 已定项 5 / D3 第 4 条。

- `09-加密.md:506` 逐字：「parity 对**密文**算；多副本必须字节相同，即同一份密文写 N 遍」。
  ⇒（这一步是我的推论，标明）无密钥的一侧**算得出 parity**，不需要明文——这正是「无密钥能搬」在条带上成立的物理前提。

- `09-加密.md:6-8` 逐字给了明文豁免的**完整清单**：「除超级块**与已定项 5 已定留明文的那一层**

两条都要动 D9 未定项 9 / C34（`09-加密.md:66`、`checks-owed.md:46`）——
而 P0 恰恰是**因为**这两格未定才否掉了候选二（反向索引带条带边）。
⇒ **P0 用「那层没定」否掉候选二，P2 却选了一个连 P1 条 d 都过不了的载体。**

## 四、攻 Q4：扫描重建那一格

### 4.1 先逐字读 C113 定案 P3 的择版本规则

`18-块里携带什么信息.md:650` 逐字（我只抄与这一格相关的那一段）：

> **扫描重建同时找到同一身份的多版容器时按 C113（扫描重建时多版单元的现行版本判定无输入） 定案的规则判（2026-09-05）**：
> 先按实例表的已发布谓词滤掉未发布的版本（定案 P2），再在对该根可见的候选里取**该类的择新键**最大者
> （定案 P3：码 1 取写序，码 3 取 (诞生代号, 实例代号, 事务号) 三元……），**两版可以同时属于不同的头**；
> 常规路径仍由 D3（空间分配） 已定项 1 的谓词判。

`.claude/kb/invariants.md:27`（I-1.8 归并后版本全序）逐字：
「码 1 / 3 的可读已发布单元按「类身份段全部字段含写序」**归并成组**之后，**同 key 的各组两两全序键不等**」。

⇒ **择版本的粒度是「同一身份的多版**容器**」。**
码 3 的身份是 (出生树 ID, 打包记录类型, 容器号, 容器出生代)（`18:144` 逐字）。

**而 P2 把权威事实放在「记录」这一级**（一条记录记一个成员落点）。
**两级错位**：容器级择新，记录级冲突。

### 4.2 我构造不出来的那一条，以及挡住我的那一步

我先试了最直接的：同一个落点的记录先住容器 C7、后随 btree 分裂搬到 C9，
让盘上同时留下 C7 的旧版（含旧记录）与 C9 的新版（含新记录）。
**构造不成。**挡住我的是：btree 把 key 从 C7 搬走必须**重写 C7**，
重写后的 C7 与旧版**同身份**，C113 定案 P3 按 (诞生代号, 实例代号, 事务号) 选新的那一版，
旧版被正确淘汰。合并那一路也堵着——`18:662` 逐字有「**3 退役记录**……容器合并时右半退役、重生时旧身份退役」。
⇒ **单头场景下这条攻不动，我明说攻不动。**

### 4.3 攻击 D：两个头各自 COW 之后，同一个**物理落点**得到两份都「现行」的成员表

这条走得通，而且它用的是仓自己登记在案的那个实例。
`.claude/kb/checks-owed.md:120`（C113）逐字：「**② 两个头共享 origin 的 inode 叶、各自 COW 之后同身份两版、同一个 key 装着不同对象**」。
C113 定案 P3 对它的答案是 `18:650` 逐字那句「**两版可以同时属于不同的头**」。

**对 inode 树，这个答案是对的**——一个 inode 在两个头里本来就可以是两个不同的对象。
**对条带表，这个答案是错的**：一个物理落点属于哪条条带，是**池级**事实，不是每头事实。

**历史**（origin 头 `H0`，从它克隆出的头 `H1`，共享条带表的一个叶容器 `C7`）：

1. **txg = 100**：`C7`（身份 = (出生树 T_s, 类型 5, 容器号 7, 出生代 100)）里有一条记录，
   key = `(D0,槽200)`，成员表 = `{(D0,200),(D1,200),(D2,200),(D3,200)=parity}`，条带诞生代 100。
2. **txg = 120**：从 `H0` 克隆出 `H1`。`C7` 成为分叉点那一版，两个头共享它。
3. **txg = 200**：`H0` 侧那条条带死透、整条回收（`02:351` 规则 2）；`(D0,槽200)` 释放、老化、被重新分配给新条带 `S_a`。
   `H0` COW `C7` ⇒ 新版 `C7'`（同身份、诞生代 200），记录改成 `(D0,槽200) → S_a`。
4. **txg = 260**：`H1` 从没写过这个 key，它的现行版本仍是 `C7`（诞生代 100）。
   **两版都可读、都已发布**（`18:672` 的已发布谓词：`i < i_now` 且无行 ⇒ 已发布）。
5. **索引全丢，扫描重建。** 扫描器找到 `C7`（诞生代 100）与 `C7'`（诞生代 200）。
   按 C113 定案 P3，两版**同身份**，择新键取 `C7'`；但那句「两版可以同时属于不同的头」明说**两版都要留下**——
   `C7` 是 `H1` 的现行版本。
6. 于是「`(D0,槽200)` 属于哪条条带」有两个都被判成现行的答案：`S_a`（H0 侧）与那条 txg=100 的老条带（H1 侧）。
   **而 H1 侧那个答案在 H1 里也是假的**：`H1` 根本不引用那条老条带的任何成员，那一格早已归 `S_a`。
   按 H1 那一版去钉住 `(D1,200)/(D2,200)/(D3,200)`，钉住的是一批和 H1 毫无关系、可能正在被 `S_a` 用着的格。

**破的是**：P1 条 b 逐字「载体本身是自描述单元，**扫描重建重造得出这张表**」。
重造得出容器，重造不出**唯一一张**表。
更根本的是**形态错误**：P2 把一个池级、非每头的物理事实，装进了一个**每头 COW**的容器里。

**最小改动**：条带表不许进任何头的 COW 树，必须由**根记录直接持有物理指针**——
这正是实例表被拿出容器索引的理由，`18:672` 逐字：
「四元组 (出生树 0, 类型 4, 容器号 = 片序号从 0 起, 出生代 0)……**不属于任何树、不进容器索引，由根记录直接持有物理指针**（D22 已定项 7）」。
代价照实写：根记录再加一条 59 字节指针（`.claude/kb/decisions/22-单元原子性怎么合成.md:394` 那一行同型），
186 → 245 字节；而且条带表的规模远大于实例表的一条链——按 P2「一条记录记一个成员落点」，
条目数 ≈ 活单元数 × w/(w−1)，做不成链，得是一棵树，于是「不进容器索引」这条要重新论证。

### 4.4 顺带：P2 的条带表**装的是一个重建不出来的事实**，而它长得像派生态

`21-权威态与派生态的分界.md:320` 逐字（D21 已定项 5 后果 2）：「派生态的**损坏必须是可检出的**。」
条带表说「`(D3,槽200)` 是这条条带的 parity」，而那一格按 P3 补丁 2 **没有头**
⇒ 盘上**没有第二个见证**能反驳这条记录。记录陈旧、错、或者被改了，检不出来。
⇒ 条带表既不满足派生态的可检出要求，又不在权威态清单里（`21:7` 逐字「权威态 = **单元 + 记账 + 根**」、
`21:299` 逐字「权威态仍是「单元 + 记账 + 根」三样，**不扩项**」——码 3 容器是单元，这一条勉强过）。
**提案没有回答它是哪一态。**这一格 P1 的四条判据里一条都没管。

## 五、攻 P4 的自举：一次单盘失效之后无论按什么顺序都解不开

P4 自陈「**存在成对互指的容器时不可解**」，并说「这一格量得出来」。
**真正的形态不是成对互指，是自指，而且它落在 w ≥ 3 的第一条条带上。**

**最小的具体摆放**（4 盘 `D0–D3`，池刚建好，条带表这棵树只有一个叶）：

1. 第一次攒批的写入量为 3 ⇒ `w = clamp(3+1, 2, 4) = 4`（`02-RAID条带策略.md:177` 逐字判据）。
2. 这一次发布要落盘的新单元恰好三个：`U1`、`U2`（码 1 数据单元，32768）与
   `C1`（码 3 条带表容器，32768，装这条条带的记录）。加上 parity 正好四格。
3. 按 P5 分桶（三格都是 32768，同一桶），分配器给出落点：
   `U1 → (D0,槽200)`、`U2 → (D1,槽200)`、`C1 → (D2,槽200)`、`P1(parity) → (D3,槽200)`。
4. `C1` 的内容 = 四条记录，key 分别是上面四个落点，成员表都是
   `{D0:200, D1:200, D2:200, D3:200(parity)}`。树只有一个叶 ⇒ 四条 key 全在 `C1` 里。
   **`C1` 描述的是它自己所在的那条条带。**
5. **`D2` 整盘失效** ⇒ `C1` 丢。要重建 `C1` 就要这条条带的 parity 落点 `(D3,槽200)`，
   **而这个事实只写在 `C1` 里**。
6. 唯一剩下的出路是扫描 `D3` 找「看起来像 parity」的 32 KiB 区域——
   **P3 补丁 2 明令 parity 不自描述**，它与一片未分配的、或已释放未清扫的旧密文
   在字节层面**无法区分**（`18:410` 那条 magic 探针 + 头校验和拒收的机制对它整个不适用）。
7. ⇒ **解不开。** 而且这不是罕见摆放：条带表的容器**必须**与它所记录的那批条带同一次发布写出（3.2），
   池小或树浅时它们必然进同一个攒批桶。**w ≥ 3 的第一条条带就撞上。**

P4 那句「条带里只要还有一个成员的记录活着就解得开」在这条历史上**为假**：
S1 的四条记录**全部**住在 S1 自己的一个成员里。

**P4 的备选补丁（条带记录容器恒走 `w = 2`）确实堵得住这一条**——两份镜像在两块不同盘，
单盘失效丢不掉两份。**但它是一条格式分支，而提案把它写成一句话，判据、测试入口、崩溃点重放都没给**：
`.claude/rules/fs-design.md` 的五条硬要求里，第 1 条要「切换判据必须显式、可计算、写下来」，
第 2 条要「每条分支必须能被测试**强制**进入」，第 3 条要「每条分支单独验，**包括崩溃点重放**」。
且 `w` 按 `02:177` 是**运行时按写入量算的**，给某一类单元开「恒 2」的例外等于往 D2 已定项 6 里插一个分支变量。

**最小改动**：把备选补丁升为定案正文的一部分，判据写成
「单元类 == 码 3 ∧ 打包记录类型 == 条带表 ⇒ `w` 恒 2」，配一个只供测试的强制开关；
并在 D2 已定项 6 里写明这是 `w` 计算式的一条显式例外。
代价：这张表占的空间翻倍（P4 已写），以及 D2 已定项 6 多一条永久分支。

## 六、攻 P3 的两处补丁

### 6.1 攻击 E：记录先死、格后死 ⇒ 补丁 1 的两支同时为假 ⇒ 永久泄漏

P3 补丁 1 把共有合取补成「头可读 **∨** 被某条条带记录指认为 parity 格」。
**这个补丁默认「记录活得比格久」，而实际顺序是反的。**

**历史**：

1. **txg = 100**：条带 S1 发布，parity 格 `P1` 在 `(D3,槽200)`；四条条带记录在容器 `C1`。
2. **txg = 200**：后台惰性重落（`02:351` 逐字「修复 = 后台把幸存者整批重落一条新条带，**旧条带整条回收**」）。
   S1 整条回收 ⇒ **四条条带记录被删**（`C1` COW 重写），四个落点进 defer 队列，释放代 = 200。
3. **txg = 200 + K**：释放代 ≤ 根环最旧根的 checkpoint_txg（`03-空间分配.md:201` 那条闸），清扫可以动这四格。
   - `U1 / U2 / U3` 的格：头可读 ✓、有条目 ✓、已释放 ✓、释放代够老 ✓ ⇒ 清扫掉。
   - **`P1` 的格**：头不可读 ✗（不自描述）、**没有任何条带记录指认它** ✗（记录在 txg=200 就删了）
     ⇒ **两支皆假 ⇒ 清扫拒绝 ⇒ 永久泄漏。**
4. 每一条走完惰性重落的 w ≥ 3 条带都留下一个这样的格。
   它们计不进 `05-快照-空间记账机制.md:294` 的「不可回收字节」（那个量记的是**钉住**，这些格已经不钉了），
   也不在任何统计量里 ⇒ **泄漏量不可观测**，撞 `.claude/rules/fs-design.md` 硬要求 4「分支必须可观测」。

**破的是**：P3 补丁 1 那句「今天它**永远清扫不掉**，是一个永久泄漏。补成『头可读 ∨ 被某条条带记录指认为 parity 格』」
——补丁只把泄漏从「记录还在时」搬到了「记录已删时」，**总量一格没少**。

### 6.2 攻击 F：反过来读补丁 ⇒ 静默清掉活着的 parity

补丁 1 若按「**没有记录指认它 ⇒ 可以清**」执行（这是把泄漏堵上的唯一读法），构造：

1. **txg = 100**：S1 发布并活着，parity `P1` 在 `(D3,槽200)`。
2. **txg = 150**：崩溃。恢复选了 txg = 100 的根（S1 在里面，全部成员活着），换新实例代号。
3. 条带表覆盖 `(D0,*)` 那段 key 的容器 `C5`，最后一次写出是在**崩溃丢掉的那个 checkpoint** 里
   ⇒ 它的诞生代 > `T_pub` ⇒ 按 `18:672` 的已发布谓词（码 3 ⇒ `b ≤ T_pub`）**判未发布** ⇒ 被 C113 定案 P2 滤掉。
4. 于是 `C5` 覆盖的那一段 key 里，**一条记录都读不到**——而它们指认的那批 parity 格**全都活着**。
5. 清扫按「没有记录指认 ⇒ 可清」把这批活 parity 抹了。
6. **设备全部在线**，`02-RAID条带策略.md:374` 的降级只读不触发；冗余度静默从 4 列掉到 3 列，
   直到下一次单盘失效才显形——**正是 E80 `free_now` 臂的失败模式：`.claude/kb/checks-owed.md:92` 逐字「盘坏之前无任何报错」。**

⇒ **补丁 1 的两个读法，一个永久泄漏、一个静默毁冗余，而提案没写清取哪个。**

### 6.3 攻击 G：孤儿那一支根本没被补（这是背景材料 1.1 那处删节的直接后果）

`03-空间分配.md:201` 逐字：「**孤儿（没有条目）要求头里的写序实例 < 当前实例 ∧ 按实例表的已发布谓词判未发布**」。

parity 格什么时候是孤儿？**扫描重建之后必然是。**
分配记录是派生态（`21:298`），重建源是「单元 + 记账 + 根」（`21:306`）；
而扫描侧的认领规则 `.claude/kb/checks-owed.md:100`（C89）逐字是
「解出一个**单元头**并认领后按声明长度跳过载荷，载荷内部探针不再参与认领」。
**parity 格没有头 ⇒ 扫描器认领不到 ⇒ 重建出来的分配记录里没有它的条目**
⇒ 它变成孤儿 ⇒ 走孤儿那一支 ⇒ 那一支要**读它头里的写序** ⇒ 读不到 ⇒ 判不出。

P3 补丁 1 只补了共有合取里的「头可读」，**孤儿支那句「头里的写序实例」一个字没动**。
⇒ **重建后的池里，每一个 parity 格都永久卡在「判不出」上**：既不能清、也不能确认它活着。

**堵住 6.1 / 6.2 / 6.3 的最小改动**（我能想到的最小的一个）：
把「我是 parity」这件事落在**与 parity 格同生共死**的地方，也就是分配记录条目本身——
跨度段（`03:205`）再借一位「parity 格」，清扫判据改成
「头可读 **∨**（有条目 ∧ 条目标着 parity 位）」，孤儿支加一句「没有条目的 32 KiB 对齐区域，
若被任何一条条带记录指认为 parity 则不许清，否则按未发布垃圾清」。
**这个改动只堵 6.1 与 6.3，堵不了 6.2**：分配记录是派生态，那一位重建不出来
——矛盾原样推回第四节。**我没有一个能同时堵住三条的最小改动，这一点明说。**

## 七、我认为更强的替代方案，以及它的代价

### 7.1 先说被逼出来的三条边界

把前六节的结论摆在一起，能落成员表的地方只剩一个：

| 边界 | 出处 |
|---|---|
| 成员表不能住任何单元的**头** | `18-块里携带什么信息.md:287`（物理落点 / 设备 ID 不许进块头） |
| 成员表不能只住**指针 / 索引** | `02-RAID条带策略.md:391`（C113 定案 P3 要求答扫描重建）+ `21:7`（索引是派生态） |
| 成员表不能住**密文** | `09-加密.md:506` + `03-空间分配.md:17`（无密钥要能搬、parity 对密文算就是为此）+ P2 自己的 P1 条 d |

⇒ 唯一剩下的落点：**一个明文的、单元载荷里的、池级的结构**。
`09-加密.md:8` 逐字已经给这类结构留好了豁免位——
「除超级块**与已定项 5 已定留明文的那一层**（**逻辑身份 → 物理地址映射 + 反向索引**）外全部加密」。

### 7.2 替代方案：条带成员表并进明文映射层，不新开一棵表

**主张**：条带成员表不做成新 keyspace，而是作为 D9 已定项 5 那层「逻辑身份 → 物理地址映射 + 明文反向索引」
的**一列**落地；载体是一个**明文载荷**的新打包记录类型（占一个 incompat 位，`18:662` 的默认档），
由**根记录直接持有指针**（与实例表同型，`18:672` / `22:394`），**不进任何头的容器索引**，
且这一类容器的 `w` 恒 2（P4 备选补丁升为定案，判据写死、配测试开关）。

四问怎么答：

| 问 | 答 | 代价 |
|---|---|---|
| **Q1** 兄弟与 parity 在哪 | 按落点点查明文映射层，O(树高) 次读，无密钥可做 | 读失败路径上多一次点查 |
| **Q2** 释放时钉住谁 | 同上；**外加**分配记录跨度段借一位「钉住」，把判定放在**分配准入**而不是释放（3.1 攻击 A 的 (a)） | 0 新增字节；D3 已定项 1 的谓词要改 |
| **Q3** 修复队列 | 第三格无戒律，按落点扫这层即可 | 无 |
| **Q4** 扫描重建 | 容器是明文头 + 明文载荷的单元，扫描器认领得到、无密钥读得到；一条条带的成员表在 w 条记录里冗余 w 份，且分配器按 D2 已定项 8 的组纪律把这 w 条记录的容器强制分到不同失败域 | 见下面代价 (c)(d) |

**它比 P2 强在哪（三条，都能指到条款）**：
1. **过得了 P1 条 d**——明文豁免是 `09-加密.md:8` 已经写下的，不需要新论证。P2 过不了。
2. **不是「第二个权威结构」的新实例**——它并进 D9 已定项 5 已经定为「物理地址权威记录点」的那一层
   （`09-加密.md:77` 逐字），而不是在它旁边再立一张落点→设备表，
   后者正是 `02-RAID条带策略.md:250` 判过的那个东西。
3. **不是每头 COW**——根记录直接持有，第四节攻击 D 的历史走不通。

### 7.3 代价，照实写

| # | 代价 |
|---|---|
| (a) | **它把未定项 12 变成阻塞项**：要先定 D9 未定项 9（明文映射层带哪些字段）与 C34（明文映射层的态别三处打架，`checks-owed.md:46`）。**这一格今天定不了，这是这条方案最大的代价，我不掩饰。** |
| (b) | **泄漏面**：全部物理几何明文。D9 已定项 5 已经为「无密钥要能搬」付过这笔（`09-加密.md:77`），本项不新增类别，但把量放大了 |
| (c) | **空间**：一条记录 56 字节 × 约（活单元数 × w/(w−1)）。拿 `03-空间分配.md:211` 的口径外推（16 TiB / 90% 填充，分配记录 4.83 亿条目、约 20 字节条目、442 ppm）：56 字节条目约 **1240 ppm ≈ 0.124% 容量**，是分配记录树的近 3 倍。**这是外推，没跑过实验**，要立实验量 |
| (d) | 容器恒 `w = 2` ⇒ (c) 再翻倍，约 **0.25% 容量** |
| (e) | **一条永久格式分支**（新打包记录类型 + 恒 w=2）。按 `.claude/rules/fs-design.md` 的格式分支判据，它买得到「用错了 ⇒ 挂不上」：新类型占一个 incompat 位（`18:591` 逐字「新增一类占一个 incompat 位」），不认识它的读者挂不上，不会静默按错布局解 ⇒ **判据过得了**。但 D15 的止损规则要跟着算 incompat 位预算 |
| (f) | **根记录 186 → 245 字节**（多一条 59 字节指针，`22:394` 同型），每次发布的 COW 量跟着涨 |

### 7.4 我不主张的那条，以及为什么

**不主张「位置条目加 10 字节直接带 parity 落点」**（14 → 24，指针 59 → 69，占盘按 `19:202` 的口径
从 0.180% 到约 0.21%）。理由不是空间，是 **Q4 直接失败**：位置条目住索引，
索引是派生态（`21:7`），扫描重建那一刻它正是丢掉的东西。
C113 定案 P3 就是为了拦这条路才加的那句话（`02-RAID条带策略.md:391`）。

## 八、另外三处，顺手记下

1. **P5 说的不是「全仓没写」，是「全仓写反了」。**
   P5 逐字「一条条带的全部格必须等宽（16384 或 32768）……今天全仓没写这一句」。
   实际上 `02-RAID条带策略.md:324`（D2 已定项 10 依据 2）逐字写着更强也更窄的一句：
   「**格 = 单元 = 32768 字节**」——它整个没有 16384 这一档。
   而 `18-块里携带什么信息.md:507-510`（D18 已定项 9）定了索引节点是 16384 且要落盘。
   ⇒ P5 该记成**对 D2 已定项 10 依据 2 的一处更正**，不是填空白。
   连带一格提案没提：分配器要跑**两个攒批桶**，于是 `02:177` 的
   `w = clamp(攒批后的写入量 + 1, 2, 4)` 里那个「写入量」变成**每桶**的量，D2 已定项 6 的输入口径要改。

2. **P2 的 incompat 账没记。** P0 给候选一记了「占一个 incompat 位」，P2 用打包记录类型 5
   却一个字没提，而 `18:662` 逐字「类型 3 / 4 按 D15（格式冻结政策）默认档 **incompat**」。同一笔账两套算法。

3. **P2 的记录里「自己是第几列 1」与「parity 格恒是成员表的最后一项」冗余**：
   成员表按列序排 + parity 恒最后 ⇒ 列号可由 key 在成员表里的位置推出。
   算术核过：`1 + 1 + 1 + 40 + 8 + 5 = 56` ✓。这条是小毛病，不影响判决。

## 九、判决

**第一版不该收。** 按提案自己的判据栏逐条判：

| 判据 | 判 | 打中它的那一节 |
|---|---|---|
| P1 条 a（不遍历、代价不随容量走） | **不成立** | 三 1（钉住在分配侧无落点，Q2 只答了一半） |
| P1 条 b（扫描重建重造得出这张表） | **不成立** | 四 3（两头各自 COW 出两份都现行的成员表）、五（自举，第一条 w≥3 条带即撞） |
| P1 条 c（不改已定条款的字节） | **不成立** | 一 3（撞 D2 已定项 8 的第二权威结构判决）、六（清扫准入的孤儿支要改） |
| P1 条 d（无密钥读得到） | **不成立** | 三 3（码 3 载荷是密文，撞 D9 已定项 5 / D3 第 4 条） |
| P0 引理 | **结论对、算术错、逃生口不可实现** | 二 |
| P3 两处补丁 | **两个读法一个泄漏一个毁冗余** | 六 |
| P6（第一版零字节） | **成立**，但漏了 incompat 位预算与未定项 12 自带的骑手「w ≥ 3 的第一条条带发出之前必须定」 | 八 2 |

**该往哪走**：先答 D9 未定项 9 / C34，让明文映射层有字段表与态别；
未定项 12 挂在它后面收口。**在那之前这一格定不了**——
今天定的任何版本，要么读不了（密文）、要么重建不出（每头 COW）、要么在第一条 w ≥ 3 条带上自指死锁。

**我构造不出来、明说的两处**：
- **崩溃窗口**（3.2）：条带表若挂根下 COW 树，记录与条带同一次发布原子生效，我打不进去。挡我的是 `03-空间分配.md:201` + D22 已定项 3。
- **单头下的记录级择版本冲突**（4.2）：btree 搬 key 必须重写来源容器，同身份 ⇒ C113 定案 P3 正确淘汰旧版。挡我的是 btree 的重写语义与 `18:662` 的退役记录。
  攻击 D 走的是**跨头**那一路，不是这一路。
