崩溃语义（串行提交、不带故障的崩溃状态）：

1. **fsync**：fsync 返回成功之后，这次 fsync 等到的那次发布带走的全部操作必须在（串行下就是调用开始之前已取号成功的全部操作，按单元计）；按状态下标读，即允许集合的下界 lo 抬到那次发布的末尾。fsync 报错时不抬 lo，报错那次发布带的操作可在可不在；之后的操作接在下一次恢复读出的状态上判。
2. **丢法：按发布边界的前缀**。崩溃落在第 hi 个操作里时，恢复允许读出的是 {S_j : j = lo，或 j 恰是某次显式发布的末尾；lo ≤ j ≤ hi}，S_j 是上一次恢复之后前 j 个操作施加出来的状态，S_0 是上一次恢复读出的内容。丢掉任意子集的那种丢法在串行提交下出局（与 D16（发布语义） 已定项 12 不相容），开并行提交时重开。
3. **抬 lo**：返回成功的发布调用、fsync、回退都抬 lo（D16（发布语义） 已定项 7：回退与 fsync 同一个返回条件）；回退算一次已确认发布，它的下标算发布末尾。
4. **回退**：回退是 RefFS 的一个操作，回退之后的内容等于整段历史里第 m 次已确认发布之后的内容；m 由调用方从实现报的回退根翻出来交入，RefFS 不判目标选得对不对。m 的编号覆盖每一个写根的入口（发布调用、回退、写行与暖机、抬 F、卸载），映到写它时的现行版本，现行版本含每次恢复读出、重新起头的那一份。
5. **崩溃时刻的归属**：崩溃落在第几个操作里，按「切开当前段的那道屏障由哪一步发出」归属，不按第一个被扣下的写；这条只给 RefFS 用，O1（内存模型对拍（HashMap 理想文件系统）） 的崩溃判官不动。
6. **恢复之后**：每次恢复之后，RefFS 先判读出的状态在允许集合里，再以它为起点接着走。

**射程**：只定做到什么程度与 RefFS 的形态，不定排期；不许读成「先做 RefFS 再做实现」——RefFS 是验证手段不是里程碑（`.claude/rules/format-evolution.md`「从写开始，不从读开始」）。显式发布点只取历史里的发布调用与 fsync：自动触发的攒批落地之前 RefFS 只接显式发布点，自动触发的发布不在 RefFS 射程，归已定项 1 的 M2 与记录核对器；崩溃恢复抛弃最新根的那一次，RefFS 以读出内容重新起头、不判那一步。带故障的崩溃状态（说谎的设备、丢整块盘 C519（丢一整块盘时恢复丢掉刚确认的那一版））不适用。独立性：RefFS 不读录制流、不调切段与状态计划，但它的 (lo, hi) 与 O1（内存模型对拍（HashMap 理想文件系统）） 崩溃判官盘级下界那一条判据的入参输入同源，记在 C191（同源性计数器只盖了一对） 那一类同源账上。D17（实现分层与第三方管道） 已定项 4 据此把「入口」的可执行定义交给 RefFS 的操作面，fsync 的持久性承诺由 RefFS 的崩溃语义定义；O3（独立规约执行器） 仍是崩溃点集合的独立执行器，职责不变。RefFS 的第一版在 `crates/singlefs-reference-filesystem`，崩溃注入两截与故障注入重开的调用点已接：验证包经翻译层 `crates/singlefs-verification/src/reference_filesystem_translation.rs` 依赖它，调用点判 RefFS 与 O1（内存模型对拍（HashMap 理想文件系统）） 崩溃判官两票、任一红即红。

#### 已定项 8：自研的两样：Merkle 根链差分与代际增量 scrub

**定案**：现成工具没有、本工程自研的两样：

**1. Merkle 根链差分 —— COW + 每事务发新根独有的杠杆。**

它能检出常规遍历式 checker 检不出的一类错误：**同步篡改后自洽的原地写**——

1. **计算放在哪**：默认 CPU。挂载参数 `background_compute`（取 `cpu` 或 `gpu`，默认 `cpu`；命令行有了之后写成 `--background-compute=gpu`）选 GPU。这一组挂载参数（第 1、2、3 条）只有一份，管全部后台任务，不按任务分设：开了 `gpu`，凡有 GPU 路径的后台任务（GC 搬迁、打包搬迁，以后接上 GPU 路径的别的后台任务）都走 GPU，没有 GPU 路径的照旧在 CPU 上算。它只活在内存里：不写进系统配置、不占 feature bit（D24（后台重活能不能卸给 GPU） 已定项 2 第 1 条），每次挂载各给各的。挂着的时候可以经已挂载会话的控制接口切换（一次切全部后台任务），从下一批开始生效；一批之内不换（`.claude/rules/fs-design.md`「分支变量不许在操作中途改变」）。GC 搬迁放上 GPU 的是三段：扫描里的校验和核对、区域扫描里的单元头解析与映射反查、选段打分；整理发布那一半照旧在 CPU 上。开了 `gpu` 就照开着跑，不按哪张卡、哪种提交间隔赚不赚自动切回 CPU；赔的卡与提交间隔写进文档与第 7 条的对照组。
2. **用哪几张卡**：挂载参数 `background_gpu_devices` 是一张卡的列表（可以点几张），点名了就只用点名的卡；不给就用本机全部独立显卡，集成显卡、虚拟显卡、软件 Vulkan 适配器与认不出类型的适配器不算「显卡」、不进「全部」，点名它们照「点名的卡不存在」拒（第 4 条）。参与的卡都用，按卡的顺序填满：点名的按点名次序，没点名的按 PCI 地址次序，先把前面的卡填到它的上限，活多了才用后面的卡，不要求每张卡都有活；按第 7 条量出来赔的卡照用；挂载时量的代价可以算，不报、不记进性能，也不再用来分活。挂载时只开参与的卡（点名了是点名的那几张，没点名是本机全部独立显卡），不参与的卡不开；挂着时切换点到还没开的卡，那一刻再开那张卡（开法与开不成的处理在第 4 条）；切换之后不再参与的卡，切换生效时关掉；从 gpu 切到 cpu 算全部卡都不再参与，切换生效时关掉全部开着的卡、丢掉还在开的那一组，之后切回 gpu 当成点到没开的卡，照第 4 条的重开规矩开，开卡期间在 CPU 上算。
3. **显存上限**：挂载参数 `background_gpu_memory_limit` 是一个带单位的字节数列表，按次序一张卡一个，与参与的卡逐个对应（给了 `background_gpu_devices` 就对它的列表，没给就对第 2 条那份全部独立显卡的列表），不补齐：`background_gpu_devices` 点了三张卡，`background_gpu_memory_limit` 要么不给、要么正好给三个数，只给一个也报错；GPU 模式下全部后台任务在那张卡上合占的显存不超过它的那一个数：这个数是上限、不是预留，用得比它少没有关系（卡上此刻空闲的不到这个数也照常跑，只用空闲的那些），任何时刻都不许比它多，缓冲、暂存区一起算在里面。不给就不设上限，后台任务跑的时候卡上能用多少用多少。装不下不拒绝：一批（连同缓冲、暂存区）在上限里装不下，就按上限自适应切成几片、缩小逐次交，挂着时单条装不下也切；挂载那一刻量代价（第 2 条）的那一段同样切片，代价取各片之和。参与的卡的上限连最小的一片都装不下，这张卡就不用（第 2 条「参与的卡都用」的例外）：照开设备、不分活、报出来，挂载不因此拒绝；挂着切换给了它装得下的上限，从下一批起照新上限按卡的顺序重新参与分活。请回来的这张卡照新上限量一次提交的代价（量之前先在这一组给的等的上限之内等账上还在跑的那次提交做完、放账；量出的代价照第 2 条不用来分活）；等不到或量不成，这张卡不参与，之后每一批都报成这张卡的 GPU 出错（`CostNotMeasuredAtTheSwitch`），直到下一次换设置。参与的卡因此一张都不剩时挂载照样不拒，后台任务照第 4 条进出错停着。
4. **配错时拒；GPU 用不上时重交、报警、停下，GC 按占用在 CPU 上补跑**：挂载或切换那一刻，`background_gpu_memory_limit` 给了而个数与参与的卡数不等、某一个数超过那张卡的显存总量、GPU 不在、驱动不对、点名的卡不存在，或 `background_gc_cpu_compensation_threshold` 超过 100（选 `cpu` 时也判），就拒绝挂载（或拒绝切换）并报错。挂载那一刻参与的卡开不成，或挂着时切换点到的卡开不成，都间隔 1 分钟重开，最多重开 3 次；头一次开卡不算重开，一张卡至多开 4 次、报 4 个原因。起不了开卡线程、开卡线程 panic 都算这张卡这一次没开成，照重开。同一张卡前一次开卡没回来就不再起下一次，算这一次又没开成，照间隔往下数。记着哪几张卡上有没回来的开卡的那张表在进程级（开卡器持有），各次挂载与切换开卡共用，只把到点之后（开它的那一方不等了）还没回来的开卡记成没回来：前一次挂载里挂住的卡，之后的挂载同样不再起，出路只有重启进程。同一张卡上前一方还在它自己的期限之内开着时，后到的一方排队等它开完再开，排队本身不算一次开不成；等的时间算进后到那一方自己的开卡期限，等满了照它自己的到点办；排队期间前一方被记成没回来的，后到的当场不再排队、报前一次开卡没回来。挂着时切换点到还没开的卡：切换请求照收，在会话锁外开新卡；重开期间照旧用切换前那组卡，开成了，下一批起换成新设置；重开 3 次都不成，GC 停下，报警里报出哪张卡、每次开不成的原因，等人处理，不自动再试：核心层不把那一组记成生效，生效的照旧是切换之前那一组，有 GPU 路径的后台任务都按开不成那个错停下、报警（报的成员同切到参与的卡一张都不剩的设置，`GpuUnusableUnderTheSettingsHandedIn`），补跑阈值取那一次切换请求给的。同一张卡在一次挂载里切换开卡连着开不成满 4 次（跨切换接着数，中间开成一次就清零），之后再有切换点到它不再开，当场答开不成，原因是单独的一个成员（`OpeningsInThisMountUsedUp`），有 GPU 路径的后台任务照开不成停下、报警；要卸载重挂。试满在交设置那一刻与切换开卡线程开每一张卡之前各判一次，读同一个判据：线程里开到一张卡时它已一次不剩，就当场照试满答它开不成（`OpeningsInThisMountUsedUp`）、不开。叫停之后没开的那几次、同一张卡前一次开卡到点没回来而这一次没起的那几次，不记进连着开不成的次数（后一种不把这张卡判成试满，出路照旧只有重启进程）；起不了开卡线程那一回算头一张要开的卡开不成一次、记进它的次数。卸载时还在开的切换开卡取消，不再接着开。挂载那一刻参与的卡重开 3 次都不成，才拒绝挂载。挂着的时候一批等 GPU 超过挂载参数 `background_gpu_wait_limit`，在同一张卡上重交（只重交超时的那一片，同一批已做完的片留着），至多 3 次，都超时才报警、判那张卡用不了；重交只在挂着时的批里做，挂载那一刻量代价的提交超时不重交，算那张卡这一次没开成。挂载时开卡（含编管线）等的上限是 5 分钟，到点当那张卡这一次没开成：参与的卡（点名了是点名的那几张，没点名是本机全部独立显卡）都间隔 1 分钟重开、最多重开 3 次，都不成才拒绝挂载；参与的卡因第 3 条的显存上限连最小的一片都装不下而一张不剩时，挂载照样不拒、后台任务进出错停着（第 3 条）；挂载等开卡成功或到点才往下走，不做回调。挂着时超时重交与空闲显存不足说的「一批」，都是一段的一次调用：扫描里的校验和核对、区域扫描里的单元头解析与映射反查、选段打分三段各自计，不按整理的一批、也不按切出来的片。每段一次调用里同一张卡的超时跨片累计，交活之前先等前一次超时提交的那一等也算进去，累计到第 4 次等超过上限就报这张卡用不了（`GpuUnusableAfterResubmissions`）。建缓冲出错之后冲掉队列待写的那一次空提交等满上限还没做完，同样算这张卡一次等超过上限，不算一次重交（那一段没交到卡上）。卡上此刻空闲的显存连这一批最小的一片都装不下（给的上限之内建缓冲显存不足，一路切小到最小的一片都建不成）：这一批不给这张卡分活，它那份转给这一批别的参与的卡，不报警；参与的卡这一批全都装不下才报 `EveryParticipatingGpuShortOfFreeMemoryForTheSmallestPiece`，按挂着时 GPU 出错办，下一批照设置重新起。建缓冲显存不足、切小重切时，这一段在这张卡上已做完的片不留，照新的切法整段从头重交。挂着的时候 GPU 出错（含重交 3 次都超时），正在算的那一批放弃，意图也删掉（单发一次只删意图的发布，已定项 1 第 3 条），那个后台任务停下，并在停着期间每次后台整理被叫起都报警：「每次」指每次叫起，发布之后的查与定时兜底的查都算，补跑的与照旧停着的都报，显式的整理入口每一趟也算（入口在任何读写之前就拒的那一次不算），直到一次通过校验的切换解除停下。报警带哪个后台任务（`task`）、原来那一次的错（`error_that_stopped_the_task`）与它点名的卡（`gpu_devices_named_by_the_error`）、停下以来叫起了几次（`wakes_while_stopped`，停了多久数叫起的次数，不读挂钟；出错停下的那一趟不算，停下之后的下一次叫起是第 1 次，挂载那一刻就停着的头一次叫起是第 1 次，在叫起里停下与在可写挂载续做里停下数法相同）、停着期间在 CPU 上补跑了几批（`batches_compensated_on_the_cpu`）；通道是返回值里必须处理（`#[must_use]`）的报警，不是日志，调用方不处理编译就警告。卸载时不等还在跑的提交，有这种提交的那张卡整张泄漏、不析构。切换关卡时有提交还在跑的卡照卸载同一个规矩，整张泄漏、不析构，并报出来：切换关卡泄漏的卡按关的先后累计，连同卸载时泄漏的那一份，运行库读得到（挂着时 `MountedRuntime::gpus_leaked_by_the_background_gpu`，卸载之后 `UnmountedPool` 的同名字段，读的是同一份）。停着的时候收到任何一次通过校验的切换请求（校验同挂载那一刻），当场解除停下，从下一批起用新设置；出错之前已经收到、还没生效的切换请求（只指请求了、还没交给实现的那一次），在停下那一刻也算数，照它解除停下；已经交给实现、实现还在开卡的切换不算这一种：这期间照旧用切换前那组卡的一批出错，出错的后台任务停下、每次叫起报警，GC 照阈值在 CPU 上补跑；实现答新卡开成（换上了）那一刻解除停下，答开不成照开不成停着。答开不成算另一回停下：报警报的错换成开不成的那一个、点名开不成的那张新卡，停下以来叫起的次数与在 CPU 上补跑的批数都从头数；新的那一组仍点着刚出错的那张卡时，答换上了照样解除停下。挂着切换到参与的卡一张都不剩的设置（第 3 条）：下一次整理入口与后台入口照旧报停着，报的是挂载那一刻同一个成员（`GpuUnusableUnderTheSettingsHandedIn`）；停着时现行那一版有活意图的，显式入口与后台入口起跑一趟、只删意图，之后不写；后台入口那一趟吃发布预算，预算扣完就等下一次用户改动之后那一次调用再删；显式入口的预算至少 1（`crates/singlefs-core/src/compaction_plan.rs` 里的 `.max(1)`），停着时照删；现行那一版没有活意图的，一个写都不发，删除续做也不走。GC 报警停着之后在每一批开头判一次占用：任一块盘「已分配 ÷ 容量」超过挂载参数 `background_gc_cpu_compensation_threshold`（默认 85%，取整百分点 0 到 100，可调），这一批在 CPU 上补跑；都不超过就照旧停着，补跑途中降到不超过，下一批起照旧停着。占用逐盘算，和水位按盘算、空间准入逐盘判是同一种口径。补跑只管 GC，打包搬迁停着时不补跑。这两个参数与第 1 到 3 条那一组一起给、一起校验，挂着随切换请求一起换、从下一批起生效；不给阈值的切换沿用原阈值。各参数的取值、默认与代码落点在 [mount-parameters.md](../mount-parameters.md)。除了 GC 的补跑与第 8 条（连续几轮状态不确定的条目按条交 CPU 判，后台任务照旧在 GPU 上跑），停着的后台任务不换到 CPU 上接着跑。判一张卡用不了、要报警的那一刻，查一次这张卡的硬件与链路：照这张卡的 PCI 地址（适配器信息里的 `device_pci_bus_id`）读本机 sysfs 的 PCI 状态，读的是卡在不在总线上（`/sys/bus/pci/devices/` 下那个地址的目录在不在）、使能位（`enable`）、链路此刻与最大的速度和宽度（`current_link_speed`、`current_link_width`、`max_link_speed`、`max_link_width`）、AER（PCIe 高级错误报告）的三类出错计数（`aer_dev_correctable`、`aer_dev_fatal`、`aer_dev_nonfatal`）。这一刻有三种：挂着时一批在同一张卡上等超时、到判那张卡用不了；开卡重开用完都开不成；卡当场报出错（设备丢失、驱动报的未捕获的错）、后台任务因此停下。平常的批、每次超时重交之前不查。读数写进报警与观测，行为不变：GC 照旧停下等人处理，照旧按占用在 CPU 上补跑，前台的空间拒绝报不加字段。内核日志里的 Xid 与 `nvidia-smi` 不读。读不到的那一样（文件不存在、读不通）报「读不到」，不当成 0，也不当成正常。只有卡不在总线上（那个 PCI 地址的目录不在了，或使能位是关的）才判硬件坏；链路速度与宽度、出错计数只报不判。挂载那一刻开卡重开用完、拒绝挂载的，读数写进挂载的报错。停着之后每次叫起交回的报警带停下那一刻读的同一份读数，不重读；这张卡再一次被判用不了时才再读一次。切换时在卡上量代价出错、原因是卡当场报出错的，同样当场读一次，之后每一批带同一份。叫停了的开卡（卸载、切回 `cpu`）不读。挂载拒绝的报错文字里写出判定：卡不在总线上（目录不在或使能位关着），或没判成不在总线上。等卡回话的那一等里图形库 panic 的（等提交时驱动报设备丢失这一类），外壳在等的那一处接住，照卡当场报出错办：交回 `UncapturedErrorOrDeviceLost`、后台任务停下、报警、读一次 PCI 状态；那次提交留在这张卡的账上，之后每次等它都不再调图形库、当场报同一个错，这张卡不再交活，卸载与切换关卡时整张泄漏。
5. **什么时候起跑**：挂载就起、按周期查。每次发布之后按已定项 1 的三水位查一次；另有定时兜底，每隔一段时间再查一次，间隔是挂载参数，默认 30 秒。周期线程住在新开的运行库一层：挂载时按参数开卡、建实例、挂载、起周期线程，前台与后台经一把锁排队；核心层照旧不起线程、不读钟。后台整理的一批分三段：会话锁里取输入（问让路、排空待发、读一次后台计算设置、现行那一版只拷指针），锁外算（GPU 与 CPU 两条路径都走；选段循环每一圈要读盘上的一段时回会话锁里读那一段再放锁），回会话锁里发布。锁外那一段算完先放 GPU 实现那把锁再回会话锁。回锁里出错先于一切；不作废：先排空待发、重取隔离集，有活意图时比起点在 R 里的未释放记录的整条记录与集合相等，变了的单元从计划里剔掉，其余在现行那一版上发布，剔完一个不剩就不发；签发时对选中的段在现行那一版上重判资格与签发前那一判，各个量取现行那一版的；回锁那一次发布同样过回退候选集那道门；回锁时有冻结的发布就丢掉这一批、记单独的停因。会话上记有一批在锁外，这时再取输入被拒。定时兜底的预算照旧与用户改动共用同一份（第 6 条），挂载不再给新预算。一次整理发布要写的根槽连同它之后的余量里的根一走、根环里不同用户状态就少于 4 个时，这次整理发布不发（守 D16（发布语义） 已定项 1 的「回退候选集保留最近 4 个可退到的不同状态」）；余量取 S 槽，S 是每区根槽数（根环共 3S 槽）。只有全空聚簇段数低于底额（已定项 3）、前台已写不进时破例，每趟至少发 1 次；破例排在第 6 条的让路之前，前台有入口在等也照发（前台已写不进，让路换不来什么）。停着时那一次只删意图的发布（第 4 条）同样过这道门：门关就不发，意图与 `R` 排他留到门开；破例的条件（全空聚簇段数低于底额、前台已写不进）成立时，这一次也照发。删除队列不空也算起跑：这一趟只走队列、不发整理，不看水位，也不被发布预算挡。两种模式起跑规则相同。
6. **起跑之后的节奏**：GC 不在用户改动的调用线程里跑（不在用户改动返回之前跑一批），挪出之后三样照旧有保证：一趟发布预算有上限、签下一条意图那一判跨趟留着、整理批不插进用户改动的抬 F 与再判之间。签下一条意图那一判读的「上一条完成的意图」只留到下一次用户改动发成为止：每次用户改动发成就清掉它，下一趟从空起照常签新意图，预算照旧是这一次改动给的那一份；被拒、没发成的改动不清。GC 占盘写带宽有一个上限（挂载参数）；前台有任何入口在等会话锁（fsync、收下改动、单发改动、读、切换后台计算）时不发下一批，这一判别子要 GC 挪出调用线程之后才看得到；它只约束整理批（每一批取输入之前问调用方一次，回会话锁里发布那一刻不再问）；前台入口不断时有下限：连着让路 N 次或让路累计 T 毫秒，哪一个先到下一批就不让，一批发成两个都清零，N 与 T 是挂载参数；全空聚簇段数低于底额、前台已写不进时的破例批仍旧不让，整理开头先走的那一遍删除不是整理批，不受它约束。整理开头先走一遍删除（把盘上留着的删除意图做完）是可选的前置优化、为了效率，不是整理的一部分：删除与整理是两件事、各是各的事务，整理也可以不先删除；那一遍删除发的版不占整理一趟的发布预算。整理一批本身就是那次移动，整理判出的死空间由分配器的常规回收放掉、不交给删除；没删完的留到下一趟整理或下一次可写挂载，不因为它没删完挡住别的操作。 发布写失败冻结之后，前台 fsync 不在冻结时答成功：先重发那一次冻结的发布，发成了才答成功，没发成交回错误。重发成了照冻结那一次的种类记账：冻结的是用户改动，照一次用户改动发成办（重给预算、清掉上一条完成的意图）；冻结的是后台批，照后台批记。
7. **值不值按省下的 CPU 时间算**：GPU 模式的目的是少占主机 CPU 时间，数据量大时跑得更快只是副产物。收益是后台任务少占的主机 CPU 时间（CPU 模式下它的 CPU 时间减 GPU 模式下它的 CPU 时间，后者含准备数据、提交、等结果、两份结果的比对，以及第 8 条交 CPU 判的那几条），挂钟与 CPU 模式持平也做；D24（后台重活能不能卸给 GPU） 已定项 3 那条按挂钟比的判据不管这一项罩着的后台任务。实现之后跑一组对照：同一负载、同一池，CPU 模式与 GPU 模式各跑，报两边的 GC 挂钟、主机 CPU 时间、前台 fsync 延迟，并在几档盘容量上各跑一遍，看收益随容量怎么变。
8. **GPU 的结果怎么复核**：两份独立写的 GPU 核（不共用核函数）对同一批输入各算一次，逐条比两份的结果。两次相同的条目算确认，交 CPU：CPU 照发布路径逐条核计划与读盘核（`crates/singlefs-core/src/transaction.rs` 的 `relocation_checked_against_the_version`），再改位图，不另外抽样复核 GPU 的结果；两次不同的条目写明状态不确定，这一批不回收、不搬，留到下一轮重算。同一个条目连续 2 轮（N = 2）都不确定，交 CPU 那一份实现单独判一次，按 CPU 的判定处理；连续不确定的计数只放在内存里，重挂清零。「轮」按落点认条目：扫描里的校验和核对与区域扫描里的单元头解析与映射反查两段，一个条目是一个落点（盘、槽、跨度），选段打分一段，一个条目是一个聚簇段（盘、起点槽）；一个落点在一批里两份核的结果不同，它就不确定一轮，结果相同或已交 CPU 判过，它的计数清零；没出现在这一批里的落点，计数不动、也不清。一批放弃（GPU 出错、等超过上限）时，那一批里已经交回的段照算一轮，放弃的那一段计数不动。一批里同一个条目键出现两次（两份核比对之前整批查出），这一批作废，重复的那一段连续不确定的计数一条不动、也不交 CPU 那一份判；核心层收到一种不归哪张卡的出错（`SameEntryKeyTwiceInOneBatch`），后台任务不停、不报警，下一批照常算；那一批的意图照第 4 条一批出错放弃的规矩删（有活意图就单发一次只删意图的发布）。重复键在交卡之前就查，重复就这一段一片都不交给卡，所以同一批里卡出错与重复键不会同时出现；同一批里别的段已交回的照算一轮。重复键每一批都出现时照旧不停、不报警，也不在 CPU 上补跑。每一批报确认、不确定、交 CPU 判的条目各多少，运行时看得出来。只有一张卡时两份核都在这张卡上跑，有几张卡时按第 2 条分活、两份核可以分开跑；不许要求多张卡，一张与几张都要能跑、判定相同。
