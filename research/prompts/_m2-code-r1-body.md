## 三、判据（跑前写死；每条写「什么观测会让它触发」）

| 判据 | 问 | 触发的观测 |
|---|---|---|
| X1 释放的口径 | S1 的「释放」是不是 D3（空间分配） 已定项 7 说的那一刻（放进 defer 队列 = 没有任何根引用它）——A 的根还在环里、还引用着这八个单元；F 不动时分配器会不会把已释放的槽发出去；`release` 假定两盘同槽、`placements` 按种类推跨度 | 一段历史让已释放的槽被重新发出，或该释放的没释放 |
| X2 记账口径 | S2 与 D28（挂载期承诺量） 已定项 1 的式子「容量 − 已分配 − defer 待释放」谁对；checker 甲的并集与分配器的「占着」什么时候会不同（复用之后、回退之后、A 的根被轮转覆写之后） | 一个状态让 I-3.1（已分配统计对得上） 或 I-5.2（空闲统计对得上） 红，或式子把 defer 扣两次 |
| X3 恢复的放开 | S6 放开的两条会不会放进本该拒的镜像（带已释放标志但代晚于根；记录数是盘数整数倍但两盘条数不等）；「映射条目数恒 6」压在什么上 | 一个走读本该拒却过了的镜像 |
| X4 层 0 oracle | S7 有没有假阴性：B 的记录持久、根没持久、某个单元两份都没持久时，走读退回 A 读第一次内容、oracle 判绿——对不对；`newest_persisted_root_txg` 只数根槽写，暖机根与 A 的根总在前缀里；`root_persisted_states` 只数 B 的根 | 一个状态该判违例而代码判绿 |
| X5 对照够不够 | 五组靶向对照与四处变异漏了哪一格：释放代写错、映射条目没删、树表诞生 txg 改了、超级块世代号、反向链 | 一条改坏了没有任何断言红的变异 |
| X6 接缝 | `BirthSequenceAllocator` 每次发布重建（出生序号从 0 起）、`FIRST_INODE_NUMBER` 写死、`walk_to_file` 只找 inode 1、`TransactionOutput::placements` 按种类推跨度：哪些第一版可以，哪些在给后面几步埋坑 | 一条与已定条款冲突的写死 |
| X7 里程碑写回 | `02-second-txn.md` 步 1 / 步 2 的「现状」两段与代码对不对得上 | 一句现状与代码不符 |
