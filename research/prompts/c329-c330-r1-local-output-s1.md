1. C329-A closes F6 because it ensures rows publish occurs before any other publish (including F-raising), preventing the old instance from lacking rows. C330-A closes F7 by setting rows for intermediate instances to (i,0,0), making units with birth checkpoint >0 unpublished. However, a reachable state where an unreferenced unit still counts as published exists: if a unit has birth checkpoint b=3 and row (i, T_pub=5, W=10), it is published due to b<=T_pub even if unreferenced. Other failures like rollback or multiple F-raising publishes do not create new published unreferenced units under these fixes, but the published predicate itself can still mark referenced units as published if conditions are met.

2. C330-A can mark a referenced unit as unpublished: if a unit is referenced by the chosen root but has birth checkpoint b>0 and row (i,0,0), b>0 means it is unpublished despite being referenced. Instances between chosen root and new instance can reference units (e.g., data from prior instances in the root). C329-C misjudges clean ends: if a clean end writes a row but crashes before completion, no row exists, causing referenced units to be unpublished due to no-row branch. Instance switches and skipped codes may also be misjudged if rows are missing.

3. C329-A requires no format change as it is a behavioral rule. If switch reserve is short, the mount cannot pay for rows publish, violating admission rules. C330-B needs 8 bytes in superblock for highest checkpoint. C330-C needs 8 bytes per unit header for the new field.

4. Failing checks: For C329-A, verify rows publish is first in replay logs. For C330-A, check intermediate instance rows are (i,0,0). For C330-B, confirm new instance uses superblock max+1. For C330-C, validate unit headers contain the new field and predicate uses it. C329-C has no reliable check because clean end row writing is prone to crash-induced inconsistency, making it impossible to verify row presence reliably.

5. C329-A contradicts admission rule when switch reserve is insufficient for rows publish, as admission requires F-raising publishes for space short but C329-A blocks them before rows. C330-B does not contradict rules as it ensures checkpoint uniqueness. C330-C does not contradict rules. C329-C does not contradict rollback rule but may conflict with published predicate requirements.

6. Recommend C329-A for C329 and C330-C for C330. A single observation that would change my mind: if switch reserve is consistently too small for C329-A to function reliably, or if the 8-byte overhead in C330-C causes unacceptable performance or storage costs.
