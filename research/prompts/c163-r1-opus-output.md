## 二、矛盾成不成立

**成立。** 三步各自走完：

### 正推

1. 取号规则（`18-块里携带什么信息.md:733`）：码 3 的事务号 = 那次 checkpoint 里已分配的最大事务号。
2. 取号时刻（`16-发布语义.md:173`）：触发之后不再分配事务进这个 checkpoint。
3. ⇒ 一个 checkpoint 内该值恒定，与固定点跑几轮无关。
4. I-1.8（`invariants.md:27`）把它放在末位，唯一职责是「同一 checkpoint 内的平局破除」。
5. ⇒ 在它**唯一被加进去的那一格**里，它是常量，判别力恒 0。

**唯一可达的事件序列**（下面这条是能构造出来的那条；别的路径见第五节「构造不出来的」）：

| 时刻 | 事件 | 盘上状态 |

| T0 | checkpoint C（`txg = T`、实例 `i`）攒批结束，最大已分配事务号 = `n`（`16-发布语义.md:173`：触发之后不再分配事务进它） | — |

### 反推

假如矛盾不成立，我该看到什么？——该看到某条已定条款说「固定点每一轮各自分配一个新事务号」或「码 3 的写序取轮序」。

### 校验（换一条不共用取号规则的独立路子）

不看取号规则，只问「同一容器在一个 checkpoint 里会不会写两次」。三条已定条款说**不会**：

- `.claude/kb/decisions/16-发布语义.md:106`：`6. **发布计数器：每次发布 checkpoint_txg + 1，fsync 触发的也是发布；同一个计数就是根槽轮转键、记账的代、重放水位。** **状态：已定。**`
- `.claude/kb/decisions/18-块里携带什么信息.md:747`：`**容器的 COW 重写与索引**：开放容器在它所属代际内每次要发布时被重写，新单元、新诞生代号、身份不变。`
- `.claude/kb/decisions/18-块里携带什么信息.md:751`：`容器每次发布重写一次，这一格的重量比数据 extent 大得多（1000 文件 / 100 次 fsync ⇒ 一个身份 100 个物理版本）。`

⇒ 一次发布 = `checkpoint_txg` 加一 = 一次容器重写 = **一个新诞生代号**。100 次 fsync ⇒ 100 个物理版本，也就是**一个 checkpoint 一版**。

**这三条与 I-1.8 括号里那句「固定点会迭代，同一容器在一个 checkpoint 里不保证只写一次」直接互斥。**

两条路子给出同一结论的两种形态：要么末位那一维**无判别力**（取号规则那条路），要么它要破的那个平局**本来就不存在**（重写规则那条路）。**两条路都不给三元键留位置。**

⚠️ 校验路子会不会红：会。把 `16-发布语义.md:106` 换成「同一 checkpoint 内可以多次发布、txg 不变」，第二条路子立刻给出相反结论。两条路不共用取号规则这个输入。

## 三、最重的一条命中：装三元键的那次判决，三条依据逐条断得掉

第九版 P3（`_c113-r9-final.md:78`）给三元键的依据只有三条。逐条打：

### 腿 1：「那句话仓里没有可判红的形态」——**假**

第八版的依据是「一个实例在一个 checkpoint 只有一个固定点」。第九版说它没有可判红的形态，所以依据不牢。

**I-1.8 自己就是那个可判红的形态。** 把码 3 的键取二元，「同 key 的各组两两全序键不等」就是一条**对镜像可判定**的检查：出现同 `(b, i)`、不同载荷校验和的两组，当场红。这正是不变量清单存在的意义（`invariants.md` 开头：「每条不变量必须写成**可判定**的形式——能对着一个镜像回答『成立 / 不成立』」）。

而且 C163 自己写的检查装置就是这个形状，`.claude/kb/checks-owed.md:171`「怎么拦」那一列逐字：

> `造一个「同一 checkpoint 的固定点两轮各写出一版同身份码 3 容器」的镜像，断言 I-1.8（归并后版本全序） 的全序键分得开它们；按现行取号规则必须红。判别力自证：把取号规则改成固定点轮序，检查必须由红转绿`

把键换成二元，这条检查照样红，判别力自证照样成立——**只是判别力自证那一句要改成「把容器改成一 checkpoint 写两版，检查必须由绿转红」**。

⇒ 第九版把「这句前提没有被**单独**写成一条检查」当成了「它**没法**被检查」。两件事不是一件事。

### 腿 2：「失败表自己又写着固定点会『收敛不了』（即会迭代）」——**推理错**

失败表里「一次固定点没收敛」走的是**实例切换**那一支。`_c113-r9-final.md:44`（P1「两支的判别子改成当下判得出的量」）；切换做什么，`23-journal的角色与格式.md:674` 逐字：

> `取新实例代号、写行 (旧实例, 最后发布的 txg, 最后施加的事务号)、重发在飞 checkpoint……**固定点单元全部按新实例重写**`

⇒ 这一路产生的两版，差在**实例代号**上，是二元键**第 2 位**就分得开的。第九版引来支持**第 3 位**的那个故障，恰好由第 2 位处理掉。这条腿一点重量都没有。

（顺带：`_c113-r9-final.md:78` 那句「失败表自己又写着固定点会『收敛不了』（即会迭代）」还把两件事并了——「收敛不了」是**失败**，「会迭代」是**正常**。E81 的正常态是 2 轮，见 `.claude/kb/experiments/81-提交的固定点.md` 实测表。用失败态去论证正常态需要平局破除器，中间那步没写。）

### 腿 3：「与 E104 跑的那个键是同一个」——**方向反了**

`research/e7-index-bench/src/bin/e104_current_version.rs:1128-1131` 整段抄：

```
        // 第八版 P3：择新键按单元类分——码 1 取写序；码 3 只在 checkpoint 的固定点写出，
        // 写序的事务号是 checkpoint 的属性、给不出全序，键取 (诞生代号, 实例代号)。
        // ⚠️ 模型按事务写容器（真实形态是固定点一次），同一 checkpoint 里同身份能出现多版 ⇒ 键末尾补一个写序当平局破除器，
        // **那一维是模型的补丁不是规则的一部分**：规则的前提「一个实例在一个 checkpoint 只有一个固定点」模型不满足。
```

第八版 P8 逐字同调（`_c113-r8-final.md:89`）：

> `模型按事务写容器（真实形态是固定点一次），码 3 的择新键末尾补了一个写序当平局破除器，**那一维是模型的补丁不是规则的一部分**。`

**这段注释今天还在源码里，第九版没有改它。** 也就是说：模型自陈「第 3 维是我的补丁、不是规则」，第九版把它提升成了规则，理由是「跟模型对得上」。

这正是 `.claude/singlefs-ai-sop/rules/evidence-discipline.md`「不许先有结论再建模型」那条的镜像形态：**先有模型，再把规则改成模型**。而且模型那一维的存在理由（`:395-396` 逐字「模型按事务写容器」）恰恰是**规则说不存在的那个形态**。

### 三条腿合起来

三元键今天靠的是：一条被误当作不可检查的可检查前提（腿 1）、一次把实例维错当事务维的推理（腿 2）、一次把模型补丁提升成规则的对齐（腿 3）。**三条都断，三元键在仓里没有剩下的支撑。**

⚠️ 这不等于二元键就对。二元键要成立，欠的是把「一个 checkpoint 一次固定点、一个容器一版」**写成一条会红的检查**——而那条检查有两半，一半（镜像侧）就是 I-1.8 二元版，另一半（实现侧）是 C83 仍欠的固定点轮数读数，且**它的上界今天没有口径**（见第四节臂 C 第 4 点）。

## 四、四条臂各一个出错的世界

### 臂 A（事务号改成固定点轮序）

**出错的世界**：某次发布固定点跑到第 3 轮，容器 K 在第 2 轮与第 3 轮各写一版；崩溃发生在第 3 轮那版的写请求发出之后、根槽写成之前 ⇒ 走实例切换，`23-journal的角色与格式.md:674` 逐字「固定点单元全部按新实例重写」。新实例把 K 重写一遍，而它自己的固定点收敛在**第 1 轮**（脏集小了）⇒ K 的新版轮序 = 1。此时盘上三版：`(T, i, 2)`、`(T, i, 3)`、`(T, i+1, 1)`。二元 / 三元都按 `(b, 实例代号)` 打头 ⇒ 取 `i+1` 那版，对。**没有错**——臂 A 在这一格站得住。

真正的代价在别处，两笔：

1. **审计与被审计共用同一个数**。C83 仍欠的那条读数逐字（`03-空间分配.md:183-185`）：「**提交路径记「本次发布的固定点收敛轮数」，超过声明上界判红**」。轮序一旦成为格式字段，checker 读的轮数与运行时记的轮数就是**同一个数**，撞 `.claude/rules/fs-design.md`「记账是事务的副产品」第二格逐字「若运行时也用遍历算，checker 的遍历与运行时就是**同一次计算**，对照关系当场归零」。
2. **改第一个事务的字节**。要改的是 D18 已定项 11 的字段表（`18-块里携带什么信息.md:733`），而 `.claude/kb/first-txn-layout.md:88` 逐字把码 3 的类身份段列进第一个事务写出的字节。材料把臂 A 写成「Zero new bytes」——字节数不变，但**含义变**，按 `.claude/kb/decisions/15-格式冻结政策.md` 判定表「改变已有字段含义」是 incompat，且块头在第 1 层（`15-格式冻结政策.md:49`「第 1 层：超级块 + 块头」）。

### 臂 B（另找判别子）

**出错的世界**：判别子必须在**写出那一刻**就能填。固定点第 k 轮写 K 的时候，实现还不知道后面有没有第 k+1 轮（收敛是判出来的，不是排出来的）。任何「本容器在本 checkpoint 内的第几版」都要求写者在写之前就知道总版数，或者事后回改已经落盘的头——后者撞 `.claude/kb/decisions/22-单元原子性怎么合成.md` 那一路的 COW 语义。剩下能填的只有单调计数器，而单调计数器就是臂 A。

**代价**：材料说「probably costs bytes in a field table that is frozen in layer 1」——核过成立（`15-格式冻结政策.md:49`）。另加一笔材料没写的：码 3 头从 103 再变宽，会连锁改 I-1.7 的边界式（`invariants.md:26` 逐字「声明长度 ≤ 32768 − 103」）、`first-txn-layout.md:88` 的 103、以及按 `18-块里携带什么信息.md:151` 的四个实验重算（C89 第 ④ 笔）。

### 臂 C（写路径纪律）——代价藏在五处

材料说它「Zero format cost」。它不是零代价，代价藏在下面五处，越往后越隐蔽：

1. **它禁掉的是一条已定条款明确留出的实现自由度**。`03-空间分配.md:186` 逐字「边插边 COW 的实现更贵」——「更贵」是被允许的，臂 C 要把它改成「不许」。这是对 D3 已定项 5 的一次收窄，要走决策变更流程。
2. **收敛必须在内存里做完** ⇒ 全部脏集要在写第一个字节之前攒住。E81 实测（`.claude/kb/experiments/81-提交的固定点.md` 实测表）：已定政策（meta_clustered）下 U=12 是 28 块、U=1024 是 1275 块；散布政策下 U=1024 是 12314 块。而 D3 已定项 5 逐字说聚簇「**是分配器政策不是格式位**……违反它的实现写出的镜像完全合法」⇒ **这个内存上界不受任何格式约束**，第三方管道（D17）不照办也合法。
3. **它要的检查有一半是欠着的**。镜像侧那一半有（I-1.8 二元版，见第三节腿 1）；实现侧那一半是 C83 仍欠的固定点轮数读数（`checks-owed.md:94`「**仍欠**：实现后提交路径记『固定点收敛轮数』、超声明上界判红」），而**它的上界今天没有可算的口径**——`_c113-r9-final.md:65` 逐字：「『一次固定点重做的最坏量』今天没有可算的口径，立成欠账」。
4. **最隐蔽的一格：臂 C 把一个没有上界的量放进发布路径的内存必需项**。按第九版 P1，挂载准入要预留「N_switch × 一次切换的最坏量」，而一次切换含「一次固定点重做」（`23-journal的角色与格式.md:674`）。臂 C 要求固定点整体在内存里收敛 ⇒ 那个「最坏量」同时是**内存需求**与**准入合取**，而它逐字没有口径。⇒ 臂 C 使一条准入闸依赖一个仓里明说算不出来的数。
5. **一个结构性的怀疑，指向臂 C 可能本来就是真的**（⚠️ **这一条是我推的，仓里没有任何一句这么说，要单独坐实**）：按 `18-块里携带什么信息.md` 的第二级登记表，打包记录类型今天只有 1（墓碑区间记录）/ 2（inode 记录）/ 3（退役记录）/ 4（实例表）四种（`checks-owed.md:160` 逐字「登记表今天有 0（无效）/ 1（墓碑区间记录）/ 2（inode 记录）/ 3（退役记录）/ 4（实例表）五项」）。而固定点的迭代链按 E81 逐字是「新块 → 新记录 → 随机砸中一片没脏过的叶 + 祖先 → 又两个新块」，只走**分配记录树与记账树**；两棵树的节点按 `18-块里携带什么信息.md:698` 逐字「**记账单元 → 2**」是**码 2**；旧版容器释放逐字「旧版容器走普通 COW 释放路径，**不写墓碑**」（`:750`）。⇒ **固定点的任何一轮都碰不到码 3 容器**。若成立，I-1.8 括号里点名的那个机制（「固定点会迭代」）对码 3 **根本不适用**，臂 C 对码 3 是结构上本来就真、不需要立成纪律。**这条要现查坐实**——它会把整个 C163 的处置从「四选一」变成「改一句话」。

### 臂 D（接受同 checkpoint 内多版不可分辨）

**出错的世界已经被 E104 量过**，不用重新构造。`.claude/kb/experiments/104-扫描重建的现行版本判定.md:74` 整行：

> `| cont_same_wseq | 1 | 0 | 0 | cont_key_wseq 复活 1 + 歧义 1 | 同身份、同写序、不同诞生代号的两版：按写序择新是平局（歧义 1），取到旧版 ⇒ 少一条 kill 记录（复活 1）——第七轮反推腿 2.1 那条历史 |`

翻成盘上的话，按打包记录类型分两种：

| 类型 | 取到早一轮那版的后果 |
|---|---|
| 1（墓碑区间记录） | 少若干条 kill 记录 ⇒ **已删对象在扫描重建后复活** |
| 2（inode 记录） | 晚一轮建的 inode 记录整批消失 ⇒ **静默丢文件**；I-9.13（类型 2 容器不空，`invariants.md:265`）只查「记录数 ≥ 1」，一条都不会响 |

⇒ 臂 D 的代价不是「一次歧义」，是**静默的数据复活与丢失**。而且材料问「whether anything else already prevents that」——答案是**没有**：今天没有任何规则说这个平局怎么破，E104 用的「最小落点获胜」自陈只存在于模型里（第二节末尾整行抄的那句）。

## 六、E104 的臂集有没有建过「同一 checkpoint 内固定点多轮」

**没有。源码级坐实，三条证据。**

1. `research/e7-index-bench/src/bin/e104_current_version.rs:395-396` 整行：
