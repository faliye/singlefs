## 问 3：甲与乙谁更符合已定判据

**结论：甲在三条判据上都优于乙，乙在其中两条（自包含、O(1)）上明确违反已定规则，在第三条（A6）上不构成优势。**

逐条：

1. **D9 已定项 6 的 A6（AAD 期望值不来自明文侧），及 E90 实测「树维从指针读回来则三次换挂全部静默」**（`.claude/kb/decisions/09-加密.md:772` 「A6 | AAD 期望值不来自明文侧 | AAD 每个字段的期望值一律不许来自明文侧」；E90 实测原句见背景材料第三节 `.claude/kb/decisions/09-加密.md:618-630` 整段）。
   E90 判过"直接信任指针里的声明"不可行，可行形态是"**指针带声明 + 读者拿克隆祖先表验收**"（`.claude/kb/decisions/09-加密.md:626`）——甲的形态逐字就是这个已验证过的机制：指针带出生 (树,txg) 两个字段当"声明"，读者用克隆祖先表验证。
   乙不把树放进指针，而是从 txg 反推——但反推同样要走"txg 落在哪个克隆点的区间"这套逻辑，**这套逻辑本身就等价于对克隆祖先表做一次查找/验证**，复杂度和甲的"验收"步骤同阶。区别不在 AAD 这条路径上（两者在这条路径上都要碰克隆祖先表，见问 4），而在**不需要认证的路径**上——见第 3 条。
   ⇒ 这一条判据本身，甲乙在 AAD 路径上打平，甲不多花代价、乙也不少花代价；甲更贴近 E90 已验证的具体形态，乙需要另证"txg 反推"这个新机制本身满足 A6（本材料未证）。**净判：甲持平或略优，乙有一处未验证的缺口**。

2. **`.claude/rules/fs-design.md:72,74`「不为省空间牺牲自包含」**：逐字「自描述数据宁可写大一点。遇到『这个字段能不能省掉 / 能不能压窄 / 能不能现算』这类权衡，默认答案是不省——除非有实测证明省下来的那部分是瓶颈。理由是两边的代价不对称：省下来的是空间，省掉的是『一个单元单独捡起来还能不能自证』」。
   乙的形态精确落在这句话点名的三种权衡的第三种——「能不能现算」：它把出生树从"指针内联字段"改成"由 txg + 克隆祖先表现算"，代价是省 8 字节/指针。**本材料没有任何实测证明这 8 字节是瓶颈**（背景材料第四节的连锁表只算字节数，没有一条速度或空间压力的实测）。
   更关键的是自包含这一半："一个单元单独捡起来还能不能自证"——乙让"这个指针指的块出生于哪棵树"这件事，**脱离了指针本身、必须依赖外部的克隆祖先表才能回答**，而这条外部结构今天连落点都没有（见问 4）。甲把答案留在指针里，读指针（配合克隆祖先表验证其真实性）就能回答；乙必须先有克隆祖先表在手才能回答，指针本身对这件事是"哑"的。
   ⇒ **乙正是这条规则要拦的形态，甲不是。**
   **观测会推翻**：若日后有实测证明 8 字节/指针在本工程的规模下确实是空间瓶颈（比如证明它把某个关键结构从能装进内存变成装不进），则乙的选择有了这条规则要求的"实测"依据，判定改变。目前无此实测。

3. **D5（快照/空间记账机制）那条 O(1) 归约**：`.claude/kb/decisions/05-快照-空间记账机制.md:161-165` 逐字 `birth = ptr.birth // 指针内联字段，零次额外 I/O`，`:245-247` 「生命周期判定按设计不要任何聚合统计量……D5 的 O(1) 证明建立在『生死判定只用 ptr.birth 与 head.prev_snap_txg，不查记账树』上」。
   这条已证的 O(1) 只覆盖"要不要立即释放"这一个判定，**只需要 txg，不需要树 ID**——甲乙都把 txg 内联，这条已证的 O(1) 两边都不受影响，不能拿它直接判甲乙优劣。
   **但本轮真正卡住的、需要 O(1) 的是另一件事**：`.claude/kb/decisions/26-后台整理与放置回收.md:118-123`（背景材料第二节整段）里 deadlist 条目要按版本身份（五元组+诞生代号）记，这个身份的树 ID 段是"出生树"——**这是materialQ3明确要求判的那个新 O(1) 需求，不是 D5 原有那条**。甲：`出生树 = ptr.declared_tree`，读指针即得，仍是零次额外 I/O 且零额外计算，O(1)。乙：`出生树 = 查克隆祖先表(ptr.birth_txg)`，这一步要在克隆链上定位 txg 落在哪个区间，**复杂度是 O(克隆链深)**——克隆链深度理论上随池的生命周期增长（每次克隆/快照都可能加一层祖先关系），不是有界常量，这正撞上 `.claude/rules/fs-design.md`（记账是事务的副产品一节，本文件已引用过的判据）「运行时决策路径……不许，且代价不许随盘容量/生命周期增长」的同类精神——虽然这条硬性条文写的是"记账"，但 deadlist 条目构造属于释放判定路径的一部分，同一类要求应当适用。
   ⇒ **乙在这个新 O(1) 需求上不合格，甲合格。**
   **观测会推翻**：若克隆祖先表被设计成"扁平索引"（比如一张全局 txg→树 ID 的排序表，用二分查找 O(log 克隆数) 而非线性走链），那么乙的复杂度会降到 O(log 克隆数)，仍非严格 O(1) 但可能被接受为"有界得足够小"；材料里没有这个结构的设计（问 4 会证明它今天完全没有落点），所以现在只能按最朴素的"沿链找"计，判 O(克隆链深)。

**Q3 综合结论**：甲在三条判据上全部占优或持平，乙至少在「自包含」与「O(1)」两条上明确违反已定规则。

## 问 4：乙的硬前置——克隆祖先表今天的状态

- `.claude/kb/decisions-history.md:2572` 逐字「格式含义两笔（指针带出生 (树, txg)、克隆祖先表住已认证结构）记录在案，**未立决策**」。

## 问 5：这笔格式代价该挂在哪条决策下面

**结论：挂 D19（块指针的结构与宽度预算），开一个新的未定项（今天是未定项 6，这笔挂未定项 7），不挂 D9 / D18 / 新决策。**

逐个排除：

- **不挂 D9（加密）**：虽然 E90（发现机制的实验）挂在 D9 名下，但 D9 自己已经明确"不当场立决策"（`.claude/kb/experiments/90-树ID进AAD与跨头共享.md:57`），把格式含义记进正文却没转成分项。更实质的理由是**这笔代价的举证责任已经被 P2 转移**——背景材料第二节（`.claude/kb/decisions/26-后台整理与放置回收.md:351-367`）逐字「前置：D18（块里携带什么信息） 已定项 11 点名的『指针带出生 (树, txg)』」，而问 3 已证明这个字段的真正刚需来自 D19 已定项 5 的释放路径（deadlist/映射 key 构造），**这个刚需与加密开不开无关**——一个不加密的池同样要能形成映射 key、同样要能对跨头共享的块做生死判定。如果挂在 D9 下面，会把这笔代价错误地限定成"加密特性的一部分"，而它实际上是核心释放路径的通用需求。
- **不挂 D18（块里携带什么信息）**：D18 已定项 11 只是**点名**了这笔债（背景材料第三节 `.claude/kb/decisions/09-加密.md` 引用链间接指向），D18 本身管的是"单元里装什么"（各类单元的头字段表），而这笔代价改的是**指针**（住在父节点里的字段），根据 `.claude/kb/decisions/21-权威态与派生态的分界.md:245-247` 的逐字节表，"单元头"（D18 的地盘）与"指针头部"（D19 的地盘）是两个不同的、已经分开记账的结构——把指针字段挂到管单元头的决策下面，会把两个本来分开的表混到一起。
- **不开新决策**：D19 今天状态是"半定"（`.claude/kb/decisions-history.md:733` 「D19 新增未定项 6（映射条目的字段表），D19 转半定」），仍在接受新未定项，2026-09-08 才刚加过一个。指针头部的字段组成（MAC/nonce/算法类型/extent 偏移/位置条目）本来就是 D19 已定项 2/3/4 逐项定出来的，"要不要再加两个字段"是同一张字段表的下一行，不是另开一个新话题——D19 的标题本身就是"块指针的结构与宽度预算"，逐字对应这个问题。开新决策会把同一个物理结构（指针）的字段表拆到两份决策文件里，`.claude/kb/first-txn-layout.md` 引用起来也会多一层间接。
- **挂 D19，理由与判据**：`.claude/kb/first-txn-layout.md:345-348` 逐字「每一处都判过『改第一个事务的字节：是』……⇒ 推论：**给这张表加一行之前，先确认它挂得到一条编号分项上**；挂不上就先立分项，否则那一格既不算已定也没有未定项承载它，三个门禁阶段一个都不会说话」。今天 first-txn-layout.md 第三节（`:49-60`，背景材料整段引用）里"块的诞生 txg（内联在指针里）"这一行已经存在、标"半定（机制已定，宽度无分项）"、挂在 D5 名下（这是历史遗留，因为 txg 的"机制"确实是 D5 的 birth 语义），但"出生树 ID"**这一行在表里根本不存在**——这正是材料命题 P3 的结论（C66 型格式级空白）。补分项时，"txg 的机制"仍可以留给 D5 解释，但"这两个字段在指针里占几个字节、放在头部哪个位置"这件事是 D19 的字段表该管的（对比已定项 3、4 都是这种"占几个字节、放哪"的分项）。挂 D19 未定项 7，正文写清两点：① 字段宽度与位置（甲 16 字节 / 乙 8 字节，二选一待定）；② 引用 D5 的 birth 语义与问 4 查明的"克隆祖先表无落点"这条硬前置，说明分项定不了案的原因是这条前置未清偿，而不是 D19 自己缺证据。

**什么观测会推翻**：如果后续论证证明这个字段的刚需**只**来自加密路径（比如 P1/P2 的论证被推翻，证明不加密池不需要它），那么挂 D9 会重新变得合理；目前 P1（D19 已定项 5 的释放路径需要出生树）与 P2（举证责任转移）都是本材料要求"先接受成立"的前提，在这个前提下，D19 是正确落点。
