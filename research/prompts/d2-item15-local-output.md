Q1. Definition: Two objects have different lifetimes if they are located in different regions. A case where this definition fails is two tombstone records from different snapshot generations placed in the same region. According to the definition, they share the same lifetime because they are in the same region. However, they belong to different generations and should not share a physical mapping unit. This violates the requirement because the tombstones have different lifetimes but are allowed to coexist in the same unit.

Q2. Two root slots in the same min IO unit on a thin provisioning target with 64 KiB block size. Slot A holds generation 1 and Slot B holds generation 2. Slot A dies when generation 2 becomes active and Slot B dies when a new generation replaces it. By the definition "die at different times", they have different lifetimes. However, by "failure of one can damage the other", they do not damage each other because the thin provisioning target uses transactional RMW: writing Slot B allocates a new block and switches only after copying, so power loss during write leaves Slot A intact. Thus, the first definition says they should not share a unit, the second says they can.

Q3. Device geometry: min IO size 65536 bytes, physical block size 512 bytes, region count 3, slots per region 16 (region size 8192 bytes). Prime strides are 2 and 3 for region offsets. Region 0 starts at 0, region 2 at 16384, region 3 at 24576. A single min IO unit (0-65535) covers all three regions. Writing a single slot in region 3 (24576-32768) requires reading the entire min IO unit. If interrupted, data in region 0 (0-8192) and region 2 (16384-24576) is damaged. This spans multiple generations beyond one, violating the bound.

Q4. A RAID5 array with 4 disks, chunk size 64 KiB. Writing a single 512 byte sector within a stripe causes the device to read the entire stripe (4 disks * 64 KiB), compute parity, and write back. If power fails during this operation, the parity and data sectors in the stripe are corrupted silently. This mechanism is the RAID5 write hole, where RMW is not transactional and neighbors are damaged.

Q5. Two data blocks from different snapshot generations: the original block from snapshot X and its modified version in snapshot Y. The filesystem allocates blocks sequentially. For a device with min IO size 65536 bytes and block size 512 bytes, snapshot X has block 0 at offset 0. Snapshot Y modifies block 0, writing a new block at offset 1024 (block 2). Both blocks fall within the same min IO unit (0-65535). The filesystem does not track cross-generation block placement, so they share a unit despite different lifetimes.
