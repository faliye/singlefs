1. Correctness under shapes not covered in rounds 1 and 2:
   - A-R4-T: A sequence where a front-end delete (point delete) is flushed to a leaf, but an internal node buffer retains an older value for the same key. Reads check buffers before the leaf, returning the stale value. A rebalance interleaved with a partial push-down causes duplicate or missing messages, leading to inconsistent reads. For monotonic statistics, a point delete marker in the leaf is ignored if a child buffer has an older value.
   - B-D-T: A root buffer message with lower sequence (but higher position) overrides a child buffer message with higher sequence. Reads return the older value from the root buffer. Stale content cannot be detected after crash due to missing publish numbers in messages (conflicts with F3), leading to invalid reads from stale buffers.
   - B-G-T: A root buffer message with lower seq (e.g., seq 10) is checked before a child buffer with higher seq (e.g., seq 15). Reads return the stale root value. The pool-wide seq counter does not resolve cross-level ordering issues.
   - C-T6: No sequences found that cause stale reads or accounting discrepancies. Front-end trees have no buffers (epsilon 0), so all updates are drained to leaves before publish. Non-front-end trees follow F5; buffers are drained before rebuild per F6. Administrator rollback or crash recovery correctly recomputes buffers from authoritative state. Deletions in reverse index and monotonic statistics are handled correctly via front-end drain.

2. Cost and format:
   - A-R4-T: Node layout includes buffers for non-front-end updates only. Seq remains 4 bytes as per F3. No persisted counters beyond seq. Write amplification: moderate (front-end flush to leaves, but buffer push-downs during restructuring). Read amplification: high (checks front end, root buffer, then all levels).
   - B-D-T: Node layout includes buffers for all updates. Seq 4 bytes but unused for ordering (position-based). No persisted counters for seq. Write amplification: high (multiple buffer push-downs per update). Read amplification: high (checks all buffer levels).
   - B-G-T: Node layout includes buffers. Seq expanded to 8 bytes (pool-wide monotonic counter persisted per publish). Write amplification: high (similar to B-D-T but with larger seq). Read amplification: high (cross-level position ordering causes stale reads despite seq).
   - C-T6: Front-end trees: no node buffers (epsilon 0), seq only in leaf values (4 bytes). Non-front-end trees follow F5 (buffers only if recomputable). Persisted counters: none for seq (seq only in leaf entries). Write amplification: low (front-end drain to leaves before publish avoids intermediate writes). Read amplification: low (no buffers for front-end trees; non-front-end buffers drained before rebuild).

3. Checks that turn red when broken:
   - A-R4-T: Check that a deleted key (front-end flush) returns no value. If a read returns a value from an internal buffer (before leaf), check fails. Proven by simulating a delete flushed to leaf while internal buffer retains old value.
   - B-D-T: Check that the highest sequence message across all levels is returned. If a lower-seq message in a higher-level buffer overrides a higher-seq message in a lower buffer, check fails. Proven by inserting root buffer (seq 10) and child buffer (seq 15) for the same key.
   - B-G-T: Same check as B-D-T. Higher-seq message in child buffer ignored due to root buffer check order. Proven by identical test case as B-D-T.
   - C-T6: Runtime assertion that every front-end tree leaf change in a publish matches a drained front-end entry. If assertion fails (e.g., leaf modified without front-end drain), check fails. Proven by attempting a front-end update not drained before publish.

4. C-T6 is picked. The single observation that would change the pick is if the inode tree (currently epsilon 0 due to F5) requires buffers for performance or correctness, but F5 explicitly states it is "cannot" recompute from authoritative state and thus has epsilon 0. If evidence shows the inode tree actually needs buffers (contradicting F5), the choice would shift to a candidate supporting buffers for such trees.
