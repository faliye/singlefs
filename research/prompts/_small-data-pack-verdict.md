## 二、空间收益：算术上弱优，不是幻觉（主 agent 自算，观测）

设小对象 n 个，容器容量 c 个 slot，单元恒 32768。

| 方案 | 占用 |
|---|---|
| 现行（补齐） | n × 32768 |
| 打包（不合并） | 容器数 × 32768，容器数 ≤ min(⌈n/c⌉, 存活对象数) |

每个非空容器至少含 1 个存活对象 ⇒ **容器数 ≤ 存活数 ⇒ 打包占用 ≤ 补齐占用，恒成立**；
等号在「每容器只剩 1 个对象」时取到。**前提**：全空容器必须能被释放——
而容器合并 / 释放纪律没有会失败的检查（C116）。

⚠️ **E103 的 9.98 倍不能用来反对提案**：那是相对**紧凑打包**的放大，不是相对补齐。
同一口径下补齐是 1e5 × 32768 = 3.3 GB，打包碎片态 140.6 MB ⇒ 打包仍省 23 倍。
背景材料把它列在「交错负载」一格，有误导，本判决撤回那处引用。

⚠️ **元数据侧打包多付**：N 个 slot 是 N 条中央映射 key，外加一棵容器索引（C103 的姊妹结构）。
数据侧省的和元数据侧多付的没有一起算过，全仓无数。

## 五、最后一关：D14 已定项 3 的判据

辩方腿判「逻辑互斥，不是工程量问题」。**主 agent 判它过强，有反例**：

- **写侧耦合消得掉**：容器做成**只追加、封闭后不改**——开放容器全量住内存，
  发布时整单元写出新版不需要读回旧版 ⇒ 不经 D4 已定项 3 的 RMW ⇒ A 的写不依赖 B 的字节。
  修改已封闭容器里的对象 = 搬出成独立单元，旧槽成垃圾等整理。
  代价是 C105（开放容器每次发布被 COW 重写）与搬出带来的空间放大。
- **读侧 / 故障域耦合消不掉**：一份 MAC 罩整个容器 ⇒ 容器里任何一处位翻转，
  里面**所有**文件一起读不出来。C100 在数据侧是「若干个完整文件的全部内容」，
  而 D2 的冗余按单元算。

⚠️ 辩方腿说「给每槽单独校验和则收益消失」——**这条也不成立**：收益是空间（不补齐），
不是共享校验和省下的开销；每槽一份 MAC+nonce 约几十字节，远小于补齐到 32 KiB 的浪费。
真正挡住每槽独立 MAC 的是三条已定条款：
`19-…` 已定项 3（MAC 与 nonce 是**恒定占位的定宽槽位**，装不下随长度而变的 N 份）、
`09-加密.md` 已定项 4（nonce 住**指针头部**，每逻辑 extent 一份）、
`04-…` 已定项 1（校验和粒度与 extent 粒度**耦合**）。
其中 AAD 组成是 day-1 永久契约，**加密开机之前定死，此后改一次就是一次格式断裂**。
