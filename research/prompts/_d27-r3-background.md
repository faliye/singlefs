# D27（小数据打包容器）第三轮论证 —— 背景材料（2026-09-07）

⚠️ **这是第三版材料。前两版各有错，第二版的错由本轮主 agent 自己查出**：
第二轮的「净收益为负」把**永久腾出的占用**减去**一次性写出的字节**，两个量单位不同、
中间没有兑换率。本版把口径拆开重问。前两版的错见文末。

## 零、用户给的决策规则（2026-09-07，逐字）

> 收益如果为负的话 我觉得就没必要存在了

⇒ **这一轮要判的就是「负不负」，而且要先把「收益」的口径定死**。

## 一、要回答的三问

**Q1（口径）**：D27 的「收益」该怎么记？
候选口径至少三种，各自的判据不同：
- (a) **稳态占用**：同一批对象在盘上常驻多少字节。`pad` 100 000 × 32768，容器形态 ⌈N/cap⌉ × 32768。
- (b) **一次性搬迁写**：整理把它们搬进容器要写多少字节（数据 + 中央映射 + 分配记录 + journal）。
- (c) **回本期**：(b) ÷ (a) 之后，对象要活多久这笔搬迁才划算；或者反过来，
  在什么样的对象生命周期分布下这笔搬迁永远回不了本。
**哪一个才是这个工程该用的口径？给理由，不要三个都报。**

**Q2（sign）**：按你选的口径，账是正是负？给绝对值与算式。
必须覆盖已定的三档对象大小（512 B / 1 KiB / 4 KiB）以及界线外的 8 KiB / 16 KiB。

**Q3（准入）**：**即使账是正的**，D27 够不够格进格式？
仓里有三处已经写下来的门槛，D27 一处都没答：

| 出处 | 逐字 |
|---|---|
| `.claude/rules/fs-design.md` | 「省空间从来不是本工程的目标，所以『我们比 X 省 / 比 X 费』这类比较**不许出现在任何判据里**」；格式分支判据「一条格式分支值不值得，看它能不能把『用错了』变成『挂不上』」，且「判据里不许出现『这样更快』」 |
| D25（目标负载优先级） | 一条**永久的**格式分支只服务次要负载，要单独证成，**不许拿收益倍数顶替** |
| D14（双轨（大小文件 / 持久临时）） 已定项 3 | 今后任何抬高内联阈值的提议，都要先答「多个文件共享一个原子单位」这一关，**性能数字答不了它** |

**注意 fs-design 那条对本轮是双刃的**：它同时否掉「我们比别人省」这类判据，
也就是说**空间收益本身可能根本不是一个合法判据**——那样的话 Q2 判正判负都不改结论。
这一步要判清楚，不能绕过去。

## 二、已经坐实的事实（前两轮，主 agent 逐字核过）

### 形态（三方收敛，未落成分项）

- **slot 修改取「搬出去」**：改一个已打包对象 = 走**未改动的**独立单元写路径写新单元，
  容器不动、旧槽标死 ⇒ **容器写出之后不可变**。
- **解引用不需要新 pointer**：槽自带逻辑身份五元组（33 字节，与中央映射 key 同一样东西），
  位置条目照旧指容器所在的 16 KiB 落点，读出整单元后按五元组认领；
  「容器还是独立单元」由单元自己的类标签回答（I-1.6）。**D19 已定项 3 / 4 / 5 零改动。**

### 数（E114 与第二轮）

- 容器容量 cap：512 B → 58，1 KiB → 30，4 KiB → 7，8 KiB → 3，16 KiB → 1。
- 稳态占用收益倍数 = cap（52.33× / 28.40× / 6.91× / 2.98× / 1.00×）。
- **收益倍数与「一个单元不可读丢几个对象」是同一个数**，比值 0.90–0.99。
- 中央映射：节点 16384（D4 已定项 1「元数据侧 16 KiB、数据侧 32 KiB」），条目 61 字节，
  每叶 267 条，N = 100 000 ⇒ 总叶 375。
  - 整理**按映射 key 序** ⇒ 搬迁的映射写 ≈ 375 × 2 × 16384 = **11.72 MiB**。
  - 整理**按容器凑满序、批量 B** ⇒ leaves(B) = (N/B)·L·(1 − e^(−B/L))；B = 1 时 **3.05 GiB**。
- **整理读字节 N × 32768 = 3.28 GB 从来没进过任何账。**
- 分配记录与 journal 的写也从来没进过任何账。

### E114 自身的两处方法论缺陷（已写进 E114 正文）

- `packbg` 是跑到一半加的第四条臂，而三条反向接受条款逐字全写「A 形态」
  ⇒ **产出定案的那条臂不在任何跑前失败条款的射程里**（C186）。
- 源码注释块头写「格式常量，全部有出处」，而 `SLOT_FULL` 里那 4 字节槽表条目、
  `SLOT_MIN = 4`、`LIVE_COUNT_ENTRY = 16` 一处出处都没有；最后一个正对 D27 未定项 5（未定）（C187）。

### 加密侧（第一轮查实）

- I-6.1 逐字：全盘任意两个**已写出**的块（不论是否仍被引用）(密钥代号, nonce) 不相同
  ⇒ **搬运必须重新加密，不论 AAD 绑谁**。量级小（51 MB 在 ~17 GB/s 上约 3 ms）。
- D9 已定项 6 的五项 AAD 带一条明令必须同引的骑手：「对快照维是瞎的，且是静默的……
  **字段表欠一次重开**」⇒ D27 未定项 9 在那次重开之前定不了。
