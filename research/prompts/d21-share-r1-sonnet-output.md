## 一、候选甲三步各自成不成立

### 第一步：按可枚举性拆两类

**前提「两个可写头引用同一个逻辑对象时用同一个 key」—— 成立，有条款支持。**

- `.claude/kb/decisions/08-核心索引结构.md:172-174`：「两个可写头各写一次同一个
  `(locality_id, inode, offset)` ⇒ 落在**同一个 key 槽**，后写覆盖先写……**这一条独立于加密：
  一个字节都不加密时它也已经错了**。」——这一段本身是 E35 在**单树**假设下的证伪，
  但它先确立了一个事实：**两个可写头对同一逻辑对象取的 key 三段完全相同**（否则谈不上「落在同一个 key 槽」）。
- `08-核心索引结构.md:182-184`：「这个冲突已于 2026-08-30 消解：D6 已定项 1 定案取『每头一棵自己的树』
  ⇒ E35 证伪的是『三段 key + **单树** + 多头』这个组合，而每头一棵树之下**三段 key 在树内唯一**，
  两个头不再落进同一个 key 槽。」——**树 ID 分开之后，key 本身（locality_id, inode, offset）不变**，
  只是它现在挂在两棵不同的树下。
- `08-核心索引结构.md:375`：「两个头共享 origin 的叶、各自 COW 之后是**同身份两版、同一个 key 装着不同对象**」
  ——这句直接给出候选甲要的那个状态：**分叉（COW）之前**，两棵头树上相同的 key 指向的是**同一个物理单元**
  （因为叶子还是共享的、没有 COW），分叉之后才各自指向不同对象。

⇒ **候选甲第一步的前提有条款支持，判定：成立。** 五元组（D1（数据可移动性 / 反向索引）已定项 5）里的
「对象 ID / 锚点偏移」段与树内三段 key 是同一套坐标，「树 ID 不同」是两个可写头唯一的差异维度。

**可枚举性 claim「树表已定 ⇒ 引用者集合 = 遍历树表 × 每棵树一次点查」—— 机制上成立，但复杂度候选甲没说清楚。**

- `.claude/kb/decisions/22-单元原子性怎么合成.md:373`：「根记录恒走间接层：固定头 + 一条指向『树表单元』
  的指针，树根一律住树表单元」，`:399`：「树表单元……装 266 棵/层，超过再嵌一层」——树表是**持久化、
  可遍历**的结构，这一半成立。
- 但树的总数**无上界**：`.claude/kb/decisions/05-快照-空间记账机制.md:377`「树 ID……**自由选择**。
  上界一条已定条款都指不到（D6 定每个可写头一棵自己的树、快照数无上界）⇒ 不许拿一个窄宽度去制造一个
  设计上限」。
⇒ 候选甲自己写的「遍历树表 × 每棵树一次点查」，字面就是 **O(树总数)**，不是 O(1) 也不是 O(共享数)。
这个复杂度候选甲的「打的面」第 3 条自己也在问（「重建代价 O(共享单元) 不是 O(盘) 是不是假的」），
但**第一步没有把这两件事合起来算**：对**一个**共享单元问「谁引用我」是 O(树总数)；
要对**全部**共享单元都问一遍（例如缩容 / 移除设备时要挪的那一批），代价是
**O(共享单元数 × 树总数)**，这比候选甲想省掉的旁表（O(实际共享条目数)）贵得多，
尤其在「树很多、共享很少」这个象限（见第五节的具体构造）。

**分类本身与已决定的稀疏旁表用途不一致 —— 这是一处需要现查才发现的冲突。**

候选甲第一步的结论是「要索引的只有第二类（非同 key 共享 / reflink / 去重），第一类（快照式共享 /
跨头共享）靠树表枚举，不需要索引」，并且说「不新开结构，挂在那张（稀疏旁表）表上」——暗示稀疏旁表
本来就是给第二类用的。**现查结果与此相反**：

- `.claude/kb/decisions/05-快照-空间记账机制.md:86-87`：「这条重开条款已经被触发过一次，并已收口
  （2026-08-30）：D6 已定项 1 定案取『每头一棵自己的树』，而**跨头共享的块就是第二个活引用**。
  ⇒ 按 D5 自己给出的正确形态收口：D5 为主 + 稀疏旁表为辅（ZFS 的 BRT 形态）」。
- `.claude/kb/decisions/06-快照实现模型.md:202`：「D5 的重开条款被触发……而 ② 的**跨头共享**正是
  第二个活引用。⇒ 已重开并按 D5 自己给的正确形态收口：D6 为主 + 稀疏旁表为辅」。
- `.claude/kb/experiments/52-两种多可写头机制的运营代价.md:22`：「旁表条目数（**跨头共享块**）」——
  E52 里旁表这个指标的定义域**就是**候选甲说的第一类（快照式共享）。

⇒ **仓里已经决定的稀疏旁表，存在的理由就是候选甲第一步说「不需要索引」的那一类（跨头共享）**，
不是候选甲说「才需要索引」的那一类（reflink / 去重——今天连一个实例都不存在，`21-权威态与派生态的分界.md`
背景材料第 10 条「第一版没有共享」）。候选甲把这两类的索引需求**对调了**。若采纳候选甲，
`D5-快照-空间记账机制.md` 与 `D6-快照实现模型.md` 里「D5 为主 + 稀疏旁表为辅」那几段的射程要重写：
要么证明「跨头共享」也可以退回树表枚举（那就要重新论证 D5/D6 当初为什么造了旁表而不是这么做），
要么承认候选甲说的「那张表」和已经决定的稀疏旁表其实覆盖两类不同的东西，需要拆成两套结构。
**候选甲现在的写法把两者当成一件事，判定：这一步的分类与已决定条款冲突，不成立。**

### 第二步：一张表两个态别（共享计数 = 权威，引用者清单 = 派生）

**共享计数一半 —— 成立，且与 D5 已有的论证同源。**

`05-快照-空间记账机制.md:80-84`：「前提 3 与 reflink / dedup / 块克隆机制上不相容：有第二个活引用时
摘掉其中一个不构成 death，而判据只看 `birth` 与 `prev_snap_txg`，两个引用的 birth 完全相同
⇒ 第一次摘除就判『立即释放』⇒ 另一个引用悬空 ⇒ **数据丢失**。」——这与 D21 的判据「丢了就丢数据」
逐字对应，候选甲把「共享计数」判为权威态，**判定：成立**。

**引用者清单一半 —— 判据本身没走完，见下面第三节。**

候选甲自己写的话已经暴露了缺口：「假阳/假阴的处置：……不许假阴（漏一个引用者 ⇒ 搬完之后那条指针
悬空 ⇒ **数据丢失**）。不许假阴不靠增量维护的正确性保证，靠『一旦这张表被判为不可信就整表作废、
退回重建』。」——候选甲自己承认「漏一个引用者」的后果是**数据丢失**，却仍把这份清单归为
「丢了只是慢」的派生态；它的兜底是「一旦被判定不可信就整表重建」，但**候选甲没有给出「怎么判定不可信」
这件事的任何机制**。这不是我补的论证，是候选甲文本自己留下的空白，详见第三节。

### 第三步：第一版条目数恒 0，不改第一个事务的字节

**成立，且是背景材料已经核实过的结论**：`21-权威态与派生态的分界.md` 未定项 6 逐字
「改第一个事务的字节：否（2026-09-01，依据：第一个可运行目标无快照、无 reflink、无去重 ⇒
一个共享单元都不存在 ⇒ 条目数为 0）」。候选甲第三步只是重复这条已经定过的判定，没有新增内容，
**判定：成立（因为它什么都没主张）**。

## 二、字节形态

**结论：算不出来。仓里没有稀疏旁表的字段表，候选甲也没有补一张。**

- 背景材料第三节第 2 点要求现查「稀疏旁表的 key 与 value 今天定到什么程度」。
  全仓搜索「旁表」「BRT」只在 `D5-快照-空间记账机制.md`、`D6-快照实现模型.md`、`E52` 三处出现，
  三处给出的都是**条目数量级**（「共享 100‰/每头 1 万条时 1000 条」「8 头/10 万条/500‰时 50000 条」，
  `05-快照-空间记账机制.md:88-90`），以及一个**类比名字**（「ZFS 的 BRT 形态」）。
  **没有一处写过 key 由哪几段组成、各多宽，value 是几个字节、装什么**。
- 「ZFS 的 BRT 形态」是外部实现的类比，按 `evidence-discipline.md`「别的项目怎么做，是线索不是证据」，
  它不许直接进论证，而且候选甲也没有写出「本工程与 ZFS BRT 的一处已知差异」（`evidence-discipline.md`
  「引用别家实现的时候，必须同时写下它和这个项目的一处已知差异」这一条硬要求），所以连当类比引用都不合规。
- 候选甲把「共享计数」与「引用者清单」都挂在「那张表」上，但连这张表现在装的是什么形状的 key 都没有先例
  可循：如果 key 是候选甲第一步给的五元组坐标（对象 ID + 锚点偏移，D1 已定项 5），那 value 至少要装下
  一个计数（宽度未定）；如果还要装「引用者清单」，value 就从定长变成变长（一个共享单元可能有 N 个非同
  key 引用者），而 D5 已定项 3 的记账树「条目是幂等完整值」这个先例是**定长**的，候选甲的清单不满足
  这个先例，需要另立编码方式（例如变长 value，或者展开成多条 (旁表 key, 引用者 key) 记录）——**这个
  选择候选甲没做，仓里也没有可以直接套用的先例**。

⇒ 卡住的未定项：`08-核心索引结构.md` 未定项 7（write buffer 条目自带的 seq，若这份数据也走 write
buffer 前端）、未定项 8（树表条目：树 ID 怎么分配与编码，若 key 要带树 ID）。这两项本身都标着「未定」，
候选甲的字节形态因此没有地基可垒。

## 三、两个态别的判定

| 量 | 判据（D21） | 候选甲的判定 | 现查结果 |
|---|---|---|---|
| 共享计数 | 丢了就丢数据 → 权威 | 权威 | **成立**。依据同第一节：D5 明写「立即释放 ⇒ 另一个引用悬空 ⇒ 数据丢失」 |
| 引用者清单 | 丢了只是慢 → 派生，但派生态的损坏必须可检出 | 派生 | **判据没走完**：候选甲自己写「漏一个 ⇒ 数据丢失」，却仍归派生 |

**「派生态的损坏必须是可检出的」这一条，对引用者清单怎么兑现——候选甲没有回答，我现推一遍看它兑不兑得现。**

候选甲允许「假阳」（多列一个，代价是一次白费的点查，可自证：搬迁时按列出的 key 去点查，查不到就跳过），
这一半确实可检出，检出手段就是操作本身。**假阴才是真正的问题**：清单漏了一个引用者时，
**从清单自身、或从被漏掉那一条正常工作的指针里，都读不出「有人漏了我」这件事**——
漏掉的那个引用者的指针本身是好的（它照常指向那个共享单元，读它的人不会报错），
问题只在搬迁方手里那份清单少了一行。要检出这个漏洞，唯一的办法是**独立地把「真实引用者集合」
重新算一遍再跟清单比对**——而「真实引用者集合」的算法，就是候选甲说的那条「退回全盘扫描重建」的路径。

⇒ **检出假阴的代价 == 重建本身的代价**，不存在比重建更便宜的检出手段。这与
`D21-权威态与派生态的分界.md:28-48`「丢了只是慢」那条前提写的完全对应：
「某个格式选择若让损坏从『可检出的不可达』退化成『检不出的陈旧』……要么放弃那个选择，
要么另立一条可检出性机制并配 checker。」候选甲目前给出的「一旦这张表被判为不可信就整表作废、
退回重建」这句话里，**「判为不可信」这个判定本身没有定义**——没有它，系统永远不知道该在哪一刻
触发重建，假阴就会一直悬在那里，直到某次搬迁真的把另一个引用者的指针搬悬空（候选甲自己写的
「数据丢失」后果）才会被发现，而那时已经太晚。

**这不是「后台无戒律」能兜住的**：`.claude/rules/fs-design.md` 第三格「无戒律」管的是「运行时决策路径
不许遍历」这条第一格禁令对后台操作不适用，**它没有说后台操作可以拿一份不保证正确性的输入去做
不可逆的物理搬迁**。销毁快照那种「可续做」操作（`D6-快照实现模型.md:19-21`）与「搬走一个共享单元的
物理位置」不是同一类可逆性——搬完之后旧位置被释放、可能被复用，漏掉的那个指针指向的字节就不再是
原来的内容了，这一步没有「续做」可言。

⇒ **判定**：共享计数按 D21 判据成立、判为权威没有异议；引用者清单按 D21 判据**尚未成立**——
它需要一条候选甲没有给出的「判为不可信」的触发机制，以及一条与之配套的、代价等于重建的 checker
（这条 checker 本身没有问题，D21 允许 checker 遍历，问题是候选甲没有把它写出来、也没有把它列进
「态别判定成立」的条件里）。

## 五、什么现象会推翻「候选甲成立」

**具体观测，这一轮做得到**：仿照 `E35-多可写头两种形态` / `E52-两种多可写头机制的运营代价` 的建模方法，
构造一个「树很多、共享很少」的极端场景——头数（树数）取 10⁴ 量级，其中**只有 1 个物理单元**被两个头
共享（其余全部私有）。分别量两条路径查「这个单元被谁引用」所需的点查次数：

1. **候选甲第一步的路径**：遍历树表、对每棵树做一次点查——按候选甲自己的公式，代价 = 树表条目数 ≈ 10⁴。
