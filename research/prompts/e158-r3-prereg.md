#### 已定项 7：发布的持久顺序

**定案**：一次发布的持久顺序恒为 COW 单元 / 节点 → 屏障 → journal 记录 → 屏障 → 根槽（FUA）→ 系统配置槽；fsync 等根槽持久之后才返回。恢复重放在施加任何记录之前，必须逐项验证点名单元的校验和。**系统配置槽在根槽持久之后再更新，每个 checkpoint 一次**，它是发布序列的最后一步、进层 0 枚举，一次发布的段序列因此唯一。**抬 F 那一串（准入与卸载）在它的第一次发布之前多一步**：先把新 F 写进每块盘的系统配置、过一道屏障（已定项 1「抬 F 那一串」）；这一次系统配置写不属于任何一次发布，每次发布内部的顺序照旧。**fsync 返回条件多一句**：新实例在本实例写成的根覆盖两块盘之前，fsync 不返回（做法与次数在已定项 8）；管理员回退是挂着时的一次向前发布（D23（journal 的角色与格式） 已定项 14），它的根持久之后才向管理员确认，与 fsync 同一个返回条件。

### 8.2　几何敏感性（`.claude/rules/mutation-sampling.md` 第六类）

判决格 = 主点 G0 上决定岔路单第 1 行的那几格：每臂的丢写格数（Q1∪Q3，0 与 > 0）、多拒数（Q4）、第 22 条没罩住格数（Q6）。每个判决格在下面每个方向相反的取样点上重跑同一格；已按岔路单出局的臂不跑（「够判后未跑」）。

| 取样点 | 相对 G0 的方向 | 重跑哪几族 |
|---|---|---|
| G_S4 = (S = 4, 3 MiB, 4 GiB) | 根环小一半：新实例的根更早盖到被藏那条根的槽，被抛弃根更早离环 | H1d 的 `none`、H1e、L2、L5 |

小环的取法（跑前写死）：从 48 KiB（12 个记录槽）起、每次加 16 KiB，取第一个 mkfs 收、且 P(3, U) 接 H1e(m = 4) 整段跑得通的环长，写进运行记录。

判定：判决格在某个取样点上翻面（某臂丢写格数从 0 变 > 0 或反过来、两候选的多拒先后对调、Q6 从 0 变 > 0 或反过来）⇒ 那一格记「不稳定」，两个点的值都写；不翻面记两点的值。**判别力自证**（每一格各做）：两个取样点上那个量的值不同时，把那一格的门槛挪到两值之间，判定必须由「两点一致」转为「翻面」；挪了不翻 ⇒ 这一格的敏感性报告作废重做。两点同值写「两点同值，自证不适用」。
