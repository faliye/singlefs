# C143（inode 号水位在回退后会退回去重发） 第一轮：攻方腿（Opus）

你的立场是**反推 / 攻**：假设主 agent 的倾向（丙）是错的，也假设甲、乙各有死角，**去造可达历史把它们打穿**。可以写一个小模型（只用 std 的 Rust 或 Python）枚举发布、崩溃、槽读不出、回退、切换、建克隆头的序列，模型源码与原始输出放 `research/prompts/c143-r1-opus-model/`（Rust 的话 `CARGO_TARGET_DIR` 设到 `/tmp` 下，不许在仓里留 target），报告里给复跑命令与文件 sha256。

要特别回答：
1. U1：三条臂各自最短的「已发布身份被重发」历史（没有就写你试了哪些形状、为什么构造不出）。重点攻丙依赖的「根环最大 + 1 大于任何被抛弃的 txg」——最新的根暂时读不出、被抛弃的根先离开根环、连续两次回退、回退那次发布里切换。
2. U2：逐个消费者找「只认号」的那一个，给具体读写序列；extent key 不带出生代（前提七）是最可疑的一格。
3. 乙：前提十的点删与根环深度的关系，给出乙读不到那一行的可达格。
4. 打中之后先问三句（写进报告）：它分不分辨臂；被判的系统在做决定那一刻看得到判别它的东西吗；它满足的是哪条判据的哪一个分句。攻方自己给的收严只算线索，写明它只在你的模型上量过。
5. 什么现象会推翻你的每一条结论。
