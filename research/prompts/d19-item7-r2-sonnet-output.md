## 一、判据 1：A 下子指针里也有出生树，是否也绕不开 C295

### 1.1 现查过的机制：A 的码 3 边 AAD 来源不是子指针，是身份引用

## 四、判据 3：找一种错法在两臂间不对称，以及两臂共有的盲区

### 4.1 单份损坏 / 崩溃残留的前件本身不会触发——这条我核过，同意材料与两轮已有分析

`.claude/kb/first-txn-layout.md:184`（我在 round1 opus 输出里见到的引文，现查确认原文仍在）：位置条目带整单元 CRC32C，父节点的头/载荷校验和覆盖整个节点净荷（含分隔 key、身份引用、子指针全部字段）——一次写要么全部落盘要么整节点判损坏，不存在「节点内部分字段是旧值分字段是新值」的中间态。**这对 A、B 一视同仁**，两臂在「单份物理损坏」这个前件下都不红（我推的，逻辑上是既有 COW + 整单元校验和机制的直接推论，未新增实验验证，标「推的」）。

### 4.2 两臂共有的盲区：出生 txg 那一半，材料写死的相等关系一个字都没提

材料第 30 行给 A 的不变量原文是：

> 立不变量「类型段 2：子指针出生树 == 身份引用出生树 == 子头出生树」

**这条不变量只提出生树，完全没有出生 txg。** 而 D19 已定项 7（`.claude/kb/decisions/19-块指针的结构与宽度预算.md:109`，我核过，已在 §1.2 抄过）明确子指针带的是「出生树 8 + 出生 txg 8」两个字段，出生 txg 对应的子头字段是**诞生代号**（`.claude/kb/decisions/18-块里携带什么信息.md` 类身份段表偏移 73，我核过其存在，行号见附录段的 D18 已定项 11 引文）——**这个字段每次子容器被 COW 重写都会变**（容器出生代——身份引用里那一份——反而终身不变）。

这正是 `research/prompts/d19-item7-r1-sonnet-output.md:89-93`（我核过原文）已经发现的洞：

```
**(d) A 特有的、判据 3 真正要抓的漏洞——出生 txg 那一半没有对应的不变量**：
这是本轮**最重要的发现**。A 的不变量原文是「子指针里的出生树 == 条目身份引用里的出生树 == 子头的出生树」（背景材料第 34 行），**这条不变量只管出生树，完全没有提出生 txg**。但已定项 8 同时要求指针里也带出生 txg（8 字节），而出生 txg 对应的子头字段是**诞生代号**（`18-块里携带什么信息.md` 偏移 73），**这个量每次子容器被 COW 重写都会变**（容器出生代——身份引用里那一份——反而是终身不变的，见前面 1.2 的辨析）。
```

**这一发现在本轮材料里没有被吸收**：本轮判据 3 的问法只问「出生树（任一份）」，本轮材料第五节的倾向理由也没有提到这个缺口。我核实这个缺口对 **B 同样成立**：B 下子指针依然带出生 txg（这是已定项 7 无关 A/B 都要带的字段），B 的 I-9.2 改写（材料写「相应改写」，没有给出具体文字）如果照抄「只比出生树」的思路，同样漏掉出生 txg。

**判定：这是两臂共有的盲区，按材料要求「另立欠账」。** 具体错法：一次 COW 重写子容器（出生树不变，只是普通同树重写，诞生代号从 T 变成 T′），写路径正确更新了子头的诞生代号，但因为一处代码 bug 忘记同步刷新父节点里子指针的出生 txg 段（这是一次纯粹的实现 bug，不涉及攻击者、不涉及跨头），**在 A 的材料原文不变量下不会被抓**（它只比出生树，出生树三处仍然相等）；**在 B 的「相应改写」下同样不会被抓**（除非 B 明确写出「子指针出生 txg == 子头诞生代号」这一条，而材料没有落这句文字）。这个错法与「C294 那条待立的不变量」（`.claude/kb/checks-owed.md:286`，我核过：「按指针 key 经映射取到的单元，头里对应各段逐一等于 key」）理论上能抓——但 C294 今天**未立**（checks-owed 状态是「无」还没有对应的分项号），所以「校验和都不报」这半句判据 3 的前件在这个具体错法下**确实为真**：I-9.2（材料原文的两种改法）、C294（未立）、校验和（只管物理完整性、不管写者逻辑）三道防线在这个错法下**全部不报**。

### 4.3 一处真正不对称的检测能力：A 有一条零 I/O 的本地校验通道，B 没有

考虑另一种错法：**写者 bug 只把子指针里的出生树写错**（比如 B 树分裂/合并时把新条目的子指针出生树复制自一个错误的来源变量），而身份引用（若存在）与子头都是对的。

- **在 A 下**：身份引用与子指针同住一个已经读进内存的父节点里，比较「身份引用出生树 == 子指针出生树」是一次**零额外 I/O 的本地比较**——不需要去抓子头就能发现这条不一致（子指针≠身份引用）。这是 A 的三份冗余里，身份引用与子指针这一对提供的**唯一在「不读子节点」前提下就能生效的检测通道**（身份引用与子头那一对、子指针与子头那一对都需要多一次 I/O）。
- **在 B 下**：身份引用没有出生树这个字段可比，唯一能发现这条错误的路径是把子指针的出生树拿去和子头比对——**这需要多读一次子容器**，而这条「子指针 vs 子头」的比较，无论在 A 下还是 B 下，今天都**没有被具体写成文字**（A 的材料原文不变量是三份互等，没有单独摘出「子指针 vs 子头」这一条独立生效；B 的材料只说「I-9.2 ... 相应改写」，同样没有把这条比较的文字钉死）。

**判定**：这是一处真正的结构性不对称——**A 提供了一条 B 结构上不可能提供的、零 I/O 的本地检测通道**（身份引用与子指针互相印证，不需要额外读取子节点）。这个不对称与「两份是否互为独立见证」这个更早的问题（round1 Opus 已经指出「两份互为见证」这条理由在扫描重建路径下不成立，因为内部节点重建时两份同源）不同——这里说的不是重建路径，是**常规写路径 + 常规校验路径**下，A 比 B 多一条不需要多读一次子节点就能生效的比对。这条不对称是**判据 3 里唯一站得住的、方向明确指向 A 更好的发现**（我推的：结构上成立，未做实验验证，标「推的」）。但它的价值有一个前提：checker 真的实现「身份引用 vs 子指针」这条本地比较——**今天两臂在这一点上都还没有具体的实现文字**，这条优势目前只是「A 结构上留了这扇门，B 结构上没有」，不是「A 已经有、B 已经没有」。
