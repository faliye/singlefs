**失败的处置按失败的性质分两支**（C113（扫描重建时多版单元的现行版本判定无输入） 定案 P1 失败表）。**判别子是当下判得出的量，不是次数**：失败发生时先对**目标设备的固定落点做一次探针写**——写不进去 ⇒ 持续失败，走**转只读到下次挂载**；写得进去，再**对这次失败的那个落点做一次只读复核**：读得出 ⇒ 瞬时失败，走**实例切换**；读不出 ⇒ 落点级的持续坏，同样走**转只读到下次挂载**。⚠️ 复核这一步**只读不写**：写探针进失败落点会抹掉那里的权威数据（8 个失败点里 4 格的落点是根槽或系统配置槽），而固定落点这一步不许改——`D2`（RAID 条带策略） **已定项 13** 逐字「与 `D23`（journal 的角色与格式） 已定项 14 的两支判别子同一个动作」靠它成立（主 agent 现查：那句话在 `.claude/kb/decisions/02-RAID条带策略.md:225`，归属已定项 13「降级期间只读」，不是已定项 15）。**失败点是屏障时没有落点可复核**，那几格只有固定落点探针写这一步。可写设备数掉到 w 的下限以下、切换自己的预留拿不到，同样直接走只读支；连续切换次数越过 **N_switch = 3**（具名可调参数）也转只读，它是兜底的兜底，真正的判别子是探针写加落点只读复核。**收敛靠的是切换的第一步就是一次会失败的写**：切换要先取号，取号要写独占打开成功的每一份系统配置、全或无 ⇒「写不出去」这类故障最多让切换走一步（探针写先拦，侥幸过了全或无也立刻判失败）。

- 切换要用的块在挂载准入时预留：**它是内存里的一个空间量**，每次挂载重算、崩溃即丢、**不落盘**——分配记录条目只有「已分配」与「已释放 + 释放代」两个态（D3（空间分配） 已定项 7），盘上没法表达第三个态，而落盘表达它本身就要写单元、回到「要写才能写」。预留量按 **(N_switch + 1) × 一次切换的最坏量**（一次挂载允许 N_switch 次切换，且实例表链每切一次长一行、写行要 COW 重写整条链，第 k 次比第 1 次贵；多的一份给这次挂载写行那次发布的元数据）；**这个量的口径与式子的权威正文在 D28（挂载期承诺量） 已定项 3**：一次切换的最坏量 = 实例表链重写（副本数 2 × 32768 × 片数，按设备算）+ 暖机空发布（至多 R 次 × 现算 c_max），**固定点重做与号 > W 的数据单元重写不另要空间**——切换是挂载内一次恢复，重建态里失败那次的分配不存在，重做走 checkpoint 的保留池；引这一段时引 D28（挂载期承诺量） 已定项 3。
- **预留挡的是分配失败那一路，不挡写失败那一路**——写失败由探针写与取号全或无挡。

- 比对器：把实现判定表复制一份、翻掉一态的放行，比对器必须报恰好 1 处不同（Q2-pc）。
- 计时：同一进程里合计用时必须包住各态耗时之和（单进程时 ≥ 之和；多进程时 ≥ 各工作进程之和的最大值），包不住的那一趟不进统计（`.claude/singlefs-ai-sop/rules/test-discipline.md`「分段计时在被测进程里计」）。

### 5.3 崩溃状态从哪来：导出格式

字节由导出装置（入库装置，读 `crates/`，5.7）从两条流的录制写流写出；执行器只读下面这份格式，格式本身不带任何解析规则或布局分类。每条流一个目录 `research/target/e170-dumps/<流名>/`（流名 `new_pool_file_creation`、`fixed_script_through_e_then_unmount`）。整数一律小端。

| 文件 | 内容 |
|---|---|
| `manifest.tsv` | `key<TAB>value` 行：`stream`、`devices`（盘身份逐个列）、`device_bytes`、`sector_bytes`（512）、`ops`、`writes`、`calls`、`sampled_states`，以及下面每个文件的 `sha256:<文件名>` |
| `base-sectors.bin` | 基镜像（录制开始那一刻的池）里每个不全为零的 512 字节扇区，一条一条：盘身份 u32、扇区号 u64、512 字节；按 (盘身份, 扇区号) 升序；没列出的扇区全为零 |
| `ops.tsv` | 录制流逐条：流序下标、盘身份、种类（`write`、`write_fua`、`write_zeroes`、`barrier`）、偏移、长度、在 `ops-payload.bin` 里的起点（整段清零与屏障写 `-`）、内容的 sha256（整段清零与屏障写 `-`） |
| `ops-payload.bin` | 普通写与 FUA 写的字节，按流序首尾相接 |
| `calls.tsv` | 驱动方每次调 API 记一行：调用序号、名字（驱动方给的标签，如 `acquire`、`warm_up`、`publish`、`roll_back`、`raise_floor`、`unmount`）、这次调用发出的第一条 op 的流序下标、调用返回时录制流的长度（返回点）、`ok` / `err` |
| `torn.tsv` + `torn-payload.bin` | 实现的枚举器认作「原地覆写、取第三态」的每一次写：写序号（在「写」里数的序号，屏障不算）、撕裂那一态在这次写范围里的字节（在 `torn-payload.bin` 里的起点与长度）、sha256 |
| `states.tsv` | 取样的每个状态一行：状态号、层 0 序号、所在段号（实现的切段）、批号（1 或 2，5.4）、落地向量（每次写一个字符：`0` 没持久、`1` 撕裂、`2` 持久，按写序号，长度 = `writes`）、镜像摘要 |
| `impl-verdicts.tsv` | 同一批状态上实现的判定：状态号、两种 journal 政策各自的 `effective_root`（实例代号、txg 或 `none`）与 `outcome` 种类、`red_items` 原样（`Layer0StateJudgement::red_items`）、池级 checker 判红的不变量、记录核对器两项、`judge_crash_image` 单线程耗时（纳秒，导出装置进程里用 `Instant` 计）。**写执行器的执行员在 5.6 冻结之前不打开这个文件** |
| `quick-tier.tsv` | 这条流在快档展开（`quick_tier_expansion`）下的状态数与全量展开下的状态数（记录用；Q4 只用 60 秒那一条预算） |

**镜像摘要**：对每块盘（按盘身份升序）、每个不全为零的 512 字节扇区（按扇区号升序），依次喂进 sha256：盘身份 u32、扇区号 u64、那 512 字节。两边各自从自己建的镜像算（导出装置从 `CrashImage` 读，执行器从自己建的镜像读），不交换中间结果。

**落地向量由谁算**：导出装置拿 `judge_layer0_state_range` 回调里给的那个 `CrashImage`（持久向量按枚举写表排，撕裂镜像与重放接在后面）折回按写序号的三值向量：原写持久记 `2`；原写没持久而它的撕裂镜像持久记 `1`；都没有记 `0`。折回之后再按 5.3 的规矩从基镜像、写流与 `torn-payload` 重建一次镜像，摘要必须与直接从 `CrashImage` 算的相同（导出装置自检，第十一节 S4）。

**执行器自己的那几样（附带，与导出的比）**：执行器另照 D13 已定项 4 的文字自己认哪几次写取第三态、自己按「新旧不同的那一截前一半新、后一半旧」算撕裂字节，与 `torn.tsv` 逐条比，不同的列出来（附带，够判后不跑）；建镜像一律用 `torn-payload.bin` 里的字节，保证两边比的是同一个状态。

**确定性**：导出装置连跑两次，全部文件的 sha256 逐个相同（第十一节作废条款 V2）。这批文件不进仓（推的：单条流十 MB 量级的二进制，没量）；产物里记每个文件的 sha256，复跑时重新导出、比 sha256。要不要改成进仓由主 agent 定（交回里列为待认项）。

### 5.4 取样规则（批 1、批 2、批 3）

每条流取 `layer0_state_ranges_by_segment(全量展开)` 给的每段序号区间 [a, b) 与总状态数 T（最后那个全持久状态的序号是 T − 1）。

- **批 1**（Q1、Q2、Q4 的那一批）：每个非空区间取 a、b − 1 与 a + ⌊i·(b − 1 − a)/7⌋（i = 1..6），去重；再加 T − 1；再对 `torn.tsv` 里有写落在其中的每一段，在区间里按序号升序扫（每段最多扫 100 000 个序号），取落地向量里带 `1` 的前 4 个、不与已取的重复。扫不到 4 个的照实报个数。
- **批 2**（几何取样点，见第八节）：每个非空区间取 a + ⌊(2i + 1)·(b − 1 − a)/14⌋（i = 0..6），去重，去掉已在批 1 的。
- **批 3**（只为 Q4 的敏感性，见第八节）：每个非空区间取 a + ⌊i·(b − 1 − a)/23⌋（i = 0..23），去重，去掉已在批 1、批 2 的。它的 Q1、Q2 数照报，标附带。

取样由导出装置做（它有区间），三批都写进 `states.tsv`，带批号。执行器不挑状态。

### 5.5 坏状态表（Q3，第三段）

坏状态 = 一个合法的崩溃状态（底态）上打字节补丁。补丁由导出装置用实现一侧的格式知识造（要重封的校验和照实现的算法重封），与执行器互不共用代码；补丁不算写，A(c) 按底态的落地向量算（第一节读法 3）。底态四种，每条流各取一次：

- **F**：全持久态（序号 T − 1）。
- **Mk**：在「发出过根槽写、返回 `ok`」的调用里按调用序号取居中那一个（共 K 个时取第 ⌈K/2⌉ 个），把流序下标小于它返回点的写全记持久、其余全没持久。导出装置报它与哪个层 0 序号的落地向量相同（找不到照实报，仍用它）。
- **Mk⁺**：Mk 再加上它之后第一次发布的第一次单元写持久；那次发布与 Mk 的最后一版须同实例（不同就顺延到下一个满足的调用，报顺延了几个）。
- **Mk⁻**：取居中的那一次带点名单元的发布 p，把流序在 p 的根槽写之前的写全记持久、其余全没持久（p 的记录已持久、根没持久、p 所在调用没返回）。

记号：底态里最新的那一版 v_n = (i, n)，它那条带末条标志的记录叫记录 n、计数器 c_n。「重封」= 照条款把被改结构的自证校验和重算写回；「不重封」= 只改那一个字节。伪记录的头照记录 n 抄，改下面写明的字段，反向链取记录 n 的 311 字节头（头校验和按零参与）的 CRC32C，点名项数 0，事务号 0、提交标记 1，载荷校验和与头校验和重算，两块盘各写一份，落在计数器决定的环槽（`layout/01-first-txn.md`「六」：记录 n 落 (计数器 − 1) mod 槽数 × 4096）。

**P 行（期望「不在」，决定 Q3）**：

| 行 | 底态 | 补丁 | 期望与依据 |
|---|---|---|---|
| P1 系统配置指错根环 | F、Mk | 两块盘上各自世代号最大的那个系统配置槽：根环起点字段 64 → 65，重封 | 不在：读者遇到根环起点与第一版常量不等整池拒（D22 已定项 16 第 1 句），L = 无 |
| P2 伪根，txg 更大 | F、Mk | 在 txg = n + 3 按区域公式该落的那一槽（区域 (n+3) mod R、槽 ((n+3) div R) mod S，盘按逐区域设备身份）写一条根：根 n 的 457 字节，txg 改 n + 3，重封；根 n 不动 | 不在：择到 (i, n+3)（D22 已定项 7、24），之上没有记录，L 不在版本表的 [ack, begun] 里 |
| P3 伪续接一条 | F、Mk | 计数器 c_n + 1、txg n + 1、本次发布内序号 1、末条标志 1、新根段树 ID 水位 = 原值 + 1000 | 不在：jsn 接得上（D23 已定项 22）、整版齐（末条标志在），施加之后的投影水位不等于任何一版 |
| P4 伪续接两条 | F、Mk | 计数器 c_n + 1、c_n + 2，都 txg n + 1，序号 1、2，末条标志 0、1，水位 + 1000 | 不在：一次两条的整版（D23 已定项 14 第五条），投影同 P3 |
| P5 根的实例代号改小 | F、Mk | 根 n 的实例代号 i → i − 1，重封（导出装置先断言版本表里没有 (i − 1, n)） | 不在：择到 (i − 1, n)，同实例同 txg 的记录一条没有、txg n + 1 的序号 1 记录也没有（D23 已定项 14 注 1），一条不施加，L = (i − 1, n, …) 不在版本表里 |

### 5.6 「规约欠一句」的两种跑法；冻结与读实现判定的次序

- **欠一句表**：写执行器时每遇到一处 kb 文字推不出唯一判法，记一行进 `欠一句表`（执行器目录里的 `spec-gaps.tsv`）：编号、步（5.2）、依据的条款（`文件@小节标题`）、缺什么、类别（「两种读法」——两种都写出来；「缺一句」——kb 里找不到任何一句可依；「只有读 crates 才写得下去」——找遍 5.7 允许读的范围仍写不下去，这一类就是 Q1 的翻面观测原文）、暂代读法（下一条）。找过哪些文件写进那一行。
- **严格跑法**：撞上欠一句表里任一行的那一态，判定写「规约欠一句 <编号>」，不给在 / 不在。Q1 只看严格跑法。
- **暂代跑法**：撞上时按那一行的暂代读法往下走。暂代读法只许取 kb 文字推得出的一种读法（「两种读法」类取其一并写明取哪一种），或「这一步不判、只靠校验和」这类不引入新事实的退法；不许取自 `crates/`。暂代读法在第一次跑批 1 之前写定，之后改要按第十二节修订。Q2、Q3、Q4 在暂代跑法下量，每态的判定行标出它用过哪几行暂代读法；严格跑法下给得出判定的态另报一遍 Q2。
- **冻结**：执行器在批 1、批 2、批 3 上的判定文件写出之后，把执行器目录里的源文件（不含比对器与变异驱动）逐个算 sha256 写进产物，这一刻叫冻结。冻结之前写执行器的执行员不打开 `impl-verdicts.tsv`、`bad-*.tsv`。冻结之后才写比对器、才读实现判定。

## 十一、作废条款与停机条款

**作废**：

- V1：装置或执行器经 `run-with-memory-cap.sh` 退 250–254：那一次输出不算，命令与退出码写进报告，不绕开包装重跑。
- V2：导出装置连跑两次，任一导出文件的 sha256 不同：导出不确定，全部作废。
- V3：A8–A10 任一不符：执行器的 CRC-32C 写错，那一趟作废。
- V4：某态的判定行缺失、读出空行或解析不了：读不到不是读到 0，那一批作废重跑。
- V5：Q2-pc ≠ 1：比对器分不出差别，Q2 作废。
- V6：计时包含自检不过：那一趟的 Q4 作废。
- V7：写执行器的执行员读了 5.7 禁读清单里的文件：执行器作废，换一位没读过的执行员从头写（不在原执行器上改）。
- V8：导出文件的 sha256 与 `manifest.tsv`、第一段产物里记的不符：作废，重导出。

**停机**（`.claude/rules/implementation-first.md` 第 4 条：装置与 `crates/` 对不上，两边都查，既不作废也不当结果，产物照打、交主 agent）：

- S2：执行器从导出文件建的镜像摘要与 `states.tsv` 里任一态的不同。
- S3：执行器读导出文件数出来的 op 数、写数、调用数、取样态数与 `manifest.tsv` 不同。
- S4：导出装置把落地向量折回、再从基镜像与写流重建的镜像摘要，与直接从 `CrashImage` 算的不同。

Mk 型底态在层 0 序号里找不到落地向量相同的：照报，不停。

**够判停机**：问题单 Q1–Q4 每一行够判就停（够判条件照问题单原文：Q1、Q2 要批 1 两条流跑完；Q3 要坏状态表每一行跑过；Q4 要批 1 跑完、挂钟量过、预算读法删定）。每段交回附一张表逐行写「已够判 / 还差什么 / 剩下的量能不能让它翻面」；某一行开着而剩下的段补不到它时写明。没跑的量逐条标「够判后未跑」（例如第二、三段之后主 agent 判停，Q2-g、Q3-f 这类附带量没跑就照这样标）。
