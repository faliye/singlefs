**读法写死**：

- 「一次挂载」：被测的那一次可写挂载，从重建分配器起，经写行、暖机，到一条 J 次覆盖写的请求流走完为止；不含之后的卸载（卸载抬 F 不判上限，三条臂在那里相同）。J = 2 × 3S + 8（S = 4 / 8 / 16 时 32 / 56 / 104），够这个进程在不卡住时把每一个读坏槽都写掉一遍。
- 「被拒次数」：J 次请求里交回拒绝的次数，分母 J。拒因分五栏各报：准入预算用完、上限不高于 F（`FloorAlreadyAtTheCeiling`）、抬 F 那一串自己取不到落点、推空的空发布取不到落点、抬 F 报自己的错（知道住着根的槽重读仍坏）。「因读坏多拒」= 同一格去掉读故障（盘面、池、请求流逐项相同）那一次的被拒次数之差。「一次挂载全 ENOSPC」= 因读坏多拒 ≥ 1，且第一次多拒之后这一次挂载里一次请求都没发成。
- 「F 越过的非空根数」：每一次抬 F（F 旧 → F 新）在真值盘面（每个槽按它真住着的内容读，无读故障）上算真值上限 C真（同一个式子：min(每块盘上最新有效根, 第 4 新的不同状态的非空有效根)，不足 4 个取最旧有效根；有效 = txg ≥ F 旧）；F 新 > C真 时，这一次越过数 = 真值有效根里 txg ∈ [C真, F 新) 且真值非空（树状态与它真值前一条有效根不同）的根数，否则 0。
- 「F 越过的状态数」与「回退候选数」：K(F) = 真值有效根里 txg ≥ F 的根带的不同用户可见状态数（按状态去重）。回退候选数报 K(F) 在请求流上的最小值与期末值；一次抬 F 少掉的状态数 L = max(0, min(4, K(F 旧)) − K(F 新))。
- 「推空发布用掉的空间」：推空臂推的、不抬 F 的空发布的次数与它们新占的块数（每次 c 块），按一次准入取最大、按一次挂载取合计；另报其中取不到落点被拒的次数。
- 「读坏」三种：e 设备报读错、g 读得出而不是全零、自证不过、z 读成功而字节全零。「持续」「瞬时」四种见第五节「读故障的持续方式」。
- 「近满」与「宽松」两种池按第五节「池」那一段定，不按百分比。

### 模型（四条 Q1 臂、两条 Q2 臂共用）

计数单位是块（16 KiB 元数据块，与 c_max 同一个单位）。两块盘镜像，每个单元两盘同槽，空间按一份记。

- **根环**：R = 3 个区域、每区 S 个槽，txg t 落区域 t mod 3、区内槽 (t ÷ 3) mod S（等价于按 t mod 3S 定槽）；区域归属 0 / 1 / 0（区域 0、2 在盘 0，区域 1 在盘 1）。每个槽的真值内容：一条根（txg、状态号、带的 F）或全零（从没写过）。
- **状态**：每次覆盖写发布产生一个新状态号；空发布（写行、暖机、抬 F、推空、卸载那一串、历史里的空发布）沿用前一版的状态号。真值非空 = 状态号与真值前一条有效根的不同；读出来的非空 = 与读得出的前一条有效根的不同（最旧那条跟「没有」比，算非空）——两者在读坏槽两侧可以不同，这就是用例里 18 被算成非空的那一形。
- **一次发布的空间**：覆盖写发布新占 d + c 块、放掉上一版的 d + c 块；空发布新占 c 块、放掉上一版的 c 块；放掉的块带释放代 = 这次发布的 txg，进待回收。d = 8，c 取 c_max ∈ {5, 10}。
- **回收**：每记一条根之后，待回收里释放代 ≤ 门槛的转成空闲；门槛 = max(F, 环里最旧有效根)。抬 F 那一串回收出来的扣到这一串最后一次发布之后才算空闲（生效）。挂载重建时回收到门槛，写行与暖机之后放开（不另分「当场可用」那一截）。
- **根环表**（照冻结树 `allocator.rs`）：每槽一项——有效根（txg）、挂载那一刻读坏（可能住过的最旧 txg、能住的最大 txg，算法照第三节 `mount.rs:1774`）、挂载那一刻读回全零（可能住过的最旧 txg）。知道住着根 = 有效根那一类。环里最旧有效根 = 三类各取 txg、钉着的取最旧 txg，取最小。记一条根 t 时先照 `allocator.rs:1219` 的循环重读：最小的是钉着的槽就读它一次，读出有效根换成它的 txg、继续看下一个最小，仍坏或全零就停；然后把 t 那一槽记成有效根 t。
- **准入**：用户发布要求 空闲 − P保留 ≥ d + c；空发布（抬 F 那一串、推空）不判这个式子，只要求 空闲 ≥ c（取不到落点就被拒）；写行与暖机从切换预留出，不动空闲，挂载一定做成。P保留 取两种：代码读法 c（ckpt_cost 取一次空发布的量）、条款读法 10 + 7c。
- **一次请求的准入循环**（照 `mounted_session.rs:423` 那个循环，B = 8）：已推 = 0；够就发、记根、回收、成功；不够就按臂处置（下一段），推了就回到判够不够，不推就拒。抬 F 推之前先核预算：已推 + 这一串次数 + 1 ≤ B，否则拒（预算用完）；这一串任一次取不到落点就整串不发、拒（抬 F 那一串被空间拒，预演那一判）。
- **算上限那一遍**（照第三节前三行）：每槽按读故障读一次；读坏而知道住着根的重读一次，仍坏就拒（抬 F 报自己的错）；读坏而不知道的进「这一遍读坏」。有效 = 读得出 ∧ txg ≥ F。C0 = min(每块盘上最新有效根, 第 4 新的读出来的不同状态非空有效根)，不足 4 个取最旧有效根。并的集合 = 「这一遍读坏」∩ 根环表里「挂载那一刻读坏」一类（Q2 并时再加「读回全零」一类，按同一个算法算能住的最大 txg），只留能住的最大 txg ≥ F 的，C并 = min(C0, 其中最小的最大 txg)。抬 F 在第一次发布之前按同一份输入再算一遍，第二遍比第一遍低就拒（与 `RollbackFloorAboveCeiling` 同一个判）。

### 历史族、读故障、池

历史从 mkfs（txg 0，根环全零，F = 0）起，用这几种事件拼：O 覆盖写发布、E 空发布、M 可写挂载（写行一次 + 暖机，照 `warm_up_publish_txgs`）、C 崩在写行根槽之前的一次挂载（占一个 txg，根环不写）、U 正常卸载（推空发布把 F 抬到现行那一版的 txg，次数照抬 F 那一串）、X 进程退出（不卸载）。一个文件 64 块，覆盖写每次换 d = 8 块。

| 族 | 被测挂载之前 | 读坏的槽 | 真值内容 |
|---|---|---|---|
| H1 崩溃、全覆盖写 | M，O × 4·3S，X（F = 0） | 单槽 X，取 txg N − j，j = 1..3S − 1 | 非空有效根 |
| H2 抬过 F、全覆盖写 | 同 H1，被测挂载之前 F_生效 = N − 3（相当于退出前刚把 F 抬到第 4 新的状态，那一串空发布不另建） | 同 H1 | 非空有效根；j ≥ 4 的槽能住的最大 txg < F，照今天不封顶 |
| H3 正常卸载 | M，O × 4·3S，U（F = 最后一次 O 的 txg V），X | 同 H1，j 走到卸载那几条空发布与 V | 卸载那几条是空根，V 是非空根 |
| H4 覆盖写与空发布交替 | M，(O E) × 2·3S，X（F = 0） | 同 H1 | j 奇偶决定是空根还是非空根 |
| H5 年轻环、崩溃留洞（只给 Q2） | M，O × S，C × 3，X（F = 0），3S 足够大使洞落在第一圈 | 不注读故障：三个洞的槽真是全零 | 没有根（洞） |

读故障的种类：e、g、z（第一节）；H5 只有 z（真全零）。读故障的持续方式（每次读这一槽时判）：

- P1 持续、写掉就好：被测挂载里每次读都坏，直到这个进程写了这一槽，之后读得出写进去的内容。
- P2 持续、写了也坏：每次读都坏，写照样成功（坏扇区）；写过之后这一槽成了「知道住着根」，再读坏就走重读仍坏那一支。
- T1 挂载里瞬时：被测挂载从读阶段到暖机做完之间每次读都坏，之后读得好。
- T2 挂载后瞬时：坏到这次挂载第一次抬 F 那一串做完（含它的两遍算上限），之后读得好。

池（都在写行与暖机做完那一刻量）：近满 k = 0 与 k = 2：空闲 = P保留 + k × (d + c)；宽松：空闲 = P保留 + (J + 3S) × (d + c) + 100（整条请求流不靠回收也发得完）。挂载之前历史留下的待回收块照历史算，不另调。

被测挂载：M，然后 J 次覆盖写请求（每次一个新状态），不卸载。

# 设计员算锚点用（独立于 crates 与装置）：根环落点、暖机次数、推空最坏次数、抬 F 那一串长度、保留池两种读法。
R=3
dev_of_region={0:0,1:1,2:0}
def slot(t,S): return (t%R,(t//R)%S)
def dev(t): return dev_of_region[t%R]
def chain(start):  # 从 start 的下一个 txg 起推到两块盘都落过，至多 R 次；start 自己算不算由调用方定
    covered=set(); n=0; t=start
    while len(covered)<2 and n<R:
        t+=1; covered.add(dev(t)); n+=1
    return n
def warmup(row):  # 写行那次已覆盖 dev(row)
    covered={dev(row)}; n=0; t=row
    while len(covered)<2 and n<R:
        t+=1; covered.add(dev(t)); n+=1
    return n
print("raise_seq_len by current txg mod 3:", {m: chain(30+m) for m in range(3)})
for S in (4,8,16):
    L=3*S
    for Nm in range(3):
        N=10*L+Nm  # 成熟环
        row=N+1; w=warmup(row)
        D=[]
        for j in range(1,L):
            tb=N-j
            assert slot(tb,S)==slot(tb+L,S)
            written_at=tb+L
            last_mount_publish=row+w
            D.append(written_at-last_mount_publish)  # >0：暖机之后还要推几次（含写掉那一次）
        print(f"S={S} N%3={Nm} warmup={w} D_max={max(D)} D_min={min(D)} positions_needing_push={sum(1 for d in D if d>0)}/{L-1}")
for c in (5,10):
    print(f"c_max={c}: reserve_D16_df=10+7c={10+7*c} ; B-1 empties*c={7*c}")

9. **读数里的一个前提**（只记，不改）：近满池在这一组历史上只在两处吃紧：第一次请求（k = 0）与环里最旧有效根被钉住、回收停下之后（k = 2 在读坏之下头几次请求之后吃紧）；没有读故障时回收随环转动补回每次请求花的块，基线上被拒次数在条款读法的池上基本是 0（以产物里 `baseline_rejected` 为准）。代码读法 P保留 = c 的池装不下一串抬 F（2 或 3 次空发布要 2c 到 3c 块、保留池只有 c），那几格上基线自己就全拒，「因读坏多拒」是 0 而不是「没跑到」，读数里 `baseline_rejected` 一列单报。
10. **补一项自检**（不改任何读数）：第一段 e、g 两种读坏的盘面里没有读回全零的槽，两条 Q2 臂在每一条 Q1 臂上必须逐位置相同；装置在第一段的每一组里把「全零并」那一臂也跑一遍、只核逐位置相同（不发格行），不同就作废（V5）。
