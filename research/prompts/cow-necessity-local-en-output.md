For question 1, structures without parent pointers such as the superblock, root ring, and journal ring do not require Merkle spine updates when modified. Since these structures have no parent pointer to reference their checksum, changing them in place does not propagate checksum updates up the tree. The claim incorrectly assumes all modifications require spine updates, but D22 explicitly allows in-place overwrite for structures without parent pointers using whole-unit checksums and generation numbers.

For question 2, consider a database workload where a frequently accessed metadata structure like a B-tree root node is updated repeatedly. In redirect-on-write, each update moves the root to a new location, causing disk seeks for subsequent reads. With in-place plus undo copy, the root remains in the same physical location, so reads always hit the same sector. For example, 100 updates to the root node would cause 100 seek operations in redirect-on-write but zero seeks for reads after updates in in-place mode, significantly improving read latency.

For question 3, the claim overlooks read locality benefits. In-place updates keep the current version of metadata in a fixed location, avoiding scatter of frequently accessed data across the disk. Redirect-on-write scatters updated metadata to new locations, increasing seek times for reads. The claim focuses solely on write amplification but ignores how in-place updates can reduce read latency for hot metadata, which is critical for performance in transactional workloads.

For question 4, the barrier argument is incorrect. Both schemes can batch barriers for entire transactions. For k units modified in one transaction, in-place plus undo copy can write all undo copies with one barrier, then write all in-place updates with another barrier. Redirect-on-write similarly writes all new units with one barrier and updates the spine with another barrier. The claim assumes per-unit barriers but batching reduces the total barrier count to two per transaction regardless of k, making the barrier cost identical. The extra barrier per unit claim does not hold when barriers are batched.
