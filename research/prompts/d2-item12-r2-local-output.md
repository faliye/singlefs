The member table is stored within the plaintext mapping layer, specifically as additional fields in each entry that record the stripe identifier and role (data or parity) for the physical location. The allocator writes these fields when a new stripe is allocated. Lookup is performed by directly accessing the mapping layer’s index structure, which provides immediate access to the stripe membership information without scanning. During a scan rebuild, the scanner reads the plaintext mapping layer from its fixed storage location (e.g., the superblock or a dedicated reserved sector). If corrupted, it reconstructs the layer by reading all units, using the known stripe width w to validate parity consistency across candidate stripes, and grouping units into stripes based on successful parity checks.

2. The keyless mount does not require the member table because repair operations can be performed by scanning for valid parity combinations without prior knowledge of stripe membership. If the stripe width w is fixed and known, the system can iterate over all possible sets of w grids to identify those where the parity condition holds. For this argument to hold, the stripe width must be small enough for practical scanning and the system must allow iterative-1 parity computation directly on ciphertext. The setting does not contradict this, as the parity is computed over ciphertext and w is a fixed value known to the system, making the scan feasible.

3. Capping w at 2 eliminates the ability to implement RAID-like fault tolerance for multiple failures with a single parity grid. For example, a stripe width of 3 allows recovery from one failure using one parity grid, whereas w=2 requires two full copies for the same fault tolerance. The strongest non-space argument is that write operations must duplicate all data across two grids, increasing write latency and reducing throughput due to synchronous writes to two locations. This performance degradation is critical for high-write workloads and cannot be mitigated by space-saving considerations per project rules.
