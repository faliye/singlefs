## 一、要定的那件事

singlefs 是从零设计的 COW 文件系统，还没有磁盘格式实现。
D3（空间分配）已定项 5 逐字只定了「提交自身产生的块……必须从 key 空间上连续的聚簇段分配；
**用户数据块的落点不受此约束**」。⇒ **用户数据落到哪，全仓一条条款都没有。**
「聚簇段里没有位置了这次分配落到哪」同样没有（C146）。

这一项 2026-09-10 才立，直接原因是另一处算不出来：
D14 未定项 2 要比「做分配器提示」与「不做」之差，而**减数那条臂在仓里不存在**。

## 三、四条候选（跑论证之前写死，不许事后加减，只许收严）

| 候选 | 政策 |
|---|---|
| **甲｜最低空槽优先** | 每次分配取全池编号最低的空槽。E93 的 `first_fit`，经典老化形态 |
| **乙｜按 key 序聚簇进段，无空段回落甲** | 同 checkpoint 的脏对象按 key 排序后连续写进聚簇段；没有空段可用时逐槽回落甲并计数。E93 的 `bump_seg`，即把 D3 已定项 5 从提交内生块推广到全部 COW 写 |
| **丙｜按到达序 / 发布批次** | 同一次发布（或连续到达）的对象放进相邻落点，不排序、不读任何盘上字段 |
| **丁｜按目录聚** | 同一父目录下的对象放一起。⚠️ **它不是基线**——它就是 D14 未定项 2 要判的那个「做提示」，列在这里只为让那一格有个减数 |

## 四、判据（跑论证之前写死，按字典序比较，靠前的关不许输）

1. **过不过 `.claude/rules/fs-design.md` 硬要求 1**：判据显式、可计算、写下来。
2. **过不过硬要求 5**：分支变量不许在一次分配操作中途改变。
3. **新增几个格式位。** 落点政策按先例应当是**零格式位**（D3 已定项 5 逐字「盘上没有任何字段声明它」）。
4. **动了几条已定条款，其中几条是用户定案。**
5. **它对 D26 已定项 1 那两个水位的读数做了什么**——起跑会不会常驻空转，停机谓词会不会永远不满足。
6. **它自己要不要一个整理预算才成立**（E93 已经量出乙需要，见附录 B 第 2 节）。
7. **收益侧有没有数，那个数依赖哪个还没测的量。**

## 六、失败条款与反向条款（跑论证之前写死）

| 条件 | 判 |
|---|---|
| 某条候选的优势只在两组负载中的一组上出现，而真实负载落在哪没有依据 | 那条优势记「**条件未知**」，不许写成正收益 |
| 某条候选要求改一条用户定案的已定项 | 不能由这一轮论证定案，只能列岔路交用户，并带上各条路的代价数 |
| 某条候选要求一个整理预算才成立，而那个预算的数全仓没有 | 那条候选的成立性记「**有前置**」，不许当作可以直接定案的候选 |
| 给某条候选挑的实现方式**支持那条路的人不会认** | 当场作废那条臂，重写。⚠️ E93 自己栽过一次：初版邻居臂在段耗尽后逐槽回落，写出的「簇」物理不连续，是稻草人，修订后结论方向就变了 |

**反向条款**：若这一轮判某条候选胜出，本该看到的是——**它不需要任何还没有的数就站得住**。
反推腿要去找的正是反面：**这条候选的成立性偷偷押在哪个全仓没有的量上**。
