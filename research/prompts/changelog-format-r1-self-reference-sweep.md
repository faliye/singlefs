### 2. 命中数是移动靶：给两个时间点的读数，不给单一「准确数」

派发材料给的估计「313 处左右（决策 193 + 实验 120）」，是正推腿用 `grep -c`（按**命中的行**计，
一行有多个引用只算一次）在**它核查时的那一版**文件上数出来的。我在本轮里两次现查，读数分别是：

| 现查时刻 | `decisions-history.md` 行数 | 命中的行数（`grep -cE`） | 命中的引用总数（同一行多处也各算，`grep -oE \| wc -l`）|
|---|---|---|---|
| 本轮开工时读到的第一版（当时约 44250 行） | 44250 | 193 | 248（决策）+ 158（实验，`experiments-history.md` 当时 8105 行）|
| 2026-09-28 14:01（写这份报告时现查，见下方命令与原样输出） | 173758 | 372 | 决策文件内命中 650 处（含围栏内 304、围栏外 346）；实验文件内 172 处，全部围栏外 |

```
$ TZ=Asia/Tokyo date +%F' '%H:%M

$ wc -l .claude/kb/decisions-history.md .claude/kb/experiments-history.md
  173758 .claude/kb/decisions-history.md
   10324 .claude/kb/experiments-history.md
$ grep -cE '20[0-9]{2}-[0-9]{2}-[0-9]{2}（其[^）]*）' .claude/kb/decisions-history.md .claude/kb/experiments-history.md
.claude/kb/decisions-history.md:372
.claude/kb/experiments-history.md:134
```

外围 39 份文件按「按行去重」统计（`other-hits.txt`，第一版口径下）是 79 处；按「同一行多处引用各算一处」
（我后来做的 occurrence 级提取）是 86 处，其中 12 处经现查判定不算「指代
`decisions-history.md`／`experiments-history.md` 的引用」（见下一节「排除」），净 74 处属于这次
摸底的范围。这一批外围文件同样在并发改写（上一节列了哪些带 `M`），所以这个 86／74 的数字
同样只是某一时刻的读数，不是终值。

**结论**：不给一个单一的「现在准确数是多少」——因为在你读到这份报告的时候，它大概率已经
不是这个数了。这不是回避，是「移动靶」这件事本身要先报给主 agent，再由主 agent 判断要不要
等它停下来。

### 3. 围栏内 vs 围栏外的判据可机检，而且判据本身不随文件增长改变

用 Python 脚本逐行扫 ``` ``` ``` 围栏状态（脚本落在
`/tmp/claude-1000/changelog-format-r1-sweep/find_hits.py`），围栏外/内的口径与三方判决第 6 条
给的判据一致：**围栏内的命中，是某条决策/实验条目「改前」段落里逐字照抄的历史快照**（比如
`decisions-history.md:47` 那一行，`text` 围栏里逐字抄着 `01-数据可移动性-反向索引.md` 当年
的原文，其中一行原文提到「撤回依据全文在 decisions-history.md 2026-09-06（其十五）」——那是在
复述**当年那份文件自己怎么写**，不是要今天的读者去 decisions-history.md 里找编号十五）。

现查（2026-09-28 14:01 这一版）：`decisions-history.md` 里 822 处命中中，304 处落在围栏内、
346 处落在围栏外（`experiments-history.md` 目前没有围栏，172 处全部围栏外）。围栏内这 304 处
按三方判决的判据**属于「历史陈述」，不需要改**——把旧编号换成新编号，这句话就从「当年确实
这么写过」变成「假装当年就是这么写的」，反而制造假话（`evidence-discipline.md`「原样保存的
证据不许事后改」）。

**围栏内数量本身也在随并发改写变化**（判决第 1 条的补抄脚本每插回一份带围栏「改前」段的
副本，围栏内命中数就跟着涨），但**围栏内/外的判据不变**——不管命中数是多少，判据永远是
「这一行有没有被 ``` ``` ``` 包住」，机械可判，随时能重新跑出当前这一刻的准确切分：

```
python3 /tmp/claude-1000/changelog-format-r1-sweep/find_hits.py \
  .claude/kb/decisions-history.md .claude/kb/experiments-history.md
```

### 4. 围栏外的命中，结构化匹配（日期+旧编号）不可信——有实测反例

这是本轮最值钱的一条发现，**不随文件增长而失效**：

我先按「日期 + 旧编号」在全文件范围内找现在还有没有一条 `#### ... （其N）` 标题带同样的
(日期, 编号)，命中唯一的就当成候选。抽查发现这个判据**会给出错误答案**：

- `decisions-history.md`（第一版）某处引用「2026-09-01（其四）写着『单元头的字节数……
  头长度应当由五个字段各自的宽度算出来』」，在 D4（校验和位置）、D5（快照 / 空间记账机制）、
  D12（目标介质）、D18（块里携带什么信息） 四个决策节下，各自本地重排后的「（其四）」标题
  都确实是「三方论证『单元头五字段多宽』……」——内容吻合，候选可信；
- 但**同一句引用**出现在 D3（空间分配） 节下时，D3 节本地重排后的「（其四）」标题却是
  「八条定案一次落——未定项从 26 降到 19」——与「单元头字节数」毫不相干，候选**不可信**。

原因是搬迁把编号从「按当天全文件顺序编的全局号」改成「按（决策/实验节, 日期）各自重新数」
（`.claude/rules/changelog-format.md`「并发写入时的编号」一节）。**旧的同一个数字，在不同节
本地重排之后落到哪一条，纯属巧合，没有必然对应关系**。这意味着：凡是只凭「日期 + 旧编号」
做匹配、不去读目标条目内容是否真的对得上引用旁边描述的那句话，就有实测坐实的误判风险——
不能把这种匹配结果直接当结论抄进表里（`verify-before-claiming.md`「核了窄的那一句,说出口的
却是宽的那一句」）。

⇒ **推论**：给围栏外每一处引用一个「应该改成什么」，**必须逐条读引用旁边的描述文字，
和目标决策/实验节当天各条目的正文比对**，结构化的（日期,编号）匹配最多只能当线索，
不能当结论。这正是派发材料里三方判决第 6 条要求的方法（「可以用引用旁边的描述文字……
去定位原文，再到现在的文件里找这条内容现在住在哪」），也是我在文件还稳定的抽查阶段
里验证过确实可行、但确实需要逐条人工读的方法。

## 没做什么

- **没有交出一张逐条打了「围栏内历史快照 / 活指针 / 定位不到」标签、行号精确到现在这一刻的
  完整表**：理由见开头——目标文件集合正在被并发改写，行号与「围栏内/外」的具体切分每次
  现查都不一样，写一张带精确行号的表，读者拿到手时多半已经对不上。已经给出的是：
  可以直接重跑取当前行号的两条命令（围栏切分、日期+编号命中）、判据本身、4 组已经逐条核实
  过内容、指向不会失效的具体改法（表述为「decisions-history.md 的 D<n>（简称） 节 日期 那一条
  『……』」，不带行号），以及 12 处经排查确认不算自引用的假阳性。
- **没有对围栏外命中逐条做「结构化候选 + 内容核对」的完整摸底**：抽查环节已经证明这件事
  本身可行（见「已经逐条读内容核实过」一节），但围栏外命中在两次现查之间从 205 涨到 346
  （决策文件）、从 158 涨到 172（实验文件），且判决第 1 条的补抄脚本还在往里插新副本——
