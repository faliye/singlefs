BACKGROUND

singlefs verifies crash safety by exhaustively enumerating filesystem states after a simulated crash ("layer 0"). The enumeration is organized as several long write streams; each stream is cut into consecutive "segments" (a run of writes that get evaluated together), and within a segment every subset of "persisted or not" for its writes (two states per write, three states for a write that overwrites data in place, since an in-place overwrite can also be torn) is one crash state. A newer redesign under discussion would instead organize the same enumeration as a tree of "nodes", where one node is one user-level operation (one publish, one mount step, one commit); this material calls that redesign "form alpha". For every crash state, today's checker pipeline runs, among other things, a "pool-level checker" that rereads on-disk structures and a set of per-unit content checks (this material calls these "(a)-class checks", following the source material's own lettering); many states in the same segment turn out to have byte-identical unit contents at the positions those checks read, so a proposed optimization ("P1") de-duplicates those checks by content instead of by state. A further proposed optimization ("G2") would classify each state by the vector of "which write ended up visible at each position this state's checks read" ("read-set key") and run the expensive checks once per distinct key instead of once per state; states sharing a key are called one "class". None of this material asks you to judge whether P1 or G2 are correct; it only gives you already-measured counts and asks you to do arithmetic with them.
