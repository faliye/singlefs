# E136 跑前登记：岔路的代价行——只装码 1 的配置、码 2 真实头宽下的扇出、映射树层数按规模区间、两笔搬迁

写于 2026-09-11 22:32 JST，装置写之前。

## 为什么跑

D19（块指针的结构与宽度预算） 未定项 6 三轮对抗第三轮（那一格的 ⑫㈤）判：交用户之前，岔路缺四样代价数——

1. C280（中央映射装哪几类单元没有条款） 取「只装码 1」那一支没有实验配置：E133 / E134 都按「指向码 2 / 码 3 的指针也带 key」算，按类复用写序键的节点指针报 83，那一支两条都应是 75；
2. 码 2 头 +4 在扇出上的代价没量：E133 的扇出式用节点头 64，自陈与 D18（块里携带什么信息） 已定项 14 的码 2 三档头 96 / 105 / 114 不是同一个口径；
3. 映射树层数差只取了一个池规模点：逻辑身份 + 写序键到 5 层的门槛 442 217 935，E109 的池规模 483 183 820 只比它高 9.3%；
4. C280 开关本身的代价（「只装码 1」时码 2 / 码 3 节点的搬迁回到指针权威、要改引用者）与逻辑身份 + 写序键的派生树码 2 节点搬迁多查的那一次，都没有数。

## 臂

三条候选 × 两种配置。

| 候选 | 臂名 | 定义 |
|---|---|---|
| 逻辑身份 + 写序键 | `k1_seq` | 与 E133 / E134 同名臂相同 |
| 混合路 | `k1_seq_class_reuse` | 与 E134 同名臂相同 |
| 按类复用写序键（收严后） | `class_reuse_tagged` | 与 E134 同名臂相同 |

| 配置 | 映射装什么 | 指向码 2 / 码 3 的指针 | 码 2 / 码 3 头的增量 |
|---|---|---|---|
| `all` | 全部指针（D19 已定项 5 字面） | 带该臂的码 2 / 码 3 key 段（E134 的配置） | 照 E134 臂表 |
| `code1_only` | 只装码 1 | 只带出生树 + 出生 txg（+16；D19 未定项 6 挡路句之后那条 ⚠️：每条候选都让指针带这两段） | 0（出生序号只为码 2 / 码 3 的映射 key 服务，那时用不上） |

`code1_only` 配置下混合路就是逻辑身份 + 写序键（码 2 / 码 3 半不存在），照报，两行逐格相同。

## 量什么（全部是计数，确定性模型）

1. **宽度与扇出**：两种配置下三条臂的指针宽、各树条目宽。扇出两套口径：
   - (a) E134 的节点头 64（只用来过跨装置闸）；
   - (b) D18 已定项 14 的码 2 三档头 96 / 105 / 114 各加该臂在该配置下的码 2 头增量当节点头，逐档报 extent 内部、inode 内部、记账内部、映射内部与映射叶的扇出。映射树的节点也是码 2 单元，照同一口径。
2. **映射树层数按池规模区间**：每条臂每种配置报 l2…l6 的门槛（只数数据单元；`all` 另报「含索引节点」那一档，⌈N / 119⌉ 同 E133），并报两两之间层数不同的规模区间；映射叶层字节报两两比值（与规模无关）。两套扇出口径都报。
3. **搬一个码 2 / 码 3 节点**：`all`（映射权威）= 映射树高那么多个节点 + 1 个根槽，与引用树数 K、节点所在层 ℓ 无关；`code1_only`（节点的位置条目回到权威）= K × ((h − 1 − ℓ) 个节点 + 1 个根槽)。K 取 1 / 2 / 4 / 8 / 16，h 取 E109 池规模下 extent 树的高，ℓ 取 0 / 1 / 2。
4. **派生树码 2 节点搬迁多查的那一次**：逻辑身份 + 写序键从落点出发拿不到派生树节点的 key 区间下界，要从根下到父节点，读 h − 1 − ℓ 个节点；混合路与按类复用写序键 key 各段都在头里，读 0 个。按 extent 树在 E109 池规模下的高报 ℓ = 0 / 1 / 2。

## 判据（跑前写死）

- **只报数，不判输赢**，与 E133 / E134 同；它的数只进 D19 未定项 6 的代价行（`.claude/rules/fs-design.md` 逐字「「比谁省」不构成任何判据」）。
- **跨装置闸三条**，任一条对不上 ⇒ 整轮作废、修装置重跑：
  1. `all` 配置 × 口径 (a)：三条臂的 widths / headers / fanouts / 映射树 thresholds / map_at_pool 各行逐行复现 E134 的留存产物；
     触发它的观测：本装置任一行与 `research/results/e134-map-key-slot-baselines-2026-09-11.out` 同名行不逐字节相同。
  2. 口径 (b) 的扇出式：条目 54、81 在三档头下复现 D18 第 308 行登记的「301 / 301 / 301」「201 / 200 / 200」；
     触发它的观测：任一档算出的扇出与那一行不同。
  3. 搬迁计数：ℓ = −1（数据单元）、h = 4、映射树高 4 时，逐格复现 E109 那张「搬一个单元」表（K = 1 / 2 / 4 / 8 / 16 ⇒ `ptr` 66 048 × K、`map` 66 048）；
     触发它的观测：任一格不等。
- **每一格都有钉绝对值的单测**，期望值在写装置之前用另一段 python 独立算出；互比断言旁边都要有钉绝对值的断言。
- **结果反过来我接不接受**（写在跑之前）：
  - 码 2 头 +4 在真实头宽下让某棵树扇出掉一格，照报；一格都没掉，照报「按构造不再相等，但这几档都不掉格」。
  - `code1_only` 那一支两条臂的节点指针与内部条目宽逐格相等，照报；按类复用写序键赢的只剩指向码 1 的指针与 extent 叶、映射，也照报。
  - 层数差的区间若把 E109 池规模排除在外，照报「那个取样点不在区间里」。

## 它答不了的

- 不算 CPU、缓存、I/O 时间；码 2 / 码 3 节点多久搬一次没人量过，搬迁只报「每搬一个节点」的字节与读次数。
- C163（固定点各轮写序相同使平局破除落空） 处置的代价（禁掉边插边 COW 那种实现）不是字节，不报。
- K 取五个点，不代表真实负载里共享的分布。

## 补记（2026-09-11 22:36 JST，写装置时、第一次运行之前）

- 第 4 项「多查的那一次」只在 `all` 配置下是逻辑身份 + 写序键多出来的：`code1_only` 配置下码 2 节点不进映射，三条臂搬一个码 2 节点都要从根下到每棵引用树里的父节点去改指针，那一次读三条臂相同。⇒ 第 4 项只报 `all` 配置；`code1_only` 的那一次读并进第 3 项，按 K × (h − 1 − ℓ) 个节点读报。
- 第 3 项的数据单元锚点：被一个叶引用的数据单元，它的 COW 路径是整棵引用树的高 h 个节点（与 E109 同口径）；码 2 节点在第 ℓ 层（叶为 0），路径是它的父节点到根，h − 1 − ℓ 个节点。
