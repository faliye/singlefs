# 背景：singlefs D9 已定项 8 —— 超级块与根的认证和回滚防护

singlefs 是从零设计的 COW 文件系统（Rust，格式设计阶段，无代码）。
下面每条都出自本仓 `.claude/kb/decisions.md` / `invariants.md` 的**已定条款**。

## 已定的加密骨架

| # | 条款 |
|---|---|
| A1 | **整卷 AEAD**，加密边界与校验和边界重合；父指针里那个校验和字段在开加密时**就是 MAC** |
| A2 | **除超级块、以及「逻辑身份 → 物理地址」明文映射层与明文反向索引之外，全部加密** |
| A3 | **MAC 取满 128 位，不截断** |
| A4 | **nonce 不许由物理位置派生**，跟逻辑身份走并存在指针里 |
| A5 | **AEAD 的关联数据 = `(fsid, 单元类型标签, 树 ID, 对象 ID, 对象出生代, 锚点偏移)`**，物理位置一律不进 |
| A6 | AAD 每个字段的期望值只许来自**读者的查找路径**或**已被上一级 MAC 认证的密文侧字段**，**一律不许来自明文侧** |
| A7 | 超级块 day-1 要有：KDF 标识 + 主密钥槽 + 加密类型 |

## 已定的根与发布

| # | 条款 |
|---|---|
| B1 | 发布语义是 **checkpoint**；**根环是 journal 之外的固定 K 槽，发根 = 覆写一个槽，不是追加** |
| B2 | 每次 fsync 发根（D23 轴一已定） |
| B3 | ⚠️ **本条已于 2026-08-30 作废**（改为「根环深度是块重用延迟的**上界**」；K 取运行时生效值）。原文：**根环深度 K = 块重用延迟，是同一个数**；且 **K 必须是运行时策略，不能是格式常量** |
| B4 | 根要自证：**整单元校验和（自证完整）+ 代号（自证是本代）+ 槽轮换（不覆写唯一副本）** |
| B5 | 读取次序是「**全扫所有槽、各自验证、再按代号择新**」，**不许先按代号挑最新再验证** |
| B6 | `invariants.md` I-7 类四条：① 自证校验和通过的槽集合 S 非空；②③④ 由 S 中代号最大者出发的递归校验必须走得通 |

## 已定的 nonce 纪律

| # | 条款 |
|---|---|
| C1 | I-6.1：全盘任意两个**已写出**的块（不论是否仍被引用），其 (密钥代号, nonce) 二元组不相同 |
| C2 | I-6.5：**记录在案的 nonce 水位 > 全盘出现过的最大 nonce**（崩溃后不重用的可判定形式） |
| C3 | I-6.2：nonce 的**代号部分必须放在明文头**，无密钥可读——否则 checker 无密钥时连「这块用过哪个 nonce」都判不出来 |
| C4 | I-6.1 是**抗 bug 检查，不是抗攻击检查**：它靠明文头 magic 枚举已写出的块，攻击者抹掉 magic 即可让块隐身 |

## 本轮要判的三问（D9 已定项 8 原文）

1. **超级块不加密，那它被认证吗？谁认证它？**
2. **I-6.5 的「记录在案的 nonce 水位」住在哪？**
   若在明文超级块且不被认证，**攻击者回滚它 ⇒ 写者重用 nonce ⇒ ChaCha20 这类流密码下
   两段明文直接 XOR 泄漏**。⚠️ **这不是「读到旧数据」，是密钥被绕过**。
3. **整卷回滚是否宣布为已知不防的范围**（同 fscrypt / dm-verity 的做法），
   还是引入 AEAD 之外的见证者。

## 已经查过的两条外部口径（2026-08-28 本机逐字现查，可直接引用）

- **fscrypt 明写不保证**：「fscrypt is not guaranteed to protect confidentiality or authenticity
  if an attacker is able to manipulate the filesystem offline prior to an authorized user later
  accessing the filesystem.」（`Documentation/filesystems/fscrypt.rst`）
- **dm-verity 的根哈希来自外部信任锚**，自陈「This hash should be trusted as there is no other
  authenticity beyond this point.」（`Documentation/admin-guide/device-mapper/verity.rst`）

## 威胁模型（按此，不要换）

攻击者能**任意读写裸设备的每一个字节**（离线，或在线绕过文件系统），但**没有主密钥**。
文件系统随后被合法用户正常挂载使用。
⚠️ **整卷单密钥**，所以「他人的数据」指的是同一卷上其他逻辑对象，不是其他租户。
