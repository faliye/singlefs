## 二、问法（五问）

1. **丙是不是乙的忠实实现。** E151 的 arrival 臂 = bump 段 + 批内到达序；E93 的 bump_seg = bump 段 + 批内 key 升序。「按 key 序聚簇进段」（乙的定义）在真实系统里能不能做到——一个事务里的对象按到达顺序 COW 落盘，分配器拿到的是到达序，除非先攒批再排序。若能做到，乙与丙是两条臂；若不能，乙就是丙、E93 那一格是假象。
2. **甲在 D2 的坐标系里怎么写。** 卡点 3 说「全池编号最低的空槽」没有指称。在（设备, 列）坐标里，「最低空槽优先」写成什么才有指称（先设备后列？只在当前设备？），写出来之后它与丙在 runs 上还打平吗。
3. **段耗尽时的回落。** 丙无空段时回落到最低空槽（E93 / E151 的取法），回落率 92%–94% ⇒ 丙 92% 的时间在走甲。这句话对政策的意义是什么：第一版是「丙 + 回落甲」还是干脆「甲」——两者在 runs 上都是 99.9%，差别只在那 8% 走进新开段的分配；整理（bump_cp）喂出空段才让丙有意义，而 D26 已定项 1 的起跑水位与停机谓词的输入（全空段数）在 E151 里恒 0。
4. **容器档要不要单独写。** ≤ 4 KiB 对象搬走之前落哪（丙？甲？），打包之后 runs 压到 0.49–0.97 倍、全空段仍是 0——本项要不要给「打包前的落点」单独一句，还是「同大对象」。
5. **要写成条款的形态。** 候选甲′把用户数据与提交内生块交给同一个 bump 分配器（D3 已定项 5 推广到全部写）、回落最低空槽、≤ 4 KiB 走 D27；它与 D26 已定项 1（水位靠全空段数）、D27 已定项 6、D14 未定项 2 的顺序有没有矛盾；整理预算那一句要不要现在写。

## 五、倾向与「结果反过来我接不接受」

**倾向甲′**：E151 之后甲与丙在两组负载上都是 99.9%，聚簇段不再是为 runs 选的，是为「一个分配器、一套回落」选的（D3 已定项 5 已经要求提交内生块走它）；回落率 92% 说明第一版行为上几乎就是甲，条款却不必写两条路径。
**反过来**：5-1 打中 ⇒ 乙回到候选表，E151 加臂；5-2 打中 ⇒ 甲′里的「回落最低空槽」也要换写法；5-3 打中 ⇒ 按那一格的量重判。
