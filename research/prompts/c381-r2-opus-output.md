| 出路 | 要动什么 | 代价 |
|---|---|---|

## 五、K1 打中三：落点持续坏而设备整体可写时，探针写恒判「瞬时」——三次切换全白做

条款自己说探针写是真正的判别子、N_switch 只是兜底（第 365 行末句逐字）：

**造一类它判不出的故障**：某个**落点**（盘 0 上一段字节）永远写不进去，设备整体还活着——坏扇区、坏映射单元、盘上一小片退化，都是这一形。
装置里实现成 `bad_ranges`：写到这段字节上一律报错、不落盘；探针写落在别处，照样过。

### 7.4 增补 3 第 4 件的故障注入要加什么（按这一轮实际用到的）

验收（同文件第 426 行，整行抄）：

> - 故障注入：每个发布步骤与挂载步骤上各注入过至少一次，报每个注入点的命中次数，没命中的逐个列名；判别力：增补 2 收口表第 40 行那一格修之前判红、修之后转绿。

这一轮用到而题面里没写明的，六样（都在 `c381r2_probe_common.rs` 的 `Control` / `Fault` 里，可以整段抄过去）：

| 要加的 | 为什么非它不可 |
|---|---|
| **撕裂写**（前半落盘，然后报错 / 或返回成功） | 「一次写只落一半」用「返回 `BlockDeviceError`」表达不出来；注意粒度：块设备只收整扇区的写，根槽宽 512 ⇒ 根槽撕不开，这一格实际注的是「**写返回成功而一个字节都没落**」，要单列一种 |
| **写落了盘、设备照样报错**（`Lying`） | 「根槽 FUA 报错而根已落盘」是第一轮坐实甲的那一格，通用包装里必须有 |
| **屏障单独报错** | 今天 `ForceUnitAccess` 与 `barrier()` 调的是同一个 `file.sync_data()`（正文第三节），按「第几次写」注入注不到屏障；要一个独立的屏障计数与注入点 |
| **整块盘从第 k 次写起持续失败** | 失败表的「持续失败」那一支只有它才走得到 |
| **按（盘, 偏移区间）的坏扇区** | 第五节那一类（落点持续坏、设备整体可写）按「第几次写」注不出来：切换之后写序全变了，只有按偏移才钉得住同一个落点。⇒ **注入点要能按偏移给，不能只按次序给** |
| **探针写本身是一个注入点** | 戊的判别子就是它；不给它单独的注入点，「探针写不过 ⇒ 转只读」那一支永远走不到 |
