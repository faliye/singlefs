1. The central mapping's root node's physical pointer cannot be stored within itself, creating a cycle. Steps: 1. To access the central mapping, the system needs the root node's physical pointer. 2. The root node's pointer is stored in the central mapping. 3. To find the root node's pointer, the system must access the central mapping, but it lacks the pointer to do so. The cycle must be broken by storing the root node's physical pointer in a fixed, known location outside the central mapping, such as a boot sector or superblock.

2. The instance table's pointer is stored in the root record, not the central mapping. Steps: 1. A reader follows the rule that the central mapping is the single entry point. 2. It looks up the instance table in the central mapping but finds no entry. 3. The reader assumes the instance table is missing and fails. The correct action is to retrieve the pointer from the root record. The reader could know this if the central mapping lookup explicitly checks for the instance table kind tag and falls back to the root record, but the current design lacks this exception handling.

3. A packed container's header does not carry the birth generation field. Steps: 1. During rebuild, the system reads the header to recover identity. 2. The header contains tree id, kind tag (record type), object id (container number), and anchor offset (zero), but lacks birth generation. 3. The rebuild uses a default birth generation (e.g., zero), causing incorrect identities. The missing field is birth generation. The smallest change is to store birth generation in the header to ensure accurate identity reconstruction during rebuild.
