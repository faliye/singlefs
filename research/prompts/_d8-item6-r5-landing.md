## 一、相对第四版改了什么

### P1 形态

- **ε = 0 的分支变量改写成 D11 已定项 4 那条谓词**：「这棵树待下刷的消息能不能只从权威态（单元 + 记账 + 墓碑单元）重算」。
  能 ⇒ 留缓冲（ε = 0.65）；不能 ⇒ 不留（ε = 0）。extent / dirent / 反向索引：能（E59 的「单元 + 记账」一行三类全 0）；
  inode 树：不能（E98 判据 2，14 个字段里 11 个）；记账树：按 D21:394「离线可由遍历重算」判能，但 E59 那一列是神谕、没实测，这一格写「按 D21 判能，未实测」。
  「叶是不是权威态单元」那句撤回——它在重算性读法下会把记账树也判成 ε = 0。
- **D11 已定项 6 的改写两轴都留**：布局轴不分支（「全部布局共用同一组 ε」原文与依据不动）；树轴新增一条（待下刷消息不能只从权威态重算的树 ε = 0，依据 D21 硬约束 6）。
- **「内部节点布局不永久」拆成两句**：载荷布局（ε = 0、条目 93）落 D15 第 4 层，不永久；**头**（共同前缀 + 类身份段，含新增的 16 字节 key 区间）是块头，落第 1 层，与记账树节点头同一格（C102）。
- **key 区间的代价证据改正**：58 / 67 / 76 是 E73 的**不带区间**基础头下界，带 16 字节区间后是 74 / 83 / 92，扇出仍 175（E103 单测钉住 92，并钉住 109 → 175、110 → 174 那道边）。
- **条目类型段 0 的登记**：第二级登记表旁写明「0 在容器头里仍是无效；出现在 inode 树内部节点条目的身份引用里表示子节点是码 2 索引节点」，是对 D18 已定项 11 的第六处改动；I-9.2 补「类型段 ∈ {0, 2}，为 2 时子容器的打包记录类型 == 2」。
- **「AAD 全部来自条目」只对码 3 那条边成立**；码 2 那条边（内部节点指内部节点）的 AAD 仍是 C107。
- **重建的射程**：按 (出生树, 容器号, 出生代) 分组认领只在**单头镜像**上成立；有克隆头时，共享叶头里的出生树是 origin，按出生树认领会把克隆头的树认残——多头镜像的归属划分要克隆祖先表（E90 第二笔 / C110），落地前多头镜像的 inode 树重建没有输入。
- **分隔 key 定义**：条目的分隔 key = 该孩子创建时的最小 key；条目按分隔 key 单调递增；查找取最后一个分隔 key ≤ 目标 key 的条目。进 I-9（I-9.12）。
- **空树**：唯一的叶被删空、无邻居可合并时，树里零片叶，根仍是码 2、零条目，key 区间写 [0, 0]（0 是无效 inode 号）。「记录数为 0 的类型 2 容器不落盘」对这一格是「不落盘」而不是「合并」。

### P2 不进本项的

- 树的种类：第四轮找出第四个消费者——**checker 要知道一棵树是 inode 树才能对它判 I-9**，而树表条目里有什么字段全仓零落点。
  处置：I-9 各条的状态列写「前置：树的种类可识别」；第一版镜像上可由类型 2 容器头里的出生树反推「哪棵树是 inode 树」，checker 不至于空转。
- **新开 D8 未定项 8「树表条目」**：树 ID 的分配与编码、树的种类、根指针以外还有什么。取代第四版「只开树 ID 分配」那一条。
- **`deleted_inodes` 树的形态**（key、记录、树 ID、第一个事务建不建）全仓只有 D8 已定项 5 一句话。本项只定一条读法：**inode 记录在回收完成前留在 inode 树里（nlink = 0），`deleted_inodes` 只存号**；它自己的形态立成欠账。I-9.5 / I-9.6 按这条读法改写。

### P4 容器身份

- **唯一性的射程**：「唯一性由构造保证」只在**一条已发布历史内**成立。崩溃后 txg 重发（D5:20「崩溃后该号会被重发」）会让被抛弃那版与重试那版四段逐字相同、内容不同、都在盘上——
  这与数据单元的五元组、码 2 节点的 (树, 层级, 诞生代号) 是同一种暴露（根记录靠 D16 骑手条款 1 的实例代号分辨，别的单元类都没有），常规路径由 D3 已定项 1 的谓词（分配记录）判、扫描重建路径归 C113，本项把它写成 C113 的一条**必然可达**的实例，不给容器单独加实例代号。
- **分裂产生的新容器，出生树 = 执行这次分裂的那棵树**（分裂是新建，与「COW 重写身份不变」不同）。
- **合并的方向进不变量**：只许左吸收右 / 左从右借（I-9.4 逼出来的），时机才是写路径策略。
- 填充率没有下界：`⌈n/233⌉` 是新建树的值，删除后不合并时 1e6 删 90% 是 9.98 倍空间放大；写进 E103 与 C100 的口径注。

### P5 水位

- **取最大值胜过「后者胜」的真正理由**是崩溃 + txg 重发那一格：同一个代段里先后出现大小两个值，取最大值给大的（浪费号，不复用号）。「未发布的等于没发生」只对常规挂载路径成立。
- **水位行只为可写头维护**，随每次发布重写（D5 已定项 2 的 K 代点删要求每行每发布重写，第 8 / 9 项同）；只读树没有这一行。
- **读现行值 = 取该维度元组下代号最大的那一行；空 ⇒ 从未维护过，不是 0**——D5 没写这条，与「新建树的记账行初始化」「设备段保留值」一起是 D5 的既有空白（C117）。
- **统计量登记表（标签值 + 维度 + 合并规则）立成独立的已冻结组件**（与记录格式同一处置，C9 按组件记）：合并规则是盘上语义，两个读者对同一批字节用不同规则会得到不同的值，四层里没有一层装得下它；C71 只罩「不认识的标签」，罩不到「认识标签但用错规则」。
- I-9.11 拆开：可判的那半（每个可写克隆头都有水位行）留下；「≥ origin 那一刻的水位」是建克隆那一刻的操作断言，转模型对拍——它的右操作数在 K 次发布后被点删，读不到。

### P6 记录

- 不变。E103 kb 里「k ≥ 10 多的正好是 2 个节点」改成「k = 1000（饱和格）差值恰为 2 个节点 65536 字节；k = 10 / 100 差 4104 / 60560 字节，随批量趋近」。
