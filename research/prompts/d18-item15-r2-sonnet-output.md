## 二、甲′：栅栏证明补全五种操作 + 跨层变高变矮

**背景材料给出的证明**（`d18-item15-r1-opus-output.md:1264-1267`，核过）：

> 「为什么『被压住』恰好等于『不在 X 里』（推的，给判据 1 的正推）：设 V 在谱系 L 的层级 ℓ−1、诞生 b_V ≤ b_X。(⇐) V 不是 X 的子项 ⇒ V 在 b_X 之前某一刻 t_r 被替换；t_r 那次发布之后，V 的区间里每一点都被当时树里的某个层级 ℓ−1 节点覆盖（铺满），那个节点诞生 ≥ t_r > b_V ⇒ V 被压住。(⇒) V 是 X 的子项 ⇒ V 从 b_V 到 b_X 一直在树里；若有 V′ 诞生于 (b_V, b_X] 且区间与 V 相交，则 b_V′ 那一刻 V 与 V′ 同层、区间相交地同在一棵树里，与铺满（无叠）矛盾；诞生相等的 V′ 由 B5 排除 ⇒ V 不被压住。∎ 这个证明要的只有：线性谱系（B4）、已发布（B1）、铺满、B5。」

这个证明是**存在性 + 单射性**的一般证明，不逐操作分类；本轮按任务要求逐操作补一遍，检验是否都落在这个一般证明的覆盖范围内。

### 2.1 分裂

分裂：旧节点 V（区间 I_V，诞生 b_V）在 t_r 时刻分裂成 V_left（区间 I_V 的左半，沿用旧号或无号，诞生 t_r）与 V_right（区间 I_V 的右半，诞生 t_r）。两个新节点区间之并 = I_V，铺满旧区间；V 从此不再被任何指针引用。**推的**：这恰好是证明 (⇐) 方向要求的「V 的区间里每一点都被当时树里的某个层级 ℓ−1 节点覆盖，那个节点诞生 ≥ t_r > b_V」——V_left 与 V_right 各自的诞生都是 t_r，覆盖各自那一半，合起来铺满 I_V。**不红**。

### 2.2 合并

乙′ 定义的合并纪律「左吸收右 / 左从右借」（`.claude/kb/decisions/08-核心索引结构.md:327-434`，核过：「合并：只许左吸收右 / 左从右借（右吸收左或右从左借会破『记录号 ≥ 容器号』）」，这条纪律写在 D8 已定项 6 给 inode 树叶容器定的，但其“左吸收右”的方向约束是否对码 2 内部节点通用，仓里没有单独条款——**这是甲′证明的一个隐含假设，本轮标出**：只要合并后产生的新节点（诞生 = 合并发生的 txg）区间覆盖原两个节点区间之并，证明就成立，方向（左吸收右还是右吸收左）不影响铺满结论。**不红，但补一条推的假设**：码 2 内部节点合并时，新节点的区间必须覆盖被合并两节点的区间之并——这本身应做成一条不变量（今天没有），否则若合并后遗漏一段 key（实现 bug），铺满断言会在合并之后立即抓到（因为不再铺满，判「不可重建」），所以这不是甲′独有的风险，而是判据 3 里「新不变量」本身要交付的检查。

### 2.3 借位（rebalance / borrow）

借位：左邻居把自己最后几个条目移给右邻居（或反之），双方区间都变化，双方都要 COW（各自诞生新版本，诞生 = 借位发生的 txg）。**推的**：借位后左右两个新版本的区间之并仍等于借位前两者区间之并，铺满性质保持；旧的左、右版本都被各自新版本压住（诞生 ≥ 借位 txg > 旧版诞生）。**不红**。

### 2.4 删空移走

背景材料明确的规则（`d18-item15-r1-opus-output.md` 甲′ 表）：「节点删空后要被移走时，邻居的区间必须扩过来（邻居因此被 COW 一次）」。设被删空节点 B（区间 I_B，诞生 b_B）在 t_r 时被移走，邻居 C 从 I_C 扩为 I_C ∪ I_B（诞生变为 t_r）。**这正是第一轮字面甲变红的那一格**（序列 A1：「inode 树里节点 B 删空后从活头移走，快照 S 仍引用 B@90」），本轮需要检验 甲′ 是否真的修复了它。

**具体场景（本轮构造，作为对判据 1 的正推）**：
- 谱系 L（inode 树某一支），层级 ℓ = 1（叶的直接父节点）。
- 节点 X（层级 2，X 的一个子节点是 B）诞生于 txg = 80，区间 I_X = [1, 200]，此时 X 的两个层级 1 子节点是 B（区间 [1, 100]，诞生 70）与 C（区间 [101, 200]，诞生 70）。
- txg = 90：X 下的所有 inode 都还在，快照 S 建立，S 的树表条目指向此刻的 X（诞生 80，即 X 未变）——注意此处 X 本身没有变化，S 引用的正是 X（80）本身，不是 X 的某个子节点单独被引用；下面把 B 也纳入快照引用范围来体现"B 被快照 S 引用"这一读法。
- txg = 95：活头把 B 里的全部 inode 记录删空，B 被移走；C 的区间扩为 [1, 200]（吸收 B 的区间），C 的新版本 C′ 诞生 95；X 因子节点变化被 COW，产生 X′（诞生 95，区间仍 [1, 200]，唯一子节点 C′）。
- txg = 100：活头继续写，X′ 所在路径上又有变化，此时假设 **X′ 本身**（诞生 95）成为丢失节点（磁盘损坏），我们需要重建 X′ 的子项。

**代入 甲′ 的挑法**：X′ 的诞生 b_{X′} = 95，区间 I_{X′} = [1, 200]。候选层级 1 节点里，诞生 ≤ 95 且区间 ⊂ [1, 200] 的有：B（诞生 70，区间 [1,100]）、C（诞生 70，区间 [101,200]）、C′（诞生 95，区间 [1,200]）。判「被压住」：B 是否被压住？——存在 C′，诞生 95 ∈ (70, 95]，区间 [1,200] 与 B 的 [1,100] 相交 ⇒ B 被压住，排除。C 同理被 C′ 压住，排除。**唯一未被压住的候选是 C′**，铺满 [1, 200]。⇒ 甲′ 挑出的子项 = {C′}，**这正是 X′（95）诞生那一刻的真实子项**，不是 B@90。

**这里回答了第一轮 A1 场景的疑虑**：字面甲变红是因为它没有 B3（T 取被重建节点自己的诞生代号）与铺满这两条约束，才会把 B@90 挑回「活头」的语境（把 R 的 txg 当成 T，或者不要求铺满）。甲′ 通过「T = X′ 自己的诞生 95」+「铺满」两条约束，正确地只挑出 C′，B 因为诞生更早且被诞生更晚、区间相交的 C′ 压住而被排除。**判据 1：不红**，这是本轮对第一轮「甲字面红」的一次正面澄清（不是推翻第一轮判决——第一轮判的是字面甲，本轮判的是甲′，两者本就是不同的臂）。

**快照 S（诞生 90）如果丢失、需要重建它引用的 X（诞生 80）呢**：S 引用的 X 诞生 = 80，b_X = 80（不是 S 的 txg 90，这是 B3 的要求：T 取被重建节点自己的诞生代号，不取 R 的 txg）。此时候选：诞生 ≤ 80 的层级 1 节点里，B（诞生 70）与 C（诞生 70）都合法且没有被诞生更晚、区间相交、诞生仍 ≤ 80 的版本压住（C′ 诞生 95 > 80，不在候选范围内）。⇒ 甲′ 挑出 {B, C}，铺满 [1,200]。**这才是 X（80）真实的历史子项**，B 仍然健在（此处 X 是被 S 引用的那个更早版本，不是被活头引用的 X′）。⇒ 判据 1：不红，且这正是 B3「快照与活头共享 X 时一次重建同时对两边成立」的具体例证：**这里 X 与 X′ 是两个不同的节点实例**（诞生不同），各自独立重建，互不干扰。

### 2.5 跨层变高变矮

任务要求补全这一步，背景材料的证明（`d18-item15-r1-opus-output.md:1264-1267`）与 B2（`d18-item15-r1-opus-output.md:1246`：「按层全局挑会把树变矮之前的旧根挑回来；自上而下只在一个节点的范围内挑，不会」，核过）都没有显式处理层级编号在树高变化时是否保持稳定。**这是本轮新增的论证，标「推的」**：

- **命题**：节点的「层级 ℓ」字段（写入 D18 已定项 11 类身份段：「树 ID + 层级 + key 区间 + …」，核过）是按**到叶子的距离**计数（叶 = 0），而不是按「到当前根的距离」计数。
- **论据**：（a）B-tree 分裂/合并只发生在树的顶端（根分裂产生新根、根收缩把唯一子节点提升为新根），不发生在树的中部——这是标准 COW B+-树实现的隐含假设，`.claude/kb/decisions/08-核心索引结构.md` 与 `19-块指针的结构与宽度预算.md` 均未显式声明这一点，本轮标「推的（未在仓里找到反例，也未找到正面声明）」。（b）若层级按「到叶距离」计数，则任一节点的层级是它自身的静态属性，跟树的当前高度、当前根在哪无关；根分裂/收缩只影响「谁是根」这件事，不改变任何既有节点的层级号。
- **推论**：设 X 是层级 ℓ 的丢失节点，我们要挑层级 ℓ−1 的候选子项。即使在 X 诞生之后树发生了根分裂（树变高）或根收缩（树变矮），只要 X 自身没有被 COW（X 仍是原来那个节点实例，诞生 = b_X 不变），X 的子项范围与层级判据都不受影响，因为「层级 ℓ−1」这个筛选条件是按叶距离算的静态值，不随根的位置变化。
- **唯一需要警惕的情形**：如果 X **自己**恰好是树的根、且树在 X 诞生之后**收缩**（X 唯一的子节点被提升为新根，X 本身被替换/废弃），那么 X 已经不再是任何在用指针的目标，此时「X 丢失」这件事本身无从谈起（没有指针指向它，也没有必要重建它）。若 X 诞生之后树**变高**（在 X 之上插入新根），X 自己的层级号不变（仍是 ℓ），只是它头顶多了一层，这不影响对 X 子项的挑选。**判据 1：不红**，但依赖的静态层级假设本轮标为「推的」，未在 `.claude/kb/decisions/08-核心索引结构.md` 或 `19-块指针的结构与宽度预算.md` 找到逐字确认，这是一条应当补齐的显式声明（归入本轮判据 6 的欠账）。

### 2.6 甲′ 判据 1 的射程总结

非克隆、非固定点同 checkpoint 多版场景下，2.1–2.5 五种操作 + 树高变化都能被「铺满 + 诞生序 + B5 排除同诞生并列」的一般证明覆盖，**判据 1：不红**。克隆场景与固定点多版场景，甲′ 与另两臂一样判不出（见第三节），**判据 1：只记**。

## 三、判据 4：B4、B5 前置卡在哪，三臂在这两格上判不出

### 3.1 克隆格（B4）——失败条款 3 的触发观测

**B4 原文**（核过，`d18-item15-r1-opus-output.md:1248`）：「谱系：码 2 头里的树 ID 读成出生树（写出它的那棵树）；对非克隆的树 w，候选只取树 ID = w 的版本；w 是克隆时另取 origin 树里诞生代号 ≤ 分叉 txg 的版本 | … 分叉 txg 与 origin 树 ID 在树表里没有载体（D8:462 条目布局、D8:420 单头射程，核过）⇒ 克隆那一格要克隆祖先表先落地」。

**本轮现查坐实**（D8 已定项 6，`.claude/kb/decisions/08-核心索引结构.md:1006-1008`，核过）：「射程是单头镜像：有克隆头时共享叶头里的出生树是 origin（I-1.3 的 C110 那一格），按出生树认领会把克隆头的树认残——多头镜像的归属划分要克隆祖先表（E90 第二笔），落地前多头镜像的 inode 树重建没有输入。」——**这是原封不动的“落地前多头镜像的 inode 树重建没有输入”这句话，正是 B4 引用的 D8:420**。

**构造一个克隆序列（本轮构造，作为失败条款 3 的触发观测）**：
- txg = 10：origin 树 O 的 inode 树内部节点 X_O（区间 [1, 100]，诞生 5）存在。
- txg = 11：从 O 克隆出头 H（分叉 txg = 11）。H 与 O 此刻共享同一批叶与内部节点，包括 X_O（头 H 的 X_O 副本头里“树 ID”字段仍是 O 的树 ID，因为按 B4「码 2 头里的树 ID 读成出生树」）。
- txg = 20：H 的活头把区间 [1, 50] 的一批 inode 删空，触发 X_O 在 H 这一侧被 COW，产生 X_H（区间 [1, 100]，诞生 20，树 ID 段仍记出生树 = O，按 B4）。
- txg = 30：O 自己也继续写，O 的 X_O 因自己的更新被 COW 成 X_O′（诞生 25，区间 [1, 100]）。
- txg = 40：H 的 X_H 丢失（磁盘损坏），需要重建。X_H 的诞生 b = 20，X_H 头里的树 ID 段 = O（出生树）。

**按 B4 的规则**：「w 是克隆时另取 origin 树里诞生代号 ≤ 分叉 txg 的版本」——分叉 txg = 11，取 origin 树（O）里诞生 ≤ 11 的版本，即 X_O（诞生 5）。但 X_H 真正丢失时要重建的是**它自己**（诞生 20）的子项，不是 origin 树诞生 ≤ 11 那个更早版本的子项——B4 这一句是用来判断「X_H 与哪些别的（可能被 O 侧持有的）节点共享谱系」，而不是直接给出 X_H 本身诞生 20 时的子项。为了正确重建 X_H 的子项，甲′/乙′的挑法需要在「谱系 L」这个变量上填入**正确的谱系**——而谱系在克隆场景下不再是单一的树 ID，需要靠**分叉 txg + origin 树 ID**来限定哪些候选节点属于「H 这条谱系在诞生 20 时刻能看到的」历史（即 origin 树上诞生 ≤ 11 的部分 + H 自己诞生 ∈ (11, 20] 写出的部分）。

**问题所在**：分叉 txg（这里是 11）与「H 是从 O 克隆而来」这件事本身，在树表条目里没有字段记录（D8 已定项 8 的树表条目字段表——第 194 字节那一版，`.claude/kb/decisions/08-核心索引结构.md:1042-1046` 核过——没有「origin 树 ID」「分叉 txg」这两个字段）。**没有这两个字段，重建时无法回答「X_H 的候选子项池，应该到 origin 树 O 的哪个 txg 为止去找、超过这个 txg 之后 O 自己写出的版本要排除」这个问题**——甲′、乙′、丙都要用到这条界线（B4 的「诞生代号 ≤ 分叉 txg」）。

**具体挑不唯一的展示**：假设 X_H 层级 1 的某个子节点 Y 在 origin 树 O 上于 txg=15（H 分叉之后、X_H COW 之前）被 O 自己重写成 Y′（诞生 15，与 Y 区间相同）。若重建时不知道分叉 txg=11，按「谱系 L = O」朴素地扫描 O 树上诞生 ≤ 20（X_H 自己的诞生）的所有候选，Y′（诞生 15）会被误当作候选纳入——而 Y′ 其实是 O 分叉**之后**自己的新版本，不属于 H 这条克隆谱系在 20 时刻应该看到的历史（H 应该看到的是 Y，诞生 ≤ 11 那一版）。**⇒ 挑出的集合把不该属于 H 的版本（Y′）也纳入，或者反过来因为不知道分叉点而无法排除，两种失效方式都成立，取决于实现怎么兜底；无论哪一种，"挑得唯一"这条判据在缺少分叉 txg 载体时就判不出（不是判红，是没有输入可判）。**

⇒ **三臂在克隆场景下都判不出**（判据 4：只记），且**这正是背景材料失败条款 3 要求的触发观测**：「一个克隆序列，三臂都挑不唯一，并引到树表条目布局里没有分叉 txg 的原文」——本节给出的序列 + 引用 D8:420、D8:1042-1046（树表条目字段表没有分叉 txg / origin 树 ID 字段）满足这个要求。**失败条款 3：触发。**

### 3.2 固定点同 checkpoint 多版格（B5）——失败条款 2 的触发观测

**B5 原文**（核过，`d18-item15-r1-opus-output.md:1249`）：「同一 (谱系, 层级, 身份, 诞生代号, 实例代号) 只许有一版：派生态、会被快照 / 克隆引用的那几棵树（extent、inode 内部节点、将来的 dirent），每个码 2 节点一个实例在一个 checkpoint 里只写出一次；扫描时撞上两组可读版本载荷不同 ⇒ 判损坏，不择 | C163 处置候选（checks-owed.md:174，核过）的一个子集…」。

**C163 原文**（核过，`.claude/kb/checks-owed.md:174`）：「I-1.8 给码 3 的全序键是 (诞生代号, 实例代号, 事务号)，并逐字说『事务号留在末位做同一 checkpoint 内的平局破除，固定点会迭代、同一容器在一个 checkpoint 里不保证只写一次』；而 D18 已定项 7 的取号规则逐字『容器只在 checkpoint 的固定点写出，事务号取那次 checkpoint 里已分配的最大事务号』。……⇒ 同一 checkpoint 内两版容器的写序逐字节相同，那个平局破除给不出任何判别力。⚠️ 同一个洞对码 2 逐字成立，而码 2 那 6 字节事务号唯一可能的用途就是这个平局破除」。**这条也已被 D18 已定项 12（2026-09-07）收口：码 2 的 6 字节事务号已经被砍掉，改给载荷 CRC 与预留**（`.claude/kb/decisions/18-块里携带什么信息.md:190-224`，核过：「C113 定案（2026-09-05）给三类单元统一加了 10 字节写序，码 2 上那 6 字节事务号今天零使用」）——**这意味着码 2 今天连「事务号」这个字段都没有，C163 那句「同一个洞对码 2 逐字成立」描述的是历史状态；今天码 2 的写序只剩 4 字节实例代号，根本不存在「事务号平局破除」这条机制，C163 处置候选（每个码 2 节点一个实例一个 checkpoint 只写一次）就是唯一能让码 2 在固定点多版下分得开的出路**——这与 B5 的表述完全一致（B5 就是把 C163 处置候选套到码 2 身上）。

**构造一个固定点多版序列（本轮构造，作为失败条款 2 的触发观测）**：
- 提交固定点按 D3 已定项 5（`.claude/kb/decisions/03-空间分配.md:171-188`，核过：「提交自身产生的块……必须从……聚簇段分配」）与 E81（提交的固定点）的模型「已脏节点本次发布只 COW 一次（假设发布末尾一次性 COW）」运行，但 D3 已定项 5 同时点名「边插边 COW」是合法但更贵的实现（`.claude/kb/decisions/03-空间分配.md`，核过：「E81 给的是下界（假设发布末尾一次性 COW），边插边 COW 的实现更贵」）。
- 设记账树的一个码 2 内部节点 M（区间 [统计量段范围]，诞生 T−1）在 checkpoint T 的固定点里，第一轮迭代因分配记录树的新增节点而被 COW 成 M₁（诞生 T，实例代号 i）；第二轮迭代因 M₁ 自己产生的分配记录又触发对同一段 key 的再次插入，M₁ 被再次 COW 成 M₂（诞生 T，实例代号 i——**同一实例，同一诞生**，因为按现行规则诞生代号 = checkpoint_txg，两轮固定点迭代都发生在同一个 checkpoint 内）。
- 只有 M₂ 最终被发布的根引用（M₁ 是被 M₂ 取代的中间版本，从未被任何根引用过，是判据 2 意义上的垃圾——这与材料第二节「正面回答」逐字一致：「已发布的根引用的恰好是每个位置最后写出的那一版；中间版在盘上、诞生代号与实例代号和最后一版相同…可它们从来没被任何根引用过，是判据 2 意义上的垃圾」）。
- 现在设 M₂ 本身（连同 M₁）都在磁盘上可读，但**指向 M 这一层的父指针本身丢失**——即需要重建的是 M 的父节点 P（层级更高），P 需要在 M₁ 与 M₂ 之间挑出正确的现行版本。

**代入甲′的挑法**：M₁ 与 M₂ 的诞生代号、实例代号逐字段相同（都是 T、i）。甲′的判据「没有被一个诞生更晚（仍 ≤ b_X）且区间相交的版本压住」——M₁ 与 M₂ 诞生相同（不是「更晚」），铺满关系也相同（假设两者区间相同，都覆盖同一段 key），**无法用诞生序分辨谁压住谁**；B5 明确要求「同一 (谱系, 层级, 身份, 诞生代号, 实例代号) 只许有一版：……扫描时撞上两组可读版本载荷不同 ⇒ 判损坏，不择」——**但这要求 M₁ 首先不应该存在（不允许多版），而不是给出一个能分辨 M₁/M₂ 的挑法**。若 B5 这条纪律没有真正落地（今天仍是待用户复核的处置候选，见 checks-owed.md C163 状态列「待用户复核」），M₁ 与 M₂ 会同时出现在候选池里，甲′、乙′、丙**都无法唯一确定该挑哪一版**（乙′同样靠诞生代号 + 实例代号排最新版，遇到并列时同样卡住；丙继承甲′的问题）。

⇒ **三臂在固定点同 checkpoint 多版场景下都判不出，且都明确依赖 B5**——这正是失败条款 2 要求的触发观测：「一条腿说明去掉 B5 三臂都挑不唯一，并引到 C163 原文」。**本节引用了 C163 原文与构造了具体序列，满足触发条件。失败条款 2：触发。**

⚠️ **本轮对材料第二节「这一格有多宽」的核实**：材料称「固定点多版本身落不到这一项的射程里；落进来的是『per-head 树的节点在同一 checkpoint 写两次』」（`d18-item15-r1-opus-output.md:1312-1313`，核过）。本轮构造的场景正是「记账树的码 2 节点在同一 checkpoint 内被固定点迭代反复弄脏」——记账树按 D21（`.claude/kb/decisions/21-权威态与派生态的分界.md:1-14`，核过：「权威态 | 单元 + 记账 + 根」）是权威态，但**记账树的码 2 节点本身仍然是索引节点（码 2），仍然要走扫描重建的父子关系挑选**——材料这句「记账树是权威态，不在射程」说的是"记账的统计值不需要在容器级择版本"（`.claude/kb/decisions/18-块里携带什么信息.md`，核过：「记账树的节点是权威态，但它的条目取幂等完整值……多版在条目级合并……不需要在容器级择版本」），**这与"记账树的码 2 节点在固定点多版下要不要被丢失重建"是两个不同的问题**——记账树节点若因磁盘损坏而丢失（本节场景），仍然需要靠父子关系重建，此时"条目级合并"救不了它（条目级合并解决的是"读现行值不用择版本"，不解决"节点整体丢失、无法读到任何条目"这个问题）。**这是本轮发现的材料表述的一处易混淆点，但不构成材料的错误**：材料原句本身没有说错（它说的是"记账树不需要在容器级择版本"这个既有结论，仍然成立），只是它举的"这一格有多宽"的分析没有覆盖"记账树节点本身因物理损坏而需要重建"这一子情形——这个子情形和 per-head 树一样，都落在 B5 的射程里，本轮把它并入第五节"材料的错"一并记录。

## 四、乙′的判据 1/2/3 与代价（第二节未覆盖的部分）

**判据 1（非克隆非固定点场景）**：见背景材料自身证明摘要（`d18-item15-r1-opus-output.md:1279`，核过）：「对丢了的节点 X：它的子项 = 层级 ℓ−1、谱系 L 里的节点号 n，满足 n 在 b_X 之前没有退役、n 的『诞生代号 ≤ b_X 的最新版本』存在、且那一版的实际 key 范围（从它自己的条目算）⊂ I_X」。本轮补充第二节 2.1–2.4 的具体操作检验：

- **分裂**：右半获得新号，节点号具备"COW 保留、分裂换号"的性质（`d18-item15-r1-opus-output.md:1277`，核过：「分裂：左半保留原号，右半取新号」），不影响判据 1——右半新号是全新分配，不与任何既有候选冲突。
- **合并/删空移走**：这正是退役记录的用武之地——「右半的号写一条退役记录：(树, 层级, 节点号, 退役 txg)」（同上，核过）。第一轮已经查明：「乙′里承重的是退役记录，不是节点号：去掉退役记录，合并后被吸收的那个号的旧版照样被挑中（序列 A1）」（`d18-item15-r1-opus-output.md:1283`，核过）。**本轮验证退役记录本身是否足以堵住 A1**：延续第二节 2.4 的场景，B 在 txg=95 被移走并退役（写退役记录 (L, 1, n_B, 95)）；若要重建的是活头一侧、诞生 95 之后的某个更高层节点，判据「n 在 b_X 之前没有退役」——若 b_X ≥ 95，n_B 因为退役 txg=95 ≤ b_X 而被排除，**不会**被误挑回活头；若 b_X < 95（重建的是快照 S 那一侧、b_X=80 的节点），n_B 的退役 txg=95 > b_X=80，判据「未退役」为真，B（诞生 70 ≤ 80）合法当选。**两种情形都对，判据 1：不红**。
- **跨层变高变矮**：与甲′同理（第 2.5 节的静态层级假设），乙′同样依赖这条推的假设，未在仓里找到显式声明，一并记入判据 6 的欠账。

**判据 2（不挑到垃圾）**：退役记录的生命周期「要活到盘上不再有该号诞生代号 < 退役 txg 的版本为止」（`d18-item15-r1-opus-output.md:1278`，核过）——这意味着只要退役记录本身还在，垃圾版本就挡得住；退役记录被清理后是否会有旧版本"复活"，取决于清理时机是否正确（这是一条操作纪律，不是格式条款，本轮标记为判据 6 里的欠账：退役记录的清理时机全仓未定，若清理过早（还有诞生 < 退役 txg 的版本在盘上未被物理回收）会重新打开 A1 那个洞）。**判据 2：不红，但附带一条新欠账**。

**判据 3（相容性）**：见结论表分析，重开 D18 已定项 12（码 2 写序 4 字节）与已定项 7（码 2 字段表）需要用户复核（材料未定项 15 原文自陈：「答案若要给码 2 头加字段，会动 D18 已定项 12……与已定项 7 的码 2 字段表，要记复核」，`.claude/kb/decisions/18-块里携带什么信息.md:886-891`，核过）。**是否撞 D18 已定项 1 的射程句**——本轮论证：已定项 1 否掉的是「为分辨陈旧副本而设的序号」（`.claude/kb/decisions/18-块里携带什么信息.md:150-164`，核过：「射程：定案否掉的是『为分辨陈旧副本而设的序号』」），乙′的节点号功能是"跨 COW 重写维持稳定身份，供丢失节点重建时挑选历史版本用"，**不是**用来分辨同一节点的哪个物理副本是陈旧的（那件事仍由诞生代号 + 实例代号 + B1 的已发布谓词负责，乙′完全没有改动这条机制）——两者用途不同，本轮判定**不冲突**，但这是本轮的论证（推的），材料与仓里原文都没有现成结论，重开时需要向用户明确讲清这条区分（这正是已定项 1 自己要求的：「重开的人得先说清它买的不是已经买到的那件事」）。

**代价**：每个码 2 头 +8 字节（节点号），加上退役记录的写放大（`d18-item15-r1-opus-output.md:1279`，核过：「代价：每个码 2 头 +8，另加退役记录的写放大（没量）」）——本轮未能补上这个"没量"的数字，仍然是欠账。

## 五、丙：甲′ + B6 门

丙继承甲′的全部判据 1/2/3 分析（第二、四节）。判据 5（门的失效面）已在结论表标注：**本轮未能把失效面收窄到一个可判定的小概率区间**。以下是本轮为收窄所做的尝试，以及为什么没有成功：

**尝试一：把位置提示排除在头校验和覆盖范围之外**。若节点头的序列化在计算/验收校验和时不包含位置提示字段（视其为不可信的缓存值），则子节点被后台整理搬迁后，重建 X 时序列化出的字节可以合法地填一个"占位值"而不影响校验和匹配。**问题**：这要求头校验和的覆盖范围从"整个明文头"改为"排除某个字段"，而现行头校验和覆盖范围是（D18 已定项 11，`.claude/kb/decisions/18-块里携带什么信息.md:711`，核过）：「覆盖从偏移 0 到该类明文头最后一个字节，端点随……字段表走」——这是一条已定条款，要单独排除某个字段需要重开这条定案，且需要证明"排除位置提示不会打开新的伪造窗口"（位置提示虽然只是提示，但若头校验和不覆盖它，攻击者可以在不破坏校验和的前提下篡改位置提示，把读者导向错误的物理位置——这本身是否构成安全问题，取决于读到错误位置之后校验和/MAC 能否兜底，本轮没有把这条论证走完，**判定：这条收窄路径未能成立，标为推的且未完成**）。

**尝试二：限制后台整理不许搬迁"仍在近 K 代根引用范围内"的码 2 节点**。I-7.4（近 K 代块未被复用，`.claude/kb/invariants.md:49`，核过：「最近 K 代有效根所引用的块，其物理范围均未被重新分配给其他对象、也未被清扫抹头」）已经保证这类块不被**重新分配**，但**没有**保证它们不被**搬迁**（重新分配 ≠ 搬迁——D5 已定项 2026-09-06 明确区分「搬迁不改 birth」这件事本身就说明搬迁是一个独立于分配状态的操作，`.claude/kb/decisions/05-快照-空间记账机制.md:817-823`，核过）。**判定：I-7.4 管不到这一格，这条收窄路径不成立**。

⇒ **判据 5 的诚实结论**：丙门的失效面（丢失节点诞生之后其子项被搬迁）今天没有已知的收窄手段，其发生频率完全取决于后台整理（D26）的搬迁策略——若 D26 的搬迁频率高（例如老化整理经常触碰码 2 节点），丙会把相当一部分重建请求打回只读，这与丙"倾向"理由里说的"即使甲′那条栅栏证明有漏洞，门也拦得住"是一个真实的权衡：**门带来的安全性是用可用性换的，而这笔换算今天没有数字**。这与材料第五节自己写的"反过来"条件一致：「若门的失效面（子项被搬过）在后台整理下是常态 ⇒ 丙大部分格子只读，取乙′或甲′」——本轮未能证伪这个"反过来"条件，也未能证实它，**只记**。

## 六、对第一轮核实与判决的复核

## 八、总结与建议

按失败条款 2、3 均触发，本轮的建议（与材料第四节自身指出的处置路径一致）：
1. 这一项（D18 未定项 15）**不宜在甲′/乙′/丙三选一定案**，因为三臂共同依赖的 B5、B4 两个前置都未落地，选哪一臂都无法回答"固定点多版怎么办""克隆怎么办"这两个真实存在的场景。
2. 固定点多版那一半应与 C163（固定点各轮写序相同使平局破除落空）并案，并且 C163 的处置候选文本需要按本轮第三节 3.2 的发现更新——码 2 今天已经没有事务号字段（已被 D18 已定项 12 砍掉），C163 原文里"同一个洞对码 2 逐字成立"这句话描述的是历史状态，处置候选的现行意义是"直接采纳每个码 2 节点一个实例一个 checkpoint 只写一次"这条纪律本身，而不是在事务号之外另找判别子。
3. 克隆那一半的射程应收窄到非克隆树，克隆场景挂到"克隆祖先表"（分叉 txg + origin 树 ID 的载体）这条已有欠账（C110）上，与该欠账同时到期。
4. 在这两个前置都落地之前，甲′（对非克隆、非固定点场景）已经证明可以正确工作（第二节），是三臂中**代价最小、不需要重开任何已定项字段表**的选项，若用户要求"先给一个能覆盖大多数场景的最小改动"，本轮的正推分析支持甲′单独先行——但这是本轮作为正推腿给出的倾向性建议，不构成定案依据本身。
