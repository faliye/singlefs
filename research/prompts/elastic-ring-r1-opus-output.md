## 一、K1：缩环在 COW 上做不做得到

### K1-1 缩环改的不是一个参数，是「记录在哪」这个函数本身

`crates/singlefs-core/src/journal.rs:107-114` 逐字：

```
/// 记录 n 落在环内偏移 `(计数器 − 1) mod 槽数 × 4096`（D23（journal 的角色与格式） 已定项 18）。
#[must_use]
pub fn record_offset(counter: u64, ring_bytes: u64) -> DeviceOffsetInBytes {
    let ring_slots = ring_bytes / JOURNAL_RECORD_BYTES;
    DeviceOffsetInBytes(
        JOURNAL_RING_START_SLOT * SLOT_BYTES + ((counter - 1) % ring_slots) * JOURNAL_RECORD_BYTES,
    )
}
```

扫描那一侧同一个量当上界，`crates/singlefs-core/src/recovery.rs:850` 逐字：

```
    let ring_bytes = system_configuration.immutable.sizes.journal_ring_bytes;
```

⇒ **缩环这个动作，盘上的字节一个都不用动，改的只是「用哪个模数解读它们」与「扫到哪里为止」。**
一条写在 R 环里、还没被重放的记录 c，缩到 R_后 之后还找得到，当且仅当它的旧位置
`(c−1) mod S` 落在 `[0, S_后)` 里（S、S_后 是缩前缩后的槽数）。落在外面的，`scan_journal`
根本不去读那个偏移，`replay_journal` 的「断号即止」当场停在它前面——**一次已经提交、
已经回过 fsync 的发布就这么没了，没有任何一条今天写下来的检查会红**。

模型一（`shrink_replay_model.py`，纯算术，把上面两个函数原样抄成 python）逐格扫「缩的时候
水位停在环的哪一格」——那一步由用户写了多少决定，不由装置定，所以 512 个残差点全扫：

```
| 旧环 | 新环 | 在飞深度 | 取样点 | 施加 0 条的取样点 | 全部施加的取样点 | 施加条数均值 | 解析：施加 0 条的残差比例 | 解析：全部施加的残差比例 |
|---|---|---|---|---|---|---|---|---|
| 768 MiB（196608 槽） | 64 MiB（16384 槽） | 16 | 512 | 469 | 43 | 1.34 | 0.9167 | 0.0833 |
| 768 MiB（196608 槽） | 256 MiB（65536 槽） | 16 | 512 | 341 | 171 | 5.34 | 0.6667 | 0.3333 |
| 768 MiB（196608 槽） | 384 MiB（98304 槽） | 16 | 512 | 256 | 256 | 8.00 | 0.5000 | 0.4999 |
| 256 MiB（65536 槽） | 64 MiB（16384 槽） | 16 | 512 | 384 | 128 | 4.00 | 0.7500 | 0.2498 |
```

（全表 21 行在 `shrink_replay_model-output.txt`。取样是均匀网格，`768 → 767 MiB` 那三行
「施加 0 条 0 次」是网格粗（512 点、步长 384 槽）扫不到那 0.13% 的残差，解析列给的
0.0013 才是那一格的数——**别引取样列，引解析列**。）

**可达的历史**（每一步指到许可它的那一句）：

1. mkfs 默认环 768 MiB（`23-journal的角色与格式.md:460`「环长是 **mkfs 参数**，**默认 768 MiB**」）。
2. 正常跑，counter 涨到 c，其中最后 d 条已提交、根还没推到（在飞深度 d ≤ 在飞上限
   `环 ÷ 4096 ÷ F`，`crates/singlefs-format/src/lib.rs:167-170`）。
3. 空间不足，按乙第 3 条缩环到 64 MiB（候选乙逐字「空间不足时缩环，缩到 `I-8.1（环几何够大）` 给的硬下界为止」）。
4. 缩完立刻崩（或缩完再崩，一样）。
5. 挂载：`choose_system_configuration` 读到新环长 64 MiB → `scan_journal` 只扫前 16384 槽 →
   那 d 条里 91.67% 的残差位置读不到 → 断号即止 → 已确认的写丢。

**乙 要补的条款**：缩环之前必须把「水位之上那一段」整体搬进新环的范围内，或者先把它重放完、
把根推到 c 为止再缩。这句话今天的条款里一个字都没有。

### K1-2 缩环不能由 journal 保护：自指

`crates/singlefs-core/src/mount.rs:1122` 与 `1125` 逐字（同形状的两处还在 617、1202 / 1205）：

```
    let system_configuration = choose_system_configuration(&*devices)?;
    let records = scan_journal(&*devices, &system_configuration);
```

顺序是硬的：**先有系统配置里的环长，才找得到 journal 记录**。所以环长是一个「journal 之前」的量，
它不可能由一条 journal 记录来改——那条记录自己的位置由改之前还是改之后的环长定，没有答案。

⇒ 问题「缩环这个动作要不要事务」的答案是：**要，但不能是 journal 事务**。它只能靠系统配置槽
自己的原子性（每盘两槽、槽 = 世代号 mod 2，`22-单元原子性怎么合成.md` 已定项 16），而那份原子性
只保证「单槽整槽自洽」，下一格就崩在这上面。

### K1-3 崩在缩的中间：跨盘的环长今天没有人比对

`crates/singlefs-core/src/recovery.rs:273-283` 逐字：

```
        match &chosen {
            None => chosen = Some(best_on_device),
            Some(previous) => {
                if previous.immutable.filesystem_identifier
                    != best_on_device.immutable.filesystem_identifier
                    || previous.immutable.device_count != best_on_device.immutable.device_count
                {
                    return Err(RecoveryFailure::SystemConfigurationsDisagree);
                }
            }
        }
```

跨盘只比 **fsid 与设备数**。环长、单元区起点、槽距、根环参数一个都不比；而 `chosen` 是
**第一块交得出配置的盘**上的那一份，之后的盘只用来做那两项一致性检查。

**可达的历史**：缩环要写 4 个槽（2 盘 × 2 槽）。写完盘 0 的两个槽、还没写盘 1 就崩
（`.claude/kb/decisions/22-单元原子性怎么合成.md` 已定项 8 的每盘一份冗余正是为这种局面留的）。
重挂之后：盘 0 说环是 R_后、盘 1 说环是 R，`choose_system_configuration` 返回盘 0 那一份，
**两块盘的 journal 都按 R_后 解读**，盘 1 的镜像从此按错的模数读——而 `scan_journal` 是
「两份镜像任一份自证过即算在」（`recovery.rs:841` 的注释逐字：「全环扫描：每盘每个记录槽都读
（有提示时只读提示的那些），两份镜像任一份自证过即算在；fsid 不符的不算数」），
于是盘 1 上按旧模数写下的**陈旧记录**会被当成「另一份镜像」收进那张 `(实例, 计数器)` 表。

这一格今天不可达（没有缩环，两块盘的环长恒相同），**乙 一落地它立刻可达**，且今天没有任何
检查看得见：I-8.* 那一类 checker 里，判环几何的 I-8.1 逐字「未实现」（`.claude/kb/invariants.md:76`），
跨盘几何一致性全仓零条目。

### K1-4 缩下来的那一段变成什么：今天是「谁都不管」，而且不会有人报警

`.claude/rules/fs-design.md:47` 那一节，第 52 与 54 行逐字：

```
⇒ **任何不做成单元的盘上空间，自动落在这些机制之外，而且不会有人报警。**
⇒ **判据**：要在盘上开一块新空间时，先问「它是不是单元」。
```

journal 环**不是单元**（没有单元头、校验和罩的是 4 KiB 记录不是 16 KiB 单元、扫描重建不认领它、
`walk::check_pool_image` 遍历的是单元区）。缩环把环的尾段交出来之后，那一段有三种去处：

| 去处 | 今天的实现给不给 | 证据 |
|---|---|---|
| 留成「既不是环也不是单元区」的空地 | **这就是今天的行为** | 探针 D 格：4 GiB 盘、环 64 MiB ⇒ 空洞 45056 槽 = 704 MiB；分配器单元区仍 211968 槽；checker 0 违例 |
| 并进单元区（让分配器发得出去） | **给不了**：单元区起点在核心层是格式常量 | `crates/singlefs-format/src/lib.rs:195` 逐字 `pub const UNIT_AREA_START_SLOT: u64 = 50176;`；`crates/singlefs-core/src/allocator.rs:212` 逐字 `let unit_area_slots = device_bytes / SLOT_BYTES - UNIT_AREA_START_SLOT;` |
| 做成单元（补齐头、校验和、扫描认领） | 条款零字 | 全仓无 |

探针 D 格原样（`geometry_probe-output.txt`）：

```
== D 环 64 MiB（4 GiB 盘）：盘 4096 MiB，环 64 MiB
   mkfs 接受
   环占槽 [1024, 5120)；代码里单元区起点常量 UNIT_AREA_START_SLOT = 50176
   空洞 45056 槽 = 704 MiB（既不是环也不是单元区）
   mkfs 的两个单元落槽 50176 与 50178；在环里吗：false / false
   分配器：单元区 211968 槽，起点 50176；环里还被当成空闲的第一个槽 None
   盘上字段：环长 67108864 字节，单元区起点 50176（偏移 333 / 417）
   choose_system_configuration 读回环长：Ok(67108864)
   checker：33 条判决，成立 20，违例 []
```

⇒ **K1 的题面「缩下来的那一段变成什么」今天有答案，而那个答案是「变成没人管的空地」。**
按 fs-design 那条判据，乙 要么逐条补齐（谁遍历它、谁认领它、哪条不变量说得出它有多大），
要么把它并进单元区——而并进单元区就是下一格。

### K1-5 已经写出去的单元的槽号还算不算数：缩的方向算数，涨的方向不算

槽号是绝对的（`SlotNumber`），单元区起点只进分配器的下标换算
（`allocator.rs:236` 逐字 `usize::try_from(slot.0 - UNIT_AREA_START_SLOT).expect("槽号在单元区内")`）。所以：

- **缩环（起点前移）**：老单元的槽号仍 ≥ 新起点，仍在单元区里，**算数**。要改的是分配器的
  位图长度与下标基准（内存量，每次挂载重建），以及盘上那个「单元区起点」字段（偏移 417）。
- **涨环（起点后移）**：新起点会盖过老单元。而单元区第一个槽上躺着的恰恰是 **mkfs 写的实例表**
  ——`crates/singlefs-core/src/make_filesystem.rs:36-37` 逐字：

```
pub const INSTANCE_TABLE_SLOT: SlotNumber = SlotNumber(UNIT_AREA_START_SLOT);
pub const TREE_TABLE_GENESIS_SLOT: SlotNumber = SlotNumber(UNIT_AREA_START_SLOT + 2);
```

  根环里每一条还活着的根都用位置条目指着它（第一个事务之后的根记录 `instance_table` 那一项，
  探针打出来的 `SlotNumber(50176)`）。要涨环就得先把实例表搬走并改掉每一条根里的指针——
  而被抛弃的根、回退候选集里的根不许改（它们是 D28（挂载期承诺量） 第九项与 I-7.4 保护的对象）。
  ⇒ **「空间大就大」若指运行时涨环，在今天这个布局（环在前、单元区紧随其后）里比缩环难得多。**

这一格不是纸上推的，探针 B 格把「起点后移」的后果直接量出来了：

```
== B 环取容量四分之一（1 GiB）：盘 4096 MiB，环 1024 MiB
   mkfs 接受
   环占槽 [1024, 66560)；代码里单元区起点常量 UNIT_AREA_START_SLOT = 50176
   重叠 16384 槽 = 256 MiB（环盖住单元区开头）
   mkfs 的两个单元落槽 50176 与 50178；在环里吗：true / true
   写到实例表那一槽的是 jsn 196609（record_offset 复核 822083584，实例表在 822083584）
   分配器：单元区 211968 槽，起点 50176；环里还被当成空闲的第一个槽 Some(50176)
   盘上字段：环长 1073741824 字节，单元区起点 50176（偏移 333 / 417）
   choose_system_configuration 读回环长：Ok(1073741824)
   checker：33 条判决，成立 20，违例 []
```

同一份探针再往前跑一步（第二个测试，取号 + 暖机 + 第一个事务全跑完）：

```
== 1 GiB 环上的第一个事务：环占槽 [1024, 66560)
   第一个事务发布成功：txg CheckpointTxg(3)
   checker：违例 []
```

根记录里三个单元的落点是 `SlotNumber(50176)`（实例表）、`SlotNumber(50247)`（映射树根）、
`SlotNumber(50248)`（树表）——**全部落在声明的 journal 环里面**。环写到 jsn 196609 那一条时
（按 E142 的「journal 占写出数据 12%」口径，大约 6 GiB 用户写之后）就开始逐个盖掉它们。
checker 一条都不红。

### K1-6 乙 一旦让单元区起点随环走，核心层与 checker 当场分家

单元区起点今天有**两个来源**：

- 核心层：格式常量 `UNIT_AREA_START_SLOT`（`allocator.rs:212 / 236 / 241 / 401`、`make_filesystem.rs:36-37`）
- checker：盘上字段偏移 417（`crates/singlefs-checker/src/image.rs:137` 逐字
  `unit_area_start_slot: read_u64(slot, 417),`；I-5.2 用它算单元区容量，`walk.rs:2141`）

而写盘的那一步把常量原样写进字段（`crates/singlefs-core/src/system_configuration.rs:360` 逐字
`writer.put_u64(UNIT_AREA_START_SLOT);`）。⇒ 今天两边恒等，**纯属巧合**。

乙 的第 1 条（mkfs 按容量算初值）一落地，字段就不再等于常量：checker 按字段算单元区容量、
分配器按常量发槽，I-5.2「空闲 + 已分配 = 单元区」当场红。**这是乙 的第一个可机检后果，也是
这条腿唯一找到的「乙 会被现有检查拦住」的一格**——它同时说明：那个常量必须先改成从系统配置读回来，
甲 的 mkfs 参数与乙 的弹性环都卡在同一格上。

## 二、K5：甲今天真的不成立吗

这一面冲着主 agent 来。主 agent 接受了用户「环是弹性的」这个前提，没举出一个今天做不到的场景。
下面是核的结果。

### K5-1 把「今天做不到」的候选逐个扫一遍：mkfs 这一侧一个都没有

模型二（`k5_capacity_scan.py`）按 10 个容量点扫，写死的输入每行标了来源。原样输出（节选，全表在
`k5_capacity_scan-output.txt`）：

逐条对用户说的六样（正文那张表的六行），问的是「今天可达吗」，不是「条款写没写」：

| 用户说的 | 今天可达吗 | 乙 多买到什么 |
|---|---|---|
| 空间大就大环 | **可达**：mkfs 传 `ring = 容量 ÷ 4` 即可；200 GiB 盘上能传到 50 GiB | **只有默认值**：把「用户不传就是 768 MiB」换成「用户不传就按容量算」 |

⇒ **mkfs 这一侧，甲 与乙 的差别是一条默认值的差别。** 「今天做不了而弹性环做得了」的场景，
在 512 MiB–2 TiB 这十个容量点上一个都举不出来。

### K5-2 运行时缩环买到的那点空间，今天进不了可分配集合

`crates/singlefs-core/src/allocator.rs:212` 逐字：

```
        let unit_area_slots = device_bytes / SLOT_BYTES - UNIT_AREA_START_SLOT;
```

单元区容量是 **设备字节数减一个常量**，式子里没有环长。缩环之后，分配器手里的可用槽数
一个都不多（探针 C / D 两格都量到：换了环长，单元区还是 211968 槽 / 15360 槽，只跟设备大小走）。

⇒ 「空间不足就缩环」要真能缓解 ENOSPC，必须做的是**把单元区起点做成一个跟着环走的量**
（K1-6 那一格），而不是「让环长变成弹性量」。这两件事被用户那句话捆在一起了，其实是两件事，
而**只有前一件买得到空间**。

### K5-3 这一轮唯一货真价实的「今天做不到」：甲 的 mkfs 参数本身是坏的

`23-journal的角色与格式.md:460` 逐字写着「单元区起始槽号随环长走，默认环下是 784 MiB（槽 50176）」。
**实现不是这样**：`crates/singlefs-format/src/lib.rs:194-195` 逐字

```
/// 单元区从槽 50176（784 MiB）起（D3（空间分配） 已定项 10）。
pub const UNIT_AREA_START_SLOT: u64 = 50176;
```

而几何检查那一步**按环长算了一个起点**，算完却没人用它——`crates/singlefs-core/src/make_filesystem.rs:155`：

```
    let unit_area_start = (JOURNAL_RING_START_SLOT + ring_bytes / SLOT_BYTES) * SLOT_BYTES;
```

它只进 `UnitAreaBeyondDevice` 那一条拒绝判定；mkfs 真正写实例表用的是常量（`make_filesystem.rs:36`）。

**可达的历史与后果**（探针 C / E 两格原样）：

```
== C 小镜像按参数缩（1 GiB 盘、256 MiB 环）：盘 1024 MiB，环 256 MiB
   mkfs 接受
   环占槽 [1024, 17408)；代码里单元区起点常量 UNIT_AREA_START_SLOT = 50176
   空洞 32768 槽 = 512 MiB（既不是环也不是单元区）
   分配器：单元区 15360 槽，起点 50176；环里还被当成空闲的第一个槽 None
   盘上字段：环长 268435456 字节，单元区起点 50176（偏移 333 / 417）
   checker：33 条判决，成立 20，违例 []

== E 环 12 KiB（I-8.1 按「任一事务」读的下界）：盘 4096 MiB，环 0.01171875 MiB
   mkfs 接受
   环占槽 [1024, 1024)；代码里单元区起点常量 UNIT_AREA_START_SLOT = 50176
   空洞 49152 槽 = 768 MiB（既不是环也不是单元区）
   盘上字段：环长 12288 字节，单元区起点 50176（偏移 333 / 417）
   checker：33 条判决，成立 20，违例 []
```

- **C 格**：条款射程逐字担保的「小镜像按参数缩」，做出来的池一半空间（512 MiB / 1 GiB = 50%）
  归零人管；mkfs 不拒、checker 不红。
- **E 格**：环设成 12 KiB（3 条记录）也照样 mkfs 成功。`I-8.1（环几何够大）` 逐字「未实现」
  （`.claude/kb/invariants.md:76`），今天**没有任何东西拦得住把环设到任意小**——
  连「环 ≥ 一条记录」都没人判。这正是正文说的「缩环时没有任何东西拦得住」，
  而它**不需要缩环就已经成立了**：mkfs 传参数就到得了。
- **B 格**（K1-5）：环 > 768 MiB 时环与单元区重叠，第一个事务的全部单元写进环里。

⇒ 甲 的表里「有」的那两格（用户可设、小镜像按参数缩），**在实现上是纸面的**。
这是这一轮真正的收获，但它的改法是「把单元区起点做成从系统配置读回来的量 + 把 I-8.1 那个字段真算出来」，
**与环长要不要弹性无关**。乙 不修这一格照样坏，丙 修完这一格之后甲 与乙 只差一个默认值。

### K5-4 「空间不足就缩」的收益上界，与它被自己的第 1 条吃掉

- 缩到硬下界（`F × 12 KiB = 36 KiB`，C310 那一行现查的 12 KiB）能腾出的 = 环长 − 36 KiB。
- 环长 ≤ 容量 ÷ 4 ⇒ 收益上界恒 ≤ **容量的 25%**；按「容量 ÷ 64」这种自动初值算恒是 **1.56%**。
- 设备容量不会自己变小，池也不支持缩容 ⇒ 运行时「空间不足」的唯一来源是用户把数据塞满了。
  这时缩环换来的是：可用空间 + 1.56%（一次性），代价是在飞上限与有效 `T_dirty` 同比例下降
  （`T_dirty` 夹取，`16-发布语义.md:122`「**挂载时还要再夹一次**」，同文件 133 行「`T_dirty` 走夹取」）——**用吞吐换最后那 1.56% 的空间，而且只能换一次**。
- 而 mkfs 时按容量取初值（乙 第 1 条）已经把「小盘别给大环」解决了。⇒ **乙 第 3 条（运行时缩）
  只在「mkfs 时那个初值算错了」这一种历史上买到东西**，而那种历史的正解是改初值的算法，不是运行时缩。

### K5-5 判决

**收丙。** 主 agent 那句「条款只明确了一半」按字面成立（`23-journal的角色与格式.md:460` 确实只写了
参数与上限），但**缺的那一半在今天可达的场景里只买到一个默认值**；而真正坏掉的那一格
（单元区起点是常量、`I-8.1` 的字段恒真、环可以设到 12 KiB）丙 全包，乙 一样要做，做完再谈弹性。
