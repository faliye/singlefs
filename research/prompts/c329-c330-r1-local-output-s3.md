1. C329-A closes F6 because it ensures the rows publish is the first action for a new instance, so the old instance's rows are written before any potential crash. C330-A closes F7 because it sets T_pub=0 for instances strictly between the chosen root and new instance, so units with birth checkpoint >0 do not count as published. For other failures: instance switch (e.g., mount takes new instance without recovery), rollback (handled by F3 which already uses (i,0,0) for between instances), falling back more than one root (e.g., multiple unreadable roots, chosen root is older), or several F-raising publishes (but C329-A prevents F-raising before rows, so no issue), there is no reachable state where an unreferenced unit counts as published with these fixes.

2. C330-A cannot mark a unit unpublished that the chosen root references because the chosen root only references units in its own instance, not in other instances. No instance strictly between the chosen root's instance and the new instance has units that the chosen root references, as the chosen root only applies to its own instance. C329-C can misjudge for unclean ends (e.g., unclean end with no row written, then mount tries to mount and units should be published but are unpublished due to no-row branch) and for instance switches (e.g., crash before rows publish, then next mount sees no row and marks units unpublished when they should be published), but not for clean ends (since clean ends write a row) or skipped instance codes (as F1 ensures no skips).

3. C329-A can be done without a format change as it only changes operation order. If the switch reserve is short, it may not have space for rows publish, but this is a sizing issue not related to format change. C330-B requires 8 bytes for a checkpoint field in the superblock or root. C330-C requires 8 bytes per unit header for the "checkpoint of the root this instance started from" field.

4. Failing checks: For C329-A, a crash after F-raising publish but before rows publish causes next mount to have no row for old instance, units published incorrectly. For C330-A, F7 scenario without enforcement causes orphan units to count as published. For C329-B, writing a root before rows publish and crashing causes next mount to have no row for old instance. For C329-C, unclean end with units present and no row, then mount tries to mount: units should be published but are unpublished. For C330-B, two mounts using same checkpoint number causes ambiguous root selection. For C330-C, F7 scenario without enforcement causes orphan units to count as published. C329-C has no reliable failing check because the misjudgment depends on the presence of referenced units and may not manifest if units are absent or not referenced, making it hard to test consistently.

5. No candidate contradicts the admission rule (space short pushes F-raising, but C329-A prevents F-raising before rows, which is consistent), warm-up rule (new instance publishes empty roots, but C329-A ensures rows first then warm-up), rollback rule (F3 handles rollback, unaffected C329-A/C330-A don't affect it), or rows unique and below mounted root rule (rows are unique and T_pub <= current root checkpoint for the instance).

6. For C329 hole, recommend C329-A. For C330 hole, recommend C330-A. A single observation that would change my mind: for C329-A, if switch reserve is consistently too small for rows publish in practice, requiring format change for reserve sizing; for C330-A, if a unit with birth checkpoint 0 exists and T_pub=0 causes it to be incorrectly published or unpublished.
