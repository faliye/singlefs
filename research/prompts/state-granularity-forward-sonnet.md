# 腿：正推（云端 A / Sonnet）——态别判据按什么粒度施加

**立场：正推。** 从条款与仓里的既有用法推到结论。不要去找反例。

**先读**：`research/prompts/_state-granularity-background.md`（背景材料，引文已核）。
原文在 `.claude/kb/decisions/21-权威态与派生态的分界.md` 等处，自己核。

**候选**：判据的施加粒度是**字段**——每一条把某结构判为派生态的条款，
正文里都要有一份逐字段的重算源清单（每个字段 → 它只从权威态的哪一组重算出来）。

**必须逐条回答**：

1. **仓里现有的「派生态」判定有哪几条？** 逐条列出（至少：索引树、索引节点、
   分配记录树、消息缓冲区、以及你能找到的其他）。对每一条说：
   它今天有没有字段表？有没有逐字段的重算源？
2. **按候选，哪几条会立刻变成「欠清单」？** 这是新立判据必须当场做的回扫。
3. **粒度取「字段」而不是「节点与叶」，买到了什么？** 用仓里已经发生过的两个实例说明：
   D21 已定项 5 第四条后果（转发信息被逐出分配记录树）、
   D11（索引节点要不要留消息缓冲区） 的消息缓冲区。
   这两处**实际施加的粒度**是哪一档？
4. **代价是什么？** 逐字段清单要维护，字段表变了清单要跟着变。
   说清这个代价落在谁身上、有没有已有的门禁形态可以复用
   （提示：仓里已有 `.claude/gate.d/38-field-table-projection.sh`
   「决策里定的字段有没有漏投影进第一个事务的表」，去读它，看形状能不能抄）。

**输出**：结论 + 逐条依据（文件与行号）+ 回扫清单（哪几条条款按候选立刻欠账）。
