## 两轮之后每条剩下什么

### 一、inode 记录

**已经站住的**（不必再攻，攻了也别记成战果）：
- 14 个字段里 **11 个**不能只从权威态重算（E98（inode 记录与 inode 树的几何） 实测）
  ⇒ 按 D21（权威态与派生态的分界） 硬约束 6，住索引节点的 value **触发**「必须扩项」，住单元不触发。
- `locality_id` 与 `blocks` 必须在记录里（前一轮已逐字核实）。
- 头判别位撤回（D6（快照实现模型） 已定项 1：每头一棵自己的树）。

**仍然缺的（第二轮挖出、尚未答）**：
1. 「打包共享单元」不属于 D18（块里携带什么信息） 已定项 7 定义的任何一类——
   233 条记录属于 233 个对象，而五元组的「对象 ID」只写得下一个。
   **这个洞是先例自带的**：D18（块里携带什么信息） 已定项 10 的墓碑单元同样是打包共享单元，
   同样从没答过单元头填什么。
2. 认领规则（D18（块里携带什么信息） 已定项 7）逐字「按声明长度把整段载荷跳过去，
   载荷内部的探针不再参与认领」⇒ 扫描器认领之后 **233 条记录一条都不会被独立发现**；
   要放回去得有记录级的类型标签 / 长度 / 校验和 / 活位，**四样全缺**。
3. 装载纪律：E84（打包墓碑的钉住量） 的「按代际装载」在 inode 上**没有对应物**
   （墓碑同生共死，inode 活到文件被删）⇒ 能搬过来的是 `append_order` 那一臂，
   也就是**驻留死占比 84.1%** 那一格。
4. **永久损失**（E98（inode 记录与 inode 树的几何） 第三轮补测）：丢一个容器永久丢
   **116**（索引叶）/ **233**（打包单元）条，**两种形态都不是 0**
   ⇒ 无论选哪个都要一条冗余 / 可检出条款。

### 二、`seq`

**修正后的结论（E99（write buffer 条目与 seq 的去重） 第二轮重跑）**：
D5（快照 / 空间记账机制） 已定项 5 的 key 末段就是「代」= checkpoint 号，
D5（快照 / 空间记账机制） 已定项 2 骑手条款逐字「跨发布合并不再可行（代进了 key）」
⇒ **同一个 key 的待去重条目必然同属一个发布窗口** ⇒ **seq 只要 4 字节窗口内序号**，
在 seq 里再放一份 txg 是**重复计账**。窗口需求 27 位（`T_dirty` ÷ 30 字节 = 71 582 788 次）。

**截断代价（第三轮补测）**：代进了 key，截断它撞的是**键的同一性**不是排序——
16 位、一千万次发布之后有 **757 947 392** 对本属不同 checkpoint 的条目塌成同一个 key；
48 位（已定下界）恒 0。

**仍然缺的**：
1. **「住 key 还是住 value」一个字没答**，而 D5（快照 / 空间记账机制） 已定项 5 末尾逐字
   「格式冻结之前必须先定它」，D15（格式冻结政策） 第 3 层冻的正是 key 编码。
2. 射程只覆盖记账树；反向索引与 LRU 的 key 布局仓里没定，模型报「不适用」。
3. 「改第一个事务的字节」判定**维持「是」**（正推腿的理由：C80 说的是运行时结构在内存，
   推不出「没有字节因它而变」；崩溃后账要能重建，总得有个持久形态）。

### 三、超级块

**E100（超级块的三段几何） 实测**：段一 162 字节（其中 feature bit 96）、固定开销 361；
512 字节槽上设备表内联**只装 2 台**，8 台爆 41 并造出 2 种撕裂态；走间接层恒 **420 字节**、零撕裂态。

**第二轮打掉的**：
1. **自举循环**：指针里的 dev id 要靠设备表才映射得到真实设备，
   而异构池（D12（目标介质） 已定项 3）下「设备 N 用哪套布局」也在表里
   ⇒ 撞 D12（目标介质） 已定项 3 逐字排除过的那条循环。
2. **第一版恒 2 盘**（D2（RAID 条带策略） 已定项 9），E100（超级块的三段几何） 自己的数是
   2 台内联 409 ≤ 512 **装得下**；而 4096 槽上内联撑到 64 台
   ⇒ 「装不下」只在**全 512e 池且 ≥7 台盘**时成立。
3. D9（加密） day-1 预留第 3 项（KDF 标识 + 主密钥槽 + 加密类型）**仍没补**——
   第一轮打的「零加密预留」那一枪，修订补的是 D9（加密） 已定项 8 的 MAC 与 nonce 水位，不是那四项。
4. 420 里至少 116 字节的宽度**没有出处**，余量只有 92 字节。

### 四、抗老化

**E101（节点头留位的代价与表达力） 实测**：代际分离要 49 个标签值、1 字节够；
节点组的上界**取不到** ⇒ 四档宽度上「第一个事务的字节是否稳定」全判否
⇒ **留位翻不了 D26（后台整理与放置回收） 未定项 4 的「是」**。

**第二轮打掉的**：「留位可以做」这半不成立——它唯一的支撑是「扇出零代价」，
而 `.claude/rules/fs-design.md` 的射程注逐字排除了这类理由（它只管「已经论证过有用的字段
该不该为省空间而砍」，不管「要不要加」）。且 D15（格式冻结政策） 判定表第一行：
预留区 / TLV 尾部加字段是 **compat 不 bump** ⇒ 不留位的将来代价不是格式断裂。

## 顺带翻出的一条决策级冲突（不属于四条提案）

D23（journal 的角色与格式） 已定项 3 逐字「tail **只在 checkpoint 持久之后写一次，不上 fsync 路径**」，
而 D16（发布语义） 已定项 6（2026-09-02）逐字「**fsync 触发的发布也是发布**，
checkpoint_txg 加一，没有『小发布不记号』的例外」。后者落地时没人回头改前者——
按 E44（序号位宽的本机实测与代价） 的 2785 fsync/秒，tail 写从每 5 秒一次变成最多每秒 2785 次，
**差三个数量级，仓里一处没记**。
