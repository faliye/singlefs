### 读法（写死）

1. **旗上操作**：照 E207 登记第一节读法 8 逐字，不另立：`final_nodes ≥ max(28, 4 × 同点同状态量窗全部操作 final_nodes 的下中位数)`（装置 `scripts/experiment-apparatus/e207_strict_scan_steps.rs` 的 `spike_line` 与常量 `SPIKE_FLOOR = 28`、`SPIKE_MULTIPLE = 4`）。本实验的「同点同状态量窗」= 一个项里同一次挂载（挂载序号相同）的全部脚本操作。**旗线灵敏度**（登记里没有条款给 28；第六节与第八节用）：下限 L 取 14、28、56 各算一遍，主读 L = 28；`flag(L) = final_nodes ≥ max(L, 4 × 下中位数)`。一个项里旗上操作超过半数时，中位数本身被拉高，旗线失去意义：该项另标 `median_inflated=yes`，两份旗（E207 逐字、只用下限）并列报，不替它选。
2. **一次操作、一次发布**：脚本里的一步 = `Measured::measure` 的一次调用（E207 histories `:694` 起）；`overwrite`、`create_one` 各是一次发布；`remount`（`pool.crash_and_mount_writable()`）不是用户操作，它自己的发布（写行一次、暖机若干次，`mount.rs:7859` 起的 `warm_up_publishes_planned`）逐个记、标 `phase=remount` 与它在挂载里的次序，但不进旗线的中位数。
3. **节点身份**：分配记录树的节点用位置三元组 `(level, device, index_in_device)` 或 `Root` 认（`allocation_record_tree.rs:186` 的 `leaf_of_slot`、`:200` 的 `parent_of`）；「同一个节点」在不同版本里是同一个位置。
4. **带出**：一个节点「被带出」= 它是某次发布定下那一轮的 `rewritten_by_the_plan`（`transaction.rs:14039`）的成员。「挂载以来带出过的集合」`C_mount(i)` = 当前挂载起点（含这次挂载自己的写行与暖机发布）到第 i 次发布之前，全部发布的定下集合之并；「从来带出过的集合」`C_ever(i)` = 池建好以来全部发布的定下集合之并（挂载不清零）。在没有重挂载的项里两者相等；岔路单第一行写的是 `C_mount`，`C_ever` 是对面那条臂（挂载不影响，只有发布影响）。
5. **新鲜度** `fresh(i)` = `|(seed(i) ∪ pulled(i)) \ C(i−1)|`，`seed(i)` 是第 i 次发布固定点第一次并重写集时弄脏的节点（E207 装置的 `seed_nodes_first_merge` 那一批），`pulled(i)` 是同一次并入顺着释放链新拉进来的（`pulled_nodes_first_merge` 那一批；站点是 `transaction.rs:14087` 的释放站点还是 `:14116` 的落点站点都取各自第一次并入）。
6. **序号**：`ordinal_user(i)` = 当前挂载里用户操作的序号（含探针、不含重挂载自己的发布），从 1 数；同一份数据另报 `ordinal_all(i)`（含写行与暖机发布）。
7. **同种操作与可比操作**（行五用）：同种 = 目标文件选择子（第五节脚本表的 `first`、`old`、`mid`、`late`、`young`、冷文件、新建）相同，且 `name=declared` 行的 `old_units`、`new_units` 相同，即同一个文件的同一种改动。一个旗上操作的可比操作 `c1`、`c2` = 同一个取样点（同几何）下别的脚本项里同一选择子、同一声明单元数、不在旗上（L = 28）的操作，按项名字典序取前两个；同一项内同一次挂载里 `user_units` 相同、不在旗上的操作另报作 `w1`、`w2`（不进判定）。为什么跨项：第一个文件（选择子 `first`）历史里只有一个，它第一次覆盖写的 `old_units` 与之后各次不同，同项内找不到同种。可比操作找不到的旗上操作不进行五，计数照报（分母）。
8. **挂载序号**：项里第 0 次挂载是池建好时的那次（历史与脚本在它里面），每个 `remount` 把序号加一。「同一次挂载那一侧」的历史是第 0 次挂载里放的，因此 `ordinal_user` 在第 0 次挂载里从历史末尾之后数起（历史发布数不计）；历史发布数另报。

**定案**：

## 十、失败条款

每条紧跟「什么观测会触发」。「没测出效应」不写成实现有 bug：阳性对照（合成臂）管判器分不分得出差别，真实基线（今天的实现上的读数）管问题本身，两个对照组的失败分开写。

- **F1（行一不成立，是正当结果）**：`fresh_since_mount` 宽读在 TEST_SCRIPT 或 TEST_GEOMETRY 上有一处不符，或在 TRAIN 上定规则失败。**触发的观测**：Q2 报的不符数 ≥ 1 或定规则失败数 > 0。后果：行一记「不成立」，如实写出首个不符的（项、序号、`fresh`、观测旗）；不改 `m`、不换读法重判（改了就是新实验）。
- **F2（阳性对照失败，整个判器作废）**：第五节任一矩阵格、挂载变体、行四合成或行五合成的实际输出与期望不同，或阈值边界自证（`m = 6`、`m = 1`）不转红。**触发的观测**：模型单测里对应的 `assert_eq!` 红。后果：该判器的全部真实读数作废，回头修判器、在产物落盘之前走第十二节修订；产物落盘之后不许改判器重判（改了就是新实验）。
- **F3（闸：可跑几何上不复现尖峰）**：Q0 在 `files_100_units_100` 与 `files_200_units_100` 的 `walk_forward` 上，L = 28 与 L = 14 都没有旗上操作。**触发的观测**：这两项的旗上操作个数都是 0。后果：行一至行四在这两个点上记「装置走不到」（分母 0，不写「没撞上」「尖峰不存在」），行五没有可判的旗上操作；报 E207 的尖峰在 F = 1000 观测到，在本实验可跑的几何（F ≤ 200）上没有，交主 agent。

## 十一、作废条款与停机条款

### 作废条款

1. 某个点的 Q0 判「不复现」：该点上行一至行四的判记「装置走不到」，不是作废全部（F3）。
2. 某判器的合成对照有一格不符：该判器的全部真实读数作废（F2）。
3. 一个项没有 `item_done` 行，或出现 `window_refused` 行：该项不读，续跑补。
4. 确定性孪生项不同：该点集合类量作废（F5）。
5. 阴性对照 `rounds > 4`：该项作废（第七节 ③ 第 8 条）。
6. 判据（第六节门槛、第五节脚本表、第一节读法）在产物落盘之后改动：改了就是新实验，重跑，不作废这一份、也不回头改。

### 停机条款（装置与 `crates/` 实现对不上：两边都查，既不作废也不当结果，`.claude/rules/implementation-first.md` 第 4 条）

2. 第七节 ② 第 1 条的常量不等：停。
3. 闭包模型对拍不符（第七节 ③ 第 3 条）：停，先查三处：装置的 `pointer_graph` 与 `seed` 记对没有、模型的算术（位置、祖先、根）、`transaction.rs:14133` 的 `merge_into_the_rewrite_set_walking_the_release_chain` 今天的样子（行号现取，它被改了也是原因）。报告写两边各看到什么。
4. 计数版与 plain 版镜像不同（第七节 ③ 第 4 条），或历史对账不符（② 第 2 条）：停。
5. 第一段第一个项（`files_100_units_100` 的 `walk_forward`）实测挂钟推出的 `files_200_units_100` 单项超过 7200 秒：停，退出清单里 F = 200 的项，另报换成 F = 150 的建议，交主 agent；不自己改点表。
