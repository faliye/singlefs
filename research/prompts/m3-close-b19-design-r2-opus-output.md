## Q2　C740：正推腿 I-3.19 三支在攻方那一对历史上

正推腿 (a) 原文：「(a) 根环里有实例 i、txg 等于 T 的自证过的根 ⇒ W 必须为 0」（`research/prompts/m3-close-b19-checker-r1-sonnet-output.md:101`）。

### 打中：(a) 在一段合法历史上误红，而且这一对镜像连钉槽 p 都相同

行里 W 的来源：「applied_transaction_high_water: journal.maximum_applied_transaction,」（`crates/singlefs-core/src/mount.rs:8914`）。钉槽 p 取挂载时读坏的槽里钉值最小的那个：「.ring_slots_pinned_since_the_mount_at_the_oldest_txg_they_can_have_held()」（`crates/singlefs-core/src/allocator.rs:2763`）之后取 `.min()`。

两段历史（前缀与故障固定，用户动作相同）：

1. 实例 i 发布到 txg T（T 那次带非 0 事务号 k），干净断电；环里另有一条更旧、不是最旧的根 X，X 那一槽的钉值（3·槽 + 区域）低于 T 那一槽的。
2. H_坏：下一次可写挂载时 X 槽与 T 槽都一时读坏。择到 T 之下最新的可读根 c，重放 (c, T] 施加到 T，写行 (i, T, k)；新实例第一个 txg = max(环里读得出的, 记录) + 1 = T + 1。两槽都钉，p = X 那一槽（钉值更低）；t 取钉值与环里有效根的最小，也是 X 的钉值。
3. H_净：同一前缀，挂载时只有 X 槽一时读坏。直接择 T、一条都不施加，写行 (i, T, 0)；新实例第一个 txg 同为 T + 1；p 同为 X 那一槽，t 同为 X 的钉值。
4. 之后新实例照常发几次（不发到 X 槽成为环里最小的位置，就不触发重读：「钉着的槽一个都不在最小的位置上时一个都不读。」，`crates/singlefs-core/src/allocator.rs:2826`）。读故障不留在盘上，镜像上 X、T 两条根都读得出。

两张镜像只差行里的 W：版本 T 的树在 H_坏 里由记录新根段施加出来、在 H_净 里来自 T 的根，内容同；回收门槛同 ⇒ 回收同 ⇒ 记账同；p 同。(a) 在 H_坏 上看到 T 那条根在环里、W = k ≠ 0，判红；H_坏 是合法历史。

只一槽（T 槽）读坏的那一形，p 会点名 T 那一槽，是个看得见的见证：(a) 照原文不看 p，照样误红；改成「新实例第一条根的 p 点名 T 那一槽时不判」能救单故障，救不了上面的双故障（推的，只在我的推理上过）。

### 打中方法：拿 I-7.9 的已认代价顶误红

正推腿给 (b) 的「瞬时读故障」与 I-8.14 的同一形都写成「与 I-7.9 同一处已认代价」（`research/prompts/m3-close-b19-checker-r1-sonnet-output.md:131`、`:341`）。I-7.9 那一句是「checker 只按镜像上读得出的根判（推的：读故障不留在盘上）」（`crates/singlefs-checker/invariants/02-根环.md:16`）：读故障让写者算出的上限更低、更保守，checker 看得见的根更多、算得更松，代价是漏判，不是误红。I-3.19 (a)(b)、I-8.14 在同一种读故障下是在合法历史上判红——方向相反，不能拿那一处已认代价当依据；照用户 2026-10-04 的口径「checker 不许因读不出的根槽误红」（`.claude/kb/checks-owed.md:422`），这类误红要么收窄判法，要么由用户另认。

### (b) 支

(b) 从「环里实例 i、txg 小于 T 的最大一条根 S」起重放。挂载时 S 与它前面那条带非 0 号的 u 都一时读坏、而 (S, T] 里全是事务号 0 的发布（抬 F、写行一类）时，真挂载从更旧的 c 起施加了 u，W = u 的号；(b) 从 S 起算出 0，误红（推的，双故障）。单故障下 (b) 没找到误红。

### 能站住的收窄

第一轮攻方的集合形（只在推理上过、被攻过零轮）：W ∈ {T 那一槽坐着的根 txg ≥ T 时的 0} ∪ {对 T 之前每条可读、按行有效的根 c，(c, T] 里实例 i 记录的最大非 0 号}；记录读不全报部分没判。H_坏 的 k 与 H_净 的 0 都在集合里，两张都绿；「W 写成 0」只在 T 从没落槽、且 (c, T] 里有非 0 号时红。代价：(a) 支的「W 必为 0」那一条判别力没有了。
推翻条件：找到 H_坏 与 H_净 之间盘上不同的一个字节（例如新实例某条根的 t、p 或实例表行之外的字段随 W 变）。

## Q4　C706：I-5.7 的前件取自哪里、循环成不成立

- 前件取自记录：正推腿 I-5.7 的前件是记录自己的点名项（`ScannedJournalRecord.named_entries`），C706 的坏镜像只换记录里分配记录树根那一项，点名项不变，I-5.7 判得到。第一轮攻方的循环（前件只能从树根读出）在这一形上不成立。

- 漏的一形：坏写者把点名项与分配记录树一起写错（点名项空、树照抄旧的）。不变量里提到点名项的只有 I-2.5（位置条目次序）与 I-8.11（点名项与被指单元头相同），没有一条判「这次新根段里出生在这一版的单元都被点名」（`grep` 过 `crates/singlefs-checker/invariants/` 的「点名项」），这一形 I-5.7 前件为假、不判。值不值得补：写者的点名项与写的角色由同一张角色清单出（mount.rs「树表 0 条的一版上一次发布的点名项与它写出的角色一一对应」那一句的断言），两者一起错要那张清单错，概率低；记成已知代价即可。
结论：I-5.7 的形站得住；条文写明射程只有那一种发布，并写明点名项与树一起错的那一形不判。推翻条件：找到第三处重建分配记录树、或一种零单元而有点名项的发布。

## Q5　C697 RCW 三条与正推腿模型的口径

### 打中模型口径：(U) 第一项在模型上恒成立

正推腿 `rcw_t.py` 里写者的计数器按定义就是 `|E(t)|`：「C=len({s for s,rec in acct.items() if rec[0]=='A' or rec[1]>newest.t})」（`research/prompts/m3-close-b19-checker-r1-sonnet-model/rcw_t.py:52`），而 (U) 的第一项是「up_ok = C <= min(len(E(th_low)), len(walked|U))」（`research/prompts/m3-close-b19-checker-r1-sonnet-model/rcw_t.py:80`），θ_low 取的就是 `newest.t`。合法世界上 `C <= len(E(th_low))` 按构造成立；「删一条」「加一条」两种变异也让 C 跟着改过的账重算，所以模型里 (L)(U) 第一项从来不比较「写者真记的数」与「从记录现算的数」。「RCW 在 12 681 102 对上 0 误红」里，(U) 第一项那一半是定义出来的，不是量出来的。
真写者是不是 `C = |E(t)|`，是读码的事：根记下时先按回收门槛回收、记账行在回收之后装（`crates/singlefs-core/src/allocator.rs:2800` 「self.reclaim_released_records_up_to(reclaim_floor, ReclaimedReuse::Immediately);」），同一个门槛记成 t；一个进程里门槛只升不降（钉只在挂载时出现，重读只解钉）。我核到的几种都同值：抬 F 的扣住回收（随后那条根带新 F，t ≥ 新 F）、隔离（不进已分配也不在 E 里）、零单元发布（t 与账都照抄上一版）。所以没打出误红，但这一半今天只有读码一条路径，模型不是第二条。

### 打中修补：RCW 下「最新根带的 F 低于 F_生效时不判」这一处例外不再需要

最新根上的 F 低于 F_生效 时 t ≤ θ_high，E(t) ⊇ E(θ_high)；真写者 C = |E(t)| ⇒ (L) 成立；(P) 的遍历按 F_生效 取候选，只会更少。所以这类镜像上 RCW 照判不误红，正推腿保留旧等式的例外等于白丢这一类镜像的判定（推的，没造镜像）。今天这一支是为旧等式「已分配 = 遍历」立的，换 RCW 时要重审。

### 没打中的

- (P)「遍历到的每个槽在 E(θ_high) 里」：可读有效根 R 引用、释放代为 g 的槽有 g > R.txg ≥ θ_high，在 E 里；隔离记录是未释放的、在 E 里（walk.rs `quarantined_slots_exempted_per_device` 文档「已分配而没有根引用的记录按单元（起点槽、跨度）归组」）。没造出合法误红。
- (L) 在挂载时一时读坏的槽上：写者的 t 被钉值压低、C 更大，(L) 更松，不误红。
- 第一轮攻方问的「走不到的一代怎么认」：θ_low 取根自己带的 t 之后，RCW 不需要认它，这个问题被绕开了。
- 模型宽窄：LR5 小世界逐行移植，单盘、没有挂载时的钉、没有扣住回收、没有隔离；「12 681 102 对」是世界 × 读不出子集，不是互相独立的历史。窄于真历史的地方正是上面读码核的那几种。
推翻条件：真写者某条路径上记账行与 t 不是同一个门槛（例如回收发生在装记账行之后）。

## Q6　C699 第四条件「R 的实例表指针出生 txg 等于 R.txg」

### 打中一：量前提的装置判据 (P1) 在实例 1 上必然不成立

正推腿 (P1)：「一个实例的第一条根的实例表指针出生 txg 等于它自己的 txg」，并要求「关清扫的组要求三句全成立、违例数 0」（`research/prompts/m3-close-b19-checker-r1-sonnet-output.md:274`）。第一次可写挂载不写行：「环里没有记录）同样走这条路：取号 1、不写行、零单元的发布推到本实例的根覆盖每块盘」（`crates/singlefs-core/src/mount.rs:8070`），写行那次「所选根的树表 0 条、要写的行为空（上一个实例是 0）时是一次零单元发布」（`crates/singlefs-core/src/mount.rs:1029`）——实例 1 的第一条根照抄 mkfs 的实例表指针，出生 txg 是 mkfs 那一版的，不等于它自己的 txg。照这个判据装置在每条流上报违例。第四条件本身不受影响（gap-row 要 R⁻ 的实例有行，实例 0 没有行），但判据要写成「写过行的实例」。

### 打中二：清扫那一形不需要读故障，环转一圈加一个洞就够

正推腿把「R 恰好是清扫改写实例表的那一版、而它前面同实例的版本又读不出」记成已知口子。读不出不是必要条件，盖掉也一样：

1. 实例 i 的最后一版 x 落了根；下一次可写挂载（实例 j）写行 (i, x, ·)，写行 x + 1、暖机 x + 2，挂载末尾清扫 x + 3（「可写挂载末尾（写行、暖机、抬 F、删除续做之后，交回之前）判一次」，`crates/singlefs-core/src/instance_table_sweep.rs:12`）。清扫只删「一个实例的根全部轮出根环之后」的那一行（`crates/singlefs-core/src/instance_table_sweep.rs:2`），x 还在环里，(i, x) 那一行留着；删的是别的实例的行，实例表指针出生 txg 变成 x + 3。
2. 实例 j 接着发到 x + 3S − 1；x + 3S 那次记录落了、根槽没落（D16 已定项 7 的崩溃形），x 那一槽没被盖，留成洞。
3. 实例 j + 1 写行 x + 3S + 1、再发 x + 3S + 2：x + 1、x + 2 两槽被盖，x + 3 还在。镜像取在这里（N = x + 3S + 2）。

镜像上相邻两版 (R⁻, R) = (x, x + 3)：txg 差 3；最新根的实例表里有 (i, x)；j > i、中间没有别的实例；R 的实例表指针出生 txg 是 x + 3 = R.txg。四个条件全成立，认成取号跳过，可 x + 1、x + 2 两版存在过。后果是这一对的用户可见树子树里的落点不判（漏判，不误红）。今天只认行的 H1-A 同样认错，第四条件在这一形上不起作用。不在清扫那一版上时第四条件有用：R 取 x + 4 之后的版本，出生 txg 是 x + 3 < R.txg，不认成跳过——所以口子只剩「R 是清扫那一版」，但它不要读故障，概率按「清扫与洞」算，不按「读坏一槽」算。
第一轮攻方的替代（取这个实例最早的、按行有效的根或记录的 txg）在 journal 还罩着 x + 1 那条记录时认得出（推的）。
四句：分辨 H1-A 与 H1-b 吗——这一形两者同错，不分辨；系统看得到吗——看得到 journal 里 x + 1、x + 2 的记录（罩着时）；满足的是 C698「把存在过的那一版认成取号跳过」那一句；两个改法：第四条件在这几格不起作用，按记录认的那一个起作用（推的）。
推翻条件：清扫发布不改写实例表指针（只改片内容），或清扫不在写行那次挂载里跑。

## Q8　C764 与 C70

### C764：正推腿 I-8.14 的「读不出整条部分没判」那一支

原文：「环里有读不出、不自证、落点对不上的根槽或记录槽时，整条报部分没判」（`research/prompts/m3-close-b19-checker-r1-sonnet-output.md:337`）。不自证的槽不只是坏槽：

- mkfs 只把第 0 代根种进三个区域的槽 0，其余根槽没写过；新池的 journal 环同样大半没写过。照字面，根环或 journal 环没转满一圈的池，I-8.14 每张镜像都整条部分没判。
- 每个崩溃态里在飞那条记录撕了或只落了一部分，那一槽不自证 ⇒ 整条部分没判；崩溃点重放的状态大多是这种。
- 不能简单把全零当「没写过」放过：写者一侧用户 2026-10-05 定「读回全零不算确认为空」（allocator.rs `record_root_written_by_this_process_rereading_slots_bad_at_mount` 文档「读回全零不算确认为空，用户 2026-10-05 定乙」），checker 照这个口径就得把全零当「可能藏着本该红的 txg」。

所以这一支要么整条 I-8.14 在多数镜像上报部分没判（判别力只剩环转满之后、没有在飞记录的镜像），要么改成按计数器圈定「可能藏着更小实例的较大 txg」的那几槽（第一轮攻方丁的思路：新实例最小计数器之下的槽才要求读得出），后者被攻过零轮。另外正推腿给「挂载那一刻读不出而今天读得出」写的「与 I-7.9 同一处已认代价」，方向问题同 Q2：那是误红，不是漏判。

### C70：分歧落在理由句

两腿判得到的对象相同：正推腿 I-3.20 (a)「空闲 + 已分配 + 不可回收 == 容量」三项都是落盘的统计量，判得；(b) 标签 6 对闭式也是落盘量对现算。第一轮攻方说的「可用(d) 不落盘、等式没有被比的一侧」与正推腿把四项写成射程外，落到镜像上是同一件事：式子左边没有盘上的值。分歧只在理由：正推腿写「只住内存」，checkpoint 保留池按 D28「按当时各记录树的高之和 + 记账节点现算」从镜像算得出，「只住内存」对它不是真话；理由该写「可用(d) 不落盘，这几项没有可比的一侧」。没找到 (a)(b) 在合法镜像上红的形（没读写者记标签 6 的代码，(b) 的闭式与真写者是否逐字节相同照旧没核）。

## Q10　core：C874 那行变异与 C745 第二次抽样

### C874：撕裂态在真实补写流上造不造得出

- 造得出：枚举对每个原地覆写接一条撕裂镜像，「torn[first_old_byte..].copy_from_slice(&old[first_old_byte..]);」（`crates/singlefs-checker-tier/src/crash.rs:2325`）。补写那块盘 D 的槽 1 是从全零覆写成新内容，也是原地覆写，撕裂态照造。
- 造不出新死盘：两轮之间有一道池屏障（「if let Err(cause) = pool.perform_commit_step(CommitStep::Barrier) {」，`crates/singlefs-core/src/transaction.rs:1291`，在「for _round in ACQUISITION_WRITE_ROUNDS {」`crates/singlefs-core/src/transaction.rs:1272` 那一圈里）；完好的盘第一轮写较旧的那一槽，第二轮写原来较新的那一槽时第一轮那一槽已过屏障；D 在基镜像里本来就死，撕了仍死，不算新死盘。所以撕裂态在流上有，只是没有一个让观察者的结论变。
- 判两腿：第一轮攻方说的「观察者只判整写那行变异在真实流上杀不掉」成立——那行变异改的是观察者，在这条流上与正确的观察者逐态同判。正推腿把变异挪到枚举侧的 `crash.rs:2325`，那行杀得掉（新流的闭式计数会少一截，`crash.rs` 自己的单测也会红），但它改的是枚举、不是观察者，杀掉它说明不了观察者的判别力。要观察者那一行有必红，仍只有第一轮攻方的两条路：合成态，或去掉两轮之间屏障的 core 变异录出来的流。
