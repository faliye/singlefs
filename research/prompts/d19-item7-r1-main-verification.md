## 三、问二（两份出生树）已判下的

- C（这类条目的指针不带出生树）：本地 s2、Sonnet、Opus 都判它撞定宽或已定项 8 的字面；Opus 指出它其实是 F1 在 inode 条目里的样子，材料把它写成了最弱形态。
- B（身份引用去掉出生树）：Opus 核出它撞 D9 第 553 行——D8 第 347 行那条边的 AAD 四段要「照抄条目」，出生树挪进指针就成了「从指针里读回来」。
- A（保留两份）：「一条定案都不改」写错了——类型段 0 条目的出生树 D8 没定义、I-9.2 类型 0 分支不查出生树（C289（码 2 的出生树取哪个字段没写） 同源）；要立的不变量要覆盖指针带的全部 key 段（Sonnet）。判据 3 几乎触发不了：两份在同一个码 2 单元里、由整单元校验和罩着（Opus，推的）。
- 本地 s1 / s2 在 A 那一格不一致（s2 的撕裂写构造站不稳）⇒ 不稳定。

## 四、不论问一怎么读都要记的

1. E128（指针带出生 (树, txg) 之后的点查代价） 记账树稳定慢 1.8%–4.5% 是已定项 8 本身的代价（丙已出局，E128 的对照臂不在候选集里），已定项 8 的代价行漏录，E134 的扇出下降（记账树内部 201 → 155、inode 内部 175 → 139）也没录。
2. 新不变量：按指针里的 key 在映射里取到的单元，头里各段必须等于那个 key（两臂都要）。
3. 「指针里的 key 段算不算 D9 期望值来源里的查找路径」全仓无条款。
4. journal 点名项凑不齐映射 key，重放时怎么凑没有条款。
5. P2 漏了 D5 deadlist 那个消费者；P3、P5 摘掉了射程句（Opus 第四节），写材料的人的错。
