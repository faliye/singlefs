## 二、定案（第三版）

### P1 形态：inode 树 = 内部节点（码 2，派生态）+ 叶（码 3 打包记录单元，记录类型 2，权威态单元）；根恒为码 2

- 叶 = 一个 32 KiB 码 3 容器，装 233 条 140 字节记录（记录类型 2 由「保留」转「启用」；day-1 类型，不需要位）。
  叶自带类身份段、记录数、记录宽、载荷校验和；扫描路径上的载荷完整性证据（C104 对码 2 的洞）对它不存在。
- 内部节点 = 码 2 索引节点，派生态，**条目 = 分隔 key 8 + 出生树 8 + 容器号 8 + 容器出生代 8 + 子指针 59 = 91 字节**（扇出 179）。
  出生树逐条目携带，是因为克隆头（D6 已定项 1）共享 origin 的叶容器，同一个内部节点里会混着出生树不同的条目；
  这正是 E90 判出的「指针带出生 (树, txg) 声明」的落点，AAD 期望值由此来自查找路径（A6）。E98 的内部扇出 243 对本形态不成立，树高不变。
- **根恒为码 2 索引节点**，即使只有一片叶（第一个事务多写一个 16 KiB 节点）。理由 F33：树表指针不带类，根的类若随树长大而变，读者按 16 KiB 读 32 KiB 是静默误读。
- **容器索引就是这棵树的内部节点**，不另立树。D18 已定项 11「容器索引是物理指针唯一持有者、别的树按身份引用」在这里读作：物理指针只住内部节点；
  dirent 树引用的是 inode 号。更新一条记录 = COW 叶容器 + 全部祖先（D23 甲）。与 D14 已否的跨文件尾部打包的区别成立：容器只有一个引用者。
- **内部节点不缓冲 inode 更新**：写路径不向 inode 树的内部节点投递消息，缓冲区恒空（一条可判的不变量）。不改 D11 已定项 6 的 ε、不开按树分支；
  代价是内部节点里 ε = 0.65 的缓冲区空着，扇出按可用区算（1e4 / 1e6 / 1e8 树高不变）。理由：整个索引被丢弃重建时缓冲里的 inode 更新会丢，撞硬约束 6。
- **态别**：叶是单元（权威态第一项），内部节点是索引（派生态）。**D21 要补一句**：「态别的载体是单元类，不是『树』这个词；一棵树的内部节点是派生态，
  它的叶若是码 1 / 码 3 则是权威态」——D21:8 与 D21:394 本来就打架（记账是树却是权威态），这一句是化解它的读法。
- **内部节点丢了从叶重建**：收集记录类型 2 的容器，按 (出生树, 容器号, 容器出生代) 分组，同身份多版的择现行 = C113（本项不解，点名）；
  每叶 key 范围由记录算；重建产物落 D18 已定项 5 的**级 1（只读挂载）**，级 2 的见证者今天不存在。
- **永久的字节**：记录格式（P5）、码 3 类身份段对类型 2 的用法、inode 树的 key 编码。**D15 第 1 层要补「打包记录单元的载荷记录格式（按打包记录类型登记）」**，
  否则这条永久契约在四层里没有归属。内部节点布局不永久（派生态整层退出冻结）。

### P2 不进本项的：树的种类、树 ID 的分配

树 ID 的分配与编码规则全仓无落点，卡第一个事务（三棵树都要 ID），立欠账；扫描重建靠码 3 头里的类型 2 + 出生树认领 inode 叶，不需要树表带种类。

### P3 装载纪律按记录类型分写（改 D18 已定项 11）

四条纪律里「② 一容器一个代际」与「快照发布前先关闭开放容器」**只对按代际回收的记录类型**（打包记录类型 1，墓碑）成立；
**记录类型 2 不适用**：inode 记录逐条死亡，容器由 B 树分裂 / 合并回收，一片叶活很多代、反复重写。按字面套用会禁止跨代际的叶合并、让树失去平衡能力。
C105 / C106 对类型 2 的口径随之改（容器数 = O(inode 数 / 233)，每次发布重写被碰到的叶——E103 第三臂量的正是它）。

### P4 容器身份不需要分配器：容器号 = 创建时第一条记录的 inode 号

- 叶容器的身份 (出生树, 类型 2, 容器号, 容器出生代)：**容器号取该容器创建时的最小 inode 号**，出生代取创建它那次发布的 checkpoint_txg。
  分裂：左半身份不变（最小 key 不变），右半是新容器（容器号 = 分裂 key，出生代 = 本次发布）；合并：保留左半身份，右半退役走 COW 释放路径。
  唯一性：同一次发布里不会有两个容器以同一个 key 创建（key 在树里唯一）；不同次发布以同一 key 创建的容器出生代不同。
- 与 C103 给墓碑容器的「单调分配、回退不破身份」是两条规则（按记录类型分），本项只定类型 2 的。

### P5 inode 树的 key：`(inode)` 8 字节；inode 号单调不复用；水位是记账里的单调统计量

- key = inode 号；唯一性范围 (树 ID, inode)。**inode 号单调不复用**（F24 / F34 同一戒律）：`deleted_inodes` 后台回收窗口里复用会让新旧对象的 extent key 三段逐字相同。
  位宽 64、声明生命周期创建总数上界 2^63（F34 要求声明）。
- **下一个 inode 号是记账里的一条统计量**：key = (统计量「inode 号水位」, 树 ID, 代)，**不带设备维**（D5 已定项 4 第 4 / 6 / 7 项的口径），value = 下一个可用号。
  **合并规则取最大值**（幂等且与次序无关）——不依赖 D8 未定项 7 的 seq，不受 write buffer 排序丢时间序影响。这是 D5 已定项 3「后者胜」之外的第二种合并语义，
  只对单调统计量开放，写进 D5 已定项 4 的表（新第 12 项）与已定项 3。标签值随 C71（十一项今天都没分配）。
- **克隆头**：新头的水位初始化为 origin 快照那一刻的水位（与 D6 已定项 2 的 `prev_snap_txg` 同一条纪律）；两个头此后分配的号不相交。
- **不变量**：水位 > 该树 inode 树内最大 key，> `deleted_inodes` 树内最大 key，> 该树全部墓碑记录的对象 ID（checker 遍历侧与运行时水位是两条独立路径）。
- 未发布的事务重发同一个号是安全的：水位与叶容器共用同一个发布屏障，未发布的事务等于没发生。

**记录宽必须等于登记表给类型 2 的宽（140）**，不等判损坏（写进 I-1.7）；改宽是 incompat。

### P7 不变量（新开 I-9 命名与对象 一类）

1. 身份对照：记录 inode == key；不等判红、EIO，不许静默修复。
2. locality 对照：记录 `locality_id` == 该对象每条 extent key 首段；**三值输出**：extent 树未经重建时判红 / 绿；重建后两侧同源，输出「不可判定」而不是「通过」。
   要在重建后有判别力需要 locality_id 在权威侧另有见证——六元组候选 `locality_id`（D18 已定项 3 待用户定案），不在本项。D9 已定项 6 排除它的那行理由随那一格重写。
3. nlink == dirent 条数，**由「dirent 树存在」门着**（不是 feature 位：开放树表不分配位，`feature-bits.md` 也不存在）；dirent 树不存在时不评估，存在时零豁免；
   前置是树的种类可识别（P2 的欠账）。第一版的唯一文件取 inode 1（0 无效），nlink = 1，不进孤儿回收。
4. inode 号水位 > 三处最大号（P5）。
5. inode 树内部节点的消息缓冲区恒空（P1）。

### P8 第一个事务写什么，以及它今天仍写不出来的三样

写：一个码 2 根节点（一条条目：key 1、出生树、容器号 1、出生代 1、指针）；一个码 3 叶容器（类型 2、容器号 1、出生代 1、记录数 1、记录宽 140）；
一条记录（inode 1、出生代 1、locality 0、nlink 1、改动计数 1、flags 0）；记账里一条「inode 号水位 = 2」。
**仍挡着的**：树 ID 的分配规则（P2）；记账条目的 seq（D8 未定项 7，水位那一条不需要它、别的记账条目需要）；统计量标签值（C71）。三样都是既有空白，不是本项新开的。
