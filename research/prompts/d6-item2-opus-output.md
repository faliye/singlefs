## 3. 假前提 B：「无戒律」豁免的是**「允不允许遍历」这一列**，不是「要不要盘上结构」；而且它自带一个前置

### 3.1 表头就是答案

`.claude/rules/fs-design.md:21-25` 逐字（整表，含表头）：

```
| 消费者 | 允不允许遍历 | 为什么 |
|---|---|---|
| **运行时决策路径**（分配、ENOSPC 准入、defer 窗口、生命周期判定） | **不许**，且代价不许随盘容量增长 | 不是慢，是**在被问到的那一刻没有答案**。准入控制要「进门前先算最坏情况」，而「释放空间这个操作本身不需要申请空间」也压在同一个数上 |
| **checker / 审计** | **必须**遍历 | 若运行时也用遍历算，checker 的遍历与运行时就是**同一次计算**，对照关系当场归零 |
| **后台、可续做、非决策路径**（销毁快照、整理、scrub） | **无戒律** | 它们走「写意图 → 分批 → 可续做」，不参与任何即时判定 |
```

⇒ **「无戒律」是「允不允许遍历」这一列的取值。** 这张表从头到尾在回答一个问题：
**这条路径许不许遍历。** 它对「这条路径要不要一个盘上的第二结构」**一个字都没说**，
也不可能说——第三格里逐字点名的「整理」与「scrub」，在本仓各自都有盘上结构与欠账
（`.claude/kb/decisions/26-后台整理与放置回收.md:89` 逐字「意图本身住 logged_ops 树（D8（核心索引结构） 已定项 5），分配器读得到」）。
**「无戒律」从来不等于「无结构」，同一格里的另外两个成员就是反例。**

## 4. 假前提 C：「销毁快照」与「销毁一个可写头」在仓里**已经被逐字分开**

判据 2 要求给出「仓里任何一处把两者归为一类或分开的逐字依据」。**分开的依据有四处，互相独立。**

### 4.1 两者各自被指派了**不同的盘上结构**

`.claude/kb/decisions/05-快照-空间记账机制.md:9-10` 逐字（销毁快照用什么）：

```
- 销毁快照时把它的 deadlist **合并到下一个更新的那一侧**，并按 `birth > prev(S).txg`
  过滤出可释放的条目。不做全盘扫描。
```

`.claude/kb/decisions/05-快照-空间记账机制.md:154-156` 逐字（销毁可写头用什么）：

```
3. **销毁一个可写头需要第二个结构**（ZFS 的 livelist 形态：ALLOC/FREE 配对、按 birth txg 分组、
   可增量、可 condense）。不承认它，「永不事后遍历」在这条路径上就是假的——
   要释放的是 `birth > origin.txg` 的那批块，散落全树。
```

⇒ **「第二个结构」这四个字本身就是分类判决**：它相对的「第一个结构」是 deadlist，
而 deadlist 是**销毁快照**那条路径的载体。一句话里同时定义了两条路径和它们各自的载体。

### 4.2 两者的代价量纲被逐字写成不同的

`05:175` 逐字：

```
**销毁快照的代价是 O(deadlist 条目数 + 桶数)，不是 O(全盘)**，
```

`05:156` 逐字：**「要释放的是 `birth > origin.txg` 的那批块，散落全树。」**

⇒ 一条明写 **不是 O(全盘)**，一条明写 **散落全树**。**同一份文件里，同一位作者，相隔 20 行。**
把两者当同一条路径，等于说这两句在描述同一个量。

### 4.3 可写头有一行记账，快照没有——所以销毁动作本身就不同

`05:341` 逐字：

```
合并规则取最大值（见已定项 3）。只为可写头维护，随每次发布重写（已定项 2 的 K 代点删要求每行每发布重写，第 8 / 9 项同），只读树（快照）没有这一行。
```

（说的是 `05:332` 第 12 项「inode 号水位」，逐字：`| 12 | inode 号水位（下一个可用 inode 号） | ... | 不带 | **带**（只为可写头维护） |`）

⇒ **销毁一个可写头，除了释放块，还要处理一行只有可写头才有的记账**；销毁快照没有这一步。
`.claude/kb/invariants.md:263` 已经把它做成不变量：

```
| I-9.11 | 可写克隆头有水位行 | 每个可写克隆头的树 ID 在记账里都有「inode 号水位」行（树表可枚举、记账可查）；...
```

⇒ **两条路径连 checker 侧的义务都不一样。**

### 4.4 约定 B 的机器对可写头没有定义

`05:9` 逐字「合并到**下一个更新的那一侧**」。
`05:152` 逐字：

```
2. **分叉点快照不许销毁**（约定 B 在分叉点没有唯一的 next）。判据是 O(1) 子计数 `children > 1` → 拒绝；

### 5.2 本仓唯一一次把「销毁」送进意图分批，结果是**破掉了 O(1) 归约的第二个前提**

`.claude/kb/decisions/05-快照-空间记账机制.md:178-189` **整节逐字**
（材料的小节清单把它标成「不抄」，理由「与本轮无关：它答的是记账口径 / 代 / key 宽度」——见第 7 节，那个理由可核为假）：

```

D8（核心索引结构） 已定无界删除走「写意图 → 分批 → 可续做」，判定因此发生在物理批次那一刻，
而逻辑死亡早得多——归约的第二个前提被破。**D5（快照 / 空间记账机制）取的处置：待删除结构（意图 key、删除中队列）

**O(1) 保住，且不需要新增任何不变量**。

代价是一个用户可见现象：`rm` 返回之后建的快照会**钉住**那批尚未释放的 extent，

**另一条路（把待删除结构算作已死）会破坏 O(1)**：正确的 deadlist 属于「逻辑死亡之后建的第一个快照」，

3. **它写死了另一条路会破坏 O(1)。**
