BACKGROUND. Singlefs stores several of its own internal indexes as trees built out of a fixed-size on-disk node format called format-2. One of these trees, the extent tree, records where a file's data units are stored on disk; today it is implemented with only a single node, which acts as both the root and the only leaf, with no internal levels at all. Unlike some other trees in this codebase, the extent tree already has a decided format for what an internal-node entry would look like if it grew a second level, given in FACT 5 below; this document computes arithmetic under a second, hypothetical, not-decided alternative format instead, given in FACT 6, purely for comparison. A design decision has been made to give this tree, among others, the ability to grow additional internal levels above its leaves as the number of entries in it grows, addressing the case where a file is large enough that all of its data-unit references can no longer fit in one single node. This document computes node-capacity, tree-height, total-node-count, and single-publish node-rewrite-count arithmetic for the extent tree, under the one hypothetical internal-node entry format given in FACT 6, given fixed already-decided numeric inputs plus that one hypothetical alternative; it does not ask you to decide whether growing extra levels is the right design, or how the split and merge logic should work, or whether the hypothetical alternative in FACT 6 is better or worse than the already-decided format in FACT 5.

FACT 1. In this filesystem, an on-disk structure called a format-2 index node is always exactly 16384 bytes in total size, regardless of whether it is a leaf node or, for a tree that has one, an internal node.

FACT 2. A format-2 index node's total header size, in bytes, is computed by a formula that depends only on that node's key width in bytes, not on whether the node is a leaf node or an internal node: header size equals 86 plus 2 times the key width in bytes plus 29. Within one single tree, every node at every level uses the same key width and therefore the same header size as every other node in that same tree. The extent tree's key width is 24 bytes, and applying the formula gives this tree's header size as 163 bytes; this 163-byte header size is itself a literal already-decided constant in this codebase, not merely something you need to derive; the formula is given only so you can see where it comes from.

FACT 3. The extent tree's leaf-entry width, in bytes, meaning the fixed size of one data record stored in a leaf node's entry area, is 112 bytes, made up of a 24-byte key plus an 88-byte data pointer. This 88-byte data-pointer width is the fixed size of a pointer that points at a format-1 data unit holding actual file content; it is different from, and 2 bytes wider than, the 86-byte child pointer defined in FACT 4 below, which points at another format-2 index node or a format-3 packed-record container, never at a data unit. The 112-byte leaf-entry width is itself an already-decided constant in this codebase.

FACT 4. In this codebase, a pointer stored inside one format-2 index node that points at a single child node, where that child may be either another format-2 index node or a format-3 packed-record container, is always exactly 86 bytes. This 86-byte width is the same fixed value used everywhere in this codebase that a format-2 node needs to point at one child; it does not vary by tree and does not vary by level. This is a different, narrower kind of pointer than the 88-byte data pointer used in a leaf entry from FACT 3, which points at a data unit rather than at a node.

FACT 5. This codebase already has two examples of a decided internal-node entry format for a format-2 tree, and both examples follow the same pattern: one internal-node entry consists of exactly one separator key plus exactly one 86-byte child pointer from FACT 4, and that one entry corresponds to exactly one child; there is no additional child pointer beyond the number of entries in the node, unlike some other tree designs where an internal node with n keys has n plus 1 children.
