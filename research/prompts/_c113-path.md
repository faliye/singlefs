# C113 的定案提案（第一版，2026-09-05，等三方论证核）

**要定的**：C113（扫描重建时多版单元的现行版本判定无输入）——索引与分配记录都丢了、只剩单元 + 记账 + 根的时候，
同一逻辑身份的多个物理版本里哪一版是哪个根的现行版本，判定的**输入住哪、规则是什么**。
它同时挡着 D21 已定项 5（分配记录的重建机制）、D11 已定项 3 / 4（重算源的归因）、D8 已定项 6 的两条实例。
**提案是推论，先过三方论证再进正文。**

## 二、问题的精确形态（提案前先把靶子画清）

扫描找到的、头校验和通过的单元，对某个逻辑身份 k 可能同时存在四类版本：

| 类 | 怎么来的 | 运行时靠什么排除 | 扫描时今天靠什么 |
|---|---|---|---|
| (a) 现行 | 被某个根（可写头或快照）引用 | — | — |
| (b) 已发布后释放的垃圾 | 被覆写 / 被删 / 快照销毁后释放，落点还没被复用 | 分配记录说它空闲 | **没有**：与 (a) 长得一样（F6 判决段第二条） |
| (c) 从未发布 | 崩溃时在飞事务写下的；崩溃后 checkpoint 号被重发 | 分配记录里没有它 | 诞生代号 > 根 txg 的那一半靠 I-1.2；**诞生代号 == 重发后已发布代号的那一半没有任何判据**（F6、F8、F14 实例 ①） |
| (d) 撕裂 | 半写的 | 校验失配 | 码 3 靠载荷校验和；码 1 / 2 是 C104 |

叠加两样让它更紧：**多可写头**（F13，同一逻辑 key 在不同头下有不同版本，头里的树 ID 是出生树，克隆头的版本与 origin 的版本要按谱系分给各自的根）；
**墓碑回收**（F11：墓碑在快照送走死亡之后可回收，而 (b) 类垃圾仍可读 ⇒ 回收之后扫描会把死 key 复活，E59「复活数 = 删除次数」的形态在墓碑被回收之后重现）。

**靶子**：给出一组输入（全部住权威态或单元头）和一条规则，让对任一根 R、任一逻辑 key k，`Current_R(k)` 与真值相等，覆盖 (a)–(c) 四类、多头、崩溃重发、墓碑回收、分配器复用释放空间；并且规则本身能被 checker 独立实现（F16）。

## 三、提案

### P1 单元头带「写序」：为该单元点名的 journal 记录的 jsn

**共同前缀加 10 字节「写序」= 那条点名它的 journal 记录的 jsn（实例代号 32 + 计数器 48，就是 D23 已定项 9 那个数），三个类一次都带上**（42 → 52；码 1 头 91 → 101，码 3 头 93 → 103，码 2 三档各 +10）。
写路径：事务成形时先取号，再写单元、屏障、写记录——D16 已定项 7 的持久顺序一个字不动，只是记录的号提前取。

**写路径纪律 W1**：一个事务里同一逻辑 key 至多写一个单元（事务成形前的重复脏数据只写最后一版；已写出但尚未被记录点名的单元允许原地重写——它不在任何已发布状态里，D16 新规则 2 管的是已发布的释放）。
⇒ 同一逻辑 key 的全部已写单元被写序**全序**（jsn 全局单调，F7）。

**它是对 D18 已定项 1 的重开，按那条自己写的射程重开**：已定项 1 否掉的是「为分辨陈旧副本而设的序号」，理由是那件事已由 D3 已定项 1 的谓词买到。
可谓词的「权威记录点」是运行时口径（F1），它买到的只有运行时那一格；扫描重建那一刻谓词的两半（分配记录、deadlist）正是被重建的东西（F1、F2）。
写序买的是**谓词没有输入的那条路径上的次序与已发布性**，不是运行时的陈旧判别——运行时照旧问分配记录。

### P2 已发布性住权威态：实例水位表

**记账里新增一个统计量「实例水位」**：key = (统计量, 实例代号, 代)，value = 该实例最后被施加的 jsn 计数器值。
**只在实例以崩溃结束时写一行**：恢复完成、新实例发布第一个根之前，把上一实例的水位写进这次发布；干净卸载不写（没有行 = 该实例的全部写序都已发布）。
**它不受 D5 已定项 2 的 K 代点删约束**——统计量登记表加一列「保留规则」，实例水位登记为「永久」；理由是 D5 要「代」的机制理由（根回退账要跟着回退，F17）对它不成立：它是一次性事实，写下之后不再变，回退到哪个根都一样。
规模：每次崩溃一行，按 D23 已定项 9 采用的场景点（每天崩 10 次、十年）是 36 500 行。

**已发布谓词**：单元 u 的写序为 (i, c)，所选根的实例为 i_now：
- i < i_now：表里没有 i 的行 ⇒ 已发布；有行 ⇒ c ≤ 水位 才算已发布（崩溃那次 txg 里重放施加了的事务在水位以内，被抛弃的在水位以外——jsn 严格连续、断号即止，F7）；
- i == i_now：u 的诞生代号 ≤ 根 txg 即已发布（当前实例没有在飞的已发布事务）；
- i > i_now：不可能出现在所选根之前的世界里，判损坏。

这正是 F20 里 bcachefs 的 journal seq blacklist 那件事在本工程的形态；差别两处：本工程的 jsn 已按实例代号切分（D23 已定项 9），所以一次崩溃只要一个数而不是一段区间；黑名单在 bcachefs 住超级块字段，这里住记账树（权威态、COW 挂根下、有校验和与 MAC）。

### P3 现行版本判定规则

输入：所选根 R = (树 t_R, 代 T_R)，全部根的集合 ℛ = 树表里的可写头 ∪ 快照列表（I-3.7，F9 欠的那份「全部根的 txg 列表」就是它），祖先表 anc(t)（见 P6），实例水位表，扫到的单元集 U，墓碑记录（P5）。

逻辑 key 与写者树按类定：码 1 的 key = (对象 ID, 对象出生代, 锚点偏移)，写者树 = 五元组的树 ID（写它的那棵树，与 E90 的出生树同一语义）；码 3 的 key = (出生树, 打包记录类型, 容器号, 容器出生代)，写者树 = 出生树（P6 让这句成立）。

```
Visible_R(u)  := 已发布(u) ∧ u.诞生代号 ≤ T_R ∧ ∃(a, c) ∈ anc(t_R): u.写者树 = a ∧ u.诞生代号 ≤ c
v*(R, k)      := Visible_R 且 key = k 的单元里写序最大者
Current_R(k)  := 若存在对 R 可见、指认 k、且死亡写序 > v*.写序 的墓碑记录 ⇒ 死；否则 v*
```

三个派生量，全部由规则算出、不再是神谕：
- 分配记录 = { loc(Current_R(k)) : R ∈ ℛ }（被任一根引用的落点即已分配）；
- 可写头 H 的 deadlist = 对 H 谱系上某快照 S 现行、对 H 不现行的落点；
- 垃圾 = 可读、已发布、不属于任何根的现行版本的单元（P4 交给 scrub 处理）。

对打包记录类型 2（inode 叶）多一层：两个对 R 可见的容器版本若装着同一个 inode 号的记录，取容器写序大的那条记录——这是 P6 容器重生之后、克隆头视野里 origin 的旧叶与自己的新叶重叠的那一格。

### P4 垃圾不在释放路径上抹，在 scrub 里抹；墓碑回收多一道门

释放路径不加任何 I/O（F10 的原则照旧）。**scrub 本来就全盘读**（F16 第三格），它顺手把「可读、已发布、不是任何根的现行版本」的单元抹掉头（写一个扇区），并记下一个「抹头水位」= 截至哪个 txg 之前的释放已全部抹完。
**墓碑记录的回收条件 = D18 已定项 10 的条件 ∧ 抹头水位 ≥ 该墓碑的死亡代号。**
理由：墓碑回收之后，(b) 类垃圾若仍可读，P3 会把它判成现行——E59 的复活形态。抹头把可读垃圾清掉，墓碑才能走。
scrub 从未跑过时墓碑只增不减，上界是删除总数（E83：一百万个对象的墓碑 107 MiB），如实记。

被否掉的形态：释放时当场抹头（每次释放一次小写、且要一张持久的待抹清单才崩溃安全）；每事务先写意图记录再写单元（每次 fsync 多一道屏障）；分配器限定在游标段内分配、恢复时只扫段尾（给 D3 加一条分配策略约束）；崩溃后烧掉整个在飞 txg（部分重放时那个 txg 是已发布的，烧不掉）。

### P5 墓碑记录带死亡写序；容器退役也写墓碑

打包记录类型 1 的记录加 10 字节「死亡写序」（删除那个事务的 jsn），P3 用它与单元的写序比大小；只有代号没有写序时，同一 txg 内先删后写与先写后删分不开。
**新增打包记录类型 3「容器退役」**：记录 = 被退役容器的 (打包记录类型 2, 容器号 8, 出生代 8) + 退役写序 10。D8 已定项 6 的合并（左吸收右）写一条；
没有它，退役容器的最后一版留在盘上、身份没有更新的版本，P3 会把它判成现行，它装着的记录在左半后来删掉之后就复活。
类型 3 的回收走 P4 同一道门。

### P6 跨头首次 COW 让容器重生；树表条目带 (origin 树, 克隆点 txg)

码 3 容器被另一个头首次 COW 时**取新身份**：出生树 = 写者树，容器号按类型的规则取（类型 2 = 容器里最小的 inode 号；类型 1 = 树内单调分配），出生代 = 本次发布。
理由：码 3 头里只有出生树，没有写者树；不重生则克隆头的版本与 origin 头的版本同身份、谱系过滤分不开（F14 实例 ②）。代价：克隆头第一次碰到每片共享叶时多出一个新身份，内部节点条目本来就要为这次 COW 重写。这就是 E90 第二笔对码 3 的答复（C110）。

祖先表：树表条目带 (origin 树 ID, 克隆点 txg) 两段，anc(t) = {(t, ∞)} ∪ 沿 origin 链上溯、每一环的上限取路径上最早的克隆点。它是 E90 要求「住已认证结构」的克隆祖先表在本工程的落点；D8 未定项 8 的其余段（树的种类等）不在这里定。

### P8 实验 E104（判据先写死，跑完不许改）

计数模型，零文件操作。世界：对象、多 txg、每 txg 多个事务、覆写 / 删除 / 截断、快照、克隆头、随机崩溃（在飞 txg 里一部分事务被重放施加、其余抛弃，checkpoint 号重发、实例代号 +1）、墓碑按 D18 已定项 10 回收、分配器按 FIFO 复用释放空间（复用即抹掉旧头）、类型 2 容器的分裂与合并、可选的 scrub 抹头。
真值：模型在每个根发布那一刻记下每个 key 的现行落点。

臂：神谕臂（E59 乙臂形态，阳性对照）；全规则臂（P1–P6）；六条消融臂各去掉一个构件（写序、实例水位、祖先表、死亡写序、容器退役记录、scrub 门）。

判据：
1. 全规则臂对全部根、全部种子：错版本 = 复活 = 判死实活 = 歧义 = 0。**任一非 0 ⇒ 提案不完整，记下是哪一类世界，不许回头改规则再跑同一个实验**。
2. 每条消融臂在它对应的靶子世界上必须 > 0，且数值钉闭式（例：去掉实例水位 ⇒ 错版本 = 被抛弃事务里「崩溃后没有再写过同一 key」的单元数；去掉 scrub 门 ⇒ 复活数 = 「墓碑已回收且旧版本仍可读」的 key 数）。闭式由世界生成器独立计数，不从被测代码读回。
3. 神谕臂恒 0；扫到的单元数 ≠ 独立算出的应有数 ⇒ 整轮作废；往任一臂注入 k 处破坏必须报出恰 k。
4. 反过来接不接受：若全规则臂在某类世界上非 0 而消融臂也非 0，说明缺的构件不在六个之内，提案回到第二节重画靶子。
