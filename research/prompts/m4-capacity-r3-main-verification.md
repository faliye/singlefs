## 二、判决

用户在两腿交回之前定了三条（弹窗，`records/2026-11-17-里程碑四收口续做.md`）：逐盘容量表不算设备描述符表；容量变小时只读挂载放行并点名该盘、可写拒；盘变大时挂载就把新容量记下来。第三条与前两轮站住的「记录只在 mkfs 写」相反，「记」怎么原子地写另立一题（m4-capacity-grow）；这份判决收其余部分。

三轮多数判：

- 落点：三轮里攻方两轮判甲不如乙、辩方一轮判甲出局站得住，没有一轮翻回。**定乙**：每块盘的系统配置带逐盘容量表，按设备号 0 到 devs − 1 排，每项 8 字节整槽数。
- 表的位置（P2 坐实）：表追加在今天 489 字节的定长部分之后，F 留在偏移 481 不动；core 里 F 的偏移改成写定长部分的常量减 8，不再从合计倒推。两腿这一轮各自得出同一写法。
- devs 的值域（P1 坐实）：读表之前判 devs ≤ 450（槽内最多 450 项，两腿算出同一个数），本盘设备号 < devs；「表项数与 devs 不等」那一句删掉，槽尾恒 0 照旧只由 checker 判（C728 的用户定案不动）。
- 读者：跨盘、跨槽（限本池 fsid、这一版认得的自证槽）容量表不等整池拒；每块盘探测值小于它那一项——可写挂载拒，只读挂载放行并在报告里点名（用户定）；表项为 0 整池拒。
- 写者：每条写系统配置槽的路抄择到的表，连 devs 一起抄（正推：`crates/singlefs-core/src/transaction.rs:723` 今天按盘表现数）；离线修复同样。盘变大时哪一步改表，归 m4-capacity-grow。
- 读数出口：全部取记录值，出口清单以正推第三轮报告第一节为准（比正文多 journal 环扫描、实例表扫描、离线修复扫描）；checker 与 GPU 判器的容量出口同样（攻方 Q5）。
- N1：根层级的设备集合按交进来的盘算，容量读数换成记录值；`fsync_drop_and_devices_without_the_selected_version.rs:262` 那条用例不动，新增「交进来的盘身份不在 0 到 devs − 1 ⇒ 整池拒」。只有正推一条腿答了这一格，攻方没攻，零轮。
- 撕裂维度：攻方撤回 N5，任务 18800 两条单测绿；505 或 513 跨不跨 512 不改崩溃点重放的态数。D22（单元原子性怎么合成） 已定项 9 那两句「跨 512 要多枚举一个撕裂维度」与实现对不上，记欠账，不在这一题改。
- 推翻的旧定案：C323（镜像大小全仓没有条款） 第 4 格「2026-09-14 用户定案：不加字段」被用户今天的「记容量、动格式」推翻；连带 `fragmentation_statistics_follow_the_probed_device_capacity.rs:125` 那条必红用例反转（探测容量加长、记录不变 ⇒ 不红），I-3.16、I-5.2 的盘末改取记录值。
- 新不变量：I-7.20（各盘各可择槽的逐盘容量表逐项相同）、I-7.21（每盘现有整槽数不小于表里它那一项）；值域进 I-7.13。编号写回时现查最大号。
