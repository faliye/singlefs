**乙、丙（码2/码3那一半）、戊**：新增的「出生序号」「实例内计数」分量按候选定义写入头（`packed_slot_extra`/头宽增量在 E133 里逐条可查），一旦写入即为自描述字段，扫描直接读出。**过。**

**丁**：候选定义（背景材料第二节第47行）「指针里的位置条目冻结在出生落点、永不刷新；三类单元头各+10（出生落点）」——把「出生时的物理坐标」写进头，之后即使被后台整理搬走，头里那份值也不跟着刷新（这正是它能扫描重建的原因：搬迁后头仍能给出与 map 里记录的**同一个**冻结值）。**结构上过**，但需要明确一点：D2（RAID 条带策略） 已定「N个副本是同一份密文写N遍、共用同一个nonce」（`.claude/kb/decisions/19-块指针的结构与宽度预算.md:42-161` 引用同一决策），而 F1（`I-2.3（补齐字节为零且参与校验和）`；`D4（校验和位置）` 开篇；`D19（块指针的结构与宽度预算） 已定项5`）要求整单元（含头）逐字节相同——**这意味着 w=2 个物理副本的头必须逐字节一致**，「出生落点」若字面理解成「我自己所在的坐标」，两个副本的头就不可能相同（它们分别落在不同的device/slot）。候选定义只写了单数的「出生落点」，隐含的读法只能是「以某个规范副本（如位置条目第0项）的坐标为准，两份头都写这同一个值」。按这个读法扫描仍能给出与 map 侧一致的 key，**过**；但按字面最弱读法（各自记自己的坐标）两个副本头就不相同，会撞 F1——这是丁需要在定案时显式写清的一条，本轮记为「过，附一条需澄清的设计细节」，不判输，因为候选表述本身用的是单数、指向「唯一入口冻结值」的读法。

### §2 引用侧可构造（射程：解引用、D5 释放判定〔单一引用块，F4 射程〕外的其它路径、deadlist/livelist 条目处理、搬迁、checker、扫描重建、模型对拍；不多读一次单元、不多查一棵树）

**判据来源**：背景材料第三节问2。**触发条件**：存在一条路径要多读一次单元或多查一棵树才凑得出 key；**唯一的例外**是 D5 单一引用块的释放判定（F4 射程内）本来就不需要完整 key。

**七条候选的共同设计**：Section 2「谁携带、单元头加什么」列全部写的是「指针（整段/部分）携带」，也就是说每条候选都选择把 key（或其能推出 key 的分量）**直接放在指针里**，而不是要求解引用/释放路径去反查别处。这正是本轮候选集相对第二轮已出局的候选②（「逻辑身份键的字面形态」，`D19（块指针的结构与宽度预算） 未定项6` 第 821 行 ②）——「对象ID与锚点偏移从extent树的key取，在reflink到另一个文件时凑出的是引用者自己的身份，映射查不到」——的直接修正：甲不再从 extent 树现算对象ID/锚点偏移，而是让指针整段携带（背景材料第二节第44行「指向码1的指针整段携带（+50，标签由路径给）」），这样即便是 reflink 之后的引用者，读到的仍是**目标单元自己的**五元组，不是引用者自己的坐标。

逐候选核对：

- **甲**：数据指针 +50（五元组除类型标签外的32字节+诞生代号8+写序10），码2/码3指针 +16（出生树+出生txg）。解引用直接读指针即得完整或近乎完整的 key；码2 的「层级」与「key区间下界」由查找路径给（背景材料第44行），这不算多一次 I/O——按树查找时，父节点本来就要给出「往哪个子节点走」，子节点的层级=父节点层级−1、子节点的 key 区间由父节点里的分隔 key 决定，这是遍历过程本身的副产品，不是额外查询。**过。**
- **乙**：指针整段携带 +24（背景材料第45行），同理直接可得。**过。**
- **丙**：码1指针 +26、码2/3指针 +24（背景材料第46行），同理。**过。**
- **丁**：位置条目本身就冻结成了出生落点，指针追加出生txg8（背景材料第47行），key 三段（出生设备、出生槽号、出生txg）解引用时同样直接可得。**过。**
- **戊**：指针 +12（背景材料第48行），实例代号本就在写序里，key 两段直接可得。**过。**
- **己**：指针 +16（随机标识本身），直接可得。**过。**
- **庚**：指针 +2（背景材料第50行；出生设备/出生槽号复用位置条目本身，每槽版本号单独+2），key 三段解引用时直接可得。**过。**

**deadlist/livelist 路径的连带解锁**：这一格值得单独指出——D26（后台整理与放置回收） 未定项5 ③（deadlist 条目装什么）此前卡住的原因逐字是「那33字节里的树ID段是出生树，而 I-1.3（块头树ID一致） 逐字「跨头共享时与引用树不同」⇒ 删除侧凑不出它，除非多读一次单元头，而那就打破了 D5（快照 / 空间记账机制） 那条 O(1) 归约」（`.claude/kb/decisions/26-后台整理与放置回收.md:351-367`）。这个卡点的前提是「指针不携带出生树」。而背景材料自己在 `D19（块指针的结构与宽度预算） 未定项6` 那一格已经指出（第821行）：「第三轮候选集里每一条都让指针携带出生树与出生txg……⇒ 这一格一旦定下，未定项7的丙被排除」。既然七条候选无一例外都让指针带上出生树+出生txg（上面逐条核对已验证），**D26 未定项5③ 的卡点在本轮任何一条候选下都不再成立**：删除侧（拿着自己那份指针）已经能直接读到出生树，不需要多读一次单元头。这不是某一条候选独有的加分，而是「选哪条候选都能解锁」的共同后果，我把它记在这里，§8 会再引用。

**结论**：Q2 对七条候选**全部过**，无一在这一格分出高下。

### §3 射程与运行期唯一（码1/码2/码3/D27 容器槽各给不给得出全池唯一的 key，含同一 checkpoint 固定点写出的多版〔F8〕、reflink 之后的覆写、跨头首次COW〔F9〕）

**这一格是本轮我作为正推腿最重要的发现：甲在码2、码3两类上都输。**

**触发条件**（判据表原文）：「某一类给不出，或存在两个活着的单元同 key」。

**F8 的字面**（背景材料第一节第32行）：「码2/码3的写序在固定点上没有判别力：容器只在checkpoint的固定点写出、事务号取那次checkpoint已分配的最大事务号、固定点各轮取的是同一个号⇒同一checkpoint里同一个容器的两版身份、诞生代号、写序逐字节相同（C163（固定点各轮写序相同使平局破除落空））；码2的写序只有实例代号4字节」。

C163 的完整原文（`.claude/kb/checks-owed.md:174`）比 F8 摘要更精确，且明确点出射程覆盖码2：

> 「I-1.8（归并后版本全序） 给码3的全序键是(诞生代号,实例代号,事务号)……事务号留在末位做同一checkpoint内的平局破除，固定点会迭代、同一容器在一个checkpoint里不保证只写一次；而 D18（块里携带什么信息） 已定项7 的取号规则逐字「容器只在checkpoint的固定点写出，事务号取那次checkpoint里已分配的最大事务号」。……各轮取到同一个号⇒同一checkpoint内两版容器的写序逐字节相同，那个平局破除给不出任何判别力。**⚠️ 同一个洞对码2逐字成立，而码2那6字节事务号唯一可能的用途就是这个平局破除**」

也就是说：C163 判定「写序」（尤其是它的事务号分量）**在码2、码3两类上都不能用来区分同一 checkpoint 固定点内的多版**——不是因为写序没有事务号字段，而是因为固定点收敛的多轮写出的事务号本来就相同。这条判决是三方论证已经走完的成品（`.claude/kb/checks-owed.md:174` 的「解法」栏点明：处置候选是「码3的择新键退回二元(诞生代号,实例代号)，并把……升成显式写路径纪律+会失败的检查」，且明写「待用户复核，它推翻的是九轮论证的产物并动一条不变量」）——它是仓里**已确立的事实**，不是我这一轮新论证出来的猜测，我只是把它套到本轮七条候选各自的 key 定义上逐条核对。

逐候选核对（码2/码3是否包含一个**不受 C163 影响**的判别分量）：

### §4 跨头共享与 reflink（一个物理版本被 N≥2 个逻辑位置引用，每个引用者拿不拿得到同一个 key；C275 的 AAD 洞不在这一格判）

**判据来源**：背景材料第三节问4。**触发条件**：存在一个共享构造，两个引用者凑出的 key 不同，或有一个凑不出。

**共同论证**：七条候选的 key 分量全部是**目标单元自身的属性**（出生树、出生txg、写序、出生序号、实例内计数、随机标识、出生落点——没有一条候选的分量依赖「当前是哪棵树在引用」），这与第二轮已出局的候选②形成直接对比：②的失败恰恰在于它的分量（对象ID、锚点偏移）从**引用者自己的** extent 树查找路径现算，reflink 之后引用者的 extent 树给出的是引用者自己文件的坐标，不是共享目标的坐标。本轮候选没有一条重犯这个错误——它们统一让指针整段（或指针+已有字段）携带**目标单元写入时就固定下来的身份**，不随「谁在引用」变化。

依据 F9（`D8（核心索引结构） 已定项6`，`.claude/kb/decisions/08-核心索引结构.md:327-446`）：「跨头首次COW的重生：新身份=(本头树ID,类型2,原容器号,本次发布代号)——克隆头第一次COW origin的叶时，叶头的出生树换成写它的那棵树；类型1容器从不跨头COW」。这说明：**共享期间**（还没有发生跨头COW）单元头的出生树/诞生代号字段不变，两个头共享的是**同一份物理字节**，因此两边读到的 key 逐字节相同；**一旦发生跨头首次COW**（写时复制产生了新的物理版本），新版本重新获得一个新身份（新出生树），而这不是「同一个物理版本被两个引用者用不同 key 指」的场景——这是产生了**两个不同的物理版本**（各自有自己的 key），Q4 问的是「同一个物理版本」的一致性，跨头COW 之后已经不是同一个物理版本了，因此不在 Q4 的触发范围内，而在 Q3（唯一性）与 Q9（下游 D6/D26 投影）的射程。

逐候选补充核实（针对**共享期间**、跨头COW 之前）：

- **甲/丙/乙/丁/戊/己/庚**：全部通过——理由同上，所有分量都是「写入时确定、随后不随引用关系变化」的静态属性，两个（或N个）引用它的头/克隆树各自持有的指针，只要正确地把**目标单元自己头里的值**复制进自己的指针（而不是套用自己树的身份），就能拿到相同的 key。这是克隆/reflink 操作本身的实现要求（复制指针，不是重算指针），与 key 族选择无关，七条候选都满足。**全过。**

**丁的补充说明（同 §1 的复本歧义）**：丁的「出生落点」若采用「规范副本」的读法（§1 已论证），N 个引用者复制的都是**同一个规范坐标值**，天然一致；若按最弱的「各自记自己所在副本坐标」读法，连**单个**引用者自己的两份副本都可能不一致（这在 §1 已经指出，是需要在定案时明确的一条，不是 Q4 独有的问题）。按候选定义里「冻结在出生落点」的单数措辞，我判定为规范读法，**过**。

**结论**：Q4 七条候选**全部过**，跨头共享/reflink 这一格不构成候选间的判别力——本轮候选集已经统一修正了第二轮候选②的核心缺陷（引用者自算身份），所以这一格不再是分歧点。

### §5 搬迁不变（逐字节搬迁〔F1〕之后 key 不变、引用者一个都不用改）

**判据来源**：背景材料第三节问5。**触发条件**：搬迁后 key 变了，或有引用者要改。

**核心依据（F1）**：「单元头随搬迁不变：码1/码3由 I-2.3（补齐字节为零且参与校验和） 罩——校验和/MAC覆盖整个单元含补齐；码2由 D4（校验和位置） 的「父节点存子节点校验和」加 D19（块指针的结构与宽度预算） 已定项5的「搬迁只改映射一条条目、引用者不动」推出——搬过去的那份要对得上引用者手里那份校验和⇒只能逐字节」（背景材料第一节第25行）。这是一条格式层的结构性保证：**任何**存放在单元头里的字段，只要该字段的写法不依赖「我现在在哪个物理位置」，搬迁前后必然逐字节相同（因为搬迁的定义就是「把这些字节原样拷到另一个位置」）。

逐候选核对（是否存在一个候选的 key 分量，其**语义**依赖「当前物理位置」而非「写入时刻」）：

- **甲、乙、丙、戊、己**：所有分量（五元组、诞生代号、写序、出生树、出生txg、实例代号、出生序号、实例内计数、随机标识）都是「写入那一刻」固定的属性，与「现在在哪」无关。搬迁只搬字节，不改这些字段的值，key 天然不变。**全过。**
- **丁、庚**：这两条候选的 key 分量字面上是「出生设备、出生槽号」——听起来像「位置」，但候选定义明确把它定义为**出生时**的坐标（「冻结……永不刷新」，「搬过的单元提示永久过期」，背景材料第47行/第50行），也就是说这个字段本来就不代表「现在在哪」，代表的是「写下第一个字节那一刻在哪」。搬迁改变的是「现在在哪」（体现在中央映射的 value/位置条目里），不改变「出生时在哪」（头里冻结的那个值，搬迁只是把这些字节原样复制，值本身不会变）。**这正是候选定义为什么要用「冻结/永不刷新」这个说法——它就是为了让这个字段在搬迁语义下表现得和其它候选一样，是一个写入时刻的静态标签，不是一个实时位置指针。** 因此丁、庚同样**过**。

  ⚠️ 需要注意区分两件事：候选**表内**还另外带着一份「位置条目」（今天已由 D19（块指针的结构与宽度预算） 已定项5 降为提示，`.claude/kb/decisions/19-块指针的结构与宽度预算.md:42-161` 已定项5 正文「位置条目……降为提示……它可能过期」），那份提示本来就会在搬迁后过期，候选丁/庚自己也承认「搬过的单元提示永久过期」——但那是位置**提示**（value 的一部分，用来找到当前物理地址），不是 key。Q5 问的是 key 不变，不是提示不过期，两者不是同一个东西，候选定义没有混淆这两者，我在这里只是把这个区分写清楚，免得下一个读这份材料的人把「提示过期」误读成「key 变了」。

**结论**：Q5 七条候选**全部过**，这一格由 F1（校验和/MAC 覆盖整单元）在格式层统一兜底，不构成候选间的判别力。

**D27 容器槽内对象的「搬出去再写一份」不算搬迁**：D27（小数据打包容器） 「两处三方收敛的形态」一节逐字「slot 修改取「搬出去」：改一个已打包对象=走未改动的独立单元写路径写一个新单元，容器不动、旧槽标死」（`.claude/kb/decisions/27-小数据打包容器.md:276-287`）。这是**新写一个版本**，不是 F1 定义下的「逐字节搬迁」，因此它由 Q3（唯一性——旧版本与新版本是否有各自不同的 key）管辖，不影响 Q5 的判断，七条候选在 Q3 的表现已在 §3 给出。

### §6 实例切换与崩溃重挂之后唯一（D23（journal 的角色与格式） 已定项14「重发在飞checkpoint，号≤W的事务照旧、号>W的按新写序重做」；被收养的旧单元与重做/新写的单元同在一个重发的号里——key 还唯一吗）

**D18（块里携带什么信息） 已定项11 逐字**（`.claude/kb/decisions/18-块里携带什么信息.md:129-224`，已定项索引行第11条）：「作废一个checkpoint必须换实例代号」——这是关键的既有防线：instance switch 时，被抛弃的那次尝试与重试那次尝试，即使 checkpoint 号（诞生代号）相同，实例代号必定不同。

（甲的码1、码3不受这个构造影响：码1有写序里的实例代号分量，§3 已论证 F7 支持它；码3见下方对「计数器族」的统一分析。）

**乙、丙（码2/码3那一半）、戊的「计数器」缺口（C274）**：这三条候选（以及丙的码2/码3那一半）都用了一个「出生序号」或「实例内计数」——**这类分量本身确实带着实例代号**，所以不会重犯甲码2的错误（不同实例代号 ⇒ key 不同）。但 `.claude/kb/checks-owed.md:266-267` 的 C274（重放收养的对象不推计数器水位）指出一个**更深一层**的问题：

> 「D8（核心索引结构） 已定项8②的树ID水位逐字「新水位=max(根环里全部根记录的该字段,本次checkpoint发出的最高树ID+1)」……而 D23（journal 的角色与格式） 已定项14 的实例切换逐字「重发在飞checkpoint，号≤W的事务照旧」，I-1.2（块头写序已发布） 把号≤W的单元判成已发布⇒在飞checkpoint里一个号≤W的事务建的树会随重放回来，全仓没写重放施加那一条时推不推水位……若内存里的分配器按根环max起步、重放补回那棵树时不推水位，下一棵新建的树会拿同一个ID。**同一个形状还管每一个「按计数器发号」的东西：D19（块指针的结构与宽度预算） 未定项6第二轮的出生序号、代理号两族都撞在这里**」

这段话讲的是同一族问题的另一个实例（树ID水位），但它明确点名「出生序号、代理号两族」——也就是乙、丙（码2/码3）、戊共用的这个计数器机制。把它套到中央映射 key 上：崩溃重挂（属于 F5③「号≤W的事务写出的码1单元被收养」，这个收养机制不限于码1，同类道理对码2/码3、以及「出生序号」计数器也成立）之后，**新实例**的出生序号计数器若在内存里从 0（或从某个默认值）重新起跑，而不去检查「已经被收养、且带着旧实例代号的那些单元里，出生序号最大用到了多少」——这本身不会导致同 key 碰撞，**因为出生序号计数器是「(树,checkpoint号,实例代号)」三元作用域**（背景材料第45行），新实例的 checkpoint 号或实例代号与被收养单元不同，理论上不会撞。**但真正的风险在于同一个新实例内部，多次崩溃重挂之间的水位维持**——如果崩溃重挂发生了不止一次（同一个实例代号下，先重挂一次、又崩溃、再重挂一次），期间「出生序号」计数器是纯内存态（背景材料第45行「内存里发，从0起」），每次重挂后从 0 重新起跑，而这个实例代号号下**之前那次重挂已经写出的、已发布的单元**所占用的出生序号不会被检查，下一次重挂可能重新分配到同一个 (树,checkpoint号,实例代号,出生序号) 组合——这正是 C274 描述的「同一个形状」。

⚠️ 我需要如实指出：C274 自己标注为「推测，没核全仓」，且它给出的构造针对的是**树ID水位**这个具体量，不是直接针对本轮的映射 key；但 C274 原文明确写「D19（块指针的结构与宽度预算） 未定项6第二轮的出生序号、代理号两族都撞在这里」，这是仓里已经落账、且第二轮就已经指出适用于本轮候选的一笔欠账，我在这里只是确认它对乙、丙（码2/3）、戊仍然成立，**没有新增未经查证的论断**。

- **甲**：码1/码3 用写序，写序的「实例代号」分量由 D23（journal 的角色与格式） 已定项14 的既有协议管理（「号>W的事务按新写序重做」——重做的单元拿到**全新分配**的事务号，这个分配走 journal 现有的、已经考虑过崩溃恢复的计数协议，不是本轮候选新引入的计数器），**不受 C274 影响**；但码2已经在上面独立判输。
- **乙**：三类**全部**依赖出生序号，C274 对三类都成立。**输/需补丁。**
- **丙**：码1那一半用写序（不受C274影响，过），码2/码3那一半用出生序号（受C274影响）。**码1过，码2/码3需同一补丁。**
- **戊**：三类全部依赖实例内计数，同乙。**输/需补丁。**
- **丁**：不依赖任何计数器，依赖的是「出生设备+出生槽号」——即物理分配结果。C274 的机理（内存态计数器崩溃后不续接水位）对丁不直接适用，因为丁靠的是分配器本身给出的物理坐标，而不是一个独立维护的序号。但丁需要回答一个**没有被 C274 覆盖、材料里也没有正面回答**的问题：被抛弃（F5②「没发布就作废」）的那次尝试所分配、但从未发布的物理落点，在崩溃重挂之后**是否可能被立刻重新分配给重试尝试**？丁自己的候选定义已经引用了 D16（发布语义） 新规则2（「checkpoint C中产生的一切释放，在C被发布之前不得进入可分配集合」，`.claude/kb/decisions/16-发布语义.md:77-103`）来处理「写失败退回的槽」，但**这条规则字面管的是「释放」**（已分配又被主动释放的空间），而一次**从未提交成功、连释放都谈不上的在飞分配**是否也归它管，材料没有把这两种情形的等价性论证清楚——这是丁需要在定案时补一句的地方，**本轮记「过，附一条未决的设计细节」**，不判输，因为候选没有给出会导致碰撞的具体构造，只是这条规则的射程需要显式确认。
- **己**：随机16字节标识，重新生成，不依赖内存态计数器，也不依赖分配结果，C274 与丁的顾虑对它都不成立。**过。**
- **庚**：候选自己的定义句（背景材料第50行）已经写明「每槽版本号要一张持久表——住哪、崩溃后怎么恢复、会不会回绕，这一轮要答」——**这句话点名的正是 Q6 要问的问题，而候选定义本身没有回答它**（持久表住在哪、崩溃后如何重建/续接、会不会回绕，三问都没有答案）。按判据表「触发时判谁输」的标准，一个候选自陈「这一轮要答」而在同一轮材料里确实没有给出答案，我判它在 Q6 **未能证明自己过**，按「输」计。**输。**

**结论**：甲（码2）、庚**输**；乙、丙（码2/码3那一半）、戊**需要一条本轮材料没有写进候选定义、但仓里已经点名（C274）的补丁**——若采纳丙/乙/戊，这条补丁必须显式写进 D23（journal 的角色与格式） 已定项14（「恢复时把计数器接到被施加记录里的最大号之后」，背景材料第821行 ④ 收严二选一的第二条已经给出了这个修法的方向）；丁有一条需要在定案时补充确认的设计细节（不判输）；己**过**，且是七条候选里唯一在 Q6 完全不依赖任何新增机制（既不用计数器也不用分配结果）就自然成立的一条。

**判据来源**：背景材料第三节问9。**触发条件**：给出一条对每一条候选都不输、且至少一格严格强于其中某一条的新路。

### 出局的两条，理由是本轮独立发现的具体构造

**甲出局**：Q3（§3）给出的反例是「同一checkpoint固定点内两轮COW写出同一个码2/码3逻辑单元，两个物理版本的甲式key逐字段相同」，依据是仓里已确立的 C163（`.claude/kb/checks-owed.md:174`）与 I-1.8（归并后版本全序）（`.claude/kb/invariants.md:15-38`）——不是我这一轮新论证出的猜测，是把已有的、已被三方论证走完的判决（C163）套到甲的 key 定义上得出的直接推论。Q6（§6）给出第二个独立反例：甲的码2 key 完全不含任何写序/实例分量，在实例切换后的「被收养单元」与「新实例重发的单元」之间会撞车，依据是 I-1.2（块头写序已发布） 对码2/码3的判定字面上不检查实例代号（`.claude/kb/invariants.md:15-38`）。**两处失分点各自独立、各自可指认具体场景，不是同一个洞的两种说法**——这是这一轮相对第二轮材料的新增发现，第二轮材料把甲当作「写材料的人的倾向」候选丙的对照组来写，但没有独立核过甲在码2/码3上的表现；这一轮逐字核对暴露了它。

**庚出局**：候选自己的定义句承认「每槽版本号要一张持久表——住哪、崩溃后怎么恢复、会不会回绕，这一轮要答」（背景材料第50行），而候选定义与整个背景材料都没有给出这张表的设计——Q6（§6）判它未能自证过关，Q7（§7）进一步指出这张表若不能并入既有的「单元/记账/根」三项权威态之一，会与 D21（权威态与派生态的分界） 已定项1（`.claude/kb/decisions/21-权威态与派生态的分界.md:1-49`）与 D19（块指针的结构与宽度预算） 已定项5 的态别行（`.claude/kb/decisions/19-块指针的结构与宽度预算.md:42-161`）字面冲突。这不是「候选本身注定不可行」，是「候选定义里承诺要答的问题，这一轮没有答」——按判据表的证据要求，没答就不能记「过」。

### 乙、戊被丙严格支配，不需要单独再论证

乙、戊与丙在 Q1、Q2、Q4、Q5 上表现相同（§1、§2、§4、§5 的论证对它们同等适用），Q6 上三者都需要 C274（`.claude/kb/checks-owed.md:266-267`）点名的同一个补丁（§6），Q7 上三者都需要重开 D23（journal 的角色与格式） 已定项14（§7）。**唯一的差别是覆盖面**：丙的码1 那一半复用既有写序、不受 C274 影响（因为写序的实例代号分量由 D23（journal 的角色与格式） 已定项14 既有协议管理，不是本轮新引入的计数器），乙、戊的**全部三类**都依赖新计数器、全部需要补丁。丙在这一点上严格不差于乙、戊，且在「不动码1头宽133」这一点上乙、戊做不到而丙做到（这一句只是记录事实，不作为判据——`.claude/rules/fs-design.md`「比谁省不构成任何判据」）。**乙、戊没有任何一格严格强于丙，可以从候选集里划掉，不必再单独论证。**
