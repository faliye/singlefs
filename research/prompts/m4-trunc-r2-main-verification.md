## 三、定案（零轮：两种收严写法都只被这一轮的另一条腿或主 agent 的交叉核攻过一次，代码轮再攻）

- **R1 载体**：inode 记录偏移 120 起放两段 8 字节（小端）：T（截断字段的 txg，0 是没写过）与 N_w（截断字段的 size）；偏移 108–119 与 136–139 仍恒 0（`records.rs` 单测 `tampered[139] = 1` 与 `checker_known_bad_images.rs` 的预留段最后一个字节都落在 139，不用改）。存 size 不存单元数：用户原话是「txg 与 size」，单元数由 ⌈N_w ÷ 净荷⌉.max(1) 现算。T = 0 ⇔ N_w = 0 不成立（截到 0 时 T ≠ 0、N_w = 0），合法性只判「T = 0 ⇒ N_w = 0」。
- **R2 什么时候写**：截断意图那次照第五节第 1 条用户选的那一写法写；各批、最后一批不碰记录（K2）；变长与 N = S 照抄上一版；整份写（顺序写、覆盖写）清零；unlink 的意图与各批照抄。
- **R3 读法 Z 第四条**：扫描重建认领数据单元时，在 K6 三条之外多判一句——有同号、同对象出生代的记录且它的 T ≠ 0 时，单元号 ≥ ⌈N_w ÷ 净荷⌉.max(1) 且单元头出生 txg < T 的，不认领。没有这样的记录的单元照旧认领（S3 不动）。
- **R4 写序那一条保留**（K6 第三条），第四条与它是合取。
- **R5 回退**：字段随记录取 R_old，不另写；回退不许把现行版本的字段并回 R_old 的记录（正推推的：并回会判死 R_old 里活的单元）。
- **R6 要改的地方**（行数是正推推的，代码轮核）：
  - 核心层 `records.rs`：`InodeRecord` 加 T、N_w，`to_bytes` 与 `parse` 按 R1 拆段，`parse` 判合法性。
  - 核心层 `truncate.rs`：写字段的纯函数。
  - 核心层 `transaction.rs`：建 `InodeRecord` 的五处——整份写清零、改 size 那一处照 R2、unlink 两处照抄。
  - 其余构造处补两个字段。
  - 池级 checker `rebuild.rs` 加第四条与白名单。
  - `walk.rs` 的 I-9.7 改成只判 108–119、136–139 与合法性。
  - 新判「T ≠ 0 时，单元号 ≥ ⌈N_w ÷ 净荷⌉.max(1) 的活单元出生 txg 都 ≥ T」，进不变量清单与 GPU 判器，与 CPU 对拍。
  - GPU 检查内核与恢复内核两处 I-9.7 跟着改。
  - 理想模型记字段并在对拍里比。
  - 变异与必红世界：
    - 写死历史第 2 步（删掉第四条、意图那次不写字段、变长丢字段，攻方 `out/fixed.txt:49` 那一形）；
    - 攻方三个细节各一条：「最近一次」→ `out/fixed.txt:163` 那条历史，整份写不清零 → 第 207 行（取 min 那一写法才有），去掉 .max(1) → `out/exhaustive.txt:18` 那条五步历史；
    - 回退到写字段之前那一版；
    - `<` 改 `<=` 的边界。
  - 字段与 layout：进 `.claude/kb/layout/` 里程碑四那一份（今天没有，阶段同步建）。
- **R7 攒批欠账**：扫描重建里按出生 txg 比新旧的每一处（K6 写序、R3 第四条），在一个 txg 装几次改动（D16（发布语义） 已定项 10）落地时都不够细，要改按写序 (实例, 事务号) 比；今天的会话造不出，记欠账，攒批那一批开。
