## 一、材料自己漏抄了「必须整抄」的那张表

材料第二节给 E93 `### 模型` 那一行写的理由逐字是：

> | `### 模型`（四条臂的定义 + 碎片度定义） | **抄**，附录 B | 候选甲乙就是它的 `first_fit` 与 `bump_seg`，**臂的定义必须整抄** |

附录 B 第一段的出处逐字是 `93-老化下的放置与碎片度.md:13-30`，而它最后两行是：

```
| 臂 | 政策 |
|---|---|
```

`sed -n '29,34p' .claude/kb/experiments/93-老化下的放置与碎片度.md` 现查，31–34 行是：

```
| first_fit | 最低空槽优先（对照：经典老化形态） |
| bump_seg | 同 checkpoint 的脏对象按 key 排序后连续写进聚簇段；无空段时回落 first_fit 并计数。D3（空间分配）已定项 5 只定了提交内生块聚簇，把它推广到全部 COW 写是候选政策，不是已定条款 |
| bump_neighbor(R) | bump_seg + 写路径邻居重写：每个脏 key 段向两侧各多重写 ≤ R 个干净邻居——「结构抗老化」的无格式改动候选形态 |
| bump_compact(B) | bump_seg + 每 checkpoint 预算 B 个对象的按 key 序轮转整理——D26（后台整理与放置回收）腿一的模型化 |
```

**丢掉的是这三样**：

1. `bump_seg` 那行自陈「**把它推广到全部 COW 写是候选政策，不是已定条款**」——
   这句话是乙的自我定性，也是判据 4（动了几条已定条款）唯一的直接输入。
2. `bump_neighbor(R)` 与 `bump_compact(B)` **两条已经量过的放置臂整个消失了**，
   而它们在成段负载上分别是 5181 / 5111 与 6073 / 3922 / 1339，全部低于甲（7997）与乙（7312）。
   材料的候选表只有四行，读的人看不出 E93 还量过另外两条更好的臂。
3. `first_fit` 那行的括注「（**对照**：经典老化形态）」——E93 把它注册成**对照**，
   材料把它升格成候选甲。这是身份变更，不是同义改写。

⇒ **这一条踩的是 `.claude/rules/three-way-inference.md` 那条**：
逐字「凡是引 kb 的条目（决策分项、挡路条、判据表格、不变量），**整条抄进去，连同它的 ⚠️ 与括注**」，

这次用了 quote-kb.py，行区间选成了 `13-30`——**机械抽取选错区间，产物本身没有断裂痕迹**，
读的人看到「附录是机械整抄的原文，以它为准」就不会再去核。

更要紧的是：**C146 的三条后果，没有一条说的是用户数据。** 附录 A 整行抄的 C146 里逐字：

> ⇒ **三条后果**：① 按 E93（老化下的放置与碎片度） 那一种，**整理**搬走区域 `R` 的第一个对象之后……

> ③ **它还决定整理自己那批搬迁**要写多少分配记录节点……

三条的主语是**整理**（①③）与**提交内生块**（②）。**用户数据块一次都没出现。**
而提交内生块的落点已由 D3 已定项 5（用户定案）定死为「必须从聚簇段分配」。

⇒ **判甲、丙、丁任一条胜出，C146 一个字都还不掉**：它们对「聚簇段里没位置了，
提交内生块 / 整理落到哪」什么都没说。判乙胜出也只答了用户数据那一半，
而 C146 ① 逐字说那个答案（回落 first_fit）恰好是让整理的目的地落回自己正在清空的段的那一种。

⚠️ **这意味着材料第一节把两笔账合成了一笔**：「用户数据落点全仓没有条款」（真，一维意义上）
与「C146 无空段时的回落政策全仓无定义」（真）是**两格不同的空白**，
这一项把它们写进同一个标题，而候选集只覆盖前者。

### 漏 5（也是最要紧的一处改写）｜判据 2 把硬要求 5 的射程改窄了，而那一改正好救活乙

`grep -n "分支变量\|只在操作期间\|填充率" .claude/rules/fs-design.md` 现查，原文逐字：

> 152:   → **只在操作期间不会变的输入上分支。** 设备类型稳定，可以；
> 153:   「当前填充率」会在操作中途越过阈值，那是危险的分支变量。
> 182: 5. **分支变量不许在操作中途改变。** 见上面第 1 条。

材料判据 2 逐字：

> 2. **过不过硬要求 5**：分支变量不许在**一次分配操作**中途改变。

**「操作」被改写成「一次分配操作」。** 这四个字是决定性的：

乙的分支变量是「现在有没有一个全空聚簇段」。E93 实测它 **91.8%–93.8%** 的时间翻转到回落分支——
这是这个仓量到过的、翻转最频繁的分支变量。按原文「操作期间」（一次发布 / 一个 checkpoint 的分配流），
乙在一次发布里就会翻转多次：批里第一个对象进得去段，最后一个进不去。
按材料改窄后的「一次分配操作」（单次分配），任何分支变量都不在单次分配中途变，
**这一关对所有候选恒真，等于没有这一关**。

而「当前填充率」被 fs-design 逐字点名为「危险的分支变量」，
乙的「有没有全空段」是填充率与碎片度的合成量——**比被点名的那个更不稳定，不是更稳定**。

⚠️ 仓里有现成的同形判例，材料里也没有。`sed -n '215,232p' .claude/kb/decisions/14-双轨大小文件-持久临时.md` 现查：

> 3. **追加写会在操作中途跨过阈值 ⇒ 阈值不是合格的分支变量**：4 KiB 文件分 8 次追加时内联臂拿到 **6.96 倍**，一次写完时恰好 **1.00**——**同一个文件大小、两个写形态，判据落在阈值两侧** ⇒ 硬要求 5 被这条分支违反

那一格的「操作」取的是**一个文件的写序列**（8 次追加），不是单次写。
⇒ **同一条硬要求，D14 取宽口径判一条候选出局，这一轮取窄口径让一条候选过关。**
判据表按字典序比较、靠前的关不许输 ⇒ **判据 2 是第二关，这一改窄决定了乙能不能走到第 3 关。**
