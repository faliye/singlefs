### 5.2 三条臂：定义逐字照岔路单，「做完会怎样」在大 k 上当待证命题

臂的名字与第一句定义照岔路单第 6 行逐字（第二节 q4 抄了第二次登记 5.2 的整段），**一个字不改**。下面只补「k > 16 时怎么做」与「做完会怎样」两栏；「做完会怎样」每一条都是要证的命题（第七节钉数、第九节变异、第十一节 V2 核），不是定义的一部分。

**甲（真实基线）**：「甲（`crates/` 今天的写法）」。
- k > 16 怎么做：一批 = 一次发布，与 k ≤ 16 逐字同一套（第二次登记 5.2 甲 + R8）；写出 = k·d 个数据单元 + 各树脏节点 + ⌈W / 67⌉ 条记录 + 1 个根槽（一块盘，FUA）+ 每块盘 1 个系统配置槽。
- 做完会怎样：每批 4 次刷写、1 次 FUA，摊到每次 fsync 是 4/k 与 1/k，**随 k 单调趋零**；没有中间版；固定点、记录、根槽、系统配置槽这几样每批只写一份，所以「每次 fsync 摊到的写」里这几样的份额随 k 单调变小，而 k·d 个数据单元那一份不随 k 摊薄。
- 反面（要是量出相反的数怎么办）：若某一格甲每次 fsync 摊到的写字节**随 k 不降反升**，先查是不是不共享那一半在这一层饱和（F14），不是的话走作废 V2（单调性被破坏）。

**wal_full-K9′**：「同第 1 行 wal_full，另外一个 checkpoint 间隔里写了又被换掉的每个中间版也写一条已释放的分配记录（E155 跑前登记 K9′）」。
- k > 16 怎么做：一批写 k·d 个数据单元 + 两棵用户树这一批的全部脏节点（叶到各自树根）+ 1 条记录（点名两个新树根）；次序 单元 → 屏障 → 记录 → 屏障；不写根槽、系统配置槽、树表与三棵固定点树。每 N 次 fsync（N_b 批；`k > N` 时 N_b = 1、间隔实际 k 次）之后一次 checkpoint，照第二次登记 5.2。
- 做完会怎样：一批 4 次刷写、0 次 FUA；摊到每次 fsync 刷写 4/k + 4/N_实际、FUA 1/N_实际；I ≥ 0，N_b = 1 时 I = 0；每一格写字节与写请求 ≥ wal_full-K9；一批写字节 ≤ 甲一批写字节。**k 变大时这条臂比甲省下的那几样（四样固定点、根槽、系统配置槽）本身就被甲摊薄了**，所以 `s` 随 k 单调不增是这条臂定义推得出的方向；`s` 会不会跨过 0 或 10%，定义推不出，是这一段要量的。
- 反面：若某一格 `s` **随 k 上升**，先核 Q7.7 的饱和（不共享在某一层撞上 n_l 会让两臂一起变贵、比值未必单调），再核 V2。

**乙-M-K9′**：「每次 fsync 写脏数据单元、脏叶与一条点名叶的记录，施加时把叶换进内存里的父节点，祖先与四样固定点由挂载后第一次发布经正常发布路径落盘，中间版照 K9′ 记」。
- k > 16 怎么做：一批写 k·d 个数据单元 + 两棵用户树这一批的脏叶 + ⌈脏叶数 / 67⌉ 条记录。⚠️ **大 k 上「⌈脏叶数 / 67⌉」不再恒为 1**：不共享时 k = 128 起脏叶数就可能过 67，记录条数随 k 涨，这是这条臂在大 k 上与 wal_full 拉开或收窄的一处（wal_full 恒 1 条记录，点名两个新树根）。checkpoint 照第二次登记 5.2。
- 做完会怎样：刷写与 FUA 同 wal_full；一批写字节 ≤ wal_full 一批写字节；稳态写量与第一次登记的乙在 K9′ 下相同（F6）。
- 反面：若某一格乙-M 一批写字节 **>** wal_full 一批写字节，那是记录条数那一项翻过来了——照报，不作废（V2 只对「写出的单元」那一半判包含关系，记录条数单列）。

|---|---|---|---|

| T2 `s` | k 轴（Q7.3′、Q7.3b′） | 每一点的值、峰值、`s` ≥ 10% 的点数、0 < `s` < 10% 的点数、`s` ≤ 0 的点数、末点的值 | Q7.3′、Q7.3b′ |
| T3 饱和 | k 轴、层号（Q7.7′） | 每一层第一次饱和的 k、饱和层数、末点是否全层饱和 | Q7.5′、F14 |

### 8.2 几何敏感性

每一个带判定的量（Q7.2′、Q7.3′、Q7.3b′、Q7.4′、Q7.5′）在它的判定串上逐个换到反向取样点重判，每个判定报一行「稳定」或「不稳定：在 ⟨取样点⟩ 翻成 ⟨判定⟩」，两边的值都报。

| 反向取样点 | 方向 | 适用 | 第二段做没做 |
|---|---|---|---|
| φ = 0.5 | 树在更小的 P 就长高；甲与 WAL 两臂都更贵 | 全部串 | **没做**（这一段补） |
| K3′（内部条目加 26） | 内部扇出变小、树更高 | 全部串 | **没做** |
| g = 0 | 分配记录树变小；K9′ 的积压那一半消失 | 全部串 | **没做** |
| `physical_block_size` = 4096 | 根槽变宽，只打在发根的那一方（甲每批、WAL 每个 checkpoint）⇒ 甲变贵、`s` 变大 | 全部串 | **没做** |
| K9′-b（中间版不进积压） | WAL 两臂变便宜 ⇒ `s` 变大 | 全部串（这一段要新建开关） | **没做** |
| 独立散点 | rand 下 WAL checkpoint 的间隔并集变大 ⇒ WAL 两臂变贵 ⇒ `s` 变小 | 落点 rand 的串 | 第二段没在第 7 行上跑 |
| N 按批计 | 一个间隔 N·k 次 fsync ⇒ WAL 两臂摊得更薄 ⇒ `s` 变大 | 全部串 | 只做了 1 个代表格 |
| 不共享取随机（F9） | 不共享的 k 条路径允许偶然共享 ⇒ 不共享那一半变便宜 | 不共享的串 | **没做**（只有占位） |
| N 不被撑满（R13 的另一种取法） | `k > N` 的格里 WAL 摊销分母取 N ⇒ WAL 两臂变贵 | 含 k > N 的串 | 这一次新加 |
| L近 / L远（主表里的两列） | 旧版全近 / 能远的全远 | 全部；这是上下两个括号 | 主表里有 |

**方向相反的取样点每个判定都有**（`.claude/rules/mutation-sampling.md` 第六类）：`s` 变大的一侧有 pbs = 4096、K9′-b、N 按批计，`s` 变小的一侧有独立散点、N 不被撑满；φ = 0.5 与 K3′ 两头都动树高。L近 与 L远 判定不同时，那一格只能按区间交出，不挑一个括号。

**判别力自证**（第六节 Q7.9′、第五节 R12）：每道门槛在**同一条 k 轴判定串的实际值上**挪一次，判定必须由一边翻到另一边，两边的判定都写进产物：

| 门槛 | 怎么挪 | 必须看到什么 |
|---|---|---|
| 规则 R 的 5% | 在某条 Q7.2′ 串上取相邻两步的 \|δ\|，把门槛挪到两者之间 | 标签由 ⟨随轴缩小 / 收敛 / 其它⟩ 翻成另一个 |
| `s` 的 10% | 在某条 `s`(k) 串上取相邻两点 `s_i` > `s_{i+1}`，门槛挪到 (`s_i` + `s_{i+1}`) / 2 | `k*₁₀` 由原值变成 k_{i+1}（或由「不翻」变成某个 k） |
| `s` 的 0 | 门槛由 0 挪到某条串里相邻两点之间的一个正值 | `k*₀` 由「k ≤ 1024 不翻」变成那个 k——**这就是「必须由绿转红」那一格** |

网格上找不到跨门槛的一对 ⇒ 写「判别力未自证」，不写「稳定」。挪到两点之间而判定**不变** ⇒ 判定那一段代码有错，作废 V5。

## 十、失败条款

每条后面紧跟「什么观测会让它触发」。触发不等于作废：写明结论收窄到哪。F1–F10 照第二次登记第十节（同一批臂、同一套模型），F11–F15 是这一段新加的。

**F1 条款本身可能错或不全。**
- 触发的观测：7.1 的 A1–A6 任一条不成立。跑之前就知道会触发的一处：A3（D23 已定项 1 字面没列四样固定点与系统配置槽）。
- 结论收窄：凡引那条条款定口径的量，改成「按 `crates` 口径」并注明条款字面与实现不一致。

**F2 不动点在某一格不收敛，或某棵树第 0 层过半变脏。**
- 触发的观测：某格迭代到 1000 次两次之间仍有量变化 ≥ 10⁻⁹；或收敛了但某棵第 0 层节点数 ≥ 64 的树第 0 层脏节点占这层节点数 ≥ 50%。⚠️ **大 k 上这一条会大面积触发**：不共享在 k ≥ n_l 时整层全脏（Q7.7′ 的饱和），第 0 层脏占比 = 100%。
- 结论收窄：那一格按「这个 k 与这个位置策略下一次持久化要重写树的一大半」报，不当模型错误作废。**F2 打中时三臂一起中、分不出臂**（`.claude/singlefs-ai-sop/rules/evidence-discipline.md`「打中不分辨臂」）：那些格不拿来判臂，Q7.2′–Q7.5′ 的判定只用没触发 F2 的那些点，并在产物里逐格标出来；一条串上触发 F2 的点数超过一半时，整串记「F2 主导，不判」。

**F3 位置策略决定结论。** 模型没有模拟真实历史，旧版落在哪是取法。
- 触发的观测：Q7.2′–Q7.5′ 任一判定在 L近 与 L远 之间不同。
- 结论收窄：那一格按「L近 下 …，L远 下 …」两头交出，不挑一个。

**F4 几何取法决定结论。**
- 触发的观测：第八节 8.2 任一行记「不稳定」。
- 结论收窄：那条判定只在主几何下成立，正文写「在 φ = 1、K3、g = 24、pbs = 512、K9′、散连续组、N 按 fsync 计、不共享取 min 公式、k ≤ 1024 下」，不写成性质。

**F5 K9′ 的释放代读法决定结论。**
- 触发的观测：Q7.3′、Q7.3b′ 任一判定在 K9′ 与 K9′-b 之间不同。
- 结论收窄：那一格两种都报，写明「取决于从没被任何根引用的中间版要不要等满根环才可再分配——D16 已定项 1 对它们怎么适用没有条款」，交主 agent 当一个要定的问题。

**F6 「M」量不到。** 乙-M 与乙只差崩溃之后那一次挂载，这个模型只算没有崩溃时的写量。
- 触发的观测：恒触发（5.2 乙-M 那一条）。
- 结论收窄：第 7 行对乙-M-K9′ 只交稳态写量，不写「乙-M 比乙好 / 差」。

**F7 WAL 两臂要改的条款不止 D23 已定项 1。**
- 触发的观测：任一格 N_b ≥ 2 而用户树节点的中间版 I > 0（同一个码 2 节点在一个 checkpoint 里写了两次以上，D19 已定项 12 字面不许）；另外 WAL 两臂 fsync 不发根，与 D16 已定项 11「fsync 只是提前触发一次发布」不符，恒触发。
- 结论收窄：WAL 两臂的数都写成「假定 D19 已定项 12 与 D16 已定项 11 随轴二一起改」；改这两条的代价不在这个实验里。

**F8 没测时间、没测真设备、不量 fsync 延迟。** 这是计数模型。
- 触发的观测：恒触发。
- 结论收窄：第 7 行只交写字节、写请求、刷写、FUA 的数与它们的比，不交挂钟。⚠️ **大 k 尤其**：组提交省下的是写量，一批里先到的 fsync 要等后到的那一段延迟、k = 1024 时的排队与内存占用，这一次一个字不交。

**F9 「不共享」取的是理想形态。**
- 触发的观测：Q7.2′–Q7.5′ 任一判定在不共享与「不共享取随机」之间不同。
- 结论收窄：那一格按两种都报，写明「不共享」是「k 条路径能分开就分开」的一端。

**F10 间隔的计法决定结论。**
- 触发的观测：Q7.2′–Q7.5′ 任一判定在「N 按 fsync 计」与「N 按批计」之间不同。
- 结论收窄：那一格两种都报，写明结论取决于 checkpoint 间隔按 fsync 数还是按批数算。

**F11 k 的上端是本机的取法，不是条款给的数。** 用户答「不限制个数，至少 16 个以上……根据硬盘和电脑的性能来做」，D25 今天没有这一条分项（第二节 q3）。
- 触发的观测：Q7.2′ 在某条串的最后三步仍标「随轴缩小」（每步 δ ≤ −5%），或 Q7.3′ / Q7.3b′ 的 `k*` 落在末档 k = 1024 上，或全部串都记「k ≤ 1024 不翻」——三者任一，就说明 1024 还没到头。
- 结论收窄：一切结论写成「在 k ≤ 1024 上……」，不写「不翻面」「收敛到」；要更大的 k 另派一段，上端的依据要换成别的（本机 `nr_requests` 不再是那个界）。

**F12 `k > P` 的格不适用，大 k 只在大池上有数。**
- 触发的观测：跑之前就知道会触发：P = 10² 在 k ≥ 128、P = 145 在 k ≥ 256 上全部记「不适用」（504 格）。
- 结论收窄：k > 64 的结论只对 P ≥ 10⁴ 成立，小池那一端交白，不许把大池的标签写成「随 k 的性质」。

**F13 `k > N` 的格退化成 N_b = 1。** 一批就把间隔撑满。
- 触发的观测：跑之前就知道会触发：N = 16 在 k ≥ 16、N = 256 在 k ≥ 256 上 N_b = 1（B-r4-9）。
- 结论收窄：那些格的 `s` 由记录条数的取整给出，照报不判；k 轴判定串按第一节截断，截断后不足 4 点的串记「点数不够，不判」。

**F14 不共享在大 k 上饱和。** 第 l 层脏节点撞上 n_l，三臂的用户树那一半变成同一个数。
- 触发的观测：Q7.7′ 报出任一格任一层「不共享脏节点 = n_l」（跑之前就知道 P = 10⁴、k = 1024 上 extent 与 inode 第 0 层都会中，B-r4-8）。
- 结论收窄：饱和的格上「不共享」不再是「k 条互不相交的脊柱」，它是「整棵树」；那些格的 Q7.5′ 记「饱和」不记「收敛」，Q7.2′ 的标签旁边注明「这一段的平坦来自饱和，不来自组提交」。

**F15 组提交的并发度 k 与 D25 的负载档是两个旋钮。** D25 已定项 1 说的是一次 fsync 内部（带 8 个叶子、落在 1 条共享脊柱上），k 说的是几次 fsync 并进一批；已定项 4「组提交能不能救」那一格是 E16 在**批**轴上的数，不是 k 轴。
- 触发的观测：恒触发（模型里两个轴独立取值，没有任何条款说它们相关）。
- 结论收窄：不写「D25 那一档下组提交怎样」这种把两个轴合起来的句子，只写「(族, 共享与否, k) 这一格上……」；与已定项 4 那两个倍数对不上时如实并列，不改它。
