## 二、问题 1：认领之后跳过的那一段，非得用明文的 `声明长度` 不可吗？

**答：不必。换成「跳到本单元起点 + 单元大小（由明文的单元类型标签定）」在语义上不弱于原规则，
而且 E88 实测的那个「错分 12 / 错分 0」一个数都不会变——因为 E88 算的本来就是新规则。**

### 2.1 新规则的两个输入都在明文里，且都不是 `声明长度`

| 输入 | 从哪来 | 加密开启时可读吗 |
|---|---|---|
| 本单元起点 | 探针地址本身（步进 16384，D18 已定项 9） | 不涉及盘上字节 |
| 单元大小 | 单元类型标签 → 已定项 11 登记表「单元大小 / 对齐」列（码 1 = 32768、码 2 = 16384、码 3 = 32768） | **可读**：标签在 flags 偏移 6，I-6.2 白名单里「共同前缀两类都许」 |

⇒ 新规则**不消费任何一个可能进密文的字段**。

### 2.2 覆盖关系：新规则的跳过区间是旧规则的超集

D4（校验和位置）已定项 5 逐字（`decisions/04-校验和位置.md:286`）：

> **单元恒 32768 字节，自描述头、声明长度、净荷、补齐全在这 32768 之内。**

配上 `声明长度 ≤ 32768 − 头`（码 1 头 105、码 3 头 103），恒有

```
头 + 声明长度  ≤  单元大小
```

⇒ 旧规则跳 `[起点, 起点 + 头 + 声明长度)`，新规则跳 `[起点, 起点 + 单元大小)`，**后者恒包含前者**。
跳得更多不会漏掉合法单元的起点：码 1 / 码 3 恒 32768 对齐、码 2 恒 16384 对齐（登记表「对齐」列），
一个 32768 对齐的单元占满 `[a, a+32768)`，分配器不可能把 `a+16384` 这个 16384 槽同时给别人。

### 2.3 唯一一个探针点上的逐格对照

E86 判据 4 逐字给了闭式：**step16k 下每个数据单元载荷内恰 1 个 16K 探针点**，
位置是 `起点 + 16384`。所以两条规则的差别只可能出现在这**一个**点上：

| 情形 | 旧规则（按 `声明长度` 跳） | 新规则（按单元大小跳） | 差别 |
|---|---|---|---|
| 码 1，`声明长度 ≥ 16280`（即 `105 + L > 16384`，载荷盖过探针点） | 跳过，不探 | 跳过，不探 | **无** |
| 码 1，`声明长度 < 16280`（探针点落在补齐区） | **要探**。合法镜像上补齐恒为 0（I-2.3）⇒ magic 不匹配 ⇒ 不认领 | 不探 | 合法镜像上结果相同；**补齐区一旦不为 0（I-2.3 被违反、或加密开启后补齐是 E(0) 的伪随机字节），旧规则要靠 4 字节 magic + 32 字节头校验和挡，新规则的误认领概率恒 0** |
| 码 3 | 同上，阈值是 `声明长度 ≥ 16282` | 同上 | 同上 |

（码 1 的阈值算法：探针点在单元内偏移 16384，旧规则覆盖到偏移 `105 + L`，
覆盖住探针点要 `105 + L > 16384` ⇒ `L > 16279` ⇒ `L ≥ 16280`。码 3 头 103 ⇒ `L ≥ 16282`。）

⇒ **在合法镜像上两条规则逐格同值；在非法镜像上新规则严格更强。**

### 2.4 顺带一格：新规则把「跳多远」这件事从攻击者手里拿走了 16 位

旧规则的跳过长度是 `声明长度`，攻击者写盘时可以在 `0..32663` 里任选（改完重算 32 字节头校验和即可）。
新规则的跳过长度只能是 `{16384, 32768}` 两个值之一，由 1 字节标签选。
**攻击者可控的跳过长度从 16 位收成约 1 位。**

⚠️ 「头校验和不带密钥」这一步是**推的，不是引的**：全仓只写了它的宽度（`decisions/18-*.md:494` 逐字
「头校验和取 32 字节」），**算法一处都没写**（现查 grep，只有 C94 那条欠账在说登记值的事）。
推它不带密钥的两条支撑：① D18 已定项 7 逐字把它与 MAC 分工——「加密开启后对元数据类只罩明文部分，
类身份段的完整性转由 MAC 承担」；② D9 已定项 5 的无密钥 scrub 要「检测损坏」，带密钥它就检测不了头。

⚠️ 不吹过头：**没有收到 0**。标签本身仍是明文、仍只由头校验和罩，攻击者仍能在两个值之间翻。
真要收到 0，得连标签一起进密文——那是问题 4 的题目，代价见第五节。

### 2.5 E88 的错分数会不会变：**不会，而且这一条是从源码读出来的，不是推的**

E88 的 `scan()` 在每个落点上只有两个探针（`PROBES_PER_UNIT = UNIT / STEP = 2`，`:35`），
第二个是载荷内部那个；认领开着时它无条件 `continue`（`:158-160`）。
**跳过的范围写死为「本单元的全部内部探针」，常量是 `UNIT`，模型里根本没有 `声明长度` 这个变量**
（`grep -c "声明长度\|decl" → 0`）。

⇒ 把决策正文的措辞从「按声明长度跳过」改成「按单元大小跳过」，
**E88 的源码一个字都不用改，四条臂的全部计数逐格不变**：

| E88 判据（`experiments/88-*.md:24-41` 逐字） | 值 | 换规则后 |
|---|---|---|
| `hdr91_claim` 级 2 恰 37 / 级 1 恰 6 / 清恰 9 / 冒名拒收恰 3 / 嵌套收进恰 0 / 坏校验和拒 2 | 全对 | **不变** |
| 判翻条款：`hdr47_claim` 错分类为 0 ⇒ 骑手翻回 | 错分 **12** | **不变** |
| 认领判别力：`hdr91_noclaim` 自身镜像恰收进 **4**；`hdr91_claim` 恰 **0** | 4 / 0 | **不变** |

### 2.6 但要如实记一笔：E88 对这条规则的形态是**取样点不敏感**

按 `.claude/rules/mutation-sampling.md` 的三分判据——一条变异没被抓时先问「换一个取样点还同值吗」——
E88 的四档夹具**没有一个取样点能把两条规则分开**，因为 `声明长度` 不是模型里的自由变量。
所以「E88 的数不变」这句话的正确读法是：

> E88 **对这条规则的形态本来就没有判别力**，两条规则在它那里同值；
> 不是「E88 验过新规则也对」。

⇒ **臂乙′ 不要求重跑 E88，但它要求 C89（单元头收口的遗留重算）第 ② 笔那个还没落地的 checker 夹具
多带一个取样点**：一个 `声明长度 < 16280` 的码 1 单元，在它的补齐区偏移 16384 处植一个解析得出的头。
旧规则下这个头会被探到，新规则下不会。**这是臂乙′ 在这一格的全部增量代价：一个夹具取样点，
不是一次重跑。**（C89 第 ② 笔今天逐字是「只写在决策正文里，没有可判红形态」⇒ 没有已落地的东西要改。）

### 2.7 顺带一个白捡的判别子（E88 没量过，不许当证据用）

登记表的「对齐」列今天没有任何消费者。码 1 / 码 3 恒 32768 对齐 ⇒
**一个自称码 1 或码 3、却落在非 32768 对齐地址上的头，按定义就不是单元起点**，可当场拒收。
它恰好挡住「嵌在载荷内部偏移 16384 处的自身镜像」这一类——E88 里那 4 个。

⚠️ **E88 不建模对齐**（`build_disk()` 里的落点没有地址维），所以这条只是「新规则顺带打开的一扇门」，
**不能拿来说 E88 的哪个数会变**，也不能拿来替代认领规则（它对自称码 2 的嵌套头无效：
16384 处对码 2 是合法对齐）。要用它得先给 E88 加地址维，那是另一笔账。

## 三、问题 2：码 3 与 journal 记录的判定顺序，加密开启后还成不成立？

**答：码 3 成立，而且是零增量——因为那条顺序的第二步今天就已经要密钥了。
journal 记录不在臂乙′ 的射程里，一个字节都不动。**

### 3.1 先把背景材料那句压缩版换成权威原文

背景材料第三节写「头校验和 → 声明长度 → 载荷校验和 → 逐条记录」。
I-1.7（打包容器合法与判定顺序）逐字是**七步**：

```
头校验和 → 类身份段 → 记录宽 == 登记表为该打包记录类型登记的宽
        → I-1.2 / I-1.3 / I-1.4 → 边界 → 载荷校验和 → 逐条记录
```

`声明长度` 只出现在第五步「边界」里（`记录数 × 记录宽 ≤ 声明长度` 且 `声明长度 ≤ 32768 − 103`）。

### 3.2 关键事实：码 3 的第二步今天就已经是密文

I-6.2（明文头字段白名单）逐字：**「元数据类仅此而已（五元组 / key 区间等身份字段一律进密文）」**，
而登记表把码 3 的 I-6.2 归入「元数据类」（`decisions/18-块里携带什么信息.md:700` 那一行）。

⇒ 码 3 的整个类身份段（偏移 42–102，61 字节）在加密开启时**今天就是密文**，
其中包括第五步要用的 `记录数`（偏移 69）与 `记录宽`（偏移 71）。

⇒ **「边界」这一步在加密开启时本来就跑在解密之后。** 把 `声明长度` 从偏移 8–9 的明文
挪成密文，只是让它和 `记录数` / `记录宽` **在同一步变得可读**，
它相对「边界」这一步的先后关系**没有任何变化**。

| 步 | 读哪些字段 | 甲 / 乙（加密开）| 臂乙′（加密开）|
|---|---|---|---|
| 1 头校验和 | 明文字段集 | 无密钥可做 | 无密钥可做（少罩 2 字节）|
| 2 类身份段 | 42–102 | **要密钥** | **要密钥**（顺带取出 `声明长度`）|
| 3 记录宽比对 | 记录宽 | 要密钥 | 要密钥 |
| 4 I-1.2/1.3/1.4 | 写序 / 树 ID / fsid | 要密钥 | 要密钥 |
| 5 **边界** | 记录数、记录宽、**声明长度** | 记录数 / 记录宽要密钥，声明长度不要 | **三个都要密钥** |
| 6 载荷校验和 | 盘上字节 103→末尾 | 无密钥可做 | 无密钥可做 |
| 7 逐条记录 | 记录区 | 要密钥 | 要密钥 |

**唯一变的那一格是第 5 步的「声明长度不要密钥」→「要密钥」，而它所在的那一步早就要密钥了。**

### 3.3 D23 的 B 条纪律为什么不破

B 条要拦的那个形态，D23 自己给了出处（`:242-244`）：ZFS 的 ZILOG2 拿块内读来的 `zc_nused`
**决定校验范围**，所以读之前必须先 `if (size < nused) return ECKSUM`。
危险来自「未经检查的自述长度驱动了一次缓冲区操作」。

在 singlefs 的码 3 上，**`声明长度` 从来没有驱动过任何一次缓冲区操作**：

| 操作 | 范围由谁定 | 与 `声明长度` 的关系 |
|---|---|---|
| 头校验和 | 偏移 0 → 该类明文头末尾（I-2.4），端点由**类标签**给 | 无关 |
| **解密** | 单元大小（标签给）减去明文字段集（标签给） | **无关**——加密的是整单元，不是「声明长度那一段」|
| **载荷校验和** | 逐字「覆盖偏移 103 到单元末尾（记录区 + 补齐）」 | **无关**——定长范围 |
| 逐条记录 | `记录数 × 记录宽`，且被第 5 步的边界夹住 | 受 `声明长度` 约束，而它排在第 7 步 |

⇒ **臂乙′ 在第 5 步之前新插入的那一步（解密）本身不由 `声明长度` 驱动**，
所以「先边界检查再算校验和」这条纪律原样成立。B 条不破。

⚠️ 顺带记一笔真话：在 singlefs 上，B 条对码 3 是**纵深防御**，不是内存安全的必需——
因为载荷校验和的范围是定长的，`声明长度` 算错也越不出单元。ZFS 那个形态在这里本来就不可达。
这不是臂乙′ 带来的，甲和乙也一样。

### 3.4 一个既有空白，臂乙′ 零增量：I-1.7 没写无密钥侧走哪条链

I-1.7 的七步链在加密开启时**无密钥一侧走不到第 2 步**，因此也走不到第 5 步。
它实际能走的是「第 1 步 → 第 6 步」两步（头校验和 + 载荷校验和，都算盘上字节）。
**I-1.7 全文没有一句写加密开启时无密钥侧的判定链是什么**（现查 `invariants.md:26` 全行）。

这是**今天就存在的空白**，甲 / 乙 / 乙′ 三条臂完全一样。臂乙′ 不加深它，也不修它。

### 3.5 码 3 的 `声明长度` 语义（问题 2 的第二问）

**是字节数，不是记录数**，逐字见 §1.6：

> **声明长度口径与码 1 相同**：声明长度 = 头之后的净荷字节数，补齐起点 = 头 + 声明长度，声明长度 ≤ 32768 − 103。

记录数是**另一个**字段（偏移 69，宽 2，`≤ 583`）。两者的关系由第 5 步的不等式
`记录数 × 记录宽 ≤ 声明长度` 约束，是「装得下」而不是「相等」。

⇒ **由此白捡一个第一轮没点名的泄漏**（见 §4.4）：`声明长度` 留明文时，
码 3 上它给出的是**容器净荷字节数**，而 `记录宽` 的取值是公开的第二级登记表
（I-1.7 逐字「类型 2 是 140」）⇒ `声明长度 ÷ 140` 直接是一个容器里的 inode 记录条数上界。

### 3.6 journal 记录：不在射程内

D18（块里携带什么信息）已定项 7 逐字（`decisions/18-块里携带什么信息.md:540-543`）：

> **自证单元（journal 记录 / 根槽 / 超级块槽）不用这张表**：各自的头已由
> D23（journal 的角色与格式）与 D22（单元原子性怎么合成）已定项 7 定；它们没有父引用、
> 没有树身份，I-1.1（块头自述逻辑地址）/ I-1.3（块头树 ID 一致）对它们**显式豁免**。

journal 记录头是 D23 已定项 4 的 78 字节，自成一张表（`decisions/23-*.md:899-901`）：

> 头部字段合计 **78 字节**（magic 4 + 类型 2 + 算法类型 1 + 填充 1 + 自述长度 4 +
> 点名项数 4 + `jsn` **10** + `checkpoint_txg` 8 + nonce 12 + 头部校验和 32）

它的 `自述长度` 是 **4 字节**、住 journal 自己的头，与共同前缀那个 2 字节的 `声明长度`
**不是同一个字段**。臂乙′ 改的是 D18 已定项 7 / 11 的字段表，**碰不到这张表**。

⚠️ **而且 journal 加不加密本身是空白**：`decisions/23-*.md:376` 逐字
「它的 journal 是加密的，校验和与 nonce 同源；**本工程的 journal 加不加密未定**」。
⇒ 「加密开启后 journal 的这条顺序还成不成立」这个问题在仓里**今天问不出答案**，
不是臂乙′ 造成的，臂乙′ 也不推进它。

### 4.4 I-2.3（补齐字节为零且参与校验和）在加密开启时怎么判

**先把两条逐字摆出来。** I-2.3（`invariants.md:107`）：

> 其声明长度（净荷字节数；补齐起点 = 头 + 声明长度）之后到单元末尾的补齐字节**恒为 0**，
> 且校验和 / MAC 覆盖**整个单元含补齐**……补齐字节非零、或校验和只覆盖声明长度，一律判红。

D9（加密）方向（`decisions/09-加密.md:6-8`）：

> **整卷 AEAD，加密边界与校验和边界重合**……除超级块……外全部加密，元数据留最小明文头。

⇒ 校验和 / MAC 覆盖含补齐，而加密边界与校验和边界重合 ⇒ **补齐区在加密覆盖范围内**
⇒ **加密开启时盘上的补齐字节是 `E(0)`，不是 `0`。**

**现查结论：仓里没有一处写「I-2.3 在加密开启时判的是解密后的明文补齐还是盘上字节」。**
（`grep -rn "补齐" .claude/kb/ --include=*.md | grep -i "加密|密文|解密|MAC"` 只命中
I-2.3 自身那行里的「校验和 / MAC 覆盖」与 D4 已定项 5 对它的引用，没有第三条。）
⇒ **这是全仓空白**，形状与 13-c 定案前一模一样（未定项 13 表格逐字：「定案前是**全仓空白**」）。

**能从已定条款逼出来的只有一个方向**：若按盘上字节判，「补齐恒为 0」对**每一个**加密单元都为假
⇒ I-2.3 在加密开启时恒红，与 I-6.4（无未加密块）合起来等于「加密卷不可能合法」。
⇒ **只能是判解密后的明文补齐**，也就是**密钥在场的 checker 才做得了这一条**。

⚠️ 这一步是**推的，不是引的**。它需要用户定案补一句，不许当已定引用。

**臂乙′ 在这一格的增量 = 0，理由逐格：**

⇒ **`声明长度` 进密文对 I-2.3 是零成本**：它的唯一消费者已经是一个必须解密的检查，
取值和被判的对象在同一次解密里一起出来。

**而且它顺带修好了一处 I-6.2 补注的既有违反。** 补注逐字（`invariants.md:220-222`）：

> | **任何明文侧字段**（明文头 flags / **长度** / nonce 代号、明文映射层条目、反向索引、位置条目里的密文校验和）| 期望值来源判据 | 期望值由被读对象自己提供，**攻击者可同时改两边，AEAD 对此零保护** |

## 五、问题 4（第一轮遗留）：「单元类型标签结构上进不了密文」经不经得起推敲？

**答：那句话的结论对，但它引的依据托不住它。依据要换，而换过之后它比原来更硬。**

### 5.1 先看它引的那句原文到底说了什么

第一轮泄漏表逐字：

> | **单元类型标签**（flags 偏移 6） | 数据单元与元数据单元各有多少 | D18（块里携带什么信息） 已定项 7 逐字「扫描器必须在解密前分出类才知道套哪张白名单」⇒ 结构上进不了密文 |

被引的原文（`decisions/18-块里携带什么信息.md:504`，flags 那一行的出处栏）：

> **偏移 6 = 单元类型标签（已定项 11 登记表的码），偏移 7 = 8 个 flag 位、第一版恒 0、非 0 一律拒收（前向兼容政策）**——加密开启后元数据身份进密文，扫描器必须在解密前分出类才知道套哪张白名单

⚠️ **这句话说的是「要先分出类」，没有一个字说「类只能从一个明文字段里读」。**
这正是这一整轮在 `声明长度` 上利用的那个缝——D4 已定项 6 的依据说的是「住单元自己身上」，
不是「明文」。**同一个缝在这里也在**。所以第一轮那个「⇒」是一步外推，不是引文。

### 5.2 「分出类」有第二条路，而且不要密钥

I-2.4（头校验和覆盖范围）逐字：加密开启后覆盖范围 = **该类白名单里的全部明文头字段**。
三个内容类各有自己的字段集 ⇒ **拿各类的字段集各算一遍 32 字节头校验和，只有真的那一张会匹配**。
误匹配概率约 2⁻²⁵⁶ 每次；头校验和**不带密钥**，所以无密钥侧也做得了。

⇒ **「结构上进不了密文」按字面不成立。** 有一条不要密钥、误判率可忽略的试算路。

### 5.3 但这条路今天分不出码 2 与码 3——而这才是真正的障碍

I-6.2（明文头字段白名单）逐字：**「元数据类仅此而已（五元组 / key 区间等身份字段一律进密文）」**，
而登记表把**码 2 与码 3 都归元数据类**。

⇒ 加密开启时码 2 与码 3 的明文字段集**逐字段相同**（都只有共同前缀）
⇒ 两者的头校验和覆盖范围相同 ⇒ **试算法对这一对没有任何判别力**。

而这一对恰恰是单元大小不同的那一对：**码 2 = 16384 / 16384，码 3 = 32768 / 32768**（登记表）。
分不出类 ⇒ 分不出单元大小 ⇒ 步进跳过与认领规则都没有落脚点。

### 5.4 落点推断（问题里点名的那条路）：**不成立，且可以逐字驳倒**

E86（扫描步进与两种单元大小）的采用臂逐字（`e86_scan_step.rs:19`）：

> | step16k_any | 数据 32K 对齐（D18 已定项 9 的硬要求），**节点任意 16K 槽** | **16384** | 全收 |

⇒ 放置政策**明令**节点可以落在任意 16 K 槽，包括 32 K 对齐的那个。逐格结论：

| 探针地址 | 落点能推出什么 | 够不够 |
|---|---|---|
| ≢ 0 (mod 32768) | 只可能是码 2，或某个码 1 / 码 3 单元的载荷内部 | 部分够 |
| **≡ 0 (mod 32768)** | 码 1 / 码 2 / 码 3 **三选一** | **不够** |

⇒ 对一半的探针地址无判别力。**「按落点所在的分配单元推断类」这条路走不通。**

另一条更硬的：分配记录（D3 已定项 1 的逐落点谓词）住记账树，记账树是元数据、载荷是密文；
而扫描重建正是「索引没了」那条路径。⇒ 无论有没有密钥都取不到。

### 5.5 换过之后的正确依据（三条，都可核）

| # | 依据 | 逐字来源 |
|---|---|---|
| 1 | 码 2 与码 3 的明文字段集完全相同 ⇒ 任何只看明文的判别法都分不出这一对，而它们单元大小不同 | I-6.2「元数据类仅此而已」+ 登记表「单元大小 / 对齐」列 |
| 2 | 无密钥一侧**必须**分得出类：它要枚举单元、要跳过载荷内部、要按类定位载荷 CRC。走「试 AAD 验 MAC」那条路要密钥 | D9 已定项 5「只读只检测」+ 已定项 11「AAD 规范编码里标签码是第一个字节，每一类都是」 |
| 3 | 买到的东西很小：泄漏表自陈只是「数据单元与元数据单元各有多少」，一个聚合比值 | 未定项 13 泄漏表第二行 |

**归纳成一句可判的话**：

> 无密钥侧要分得出类 ⟺ 明文里存在一个类的判别子。
> 把标签换成 per-class magic、换成别的明文位、换成明文可算的任何函数，都只是**换个地方放同一个判别子**。
> ⇒ 「类标签进不了密文」的真正理由不是「解密前要分类」这句话本身，
> 而是 **D9 已定项 5 要求无密钥侧仍能枚举与跳过**。

### 5.6 顺带：这个泄漏比表里写的还要小

**类标签就算藏起来，单元大小仍然从别处漏**（推得，非引文）：
明文 magic 让攻击者枚举得出全部单元头的地址，**相邻两个头的间距**就已经给出一部分类信息：
间距 16384 ⇒ 前一个必是码 2（码 1 / 码 3 会占满 `[a, a+32768)`，那里不可能有第二个头）。
反方向不成立——间距 32768 也可能是「码 2 后面跟一个空槽」，所以这只是**一半**的判别力，没有量过。
⇒ 把标签藏进密文买到的比泄漏表写的还少，具体少多少要看盘上码 2 与码 1 / 3 的混布比例（本轮没量）。

### 5.7 这一格与臂乙′ 的交互（必须记，是臂乙′ 的一项代价）

§2 把认领规则的跳过长度从 `声明长度` 换成了**由类标签给的单元大小**。
⇒ 臂乙′ 之后，类标签多了一个消费者，而且是无密钥侧的消费者。
⇒ **臂乙′ 使「把类标签也藏起来」这条路变得更贵**，不是更便宜。

这是一笔诚实的账：臂乙′ 把 `声明长度` 这一格清零，代价之一是把重量压到了另一格上。
但那一格本来就按 §5.5 的三条依据关着，**臂乙′ 没有新开一扇门然后又焊死它**。
