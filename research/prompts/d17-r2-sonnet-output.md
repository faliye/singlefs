## 4-2：今天是不是 1；「逐路径读」怎么在条款文本里堵死

**今天已开的线只有一条**（D12（目标介质） 已定项 5：「第一版只实现普通 SSD 那一套布局」，
`.claude/kb/decisions/12-目标介质.md:245-296`）。候选甲′的等价关系是「两条线同类 ⟺ 对每一条根槽写
路径，两条线的段序列同构」——这个关系只在**至少两条线**之间才有内容；只有一条线时，「等价类数」
按定义就是 1（一条线自己和自己同构，无需比较任何东西）。**这不是数出来的 1，是集合只有一个元素的 1。**
所以「今天 1」不依赖 4-1 里任何一段的具体切法，只依赖 D12（目标介质） 已定项 5 这一句——**这一点我推得出来**。

**「逐路径读」的具体读法是什么、会不会把今天数成 ≥ 2**：我按 4-1 逐段核出来的四条路径的段序列形状互不相同——

| 路径 | 段序列（今天能核到的部分） |
|---|---|
| mkfs 种根 | `4, 1, 1, 1, 2`（5 段，不进层 0 枚举） |
| 空发布（单次，孤立看） | `2, 1, 2`（3 段） |
| 普通发布（单次，孤立看） | `16, 2, 1, 2`（4 段，孤立时第一段是 16 不是 18） |
| 实例切换 / 管理员回退 | 预想，未写成字节 |

如果把这四行当成「四个待比较的对象」互相比对（问「mkfs 的段序列与普通发布的段序列同不同构」），
答案是**不同构**——`4,1,1,1,2` 与 `16,2,1,2` 段数、段大小都不同。这正是第一轮反推腿（Opus）指出的
「逐路径读今天四个互不相等的集合 S1–S4」（`d17-r1-main-verification.md:32`，O-2）。**如果把这个「不同构」
当成「多一个等价类」去计数，今天就会被数成 4，不是 1**——这就是 4-2 要堵死的读法。

**候选甲′原文怎么防它、防得住不住**：原文是「两条线同类 ⟺ **对最小封闭单元里的每一条根槽写路径**
……两条线录制流的段序列……同构」。逐字读，比较的主语是「两条**线**」，四条路径是被比较对象**内部**的
四个分量，不是被比较对象本身——也就是说，判据要求的是「线 A 的 mkfs 段序列 与 线 B 的 mkfs 段序列
同构，**并且** 线 A 的空发布段序列 与 线 B 的空发布段序列同构，**并且**……」，四次比较全部按**同一路径
角色**跨线配对，从未要求「线 A 内部 mkfs 与线 A 内部普通发布」这两者同构。**按字面读，这条判据本身
没有把 4-2 担心的那种读法写进去**——但它也没有**显式排除**它：一个不熟悉这条判据意图的人，看到
「每一条根槽写路径……段序列同构」这半句，容易把它读成「这条线的每条路径都要同构（互相同构）」，
而不是「跨线同一路径角色同构」。**这正是措辞的歧义，不是判据本身错了**：候选的**逻辑**是对的
（今天只有一条线，无论按哪种读法，「等价类数」都应该是 1，因为压根没有第二条线可比），但**文字**
留了一个可以被误读成「线内部互相比较」的缝。

**我推得出的结论**：4-2 判红条件（「有腿按候选判据数出 ≥ 2」）**没打中**——不管按跨线读法还是
按线内互比读法，今天都只有一条线，「多出一个等价类」需要**第二条线**才有意义，线内部四条路径
形状不同不产生第二条线。但**措辞要堵死歧义**，堵法是在候选条款里显式加一句排除句：

> 比较只在「同一路径角色、跨线」之间进行——mkfs 只与另一条线的 mkfs 比，空发布只与空发布比，
> 依此类推；同一条线内部四条路径的段序列不要求彼此同构，也不参与等价类计数。

这句我推得出（4-1 已证四条路径形状本来就不同，如果不加这句，措辞留下的缝会在**将来开第二条线**时
被人误读成「先要求线内部四条路径统一形状，再谈线间比较」，那时才会真的数错，不是今天）。

## 4-3：切换 / 回退没写成字节，条款能不能写

**登记表现在怎么写**（`.claude/kb/first-txn-layout.md:455`）：
「实例切换 / 管理员回退 | **预想**（没写成字节）：[实例表单元 + COW 单元] 屏障 [记录] 屏障 [根 FUA]
[超级块槽]——与普通发布同型，多的是内容不是步骤」。

**我推出这句「与普通发布同型」推不住，理由是三处已定条款互相印证、且都晚于或同于这一行的措辞**：

1. `.claude/kb/decisions/16-发布语义.md:288`（已定项 7 的 2026-09-13 射程注，C199（实例代号递增与
   jsn 断号即止互相矛盾） 两轮三方论证）逐字：「每个新实例（每次可写挂载、恢复、切换、回退）的第一个根
   在下一次发布之前是单点……要不要让新实例先把根写到两块盘上再确认，是 D16（发布语义） 已定项 8」。
   ⇒ 这句把「新实例第一个根是单点」的风险**明写成同等适用于切换与回退**，不是只适用于 mkfs 之后的
   第一次挂载。
2. `.claude/kb/decisions/16-发布语义.md:203`（已定项 8 定案原文）逐字：「新实例在本实例写成（FUA 返回）
   的根覆盖两块盘之前，不让任何 fsync 返回、**不向管理员确认回退**；做法是连推空发布，第一版几何至多
   R = 3 次」。⇒ 「不向管理员确认回退」这半句点名了回退这一种场景——定案本身把「连推空发布」的
   义务同时压在回退头上，不是只压在 mkfs 后的首次挂载头上。同一行 186（已定项索引表）写的是
   「**新实例**在确认之前先让本实例的根落到两块盘上（暖机）」，主语是「新实例」，不是「mkfs 之后的
   第一个实例」。
3. `.claude/kb/decisions/16-发布语义.md:216`（已定项 8 的三方论证记录，甲′臂的代价）逐字：
   「**D28（挂载期承诺量） 已定项 3 的切换预留要加每次切换至多 R 次空发布**，而空发布的开销 c_max
   没有口径」。⇒ 这不是我的推论，是仓里**另一条决策**（D28）已经把「切换需要至多 R 次空发布」
   算进挂载期承诺量的预留式子里——如果切换真的「与普通发布同型」（一次性、无额外空发布），
   D28 已定项 3 就不该单独给切换记这笔「至多 R 次空发布」的账。

**这三处放在一起推出的结论**：「实例切换 / 管理员回退」的真实段序列形状更接近
「一次含实际内容的发布（redo 的 COW 单元 + 实例表行 + 记录 + 根 FUA + 超级块槽）+ 至多 R 次
**空**发布链接（与暖机同构造：屏障 [空记录×2] 屏障 [根 FUA][超级块×2]，重复 0 到 R 次，
直到新根覆盖两块盘）」，而不是登记表现在写的「单次发布，与普通发布同型」。**多出来的不是新的
步骤种类**（空发布用的还是写单元 / 写记录 / 根 FUA / 超级块覆写 / 屏障这五种，`.claude/kb/
first-txn-layout.md:1448` 逐字「步骤种类只有五种」这句仍然站得住），**是多出的序点**——每一次
额外的空发布都带自己的一组屏障 + FUA + 超级块覆写，段边界的位置比「与普通发布同型」多出好几处
（暖机两次空发布贡献的段序列是 `2,1,2,2,1`，五段；如果切换需要同样多的空发布，切换路径的段序列
长度会从「与普通发布同型」暗示的 4 段涨到 4 + 5×(空发布次数) 段）。

**这正对上 4-3 判红条件写的「段序列结构上不可能与普通发布同型（多一种步骤或多一道序点）」**——
我推出来的是「多一道序点」这一支（不是多一种步骤）。**判红条件打中。**

**条款怎么写**：按 4-3「触发时怎么记」那一列，动作是「条款加『切换 / 回退写成字节之前登记表那两行是
预想，写成字节时按 4-1 复核』」——这个动作本来就在候选甲′的门禁形态里，不需要新增。但我推出的这条
理由**足够具体**，值得把登记表那一行的措辞现在就改掉，不必等写成字节才发现：

> 实例切换 / 管理员回退 | **预想**（没写成字节，且不与普通发布同型）：一次含实际内容的发布
> （[实例表行 + redo 的 COW 单元] 屏障 [记录] 屏障 [根 FUA][超级块槽]）之后，可能还要链接
> 至多 R 次空发布（与暖机同构造），直到新根覆盖两块盘——D16（发布语义） 已定项 7 注 / 已定项 8、
> D28（挂载期承诺量） 已定项 3 都把这条义务同等施加于切换与回退；写成字节时按 4-1 复核实际段数。

**这条修正不改变「今天等价类数 = 1」这个结论**——甲′的等价关系是跨线比较（见 4-2），
切换 / 回退这条路径的真实形状再复杂，只要它没有第二条线可比，就不产生第二个等价类。
它改变的是登记表这一行的**准确性**，以及将来切换 / 回退真的写成字节时该核对的形状预期。

## 4-4：门禁形态过不过「改一段切法由绿转红」；kb 表与源码常量之间谁盯

**「改一段切法必须由绿转红」这条自证，对已写成字节的两条路径（暖机 + 普通发布合并的那一段流）成立，
有源码实证**：`e142_first_transaction_dry_run.rs` 里同一个切法参数 `fua_is_boundary`（`split_into_segments`
函数第 2384 行的形参）取 `true` 和 `false` 两个值，分别喂给两个不同的单测——

- `layer0_state_count_is_262162_with_zero_violations`（2881–2896 行）：`fua_is_boundary = true`
  （2884 行 `split_into_segments(&recording.operations[mkfs_operation_count..], true)`），
  断言段序列 `vec![2, 1, 2, 2, 1, 18, 2, 1, 2]`、状态数 262162。
- `fua_not_a_boundary_gives_524311_states`（2900–2904 行）：`fua_is_boundary = false`
  （2902 行同一函数传 `false`），断言状态数 524311。
