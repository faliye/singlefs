Part 1. Four admission rules for a storage pool.

Each rule defines available(d) and demand(d), both computed per physical disk, and what happens when available(d) is less than demand(d) on some disk ("does not pass").

Rule T (today's code): available(d) = capacity(d) minus already-allocated(d) minus unreclaimable(d) minus deferred-pending-release(d) minus mount-time-commitment(d) minus abandoned-root-exclusive(d) minus [pending-delete + committed-reservation + checkpoint-reserve-pool] divided by R. This is computed by the function available_on_each_device in crates/singlefs-core/src/admission.rs. demand(d) = the sum, over the roles rewritten by this publish, of span_slots for every role whose space_budget_of_role is Demand (ordinary allocation: user data units, and extent-tree/inode-tree nodes rewritten because the user changed content). This is computed by the function demand_of_the_roles_on_each_device in the same file. When it does not pass: refuse. A publish returns PublishError:: SpaceAdmissionRefused; a mount returns MountError:: SpaceAdmissionRefusedBeforeAcquisition.

Rule P2: available(d) = the same formula as T with the single term "minus deferred-pending-release(d)" removed; every other term is unchanged. demand(d) = the sum of span_slots over every role rewritten by this publish, without filtering by space_budget_of_role (so it includes both the ordinary-allocation roles and the fixed-point roles written this time: allocation-record tree, accounting tree, mapping tree, and the tree table), and without adding the slots being replaced (released) by this publish. When it does not pass: refuse (same as T).

Rule P1 (T plus a not-yet-implemented recovery step): available(d) is exactly T's available(d). demand(d) is exactly T's demand(d). When it does not pass: first push one empty publish to raise the rollback floor F, taking F to the admission ceiling defined in fact B2 below; then re-check available(d) versus demand(d). At most 8 such empty publishes are pushed within one admission attempt (fact B1 below). Only refuse after all 8 have been pushed and it still does not pass. This recovery step is never pushed before the publish that first writes a row into a brand-new instance's table.

Rule P3 (P2 plus the same recovery step as P1): available(d) is exactly P2's available(d). demand(d) is exactly P2's demand(d). When it does not pass: exactly the same recovery step as P1 (push up to 8 empty publishes, re-checking after each, using the same ceiling definition in fact B2).

Part 2. Two rules quoted whole from the design decision that defines the recovery step (source file decision file D16).

Fact B1, source decision file D16 line 41, quoted whole (the row is a table row from the source; punctuation kept as in the source): "Admission: allocatable = min(reallocatable + live metadata minus reserve pool, df); when admission is insufficient, first push an empty publish to raise F (this is never pushed before the publish that writes the row: that publish is the new instance's first publish, its metadata goes through the instance-switch reserve, and if the user-data redo within that same publish is insufficient it returns ENOSPC directly); at most B = 4 + 2 k_tol publishes are pushed within one admission attempt (k_tol = 2, so B = 8); only report ENOSPC after doing the full amount and still being insufficient."

Fact B2, source decision file D16 line 36, quoted whole: "Ceiling for raising F: admission raise-F uses min(the newest persisted valid root on that disk, the 4th-newest non-empty persisted valid root); when there are fewer than 4 non-empty valid roots, the oldest valid root is used instead. The target of one reclaim pass = min(the release-generation being freed this time, the 4th-newest non-empty root). Unmount raise-F (a different, non-admission path) instead raises F to the txg of the currently active version, with no separate ceiling check (this is equivalent to taking the ceiling as the newest persisted valid root without taking the minimum across disks)."
