## 三、提案（第四版）

### P1 单元头带「写序」= (实例代号 4, 事务号低 48 位)

每个单元的类身份段加 10 字节写序 = 写出它的那个事务的 (实例代号, 事务号)。
**事务号**是 D23 已定项 7 已定要加进记录头的那个 8 字节字段：按实例计数、从 1 起、高 16 位恒 0（2⁴⁸ 每实例够用，口径同 D23 已定项 9 的计数器）；提交标记 1 字节；记录头的 9 字节增量不动，五处实验常量不动。同一事务的全部记录共享事务号；jsn 按记录递增、事务号按事务递增，是两个计数。
住类身份段不住共同前缀：码 1 与五元组、诞生代号同列（明文）；码 2 / 3 与诞生代号同待遇（加密开启后进密文）。

**取号纪律**：
1. **取号 = 事务被分配进某个 checkpoint 那一刻**，同时钉死它的 checkpoint 号（诞生代号由此写得出）；checkpoint 的切分等齐已分配进它的全部事务（ZFS 的 quiesce 形态）——这是对 D16 已定项 5 触发规则的一条约束：触发只是停止再分配事务进本 checkpoint，切分在最后一个已取号事务写完之后。代价是切分延迟 ≤ 最长的一个在飞事务。取号之后用户数据单元随时可写，树节点照旧在固定点收敛后写。
2. 记录按事务号顺序追加；事务号 N 的 fsync 在向调用者返回之前必须等 < N 的记录全部已追加或已确定实例结束（排队义务）。D13 已定项 2 已定第一版串行提交，这一条在第一版空转，是对将来并行提交的一条前置约束（journal 追加成为全序临界区）。
3. **失败表（封闭）**：① 取号之前失败（准入拒绝等）⇒ 无事；② 取号之后、写出任何单元之前失败 ⇒ 号作废，不写单元不追加记录（事务号留洞无害：没有单元或记录带它，jsn 仍连续）；③ 写出单元之后：单副本写失败 ⇒ 换落点重试、写序不变（两份内容相同，P3 归并）；不可恢复的失败（全部副本失败、内部不变量破、固定点不收敛）⇒ 实例结束，转只读，下次挂载走恢复并写行。不存在「中止写空记录」。
4. **W1**：一个事务对一个逻辑 key 至多留一种净效果（单元 / 墓碑 / 无）；未点名的单元允许原地重写或不点名；写序相等且不是副本时墓碑赢。

**10 字节买三件事**（同第三版，E104 `no_wseq` / `inst_only` 两臂）；发生频率未测。
**与唯一先例的差异**：bcachefs 两个字段（节点重写序 + journal_seq），且不给数据 extent 做扫描择版本；本工程一个字段，且把它加在数据单元上——后者能做是因为 D18 已定项 3 让数据单元头带逻辑身份（五元组），bcachefs 的数据 extent 头里没有 key。未在本项目验证。
**重开两句已定**：D18 已定项 1（射程条款重开）；D8 已定项 6「别的单元类都没有……不给容器单独加实例代号」。

### P2 实例表（码 3 打包记录类型 4）；实例代号的取号规则

**实例表单元**：码 3 打包记录单元，打包记录类型 4「实例表行」，记录宽 64：
- 行记录：`kind 1 = 0 | 实例代号 4 | 发布上限 txg 8 | 事务号上限 8 | 预留 43`；
- 链指针记录：`kind 1 = 1 | 位置指针 59 | 预留 4`（一片的最后一条）。
四元组取 (出生树 0, 类型 4, 容器号 = 片序号从 0 起, 出生代 0)——出生树 0 与 D5 已定项 4 给「全池 / 无归属」行的约定同一个数；它不属于任何树、不进容器索引，由根记录直接持有物理指针（D18 已定项 11「容器索引是打包单元物理指针的唯一持有者」加一条例外）；I-1.1 加第三条臂「类型 4 走根记录的物理指针」，I-1.3 的豁免行加类型 4；I-1.7 与 D18 已定项 11 的三处 93 改 103。一片 (32768 − 103) / 64 = 510 条记录（含链指针）。
根记录加一条 59 字节指针（127 → 186）。**COW 重写：每次写行重写整条链**（单链下没有只重写一片的选项），代价 n × 32 KiB × w 每次非干净恢复，n 由回收压住；mkfs 写出一片空表。它属于 D21「根」那一格（根记录 + 树表单元 + 实例表单元 = 根的间接层），载荷格式落进 D15 冻结组件 ①；类型 3 / 4 按 D15 默认档记 incompat（冻结前零代价）。

**行怎么写**：实例表按实例代号唯一，后写的行覆盖同实例已有的行。
- 任何非干净结束的实例（崩溃、内部失败转只读）在下次恢复时写行：给 [所选根的实例, 新实例) 每个实例写 (i, 在飞 txg, 重放施加的最大事务号)，一条都没施加的写 (i, 在飞 txg, 0)；
- 回退（P3）：写 (r_old, T_old, ∞) 与中间实例的 (i, 0, 0)；
- 与恢复 / 回退后的第一个根同一次发布写出。
**回收**：一行可删当且仅当清扫（P4）确认盘上不再有该实例超出上限的可读单元。zoned 第一版不回收。
**表不可读时分两句**：① 正常挂载（索引在）不受影响、可写，但要记一条持久标记「实例表曾不可读」（与 `map_provenance` 同形态），此后扫描重建对该段实例里「诞生代号 == 某次重发代号」的多版只能记歧义——这是把 C113 的一角重新暴露，不是兜住；② 扫描重建时读不到实例表 ⇒ 停在级 1（D18 已定项 5）。

**已发布谓词（全局）**：i_now = 挂载根的实例；单元写序 (i, n)、诞生代号 b：i < i_now 时无行 ⇒ 已发布，有行 (i, T, W) ⇒ b ≤ T ∧ n ≤ W；i == i_now ⇒ b ≤ 挂载根的 txg；i > i_now ⇒ 判损坏。

**实例代号**：住超级块（E100 段四那 4 字节，这里补语义）。新代号 = max(全部可见超级块的代号, 根环里全部根记录的实例代号) + 1——根环按区域落在不同盘上（I-7.6），是超级块之外的独立见证；实例表里的代号恒小于当前实例，不进 max。每次可写挂载（含干净挂载、只读转可写）取一次新号并先写全部可见超级块再动任何单元；只读挂载不取号；从 1 起、0 无效；32 位按挂载次数够用（D23 已定项 9 那个场景点是崩溃次数，这里的量是挂载次数，口径不同，数量级够）。
**射程**：它挡的是镜像内部的不同步（掉盘降级、盘失而复得）；整卷回滚（拷旧镜像）随 D9 已定项 8 宣布不防。**分叉盘**：一块盘回归时其超级块代号与当前根环对不上（它记的时间线不是当前时间线的祖先）⇒ 该盘内容整盘作废、重同步后才进候选集，不许把它上面的单元按写序参与择版本；重同步的形态归 D26 / D22 未定（今天没有落点，如实记）。

### P3 现行版本判定规则

输入：挂载根，根集 ℛ = 树表里的可写头 ∪ 快照列表（I-3.7 的结构字段未定，按「只带 txg」假设），祖先表（P6），实例表，扫到的单元集，墓碑 / 退役记录。

**副本归并（先于择版本）**：同 (类身份段全部字段含写序) 的多份可读单元是同一逻辑版本的副本（D2 已定项 6 的 w ≥ 2：同一份内容写 N 遍；P1 失败表 ③ 的重试同理），先归并成一个候选，成员必须逐字节相同、不同即判损坏；Current 返回一个版本与它全部副本的落点。bcachefs 的 cookie 合并是同一步。

**回退的定义**（D23 已定项 14 的显式例外）：管理员带外选定根环里的旧根 R_old（恢复算法自己恒选最新）= 一次恢复：不施加 R_old 之后的任何记录（被跳过的记录实例代号小于新实例，此后按 D23 已定项 14 自然被排除）；取新实例代号；写回退行；**第一个新根的 checkpoint_txg = 根环里全部根记录 txg 的最大值 + 1**（不是 T_old + 1，否则下次择新按代号最大者挑回被抛弃的线）；运行时的 defer 队列、分配器游标、全部记账统计量的现行值一律从 R_old 那棵账重新载入，被抛弃时间线的条目一条不带。

逻辑 key 与写者树同第三版。规则：
```
Visible_R(u)  := 已发布(u) ∧ u.诞生代号 ≤ T_R ∧ ∃(a, c) ∈ anc(t_R): u.写者树 = a ∧ u.诞生代号 ≤ c
v*(R, k)      := Visible_R、key = k、归并之后的候选里写序最大者
Current_R(k)  := 若存在对 R 可见、指认 k、死亡写序 ≥ v*.写序 的墓碑记录 ⇒ 死；否则 v*
```
三步求值、类型 1 容器撕裂的因果、派生量（分配记录 = 各根 Current 的全部副本落点 ∪ 重建新写的索引落点 ∪ 固定结构；旧码 2 节点一律垃圾；重建产物占新空间、晋升前只读）同第三版。

### P4 垃圾清扫

**输入先造出来**：D3 已定项 7 的分配记录条目在落点释放时不删，value 改写成「已释放标志 + 释放代」（分配代 8 字节那一段复用，最高位标志），K 代之后点删（当前代 − K 算得出来，不是扫描）；它是派生态、改格式免费，顺带把崩溃后 defer 队列内存态丢失那一格补上（分配器重启后照释放代判能不能复用）。
**准入（合取，全部来自运行时结构）**：分配记录条目标已释放 ∧ 释放代 ≤ 环里最旧根的 checkpoint_txg（这一个量同时是 I-7.4 的 K 代保护与 D22 已定项 4 重放窗口在运行时的取值，两条合一）∧ 头可读。
**孤儿单列**：没有分配记录条目、也不在分配器在飞 overlay（D3 已定项 6）里的可读单元，按实例表判：其写序所属实例 < 当前实例且按 P2 谓词未发布 ⇒ 清；这一条用的是实例表（权威态）不是 P3 的择版本。当前实例的单元一律不碰。
清扫是与 D13 增量 scrub 不同的第二个 pass，全盘、低频、可续做；水位只在整轮完成时推进；非 zoned 抹头，zoned 第一版不支持。`map_provenance = rebuilt` 未晋升期间禁止；晋升要级 2 见证者，今天不存在 ⇒ **扫描重建的产物今天永久只读：C113 买到的是可读回，不是可续用**（重建过的镜像只读，也不产生新墓碑）。
**清扫水位与最近一次根销毁的代号**是 D5 已定项 4 第 13 / 14 项，随每次发布重写（已定项 2 的 K 代点删要求，与第 12 项同），合并规则取最大值，完备性理由「回收判定要它」；已定项 3 那句「今天只有第 12 项」改。代价：每轮一遍全盘读；每次发布多两条记账写。

## 六、对立臂（第三轮反推腿建的，写进正文当决策的对立面）

**对立臂 B**：写序只加在码 2 / 3 上；数据单元头不动；extent 树的叶改成码 3 打包记录单元（与 D8 已定项 6 给 inode 树做的同型）；扫描重建重建的是每棵树的现行节点集合，数据 extent 顺着重建出来的 extent 树到达，从不按 key 择版本。这是唯一先例 bcachefs 的形状。

| | 第四版（臂 A） | 臂 B |
|---|---|---|
| 数据单元头 | 91 → 101 | 91 不动 |
| 墓碑记录 | +10 死亡写序；583 → 494 | 不动（数据 key 不按 key 择版本）；墓碑对 extent 变成冗余 |
| I-6.2 / C110 | 数据类白名单加写序 | 不动 |
| extent 树的叶 | 码 2、16 KiB、派生态 | 码 3、32 KiB、权威态（叶写放大同 E103 打包侧 1.25–1.5 倍） |
| extent 树的内部节点缓冲 | 保留 ε = 0.65（消息可从数据单元 + 写序重算，E59 乙臂换成机制） | **ε = 0**（D11 已定项 4 谓词：待下刷消息不能只从权威态重算——数据单元没有写序，E59 甲臂的歧义原样在；同 inode 树那一格） |
| 叶单元两副本都毁时 | 数据映射仍可从数据单元头重建 | 该叶覆盖的 extent 映射丢失（数据单元在盘上，但同 key 多版分不出） |
| D21 | 索引仍是派生态，清单不动 | extent 树的叶成权威态单元（与 inode 叶同型，清单也不动，但「索引整个丢了也能重建」对 extent 树改读「叶在就能重建」） |
| 实例表、清扫、类型 3 / 4、祖先表 | 要 | 同样要 |

**判决：取臂 A。** 两条臂共用实例表、清扫、退役、祖先表，差额只在数据单元的 10 字节、墓碑的 10 字节与 I-6.2 那一格——按 `.claude/rules/fs-design.md`「比谁省不构成判据」，这三样不进判据。进判据的两样都偏向 A：① 臂 B 让 extent 树（最热的树）按 D11 已定项 4 的谓词失去消息缓冲区（E56：排空后 2.62× 对 2.91×，那是 D11 整条定案买的东西），臂 A 保住它；② 臂 A 在叶单元两副本都毁时仍能重建映射，臂 B 不能。臂 B 唯一的独有优势是数据单元头与明文白名单不动，而写序与已在明文里的诞生代号是同一类知情泄漏（D18 已定项 3 的定案理由）。
**bcachefs 不走 A 的已知差异**：它的数据 extent 头里没有逻辑 key，按 key 择版本在那里根本写不出来；本工程 D18 已定项 3 让数据单元自带五元组，A 才可能。未在本项目验证。

**什么现象会推翻第四版**：第四轮给出一条 P3 判错的可达历史；取号 / 实例代号 / 释放代规则在某条已定条款下写不出来；E104 按第四版纪律建模后全规则臂非 0；或者臂 B 被证明能保住 extent 树的缓冲（那 ① 就不成立）。
