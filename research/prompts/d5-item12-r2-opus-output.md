三条臂的意图目标态（续做时判「做完没有」就用这一句，不带游标、不带「再做 N 条」）：

回退（RB）会让 txg 与树 ID 跳号，三条臂都只拿它们当值比较，不受影响。取样范围与判红数在 2.6。

### 2.5 克隆与给克隆建快照落在 origin 那个 checkpoint；同一个头第二次杀同一块

**克隆那一型：三条臂都不中。** 模型加了发布操作 PSC：同一个 checkpoint 末尾建快照 O、从 O 克隆出头 H、给 H 建快照 C1，于是 C1.txg = O.txg = prev(H) = t。

量：`out-replay.jsonl` 的 H3（9 步：PSC 之后克隆头杀继承块、再建快照、再杀、销毁 C1、做完意图）17 个变体都不中（历史走完再按提交序把意图做完，也不中）；BFS「2 个头、2 块、3 个活快照、txg ≤ 3、允许 PSC / PSS / 克隆、深度 ≤ 8」对四条臂（含阳性对照）都搜完、都不中；fuzz 里 PSC 权重 0.3，强配置 0 / 300。

**同一个头第二次杀同一块：在现有操作里构造不出。** 试过的途径：

## 三、U2：代价

### 3.1 丙′ 杀块那一刻「头的上一个快照的树 ID」从哪来

树表条目的字段表（`08-核心索引结构.md` 第 466 行）：树 ID 8 + 条目长度 2 + 种类 2 + flags 2 + 根指针 86 + `previous_snapshot_txg` 8 + 诞生 txg 8 + 头 ID 8 + 预留 24。里面只有 prev 的 txg，没有「上一个快照的树 ID」，也没有克隆的 origin 链接。三条来路：

| 来路 | 杀块那一刻做什么 | 代价 |
|---|---|---|
| (a) 按 txg 查树表 | 找「头 ID = h、诞生 txg = prev(h)」的快照条目里树 ID 最大的那条（同 txg 可以有两个快照，`16-发布语义.md` 第 85 行） | 树表按树 ID 升序排（`08-核心索引结构.md` 第 76 行），同一个头的快照不连续 ⇒ O(树表条目数)，随树数涨（二层封顶约 1.19 万棵）。**不是 O(1)** |
| (b) 内存里的派生量 | 挂载时扫一遍树表，建「头 → 最新的活快照的树 ID」；建 / 销快照时顺手改 | 杀块 O(1)；挂载时 O(树表条目数)；是一条新的派生态与重建路径，材料没提 |
| (c) 存进树表条目预留 8 字节 | 头条目多一个字段，与 prev 同处 | 杀块 O(1)；吃预留 8，与乙一样挤认购者（第四节） |

(b) 要两个前提：
1. 快照条目认得出属于哪个头：头 ID 写「创建这棵树的那次发布所服务的可写头」（`05-快照-空间记账机制.md` 第 247 行），快照的条目按这句写 h ⇒ 认得出。
2. **克隆头的第一段装 origin 的树 ID 做不到**：origin 链接没有字段（字段表里没有，第四节末那次 grep 也没找到落点；`checks-owed.md` 第 252 行 C271（livelist 的 FREE 在什么时刻记没有定义） 自己写着「过滤用的『克隆时刻』要一个固定不变的字段」没钉）。克隆头还没建快照时，(a)(b) 都拿不到 origin 的树 ID，只剩 (c)。
   改成「装 0」就不需要它：前缀已经是克隆头自己的树 ID，0 不会与任何段撞。模型里 `first_seg=zero` 与原样逐格同结果（2.6 表），但这改了定义，算新形态，被攻过零轮。

级联还要「S 的上一个快照的树 ID」当改键的目的段：S 在写意图时就从树表删了，要在那一刻从 (b) 或 (c) 取出写进意图；走 (a) 就是写意图时按 txg 查一次，O(树表条目数)，不在杀块路径上。
先例：`08-核心索引结构.md` 第 478 行给 prev 找盘上落点的理由是「『活头头部』是什么盘上结构此前全仓 grep 零命中，树表条目正好补上这一格」——杀块路径上的那个标量当时选的是落盘，不是派生。(b) 与这个先例方向相反，是一个要单独拍板的选择。

判：只按盘上字段走 (a)，反向接受条款「丙′ 在 U2 被『杀块那一刻要按 txg 查上一个快照的树 ID、不是 O(1)』打中」按字面触发。交用户时摆三条：丙′ + (c)（吃预留 8，改第一段为 0 也行不改也行）、丙′ + (b)（零字节，但第一段必须改成 0，并新立一条派生态）、另两条臂。

六个几何上每条臂真值都零判红。读法：
1. **改键条数分批前后不变**：丙-区间 0、乙 min(D(S), K)、丙′ K，与第一轮原子级联的式子相同；G2–G5 里丙-区间、乙（挑少的）、乙固定搬 S、丙′ 四列，与第一轮 `research/prompts/d5-item12-r1-opus-model/out-all.jsonl` 里 N = 4000 的 geometry 行（丙-区间、乙 min、乙 move、丙′）逐格是四分之一（现算核过）；「固定搬下一侧」第一轮没有这一列。G6 说明批与批之间建快照不改变改写量。
2. **乙挑边要先数两份**：盘上没有每份 deadlist 的条数（树表预留也放不下，第四节），写意图那一刻要读 D(S) + D(N) 条（上表第三个数）。放进写意图的那个事务就是一次无界读；要么先分批数完再写意图，要么不挑、固定一个方向——那样最坏是 max(D(S), K)（「固定搬 S / 固定搬下一侧」两列的 1000）。丙-区间、丙′ 不挑边，不用数。
3. **续做的读**：丙-区间原地过滤，被放的条目散在留下的条目中间。按分桶 (i)，每批重新定位「birth > P」那一段，每个（纪元, 类标签, 出生树）组一次定位（第一轮报告 3.4），这笔定位按批数乘；带游标能省掉，而游标在强配置下不影响正确性（2.6 表：游标变体不中）。乙、丙′ 搬走的条目离开源段，下一批直接取源段最小键，不重定位。
4. **每批要写的叶**：丙-区间只删不插；乙、丙′ 每搬一条是删一条加插一条，目的段的叶要新写 ⇒ 释放空间的路径上多了分配（推的，模型不算节点）。
