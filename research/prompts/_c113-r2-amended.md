## 三、提案（第二版）

### P1 单元头带「写序」= 事务号

**每个单元的类身份段加 10 字节「写序」= 写出它的那个事务的事务号 = 该事务首条 journal 记录的 jsn（实例代号 32 位 + 计数器 48 位，D23 已定项 9 那个数）。**
住类身份段不住共同前缀：码 1 与五元组、诞生代号同列（明文，I-6.2 数据类白名单加一项，泄漏的是写入次序，与诞生代号同一类知情泄漏）；码 2 / 3 与诞生代号同待遇（加密开启后进密文——无密钥时元数据身份本来就读不到，D21 已定「无密钥重建本来就不可能」）。

**取号纪律**（反推腿 1.5 / 1.6 逼出来的三条，都是写路径义务）：
1. 取号时刻 = 提交固定点收敛之后、写任何单元之前（D3 已定项 5 引 E81 时说的「发布末尾一次性 COW」从下界升格为义务）；
2. 取到号的事务必写记录——中止也写一条空记录，记录按取号顺序追加，号永不回收（保住 D23 已定项 3 的「jsn == expected、断号即止」）；
3. **W1**：一个事务对一个逻辑 key 至多留一种净效果——单元、墓碑、或都没有（先删后写只留单元，先写后删只留墓碑）；已写出但尚未被记录点名的单元允许原地重写或干脆不点名，不必作废；**写序相等时墓碑赢**（相等只可能来自同事务先写后删的残留）。

**10 字节买三件事**（反推腿 1.4 的拆账，E104 各有一条臂）：

| 要买的 | 更便宜的东西够不够 | E104 |
|---|---|---|
| 同一 key 的已发布版本定序 | 诞生代号 + W1 就够——同一发布内一个 key 至多一个单元 | `no_wseq` 臂在 same_txg 世界歧义 3（两个数据 key 各两次覆写 + 墓碑容器自己的两版），因为那个世界故意让两个事务在同一 txg 改同一 key；按 W1 改成「一次发布内至多一个」则诞生代号够 |
| 分辨崩溃前后两条时间线 | 4 字节实例代号就够 | `inst_only` 臂在 crash_clean 世界 0 |
| 在飞 txg 被部分重放：同实例同 txg 里一半已施加、一半被抛弃 | **非要计数器不可** | `inst_only` 臂在 crash 世界复活 6 = 被抛弃单元数；E42 实测 87.4% 崩溃点落在事务中间，这不是边角 |

⇒ 实例代号 4 + 计数器 6 = 10，就是 jsn 的两段；不另造编码。

**与唯一先例的差异**（反推腿 6.3）：bcachefs 用两个字段——每节点的重写序 `BTREE_NODE_SEQ` 定序、bset 的 `journal_seq` + 黑名单定已发布性。本工程一个字段够，因为每次重写都是一个新事务，事务号本身就是每身份的重写序；代价是同一发布内不许两个事务改同一 key（W1）。**未在本项目验证**。

**重开两句已定**：D18 已定项 1（谱系重写序号不做——按它自己的射程重开：写序买的是恢复口径，运行时仍问分配记录）；D8 已定项 6「根记录靠实例代号分辨，别的单元类都没有……不给容器单独加实例代号」——前提「别的单元类都没有」被 P1 改掉，容器不是单独加，是全部单元类一起加。

### P2 已发布性住「实例表单元」，实例代号住超级块

**实例表单元**：一个由根记录直接指向的 16 KiB 元数据单元（码 2 类身份段，与树表单元同级、同 w = 2），每行 (实例代号 4, 计数器 6)，一片装约 1600 行，满了链下一片；根记录加一条 59 字节指针（127 → 186，512 槽余 326）。
**为什么不住记账树**（反推腿 3.1）：读它不许依赖任何择版本——记账树的内部节点是码 2、丢了要从叶重建、重建要择版本、择版本要这张表，循环。根记录直接指向的单元由根的指针（含校验和）指认唯一一版，没有择版本这一步。这正是 bcachefs 把黑名单放进超级块字段的机制理由（消费者在读 btree 之前就要它）。D5 已定项 1 / 3 / 5 与 D8 未定项 7 因此都不动。

**写行**：恢复时给 [所选根的实例, 新实例) 之间的每个实例各写一行，值 = 重放施加的最大计数器（一条记录都没被施加的实例写 0）；与恢复的第一个根同一次发布写出——这也是「回退到哪个根都一样」成立的真正理由：行与 txg 重发在同一次发布，比它早的根用不到这一行（反推腿 3.5）。
**回收**（反推腿 6.1）：一行可删当且仅当清扫（P4）确认该实例计数器 > 水位的单元已全部不可读；不永久。

**实例代号本身**：载体 = 超级块（D22 已定项 8：每盘一份、按槽轮换、原地覆写带世代号），恢复开始先把 +1 后的代号写进超级块、再动任何单元；从 1 起、0 无效。这是 D23 已定项 9 欠账 1「代号住哪儿」那一半；「谁防回滚」与 D9 已定项 8 的 nonce 水位同载体，加密开启后由主密钥派生的 MAC 覆盖，第一版只有非密钥校验和（与 `map_provenance` 同口径）。

**已发布谓词是全局的**（反推腿 4.4）：i_now = 挂载根（最新根）的实例；单元 u 的写序 (i, c)：
- i < i_now：表里没有 i 的行 ⇒ 已发布；有行 ⇒ c ≤ 水位；
- i == i_now：诞生代号 ≤ 挂载根的 txg；
- i > i_now：判损坏。
快照根不带实例代号，它们只用 P3 的 `诞生代号 ≤ T_R` 那一维。

### P3 现行版本判定规则

输入：挂载根，根集 ℛ = 树表里的可写头 ∪ 快照列表（I-3.7），祖先表（P6），实例表，扫到的单元集 U，墓碑与退役记录（P5）。根环里的 K−1 个旧根不参与择版本；回退之后旧根成为挂载根再判，它引用的单元由 defer 窗口保护（I-7.4）。

逻辑 key 与写者树按类定：码 1 的 key = (对象 ID, 对象出生代, 锚点偏移)，写者树 = 五元组的树 ID；码 3 的 key = 四元组，写者树 = 出生树（P6 保证）。

```
已发布(u)     := P2 的全局谓词
Visible_R(u)  := 已发布(u) ∧ u.诞生代号 ≤ T_R ∧ ∃(a, c) ∈ anc(t_R): u.写者树 = a ∧ u.诞生代号 ≤ c
v*(R, k)      := Visible_R 且 key = k 的单元里写序最大者
Current_R(k)  := 若存在对 R 可见、指认 k、死亡写序 ≥ v*.写序 的墓碑记录 ⇒ 死；否则 v*
```

**三步求值**（反推腿 4.7）：① 先对全部码 3 容器身份求 v*（只依赖头、实例表、祖先表）；② 从现行的类型 1 / 3 容器取出全部墓碑与退役记录；③ 数据 key 与类型 2 容器套用 kill / retire。类型 1 容器不受退役记录影响：一个陈旧的墓碑容器版本被误当现行只会多出墓碑，而墓碑只杀写序更小的版本，无害。类型 2 记录：两个现行容器装着同一个 inode 号时记成歧义（规则上不该发生，E104 把它计入 ambiguous）。

**派生量**（反推腿 4.1）：分配记录 = 各根走读到的全部落点（码 2 节点、树表单元、实例表单元、根环、journal、超级块区）∪ 各根的 Current 落点；可写头 H 的 deadlist = 对 H 谱系上某快照现行、对 H 不现行的落点；垃圾 = 可读、已发布、不属于任何根现行版本的单元，加上「实例代号 < i_now 且未发布」的孤儿。

### P4 垃圾清扫：独立的 pass，只碰已可分配的落点

释放路径不加任何 I/O。**清扫**是与 D13 的代际增量 scrub 不同的第二个后台 pass：全盘、低频、可续做、按需（例如墓碑积累到阈值时），代价是每轮一遍全盘读——D13 买到的「每次提交全量验证本次改动」在挂钟上可行那条性质不受影响，因为增量 scrub 照旧。
**判据用运行时分配记录，不用 P3**（反推腿 5.4）：一个落点已进入可分配集合（defer 窗口之外，I-7.4 的 K 代保护由此自动满足）且头仍可读 ⇒ 垃圾。P3 只在离线重建与 checker 里用，清扫不是它的审计对象。
**手段按介质分**（反推腿 2）：非 zoned 原地抹头（写一个扇区）；zoned 不能原地覆写（D23 已定项 3 出路表原文），由 D26 的整理把活数据搬走后重置 zone。两者背后是同一个谓词「垃圾已不可读」，清扫记下**清扫水位** = 截至哪个 txg 的释放已确认不可读。
**对 D18 已定项 3 连锁表那句「scrub 从只读变成写」的知情重开**（反推腿 5.2）：那句否决的是「每扫一遍造新块、把旧块判死灌进 deadlist」；清扫只写头扇区、不造新块、不进 deadlist、只碰已可分配的落点；射程写清，不当成没发生。

### P5 墓碑记录带死亡写序；容器退役记录；回收条件

类型 1 记录加 10 字节死亡写序（= 删除事务的事务号）。新增打包记录类型 3「容器退役」：(打包记录类型 2, 容器号 8, 出生代 8, 退役写序 10)；D8 已定项 6 的合并（左吸收右）与叶被删空各写一条，P6 的重生也写一条。
**回收条件（类型 1 与类型 3 同）**：D18 已定项 10 的条件（没有快照还引用它指认的死亡 / 没有根还引用退役容器的任一版）∧ 清扫水位 ≥ max(死亡或退役代号, 最近一次根销毁的代号)。第二项的下限取根销毁代号是 E104 打出来的：被快照钉住的旧版本在快照销毁之后才变垃圾，清扫若在销毁之前跑过、门就已放行。
**永不清扫时**：墓碑只增不减，上界是删除总数，且它以 D3 已定项 2 / 4 的「已承诺预留量」形式吃可用空间（反推腿 7.9）。

### P6 跨头首次 COW 让容器重生并退役旧身份；祖先表

码 3 容器被另一个头首次 COW 时取新身份（出生树 = 写者树，容器号 = 容器里最小的 inode 号，出生代 = 本次发布），并在本头的墓碑容器里给旧身份写一条退役记录（只对本头谱系可见，origin 不受影响）。
**唯一性重证**（反推腿 4.6）：重生容器的号都是从 origin 继承来的 inode 号，< 本头的 inode 水位（克隆时取 origin 的水位，D8 已定项 6）；本头分裂产生的号都 ≥ 水位；两个重生容器的 inode 集互不相交 ⇒ 最小值不同；与 origin 的容器出生树不同。四种情形两两不撞。
**祖先表**：树表条目带 (origin 树 ID, 克隆点 txg)，克隆点 = origin 快照的 txg（与 D5 克隆三条里 `prev_snap_txg` 的初始化同一个数）；anc(t) 沿 origin 链上溯，每一环的上限取路径上最早的克隆点。销毁一棵有后代的树时条目退役成存根、保留这两段，直到没有后代（反推腿 4.5）。
