## 一、判决 2 复核：H1 / H2 / H3 今天可不可达

判决 2 说：甲 / 乙被三段丙不中的 1 故障历史打中（H1、H2、H3），H2 只在最弱读法下成立，按判据字面甲 / 乙不成立。逐段核。

### 1.1 H1（回退那一刻最新的根槽读不出）——可达，没有条款拦它

模型：txg4 建 inode 2（已确认，本实例已覆盖两块盘）；回退发生时，txg4 所在的那块盘暂时读不出；候选集里可读的最大根是 txg3；新根 txg4（新实例）取到的水位是 2（txg3 那一刻的水位），回退后重发 inode 2。

全仓搜索「回退」与「读不出 / 拒绝」的组合（`grep -n "回退.*读不出\|读不出.*回退\|回退.*拒绝\|拒绝.*回退" .claude/kb/decisions/*.md .claude/kb/invariants.md .claude/kb/checks-owed.md`），命中的都是别的话题（fsync 返回条件、I-8.3 重放前缀、实例表行怎么写），**没有一条条款要求回退候选集覆盖根环里的每一个槽、或在某个槽读不出时拒绝回退**。

`.claude/kb/decisions/23-journal的角色与格式.md:691`（D23 已定项 14）逐字：「管理员回退：从回退候选集（根环里按实例表判仍有效、且 txg ≥ F_生效的根）选 R_old……第一个新根的 checkpoint_txg = 根环里全部根记录 txg 的最大值 + 1」——这句话只说「根环里全部根记录」，不区分「读得出的」与「实际发布过的」，而实现上只能对**读得出的**根记录取 max。这不是我读漏的一句，是条文本身对这两者不作区分。

`.claude/kb/checks-owed.md:304`（C332）本身登记着「回退实例两个根都读不出时回退被撤销」这一类姊妹问题尚未解决，side by side 确认本工程今天确实没有为「回退时某些根读不出」设计任何拦截机制。

⇒ **H1 站得住**：没有找到任何一条已定条款会在回退那一刻因为某个根槽读不出而拒绝回退或改变取值方式。1 个故障即可复现，与第一轮的判定一致，我不推翻它。

### 1.2 H2（回退那次发布里切换）——读法之争，"reload" 不是文本更支持的那个

H2 的历史：回退这次发布（第一个新根）本身的根槽写失败，触发实例切换。攻方腿的模型按 **reload** 读法：切换 = 「挂载内做一次恢复」，所选根取 R_old，于是水位从 R_old 那一版**重新计算/载入**，回退时已经取到的（更高的）max 值被丢弃，新对象拿到偏低的号。

逐字核 `.claude/kb/decisions/23-journal的角色与格式.md:691`（D23 已定项 14 那一大段）里关于「实例切换」的定义：「**实例切换** = 挂载内做一次恢复：取新实例代号、写行、**重发在飞 checkpoint**——所选根取被重发的那个在飞 checkpoint 所基于的根（旧实例发布过根时是它最后发布的根，没有时是这次挂载恢复重放之后的根，**回退那次发布里是 R_old**），行只落在 [这个根的实例, 新实例)，每个被照旧事务的写序实例 k 写……号 ≤ W 的事务照旧……号 > W 的按新写序重做……」

这段话定义了切换要做什么：①取新实例代号；②写实例表行；③**重发**在飞 checkpoint（"重发"是关键动词——它说的是把已经算好的那个 checkpoint 的内容再发一次，不是"重新计算"）；④对号 ≤ W 的事务"照旧"（keep 的字面依据）。**没有一个字提到"水位要不要重新从 R_old 载入"**。

"所选根取 R_old"只回答了"这次重放/切换的基准点是谁"，不回答"回退时已经算好、还没来得及持久化的那批派生量（水位 max、树 ID 水位……）要不要作废重算"。真正规定"回退要重新载入"的那句话，出自 D23 已定项 14 更前面描述**回退本身**（管理员发起的那次动作）的段落——"defer 队列、分配器游标、全部记账统计量的现行值从 R_old 那棵账重新载入"——这是**回退这个动作触发一次**的载入，不是"每次涉及 R_old 的后续操作都要重做一遍"。

而且，D23 已定项 14 明写：「回退与它的第一个新根**同一次发布**：回退行、那次发布的单元与回退根在那次发布之前都不生效，**崩了就重做**——崩在它之前，下一次挂载选的根、施加的记录、已发布谓词的判定都**与没发起回退时相同**」。这句针对的是"崩溃后下一次挂载"，不是"同一次挂载内因写失败切换"，但它透露的原则是一致的：这次发布在持久之前，是一个**尚未生效的整体**，失败时"重做"指的是"用同样的内容再试一次"，不是"退回到比这次尝试更早的状态重新算"。

⇒ 我的判断：**H2 依赖的"reload"读法比"重发"（keep）读法更弱**。"重发在飞 checkpoint"这个动词短语，字面更支持"把已经计算好的内容原样再发一次"（keep），而不是"重新从 R_old 触发一次完整的回退初始化逻辑"（reload）。第一轮判决已经指出"H2 只在最弱读法下成立"，我进一步确认：**这个"最弱读法"没有被条文正面支持，是"挂载内做一次恢复"这个借用式短语的参数没绑死留下的空子**，不是条文明写的行为。

**但我不把这一格判成"H2 不成立"，只判成"降级"**：条文确实没有一句话显式排除 reload 读法（"重发"没有强到禁止实现者顺手把水位也重算一遍），这正是 `.claude/rules/fs-design.md`「借用式条款要把被借规则的每个参数都绑死」要拦的那种空子——**没绑死就是两种读法都合法**，不能只因为我论证了 keep 更自然就宣布 reload 不可能被实现出来。这一格记为**待绑定的参数缺口**，不算「甲 / 乙被打中」，但也不算「甲 / 乙全须全尾」——它是一条必须显式写进条文的空白，写法：「回退那次发布里的切换，重发在飞 checkpoint 时**水位与树 ID 水位等派生量维持切换前已计算的值**，不重新从所选根触发回退的重新载入步骤」。

### 1.3 H3（根环缺口：R_old 靠一次根槽写失败留在环里，带某头的被抛弃根已离开）——可达，直接由已定条款推出

模型：头 19 建过 inode 2（已确认）；头 19 随后被销毁；R_old（那一刻的根）之后，同一个槽有一次写失败——"写失败的槽按旧内容算"（`.claude/kb/decisions/16-发布语义.md:372`，D16 已定项 1 环里最旧有效根定义：「写失败的槽**按旧内容算**，在飞、没持久的发布不算」），于是 R_old 那个较旧的根多留在环里一圈；而同一时间窗口里，其余槽已经轮转到不带头 19 信息的更新根。回退到 R_old 时，环里唯一还带着头 19 水位信息的根就是 R_old 自己，取到的水位比头 19 实际发布过的（inode 2 那次）低。

这不是推测出的边角情形，是**直接调用已定条款产生的结果**：D16 已定项 1 明文规定失败的槽保留旧内容，而根环各槽轮转周期不同、内容异步，"某个槽因为写失败多留了几圈"与"其余槽已经推进很远"两件事都是各自的已定行为，组合起来就是 H3。**我核实后确认这条历史站得住，没有条款能挡住它**，与判决一致，不翻案。

### 1.4 判决 2 小结

H1、H3 是真实的、由已定条款直接推出、没有拦截机制的 1 故障历史，我维持第一轮判决。H2 我把它从"打中"降级为"读法未绑定的空白"——按文本最自然的读法（"重发"≈keep）**不**打中甲 / 乙，但条文没有强到排除 reload 读法，所以这一格必须补一句显式的话，不能算作"甲 / 乙毫发无损"。**净效果**：甲 / 乙在 U1 上仍然被两段扎实的历史（H1、H3）打中，判决 2"按判据字面甲 / 乙不成立"的结论维持，但支持它的历史从三段收窄到两段，H2 改记为条款缺口，不是打中。

## 二、判决 3 复核：H8 与「丙没有收严的余地」

### 2.1 H8 今天不触发「丙出局」——今天没有这个消费者

`.claude/kb/decisions/17-实现分层与第三方管道.md:95`（D17 已定项 5）逐字：「**已定（2026-09-03，用户定案）：纯用户态库 + 块设备抽象（文件与 `O_DIRECT` 裸设备两个后端），第一版不挂载；FUSE 等目录与 POSIX 面出现后再加，内核模块暂不做。**」

H8 描述的场景要求一个"只认 (树, 号) 的对外观察者"：NFS 客户端拿到句柄、按句柄查找对象。这个观察者的运行前提是存在一个挂载 / POSIX 面，把 inode 号暴露给外部——而 D17 已定项 5 明写第一版没有这个面，要等 FUSE 等目录出现之后才加。**今天没有任何代码路径会把 inode 号发给外部、也没有任何代码路径会按外部句柄查找对象**——这不是"消费者存在但没测"，是"消费者在这个版本里根本不存在"。

U2 判据的原文（`_c143-r2-background.md:48`）要求「写出一个只认号的消费者在某条臂下失效的具体读写序列；这个消费者要指得出它今天住在哪条条款里」——H8 满足不了"今天住在哪条条款里"这半句：全仓 grep `st_ino`、`NFS`、`i_generation`、`文件句柄`（第一轮攻方腿已做过这次 grep，`c143-r1-opus-output.md:314`），命中的只有一处引 ext4 的校验和种子做机制类比，与两处 `prior-art.md`，**没有一条定义"本工程的对外身份是什么"的条款**。没有定义的东西不能被"打中"，只能被"欠账"。

⇒ 我的判断：**H8 不触发丙出局**。它揭示的是三条臂共同欠着的一笔账——"对外身份要不要带出生代"——而不是丙独有的弱点：第一轮判决自己也指出"甲 / 乙在 H1 那种 1 故障历史里同样要靠这条条款才分得开新旧对象"（`c143-r1-main-verification.md:53`）。这笔账应该落进 `checks-owed.md`，与 D17 已定项 5 的"第一版不挂载"挂钩（前提是"等挂载面出现"），而不是作为 U2 的判负证据。

### 2.2「丙没有收严的余地」——窄读法站得住，宽读法会把条款写成不可推翻

条款原文（`research/prompts/_c143-r1-background.md:48`，第一轮候选材料的反向接受条款）：「丙在 U2 被一个只认号的消费者打中 ⇒ 丙出局，在甲、乙之间按 U3 选（**丙没有收严的余地：它本身就是把唯一性放宽的那条臂**）。」

这句括注要回答的问题是"丙出局之后还有没有救"。它给的理由是"丙本身就是把唯一性放宽的那条臂"——这句理由**只谈唯一性这一个维度**：丙把"号不复用"放宽成"(号, 出生代)不复用"，再往"更紧"收，只有两个方向——要么维持(号, 出生代)（那就是丙本身，没有更紧的中间态），要么彻底不放宽（那就变成甲或乙）。**在唯一性这一个维度上，"没有收严的余地"字面成立**：丙确实没有比"(号, 出生代)"更紧、又比"号"更松的第三种唯一性判据可选。

但攻方腿指出的三样东西——CJ / CJ2（txg 取法多要求一个见证）、对外身份多要求带出生代、按号作 key 的结构多要求随根回退或带出生代——**没有一样触及唯一性判据本身**。它们回答的是三个完全不同的问题：CJ/CJ2 问"新根的 txg 从哪个证据集合里取最大值"，对外身份问"暴露给外部的标识符要不要带出生代"，按号作 key 的结构问"将来新增的按号索引结构要不要遵守随根回退的纪律"。**这三个都是"多要求一件事"，不是"把(号,出生代)这条唯一性判据本身改得更松或更紧"**。

用 `.claude/singlefs-ai-sop/rules/evidence-discipline.md` 的判据检验一次：如果把这句括注读成"丙出局之后，不许再对丙做任何补救、包括与唯一性无关的补救"，那这条条款就变成了**不可能被任何后续证据推翻**的东西——不管以后发现哪条唯一性之外的收严有效，都会被这句话挡在门外。这正是 evidence-discipline 明确警告的那种写法。**窄读法（只挡唯一性维度的收严）才是这句话唯一能被推翻的读法，所以窄读法是唯一站得住的读法**。

再有一层佐证：本轮候选材料（`_c143-r2-background.md:41`）自己把 CJ/CJ2 和"丙的配套"列成**候选描述的一部分**：「**丙的配套**（只多要求）：对外暴露的对象身份 = (inode 号, 对象出生代)；凡按 inode 号作 key 的结构随根回退，或 key 带出生代」——这两条本来就是丙这条臂当前候选形态的组成部分，不是"丙出局之后临时抱佛脚加的补丁"，用它们不需要"收严的余地"，因为它们从一开始就在丙的候选描述里。

⇒ 我的判断：**攻方腿的异议成立**。"丙没有收严的余地"只挡住"在唯一性判据本身上再收紧"这一条路，不挡 CJ/CJ2、对外身份、按号作 key 结构这三条正交的强化；这三条都属于丙这条臂本身候选描述已经预留的"配套"，不受这句括注约束。

### 2.3 判决 3 小结

H8 不触发丙出局（今天没有对应消费者）；「丙没有收严的余地」窄读法成立，CJ/CJ2 与配套条款不受它阻挡。这意味着：即使将来某个消费者补齐之后丙真的在 U2 被打中，丙 + CJ/CJ2 + 配套仍然是一条可以继续论证的候选，不因这句括注被提前判死。

## 三、CJ / CJ2 的载体：journal 里 checkpoint_txg 的最大值会不会退回

问题分三部分：①环在一次回退的窗口里转过一圈；②两块盘上同一条记录的槽同时读不出；③新实例从前缀末 + 1 覆写被抛弃时间线的记录。逐条推。

### 3.1 journal 是两盘镜像，故障域比根环窄一格

`.claude/kb/decisions/22-单元原子性怎么合成.md:229`（D22 已定项 8）逐字：「超级块每盘一份（更新走 ≥2 槽轮换）；**journal 环两盘镜像**（D2（RAID 条带策略）已定项 6 的 w≥2 下限对 journal 记录写同样生效）；mkfs 把第 0 代根种进全部根环区域。」

对比根环：`.claude/kb/decisions/22-单元原子性怎么合成.md:1013`（D22 已定项 16 第 4 句）「根环三个区域的设备归属第一版写死 0 / 1 / 0」——**每个 txg 的根只落在一块盘上**，这正是 H1 一个故障就能打中甲 / 乙的物理原因。journal 记录不同：**每条记录两块盘各一份**，要让"CJ 读到的那条最高 checkpoint_txg 记录"读不出，需要**两块盘上同一个槽同时失败**，这比根环的单副本故障门槛高一级——与根环相比，这是本质上更难触发的故障。

### 3.2 CJ 的计算是"读后写"，不存在与自己竞争的写覆盖

CJ 的定义（`_c143-r2-background.md:40`）：「回退的第一个新根 txg = max(可读根的 txg, 环里全部自证通过的记录的 `checkpoint_txg`) + 1」。这个 max 只在**回退发起那一刻**计算一次，计算完成之后才会有新实例开始写自己的记录。**计算的时刻严格早于任何可能覆盖旧记录的新写入**——不存在"边读边被自己写覆盖"的竞态。这一步的正确性只取决于：计算那一刻，被抛弃时间线里 txg 最高的那条记录，是不是还**物理存在**于环里、且**至少一份镜像**可读。

### 3.3 环内覆写方向只会推高、不会推低（同一条时间线内）

`.claude/kb/decisions/23-journal的角色与格式.md:1235`（D23 已定项 14 跨实例边界第 3 条）：「**计数器全池接着走**：新实例从前缀末 + 1 接着写、不归零。定长环的槽位由 jsn 决定……归零会让新实例的记录落到旧前缀还要用的槽上」。

槽位由 jsn（含 48 位计数器）决定、计数器不归零、单调递增。在**同一条时间线内**，后写的记录 jsn 更大、checkpoint_txg 也更大（因为 checkpoint_txg 随发布单调推进）——物理覆盖发生在"用一个更大的 jsn/更高的 checkpoint_txg 记录，覆盖一个更小 jsn/更低 checkpoint_txg 的旧记录"，环内**当前存在的最大 checkpoint_txg 只会随时间推进而增大，不会因为同一条时间线自己的推进而"退回"**。

被抛弃时间线在回退之前的自我推进（哪怕环转了好几圈）也遵守这条规律：它自己的最高 checkpoint_txg 记录，只要没被**更晚**的写覆盖，就还在环里；而"更晚的写"要么是它自己（推进只会更高，不会更低），要么是回退之后的新实例——但按 3.2，CJ 的读发生在新实例开始写之前。

⇒ **"环在一次回退的窗口里转过一圈"不会让 CJ 那一次计算读到偏低的值**：真正能让它偏低的只有 3.1 指出的双盘同时失读（比根环故障门槛更高一级的情形），或者被抛弃时间线自己的高 txg 记录，在回退发起**之前**就已经被自己更晚的写盖掉——但那种情形下，环里现存的最大值只会是那个"更晚"的、更高的 checkpoint_txg，CJ 拿到的 max 依然安全（它取的是环里现存的最大值，不是某一条特定记录）。

### 3.4 残留风险与它的落点

真正没被建模、也没被条文正面回答的，是**跨越多次回退**时的情形：设第一次回退把系统带到 txg 101（CJ 保证的安全下界），此后这条新实例继续写到 txg 150；若这时再来一次回退，CJ 要读的是"环里全部自证通过的记录"——这时环里可能已经**不再包含**第一次回退之前被抛弃时间线的记录（它们早被 101..150 这段自然覆盖掉了），但这不是问题，因为它们的 checkpoint_txg 已经被 101..150 段的更高值代替，CJ 读到的 max 仍然 ≥ 它们。真正的边界情形是：**被抛弃时间线本身写了非常多的记录（超过环容量），导致它自己最新、最高 txg 的那批记录在回退发起之前就已经被自己更早期的写覆盖**——但这在单调递增的环里逻辑上不可能发生（新写永远覆盖更旧的槽，不会覆盖自己刚写的）。我没有找到能让 CJ 的 max 偏低的路径，除了 3.1 的双盘同时失读。

⇒ **推翻这条结论的观测**：两块盘上存被抛弃时间线最高 checkpoint_txg 记录的那个槽，在回退发起那一刻**同时**读不出；或者找到一条写路径，让"当前存在于环里的最大 checkpoint_txg"在没有双盘同时失读的情况下反而小于某个已经离开环的历史记录的 checkpoint_txg（按 3.3 的单调覆盖论证，我认为这条路径不存在，但这是**没有被 opus 的模型检验过的推理**，opus 报告第八节 R11 也如实标注"本模型没测，这一条是推理"——我同意这个标注，不升格这条结论为"已验证"）。

### 3.5 与 C331 的关系：CJ 买到的安全性和 C331 的取证价值是两件事

`checks-owed.md:303`（C331）指出"新实例的第一条记录落在读不出那条根的记录槽上，把它唯一的记录见证盖掉"——这是关于"事后能不能证明某次写确实发生过"的取证问题，与 CJ 的数值安全性（"新分配的号会不会撞历史号"）是两个不同的量。CJ 保证的是后者；前者仍然是 C331 名下悬而未决的一笔账，CJ / CJ2 不解决它。

## 五、结论汇总与什么现象会推翻它们
