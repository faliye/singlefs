## 一、题面

C651（全池没有可用的系统配置槽 0 时 checker 与实现找槽 1 的读法不同）：系统配置槽 1 的偏移 = 固定结构槽距（D22（单元原子性怎么合成） 已定项 16「槽 i 的设备内偏移 = i × 固定结构槽距」；槽距 = max(4096, mkfs 时探测的 io_min)，D2（RAID 条带策略） 已定项 19），而槽距住在槽自己里（`.claude/kb/layout/01-first-txn.md`「系统配置槽 0 与槽 1 的位置」那一段）。全池没有一个可用的槽 0 时，读者不知道槽距。这一轮要定**一句条款**：那时槽 1 去哪找，checker 与实现照同一句。E170（O3规约执行器第一版） 的执行器在这一类状态上撞「规约欠一句」G03（第二段严格跑法批 1 撞 10 + 60 态，报告 `/tmp/claude-1000/e170-segment2/report.md` 欠一句表），这一句定了它才写得下去。

## 二、实现今天的样子（主 agent 的观测，2026-10-02）

- checker：`crates/singlefs-checker/src/image.rs` 第 567 行起 `system_configuration_slot_readings`（布局表与 C651 那一行写的第 451–482 行是旧行号），槽 1 的偏移依次取 ① 本盘可用槽 0 自述的槽距；② 池里按设备次序第一块槽 0 可用的盘自述的槽距；③ 都没有时取 4096（`FIXED_STRUCTURE_SLOT_SPACING_MINIMUM_BYTES`，`crates/singlefs-format/src/lib.rs` 第 238 行）。不做逐档扫描。
- 实现：`crates/singlefs-core/src/recovery.rs` 的 `choose_system_configuration`（第 1034 行起），① ② 与 checker 相同；③ 全池没有可用槽 0 时，在 4096 到 1 MiB − 4096 之间每 512 字节一档各读一槽（第 962 行 `slot_one_found_by_trying_every_slot_spacing_the_format_allows`），只收自证过、自述槽距正好等于所在偏移的槽，几档都收得到时取世代号最大的、世代号相同取偏移小的。

- 第一版 mkfs 写的槽距是 4096（`.claude/kb/layout/01-first-txn.md` 第 41 行）；io_min 大于 4096 的设备今天是否存在于任何测试里，现查：`grep -rn 'io_min' crates/singlefs-harness/tests/ | wc -l` 由腿自己数。

## 三、格

### V1　槽距从哪来
候选至少三种：**V1-常量**（全池槽 0 都不可用时只认槽距 4096，等于 checker 今天的 ③）；**V1-逐档**（照实现今天的 ③：格式允许的每个槽距各试一档，只收自述槽距等于所在偏移的自证槽）；**V1-拒**（全池槽 0 都不可用时整池拒挂载，不去找槽 1）。要答：每个候选与 D22 已定项 16、D2 已定项 19、D23（journal 的角色与格式） 已定项 3（tail 住在自证过的槽里）、I-8.5（tail 槽有效集非空） 相不相容；在什么崩溃状态或介质损坏下各自给出不同结局（例：io_min = 8192 的池槽 0 全坏，V1-常量读到的 4096 处是什么）；逐档那一种「自述等于所在偏移」会不会把一个旧的、槽距不同的残留槽当成槽 1。

### V2　几档都收得到时取哪一槽
只对 V1-逐档有意义：世代号最大、世代号相同取偏移小，这一条依据是哪一句条款，还是要新写。

### V3　checker 与实现照同一句之后怎么验
坏盘输入里造「全池槽 0 都坏、槽 1 在非 4096 的槽距上」的镜像（C651 欠的检查）：两边结论必须相同。要答：这张坏镜像用哪个装置造、进哪一档；O3 严格跑法照这一句写的那一步是什么。
