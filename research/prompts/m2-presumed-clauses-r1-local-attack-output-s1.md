1. Under K1-A, the central-mapping-tree (t7) remains second-to-last and tree-table (t8) last in the complete sequence. Under K1-B, t8 becomes second-to-last and instance-table becomes last. Under K1-C, instance-table becomes second-to-last and t8 remains last. The three candidates disagree on which units occupy the second-to-last and last positions. This would be overturned if the actual write sequence for any candidate shows t7 or t8 not in the stated positions.

2. Under all candidates (K1-A, K1-B, K1-C), the instance-table unit must be classified as a commit-generated block, as it participates in the open-segment bump order during publish events. It is not compatible with being allocated outside this classification (e.g., via lowest-numbered-empty-slot directly). The three candidates agree on this classification requirement. This would be overturned if the instance-table unit were observed to be allocated via lowest-numbered-empty-slot without being part of the commit-generated block classification.

3. Under all candidates (K1-A, K1-B, K1-C), the clause’s list of units (accounting-tree nodes, allocation records, mapping entries, tree-table unit) does not include the instance-table unit, but the instance-table is written during warm-up publishes. This contradicts the clause’s statement that warm-up publishes write "zero units" when the tree table has zero entries. The three candidates agree that the clause’s "zero units" claim is invalid due to the instance-table being written. This would be overturned if the warm-up publish were observed to write zero units despite the instance-table being present.

4. Under all candidates (K1-A, K1-B, K1-C), the count of warm-up publishes (2) and first transaction’s txg (3) remain unchanged by the instance-table’s position in the write order, as these values derive solely from disk-ownership geometry. The three candidates agree that these constants are unaffected. This would be overturned if changing the instance-table’s position altered the observed warm-up publish count or first txg value.

5. Under K3-1 (no marker), the admission formula computes allocatable space without reading any clean-shutdown marker. Under K3-2 (marker present), the admission formula still computes identically, as the marker does not affect the on-disk state used in the formula. Both candidates yield the same admission outcome. This would be overturned if the admission calculation differed produced different results when a valid clean-shutdown marker was present.

6. Under K3-1 (no marker), the warm-up requirement to cover two disks applies unconditionally. Under K3-2 (marker present), the existence of a valid clean-shutdown marker permits skipping or shortening warm-up, violating the clause’s unconditional requirement. The two candidates disagree on whether warm-up is always required. This would be overturned if a mount with a valid clean-shutdown marker still required full warm-up.

7. Under both candidates (K3-1 and K3-2), the rollback candidate set is computed identically from on-disk root ring and instance table data, as the marker does not affect the scan process. Both candidates produce the same candidate set. This would be overturned if the candidate set computation changed when a clean-shutdown marker was present.

8. Under both candidates (K3-1 and K3-2), the effective F value is computed as the minimum across surviving disks of each disk’s maximum F value, regardless of whether recovery is skipped due to a valid marker. Both candidates use the same computation method. This would be overturned if the effective F calculation differed when recovery was skipped due to a valid clean-shutdown marker.
