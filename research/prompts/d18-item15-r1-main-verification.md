## 三、材料自己的错

1. P3「与码 3 同形」只抄了身份不变那一半，漏了跨头首次 COW 的重生与退役记录（Opus，核过 D8 第 372 行）。
2. P2 与 P6 并排互相冲突：P2 说的「规则的前提」只是 E104 源码里的一句注释，不是条款（Opus）；P6 写成事实，而仓里没定论（主 agent）。
3. key 区间的语义没定：inode 树现行写法按实际最小 / 最大 key 算，甲在这个读法下必红（Opus）。
4. 失败条款 2 的射程写窄了：没有 key 区间的不止 dirent 树（Sonnet）。
5. 材料让人以为补上择版本规则就能回到可写——重建产物照样停在级 1 只读，因为级 2 的见证者没了（Opus，核过 D18 第 536 行）。

## 四、判决

- 按字面，**甲、乙都红**；失败条款三条都不触发。
- Opus 按「记一次输 / 只许收严 / 写明收严在哪」补出三个候选，这一轮没有任何腿攻过它们：
  - **甲′**：key 区间取栅栏语义（相邻节点首尾相接、铺满父节点的范围），从树表根指针自上而下重建，T 取被重建节点自己的诞生代号；节点消失的地方一定被一个诞生更晚的版本覆盖，旧版自动被压住。代价：extent 树内部扇出 152 → 151；inode 树 0 字节。
  - **乙′**：节点号 + 码 2 退役记录；Opus 指出节点号本身不承重，承重的是退役记录。代价：每个码 2 头 +8，另加退役记录的写放大（没量）。
  - **丙**：甲′ + 验收门——重建出的节点必须逐字节复现父指针里的校验和，父指针一路追到树表（权威态）；丢失节点诞生之后它的子项被搬过，门就过不了，那一格只能只读。
- **一条会影响用户那次选择的发现**：补上择版本规则让快照那一刻的历史版本读得回来、R1 能用到任意一层，但**不让池回到可写**——回到可写要级 2 见证者，今天没有（D18 第 536 行）。
- 下一步：开第二轮（立场对调），判甲′、乙′、丙；同一 checkpoint 写两次的那一格并进 C163。是否继续，先请用户看上一条发现。
