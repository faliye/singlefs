# journal 环与日志的弹性：空间大就大、空间小就小、空间不足就缩（2026-09-22）

用户 2026-09-22 逐字提出：

> 我们的环是弹性环 因此具有空间大就大环 空间小就小环 空间不足就缩环的特征 这个应该已经明确过了。
> 我们的环和日志等是有弹性的 因此具有空间大就大 空间小就小 空间不足就缩的特征。当然我们应该设置一个默认上限，我们也应该允许用户来设置最大和最小值。 这部分需要明确一下。

## 条款今天到哪一步（主 agent 2026-09-22 现查）

`.claude/kb/decisions/23-journal的角色与格式.md` 已定项 19 ③ 逐字：

> **③ 环长**：环长是 **mkfs 参数**，**默认 768 MiB**；约束 **环 ≤ 设备容量 ÷ 4**，越界**拒绝 mkfs**。系统配置里仍只存「环长度（字节）」这一个字段，不另存容量或比例。

它的射程逐字：「③ 的「参数 + 上界」让大盘上 768 MiB 只占容量的百分之几、小镜像按参数缩，`环 ≤ 容量 ÷ 4` 挡住「环吃掉整个盘」」。

| 用户说的 | 条款今天 |

## 这一格与另一处已经坐实的缺陷是同一个

`checkpoint-trigger-r1` 那一轮（判决 `research/prompts/checkpoint-trigger-r1-main-verification.md` 判定一）坐实：

`I-8.1（环几何够大）` 的判据是「`环大小 ≥ F × 任一事务的最坏 journal 占用`」，而盘上那个「最坏占用」字段填的是

```
crates/singlefs-format/src/lib.rs
    ring_bytes / JOURNAL_RECORD_BYTES / JOURNAL_SAFETY_FACTOR
```

乘回记录尺寸就是 **环 ÷ F**。代进判据是 `环 ≥ F × (环 ÷ F)` = `环 ≥ 环`，**恒真，余量恰好 0**（主 agent 与核查员各算一遍，数一致）。

⇒ **弹性环缺的那个下界，正是 `I-8.1（环几何够大）` 本该给出而今天给不出的那个数。** 真正的「任一事务的最坏 journal 占用」按 `C310（事务切分纪律与记录数口径打架）` 现查是 **12 KiB**，`F × 12 KiB = 36 KiB` 才是环能缩到的硬下界。今天那个字段填成环长的函数，缩环时**没有任何东西拦得住**。

## 候选

**甲（今天）**：环长是 mkfs 一次性参数，越界拒绝，没有下界、不能运行时改。

**乙**：环长做成弹性量——

1. mkfs 时按容量算一个初值（「空间大就大、空间小就小」），而不是恒取 768 MiB
2. 定一个默认上限与默认下限；用户可设最大值与最小值
3. 空间不足时缩环，缩到 `I-8.1（环几何够大）` 给的硬下界为止；到了下界还不够就报错，不再缩
4. `I-8.1（环几何够大）` 那个字段真算（`F × 任一事务最坏占用`），mount 时复算比对

**丙**：只做第 4 条（把字段真算出来、判据不再恒真），环长仍是 mkfs 一次性参数。

## 实现今天的样子（主 agent 的观测，2026-09-22 现查）

- `crates/singlefs-core/src/make_filesystem.rs` 收环长参数、按最小那块盘的容量 ÷ 4 拒绝越界
- 默认值是 `crates/singlefs-format/src/lib.rs` 的 `JOURNAL_RING_DEFAULT_BYTES`
- 系统配置里存「环长度（字节）」这一个字段（`journal_ring_bytes`）、在飞上限、最坏占用、安全系数 F
- 单元区起始槽号随环长走（默认环下是 784 MiB、槽 50176）——**环长一变，单元区起点就变**
- 运行时缩环、环长可变这两样：`grep` 全仓零命中

## 要攻的五个面

| 面 | 问什么 |
|---|---|
| **K1 缩环在 COW 上做不做得到** | 环缩小意味着单元区起点前移或环的尾段被回收。那一段里可能还躺着**没被重放完的记录**，也可能已经被分配器当成可用槽发出去了。缩环这个动作要不要事务？崩在缩的中间怎么办？`.claude/rules/fs-design.md`「不是单元的盘上空间，核心层对它零覆盖」在这里怎么用 |
| **K2 「空间不足」是谁说了算、什么时候判** | 用户说「空间不足就缩」。那个判定发生在哪：mkfs？挂载？还是运行时 ENOSPC 路径上？它与 `D28（挂载期承诺量）` 已定项 1 的准入不等式是同一个量还是两个量？⚠️ 按 `.claude/rules/fs-design.md`「记账是事务的副产品」，运行时决策路径上的量**不许靠遍历算** |
| **K3 环长进不进格式的永久承诺** | 环长今天是系统配置里的一个字段。做成弹性量之后，「这个池的环曾经是多大」要不要留痕？旧读者挂上一个缩过环的池会怎样——`.claude/rules/fs-design.md`「一条格式分支值不值得，看它能不能把『用错了』变成『挂不上』」怎么判这一格 |
| **K4 上下限取什么、谁来定** | 默认上限今天是容量 ÷ 4。默认下限该是 `I-8.1（环几何够大）` 给的 `F × 最坏占用` 还是别的？用户设的最大最小与这两个默认值怎么合成（取交？用户的赢？）——⚠️ 参照 `D16（发布语义）` 已定项 5 那句射程：同一段里 `T_dirty` 走夹取、`T_time` 走警告，**两个字段两种规则**，这里也要说清环长的最大最小各走哪种 |
| **K5 甲今天真的不成立吗** | ⚠️ **这一面冲着主 agent 来**：主 agent 接受了用户「环是弹性的」这个前提，但那是当场做的判断。去核：今天「默认 768 MiB + 容量 ÷ 4 上界 + 用户传参数」这一套，在**哪些具体场景**上真的不够用？举得出一个今天做不了而弹性环做得了的可达场景，这一轮才立得住；举不出来，该收成丙（只修那个字段） |
