## 三、四层、两个独立冻结组件（同文件，整段抄）

```markdown
### 冻结分四层，有严格依赖顺序

```
第 1 层：超级块 + 块头（自身地址 / generation / 树 ID / fsid / magic）
    ↓
第 2 层：指针字段布局（D4 校验和 + D9 的 MAC / nonce / 密文校验和）
    ↓
第 3 层：各 keyspace 的 key 编码（D8 的 locality_id / inode / offset）
    ↓
第 4 层：索引节点内部布局（节点大小规则、bset 形态、D11 的消息缓冲区）
```

依赖方向的理由：第 1 层是「元数据块必须自描述」的物理前提，后面所有层都建在它之上；
第 2 层被 D9（加密）的 MAC / nonce / 密文校验和「事后加不进去」钉死，必须先于依赖它的树结构；
第 3 层的 key 编码定了，节点内部怎么组织这些 key 才有讨论基础。

⚠️ **分批冻结的风险必须显式接受**：早冻的层若漏留字段，后面只能走 incompat 打补丁，
等价于提前烧掉一次本该整体设计时留的余量。
止损规则只有一条：**第 1、2 层冻结前必须已包含 D9（加密）全部四项预留**，
因为它们恰好是「已知迟早要用」的字段，不能指望第 3、4 层再补。

**四层之外的独立冻结组件**（2026-09-05，随 D8（核心索引结构） 已定项 6 立）：有两样永久字节不属于四层里的任何一层，各立成一个组件，C9（冻结后偷改格式） 的 `spec_hash` 按组件记，四层不动——
① 打包记录单元的载荷记录格式，按打包记录类型登记：类型 2 的 140 字节 inode 记录表（D8（核心索引结构） 已定项 6），冻结时刻是第一个写出类型 2 容器的镜像；类型 1 的随 C84（墓碑单元的粒度没人定） 各自独立，不因类型 2 一起冻结；
② 统计量登记表（标签值 + 维度 + 合并规则，D5（快照 / 空间记账机制） 已定项 3 / 4）——合并规则是盘上语义，两个读者对同一批字节用不同规则会算出不同的值，C71（不认识的统计量标签静默忽略） 只罩「不认识的标签」，罩不到「认识标签但用错规则」。
两个组件的 spec 文件今天都不存在（C119（两个冻结组件没有 spec 文件））。

```

### 5.2 D13（验证路线）已定项 5：checker 与实现只共享一份从 kb 生成的常量

```markdown
#### 已定项 5（2026-09-03，用户定案，按三方对抗定）：只共享一份从 kb 生成的常量

**checker 与实现之间只共享一样东西：一份由 kb 的字段表生成的常量模块**，生成器从 kb 读、
两边都只消费、任何人不许手改（`.claude/singlefs-ai-sop/rules/machine-first.md`：重复要生成，不能手抄）。
**其余一律不共享**：地址空间的 newtype 各自声明、格式解析各写一份、校验和各用一份独立实现、
遍历与记账代码交集为空（C12（增量语义共用）已定的符号级判据，「格式解析与常量除外」那条例外就是这一项在用）。

**判定宽度不许从别处拿**：I-7.5（根槽按判定宽度对齐）与 I-8.2（记录头不跨原子单元）的判据是挂载时探测的
`physical_block_size`，它不在镜像里。checker 自己探一次，再与超级块记录的 mkfs 时取值比对
（D22（单元原子性怎么合成）已定项 2「mkfs 按池内最大值划、挂载时逐设备复算比对」的 checker 侧形态）。
**探不到时报「声明值，未探测」，不许当成探到的**——文件当设备的镜像属于这一类，
崩溃点重放的绝大多数镜像都是文件，所以这条不是边角。异构池里判定宽度是一个集合不是一个数
（C17（设备几何当全局参数）），checker 要复算 mkfs 那步取最大值的聚合，不然健康的异构池上会假红。

**生成器拒绝发射没有 kb 落点的常量**。五元组现在只有 33 字节这个总数、没有分字段宽度
（D18（块里携带什么信息）已定项 3），这类字段要先在 kb 里钉死才生成得出来。

**它买到什么、买不到什么**（三方对抗，2026-09-03，腿况在 [verification-build.md](../verification-build.md)）：

| 类别 | 共享一份生成常量 | 两边各写一份手抄常量 |
|---|---|---|
| 抄错（一边写 78 一边写 91） | **抓住**，只有一处来源 | 抓住，两边不一致会当场对不上 |
| kb 里没定的宽度（五元组的分段） | **抓住**，生成器拒绝发射 | 抓住，两边各自发明一个切法必然不同 |
| **kb 里就写错的值** | **抓不住** | **同样抓不住**——两边读同一句话 |

⇒ 第三类不是共享造成的，也不是不共享能解决的，它要一条正交的门禁：登记值必须等于同一份正文里
那些已定增量之和。落成 [checks-owed.md](../checks-owed.md) C94（登记的格式常量与后来的定案对不上），
连同「[first-txn-layout.md](../first-txn-layout.md) 表里每个已定宽度都要有登记标记」——现在全仓只登记了 3 个。

⚠️ **一条边界要守住**：生成器只发射标量值。它一旦开始发射「按字段表算出来的偏移函数」，
那就是 D13（验证路线） 明令不许共享的格式解析，而不再是常量。判据是发射物里有没有分支与算术。
⚠️ **CRC32C 各写一份的前提是参数钉死**（多项式、初值、输入输出反转、异或输出）：
参数不钉死，两份独立实现会在健康镜像上给出不同结果，那是假红而不是独立性。
```

### 5.3 `.claude/rules/fs-design.md` 的格式分支判据

```markdown
### 由此得到格式分支的判据

> **一条格式分支值不值得，看它能不能把「用错了」变成「挂不上」。**

| 能 | 值得。它买到的是「误用不可能发生」，代价（永久支持这套布局）换到了对等的东西 |
|---|---|
| **不能** | **不值得。** 它只是多了一套要永远维护的布局、多一份 checker、多一遍崩溃点重放，**没买到任何安全性** |
```

### 9.2 问题二：未定项 3「`spec_hash` 的来源」
