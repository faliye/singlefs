# 树 ID 水位：三条臂在六根轴上重比（2026-09-06）

**为什么重比**：2026-09-06 定案时只在「回退」一根轴上比过三条臂，
而第二 / 三轮对抗找出了另外几根轴。辩方腿逐字指出「原定案只在一根轴上比过三条臂，
第二轮找到了第二根轴，却没有重比」。下面每一格的出处主 agent 都逐字现查过。

## 三条臂

- **甲 超级块臂**（现行采纳）：水位住超级块，挂载时取
  `max(独占打开成功集合里各超级块的水位, 已发布树表里的最大树 ID + 1)`，
  写 `base + K` 进那个集合里的每一份、全或无；本次挂载发的号取自 `[base, base+K)`。
- **乙 记账臂**：水位是一个记账统计量，形态照 inode 号水位（D5 已定项 4 第 12 项）。
- **丙 根记录臂**：水位是根记录字段表里的一行（D22 已定项 7）。
  取值规则有两种读法，**这正是当初漏掉的分岔**：
  丙-1「读所选根里的值」；丙-2「取**根环里全部根记录**的 max」。

## 六根轴（每格带出处）

| 轴 | 甲 超级块 | 乙 记账 | 丙 根记录 |
|---|---|---|---|
| **1 回退** | 不受影响：回退不动超级块 | **输**。D23 已定项 14 逐字「defer 队列、分配器游标、**全部记账统计量的现行值从 R_old 那棵账重新载入**」 | 丙-1 输；**丙-2 不输**——D23 已定项 14 自己就用这个形态给别的量取值：「第一个新根的 checkpoint_txg = **根环里全部根记录 txg 的最大值 + 1**」（注意是「全部」不是「候选」；候选集才排除被抛弃时间线的根）。且同条逐字「**回退深度 ≤ 根环深度**」⇒ 能被回退跨过的根都还在环里 |
| **2 写时机（水位要先于使用落盘）** | **输**，靠区段预留补：实例代号那个装置是「挂载时取一次号，**之后才动任何单元**」（D18 已定项 11），而树 ID 一次挂载要发很多次 | 赢：记账随发布原子落盘 | 赢：根槽 FUA 就是发布本身，checkpoint N 发布的树，其 ID 必 ≤ 根 N 里的水位 |

## 当初否掉乙丙的那句话，射程有多大

D8 未定项 8 定案时写的是：「放进记账或放进根记录，**回退之后都会退回去把号重发**
（D23 已定项 14 逐字『全部记账统计量的现行值从 R_old 那棵账重新载入』）」。
**那条引用只覆盖乙。** 它一个字也没说根记录，而丙-2 有轴 1 那一格的现成先例。

## 已知我不知道的

- 轴 6 里「号被重发、而盘上留着用了那个号的孤儿单元」到底会不会造成实际错误，**没有定论**。
  相关条款：C113 定案的已发布谓词判那些孤儿为**未发布**；五元组身份是
  (树 ID, 对象 ID, 对象出生代, 锚点偏移)，择新键按写序（实例代号 + 事务号）取新。
  另一侧：D6 判据 9 逐字「回收一个快照 ID 会让盘上遗留的旧 key 在新快照里**变成可见**」——
  但那句说的是**已发布**的旧 key。两者谁管孤儿单元，仓里没写。
- 甲的区段预留把「全或无写」从每次挂载 1 次变成 1 + ⌈建树数/K⌉ 次，
  而 D18 已定项 11 那套回卷出路（「回卷不成才**只读挂载**」）是挂载时才做得出的动作（C147 ㈠）。
