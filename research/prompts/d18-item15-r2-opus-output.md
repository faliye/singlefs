### 1.3 其余几种形状：打不穿，或只打出保守结局（推的）

| 形状 | 结局 | 理由 |
|---|---|---|
| 分裂 / 合并 / 借位 | 不红 | 三种操作都重写区间变了的节点，诞生更晚、区间覆盖旧版，旧版被压住（区间在头里，改区间就要 COW） |
| 变高（根分裂） | 不红 | 新根层级更高，旧层级的节点照常被压 |
| 变矮之后再变高 | 不红 | 层级 ℓ 消失期间没有 X 需要它；它再出现时新节点诞生更晚、铺满，旧版被压。唯一的洞是根层级，见 R-L |
| 区间边界相等 | 只打出保守结局，定义要补 | 栅栏写成闭区间且相邻两节点共用端点时，每个节点都被它右边诞生更晚的邻居「压住」⇒ 铺不满 ⇒ 不可重建。「相交」必须定义成有正测度的重叠，端点口径（半开还是闭）必须写死；第一轮只写了「首尾相接」 |
| 同一 checkpoint 先分裂再合并 | 取决于 B5 | 全在内存里做完、只落盘一次 ⇒ 不红；中途落盘过 ⇒ 见 R-B5（第三节） |
| 已发布但从没被根引用过的单独一版 | 不红，但证明有缺口 | 证明（⇐）一段假设「V 在 b_X 之前某一刻被替换」，漏了「V 从没进过已发布的树」这一格。I-1.2（invariants.md 第 21 行）只说「判不成已发布者必是……垃圾」，没说「已发布的必被根引用过」。今天能产生这种单元的路径（事务失败）走实例切换、被 B1 滤掉（D18 第 852 行实例表那一段），所以打不出实例；但证明要显式补一条前提，B5 的写法也要罩到它（第三节） |

### 1.4 栅栏语义与 I-9.12、inode 树现行写法（判据 3，核过引文，冲突分析是推的）

- **I-9.12 本身与栅栏相容**：栅栏下第 i 个孩子的下界就等于第 i 条分隔 key，第 i−1 个孩子的上界 = 分隔 key − 1，两条不等式都成立（invariants.md 第 265 行）。第一轮 Opus 把 I-9.12 列成「改」（r1-opus 第 191 行），严格说是不必改。
- **冲突在 D8 第 350 行**：「分隔 key = 该孩子创建时的最小 key」把分隔 key 钉在创建时刻。栅栏下左端节点被移走时，右邻居必须往左扩（inode 号单调，最老的号在最左，删到最左端节点整片空是常见形态，D8 第 365 行），扩完它的下界比创建时小 ⇒ 要么分隔 key 跟着改（违 D8 第 350 行字面），要么不改（违 I-9.12「分隔 key ≤ 孩子区间下界」，且查找「取最后一个分隔 key ≤ 目标 key」会把被扩进来的那段路由错）。第一轮第五节没列 D8 第 350 行。
- **空树 [0, 0]**：D8 第 341 行与 I-9.1（invariants.md 第 254 行）都写空树根的 key 区间是 [0, 0]；栅栏下根必须铺满整个 key 空间。第一轮只列了第 422 行的 [1, 1]。
- **同一个字段两种语义**：记账树节点头的区间，first-txn-layout 第 274 行取值写「首末两条 key」（实际 key 读法）；甲′ 只把 extent / inode 改成栅栏 ⇒ 同一个头字段按树的种类有两种含义。它不违反哪条已定条款（树的种类可识别，D8 已定项 8），但 checker 与重建路径都得先读种类才解得了这个字段，要写进条款。first-txn-layout 第 258 行 extent 树区间 [(0,1,0), (0,1,0)] 也是实际 key 读法。
- 顺带（与三臂无关，推的，没全仓核）：D8 第 350 行的「创建时的最小 key」与第 370 行的「左从右借」放在一起，今天就会让右孩子被借走的那几条 key 路由错、或违 I-9.12 的第二条不等式——除非借位时改分隔 key。

### 1.5 重建出的节点装不回树里（判据 3 的边界，推的）

甲′ 不带门 ⇒ 它造出的 X′ 与 X 不保证逐字节相同。完好的父节点 Q 里指 X 的那根指针带着 X 的校验和，**X′ 从 Q 读下来必然校验失败**。要把 X′ 挂回去只有两条路：改写 Q（Q 被快照共享，碰已发布块的字节，撞 D6 第 113 行判据 4），或者给 X′ 新身份（就是 C292 那条「新发身份被活头判立即释放」）。只把 X′ 放在只读挂载的内存修复表里用，才不撞条款。第一轮在门存在的前提下判判据 3 不红（r1-opus 第 165 行），第二轮甲′ 没有门，这句前提没了。

### 1.6 extent 树的消息缓冲区：子项对了，节点仍不是那个节点（判据外，但决定 C302 的验收，核过引文）

D11 第 248–249 行：能从权威态重算待下刷消息的树留缓冲、ε = 0.65，「extent / dirent / 反向索引……判能」；只有 inode 树 ε = 0。⇒ **extent 树的内部节点在 b_X 那一刻装着一段还没下刷的消息，它们不在任何子项里**。甲′ / 乙′ / 丙都只从子项拼 X′：

- 甲′、乙′：X′ 少了那段缓冲 ⇒ 快照读出的 extent 映射缺那几条插入 / 删除。判据 1 字面只问子项集合，所以不计入红；但 C302（快照那一刻的码 2 历史版本取不出）的验收是「重建出的快照树必须与丢失前逐节点相等」（checks-owed.md 第 293 行），**这一条对 extent 内部节点按设计就过不了**。
- 丙：缓冲非空 ⇒ 门必不过（第四节）。
- 能不能从权威态把缓冲算回来：D11 已定项 4 的谓词说消息集合能从权威态重算，但「b_X 那一刻哪些还压在 X 的缓冲里、哪些已下到子项」是另一个问题，三臂都没有这一步，没人量过（推的）。
