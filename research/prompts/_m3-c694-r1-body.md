## 二、实现今天的样子（主 agent 的观测，2026-10-07）

- C694 的拒在 `crates/singlefs-core/src/mount.rs`：`isolate_slots_referenced_only_by_abandoned_roots`（第 1483 行）读被抛弃的根的账，读不出、从映射现算也不成、重读一次仍不成，在第 1540–1546 行交回 `MountError::NewerStateStillUnreadableAfterOneReread(… AccountOfAnAbandonedRoot …)`。走到它的三条路（调查员 trace 实测，主 agent 读码对过）：卸载 `unmount`（第 2938 行）→ 第 2958 行 `raise_the_floor_through`（第 3393 行）→ 第 3511 行；会话覆盖写 `raise_rollback_floor`（第 2899 行）→ 第 2907 行 → 第 3511 行；再可写挂载 `rebuilt_allocator`（第 1953 行）→ 第 2218 行。
- 调查员报的机理：取新实例那次挂载时这条根的根槽读回全零，挂载看不见它、一个槽都没隔离（两盘 `mount_isolated` 都是 0），它的树表（槽 1542）与中央映射根（槽 1541）在新实例里被当空闲槽重新发出去写掉；卸载时账读不出。推翻条件也造过：只抹树表槽卸载照样做成，树表槽与映射根槽一起抹就报同一个错；78 格逐格交叉对得上。
- C695 在 `crates/singlefs-core/src/mounted_read.rs`：`open_pool_for_read` 第 376 行先 `read_code_two_tree(&root.mapping_root, …)`，树表 0 条那一版的映射根是空指针（两条位置条目都是 0 号盘槽 0），读到槽 0 交错；第 409–411 行 `if tree_table.entries.is_empty() { return Err(OpenPoolForReadFailure::TreeTableHasNoEntries); }` 走不到。调查员在副本里加「映射根是空指针就跳过」，四格都变成 `TreeTableHasNoEntries`、槽 0 一次没再读（副本改动 `~/.local/share/singlefs/work/m3-3-5-repro/diagnostic-prints-in-the-copy.diff`）。
- 方案按 `crates/` 今天的实现来谈。

## 三、格

### K1　C694：对的世界是什么
- 这几份盘面上，正常卸载、会话写、再可写挂载该不该做得成。登记行给的两条出路：U1 做得成；U2 条款写明拒得合法、且之后的某一次卸载做得成。U2 的后半句在产品路径上今天不成立（走不到那条根离开根环），要判它还能不能救。
- 被抛弃的根的账读不出、它引用的槽已经被新实例写掉时，影子账还有没有东西要护；不护会不会让别的某一形丢数据或误放（举一形）。
- 挂载那一刻根槽读回全零而之后读得出，D16 已定项 1 那一行与 D23 已定项 14 C554 乙-配置续各管到哪一半、哪一半没人管。

### K2　C694：改法候选与代价
- 至少给出两个候选（各自的定义、改 `crates/` 哪几处、碰哪些崩溃点、要不要新条款），写明各自在复现那 11 个起点上的结局、在 C554 那一形上的结局、会不会放过一个今天拒得对的盘面。
- 每个候选的代价数：要量的量量过了吗；没量的写「推的」。

### K3　C695：树表 0 条那一版
- 只读挂载落到树表 0 条那一版时，对的结局是什么（报 `TreeTableHasNoEntries`、换一条根、还是别的），与 C683 的读法、C563 的择根怎么衔接；先读空映射根是不是 bug，改成先判树表 0 条会不会让别的版本读错。
- 可写挂载、恢复、池级 checker 碰到同一版走的是不是同一个顺序（逐处列 `crates/` 行号）。

### K4　回扫
- 同一个「读回全零的根槽当没有根」的前提，`crates/` 里还有哪几处在用；各自会不会撞出同一形。
