## 一、K1 第一条：六处逐处对用户原话

### 1.1 判定库那三处

处 1（`verification.md`）：

- 什么算「自己的库」：「不许任何测试、门禁、入口脚本、实验装置、agent 新建自己的判定库：另开一个目录存判定文件、另写一张 TSV 或 sqlite、另开一份 RocksDB 都算。」（`.claude/rules/verification.md:73`）。这是一条能判的列举。缺口一：「判定」本身没定义。写 research/results 下一次性实验产物算不算「判定」，条文没说，读的人只能靠 `verification.md` 别处的「单元键」去猜。缺口二：列举里没有 JSON 与 key=value 文本，而今天三家恰好是这两种（正文第二节的观测），靠「另开一个目录存判定文件」兜得住，但单文件、内存里的临时库没点到。
- 要存判定怎么存：「判定全部写进它，各族各自的键前缀」（`.claude/rules/verification.md:72`）加 73 行点名的两个客户端，可执行。缺口三：没写开关。今天三家 Python 库要设 `SINGLEFS_VERDICT_LIBRARY_SERVICE=prune-server` 才走服务（`scripts/prune-server/prune_server_client.py:14`），按这一处照做、什么都不设，写的仍是本地文件。新族要登记键前缀由谁定也没写。
- 旧文件库怎么办：「三家原来的文件库是旧物，只读不写。」（`.claude/rules/verification.md:73`）。「三家」在六处里都没定义（定义在 `scripts/prune-server/prune-server-import.py` 文件头，是 verdict-library、unit-verdicts、mutation-units 三族）。「全部写进它」（72）与上面两样没换存法的存放处也对不上：replay-row 与 flow-lines 今天仍是文件。
- 条文自带的执行办法：「立前靠 review：审改动时见到新的判定存放处就打回。」（`.claude/rules/verification.md:75`）。判得出，是人判。

处 2（`agent-common.md:39`）：「判定一律经 prune-server 的客户端写进那一份、按各族的键前缀」「不许另开目录、TSV、sqlite 或另一份 RocksDB 存判定」「三家原来的文件库只读不写」「改动里出现新的判定存放处，主 agent 打回」（`.claude/agent-common.md:39`）。三样都有，但没有客户端的名字（只指到处 1），读的子 agent 要再去读 `verification.md`。「打回」的是主 agent，对子 agent 自己写的动作没给自查办法。

处 3（`main-agent.md:12`）：「轻型、重型、Python 三家、崩溃几道、实验装置的判定全部写进 prune-server 原地打开的那份 RocksDB」「审 diff、写派发提示时见到新的判定存放处（另一个目录、TSV、sqlite、另一份 RocksDB）一律打回」（`.claude/main-agent.md:12`）。给了主 agent 的动作（审 diff、写派发提示）。旧库一项没有。「Python 三家」未定义。

### 1.2 多机可用那三处

处 4（`verification.md` 77-82）：

- 读什么算依赖一台：「不读本机独有的路径与状态（本机家目录下的库、本机 `~/.local/share/singlefs/` 下的运行状态、只在本机的设备）」（`.claude/rules/verification.md:79`），加「环境相关的一切只由多机配置 `multi-host.env` 定（没写就是没有，不补缺省）」（79）。判得出：三类例子加一个来源。
- 什么算多机可用：「在两台里任何一台都要跑得起、判得对」（`.claude/rules/verification.md:79`）。判得出「跑得起」；「判得对」没写对什么比（`.claude/kb/checks-owed.md:606` 的 C949 写了「判定库里按单元键记两台各一条」与本机结局相同才绿，规则正文没抄这个比法）。
- 新测试什么时候算写完：「新写的测试与自证先在第二台跑过一趟才算写完；只在本机绿过的不算。」（`.claude/rules/verification.md:81`）。判据清楚，但「跑过一趟」与「绿」没分开：跑过但红算不算写完，条文没说。
- 例外：「只能在一台上跑的（装服务、改本机工作区、读本机私有库导入）不算测试」（`.claude/rules/verification.md:80`）与「测试一律不登那张表。」（80）。

处 4 的三个缺口，都是对着今天的实现核的：

1. 「写完」没人做得出。挑台由服务按余量均衡定（`task-server/task_server_lib.py:122`「按余量均衡」），调用方不写、不判（`.claude/agent-common.md:62`「哪台机器、哪几张卡、GPU 清场、排队次序、分片、卡住、撞上限放大重排都由服务定，调用方不写、不判」）。调用方能钉到第二台的只有 `PEER_ONLY_ENTRIES`（`task-server/task_server.py:216`，此刻登一个入口）。结局落在哪台只能事后从 `task wait` 末行看：「host=peer peer_tree=<路径>」（`.claude/agent-common.md:62`）。条文没写「以末行 host=peer 为准」，也没写落不到第二台怎么办。
2. 带判定库的门禁与崩溃几道今天只在本机：「崩溃判定库那几道（crash-point-replay、crash-amplification、checker-tier-crash-point-replay）不在这里，照旧只在本机」（`task-server/task_server.py:203`）。它们是 checker 档的主体测试，按处 4 的「写完」做不到；条文没给这类的处置。
3. 「测试一律不登那张表」与表的现状冲突：`LOCAL_ONLY_DIRECTORIES` 把 `scripts/hosts`、`.claude/hooks` 整个目录登在里面（`task-server/task_server.py:212`），行尾注释写的理由就是自证：「multi-host-run.sh 的自证派去第二台全红」（`task-server/task_server.py:212`）。这是测试，登在表里，与「一律不登」字面相反。条文还把表写成两张：「LOCAL_ONLY_DIRECTORIES、LOCAL_RESOURCE_ENTRIES」（`.claude/rules/verification.md:80`），实际还有 `LOCAL_ONLY_WRITERS`（`task-server/task_server.py:228`）与 `LOCAL_ONLY_CARGO_BINS`（`task-server/task_server.py:242`）。这条属于 K2 的边角，这里只记它让「什么算多机可用」的判据与今天对不上。

另有一处小冲突在同一节里：79 行禁读「本机家目录下的库」，72 行的库正是「本机那份崩溃判定 RocksDB」，只靠 79 行末「要存判定经 prune-server 写进那一份库」化解，而那一句只说存、没说读。第二台经 TCP 连服务（`scripts/prune-server/prune_server_client.py:32`「TCP：没有 socket 文件时走 TCP（第二台）」），读也走服务，但规则没写。

处 5（`agent-common.md:40`）：

- 判据：「不读本机独有的路径与状态、不写死主机名与地址，环境只从多机配置 `multi-host.env` 读」（`.claude/agent-common.md:40`）。没有例子，要读者自己去处 4 看。
- 写完：「新写的先在第二台跑过一趟（经 task-server 派）才算写完，报告里写明在哪台跑过」（`.claude/agent-common.md:40`）。读者是子 agent，而同一份文件规定「子 agent 不往服务交任务」（`.claude/agent-common.md:62`），挑台也不归调用方。所以这句话对它的读者是一条做不出的动作：子 agent 既不能派，也不能指定第二台。能做的只有把命令写进报告「要主 agent 跑的命令」一节。结论：这句做的不是「新测试什么时候算写完」的判据，是一句指令错了对象。

处 6（`main-agent.md:13`）：

- 判据：「审 diff 时见到测试、自证、门禁、装置读本机独有路径或状态、写死主机名与地址、只在本机才跑得起的，一律打回」（`.claude/main-agent.md:13`）。三类，比处 4 多一类结果型（「只在本机才跑得起的」），可判。
- 写完：「新写的测试没在第二台跑过一趟不算写完」（`.claude/main-agent.md:13`）。主体是主 agent，派第二台是它能做的（交服务），但落台不由它定（同上缺口 1）。
- 例外：「只能在一台上跑的活登进 task-server 只在本机的表，不当测试」（`.claude/main-agent.md:13`）。该处头部同时写着「核心策略，没有例外」，同一条里有例外子句，字面自相冲突。
