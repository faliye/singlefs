## 攻击面 1：失败表 ③ 与「实例结束」

第六版 P1 逐字：「**失败表（封闭）**：① 取号之前失败 ⇒ 无事；② 取号之后、**尚未向设备发出任何单元写请求**时失败 ⇒ 号作废……
③ 发出过任一单元写请求之后：单副本写失败 ⇒ 换落点重试、写序不变，预算 T_retry；
预算用尽或别的事务级失败 ⇒ **实例结束**——转只读、号更大的事务的记录一条都不追加，下次挂载走恢复并写行。
准入在取号前做完（`.claude/rules/fs-design.md`「进门前先算最坏情况」），所以 ③ 里不存在准入拒绝。」

### 1.1 表自称封闭，而它的三格全按「事务」划分；码 2 / 3 单元不由事务写出，固定点与发布阶段的失败落在表外（可达）

**若这张表封闭，那么写出一个单元的每一条路径都得落进某一格。** 第六版自己在同一页把码 2 / 3 排除在事务之外：
P1 逐字「码 2 / 3 只在 checkpoint 的固定点写出，一个版本合并了多个事务的效果」。
固定点不是任何一个事务，它没有事务号可作废，也没有「发没发出单元写请求」这个状态可判。

**可达历史**（实例 7，checkpoint 501，池接近满）：

1. 事务 812–841 分配进 checkpoint 501，各自写完自己那一个数据单元，记录按事务号顺序全部追加，W = 841。
2. 触发切分：成员资格关闭，进入固定点。
3. 固定点第一轮 COW 掉三十几个容器与它们的祖先，产生新的分配 ⇒ 记账树又要写节点 ⇒ 第二轮；
   E81（提交的固定点） 量的正是这个循环（散布分配把 12 单元的 fsync 放大到 5909 个元数据块）。
4. 第三轮收敛时分配失败。E82（准入的在飞合成） 实测的准入类失败形态逐字就是「分配中途才失败」，
   而第六版把准入挪到取号前只挡住了**事务**这一侧，固定点自己申请的那批块从来没有过准入。
5. 这一格既不是 ①（号早取了）、也不是 ②（单元写请求发出过一大批）、也不是 ③ 描述的「某个事务的失败」——
   失败的是发布阶段，它不属于任何事务。

两条出路各有一个坏结局：判成 ③ 那类「别的事务级失败」⇒ **盘接近满时每次固定点收敛不了就把整卷转只读**，
而 D25（目标负载优先级） 的负载与 C83（提交固定点没人回答） 记的读数都说这不是边角；
不判成 ③ ⇒ 表不封闭，第六版最核心的那句「③ 之后不追加更大的号，恢复行的 W 就是精确的前缀」失去封闭性依据。

**为什么便宜的第三条出路不存在，第六版没写**：直觉上该做的是「作废整个 checkpoint、重做」。
做不到，而理由恰恰在 P2 的谓词里：当前实例没有行，谓词逐字「i == i_now：b ≤ 挂载根的 txg」；
被作废的 checkpoint 号按 D5（快照 / 空间记账机制） 逐字「崩溃后该号会被重发」会被重发，
重发那次一发布，诞生代号等于该号的孤儿全部 ≤ 挂载根 txg ⇒ **判已发布 ⇒ 复活**。
⇒ **任何「作废一个 checkpoint 而不换实例代号」的路径都会复活孤儿**，所以第六版只剩「实例结束」这一条。
这是它这次改动的真实约束，比它写下的理由硬得多，而正文一个字都没有。

**判定：可达**（表不封闭；且封闭性的真实依据没写出来）。
**最小改法**：失败表加第四格「固定点 / 发布阶段失败」，处置写死为实例结束，
并把「当前实例的孤儿没有前缀维、所以作废一个 checkpoint 必须换实例代号」这句话写进 P2 的谓词旁边——
它是三格失败表能封闭的唯一理由。

### 1.2 「实例结束」是一次没记账的可用性收缩，而事务切分纪律把它的触发机会乘上单元数（可达，代价漏记）

**若「实例结束」只是一条兜底，它的触发频率就该是罕见量级。** 切分纪律把它抬成了每次大写请求都要过的闸。

P1 取号纪律 2 逐字：「一次写请求按单元切成若干事务各自取号 ⇒ 一个事务最多写一个单元的用户数据」。
一次 1 MiB 的写请求在 32 KiB 单元上切成 32 个事务，每个事务都各自发出过单元写请求 ⇒ **32 次落进 ③ 的机会**。
其中任何一个单元的写在 T_retry 墙钟内换落点也没成功，整卷转只读，另外 31 个已经落盘的单元连同它们的记录一起作废。

第五版在同一格的处置是写一条作废行、实例继续活着。第六版把它换成整卷只读，
**这是拿可用性换正确性**，而第四节那张代价表里只有 D23（journal 的角色与格式） 已定项 14 的「崩溃原子性的单位是一个单元」那一行——
那条记的是**丢多少**，不是**还能不能写**。两件事不同量级：前者丢一次写请求的尾巴，后者整个池停写到下次挂载。

现查落地正文，D23（journal 的角色与格式） 已定项 7 只写了「一个事务在发出单元写之后失败即实例结束、号更大的记录一条都不追加——这是实例表行的 W 能当精确前缀的依据」，
D13（验证路线） 已定项 2 的前置约束里也只把「已确定实例结束」当成一种等待状态；
**没有任何一条正文承认这是一次可用性语义的收缩**，也没有引 D25（目标负载优先级） 或 D2（RAID 条带策略） 已定项 9 的可用性口径去论证它可接受。

⚠️ 顺带：单副本写失败换落点重试时「写序不变」，于是失败那次可能留在盘上的残片与重试成功的那份
同 key、同诞生代号、同写序。码 1 靠 C104（扫描路径上码 1 / 2 的载荷完整性无自包含证据） 新加的载荷 CRC 筛得掉，
码 3 靠载荷校验和筛得掉，**码 2 那一半 C104（扫描路径上码 1 / 2 的载荷完整性无自包含证据） 还欠着**——
好在码 2 不进 P3 的择版本，所以只是欠账不是漏洞，写下来是免得下一轮当成关上了。

**判定：可达（代价漏记 + 一次没论证的可用性收缩）**。
**最小改法**：代价表加一行「③ 的兜底从作废行换成实例结束：单个单元写在 T_retry 内不成功即整卷转只读，
触发机会 = ⌈写请求字节数 / 单元大小⌉ 每请求」，并在 D16（发布语义） 已定项 5 送用户复核的那句话里
把 T_retry 的两个用途一起摆出来——它既是丢失窗口的加项，也是整卷停写的判据。

## 攻击面 2：实例表行的编码与写法（P2，第六版全新）

第六版 P2 逐字：「任何非干净结束的实例在下次恢复写行：给 [所选根的实例, 新实例) 每个实例写
**(i, 在飞 txg − 1, 重放施加的最大事务号)**，一条都没施加的写 (i, 在飞 txg − 1, 0)」；
落地的 D18（块里携带什么信息） 已定项 11 逐字同句。

### 2.1 「在飞 txg」在「所选根不是最新已发布根」那一格有两种读法，一种把整个被抛弃的 checkpoint 判成已发布（可达）

**若 (i, 在飞 txg − 1, W) 是一个良定义的行，那么「在飞 txg」在恢复那一刻必须只有一个值。** 它有两个：
崩溃实例当时开着的那个 checkpoint 号，与**所选根的 txg + 1**。
恢复恒选最新已发布根时两者相等，所以正文看不出差别；两者不等的那一格上它们给出相反的结论。

**可达历史**（实例 7）：

1. 实例 7 依次发布根 R500、R501、R502，随后在 checkpoint 503 上崩溃。
2. 挂载时 R502 的根槽自证不过。第一版的两路见证不独立——I-7.7（超级块实例代号不低于根环） 落地正文逐字
   「只在 devs ≥ R 时根环才是超级块之外的独立见证，第一版 (R = 3, devs = 2) 时两路见证的失败域是同一对盘」——
   R502 的几份拷贝落在同一对盘上，一次介质损坏就能一起带走。⇒ 所选根 = R501。
3. 实例 8 恢复，按 D23（journal 的角色与格式） 已定项 14 只施加 (实例代号, checkpoint_txg) 严格大于 R501 的记录，
   重发 checkpoint 502，写行。
4. 按读法 A（在飞 txg = 503）：行 = **(7, 502, W)**。实例 7 在 checkpoint 502 里写下的全部单元 b = 502 ≤ 502
   ⇒ **判已发布**，而它们正是被抛弃的那一段。
   按读法 B（在飞 txg = 所选根 txg + 1 = 502）：行 = (7, 501, W)，那批单元 b = 502 = T_pub + 1、
   n 与 W 比一比，只有被重放施加的那些算数 ⇒ 正确。
5. 读法 A 之下，实例 8 重发的 checkpoint 502 与实例 7 被抛弃的 checkpoint 502 诞生代号相同、都判已发布。
   同 key 两版时写序按实例代号分得开（实例 8 大）；**只在实例 7 的 502 里创建、实例 8 没有重建的那些 key
   只有一个候选** ⇒ v\* 选中它 ⇒ **复活**。这正是靶子第 (c) 类。

**E104（扫描重建的现行版本判定） 分不出两种读法**：现查 `research/e7-index-bench/src/bin/e104_current_version.rs`，
`crash_and_recover` 里逐字 `rows.push((crashed_inst, (self.txg - 1, w)))`，而模型永远选最新已发布根，
两种读法在模型里恒等。E104（扫描重建的现行版本判定） 正文「它答不了的」也没有「恢复选了非最新根」这一项。

**判定：可达（口径二义，触发条件是所选根不是最新已发布根）。**
**最小改法**：把两处正文（第六版 P2 与 D18（块里携带什么信息） 已定项 11）的「在飞 txg − 1」逐字换成
「所选根的 checkpoint_txg」，零字节代价；并给 E104（扫描重建的现行版本判定） 加一个「最新根不可选、恢复退一格」的世界，
读法 A 必须报非 0。

### 2.2 码 2 / 3 的写序是一个 per-checkpoint 常量，它的严格单调性没有论证；I-1.8 对码 3 的全序因此没有依据（可达）

第六版 P1 逐字：「码 2 / 3 只在 checkpoint 的固定点写出……写序 = (实例代号, 那次 checkpoint 里已分配的最大事务号)。
判定（P2）对码 2 / 3 只用实例代号与诞生代号，**事务号那 6 字节在码 2 / 3 上只保证 I-1.8（归并后版本全序） 的全序**。」
I-1.8（归并后版本全序） 落地逐字：「码 1 / 3 的可读已发布单元按『类身份段全部字段含写序』归并成组之后，**同 key 的各组两两写序不等**」。

**若那 6 字节保证得了全序，「那次 checkpoint 里已分配的最大事务号」就必须在一个实例内逐 checkpoint 严格增。**
它只是单调不减，而且有一格可构造地相等：

1. 实例 8 恢复，重发 checkpoint 501。它施加的全部事务都属于实例 7——D23（journal 的角色与格式） 已定项 7 逐字
   「事务号按实例计数、从 1 起」，实例 8 自己一个号都没分配 ⇒ checkpoint 501 里实例 8 已分配的最大事务号 = **0**
   ⇒ 501 的全部码 3 单元写序 = (8, 0)。
2. 实例 8 再发布一个不分配自己事务号的 checkpoint 502（纯后台的墓碑回收重写、退役记录重写这一类
   「后台、可续做、非决策路径」，`.claude/rules/fs-design.md` 明写它们无戒律，也就没人保证它们要取事务号）
   ⇒ 502 的码 3 单元写序还是 (8, 0)。
3. 同一个容器身份 (出生树, 2, 容器号, 出生代) 在 b = 501 与 b = 502 各有一版
   （身份在 COW 重写时不变，D8（核心索引结构） 已定项 6 逐字；变的是头里的诞生代号）。
   501 那一版释放后进 defer，在根环深度那么长的窗口里仍然可读。
4. 两版都判已发布（码 3 的谓词逐字 b ≤ T_pub），写序相等、载荷不同 ⇒ 按 I-1.8（归并后版本全序） 逐字
   「不同即判损坏、不择」⇒ **那个 inode 叶在扫描重建里整片判损坏**；
   若实现按 P3 的「取写序最大者」走，则是一次无判据的任选。

**更硬的一半**：第六版自己写着判定对码 2 / 3 只用实例代号与诞生代号。
那 6 字节在码 2 / 3 上唯一被声称的用途就是 I-1.8（归并后版本全序） 的全序，而它给不出全序；
**同一个 checkpoint 里写出的全部码 3 单元写序逐字节相同**，这个量根本不是单元的属性，是 checkpoint 的属性。
真正能给码 3 全序的是 (诞生代号, 实例代号)：同一 checkpoint 只有一个固定点 ⇒ 同 b 同实例不可能有两版，
崩溃重发那一格由实例代号分开——这两样谓词已经在用了。

**E104（扫描重建的现行版本判定） 对这一格零证据**，而且实验正文自己承认：「它答不了的」逐字写着
「**容器按事务写不按固定点写**（比实物多出中间版本，写序 n 取事务号；判定只用实例代号与诞生代号，多出来的版本不改结论）」。
那句「不改结论」是推理不是实测：模型里每个容器版本的写序两两不同，恰好把全序问题绕开了。
而第四节的代价表把 D18（块里携带什么信息） 已定项 11 标成「改第一个事务的字节：**是**」——
一条动字节的规则，模型里一格都没建。

**判定：可达（I-1.8（归并后版本全序） 的依据不成立；等号可构造）。**
**最小改法**：I-1.8（归并后版本全序） 对码 3 的全序键改写成 (诞生代号, 实例代号)；
D18（块里携带什么信息） 已定项 11 里那 6 字节在码 2 / 3 上明写「不参与任何判定，取该 checkpoint 已分配的最大事务号只为字段对齐」；
或者给它一个真的单调量（例如该实例的发布计数）。三条都不动字节数。

## 攻击面 3：行回收的根环合取（P2，第六版对第五轮 4.1 的处置）

第六版 P2 逐字：「**回收**：kind 0 行可删当且仅当整轮清扫确认盘上不再有该实例按行判未发布的**可读**单元
∧ 全部设备在线 ∧ **根环里没有该实例发布的根**」；I-3.8（实例表行唯一且低于挂载根） 落地同句。

### 3.1 根环那一条关上了第五轮 4.1，可是回收判据拿「可读」当输入，而可读性会变回来（可达）

**若「无行 ⇒ 已发布」在删行之后仍然安全，那么删行那一刻盘上就不能有任何一个「将来会变得可读」的未发布单元。**
判据只问「现在读不读得到」。

**可达历史**（实例 7 崩在 checkpoint 501，行 (7, 500, 815)）：

1. 实例 7 在 501 里写下的单元里，事务号 816–841 那批没被重放，是孤儿、按行判未发布。
2. 清扫按 P4 的孤儿支抹它们的头。P4 的准入合取逐字含「头可读」：
   落点 L 的两份副本分别在盘 A 与盘 B 上，盘 B 那份抹掉了，盘 A 那份这一次读返回介质错误。
   读不到 ⇒ 准入不过 ⇒ 不清，**而且不报错**（准入不过与「清完了」在这条规则里长得一样）。
3. 回收判据问「盘上不再有该实例按行判未发布的**可读**单元」——盘 A 那份此刻不可读 ⇒ 判据成立。
   「全部设备在线」也成立：盘 A 只是一个扇区坏，设备没离线。
4. 根环轮转把实例 7 发布的根全部挤出去 ⇒ 第六版新加的那条合取不再挡 ⇒ **删掉行 (7, 500, 815)**。
5. 那个扇区后来读成功了（介质错误是概率性的；D26（后台整理与放置回收） 的常驻整理重写一遍也能修好它）。
6. 索引丢失走扫描重建：那个单元 i = 7 < i_now、实例表无行 ⇒ 谓词逐字「无行 ⇒ 已发布」⇒ 判已发布
   ⇒ 它是那个 key 上写序最大的候选 ⇒ **复活**。

**还有一层**：删行之后 P4 的孤儿支要求「按 P2 谓词未发布」才清，而它现在恒判已发布
⇒ **既清不掉、又会复活**，I-1.9（清扫水位内无可读垃圾） 逐字「清扫水位以内不存在可读垃圾」由此在那一格为假。

第六版这次加的「全部设备在线」是设备维的同一道闸，说明作者已经想到「读不到不等于不存在」；
**缺的是扇区维那一半**——而扇区维恰恰是第一版就会遇到的常态。

**判定：可达。**
**最小改法**：回收的第一条合取改写成「整轮清扫对每一个落点都得出了判定（读成功、已抹头、或已被覆盖），
且其中没有该实例的未发布单元；这一轮里任何一次读失败都让它不构成回收依据」，
与「全部设备在线」并列——两条是同一件事的设备维与扇区维。

## 攻击面 4：P6 的重生保留容器号

第六版 P5 / P6 逐字：「**重生的新身份 = (本头树 ID, 类型 2, 原容器号, 本次发布代号)**——保留容器号，只换出生树与出生代」；
落地的 D8（核心索引结构） 已定项 6 逐字同句。

### 4.1 重生规则只覆盖类型 2；继承来的墓碑容器跨头 COW 之后同身份两版，而它对 origin 也可见（可达，本轮最重）

**若「跨头首次 COW 要重生」是一条按机制成立的纪律，它就该按「码 3 容器」成立，而不是按打包记录类型成立。**
第六版把它逐字钉死在类型 2 上。类型 1（墓碑容器）同样是码 3 容器、同样被两个头共享、同样要被两个头各自 COW。

**可达历史**：

1. 树 A 有一个开放的墓碑容器，身份 (A, 1, 7, 300)——类型 1 的容器号按 D18（块里携带什么信息） 已定项 11 逐字
   「按 C103（容器索引无落点） 那套单调分配」，与 inode 号无关。
2. 在 A 上建快照 S，从 S 克隆出头 B。克隆是这棵树的一份 COW 拷贝，容器索引照抄
   ⇒ B 引用同一个 (A, 1, 7, 300)。
3. B 里删掉一个对象 ⇒ 往开放的墓碑容器追加一条 kill 记录 ⇒ 跨头首次 COW。
   P6 只对类型 2 重生 ⇒ B 写出的新版本身份仍然是 **(A, 1, 7, 300)**，只是诞生代号更新、写序更大。
4. A 自己后来也删了别的对象，写出自己的那一版，身份同样是 (A, 1, 7, 300)。
5. 扫描重建根 A：可见性判据按祖先表比的是**写者树**，而**码 3 的头里只有出生树，没有写者树**
   ——第六版 P1 逐字「住类身份段」，E104（扫描重建的现行版本判定） 源码注释逐字
   「码 3 的头里只有出生树，没有写者树：模型不许给重建多于头里有的信息」。
   B 写的那一版出生树是 A ⇒ **对根 A 可见**。
6. 两版同身份、都判已发布，择新取写序最大者 ⇒ 谁后写谁赢。
   B 后写 ⇒ 根 A 读到 B 的 kill 记录 ⇒ A 里还活着的对象被判死（判死实活）；
   A 后写 ⇒ 根 B 丢掉自己的 kill 记录 ⇒ B 里已删的对象复活。

这与 E104（扫描重建的现行版本判定） 的单测 `rebirth_is_load_bearing` 钉住的失败逐格同形，只是发生在类型 1 上。

**E104（扫描重建的现行版本判定） 造不出来，而且靠的是一个没有正文依据的建模选择**：
现查 `clone_head`，克隆头逐字 `tomb_open: None, tomb_closed: Vec::new()`，并把墓碑容器号设成
`origin.next_tomb_no + 1_000`——克隆从不继承 origin 的墓碑容器，也就从不跨头 COW 它们。
那个 `+ 1_000` 是个魔数，仓里没有任何一条正文说克隆头的类型 1 容器号从哪里起。
E104（扫描重建的现行版本判定） 正文「它答不了的」也没有这一项。

**两条分支各欠一样**：

| 克隆继不继承 origin 的墓碑容器 | 欠什么 |
|---|---|
| 继承（把克隆当成树的拷贝，最自然的读法） | 上面那条历史直接可达 ⇒ P6 的重生必须覆盖类型 1 |
| 不继承 | 仓里要有一条正文写下来，并交代克隆头的类型 1 容器号从哪起；D8（核心索引结构） 已定项 6 那句唯一性论证（「每个容器号都是某条记录首次插入时的 inode 号，号在树内不复用」）**对类型 1 根本不适用**，而 C103（容器索引无落点） 至今无落点 |

**判定：可达（本轮最重）。**
**最小改法**：P6 的重生规则去掉「类型 2」这个限定——
「跨头首次 COW 的任何码 3 容器都重生：新身份 = (本头树 ID, **原打包记录类型**, 原容器号, 本次发布代号)，
同时给旧身份写退役记录」；给 E104（扫描重建的现行版本判定） 的克隆头继承 origin 的墓碑容器，
加一条「两个头各自往同一个继承来的墓碑容器追加 kill 记录」的世界，不重生时必须报判死实活。

## 攻击面 5：可写挂载互斥这条新前提（P2，第六版对第五轮 7.3 的处置）

第六版 P2 逐字：「**前提（写下来）**：同一时刻只有一个可写挂载，由**块设备独占打开**保证。
两个并发可写挂载会算出同一个 max + 1，谓词的三支分不出它们（第五轮反推腿 7.3）；
多主机共享存储不防，随 D9（加密） 已定项 8 那一类宣布。」

### 5.1 块设备独占打开是每设备的排它，池级排它要靠「任两个可写挂载至少共用一块盘」，而这一步在盘数 ≥ 4 时为假（可达）

**若独占打开能保证同一时刻只有一个可写挂载，那么任意两个可写挂载的设备集合就必须相交。**
可写判据逐字是「可写设备数 ≥ w 的下限」，第一版 w = 2；盘数 ≤ 3 时任意两个 2 元子集必相交，结论成立；
盘数 ≥ 4 之后互不相交的 2 元子集就存在了，而 D2（RAID 条带策略） 已定项 3 逐字
「设备集合变化之后走显式『几何再求值』事务，**不许强制重挂**」——加盘是在线操作，不重挂、也就不重新判这条前提。

**可达历史**（4 盘池，在线加盘两次之后）：

1. 挂载甲独占打开盘 1、2，可写设备数 2 ≥ w ⇒ 可写；取号 = max(它看得见的超级块代号 N, 它看得见的根记录实例代号 N) + 1 = N+1。
2. 挂载乙（同一台机器上的第二次挂载，或者另一个挂载命名空间）独占打开盘 3、4。
   独占打开对盘 1、2 没有任何意见——乙根本没碰它们 ⇒ 乙同样判可写，同样算出 **N+1**。
3. 两条时间线的单元写序都是 (N+1, ·)。谓词三支逐字（i < i_now 查行、i == i_now 比 txg、i > i_now 判损坏）一支都分不出。

第六版把第五轮 7.3 记成「采纳，持有位不采纳」。不采纳持有位的理由是对的
（崩溃之后持有位留在盘上会把合法挂载永远拒掉，第六轮本地腿 4 打中）；
**但「采纳」那一半只是把前提写下来了，写下来的那条前提证明不了它要证的东西**。

**判定：可达（前提与结论之间差一步，那一步在盘数 ≥ 4 时为假）。**
**最小改法**：前提改写成「任一可写挂载必须独占打开池中**过半**的设备」——任意两个过半集合必相交，
独占打开于是真的排它；把它写成可写挂载准入的一条合取，与「可写设备数 ≥ w 的下限」并列。
代价要显式选一边：4 盘池只剩 2 块可写时按这条规则只能只读挂载，与 D2（RAID 条带策略） 已定项 9
「2 盘掉一块只能只读」是同一取向，不是新口味。C120（分叉盘回归的判定与重同步） 的日程随之改成
「加第三块盘之前，且与过半规则同时到期」。

### 5.2 取号写超级块没有成功判据，一次部分落盘加一次掉盘就让代号被两条时间线共用（可达）

第六版 P2 逐字：「② 新代号 = max(全部可见超级块的代号, 根环里全部根记录的实例代号) + 1，**写进全部可见超级块**；
③ 之后才动任何单元。」写不进去算什么，正文一个字都没有；
I-7.7（超级块实例代号不低于根环） 逐字只要求「超级块的实例代号 ≥ 根环里任一根记录的实例代号」，
**不要求各盘的超级块代号相等**，所以部分落盘不违反任何一条不变量。

**可达历史**（3 盘池，在线加盘之后，w = 2）：

1. 可写挂载判可写通过，取号 N+1，向盘 A、B、C 的超级块各发一次写：A 成功，B、C 返回介质错误。
   没有任何一条正文说这时候要退回只读 ⇒ 挂载继续。
2. 实例 N+1 写了一批单元（写序 (N+1, ·)、诞生代号 = 在飞 checkpoint），在第一个根之前掉电。
3. 盘 A 随后离线。B、C 可写、2 ≥ w ⇒ 可写挂载。
4. 新代号 = max(B、C 的超级块代号 N, 根环里全部根记录的实例代号 N) + 1 = **N+1**：
   实例 N+1 一个根都没发布过，它的代号不在任何一条根记录里，max 规则看不见它。
5. 两条时间线共用代号 N+1。新那条一路发布，挂载根的 txg 越过旧那批孤儿的诞生代号 ⇒
   谓词逐字「i == i_now：b ≤ 挂载根的 txg」把它们判成**已发布** ⇒ 复活。

第五轮 7.1 打的是「取号顺序把掉盘 ⇒ 不取号破掉」，第六版靠「先判可写再取号」关上了那一半；
**这一格是剩下的另一半**：取号那一步自己会失败，而失败之后怎么办没写。

**判定：可达（取号缺一条成功判据）。**
**最小改法**：取号写成全或无——「新代号必须成功写进全部可见超级块，任何一份写不成即拒绝可写挂载」；
I-7.7（超级块实例代号不低于根环） 加强成「全部可见超级块的实例代号相等，且 ≥ 根环里任一根记录的实例代号」。
加强之后它顺带成了 5.1 那条互斥前提在盘上唯一可检出的痕迹。

## 攻击面 6：P4 的释放口径（第六版对第五轮 5.1 / 5.2 的处置）

第六版 P4 逐字：「一个落点被释放 = 分配器把它放进 defer 队列那一刻 = 没有任何根（含快照）引用它；
被快照引用的落点按 D5（快照 / 空间记账机制） 的 deadlist 纪律进 deadlist、不进 defer，快照销毁时才释放
⇒ 释放代 > 最后一个引用它的根被销毁的代。分配记录条目在释放时不删，改写成『已释放 + 释放代』。」

### 6.1 「条目改写与它对应的 COW 是不是同一次发布原子生效」没写，两个方向各有一个可达坏结局（可达，口径缺一句）

**若清扫的条目支（标已释放 ∧ 释放代 ≤ 环里最旧根的 checkpoint_txg ∧ 头可读）能当准入，
那么『条目已释放』这个状态就必须与『那次 COW 真的发布了』同生共死。** 正文没有这一句。
分配记录是派生态（D21（权威态与派生态的分界） 已定项 5），派生态可以有自己的写路径与批量节奏，
所以两个方向都不是无理取闹：

| 条目改写相对 COW 的持久时刻 | 坏结局 |
|---|---|
| **早**（条目先落盘，checkpoint 随后被崩溃抛弃） | 盘上留下「已释放 + 释放代 T」，而那个落点仍被所选根引用；根环轮转过 T 之后，条目支的三条合取全真 ⇒ **清扫抹掉一个活单元的头** |
| **晚**（COW 已发布、条目还没改） | 落点已经不被任何根引用而条目仍是「已分配」⇒ 条目支永远不清它，孤儿支也够不着（它有条目）⇒ **永久泄漏** |

**判定：可达（口径缺一句，两个方向各一个坏结局）。**
**最小改法**：P4 与 D3（空间分配） 已定项 7 各补一句——
「条目从『已分配』改写成『已释放 + 释放代 T』与产生这次释放的那次 COW 在同一次发布里原子生效；
T = 那次发布的 checkpoint_txg」。

### 6.2 D3 落地正文里那句「释放代补上了崩溃后 defer 内存态丢失那一格」按逐字为假（只是说法问题，但要改）

现查 D3（空间分配） 已定项 7 落地逐字：「释放代顺带把崩溃后 defer 队列内存态丢失那一格补上
（分配器重启后照释放代判能不能复用）」。这句第六版的提案正文里没有，是落地时新加的。

**若它成立，崩溃时正躺在 defer 里的那批落点在盘上就得留下它们的释放代。** 留不下：
按 6.1 的正确读法（条目改写与 COW 同一次发布），崩溃丢掉的恰恰是那个没发布的 checkpoint，
它里面的释放一条都没在盘上留下痕迹 ⇒ 条目仍是「已分配」，而那是对的（旧版本还被所选根引用）。
释放代补上的是**已发布的释放**，也就是本来就不会丢的那一半。

顺带一条要写下来的：defer 窗口是 I-7.4（近 K 代块未被复用） 里那个运行时的 K，崩溃后它清零，
接手的是「释放代 ≤ 环里最旧根 txg」这条闸；两者的宽度不一定相等（I-7.4（近 K 代块未被复用） 逐字
「K ≤ 根环深度……下限 ≥ 2」）⇒ **崩溃会改变 I-7.4（近 K 代块未被复用） 的实际保护宽度**，
而 I-7.4（近 K 代块未被复用） 的正文没写这件事。

**判定：只是说法问题，但那句话按逐字为假。**
**最小改法**：D3（空间分配） 已定项 7 那句改成「崩溃后 defer 队列的内存态丢失，接手的是『释放代 ≤ 环里最旧根 txg』这条闸；
未发布的释放本来就不该在盘上留痕，它们对应的旧版本仍被所选根引用」；
I-7.4（近 K 代块未被复用） 加一句「崩溃后 K 由根环深度接管」。

## 攻击面 7：实例表自身的判定与「表不可读」的射程

### 7.1 落地的 D21 正文把「表不可读」的射程写得比第六版窄一个数量级（落地文本与第六版不一致）

第六版 P2 逐字：「**表不可读时**：只读挂载；扫描重建停在级 1。」
落地的 D21（权威态与派生态的分界） 逐字：「实例表两副本都不可读时，扫描重建对该实例内
**『诞生代号等于重发后已发布代号』的单元**没有判据：重建停在级 1 并显式报告，不静默放行」。

**若射程真的只有那一类单元，表没了之后别的单元就该照样判得出。** 判不出：
表没了 ⇒ 一条行都没有 ⇒ 谓词逐字「i < i_now：无行 ⇒ 已发布」对**每一个**旧实例的**每一个**单元成立。
里面包括被回退抛弃的整段时间线——回退行 (r_old, T_old, 0) 与中间实例的 (i, 0, 0) 跟着表一起没了，
而那两种行正是第六版用来把被抛弃时间线判成未发布的唯一输入。

第五轮 1.3 打的是同一处，当时第五版说「只能记歧义」。第六版把机制改对了（只读挂载 + 停在级 1），
**而落地正文那句射程还是第五版的窄口径**。

**判定：落地文本与第六版不一致（机制换了，射程没换）。**
**最小改法**：D21（权威态与派生态的分界） 那句改成「实例表两副本都不可读时，全部旧实例的单元一律落进
『无行 ⇒ 已发布』，被回退抛弃的整段时间线也在内；所以挂载只读、重建停在级 1，而不是记歧义」。

### 7.2 实例表单元自己的已发布判定是一个自举循环，绕开它的那条理由没写下来（只是说法问题）

实例表单元是码 3 打包记录单元，I-1.2（块头写序已发布） 逐字对「任一单元」成立，
而判它要用的行就装在它自己里面。常规路径绕得开：根记录直接持有它的物理指针（D22（单元原子性怎么合成） 已定项 7），
读到的就是那一版，不需要择版本；扫描重建路径上 P2 明写停在级 1，也绕开了。
所以不是漏洞——但两条正文都没有把这句话写下来。
I-1.7（打包容器合法与判定顺序） 逐字已经给打包记录类型 4 开了一个例外（不套用「记录宽 == 登记表的宽」），
**却没给 I-1.2（块头写序已发布） 开对应的一条**，照字面读它要求实例表单元用自己去判自己。

**判定：只是说法问题。**
**最小改法**：I-1.2（块头写序已发布） 加一句例外——「打包记录类型 4 的实例表单元不走这条谓词：
它的现行版本由根记录持有的物理指针唯一确定；指针指不到或校验不过时按 P2 走只读挂载」。

## 攻击面 8：第五节的判决改靠态别（第六版第二次重写）

第六版第五节逐字：「**判决：取臂 A（写序上全部三类）。理由改成两条不依赖 p 的**：
**态别**：臂 B 把 extent 叶变成权威态（叶丢了那段数据的版本判定就没了），
D21（权威态与派生态的分界） 的『索引（树）是派生态、丢了只是慢』**要开例外**；臂 A 让全部索引仍是派生态……」

### 8.1 那个例外早就开了，而且就写在同一份正文里、同一天落的（可达，判决理由的原文为假）

现查 D21（权威态与派生态的分界） 落地正文逐字（2026-09-05 随 D8（核心索引结构） 已定项 6 补的那一段）：
「**态别按重算性判，不按『树』这个词判**……一棵树的内部节点可从它的叶重算 ⇒ 派生态；
**叶若装着算不回来的值（inode 树的叶是码 3 打包记录单元，D8（核心索引结构） 已定项 6）⇒ 权威态**。」

⇒ 「索引（树）是派生态」这条**已经**对 inode 树的叶开过例外。
判决把「要开例外」当成否掉臂 B 的唯一非概率理由，而例外在同一份正文里已经在了
⇒ 一句「要开例外」既拦不住臂 B，也说不清 inode 叶做成码 3 和 extent 叶做成码 3 差在哪。

**真正分得开两者的是 D21（权威态与派生态的分界） 自己那条判据（按重算性判）**：

| | inode 叶做成码 3 | extent 叶做成码 3（臂 B） |
|---|---|---|
| 叶里装的是什么 | inode 记录本身，它就是那份数据 | 「哪个 extent 在哪」——一份指向别处的映射 |
| 在臂 A 下算不算得回来 | **本来就算不回来**，做不做成码 3 都是权威态 | **算得回来**：数据单元自己的头带五元组 + 诞生代号 + 写序，扫一遍就重建得出 |
| 改成码 3 之后 | 态别没变 | 臂 B 同时把数据单元头里的写序拿掉 ⇒ 那份映射**变得算不回来** ⇒ 主动把一份可重算的东西降级成权威态 |

这句话不依赖 p，也不依赖 E105（extent 叶改码 3 的代价） 的任何一个数，
而且它正面回答了「同样是码 3，为什么这一个可以那一个不行」——第六版写的那句两样都做不到。

**判定：可达（判决理由的原文与落地正文冲突；结论不变，理由要重写）。**
**最小改法**：第五节第一条理由整句换成上表那条重算性论证，并点名 inode 叶那个已有例外，
说明两者的差别在「本来就算不回来」与「被改成算不回来」；
D21（权威态与派生态的分界） 落地那段末尾「判决靠态别，不靠那两个数」同步改写成同一句话。

## 攻击面 9：攻不动的两处（如实记）

### 9.1 串行提交下 W 的前缀性成立，但第六版把理由挂错了地方（没打中，只是归属问题）

任务问的那一格——「事务 N 在写单元时失败，N+1 的记录能不能已经在 journal 里」——第一版答案是不能：
D13（验证路线） 已定项 2 逐字「先串行提交」⇒ 记录追加顺序就是事务顺序，
N+1 的记录不可能先于 N 出现。P1 纪律 4 由此空转（第六版自己写了这句），W 是前缀恒成立。

单元写不受这条约束：P1 纪律 1 逐字「已分配的事务把各自的单元写完；发布阶段等全部单元落盘」
⇒ 同一 checkpoint 里 N+1 的单元完全可以先于 N 的单元落盘。这不破 W 的前缀性——
W 是**记录**的水位不是**单元**的水位。**这一格攻不动，如实记。**

由此得到一条归属上的话：**W 是精确前缀，第一版靠的是串行提交，不是靠 ③**；
③ 买的是「并行提交打开之后 W 仍是前缀」。第六版把两件事写在同一句里
（「③ 之后不追加更大的号，恢复行的 W 就是精确的前缀」），
于是一条只在将来才承重的纪律，今天就付了整卷转只读的代价（攻击 1.2）。
写清归属之后，「T_retry 用尽是不是非得实例结束」在第一版就成了一个可以单独重开的问题。

### 9.2 回退行 (T_old, 0) 的射程（没打中）

任务问的另一半——「r_old 在 T_old 那个 checkpoint 里施加、诞生代号 = T_old 的数据单元按 b ≤ T_pub 判已发布，
它们都在 R_old 里吗」——我构造不出反例：
同一 checkpoint 里被两次覆写的同 key 两版都判已发布，择新取写序最大者，赢的那一版就是 R_old 引用的那一版；
同 checkpoint 里被删掉的由墓碑加死亡写序压住；
诞生代号 = T_old 的码 3 版本只有固定点写出的那一份，正是 R_old 引用的那一份。
回退行的 W 恒 0 让码 1 那半句 `b = T_pub + 1 ∧ n ≤ W` 恒假，方向是保守的。**这一半攻不动。**
