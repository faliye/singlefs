#### 已定项 5：`T_time` 与 `T_dirty` 取多少，丢失窗口的口径

**定案**：`T_time` 默认值 5 s，取可行区间 [200 ms, 5 s] 的上端——默认丢失窗口是 5 秒，取更小只减少摊销、不多买任何东西，拦住丢失的是那 5 秒本身。**`T_time` 用户可设，不限制**：挂载时传的值覆盖盘上的字段并回写；超出 [200 ms, 5 s] 不拒绝，只给警告（用户 2026-09-20）。`T_dirty` = 2 GiB（初值，写代码时再调）；它不由丢失窗口定——`∨` 规则下时间那一支已经保证了窗口，`T_dirty` 管的是**量**，它就是脏页内存预算本身。**`T_dirty` 是可调值，不是格式常量**：系统配置里那个字段是格式，字段里放什么数不是。**挂载时还要再夹一次**：有效 `T_dirty` = min(系统配置里那个字段, 环长 ÷ F)；环长是 mkfs 参数（默认 768 MiB、约束环 ≤ 设备容量 ÷ 4），所以「环装不装得下 `F ×` 最坏占用」不由一条 mkfs 时的下界保证，改成挂载时把脏字节预算压下去；默认环下有效值 = min(2 GiB, 256 MiB) = **256 MiB**，系统配置里 `T_dirty` 仍写 2 GiB、字段不动。

**丢失窗口的口径**：取号 = 事务被分配进某个 checkpoint 那一刻，checkpoint 的切分只关闭成员资格——触发之后不再分配事务进它，已分配的事务把各自的单元写完，发布阶段等全部单元落盘（任何 COW checkpoint 都要等最慢的那次 I/O，ZFS 的 txg sync 同样等最慢的 vdev，未在本项目验证）。事务切分纪律是一事务一单元。落到取号上，事务切分纪律把一次写请求按单元切成若干事务各自取号，一个事务最多写一个单元的用户数据，**同一次请求切出的若干事务按其单元的 key 升序取号**（提交路径要记「同一请求内取号序与 key 序不一致的次数」、非 0 判红）。单元写的重试预算是墙钟 T_retry（具名可调参数，不是格式常量；用尽即按失败的性质走实例切换或转只读，D23（journal 的角色与格式） 已定项 14——它同时是丢失窗口的加项、挂载内实例切换的判据、以及连续切换计数的时间基准）。**由此崩溃最多丢的是 T_time + N_switch × (T_retry + T_redo)，不是恰好 5 秒**——一次挂载允许 N_switch 次实例切换，每次都要熬完 T_retry 再把在飞 checkpoint 重做一遍（T_redo），而重做期间开放的那个 checkpoint 发布不了、只能一直攒。这里的 `T_time` 是本次挂载生效的那个值，不是 5 秒这个常数；`T_time` 可调之后，2026-08 用户定案的「崩溃最多丢 5 秒的写」降级成**默认值下的承诺**，不是全局承诺。**「上次 checkpoint 的时刻」在重发时取重发那一刻**（取原来那一刻的话，切换期间触发条件一直成立而在飞深度只有两个，触发只能空转）；在飞 checkpoint 深度 = 开放 + 发布中两个；并发 fsync 的返回时刻被同 checkpoint 的其他事务拖住是组提交固有的代价。这是已定项 14 那条「快照发布点钉在这个 checkpoint 全部数据变更之后」的可执行形态。

**射程**：定的是两个阈值取什么数与崩溃最多丢多少，不定环几何本身、也不定重做期间开放的那个 checkpoint 会不会堵住写者（D28（挂载期承诺量） 已定项 3 点名的那一格口径空白，D16（发布语义） 没写）。七样已知边角：

#### 已定项 7：发布的持久顺序

**定案**：一次发布的持久顺序恒为 COW 单元 / 节点 → 屏障 → journal 记录 → 屏障 → 根槽（FUA）→ 系统配置槽；fsync 等根槽持久之后才返回。恢复重放在施加任何记录之前，必须逐项验证点名单元的校验和。**系统配置槽在根槽持久之后再更新，每个 checkpoint 一次**，它是发布序列的最后一步、进层 0 枚举，一次发布的段序列因此唯一。**fsync 返回条件多一句**：新实例在本实例写成的根覆盖两块盘之前，fsync 不返回、不向管理员确认回退（做法与次数在已定项 8）。

**射程**：定的是一次发布内部这几步的先后与 fsync 什么时候返回，不定屏障的真机代价、也不定根槽本身的冗余形态（D22（单元原子性怎么合成） 已定项 2）。三样已知边角：

- **「fsync 等根槽持久之后才返回」的射程**：返回之后这一代只由那一个根槽罩着（根槽不镜像）。同一实例里退一代，靠 journal 重放追得上；**每个新实例（每次可写挂载、恢复、切换、回退）的第一个根在下一次发布之前是单点**——那个槽读不出或它所在的盘掉了，恢复退到上一个实例的根，重放按严格前缀停在实例边界（D23（journal 的角色与格式） 已定项 14 的注 1），这次挂载里 fsync 已返回的事务丢，一个故障就够。要不要让新实例先把根写到两块盘上再确认，是已定项 8。
- **屏障口径**：两道 FLUSH + 根槽 FUA = 每次发布三个序点，比 D25（目标负载优先级） 推导的两个多一个——那是第二道屏障的价钱，知情接受。
- **第二道屏障买的是记录流完整性**，不是数据完整性：数据完整性的必要屏障恰一道（根槽之前）；不上第二道有 7 类「根在案而记录缺席」的状态，记录核对器与反向链的输入有洞。用户定案「需要」，两道都上。

**依据**：

- E77（发布的持久顺序）：崩溃子集穷举——不上根槽之前那道屏障，1024 个崩溃状态里 504 个违例；拿掉「重放施加前验证点名单元」这一步，b_rs 臂 63 处静默嫁接，所以它是承重步骤。

- **恢复算法**：在「jsn 严格连续 + 校验和 + 反向链」之后**再加一步**——**丢掉提交标记还没出现的那个事务的全部记录**。⚠️ **它不能靠反向链代劳**：被丢的尾巴在链上是**连续**的（它们本来就是顺序写的），链检查一条都拦不住。**两条闸管的是两件事**：链管「是不是同一条时间线」，提交标记管「这个事务写完了没有」。
- ⚠️ **丢尾巴是常态不是边角**：前缀落在事务中间的是绝大多数崩溃点 ⇒ 恢复路径里那一步会被绝大多数崩溃点走到，它必须和主路径一样被崩溃点重放覆盖，不许当异常分支。

**射程**：管事务与记录的对应；记录与时间线的对应是已定项 8，两条不是同一条——已定项 7 取任一答案，时间线那一格照样漏。⚠️ 它不是 D13（验证路线） 已定项 2（串行 / 并行）的推论——串行下同样会切开。I-8.2（记录头不跨原子单元） 只约束**记录头**，没有任何规则禁止一条大记录；一个事务写几个单元的用户数据归 D16（发布语义） 已定项 5 末段的切分纪律，它与记录数口径的冲突归 C310（事务切分纪律与记录数口径打架）。「一事务一条」那一侧还有两条没建模的代价：环回绕要连续空间、整条记录要先在内存里缓冲齐才能开始写。

#### 已定项 3：key 布局 —— 改名与索引分开处理

**定案**：**key = `(locality_id, inode, offset)`**，`locality_id` 在创建时从父目录继承，**改名时故意不更新**。

- 命名走 dirent 树（`parent, name` → inode），改名就是删一条加一条，**O(1)**
- 数据按 inode 编 key，与名字彻底解耦
- scan 局部性来自继承的 `locality_id`，改名后**局部性缓慢退化，正确性不受影响**
- 退化由 D3（空间分配） 已承诺的常驻后台整理修复，不是新增负担

**批量改名**：`mv 大目录 别处` 在这个设计下**只改一条 dirent**。三处会把它重新变成无界操作，必须一开始就堵死：

1. **`locality_id` 永远不许被改名更新。** 它是**提示，不是正确性的一部分**——可以是错的、可以过期。
2. **改名覆盖已存在的目标 = 一次删除**，必须走已定项 5（whiteout 删除）的 intent log。
3. **后台重新聚簇必须是增量、可中断、可续做的**，且随时可以停掉不做。

**推论（可当 review 判据用）**：**任何让 rename 触及后代的设计改动，一律否决。**

**inode 记录必须存一份 `locality_id`**：它既是数据 key 的首段、又永不随改名更新，而命名树的 value 只有 inode、数据单元头的五元组里也没有它，所以盘上只有 key 自己带着它——读者打开一个改过名的文件时必须有地方拿到它，否则改名之后数据只能靠扫描才找得到。落点是已定项 6（inode 记录的盘上字段表）；这个值按本项从父目录继承，而第一版没有目录，所以「没有父目录时取什么」也要一起定——第一版取 0，登记在已定项 6 的记录字段表。扫描重建时重编出来的 key 首段按 inode 记录 > 幸存 extent key > 0 给这个对象的全部 key 编同一个首段（2026-09-16 用户定案，D18（块里携带什么信息） 已定项 3 那条加字段的提议不收）。

## 五、臂、阳性对照、真实基线

### 五·一、四条臂（逐字写死；每条分「怎么做」与「做完会怎样」两格，后者必须能从前者推出来）

**岔路单第 1 行（C490，extent 叶 key 的 offset 段取什么单位）**

| 臂 | 怎么做 | 做完会怎样（从左边一格推得出） |
|---|---|---|
| **1甲　文件字节偏移** | 写第 `n` 个单元的 extent 叶记录时，key 第三段那 8 字节写 `n × C`（`C` = 写它那天的净荷容量）。读文件字节偏移 `f` 那一页时，在树里找「最后一个 key ≤ `(locality_id, inode, f)`」的那条记录 | 同一文件的 key 序列是 `0, C, 2C, …`；从 key 判「这是第几个单元」要除一次 `C`；查找输入就是请求里那个字节偏移，读者不先做除法 |
| **1乙　单元序号** | 写第 `n` 个单元的 extent 叶记录时，key 第三段写 `n` 本身。读文件字节偏移 `f` 那一页时，读者先算 `n = f / C`，再在树里找 key = `(locality_id, inode, n)` | 同一文件的 key 序列是 `0, 1, 2, …`；从 key 还原「这个单元占文件哪一段字节」要乘一次 `C`；查找输入是读者自己算出来的单元序号 |

⚠️ **对面那条臂写成支持它的人认的样子**：1乙 不写成「读者每次都要额外做一次除法」那种稻草人形态——除法在 1甲 下同样要做（判位次时），两条臂只是把它挪到了不同的一侧，上表两行逐字对称。1甲 也不写成「key 会随容量变化而腐化」——那是量 1.3 要量的东西，不是臂的定义。

**岔路单第 2 行（C491，N 条记录时共享的提交内生块在哪一条点名）**

| 臂 | 怎么做 | 做完会怎样（从左边一格推得出） |
|---|---|---|
| **2甲　每条记录各点名一遍** | 一次发布切成 N 条记录（切分纪律，N 个单元 = N 个事务 = N 条记录）。第 `i` 条记录的点名项数组 = 它自己那个数据单元 + 这次发布全部 `K` 个共享提交内生块，共 `1 + K` 项；`1 + K` 超过一条记录的点名项容量时，这个事务按 `⌈(1+K) / 容量⌉` 条续写 | 任一条记录单独拿出来，它点名的单元集合自洽（数据单元 + 它要挂进去的那几个元数据单元）；同一个共享内生块在这次发布的记录流里出现 N 次 |
| **2乙　只在最后一条点名** | 第 1..N−1 条记录的点名项数组只有它自己那个数据单元，共 1 项；第 N 条记录的点名项 = 它自己那个数据单元 + 全部 `K` 个共享提交内生块，共 `1 + K` 项，超过容量时第 N 条按 `⌈(1+K) / 容量⌉` 条续写 | 每个共享内生块在这次发布的记录流里只出现一次；前 N−1 条记录每条只点名 1 项 |

⚠️ 两条臂**共用**的前提（不是任一条臂的定义，写在这里免得被当成某一臂的特权）：记录条数按切分纪律走（C310 2026-09-16 用户定案）；点名项 56 字节、记录 4 KiB 定长（D23 已定项 12 / 17）；持久顺序是「COW 单元/节点 → 屏障 → journal 记录 → 屏障 → 根槽 → 系统配置槽」（D16 已定项 7）⇒ 崩在第 `k` 条记录之后时，**这次发布的全部 N + K 个单元都已落盘**，落的是记录流的前缀。

## 六、报哪些量与各自的判据

**写门槛之前，先把四条臂的定义并排放一遍**（第五·一节那两张表原样适用，这里不再抄一遍字，只点名：1甲 `key = n × C` / 1乙 `key = n`；2甲 每条记录 `1 + K` 项 / 2乙 前 N−1 条 1 项、第 N 条 `1 + K` 项）。下面每一格门槛后面都跟一句「为什么它不是臂定义的同义反复」；跟不出那句的量，一律标成「不设门槛、只报数」。

**每个量各占一行、各报各的判定。不许把两个量合成一个 `true` / `false`**，合取留给主 agent 做。

### 六·一、岔路单第 1 行（C490）的量

**量 1.1a　冷走定位一页的节点读取次数**
- **怎么算**：给定 `(N, 页号 p)`。先算这一页覆盖的单元序号 `n₁ = ⌊4096p / C⌋`、`n₂ = ⌊(4096p + 4095) / C⌋`；再按该臂的查找方式从 extent 树根走到要用的那条（或那两条）叶记录，数**经过的码 2 节点个数**（根计 1）。`n₁ ≠ n₂` 时第二条记录落在同一叶计 0、落在相邻叶计 +1。分母：一次读，不折算成时间。
- **门槛**：任一取样点上 `|1甲 − 1乙| ≥ 1`。
- **为什么不是同义反复**：两条臂的 key 宽 24、记录宽 112、节点头 163、比较序全都相同，差 0 与差 ≥ 1 都可能；臂的定义里没有一句直接给出这个差。
- **判定**：差 ≥ 1 且 1甲 更少 ⇒ 岔路单第 1 行 ① 指向 1甲；差 ≥ 1 且 1乙 更少 ⇒ 指向 1乙；全部取样点差 = 0 ⇒ ① 判「这一格分不开」，第 1 行改由 ②③ 判。
- **对应岔路单**：第 1 行 ①。**够判点**：第八节 `N` 的十四个取样点 × 第八·一节那个页集合跑完，① 就能判。

**量 1.1b　挂载态定位一页的节点读取次数**
- **怎么算**：同 1.1a，但根与全部内部节点已在挂载态里（`mounted_read.rs` 今天的形态）⇒ 只数**叶节点**那几次读。
- **门槛**：任一取样点上 `|1甲 − 1乙| ≥ 1`。
- **为什么不是同义反复**：同 1.1a；另外这一格与 1.1a 可能给出不同答案（冷走差 0 而挂载态差 1，或反过来），所以它不是 1.1a 的复述。
- **判定**：同 1.1a，单列一行判定，不与 1.1a 合取。
- **对应岔路单**：第 1 行 ①。**够判点**：同 1.1a。

**量 1.2a　叶片数**｜**量 1.2b　树高**｜**量 1.2c　节点总数**（三个量，三行判定）
- **怎么算**：叶片数 = `⌈N / 叶容量⌉`（叶容量 = ⌊(NODE_BYTES − 163) / 112⌋）；上层按内部扇出 `⌊(NODE_BYTES − 163) / 内部条目宽⌋` 逐层收到 1 个节点为止，树高 = 层数（根兼叶时 1）；节点总数 = 各层节点数之和。
- **门槛**：各自在任一取样点上 `|甲 − 乙| ≥ 1`。
- **为什么不是同义反复**：两条臂只改 key 的**取值**，不改 key 宽与记录宽 ⇒ 差是不是 0 要算了才知道；臂的定义没说树的形状。
- **判定**：三格分别判；任一格差 ≥ 1 ⇒ 第 1 行 ② 判「分得开」并指向节点少的那条臂；三格全为 0 ⇒ ② 判「分不开」。
- **对应岔路单**：第 1 行 ②。**够判点**：取样表跑完 + 第七节 B1 的绝对值锚对上，② 就能判。

**量 1.3a　换一档净荷容量之后，「单元序号」还原正确的 key 条数**
- **怎么算**：key 写在容量 `C₀` 下、读在 `C₁` 下。逐条 key 算读者得出的单元序号（1甲：`⌊key / C₁⌋`；1乙：`key` 本身），与写它时的 `n` 比较，数相等的条数。分母 `N`。
- **门槛**：**不设门槛**（下一行说明为什么降级）。降级前写的是「`Δ = C₁ − C₀ ≠ 0` 的取样点上 `|1甲条数 − 1乙条数| ≥ 1`」，原样留在这里备查，不许拿它出判定。
- **为什么不是同义反复**：条数是 `(N, C₀, C₁)` 的算术函数，取值可能是 0、1、`N` 或介于之间；臂的定义只说 key 写什么，没说换一档容量之后还剩几条认得出。
- **判定**：⚠️ **这一格降级成对拍量，不当判据**——写登记时它已经被算出来了（第四节那一行：`C₀ = 32634` / `C₁ = 32635` 下 1甲 恒 1、1乙 恒 `N`）。装置必须复现这组数，复现不出就是装置错（第十节 F1）；第 1 行 ③ 的判定由量 1.3b 与 1.3c 给。⚠️ `Δ = 0` 那一档两臂必然都等于 `N`（第五类：两个口径在基线上恰好同值）⇒ **那一档只当对照 P2a，不当判据**。
- **对应岔路单**：第 1 行 ③。**够判点**：第八节四组 `(C₀, C₁)` 全跑完，③ 的这一读法就能判。

**量 1.3b　换一档净荷容量之后，「字节区间」还原正确的 key 条数**
- **怎么算**：读者得出的区间 = `[start, start + C₁)`（1甲：`start = key`；1乙：`start = key × C₁`），与写它时的 `[n × C₀, n × C₀ + 这一单元的声明长度)` 比较，**起点与终点都相等**才计一条。分母 `N`。
- **门槛**：`Δ ≠ 0` 的取样点上 `|1甲条数 − 1乙条数| ≥ 1`。
- **为什么不是同义反复**：同 1.3a；而且它与 1.3a 是**同一个岔路格的两个口径**，两者在 `Δ = 0` 上同值、在 `Δ ≠ 0` 上可能方向相反 ⇒ 必须各占一行（`.claude/rules/mutation-sampling.md` 第五类）。
- **判定**：单列判定，不与 1.3a 合取。
- **对应岔路单**：第 1 行 ③。**够判点**：同 1.3a。

**量 1.3c　按 D9 已定项 6 的现算式算 AAD 锚点偏移、与单元头那 8 字节相等的 key 条数**
- **怎么算**：读者按第二节抄的那一行现算 `key.offset − ptr.extent_off`（这一版一个单元一个 extent ⇒ `ptr.extent_off = 0`），与单元头偏移 67 那 8 字节里写的值（写它那天的 `n × C₀`）比较，数相等的条数。`Δ = 0` 与 `Δ ≠ 0` 两档各报一次。分母 `N`。
- **门槛**：`|1甲条数 − 1乙条数| ≥ 1`。
- **为什么不是同义反复**：门槛落在**条数**上，不落在「式子对不对得上」上；条数是 `(N, C₀, C₁)` 的函数。⚠️ 这一格最容易被写成倾向（那行定义看着偏向某一条臂）⇒ 判定只准引条数，不准引「式子天然是字节口径」这类话。
- **判定**：差 ≥ 1 ⇒ 第 1 行 ③ 指向条数大的那条臂；差 = 0 ⇒ 不给方向。
- **对应岔路单**：第 1 行 ③。**够判点**：两档 `Δ` 各跑完即可。

**量 1.4（附带，够判后不跑）　8 字节 offset 段能表达的最大文件字节数**
- **怎么算**：1甲 `2⁶⁴ − 1` 字节；1乙 `(2⁶⁴ − 1) × C` 字节。
- **不设门槛、只报数**：它能从臂的定义直接推出来 ⇒ 不当判据、不参与任何判定。对应第 1 行 ③ 的边角。

### 六·二、岔路单第 2 行（C491）的量

**量 2.1　这次发布写进 journal 的字节数**
- **怎么算**：`4096 × 量 2.2 的记录条数`（记录 4 KiB 定长，D23 已定项 12）。分母：一次发布。
- **门槛**：任一取样点上 `|2甲 − 2乙| ≥ 4096`（= 至少差一条记录）。
- **为什么不是同义反复**：差是不是 0，取决于 `1 + K(N)` 有没有超过一条记录的点名项容量，而 `K(N)` 由 extent 树几何算出来（这次发布重写几个节点）、臂的定义里一个字没说。
- **判定**：差 ≥ 4096 ⇒ 岔路单第 2 行 ① 判「分得开」，指向字节少的那条臂；全部取样点差 = 0 ⇒ ① 判「这一格分不开」，第 2 行改由 ②③ 判。
- **对应岔路单**：第 2 行 ①。**够判点**：第八节 `(N, K)` 取样表跑完（含 `1 + K > 容量` 那一档），① 就能判。

**量 2.2　这次发布的记录条数（含点名项装不下时多开的）**
- **怎么算**：2甲 `N × ⌈(1 + K) / 容量⌉`；2乙 `(N − 1) + ⌈(1 + K) / 容量⌉`。两条都按第五·一节的臂定义直接展开，不另引条款。
- **门槛**：任一取样点上 `|2甲 − 2乙| ≥ 1`。
- **为什么不是同义反复**：`⌈(1 + K)/容量⌉` 在 `1 + K ≤ 容量` 时恒为 1、两臂同为 `N` 条 ⇒ 差是不是 0 取决于 `K(N)` 这个几何量，不由臂定义给出。
- **判定**：差 ≥ 1 ⇒ 第 2 行 ② 判「分得开」，指向条数少的那条臂；差 = 0 ⇒ ② 判「分不开」。
- **对应岔路单**：第 2 行 ②。**够判点**：同 2.1。

**量 2.2b　这次发布的点名项总数（跨全部记录求和）**
- **怎么算**：2甲 `N × (1 + K)`；2乙 `N + K`。
- **不设门槛、只报数**：它能从臂的定义直接推出来。它是 2.1 / 2.2 的**输入与对拍量**（拿它反算记录条数，两条路对不上就是装置错），不参与任何判定。
- **对应岔路单**：第 2 行 ①（分子）。

**量 2.3a　崩在第 `k` 条记录之后，已落盘的**码 1 数据单元**里没有任何记录点名的条数（轨迹）**
- **怎么算**：按 D16 已定项 7 的持久顺序，崩在第 `k` 条记录之后时这次发布的 `N + K` 个单元**全部已落盘**、记录只落了前 `k` 条。逐个码 1 数据单元判「它的身份出不出现在前 `k` 条记录的点名项里」，数不出现的条数。**对每个 `k = 0..N` 各报一个数**，另报三样：峰值、为正的 `k` 的个数、期末值（`k = N`）。分母：这次发布的 `N` 个数据单元。
- **门槛**：任一 `k` 上 `|2甲 − 2乙| ≥ 1`。
- **为什么不是同义反复**：两条臂对**数据单元**的点名规则是同一句（「第 `i` 条记录点名它自己那个数据单元」）⇒ 差很可能恒 0，但那是量出来的、不是定义给的：`1 + K > 容量` 那一档下 2甲 的续写记录会改变「第 `k` 条」对应哪个数据单元，差可能不为 0。
- **判定**：任一 `k` 差 ≥ 1 ⇒ 第 2 行 ③（这一读法）判「分得开」，指向峰值小的那条臂；全部 `k` 差 = 0 ⇒ 判「这一读法分不开」。
- **对应岔路单**：第 2 行 ③（读法一：只数码 1）。**够判点**：`N` 取样表里至少两个点（一个 `1 + K ≤ 容量`、一个 `1 + K > 容量`）各跑完整条轨迹。

**量 2.3b　崩在第 `k` 条记录之后，已落盘的**全部单元**（码 1 + 共享提交内生块）里没有任何记录点名的条数（轨迹）**
- **怎么算**：同 2.3a，但分母是这次发布已落的 `N + K` 个单元，共享内生块也逐个判。**对每个 `k = 0..N` 各报一个数**，另报峰值、为正的 `k` 的个数、期末值。
- **门槛**：任一 `k` 上 `|2甲 − 2乙| ≥ 1`。
- **为什么不是同义反复**：门槛落在「条数」与「哪个 `k` 上开始归零」上；臂的定义说的是「共享块在哪条记录里点名」，没说任一 `k` 上未点名的**单元条数**是多少——那要把 `K(N)` 这个几何量算出来才有数。
- **判定**：任一 `k` 差 ≥ 1 ⇒ 第 2 行 ③（这一读法）判「分得开」，指向峰值小的那条臂；全部 `k` 差 = 0 ⇒ 判「这一读法分不开」。**单列判定，不与 2.3a 合取。**
- **对应岔路单**：第 2 行 ③（读法二：全部已落单元）。**够判点**：同 2.3a。
- ⚠️ **第五类提醒**：2.3a 与 2.3b 在 `k = N` 处必然同值（那时两条臂都点名完）；只报期末值就会把两个口径看成同一个量。⇒ 两个量都必须报整条轨迹（第八节）。

**量 2.4（附带，够判后不跑）　被不止一条记录点名的单元数**
- **怎么算**：2甲 `K × (记录条数 − 这个发布里点名它的记录数为 1 的那些)`；2乙 `0`。
- **不设门槛、只报数**：能从臂定义直接推出来 ⇒ 不当判据。对应第 2 行 ① 的边角（它是 journal 字节数为什么会差的解释量）。

## 八、轨迹与几何敏感性

### 八·一、被谓词消费的量要报轨迹

岔路单第 2 行 ③ 逐字要「对每个 `k` 报轨迹，不只报 `k = N`」。⇒ 量 **2.3a** 与 **2.3b** 各报四样，缺一样这一格不算跑过：

1. **整条轨迹**：`k = 0, 1, …, N` 每个 `k` 一行（`N` 大的取样点上按 `k ∈ {0, 1, 2, ⌊N/2⌋, N−2, N−1, N}` 抽，抽法写进产物，不许只留端点）；
2. **峰值**（整条轨迹的最大值）与它出现在哪个 `k`；
3. **为正的 `k` 的个数**（不是「为正的轮数」那个词的比例形态，就是个数）；
4. **期末值**（`k = N`）。

⚠️ 正文里出现「从来」「恒」「一直」这类说轨迹的词时，产物里必须有上面第 1 样；只有期末值就不许写这些词（`test-discipline.md`「端点不是轨迹」）。

量 1.1a / 1.1b 也报轨迹形态：**对页号 `p` 的集合逐个报**，不只报第 0 页。页集合 = `{0, 7（跨单元那一页，B6）, 覆盖第 143→144 个单元边界的那一页, 覆盖最后一个单元的那一页}`。
