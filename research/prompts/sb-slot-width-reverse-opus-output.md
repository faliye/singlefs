> **真设备把这条张力收窄了（E34（根环槽几何），2026-09-02，真 md/raid5，10 轮判决一致）**：

> ⇒ **暴露面 ≠ 损失面，算术那一半的 16 是上界。**

⇒ **在乙唯一赢的那台设备上，硬要求 1 要防的那个损害被真设备实测为零**（邻槽 10/10 完好，带阳性 + 阴性对照）。

**而机制仍然活着的那类设备，E126 的设备集里一台都没有。** 现查 `research/e7-index-bench/src/bin/e126_superblock_slot_width.rs` 第 145–150 行逐字：

```rust

    let devices: [(&str, u64, u64); 3] = [
```

而 D2 自己的表定义了第四类设备，`.claude/kb/decisions/02-RAID条带策略.md` 第 16–19 行逐字：

> | `io_min` | `lim->io_min = phys_bs`，`phys_bs = bs * (1 + npwg)`（NPWG = Namespace Preferred Write Granularity） | **不诱发设备 RMW 的最小写宽度** |
> | `physical_block_size` | `lim->physical_block_size = min(phys_bs, atomic_bs)`（`atomic_bs` 由 NAWUPF 定，未声明则等于逻辑块） | **设备承诺的掉电原子宽度** |

⇒ 任何 `atomic_bs < phys_bs` 的裸 NVMe（例如 `bs=512`、`npwg=7`、未声明 NAWUPF）就是

> 但**只覆盖 RAID5 写洞这一条机制**——掉电注入与「SSD 内部对整个映射单元的 RMW」两条都还注入不了。**槽宽这一格暂不改。**

**⇒ 结论**：E126 的设备集**恰好**只在「机制已被实测为无损失」的那一格上让乙赢，
而**唯一能给乙一个未被证否的理由**的设备类（裸 NVMe，`pbs < io_min`）**一台都没建**。
按 `.claude/rules/fs-design.md` 的格式分支判据：

> **一条格式分支值不值得，看它能不能把「用错了」变成「挂不上」。**

## 打中 3：判据 5 的取样点对乙零判别力，换一格结论就反过来

现查 `research/e7-index-bench/src/bin/e126_superblock_slot_width.rs` 第 200–201 行逐字：

```rust
    // ── 判据 5：异构池（pbs 512 与 4096 混合）上取到几个不同值 ──
    let hetero: [(u64, u64); 2] = [(512, 512), (4096, 4096)];
```

**这个池的两台盘都满足 `io_min == pbs`** ⇒ `max(pbs, io_min) ≡ pbs` ⇒ **乙在这个取样点上恒等于甲**。
产物第 167–171 行的 `yi distinct_widths=2` 量的是甲的离散度，不是乙的。

逐字复制该文件第 73–79 行的 `width()` match 臂与第 118–123 行的 `distinct_widths()`，
换一个取样点重算（`/tmp/.../w.py`，纯算术）：

```

  arm=jia_probe_pbs        widths=[512, 4096]  distinct_widths=2
  arm=yi_probe_max_iomin   widths=[512, 4096]  distinct_widths=2
  arm=bing_const_512       widths=[512]        distinct_widths=1
  arm=bing_const_4096      widths=[4096]       distinct_widths=1
  arm=ding_min_unit        widths=[16384]      distinct_widths=1
pool = 未取样 [(512,512),(512,65536)] 一台裸盘 + 一台 md/raid5
  arm=jia_probe_pbs        widths=[512]         distinct_widths=1
  arm=yi_probe_max_iomin   widths=[512, 65536]  distinct_widths=2
  arm=bing_const_512       widths=[512]         distinct_widths=1
  arm=bing_const_4096      widths=[4096]        distinct_widths=1
  arm=ding_min_unit        widths=[16384]       distinct_widths=1
```

⇒ **在第一版 2 盘（D2 已定项 9，用户定案）的一个完全现实的异构组合上，甲是单值的，乙是唯一非单值的臂**，
池内跨度 **128 倍**。E126 报出的「甲乙并列 2」是取样点的产物。

E126 自己给判据 5 写的理由（`.claude/kb/experiments/126-超级块槽宽四条候选的代价.md` 第 42 行）逐字：

> 5. **异构池上是不是单值**：甲 / 乙 依赖探测 ⇒ 池内不同盘可能不同；丙 / 丁 是格式常量 ⇒ 恒单值。

⇒ 理由写的是「依赖探测 ⇒ 可能不同」，而**它选的池恰好让乙的那个探测量退化**。

### 4a. `io_min` 是栈属性，不是盘属性——两条现查

**证据一（Linux 稳定 ABI，仓内 2026-08-29 现查）**，`research/e7-index-bench/src/bin/e34_ring_iomin.rs` 第 8–11 行逐字：

```
//! - Linux 稳定 ABI（`Documentation/ABI/stable/sysfs-block`，2026-08-29 现查）：
//!   `minimum_io_size`「For RAID arrays it is often the **stripe chunk size**」；
//!   `physical_block_size` 是「the smallest unit a physical storage device can write **atomically**」。
//!   ⇒ 两个量管的不是一件事，内核里 `physical_block_size ≤ io_min` 恒成立。
```

⇒ 内核自己的稳定 ABI 把两个量归到不同范畴：
`physical_block_size` 是「**a physical storage device**」的属性；
`minimum_io_size` 在阵列上是「**the stripe chunk size**」——**阵列配置的属性，不是盘的属性**。

**证据二（本机现查 2026-09-10，`man mdadm`）**：

- 第 375–377 行：`-c, --chunk=` ／「Specify chunk size in kilobytes.  The default when creating an array is **512KB**.」

⇒ 两件事同时成立：
1. **`mdadm --grow` 可以在带数据的活阵列上改 chunk-size** ⇒ `io_min` 在 mkfs **之后**可被管理员改变，这是受支持的在线操作。
2. **mdadm 默认 chunk 是 512 KB**，不是 E34 量到的 64 KB ⇒ 一个**默认配置**的 md/raid5 上乙的槽宽是 **524288**，
   16 槽 × 2 盘 = **16 MiB**，`sectors = 1024`。E126 判据 1 / 4 报的 2 MiB / `sectors=128` 是取样点的产物，
   **乙的槽宽在格式里没有上界**。

### 4c. 构造：`mdadm --grow --chunk` 之后的三种结局，没有一种是好的

**场景**（全部用受支持的管理操作，不涉及任何故障）：
第一版 2 盘池（D2 已定项 9，用户定案），成员之一是 `/dev/md0`，raid5，chunk 64K ⇒ `io_min = 65536`。
mkfs 时乙划下槽宽 65536，槽 k 落在 `k × 65536`。
数月后管理员跑 `mdadm --grow /dev/md0 --chunk=512` ⇒ `io_min = 524288`。重新挂载。

| 结局 | 发生条件 | 后果 |
|---|---|---|
| **① 全池挂不上** | 挂载按新探测值 524288 复算，与盘上 65536 对不上 ⇒ 按 C47 逐字「按较小那个划会让较大的那块盘**永久判红**，而偏移是盘上既成事实、改不了」 | **数据、根、journal 全好，整池不可挂，且不可修复** |
| **② 静默读到陈旧超级块** | 若槽 0 落在固定点、记录宽是常量（合并臂 389 / 477 字节，远小于任一槽宽），则按新步长 524288 扫描时**槽 0 仍是一条完整合法记录**（校验和过、世代号过），而真正最新的那一槽落在 `j × 65536`，新步长**永远扫不到它** | **挂得上，用的是陈旧超级块。** 这正是 D22 已定三第 48–50 行逐字要防的那件事：「一条**完全没落盘**的记录，读到的是同一位置上一圈遗留的**完整合法旧记录**——校验和通过，而它是陈旧的。」⚠️ **已定三的两个字段在这里全部失效**：校验和过，世代号也过——世代号答的是「它是不是本代的」，而在**只扫得到一个槽**的情况下，它就是那一代里最新的 |
| **③ 越界写** | 若挂载后按新宽度 524288 × 2 槽（已定项 8 下界）写，而 mkfs 只按 65536 × N 划了区域 | **写出超级块区域之外**，覆盖后面的东西。乙的槽宽无上界（4a），所以越界量也无上界 |

> 参数化布局的失败模式是**静默误读**，incompat 位的失败模式是**拒绝挂载**。

**结局①的代价被单独量过，而且是 E87 花一整个实验消除掉的那一格**，
`.claude/kb/decisions/22-单元原子性怎么合成.md` 第 509–511 行逐字：

## 第 4 问：丁（槽 = 一个单元 16384）真的能拿到那五条机制吗？——**部分拿不到，理由要重写**

**丁的卖点是假的一半。** E126 给丁写的理由（`.claude/kb/experiments/126-…md` 第 24 行）逐字：

> | **丁** | `= 池内最小单元大小`（第一版 16384，D18（块里携带什么信息） 已定项 9） | 让超级块槽**就是一个单元** ⇒ 按 `.claude/rules/fs-design.md`「不是单元的盘上空间，核心层对它零覆盖」自动拿到那五条机制 |

**但超级块槽已经是登记在册的单元类，而且对其中两条机制是显式豁免的**——见打中 1 的四处逐字，
`.claude/kb/decisions/18-块里携带什么信息.md` 第 613–617 行逐字：

> **自证单元（journal 记录 / 根槽 / 超级块槽）不用这张表**……
> I-1.1（块头自述逻辑地址）/ I-1.3（块头树 ID 一致）对它们**显式豁免**……
> 它们在已定项 11 的登记表里占码 16 / 17 / 18，只做 AAD 域分隔子。

⇒ **豁免是按「类」给的，不是按「大小」给的。** 把槽撑到 16384 不会让 I-1.1 / I-1.3 回来。
⇒ 丁的「自动拿到那五条机制」**至少两条拿不到**，理由要重写。

**问「超级块槽要不要带单元头？带了还装得下吗？」——装得下，不是瓶颈**：
D18 已定项 7 的三档头是 68 / 77 / 86（D22 未定项 9 正文逐字「单元里最多付 86（D18 已定项 7 三档头）」），
而记录字节数六格是 507 / 566 / 536 / 595 / 389 / 477。**16384 槽下 `595 + 86 = 681 ≪ 16384`。**
产物第 51 行也逐格确认 `ding_min_unit` 在全部记录尺寸上 `fits=1`（E126 的阴性对照条款正是这一条）。

**丁真正的、材料没写的收益**：D18 已定项 9（**用户定案**）逐字「扫描器按池内最小单元大小步进（第一版 16384）」
⇒ **只有丁的槽落在扫描器的步进格上**。512 / 4096 宽的槽在 16384 步进下**扫不到**，
65536 宽的槽会被当成 4 个步长。⇒ 这是「全盘扫描重建」这条最后手段能不能认领超级块槽的问题，
E126 五个判据一个都没量它。

⚠️ **对「超级块当单元合不合法」的疑虑不成立**，`.claude/rules/fs-design.md` 逐字：

> ⚠️ **这与「不许指向核心层的对象」不冲突**：**「是单元」说的是格式形态，
> 「核心层的对象」说的是可达性身份**，两者是两回事——
> 一块空间可以既是单元、又不从任何根独立可达（生命周期绑在宿主上）。

⇒ 「每盘一份、位置固定、不从根可达」**不妨碍**它是单元。

## 第 5 问：有没有第五条路？——**有，而且「四选一」本身就是假的**

**E126 只把 C212 三条候选里的 ① 建成了臂。** C212 逐字（`.claude/kb/checks-owed.md` 第 207 行）：

> ⚠️ **三条候选互不相同，不许预设走哪一条**：① 抬固定结构的写宽到 `io_min`（根槽宽改成 `max(physical_block_size, io_min)`，代价见 D22（单元原子性怎么合成） 已定项 2 的槽宽张力那一节）；② 收窄硬要求 1 的射程，明写它只管数据 / 单元写，固定结构另有一套（那要给出为什么固定结构不怕设备内 RMW，而 E34（根环槽几何） 的真设备那一轮只证到 RAID5 写洞这一条机制）；③ 挂载时拒绝 `io_min` 大于固定结构写宽的设备（C82（io_min 不在挂载比对清单） 那道闸的推广形态，代价是一批阵列上挂不上）。

⇒ **乙就是候选 ①。候选 ② 与 ③ 在 E126 里一条臂都没有。**
「四条里没有一条全面占优」这句话，是在一个**少了两条路**的候选集上说的。

**四条之外，本腿另给三条，都能拿到乙的 `honors` 收益而不付它的可变性代价**：

| 路 | 形态 | 它解掉什么 / 还欠什么 |
|---|---|---|
| **戊：mkfs 时探测、写进盘上** | 槽宽 = mkfs 那一刻的 `max(pbs, io_min)`，**作为一个池级常量写进盘**，挂载时**读盘上的值**，不重新探测；探测值只用来比对并在不匹配时按已定项 2 同型的「未达到拒绝挂载」处理 | **同时拿到乙的 honors 与丙丁的不可变性**。它把 4c 的三种结局全部收成「拒绝挂载」这一种（fs-design.md 判据要的那一种）。⚠️ 欠一步：槽 0 要落在一个固定点且自描述，而**超级块落点全仓未定**（first-txn-layout 第 20 行「—」） |

| **庚：C212 候选 ③（挂载准入）** | mkfs 时记下固定结构写宽，挂载时 `io_min > 写宽` 直接拒绝可写挂载 | 与 C82 已登记的闸同族（`.claude/kb/checks-owed.md` 第 93 行）。代价 C212 自己写了：「**一批阵列上挂不上**」。**E126 一个判据都没给它建臂** |

⚠️ **「超级块不做槽轮换改做 COW」这条路走不通**，D22 已定项 8 是 2026-09-02 **用户定案**

且逐字定了「做成槽轮换，每盘至少 2 个槽」。改它要先推翻一条用户定案，**不属于「第五条路」，属于另一条决策**。

## 一句话结论

**乙站不住。** 它与一条已定条款正面冲突（D20 第 69 行「等于 `physical_block_size`」，
而超级块槽在四处逐字被登记为该类）；它唯一的优势格是真设备实测「邻槽 10/10 完好」的那一格；
它是四条里唯一把一个 `mdadm --grow --chunk` 就能改的量塞进 mkfs 冻结几何的候选，
而超级块槽**结构上建不起根槽那道守卫**；
唯一的现役参照用一个常量注释逐字封掉了这个动作。
**这一格该按 C212 收窄射程（候选 ②）或走「戊：mkfs 时探测、写进盘上」解，不是按「抬槽宽」解。**
