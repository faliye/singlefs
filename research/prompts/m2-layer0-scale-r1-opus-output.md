## 一、L1：甲的前提

### 1.1 先说前提管到哪、管不到哪

前提（背景材料第 13 行 L1 那一行）的假设只说「恢复可能选中的版本」与「journal 重放」读不读得到 COW 写，结论却是「恢复出的可见状态…逐项相同」。层 0 每个状态判红的不只是恢复：`evaluate_state_for_versions` 还跑池级 checker 与记录核对器。冻结副本里有四处判据读的东西不经过任何根：

| 判据 | 读什么 | 出处（冻结副本，现查） |
|---|---|---|
| I-7.7 | 单元区里每个写过的槽的单元头（写序里的实例代号） | `crates/singlefs-checker/src/walk.rs:1709`、`:1741` |
| I-7.8 | 单元区扫描出来的码 2 节点的树 ID | `crates/singlefs-checker/src/walk.rs:1643` |
| I-1.8 | 单元区扫描出来的码 1 / 码 3 已发布单元，按镜像归组 | `crates/singlefs-checker/src/walk.rs:3614` |
| 记录核对器第二条 | 写表里每一次发布的每个单元落点，连同「被更晚的已持久写盖过」的豁免 | `crates/singlefs-harness/src/crash.rs:714` |

`walk.rs:1709` 原文：

```
/// 盘上带实例代号的东西：根环里自证过的根、journal 环里 fsid 相同的记录、单元区里头校验和过且 fsid 相同的单元写序。
```

`crash.rs:714` 原文：

```
    let copy_is_missing = |copy: usize| !in_place(copy) && !written_over_later(copy);
```

所以前提要当甲的依据，假设那一半得改成「这一段的 COW 写不改变层 0 任何一个判据的读数」，而不是「不被可能选中的版本引用」。下面 1.3 与第二节 L3 各有一格就是从这个缺口进来的。

### 1.3 打中：挂载时暂时读错造出被抛弃的根，新实例复用它的单元槽（H1）

历史（每一步都指到许可它的条款）：

1. mkfs → 取号 1 → 暖机 → A（txg 3）→ B（txg 4），同一进程。
2. 进程重开、可写挂载；挂载期间 dev1 上 B 那次发布的 15 次写落下的区间（根槽、单元、记录那一份）读报错。择根跳过读不出的根（`recovery.rs:668` 起的 `choose_root` 只按自证与回退见证挑，`:680`），落到 A；B 的记录一份读得出、点名单元有一份读不出，按 D23 已定项 14 前缀第四条「两份都验过才施加」不施加。实测：`chosen=(1,3) effective=(1,3) instance=2 rows=[(1, 3, 0)] row_publish_txg=5 warmups=[6, 7]`。
3. 撤故障。按 D23 已定项 14（`.claude/kb/decisions/23-journal的角色与格式.md` 第 384 行那一段）B 的根离开根环之前，它引用的单元不许重新分配；而挂载那一刻影子账读不到 B 的根（C554，`.claude/kb/checks-owed.md` 第 477 行），隔离 0。
4. 实例 2 覆盖写一次（txg 8）：数据单元落在槽 50182，正是 B 的数据单元槽（`OVERWRITE H1 write#137 dev0 slot50182 txgSome(8) overwrites: stream=#41(unit_write,txgSome(4))`，dev1 同）。B 的根 (1,4) 这时还在根环里。

结果：txg 8 那一段（第 22 段，2 原地 + 24 COW）324 个取样状态里 124 个与 (I, ∅) 判定不同，全是记录核对器第二条从不报变成报（`claimed_state_missing_unit`）；(I, ∅) 一个都不报。

四句：
- **分不分辨臂：不分辨。** 甲在下一段（txg 8 的记录段，那里这一段已整段持久）照样判红：甲 78 个状态里 7 个红、甲二 93 个里 10 个红、全量取样多出 124 个红，三条臂都红。它打的是前提的字面，不是甲的结论。
- **被判的系统当时看不看得到：** 分配器看不到（影子账那一刻读不到 B 的根，这正是 C554）；枚举器在切段时看得到——B 的根写与单元写都在写表里、都已持久。所以 L2 的「引用集合」只能从崩溃镜像独立算，不能取实现的账。
- **满足判据字面哪一句：** L1 问句「有没有一种可达历史（…被抛弃时间线与影子账…）让一次 COW 写落在某个仍可能被选中的版本引用的块上」。要说清：B 被实例表抛弃，按 D16 已定项 1 的候选集它不算「可能被选中」；判红的是记录核对器，它的「恢复自称的 txg ≥ B 的 txg 就该有 B 的单元」在被抛弃的时间线上本身不成立，打中的这一格有「归错判据」的成分——真正被违反的条款是 D23 已定项 14 的影子账那一句。
- **改法还中不中：** 背景材料 L2 的现判若按「可能被选中的版本」取引用集合、且取的是 D16 候选集，这一格不报；若按「写表里任一已持久写落过的扇区」取，报（这一段两次写都盖旧扇区）。

用户动作放开扫（前缀固定为 A、B 与挂载时的读故障，之后 0–3 步，每步取覆盖写 / 重挂 / 卸载再重挂 / 抬 F）的结果在 1.5。

### 1.4 卸载那一串（H2）：没打中

A、B → 正常卸载（F 抬到 4）→ 重挂 → 覆盖写 3 次 → 再卸载 → 重挂 → 覆盖写一次。466 次写、65 段、全量闭式 3429236868。卸载之后的覆盖写大量复用 F 以下的旧槽（`OVERWRITE H2` 共 86 行，落在 txg 11、12、17、18、19、20 六次发布的单元段）。取样 4396 个 COW 非空状态、甲 210 个状态：观测零差异、零红。按 D16 候选集读法，这些旧槽只被 txg < F 的根引用，恢复与四处判据都不读；按「根环里任一可读根」的宽读法，L2 会在这六段退回全量（每段 2^22–2^30 个状态），甲在最需要它的地方省不下来（推的，没量）。

### 1.5 用户动作放开扫

前缀固定（A、B；另一组再加挂载时 dev1 上 B 的扇区读报错、撤故障），之后 0–3 步，每步取 O（覆盖写）、M（进程重开可写挂载）、U（正常卸载再重挂）、R（抬 F 到能抬的最高，抬不了记成 `-`），两组各 85 条、共 170 条流；每段每个原地子集取全集、单点、去单点、4 个随机子集。汇总行原样：

```
SWEEP_TOTAL streams=170 arm_a_misses_a_red_stream=0 streams_with_any_observation_difference=27 elapsed_seconds=583.9
```

- 有差异的 27 条全在带读故障那一组，而且全是「读故障那次挂载之后第一步就是 O」（或前面只有抬不了的 R）：每条都是同一段（被抛弃的 B 的数据单元槽被复用）上 104 个取样状态从不红变红，甲在后面的段里照样红（8–144 个）。
- 读故障之后先 M 或 U 的那些条一条都没差异：再挂一次时 B 的根读得出，影子账把 B 的槽隔离了。所以 H1 那一格要的是「读故障那次挂载里接着写」，挂载一次就换不掉。
- 甲漏掉整条流的红：0 条。
- R 在 170 条里实际抬成的只有 23 条（其余都被上限拒，记成 `-`），抬 F 这一步放开得不充分。
## 二、L3：甲漏不漏

### 2.1 变异表里点名层 0 的 32 行：按构造都还在甲的状态集里

`crates/mutations.tsv` 里第五段点名名字带 `layer0` 的测试共 32 行（`awk -F'\t' '$1 !~ /^#/ && $5 ~ /layer0/'` 现数），点名的全是不标 ignored 的快用例，没有一行点名全量那几条。快用例的展开谓词现查：`segment.len() < 10`（第二条流、并行线一、只做过 mkfs 的池）、`< 18`（第一条流）、`< 64`（并行线三）、`< 4`（树分裂）、「残留记录 / 陈旧 tail 那两条只展开复用那一段之后的小段」、手摆的状态（靶向对照、`a_unit_whose_only_later_write…`）。冻结副本的流里这些小段全是原地覆盖的写（系统配置槽、journal 记录、根槽），甲对它们照样全枚举，所以 31 行的判红状态甲一个不少。

例外只有一行：第 304 行「步 3 验收：取号之后没有屏障（取号的系统配置槽写与写行那次发布的单元写并成一段）」，点名 `second_transaction_step_three_acquisition_barrier_layer0` 的 `no_unit_of_the_new_instance_persists_before_the_acquired_instance_in_any_crash_state_of_the_remount`。那条用例特意按位置展开「取号那一段」与「取号之后第一个带单元写的那一段」。

### 2.2 打中：原地写与 COW 写之间少一道屏障这一类，甲的枚举一个红都摆不出来

在副本上照第 304 行原样改 `crates/singlefs-core/src/transaction.rs`（补丁 `mutation-304-no-barrier-after-acquisition.patch`，锚点恰好命中一次），重建流 C：取号的两次系统配置槽写、B 的两次轮换与写行那次发布的 18 个单元写并成一段 `[system_configuration_slot×4,unit_write×18]`（第 12 段）。

| 臂 | 状态数 | 判红的状态 |
|---|---|---|
| 甲（每个原地子集 × COW 取 ∅） | 78 | 0 |
| 甲二（每个原地子集 × COW 取 ∅ 或全集） | 108 | 12 |
| 全量取样（第 12 段每个原地子集 × 全集、单点、去单点、32 个随机） | 2596 | 比甲多 828 |

判红的是 I-7.7 ①，原样：`I-7.7:盘 0 槽 50304 的单元写序带实例代号 2，高于各盘系统配置的最大者 1（①）`。要红必须同时满足「取号那次系统配置槽写没落」与「写行那次发布有一个单元写落了」；甲的代表状态 COW 取 ∅，后一个条件永远不成立，下一段的状态里取号已整段落盘，前一个条件永远不成立。

这一段没有任何一次单元写盖到之前写过的扇区（这份流的 `OVERWRITE` 行数为 0），所以 L2 的现判不管引用集合按哪一种读法取，都不会在这一段退回全量。

四句：

## 四、L7：断点续跑

### 4.1 原型

在副本的 `crates/singlefs-harness/src/crash.rs` 里加 `enumerate_layer0_resumable`（补丁 `l7-resume-prototype-crash-rs.patch`，252 行）：片长固定、不随线程数变；头行逐字比；每跑完一片追加一行并 `sync_data`；续跑时读回已完成的片、只跑剩下的、按片号并。两种读法对照：

- **严格**：一行要以换行结尾、带 crc32c、片号对应的状态区间与计划相符，遇到第一行不合格就停、把文件截到最后一行合格的末尾；同一片号只收第一次。
- **宽松**：按换行切，最后一段没换行也收，能解的 `key=value` 都收、缺的取 0。

行里字段的次序是先状态数、后违例类（这是背景材料没规定的一处；换个次序，宽松读法丢的就是别的字段）。

计划：固定脚本到 E18，展开写数小于 10 的段，版本表照 `one_state_slices_on_eight_threads…` 那条用例的做法把 B 的内容换成 C 的（让违例散在很多片上），片长 3：127 个状态、43 片，一口气跑完 22 个违例、19 个不看 journal 那一遍的违例。

### 4.3 打中的几格，逐条四句

**(a) 键只写「输入哈希 + 切片方案」不够，会假绿。** 54 号的输入哈希是整道的（登记路径全体加 54 号与工具链），两条流、同一个二进制里的几条用例共用一个哈希；片方案相同、状态数也相同的两次枚举（同一条流、同一个展开谓词、不同的版本表或被判的根）会互相拿对方的进度。
- 分辨臂：只分辨续跑的几种候选键；甲、乙不涉及。

## 八、这条腿自己的限度

- 全部数出自冻结副本的拷贝（`/tmp/claude-1000/m2-layer0-scale-r1-opus/` 下 `repo`、`repo-m304`、`repo-msl`、`repo-l7` 四份，交回前已删，`rerun.sh` 按补丁重建），不是入库装置；要引须在入库装置上重做。

- 续跑原型是我写的，严格读法的格式也是我定的，被攻过零轮；真杀只有 5 次，没模拟掉电（fsync 之后的持久性按 ext4 的承诺算）。
