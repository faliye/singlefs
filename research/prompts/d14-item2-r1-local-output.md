1. For Arm A, create a file named temp.txt and write 100 bytes to it. The allocator places it in the suffix region for .txt files. Rename the file to secret.key. The blocks remain in the .txt region. The raw disk shows this region contains encrypted data that was originally labeled as text, but the actual content is sensitive. The cost is not just lost locality but potential exposure of sensitive data structure to raw disk analysis. The fifth requirement is violated because the suffix changed during the rename operation after allocation, altering the branch variable mid-operation.

2. For Arm B, a malicious process sets the short-lived hint for all its writes. It creates 10,000 small files and marks them as short-lived. The allocator places all in one region expecting quick deletion. The process never deletes these files. The region fills up completely and cannot be reused for new allocations. Other processes attempting to write short-lived data fail to allocate space because the region is full but never freed, causing the filesystem to run out of space prematurely.

3. For Arm C, create a directory with two subdirectories: one for temporary logs and another for critical database files. The administrator marks the parent directory as short-lived. The allocator places all files from both subdirectories in the same physical region. The log files are deleted frequently, but the database files remain. The region becomes fragmented with small free blocks between database file blocks, causing slow write performance for new database entries compared to if the database files were in a dedicated region.

4. To satisfy the requirement that every branch is observable at run time and forcible in a test, the filesystem must store the hint type for each allocated block in its metadata. This metadata must be written to disk to allow crash-point replay verification. For example, each data extent record in the inode must include a field indicating the hint used. This field is part of the on-disk format, contradicting the zero format bits claim.

5. Under encryption, Arm A groups files by suffix. An attacker reading the raw disk sees that all blocks in a specific region correspond to the same suffix. Even with encrypted content, the physical clustering reveals that all files in that region share the same suffix type. For Arm C, the directory annotation causes all files in a directory to be placed together. The raw disk shows a contiguous block range for files written in the same commit, revealing which files belong to the same directory, leaking path information despite encrypted filenames.

6. The assumption that the hint remains valid for the entire lifetime of the file is most likely false. The observation that reveals this is when a file initially created as small and short-lived is later extended to a large size and kept permanently. The allocator placed it in a region optimized for small, temporary data, but the file now requires long-term storage in a region designed for larger data, causing severe fragmentation and performance degradation.
