### 2.2 几个头（原头与克隆头）的意图交错：三条臂都不中

条件：原头与克隆头各挂未完成的意图，按第三轮前提能动的意图之间任意交错——丙-区间的级联之间不排次序；乙、丙′ 只在同一个头上按写意图的次序，头与头之间不排；销毁头等同一个头上更早的级联；一批可以一条（B）或顺序施加多条（BA）。

为什么不中（推的，下面的搜索是它的量）：
- 三条臂的键都以头打头（丙-区间、丙′ 是头的树 ID，乙的号是某一棵树的树 ID、各头不重），一个意图只动它自己那个头的条目；下一侧也总在同一个头的谱系里（克隆头第一个快照的下一侧是克隆头自己）。

### 2.3 回退让写意图的那个 checkpoint 号被重发：三条臂都不中；上界误读成「已发布的号」时丙-区间 5 步漏放

条件：意图写在 checkpoint c（丙-区间记 hi = c）；之后崩溃挂回、回退一个根、按候选根重发 txg 与树 ID（误读）、或写意图那次发布的根槽写失败、推进一格再发（c 那次发布以 c + 1 落盘，意图里的 hi 仍是 c）。问的是：上界会不会撞上新时间线里建的快照的 txg（纪元），让之后杀的块落进 [lo, hi) 被放掉。

为什么撞不上（推的，下面的搜索是它的量）：
- 意图只在含它那个 checkpoint 的时间线上活着：挂回的根早于 c，意图随之不在；挂回的根不早于 c（txg 记 r ≥ c），新 txg 至少 r + 1 > c。按 D23 已定项 14 的字面（全部根的 max + 1，整行在附录 A）如此，按误读（候选根的 max + 1）也如此——所选根自己就在候选里。
- 快照只在 checkpoint 末尾建（`16-发布语义.md` 第 80 行新规则 1）：写意图那个 checkpoint 末尾建的快照 txg = c = hi，在区间外；写意图之前的纪元都是更早发布的快照的 txg（< c）。⇒ 写意图之后头上新杀的块，纪元是继承来的 P 或 ≥ c 的快照 txg；P 落进区间只在 P = lo（同 txg 姊妹）时，那些块 birth ≤ P，过滤永远不放。
- 根槽写失败推进一格再发：意图里的 hi 仍是 c，那次发布建的快照拿 c + 1，仍 ≥ hi。
- 乙、丙′ 的号 / 段是树 ID：回退后树 ID 水位按全部根的 max 取，不重发已发布的号；按误读重发的号只可能是被抛弃时间线上发过的，挂回的状态里没有任何条目带着它们。

量（每条只在本模型的取样范围内成立）：
- H3 / H3b / H4（`out-replay.jsonl`）：意图写在 checkpoint 3、发布，再建快照、杀块，回退（H3 按候选根重发 txg 4 与树 ID 14，H3b 按全部根取号），再建快照、杀块，最后跑完意图；H4 是写意图那次发布根槽写失败、推进一格再发。三条臂与阳性对照都不中。
- BFS（1 个头、≤ 2 块、≤ 2 个活快照、txg ≤ 5、允许 CR / RB / RBC / PF、深度 ≤ 8，`out-bfs-crash.jsonl`）：丙-区间 564 537、乙 545 583、丙′ 547 777 个节点，搜完，都不中。
- 深 BFS（同范围、深度 ≤ 11、预算 600 万个节点，`out-bfs-crash-deep.jsonl`）：数在 2.6。
- fuzz（2.1 同一套范围，CR / RB / RBC / PF 都开）：去掉 BS 时三条臂 0 / 400。

**上界的一个误读**：hi 取「写意图时最后一个已发布的号」（`hi=pub`），而不是写意图那个开放 checkpoint 的号。同一个 BFS 范围给出 5 步漏放（`out-bfs-crash.jsonl` 末条）：

| 步 | 操作 | 丙-区间（hi 取已发布的号） | 真值 |
|---|---|---|---|
| 1 | 头 11 写 b0 | birth 1 | 头引用 b0 |
| 2 | 发布 txg 1，建 S12 | prev(头) = 1 | S12 引用 b0 |
| 3 | 头杀 b0 | birth 1 ≤ 1 ⇒ 键 (11, 纪元 1, b0) | S12 仍引用 b0 |

### 2.4 写意图与传递 prev 之间崩溃：共同前提下落不进去；拆到两次发布时三条臂一起多放（5 步），不分辨臂

共同前提把两件事放在同一个事务里（背景材料第 38 行），而一次发布整体施加或整体不施加（`16-发布语义.md` 第 193–195 行；D23 把它列成前缀判定的第六条口径，`23-journal的角色与格式.md` 第 691 行末句；两处整行在附录 A）⇒ 崩溃只能停在某次发布刚完成的状态，这两件事要么都在、要么都不在。模型里崩溃 = 挂回一个根、发布是原子的，这一格建不出新历史。

为了看「真落进去会怎样」，模型加了两个变体：`inherit=nextpub`（写意图那次发布之后才传 prev，崩溃挂回后照意图补传）与 `inherit=nextpub_lost`（崩溃挂回后不补）。BFS（1 个头、≤ 2 块、≤ 2 个活快照、txg ≤ 4、允许 CR / RB、深度 ≤ 7，`out-bfs-split.jsonl`）对六个变体给出同一段 5 步，每个展开 658 个节点：

| 步 | 操作 | 拆开的变体（三条臂同） | 第三轮形态（三条臂同） | 真值 |
|---|---|---|---|---|
| 1 | 头 11 写 b0 | birth 1 | 同左 | 头引用 b0 |
| 2 | 发布 txg 1，建 S12 | prev(头) = 1 | 同左 | S12 引用 b0 |
| 3 | 销毁 S12（下一侧 = 头），写意图 | prev 暂不传，prev(头) 仍是 1 | prev(头) := 0 | S12 不再引用 |
| 4 | 发布 txg 2，建 X13 | prev(X13) = 1（指着已销毁的 S12，本该是 0），prev(头) = 2；发布之后才传：prev(头) := 0，把 2 盖掉 | prev(X13) = 0，prev(头) = 2 | X13 引用 b0 |
| 5 | 头杀 b0 | birth 1 > prev(头) 0 ⇒ 直接放 ⇒ **多放** | birth 1 ≤ 2 ⇒ 进 deadlist | X13 仍引用 b0 |

fuzz（2.1 同一套范围）：`nextpub` 三条臂 312 / 305 / 333 段判红、`nextpub_lost` 340 / 334 / 360 段（共 400），多放与漏放都有。
崩溃那一格单独看（`out-replay.jsonl` 的 H5b：第 4 步那次发布之后插一次崩溃挂回）：`nextpub` 照意图补传，与不崩溃完全相同，第 6 步多放；`nextpub_lost` 在这一段上不中，可是同一段不崩溃时它第 5 步就中了。⇒ **病根是「拆到两次发布」本身，不是崩溃**：写意图那次发布末尾建的快照读到的是还没传的 prev，之后补传又把头的 prev 盖回去（第二轮 2.3「最后一批才传」是同一型）。

三句：
- **分辨臂**：不分辨。六个变体同一段历史、同一步中 ⇒ 按反向接受条款「打中不分辨臂，病根另记」。
- **判别子在做决定那一刻看得到吗**：看得到。写意图那一刻下一侧是谁、P 是多少都已知；缺的是「必须在同一个事务里传」这一句落进 kb。
- **满足哪条判据的哪一个分句**：U1 第一个分句「某块被释放而仍被某个快照引用」（b0 被放时 X13 仍引用它）。

结论：共同前提那句「prev 在写意图的那个事务里传」连同 D16 已定项 4 已经把这一格堵死；要守的是这句话不许被实现拆成两次发布（例如放到后台去传、放到第一批里传）。它今天只在材料的共同前提里，kb 正文没有（第七节）。

### 2.5 级联没做完时建克隆、销毁克隆头：三条臂都不中；一处与臂无关的读法要另记

试过的形状（都在 2.2 那两组两个头的 BFS 与 fuzz 的范围里；后三行 H2 逐步走过）：

| 形状 | 为什么不中（推的） |
|---|---|
| 级联没做完时，从它的下一侧 N 克隆 | 未完成意图要放的都是在 N 之前被杀的块，不在 N 的捕获集合里，克隆头继承不到 |
| 级联没做完时，从 S 的上一个快照 Q 克隆 | 要放的块 birth > P = Q.txg，不在 Q 的捕获集合里 |
| 级联没做完时，从写意图之后才建的快照 Y 克隆 | 要放的块在写意图之前就被杀了，不在 Y 里 |
| 克隆头的级联没做完就销毁克隆头 | 共同前提让销毁头等同一个头上更早的级联；等完之后克隆头那一份里只剩 birth ≤ origin.txg 的继承块，按前缀 / 号删掉、不放 |
| 销毁克隆头之后立刻销毁 origin | origin 的级联放的是原头在 origin 之后杀掉、birth > prev(origin) 的块；克隆头的 livelist 只放 birth > origin.txg 的克隆头自己的块，两边不相交 |
| 有未完成意图时，在同一个 checkpoint 末尾建快照、克隆、给克隆建快照（PSC） | 第二轮 2.5 判过不中；这一轮在有未完成意图时再开，BFS 两个头允许 PSC，搜完不中 |

**与臂无关、要另记的一处读法**：模型让被销毁的头从写意图那一刻起不再引用它的活集合（与共同前提对快照的那句同形），分叉点闸的 `children` 因而在销毁克隆头写意图那一刻就减、origin 随即可销毁。可是 `05-快照-空间记账机制.md` 第 195–196 行（整段在背景材料附录 `:192-203` 那一块）把「待删除结构（意图 key、删除中队列）」算作活引用；按那句的字面，挂着的销毁头意图仍引用克隆头的活集合，那么 H2 第 15 步起 origin 的级联会在克隆头的销毁意图做完之前放掉克隆头活集合里的继承块 b0——三条臂同一步同样放（放的是原头那一侧的条目），**不分辨臂**。它伤不伤数据取决于挂着的销毁头意图还读不读那批块（模型里不读：它只删克隆头的条目、放 livelist 里 birth > origin.txg 的块）。病根另记：`children` 在销毁头写意图时减还是做完时减，全仓没有条款；第二轮要补的「被销毁的快照从写意图那一刻起不算活引用」要不要连头一起写，也要一起定。
