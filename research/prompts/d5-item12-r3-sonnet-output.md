## 一、Q1：第二轮判决 1 复核——「意图照定义记成 [S.txg, ∞)」是不是分批时的逼出读法，「意图带上界」算不算只许收严

### 1.1 材料定义的字面：两种读法都合法，问题出在哪一种被写进持久意图

第二轮材料给丙-区间的定义（`_d5-item12-r2-background.md:35`，与判决引用一致）：

> 丙-区间（归属 = (头的树 ID, 纪元)，纪元 = 块被杀那一刻头的 `previous_snapshot_txg`）：key = 头的树 ID 8 + 纪元 8 + 中央映射 key 27 = 43，value 空。快照 X 的 deadlist = 纪元落在 `[prev(X).txg, X.txg)` 的全部条目，头的 = `[prev(头), ∞)`。建快照只推进头的 `previous_snapshot_txg`，不改任何条目；销毁 S（下一侧 N）：把 N 那一份里 `birth > prev(S).txg` 的放掉，不改任何条目的键，然后 N 继承 `prev(S)`，N 的区间自然盖住 S 原来那一段。同 txg 的快照那一份区间为空（前提十二）。零树表字节，级联改写 0；依赖前提十三。

这句话描述的是一次**原子**销毁（单步完成、期间没有别的写入插入）下的稳态语义：「N 那一份」这个短语本身是一个**随时间变化的动态区间**——它的值取决于此刻谁是 N 的直接前驱。原子操作里这个区间的值只在这一步内被读一次，读完立刻执行释放，不存在「区间的值在读取之后又变了」这件事，所以「N 那一份 = [prev(头), ∞)」在原子语义下是精确、无害的。

D8（核心索引结构） 已定无界删除走「写意图 → 分批 → 可续做」（`08-核心索引结构.md:269`），销毁快照走级联删除、要落进这套机制（本轮前提十六、十七）。分批意味着：这句定义要被**冻结成一份持久意图**，之后跨越若干次发布、由若干批各自读取并推进。这里出现了材料定义没有回答的问题：**意图里到底记录了「N 那一份」这个短语的哪一种含义**——是「在写意图那一刻，把这个动态短语求值一次、把求出来的（可能无界的）区间原样写进意图」，还是「把这次销毁**应该**释放的那个逻辑上有限的集合，用一个自封闭的、不随后续操作变化的描述写进意图」？

**第二种读法（自封闭描述）本来就该是唯一合法的读法**，理由不是「哪种更保守」，是 D8（核心索引结构） 已定项 5 自己的硬要求。`08-核心索引结构.md:277` 逐字：

> 1. **意图声明目标状态，绝不声明增量。**「把文件 X 截到 N 字节」可以重复执行，「再删 1000 个 extent」不能。

一个上界为 ∞ 的区间，字面上就是「把这个区间里未来出现的任何新东西也一并处理掉」——这正是「声明增量」的一种变体：它不描述一个**此刻确定、以后不再变化**的目标集合，而是把「谁在这个区间」这件事继续交给未来的状态决定。`invariants.md:151`（I-4.4，意图只描述目标态）与这句硬要求是同一条规矩的两处落点，字面是「其字段只描述目标状态，不含任何增量字段」。**按 I-4.4 的字面，[S.txg, ∞) 这个上界本身就不构成一个合法的意图字段**——不是这一轮才发现它错，是它从写下这份材料定义的那一刻起就已经与 D8（核心索引结构） 已定项 5 硬要求 1、I-4.4 冲突，只是原子语义的场景里从没有人把它当成一份要跨批持久化的意图，冲突才没有显现。

### 1.2 因此「[S.txg, ∞)」不是「唯一的逼出读法」，但它是「按字面直译」最容易落地的读法，而这个直译本身违反已定规则

回答第一句问题：材料定义在分批场景下**不逼出**这个区间——它逼出的是「意图必须记录一个自封闭的目标集合」，[S.txg, ∞) 只是把「N 那一份」这个短语**不假思索地照抄进意图**得到的结果，而这个照抄动作本身在动笔那一刻就已经撞上 I-4.4。第二轮攻方腿在 `d5-item12-r2-opus-output.md:72`「意图照这句记成 [S.txg, ∞)」是**对材料按字面最朴素直译**的产物，这个直译确实是丙-区间原始定义留下的一个真实、可被构造出的空子（第二轮 6 步历史、149/300 段 fuzz 判红，`d5-item12-r2-opus-output.md:81,90,97`，我在第 1.4 节独立复跑核实过），**不是稻草人**；但它不是材料定义在 D8（核心索引结构） 已定项 5 与 I-4.4 已经存在的约束之外「新发明」出来的一种额外错误，而是原始定义本身对「意图记什么」这件事留白，留白被按最省事的方式填上之后，与旁边一条早就定死的规则相撞。

**什么现象会推翻这个结论**：如果能找到一段历史，在「意图记录一个自封闭目标集合」这个更严的读法下（不管这个封闭集合具体怎么算）仍然出现多放或漏放，那就说明问题不在「上界」这一处，判决 1 的归因要重新写。我在第 1.4 节的复跑里没有找到这样的历史；第二轮攻方腿的强配置（`hi: fixed`）扫过单头 BFS（2 319 节点搜完）、fuzz（300 段全过）、大范围 BFS（194 万节点搜完）与克隆 BFS（69.8 万节点搜完），也没有找到。

### 1.3 「意图带上界」按 `evidence-discipline.md`「臂的定义也在『跑前写死』之列」三步判

第二轮攻方腿提出的收严（`d5-item12-r2-opus-output.md:92-93`）：意图多记一个上界 `hi`——下一侧是快照时取它的 txg、是头时取写意图那一刻的 checkpoint 号（`commit_txg`）。我读了 `dl2.py` 第 278–283 行的 `BingRange.make_cascade`，逐字确认实现与这句描述一致：

```python
def make_cascade(self, world, sid, info, prev_txg):
    if info["next"][0] == "s":
        upper = info["next_txg"]
    else:
        upper = info["commit_txg"] if self.cfg["hi"] == "fixed" else INF
    return dict(head=info["head"], lo=info["s_txg"], hi=upper, cursor=None)
```

`commit_txg` 在调用处（`dl2.py:631`）取值 `world.txg`——写意图那一刻的当前 checkpoint 号，与描述逐字相符；`hi == "inf"` 是唯一另外测过的对照分支，对应「按字面直译」的坏读法。

按三步逐条判：

1. **记一次输**：按最弱读法（`hi: inf`），丙-区间在第二轮 U1 输给乙、丙′——1.1 节已确认这一步没有争议。
2. **只许收严**：「多记一个 `hi`」这个改动，**对判定逻辑的唯一影响是把候选集合从 `[lo, ∞)` 收窄到 `[lo, hi)`**（`dl2.py:284-286` 的 `candidates()`：先按 `(head, lo)` 到 `(head, hi)` 取区间，再筛 `birth_of(key) > intent["P"]`）——`hi` 只出现在区间的**上端**，从不出现在下端、从不改变筛选谓词本身。任何在 `hi: fixed` 下被释放的条目，在 `hi: inf` 下也一定被释放（因为 `[lo, hi) ⊆ [lo, ∞)`，谓词相同）；反过来 `hi: inf` 释放而 `hi: fixed` 不释放的那些，正是第二轮打中的那类过判。这满足「新形态要被原来那套判据判得更严或相同，放宽一个字都不行」——我没有找到一条被 `hi: fixed` 释放、却不被 `hi: inf` 释放的条目（不可能存在，因为区间只收窄不放宽），也没有找到一条 `hi: inf` 判「不释放」而 `hi: fixed` 判「释放」的条目（同一个理由）。
3. **写明收严在哪**：多要求意图额外携带一个 8 字节的 `hi` 字段（住意图记录本身，不占 deadlist 条目的 43 字节、不占树表预留），且这个字段的取值规则是确定性的（下一侧是快照取它当时的 txg、是头取写意图那一刻的 checkpoint 号）——没有少要求任何东西：原来「不改任何条目的键」「零树表字节」「建快照只推进 prev(头)」三句一字不改。

**这是合法的「只许收严」，不是新臂**——我的判断与第二轮攻方腿一致（`d5-item12-r2-opus-output.md:90-94` 已经自己走过这三步），我在这里做的是独立复核，不是复述：我验证了 `hi: fixed` 在实现里确实只出现在区间上端这一个位置（没有第二处隐藏影响），也验证了收严前后候选集合的子集关系不是靠模型跑出来的巧合，而是 `[lo, hi) ⊆ [lo, ∞)` 这个集合论事实的直接推论——**这一条即便不跑模型也能证明**，模型跑出的 0/300、0/2319 只是在确认实现没有引入额外 bug，不是在证明这条收严本身合法。

**什么现象会推翻这个结论**：找到一条被 `hi: fixed` 释放、但不被 `hi: inf` 判定为「候选」的条目——按集合包含关系这不可能发生，除非 `candidates()` 的实现在 `hi` 之外还有第二处依赖 `hi` 取值的分支（我读过整个 `BingRange` 类，没有）。

## 二、Q2：丙′ 在杀块那一刻要「头的上一个快照的树 ID」，这一轮把它存进预留 8 字节之后还剩什么代价

### 2.1 模型今天的 `BingTid` 走的是「派生态」，不是这一轮要评估的「预留字节」

我读了 `dl2.py` 第 330–372 行的 `BingTid` 类。它的实现用 `self.pth`（头 → 上一个快照的树 ID）、`self.pts`（快照 → 它自己的上一个快照的树 ID）两个**内存字典**维护这个值，在 `on_snapshot`／`on_clone`／`inherit_extra` 三处增量更新——这正是第二轮报告 3.1 节里的路线 (b)（内存派生量，需要挂载时扫一遍树表重建），**不是这一轮任务书点名的「存进预留 8 字节」那条路线 (c)**。

这一点对我的判断很重要：**路线 (b) 与路线 (c) 在「杀块那一刻算出的值」上是外延相同的**——两者存的是同一个逻辑量（头 / 快照此刻的「上一个快照的树 ID」），差别只在这个量**住在哪**（内存派生 vs 持久字段）。`BingTid` 在第二轮全部攻击面（单头 BFS 2 108 节点、克隆 BFS 160 899 节点、fuzz 300 段、大范围 BFS 166 万节点，见 `d5-item12-r2-opus-output.md` 2.6 节，我在 1.4 节已独立复跑核对过 bfs/fuzz 两项与留存产物逐字节一致）上跑出的**正确性**结论，对路线 (c) 同样成立——把同一个值从「内存字典」搬到「持久字段」不改变任何一次判定用的是哪个数，U1 的证据可以直接沿用，不需要重跑。**这一轮真正要单独评估的，是路线 (c) 相对路线 (b) 在其它三个维度上买到什么、还欠什么**，不是重新证一遍 U1。

### 2.2 路线 (c) 相对 (b) 买到的东西：不需要挂载时重建扫描

路线 (b) 要求挂载时扫一遍树表，把 `pth`／`pts` 从头建一遍——这是**一条新的派生态与重建路径**，第二轮攻方腿已经点出（`d5-item12-r2-opus-output.md:231`「是一条新的派生态与重建路径，材料没提」）。这条路径今天没有被写进任何决策正文，也没有被 `verification-build.md` 点名成三样验证手段之一要覆盖的对象——多一条挂载时才跑的重建逻辑，就多一类只在挂载路径上才会暴露的 bug（`.claude/rules/fs-design.md`「记账是事务的副产品，不是事后的遍历」第一格管的是运行时决策路径不许遍历，挂载重建不落在那一格的字面射程里，但它买不到「被问到那一刻有没有答案」这条判据要的东西——挂载完成之前，`pth`／`pts` 是空的，这段时间窗口里如果有任何路径需要查这个值，答案是「没有」）。

路线 (c) 把值直接持久化在树表条目里，挂载时随条目一起读进来，**不需要任何专门的重建扫描**——这与 `08-核心索引结构.md:478` 给 `previous_snapshot_txg` 选择持久化而不是派生的理由完全同型（现查该行：「『活头头部』是什么盘上结构此前全仓 grep 零命中，树表条目正好补上这一格」）。按这个先例，路线 (c) 是更保守、与已有决策风格一致的选择——这是**买到的东西**，不是白付 8 字节。

### 2.3 还欠的三笔：克隆头初值、快照条目要不要这个字段、与乙同价的预留争用

即便认定路线 (c) 值得付，付完 8 字节仍然**没有**把丙′ 变成一个完整定义的臂，还欠三笔：

**① 克隆头的初值**。`dl2.py:346-347` 的 `on_clone`：`self.pth[new_head] = origin_sid if self.cfg["first_seg"] == "origin" else 0`——默认（`first_seg` 缺省）就是 `0`，不是 origin 的树 ID。第二轮攻方腿已经指出（`d5-item12-r2-opus-output.md:236-237`）「克隆头的第一段装 origin 的树 ID 做不到——origin 链接没有字段」，「改成『装 0』就不需要它……模型里 `first_seg=zero` 与原样逐格同结果，但这改了定义，算新形态，被攻过零轮」。这句话现在要反过来读：**「装 0」不是丙′众多形态里的一个可选项，是路线 (c) 唯一今天拿得出字段支持的形态**——「装 origin 的树 ID」需要 Q3 里查出的 origin 链接字段，而那个字段今天没有落点。所以路线 (c) 的克隆头初值只能定成 0，且这个定法「被攻过零轮」这句话仍然成立，需要在这一轮或下一轮补上：克隆头刚建、还没有自己的快照时，它的「上一个快照的树 ID」字段读作 0，这个 0 要能与「真实树 ID 为 0」的任何对象区分开（今天树 ID 从 11 起编，`19-块指针的结构与宽度预算.md:1068` 现查「第一版树 ID 从 11 起编」，0 不会被真实分配，语义上安全，但这句判断要写进条款，不能只留在模型的默认参数里）。

**② 快照条目要不要携带这个字段**。丙′的候选定义（`_d5-item12-r3-background.md:42`）「销毁 S 时写意图，把下一侧那一段里 birth > prev(S).txg 的放掉、留下的改键到 (头, S 的上一个快照的树 ID)」——这句话要求在**写意图那一刻读出 S 自己的「上一个快照的树 ID」**，而 S 是一个快照，不是头。按 `dl2.py:350-352` 的 `make_cascade`，读的是 `self.seg_of(info["next"])`（下一侧的值）与 `self.pts.pop(sid)`（**S 自己**的值）——模型里 `pts` 对每个快照都单独维护了一份。这意味着**路线 (c) 若要在盘上落地，每一条快照的树表条目也要携带这个字段，不能只加在头条目上**。这正撞上本轮前提十三点出的那对矛盾：`D5（快照 / 空间记账机制） 已定项 9`（`05-快照-空间记账机制.md:635` 现查）写「`previous_snapshot_txg` 只写在该头 inode 树那条树表条目里，其余条目写 0」，而 `D8（核心索引结构） 已定项 8` ③（`08-核心索引结构.md:958` 现查）写「对活头条目与快照条目都有定义」。前提十三把这对矛盾记成「与臂无关，第一轮已另记」——**这句判断对丙′不成立**：丙′的正确性直接依赖「快照条目上也有一份可读的『上一个快照的树 ID』」，所以它比乙、丙-区间更早地撞上这对矛盾必须先收口，不能继续挂着。

**正面论证**：`YI` 类（`dl2.py:398` 起）用号（head / snapshot 各自持有一个号，初值等于自己的树 ID）标识归属，销毁 S 时挑「改键条数少的那一份」搬、把搬走的号换成 S 自己的号。这条臂的候选正确性依赖两件事：① 换号必须在写意图那一刻做，不能拖到最后一批——第二轮 2.6 节的「乙，换号放在最后一批」变体给出 8 步漏放（`d5-item12-r2-opus-output.md:205,212`，我在 1.4 节的 bfs 复跑里核对过这一行与留存产物一致）；② 同一个头谱系上的级联意图必须按写意图的次序做，不能任意交错——第二轮 2.2 节的 10 步漏放变体（`d5-item12-r2-opus-output.md:97-114`）在按提交序（fifo）下不中，我读 `dl2.py:644` 的 `run_unit` 调用点确认「强配置」默认就是 `order: "fifo"`（`dl2.py:13`），也就是说**这一轮候选定义里的「乙带次序」，字面就是把第二轮打穿的地方补齐成默认配置**，不是一个新形态。

按 3.2 节 U2 代价表（`d5-item12-r2-opus-output.md:264-268`，我读源码 `Yi` 类确认字段与描述一致）：条目 35 字节、树表预留 8 字节（头 + 快照条目各要，本轮 3.2 节已重算）、建快照改写 2 个号字段（O(1)）、级联改写 `min(D(S), K)`（挑边挑得动时）或固定方向时 `max(D(S), K)`（挑不动、直接固定搬一侧时）。**挑边本身要求写意图那一刻读出 D(S) + D(N) 两份的条数**，而盘上没有任何计数器记这两份各有多少条——这是第二轮攻方腿指出、我复核确认成立的一笔硬代价（`d5-item12-r2-opus-output.md:258`「乙挑边要先数两份……放进写意图的那个事务就是一次无界读」）：要么接受这次无界读（与 D8（核心索引结构） 已定项 5「无界规模的操作一律不许做成单个事务」字面冲突——挑边这一步本身若要遍历两份条目决定挑哪边，遍历动作发生在写意图那一步，而写意图是单个事务），要么放弃「挑少的」这个优化、固定方向（例如「固定搬 S 那一份」），代价从 `min` 退化成 `max`，这个退化本身是这一轮候选定义还没写清楚的一处空白。

**要改的 kb 正文**：`08-核心索引结构.md:466,471`（已定项 8 字段表）把预留 24 里的 8 字节命名成「deadlist 号」，写明头条目与快照条目都要；`05-快照-空间记账机制.md:6-12`：交接写成「新快照拿走头的号，头换成新快照的树 ID」，级联写成「写意图时决定搬哪一份并当场换号，两个号与方向写进意图」；**挑边策略要在这一轮写死**（固定方向或补一个计数落点），不能继续留白——留白会让「乙的代价是 min(D(S),K)」这句話缺一个前置条件而站不住；`checks-owed.md:1346` C145 检查句同上；`08-核心索引结构.md:276-291` 补次序（同前提）。**改第一个事务的字节：是**——头的 inode 树条目那 8 字节要写头自己的树 ID（12），这是第二轮已经指出、这一轮维持的结论（`d5-item12-r2-opus-output.md:367`）。

## 五、结论汇总

| 问题 | 我的判断 | 什么现象会推翻它 |
|---|---|---|
| Q1：判决 1 | 「[S.txg, ∞)」不是材料定义唯一的逼出读法，是「N 那一份」这个动态短语被直译进持久意图时最省事的填法，而这个直译从一开始就与 D8 已定项 5 硬要求 1、I-4.4（意图只描述目标态） 冲突；「意图带上界」按三步判是合法的只许收严（集合只收窄不放宽，多要求 8 字节，不少要求任何东西） | 找到一段历史，在「意图记录自封闭目标集合」的更严读法下（不限定 `hi` 具体怎么取）仍然多放或漏放；或找到一条被 `hi:fixed` 释放却不属于 `[lo,hi)` 候选集合的条目 |
| Q2：丙′ + 预留 8 字节 | 付完 8 字节，U1 的正确性证据可以从路线 (b) 直接沿用（外延相同）；U2 的 O(1) 争议解决，但级联改写量 K 仍劣于丙-区间的 0；还欠两笔独立账——克隆头初值只能定成 0（origin 链接今天没有落点）、快照条目要不要携带这个字段直接撞上 D5 已定项9／D8 已定项8③ 的矛盾，且这次是丙′自身正确性的前置，不能再挂着不解 | 给出不需要快照条目重复携带字段、也能 O(1) 拿到「S 的上一个快照树ID」的算法；或 origin 链接字段被别的理由独立确立 |
| Q3：认购表 | `children`、origin 链接独立复核确认全仓无落点；三条 deadlist 候选臂之间「谁挤掉谁」的差别不是本轮真正的瓶颈——在任何一条候选臂被计入之前，头条目预留（24）已经被 livelist 计数器 + 第二道销毁闸计数 + inode 号水位 + origin 链接四笔账推到 32（超 8），快照条目被区间标号 + `children` 两笔账吃满（24）；deadlist 已定项 11 把 deadlist 自己从「预留字节认购者」改成「独立树」的先例，是这批背景占用的一条可能出路，但本项不替它下判断 | 更宽的同义词搜索命中一处给出字段位置的条款；或本轮之外有人已经把某个背景认购者迁出预留字节 |
| Q4：三条臂 | 丙-区间在 U2、U3 均不劣于乙、丙′，且是唯一零树表字节、零级联改写的候选；乙与丙′在 U2/U3 打平，乙的级联改写有 min(D(S),K) 的潜在优势但依赖挑边策略先写死（本轮仍缺），丙′多背一笔矛盾收口的前置账 | 见 4.4 节表内各行 |

**交用户时的建议摆法**：与第二轮 Sonnet 报告的结尾一致——按这一轮补齐的证据，丙-区间在四项判据上都不劣于另两条，且它唯一的额外机制（`hi` 字段）是可以脱离模型独立证明的收严，风险最低；如果用户不接受「级联维护协议换成边界位移」这处做法（第二轮已指出的、丙-区间相对丙原始点匹配定义的另一处实质改变），退路是乙，但要先在这一轮把「挑边策略」写死，不能继续留白；丙′相对丙-区间已经没有任何 U2/U3 优势，它唯一还没被证伪的价值仍然是第二轮已经指出的「概念更保守、维护逻辑更接近乙」这个未量化的说法，且这一轮又多发现它要求先解决一对已有矛盾——除非用户有独立理由偏好这种保守形态，丙′在四条判据上都排在丙-区间之后。
