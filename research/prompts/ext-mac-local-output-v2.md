A counterexample exists for R4 verification when encryption is on. The checker must verify that a pointer inside the extension point targets allocated space, but when encryption is active, the entire unit (including the extension point) is ciphertext. The keyless checker cannot read the extension point's contents due to encryption. Since the pointer's value is stored within the encrypted extension point, the checker cannot access it to check if the target range is allocated. This violates R4's requirement, as the checker cannot perform this verification without the key. The candidate conclusion's assumption that the whole-unit MAC and per-location checksum cover the extension point is irrelevant here—integrity detection (via checksum) does not resolve the inability to read the pointer's value for allocation checks. This is a pre-existing hole created by encrypting the extension point, not a new issue from the candidate conclusion. R4's verification is impossible under encryption, regardless of checksum coverage.
