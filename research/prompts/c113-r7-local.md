Background (settled, verified by the asker): units are the on-disk objects. Code 1 units are data units written by the transaction itself, before its journal record; their header carries a five-tuple identity, a birth checkpoint number and a 10 byte write sequence (instance id, transaction number). Code 2 units are B-tree nodes and code 3 units are packed record containers; both are written only at the fixed point of a checkpoint (once per checkpoint per instance) and carry the instance id and the birth checkpoint. Every publish increments the checkpoint number by one. Persistent order per publish: units, barrier, journal records, barrier, root slot. The root ring keeps the last K root records. Recovery picks the newest readable root that passes its self check, then applies journal records after that root's tail in strictly consecutive sequence order and stops at the first gap. Each writable mount, and each instance switch, takes a fresh instance id. Transaction numbers are per instance and monotonic; records are appended in transaction number order. Journal records are reclaimed only after their checkpoint has been published.

The seventh version of the fix for C113 (after a scan that lost the indexes, several readable units with the same logical key exist and nothing says which is current or whether a unit was ever published):

P1. Failure table, closed, four cells. (1) Failure before taking a number: nothing. (2) After taking a number but before any unit write request was issued: the number is burned. (3) After a unit write was issued: a single replica failure retries elsewhere with the same write sequence under a wall clock budget T_retry; if the budget is exhausted or any other transaction level failure happens: instance switch. (4) Fixed point or publish stage failure (allocation failure, fixed point does not converge, root slot write fails): instance switch. Instance switch means a recovery performed inside the running mount: take a new instance id, write a row (old instance, last published checkpoint, last applied transaction number), reissue the in-flight checkpoint; transactions with number at most W keep their effects (their records are appended), transactions above W are redone under the new write sequence (their data units rewritten) or fail back to callers that have not returned; all fixed point units are rewritten under the new instance. The reason the checkpoint cannot simply be abandoned under the same instance: the current instance has no row, so its units are judged only by birth at most mounted root checkpoint, and reissuing the same number would publish the orphans.

P2. Instance table: code 3 container, record type 4, rows (instance id, T_pub, W). At recovery T_pub is the checkpoint number of the chosen root (normally the newest published one; if the newest root slot is unreadable the recovery falls back one root) and W is the largest transaction number applied by contiguous replay from that root's tail (nothing applied means W = 0). Rollback writes (r_old, T_old, 0) and (i, 0, 0) for intermediate instances. Published predicate for a unit (i, n) with birth b: if i is less than the mounted instance: no row means published; a row means, for code 1, b at most T_pub or n at most W; for code 2 and 3, b at most T_pub. If i equals the mounted instance: b at most the mounted root checkpoint. Larger: corrupt. Row reclaim requires that a full sweep pass reached a verdict for every location that instance wrote (read succeeded and judged by the row, or already erased, or already overwritten) with no unpublished unit among them and no read failure during that pass, all devices online, and no root of that instance in the ring. If the table is unreadable the mount is read-only and rebuild stops at level 1. The instance table unit itself is not judged by this predicate; the root record's physical pointer determines its current version. Writable mount admission: enough writable devices, exclusive open of a majority of the pool's devices, instance table readable; then the new id = max(ids in visible superblocks, ids in ring roots) plus 1 is written to every visible superblock all or nothing (any failure means read-only mount); only then units are touched. Invariant: all visible superblocks carry the same instance id.

P3. Current version rule: replica merge for code 1 and 3; Visible_R(u) = published(u) and u.birth at most T_R and an ancestry entry (a, c) for the tree of R with u.writer tree = a and u.birth at most c; v* is the visible candidate with the largest write sequence for code 1, or the largest (birth, instance) for code 3; current is dead if a visible tombstone names the key with a death write sequence at least v*'s. Rollback candidates: ring roots valid per the instance table.

P4. A location is released when it enters the defer queue, that is when no root including snapshots references it (snapshot referenced locations go to the deadlist and are released only when the snapshot is destroyed). The allocation record entry becomes (released, release checkpoint) in the same publish as the COW that released it (the allocation record is a COW tree under the root). Sweep admission: not in the allocator in-flight overlay and header readable; with an entry: marked released and release checkpoint at most the oldest ring root checkpoint; without an entry: write sequence instance below the current instance and unpublished by P2.

P6. Type 1 (tombstone) containers belong to the writing tree: before a snapshot is published the open tombstone container is closed and written out; a clone does not take the origin's type 1 containers into its own container index; only the owning tree rewrites them at reclaim; other heads read them through the ancestry table during rebuild; a clone's type 1 container numbers start at 1 per tree and identities differ by birth tree. Therefore type 1 containers are never modified across heads and rebirth applies only to type 2 (inode leaf) containers: on first cross-head modification the container is reborn as (clone tree, type 2, original container number, current checkpoint) with a retirement record for the old identity.
