# E97 三方论证 第三轮：两轮之后的提案

**前两轮各打掉一块，实验都改了并重跑（判据 1..8 一个字没动，只加了 9 / 10 并改正判据 8 的口径）。**

- 第一轮（反推腿）：拿 D18（块里携带什么信息） 已定项 9「索引节点对齐 16384」
  证伪「按 32 KiB 单元号编码落点」。
- 第二轮（反推腿）：① 判据 8 的回绕期用错了口径——D5（快照 / 空间记账机制） 已定项 2 的骑手条款
  逐字「代按发布走，不按 5 秒窗口走」「代段宽度 ≥ 48 位」，正确口径就在被引条款正上方，
  第一版差约 14000 倍，而「≥48 位」本就是已定条款；② 段清单漏了 D8（核心索引结构）
  write buffer 硬要求 3 的 `seq`，而判据 2 对没列出来的段天然失明；
  ③ 预算要按脏的 16 KiB 节点算，按条目字节算是系统性低估；④ 提案采纳的编码没有一条臂。
  同一腿开出的「一单元一条 + 1 字节跨度段」替代，补跑之后**在两个轴上严格更好**。

**别重复**。这一轮要问的是：这些字段一旦写进盘上格式就删不掉，那么——

## 两轮之后的提案

**A. 记账 key 与条目**

| 段 | 取值 | 依据强度 |
|---|---|---|
| 统计量类型标签 | 2 字节 | 自由选择（1 字节今天够，取 2 留余量）|
| 树 ID | 8 字节 | 自由选择，上界指不到任何已定条款 |
| 设备 ID | **不在这里定**，去 D19（块指针的结构与宽度预算） 新开分项，与位置条目一起定 | 全仓「dev 1 字节」没有决策出处 |
| 代 | 8 字节完整 checkpoint 号，不取模 | **已定条款**：D5（快照 / 空间记账机制） 已定项 2 骑手条款「≥ 48 位」；E97 复现了它（模 2³² 17 天、模 2⁴⁸ 3204 年）|
| 完整值 | 8 字节 | 统计量是字节计数 |
| **`seq`** | **仍未定** | D8（核心索引结构） write buffer 硬要求 3 要求它存在，宽度 / 住 key 还是 value / 跨挂载单不单调，三问都没答 |

「哪几个统计量带树维」取**窄读**：宽读在 t=8192 / d=64 那格连 value 都装不下；
换成脏节点口径后宽读又多两格过界，窄读四格全过（最紧占预算 53%）。

**B. 分配记录条目**：`dev + 6 字节 16 KiB 槽号 + 1 字节跨度段 + 8 字节代 = dev + 15`，
**一条记一个单元**（不是一条记一个 16 KiB 槽）。

| 轴 | 一槽一条（15+dev）| **一单元一条 + 跨度段（16+dev）** |
|---|---|---|
| 每设备寻址 | 4 EiB | 4 EiB |
| 非 16K 对齐起点可表示 | 0 | 0 |
| **半个数据单元可表示** | **是** | **否** |
| 16 TiB 条目数 | 966 367 641 | **483 183 820** |
| 16 TiB 占容量 | 830 ppm | **442 ppm** |
| 树高 | 4 | 4 |

**C. 顺带钉住 / 顺带立项的**
1. 位置条目的偏移段也变成 **16 KiB 槽号**（D3（空间分配） 已定项 3 依据逐字要求同一个坐标系）。
   宽度仍 6 字节 ⇒ **若设备 ID 仍是 1 字节**，位置条目仍 11 字节、树表单元指针仍 53、根记录仍 121。
2. 「落点粒度」此前没有任何分项号，这次要单独立项。
3. D19（块指针的结构与宽度预算） 要新开一条「位置条目各段的宽度」分项（现在是半定，
   而 D22（单元原子性怎么合成） 已定项 7 的 53 字节已经在消费一个没定过的数）。
