## 一、模型与口径

**被测对象**：`research/prompts/c245-r1-opus-model/model.py`（只用 Python std，确定性计数模型，零文件操作）。
同一输入跑 N 遍结果必然相同，所以轮数不是证据；证据强度来自判别力自证（`selftest.txt` 六行：三处注入的毛病各自由 0 转正、两条不注入的基线是 0、TRUST_TAIL 阳性对照非零）与钉死的状态数（每个录制流的崩溃状态数与闭式 1 + Σ(2^n − 1) 逐个相等，`closed_form_ok` 行）。

**几何（模型取小，让回绕、根槽轮转、块重用进得了枚举）**：journal 环 12 槽、F = 3 ⇒ 在飞上限 N = 4；根环 R = 3 区域 × S = 2 槽；单元落点 16 个；两块盘，journal 与单元按任一份自证过即算在折成一份（D23 已定项 14 索引行末尾那一句，`decisions/23-journal的角色与格式.md:691`，只指路不抄），超级块逐盘两槽、世代号逐盘 + 1。

**写路径**（D16 已定项 7 的持久顺序）：单元 → 屏障 → 记录 → 屏障 → 根槽 FUA → 超级块槽 × 2（甲）。空发布开头带一道屏障（与 E142 的段序列同形）。切段照 D13 已定项 4：屏障与 FUA 切段、段内任意整写子集。
一次发布 = 一个事务（1 或 2 条记录，提交标记在最后一条），所以「整体施加」由提交标记给出；多事务发布的边界怎么判不在模型里。
取号 = max(超级块, 根环) + 1，先写进每一份超级块；tail 照抄择到的超级块（字节表 a1 的写法）。新实例第一次发布的 txg 按 CJ2。暖机两次空发布。
分配：环里读得出的根引用的单元不复用（`decisions/16-发布语义.md:371` 整行：`| 可再分配 | 已释放 ∧ 释放代 ≤ max(F_生效, 环里最旧有效根) |`；模型里 F 不动）；回退从 R_old 的账载入，影子账按 `decisions/23-journal的角色与格式.md:1209` 的窄读法隔离：比 R_old 新的可读根引用、而 R_old 那棵账不引用的落点。

**恢复**（六条口径里模型碰得到的五条）：择根 = 可读根里 (txg, 实例代号) 最大；全环扫描；同实例严格连续、跨实例即停；(实例代号, checkpoint_txg) 大于根的水位；提交标记齐全才施加；施加前验证点名单元，不过即停；回退行 W 截断；前缀最多 N 条。
各实现只在两处不同：**链首从哪接**、**下一次写接的计数器**。清单与各自的定义在 `model.py` 文件头，这里只列要紧的：

| 名字 | 是哪条臂 | 链首 | 超级块 tail 读来做什么 |
|---|---|---|---|
| ORACLE | 条款真值（不是臂：它读模型真值「所选根覆盖到的计数器」，盘上今天没有；等价于根记录带这个计数器） | 真值 + 1 | 不读 |
| JIA_LITERAL | 甲，照前提七字面：tail 只是扫描起点的优化 | 环里读得出的同实例、txg ≤ 根的最大计数器 + 1 | 只决定扫描次序 |

### 3.3 阳性对照：模型分得出 tail 的取值
