# D8 未定项 6 的定案提案（第一版，2026-09-05，等三方论证核）

**要定的**：D8（核心索引结构）未定项 6——inode 记录的盘上字段表，及其前置「选路」：
路 ①（记录打包进 D18 已定项 11 的码 3 容器、inode 树按身份引用、容器索引持物理指针）还是
路 ②（D21 权威态清单扩项：inode 记录是权威态，住 inode 树的叶）。**提案是推论，先过三方论证再进正文。**

## 二、提案

### P1 选路 ②：inode 树是住在树里的权威态，照记账树的先例

**权威态清单扩一项：权威态 = 单元 + 记账 + inode 记录 + 根。** inode 记录住 inode 树的叶，inode 树整棵是权威态树，
形态与记账树相同（F6）：COW 挂父指针下、节点带 key 区间、正常路径从根下去、索引丢了时按树的种类**抢救**而不是**重建**。

**为什么不是路 ①**：
- 路 ① 的全部收益是「不扩权威态清单」，但它同时立了一棵容器索引（C103 无落点）、多一次 32 KiB 单元读、单次更新贵 1.25–1.5 倍（F5）、
  容器每次发布重写一次（C105）、爆炸半径 233 对 116（F4）。
- 而「不扩项」买到的东西在这里是空的：F1 的判据逐字说不能重算的东西**必须**扩项——路 ① 只是把扩项换了个名字（码 3 容器本来就是「单元」，权威态第一项），
  它没有让 inode 记录变得可重算。
- 仓里已经有一个「住在树里的权威态」——记账（F6）。路 ② 不新造机制，把 inode 树按记账树的先例处理。

**为什么路 ② 不撞硬约束 6**：硬约束 6 的对象是「可重建的容器」（F2）。inode 树按本项是权威态，**不是可重建的容器**，
「索引可从单元重建」这句对它不成立也不需要成立——就像它对记账树不成立一样。E98 判「住索引叶触发硬约束 6」的前提是
「索引节点是派生态」，本项改的正是这个前提（对 inode 树这一棵）。

**代价照实记**：
- D21 那句「索引是派生态」改成「索引是派生态；记账树与 inode 树是住在树里的权威态，节点带 key 区间、丢了不是慢而是丢数据」。
- inode 树的每片叶都是权威态 ⇒ 永久损失 116 条/叶（F4），C100 照旧；缓解手段与记账树相同（w = 2 副本，D2 已定项 9）。
- 抢救出来的多版节点怎么择现行版本 = C113，与记账树同一格；本项不解它。

### P2 树的种类要落盘：树表条目带「种类」，种类决定态别

F9：树表条目只有 tree_id + 指针，扫描器无从知道哪棵树该抢救、哪棵该重建。**本项要求树表条目带 2 字节「树的种类」**
（extent / inode / dirent / 反向索引 / 空闲空间 / 记账 / 容器索引 …，D8 结构层的枚举），**态别由种类静态决定**：
记账与 inode 是权威态（抢救），其余派生态（重建）。落点在 D22 已定项 7 的树表单元条目；每头一棵树时同一种类有多棵，种类不唯一。
新增种类走 D15「新增一棵 keyspace ⇒ compat」；把一个种类从派生改权威是 D15「改变已有字段含义」⇒ incompat。

### P3 inode 树的节点带 key 区间

把 D18 已定项 2 对记账树的定案扩到 inode 树（key = inode 8 ⇒ 区间字段 16 字节；E73 同型，代价一格以内）。
理由与记账树相同：抢救时一个节点单独捡起来要能自证它该覆盖哪一段 key。dirent 树那一格照旧推迟。

### P4 inode 树的 key：`(inode)` 8 字节，不留判别位

D6 已定项 1 每头一棵树 ⇒ 同一个 inode 在不同头住不同的树，E98 判头判别位没有对象（F8）。`locality_id` 不进 key（它是记录告诉你的东西，进 key 是循环）。
**inode 号分配**：树内最大号 + 1（区间字段在手，O(log N) 最右键查询，与 C103 给容器号的规则同形）；复用由对象出生代判别（F14）。

### P5 记录字段表（定长 160 字节，初值；宽度是本项取值）

| 段 | 字段 | 宽 | 为什么 |
|---|---|---|---|
| 身份 | inode | 8 | 与 key 重复；key 权威、记录只作对照（P6） |
| 身份 | 对象出生代 | 8 | 创建该对象那次发布的 checkpoint_txg；**同时是 inode 号的复用判别子**（F14），与五元组同一字段——F11 的三个「generation」收成两个：对象出生代（本字段）与节点诞生代号（头里） |
| 身份 | locality_id | 8 | F10；第一版无父目录时取 0（保留值，表示无父目录） |
| 属性 | mode / uid / gid / nlink | 4 × 4 = 16 | POSIX 核心 |
| 属性 | size | 8 | 逻辑长度；尾部是洞时扫描给不出它（F4） |
| 属性 | blocks | 8 | 占盘单元数；D4 已定项 2 补齐到 32 KiB ⇒ 从 size 推不出 |
| 属性 | rdev | 8 | 设备节点 |
| 属性 | flags | 8 | 第一版恒 0，非 0 ⇒ 该记录判损坏（EIO），赋义要 incompat——与 F18 单元头 flags 同一政策；属性 keyspace 的存在位日后也走这条 |
| 属性 | atime / mtime / ctime / btime 秒 | 8 × 4 = 32 | 有符号 Unix 秒 |
| 属性 | atime / mtime / ctime / btime 纳秒 | 4 × 4 = 16 | 0..999999999 |
| 属性 | 改动计数 | 8 | 最后一次改动所在发布的 checkpoint_txg；**提交锚 = 叶节点头的诞生代号**（扫描单位是节点，F12）——同一 checkpoint 内多次改动只有最后一版落盘，不需要窗口内序号 |
| 预留 | 预留 | 32 | 全零；非 0 判损坏 |

秒与纳秒分组存放使每个字段自然对齐。字节序：小端，与单元头一致（本项定）。不放 extent 指针（F13 内联阈值 0；数据经 extent 树）。

### P6 三条不变量

1. **身份对照**：记录里的 inode 必须等于 key；不等 ⇒ checker 判红、内核路径 EIO，不许静默修复。
2. **locality 对照**：记录里的 `locality_id` 必须等于该对象每条 extent key 的首段；不等 ⇒ 判红、不许静默修复；
   扫描重建时以记录里的值为准放回数据单元（单元头给 (对象 ID, 锚点偏移)，记录给首段）。这是 F12 说的那条「三方对照」，两侧都在权威态里。
3. **nlink 的 gate**：超级块一个单调 feature 位「dirent 树已上线」；位未置时 checker 不评估「nlink == dirent 条数」，置了之后零豁免。
   第一版写 nlink = 1，那个文件由一个保留 inode 号指认（named-by-construction），不进孤儿回收。

### P8 第一个事务写什么

一个保留 inode 号的文件：inode 树一片叶（16 KiB，头 = 索引节点类身份段 + 区间字段 16，装一条 160 字节记录），
记录 locality_id = 0、nlink = 1、flags = 0、改动计数 = 本次发布的 checkpoint_txg；树表里 inode 树种类 = inode、态别权威。
