1. Path one requires storing preorder and postorder numbers in the unit headers, violating the header constraint that it must name exactly one birth owner and nothing else. If stored elsewhere (e.g., in a derived index), creating a snapshot requires traversing the entire tree to compute these labels for the new snapshot's structure. For a tree with 10,000 nodes, this takes 10,000 operations, breaking the bounded, cheap snapshot creation requirement. No units are rewritten (labels are in a separate index), but the operation time is linear in tree size. Smallest change: avoid using preorder/postorder for snapshot creation; instead, use a structure that doesn't require full traversal.

2. Path two's indirection layer allows silent data corruption if the layer isn't updated before the old physical slot is overwritten. Steps: 1) Unit X at slot A. 2) Defragmentation moves X to slot B. 3) Before updating indirection layer, slot A is overwritten with new data Y. 4) Reader follows pointer to A, checks indirection layer (still A→A), reads Y instead of X. Smallest extra field: a checksum in the indirection layer entry. Reader compares it with data read from the new location to detect mismatches.

3. Path three requires writing one new unit per sharing relationship when creating a snapshot. For a tree with 1 million references to shared units, 1 million new units must be written. This is O(n) where n is the number of references, violating the bounded, cheap snapshot creation requirement. Smallest change: store references directly in parent units instead of separate sharing units.
