## 三、定案

### P1 单元头带「写序」= (实例代号 4, 事务号低 48 位)

每个单元的类身份段加 10 字节写序。事务号是 D23 已定项 7 记录头里的 8 字节字段：按实例计数、从 1 起、高 16 位恒 0；提交标记 1 字节；记录头增量 9 与五处实验常量不动。jsn 按记录递增、事务号按事务递增，是两个计数；同一事务的全部记录共享事务号。
**写序取谁的号，按单元类分**：码 1 = 写出它的那个事务；码 2 / 3 只在 checkpoint 的固定点写出，一个版本合并了多个事务的效果，写序 = (实例代号, 那次 checkpoint 里已分配的最大事务号)。判定（P2）对码 2 / 3 只用实例代号与诞生代号，事务号那 6 字节在码 2 / 3 上只保证 I-1.8 的全序。
住类身份段不住共同前缀：码 1 与五元组、诞生代号同列（明文）；码 2 / 3 与诞生代号同待遇（加密开启后进密文）。

**取号纪律**：
1. **取号 = 事务被分配进某个 checkpoint 那一刻**，同时钉死它的 checkpoint 号，诞生代号由此写得出。切分只关闭成员资格：触发之后不再分配事务进这个 checkpoint，已分配的事务把各自的单元写完；发布阶段等全部单元落盘。这是 D16 新规则 1「快照发布点钉在这个 checkpoint 全部数据变更之后」的可执行形态。
2. **事务切分纪律**：一次写请求按单元切成若干事务各自取号 ⇒ 一个事务最多写一个单元的用户数据。子事务的数据 key 各不相同；它们共同改的那条 inode 记录住码 3 容器，在固定点合成一个版本，不产生同 key 多版。同一 checkpoint 里两次 write() 覆写同一偏移会产生同 key 两版，靠写序定序（这是 `no_wseq` 臂歧义的那一格，频率 = 一个 checkpoint 窗口内的重复覆写数）。**与 ZFS 的差异**（现查 `zfs_vnops.c:780` 的循环）：ZFS 把一次 write() 切成每个记录块一个 dmu_tx，本工程的事务是应用可见的原子单元。**崩溃原子性的单位由此是一个单元，不是一次写请求**——仓里没有任何决策承诺过写请求级原子性，这是一次对外语义的收缩，记进 D23 已定项 14 的注。
3. **丢失窗口的口径**（改 D16 已定项 5，待用户复核）：单元写的重试预算是墙钟 T_retry（具名可调参数，不是格式常量；超过即实例结束）⇒ 崩溃最多丢的是 **T_time + T_retry**，不再恰是 5 秒。E70 的下界不受影响。在飞 checkpoint 深度 = 开放 + 发布中两个；并发 fsync 的返回时刻被同 checkpoint 的其他事务拖住是组提交固有的代价。
4. **记录按事务号顺序追加**；事务号 N 的记录追加之前，< N 的事务全部已追加 ∨ 已作废（② 的作废）∨ 已确定实例结束。D13 已定项 2 第一版串行提交下这一条空转，是对将来并行提交的前置约束。
5. **失败表（封闭）**：① 取号之前失败 ⇒ 无事；② 取号之后、**尚未向设备发出任何单元写请求**时失败 ⇒ 号作废，不写单元不追加记录（事务号留洞无害：洞上没有单元）；③ 发出过任一单元写请求之后：单副本写失败 ⇒ 换落点重试、写序不变，预算 T_retry；预算用尽或别的事务级失败 ⇒ **实例结束**——转只读、号更大的事务的记录一条都不追加，下次挂载走恢复并写行。准入在取号前做完（`.claude/rules/fs-design.md`「进门前先算最坏情况」），所以 ③ 里不存在准入拒绝。**没有作废行**：③ 之后不追加更大的号，恢复行的 W 就是精确的前缀，不需要第二种记录来表达洞。
6. **W1**：一个事务对一个逻辑 key 至多留一种净效果；未点名的单元允许原地重写或不点名；写序相等且不是副本时墓碑赢。

**10 字节买三件事**（不变）：同 key 已发布版本定序；分辨崩溃前后时间线；在飞 checkpoint 被部分重放时分开同实例同 txg 的已施加与被抛弃（`inst_only` 臂在 crash 世界复活 6）。
**与唯一先例的差异**、**重开两句已定**：同第五版。

### P2 实例表（码 3 打包记录类型 4）；实例代号

**实例表单元**：码 3 打包记录单元，打包记录类型 4，记录宽 64，两种记录按首字节 kind 分：
- kind 0 行记录：`kind 1 | 实例代号 4 | 最后发布的 txg T_pub 8 | 在飞 txg 里最后施加的事务号 W 8 | 预留 43`；
- kind 1 链指针记录（恒为一片的最后一条）：`kind 1 | 有无下一片 1 | 位置指针 59（无下一片时清零占位）| 预留 3`。
四元组、持有方式、片容量 510、mkfs 空表（记录数 1）同第五版。根记录加实例表单元指针 59：127 → **186**，512 槽余 326。COW 重写：每次写行重写整条链，行只在恢复与回退时写（不在正常发布路径上）；非 zoned 上 n 由行回收压住，zoned 第一版不回收、链长无上界（第一版不跑 zoned，C121）。

**行怎么写**：按实例代号唯一，后写覆盖。
- 任何非干净结束的实例在下次恢复写行：给 [所选根的实例, 新实例) 每个实例写 (i, 在飞 txg − 1, 重放施加的最大事务号)，一条都没施加的写 (i, 在飞 txg − 1, 0)；
- 回退：写 (r_old, T_old, 0) 与中间实例的 (i, 0, 0)；
- 全部与恢复 / 回退的第一个新根同一次发布写出。
**回收**：kind 0 行可删当且仅当整轮清扫确认盘上不再有该实例按行判未发布的可读单元 ∧ 全部设备在线 ∧ **根环里没有该实例发布的根**（被抛弃的根留在环里时，它的行是回退候选判据的输入）。
**表不可读时**：只读挂载；扫描重建停在级 1。

**已发布谓词（全局）**：i_now = 挂载根的实例；单元写序 (i, n)、诞生代号 b、类 c：
- i < i_now：无行 ⇒ 已发布；有行 (i, T_pub, W)：c = 码 1 ⇒ b ≤ T_pub ∨ (b = T_pub + 1 ∧ n ≤ W)；c = 码 2 / 3 ⇒ b ≤ T_pub（一个没发布的 checkpoint 的固定点单元一律未发布，恢复实例会重写它们）；
- i == i_now：b ≤ 挂载根的 txg；
- i > i_now：判损坏。
**射程**：「无行 ⇒ 已发布」只对同一时间线成立。

**实例代号**：住超级块（E100 段四那 4 字节）。可写挂载的顺序：① 判定本次能不能可写（可写设备数 ≥ w 的下限；表可读）；② 新代号 = max(全部可见超级块的代号, 根环里全部根记录的实例代号) + 1，写进全部可见超级块；③ 之后才动任何单元。只读挂载不取号。
- **前提（写下来）**：同一时刻只有一个可写挂载，由块设备独占打开保证。两个并发可写挂载会算出同一个 max + 1，谓词的三支分不出它们（第五轮反推腿 7.3）；多主机共享存储不防，随 D9 已定项 8 那一类宣布。第五轮反推腿 7.3 提的超级块「持有位」不采纳：崩溃之后持有位留在盘上、代号是自己的，盘上状态分不出「上一次没干净收尾」与「另一个可写挂载还在」，拒绝会把崩溃后的合法挂载永远拒掉（第六轮本地腿 4 打中），而「没干净收尾」这件事恢复路径本来就判得出。
- **射程**：取号那一刻两路见证不完整可见时不额外拦截，与整卷回滚同格，随 D9 已定项 8 宣布不防；I-7.6 只在 devs ≥ R 时让根环成为独立见证，第一版 (R = 3, devs = 2) 不成立。
- **分叉盘**：第一版 2 盘、掉一块只能只读挂载 ⇒ 不可达；D2 已定项 3 / 4 允许在线加盘 ⇒ 第三块盘一加就可达。**C120（分叉盘回归的判定与重同步）在允许加第三块盘之前到期**，候选判据是每盘超级块记「这块盘见过的最大 (实例代号, txg)」并要求它在当前根环里找得到对应的根。

### P4 垃圾清扫

**「释放」的口径**：一个落点被释放 = 分配器把它放进 defer 队列那一刻 = 没有任何根（含快照）引用它；被快照引用的落点按 D5 的 deadlist 纪律进 deadlist、不进 defer，快照销毁时才释放 ⇒ 释放代 > 最后一个引用它的根被销毁的代。分配记录条目在释放时不删，改写成「已释放 + 释放代」（标志位借跨度段最高位），留到落点被重新分配时覆盖。
**准入**：两支共有的合取 = 不在分配器在飞 overlay 里 ∧ 头可读；再分支——有条目：标已释放 ∧ 释放代 ≤ 环里最旧根的 checkpoint_txg（由释放的口径，此时环里没有根还引用它；单元属于哪个实例无关，当前实例自己释放的落点也要能清，否则一次挂载活多久就漏多久）；孤儿（没有条目）：头里的写序实例 < 当前实例 ∧ 按 P2 谓词未发布（当前实例没有行，它的孤儿只能是在飞的写，交给 overlay 那一条）。第六轮 Sonnet 审计核出第五版把「写序实例 < 当前实例」写成了两支共有，与 E104 的 `sweep_candidates` 不一致，按模型改正文。清扫水位只推进到「环里最旧根的 txg」，只在整轮完成时推进。
E74 的判据 1「条目数恰好等于已分配落点数」在新口径下按定义为假，改成「条目数 == 曾分配过、尚未被覆盖的落点数」后重跑取新的绝对值（C122）。其余同第五版（第二个 pass、rebuilt 永久只读、第 13 / 14 项统计量）。

### P5 / P6

同第五版，一处改动：**重生的新身份 = (本头树 ID, 类型 2, 原容器号, 本次发布代号)**——保留容器号，只换出生树与出生代。取「最小 inode 号」当容器号时，同一 txg 里「合并退役 (t, 2, 5, T)」之后左邻重生又得到 (t, 2, 5, T)，退役记录把新身份一起杀掉（E104 mixed_w2 seed=5，神谕臂也丢 1）。容器号是 inode 号、树内不复用，保留它不破「记录号 ≥ 容器号」，树内唯一性由 origin 的唯一性继承。

### P8 E104 / E105

## 五、对立臂的判决（第二次重写）

**臂 B**：写序只上码 2 / 3；数据单元头不动；extent 树的叶改成码 3 打包记录单元；数据 extent 顺着重建出来的 extent 树到达。

**两个量出来的数，各说到哪一步**：
1. E104 `wseq_meta_only` 臂量的是 **extent 叶丢失之后** 数据单元靠自己的头能不能判——不是完整的臂 B。那一格上崩溃 / 回退各世界的数据孤儿全部复活（crash 6、crash_double 7、crash_clean 6、txn_fail 4、rollback 3、rollback_after_crash 6），同 txg 世界歧义 4 + 复活 1。叶完好时臂 B 的数据判定 = 叶的版本判定 = 码 3 的规则 ⇒ 与全规则臂同为 0，这是结构推论，没有建臂。叶丢失的概率 p 没有量。
2. E105：extent 叶改码 3 让单次更新与点查的字节比 = 1 + 1/树高（1.5 / 1.333 / 1.25），乙矮一层的区段（对数轴上 13.2% 的 N）恒 1.000 且点查少读一个节点；批量散开更新 1.44–1.78×；比值 ≥ 1 无例外。

**判决：取臂 A（写序上全部三类）。理由改成两条不依赖 p 的**：
- **态别**：臂 B 把 extent 叶变成权威态（叶丢了那段数据的版本判定就没了），D21 的「索引（树）是派生态、丢了只是慢」要开例外；臂 A 让全部索引仍是派生态，任何索引节点丢失都能从单元头重建。这是本工程「全盘扫描重建」那条底线（`.claude/rules/fs-design.md`「元数据块必须自描述」）的直接形态，不是概率论证。
- **代价**：臂 A 的价钱是每个数据单元与墓碑 +10 字节、I-6.2 白名单加两项（写序、载荷 CRC）；臂 B 的价钱是最热的树 1.00–1.78× 的写放大外加一条格式分支。两边都量了，量出来的不是同一维度的数，判决靠第一条。
**什么会推翻它**：量出 p 之后，若用户接受「叶双毁 = 那段数据不可判」与 D21 的例外，臂 B 的写代价在等高段上不比 A 差——那时要重开。
