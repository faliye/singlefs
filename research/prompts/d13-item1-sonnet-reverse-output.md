## 二、臂 B（一次发布的原子性）的反推观测

### 观测 B1：D13 已定项 4 定义的崩溃状态集合，到底是「规范」还是「模型」——这决定了材料问题 2 的答案

**假设**：若 D13 已定项 4 真的是 crash refinement 右边那个「规范允许的集合」，它自己的正文不应该出现「这只是模型层的东西，不是正确性判据」这类射程限定。

`.claude/kb/decisions/13-验证路线.md:296-297`（已定项 4 正文自带的射程条款）逐字：

> ⚠️ **射程**：它定义的是**模型层的枚举域**。真实设备的 FLUSH / FUA 是否如宣称生效归 C6（块层语义假设写错），
> 要在 QEMU 里用真设备验；设备把一次写撕成恰好撞上校验和碰撞的形态不在模型内。

**结果：出现，而且是决定性的**。已定项 4 自称定义的是「模型层的枚举域」——即**给定一个真实的写请求流，
枚举它可能崩溃在哪些状态**，这是崩溃点重放（测试型）的输入域定义，回答的是「哪些磁盘状态可能出现」。
crash refinement（Yggdrasil 式）右边要的是「哪些磁盘状态**被规范允许**」——这是一个正确性谓词，
不是一个可达性枚举。**两者不是同一个东西**：前者关心「实现会不会走到这里」，后者关心「走到这里算不算对」。
一个显然的证据：已定项 4 的正文里没有出现任何形式的「合法/非法」判定，只有「哪个位置放旧字节」「怎么生成镜像」——
它是喂给 checker 的**输入构造规则**，不是 checker 本身要判的**谓词**。

⇒ **材料问题 2 那句「臂 B 与臂 C 的规范右边已经由 D13 已定项 4 定死了」不准确**——它把材料自己在
第七节射程注里已经写明的「模型层枚举域」读成了「规范」。真正能充当 crash refinement 右边规范的，
是 [invariants.md](../../.claude/kb/invariants.md) 里的 I-4.x（臂 B）/ I-7.x（臂 C）系列——这些是状态谓词，
是不变量，不是崩溃状态的枚举规则。而 I-4.x 与 I-6.5 一样，**都还没有被写成任何形式化语言**，都要「另建」。

⇒ **材料问题 2 给的两个不对称是假的**：臂 A 与臂 B / C 在「规范要不要另建」这件事上处于**同一起跑线**——
I-6.5 与 I-4.x / I-7.x 都是已经写在 invariants.md 里的自然语言不变量，都还没有被翻译成 Z3/符号执行能吃的形式。
真正的不对称不在「规范现成与否」，在**观测 A2 揭示的那条**：I-4.x / I-7.x 已经排进 v1 checker 的覆盖范围，
I-6.x 整类被挡到加密开启之后。

### 观测 B2：臂 B 的 spec 是否会与 O1（RefFS 模型对拍）同源——这是材料冲突 2 点名要查的

**假设**：若臂 B 的 spec 与 RefFS 的崩溃语义模型是「同一个东西的两种写法」，D13 已定项 3（RefFS 做到极致）
的正文里应该已经出现与「持久顺序/崩溃状态」高度重合的表述。

`.claude/kb/decisions/13-验证路线.md`（已定项 3 正文）逐字：

> **不做只管功能的内存模型，做一个自己处理持久化与崩溃语义的参照实现。**
>
> ⚠️ **它同时改变 D13（验证路线） 三个 oracle 的关系**：O1（内存模型对拍（HashMap 理想文件系统））原本只答功能正确性，
> 现在 RefFS 要覆盖持久性 ⇒ 「三 oracle 合谋测试」防的那个**共同误解**，
> 其最危险的落点从「三份 replay 实现是否一致」挪到
> 「**RefFS 与实现是否共享同一个崩溃语义的错误理解**」。⇒ 两者不许共用崩溃点枚举的那段代码。

**结果：出现，方向对臂 B 不利**。RefFS「自己处理持久化与崩溃语义」——这与臂 B 要形式化的「持久顺序 + 崩溃状态集合」
是**同一个题目**：什么算持久、崩溃后能恢复出什么状态。条款自己都要求「两者不许共用崩溃点枚举的那段代码」，
这恰恰是因为写的人清楚这两样天然长得像。⇒ **臂 B 在冲突 2（spec 与 model 同源）上的风险是三条臂里最高的**，
因为它与 RefFS 的重叠不是「都会用到某个共享工具函数」这种表层重叠，是**题目本身重叠**。

### 观测 B3：臂 B 的规范是否真的能避开 D8（三层绑架）——这决定它是不是变相在验「整个事务层」

**假设**：若臂 B 的 I-4.x 不需要触碰树遍历/指针语义，它应该可以把节点当不透明的校验和容器处理；
若它需要真正的「遍历完整」判定，就可能重新绊上 D13 连锁表里 D8 那一行点名的三层绑架。

`.claude/kb/invariants.md:145` I-4.1 逐字：

> | I-4.1 | 重放后树可遍历 | 任一崩溃点重放后，超级块指向的树全部可完整遍历 | 未实现 |

`.claude/kb/decisions/13-验证路线.md:372` D8 那一行逐字：

> | D8（核心索引结构） | 日志结构节点、write buffer、key cache 三层都会绑架符号执行（循环上界、滞后窗口、缓存一致性），使「Yggdrasil 一分钟内」的口径在本工程不成立 |

**结果：部分出现，是个真实但可控的风险**。「可完整遍历」只需要「父指针 → 子节点校验和匹配」这一层语义，
这与 D13 已定项 4 已经在用的「有父指针的单元，校验和住在父指针里」（同已定项 4 引用 D4（校验和位置）已定项 1）
是同一个抽象层级——**可以把节点当不透明的带校验和的 blob 处理，不需要理解 write buffer 的合并逻辑、
key cache 的一致性窗口**。D8 那一行点名的复杂性（循环上界、滞后窗口、缓存一致性）属于**节点内部的合并/缓存机制**，
不属于「指针链是否完整、校验和是否匹配」这层。⇒ **臂 B 结构上可以避开 D8 的复杂性，但不是自动的**——
它依赖写 spec 的人守住「只到指针+校验和这一层，不到节点内部语义」这条边界；仓里没有任何机制强制这条边界，
一旦 spec 顺手多写一句「而且这棵树的 key 分布符合 B+ 树性质」，就滑回了 D8 的射程。这是**纪律风险，不是结构性风险**——
与臂 C「结构上不可能碰到 btree」不同档。

### 观测 B4：D13 未定项 1 本身是否点名「不要拿整个事务层去试」，而臂 B 是否已经很接近整个事务层

`.claude/kb/decisions/13-验证路线.md:340` 未定项 1 逐字：

> | 1 | crash refinement 先验哪一块 | **不要拿整个事务层去试**。候选：把 I-6.5（nonce 水位单调） 在任意崩溃-恢复序列下形式化——它只涉及水位变量与恢复路径，**不碰 btree 节点内部**，绕开日志结构节点 / write buffer / key cache 对符号执行的全部绑架。改第一个事务的字节：否（2026-09-01，依据：选哪条性质先做形式化，落点是验证工程，一个盘上字节都不产生）。 状态：**未定** |

**结果：出现，对臂 B 是个真实但不致命的提醒**。臂 B 覆盖 D16 已定项 7 定义的完整发布协议（单元 → 屏障 → journal
记录 → 屏障 → 根槽），这已经是 CLAUDE.md「第一个可运行目标」的核心内容，比「整个事务层」窄（不含目录、
快照、加密），但比臂 A / C 都宽——它是三条臂里唯一同时涉及「多种单元类型的持久顺序」与「journal 记录语义」的一条。
这不构成「臂 B 就是整个事务层」，但支持「臂 B 的验证工程量显著大于 A / C」这个判断。

## 三、臂 C（根环择新）的反推观测

### 观测 C1：根环择新是否真的能证明是臂 B 的严格子集——材料明确要求核这一条

**假设**：若臂 C 不是臂 B 的子集，「根环择新」应该在恢复流程之外独立生效，B 的规范（发布持久顺序 + 崩溃状态判定）

## 五、排序与翻转条件

**排序：C（根环择新）> B（一次发布的原子性）> A（nonce 水位单调）。**

依据（不重复上面的观测，只归纳）：
- A 被三条独立证据同时打中：加密整类不在 v1 checker 范围（观测 A2）、目标字段所在的超级块格式是全仓最不稳定的开放循环之一（观测 A3）、代际新鲜性判定与根环/超级块选代问题结构同源却假装能绕开（观测 A4）。
- B 是三条臂里工程量最大、与 O1/RefFS 同源风险最高的一条（观测 B2），且它的复杂度控制依赖纪律而非结构（观测 B3）；但它的规范目标（I-4.x）已在 v1 checker 范围内，且是 CLAUDE.md 明确的第一个里程碑核心。
- C 结构上真正独立于 D8 三层绑架（不像 B 需要靠纪律避开）、目标格式已定且有实测背书（观测 C2）、规范已在 v1 checker 范围（观测 C3，但有 I-7.7/I-7.8 归属细节待钉）、并且是 B 的一个真子集（观测 C1）——选它相当于选了「B 这个更大目标里最先必须成立、且形式化成本最低的那块」。

**什么会让这个排序翻转**：

1. **若 D22 未定项 9（超级块字段表）在选定验证目标之前被定案**，观测 A3 的核心证据消失，A 与 B/C 在「目标格式是否稳定」这一维打平；此时 A2（I-6 类被 v1 checker 跳过）与 A4（新鲜性判定同源）仍然成立，A 的排序不会升到第一，但可能升到与 B 接近。
2. **若有人证明 I-4.1（重放后树可遍历）不需要触碰任何指针/校验和以外的语义**（即观测 B3 的纪律风险可以被结构性地消除，例如把「可遍历」重新定义为纯粹的校验和链完整性），B 与 C 在「D8 绑架风险」上打平，此时 B 优先于 C——因为 B 覆盖的判据更多、更接近项目的第一里程碑目标。
3. **若观测 C4 的质疑被坐实**（即证明根环 48 槽的状态空间用穷举测试已经能达到符号执行同等的置信度，且没有其他理由要为它单独建 Z3 工装），C 应该让位——不是让给 A，而是让给 B 或者「先不做 crash refinement，先把崩溃点重放 harness 建完」。
4. **若 D13 已定项 4「模型不是规范」这条判断本身被推翻**（观测 B1 的核心依据），即找到证据证明该已定项确实同时承担了规范的角色，则材料原来的「B/C 已有规范」优势重新成立，会拉高 B 与 C 相对 A 的排序（但不改变 B 与 C 之间的相对顺序，因为这条对 B、C 是等价的）。

## 六、对排第一的臂（C）的最强反对（第五问）

**状态空间太小，可能不需要建一整套 Z3/符号执行工装就能拿到同等置信度**（即观测 C4）：
R=3、S≤16，根环总槽数上界 48，是一个有限、易穷举的组合空间。项目本来就要建崩溃点重放 harness
（D13 已定项 4 已经在定义枚举域），对 48 个槽的择新逻辑做穷举式的有界模型检查/属性测试，
工程量远小于新建一条 Yggdrasil 式的符号执行流水线。如果崩溃点重放 harness 本身就能把这 48 个槽的
所有崩溃点走一遍并跑 checker 的 I-7 系列，那么再单独为它建符号执行工装，买到的增量置信度
（「证明了所有可能，不只是测过的那些」）在这么小的状态空间上可能微乎其微——crash refinement
真正的价值（Yggdrasil 论文声称的、本仓未核实的「无需人工标注、自动覆盖不可枚举的状态空间」）
恰恰是在**大**状态空间上才体现，而根环择新可能小到穷举就够了。

这条反对**不会把排序推回 A**（A 的三条独立缺陷跟这条无关），但它指向一个观测 C1 之外的可能性：
**先把崩溃点重放 harness 建完、跑一遍 I-7 系列的穷举结果，再决定 crash refinement 的第一个目标要不要是根环**——
如果穷举已经给出了满意的置信度，crash refinement 的第一份投入应该找一个**穷举做不到**的目标，
而「臂 C 是臂 B 的严格子集」这个事实本身提示：**也许真正该选的不是 C，而是 B 减去 C 之后剩下的那部分**
（journal 记录的前缀判定与提交原子性——这部分涉及跨记录的时序推理，比根环的静态比大小更接近
「符号执行才擅长而穷举不擅长」的那类问题）。这是材料没有列出的第四种候选，值得在最终定案前明确排除或纳入。
