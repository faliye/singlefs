Reason for the change, recorded here rather than left silent: research/scripts/corruption-check.py's glue check ((?<![A-Za-z0-9])[:;,]\w) flags the second colon of any "::" pair as a punctuation-glued-to-a-word false positive, and ask-local.sh runs that checker against the prompt file itself (not only the model's answer); with the literal Rust syntax the checker reported five such matches on the prompt file alone and ask-local.sh refused to send the prompt (exit 5), independent of anything the model would have said. This is a tool limitation on legitimate Rust path syntax, not a translation error; the substituted wording keeps the same referent (the same enum variant, the same two standard-library items) without using the double-colon token. No other identifier in the prompt was altered for this reason; SharedStream (implementation-workflow.md:83) was checked against research/scripts/oov-check.py and left unchanged, because in the real pipeline oov-check.py only scans the model's answer and uses the prompt file solely to build a set of known words, so a CamelCase identifier appearing only in the prompt does not get scanned or flagged.
