## 攻击面 1：quiesce（P1 取号纪律 1）

第四版逐字：「**取号 = 事务被分配进某个 checkpoint 那一刻**，同时钉死它的 checkpoint 号……
checkpoint 的切分等齐已分配进它的全部事务（ZFS 的 quiesce 形态）——这是对 D16（发布语义）已定项 5
触发规则的一条约束：触发只是停止再分配事务进本 checkpoint，切分在最后一个已取号事务写完之后。
代价是切分延迟 ≤ 最长的一个在飞事务。」

### 1.1 「代价是切分延迟 ≤ 最长的一个在飞事务」把 5 秒丢失窗口那条用户定案改掉了，而代价表写「—」（打中，本攻击面最重）

**若这条只是「加一条约束」，D16（发布语义）已定项 5 的两个数就都不该动。** 现查已定项 5，
`T_time` = 5 s 的来历不是算出来的，是**丢失窗口本身**：

`.claude/kb/decisions/16-发布语义.md:146-147` 逐字：
「**上界也定了（2026-08-31 用户定案）：崩溃最多允许丢 5 秒的写。**
`∨` 规则里时间那一支就是丢失窗口的执行者 ⇒ **`T_time` ≤ 5 s**。」

「时间那一支就是丢失窗口的执行者」这句话成立的前提是**触发即切分**：`now − 上次 checkpoint ≥ T_time`
一旦为真就发布，于是没落盘的写最多是 5 秒的量。第四版把触发与切分拆成两件事之后，
真实的丢失窗口变成 `T_time + Δ`，Δ = 最后一个已取号事务把它的单元写完所需的时间。
**5 s 不再是丢失窗口，只是丢失窗口的一个分量**，而 Δ 在提案里没有任何上界。

⇒ 这不是「对触发规则的一条约束」，是**把已定项 5 的上界口径重开**：
要么把 `T_time` 下调到 `5 s − Δ_max`（那就要先有 Δ_max，见 1.2），
要么请用户重新定案「丢失窗口是 5 s + 一个在飞事务」。
第四版代价表 D16（发布语义）已定项 5 那一行写的是「切分等齐已取号事务（quiesce）」、
「改第一个事务的字节」栏「—」，**一个字都没提上界口径**。

### 1.2 Δ 的上界写不出来，因为提案从没定义「事务什么时候结束」；而借来的 ZFS 形态，它的界恰恰全在那条定义上（打中）

**若「ZFS 的 quiesce 形态」这个引用成立，ZFS 那边的等待对象与本工程的应当是同一类东西。** 现查本机源码树，不是：

| 处 | 逐字 | 说明 |
|---|---|---|
| `/home/fy5090/code/fs-refs/zfs/module/zfs/txg.c:409-418` | 「Quiesce the transaction group by waiting for everyone to call `txg_rele_to_sync()` for their open transaction handles.」`while (tc->tc_count[g] != 0) cv_wait(...)` | 等的是 `tc_count` 归零 |
| `/home/fy5090/code/fs-refs/zfs/module/zfs/dmu_tx.c:1466-1467` | `if (tx->tx_anyobj == FALSE) txg_rele_to_sync(&tx->tx_txgh);` 在 `dmu_tx_commit` 里 | 归零的时刻 = `dmu_tx_commit` |
| `/home/fy5090/code/fs-refs/zfs/module/zfs/zfs_vnops.c:780 / 850 / 857 / 1034` | `while (n > 0) { ... dmu_tx_create ... dmu_tx_assign ... dmu_tx_commit ... }` | **一次 `write()` 系统调用被切成每个记录块一个 `dmu_tx`**，不是一个 |

⇒ ZFS 那个 hold 的持有单位是**一个记录块**（`z_max_blksz`，缺省 128 KiB、上限 1 MiB），
**不是应用可见的原子单元**。几 GiB 的一次 `write()` 在 ZFS 里是几千个 `dmu_tx` 依次持有再释放，
`txg_quiesce` 任何时刻最多等一个块。**quiesce 的界完全来自这条切分纪律，不来自 quiesce 本身。**

再看 I/O 在不在 hold 里。ZFS 的普通写路径里不在（`dmu_tx` 只脏化 dbuf，实际写在 `spa_sync` 的
syncing context）；Direct I/O 那条路**在**——`/home/fy5090/code/fs-refs/zfs/module/zfs/dmu_direct.c:233`
逐字 `err = zio_wait(pio);`，参数里带着 `dmu_tx_t *tx`。
**但它照样被 `zfs_vnops.c:780` 那个循环切到了一个块**，所以 Δ 的量级是「一个块的写延迟」。

本工程这一侧，两条纪律把 Δ 顶开：

1. **事务是应用可见的原子单元。** P1 的 W1 逐字「一个事务对一个逻辑 key 至多留一种净效果」，
   D23（journal 的角色与格式）已定项 7 的恢复义务逐字「**丢掉提交标记还没出现的那个事务的全部记录**」
   （`.claude/kb/decisions/23-journal的角色与格式.md:421-424`）——事务就是原子性的单位。
   提案没有任何一句说「实现可以把一次大写切成多个事务」，也没有说事务什么事件算结束。
2. **单元写在事务里，不在切分之后。** P1 逐字「取号之后用户数据单元随时可写」。
   ⇒ 切分要等的不是「脏化完成」，是**这个事务的全部用户数据单元真的落盘**。

⇒ **Δ = 一个事务的全部单元写完的时长**，规模由 W1 与 fsync 边界定，提案对它零约束。
第四版引 ZFS 时**一处差异都没写**，而 `.claude/singlefs-ai-sop/rules/evidence-discipline.md` 逐字
「**引用别家实现的时候，必须同时写下它和这个项目的一处已知差异。** 写不出差异，说明还没搞懂
那个做法在那边为什么成立，这时候的引用是**搬运**，不是论证」。第六节给 bcachefs 写了差异
（「与唯一先例的差异」「bcachefs 不走 A 的已知差异」），**给 ZFS quiesce 这一处没写**。

⇒ 第五版要补两样：① 一条**事务切分纪律**（大写按块切成多个事务，写序各自取号——W1 不受影响，
它们碰的 key 不同），把 Δ 压到「一个单元的写延迟」；② 引 ZFS 时把上面这条差异写进去。

### 1.3 quiesce 与失败表 ③ 相乘：一次介质超时把全池的发布拖住（打中，第四版两处新改动的乘积）

P1 失败表 ③ 逐字：「单副本写失败 ⇒ 换落点重试、写序不变」。**重试次数与超时没有上界。**
把它和 1.2 的 Δ 合起来：一个已取号事务撞上一块正在超时的盘 ⇒ 它「写完」的时刻被重试拖长
⇒ **本 checkpoint 切不下来 ⇒ 全池发不出新根 ⇒ 所有并发 fsync 一起阻塞**。

ZFS 结构上撞不到这一格：`txg_quiesce` 等的是 `tc_count`，普通写路径下它归零时一次 I/O 都还没发。
本工程把 I/O 挪进了 hold 里，于是把「一块盘慢」升级成「全池停止发布」。

⚠️ 这一格与第三轮 1.2 不是同一条。第三轮打的是「诞生代号在写单元时还不知道」，
第四版用「取号即钉死 checkpoint 号」闭合了那一条；**这一格打的是闭合的方式本身的代价**。

⇒ 第五版要么给重试一个墙钟上界（超过就转失败表 ③ 的第二半「不可恢复 ⇒ 实例结束」，
那又是把一次介质抖动升级成全池只读），要么让切分不等 I/O（即退回「单元在固定点之后写」，
而那正是第三版形态、被第三轮 1.2 打掉的那个）。**这两条互相咬着，第五版要显式选一边。**

### 1.4 fsync 密集负载下「停止再分配」防住了饿死，但防不住 fsync 之间的延迟耦合（部分打中）

任务问的「新事务不断进来会不会永远切不下来」——**不会**，提案那句「触发只是停止再分配事务进本
checkpoint」按字面就闭合了：新事务进下一个 checkpoint，本 checkpoint 的等待集合是有限的。**攻不动，如实记。**

真正打得动的是另一件事。D16（发布语义）已定项 6 逐字「**fsync 触发的发布也是发布**」，
同节骑手条款 3 逐字（`.claude/kb/decisions/16-发布语义.md:206-208`）：
「**E70（checkpoint 两个阈值的可行域）的 `T_time` 下界推导（197 ms）只适用于非 fsync 触发的发布**——
那步推导以『一窗多次操作共享一次发布』为前提，**fsync 密集负载下窗口由 fsync 自身触发**。」
⇒ D25（目标负载优先级）那一类负载下，发布节奏 = fsync 节奏（E44 本机 2785 次/秒）。

于是：并发的 F1、F2 都被分配进 checkpoint C，F1 先到并触发 C 的切分
⇒ **F1 的返回时刻被 F2 的数据写拖着**，而 F1 与 F2 之间没有任何逻辑依赖。
第三版没有这一格（那时没有等齐义务）。ZFS 用两样兜：
`/home/fy5090/code/fs-refs/zfs/include/sys/txg.h:31` 逐字 `#define TXG_CONCURRENT_STATES 3 /* open, quiescing, syncing */`
（硬管道深度），以及 `txg_quiesce_thread` 里那句注释逐字「we can only have one txg in 'quiescing' or
'quiesced, waiting to sync' state」（`module/zfs/txg.c:622-625`）——**同一时刻只许一个 checkpoint 在 quiesce**，
配合写节流。本工程**没有「在飞 checkpoint 深度」这个量**，提案也没提。

⇒ 第五版要么写明在飞 checkpoint 深度上界与超出时的节流形态，要么把这条延迟耦合作为已知代价写进
D25（目标负载优先级）的连锁里。**这不是格式问题，但它是这条取号纪律唯一的实际成本，不能只写一句「代价是切分延迟」。**

### 1.5 D16（发布语义）新规则 1 在这个形态下读得通，quiesce 反而是它的执行者（没打中，如实记）

新规则 1 逐字（`.claude/kb/decisions/16-发布语义.md:79`）：「快照发布点必须与 checkpoint 边界对齐，
且位置钉死在『**本 checkpoint 全部数据变更之后**』。」
第四版的 quiesce 恰好就是「本 checkpoint 全部数据变更之后」的可执行形态——
不等齐已取号事务，「全部数据变更之后」在实现上没有落点。**攻不动，反而要记成 quiesce 的一条正面理由**：
第四版只把它写成「对触发规则的一条约束」，漏了它同时是新规则 1 的实现前提。
代价照旧：快照的返回时刻也被最长在飞事务拖着（同 1.1 的 Δ）。

### 1.6 E70（checkpoint 两个阈值的可行域）不用重跑（没打中，如实记）

E70 算的是**下界**：`.claude/kb/experiments/70-checkpoint两个阈值的可行域.md` 判据 2 逐字
「给定摊销预算 `B`（块/操作），从 E16（journal 的角色：WAL vs 意图日志）的两点插值反解一次 checkpoint
至少要盖住多少次操作，再按 E44（序号位宽的本机实测与代价）的 fsync 率折成毫秒」。
quiesce 只会把实际发布间隔**拉长**，盖住的操作数只增不减 ⇒ 下界更容易满足。
`T_dirty` 的上界由环几何算（同文件「`T_dirty` 的上界」一节），与切分时刻无关。
⇒ **E70 的两个界都不受 quiesce 影响，不用重跑。** 被冲击的是 D16（发布语义）已定项 5 的**上界**那一半，
而那一半不是 E70 算的，是用户按丢失窗口定的（见 1.1）。

## 攻击面 2：失败表（P1 取号纪律 3）

第四版逐字三行：「① 取号之前失败（准入拒绝等）⇒ 无事；② 取号之后、写出任何单元之前失败 ⇒ 号作废，
不写单元不追加记录（事务号留洞无害：没有单元或记录带它，jsn 仍连续）；③ 写出单元之后：单副本写失败 ⇒
换落点重试、写序不变……不可恢复的失败（全部副本失败、内部不变量破、固定点不收敛）⇒ 实例结束。」

### 2.1 纪律 2 只认两种终态，纪律 3 造出第三种，排队义务在 ② 发生时无解（打中，纯文本内部矛盾）

同一节里两句：

- 纪律 2 逐字：「事务号 N 的 fsync 在向调用者返回之前必须**等 < N 的记录全部已追加或已确定实例结束**（排队义务）。」
- 纪律 3 ② 逐字：「号作废，**不写单元不追加记录**」。

⇒ 事务 50 走 ②，事务 51 要返回，它等的是「50 的记录已追加」（永远不会）或「已确定实例结束」
（也不会——② 是良性失败）。**第三种终态不在纪律 2 的等待条件里**，按字面 51 永远返回不了。

这不是措辞小病：② 是第四版**新加的一行**（第三轮 2.2 逼出来的），而纪律 2 的两种终态是第三版就有的写法，
两处没有对齐。⇒ 第五版把纪律 2 改成三态：「已追加 ∨ 已作废 ∨ 已确定实例结束」，
并写明作废这个事实怎么让并发的后继看得见（它不落盘，是纯内存的提交管道状态）。

### 2.2 「固定点不收敛」按仓里已入库的实测根本不是一个事件，而 C83（提交固定点没人回答）要的处置也不是实例结束（打中）

**若「固定点不收敛」是一类可达的不可恢复失败，仓里应当有一处说它会不收敛。** 现查两处，说的都相反：

| 处 | 逐字 |
|---|---|
| `.claude/kb/checks-owed.md:94`（C83 行） | 「**E81（提交的固定点）实测收敛总会发生（脏节点集有限）**，但上界由『提交自身产生的块聚不聚簇』定」 |
| `.claude/kb/decisions/03-空间分配.md:174-176`（已定项 5） | 「它是**分配器政策不是格式位**……**违反它的实现写出的镜像完全合法**，只是每次发布贵几百倍。⇒ 拦它只能靠运行时读数：提交路径记『本次发布的固定点收敛轮数』，**超过声明上界判红**」 |

⇒ 两点都对不上：

1. **事件名不存在。** 存在的事件是「收敛**轮数**超过声明上界」，不是「不收敛」。
   E81 实测的最坏形态是散布分配下 65 轮、5909 个元数据块，**仍然收敛**。
2. **处置过重。** C83 那条读数管的是**性能悬崖**（D3（空间分配）已定项 5 逐字「悬崖不报错」，
   引 `.claude/rules/fs-design.md` 硬要求 4），而超上界那次发布写出的镜像「完全合法」。
   第四版把它升级成「实例结束、转只读、下次挂载走恢复」——**一次分配器政策失误（聚簇段选得不好）
   会让整池转只读**，而按 D3（空间分配）已定项 5 它连一个坏字节都没写出来。

真正会逼出「这次发布发不出去」的是另一条：轮数涨上去之后 journal 点名项跟着涨
（E81 那一格逐字 5921 项），撞 I-8.1（环几何够大）的「任一事务的最坏 journal 占用」。
**那是一次事务级的失败，不是实例级的。** ⇒ 第五版把这一行改写成
「固定点收敛轮数超过声明上界 ⇒ 该次发布放弃、记读数、按下面第四行处置；C83 的读数是它的检测手段」，
并把「实例结束」留给真正的不可恢复项（全部副本失败、内部不变量破）。

### 2.3 ② 的判据「写出任何单元之前」在失败发生的那一刻判不出来（打中，本攻击面最重）

**若 ② 与 ③ 是一张封闭表的两格，它们之间那条线必须在失败发生时可判定。** 现查两条已定，判不出来：

- P1 自己逐字「取号之后**用户数据单元随时可写**」⇒ 失败发生时该事务名下可以有**在飞的单元写请求**：
  已经交给设备、还没回来。
- `.claude/kb/decisions/03-空间分配.md` 已定项 6 逐字记着 E82（准入的在飞合成）实测的失败形态：
  「只读已发布值 ⇒ 同窗并发超卖（80/120 格，**分配中途才失败**）」——**准入类失败的实测形态就是「中途」**，
  不是「进门前」。已定项 6 的在飞 overlay 修的是同窗超卖，修不掉「预留不够」这一类
  （预留量由「最坏情况下解开自己需要多少」算，而 2.2 那条轮数超上界正好会把实际用量顶过预留）。

⇒ 一个事务在「已经发出若干单元写请求、尚未收到全部完成」的状态下失败，实现必须当场在 ②（号作废、不写行）
与 ③（实例结束、写行）之间选一边，**而它手上没有可判定的谓词**：一次返回 EIO 的写请求也可能已经落盘。
选错 ② 的后果是格式级的：那些孤儿单元带着写序 (i, n)，

- 当前实例内：P2 谓词那一支逐字「i == i_now ⇒ b ≤ 挂载根的 txg」——孤儿的诞生代号就是它被分配进的那个
  checkpoint，该 checkpoint 照常发布之后 b ≤ 挂载根 txg ⇒ **判已发布**；它又是那个 key 上写序最大的
  ⇒ v* 选中它 ⇒ **不用崩溃就复活了一个从未提交的版本**。这正是靶子第 (c) 类。
- 实例干净结束之后：P2 逐字「i < i_now 时**无行 ⇒ 已发布**」，同样判已发布。

⇒ 第五版把 ② 的判据换成一个**可判定且保守**的谓词：「该事务尚未**向设备发出**任何单元写请求」
（发出过就当发出过，一律走 ③）。代价是把一部分本来良性的准入失败推进 ③——所以 2.2 那一行必须先改成
「事务级作废 + 写行」，否则每一次中途 ENOSPC 都要杀掉整个实例。

### 2.4 洞落在「事务号上限」之下的那条路：回退行的 ∞ 把 n ≤ W 这一维整个关掉（打中）

任务问的「洞在上限之下时会不会有别的路径给那个号写出单元」，先答直路：
**同一事务号被两个并发事务拿到，不可达**——事务号按实例单调计数、作废不回收（P1 逐字「事务号留洞无害」），
两个事务拿到同一个号只能是计数器实现错，不是格式能表达的状态。**这条攻不动，如实记。**

打得动的是回退那一格。P2 逐字：「回退（P3）：写 **(r_old, T_old, ∞)** 与中间实例的 (i, 0, 0)」，
而谓词逐字「有行 (i, T, W) ⇒ b ≤ T ∧ n ≤ W」。**W = ∞ 把事务号这一维整个关掉**，
只剩诞生代号那一维在挡。于是 2.3 那批「号作废但单元落了盘」的孤儿，只要它们的诞生代号 ≤ T_old，
回退之后**全部判已发布**——而它们的诞生代号恰恰就是某个已发布的 checkpoint 号。

第三版也写着 ∞，但第三版没有 ② 这一行（那时取号之后只有「实例结束」一种失败），
**是第四版新加的 ② 把这类孤儿造出来的**，∞ 才第一次失去了兜底。
⇒ 第五版把回退行的 W 从 ∞ 改成一个真值：`W = 该实例在 T_old 那次发布里实际施加的最大事务号`——
这个数在回退那一刻读得出来（就是 R_old 那条时间线上最后一条被施加的记录的事务号），
写 ∞ 只是图省事，代价是关掉了一整维判据。

## 攻击面 3：副本归并（P3）

第四版逐字：「同 (类身份段全部字段含写序) 的多份可读单元是同一逻辑版本的副本（D2（RAID 条带策略）已定项 6
的 w ≥ 2：同一份内容写 N 遍；P1 失败表 ③ 的重试同理），先归并成一个候选，**成员必须逐字节相同，不同即判损坏**；
Current 返回一个版本与它全部副本的落点。」

### 3.1 「同身份段 ⇒ 副本」对码 2 直接为假，而仓里早就写下了这句话（打中，本轮最重）

**若这条归并判别子成立，仓里不该有任何一处说「同一事务写出的两个不同单元会同身份段」。** 有，
而且就写在被这条提案重开的那一分项自己的候选表里：

`.claude/kb/decisions/18-块里携带什么信息.md:89`（已定项 1 的候选表第 1 行）逐字：
「⚠️ **事务号做不到**：同一次事务里 split 出的两个节点事务号相同」。

再看码 2 的类身份段有什么。`.claude/kb/decisions/18-块里携带什么信息.md:140`（已定项 7）逐字：
「索引节点 = 树 ID + 层级 + **该树已定携带的 key 区间** + 诞生代号 + fsid」；
`:136`（已定项 2）逐字：「**记账树的节点带 key 区间；inode 树也带**（2026-09-05，D8（核心索引结构）已定项 6）；
**dirent 树那一格推迟到有 dirent 树时再判**。」

⇒ **有一整类树的码 2 节点不带 key 区间**——dirent 树明写推迟，extent 树、反向索引树一处都没定。
第四版自己的代价表也在按这一类计价：第三版第四节逐字「码 2 三档 68 / 77 / 86（**带区间** 84 / 93 / 102）」，
两档并列说明「不带区间」是活的形态。

于是一次分裂：同一事务在一棵不带 key 区间的树上把一个内部节点裂成两个，两个新节点的
**树 ID 相同、层级相同、诞生代号相同、fsid 相同、写序相同**——**类身份段逐字节相同，而内容不同**。
按 P3 的判别子它们是「同一逻辑版本的两份副本」⇒ 「成员必须逐字节相同，不同即判损坏」
⇒ **一次正常的节点分裂，在扫描重建里判成损坏**；退一步就算不判损坏，v* 也只会留下其中一个，
另一半整棵子树在重建产物里消失。

⚠️ 这一格与第三轮 2.1 不是同一条。第三轮打的是「I-1.8 按字面被 w = 2 的两份副本红掉」，
第四版补了归并把那一格闭合；**这一格打的是归并判别子本身选错了字段**，
而且它挑的正是 D18（块里携带什么信息）已定项 1 亲口说「做不到」的那个字段。

⇒ 第五版三选一：① 把 key 区间从「按树可选」抬成**全部码 2 节点必带**（那是重开 D18（块里携带什么信息）
已定项 2，代价是 E73（节点 key 区间的扇出代价）那笔扇出账要对每棵树付，且码 2 余量从 7 变负）；
② 归并只对码 1 与码 3 做，码 2 走另一条路（但 P3 的 v* 同样要给码 2 定序，问题原样还在）；
③ 把候选表第 1 行那个「谱系重写序号」捡回来——**而 D18（块里携带什么信息）已定项 1 逐字是「不做」**，
第四版说的「射程条款重开」重开的正是这一条，那就该把它重开到底，不能只借事务号又不认它自陈的短板。

### 3.2 归并的成员判别要「逐字节相同」，而码 1 / 码 2 在扫描路径上没有载荷完整性证据（打中）

**若「不同即判损坏」是可执行的处置，扫描时应当分得出「哪一份是好的」。** 现查 C104
（`.claude/kb/checks-owed.md:111`）逐字：
「扫描认领时没有父指针，头校验和只罩头（D18（块里携带什么信息）已定项 7 逐字『头完整性唯一防线』）
⇒ 数据单元与索引节点在扫描路径上载荷完整性无任何自包含证据……**码 3 由类身份段里的载荷校验和补上，码 1 / 2 没有**」。

把它和 P1 失败表 ③ 摆一起，得到一条必然可达的历史：

1. 事务 n 写单元 U，落点 L1（w = 2 ⇒ L1a / L1b）；L1a 写到一半设备报错。
2. 失败表 ③：换落点重试，**写序不变** ⇒ L2a / L2b 写出，内容与 U 相同。
3. 盘上现在有三份或四份**头都完好、写序全等**的可读单元，其中 L1a 的**载荷是撕裂的**——
   而码 1 没有载荷校验和，头校验和照过 ⇒ 它进得了归并组。
4. 归并规则：「成员必须逐字节相同，不同即判损坏」⇒ **判损坏**。

⇒ 两件事同时发生：① 一次本该被冗余救回来的撕裂（真值里有 2–3 份好的）被规则升级成 key 级损坏；
② 就算改成「多数决」，w = 2 加一次重试可以凑出 2 对 2，**而没有任何证据能打破平局**——这正是 C104 那个洞。

**第四版把 C104 变成了承重项而没写。** 第三版 / 第四版代价表里 C104 只出现在「码 2 余量……
与 C104 的 4 字节载荷 CRC 抢同一段」这一句里，说的是**预算**；而 P3 的归并让 C104 从
「扫描重建可能读到坏载荷」升级成「**归并判不出该留谁，一整条 key 判损坏**」。
⇒ 第五版必须把 C104 的射程条目改写，并把「归并的成员判别子」列成它的新消费者；
若第一版就要 P3 归并，那 4 字节载荷 CRC 就从「候选」变成**前置**。

### 3.3 D2（RAID 条带策略）那一格：w = 2 时「逐字节相同」为真，w ≥ 3 时归并是空的而分配记录漏掉 parity 列（部分打中，方向与任务提示相反）

任务提示说「第二份『副本』是 parity 不是逐字节相同的拷贝」。**现查下来这半句不成立，如实记。**
`.claude/kb/decisions/02-RAID条带策略.md:371`（未定项 12）逐字：「第一版 2 盘恒 w = 2，**parity 即第二副本**、
位置条目每副本一条已覆盖发现」；同文件 `:295` 逐字「parity 对密文算，**多副本是同一份密文写 N 遍**」。
w = 2 时数据列只有一列，parity = 该列自身的异或 = 该列本身 ⇒ **两列逐字节相同**，
配上 `:48`（已定项 10）逐字「一个单元**整个落在一列上，位置条目 1 条 / 副本**」，两份都可读、都是完整单元。
⇒ **第一版里「同一逻辑版本的副本逐字节相同」为真，I-1.8 后半句站得住。**

打得动的是 w ≥ 3。已定项 6 逐字 `w = clamp(攒批后写入量 + 1, 2, 4)` ⇒ w 可以是 3 或 4，
那时是 2–3 个**数据列** + 1 个 parity 列，而一个单元整个落在一列上
⇒ **每个单元只有一份可读副本，parity 列装的是几个不同单元的异或**，既不是谁的副本，也过不了任何单元头校验和。
于是：

- I-1.8 后半句在 w ≥ 3 下**空转**（一组里只有一个成员），P3 的归并步骤同样空转——**它是一条 w = 2 专属的规则，第四版没有写这个射程**；
- 更实的一格：P3 逐字「分配记录 = 各根 **Current 的全部副本落点** ∪ 重建新写的索引落点 ∪ 固定结构」。
  **parity 列的落点不是任何单元的副本落点**，也不是索引落点、不是固定结构
  ⇒ **重建出来的分配记录把每一个 parity 列记成空闲** ⇒ 接 P4 的准入「分配记录条目标已释放」……
  这一条第四版改成了「条目标已释放 ∧ 释放代 ≤ …」，parity 落点在重建产物里**连条目都没有**
  ⇒ 落进 P4 的「孤儿单列」那一格 ⇒ 它头不可读（parity 不是单元）⇒ 按 P4 第三条合取「头可读」不清。
  **这一格侥幸不塌，但塌不塌是碰巧，不是设计。** 而 D2（RAID 条带策略）已定项 11 逐字要求
  「部分条带钉住、后台惰性重落；**修复前成员格不得复用**」——重建出来的分配记录里
  **一条条带成员关系都没有**（parity 在哪、谁和谁同条带，D2（RAID 条带策略）未定项 12 明写全仓无落点），
  ⇒ 重建之后已定项 11 那条规则没有输入。

⇒ 第五版要写明：① 归并与 I-1.8 后半句的射程是 w = 2（parity 即第二副本），
w ≥ 3 时每个单元一份副本、parity 列不进归并；② P3 的「分配记录」派生量要加一句
「parity 列的落点在扫描重建后不可重建，随 D2（RAID 条带策略）未定项 12 一起定」，
不能让读者以为分配记录被 P3 完整重建出来了。

### 3.4 「两个不同事务、不同 key 的单元不可能同身份段」这半句对码 1 / 码 3 成立（没打中，如实记）

码 1 的类身份段含五元组（标签 1 + 树 ID 8 + 对象 ID 8 + 对象出生代 8 + 锚点偏移 8，2026-09-05 定案），
不同 key ⇒ 锚点偏移或对象 ID 不同；不同事务 ⇒ 写序不同。
码 3 的四元组含容器号，而容器号的分配规则逐字（`.claude/kb/decisions/18-块里携带什么信息.md:607`）
「类型 1 树内单调分配；类型 2 = 触发分裂的那条新记录的 inode 号」⇒ 同一事务分裂出的两个容器号不同。
**这两类攻不动。** 塌的只有码 2 那一类（3.1），因为它的身份段里唯一能区分兄弟节点的那一段是可选的。

## 攻击面 4：实例代号（P2）

第四版逐字：「新代号 = max(全部可见超级块的代号, 根环里全部根记录的实例代号) + 1——根环按区域落在不同盘上
（I-7.6（根环区域落在互不相同的盘上）），是超级块之外的独立见证……每次可写挂载（含干净挂载、只读转可写）
取一次新号并**先写全部可见超级块再动任何单元**……**分叉盘**：一块盘回归时其超级块代号与当前根环对不上
（它记的时间线不是当前时间线的祖先）⇒ 该盘内容整盘作废、重同步后才进候选集。」

### 4.1 「先写全部可见超级块」中途崩不造成回退，而第三轮 3.2 的处置在正文里一句都没有（部分打中：前半没打中，后半是处置漏了）

更进一步，第一版根本走不到「只有一盘可见还在写」那一格：
`.claude/kb/decisions/02-RAID条带策略.md:47`（已定项 9）逐字「已定项 6 的 `w ≥ 2`（零冗余的条带不许发出）
与『再夹当时可写的设备数』在单设备上互斥……**第一版不跑单盘**」
⇒ 2 盘掉一块之后写不出任何单元 ⇒ 只能只读挂载 ⇒ **P2 逐字「只读挂载不取号」** ⇒ 号不动。
**第三轮 3.2 那条「三个来源读不全 ⇒ 取号静默回退」的历史，在第一版的几何下不可达。**

**但处置本身漏了。** 第四版处置表把「反推腿 3.1–3.4」整行记成「采纳 ⇒ P2」，

**「见证读不全」这一格一个字都没有**。上面那条「第一版不可达」是我核出来的，不是提案写的；
盘数一旦 ≥ 3（`w = clamp(…, 2, 4)` 允许，D2（RAID 条带策略）已定项 8 的 g 初值就是 4），
降级可写挂载立刻可达，那条历史就回来了。⇒ 第五版把这句射程补进 P2，不能靠读者自己去核几何。

### 4.2 拿 I-7.6（根环区域落在互不相同的盘上）当「独立见证」的依据，而第一版的几何恰好落在它不成立的那一格（打中）

**若「根环按区域落在不同盘上」成立，第一版的 R 与 devs 应当满足它。** 现查三处，不满足：

| 处 | 逐字 |

| `.claude/kb/experiments/48-根环几何的可行点.md:23` | 「乘 P 是模 devs 的一个双射 ⇒ r 两两不同时归属两两不同，**只要 `R ≤ devs`**」 |
| 同文件 `:35` / `:56` | 「**`devs < R` 的格子不作要求**」／「会撞的是 `devs < R`（掉盘 / 换成更少的盘），**那是鸽笼**」 |

于是 P2 那句依据在第一版里是空的——根环与超级块的失败域集合**就是同样那两块盘**，
掉一块盘同时掉掉一份超级块和至少一个根环区域。**「超级块之外的独立见证」这个说法在第一版买不到任何东西。**

⚠️ 顺带一条更硬的：I-7.6 逐字「不成立即拒绝挂载」，而第一版的 (R=3, devs=2) 按字面就不成立
⇒ **按 I-7.6 的字面，第一版自己的几何挂不上。** 这不是 C113（扫描重建时多版单元的现行版本判定无输入）
带出来的问题（它早就在），但第四版是第一份**引用它当依据**的文档，
所以它要么把 I-7.6 的射程写清（「R ≤ devs 时两两不同；devs < R 时按 E48（根环几何的可行点）不作要求」），
要么换一条依据。**照现在这样引，是拿一条在第一版为假的不变量去撑一条新规则。**

### 4.3 「不是当前时间线的祖先」这个判据在仓里没有可判定的形式，而两个方向的失配需要相反处置（打中，本攻击面最重）

**若这条分叉盘规则可执行，根记录里应当有能判「祖先」的东西。** 现查 D22（单元原子性怎么合成）
已定项 7 的根记录字段表（`.claude/kb/decisions/22-单元原子性怎么合成.md` 已定项 7），
全部字段是：magic 4 / fsid 16 / flags 4 / **实例代号 4** / **checkpoint_txg 8** / 树表单元指针 59 / 自证校验和 32 = 127。
**没有任何指向前一个根的字段**，也没有时间线谱系。C88（根环的时间线判别未实现）已还的那一半逐字只是
「D22（单元原子性怎么合成）已定项 7 给根记录加了实例代号、**择新平局按它高者赢**」——
那是 (checkpoint_txg, 实例代号) 上的一个**全序**，不是祖先关系。**一个序判不出「谁是谁的祖先」。**

两个方向的失配需要相反的处置，而 P2 一句话把它们混成了一件事：

| 回归盘的超级块代号 | 真实含义 | 该怎么处置 | P2 现在怎么处置 |
|---|---|---|---|
| **比当前小** | 绝大多数情况是「它只是离线过，没被写过」——这是掉盘再回来的**正常**形态 | 重同步即可，不需要「整盘作废」这个说法 | 按「对不上」⇒ **整盘作废** |
| **比当前大** | 它被**另一条时间线**写过（分叉），这是真正危险的那一格 | 必须拒绝 / 隔离 | **max 规则先把它吃进去**：新号取 max + 1 ⇒ 没有撞号；然后这块盘上那些实例代号 < 新号的单元，**实例表里没有它们的行**（那些行住在另一条时间线的实例表里）⇒ P2 谓词逐字「i < i_now 时**无行 ⇒ 已发布**」⇒ **分叉盘的单元被判已发布** |

⇒ 危险的那个方向被 max 规则**静默吸收**：它抬高新号（看起来很安全），
却让分叉时间线的单元走进「无行 ⇒ 已发布」这条默认。**P2 的默认值在这一格是错的方向**——
「无行」既可能是「那个实例干净结束过」，也可能是「那个实例根本不属于这条时间线」，两者在谓词里长得一样。

⇒ 第五版要给分叉盘写一个**可判定**的谓词。手上唯一现成的材料是 fsid（I-1.4（块头 fsid 一致））
与 (实例代号, checkpoint_txg)，都判不了分叉。可行的形态只有两条：
① 每块盘的超级块里记一条「本盘见过的最大 (实例代号, txg)」并要求它在当前时间线的根环里**找得到对应的根**，
找不到即判分叉（这要求根环足够深，是个真前提，要写）；
② 承认分叉不可判，把它与整卷回滚放进同一格随 D9（加密）已定项 8 宣布不防——
**但那样 P2 的射程句就不能再说「它挡的是镜像内部的不同步（掉盘降级、盘失而复得）」**，
因为盘失而复得正是分叉最可能发生的地方。

### 4.4 「整盘作废、重同步」在第一版的几何下等于整池停写，而这个后果算得出来却没写（打中）

第四版把重同步的形态归给「D26（后台整理与放置回收）/ D22（单元原子性怎么合成）未定（今天没有落点，如实记）」——
**这句诚实，不算把未定项当前提。** 但它漏了一个今天就算得出来的后果：

2 盘池里一块盘被判分叉 ⇒ 它「整盘作废、重同步后才进候选集」⇒ 在重同步完成之前，
可用设备数 = 1 ⇒ `w = clamp(…, 2, 4)` 再夹可写设备数 = 1 < 2
⇒ D2（RAID 条带策略）已定项 6 的 `w ≥ 2` 硬下界发不出任何写
⇒ 按已定项 9 逐字「第一版不跑单盘」⇒ **整池在整个重同步期间只能只读**。

而重同步本身要写（往被作废的那块盘上拷）——那些写是修复写还是普通写、要不要满足 `w ≥ 2`，
D2（RAID 条带策略）已定项 11 的「后台惰性重落」只覆盖部分条带，覆盖不到整盘。
⇒ 第五版要在代价表里写下这一行：「分叉盘规则在 2 盘第一版上的代价是整池只读直到重同步完成，
而重同步的写路径本身没有落点」。这比「归 D26 / D22 未定」重得多，它是一条**可用性**结论，不是格式空白。

## 攻击面 5：释放代进分配记录（P4）

第四版逐字：「D3（空间分配）已定项 7 的分配记录条目在落点释放时不删，value 改写成
『已释放标志 + 释放代』（分配代 8 字节那一段复用，最高位标志），**K 代之后点删**
（当前代 − K 算得出来，不是扫描）；它是派生态、改格式免费，顺带把崩溃后 defer 队列内存态丢失那一格补上。」

### 5.1 「点删」在这棵树上做不到，因为它的 key 里没有代——而它抄的那条规则的 key 里有（打中，本攻击面最重）

**若「当前代 − K 算得出来，不是扫描」成立，分配记录的 key 里应当有一段代。** 现查两处，一处有一处没有：

| 结构 | key 逐字 | 按代点删做不做得到 |
|---|---|---|
| 记账树 | `.claude/kb/decisions/05-快照-空间记账机制.md:208`（已定项 5）：`(统计量标签 2, 树 ID 8, 设备 4, **代 8**)` | **做得到**：统计量与维度元组是有限且已知的一小把，给定 G 就能逐个点删。D5（快照 / 空间记账机制）已定项 2 逐字「要丢的那一代算得出来（当前代 − K），不用找 ⇒ 是点删不是扫描」说的正是这个 |
| 分配记录 | `.claude/kb/decisions/03-空间分配.md:200`（已定项 7）：`key = (设备身份 4, 16 KiB 槽号 6)`，`value = 分配代 8` | **做不到**：树按落点排序，代住在 value 里。要删掉「释放代 == 当前代 − K」的那批条目，得先知道**哪些落点**在那一代被释放过——这个集合既不在 key 序里，也算不出来 |

⇒ 第四版把 D5（快照 / 空间记账机制）已定项 2 那句「算得出来，不是扫描」原样搬到了一棵 key 里没有代的树上。
**搬运，不是论证。**

更糟的是它**自指**：要做到点删，就得有一份「按代组织的已释放落点清单」住在内存里；
而第四版给「释放代」写的第二个理由逐字正是「顺带把**崩溃后 defer 队列内存态丢失**那一格补上」——
**它要补的那份内存态，恰恰是它自己做点删所必需的。** 崩溃之后那份清单没了，点删就无从下手，
只能全树扫一遍找已释放标志，而全树是 4.8 亿条（E97（记账与分配记录的条目编码）实测 16 TiB / 90% 填充
483 183 820 条、树高 4）。

⇒ 第五版三选一：① 给分配记录加一条按 `(释放代, 落点)` 排的第二索引（新增一棵 keyspace，
按 D3（空间分配）已定项 3 逐字那是 compat 改动，但条目数翻一番、E74（分配记录的条目数与整理开销）
与 E97（记账与分配记录的条目编码）都要重跑）；② **不点删**——已释放条目一直留到该落点被重新分配时被覆盖，
那样条目数变成「全部曾分配过的落点数」，同样要重跑那两个实验；③ 把释放代挪出分配记录。
**三条都要付账，第四版一条都没记。**

### 5.2 释放代的寿命是毫秒，清扫周期是小时，两个数差六个数量级（打中）

P4 的准入逐字：「分配记录条目**标已释放** ∧ 释放代 ≤ 环里最旧根的 checkpoint_txg ∧ 头可读」。
而条目「K 代之后点删」。K 的量纲：I-7.4（近 K 代块未被复用）逐字「K ≤ 根环深度」，
根环深度 = R × S = 3 × S，S ∈ 1..16（D22（单元原子性怎么合成）已定项 2）⇒ K ≤ 48；
发布速率按 E44（序号位宽的本机实测与代价）的 2785 次/秒 ⇒ **K 代 ≈ 17 毫秒**。
而 P4 自己写着清扫「每轮一遍全盘读」，第三版给的量是「16 TiB 盘 2 GB/s 约 2.3 小时」。

⇒ **清扫扫到某个落点时，它的「已释放 + 释放代」在一万倍以前就被点删了。**
读回来是「没有条目」⇒ 掉进 P4 的「孤儿单列」那一格 ⇒ 那一格的判据逐字是
「其写序所属实例 < 当前实例且按 P2 谓词未发布 ⇒ 清；**当前实例的单元一律不碰**」
⇒ 一个长期挂载的实例里，**它自己释放掉的、还没被重新分配覆盖的可读单元，一轮都清不掉**。

于是 I-1.9 逐字「清扫水位以内不存在可读垃圾」在一个连续运行的实例上**不可能成立**。

⚠️ 这一格与第三轮 6.3 同形而不同处。第三轮打的是「清扫水位 / 根销毁代号做成记账统计量会被 K 代点删清掉」，
第四版把那两个量改成「随每次发布重写」修好了；**同一个形状被原样搬进了新加的『释放代』这一格，而这次没修。**

⇒ 第五版要给释放代的寿命一个与清扫周期同量纲的下界（那就等于 5.1 的第 ② 条：不点删），
或者把清扫的准入换成一个不需要长寿命结构的判据。

### 5.3 「最高位当标志」把已定项 7 逐字的两句话破了，而 D16（发布语义）骑手 2 那条不是它的对手（部分打中）

`.claude/kb/decisions/03-空间分配.md:200 / :207` 逐字两句：「value = 分配代 8 字节，**存完整 checkpoint 号**」；
「分配代 8 | 与 D22（单元原子性怎么合成）已定项 7 的 `checkpoint_txg` **同宽同值域**」。
最高位挪去当标志之后剩 63 位，**「完整」与「同值域」按字面都不再成立**——
一个最高位为 1 的 `checkpoint_txg` 存不进去。E97（记账与分配记录的条目编码）判据 3 / 8 逐字
「任何有限模都只是把破 key 序推迟到回绕那一刻」正是为了排除这类截断。

**可达性上这条不承重**：2⁶³ 次发布按 2785 次/秒是 10¹¹ 年量级。
任务问的「与 D16（发布语义）已定项 6 骑手 2『代段宽度 ≥ 48 位』相不相容」——**相容**，
63 ≥ 48；而且骑手 2 逐字管的是**记账 key 的代段**，不是分配记录的 value，射程本来就不同。**这半句攻不动。**

⇒ 但两句逐字被破仍要处理，代价近乎为零：把标志位放进跨度段（已定项 7 逐字「跨度段 2（初值）……
第一版恒为 1 或 2」，两个值用不掉 16 位），条目宽仍是 20 字节、扇出 816 不动。
⇒ 第五版改这一句，别动分配代那 8 字节。

### 5.4 条目数不再等于已分配落点数，而那是 E74（分配记录的条目数与整理开销）跑前写死的绝对值断言（打中）

`.claude/kb/experiments/74-分配记录的条目数与整理开销.md` 判据 1 逐字：
「**绝对值断言**：条目数必须**恰好等于已分配落点数**，不许只看它『大致随容量走』。」
P4 之后条目数 = 已分配落点数 + 尚未点删的已释放落点数（按 5.1 的第 ② 条走则是「全部曾分配过的落点数」）。
⇒ **E74（分配记录的条目数与整理开销）那条断言按字面为假**，E97（记账与分配记录的条目编码）
那组数（483 183 820 条、树高 4、442 ppm）也是按已分配落点数算的。

第四版代价表 D3（空间分配）已定项 7 那一行只写了「分配记录 value 加『已释放 + 释放代』，K 代点删」，
**E74（分配记录的条目数与整理开销）与 E97（记账与分配记录的条目编码）一个都没点名**，
而 `.claude/gate.d/40-results-cited.sh` 管的正是「跑过的必须被点名」这一类。
⇒ 第五版在代价表里补一行：两个实验按新的条目数口径重跑；条目宽度不变（4 + 6 + 2 + 8 = 20），
所以扇出 816 与树高不动，变的只有条目数那一列。

### 5.5 重建之后清扫的输入没了，而这与「重建产物永久只读」自洽（没打中，如实记，但要写进正文）

P3 逐字：「分配记录 = 各根 Current 的全部副本落点 ∪ 重建新写的索引落点 ∪ 固定结构」——
**重建出来的条目全部是「已分配」，一条「已释放 + 释放代」都没有**（重建只看得到现行，看不到何时释放）。
⇒ P4 的第一条合取「条目标已释放」在重建产物上恒为假 ⇒ 清扫在重建产物上寸步难行。
而 P4 自己逐字写着「`map_provenance = rebuilt` 未晋升期间禁止；晋升要级 2 见证者，今天不存在
⇒ **扫描重建的产物今天永久只读**」⇒ **两句自洽，攻不动。**

**但它有一个该写进正文的推论**：C113（扫描重建时多版单元的现行版本判定无输入）这条路线上，

而它其实是这条路线的**射程声明**，该和「C113 买到的是可读回，不是可续用」写在一起。

## 攻击面 6：第六节那条对立臂的判决

第四版逐字：「**判决：取臂 A。**……进判据的两样都偏向 A：① 臂 B 让 extent 树（最热的树）按 D11（索引节点要不要留消息缓冲区）
已定项 4 的谓词失去消息缓冲区（E56（消息缓冲的收益 vs ε）：排空后 2.62× 对 2.91×，那是 D11 整条定案买的东西），
臂 A 保住它；② 臂 A 在叶单元两副本都毁时仍能重建映射，臂 B 不能。」
表格里那两格逐字是：臂 A「消息可从数据单元 + 写序重算，**E59（缓冲消息能不能只从单元重算）乙臂换成机制**」；
臂 B「**E59 甲臂的歧义原样在**」。

### 6.1 ① 引错了 E59（缓冲消息能不能只从单元重算）的臂：甲臂那个模型里，单元头**没有**诞生代号（打中，本轮与 3.1 并列最重）

**若「臂 B 下 E59 甲臂的歧义原样在」成立，甲臂的单元头应当和臂 B 的数据单元头带同样的字段。** 现查源码，不带：

`research/e7-index-bench/src/bin/e59_msg_recompute.rs:14-16` 逐字（建模前抄进注释的条款）：
「D18（块里携带什么信息）已定项 3……`(单元类型标签, 树 ID, 对象 ID, 对象出生代, 锚点偏移)`……
⇒ 头里**没有**『这一次写是第几次写』——`对象出生代` 是对象的出生代，**不是本次写的序号**。」
同文件 `:188` 逐字：`birth_gen: 1, // 对象出生代：覆写不改它，这正是 D18 已定项 3 字段集的形状`。

⇒ **E59 甲臂的单元头里根本没有诞生代号（这一次写属于哪个 checkpoint）**，只有一个覆写不改的「对象出生代」。
它 2026-08-31 跑的时候，D18（块里携带什么信息）已定项 7（2026-09-02 定案）还没把诞生代号写进单元头字段表。
所以甲臂那个「分不出的副本 = **覆写次数**」是在一个**一点定序信息都没有**的头上量出来的。

而臂 B 的数据单元头**带诞生代号**（D18（块里携带什么信息）已定项 7 的类身份段逐字含它）。
⇒ **臂 B 不是 E59 甲臂**，两者差着一整个定序字段。第四版那句「E59 甲臂的歧义原样在」按字面为假，
而判决的第一条腿整根架在它上面。

顺带另一格也引错了：臂 A 那格写「E59 乙臂换成机制」。乙臂逐字是「单元 + **记账**」，
而记账在 E59 源码里是 `live: bool` 神谕（`e59_msg_recompute.rs` 的 `Unit.live` 注释逐字
「**只有乙臂的重建路径看得到它**」，C113（扫描重建时多版单元的现行版本判定无输入）的欠账行也逐字点了这一条）。
臂 A 给的是**定序**不是「活没活」，它对应的是 E59 的**丁臂**（序号 + 显式墓碑单元，四类全 0），不是乙臂。
⇒ 两格引用各错一处，方向相反：臂 A 那格把自己说弱了（该引丁臂），臂 B 那格把对方说弱了（不该引甲臂）。

### 6.2 D11（索引节点要不要留消息缓冲区）已定项 4 的谓词在两条臂上都判不出差别，因为它自己的那个组合一条臂都没跑过（打中）

D11（索引节点要不要留消息缓冲区）已定项 4 逐字：「能重算，源是『**单元 + 记账 + 墓碑单元**』……
**它不是『只从单元』**——那个更窄的问法实测答案是不能」。

C113（扫描重建时多版单元的现行版本判定无输入）自己的欠账行（`.claude/kb/checks-owed.md:120`）逐字：
「D11（索引节点要不要留消息缓冲区）已定项 3 的第一个重算源写『记账逐落点答得出活没活』，
已定项 4 自陈欠的『两处正文要跟着改』未改，且**它的组合「单元 + 记账 + 墓碑单元」E59 七条臂一条都没跑过**」。

⇒ 已定项 4 那个谓词的判据本身没有实测支撑，而它的「记账」那一半正是 C113 要证明**在重建时拿不到**的东西。
拿这样一条谓词去区分 A 与 B，两边都判不出来：

| 臂 | 待下刷消息的实际重算源 | 与已定项 4 逐字那三样的差 |
|---|---|---|
| A | 数据单元（带写序）+ 墓碑单元 + 实例表 + 祖先表 | **换掉了「记账」**，加了两样 |
| B | 数据单元（带诞生代号）+ 墓碑单元 + 实例表 + 祖先表 | 与臂 A 同样换掉了「记账」、加了两样，只是定序粒度从事务退到 checkpoint |

**两条臂改的是同一处，差别只在最后半句。** ① 那句「臂 B 失去缓冲、臂 A 保住」在这条谓词下读不出来。

### 6.3 臂 B 的残余歧义有实测的数，而它就在 E104（扫描重建的现行版本判定）里，第四版没拿来用（打中）

`.claude/kb/experiments/104-扫描重建的现行版本判定.md` 的 same_txg 世界逐字：
「`no_wseq` **歧义 3**」，闭式逐字「**同一诞生代号上多版的身份 3（两个数据 key + 墓碑容器自己的两版）**」；
其余十类靶子世界 `no_wseq` 全 0。

`no_wseq` 是「三个类都不带写序」；**臂 B 是「码 2 / 3 带、码 1 不带」**，严格夹在 `full`（0）与 `no_wseq`（3）之间：
那 3 个身份里，墓碑容器（码 3）那一个被臂 B 的写序解掉 ⇒ **臂 B 的残余歧义恰好是 2 个数据 key**，
而且只在「同一个 checkpoint 里跨事务改同一个 key」那一格。

⇒ 这才是 ① 该量的东西：**A 相对 B 唯一多买到的，是「同 checkpoint 同数据 key 多版」的定序**。
它不是「失去消息缓冲区」，是「缓冲重算在这一格上留一个歧义」。
⚠️ **W1 挡不住这一格**：W1 逐字只管「一个**事务**对一个逻辑 key 至多留一种净效果」，
而一个 checkpoint 装多个事务（D16（发布语义）本条定案的全部理由就是「攒够一批脏节点再发布一次根」）；
第三版还专门删掉过「同一发布内不许两个事务改同一 key」那句（第三版处置表逐字「自相矛盾且被 E104 证否」）。
⇒ **可达，且第四版自己的 P1 拆账表第一格就是这么写的。**

⇒ 第五版该做的不是重新论证，是**加一条 E104 消融臂 `wseq_meta_only`**（写序只上码 2 / 3），
把这个数直接量出来；再在 D25（目标负载优先级）的目标负载上量一次「同 checkpoint 同 key 多次改写」的可达频率——
**那个频率就是这 10 字节的全部价钱**，而它今天一个字都没量过（第四版自己逐字写着「发生频率未测」）。

### 6.4 ② 与 ① 不是两条独立的腿，它塌进 ①（打中）

第六节表格逐字：臂 B「叶单元两副本都毁时……**该叶覆盖的 extent 映射丢失**（数据单元在盘上，但同 key 多版分不出）」。

差别只有 6.3 那一格。⇒ **丢的不是「该叶覆盖的 extent 映射」，是那批同 checkpoint 多版的 key。**
括号里「同 key 多版分不出」这句话是对的，但它只对**同一 checkpoint 内**的多版成立，
而表格把它写成了整个叶覆盖范围。

再看量级（任务问的「是不是同一量级」）：D2（RAID 条带策略）已定项 6 的 `w ≥ 2` 对所有单元一视同仁
（已定项 8 逐字连 journal 记录都算进去），**叶单元与数据单元的单份双毁概率同量级**。
臂 B 的 extent 叶是 32 KiB 码 3 容器，一条 extent 记录约 (对象 ID 8 + 出生代 8 + 锚点偏移 8 + 位置条目 14 × 2) ≈ 52 字节
⇒ 一片装约 (32768 − 103) / 52 ≈ 628 条 ⇒ **叶数 ≈ 数据单元数 / 628**。
于是「因叶双毁而受影响的 extent 数」的期望 = 叶数 × p × 628 = 数据单元数 × p = 「数据单元双毁数」的期望——
**同量级，不是臂 A 独有的优势**；而且数据单元自己双毁时数据本身也没了，映射在不在没有意义。
⇒ ② 站不住，它既不独立（塌进 ①），量级上也不是一个新维度。

### 7.4 由 7.3 推出一条**提案级**的可达历史：回退之后，环里被抛弃的根变成假的回退候选（打中，本轮最重的一条可达历史）

这一条不是模型的毛病，是规则的。逐条走：

1. 管理员回退（P3）：`R_old` 之后的 m 个根被抛弃，**它们仍在根环里**（D22（单元原子性怎么合成）已定项 2
   的环是覆写轮转、回退不删槽；I-7.3（环健康性）逐字还要求「S 中除代号最大者外，至少还存在一条更早代号的记录」）。
2. P3 逐字：「全部记账统计量的现行值一律从 R_old 那棵账重新载入，**被抛弃时间线的条目一条不带**」
   ⇒ 被抛弃时间线独占分配的那些落点，**在分配记录里没有条目**（模型里就是 `:618-619`
   的 `alloc_rec.remove(&l)`）。
3. P4 的孤儿分支逐字：「没有分配记录条目、也不在分配器在飞 overlay 里的可读单元，按实例表判：
   其写序所属实例 < 当前实例且按 P2 谓词未发布 ⇒ **清**」。被抛弃的那批正好满足：实例更小，
   而回退行 `(r_old, T_old, ∞)` 与 `(i, 0, 0)` 恰恰把它们判成未发布。⇒ **抹头**。
4. 结果：环里那 m 个根**自证仍然合法**（它们的自证校验和没被动过），而它们指向的单元已经被抹头。
5. P3 逐字允许「**管理员带外选定根环里的旧根**」——**没有任何一句禁止选中被抛弃的那几个**。
   ⇒ 第二次回退可以挂上一棵指向被抹掉的单元的树。

I-7.4（近 K 代块未被复用）逐字禁的正是这个结局：「最近 K 代根所引用的块，其物理范围均未被重新分配给其他对象
……**不满足则环里的旧根是假的回退候选**」。抹头不是「重新分配」，但**造出来的正是它要拦的那个状态**。

⇒ 第五版要补一条，代价很小：**回退候选集 = 根环里按实例表判仍然有效的根**——
根 `(i, T)` 可选 ⟺ 实例表无行，或有行 `(i, Ti, Wi)` 且 `T ≤ Ti`。
被抛弃的根按定义落在 `(i, 0, 0)` 或 `T > T_old` 上，一条都选不中。

⚠️ **E104 今天证不了这条**：它的根集合里没有被抛弃的根（7.3），要证得先给模型加一个真的根环。

### 7.6 `no_replica_merge` 只证了「不归并会平局」，没有任何臂能抓住「归并把不该并的并了」（部分打中）

`replicas` 世界的闭式逐字是「三个根各自引用的身份数之和（不归并时每个身份在每个根上一次平局）」，
数值 18。这条消融证明的是**归并这一步承重**。
但按 `.claude/singlefs-ai-sop/rules/test-discipline.md` 的「只让多条臂互相比，测不出『所有臂一起错』」：
**判别子选错字段时，`full` 与 `no_replica_merge` 会一起错**——前者把两个不同版本并成一个（歧义变 0，看起来更好），

⇒ 第五版补一个反向世界：造两个**类身份段全部字段相同、载荷不同**的可读单元（就是 3.1 那条历史），

## 一句话判决

**第四版不能按现在这样进正文。** 它的 P3 择版本算术我照旧攻不动，三轮打过的面也确实都还上了；
但它自己写的两条推翻条件**这一轮各中一条**——7.4 给出了一条 P3 判错的可达历史
（回退之后被抛弃的根在环里变成假的回退候选，而 P4 的孤儿分支正是抹掉它们的那只手），
6.1 证明了「臂 B 保不住 extent 树的缓冲」这条判据引错了实验臂（E59 甲臂的模型里根本没有诞生代号），
于是第六节「取臂 A」的两条腿都要撤，判决改判**判据不够**、要先补两个今天就跑得出来的数。
另外三处是新引入部分自己的硬伤：归并判别子挑中的字段正是 D18（块里携带什么信息）已定项 1
亲口说「做不到」的那一个（3.1）；「K 代点删」搬到了一棵 key 里没有代的树上（5.1）；
失败表 ② 与 ③ 的分界在失败那一刻判不出来（2.3）。
⇒ **建议出第五版**：改 P1 的失败表与取号纪律、P3 的归并判别子、P4 的释放代载体与回退候选集，
第六节的判决整段改写成「判据不够 + 两条要补的测量」，然后再打一轮。
