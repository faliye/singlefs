1c. Yes, effective_rollback_floor includes abandoned roots because it applies no abandonmentfilter. For example, after a rollback, an abandoned timeline's root on device A has rollback_floor=20 and the current timeline's root has rollback_floor=10. effective_rollback_floor would be 20 (smallest of per-device maxes). Then reclaim_floor = max(20, oldest_valid_root), which could be 20. If a placement was released with generation=15, it would be reclaimed even though the current timeline's rollback_floor is only 10, violating D1 which requires reclaiming only up to the larger of effective_floor (based on valid roots) and oldest_valid_root. This is refuted by: if effective_rollback_floor filtered out abandoned roots before computing per-device maxes, the abandoned root's rollback_floor=20 would not be included, but the current code does not do this.

Thus, at least the newest root is always valid. This is refuted by: if the current mount's newest root were abandoned by its own instance table, but G2 ensures that for the root's own instance, selected_root_txg >= checkpoint_txg, so it cannot be abandoned.
