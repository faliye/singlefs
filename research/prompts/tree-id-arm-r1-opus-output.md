## 二、轴 6 的机制链：判孤儿的那把尺子里**没有树 ID**

### 2.1 孤儿被谁判、按什么判

`18-块里携带什么信息.md:697` 逐字：

> **已发布谓词（全局）**：i_now = 挂载根的实例，单元写序 (i, n)、诞生代号 b——i < i_now 且无行 ⇒ 已发布；有行 (i, T_pub, W)：码 1 ⇒ b ≤ T_pub ∨ n ≤ W（在所选根里，或被重放施加……），码 2 / 3 ⇒ b ≤ T_pub（所选根之后的固定点单元一律未发布，恢复实例重写它们……）；i == i_now ⇒ b ≤ 挂载根的 txg；i > i_now ⇒ 判损坏。

同一行逐字：

> **作废一个 checkpoint 必须换实例代号**：当前实例没有行，谓词对它只能问「诞生代号 ≤ 挂载根 txg」，重发同一个号一发布，诞生代号等于它的孤儿全部判已发布——这是失败表能封闭的依据

代入题设：checkpoint T 分配了树 ID = 42、写出带 42 的单元、根没写成就崩了。
- 该 checkpoint 被作废 ⇒ **必须换实例代号**，下次挂载的 i_now > i_old。
- 下次恢复给 i_old 写行 (i_old, T_pub, W)，T_pub = 所选根的 checkpoint_txg = T − 1。
- 孤儿的诞生代号 b = T > T_pub。码 2 / 3 ⇒ 未发布；码 1 ⇒ b ≤ T_pub 假，n ≤ W 只在「被这次重放施加」时为真，而被施加的那些按定义已进入恢复后的时间线、不是孤儿。

⇒ **那批 42 全部判未发布。** `invariants.md:21`（I-1.2 块头写序已发布）逐字给出这句判定的用途：

> **判不成已发布者必是未发布的撕裂事务垃圾或被抛弃时间线的残留**——这是扫描方向独立于遍历方向判它的依据

判定的输入是 (实例代号, 事务号, 诞生代号)。**一个字都没有树 ID。**

### 2.2 谁赢：先滤后择，两道闸都不看树 ID

`18-块里携带什么信息.md:675` 逐字：

> 先按实例表的已发布谓词滤掉未发布的版本（定案 P2），再在对该根可见的候选里取**该类的择新键**最大者（定案 P3：码 1 取写序，码 3 取 (诞生代号, 实例代号, 事务号) 三元——诞生代号打头……事务号留在末位做同一 checkpoint 内的平局破除……）

**第一道闸**滤掉孤儿。**第二道闸**（择新键）即使孤儿混进来也判它输：
写序 = 实例代号 + 事务号，而 i_old < i_new 恒成立（作废必换代号，且代号取 max + 1 单调）。
码 3 的三元里诞生代号打头会平局（回退 / 恢复后 `第一个新根的 checkpoint_txg = 根环里全部根记录 txg 的最大值 + 1`
= 被作废那个 T，`23-journal的角色与格式.md:1172` 逐字），**平局由第二位的实例代号破除，仍是活的赢**。

### 2.3 决定性的一条：**孤儿与活版共用五元组，是这套设计的常态，不是树 ID 重发造出来的**

五元组 = (标签, 树 ID, 对象 ID, 对象出生代, 锚点偏移)（`18:637` 定案）。
取一个**早就发布过的**树（比如 extent 树，树 ID = 7）：崩溃前那个 checkpoint 改写了它的
(树 7, 对象 9, 出生代 G, 偏移 0)；恢复后同一个逻辑块被重写，仍是 (树 7, 对象 9, 出生代 G, 偏移 0)——
对象出生代是**对象创建时固定**的值（`18:570`，删除记录按同口径带它），锚点偏移是文件内偏移，两者都不随重写变。

⇒ **每一次崩溃、每一个脏块，都会在盘上留下一对五元组完全相同的「孤儿 + 活版」。**
这正是 C113 那条欠账的名字所说的东西——「扫描重建时多版单元的现行版本判定」——
也正是 2026-09-05 给三类单元的类身份段统一加 10 字节写序（定案 P1）要解决的问题。

**丙-2 的树 ID 重发没有创造任何新的失败形态**，它只是把一个**已经被专门解决过、而且是主线情形**的
碰撞，从「已存在的树」扩到「新建的树」。判定这个碰撞的机制（写序 + 实例表行 + 已发布谓词）
**与树 ID 正交**，且它今天就在为常态承重。

### 2.4 D6 判据 9 的理由句管不管孤儿

`06-快照实现模型.md:110` 逐字：

> | 9 | **标识不回收 + 布局无关**：快照标识单调不回收，位宽写进格式并声明生命周期内创建总数上界 | 回收一个快照 ID 会让盘上遗留的旧 key 在新快照里**变成可见**，与 C11（feature bit 跳号） 同型。

理由句的动词是「**变成可见**」。可见性由判据 1 的单一谓词给出（`06:` 判据 1 逐字
「存在唯一一个「S 引用 b」的谓词，**同时**驱动读可见性与空间回收」），
而那个谓词作用在**树里的 key** 上。孤儿单元不在任何树里——根压根没写成，没有任何索引路径指到它。

⇒ **判据 9 的理由句只覆盖已发布的 key，管不到孤儿。** 材料里那句「仓里没写」，
答案是：写了，写在理由句的动词里，只是要把它读准。

唯一一条**不经索引**就能看见孤儿的路径是扫描重建——而已发布谓词这道闸正好装在那里（§2.1 / §2.2）。

### 2.5 扫描重建三级降级：重发的 42 在哪一级被看见

`18:344-352` 的表：

| 级 | 拿到什么见证 | 处置 |
|---|---|---|
| 2 | 分配记录 + 校验和 / MAC 双证 | 可写，正常晋升 |
| 1 | 只有校验和 / MAC 自洽，没有分配记录 | **只读挂载** |
| 0 | 连校验和都验不了 | 只报告，不进映射 |

同节 2026-09-03 用户定案逐字：「分配记录**是派生态**……⇒ **级 2 的见证者没了**。级 2 要么另找一个住在权威态里的双证，要么这一格重开；**级 1 与级 0 照常可用**」
⇒ **今天只有级 1 与级 0 存在。**

孤儿的头是完整写下去的（校验和自洽）⇒ 落在**级 1**（撕裂的落级 0）。级 1 = **只读挂载**，
且 `18:` 落实第 3 条逐字「任何权威态结构不得由重建结果就地修复」。
所以即使前面两道闸全失效，最坏结局也被夹在「只读 + 不许就地修复 + `map_provenance = rebuilt`」里。

**最坏的那一格单独看**：实例表读不出来时，`18:697` 逐字
「表没了就一条行都没有，全部旧实例的全部单元落进「无行 ⇒ 已发布」」。
这时第一道闸整个失效，孤儿被判已发布 ⇒ **只剩择新键**。而择新键里的实例代号仍然判活的赢（§2.2）。
⇒ **这条最坏路径上丙-2 也不产生错答案**，只是防线从两道退到一道。
注意这一格与树 ID 无关：表没了的时候，甲的孤儿同样全部判已发布，只是它们的树 ID 不撞车而已——
而不撞车在这里买不到东西，因为撞车的判别本来就不由树 ID 做。

### 2.6 孤儿什么时候被回收、之前存在多久

`03-空间分配.md:201` 逐字：

> 孤儿（没有条目）要求头里的写序实例 < 当前实例 ∧ 按实例表的已发布谓词判未发布（当前实例没有行，它的孤儿只能是在飞的写，交给 overlay 那一条）

⇒ 孤儿的回收准入**同样只看写序实例 + 已发布谓词，不看树 ID**，且题设的 42 一开门就满足（i_old < i_now ∧ 判未发布）。

**存在多久**：到下一轮覆盖到它的整轮清扫为止；清扫水位（D5 已定项 4 第 13 项）
「只在整轮清扫完成时推进，中途进度不持久化」（`05-快照-空间记账机制.md:331`）。
⚠️ **zoned 第一版不回收、链长无上界**（`18:697` 逐字，C121）⇒ **zoned 上这批 42 在第一版里永久存在。**
这不改变结论：`18:697` 的回收条件逐字要求「其中没有该实例的未发布单元」
⇒ **孤儿在，实例表的行就删不掉，谓词就一直判它未发布。判定与回收互相扣死，不会出现「孤儿还在而行没了」的空窗。**

## 三、三种结局逐一论证

### (a) 根本不是错误 —— **采纳**

依据是 §2.1–§2.6 的合取，五条独立成立：

| # | 论点 | 逐字出处 |
|---|---|---|
| 1 | 作废 checkpoint 必须换实例代号 ⇒ 孤儿与活版的实例代号必不相等 | `18:697`「**作废一个 checkpoint 必须换实例代号**」 |
| 2 | 已发布谓词把孤儿判成未发布，输入里没有树 ID | `18:697` 谓词全文；`invariants.md:21` |
| 3 | 扫描重建先滤后择，两步都不看树 ID；择新键含实例代号 ⇒ 孤儿恒输 | `18:675`「先按实例表的已发布谓词滤掉……再……取该类的择新键最大者」 |
| 4 | 孤儿 / 活版共用五元组是**常态**，写序就是为它加的；树 ID 重发不新增形态 | C113 的名字（「扫描重建时**多版单元**的现行版本判定无输入」）；`18:675`「码 1 取写序」；`18:451` 定案 P1 给三类身份段统一加写序 10 |
| 5 | 判据 9 的害处是「变成**可见**」，可见性作用在树里的 key，孤儿不在树里 | `06:110` 理由句；`06:` 判据 1 |

**反推（假设 (a) 错，本该看到什么）**：应当存在**至少一条**判定路径，它的输入里有树 ID 而没有
(实例代号 / 诞生代号)。逐个查了树 ID 的全部身份用途——
五元组（码 1）、索引节点类身份段（码 2）、容器索引 key `(出生树 ID, 打包记录类型, 容器号, 容器出生代)`、
记账 key `(统计量, 树 ID, 设备, 代)`、inode key 唯一性范围 `(树 ID, inode)`、
平局判别子候选 `(诞生 txg, 树 ID)`——**零命中**：
前四条都经 §2.2 的两道闸；码 2 逐字「**不进扫描重建的择版本规则**」（`18:675`）；
第五条比的是活树内部的 key，孤儿不在树里；第六条只在**已发布**的快照之间取全序，
而丙-2 保证的正是「已发布序列上的单调」（§4.2）。

### (b) 是错误但补得上 —— **只剩一条骑手，且它是字面问题不是机制问题**

**唯一没被 (a) 吃掉的**：D6 判据 9 的**字面**要求是「快照标识单调不回收」，
而丙-2 在崩溃那一格**确实回收了**一个发出过、但只被孤儿用过的标识。
机制上无害（§2.4），**字面上违反**。

- **补法**：把判据 9 的射程收窄成「**已发布**的快照标识单调不回收」，依据是它自己的理由句
  （害处是「盘上遗留的旧 key **变成可见**」，而可见性只对树里的 key 有定义）。
- **要动的已定条款**：`06-快照实现模型.md:110` 判据 9 的条件列（正文改一句），
  以及 `08-核心索引结构.md:366`「**inode 号单调不复用**（D6 判据 9 的戒律）」那句的引用射程。
- **代价**：一次决策变更 + 一条历史条目；**要用户定案**（判据 9 是 D6 的九条准入条件之一）。
- ⚠️ **收窄之后要当场回扫已在册的条目**（`evidence-discipline.md`「新立一条判据，当场拿它回扫」）：
  收窄同样落到 C143（inode 号水位在回退后会退回去重发）身上——按新射程，
  inode 号在回退后被重发**只在它被重发给已发布对象时**才违规。这会让 C143 的形状变，
  **不是让它消失**（回退与崩溃不同：回退抛弃的是**已发布过**的时间线，`23:1172` 的候选集规则逐字排除它们）。
  这一条必须与丙-2 的定案同时处理，不许留到以后。

### (c) 是错误且补不上 —— **不成立**

要走到 (c)，得举出一条判定，它 ① 看得见孤儿 ② 输入里有树 ID ③ 输入里没有实例代号。
上面的普查零命中。**我没有找到 (c) 的实例，也说得出什么现象会推翻这句话**：
若有人指出某条判定同时满足 ①②③，(a) 与 (b) 一起作废。

## 四、材料说「甲在轴 6 上赢」——真的赢吗

### 4.1 中途预留崩在半路：**甲仍然赢，我攻不破**

题设：挂载时写了 `base + K`，本次建了 K+1 棵树，中途预留第二段，第二段的超级块写崩在半路。

三条独立理由，合起来封死：

1. **先持久后使用**。`08:432` 逐字：「水位**永远先于使用落盘**（发号之前那一整段已经写下去了）⇒
   「根槽 FUA 已落、超级块没写」那个窗口不存在」。⇒ 第二段的号在全或无写完成之前**一个都没发出去**。
   崩在半路 ⇒ 盘上部分副本是 `base+K`、部分是 `base+2K`；下次挂载取 max ⇒ 不低于任何已发过的号。
2. **过半独占打开 ⇒ 写入集合两两相交**。`18:697` 逐字：「**独占打开池中过半的设备**——任意两个过半集合相交」，
   且「取号的写入集合与 max 的取值集合取同一个」。⇒ 下次挂载的取值集合必然含前一次写入集合里的至少一台设备。
3. **甲-2 的树表项只把 max 顶上去**。`08:432` 逐字：「树表这一路**只会把 max 顶上去、不会拉下来**」。

**回卷那条路也不破**：回卷写的是内存里那个「旧值」= `base+K`，而第二段的号从未发出 ⇒ 回卷到 `base+K` 安全；
回卷自己崩在半路，盘上是新旧混杂，取 max 仍取到高的那个 ⇒ 更安全的方向。

⇒ **轴 6 那一格判甲赢，我复核后维持。** 材料没写错。

### 4.2 但要把「赢了什么」和「为此付了什么」分开记

**赢的那样东西，按第三节等于零。** 甲多盖住的是「被抛弃 checkpoint 里发过的号」，
而那些号的唯一用户是孤儿，孤儿的判定与树 ID 正交（§2）。

**丙-2 在同一格失去的也不是全部单调性**：根记录里的水位是**累计高水位**（每次发布重写，
取「环里的 max 与本 checkpoint 发出的最高号」的较大者），所以
**已发布的树 ID 序列在丙-2 下仍然严格递增**——这正是 `08:432` ② 给平局判别子
`(诞生 txg, 树 ID)` 要的那条性质（「②让它单调 ⇒ (诞生 txg, 树 ID) 就是与创建序一致的全序」）。
丙-2 只在**未发布**那一段不单调。

**甲为这个零付的价**（全部逐字出自 `08:432` 与 `checks-owed.md:153`）：

| 付出 | 逐字 |
|---|---|
| 甲-1 区段预留把协议从「挂载时一次」改成「挂载时 + 运行期反复」，**由此带出六件没定的事**（C147） | 「区段预留把「挂载时一次、动单元之前」的协议改成「挂载时 + 运行期反复」，由此带出六件没定的事」 |
| ㈠ **一个没有出路的洞** | 「挂载中途预留失败没有出路……回卷成功则这次挂载一个号都发不出来却还活着，**行为无定义**」 |
| ㈢ **一条格式级硬要求，是第一个事务的字节** | 「树 ID 必须落在每条条目的固定前缀里，不认识其余部分也取得到——是第一个事务的字节」 |
| ㈣ **没有任何不变量** | 「实例代号有 I-7.7、inode 号水位有 I-9.6、nonce 有 I-6.5，**树 ID 水位一条都没有**」 |
| ㈤ 「水位」两义 / ㈥ 消耗速率是 `K × 挂载次数` | 同条 |
| 超级块 420 → 428 | `08:432` |

**丙-2 在这几格的对照**：
㈠ 不存在——根记录每次发布本来就写，没有第二条写路径、没有回卷；
㈢ 不存在——不用树表当见证；
㈣ 有现成形态可抄（I-7.7 同形，材料轴 5）；

字节代价 186 → 194，槽内余量 326 → 318（`22:396`）。

### 4.3 一处甲**输给**丙-2 而材料没记的轴：回退与崩溃是同一套机制

甲要两套：崩溃靠超级块 max（轴 6），回退靠「回退不动超级块」（轴 1）。
丙-2 只用一套：`根环里全部根记录的 max`，而 `23:1172` 逐字「回退深度 ≤ 根环深度」
保证被回退跨过的根都还在环里 ⇒ 同一个公式同时覆盖两格。
`.claude/rules/fs-design.md`「一个事务层，所有结构共用」的取向站在丙-2 这边。

## 五、一句话结论

> **丙-2 该取代甲**：轴 6 那个「输」经论证**根本不是错误**（判孤儿的尺子是写序 + 实例表行 + 诞生代号，
> 里面一个字的树 ID 都没有；孤儿 / 活版共用五元组是这套设计的**常态**，写序就是为它加的），
> 而甲为盖住这个零付出了 C147 的六件事、一个行为无定义的洞（㈠）、一条第一个事务的格式级字节（㈢）
> 和一条根本不存在的不变量（㈣）。**丙-2 在其余五根轴上不劣于甲，接受条款的后半句成立，这条定案应当重开。**
> 代价是一次要用户定案的骑手：把 D6 判据 9 的「快照标识单调不回收」收窄成「**已发布**的快照标识单调不回收」，
> 并当场把这条新射程回扫到 C143 上。

**我最不确定的那一处**：**丙-2 的水位取值语义仓里还没有一个字**——我按「每次发布重写的累计高水位」读它，
§4.2 的「已发布序列仍严格递增」全靠这个读法。若有人把它读成「本 checkpoint 发出的最高号」
（不累计前代），那么一棵树的 ID 随根轮出环就会被重发，**那时 (a) 立刻不成立，因为被重发的号
属于已发布的树，判据 9 的理由句正面命中**。
⇒ **重开定案时这一句必须与丙-2 同时写死**：「根记录里的树 ID 水位 =
max(根环里全部根记录的该字段, 本次 checkpoint 发出的最高树 ID + 1)，每次发布重写」。
写不死它，丙-2 就不该采纳。

次不确定的一处：`09-加密.md:483` 的 `AAD = (单元类型标签, 树 ID, 对象 ID, 对象出生代, 锚点偏移)`
与五元组逐字段相同 ⇒ 孤儿与活版的 AAD 也相同。我判它**不是丙-2 的新债**（§2.3：这在甲下对
所有既有树同样发生，是 D9「AAD 缺快照维」那次欠着的重开的一部分，且 D9 已定项 10 定加密不进第一版），
但这个判断依赖「AAD 碰撞在有 MAC 逐块比对时买不到额外攻击面」，**我没有在仓里找到把这句话钉死的条款**。
