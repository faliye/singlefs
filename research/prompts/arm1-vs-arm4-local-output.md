1. The sweeper predicate in F6 only governs wiping blocks but does not address reallocation. A block can be reallocated even if the sweeper predicate would not wipe it. For example: a block is freed with free generation 100. The oldest root in the ring has checkpoint generation 50. The sweeper predicate (F6) requires free generation <= 50 to wipe, so this block is not wiped. However, the allocator can reallocate this block immediately after freeing. If a root with generation 60 references this block, the reallocation would overwrite the block, making the root's reference invalid. This creates a fake candidate because the root is valid but references a reallocated block.

2. The conjunct would need to check that the block's current allocation generation is greater than or equal to the root's generation. However, F10 states allocation records are rewritten as "freed plus free generation" when freed and overwritten when reallocated. When reallocated, the allocation record no longer contains a free generation field. Thus, on-disk state lacks information about when the block was reallocated. For example: a block is freed with free generation 50, then reallocated. The allocation record now shows allocated state without generation data. A root created at generation 40 references this block. On-disk state shows allocated but no generation to compare against the root's generation. The system cannot determine if the reallocation occurred after the root was created.

3. Deriving K from F6's predicate fixes K to a value determined by the oldest root's checkpoint generation, making it non-tunable. F12 explicitly warns that K must remain a runtime policy with lower bound 2 and not become a format constant because welding it down buys nothing. FOUR's approach makes K fixed (not tunable), subject to the same objection as ONE despite claiming zero new parameters.

4. Under ONE, K equals N. If R=3 and S=10, N=30. Today, an administrator could set K=2 to minimize storage overhead for rollback. Under ONE, K must be 30 regardless of storage needs. This prevents reducing K below N, forcing retention of all 30 roots even when only 2 are needed, increasing storage costs unnecessarily.

5. FOUR is more likely to fail silently. The derived K from F6's predicate governs the sweeper but does not ensure the allocator checks sufficient roots. For example, if the allocator uses a K derived from the sweeper's oldest root generation (e.g., K=1), it may reallocate a block referenced by a root older than the oldest root in the ring. The system would not detect this because the allocator's check uses insufficient K, leading to corrupted data without any error reporting.
