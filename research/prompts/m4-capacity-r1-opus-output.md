## 三个候选都要碰的三件今天的实现

1. **写系统配置槽的入口每写一次都从内存里的参数与这一刻的盘表重拼整槽。**「let identity = self.devices[index].0;」（`crates/singlefs-core/src/transaction.rs:679`），「this_device: identity,」（`crates/singlefs-core/src/transaction.rs:722`），「sizes: self.parameters.geometry,」（`crates/singlefs-core/src/transaction.rs:725`）。本盘设备号这个唯一的盘级字段，就是每次写都按这一刻的盘表现填的；mkfs 那一侧的说法是「本盘设备号由 mkfs 逐盘现填，设备数由池里的盘数现数」（`crates/singlefs-core/src/system_configuration.rs:247`）。取号两轮、发布末尾的轮换、抬 F、离线出路 α'（`crates/singlefs-core/src/system_configuration_repair.rs:402`「两槽都不自证时写两次」）、补写全经这一个入口。
2. **择系统配置只留按盘表次序第一块可择的盘那一份**，后面的盘只核 fsid 与设备数：「|| previous.immutable.device_count != best_on_device.immutable.device_count」（`crates/singlefs-core/src/recovery.rs:1901`）；一块盘两槽都不可择时跳过它：「一块盘两个槽都无效时**跳过这块盘**，接着看别的盘」（`crates/singlefs-core/src/recovery.rs:1758`）。池级值被拒时整池拒的理由也押在「各份相同」上：「池级字段两盘四槽同值，换一槽换一盘读到的还是它 ⇒ 整池拒绝挂载」（`crates/singlefs-core/src/recovery.rs:755`）。
3. **只读挂载不判分配记录的落点。** 它的整条路是「/// 只读挂载：择系统配置 → 择根 → 全环扫描 journal → 按前缀口径施加 → 沿施加之后的根打开挂载态。」（`crates/singlefs-core/src/mounted_read.rs:640`）；落点越过单元区末尾那一判（「what: "分配记录的跨度越过单元区末尾",」，`crates/singlefs-core/src/recovery.rs:2868`）在只读挂载那份文件里一处调用都没有：

```
$ grep -c 'allocation_records\|placement_lies' crates/singlefs-core/src/mounted_read.rs; echo rc=$?
0
rc=1
```

（只核了 `mounted_read.rs` 这一份；它调到的 `recovery` 函数里有没有间接判，没逐个追，推的是没有：`mount_read_only_from_the_system_configuration_choice` 调的是 `choose_root`、`scan_journal`、`replay_journal`、`fall_back_judged_on_the_three_readers`、`open_pool_for_read`，名字里都不是分配记录。）

另：分配器今天的界取探测值，「DeviceFreeMap::with_unit_area_start(*identity, device.size_in_bytes(), unit_area_start)」（`crates/singlefs-core/src/mount.rs:3242`）。

## 第 1 格：三个候选各自哪里把「用错了」漏成「挂得上」

判据照 `.claude/rules/fs-design.md@格式分支的判据`：「能就值得，不能就不值得」。这一轮的「用错了」= 交给挂载的盘比池上次用它时小（截短、换成更小的盘、撤回扩容）；「挂不上」= 挂载拒或至少报出来。每条历史只固定前缀与故障，用户动作放开扫（`.claude/rules/three-way-inference.md@判决由主 agent 做，不由投票做` 最后一条）。

### H1 甲：盘 d 的容量记录只住在盘 d 自己两槽里，两槽全废时没有第二份（打中，分辨甲与乙丙）

- 前缀：mkfs 两块 4 GiB 盘（甲：每盘自己两槽记 4 GiB）；写若干版本，使某一版回退候选（txg ≥ F）在两盘同一槽号 s 上有单元、s 在 3 GiB 之后（造法同 `unequal_devices.rs` 直接改空闲图那一路）。
- 用户动作 u1：盘 1 换成 3 GiB 的盘（块拷贝拷到盘尾报满，或 `lvreduce` 原地截短）。
- 用户动作 u2：盘 1 头 8 KiB 被写成读得出而自证不过（例：对盘 1 误跑分区工具，GPT 写 LBA 0–33，盖住槽 0 [0, 4096) 与槽 1 [4096, 8192)）。
- 甲：择系统配置跳过盘 1（`recovery.rs:1758`），盘 1 的容量比对没有左边。条款写「没有记录就不比」：只读挂载做成，读到 s 上的单元时盘 1 那份越界读不出、退到盘 0 那份，冗余静默少一份 ⇒ 用错了 → 挂得上。条款写「没有记录就拒」：撞 `.claude/kb/decisions/22-单元原子性怎么合成.md@已定项 8：固定结构的放置` 射程里用户开的补写例外（「某块盘两槽全废（一份本池自证过的系统配置都没有）时，取号那一步补写它的两槽」）——补写要往盘 1 槽里写一个容量值，甲手里只有探测值 3 GiB，写进去就把缩小洗白成「记录 = 探测」；补写闸只核「这块盘带所选那一版的全部单元」，回退候选在 s 上的单元不在闸里。
- 乙、丙（槽内表）：盘 0 两槽带 rec[1] = 4 GiB，比对有左边 ⇒ 拒（或报，看第 3 格）；补写时写者从择到的那份抄 rec[1]，不洗白。
- 放开扫：u1 单独 → 三个候选都拒（盘 1 两槽在）；u2 单独 → 三个候选都照 C463 走、容量不变，不涉；u1、u2 两种先后 → 甲漏、乙丙拒；u1 换成「原地截短」同；u2 换成「头部介质坏、读报错」→ 可写那一半今天补写闸照旧拒（同一射程「有一槽设备报读错的照旧拒」），只读那一半甲照样没有左边。
- 四问：① 分辨甲与乙丙。② 乙丙在挂载那一刻看得到判别子（别的盘槽里的 rec[1]）；甲的盘面上根本没有它——这正是候选之间要比的格式差，不是判据写错。③ 满足判据的反面：用错了（盘 1 缩小）→ 挂得上（甲只读做成）。要两步用户动作，或一步用户动作加头部两槽一起坏；D22 已定项 8 射程「容错承诺是单故障：每盘一槽系统配置坏在承诺里」，两槽都坏不在单故障承诺里，但补写例外是用户为这一形专开的路，所以它在被支持的路上。④ 甲唯一的改法是「盘 d 没有自证过的槽就拒、补写也拒」，等于对容量撤掉补写例外（撞用户定案）；乙丙不用改。
- 推翻条件：主 agent 现查出补写与只读挂载在两槽全废时另有一个盘 d 旧容量的来源（甲的设计里写了别处），H1 就不分辨。

### H2 甲字面「照本盘设备号那样」，退化成 C180 的同形（打中，写法问题，三个候选都可能中，甲字面带着它）

正文第 1 格把甲定义成照本盘设备号那样每块盘只记自己（转述正文问题第 1 条）。本盘设备号的写法见上面第 1 件：每次写都按这一刻的盘表现填。C180 立账的理由正是这个写法：「若身份只从各盘自己的系统配置取，两边恒等、比对恒真」（`.claude/kb/checks-owed.md:138`）。

- 甲照抄这个写法，容量那一格每次系统配置写都按这一刻的探测值现填 ⇒ 记录 = 上一次写那一刻的探测值。可写挂载上判容量在任何写之前，「两次挂载之间缩没缩」这一半还在；凡是不先判容量就写系统配置的路都把缩小洗白。
- 历史：盘 1 截短 → 可写挂载按容量拒 → 盘面同时落在 R2 判不出那一形（D22 已定项 8 射程的离线出路前提）→ 管理员跑离线出路 α'，它重写盘 1 不自证的那一槽，新世代号那一槽带探测值 → 下一次挂载记录 = 探测 ⇒ 过；X 之后有已发布落点的，可写挂载由落点判兜住，只读挂载放行。
- 四问：① 不分辨候选（是写者取值的来源）；甲是唯一字面带它的。② 离线出路读得到盘 1 另一槽（若自证过）里的旧记录；两槽都不自证时读不到（回到 H1）。③ 同 H1。④ 改法「写者抄择到的记录；探测值只在变大、判过之后经一次显式的记进来」修这一格全部；修不了 H1 里甲两槽全废那一格。

### H3 乙：池级字段第一次会变，而择系统配置只留第一块盘（打中一半，分辨乙丙与甲）

乙让容量表成为池级、而且会变。今天的池级字段 mkfs 之后都不变，择系统配置靠这一点只留第一块盘、只核 fsid 与设备数（「各盘择到的之间 fsid 与设备数要对得上」，`crates/singlefs-core/src/recovery.rs:1680`），值拒绝整池拒的理由也押在「四槽同值」上（`recovery.rs:755`）。

- 历史 1：盘 1 从 X 长到 2X → 可写挂载，取号第一轮写完盘 0、写盘 1 之前崩溃 → 盘 0 最新槽 rec[1] = 2X、盘 1 最新槽 rec[1] = X。读者取第一块盘得 2X；用户再把盘 1 退回 X ⇒ 拒（假红，安全向）；盘 0 两槽之后都不可择（C463 形）⇒ 择到盘 1 那份得 X。这一态里没有分配越过 X（分配在挂载做成之后），不漏。
- 历史 2（把「记」放到发布末尾的轮换，见 G1）：轮换按盘表次序若先写盘 1，崩溃在写盘 0 之前 → 盘 1 新、盘 0 旧；根已 FUA、单元已在 X 之后；用户把盘 1 截回 X → 读者取第一块盘得 rec[1] = X = 探测 ⇒ 容量比对放行；可写挂载由落点判兜住，只读挂载放行 ⇒ 漏。
- 四问：① 分辨乙与甲（甲每盘只比自己）。② 两盘的槽都读得到，读者取得出各盘最新可择槽的逐项最大值。③ 历史 2 满足判据的反面（只读）。④ 改法 a「逐项取大合并」修历史 2 里择到旧份那一格；改法 b「记随取号两轮、先于分配器建图」修「记得晚」那一半；两个合起来乙不漏。两个都只在我的推演上过，被攻过零轮。

### H4 乙照 I-7.15 的形态立 checker 不变量，会把合法崩溃态判红（打中，第 7 格连带）

「I-7.15：各盘所选的系统配置槽里的设备数相同（形态抄 I-1.4 的 fsid 那一判）」（`crates/singlefs-checker/src/image.rs:473`）。给乙照抄成「各盘所选槽里的容量表相同」，H3 历史 1 那一态（取号一轮写到一半崩溃）是合法崩溃态，崩溃点重放每个态恢复之后都跑 checker，它会红。甲没有跨盘相等这一说，不中；丙槽内同乙。

- 四问：① 分辨乙丙与甲。② checker 看得到两盘的槽。③ 不是第 1 格判据的分句，是第 7 格的连带（交主 agent 归格）。④ 改法：判「各盘合并后的记录 ≥ 被任一根引用的落点所需」与「记录 ≤ 镜像里那块盘的字节数（缩小那一形另判）」，不判跨盘相等。零轮。

### H5 丙：越位（打中，第一轮「过度外推与越位」那一面）

D12 已定项 5 写设备描述符表「加第二套布局前必须写」，D22 已定项 15 写「第一版不留间接目录单元指针（显式留白，不是留位），设备描述符表第一版不写」（`.claude/kb/decisions/22-单元原子性怎么合成.md:337` 的定案句，转述其中两段）。丙等于现在就写，而那张表在条款里装的不只容量：

- 它是 D12 已定项 2 第一桶「设备 → 布局」表的落点（`.claude/kb/decisions/12-目标介质.md@已定项 3：设备级几何量住系统配置里的设备描述符表`）；
- 身份列要设备内禀身份，落点与宽度没定（C180）；
- 表住槽内还是移出槽、移出时取哪个码没定（C218）；
- 条目宽没定：「它的条目宽度按 24 / 40 / 64 三档各算一次，都是假设，仓里没定过」（`.claude/kb/decisions/12-目标介质.md:58`）。

两种做法各撞一处：只放容量一列 ⇒ 机制上就是乙（槽内逐盘一项、每份都带），另把「设备描述符表」这个名字占给一张缺布局列与身份列的表，加第二套布局时扩列是又一次动格式；放全列 ⇒ 这一轮替上面四件没定的项拍板，超出这一题。移出槽的那一形另有一处：表单元挂在系统配置下、不挂根下，变大要换单元、改每份系统配置里的指针，旧单元何时能回收没有条款（不随根走，D2 已定项 15 的死亡触发事件判据对它答不出），回收早了，崩溃留下的旧槽指到被复用的槽（单元头自证会拒、不静默，推的）。

- 四问：① 丙住槽内与乙不分辨；移出槽那一形分辨。② 不适用。③ 不是第 1 格判据的打中，是越位。④ 改法：丙降成「乙，字段名不叫设备描述符表」；或把「现在开那四件」交用户。

## 第 4 格：「变大 ⇒ 放行并记」

条款原文「| 设备容量 | 变小 ⇒ **拒绝**；变大 ⇒ 放行并记 |」（`.claude/kb/decisions/12-目标介质.md:74`）只说记，不说记在哪一步、写几份、先于什么。

### G1 记晚于分配：崩溃窗里撤回扩容，只读挂载放行（打中，三个候选都中）

前提：「记」随发布末尾的系统配置轮换写（发布顺序里系统配置在根之后：「系统配置槽写是发布序列**之后**的最后一步」，`.claude/kb/decisions/22-单元原子性怎么合成.md:301`），分配器的界取探测值（今天就是，`crates/singlefs-core/src/mount.rs:3242`）。

盘面照 `unequal_devices.rs`：盘 0 4 GiB、盘 1 3 GiB + 33 槽（单元区末尾槽号 196641）。

1. 盘 1 长到 4 GiB（`lvextend`、`losetup -c`）。
2. 可写挂载：探测 4 GiB > 记录 ⇒ 放行；取号两轮不带新容量（「记」不在取号里）。
3. 一次发布：数据单元两盘同槽落在 196641 之后（分配器要两盘同槽，盘 0 本来就有、盘 1 长出来之后也有）；单元写、屏障、journal 记录、根 FUA。
4. 崩溃在根 FUA 之后、系统配置轮换之前。
5. 用户撤回扩容：把盘 1 截回 3 GiB + 33 槽。
6. 只读挂载：记录 = 探测 ⇒ 放行；只读挂载不判落点（上面第 3 件）；读那个文件，盘 1 那份越界读不出、退到盘 0 那份 ⇒ 读得到，冗余静默少一份。可写挂载由落点判（`recovery.rs:2868`）拒，兜住。

放开扫步 5：什么都不做 ⇒ 下一次挂载再判变大、再放行，不漏；换回扩容之前那块旧盘（内容旧）⇒ 落后支处置，与容量无关；截到比 3 GiB + 33 槽还小 ⇒ 三个候选都拒。漏只落在「截回不小于旧记录」这一族，正是撤回扩容的自然动作。

### L2 写成池级标量、或照 C1040 行字面互比：红

## 最脆弱的前提

### P1 「容量记录是探测之外的第二个来源」

整套「变小拒、变大放行并记」只在记录不是探测值的回声时才有判别力。今天的写者每写一次系统配置就按这一刻的输入重拼整槽（transaction.rs 第 679、722、725 行），已有的盘级字段就因此没有第二个来源（C180）。要让容量记录真是第二个来源，两件事必须同时成立：

- (a) 每一条写系统配置的路写的是记录，不是探测；探测值只在变大、判过之后经一次显式的记进来（H2、G4）；
- (b) 记在分配器用到新空间之前，已经落在读者可能择到的每一份里（甲：那块盘两槽；乙丙：每块盘两槽），不靠之后的轮换补齐（G1、G2）。

被打穿时谁站得住：

| 被打穿的那一半 | 甲 | 乙（与丙槽内） |
|---|---|---|
| (a) 有一条路照写探测值（离线出路 α'、补写、将来的写入口） | 倒：那块盘两槽一起被重写时旧值无处可取（H1、H2） | 站得住，条件是写者从择到的那份抄、读者逐项取大：旧值在别的盘上 |
| (b) 取号第二轮被删（C974） | 倒：一槽坏、退回旧槽就退回旧容量（G2） | 站得住，条件同上：别的盘槽里有新值 |

## 没打中的形状

- **设备对调、克隆盘冒名**：可写挂载在容量比之前先判本盘设备号与盘表给的身份（`own_device_numbers_on_disk_differing_from_the_identities_handed_in`，`crates/singlefs-core/src/mount.rs:7418`），对调与克隆冒名在那里就拒；甲（记录跟着盘内容走）与乙（记录按盘表位置索引）在可写挂载上不分辨。只读挂载判不判本盘设备号没查，那一半没攻。
- **回退下界、回退候选集**：见第 4 格末节，没打中。
- **截到单元区起点之前**：`every_device_reaches_the_unit_area_start`（`crates/singlefs-core/src/recovery.rs:2880`）今天就拒，三个候选同。
- **三块盘以上、乙的表长随设备数变**：「第一版加盘准入拒绝让 `w ≥ 3` 可达的设备集合变化，`devs` 上限 2」（`.claude/kb/decisions/02-RAID条带策略.md:302`），第一版不可达，没攻。
- **挂着时盘在线长大**：句柄打开时取的字节数在这次挂载里不变，下次挂载才判，三个候选同。
- 扫过的用户动作：撤回扩容（截回旧记录 / 截得更小）、什么都不做、换回扩容前的旧盘、拔掉缩小的盘、对盘误跑分区工具、跑离线出路、管理员回退、对调两块盘的接线。

另报一处第 2 格的实现陷阱（不在这四格里，不算打中）：回退下界 F 的偏移由字段表合计推出，「const ROLLBACK_FLOOR_OFFSET: u64 = SYSTEM_CONFIGURATION_BYTES - ROLLBACK_FLOOR_FIELD_BYTES;」（`crates/singlefs-core/src/system_configuration.rs:85`）。容量字段若「追加在字段表末尾」、改大合计，core 里 F 的偏移跟着静默挪到新表的末 8 字节；而 journal tail 是写死的「const TAIL_OFFSET: u64 = 469;」（`crates/singlefs-core/src/system_configuration.rs:80`），checker 与 GPU 判器各有自己的偏移。插在 F 之前则 469 之后的每个写死偏移都要挪。三个候选不分辨。

## 这条腿自己的限度

- 没写模型、没枚举崩溃态。G1、G2、H3 各只挑了一个崩溃态推的；没有一个数。坐实它们要建的原型（形状，交主 agent 定要不要派）：盘面取 `unequal_devices.rs` 那一种、内存稀疏盘；历史「mkfs → 盘 1 变大 → 可写挂载 → 一次发布落到旧末尾之后」；对录制流调 `enumerate_crash_states` 逐段展开；每个崩溃态恢复之后再放开用户动作 {不动、截回旧记录、截得更小}；臂取 {甲、乙取第一块盘、乙逐项取大} ×「记」的位置 {取号两轮、取号一轮、发布末尾轮换}；判「只读挂载放行且有已发布落点越过探测」的态数。状态数没估。
