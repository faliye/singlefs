1. Workload: 100000 objects of 512 bytes each written once then modified 100 times at 1 modification per minute. Compaction triggered every minute with compactor walking in container fill order. Without proposal: 101 writes per object × 100000 objects × 32768 bytes = 3312800000 bytes. With proposal: initial writes 3276800000 bytes + 100 modifications × 3276800000 bytes + 100 compaction runs × (113000000 bytes container writes + 3280000000 bytes mapping rewrites) = 3276800000 + 327680000000 + 339300000000 = 670528000000 bytes. Proposal loses by 339248000000 bytes.

2. Workload: single 512-byte object modified 10 times. Each modification triggers compaction. Without proposal: 1 initial write + 10 modifications × 32768 bytes = 360448 bytes. With proposal: initial write 32768 bytes + 10 × (modification write 32768 bytes + container write 32768 bytes + mapping rewrite 16384 bytes) = 32768 + 10 × 81920 = 851968 bytes. Proposal loses by 491520 bytes. Trigger policy: only compact objects modified more than 5 minutes ago. Policy cost: storing 8 bytes per object for last modification timestamp and checking it during compaction.

3. Workload: 100000 objects of 512 bytes written then 99000 deleted. Without proposal: 1000 live objects × 32768 bytes = 32768000 bytes. With proposal: 1725 containers × 32768 bytes = 56524800 bytes. Proposal loses when dead slots exceed 99% of total slots (99000 dead out of 100000 slots).

4. Data loss scenario: a single disk sector failure corrupts one container unit holding 58 objects of 512 bytes. Without proposal, one unit failure loses one object. With proposal, one container failure loses 58 objects. Acceptable only if redundant storage (e.g., RAID or replication) exists to recover the container unit.

5. Failed constructions: attempting variable-sized containers below 32768 bytes failed because all units must be exactly 32768 bytes. Allowing mutable containers failed because it violates copy-on-write semantics requiring new units for modifications. Not rewriting central mapping entries failed because object locations would become inaccessibleorrupted. Using fixed slot counts for all object sizes failed because it wasted space for smaller objects or failed to pack efficiently. Running compaction before object writes failed because objects were not yet written and compaction had nothing to process.
