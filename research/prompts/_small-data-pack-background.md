# 论证轮：小数据打包容器（用户 2026-09-07 提案）

## 提案原文（用户，逐字）

> 我们的单元 32kib 我们允许头以外的文件数据长度为0 我们用一个标记来标记 如果一个单元的头存在
> 长度为零 标记打开 那么这个单元就是用来存储小数据的 小数据存在slots中。 如果其他的按照cow执行，
> 如果一个小数据大于了我们的界线 那么我们将这个 单元 拆为老的单元 大于界限的数据 剩余的小数据slots。
> 因为末尾的剩余的小数据slots，我们向后查询，如果后面单元是小数据，那么这个单元就存到后面单元的
> slots头部，如果不是，那么就新建一个单元存储这些剩余的小数据slots

补充口径（用户）：「用来部分优化小数据的存储，用来解决连续小数据的空间浪费问题」；
「小数据存到树上，有点别扭」；「遇到致命的 小大小大小大 就不太好用了」。

⇒ 判据是**空间**，不是读写性能；用户已自陈交错负载是弱点。

## 主 agent 的六条判断（这一轮要打的就是这些）

| # | 判断 |
|---|---|
| M1 | 这条路重开的唯一合格入口是「量出小文件负载下 ENOSPC 准入什么时候先撞墙」，空间倍数不构成判据 |
| M2 | D14 已定项 3 立的那一关（多个文件共享一个原子单位）提案没答；码 3 打包记录单元之所以过关靠的是「容器号间接 + 记录不靠别的对象自证」，数据侧照搬需要同一层间接 |
| M3 | 容器身份必须走 D18 已定项 11 登记表的一个新码，不能用「声明长度 = 0 + flags 位」这种隐式编码 |
| M4 | 「向后查询相邻单元是不是小数据容器」违反 fs-design.md 记账纪律第一格；「把溢出 slots 写进已存在容器的头部」纯亏（多一次整容器 COW + 该容器全部对象的引用更新） |
| M5 | 提案重新引入阈值 ⇒ E8 量到的「阈值不是合格的分支变量」重新适用，D14 未定项 5 的崩溃语义重新有对象 |
| M6 | D19 已定项 5（中央映射是解引用唯一入口）削弱了 E66 / D14 当时「另一个文件的指针也得改」这条反对理由，但不消除它——N 个 slot 仍是 N 条映射 key，除非再加一层容器号间接 |

## 已定条款逐字（主 agent 已逐字核过原文，出处在括号里）

- `decisions/04-校验和位置.md` 已定项 2：「单元恒为 32 KiB。短 extent（小文件、尾块、被截断的 extent）
  补齐到整单元，校验和 / MAC 覆盖补齐后的整单元 ⇒ 格式里没有『变长单元』这条分支。」
  代价表：1 KiB 文件 32 倍，4 KiB 文件 8 倍。并写明「空间放大会经 D5 的记账进入 ENOSPC 准入，
  那是运行时决策路径，不是纸面数字」。
- `decisions/04-校验和位置.md` 已定项 7：「占盘长度恒 32768 字节，一个 extent 一个单元，不跨多单元」；
  「切分已收口（2026-09-03，用户定案，三方论证三腿一致）：切分是预留特性，第一版关闭，`extent_off` 恒为 0。」
  重开门槛逐字：「不许拿倍数说事，要拿一个小文件负载量出 ENOSPC 准入什么时候先撞墙。」
  留位理由逐字：「将来唯一可能让切分复活的是压缩……等到真要把多个压缩 extent 打进同一个单元时，
  `extent_off` 才会有非零值。」
- `decisions/04-校验和位置.md` 已定项 3：凑不满一个单元的写走读—改—写，字节写放大恒 8 倍（4 KiB / 32 KiB 单元）。
- `decisions/04-校验和位置.md` 已定项 6：extent 声明长度住单元自描述头，2 字节，值域 0..32768。
- `decisions/14-双轨大小文件-持久临时.md` 已定项 3（2026-08-31 用户定案）：内联阈值 0，一个字节都不内联。
  「判据是原子性，不是性能。」「内联让多个文件的数据挤在同一个索引节点里 ⇒ 一个文件的写牵动同节点上
  其他文件的原子单位。这与 E66 判出局的 `pack` 臂（多个小文件共享一个数据单元）是同一个形状的耦合，
  只是换了个容器。」「今后任何抬高内联阈值的提议，都要先答『多个文件共享一个原子单位』这一关，
  性能数字答不了它。」
- 同上正文「跨文件尾部打包」一行逐字：「否：两个文件共享一个单元 ⇒ 写其中一个要 COW 整个单元 ⇒
  另一个文件的指针也得改，D20 的『单元自包含』当场破掉。」旁证：Linux 里唯一做 tail-packing 的是
  erofs，而它是只读的（`fs/erofs/super.c:658` 无条件置 `SB_RDONLY`）。
- `experiments/66-补齐之后小文件怎么落.md`：三臂实测（真 NVMe，N=5，两条对照全过）。
  `pack` 读与 `extent` 逐档相同（差 ±1.06%），`pack` 写贵 1076–1106%。结论逐字：
  「`pack` 出局。读与 `extent` 逐档相同，写却贵约 11 倍 ⇒ 在 I/O 上纯劣，只买到空间，
  而空间不是本工程的判据。」`pack` 写的 I/O 构成：32768 读 + 32768 写 = 65536。
- `decisions/18-块里携带什么信息.md` 已定项 7：共同明文前缀 42 字节，其中 flags 2 字节——

  「未登记 ⇒ 拒收；新增一类占一个 incompat 位」。码 3 的类身份段是（标签, 出生树 ID, 打包记录类型,

  C103 容器索引无落点；C105 打包容器按发布频率重写的写放大（开放容器在它所属代际内每次发布被 COW

  C106 开放容器数上界 = 树数 × 活代际数 × 活头数；C108 扩展点归属对打包记录单元无判定；
  C116 叶容器的分裂 / 合并纪律没有会失败的检查。

## 未核实 / 显式不知道
