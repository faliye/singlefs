## 三、改法（都被攻过零轮；这一段实现之后的代码轮攻它们）

- **K1 意图载体**：截断意图住 logged_ops，种类码 2，条目宽仍 44（key 10 = 种类 2 + 签发 txg 8；value 34 = inode 号 8、对象出生代 8、目标 size 8、补零 10，非零拒收）；全池活截断条目至多一条。管理员回退时 logged_ops 按种类分来源：截断条目取 R_old 那一版的，整理条目照旧随现行（攻方「甲一」）；`transaction.rs:2971` 那句注释改成照实写、不引 D23。截断进共用走空，次序 `deleted_inodes` → 销毁中的快照 → 截断 → 整理；「队列空」的四处判断（`mount.rs:6574`、`mounted_session.rs:1388`、`:2003`、`admission.rs:448`）改成同一个方法、都算上截断条目。发截断意图的入口断言上一版 `deleted_inodes`、销毁中的快照、截断条目都为空。对 nlink = 0 或不在树里的 inode 截断，在任何写之前拒成类型化错误。
- **K2 先落目标**：意图那次一次发布写记录的 size = N（blocks、改动计数、时间照 unlink 意图的写法）、签截断条目、按 K3 重写尾单元；每一批只从尾部放 K 个单元（与 unlink 共用 `UnlinkBatchSize`），不碰 inode 记录；最后一批放完剩下的（可以 0 个）、同一次发布删截断条目。崩溃后读者只读到截前或截后。读者（`mounted_read.rs`、`recovery.rs`）容忍 size 之外还挂着的单元（不读、不判声明长度），由 K7 的 T-2 保证它们有账。I-1.13 两侧都按 size 滤：重建一侧照 K6 不认领，遍历一侧不收 size 之外的单元与它们的映射 key，两侧各写各的。
- **K3 尾单元与 extent 计划**：N 落在单元 k 中间、单元 k 的声明长度不等于 `N − k × 净荷` 时，意图那次重写单元 k（声明长度 `N − k × 净荷`、补零、整单元校验和）；截到 0 留一个声明长度 0 的单元。`roles_replaced_via_mapping` 去掉「含 Data(0) 就当整份重写」的推断，改成发布路径显式交「这次是不是整份从 0 重写」（三个调用点同一个值），`:9054`–`9070` 那条相等断言原样保留。截断的 extent 计划自己写（不调 `plan_the_extent_tree_after_a_deletion_batch`，它断言至少截掉一个），把罩着被重写单元 k 的那片下段叶到根恒并进重写集。
- **K4 快照**：截断换下的单元（尾部与重写前的单元 k）经 `deadlist_changes_of_this_publish` 判生死。理想模型对数据单元按单元号记出生 txg。
- **K5 变长与洞**：变长不立意图、一次发布做完：最后一个存在的单元声明长度小于 `min(N − 起点, 净荷)` 时把它补零重写到那个长度，之后到 N 都是洞、不写单元。洞在盘上声明（用户 2026-10-16 定）：上段叶条目加两个标签值——3「下段根，下段最后一个单元之后到 size 是洞」、4「内联单元 0，单元 0 之后到 size 是洞」；标签 0（没有数据单元）配 size > 0 是整个文件都是洞。只有标签 3、4、0 的 inode 许单元数少于 ⌈size ÷ 净荷⌉.max(1)；标签 1、2 照旧要相等。读者读洞答 0、不读盘。变长之后再缩回洞里（N 不大于最后一个存在的单元末尾以外）：照 K2 / K3，没有单元可放时意图与最后一批照走单一路径（K11）；洞全被截掉后标签换回 1 或 2。整份覆盖写把洞写成真字节的单元，标签换回 1 或 2。新标签值进 D8（核心索引结构） 已定项 14 与 `.claude/kb/layout/04-fourth-txn.md`。
- **K6 读法 Z 加写序**（用户 2026-10-16 定）：重建时数据单元按重建出的 inode 记录判死活三条，都满足才认领：对象出生代相同；偏移在 ⌈size ÷ 净荷⌉.max(1) 之内（size 之外不认领，不再报不适用，还 C827 的覆盖写变短那一格）；同一 (inode, 对象出生代) 的当前版本里没有偏移更小、出生 txg 更大的单元（有就判死、不认领）。前提是活单元的出生 txg 随偏移不降，出现「写到偏移 o 而不重写 o 之后的单元」的入口（pwrite、punch）时这条要重开，记欠账。D18（块里携带什么信息） 已定项 10 读法 Z 那一句照这三条改写。
- **K7 checker**：T-1 I-4.4 白名单加截断种类（value 只装那三段、补零全 0、inode 在同一版存在且 nlink ≥ 1、对象出生代相等、目标 = 记录的 size、全池至多一条）；T-2 截断中间态有账（每个 inode 存在的单元多于 ⌈size ÷ 净荷⌉.max(1) ⇔ 有一条对得上的截断条目）；T-3 单元数对 size，nlink = 0 与 ≥ 1 都判（合并 I-4.6 与 C711）：存在的单元从 0 起连号，标签 1、2 的个数等于 ⌈size ÷ 净荷⌉.max(1)、标签 3、4、0 的不多于它，有截断条目时可以多；T-4 每个存在而在 size 之内的单元声明长度 = `min(size − 起点, 净荷)`；T-5 I-1.13 两侧按 size 滤（K2）、重建照 K6。每条带必红世界（正推 W7 那张表的十一个世界，加攻方的「删掉截断条目、留着尾部单元」）。新判都进 GPU 判器内核、与 CPU 对拍，不新增「内核不置位」的下标。
- **K8 模型、RefFS、翻译、随机历史**：模型 `ModelFileVersion` 加存在的单元数与洞标签，`role_written_at` 对数据单元按单元号记；`ModelPublishKind` 加截断意图、截断批、截断最后一批、只改记录的变长（各带「是否重写尾单元」）。RefFS 加 `Operation::Truncate(u64)`，作内容改动型（同 `OverwriteTheFile`），施加 = 截短或补 0；崩溃允许集合只截前、截后。翻译层：截断发成（不论几个版本）交一个 `Truncate(n)`，任何写之前拒交空，写了之后报错交 `FailedAfterWriting`。随机历史加 `HistoryOperation::Truncate`，目标按类取（缩到 0 / 单元边界 / 单元中间、单元内变长、跨单元变长），比重进自己那一组，另进带整理的那一组（`broad-compaction`）；`simpler_variants` 往 0、往当前 size 两个方向缩。`UserChange` 加 `Truncate { inode, new_size, write_time_seconds }`。
- **K9 崩溃流与用例**：崩溃流三条，接在多记录流「取号 → 暖机 × 2 → A → B → C」之后：缩到 0、缩到单元中间再变长、快照下缩（对照 `unlink-under-a-snapshot`），登记进 `.claude/gate.d/stage-inputs.tsv` 与 `crash-point-replay-items.tsv`。harness 层另加：144 叶边界的计划纯函数用例（留下 144、288 个单元时罩着单元 k 的叶被重写）；确定性回退用例「截断批间 → 回退到批间那一版 → 续做」与它的必红世界（logged_ops 截断条目改回随现行）；截断斜率用例（照 `unlink_writes_per_transaction_do_not_grow_with_the_file.rs`）。变异照正推 W9 那张表七条，其中「最后一批与截断意图同事务」的会红版本是「最后一批删条目而不放单元」（T-2 红），不照 unlink 写成「最后一批不删条目」（那一形是合法中间态）。只供测试的开关：批大小复用；尾单元时点不是分支、不设开关。
- **K10 准入**：截断的意图、各批、最后一批当删除类（不判式子那一判、落点那一判照判，被落点拒时推抬 F，照 unlink）；变长当普通写。单测钉截断意图那次每盘新占槽数的绝对值，并核它不超过 D28（挂载期承诺量） 已定项 1 的 W 里那一项 24；D28 已定项 1「删除批只改尾叶时成立」那一句随阶段同步改写。
- **K11 单一路径**：缩短一律走「意图 + 若干批 + 最后一批」，放 0 个单元的也走（最后一批放 0 个），不设快路。
- **K12 边界值**：N = S 发一次只改记录的发布（改动计数、时间），不拒；N 的上限是 ⌈N ÷ 净荷⌉ × 净荷不溢出 u64，超了在任何写之前拒成类型化错误。D16（发布语义） 已定项 5 末句「一个事务最多写一个单元的用户数据」随阶段同步补上 D19（块指针的结构与宽度预算） 已定项 6 那半句（截断的尾单元算）。

## 六、交回后补定（主 agent，2026-10-16，零轮）

- **S1 洞整个截掉时换标签的那一次**（截丙交回停下的一处）：缩短把尾部的洞全部截掉、而尾单元不用重写、最后一批又没有单元可放时（例：变长到三个净荷之后截到恰好一个净荷），换标签写在意图那次——意图那次照 K2 先落目标把目标态的 size、尾单元、标签一起写下，标签与 size 不一致时就为换标签重写上段叶到根。同时把 K5、K7 T-3 的标签判法收成唯一：标签 3、4 必须至少有一个洞单元（存在的单元少于 ⌈size ÷ 净荷⌉.max(1)，截断中间态 size 之外挂着的不算），标签 1、2 不许有洞；标签 0 是这个 inode 一个单元都没有（size 0 的空 inode，或 size > 0 的整个文件都是洞）。
- 截丙报告「按结构读的几处」11 条（`~/.local/share/singlefs/work/m4-trunc-model-reffs-writer/patch/report.md`）在截甲交回时逐条对；对不上的两边哪一边改，照判决原文与补定判。
- **S2 T-2 只判一个方向**（截乙交回停下的一处）：K7 T-2 写的「⇔」改成「⇒」——存在的单元多于 ⌈size ÷ 净荷⌉.max(1) ⇒ 有一条对得上的截断条目；反方向在合法状态上不成立：截在最后一个单元之内的意图那一版条目挂着、size 之外一个单元都没有（下一步是放 0 个单元的最后一批，K11）。条目对不对得上记录归 T-1。
- **S3 K6 三条判死只对有记录的单元判**（截乙交回停下的一处）：对象出生代、⌈size ÷ 净荷⌉ 之内、写序三条只在 inode 树里有同号、同对象出生代的记录时判，没有这样记录的单元照旧认领（扫描重建文件头那条既有读法不动）；照字面读成「没有记录就不认领」会让既有坏镜像多红 I-1.13、破坏「只红自己」。
- **S4 I-1.13 留在内核不置位**：K7「不新增内核不置位的下标」管新立的 I-4.10、I-9.38 与改判的 I-4.4、I-4.6；I-1.13 在截断之前就是内核不置位，T-5 的两侧按 size 滤与读法 Z 加写序只在 CPU 一侧，不上 GPU。
- **S5 GPU 恢复内核里洞的内容怎么比**（截戊交回停下的一处）：不给判表加「这一块全零」位、不加从镜像算出的列；内核读到洞时自己现算那 L 字节全零的 CRC，与判表按版本表给的期望比，判表期望一侧缺有洞那几版的逐单元期望就照版本表补齐。理由：判器不从被判镜像取答案，期望只来自版本表。恢复内核的三处读法（收标签 3、4；标签 1、2 单元数不少于 ⌈size ÷ 净荷⌉.max(1)、size 之外不读；标签 3、4 与标签 0 配 size > 0 之后到 size 读 0）照 core 与 K5。
