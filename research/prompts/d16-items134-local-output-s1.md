Proposal

1. Proposal 1: A sequence where S=1 (N=3). Start with mkfs seeding all slots with generation 0. Publication 1: checkpoint_txg=1 writes to slot 1. Publication 2: checkpoint_txg=2 writes to slot 2. Publication 3: checkpoint_txg=3 writes to slot 0. Ring now has slots 0:3, 1:1, 2:2. Oldest root txg=1. Block A freed in txg=2 (f=2). Administrator rolls back to root txg=1. New publication: checkpoint_txg=4 writes to slot 1 (overwriting txg=1). Ring now has slots 0:3, 1:4, 2:2. Oldest root txg=2. Since f=2 <= oldest root txg=2, block A is reallocated. But the rollback root txg=1 still references block A. The system is using txg=1 as the active root, so reallocation corrupts block A.

2. Proposal 3: Layer 3 changes the key encoding for position entries in the named items of journal records. The journal component is frozen at layer 2. After layer 3 freeze, a new key encoding is introduced. Journal records written after layer 3 freeze use the new encoding but the frozen journal format does not reflect it. When replaying, the position entries are misinterpreted because the frozen journal format expects the old encoding, causing incorrect pointer application.

3. Proposal 4: The root selection step requires verifying that a root's tree structure is valid (e.g., no cycles, all blocks allocated). The record checker only checks checksums of ring slots. A bad implementation creates a root with a valid checksum but a cyclic. The record checker selects this root, applies journal records syntactically, and compares with the post-crash image. The checker passes because it only checks checksums and pointer layer structure, but the actual filesystem is broken due to the invalid tree structure.
