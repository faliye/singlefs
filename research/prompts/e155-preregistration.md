### 读法写死

- **一次持久化**：一次 fsync 返回之前交给设备的全部写。甲下它就是一次发布；wal_full 与乙下 fsync 与 checkpoint 分开，checkpoint 的写单独记、按间隔摊。
- **写字节**：交给设备的写调用的字节数之和，两块盘各算一次，与 `crates` 的计法同口径（`crates/singlefs-core/src/transaction.rs:127-131` 每块盘一次写调用各记一次）。锚点 344 576。
- **写请求**：写调用次数，同上口径。锚点 21。另附一列块层写请求 = 写调用 + 刷写次数 + FUA 次数（锚点 26），附带，够判后不跑。
- **屏障数**：刷写次数，每块盘一次 `barrier()` 算一次（`transaction.rs:172-179`），锚点 4；FUA 另占一列，锚点 1。两列各报，不相加。
- **fsync 行**：那一次 fsync 写出的。**摊销行**：（一个 checkpoint 间隔里 N 次 fsync 写出之和 + 这个间隔末尾那次 checkpoint 写出的）÷ N。甲每次 fsync 就是一次发布，两行同值（这一格对甲恒真，不算判据）。
- **份额**：分子是这一格要问的那部分字节，分母是**同一格**甲的每次持久化写字节（第 2–4 行与 G23.1 都用这个分母）。
- **「树高 1」那一格**读作 P = 1：extent、分配记录、记账、映射、树表各 1 层，inode 树 2 层（码 2 根 + 码 3 叶容器，D8 已定项 6 定根恒为码 2，这是它的最低高度）。其余格的「树高」一律报每棵树各自的层数。
- **池里对象数 P**：文件数。主网格每个文件一个数据单元（内容 4100 字节，与发布 B 相同），extent 树条目数 = inode 记录数 = P。
- **两块盘**（`D` = 2）、`physical_block_size` = 512（`.claude/kb/layout/01-first-txn.md` 第零节；发布 B 的根槽 512 字节即此值，`transaction.rs:264-266` 根槽宽取它）。
- **「D25 已定那一档」**：D25 逐字「一次 fsync 带 8 个叶子，落在 1 条共享脊柱上」、负载表那一行叫「seq 顺序大文件」，而岔路单把它放在「一次 fsync 的脏文件数」这根轴上，于是有两种读法：
  - **F8A**：一个文件、一次 fsync 改 8 个相邻数据单元（顺序大文件）；
  登记时还有另一种读法「8 个相邻文件、每个改 1 个数据单元」，主 agent 装置写之前删去（第十二节）。

### 5.2 池与负载

- **池**：P 个文件。F1 每个文件 1 个数据单元（数据单元数 = P）；F8A 每个文件 8 个数据单元（数据单元数 = 8P）。inode 记录数 = P。
- **族**（d = 一次 fsync 改的数据单元数，f = 改的 inode 记录数）：F1：d = 1、f = 1（发布 B 的形状）；F8A：d = 8、f = 1，一个文件的 8 个单元。
- **一次 fsync 之内**这 d 条 extent 记录、f 条 inode 记录在 key 上相邻（D25 的「1 条共享脊柱」；F1 只有一条）。
- **落点方式只管 fsync 与 fsync 之间**：seq = 第 t 次 fsync 改第 t 个位置起的那一段，依次往后推、到尾回绕；rand = 每次在全池里均匀取一段。
- **覆盖写**：每次 fsync 改的数据单元都换新落点，旧版释放（与发布 B 同，`transaction.rs` 1196–1211）。
- **checkpoint 间隔 N**：WAL 两臂每 N 次 fsync 做一次 checkpoint；甲每次 fsync 就是一次发布，N 对甲不起作用。

### 5.3 一次持久化碰到哪些节点（期望值公式）

**记号**：树 T 第 l 层（叶为 0 层）有 `n_l` 个节点，一个第 l 层节点罩 `cov_l` 条条目（`cov_0` = 有效叶容量，`cov_{l+1}` = `cov_l` × 有效内部扇出）。一次持久化对一棵树的改动分成若干**组**：

- **连续组**：从位置 s 起相邻的 k 条。
- **散组**：k 条，在一段长 R 条的区间里均匀独立地落。

**第 l 层期望脏节点数**：
1. 一棵树上的连续组按起点排好，相邻两组之间的空隙 `gap_i` = 后一组起点 − 前一组末条位置。连续组合起来碰到的第 l 层节点数 `C_l = min(n_l, 1 + Σ_i (k_i − 1)/cov_l + Σ_i min(1, gap_i/cov_l))`（节点边界位置随机时区间并集跨过的边界数的期望加 1）。
2. 一个散组在第 l 层：`m = max(1, R/cov_l)`，期望碰到 `S_l = m × (1 − (1 − 1/m)^k)` 个。
3. 几组合起来：`U_l = n_l × (1 − (1 − C_l/n_l) × Π_散组 (1 − S_l/n_l))`；没有任何改动的层记 0；有改动时根层恒 1。

**各树的组从哪来**（「新」= 这次写出的单元，「旧版」= 它替换掉的那一版）：
- extent 树：一个连续组，k = d，位置 = 这次 fsync 改的那一段。inode 树：一个连续组，k = f。
- 记账树：15 行全部重写（D5 已定项 2「每行每发布重写」），全部节点脏。
- 树表：改了根的树（extent、inode、分配记录、记账）是相邻 4 条，一个连续组。
- 映射树：key = (类, 出生树, 出生 txg, …)，条目按区间排：(1,11) 数据单元、(2,11) extent 节点、(2,12) inode 内部节点、(2,13) 分配记录树节点、(2,14) 记账树节点、(3,12) inode 叶容器，区间长度 = 各自的个数；区间内按出生 txg 从旧到新。每个新写的受映射单元在它那个区间末端插一条（连续组）；每个旧版删一条，位置按下面的位置策略。
- 分配记录树：key = (设备, 槽号)，每块盘一个区间，区间内按分配先后排（K8 的近似：槽号序 ≈ 分配序）。每个新写的单元每块盘在区间末端加一条（连续组）；每个旧版每块盘改写一条，位置按位置策略。

**位置策略（K8，三个取样点，全部格都算）**：一个旧版要么「近」（上一次持久化刚写的，落在区间末端、与插入并成一个连续组），要么「远」。
- **L近**：只有数据单元的旧版可以远（数据单元数 > d 时：seq 远的是全池最旧的那一段，连续组、在区间起点；rand 是散组）；节点的旧版一律近。
- **L远**：节点所在层 `n_l` > 1 的，旧版一律远（seq 放区间起点连续组、rand 散组）；数据单元同 L近；rand 下数据单元新落点的分配记录也按散组（最低空槽复用打散槽号序）。
- **L均（主）**：seq：第 l 层节点的旧版远的比例 = min(1, d/cov_l)（推进时跨过节点边界的频率），远的放区间起点连续组；rand：远的比例 = 1 − q，`q = min(1, U_l / n_l)` 取这一格稳态下同一层每次持久化被碰到的比例（自洽：它随不动点一起迭代），远的放散组。数据单元同 L近。

**不动点**：写出单元数 W = d + 各树脏节点数之和。映射的插删取决于数据单元、extent、inode、分配记录树、记账树的脏节点；分配记录的新增与改写取决于 W 与各旧版；而分配记录树、映射树自己的脏节点又进 W。同时各树条目数（K5）也依赖节点数。做法：从「只有 extent、inode、记账、树表」起，反复重算条目数、层数、各组、`U_l`、W，直到两次迭代之间每个量变化都 < 10⁻⁹；上限 1000 次，到上限还在变就记「不收敛」（第十节 F2）。同一个节点在一次持久化里只写一次，由 `U_l ≤ n_l` 保证。

### 5.4 三条臂

臂的名字与第一句定义照岔路单第 1 行抄；后面的「怎么做」是登记补的，每条写明「做完会怎样」并当成要证的命题（第七节钉数、第九节变异）。

**甲（真实基线，`crates` 今天的写法）**：「每次 fsync 是一次全量发布，按 `crates/` 今天的写法写脏数据单元、脏叶与全部祖先、四样固定点（记账、分配记录、中央映射、树表）、一条记录、根槽、超级块槽」。
- 怎么做：每次 fsync 算一次 5.3 的不动点；写出 = d 个数据单元 + extent、inode 两树的脏节点（叶到根）+ 分配记录、记账、映射、树表的脏节点 + ⌈W/67⌉ 条记录（W 个点名项，每个写出的单元一项，`transaction.rs` 1794–1803）+ 1 个根槽（一块盘，FUA）+ 每块盘 1 个超级块槽。次序：单元 → 屏障 → 记录 → 屏障 → 根槽 FUA → 超级块（1831–1853）。
- 做完会怎样：每次 fsync 刷写 2 × D = 4 次、FUA 1 次；fsync 行与摊销行同值；挂载时最多施加 ⌈W/67⌉ 条记录（崩在记录落盘之后、根槽落盘之前，D23 已定项 15）。P = 1、F1 时写出的单元种类、次序、字节数与写调用与发布 B 逐项相同（第七节 B2、第十一节 S1）。

**wal_full（E16 的 `wal_full`，写成支持它的人认的样子）**：「每次 fsync 写脏数据单元、脏叶与全部祖先、一条点名子树根的记录，不发根，根与固定点在 checkpoint 写」。
- fsync：d 个数据单元 + extent、inode 两树的脏节点（叶到各自的树根，与甲同一套 5.3 公式）+ ⌈被碰到的用户树棵数 / 67⌉ 条记录（每棵被碰到的树点名它的新树根一项）。次序：单元 → 屏障 → 记录 → 屏障。不写根槽、不写超级块槽（tail 只在 checkpoint 推进，D23 已定项 18；恢复不先信 tail）、不写树表、不写三棵固定点树。
- checkpoint（每 N 次 fsync 之后）：一次甲形态的发布，只写三棵固定点树与树表的脏节点 + ⌈这次写出单元数 / 67⌉ 条记录 + 根槽 FUA + 超级块槽。固定点的改动按 K9 取这个间隔的净改动：插入 = 间隔里写出、到 checkpoint 仍活着的单元（数据单元按间隔内不重复的个数：seq `min(N d, 数据单元数)`，rand `数据单元数 × (1 − (1 − 1/数据单元数)^{N d})`；两棵用户树按间隔并集的脏节点数，即把 5.3 的组换成「N 次 fsync 合起来」：seq 连续组 k = N d，rand 散组 k = N d）+ checkpoint 自己写出的固定点节点；删改 = 它们在上一个 checkpoint 时活着的那一版，位置按位置策略（「上一次持久化」读作上一个 checkpoint）。
- 做完会怎样：fsync 刷写 4 次、FUA 0 次；checkpoint 刷写 4 次、FUA 1 次；在飞记录在间隔里单调涨到 `N × r_f + r_c`（`r_f` = 每次 fsync 的记录数，`r_c` = checkpoint 的记录数），checkpoint 的根槽落盘之后归 0；挂载时最多施加 `N × r_f + r_c` 条。

**乙（E16 的 `wal_leaf`）**：「每次 fsync 只写脏数据单元、脏叶与一条点名叶的记录，祖先、固定点与根延到 checkpoint」。
- fsync：d 个数据单元 + extent、inode 两树第 0 层的脏节点 + ⌈脏叶数 / 67⌉ 条记录（每片脏叶一项）。次序同 wal_full。高度为 1 的树，根就是叶，照写。
- checkpoint：两棵用户树在这个间隔里被碰过的路径上第 1 层起的全部节点（每个写一次，按间隔并集算）+ wal_full checkpoint 写的那些 + 记录、根槽、超级块。固定点净改动同 wal_full（K9），插入里的用户树节点是间隔并集的叶加上 checkpoint 写的祖先。
- 做完会怎样：同 wal_full 的刷写、FUA、在飞记录形状；fsync 行字节 ≤ wal_full 的 fsync 行（每一格都要成立，第十一节 V2）。

**E16 表里的第三格 `intent`** 就是甲的前身，不另立臂。岔路单第 1 行没有丙（E22），不建。

### 5.5 阳性对照与真实基线

**真实基线**是甲：它必须在 P = 1、F1、seq 一格与 `crates` 发布 B 逐字节对上（第七节、第十一节 S1）。

**阳性对照每条臂都跑**：每条臂各有一格，它的定义与别的臂分开的那一处在那一格上必须按一个事先算好的量出现；差量为 0 或不等于事先算的数 ⇒ 这套模型分不出臂，整轮作废（V1）。

## 六、报哪些量与各自的判据

**标签规则 R（Q1.4、Q2、Q3、Q4 的「随某根轴怎么变」共用）**：一串值 v(x₁) … v(x_m) 按轴排好，第 i 步变化 `δ_i = v(x_{i+1}) / v(x_i) − 1`。
- **随轴扩大**：最后 min(3, m − 1) 步每一步 δ ≥ +5%；**随轴缩小**：最后 min(3, m − 1) 步每一步 δ ≤ −5%；
- **收敛**：最后一步 |δ| < 5%；**其它**：以上都不是（报每一步的 δ）。
- 5% 是登记时选的，不由任何臂的定义推出，定的时候除第四节列的两格外一格没算过。判别力自证：同一串值上把 5% 挪到相邻两步的 |δ| 之间，标签必须翻（第八节）。

## 十、失败条款
