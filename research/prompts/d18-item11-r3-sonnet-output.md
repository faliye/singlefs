# 第三轮反推腿（Sonnet）：落地文本与门禁可判性

攻击面：P2–P8 每条规则能不能翻译成「黄金镜像样本 + 判定 + 判别力自证」；P9 那份落地清单本身有没有让门禁红、让 kb 自相矛盾的地方。立场按裁定要求执行，不做提案摘要。

## 一、逐条翻译

### 1.1 P2 未登记码 ⇒ 拒收（`_d18-item11-r3-amended.md:42`：4–15 / 32–255「未登记 ⇒ 拒收」）

判决：只能是提醒句，除非补一个新登记位。

理由：这条规则管的是全部 256 个码，不只是码 3。P9 计划新增的不变量落点只有一个——I-1.6，而 P4 段落把 I-1.6 的内容明确定义为「判定顺序」，逐字「头校验和 → 类身份段 → I-1.2 / I-1.3 / I-1.4 → 记录数 × 记录宽 ≤ 声明长度 → 载荷校验和 → 逐条记录」，这是码 3 专属的五步顺序，不是「码在不在登记表里」这条判据。P9 计划改动的另一处——「I-1 注（含 :27-28 落点句）」——指向 `invariants.md:26-33` 那段已有的 ⚠️ 注记：「一种新单元类要么在字段表里有类身份段，要么在豁免行里点名，两边都不在即判红」。这句话字面上覆盖了「未登记码」的一半含义，但它是散文注记，不是 `<!-- doc-lint:registry -->` 登记表里的一行，不能被单独引用为「I-1.x」，也没有自己的 checker 状态列。若 P9 只把这句改成指向新登记表，而不新开一个 I-1.x 行，这条规则在 kb 里就没有可被 `.claude/gate.d/22-item-ref-status.sh` 或 `31-blocking-verdict.sh` 追踪的身份，退化成一句谁都可能读漏的提醒。

若要可判：新开 I-1.7（单元类型码在登记表内），样本：mkfs 一份合法镜像，取一个单元把偏移 6 改写成 4（保留区，未登记），重算头校验和使它通过；判定：checker 遇到 flags[6] ∉ {已登记码集合} 时必须报损坏并拒绝把该单元计入合法单元集合；自证：删掉这条判定后同一样本必须由红转绿；另配阳性对照——码 = 1（已登记）时不许被这条判定误伤。

### 1.2 P2 码不回收（`_d18-item11-r3-amended.md:34`：「码一旦用过不许回收，退役码含义永久锁定」）

判决：不是镜像可判的不变量，是治理规则，落 checks-owed，不落 invariants.md。

理由：invariants.md 开篇逐字「每条不变量必须写成可判定的形式——能对着一个镜像回答『成立/不成立』」。「码不回收」问的是「这个码在历史上有没有被赋过别的含义」，这个信息不在任何单一镜像里，甚至不在这个文件系统的任何盘上结构里——它是跨时间的分配历史，只存在于 `decisions/18-块里携带什么信息.md` 的登记表本身。这与 D15（格式冻结政策）已经给 feature bit 定的治理方式完全同构（`15-格式冻结政策.md:97-98`：「位号严格递增、不许跳号、不许有代码引用了表里不存在的位号——机械仲裁」+ C11「feature bit 跳号」）。可执行的检查形态应当是同一类：门禁扫 D18 已定项 11 的登记表，位号只许严格递增，任何一次编辑若把某个已使用码的「类」列改成另一个含义（且没有走 D15 判定表「改变已有字段含义」那一行的 incompat 流程），判红。这是一个新的 checks-owed 条目（见第四节），不是 invariants.md 条目。

自证怎么翻转：造一个 diff，把已登记的码 2（索引节点）行的「类」列改写成别的东西且不触碰 D15/incompat 相关文件，检查必须红；把同一改动补上 incompat 位与 D15 判定表新行，检查必须绿。

### 1.3 P3 偏移 7 非 0 判损坏（`_d18-item11-r3-amended.md:65`）

判决：可判。

样本：mkfs 一份合法镜像，取一个已登记码（如 1）的单元，把偏移 7 的字节从 0 改成任意非零值，重算头校验和使检查不因校验和先失配而提前拒收（要单独测这条规则，需要让头校验和依然自洽，才能确认拒收是「非 0 」这条判据触发的，不是校验和判据触发的）。
判什么：checker 遇到偏移 7 ≠ 0 时判该单元损坏并拒收。
自证：删掉这条判定，同一样本转绿；阳性对照：偏移 7 = 0 时不得被误伤。
落点：I-1 类，新分项（或折进 P9 计划的 I-1.6，但见 1.6 节的冲突判断——I-1.6 已被 P4 段落声明为码 3 专属判定顺序，偏移 7 检查对全部单元类都成立，不应该塞进一个已经被限定成「码 3」语境的分项里）。
执行阶段：checker（挂载 / 扫描重建路径）。

### 1.4 P3 五元组首字节 = 偏移 6 标签（`_d18-item11-r3-amended.md:68`）

判决：可判。

样本：mkfs 一份合法数据单元镜像，把类身份段里五元组的首字节（单元类型标签副本）改写成一个与偏移 6 不同的合法码（例如偏移 6 = 1，五元组首字节改成 2），其余字段与校验和都保持自洽以外的部分不动，重算头校验和。
判什么：checker 比对偏移 6 与五元组首字节，不等判损坏。
自证：删掉比对，样本转绿；阳性对照：两者相等时不得误伤。
落点：I-1 类，与 1.3 同一条或紧邻一条。
执行阶段：checker。

⚠️ 这条规则本身依赖 D18 已定项 7 的字段表已经把偏移 6（flags 高字节）与五元组首字节都算进头校验和覆盖范围——如果头校验和只覆盖到偏移 6 而不覆盖五元组区域（类身份段），篡改五元组首字节不会导致头校验和失配，这条比对就是唯一防线。P4 段落把头校验和覆盖范围定成「0 到该类明文头末尾的全部字节」，两者相容，但这层依赖关系目前没有写成一条交叉引用——第五节会指出这类依赖没有落成检查（见 checks-owed 新条目里「记录级不带字段」附近那一类）。

### 1.5 P4 头校验和覆盖范围——两种状态（`_d18-item11-r3-amended.md:93-97`）

判决：可判，但落点不是 P9 计划写的那一处。

内容拆两半：

明文态：覆盖偏移 0 到该类明文头末尾全部字节（码 1：0–90；码 2：未定，因为索引节点类身份段宽度「随实现定」，first-txn-layout.md:109 标「半定」；码 3：0–92），头校验和字段自身按 0 参与计算。
加密态：元数据类身份段进密文由 MAC 罩，头校验和只罩仍在明文的部分（共同前缀 + 该类白名单里的明文字段）。

样本（明文态）：取一个码 1 单元，改动偏移 90 之内任一字节（例如五元组的某个字节），头校验和必须失配；改动偏移 91 之后（净荷区）任一字节，头校验和不参与、不得失配（净荷改动由载荷校验和管，不该被头校验和误伤，也不该被头校验和放过）。
判什么：头校验和覆盖区间的上界必须恰好落在 0–90（码 1）/ 0–92（码 3），不多不少。
自证怎么翻转两个方向：① 把覆盖区间的实现故意收窄到只到偏移 41（只覆盖共同前缀），改动偏移 42–90 之间的字节必须仍然通过头校验和（漏检，检查从「正确判损坏」退化成「放过」）——这一步验证判定「不多不少」里的「不少」；② 把覆盖区间故意扩到整个单元（含净荷），改动净荷字节必须导致头校验和也失配——这一步验证「不多」（头校验和不该管净荷，管了净荷就与载荷校验和的职责重叠、混淆两种损坏的可分辨性，这正是 D23 已定项 13 排除候选甲的理由，`23-journal的角色与格式.md:1146`：「会失去『头落尾没落』的可分辨性」）。

样本（加密态）：本项定案对第一版不生效（D9 已定项 10 已定加密不进第一个可运行版本），所以这半条第一版不可执行；作为一条格式级约定，它只能在加密实现落地后才有黄金镜像可造，当前只能是文字约定，不是当下能跑的检查。这一半判「只能是提醒句」，直到 D9 未定项 9（明文映射层的字段口径）与加密实现落地。

落点问题：P4 原文写「这句话同时写进 I-6.2 那条补注旁边」（`_d18-item11-r3-amended.md:97`）。但 I-6.2 是「明文头字段白名单」类，管的是「哪些字段允许出现在明文」，不是「校验和覆盖哪些字节」——这是两个不同的判定对象。把「头校验和覆盖范围」的定案文字写进 I-6.2 的补注里，读的人检索到 I-6.2 时会看到一段与白名单本身无关的校验和覆盖范围声明，且它不是可判定形式（没有自己的 checker 状态列，不能被单独引用为「I-6.2 已实现」还是「未实现」）。这条规则本该落 I-2 类（校验和），新增一条 I-2.4，理由是 I-2 类现有三条（校验和与内容匹配 / 算法一致 / 补齐字节参与校验和）管的正是「校验和覆盖了什么、算没算对」这一类判定，头校验和覆盖范围是同一类问题在头部这个字段集合上的实例。

### 1.6 P4 载荷校验和覆盖范围（`_d18-item11-r3-amended.md:91`：偏移 93 到单元末尾，含记录区 + 补齐）

判决：可判。

样本：三份，对照 D23 已定项 13 的判别力形态（`23-journal的角色与格式.md:1152-1154`已经证明这个覆盖范围形态在 journal 记录上可判别）：① 头落了、载荷只落了一半（截断样本，模拟撕裂写）——头校验和判过、载荷校验和判不过；② 载荷完整落盘但被改一个字节（含补齐区域内的字节）——载荷校验和判不过；③ 记录区之外、补齐区域被写非零值——载荷校验和判不过（因为覆盖含补齐），这条同时验证 P4 与 I-2.3（补齐字节为零且参与校验和）在码 3 上的射程（「I-2.3 射程扩到码 3」，`_d18-item11-r3-amended.md:108`）没有留缝。
自证：把载荷校验和的覆盖范围故意收窄到只到「记录数 × 记录宽」那个声明范围、不含补齐，样本 ③ 必须从「判损坏」退化成「放过」——这一步是这条规则唯一的判别力来源，不做这一步就只是复述 D23 已定项 13 的既有形态，没有验证它真的适用到码 3。
落点：I-2 类，与 I-2.3 同一条或紧邻一条，且要求「射程扩到码 3」这句话本身落成可判定形式（当前只是散文），即样本 ③ 本身就是这条扩展的判别力证据。
执行阶段：checker。

### 1.7 P4 声明长度口径（`_d18-item11-r3-amended.md:99-101`）

判决：可判，且与 P5 第 4 条是同一条判定的两种写法，应当合并成一条。

内容：声明长度 = 头之后的净荷字节数（记录区）；补齐起点 = 头 + 声明长度；声明长度 ≤ 32768 − 93；记录数 × 记录宽 ≤ 声明长度。

样本：① 声明长度 = 32768 − 93 + 1（超界 1 字节）——头合法性判定必须拒收（mount-time / claim-time）；② 记录数 × 记录宽 > 声明长度（比如声明长度写小了但记录数字段没跟着改）——头合法性判定必须拒收；③ 记录数 × 记录宽 ≤ 声明长度但补齐起点算错（比如实现里仍然按「头 + 记录数 × 记录宽」当补齐起点，而不是「头 + 声明长度」）——这条要专门测，因为两个数在「记录数 × 记录宽 = 声明长度」时刚好相等、测不出差异，必须构造「记录数 × 记录宽 < 声明长度」（声明长度里有额外的预留/填充空间）的样本才能把两种起点算法分开。
自证：把「头合法性」判定的比较符从 `≤` 改成没有上界检查，样本①必须从红转绿。
落点：新增 I-1.6（不是 P4 段落说的「判定顺序」意义上的 I-1.6，是这条边界判定本身），或与判定顺序合并成同一条（判定顺序描述的正是「先做这条边界检查」这个次序，参见 1.8 节）。
执行阶段：checker，mount-time 头合法性判定。

### 1.8 P4 判定顺序（`_d18-item11-r3-amended.md:109-110`：I-1.6）

判决：可判，但这是一条「元判定」（判定的是检查步骤的先后关系），需要专门的样本形态，且它与 1.1/1.7 的内容重叠，三者不能都叫 I-1.6。

样本：构造一份镜像，让「记录数 × 记录宽 ≤ 声明长度」这条边界检查会失败（记录数字段被改大），同时让某一条记录内部的校验和字段恰好因为越界读取到了别的单元的字节而「碰巧」算出一个能通过的值（这需要精心构造，或者退一步：只要证明实现代码在边界检查失败时不再往下读那些越界字节，就等价地证明了顺序对）。这与 D23 已定项 1 的 B 条同一纪律（`23-journal的角色与格式.md:1037`：「类型字段只说『这是什么』，不说『这有多长』」「先边界检查再算校验和」）。
判什质：违反顺序时（先算校验和再检边界）会读到未声明范围内的字节去做校验和计算，可能读到不属于本单元的数据甚至越界访问；按正确顺序时，边界检查失败应当在触及越界字节之前就终止。
自证：把实现故意改成「先算全部记录校验和、再检查记录数 × 记录宽 ≤ 声明长度」，用一份记录数字段故意改大、且记录宽 × 改大后的记录数远超 32768 的样本，正确顺序下应该在边界检查那一步就报错退出；错误顺序下会先尝试读取并计算越界内存/越界扇区，这本身可以做成一个内存越界检测意义上的自证（用地址消毒器或者一个显式的越界读计数器）。
落点：建议这条单独占 I-1.6，1.1（未登记码）与 1.7（声明长度边界）各自另起编号，因为三者分别检查「码合不合法」「声明的长度合不合法」「检查步骤有没有按正确先后做」，是三个不同的判别对象，混编成一个 I-1.6 会让引用处（比如某处写「I-1.6 判定顺序」）与另一处（写「I-1.6 未登记码」）各说各话，正是 kb-discipline 第 5 条「编号只能做索引，不能做称呼」要拦的那种坍缩。
执行阶段：checker，且必须与 1.7 的边界检查在同一次实现里体现出真实的先后关系，不能只是文档声明顺序而代码里没有对应控制流。

### 1.9 P4 多版容器按 D3 已定项 1 谓词判（`_d18-item11-r3-amended.md:115-117`）

判决：可判，且已有直接对照实验（E59）。

D3 已定项 1（`03-空间分配.md`「已定项 1」）逐字定义谓词由两半合成：「这个落点分配出去了吗」（D3 的分配记录）+「分出去的属不属于现行版本」（D5 的 deadlist）。E59（缓冲消息能不能只从单元重算）已经实测：「只扫单元时同一个 key 的多份可读副本分不出现行值」「加上这个谓词之后四类消息的分歧全部归零」——这正是 P4 这条规则要用的机制，且已经被跑过。

样本：造一份镜像，同一身份（出生树、类型、容器号）存在两版容器（旧版被某个快照头引用，新版被可写头引用，物理上都在盘上，因为「被重写的旧容器走普通 COW 释放路径」，还没被回收）。
判什么：checker 用 D3 已定项 1 的谓词分别对两版容器判定，各自应当恰好属于各自的头（旧版属于快照根的可达闭包，不属于可写头的可达闭包，反之亦然）；且不许出现「按诞生代号择新」这条已被否掉的规则（`_d18-item11-r3-amended.md:115`：「不按诞生代号择新——那正是 D18 已定项 1 否掉的用途」）。
自证：把 checker 换回「按诞生代号取最大值」这条旧规则，构造一份「旧版容器诞生代号大于新版」的样本（比如新版容器因为某种原因诞生代号反而更小，虽然这在正常写路径下不该发生，但正是要测的极端情形），旧规则会判错，新规则（谓词判）必须判对。
落点：这不是 invariants.md 新条目，是 I-1（或专属码 3 的分项）在「候选归属判定」这一步复用 D3 已定项 1 谓词的具体应用，属于扫描重建路径的实现细节，checker 状态在 I-1 类里体现即可，不需要单独开号。
执行阶段：checker（扫描重建路径）。

### 1.10 P5 四条装载纪律

### 1.11 P5 快照发布前先关容器（`_d18-item11-r3-amended.md:126`）

判决：不是镜像可判的不变量，需要崩溃点重放。

理由：「开放容器」是运行时缓冲状态，不是盘上结构——一个真正开放（尚未关闭写出）的容器根本不在盘上，静态镜像上看不出「关闭动作」与「发布动作」谁先谁后。这条纪律只能通过观察写请求序列的因果顺序来验证，与 D16 已定项 7「墓碑先于发布它的根落盘」是同一类次序纪律（`_d18-item11-r3-amended.md:127`原文就是这样类比的）。

样本：崩溃点重放序列——① 打开容器、写入若干条打包记录；② 发布新代际（快照发布事务落盘）；③ 在①②之间的某个点崩溃、重放。判定：重放后的镜像上，若代际已经发布（根记录 checkpoint_txg 前进），则该代际此前打开的容器必须已经被关闭并完整写出（容器不存在「属于已发布代际但仍标记为开放」的状态——但这句话本身依赖「开放」这个标记在盘上怎么体现，若 P5 说「代际不存字段」，容器本身不带显式的开放/关闭标记，那么这条判定退化成「不存在半截容器」这种更弱的形式，需要另外定义什么叫「半截」）。
自证：故意把写路径的次序改成「先发布代际、后关闭容器」（违反规则），构造对应的崩溃点，重放后必须能观测到一个可判红的症状（例如：该代际的墓碑记录部分丢失，导致被删对象复活——这与 P7 表格里「死者由墓碑区间记录自己的字段指认」呼应）；若观测不到任何症状，说明这条次序纪律实际上买不到东西，那正是本项应该诚实记下的欠账，而不是含糊地留在提醒句层面。
落点：checks-owed 新条目（见第四节），不是 invariants.md；前置是崩溃点重放 harness（当前尚不存在，`.claude/kb/verification-build.md` 里排的三样验证手段之一）。

### 1.12 P6 四条限定

| 条 | 判决 | 理由 |
|---|---|---|
| ① 只对定宽记录类型开放，变宽的只能新开单元类走 incompat | 不是镜像可判，是注册时（登记新类型时）审查规则 | 判的是「登记这个类型时选没选对通道」，不是任何单一镜像上能观察到的性质——一个变宽记录类型如果真被错误地当 compat_ro 注册了，镜像上不会自动出现任何异常标记，除非有第二份「这个类型应该是定宽还是变宽」的权威记录去对照。可行形态是给第二级登记表（P6 那张表）加一列「宽度类别：定宽/变宽」，门禁比对「状态 = compat_ro」的行，其「宽度类别」列必须是「定宽」，不是即判红——这是 kb 内部的登记表一致性检查，不是镜像 checker，落 checks-owed 或者一个新的 gate.d 阶段 |
