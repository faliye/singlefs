G3. rebuilt_allocator (mount.rs lines 196-252) is called at every mount that needs to rebuild the allocator, both an ordinary writable mount and a mount that is performing a rollback. Inside it, in this exact order:
 - It rebuilds the allocator from the previous version's on-disk allocation records (mechanism described in G7 and G8 below).
 - It computes effective_floor by calling effective_rollback_floor (recovery.rs lines 351-371). That function reads every currently readable root in the ring with absolutely no filtering by abandonment, by validity, or by checkpoint_txg; it groups all of them by device (each root is assigned to a device by mapping its own checkpoint_txg through a fixed placement rule); for each device that has at least one currently readable root assigned to it, it keeps the largest rollback_floor field seen among every root assigned to that device, abandoned or not; a device with no readable root assigned to it at all is excluded from what follows, not treated as if it read zero; the function's final result is the smallest of those per-device largest values, or zero if there are no readable roots anywhere in the ring at all.
 - It separately calls readable_roots again (an independent, fresh read of the same on-disk root ring) and stores the result in a local variable named roots.
 - It computes newest_table by calling choose_root (recovery.rs lines 287-303, which scans every self-certified root in the ring and keeps the one with the largest (checkpoint_txg, instance) pair, comparing checkpoint_txg first) on the devices and superblock available to this exact call, and then reading that chosen root's own instance-table unit off disk; if either step fails, newest_table becomes an explicit absent value.
 - It defines a helper is_abandoned that returns true for a given root if a caller-supplied closure named extra_abandoned returns true for it, or if newest_table is present and abandoned_by_table (G2) returns true for that root against that table. For an ordinary mount, extra_abandoned always returns false. For a rollback, extra_abandoned returns true only for roots whose (checkpoint_txg, instance) pair is strictly greater than the chosen rollback target's own pair.
 - It computes oldest_valid_root as the smallest checkpoint_txg among every member of roots for which is_abandoned returns false. Nothing in this computation requires that smallest value to be at or above effective_floor, or above anything else; a root can be counted here even if its own checkpoint_txg is far below effective_floor.
 - It calls a method named reclaim_released_up_to on the allocator, passing reclaim_floor(effective_floor, oldest_valid_root) as computed by G1, exactly once.

D1 (rollback floor and reclaiming, decision D16 item 1). A released placement is reclaimable exactly when its release generation is less than or equal to the larger of two quantities: effective_floor (also called effective rollback floor), and the smallest checkpoint_txg among every root in the ring that is self-certified and still valid per the instance table (this second quantity carries no requirement, in its own definition, that it be at or above effective_floor; a root below effective_floor can still count toward it as long as it is not abandoned by the table). Effective rollback floor, after any remount, equals the smallest, across every surviving device, of the largest rollback_floor field carried by any readable root assigned to that device.

D2 (allocation record rewrite policy, decision D3 item 7). Placement granularity is 16384 bytes. When a placement is released, its existing allocation record is rewritten in place to released plus a release generation, never deleted; the same record is later overwritten again, in place, with new allocation data (a new generation, is_released cleared) when and if that exact placement is reallocated.

D3 (shadow ledger narrow reading, decision D23 item 14, chosen 2026-09-16). The set of slots that get isolated so they cannot be reused is limited to slots referenced by roots that are actually judged abandoned; roots that are merely below the current floor but not abandoned by the table are not covered by this particular mechanism at all (their protection, if any, has to come from the reclaim-floor mechanism in D1, not from isolation).
