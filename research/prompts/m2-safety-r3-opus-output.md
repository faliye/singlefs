## 一、这条腿怎么实现 P1–P3（与第二轮模型相比换了哪几步）

- **式子两处**（`core-arms.patch`，只在草稿副本里）：`admission.rs` 的 `admission_reading_before_a_publish` 在臂开了 ND 时把逐盘「defer 待释放」置 0——发布与可写挂载读的是这一个函数，两处一起改；`transaction.rs` 的 `prepare_the_version_publish` 在臂开了 A1n 时把判的需求换成这次重写的全部角色的 `span_slots`。**判不判**照今天：有普通分配才判（`transaction.rs:4718` 那一行起的 `demand_is_judged`），空发布、写行、暖机、抬 F、回退都不判——正文 P2 的式子只换需求的量，没写换判不判；这一读法写在这里，量出的数都按它。
- **C283**（驱动里，`opus_r3_p3_attack.rs` 的 `Pool::user_publish` / `c283_step`）：用户发布报 `SpaceAdmissionRefused` 时，先用 `raise_rollback_floor` 在任何写之前按上限拒的那一条读出准入上限，上限高于现行根上的 F 就调 `raise_rollback_floor` 把 F 抬到上限（那一串照冻结副本的实现：整串预演、先写系统配置、推到每块盘都有带新 F 的根），推完重判；一次准入至多 8 次发布，算上被准入的那一次用户发布，推之前按那一串要推几次先判预算。上限不高于现行 F（抬不动）、预算不够、那一串自己报错，都报拒。依据：`admission.rs:401` 整行 `/// 先推空发布抬 F 再判一次（D16（发布语义） 已定项 1）是调用方的事，这里不做。`
- **挂载那一处不推**：D16（发布语义） 已定项 1「准入」那一行的括注「写行那次发布之前不推」（`.claude/kb/decisions/16-发布语义.md:41`），可写挂载的准入判在取号之前（`mount.rs:2157` 的 `establish_instance`），所以四条臂的挂载被拒之后都没有可推的，P1 与 T、P3 与 P2 在挂载那一格的判法相同。
- **两支**：正常卸载再挂 = `mount.rs:1236` 的 `unmount` 之后 `mount_writable_with_space_admission`；崩了再挂 = 丢掉会话（盘停在最后一次发布之后）再挂。
- **从第二轮模型搬过来换了的几步**：第二轮的 `Op::RollbackAny`（关掉会话、`mount_rollback_with_space_admission` 挂载时回退）换成 `Op::Rollback(k)`：挂着时按驱动自己记的账挑第 k 新的另一个状态，调 `mount.rs:3021` 的 `roll_back_by_a_forward_publish`；第二轮的 `Op::Remount`（丢会话再挂）拆成 `UMount`（走 `unmount`）与 `CMount`；`RaiseF` 保留（测试入口）；新加 `Abandon`（`tests/common/mod.rs` 的 `abandon_the_newest_root_by_a_recovery_that_lands_on_the_root_before` 同一形，写回只写挂载期间没被写过的那几处，见第六节）。崩溃模型从「按发出次序的写前缀」换成层 0 的枚举域（第五节）。
- **起点**：mkfs、取号、暖机、第一个文件，再崩了再挂一次（与第二轮同一个起点，挂载那一步换成新代码）。几何：`HistoryDeviceWidth::UnitAreaOf384Slots` 的参数、两块盘，盘宽按单元区槽数 240–1024 九档取（根环每区 8 槽、共 24 条根）。

## 六、P3 的安全性

### 6.1 崩在准入推空发布的那一串中间（E5）

取样：沿脚本（每次覆盖写 2999 字节 / 长到 6 个单元再截断，十轮）按臂走，第一次在准入里推了空发布的那一步，把那一刻的池取下来，只录抬 F 那一串（先写每块盘系统配置、那 2–3 次带新 F 的空发布），不录之后那一次用户发布（整条流连用户发布一次就是 4.2×10⁶–6.9×10¹⁰ 个状态，超过单流上限，`out/e5-count.log`）。崩溃状态照层 0 的枚举域取：`enumerate_layer0_in_state_slices`，每段都展开（与 `enumerate_layer0_versions` 同一个枚举域，只把工作线程数定成 1、多条历史在外面并行），每个状态恢复后跑 checker（枚举器自己跑）；再按同一臂可写挂载，挂载后的镜像再跑一次 checker，再写一次那一步的用户发布，写不进就崩了再挂再写。

12 条历史（P1 5、P3 7）共 295,077 个状态，另有估时那一趟（256 槽 P1）20,493 个，全部：oracle 违例 0，恢复后镜像 checker 违例 0，挂载后镜像 checker 违例 0。挂载：P1 每条历史的第 0 个状态（这一串一个写都没落盘）挂载被拒，其余全挂上；P3 全挂上。写回：P1 挂上的全部当场写进；P3 除 448 槽第 0 个状态（第五节那一形）外全部写进。原样一行：

```

近满截断成 0 那一次发布，一条流 16,777,223 个状态（段 [24, 2, 1, 2]，`out/e5-count.log`），超过约 10⁶ 的单流上限，照定义不跑，交主 agent。第二轮只取了按发出次序的写前缀（第二轮判决「安全性」一节），这一格在层 0 的枚举域上两轮都没量。

每一步之后按驱动自己记的账（不读 core 的「非空」判法）取这条时间线上最近 4 个不同状态，逐个核它还是不是回退候选：根环里有它的根、不低于现行 F、在拷贝上真回退得过去。12 条脚本（第二节的八条，加每次写之后崩了再挂 / 崩了再挂两次 / 近满时每次写之后崩了再挂 / 两个状态来回回退）× 9 个盘宽。`out/e6-summary.txt` 原样：

```

- P3：除「正常卸载把 F 抬到了现行那一版」（B1 定的代价，D16（发布语义） 已定项 1「正常卸载的代价」）外 0 格。
- P1 有 49 格「准入推的空发布之后，状态已不在根环里」，其中 48 格根环里只剩 2 个不同状态、1 格剩 3 个，都在「每 3 次覆盖写回退一次」「两个状态来回回退」两条脚本上。「根环容量是这句的边界」那一段（`.claude/kb/decisions/16-发布语义.md:29`）只写了两个状态来回交替；根环里剩 3 个不同状态的格（T、P1、P2 都有，含「每次写之后崩了再挂两次」那条脚本上 P1、P2 的格，`out/e6.log`）是挂载的根或空发布把第四个状态挤出根环，条款没写这一形，交主 agent 判；P3 上没有。

## 这条腿自己的限度

- 数都在草稿副本上量（冻结副本的拷贝 + `core-arms.patch` + 这条腿的驱动），不是入库装置上的数。
- C283 是这条腿自己写在驱动里的一种实现：推之前按上限判抬不抬得动，抬不动就不推。另一种字面读法「做满 8 次发布再报拒」（抬不动也推空发布转根环）没实现、没量；它会让空发布把状态挤出根环（6.3 那一形），也会多占 defer（推的）。
- P2 / P3 的「判不判」取今天的触发（有普通分配才判），正文没写；若 A1n 连空发布、回退也判，2.x 与第五节的数会变（推的）。
- 两支里「崩了再挂」只取发布与发布之间的干净崩溃点；崩在一次发布中间的，只在 E5（抬 F 那一串）上按层 0 的枚举域取了，删除那一次没跑（6.2）。
- 被抛弃的根只用「最新根槽与它的数据单元暂时读不出、挂载后原样写回」一种设备行为造出（与仓里用例的帮手同一形），没造别的抛弃方式。
- 行数的历史只用连着崩了再挂推（一次挂载写一行）；没造「行回收」（冻结副本里没有）。
- 状态号是驱动自己记的账（用户发布加一、回退取目标的号），挂载落到账外的根时记一个新号；E6 的判定依赖它。
- E1、E3、E4、E7 与第一趟 E6、E8 是在驱动后来加的几处改动（抛弃写回修正、E5 只录抬 F 那一串、E6 标根环状态数、P3r 臂）之前跑的；那几处不碰这几个实验走的代码路径。E1、E3、E4 用最终的源码重跑了一遍，数据行与入库的日志逐字比过（结果见文件头「复跑核对」）。
- 估时与缩取样：E5 先跑一条 20,493 个状态的流量得每状态约 27.8 ms（569 s），全量（P1、P3 两条脚本九个盘宽里第一次推空发布的全部 25 条流，`out/e5-count-raise-only.log`）1,904,995 个状态、单线程约 14.7 小时、6 线程约 2.5 小时，超过 40 分钟；缩成 12 条历史（去掉单流超过 10⁵ 的与 640 槽以上），295,077 个状态，实跑 43 分 51 秒（`time` 的 real）。缩的只是历史条数，每条留下的历史的崩溃状态一个不落。
- **全量状态数合计（这条腿，没有接手的腿）**：E5 实跑 295,077 + 估时那一趟 20,493 = 315,570 个，低于约 10⁷；只数没跑的流（整条连用户发布、删除类）不算在内。

## 没做什么

- 没判正推、辩方那几格；没替主 agent 采纳；副本上的数不算入库装置上的数。
- 删除类发布中间的崩溃（6.2）没跑：一条流 16,777,223 个状态，超过单流上限。
- 「做满 8 次发布」的那一种 C283 读法、P3r + P3pl 合起来、4.2 与第五节的改法，都没实现。
- `df` 没有实现，D3（空间分配） 已定项 9 第 1 条（`df` 报出 s 就能写 s）这一轮在 P3 上判不了。
