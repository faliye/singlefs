## 一、攻背景材料本身（优先级最高）

### 1.1 I-1.2 那一条：转述准确，但**漏掉的那一半正好是判决要用的**

材料写：

> code 1 requires b <= T_pub OR n <= W. Code 2 and code 3 require b <= T_pub only.
> So the published predicate never reads n for code 2.

原文（`.claude/kb/invariants.md:21`，整行抄相关段）：

> 有行 (i, T_pub, W) ⇒ 码 1 要 b ≤ T_pub ∨ n ≤ W、码 2 / 3 要 b ≤ T_pub

⇒ **前半句准确。** 但材料把它当成「码 2 的 n 没人读」的一条证据，而**同一条谓词对码 3 也只要 b ≤ T_pub**，
码 3 的那 6 字节却是 P3 / I-1.8 的择新键末位。⇒ **「已发布谓词不读 n」与「n 没有消费者」之间没有推理关系**，
材料把一个对码 3 已知为假的蕴含用在了码 2 上。**这是材料的论证结构缺陷，不是转述错误。**

⚠️ 另有两处漏引，判决用得上：I-1.2 的分支还有 `i > 挂载根实例 ⇒ 判损坏`（读的是实例代号那 4 字节，砍不掉）
与「**例外**：打包记录类型 4 的实例表单元不走这条谓词」。后者说明这条谓词本来就是按类开例外的，
「按类给不同宽度」在本仓不是新形态。

### 1.4 那条扇出公式：**材料把一句警告改写成了一条资历**

### 3.2 臂 C（留位恒零 + 非 0 拒收）：**它买不到它看起来买到的那个 compat 通道**

`.claude/kb/decisions/15-格式冻结政策.md:86 / :89` 判定表两行，整行抄：

> | 新增字段在预留区 / TLV 尾部 | 忽略，继续正常工作 | **compat** | 否 | 没有语义依赖的纯加法，「忽略陌生字段」这条安全网够用 |
> | 改变已有字段含义 | 按旧含义解读，**不报错**地产生错误行为 | **incompat，且弃用旧位置不复用** | 是 | ……两个实例（D18 已定项 11）：……**给共同前缀偏移 7 里恒 0 的 flag 位赋义（旧读者对非 0 位一律拒收）**

⇒ 判定表把「恒 0 + 非 0 拒收的段，将来赋义」**逐字列成 incompat 那一行的实例**，
而且带一句「**弃用旧位置不复用**」。⇒ 臂 C 将来要用那 6 字节时：要 bump incompat，
而且按判定表还不许复用那个位置。**臂 C 相对臂 A 的额外收益，在 D15 的判定表下等于零，代价是每节点 6 字节。**

**第二个出错世界**（拒收的粒度）：臂 C 说「readers rejecting a non-zero value，object level, not the whole pool」。
码 2 没有记录级（1.6），拒收一个索引节点 = 拒收它下面整棵子树。

⚠️ 我构造不出臂 C 的「静默错」世界：它不会导致误读，只会导致多一条拒收路径与 6 字节。

### 3.3 臂 B（维持现状写真值）：**已定的值规则让它在最需要判别力的那一格没有判别力**

   固定点不分配新事务号 ⇒ **两版 n 逐字节相同**。

## 四、攻「举证责任在留着那一边」这个判据

D18 未定项 12 正文逐字：

### 4.1 它把射程注读窄了：这 6 字节不是「要不要加」，是「已经在表里的要不要砍」

`.claude/rules/fs-design.md` 那一段的原文，整段抄：

> **自描述数据宁可写大一点。** 遇到「这个字段能不能省掉 / 能不能压窄 / 能不能现算」这类权衡，默认答案是**不省**——除非有实测证明省下来的那部分是瓶颈。
> ……
> ⚠️ **这条不是「随便加字段」**。它管的是**已经论证过有用**的字段该不该为省空间而砍，不管「要不要加这个字段」——后者仍然要各自给理由。

那 10 字节**已经在已定条款里**（D18 已定项 7，2026-09-02 用户定案 + 2026-09-05 C113 定案改写；
`first-txn-layout.md:44` 已把它列成第一个事务要写的字节、状态「已定」）。
⇒ 本项问的字面就是原文括号里那三个词之一：「**能不能压窄**」。**射程注管的正是这一格。**

⇒ **正文那一步是把射程注反过来用**：射程注说的是「加字段要另给理由」，
被读成了「加的时候没单独给过理由的字段，砍的时候不受保护」。
