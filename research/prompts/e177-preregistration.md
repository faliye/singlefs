### 读法写死

- **「11 种树」**：`crates/singlefs-core/src/records.rs:373-385` 的十一个 `TREE_KIND_*` 常量，种类码 1 extent、2 inode、3 分配记录、4 记账、6 livelist、7 稀疏旁表、8 deadlist、9 `deleted_inodes`、10 墓碑、11 谱系、12 logged_ops。种类码 5 中央映射树不在这十一种里（它的根住根记录、不进树表，D8 已定项 9），今天有对象，归岔路 T2「多出来的树」那一组单独报（第六节 Q6）。实例表、树表、根记录不是 keyspace，不量。
- **「key 死亡」**：某棵树的 key 在第 k 版（第 k 次发布之后的现行那一版）里有、在第 k+1 版里没有。key 还在而值变了（覆盖写换指针、inode 记录改 nlink、记账值变）不算死亡。例外：分配记录树（种类码 3）的释放写成带已释放位的记录、key 留在树里（第三节 S20），这棵树另报口径 (b)「分配 → 已释放」当死亡；口径 (a) 照通则（key 不在了）。两个口径在 Q1、Q2、Q4、Q8 里各占分配记录树的一行。同一个 key 后来又出生（分配记录树的槽号会重用）的，按扫描时刻那一版判。
- **「扫描重建」**：`crates/` 里没有读侧（第三节）。读法当成一维，登记三种（第五节 R-U、R-S、R-G），各报各的，不预先选一种；读法不是问法的两种读法，三种都要报，判据按读法分行，不合并。
- **「复活数」r**：扫描时刻 t（第 t 次发布落盘之后、下一次发布开始之前的盘面）上，读法判活、而第 t 版现行那一版里该树没有的不同 (树, key) 条数。两盘镜像的两份按一条 key 计。分母另报、不当判据：到 t 为止该树死过的不同 key 数 d。
- **「漏活数」m**：同一扫描时刻，第 t 版现行那一版里有、读法判死（没收进来）的不同 (树, key) 条数。r = 0 只在同一格 m = 0 时算「量到 0」（第六节 Q5）。
- **「不写墓碑」**：第五节臂 N。
- **扫描时刻**：每一次发布之后都扫一次，每段历史得一条 r 的轨迹（第八节）。只扫干净状态，不扫发布中途、不扫崩溃态（第十一节「没做的格」）。
- **「能不能量」（还没有对象的树）**：两样都有才算可量——① `crates/` 里有写出这棵树非空节点或容器的代码路径；② kb 里有这棵树的 key 与盘上载体（单元类、容器形态、记录字段表）。缺 ① 而有 ② 的，记「crates 里没有对象，kb 有定义」，本实验不给数（不是 `crates/` 今天的树）；两样都缺的记「不可量」。判法用第六节 Q7 写死的 grep 命令。

**下一个 inode 号是记账里的一条统计量**（D5（快照 / 空间记账机制） 已定项 4 第 12 项「inode 号水位」）：key = (统计量, 树 ID, 设备段, 代)，不带设备维，value = 下一个可用号，**合并规则取最大值**（幂等、交换、结合）；条目照样带 seq（已定项 15 第 3 条是格式要求，一棵 write buffer 树一套条目格式），只是**合并结果不依赖它**。选它而不是「后者胜」的理由是崩溃后 txg 重发那一格：同一个代段里先后出现大小两个值，取最大值给大的（浪费号、不复用号）；「未发布的等于没发生」只对常规挂载路径成立，扫描重建看的是盘。「标签 → 合并规则」是盘上语义，统计量登记表立成独立冻结组件（D15（格式冻结政策））。水位行只为可写头维护、随每次发布重写（D5（快照 / 空间记账机制） 已定项 2：每条根的记账树只装这条根那一代的行，每次发布把这一代的行全写一遍），只读树没有这一行；读现行值 = 取该维度元组下代号最大的那一行，空 ⇒ 从未维护过、不是 0。克隆头：新头的水位 = origin 那一刻的运行时水位（含还在 write buffer 里没落盘的那条），建克隆那次发布必须为新树写出这条水位行；两个头此后各自分配，号会相交，唯一性靠 (树 ID, inode)。

**写入时间（偏移 64 起三个秒字段、偏移 96 起三个纳秒字段）取写这条记录的那一次发布的参数，不取系统时钟**：每次发布调用带一个写入时间，同一个参数两次发布逐字节相同（可复现）。三个秒字段都写参数的秒数；三个纳秒字段写参数的纳秒部分，今天的参数只带秒数，所以写 0。**新建**（新池新建文件、新建 inode）写创建那次发布的参数；**改写内容**（覆盖写、顺序写）重写这条记录时写这一次发布的参数，不照抄上一版的值；**unlink 的意图那次**写调用方随这次 unlink 给的时间，三个时间秒（atime、mtime、ctime）共一个值，各批照抄意图那次写的值；**不改这条记录内容的发布**——同一片叶里别的记录改动、这条被连带重写，回退——照抄这条记录上一版的值。

**射程**：**同一条时间线上 inode 号不复用**——「时间线」指所选根的祖先链：含管理员回退抛弃的那一段（回退那次发布的水位取 max，那一段里发过的号不重发），不含崩溃恢复抛弃的那一段（崩溃恢复落到较旧的根之后，被抛弃那一段里发过的号可以重发）。**唯一性的射程是一条已发布历史内**——每个容器号都是某条记录首次插入时的 inode 号；号在崩溃恢复落到较旧的根之后可以重发（管理员回退那次发布的水位取 max、不重发，D23（journal 的角色与格式） 已定项 14），所以同一棵树里两个容器可以同号，分开它们的是容器出生代（右半的出生代 = 触发分裂那次发布的 txg，而恢复之后新实例的每一个 txg 都大于环里读得出的每一条根与记录的 txg，D23（journal 的角色与格式） 已定项 14 注 3），同一次发布内「分裂 → 合并 → 再分裂」也造不出同身份两版。跨崩溃不成立：崩溃后 checkpoint 号会被重发，被抛弃那版与重试那版四段逐字相同、内容不同、都在盘上——这与数据单元的五元组、码 2 节点的 (树, 层级, 诞生代号) 是同一种暴露（根记录靠 D16（发布语义） 骑手条款 1 的实例代号分辨，别的单元类靠类身份段里的写序 (实例代号, 事务号) 分辨——容器不单独加实例代号，写序里那 4 字节就是它），常规路径由 D3（空间分配） 已定项 1 的谓词（分配记录）判，扫描重建路径按 C113（扫描重建时多版单元的现行版本判定无输入） 定案的 P2 / P3 规则判。⚠️ **判它安全的依据与树 ID 那条同源**：孤儿与活版的实例代号必不相等（D18（块里携带什么信息） 已定项 11「作废一个 checkpoint 必须换实例代号」），扫描重建的两道闸按写序择新。⚠️ **残留的疑点**：讲统计量合并规则那一句「『未发布的等于没发生』只对常规挂载路径成立，**扫描重建看的是盘**」读起来像是反方向的——它管的是「水位在一个代段里取最大值而不是后者胜」，与「未发布过的号可不可以重发」不是同一个命题，但两者挨得很近。⚠️ **重建的射程是单头镜像**：有克隆头时共享叶头里的出生树是 origin（I-1.3（块头树 ID 一致） 的 C110（跨头共享与加密后元数据类的块头一致性读法） 那一格），按出生树认领会把克隆头的树认残——多头镜像的归属划分要克隆祖先表（E90（树 ID 进 AAD 与跨头共享） 第二笔），落地前多头镜像的 inode 树重建没有输入。⚠️ 填充率没有下界：`⌈n/233⌉` 是新建树的值，1e6 顺序创建再删 90% 不合并是 9.98 倍空间放大；加宽记录能同时缩小爆炸半径（160 ⇒ 204 条），这笔取舍归 C100（inode 容器丢失是永久损失而没有任何冗余条款覆盖它）。⚠️ **挡着「新池新建文件写」的九样，① ② 已定案，其余照录**：① 树表条目已由已定项 8 定；② 记账条目的 seq 住 value、宽 4 字节（已定项 7）；③ 统计量标签值（C71（不认识的统计量标签静默忽略））；④ 不带设备维的统计量的设备段取值、新建树的记账行初始化、读现行值的读法（C117（不带设备维的统计量的设备段没有取值））；⑤ 码 3 容器带不带扩展点（C108（扩展点归属对打包记录单元无判定））；⑥ 码 2 节点头的基础字节数（已由已定项 11 收口）；⑦ `deleted_inodes` 的形态（已定项 16）；⑧ ⑨ 记录格式与统计量登记表两个冻结组件的 spec 文件（C119（冻结组件没有 spec 文件））。⚠️ 跨头首次 COW 时容器身份要不要重生的另一半归 E90（树 ID 进 AAD 与跨头共享） 第二笔。⚠️ **`blocks` 不承担对外的 `st_blocks`**：stat 报的 `st_blocks` 怎么给（stat 时从 extent 树现算分到的单元）、SEEK_HOLE / SEEK_DATA，挪到做 POSIX 面的里程碑。`blocks` 按文件长度向上取整改新池新建文件的字节：那条记录偏移 48 的 8 字节从 64 变 6。 ⚠️ **写入时间单镜像判不出**：取值是发布参数，单个镜像里看不出参数是什么——O1（内存模型对拍（HashMap 理想文件系统）） 的模型与对拍不带写入时间，O2（独立解析器 + checker） 只判单个镜像，O3（独立规约执行器） 的投影不进 inode 树；判它的是按写路径钉写的 harness 用例（覆盖写、顺序写、建 inode、unlink 各一条），多单元顺序写、回退、同一片叶里被连带重写的别的记录三格没有用例（C677（写入时间在三格写路径上没有用例））。

## 五、臂、阳性对照、真实基线

### 5.1 模型（执行员照写，规则出处是第三节 S 号）

- **盘**：E142 那套两块镜像盘、同槽（`deletion_write_dump.rs` 文件头的几何），槽 16 KiB；码 2 节点占 1 槽，码 1 数据单元与码 3 容器占 2 槽、起点偶数槽（S14）。两盘同槽同内容，模型只模一份槽阵列；r、m、d 都按 key 计，不按副本计。
- **单元**：模型里一条单元记录 = 单元类（1 / 2 / 3）+ 所属树 + 类身份（码 1：出生树、对象 ID、对象出生代、锚点偏移；码 3：出生树、打包记录类型、容器号、容器出生代（S16）；码 2：树 ID、层级、key 区间）+ 写序（实例代号恒 1——历史里没有崩溃与恢复，不换实例；事务号随发布单调）+ 诞生代号（发布的 txg）+ 内容（key 集合；inode 记录带 inode 号、对象出生代、nlink；数据单元带五元组）。一个数据单元对应一条 extent key (0, inode, 单元号 × 32634)，锚点偏移取同一个值（D8 已定项 3）。
- **每次发布**：照 S3–S13 算出这一版每棵树的 key 集合与这次重写的单元，取落点（S14：码 1 / 码 3 取槽号最小的偶数起点空槽，码 2 取槽号最小的空槽；不模开放聚簇段——它只改落点不改哪些单元在盘上），写进槽阵列；被换下的旧单元的槽进「扣着」。
- **墓碑与谱系**：墓碑容器照 S7（815 条一容器、意图那次写、只增不删、开放容器有新记录那次才重写）；第一段历史里没有管理员回退，谱系树零根。
- **几何旋钮**（第八节）：G-宽 扣着的槽永不放回，盘不设上限——依据是 S14「抬 F 扣住」的槽在 F 抬过之前发不出去，而 F 只在准入不够时抬（`mounted_session.rs` 文件头）；这一条执行员在 `allocator.rs`、`mount.rs` 现查坐实，查出相反按第十一节停机。G-紧 是模型自定的另一端，不是 `crates/` 的抬 F 上限式子（`mount.rs:3112` 的 `rollback_floor_ceiling` 不模）：盘槽数取这段历史在 G-宽 下峰值活槽数的 1.25 倍（向上取整到偶数），取不到落点时把「扣着」里除最近一次发布换下的之外全部放回空闲，再照 S14 取；放回之后仍取不到，这段历史在 G-紧 记「装不下」，不算结果。

### 5.3 臂（墓碑政策）

| 臂 | 怎么做 | 做完会怎样（由「怎么做」推得出的那一句） |
|---|---|---|
| N 不写墓碑 | 写路径照 5.1，意图那次不写墓碑记录，墓碑树始终零根 | 盘上没有任何记录说「这个 key 死过」，读法判死只能靠「同身份有更新的版本」或「从权威态重算时不再出现」 |
| B 今天的墓碑（真实基线） | 照 `crates/` 今天：unlink 意图那次发布写一条整对象墓碑 (对象 ID, 对象出生代, [0, 2⁶⁴ − 1], 死亡 txg = 意图那次的 txg)（S7、D18 已定项 24 第 2 条） | 带 (对象 ID, 对象出生代) 的记录（inode 记录、数据单元）能被这条墓碑指认；不带对象身份的 key（分配记录、记账、中央映射）指认不了，只能靠读法 |
| P 每次 key 死亡都写死亡记录（阳性对照臂） | 模型专用：每个 (树, key) 在第 t 次发布死亡时，写一条死亡记录 (树, key, t)，放进模型专用、永不复用的区（不占 G-紧 的槽数） | 每个死过的 key 盘上都有一条晚于它所在单元的死亡记录，读法只要认死亡记录就判得死它 |

**臂 B 的墓碑效力（K-W5b 没定，装置自定、写死）**：盘上找到的每条墓碑 (o, b, [0, 2⁶⁴ − 1], t_d)（墓碑树容器的读法与该读法读 inode 容器相同）压掉：inode 记录 (inode = o, 对象出生代 = b)；五元组 (o, b) 的数据单元；R-U 下 extent 叶里 inode = o、数据指针出生 txg ∈ [b, t_d] 的 extent 记录；R-U 下 key = o 的 `deleted_inodes` 条目。R-S / R-G 下派生树跟着被压掉的源走。分配记录、记账、中央映射的 key 不被墓碑直接指认。对面那条读法（墓碑只在删除做完之后才生效）在意图到最后一批之间的效力不同，本实验不另设，它的影响由 m 报出来（第十节 F4）。

**臂 P 的效力**：一个读法要收 (树, key) 时，若这条 key 最晚一条死亡记录的 t ≥ 供出它的那个单元版本的诞生代号，就不收；同一 key 后来在更新的单元里重生（诞生代号 > t）照收。

### 5.4 读法（扫描重建的三种读侧，每种对每棵树写死）

扫描 = 读槽阵列里此刻每个读得出的单元（被覆写掉的旧版本读不到）。三种读法都只读盘，不读模型的现行那一版。

| 树 | R-U 全收 | R-S 照 kb 已定的择现行 | R-G = R-S + 对象门控 |
|---|---|---|---|
| inode（种类码 2） | 每个类型 2 容器里的每条记录 | 类型 2 容器按 (出生树, 容器号, 容器出生代) 分组，每组取 (诞生代号, 实例代号, 事务号) 最大的一版（D8 已定项 6「重建」、C113 定案 P3，D18 已定项 11 的择新键那一行），收它的记录 | 同 R-S |
| extent（种类码 1） | 每个 extent 节点里的每条叶记录（含上段叶的内联条目） | 码 2 不进择现行规则（D18 已定项 15），extent 树是派生态（D21 已定项 9）：从数据单元重算——数据单元按 (出生树, 对象 ID, 对象出生代, 锚点偏移) 分组、取写序最大的一版，每组给一条 extent key | 只收「(对象 ID, 对象出生代) 在 R-S 重建出的 inode 树里有一条记录」的那几组 |
| 分配记录（种类码 3） | 每个分配记录叶里的每条记录 | 从被判活的单元算：R-S 收下的数据单元与码 3 容器的落点；码 2 节点的落点两边都不比（重建要重造码 2 节点，D21 已定项 10 第一行） | 同 R-S，数据单元按 R-G 收 |
| 记账（种类码 4） | 每个记账叶里的每条条目 | kb 没有码 2 的择现行规则；取 D8 已定项 6「读现行值 = 取该维度元组下代号最大的那一行」：每个 (统计量, 树, 设备) 只收代最大的那一行 | 同 R-S |
| `deleted_inodes`（种类码 9） | 每个 `deleted_inodes` 节点里的每条 key | 派生态（S6「队列 = inode 树里 nlink = 0 的号集合」）：R-S 重建出的 inode 记录里 nlink = 0 的号 | 同 R-S |
| 墓碑（种类码 10）、谱系（种类码 11） | 每个类型 1 / 类型 5 容器里的每条记录 | 同 inode 那一行，类型换成 1 / 5 | 同 R-S |
| livelist、稀疏旁表、deadlist、logged_ops（种类码 6、7、8、12） | 今天没有单元（S2）；三种读法都只核「盘上找不到这四棵树的任何单元」，不算 r | 同左 | 同左 |
| 中央映射（种类码 5，不在十一种里） | 每个映射叶里的每条条目 | 从被判活的单元算：R-S 收下的数据单元与码 3 容器的映射 key（`records.rs:299-324` 的 key 形态）；码 2 节点的映射 key 两边都不比 | 同 R-S，数据单元按 R-G 收 |

分配记录树口径 (b)：读法侧一个槽判「已分配」——R-U 下盘上该 key 任一版记录不带已释放位，R-S / R-G 下有被判活的码 1 或码 3 单元落在这里；真值侧第 t 版里该 key 不在或带已释放位，记一条复活。口径 (b) 的 m：真值侧带「已分配」、读法侧判不出「已分配」。

真值一侧（判 r、m 用）：第 t 版现行那一版该树的 key 集合；分配记录与中央映射在 R-S / R-G 下只取码 1、码 3 单元那一部分，与读法同口径。

### 5.5 阳性对照（三条臂、三种读法、每棵有死亡的树，全跑）

在每段历史的最后一次扫描上另做，不改主轨迹：

- **PC1 植入一条已死的 key**：取这棵树一个已死的 key k（死在第 t_k 次发布），造一个身份全新（同身份没有更新的版本）、诞生代号与写序早于 t_k、内容只有 k 的单元，单元类取该读法从哪一类单元收这棵树的 key（R-U：这棵树自己的节点或容器；R-S / R-G：inode 树与 `deleted_inodes` 植类型 2 容器（记录 nlink = 0），extent、分配记录、中央映射植一个已死对象的数据单元）。期望增量：臂 N 每种读法 +1（`deleted_inodes` 在 R-S / R-G 下随植入的 nlink = 0 记录 +1，分配记录与中央映射随植入的数据单元各 +1）；臂 B 取一个没有墓碑指认的 k +1，取一个有墓碑指认的 k +0（只有 inode、extent、`deleted_inodes` 与由它们派生的格有这一种）；臂 P +0，再删掉 k 的死亡记录 +1。
- **记账在 R-S / R-G 下**：整段历史里 (统计量, 树, 设备) 的元组集合不变，没有可植的已死元组；这一格改植一条代号大于现行那一版、第 t 版里没有的条目，期望 +1（证计数器认得出 R-S 下多出来的 key，不证死亡判得出），照实写明这一格的阳性对照弱一档。
- **PC2 漏活对照**：把第 t 版现行那一版里一个装着活 key 的单元（取这棵树在该读法下的源单元类）整个抹掉，期望 m 增加的条数 = 那个单元里的活 key 数加上由它派生的 key 数（执行员先手算再跑）。

任一格增量与期望不符，按第十一节作废。

## 六、报哪些量与各自的判据

每个量一行、各判各的，不合成一个真假。「峰值」取一段历史里全部扫描时刻的最大值，「为正轮数」是 r > 0 的扫描时刻数，「期末」是最后一次扫描；判定按全部 35 段历史取并：任一段峰值 > 0 即判「复活」。每棵树的状态只取四种之一：「没有对象」（盘上从没出现过这棵树的单元）、「没有死亡」（d 恒 0）、「量到 0」（d > 0、r 峰值 0、同一格 m 峰值 0、阳性对照过）、「复活」（r 峰值 > 0）。

门槛与臂定义并排核过：臂 N 只说「不写墓碑」，R-S / R-G 只说「怎么择现行、怎么从权威态重算」，两者都推不出某棵树的 r 是 0 还是大于 0；R-U 在 G-宽 上推得出 r = d，那一格不当判据，写成第七节断言 A3。

|---|---|---|---|---|
| Q1 | 臂 N × R-S × G-宽，11 种树逐树：r 的峰值、为正轮数、期末，d 的期末 | r 峰值 > 0 ⇒「复活」；= 0 且满足「量到 0」三条 ⇒「量到 0」；另两种状态照上 | 翻面观测「每种树的 key 死亡时不写墓碑，扫描重建会复活几条」；够判条件「11 种树各自的复活数都量到」 | 一棵树在「复活」与「量到 0」之间换边，T1 那张逐树表里这棵树「key 死亡要不要墓碑（按 kb 已定的读法）」那一格跟着换 |

## 八、轨迹与几何敏感性

- **被谓词消费的量**：r（Q1、Q2、Q4、Q6 的判定吃「峰值 > 0」）与 m（Q5 吃「峰值 > 0」）。每段历史 × 每臂 × 每读法 × 每几何 × 每棵树报四样：峰值、峰值出现在第几次发布之后、为正轮数（r > 0 的扫描时刻数）、期末值；d 报期末值。只报期末的格正文不许写「从来」「恒」。一行产物带齐：`name=trajectory family=… seed=… geometry=… arm=… reader=… tree=… publishes=… r_peak=… r_peak_at=… r_positive_scans=… r_final=… m_peak=… m_positive_scans=… m_final=… d_final=…`。
- **扫描次数自检**：每段历史的扫描次数 = 这段历史的发布次数（含 unlink 内部的意图与每一批）；对不上作废。
- **几何敏感性（`mutation-sampling.md` 第六类）**：判决格是 Q1、Q2、Q4、Q6 的「峰值 > 0」。两个取样点方向相反：G-宽（旧版本全部留在盘上，r 的上端）与 G-紧（旧版本只留最近一次发布换下的，r 的下端），第五节 5.1 写死。每棵树报两点；两点状态不同记「随几何翻面」，相同记两点。另一个旋钮是历史：判定按 35 段取并，同时报每棵树「复活」出现在哪几个历史族、哪几个删序上——只在一个族上复活的，判定后面写明那个族。
