1. The rebuild claim assumes cost proportional to shared units, but actual rebuild requires scanning all trees and their units. Consider a system with 1 million trees, each containing 100 unique units (no sharing), and only 1 shared unit. To rebuild the referrer list for that single shared unit, the system must scan all 100 million units across all trees to find references. This cost is O(total units), not O(shared units). The claim fails because scanning all trees is unavoidable, and the number of trees and units per tree dominates the cost. Smallest change: store referrers in a dedicated index structure instead of requiring full tree scans.

2. If the sparse side table storage is corrupted (e.g., partial write), the authoritative count and derived list are both damaged. Suppose the count is corrupted to 1 but actual references are 2; the system frees the unit prematurely, causing data loss. Even if the list is lost but the count is intact, the count’s correctness depends on the same storage as the list. If the storage mechanism fails, the count can be wrong, breaking the "authoritative" guarantee. The derived half cannot be treated as losable when it shares storage with the authoritative half because corruption affects both. Smallest change: store the authoritative count in a separate, transactionally safe structure (e.g., write-ahead log) independent of the derived list.

3. Two heads can refer to the same logical object with different keys. History: (1) Tree A writes file /a at offset 0 to unit U, using key "/a:0". (2) Tree B (inks U to file /b at offset 0, using key "/b:0". (3) When scanning trees for referrers of U, Tree A’s lookup on "/a:0" returns U, but Tree B’s lookup on "/b:0" also returns U. The system correctly identifies both referrers. The assumption that keys must be the same is false, but the process still works because each tree’s key is used independently. No failure occurs—the point lookup returns the correct unit regardless of key differences. Cannot construct a failure case because the lookup depends on the tree’s specific key, not a shared key. The assumption is irrelevant to correctness.
