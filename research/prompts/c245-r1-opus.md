# C245（超级块槽的写频率，两条条款说反话） 第一轮：攻方腿（Opus）

你的立场是**反推 / 攻**：主 agent 倾向「tail 今天不承重」（材料第五节）。**假设这个倾向是错的，去造崩溃与写序列把它打穿**；也假设乙、丙各有死角。可以写一个小模型（只用 std 的 Rust 或 Python）：定长环、带 jsn 与 (实例代号, checkpoint_txg) 的记录、带水位的根环、两槽轮换的超级块（甲臂存 tail）、块重用、若干发布点与崩溃点，逐状态比对三条臂的恢复结果（所选根、施加的记录集合、读回的内容、下一次写接的 jsn）。模型源码与原始输出放 `research/prompts/c245-r1-opus-model/`（Rust 的话 `CARGO_TARGET_DIR` 设到 `/tmp/claude-1000/` 下，不许在仓里留 target），报告里给复跑命令与文件 sha256。

要特别回答：
1. T2 三格：在甲臂下把 tail 改成 0、陈旧 k、超前 k，再叠上块重用，找恢复结果会变的最短序列；没有就写试了哪些形状、各多少个状态。
2. T1：乙、丙两条臂各自最容易出错的形状——环回绕之后前缀末怎么找、实例切换、回退行 W、在飞记录数上限、一条中间记录校验和不过——三条臂结果一不一致。
3. 前提十二那条观测：去附录的超级块字段表里找「每次发布必变、且不是 tail」的字段；找到了，那条倾向的地基就塌了一半。
4. 打中之后先问四句（写进报告）：分不分辨臂；被判的系统在做决定那一刻看得到判别它的东西吗；满足的是哪条判据的哪一个分句；你给的改法在打中的格上还中不中。你自己提的收严只算线索，写明它只在你的模型上量过、被攻过零轮。
5. 什么现象会推翻你的每一条结论。
