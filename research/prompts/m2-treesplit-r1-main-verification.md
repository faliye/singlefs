## 三、逐格判决

### T1　分裂与收缩规则

**分隔 key：主 agent 定「跟着维护」，不交用户。** 攻方打中：把 D8 已定项 6 给 inode 树定的「分隔 key = 孩子创建时的最小 key、之后不变」搬到分配记录、映射、extent 这几棵插入不单调的树上，读者按分隔 key 会找不到一条确实在树里的 key，checker 在恢复后判红——t1.out 取这一条的 24 格全红（check_red 34952–562983），同一批历史改成「跟着维护」（插到最左分隔 key 之下时把它压低；借一条之后把右孩子的分隔 key 改成它新的最小 key）24 格全是 0。判据靠的是块头自带的 key 区间：分隔 key ≤ 孩子头的最小 key、> 左邻孩子头的最大 key，逐层可判。另一处打中是推的：D8 已定项 6 的「左从右借」对 inode 树本身也会让 I-9.4「左容器的最大 key < 右容器号」当场为假；今天实现没有删除，还没有历史走到，记欠账。

**写序：交用户。** 三种写序在崩溃历史上都没打中（recover_fail、root_lost、content_mismatch 全 0），理由攻方写明：根槽 FUA 之前有两道屏障，根落了单元与记录全落了，根没落要么施加记录（点名单元逐项核过）要么回到上一版，分裂出来的单元与别的单元走同一条路。

| 候选 | 代价（原型同一批 8684 段历史，Maintained、中间切） | 另外的打中 |
|---|---|---|
| 整条路径在一次发布里照常 COW，分裂出来的单元与别的单元同一段 | 层 0 状态数 2746620；第一个事务那条流上一次发布让三棵根兼叶的树同时分裂，闭式 262168 → 1073741848 | 无 |
| 分裂单开一段：分裂新建的单元先写、屏障、再写其余 | 状态数 1219536（少一半多）；同一情形闭式 266263；分裂的那次发布每块盘多一次 FLUSH | 无 |
| 分裂单开一次发布 | 发布多 11.6%、单元写多 26.0%、状态数 2.74 倍 | **打中**：只改结构的发布被实现的「非空」判定算成改了用户可见状态，挤掉 D16 已定项 1「最近 4 个可退到的不同状态」——窗口里不同内容不足 4 个的历史 3454 段，另两种都是 120（装置的底数） |

「分裂单开一次发布」出局。前两种安全性相同，差别只在层 0 状态数与每次分裂多不多一次 FLUSH。攻方另指出：层 0 的分裂流按「分裂之前那一大截放进起点镜像、不枚举，只录分裂那一次」切，段长只随那一次发布写几个单元涨，不随树里有多少条涨。

**收缩与分裂点：交用户。** 在崩溃历史上都没打中：收缩「只摘空节点」与「低于一半合并（借或不借）」零对零，「只摘空节点」若根只剩一个孩子时不降高，树高只涨不降（ev_height_down = 0），T5 的 ckpt_cost 会跟着只增不减；分裂点「从中间切」与「追加时末尾切」零对零，末尾切在非追加负载上切出一条一条的叶（分裂 5427 次对 2360 次），它的根分裂只有一段定向历史（覆盖最薄）。

### T3　挂载态读多层映射：推不出，交用户

正推：`.claude/kb/decisions/19-块指针的结构与宽度预算.md`「#### 已定项 5」自己写明「映射长成多层时重定这一条」；压着它的有硬规则 1（释放经映射不变）、硬规则 3（提示过期多跳的观测点，射程要扩到多层）、「提示过期的一次解引用发 3 次设备读」这个读数（骑在映射根兼叶上，多层之后要重算）、已定项 8 与 11 的指针格式。另查出写侧今天没有映射树的容量准入，不溢出靠的是两棵无关树的数字巧合（`.claude/kb/milestone/02-second-txn.md` C483 那一行），重定要连写侧一起补。候选：挂载时把整棵映射树读进挂载态（今天「整片读」的推广），或挂载时只读根、解引用时按需走树。

### T4　层 0 要加的流：推得出方法，落到实现

D13 已定项 4、9 已定枚举方法；攻方给了 L1–L8 八条流（叶分裂、根分裂树高 +1、两层连着分裂、合并、借、降高、inode 叶容器末尾分裂、一次发布多条记录共享点名跨记录），写法「起点镜像不枚举 + 只录分裂那一次」。按用户「分裂的每一种新写序都要进层 0 崩溃点」，这几条随实现一起做；**L7（inode 叶容器末尾分裂）今天就欠着**，不等分裂规则定下来。

### T5　保留池的树高：一半推得出，树高从哪读交用户

准入不设常数上限、按结构现算，D28 已定项 4 推得出，分裂不改变它。树高从哪读，C363 逐字「全仓没有条款」；候选：从码 2 根节点头里的层级字段现读（块自描述，用户那条嘱咐指的就是这一类），或内存里的派生态。一次发布最多分裂几次，随 T1 的规则由实现算出上界；四棵树互喂那一圈原型没建，由实现与层 0 补。

### T6　末条装不下：交用户

| 候选 | 读数 |
|---|---|
| 维持拒绝 | **打中**：同一个「覆盖写一个 40 个数据单元的文件」，池里 4000 个对象时碰 7 片分配记录叶，40000 个对象、每 700 个删一个留洞时至少碰 70 片 > 67，被拒——拒不拒取决于池的历史，不取决于用户做了什么（costs.out AGED 五行，下界） |
| 末条再跨记录、按今天的字面认末条 | **打中**：只落了共享点名的前一条时，恢复把它认成末条、施加半次发布 8826 个状态；再叠「只在后一条点名的单元两盘都读不出」读到坏树 53520 个状态 |
| 末条再跨记录、末条带标志位 | 同一批状态 0 / 0，不拒；代价是多一条或几条记录、多一个标志位（落在记录头还是点名项的 flags 字节，推的） |
| 发布拆成几次 | 修不到单个操作就装不下的那几格，拒掉的历史与维持拒绝同一批（2875 段），发布多 639 次 |

主 agent 推荐「末条带标志位」。记录头正由实十三加「本次发布内序号」（D23 已定项 4，307 → 311），标志位放哪一并在那里定。
