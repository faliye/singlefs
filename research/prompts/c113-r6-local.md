Background (settled, verified by the asker): units are the on-disk objects. Code 1 units are data units whose header carries a five-tuple identity and a birth checkpoint number. Code 2 units are B-tree nodes (derived state, always garbage after a scan rebuild). Code 3 units are packed record containers with a four-tuple identity (birth tree, record type, container number, birth checkpoint). Every publish increments the checkpoint number by one. Persistent order per publish: units, barrier, journal records, barrier, root slot. The root ring keeps the last K root records. Recovery applies journal records in strictly consecutive sequence order and stops at the first gap. Each writable mount takes a fresh instance id. A crash leaves an in-flight checkpoint whose number is reissued by the recovery instance. Code 2 and code 3 units are written only at the fixed point of a checkpoint (once per checkpoint, merging the effects of all transactions of that checkpoint); code 1 units are written by the transaction itself, before its journal record.

The sixth version of the fix for C113 (after a scan that lost the indexes, several readable units with the same logical key exist and nothing says which is current or whether a unit was ever published):

P1. Every unit header gets a 10 byte write sequence (instance id 4, transaction number low 48 bits). For code 1 the transaction number is the transaction that wrote the unit. For code 2 and 3 it is the largest transaction number assigned into the checkpoint whose fixed point wrote the unit; the judgment for code 2 and 3 uses only the instance id and the birth checkpoint. A transaction takes its number when it is assigned into a checkpoint; that fixes its birth checkpoint. Cutting a checkpoint only closes membership. A write request is split per unit into transactions, one data unit per transaction. Journal records are appended in transaction number order: record N is appended only after every transaction below N is appended, or voided, or the instance has ended. Failure table: before taking a number, nothing; after taking a number but before any unit write request was issued, the number is burned; after a unit write was issued, a single replica failure retries on another location with the same write sequence under a wall clock budget T_retry; if the budget is exhausted or any other transaction level failure happens, the instance ends: the mount turns read-only, no record with a larger transaction number is ever appended, the next mount recovers and writes rows. Admission is decided before taking a number, so it never fails after a write was issued. There are no void rows.

P2. Instance table: a code 3 container of record type 4, records of 64 bytes, two kinds: kind 0 row (instance id, T_pub = last published checkpoint of that instance, W = last applied transaction number of the in-flight checkpoint), kind 1 chain pointer. The root record gets a pointer to the instance table (root record 127 to 186 bytes). Rows are written only at recovery and at rollback, together with the first new root: after a non-clean end, one row per instance in [instance of the chosen root, new instance): (i, in-flight checkpoint minus 1, max transaction number applied by replay) or (i, in-flight minus 1, 0). Rollback writes (r_old, T_old, 0) and (i, 0, 0) for intermediate instances. Published predicate, with i_now the instance of the mounted root, a unit (i, n) with birth b: if i is less than i_now: no row means published; row (i, T_pub, W) means, for code 1, b at most T_pub, or b equal to T_pub plus 1 and n at most W; for code 2 and 3, b at most T_pub. If i equals i_now: b at most the mounted root checkpoint. If i is greater than i_now: corrupt. Row reclaim: a row may be deleted only when a full sweep confirmed no readable unit of that instance is judged unpublished by the row, all devices are online, and the root ring holds no root published by that instance. If the table is unreadable the mount is read-only. Instance id and a one byte held-by-writable-mount flag live in the superblock; a writable mount first checks that it can be writable, then takes max(ids in superblocks, ids in ring roots) plus 1 and writes it with the held flag to every visible superblock, then touches units; a set held flag with a foreign id refuses the writable mount. Premise written down: at most one writable mount at a time.

P3. Current version rule. Replica merge first for code 1 and 3 (same class identity segment including the write sequence, payload equal by checksum or CRC). Visible_R(u) = published(u) and u.birth at most T_R and an ancestry entry (a, c) exists for the tree of R with u.writer tree equal to a and u.birth at most c. v* is the visible candidate with the largest write sequence for the key. Current is dead if a visible tombstone names the key with a death write sequence at least v*.write sequence, else v*. Rollback: the administrator picks R_old from the candidate set, which is the roots in the ring that are still valid according to the instance table: (i, T) is a candidate iff no row for i, or a row (i, T_pub, W) with T at most T_pub. Rollback applies no record after R_old, takes a new instance id, writes rollback rows, and the first new root gets checkpoint = max in ring plus 1; runtime state reloads from R_old.

P4. Sweep. A location is released when the allocator puts it into the defer queue, that is when no root including snapshots references it; snapshot-referenced locations go to the deadlist and are released only when the snapshot is destroyed, so the release checkpoint is later than the destruction of the last root that referenced it. Allocation record entries are not deleted on release; they become (released, release checkpoint) and stay until the location is allocated again. Admission, common to both branches: not in the allocator in-flight overlay, header readable, header write sequence instance less than the current instance; then with an entry: marked released and release checkpoint at most the checkpoint of the oldest root in the ring; without an entry (orphan): unpublished by the P2 predicate. The sweep watermark advances only to the oldest ring root checkpoint and only when a full pass completes.

P6. When a clone head first modifies a container shared with its origin, the container is reborn with identity (clone tree, type 2, the original container number, current checkpoint) and a retirement record for the old identity is written. The number is kept, not recomputed from the smallest inode number, because recomputing collides with an identity retired in the same checkpoint.
