### 读法写死

1. **key 与计数口径**：inode key = (inode 号, 对象出生代)；extent key = (inode 号, 对象出生代, 单元序号 k)，一个数据单元一条（单元序号 = 文件字节偏移 ÷ 净荷容量 32634，`crates/singlefs-core/src/unit.rs:233-236`）；容器 key = (出生树, 打包记录类型, 容器号, 容器出生代)。一次扫描读出的 key 集合记 R，真值（这次扫描时现行那一版、已发布那一版里的 key 集合）记 T：**复活数 r = |R − T|**，**漏活数 m = |T − R|**，按 inode、extent、容器三个名字空间各报，不相加。按 key 计，不按副本计（两盘镜像同内容，单元数另报「每份」）。
2. **误判死亡数（X2）** = 真值里活着、而读法判死的 key 数，即 m；X2 那几行只取「这一版里没有 nlink = 0 的记录」（不在任何 unlink 途中）的扫描，in-window 的 m 归 X3；另报一行「E-L 两臂下 unlink 途中的 extent m」，那几次扫描里整对象墓碑不施行，m 只来自变短那条规则。
3. **区间墓碑每次发布多写的单元数（X2）** = 同一段历史、同一次发布、同一条 X3 臂下，臂 T 写的单元数减臂 Z 写的单元数，分码 3（32 KiB）与码 2（16 KiB）两列报，每份计；**多写发布占比** = 多写 > 0 的发布数 ÷ 这段历史的发布总数。分母口径与 E177 装置的 `publishes=` 相同：每一次发布都算，含新池新建文件、挂载的写行与暖机那两次（E177 装置第 3331–3336 行与第 3400 行）。
4. **unlink 途中**：对象 N 的意图那一版起、到最后一个不是最后一批的那一版为止（这一版里 N 的记录 nlink = 0）。**漏活峰值** = 这段里各次扫描 m 的最大值，inode 与 extent 各一个数；整段历史报所有 unlink 途中的最大值、为正的扫描次数、期末值。
5. **意图到最后一批之间崩溃**：现行那一版是意图那一版或某个不是最后一批的批（记 p），下一次发布 p + 1 的单元全部写上了盘、它的根没写（最坏的一格）；恢复回到 p，换一个实例代号，实例表里旧实例的已施加事务号 = p 的最后一个事务号。在这个盘态上扫一次。
6. **重建视图多出的对象数**有两种读法（文件头那一句）：**O1** = 重建出的记录 nlink > 0、而真值里 nlink > 0 的对象集合没有它的 (inode 号, 对象出生代) 个数；**O2** = 重建视图里有记录（nlink 不论）、而 p 里它的意图已发布的对象个数。
7. **借**：一次发布里合并策略把右邻容器最小的若干条记录挪进左容器、两片都留着；**吸收**：左容器把右邻整片收进来、右邻不再出现；**删空**：一片的记录删光、不落盘（今天 `crates/` 的那一种）。**每次借多写的单元数（X4）** = 同一段历史、同一个 θ 与容量、同一次借的发布里，N2 写的单元数减 N1 写的单元数，分码 3、码 2 两列；**每次借的退役记录数** = 那一次发布追加的退役记录条数。
8. **N1 判得出、判不出（X4）**：对第五节 5.6 列的每一个坏镜像形态，分别报今天的 I-9.4 谓词、N1 改过的 I-9.4 谓词、I-9.12 谓词三者各自的红 / 绿，再报「今天 I-9.4 红而 N1 的 I-9.4 绿」的形态与个数（只看 I-9.4 一条），以及并上 I-9.12 之后同一句的形态与个数。
9. **底座**：一个打包记录类型 2 容器身份不再出现在下一版里（删空、被吸收、N2 借时换身份）的那一次发布，追加一条退役记录 (出生树 8, 打包记录类型 2, 容器号 8, 容器出生代 8, 死亡 txg 8) = 34 字节（四元组照 D18 已定项 11 的类型 3 一行，死亡 txg 是本题前提加的；宽度是本实验自定，条款里没定）；记录装进打包记录类型 3 的容器，容器挂在一棵专用的退役树下，形态照 D18 已定项 24 第 1 条墓碑树（码 2 根、120 字节条目、开放容器有新记录那次才重写、满了才关），随现行那一版、回退时不取 R_old 的（照墓碑树）。**按谱系滤**：一条退役记录（与墓碑记录、区间墓碑记录）只在它的死亡 txg 落在被扫那一版的父链上时施行，父链照 I-9.18 的定义（谱系记录 (T_rb, T_old) 让 T_rb 的父是 T_old，其余 txg 的父是 txg − 1）。

**容器身份不需要分配器**：inode 号在每一条时间线上单调（管理员回退的新根取 R_old 那一版的 inode 树、水位取 max(现行那一版内存里的, 环里读得出的根的)；崩溃恢复回到所选根的树与它的水位；两种之后发的号都大于那棵树里每一个 key）⇒ 插入永远落在最右的叶 ⇒ 分裂只发生在最右叶，**分裂点取末尾**——左半保留全部原有记录与身份，右半从触发分裂的那条新记录起，**右半容器号 = 那条新记录的 inode 号**，出生代 = 本次发布的 checkpoint_txg，**出生树 = 执行这次分裂的那棵树**（分裂是新建，与「COW 重写身份不变」是两件事）；第一个容器的号 = 第一条记录的 inode 号。内部节点同样在右端溢出、末尾分裂，右半是码 2、没有容器身份。合并：只许**左吸收右 / 左从右借**（右吸收左或右从左借会破「记录号 ≥ 容器号」），保留左半身份，右半退役走 COW 释放路径；合并时机是写路径策略（单测 / 模型对拍），不进格式。**记录数为 0 的类型 2 容器不落盘**（发布前必须合并掉；唯一的叶被删空时是不落盘、根变成零条目）。**跨头首次 COW 的重生**（C113（扫描重建时多版单元的现行版本判定无输入） 定案 P6）：新身份 = (本头树 ID, 类型 2, 原容器号, 本次发布代号)——保留容器号、只换出生树与出生代，同时给旧身份写退役记录。重生只对类型 2：类型 1 容器归写者树独占、克隆不收进自己的容器索引（D18（块里携带什么信息） 已定项 11），从不跨头 COW。两条不同的断言并存：「容器被 COW 重写时身份不变」（内容同、位置变）与「分裂后左半身份不变」（内容少了、身份不变）。类型 1 的容器号仍按 C103（容器索引无落点） 那套单调分配，两条规则按记录类型分。

**key 与 inode 号**：key = inode 号 8 字节，唯一性范围 (树 ID, inode)，位宽 64，声明生命周期创建总数上界 2^63。**已发布的 (inode 号, 对象出生代) 不复用**（D6（快照实现模型） 判据 9 的戒律）：`deleted_inodes` 后台回收窗口里复用会让新旧对象的 extent key 三段逐字相同。⚠️ **「已发布的」这四个字不是为了对齐措辞，是让现行设计自洽**：水位住记账（D5（快照 / 空间记账机制） 已定项 4 第 12 项），被抛弃 checkpoint 的那笔账随它一起丢 ⇒ **每一次普通崩溃**都会让那一代发过的 inode 号被重发。管理员回退是挂着时的一次向前发布，那次发布的 inode 号水位取 max(现行那一版内存里的, 环里读得出的根的)，已发过的号不重发（D23（journal 的角色与格式） 已定项 14）；崩溃恢复落到较旧的根时水位随所选根那棵账载入，被抛弃时间线里已发过的号会被重发，而恢复之后每一个新对象的出生代都大于环里读得出的每一条根与记录的 txg（D23（journal 的角色与格式） 已定项 14 注 3）——要几个故障才撞得上被抛弃时间线里已发布对象的出生代，崩溃恢复那一形没量过，见 C143（inode 号水位在崩溃恢复落到旧根后退回去重发）；对外暴露的对象身份 = (inode 号, 对象出生代)，凡按 inode 号认对象的结构都要带上出生代或随根回退。`deleted_inodes` 回收窗口里 extent key 三段逐字相同那一句说的是同一条时间线里的复用（旧对象已发布、它的 extent 在树里等后台回收），照旧被禁；崩溃恢复之后重发同一个号，新对象的 extent 落在所选根那棵 extent 树里，旧对象的 extent 随被抛弃的根一起不在树里——**这靠 extent 树与 `deleted_inodes` 都随所选根**；管理员回退那次发布的新根取 R_old 的 inode 树与 extent 树，`deleted_inodes` 也取 R_old 那一版的（否则 R_old 之后删掉、随 R_old 的 inode 树回来的对象会被后台回收再收一次；主 agent 2026-09-26 定，推的，被攻过零轮）；`deleted_inodes` 的形态（已定项 16）守这两条；盘上分开两者的是单元五元组里的对象出生代（D9（加密） 已定项 6）。**inode 记录在回收完成前留在 inode 树里（nlink = 0），`deleted_inodes` 只存号**。

**下一个 inode 号是记账里的一条统计量**（D5（快照 / 空间记账机制） 已定项 4 第 12 项「inode 号水位」）：key = (统计量, 树 ID, 设备段, 代)，不带设备维，value = 下一个可用号，**合并规则取最大值**（幂等、交换、结合）；条目照样带 seq（已定项 15 第 3 条是格式要求，一棵 write buffer 树一套条目格式），只是**合并结果不依赖它**。选它而不是「后者胜」的理由是崩溃后 txg 重发那一格：同一个代段里先后出现大小两个值，取最大值给大的（浪费号、不复用号）；「未发布的等于没发生」只对常规挂载路径成立，扫描重建看的是盘。「标签 → 合并规则」是盘上语义，统计量登记表立成独立冻结组件（D15（格式冻结政策））。水位行只为可写头维护、随每次发布重写（D5（快照 / 空间记账机制） 已定项 2：每条根的记账树只装这条根那一代的行，每次发布把这一代的行全写一遍），只读树没有这一行；读现行值 = 取该维度元组下代号最大的那一行，空 ⇒ 从未维护过、不是 0。克隆头：新头的水位 = origin 那一刻的运行时水位（含还在 write buffer 里没落盘的那条），建克隆那次发布必须为新树写出这条水位行；两个头此后各自分配，号会相交，唯一性靠 (树 ID, inode)。

**写入时间（偏移 64 起三个秒字段、偏移 96 起三个纳秒字段）取写这条记录的那一次发布的参数，不取系统时钟**：每次发布调用带一个写入时间，同一个参数两次发布逐字节相同（可复现）。三个秒字段都写参数的秒数；三个纳秒字段写参数的纳秒部分，今天的参数只带秒数，所以写 0。**新建**（新池新建文件、新建 inode）写创建那次发布的参数；**改写内容**（覆盖写、顺序写）重写这条记录时写这一次发布的参数，不照抄上一版的值；**unlink 的意图那次**写调用方随这次 unlink 给的时间，三个时间秒（atime、mtime、ctime）共一个值，各批照抄意图那次写的值；**不改这条记录内容的发布**——同一片叶里别的记录改动、这条被连带重写，回退——照抄这条记录上一版的值。

## 五、臂、阳性对照、真实基线

### 5.0 为什么另立装置，不在 E177 装置上加臂

1. E177 装置的写路径照 `crates/` 今天写死：只有 inode 1 带数据单元（`Version.file_units` 只装 inode 1 的单元，装置第 1728–1729 行；`truth_of_the_version` 的 extent 真值只取 inode 1，第 3102–3104 行），叶容器只有「删空即摘」（`plan_inode_record_removal`，第 1948–1967 行），没有借、吸收、退役记录、回退、崩溃。本题三行要的历史（多个对象带数据、记录被借走或被吸收、回退、意图到最后一批之间崩溃）每一样都要改它的核心数据结构。
2. 改 E177 的装置等于改一个已经出过产物的实验：它的 51 段产物要按新装置重出、逐行回对（门禁 doc-experiments 的 evidence-in-repo 格判「装置改了而产物比它旧」），E177 的判定会被本题的改动牵连。
3. 本题量的是 `crates/` 今天没有的候选（第三节末段），`implementation-first.md` 第 4、5 条给的位置是 `research/` 下的独立模型；E177 用分配器落点决定旧版本读不读得出，本题把它换成一个显式旋钮 W（5.1），候选之间的差别不经过分配器。
4. 「在 E177 的 51 段上量」由历史复现兑现：新装置照 E177 装置的参数与随机源逐段重放这 51 段的用户改动序列，复现由第七节 A1 核（对不上作废）。

### 5.1 模型（执行员照写）

- **单元**：码 1 数据单元（类身份：出生树、对象 inode 号、对象出生代、单元序号 k）；码 3 容器（打包记录类型 1 墓碑、2 inode、3 退役；类身份：出生树、类型、容器号、容器出生代）；码 2 节点只记 inode 树根、墓碑树根、退役树根三种的重写次数（算写的单元数），读者不读码 2（派生态，重建时从码 3、码 1 现算）。extent 树节点、分配记录、记账、映射这几样各臂相同，不模、不计。
- **写序**：每次发布一个事务号（D8 已定项 16 第 2 条「各占一个事务号」），写序 = (诞生 txg, 实例代号, 事务号)；同组择新按写序取最大。另有一个跨崩溃单调的发布序号 p，只给旋钮 W 用。
- **一次发布写哪些单元**：新写的数据单元；记录有变的 inode 容器、新开的容器、因左边删空或被吸收而位置左移的每一片（照 `inode_tree.rs:286-318` 的位置规则）；有容器重写就重写 inode 树根；墓碑树、退役树各自有新记录的那次发布重写开放容器与根，满了开新容器（墓碑 815 条、退役 959 条一容器，第七节 K2、A2）。
- **旋钮 W（读得出的窗口）**：一个单元在发布序号 p_r 那次被换下（它所在的那一版被下一版取代、而下一版不再引用它）之后，在发布序号 p 的扫描里读得出当且仅当 p − p_r ≤ W；从没被换下的恒读得出。W ∈ {∞, 23}：∞ 是「换下的永不被盖」那一端，23 取 E177 装置 `RING_WINDOW_IN_PUBLISHES`（第 39 行）与根环 3 × 8 = 24 那一格（同装置第 32–35 行抄的 `crates/singlefs-format/src/lib.rs:261`、`:279`）。崩溃时没发布的那次写上盘的单元算在崩溃那一刻被换下；管理员回退把 R_old 引用的单元重新算作被引用（回退距离不超过 20 次发布，W = 23 下 R_old 的单元都还读得出，见 F11）。
- **实例表**：已发布谓词 = (实例代号, 事务号) 不超过实例表里该实例的已施加事务号（D18 已定项 11 的实例表、C113（扫描重建时多版单元的现行版本判定无输入） 定案 P2）；每次崩溃恢复换一个新实例代号，txg 重发（第二节 D8 已定项 6「崩溃后 checkpoint 号会被重发」）。
- **谱系**：管理员回退那次发布追加谱系记录 (T_rb, T_old)；父链照 I-9.18。
- **合并策略 M(θ)**（写路径策略，D8 已定项 6「合并时机是写路径策略」）：一次发布删掉一条记录之后，看丢了记录的那片 C（还在的话）：|C| < θ 时，C 有右邻 R：|C| + |R| ≤ 容量 ⇒ C 吸收 R；否则借：R 最小的 ⌈(|R| − |C|) ÷ 2⌉ 条挪进 C。C 是最右一片、有左邻 L 且 |L| + |C| ≤ 容量 ⇒ L 吸收 C。别的情形不动。同一次发布里做完。删空照今天：那片不落盘。θ = 0 就是今天的 `crates/`（只有删空）。
- **几何旋钮**（第八节）：W ∈ {∞, 23}；θ ∈ {0, ⌊容量 ÷ 4⌋, ⌊容量 ÷ 2⌋}；叶容器容量 ∈ {233, 16}（16 是模型自定的只供测试的旋钮，照 `crates/` 墓碑容器容量旋钮的先例，`crates/singlefs-core/src/unlink.rs:21-37`）；批大小 b 随历史。容量 16 时 θ ∈ {0, 4, 8}，233 时 θ ∈ {0, 58, 116}。
- 模型是确定性的：同一格跑 2 次逐字节相同，只说明没有隐藏状态，不是统计上稳定（`test-discipline.md`「单次观测不算数」）。

### 5.3 臂

每条臂两列：「怎么做」与由它推得出的「做完会怎样」。对面那条臂都按支持它的人会认的样子写。

| 臂 | 怎么做 | 做完会怎样 |
|---|---|---|
| **B-on 底座**（本题前提） | 第一节读法 9：容器身份消失那次发布追加退役记录 (四元组, 死亡 txg)；读者丢掉「有一条在谱系上的退役记录指认它、且它的诞生 txg ≤ 那条记录的死亡 txg」的容器版本 | 一个已消失的身份，它最后那一版就算读得出、已发布、在谱系上，也不被读；回退后重新出现在 R_old 里的身份，它的退役记录死亡 txg 不在新父链上，不被丢 |
| B-off-ret（阳性对照；也是今天 `crates/` 的写法） | 不写退役记录 | 删空、被吸收、N2 换下的身份，最后一版读得出时被当成现行容器读进来 |
| B-off-lin（阳性对照） | 写退役记录，读者施行时不看谱系 | 回退之后，缺口里退役、而在 R_old 里活着的身份被丢掉 |
| **Z 读法**（X2） | 不为变短写任何记录；扫描时数据单元 (o, b, k) 判活当且仅当重建出的 inode 树里有 o 的记录、记录的对象出生代 = b、且 k < ⌈记录 size ÷ 32634⌉；同一个号在几个被选中的容器版本里都有记录时取写序最大的那个容器里的那条 | 变短之后 k ≥ 新单元数的旧单元判死；判对判错全看重建出的那条记录对不对 |
| **T 区间墓碑**（X2） | 变短那次发布往墓碑树追加 (o, b, [新单元数 × 32634, 2⁶⁴ − 1], 死亡 txg = 本次 txg)；E-L 两臂下，不是最后一批的每一批也算变短、同样追加；读者对数据单元先按对象门控（重建出的 inode 树里有 (o, b) 才收），再丢掉「有一条在谱系上的区间墓碑 (o, b, [s, 2⁶⁴ − 1], d) 满足 k × 32634 ≥ s 且单元诞生 txg ≤ d」的单元；要改 I-9.20「第一版只许整对象」（模型里不判 I-9.20） | 变短之后被截掉的旧单元判死，不依赖记录里的 size；之后长回来的单元诞生 txg > d，照收 |
| G0（X2 的阳性对照） | 不写变短记录、读者只按对象门控、不看 size | 变短之后被截掉的旧单元，最新那一版读得出就被判活 |
| **E-I 意图那次生效**（X3；今天的 `crates/` 与 D18 已定项 24） | 意图那次发布写整对象墓碑 (o, b, [0, 2⁶⁴ − 1], 死亡 txg = 意图 txg)；读者对 (o, b) 的 inode 记录（不论哪一版）与诞生 txg ≤ 死亡 txg 的数据单元一律丢掉，墓碑在谱系上才施行 | 从意图那一版起，扫描读不到 o 的记录与它剩下的单元，`deleted_inodes`（= 重建树里 nlink = 0 的号）里也没有 o |
| **E-L-w 最后一批生效，写在最后一批** | 整对象墓碑改在最后一批那次发布写，死亡 txg = 最后一批的 txg；读者效力同 E-I | unlink 途中盘上没有 o 的墓碑；最后一批之后同 E-I |
| **E-L-r 最后一批生效，写在意图、读时推迟** | 墓碑照今天写在意图那次；读者只在「去掉墓碑之前重建出的 inode 树里没有 (o, b) 的记录」时才施行它 | unlink 途中 o 的记录还在树里，墓碑不施行；最后一批删掉记录之后才施行 |
| **N1**（X4） | 借时右片保留身份；右片的分隔 key 抬到借之后右片的最小 key；I-9.4 第三句改成「左容器的最大 key < 右容器的分隔 key」，其余三句不动 | 借之后右片的容器号小于等于左片最大 key，今天的 I-9.4 第三句在合法镜像上红，N1 改过的那句绿 |
| **N2**（X4） | 借时右片换身份：容器号 = 借之后的最小 key，出生代 = 本次 txg，出生树不变，分隔 key = 新容器号；旧身份写退役记录；I-9.4 不动 | 借之后的镜像按今天的 I-9.4 全绿；每次借多一条退役记录、多重写一次退役树 |

**两个「最后一批生效」臂**：岔路单没写墓碑在哪一次写，两种写法都是支持「最后一批生效」的人会认的样子，各跑一条臂、各报各的。读者对数据单元一律先按对象门控，所以 E-L-r 在 B-on 下与「没有整对象墓碑」读出同一个结果是这条臂定义的推论，照实报，不算两条臂一样就是对的。

### 5.4 读者（一个，按臂取参数）

一次扫描 = 读此刻盘上每个读得出的码 1、码 3 单元（5.1 的旋钮 W），不读模型的现行那一版：

1. **候选**：读得出、已发布（实例表谓词）、诞生 txg 在被扫那一版的父链上且不大于它的 txg。
2. **择新**：码 3 按 (出生树, 类型, 容器号, 容器出生代)、码 1 按 (出生树, 对象, 对象出生代, 单元序号) 分组，每组取写序最大的一版（D8 已定项 6「重建」、C113 定案 P3）。
3. **底座**：B-on 按 5.3 丢掉被退役记录指认的类型 2 容器版本；B-off-ret 不丢；B-off-lin 丢、不看谱系。
4. **重建 inode 树**：剩下的类型 2 容器里的记录，同号多条时取写序最大的那个容器里的；再按 X3 臂施行整对象墓碑（E-I、E-L-w 直接施行，E-L-r 只在这一步之前的树里没有 (o, b) 时施行）。`deleted_inodes` = 重建树里 nlink = 0 的号（派生态，D8 已定项 16 第 3 条）。
5. **数据单元**：按 X2 臂（Z、T、G0）判活，再按 X3 臂施行整对象墓碑。
6. **计数**：与真值（被扫那一版）比，按第一节读法 1 报 r、m（inode、extent、容器三个名字空间）；崩溃点另报 O1、O2。

读者对每次发布之后的那一版扫一次；崩溃支在崩溃那一刻多扫一次。增量计数为主，每段的最后一次扫描、每个崩溃点、全部阳性对照另用整扫一遍的参照路径算，两路逐数相同（不同按第十一节 V3 作废）。

主格（每次扫描都读）：B-on × {Z, T} × {E-I, E-L-w, E-L-r} × W ∈ {∞, 23}，12 个读者。对照格（每次扫描都读）：{B-off-ret, B-off-lin} × Z × E-I × W 两档，4 个；G0 × B-on × {E-I, E-L-w} × W 两档，4 个。

**预计挂钟**（推的，没量过；不含写装置的时间）：

- 第二段：按组增量计数，每次发布只动这次写出与这次变得读不出的组，每组 × 20 个读者；按每次发布 10²–10³ 个组算，一段 6,000 次发布约 10⁸ 次操作，(51 + 28 + 4) 段 × 12 格 ≈ 1,000 次模拟约 10¹¹ 次；整扫参照路径只在每段最后一次扫描与阳性对照上跑（一次约 10⁵ 单元 × 20 读者）。单线程 2–20 分钟每千次模拟的量级再乘常数，按历史切片在派发提示给的线程数上并行（线程数取环境变量 `E178_THREADS`，产物按段的次序输出、与线程数无关），推的 2 小时内。

三段都推在 2 小时内，不写分片、续跑、多机三样；执行员实测哪一段超过 2 小时，停在能交接的点交回主 agent，不自行改跑法。本实验没有计时类的量：挂钟只用于进度行，不进任何判据。

    versions = 0
    with_stub = 0

        nonlocal versions, with_stub, first_stub_publish
