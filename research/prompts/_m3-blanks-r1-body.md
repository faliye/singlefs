## 三、格

每一格都要答：候选（腿可以加）、每个候选改哪些字节与哪些已定条款、对哪条不变量 / checker / 崩溃流有影响、代价数（能算的算出来）。

### B1　四棵新树的种类码
D8 已定项 9「新树只追加不重用码」推出 9..12；D8 已定项 11 写「第一版树 ID 从 11 起编（extent 11 …… 水位 19），与树的种类码 1..8 错开」，树 ID 从 11 起编是用户 2026-09-13 定案。取 9..12 之后码 11、12 与树 ID 11、12 同值。判：「错开」是不是要守的性质（有没有哪个读者、checker、扫描重建路径靠它分辨两个量）；种类字段 2 字节、树 ID 8 字节且随水位只增，任何固定的种类码迟早与某个树 ID 同值时「错开」还守不守得住；候选至少：甲 照追加取 9..12、把「错开」改写成只对 1..8 成立的说法；乙 种类码另取一段（说清取哪段、为什么那段永远不撞）；丙 树 ID 整体挪到种类字段取不到的范围。

### B2　墓碑容器与谱系容器的容器号
`.claude/kb/layout/03-third-txn.md` 第一节「墓碑容器」「谱系容器」两行：容器号沿树条目严格递增、怎么取是格式级空白。D18 已定项 11 类身份段表「容器号」那一行：类型 1「树内单调分配（C103 那套，回退不破身份）」；`.claude/kb/checks-owed.md` C103 那一行：下一个号 = 最大号 + 1、派生态、扫描可重建、计数器回退不破身份（出生代不同）。判：第一个号取几（0 / 1 / 别的）、空树时「最大号」怎么读；谱系容器（类型 5，只增不删、随现行）是否同一规则；墓碑树随现行、`deleted_inodes` 取 R_old 时，回退之后再开新墓碑容器的号会不会与回退前写过、现在不可达的容器撞身份；容器号 0 在别处有没有已登记的含义（inode 树内部节点条目类型段 0、实例表片序号从 0 起）。

### B3　四条新树表条目的头 ID
D8 已定项 8「头 ID 8 字节的取值」只点名了七棵已有树。判四棵新树各写什么：`deleted_inodes` 回退时随 R_old（与 extent 树同类）是不是该照 extent 树写它服务的头（12）；墓碑树、谱系树随现行；logged_ops 字段表未定（C364）。写错了谁会读错（D5（快照 / 空间记账机制） 已定项 9 头 ID 的读者）。

### B4　`deleted_inodes` 装不下一个根时
key 8、无 value，码 2 条目宽 8，一个根约 2031 个号（实现员推的，没跑）。判：第一版队列的长度上界是多少（unlink 是一次调用跑完全部批，还是意图之后可以先返回、续做之前能攒多个；挂载续做走到空）；上界小于一个根时，第一版写「多于一个根就拒」是否成立、拒成什么；要长层时照哪条已定写法。

### B5　墓碑树根长高
D18 已定项 24 第 1 条：根满时长高，照 D8 已定项 6；C619（墓碑树根长高那次发布没有崩溃流）。今天的 inode 树写法在根满时拒。判：第一版要不要实现墓碑树根长高（根装 135 个容器 × 815 条 ≈ 11 万次 unlink 之后才满，推的）；不实现时到满那一刻拒成什么（不许假性 ENOSPC，D3 已定项 9），删除路径能不能被这一拒挡住（D3 已定项 17：释放空间这个操作本身不需要申请空间）。

### B6　环窗口式子里的「根环里的根数」
D28 已定项 1「环窗口」那一条：环窗口 = (根环里的根数 + 1) × W。读法甲：根环槽数 3 × S（S 是系统配置每区槽数）；读法乙：此刻环里读得出的根条数。`research/prompts/m3-delete-r3-main-verification.md` 第三节 G1-窗口系数那一行「顶点在第 3S 次发布附近」与辩方腿 3.1 节按甲量。判：哪种读法罩得住顶点、哪种在准入那一刻算得出（不遍历，`.claude/rules/fs-design.md`「记账是事务的副产品」第一格）；两种读法给出的数在 S = 4、8、16 上各是多少。

### B7　墓碑预付的摊分式子
D3 已定项 2：每个活对象（nlink ≥ 1）一份墓碑记录的摊分（含墓碑树内部节点的摊分）记进已承诺预留（记账标签 6），另加全池常驻一份（一个开放墓碑容器 + 根）。`research/prompts/m3-delete-r3-main-verification.md` 第三节 G1-墓碑预付那一行引辩方算的 41 字节 / 对象、常驻 3 槽。判：实现要照写的精确式子（单位是字节还是槽、按副本之和还是每盘、向上取整在哪一步、两份副本怎么记，照 C375（待删占用与已承诺预留按份还是按和记没有条款） 的已定口径）；它改新池新建文件那一版记账树的哪几个字节；标签 6 在意图、各批、最后一批、回退各取什么值（D8 已定项 16 第 7 条判据 ④「标签 4、6 等于从这一版镜像现算的值」要算得出）。

### B8　unlink 的接口形态
判：unlink 挂在会话的用户改动上（`publish_user_change` 的一个成员）还是 `transaction` 里一个独立入口；一次调用是只写意图那一次发布、还是意图加全部批一路做完；只供测试的批大小旋钮放在哪；崩溃注入怎么点名「意图之后、第 k 批之后」。这一格是实现形态，不改格式，判它是为了让 B4 的队列上界有依据。
