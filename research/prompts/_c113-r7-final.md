## 三、定案

### P1 单元头带「写序」= (实例代号 4, 事务号低 48 位)

字段、住哪、取号纪律 1 / 2 / 3、W1 同第六版。改动三处：

- **码 2 / 3 的写序**：事务号那 6 字节 = 那次 checkpoint 里已分配的最大事务号，**不参与任何判定**（判定只用实例代号与诞生代号，I-1.8 对码 3 的全序键是 (诞生代号, 实例代号)：一个实例在一个 checkpoint 只有一个固定点）。
- **记录按事务号顺序追加**：第一版串行提交（D13 已定项 2）下这条恒成立，W 的前缀性第一版靠的是串行提交；③ / ④ 买的是并行提交打开之后 W 仍是前缀。
- **失败表（封闭，四格）**：① 取号之前失败 ⇒ 无事；② 取号之后、尚未向设备发出任何单元写请求 ⇒ 号作废；③ 发出过单元写请求之后：单副本写失败换落点重试、写序不变、预算 T_retry；预算用尽或别的事务级失败 ⇒ **实例切换**；④ 固定点 / 发布阶段失败（分配失败、固定点收敛不了、根槽写失败）⇒ **实例切换**。
  **实例切换 = 本次挂载内做一次恢复**：取新实例代号（P2 的取号规则），写行 (旧实例, 最后发布的 txg, 最后施加的事务号)，重发在飞 checkpoint；号 ≤ W 的事务的效果照旧（它们的记录已追加），号 > W 的事务按新写序重做（数据单元重写）或向还没返回的调用者报错；固定点单元全部按新实例重写。不转只读、不等下次挂载；只有取号自己失败（P2）才只读。
  **为什么只剩这一条路**：当前实例没有行，谓词对它只能问「诞生代号 ≤ 挂载根 txg」；作废一个 checkpoint 而不换实例代号，重发那个号一发布，诞生代号等于它的孤儿全部判已发布 ⇒ 复活。**作废 checkpoint 必须换实例代号**，这是四格失败表能封闭的依据。
  **代价**：一次实例切换 = 一条行 + 整条实例表链重写 + 在飞 checkpoint 里号 > W 的数据单元重写 + 一次固定点重做；触发机会 = 每个单元写与每次发布。频率未测。

### P2 实例表（码 3 打包记录类型 4）；实例代号

单元、记录、四元组、持有、片容量、根记录 186 同第六版。改动：

- **行**：(实例代号, T_pub, W)。恢复写行时 **T_pub = 所选根的 checkpoint_txg**（恒选最新可读且自证通过的根；它可以不是最新发布过的根），**W = 从所选根的 tail 起连续重放、施加的最大事务号**（连续性由 jsn 给：接不上就一条都不施加，W = 0）；实例切换同此；回退行 (r_old, T_old, 0)；中间实例 (i, 0, 0)。
- **谓词**：i < i_now 且无行 ⇒ 已发布；有行：码 1 ⇒ **b ≤ T_pub ∨ n ≤ W**（在所选根里，或被重放施加；事务号在实例内单调、记录按事务号顺序追加，两个条件覆盖全部已施加的事务）；码 2 / 3 ⇒ b ≤ T_pub（所选根之后的固定点单元一律未发布，恢复实例重写）；i == i_now ⇒ b ≤ 挂载根的 txg；i > i_now ⇒ 判损坏。
- **回收**：行可删 ⟺ 整轮清扫对该实例写过的每一个落点都得出了判定（读成功并按行判、已抹头、已被覆盖），其中没有未发布单元，且这一轮里没有任何一次读失败 ∧ 全部设备在线 ∧ 根环里没有该实例发布的根。设备维与扇区维是同一条闸的两半。
- **表不可读**：只读挂载；扫描重建停在级 1。**射程**：表没了 ⇒ 一条行都没有 ⇒ 全部旧实例的全部单元落进「无行 ⇒ 已发布」，被回退抛弃的整段时间线也在内——所以是只读与停在级 1，不是记歧义。
- **实例表单元自己**：不走 I-1.2 的谓词，它的现行版本由根记录持有的物理指针唯一确定；指针指不到或校验不过 ⇒ 表不可读那一支。
- **可写挂载的准入与取号**：① 判可写：可写设备数 ≥ w 的下限 ∧ **独占打开池中过半的设备**（任意两个过半集合相交，块设备独占打开才成为池级互斥；4 盘池只剩 2 块可写时只能只读，与 D2 已定项 9 同一取向）∧ 实例表可读；② 新代号 = max(全部可见超级块的代号, 根环里全部根记录的实例代号) + 1，**写进全部可见超级块、全或无**——任何一份写不成即只读挂载；③ 之后才动任何单元。I-7.7 加强：全部可见超级块的实例代号相等，且 ≥ 根环里任一根记录的实例代号。前提「同一时刻只有一个可写挂载」由 ① 保证；多主机共享存储不防。C120 在允许加第三块盘之前到期、与过半规则同时。

## 五、对立臂的判决（第三次重写理由，结论不变）

**臂 B**：写序只上码 2 / 3；数据单元头不动；extent 树的叶改成码 3 打包记录单元；数据 extent 顺着重建出来的 extent 树到达。

**判决：取臂 A（写序上全部三类）。理由是 D21 自己的重算性判据，不是「开例外」**——D21 已经写着「态别按重算性判，不按『树』这个词判：叶若装着算不回来的值（inode 树的叶）⇒ 权威态」，inode 叶做成码 3 的例外早就在。两者的差别：

| | inode 叶做成码 3 | extent 叶做成码 3（臂 B） |
|---|---|---|
| 叶里装的是什么 | inode 记录本身，它就是那份数据 | 「哪个 extent 在哪」——一份指向别处的映射 |
| 在臂 A 下算不算得回来 | 本来就算不回来，做不做成码 3 都是权威态 | 算得回来：数据单元自己的头带五元组 + 诞生代号 + 写序，扫一遍就重建得出 |
| 改成码 3 之后 | 态别没变 | 臂 B 同时把数据单元头里的写序拿掉 ⇒ 那份映射变得算不回来 ⇒ **把一份可重算的东西降级成权威态** |

量出来的两个数只当量出来的数：E104 `wseq_meta_only` 臂量的是叶丢失那一格（数据孤儿全部复活）；E105 量的是臂 B 的写代价由树高定（等高段 1.000、其余 1 + 1/树高、批量 1.44–1.78×）。臂 A 的价钱：每个数据单元与墓碑 +10 字节、I-6.2 白名单加两项。
