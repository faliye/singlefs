## 候选与读者规则的定义

记号：盘 0、盘 1；旧表 T0（盘 1 那一项 = X 整槽），新表 T1（盘 1 那一项 = 2X）；每盘两槽，世代号逐盘计。今天可写挂载的写序（读码）：

1. 读阶段与重建分配器之前不写盘：「逐盘核只读盘、不写，排在前面不改盘上的结局。」（`crates/singlefs-core/src/mount.rs:7917`）。分配器在取号之前按探测值建空闲图：「DeviceFreeMap::with_unit_area_start(*identity, device.size_in_bytes(), unit_area_start)」（`crates/singlefs-core/src/mount.rs:3242`）；取号之前先在拷贝上预演之后几次发布的落点（`crates/singlefs-core/src/mount.rs:7904`）。
2. 取号两轮：「每轮逐盘写一次系统配置槽、之后一道池屏障。两轮按世代号逐盘 +1 写，第二轮落在第一轮没碰的那一槽，两轮都完成之后每块盘两槽都带新号——」（`crates/singlefs-core/src/transaction.rs:1302`）。
3. 写行那次发布（第一个单元写）：「let row_publish = match &start.previous {」（`crates/singlefs-core/src/mount.rs:8685`），单元两盘同槽：「device.write_at(slot.to_device_offset(), unit, WriteDurability::Plain)?;」（`crates/singlefs-core/src/transaction.rs:585`）。
4. 每次发布末尾：「/// 发布的最后三步（D16（发布语义） 已定项 7 的持久顺序）：根槽 FUA 写 → 系统配置槽轮换 → 屏障，屏障完成才返回。」（`crates/singlefs-core/src/transaction.rs:1714`），轮换逐盘各写较旧那一槽，盘与盘之间不隔屏障（`crates/singlefs-core/src/transaction.rs:628`）。

候选：

- 搭取号：探测值大于生效表时，取号两轮写的系统配置带 T1（只改内容，不加写）。不变大时取号照抄生效表，新池新建文件的字节不变。
- 单独两轮：取号之后、写行之前另发两轮（每轮逐盘一写、轮后池屏障），把四槽写成 T1。按 `crates/singlefs-verification/src/writable_mount_phases.rs:21` 的分段定义「/// 取号：写行那次发布的第一个单元写或 journal 记录写之前的那几次系统配置槽写。」它仍落在取号段，不加第七段。变体「单独两轮放在逐盘核之前」见 J8。
- 意图三轮：取号之后另发三轮：第一轮写较旧槽 = T0 + 「正在改表」标记；第二轮写另一槽 = T1；第三轮写带标记那一槽 = T1；每轮后池屏障。要在系统配置里多一个标记字段（格式改动）。变体「意图折进取号」：标记随取号第一轮、T1 随取号第二轮，见 J7。

读者认中间态的规则（判决原文是「跨盘、跨槽（限本池 fsid、这一版认得的自证槽）容量表不等整池拒」，`research/prompts/m4-capacity-r3-main-verification.md:28`）：

- 逐项取大：本池、认得的自证槽里每一项取最大。
- 逐项取小：每一项取最小。
- 取择到那份：取今天跨盘择到的那一份，即盘表次序第一块有可择槽的盘、它两槽里世代号大的那一槽（「None => chosen = Some(best_on_device),」，`crates/singlefs-core/src/recovery.rs:1897`；「if one.quantities.slot_generation > zero.quantities.slot_generation {」，`crates/singlefs-core/src/recovery.rs:1889`）。
- 取世代号最大：跨盘跨槽取世代号最大那一槽的表。
- 意图在场取旧表：只配意图三轮；有一槽带标记就取带标记那几槽的表，没有标记而表不等就逐项取大（或照判决原文整池拒）。

## 第 2 格：写的范围、次序与中间态读者怎么认

正文第 2 问原文：「2. 写几块盘几个槽、次序；写到一半崩溃，各盘各槽的表不相等——而那一题定了「跨盘跨槽表不等整池拒」，这两句怎么并存：读者在什么条件下认「正在改表」的中间态、取哪一份。」（`research/prompts/_m4-capacity-grow-r1-body.md:12`）

### J1 判决原文「不等整池拒」：一次挂载中途断电就整池拒（打中，三个候选都中）

历史（搭取号；单独两轮、意图三轮同形，换成它们的那几轮）：

1. 盘 1 从 X 长到 2X。
2. 可写挂载：取号第一轮先写盘 0 较旧那一槽（T1，世代 g+1），盘 1 那一写还在缓存里；断电（两写同段、之间没有屏障，`crates/singlefs-core/src/transaction.rs:1302` 那一句写的是每轮之后才一道池屏障）。
3. 盘上：盘 0 {g+1: T1, g: T0}，盘 1 {g: T0, g-1: T0}。下一次挂载照判决原文跨盘跨槽比，不等整池拒；可写、只读与恢复同一个择系统配置，都拒。离线出路只认判不出的盘面，这一面不是。

放开扫用户动作：不动、再长大、缩回，三样都在同一个择槽里先被拒，到不了容量比较。四问：① 不分辨候选：四槽不可能一次原子写完，三个候选都至少分两轮；病根是判决原文那一句本身。② 系统看得到两份表，看不到「这是写到一半」——要另给它判别子（J5 的取大、J6 的标记）。③ 满足第 2 问「这两句怎么并存」那一分句：照原文并存不了。④ 判决原文没给改法；J3–J7 逐条核各规则。

### J2 判决原文 I-7.20 与中间态冲突，而崩溃点重放走不到这些态（打中，内部矛盾）

判决原文：「新不变量：I-7.20（各盘各可择槽的逐盘容量表逐项相同）」（`research/prompts/m4-capacity-r3-main-verification.md:34`）。J1 那些崩溃态在池级 checker 上 I-7.20 必红，崩溃点重放每个崩溃态恢复之后都跑 checker，变大那一次挂载的每个取号段崩溃态都会红。今天看不见，是因为装置造不出变大：「/// 崩溃点重放的内存池每块盘一样大，字节数住 `device_size_in_bytes` 那个字段；池里没有这块盘就 `None`。」（`crates/singlefs-verification/src/memory_pool.rs:418`）——整池一个字节数，单独长一块盘在内存池里写不出来。

四问：① 不分辨候选。② checker 看得到全部槽，判据本身错。③ 第 2 问「中间态读者怎么认」：checker 也是读者，同一条规则要进 I-7.20。④ 改法：I-7.20 改成「各槽表之间只差一次记表（每项要么旧要么新，新 ≥ 旧）」，并在内存池里加逐盘字节数（推的，零轮）。

### J3 逐项取小、取择到那份：换回旧盘镜像的缩回被认成中间态放行（打中）

历史：

1. 池：盘 0 4 GiB，盘 1 X。用户给盘 1 留了一份镜像（LVM 快照或整盘拷贝），里面两槽都是 T0。
2. 盘 1 长到 2X，可写挂载记下 T1（搭取号：取号两轮之后四槽 T1）；之后的发布在两盘同槽写下 X 之后的单元，根落盘。
3. 用户把盘 1 换回第 1 步那份镜像，盘尺寸回到 X。
4. 只读挂载：盘 0 两槽 T1，盘 1 两槽 T0。逐项取小 → 盘 1 那一项 X = 探测值 → 放行，不点名；读 X 之后那些单元，盘 1 那份越界、退到盘 0 那份，读得到，冗余少一份没人报。取择到那份：盘 1 排在盘表第一块时取它的 T0，同样放行；盘 0 在前时取 T1，点名。
5. 可写挂载：盘 1 落后于所选那一版，走落后支（「落后支只在这块盘落后于所选那一版时才看单元与根槽那一半」，`.claude/kb/decisions/22-单元原子性怎么合成.md:185`），与容量无关；这一格只漏只读。

放开扫第 3 步：换回镜像但盘仍是 2X ⇒ 探测不小于任何一份表，容量不判，落后支照管；镜像放进比 X 还小的盘 ⇒ 五条规则都拒；什么都不换 ⇒ 四槽同为 T1，不是中间态（M1）。漏只在「旧镜像放回 X 大的盘」这一族。这是本池的旧盘（落后盘），不是「两块盘来自两个池」（那一句的射程在 `.claude/kb/decisions/22-单元原子性怎么合成.md:185`）。

四问：① 分辨规则：取小、取择到那份中，取大、意图三轮不中。② 系统当时看得到盘 0 两槽的 T1，规则把它丢了。③ 满足第 2 问「取哪一份」与第 5 问「有没有落点越过缩回后的盘尾而读者看不出的历史」（`research/prompts/_m4-capacity-grow-r1-body.md:15`）。④ 取大修；意图三轮修（无标记 ⇒ 取大）。

### J4 取世代号最大：跨盘比世代号没有锚（打中）

世代号逐盘计，补写过的盘从 1 重数：「/// 一块盘写一次系统配置槽：世代号 = 这块盘两槽里自证过的最大世代号 + 1（两槽都读不出时从 1 起），槽 = 世代号 mod 2；」（`crates/singlefs-core/src/transaction.rs:666`）。历史：盘 0 两槽全废、某次可写挂载过了补写闸，盘 0 世代号回到 1、2，盘 1 仍在几百；用户留盘 1 镜像（T0，世代号几百）；之后照 J3 第 2、3 步。盘 0 自补写以来的发布次数少于盘 1 镜像里的世代号差时，跨盘最大世代号落在旧镜像那一槽 → T0 → 同 J3 第 4 步放行。四问：① 分辨规则。② 看得到 T1，比较的量没有意义。③ 同 J3。④ 取大修。

### J5 逐项取大：安全上没打中，多一格误拒（代价）

试的形状：J1 各崩溃态 × 用户动作 {不动、缩回 X、再长大、换回旧镜像}；J3、J4 历史；取号第二轮被删（K3）。漏都没有：落点越过 X 之前四槽都已 T1（K2），取大只会取到 T1 或更大。

代价历史：盘 1 长到 2X → 可写挂载 → 取号第一轮盘 1 那一写落了就断电（盘 1 {T1, T0}，没有任何单元越过 X）→ 用户看挂载失败，把盘 1 缩回 X → 下一次：取大得 2X > X ⇒ 可写拒、只读放行点名；没有出路让表变回 X（表只增，D2（RAID 条带策略） 已定项 3 那条显式事务第一版没有），只能再把盘长回 2X。取号报 I/O 错、回卷之后再缩回，同形。M3 那一格（记下、没用、缩回，可写永久拒）是定案自己接受的；J5 把它从「记成了」推到「记到一半」。

### J6 意图三轮 + 意图在场取旧表：没打中（只剩一个五步的构造形）

逐段：第一轮中断，各槽表都是 T0（有的带标记），表相等；第二轮中断，带标记那一槽在 ⇒ 取 T0，此时还没有越过 X 的单元，对；第三轮中断（盘 0 {T1, T1}、盘 1 {T0+标记, T1}）同上；第三轮屏障之后四槽 T1、无标记，单元才写。J3、J4 的旧镜像不带标记 ⇒ 取大 ⇒ 点名。

构造形（推的，五步，含一次断电）：第二轮中断留下带标记的槽 → 用户此时给盘 1 留镜像 → 再挂载把三轮走完、写下 X 之后的单元 → 把镜像放回 X 大的盘 → 只读：标记在场取 T0 → 放行不点名。零轮改法：标记带写它那一次的实例代号，有不带标记的 T1 槽实例代号严格大于标记的实例代号时取大；同一次挂载里中断的两轮实例代号相等，不翻。

### J7 意图折进取号：标记槽活到单元越过旧容量之后（打中）

历史：取号第一轮写较旧槽 = T0 + 标记（世代 g+1），第二轮写另一槽 = T1（g+2），屏障；写行那次发布把单元写过 X、根 FUA；断电在它的系统配置轮换之前（轮换才覆写带标记那一槽，`crates/singlefs-core/src/transaction.rs:1714`）。用户把盘 1 缩回 X。读者：标记在场取 T0 = X ⇒ 只读放行、不点名；可写由分配记录越过单元区末尾那一判拒。四问：① 分辨「折进取号」与「意图三轮」。② 系统看得到 T1 槽，规则不认它。③ 第 3 问「崩溃在哪一步之后才可能有落点越过旧容量」（`research/prompts/_m4-capacity-grow-r1-body.md:13`）与第 5 问。④ 加第三轮（即意图三轮）修。

### J8 单独两轮放在逐盘核之前：绕过补写闸（打中，摆法）

两槽全废的盘今天只在取号里补写，补写之前过闸（`crates/singlefs-core/src/mount.rs:7922`）。单独两轮若放在逐盘核之前、逐盘都写，那块盘先得到一槽自证过的系统配置，逐盘核看它就不是两槽全废、走落后支（「下一次挂载走落后支、不再过补写闸」那一句的同一个后果，`.claude/kb/decisions/22-单元原子性怎么合成.md:185`），带全部单元、环槽读错、单元区扫描几件闸都没判。四问：① 分辨摆法。② 系统写之前看得到两槽全废。③ 第 1 格写的时点。④ 摆在取号之后修（「单独两轮」的定义就是这一摆）。

## 第 3 格：新容量生效与分配的先后

正文第 3 问原文：「3. 新表生效之前谁都不许按新容量分配：次序怎么保证，崩溃在哪一步之后才可能有落点越过旧容量。」（`research/prompts/_m4-capacity-grow-r1-body.md:13`）

### K1 写者照判决原文「抄择到的表」：同一次挂载的轮换把旧表写回（打中，三个候选都中）

判决原文：「写者：每条写系统配置槽的路抄择到的表，连 devs 一起抄」（`research/prompts/m4-capacity-r3-main-verification.md:29`）。写入口按读阶段择到的那一份建（`crates/singlefs-core/src/mount.rs:9876`），择到的是 T0。

## 第 4 格：跨分配记录树根层级边界

正文第 4 问原文：「4. 变大跨过分配记录树根层级边界时怎么办（今天可写挂载会被层级错拒掉，两条腿读码推的，没有用例验过；两盘等大时边界约每盘 175.89 GiB，单盘 1→2 那道边界约 1.04 GiB）：拒记、还是连树一起重建。」（`research/prompts/_m4-capacity-grow-r1-body.md:14`）

### L1 记录与树的层级改不成原子（打中，三个候选都中）

历史：盘 1 长过边界；搭取号把四槽写成 T1（层级 L+1），屏障完成；断电在写行那次发布的根落盘之前（或写行之前任何一处报错、挂载失败）。下一次挂载：四槽 T1，所选那一版的分配记录树是 L 层写的，按 T1 算 L+1 读，709 行那一判拒；可写挂载在写任何东西之前就拒，这一版的树永远没机会重写，此后每一次可写挂载都拒。反过来先写 L+1 层的树、后改表，表还是 T0 时同样对不上。单独两轮、意图三轮同形（表在系统配置、树在根下，两处由不同的写落盘）。

四问：① 不分辨候选。② 系统读得到根节点头里自述的层级，判法拿它比现算值而不是用它。③ 第 4 问「连树一起重建」那一支。④ 拒记修；「根层级取根节点自述、只判它装得下这一版的全部记录」修（零轮，core、checker、GPU 判器三处一起改）。

### L2 就算改成了，环里旧根的树全读不了（打中，三个候选都中）

层级是池级量，不是每条根各带的量。跨过之后环里与回退候选里在跨过之前写的根，它们的分配记录树都是 L 层：影子账与抬 F 的上限读别的根的账（「// 读的是别的根（影子账、抬 F 的上限）的账：映射树只按「拼得成一棵树」核，与这里读分配记录树同一个口径。」，`crates/singlefs-core/src/recovery.rs:2929`），读不出；判退那一支「退过去的那一版建不出来，留在所选的那一版」（`crates/singlefs-core/src/mount.rs:9910`），结局被静默改掉；管理员回退到跨过之前的根读不了账、拒。根记录写了就不改，「连树一起重建」重建不了它们。四问同 L1；④ 只有根层级取根节点自述（或根记录自带层级，动根记录字段表）修，拒记也修（层级不变）。

### L3 拒记：安全上没打中，代价是一档封顶

拒记 = 这次要记的每一项取探测值与「不改层级的最大值」的小者。层级不变，L1、L2 都没有对象。代价（算术，推的）：叶 812 槽（`crates/singlefs-format/src/lib.rs:163`）、扇出 169（`crates/singlefs-format/src/lib.rs:169`），两盘等大时每盘最多 84 格：层级 1 每盘 84 × 812 = 68 208 槽 ≈ 1.04 GiB，层级 2 每盘 11 527 152 槽 ≈ 175.89 GiB，层级 3 每盘 1 948 088 688 槽 ≈ 29.03 TiB。mkfs 时每盘 100 GiB 的池，之后最多长到约 175.89 GiB；1 GiB 建的测试池最多约 1.04 GiB。两盘都长而只能长一块时，先给哪块要另定。这是交用户的岔路（拒记 / 根层级取自述 / 根记录带层级），不是安全漏。

### 第 4 格之后：这一题最脆弱的前提

「分配记录树根层级是池级量、按容量现算」：它让每一条历史根的树形依赖一个会变的池级值，第 4 格因此在系统配置的任何写序下都解不开（L1、L2 对三个候选一起中）。推翻它的观测：拿 `allocation_record_tree.rs:709` 那一判按根节点自述层级改写，跨过边界之后 L 层旧根与 L+1 层新根都读得出、checker 违例 0。第二脆弱的是验证装置：内存池整池一个字节数（`crates/singlefs-verification/src/memory_pool.rs:418`），第 2、3 格的结论今天没有一条能在崩溃点重放上量。
