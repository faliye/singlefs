### 读法写死

| 词 | 口径 |
|---|---|
| GC | 核心层后台入口 `MountedSession::run_compaction_in_the_background`（`crates/singlefs-core/src/mounted_session.rs:2401`）的每一次调用，连同它调用末尾发的 discard。核心层不起线程（第三节），装置起一条专门的 GC 线程一次次调它，这条线程只做这件事 |
| 同一负载、同一池 | 同一档的每一次跑都从逐字节相同的起步镜像开始（第五节「负载」），重挂之后交同一串用户改动（同一个种子），挂载参数只差 `background_compute` 与 GPU 那几项（卡、上限）；整理只供测试的开关两种模式相同（第五节） |
| 一次整理（问题单第 1 行） | 一次跑里 GC 线程从第一次调后台入口到最后一次调用返回为止做的全部整理；交替跑里是这一次跑的全部 GC 调用（第五节「两种跑法」） |
| GC 挂钟 | 交替跑：GC 线程上每一次后台入口调用前后读 `std::time::Instant`，各次之差相加（起不起跑的调用都算；不起跑的那几次几乎不花时间，照算）。另报每批摊到的挂钟（÷ 这次跑的搬迁批数）。并发跑另报跨度挂钟（附带）：头一批所在那次调用开始到最后一批所在那次调用返回 |
| 一批 | 一次整理发布里 `units_relocated_by_this_publish` 非空的那一次（同 E185（GC一批搬迁的挂钟拆分） 跑前登记第一节的口径），签发、删意图不算批，单列 |
| GC 的主机 CPU 时间（判据用的口径，记作「进程口径」） | 交替跑里前台线程在 GC 调用期间阻塞着（等通道），GC 调用窗口里进程用掉的 CPU 就是 GC 线程加驱动等别的线程为它用掉的：每次 GC 调用前后读 `clock_gettime(CLOCK_PROCESS_CPUTIME_ID)`，差相加，再减去同一窗口里前台线程与主线程各自 `CLOCK_THREAD_CPUTIME_ID` 的增量（应接近 0，照减、照报）。这样「它起的线程」与 Vulkan 驱动在本进程里起的线程都算进去 |
| GC 线程口径（附带） | 同一窗口里 GC 线程自己的 `CLOCK_THREAD_CPUTIME_ID` 增量之和。与进程口径各报各的，判据只用进程口径 |
| 不含挂载那一刻量代价 | 挂载与开卡（`open_background_gpu_compute`，里面每张卡量一次提交的代价，`crates/singlefs-background-gpu/src/background_gpu.rs:1070`）都在第一次 GC 调用之前做完，窗口外；开卡那条线程（`waiting_for_the_gpu.rs:290`）到点没交回而还在跑的，那一次跑作废（第十一节） |
| 省下的 CPU 时间 | 同一档、同一次重复里，CPU 臂的进程口径减 GPU 臂的进程口径（成对相减，不拿中位数相减） |
| 前台 fsync | 核心层没有 POSIX 那一层，一次用户改动的发布（`MountedSession::publish_user_change`，`mounted_session.rs:2101`，返回时已过屏障）就是一次 fsync。延迟 = 发布返回时刻 − 这一次按计划该发出的时刻（开环，计划时刻固定，落后了照算进延迟，不只算从真正发出起） |
| 重复次数 | 每档每臂 5 次（`.claude/singlefs-ai-sop/rules/test-discipline.md`「单次观测不算数」：真实时序与驱动都在，观测有变化） |
| 离散度 | 每档每臂 5 个数报中位、最小、最大与中位绝对偏差；成对差 5 个报全部 5 个数、中位、最小、最大。正负：5 个都 > 0 记「正」，都 < 0 记「负」，有正有负记「不稳定」 |
| 卡 | 「点名一张卡」：`background_gpu_devices` 只点本进程看得到的独立显卡里 PCI 地址最小的那一张；「全部卡」：不给 `background_gpu_devices`（用本进程看得到的全部独立显卡，按 PCI 地址次序填满）。两种都给每张参与的卡 `background_gpu_memory_limit` = 1 GiB。装置不点卡号，看得到哪几张由服务定 |

### 盘容量的两种读法与各档取值

「盘容量」= 池里每块盘的 `size_in_bytes`（两块盘一样大）。两种读法给的答案可以不同，判据形式相同，都登记（文件头那一句）：

| 读法 | 怎么变 | 三档（每块盘字节 = 784 MiB + 单元区） | 数据量 P（码 1 数据单元，活的） |
|---|---|---|---|
| 定占用读法 | 容量涨，活数据占单元区的比例固定 50% | 单元区 256 MiB、1 GiB、4 GiB（每块盘 1040 MiB、1808 MiB、4880 MiB） | 4096、16384、65536 |

取值的理由：
- 784 MiB 是默认环长下单元区的起点（槽 50176 × 16 KiB，`crates/singlefs-core/src/allocator.rs:290-293` 与 `:421`），每块盘都要先装下它；用默认环长，不为实验另造一个真环境不会有的环长（`.claude/singlefs-ai-sop/rules/test-discipline.md`「测试照真实的条件造」）。
- 最小档单元区 256 MiB（256 个聚簇段）：装得下 4096 个活数据单元连同造碎片时的旧副本（占单元区 75%），碎片段 128 个，够一次跑用（第五节「负载」的算式）。
- 定占用读法每档 4 倍：GC 每批读的中央映射、分配记录条数随 P 涨，选段打分的段数随单元区涨，4 倍一步两样都分得开；顶档 4 GiB 受内存限：起步镜像加一份工作副本约 13 GiB（第十四节），再往上一档约 52 GiB，装不进本机 60 GiB 的内存里与别的任务并存。
- 测不到的：真盘的 TB 级容量（内存放不下，真盘镜像在共享根上走网络，挂钟不可比）。这一条写明测不到，不拿小档外推当量到。

#### 已定项 13：后台任务的计算放在哪、怎么开、什么节奏

**定案**：八条。

1. **计算放在哪**：默认 CPU。挂载参数 `background_compute`（取 `cpu` 或 `gpu`，默认 `cpu`；命令行有了之后写成 `--background-compute=gpu`）选 GPU。这一组挂载参数（第 1、2、3 条）只有一份，管全部后台任务，不按任务分设：开了 `gpu`，凡有 GPU 路径的后台任务（GC 搬迁、打包搬迁，以后接上 GPU 路径的别的后台任务）都走 GPU，没有 GPU 路径的照旧在 CPU 上算。它只活在内存里：不写进系统配置、不占 feature bit（D24（后台重活能不能卸给 GPU） 已定项 2 第 1 条），每次挂载各给各的。挂着的时候可以经已挂载会话的控制接口切换（一次切全部后台任务），从下一批开始生效；一批之内不换（`.claude/rules/fs-design.md`「分支变量不许在操作中途改变」）。GC 搬迁放上 GPU 的是三段：扫描里的校验和核对、区域扫描里的单元头解析与映射反查、选段打分；整理发布那一半照旧在 CPU 上。开了 `gpu` 就照开着跑，不按哪张卡、哪种提交间隔赚不赚自动切回 CPU；赔的卡与提交间隔写进文档与第 7 条的对照组。
2. **用哪几张卡**：挂载参数 `background_gpu_devices` 是一张卡的列表（可以点几张），点名了就只用点名的卡；不给就用本机全部独立显卡，集成显卡、虚拟显卡、软件 Vulkan 适配器与认不出类型的适配器不算「显卡」、不进「全部」，点名它们照「点名的卡不存在」拒（第 4 条）。参与的卡都用，按卡的顺序填满：点名的按点名次序，没点名的按 PCI 地址次序，先把前面的卡填到它的上限，活多了才用后面的卡，不要求每张卡都有活；按第 7 条量出来赔的卡照用；挂载时量的代价可以算，不报、不记进性能，也不再用来分活。
3. **显存上限**：挂载参数 `background_gpu_memory_limit` 是一个带单位的字节数列表，按次序一张卡一个，与参与的卡逐个对应（给了 `background_gpu_devices` 就对它的列表，没给就对第 2 条那份全部独立显卡的列表），不补齐：`background_gpu_devices` 点了三张卡，`background_gpu_memory_limit` 要么不给、要么正好给三个数，只给一个也报错；GPU 模式下全部后台任务在那张卡上合占的显存不超过它的那一个数：这个数是上限、不是预留，用得比它少没有关系（卡上此刻空闲的不到这个数也照常跑，只用空闲的那些），任何时刻都不许比它多，缓冲、暂存区一起算在里面。不给就不设上限，后台任务跑的时候卡上能用多少用多少。装不下不拒绝：一批（连同缓冲、暂存区）在上限里装不下，就按上限自适应切成几片、缩小逐次交，挂着时单条装不下也切；挂载那一刻量代价（第 2 条）的那一段同样切片，代价取各片之和。参与的卡的上限连最小的一片都装不下，这张卡就不用（第 2 条「参与的卡都用」的例外）：照开设备、不分活、报出来，挂载不因此拒绝；挂着切换给了它装得下的上限，从下一批起照新上限按卡的顺序重新参与分活。参与的卡因此一张都不剩时挂载照样不拒，后台任务照第 4 条进出错停着。
4. **配错时拒；GPU 用不上时重交、报警、停下，GC 按占用在 CPU 上补跑**：挂载或切换那一刻，`background_gpu_memory_limit` 给了而个数与参与的卡数不等、某一个数超过那张卡的显存总量、GPU 不在、驱动不对、点名的卡不存在，或 `background_gc_cpu_compensation_threshold` 超过 100（选 `cpu` 时也判），就拒绝挂载（或拒绝切换）并报错。挂着的时候一批等 GPU 超过挂载参数 `background_gpu_wait_limit`，在同一张卡上重交（只重交超时的那一片，同一批已做完的片留着），至多 3 次，都超时才报警、判那张卡用不了；重交只在挂着时的批里做，挂载那一刻量代价的提交超时不重交，算那张卡没开成。挂载时开卡（含编管线）等的上限是 5 分钟，到点当那张卡没开成：点名的卡照「点名的卡不存在」拒绝挂载，没点名的卡不用，参与的卡一张不剩时挂载照样不拒、后台任务进出错停着（第 3 条）；挂载等开卡成功或到点才往下走，不做回调。挂着时超时重交与空闲显存不足说的「一批」，都是一段的一次调用：扫描里的校验和核对、区域扫描里的单元头解析与映射反查、选段打分三段各自计，不按整理的一批、也不按切出来的片。每段一次调用里同一张卡的超时跨片累计，交活之前先等前一次超时提交的那一等也算进去，累计到第 4 次等超过上限就报这张卡用不了（`GpuUnusableAfterResubmissions`）。卡上此刻空闲的显存连这一批最小的一片都装不下（给的上限之内建缓冲显存不足，一路切小到最小的一片都建不成）：这一批不给这张卡分活，它那份转给这一批别的参与的卡，不报警；参与的卡这一批全都装不下才报 `EveryParticipatingGpuShortOfFreeMemoryForTheSmallestPiece`，按挂着时 GPU 出错办，下一批照设置重新起。建缓冲显存不足、切小重切时，这一段在这张卡上已做完的片不留，照新的切法整段从头重交。挂着的时候 GPU 出错（含重交 3 次都超时），正在算的那一批放弃（意图留在盘上，目标态单调，已定项 2），那个后台任务停下，并在停着期间每次后台整理被叫起都报警：「每次」指每次叫起，发布之后的查与定时兜底的查都算，补跑的与照旧停着的都报，显式的整理入口每一趟也算（入口在任何读写之前就拒的那一次不算），直到一次通过校验的切换解除停下。报警带哪个后台任务（`task`）、原来那一次的错（`error_that_stopped_the_task`）与它点名的卡（`gpu_devices_named_by_the_error`）、停下以来叫起了几次（`wakes_while_stopped`，停了多久数叫起的次数，不读挂钟；出错停下的那一趟不算，停下之后的下一次叫起是第 1 次，挂载那一刻就停着的头一次叫起是第 1 次，在叫起里停下与在可写挂载续做里停下数法相同）、停着期间在 CPU 上补跑了几批（`batches_compensated_on_the_cpu`）；通道是返回值里必须处理（`#[must_use]`）的报警，不是日志，调用方不处理编译就警告。卸载时不等还在跑的提交，有这种提交的那张卡整张泄漏、不析构。停着的时候收到任何一次通过校验的切换请求（校验同挂载那一刻），当场解除停下，从下一批起用新设置；出错之前已经收到、还没生效的切换请求，在停下那一刻也算数，照它解除停下。挂着切换到参与的卡一张都不剩的设置（第 3 条）：下一次整理入口与后台入口在任何写之前就报停着，删除续做也不走，报的是挂载那一刻同一个成员（`GpuUnusableUnderTheSettingsHandedIn`）。GC 报警停着之后在每一批开头判一次占用：任一块盘「已分配 ÷ 容量」超过挂载参数 `background_gc_cpu_compensation_threshold`（默认 85%，取整百分点 0 到 100，可调），这一批在 CPU 上补跑；都不超过就照旧停着，补跑途中降到不超过，下一批起照旧停着。占用逐盘算，和水位按盘算、空间准入逐盘判是同一种口径。补跑只管 GC，打包搬迁停着时不补跑。这两个参数与第 1 到 3 条那一组一起给、一起校验，挂着随切换请求一起换、从下一批起生效；不给阈值的切换沿用原阈值。各参数的取值、默认与代码落点在 [mount-parameters.md](../mount-parameters.md)。除了 GC 的补跑与第 8 条（连续几轮状态不确定的条目按条交 CPU 判，后台任务照旧在 GPU 上跑），停着的后台任务不换到 CPU 上接着跑。
5. **什么时候起跑**：每次发布之后按已定项 1 的三水位查一次；另有定时兜底，每隔一段时间再查一次，间隔是挂载参数。两种模式起跑规则相同。
6. **起跑之后的节奏**：GC 不在用户改动的调用线程里跑（不在用户改动返回之前跑一批），挪出之后三样照旧有保证：一趟发布预算有上限、签下一条意图那一判跨趟留着、整理批不插进用户改动的抬 F 与再判之间。签下一条意图那一判读的「上一条完成的意图」只留到下一次用户改动发成为止：每次用户改动发成就清掉它，下一趟从空起照常签新意图，预算照旧是这一次改动给的那一份；被拒、没发成的改动不清。GC 占盘写带宽有一个上限（挂载参数）；前台有 fsync 在等时不发下一批，这一判别子要 GC 挪出调用线程之后才看得到；它只约束整理批（每一批之前问调用方一次），整理开头先走的那一遍删除不是整理批，不受它约束。整理开头先走一遍删除（把盘上留着的删除意图做完）是可选的前置优化、为了效率，不是整理的一部分：删除与整理是两件事、各是各的事务，整理也可以不先删除；那一遍删除发的版不占整理一趟的发布预算。整理一批本身就是那次移动，整理判出的死空间由分配器的常规回收放掉、不交给删除；没删完的留到下一趟整理或下一次可写挂载，不因为它没删完挡住别的操作。
7. **值不值按省下的 CPU 时间算**：GPU 模式的目的是少占主机 CPU 时间，数据量大时跑得更快只是副产物。收益是后台任务少占的主机 CPU 时间（CPU 模式下它的 CPU 时间减 GPU 模式下它的 CPU 时间，后者含准备数据、提交、等结果、两份结果的比对，以及第 8 条交 CPU 判的那几条），挂钟与 CPU 模式持平也做；D24（后台重活能不能卸给 GPU） 已定项 3 那条按挂钟比的判据不管这一项罩着的后台任务。实现之后跑一组对照：同一负载、同一池，CPU 模式与 GPU 模式各跑，报两边的 GC 挂钟、主机 CPU 时间、前台 fsync 延迟，并在几档盘容量上各跑一遍，看收益随容量怎么变。
8. **GPU 的结果怎么复核**：两份独立写的 GPU 核（不共用核函数）对同一批输入各算一次，逐条比两份的结果。两次相同的条目算确认，交 CPU：CPU 照发布路径逐条核计划与读盘核（`crates/singlefs-core/src/transaction.rs` 的 `relocation_checked_against_the_version`），再改位图，不另外抽样复核 GPU 的结果；两次不同的条目写明状态不确定，这一批不回收、不搬，留到下一轮重算。同一个条目连续 2 轮（N = 2）都不确定，交 CPU 那一份实现单独判一次，按 CPU 的判定处理；连续不确定的计数只放在内存里，重挂清零。「轮」按落点认条目：扫描里的校验和核对与区域扫描里的单元头解析与映射反查两段，一个条目是一个落点（盘、槽、跨度），选段打分一段，一个条目是一个聚簇段（盘、起点槽）；一个落点在一批里两份核的结果不同，它就不确定一轮，结果相同或已交 CPU 判过，它的计数清零；没出现在这一批里的落点，计数不动、也不清。一批放弃（GPU 出错、等超过上限）时，那一批里已经交回的段照算一轮，放弃的那一段计数不动。每一批报确认、不确定、交 CPU 判的条目各多少，运行时看得出来。只有一张卡时两份核都在这张卡上跑，有几张卡时按第 2 条分活、两份核可以分开跑；不许要求多张卡，一张与几张都要能跑、判定相同。

### 负载：池怎么造

每档造一份起步镜像，同一档的全部跑都从它的逐字节拷贝开始：
1. 两块内存盘（装置自己写的稀疏内存盘，按 64 KiB 块懒分配，没写过的读回 0；照 `tests/common_pool_on_memory_devices/mod.rs` 的录制写法记改盘动作，记的是摘要，不存字节），每块盘字节按第一节那一档；mkfs 参数照同一个模块的 `parameters()`（region 设备 0、1、0，默认环长，512 字节扇区），fsid 换成本实验自己的 16 字节。取号、暖机、新池新建文件照 `pool_after_a_sequential_write_in_an_earlier_mount` 那一串。
2. 造数据挂载：可写挂载，第一个文件顺序写 P 个数据单元（`SequentialWriteOfAnInode` 或 `SequentialWrite`，按段顺序写满 P ÷ 32 段），会话丢掉。
3. 造碎片挂载：重挂，对第一个文件里每段按槽序每 2 个单元覆盖写其中 1 个（单元下标为奇数的那些，共 P ÷ 2 个；`WriteAtOffset` 一次一个，或 `DataChangesPublishedTogether` 一次合几个，执行员挑造得快的，几何照下面核），抬回退下限到准入上限（`raise_rollback_floor_to_the_admission_ceiling`，`mount.rs:4568`）直到被覆盖的旧落点按记录已释放，会话丢掉。
4. 几何核（不过就记「几何没造成」、改负载重造，不算修订判据，同 E185（GC一批搬迁的挂钟拆分） 的做法）：造数据挂载写的 P ÷ 32 段里至少 90% 的段活槽数恰好是 32；量挂载重挂之后 greedy 要选的那一段活槽数 ≤ 32 且里面未释放记录全是码 1 数据单元；打每段活槽数的直方图、全空段数、`mapped_units` 条数。改三次仍造不成的那一档停下交主 agent。

量挂载（每一次跑）：从起步镜像拷一份，按这一条臂的设置可写挂载（`mount_writable_with_background_compute_settings`），装上整理只供测试的开关：批大小 `ForcedForTests(4)`（几何敏感性那一点取 16，第八节），起跑 `ForcedToStartForTests`，其余照 `CompactionSwitches::PRODUCT`（同测试共用模块 `remounted_with_compaction_forced_to_start` 的写法）。节奏 `CompactionPacing`：定时兜底每 1 毫秒、写带宽不限。

前台那串用户改动：种子 0xE202，每次在第一个文件 [0, P) 里均匀取一个单元下标，`WriteAtOffset` 覆盖写那一个单元，内容由种子与这次改动的序号算出。交替跑 24 次，并发跑 256 次；两种模式、各条臂用同一串。

### 两种跑法

- **交替跑**（问题单第 1、2、4、5 行）：主线程起前台线程与 GC 线程，两条线程经通道交替：前台发一次用户改动、返回之后通知 GC 线程；GC 线程一次次调后台入口，直到某一次调用一次整理发布都没发（或交回不起跑），再通知前台发下一次。24 次用户改动做完、最后一轮 GC 调用返回，这次跑结束。调用方的钟是装置给的假钟，每次调用前进 1 毫秒（定时兜底每次都到点），`foreground_fsync` 恒答没有在等：两种模式发的每一版逐字节相同才可能，第五节「装置约束」照这一点核录制流。GC 调用期间前台线程阻塞在通道上。
- **并发跑**（问题单第 3 行）：前台线程照计划时刻发 256 次用户改动，计划时刻从开跑起每 50 毫秒一次（几何敏感性那一点 500 毫秒），发之前把「有 fsync 在等」置上，拿到会话锁、发布返回之后撤下；GC 线程循环：拿会话锁调一次后台入口（钟是真的单调钟，`foreground_fsync` 读那个标志），放锁，这次调用一次整理发布都没发就在条件变量上等下一次用户改动发成或 1 毫秒，前台做完就停。会话与两块盘放在一把锁里，前台与 GC 不同时动它们。

### 计时与计数怎么做（都在被测进程里计）

- 每次 GC 调用前后读 `Instant`、`CLOCK_PROCESS_CPUTIME_ID`、GC 线程的 `CLOCK_THREAD_CPUTIME_ID`，并读前台线程与主线程各自的线程 CPU 钟（`pthread_getcpuclockid`）；结果行由这个进程自己写，不在转发输出的循环里打时间戳（`.claude/singlefs-ai-sop/rules/test-discipline.md`「分段计时在被测进程里计」）。
- 调用返回之后（窗口外）读这次调用交回的整理记账：发了几次整理发布、几批、每批 `units_relocated_by_this_publish` 的条数、停在哪、每批 `BackgroundComputeOfOneBatch`（请求的后端、走的路、三段条目数、三段提交、分到活的卡）。
- 并发跑的每一次用户改动记三个时刻：计划时刻、拿到锁的时刻、发布返回的时刻；延迟 = 返回 − 计划，另报「锁里发布用了多久」= 返回 − 拿到锁。
- 内存盘的录制摘要与读文件内容摘要在窗口外做；录制摘要随写在窗口里做（每个改盘动作喂一次 SHA-256），这份开销两种模式一样多，照算进两边，另在内存盘里用线程 CPU 钟累计它、报出来（`name=recording_overhead`）。
- 包含自检：每次调用挂钟 ≥ GC 线程 CPU；进程口径 ≥ GC 线程口径；CPU 臂（与 CPU 多判臂）每次跑 GC 线程 CPU ÷ GC 挂钟 ≥ 0.9（内存盘上 CPU 模式整条路都在算，不等盘、不等卡）。不满足的那一次跑作废（第十一节）。
- 开跑自检：本线程的 CPU 钟 1 ms 里前进不到 100 次就停（第十一节）。
- 每次跑开头另记 `/proc/stat` 的全机忙时与本进程 CPU，跑完再记一次，算出这次跑期间本进程以外平均占了几个核（`name=host_load`）。

### 阳性对照（每条臂都跑）

每条臂各配一条多判臂，同一次重复里与它成对：

- **GPU 两条多判臂**（问题单第 5 行那一处「故意的多判」）：GPU 实现外面包一层（装置里的类型，实现 `BackgroundGpuCompute` 与 `GpuInventory`，每个方法原样转给产品那一份 `BackgroundGpuComputeOnTheParticipatingGpus`）。三段的方法交回之后，对每一条 `ConfirmedByBothKernels` 的条目在 GC 线程上照核心层的 CPU 写法再判一遍：校验和段 `crc32_castagnoli(单元字节)` 与 `expected_crc32c` 比；区域记录段对那一条记录调 `scan_region_over_the_identity_index`（映射条目照这一次交进来的那一份建按身份的索引，每次调用建一次，算在多判的活里）；活槽段每次调用对全部分配记录调一次 `live_slots_per_cluster_segment_by_the_records`，取每个确认段的那一个数。判定原样交回，不改。多判那段代码前后读线程 CPU 钟，累计成里层计时 E；另数 GPU 确认的结果与再判的结果对不上的条数。
- **CPU 多判臂**：CPU 模式下核心层不交出条目，装置在 GC 线程上、每次 GC 调用返回之后（仍在这次调用的计时窗口里，窗口包到它做完）对这次调用发出的每一批把三段的 CPU 写法各再跑一遍：R 取这一批的意图区域，映射取 `central_mapping_as_the_compaction_reads_it`（`mounted_session.rs:3513`）交 `scan_region_over_the_identity_index`，读单元的闭包从内存盘取，对扫描判成可搬的每个单元算整单元 CRC，再对每块盘的分配记录调一次 `live_slots_per_cluster_segment_by_the_records`。里层计时 E 同上。
- 判法（第六节量 P）：多判臂与不多判臂成对，进程口径之差 Δ 的 5 个数都 > 0，且 Δ 的中位落在 E 的中位的 [0.8, 1.25] 倍里；GPU 多判臂另要省下的（CPU 臂减 GPU 多判臂）5 对都比不多判的那一对少。不过的那一档整档作废（`.claude/singlefs-ai-sop/rules/test-discipline.md`「阳性对照：测不出差异时实现有问题，整轮作废」）。

| 量 S（省下的 CPU） | 同一档同一次重复：CPU 臂的 C 减 GPU 臂的 C，两条 GPU 臂各一组；报 5 个成对差、中位、最小、最大；另报 ÷ 批数 | 5 个都 > 0 判「省」，都 < 0 判「多占」，有正有负判「不稳定」 | 第 2 行「省下多少、正负、离散度」：每档两组 5 个成对差都有就够判；「省」与「多占」互为翻面 |
| 量 T（随容量的走向） | 每档 S 的每批值（S ÷ 批数）5 个数，按单元区从小到大三档 | 相邻两档：大档 5 个数的最小 > 小档 5 个数的最大记「升」，大档的最大 < 小档的最小记「落」，否则记「交叠」。两步都「升」判「涨」；都「落」判「降」；两步都「交叠」且顶档与最小档的中位之差的绝对值 ≤ 两者绝对值大者的 10% 判「平」；别的判「说不出」（不作废，登记加重复次数要主 agent 定） | 第 4 行：三档都有 S 才判；分类落在哪一格就是答案，「涨 / 平 / 降」任一格都够判，「说不出」不够判 |
| 量 P（阳性对照） | 每条臂与它的多判臂成对：Δ = 多判臂 C − 不多判臂 C（5 个）；E = 多判臂里层计时（5 个）；GPU 多判另算 S 多判 = CPU 臂 C − GPU 多判臂 C | 三条臂各自：Δ 5 个都 > 0，且 median(Δ) ∈ [0.8, 1.25] × median(E)；两条 GPU 臂另要 S 多判 < S 在 5 对里都成立 | 第 5 行：两条 GPU 臂在每一档都过就够判；不过的那一档整档作废（不算第 2、4 行的数） |
| 量 F（前台 fsync 延迟） | 并发跑每次跑 256 次用户改动的延迟（返回 − 计划时刻）；每档每臂 5 次跑合起来 1280 个数的中位、p99、最大，另报每次跑各自的中位与 p99（看离散度）；另报锁里发布用了多久的同样三个数 | 只报分布，两种模式各一份；另报 GPU 臂减 CPU 臂的 p99 与最大（5 次跑成对），5 个同号记方向，有正有负记「不稳定」 | 第 3 行：每档 CPU 臂与 GPU 点名一张卡臂各有一份 1280 个数的分布就够判 |
| 量 F 底（附带） | 「不跑 GC」臂的同一份延迟分布 | 只报 | 附带，够判后不跑 |
| 量 K（卡上的活） | 每批三段的 `devices_given_work`、交成的提交数、片数、重交、重切 | 照第七节甲类锚点判 | 前提（「装置要求」第一条：按卡的顺序填满），不翻问题单哪一行 |
| 量 H（机器负载，附带） | 每次跑期间本进程以外平均占的核数 | 照第十一节作废条款判 | 附带 |
| 量 B（造池，附带） | 每档造起步镜像的挂钟与发布次数（顶档约 98304 次发布） | 只报，核第十四节的估计 | 附带 |

门槛与臂的定义并排放：臂的定义只说「若三段的 CPU 大于提交开销就省」，推不出 S 的正负，也推不出 T 落在哪一格；阳性对照的 [0.8, 1.25] 是测量包不包得住里层计时，与哪条臂赢无关；10% 是「平」的宽度，与臂无关。

|---|---|
| 每块盘单元区槽数与整段数 | 1040 MiB：16384 槽、256 段；1808 MiB：65536 槽、1024 段；4880 MiB：262144 槽、4096 段；66320 MiB：4194304 槽、65536 段（式子：每块盘字节 ÷ 16384 − 50176，再 ÷ 64） |

## 八、轨迹与几何敏感性

### 轨迹（被谓词消费的量）

| 量 | 哪个谓词消费它 | 报什么 |
|---|---|---|
| 每块盘的全空聚簇段数 | 签下一条的全局差值（`the_completed_intent_yielded`） | 每条意图签发与完成时各一个读数；峰值、全局差值为真的意图条数（为正的轮数）、期末值 |
| 上一次用户改动给的预算还剩几次 | 后台入口起不起跑（`publishes_left_of_the_budget_given_by_the_last_user_change`） | 每次 GC 调用前后；峰值、剩余 > 0 的调用次数、期末值 |
| 每批三段的不确定条目数 | 连续 2 轮不确定交 CPU 判（第 8 条） | 每批；峰值、> 0 的批数、期末值（健康的卡上预期全 0） |
| 前台「在等」标志被答成「在等」的次数 | 节奏让路（第 6 条） | 每次并发跑；峰值（一次调用里）、答成「在等」的调用次数、期末值 |

只报期末值的量，实验页不写「从来」「恒」这类说轨迹的词。

### 几何敏感性（每个带跑前判决的量至少一个方向相反的取样点）

| 判决 | 主取样点 | 方向相反的取样点 | 为什么方向相反 |
|---|---|---|---|
| 量 S 的正负（与量 W 的正负） | 批大小 4 个单元 | 批大小 16 个单元（一条意图一批），中档、CPU 臂与 GPU 点名一张卡臂各 5 次交替跑 | 每批的 GPU 提交开销是按批付的固定价，批大 4 倍摊薄它：GPU 臂相对 CPU 臂的位置往相反方向挪 |
| 量 F 的方向 | 前台间隔 50 毫秒（前台跟不上、整理批常挡在前面） | 前台间隔 500 毫秒（中档，三条臂各 5 次） | 间隔大于一批的挂钟时整理批多半在两次 fsync 之间做完，挡不住前台 |
| 量 T 的分类 | 主 agent 留下的那一种读法 | 另一种读法（若主 agent 两种都留） | 一种只涨段数，一种段数与数据量一起涨 |

翻面就记「不稳定」，不翻就记两点。没扫的旋钮：段内活槽占比（取 0.5）、一次跑的用户改动次数（取 24）、等 GPU 的上限（取默认 10 秒）。实验页的结论只说「在这几个取样点上」，不写「这是两种模式的性质」。判别力自证：把量 S 的判定门槛从 0 挪到两个取样点的中位之间，主取样点与相反取样点必须一绿一红（装置自证里用两组合成的数做）。

## 十一、作废条款与停机条款

### 作废

1. 读任何一个钟交回出错，或读出的增量是负的：那一次跑作废，重跑一次（`.claude/singlefs-ai-sop/rules/test-discipline.md`「读不到 ≠ 读到 0」）。
2. 包含自检（第五节）任一条不成立：那一次跑作废，重跑一次。
3. 量 H > 16 个核（这次跑期间本进程以外平均占的）：那一次重复（六条臂或三条臂整组）作废，同一档重排一次；一档里作废的重复多于 2 次，那一档交主 agent，不自己放宽。
4. GPU 臂一次跑里出现 `compute_error_that_abandoned_the_batch`（卡出错、等超过上限）：那一次重复作废，错照原样写进产物；同一档累计 3 次，停下交主 agent。
5. 阳性对照（量 P）不过：那一档整档作废。
6. 乙类锚点不符：那一档作废，交主 agent（多半是登记的算式错了，主 agent 在产物之前修订，第十二节）。
7. 开卡线程在第一次 GC 调用时还在跑：那一次跑作废，重跑一次。
8. 要卡的子命令看不到独显：那一条臂报本次未跑（`name=not_run`），不作废别的臂；全部卡臂只看得到一张时同样报本次未跑。

### 停机（装置与 `crates/` 实现对不上：两边都查，既不作废也不当结果，`.claude/rules/implementation-first.md` 第 4 条）

1. 第五节常量回比任一项不等。
2. `name=crates_version` 的 sha256 在同一段的几条命令之间变了（`crates/` 中途被改）。
3. 第三节点名的入口在装置写的那一版里不在或签名变了（第 66 批改名之外的）。
4. 第七节甲类任一条不成立，或第十条前四条触发。
5. 前提 I 不过（录制流或内容摘要不同、多判对不上的条数 > 0）。
6. 几何核改三次仍造不成。

停机时产物照打、退 3，交主 agent。

### 够判停机

问题单五行每一行都够判就停：第一段交回后第 1、2、4、5 行够判就不再为它们跑；第二段交回后第 3 行够判就不跑第三段，第三段的几何敏感性两行标「够判后未跑」，交主 agent 判要不要补（`mutation-sampling.md` 第六类要求的那一点不补时，实验页照写「判决只在一个批大小与一个前台间隔上量过」）。没跑的量逐条标「够判后未跑」。

## 十二、修订

独立单位：造起步镜像按档互相独立（几何核那一条命令里各档各一条线程、各建各的池）；计时的单位是（档、臂、重复），同一档的六条臂在同一次重复里按轮换次序串着跑（第 r 次重复从第 r 条臂起轮换），档与档之间分成各自一条命令。
线程：造池并行时线程数取登记值 `.claude/heavy-thread-default`（31），实际只用到档数那么多条（几何核至多 5 条）；计时的跑只有主线程、前台线程、GC 线程三条，装置不另设线程数。
串行：计时的跑全部串行——两条臂同时跑会互相抢 CPU、内存带宽与卡，进程口径的 CPU 与挂钟都会被对方污染，所以同一时刻只跑一次；同一次重复里的六条臂串着、按轮换次序，让机器状态的慢漂移平摊到各臂；造池在计时之前做完，不与计时重叠。
预计挂钟：第一段顶档 30 次 × 144 批 × 0.98 s ≈ 4234 s；中档 30 次 × 144 批 × 0.25 s ≈ 1080 s；最小档 30 次 × 144 批 × 0.06 s ≈ 259 s；造池顶档 98304 次发布 × 2 ms ≈ 197 s；第二段顶档 10 次 × 256 次 × 0.98 s ≈ 2509 s；中档 10 次 × 256 次 × 0.25 s ≈ 640 s；最小档 10 次 × 256 次 × 0.06 s ≈ 154 s；第三段前台间隔 500 毫秒那一点 15 次 × 256 次 × 0.5 s ≈ 1920 s；批大小 16 那一点 10 次 × 144 批 × 0.25 s ÷ 4 ≈ 90 s（依据：一批约 15 µs × P，推自 `.claude/kb/milestone/04-fourth-txn.md:147` 的 62.38 ms ÷ 4096，P 取各档数据量；批数推自第四节；一次发布 2 ms 是推的；另加每次跑挂载与开卡约 10 s，推的；几何核量出真数后，顶档超过这里两倍就停下交主 agent，第一节未定项 6）。
预计在用核数：计时的跑约 2 个核（GC 线程 1 个，驱动线程推的不到 1 个，交替跑里前台线程阻塞着），并发跑约 3 个（前台线程多 1 个）；几何核造池约 5 个（各档一条线程）。

超过 2 小时的段（第一段合计约 1.7 小时、第二段约 0.9 小时，都是推的；按最坏两倍算会超过）照 `.claude/rules/test-script-discipline.md`「用上现有的硬件加速」「判定可复用：按输入存，按前缀剪」写明两样：
- 分片单元：（读法、档）一条命令一份产物（`research/results/e202-gpu-cpu-gc-comparison-<日期>/lockstep-<读法>-<单元区>.out`、`concurrent-<读法>-<单元区>.out`），顶档一条命令预计约 1.2 小时。计时的跑不在一条命令里再拆到几台机器上：成对相减要两条臂在同一台、同一组卡上跑。
- 续跑入口：同一条命令重起，装置读那份产物里已有的 `name=repeat_done` 行，跳过做完的重复，只补没做完的；没做完的那一次重复整组重跑（一次重复里六条臂成对，不拼半组）；起步镜像每次重起都现造（不存镜像，造池顶档约 197 s，推的）。文件头写 `// task-server-resumable: lockstep concurrent sensitivity`。判定库那一层做不到：计时是新观测，不复用（第一节未定项 4）。

起法（仓根起，`--cwd` 写仓根；`cargo run` 不要范围声明；要卡的带 `--features tests-on-a-real-gpu` 让服务认出要卡与清场）：

```
task-server/task submit -- cargo run --release -p singlefs-background-gpu --bin e202_gpu_cpu_gc_comparison -- geometry-check --product research/results/e202-gpu-cpu-gc-comparison-<日期>/geometry.out
task-server/task submit -- cargo run --release -p singlefs-background-gpu --features tests-on-a-real-gpu --bin e202_gpu_cpu_gc_comparison -- lockstep --reading <occupancy|data> --unit-area <256MiB|1GiB|4GiB|64GiB> --product research/results/e202-gpu-cpu-gc-comparison-<日期>/lockstep-<读法>-<单元区>.out
task-server/task submit -- cargo run --release -p singlefs-background-gpu --features tests-on-a-real-gpu --bin e202_gpu_cpu_gc_comparison -- concurrent --reading <occupancy|data> --unit-area <…> --foreground-interval-milliseconds 50 --product research/results/e202-gpu-cpu-gc-comparison-<日期>/concurrent-<读法>-<单元区>.out
task-server/task submit -- cargo run --release -p singlefs-background-gpu --features tests-on-a-real-gpu --bin e202_gpu_cpu_gc_comparison -- sensitivity --batch-units 16 --foreground-interval-milliseconds 500 --product research/results/e202-gpu-cpu-gc-comparison-<日期>/sensitivity.out
```

产物是标准输出与 `--product` 那份文件上同样的结果行（`E202 name=<种类> 键=值 …`），末行 `name=done emitted=<行数>`；进度打到标准错误。退出码：0 正常；2 命令行不对；3 停机条款触发；4 阳性对照没过（产物照打）；77 一条臂都没跑到（看不到独显）；78 准入或运行条件不满足。
