## 攻击面 1：作废行（P1 失败表 ③ × P2 的 kind 2）

第五版逐字：「事务级失败（准入中途拒绝、超过重试上界之外的可恢复错误）⇒ **写一条作废行 (i, n)**
（P2 实例表 kind 2）与这个 checkpoint 同一次发布，该事务的单元由此判未发布」；
P2 逐字：「事务级失败：作废行 (i, n) 与这个 checkpoint 同一次发布」、
「任何非干净结束的实例在下次恢复写行：给 [所选根的实例, 新实例) 每个实例写 (i, 在飞 txg, 重放施加的最大事务号)」；
谓词逐字：「(i, n) 有作废行 ⇒ 未发布；i < i_now：无 kind 0 行 ⇒ 已发布；有行 (i, T, W) ⇒ b ≤ T ∧ n ≤ W」。

### 1.1 作废行和它要证伪的那批孤儿同生共死；恢复行只写得出前缀，写不出洞（可达，本轮最重）

**若「该事务的单元由此判未发布」在崩溃之后仍然成立，作废行的持久化就不能挂在造出孤儿的那次发布上。** 它恰好挂在那上面。

**可达历史**（实例 i = 7，checkpoint T = 500，事务号按实例计数）：

1. 实例 7 把事务 812、813、…、820 分配进 checkpoint 500，各自取号并钉死诞生代号 500。
2. 事务 812 已经向设备发出单元写请求（走的是失败表 ③ 那一支），随后撞上准入中途拒绝——
   E82（准入的在飞合成）实测的准入类失败形态逐字就是「分配中途才失败」。
   按第五版处置：写作废行 (7, 812)，排队等 checkpoint 500 发布。**它的单元此刻已经在盘上，头完好。**
3. 事务 813–820 正常写完、记录按事务号顺序追加进 journal，jsn 连续。
   D13（验证路线）已定项 2 的第一版串行提交并不挡这一步：串行只保证顺序，不保证 812 失败之后 813 不许接着做。
4. checkpoint 500 发布之前掉电。作废行 (7, 812) 从来没落盘。
5. 实例 8 恢复：按 D23（journal 的角色与格式）已定项 14 重放 jsn 连续前缀，施加到事务 820；
   按 P2 写行 **(7, 500, 820)**。
6. 索引在某次后续故障里丢了，走扫描重建。事务 812 的孤儿单元：b = 500 ≤ 500 ✓，n = 812 ≤ 820 ✓，
   作废行不存在 ⇒ **判已发布**；它又是那个 key 上写序最大的候选 ⇒ v\* 选中它 ⇒ **复活**。

这正是靶子第 (c) 类，也是第四轮 2.3 打开、第五版声称已经关上的那个口子。
第五版把 ② 的分界改成「尚未向设备发出任何单元写请求」是对的、可判定的；
**问题不在分界，在分界另一侧的那条兜底**：③ 的兜底是一条与崩溃同一次发布的行，
而 (i, T, W) 这个三元组的结构只表达得了**前缀**（n ≤ W），表达不了「812 作废但 820 已施加」这个**洞**。
洞是 ③ 自己造出来的，唯一能表达它的容器（kind 2 作废行）却和洞一起丢。

**能关上它的最小改法**：作废的持久形态从「实例表的行」换成 **journal 里的一条记录**，按事务号顺序追加。
这样它和 813–820 的记录共享同一条 jsn 连续性：只要 820 被重放到，812 的作废记录必然也被重放到
（它在链上更靠前），恢复就写得出 kind 2 行。
第五版第五节的「被否形态」里点过「中止写空记录」，那条否决要重开——
否掉它的理由是「不存在中止写空记录」，而第五版自己新造了一个中止事件。
退一步的改法：把恢复行的 W 定义成**最大的前缀水位**（≤ W 的事务全部已施加），
代价是洞之上那批已施加事务被判未发布，错的方向从复活变成丢失。**两条都要显式选一边。**

### 1.2 发布本身失败时，同一条历史更短，而且不需要掉电（可达）

第五版逐字：「不可恢复的失败（全部副本失败、内部不变量破）⇒ 实例结束，转只读，下次挂载走恢复并写行。」

把 1.1 的第 4 步换成：checkpoint 500 发布过程中根槽全部副本写失败 ⇒ 实例 7 结束、转只读。
作废行 (7, 812) 与根同一次发布，一起没落盘。下次挂载走恢复，写 (7, 500, 820)，第 6 步原样成立。
⇒ **「实例结束」这条终态自己就是作废行的杀手**，不需要任何外部事件。

### 1.3 实例表不可读时，第五版说「可写」，而那一格恰恰写不出作废行（可达，说法与机制对不上）

第五版逐字：「**表不可读时**：① 正常挂载不受影响、**可写**，但记持久标记『实例表曾不可读』」。
同一节逐字：「COW 重写：**每次写行重写整条链**」。

链上的片读不出来，就重写不出整条链 ⇒ **这次挂载一条 kind 2 行也写不出来**。
于是失败表 ③ 的事务级失败在这一整段挂载期内没有任何持久表达，
它造出的孤儿在下次扫描重建里按 1.1 那条路径全部判已发布。
第五版给「表不可读」写的后果只有「对那些实例里『诞生代号 == 某次重发代号』的多版只能记歧义」，
**这一格比那句重**：它不是记歧义，是判成已发布。

**最小改法**：表不可读时禁止可写挂载（与 P2 第二句「扫描重建时读不到实例表 ⇒ 停在级 1」同一取向），
或者明写「表不可读期间事务级失败一律升级成实例结束」。

### 1.4 事务级失败把实例表整链重写塞进发布的关键路径，代价表里没有这一行（可达，代价漏记）

P2 逐字：「COW 重写：每次写行重写整条链，代价 n × 32 KiB × w」。
一次事务级失败 ⇒ 一条 kind 2 行 ⇒ 一次整链重写，**而它与这个 checkpoint 同一次发布**。
E82（准入的在飞合成）实测准入类失败是「分配中途」，盘接近满时这类失败按 D25（目标负载优先级）的负载是常态而非边角；
D16（发布语义）已定项 6 的骑手条款 3 又说 fsync 密集负载下发布节奏 = fsync 节奏。
⇒ **接近满盘时，每次准入失败给发布关键路径加一次 n × 32 KiB × w 的写**。
第五版第四节那张代价表里 D22（单元原子性怎么合成）已定项 7 与 D18（块里携带什么信息）已定项 11 两行都在，
**这条运行时代价一个字都没有**。

## 攻击面 2：事务切分纪律（P1 取号纪律 2，第五版全新）

第五版逐字：「**事务切分纪律**：一次写请求按单元切成若干事务各自取号（W1 不受影响，它们碰的 key 不同）
⇒ 一个事务最多写一个单元的用户数据，切分延迟 ≤ 一个单元的写延迟。」

### 2.1 「它们碰的 key 不同」为假：同一次写请求的每个子事务都要碰同一条 inode 记录（可达）

**若这半句成立，一次写请求的各个子事务之间应当没有共享的逻辑 key。** 有一条，而且是必经的：
D8（核心索引结构）已定项 6 逐字把 inode 树的叶定成码 3 打包记录单元（记录宽 140），
一次写请求要改的 size / mtime 就住在那条记录里。
切成 32 个子事务之后，**32 个事务在同一个 checkpoint 里改同一个逻辑 key**。

后果有两层：

1. 第五版 P1 逐字「同 key 已发布版本定序（诞生代号 + W1 够——`no_wseq` 臂只在同 txg 跨事务改同 key 时歧义）」——
   切分纪律把那个「只在」从边角变成**每一次跨单元写请求都发生**。
   第五版同一段还写着「第三格的发生频率未测」，**而第一格的频率刚被这条新纪律抬成 ⌈写请求字节数 / 单元大小⌉**，也没测。
2. 第五版 P1 那句括号里的理由按字面为假，得改写。它现在承担的是「切分不破 W1」这个论证，而论证的依据不成立。

### 2.2 固定点写出的节点与容器，写序取哪个事务的号，第五版没写；E104（扫描重建的现行版本判定） 也看不见这一格（可达，本攻击面最重）

**若「写序 = 写出它的那个事务的 (实例代号, 事务号)」对全部三类单元都成立，那么每个单元都得由恰好一个事务写出。**
元数据单元不是这样：D3（空间分配）已定项 5 逐字给的模型是「假设发布末尾一次性 COW」，
E81（提交的固定点）量的固定点收敛也是**一个 checkpoint 收敛一次**——
一个 checkpoint 里被 32 个子事务碰过的那条 inode 记录，它所在的容器在固定点只写**一次**。

于是问：那一份码 3 容器的写序写谁的号？三种写法各有一个当场可达的坏结局：

| 写法 | 坏结局 |
|---|---|
| 取本 checkpoint 内碰过它的最大事务号 | 崩溃后只重放到中间某个事务时，该容器按 P2 谓词判未发布（n > W），**整个容器退回上一版**，而它已经合并进去的低号事务的效果一并丢——这些效果的数据单元却因 n ≤ W 判已发布，重建产物自相矛盾 |
| 取最小 | 容器判已发布，而它装着尚未施加的高号事务的记录 ⇒ **未提交内容被判成现行** |
| 每个子事务各写一份容器 | 一次跨 32 单元的写请求变成 32 次「32 KiB 容器 + 全部祖先」的 COW，按 E105（extent 叶改码 3 的代价）的算术是单次更新代价的 32 倍 |

第五版 P1 逐字只说「每个单元的类身份段加 10 字节写序 = 写出它的那个事务的 (实例代号, 事务号)」，
**一个字都没有交代多事务合写一个单元时取谁**；而切分纪律把这一格从罕见抬成必然。

**E104（扫描重建的现行版本判定）证不了这一格**：现查 `research/e7-index-bench/src/bin/e104_current_version.rs:339-353`，
`write_unit` 在 `txn` 内部被调用、写序恒取当前事务的计数器，
**模型里不存在「一个单元由多个事务合写」这种状态**。E104（扫描重建的现行版本判定） 正文「它答不了的」列了七八项，没有这一项。
⇒ P8 那句「全规则臂 24 个种子全 0」对切分纪律带来的这一格零证据。

**最小改法**：给码 2 / 3 的写序写一条独立定义（例如「= 写出它的那次发布里，它合并进去的最大事务号」），
并把随之而来的「容器判未发布时低号事务的效果怎么办」写进 P3；
再给 E104（扫描重建的现行版本判定） 加一条「一个容器由同 checkpoint 的多个事务合写」的世界。

### 2.3 上界口径「T_time + 一个单元的写延迟」与同一段里的重试上界互相矛盾（可达）

第五版逐字：「**D16（发布语义）已定项 5 的上界口径由此改写**：崩溃最多丢的是 T_time + 一个单元的写延迟」；
同一节失败表 ③ 逐字：「单副本写失败 ⇒ 换落点重试、写序不变，**重试有次数上界**」；
纪律 1 逐字：「发布阶段等全部单元落盘」。

重试上界是**次数**，不是墙钟。一次介质超时的时长不由次数定。
⇒ 发布要等的是 `(重试次数上界 + 1) × 单元写延迟 + 介质超时 × 重试次数上界`，
而「一个单元的写延迟」这个说法把后两项都吞掉了。
第四轮 1.3 要的是「给重试一个墙钟上界，或者让切分不等 I/O，显式选一边」；
第五版选了「切分不等 I/O、发布阶段等」——**这只是把等待从切分挪到发布，没有给等待封顶**，
而要交给用户复核的正是那个封顶值。

**最小改法**：把口径写成 `T_time + 单元写延迟 × (重试上界 + 1) + 介质超时预算`，
或者给重试加墙钟上界并把它写成一个具名参数；两者都要在送用户复核的那句话里出现。

### 2.4 一次写请求的崩溃原子性被切细了，而这个语义变更没有落点（可达，语义变更漏记）

D23（journal 的角色与格式）已定项 14 的恢复义务逐字：「**丢掉提交标记还没出现的那个事务的全部记录**」——
事务是崩溃原子性的单位。切分之后，一次写请求的崩溃原子性从「整次写请求」降到「一个单元」：
崩溃可以留下前 k 个单元已发布、后面的没有。
仓里没有任何一条决策承诺过写请求级原子性，所以**这不是破了哪一条**；
但它是一次对外可见语义的收缩，第五版第四节的代价表里没有它，
D23（journal 的角色与格式）已定项 7 / 14 那两行也没被点名。

## 攻击面 3：根记录的「最大已施加事务号」（P2，第五版全新的 8 字节）

第五版逐字：「根记录加两样：实例表单元指针 59、**最大已施加事务号 8**
（这个根发布时该实例最后一条被施加记录的事务号；回退行的 W 取它）：127 → 194，512 槽余 318。」

### 3.1 恢复后的第一个根，「被施加的记录」属于上一个实例，而这个字段没有实例维（可达）

**若「该实例最后一条被施加记录的事务号」是一个良定义的量，那么被施加的记录与发布这个根的实例必须是同一个实例。**
恢复那次不是：实例 8 发布的第一个根，它施加的记录**全部属于实例 7**，事务号是实例 7 计数器上的值。
而 P1 逐字「事务号是……按实例计数、从 1 起」——两个实例的事务号在同一个值域上各数各的。

于是这个 8 字节字段在恢复后的第一个根里存的是**实例 7 的 812**，而字段本身不带实例代号。
再往后：实例 8 在同一个 checkpoint 里既施加重放来的实例 7 记录，又施加自己的事务 1..k，
「最后一条被施加记录」到底取谁，第五版没有答案。
回退行取它时按 P3 逐字配上的是 `r_old`，即**发布这个根的实例**——
于是一个属于实例 7 的号被写成实例 8 的上限。

**可达后果**：管理员回退到「实例 8 恢复后发布的第一个根」R_f（txg = 501），
回退行写成 (8, 501, 812)。实例 8 后来写过 900 个事务，其中 1..812 号那批的诞生代号若落在 501
（同一个 checkpoint 里既有重放又有新事务，就会落在 501）⇒ b ≤ 501 ∧ n ≤ 812 ⇒ **全部判已发布**，
而它们正是回退要抛弃的那批。

**最小改法**：字段改成 (实例代号 4 + 事务号 8) = 12 字节（根记录 194 → 198，512 槽余 314），
或者明写「只记发布该根的实例自己的事务号；重放施加的旧实例记录不计入，旧实例的上限从它自己的行取」。

### 3.2 回退行的 W 换成真值之后，第四轮 2.4 的洞还在，只是换了个填法（可达，与 1.1 同源）

第四轮 2.4 打的是 `W = ∞` 关掉了事务号维。第五版把它换成真值，方向对。
但真值同样是一个**上限**：它表达不了「812 作废、820 已施加」这个洞——
洞在回退这一支上一样存在（回退到 T_old 时，实例 r_old 在 T_old 那个 checkpoint 里作废过的事务号照样 ≤ W_old）。
⇒ 第五版对第四轮 2.4 的处置**关上了 ∞ 那一半，没关上洞那一半**，而洞是第五版自己新造的 ③ 带来的。

## 攻击面 4：回退候选集（P3，第五版对第四轮 7.4 的处置）

第五版逐字：「候选集 = 根环里按实例表判仍然有效的根：(i, T) 可选 ⟺ 实例表无 i 的行，
或有行 (i, Ti, Wi) 且 T ≤ Ti（**被抛弃时间线的根一条都选不中**）」；
P2 逐字：「**回收**：kind 0 行可删当且仅当清扫确认盘上不再有该实例超出上限的可读单元，且全部设备在线」。

### 4.1 (i, 0, 0) 行被回收之后，被抛弃的根整批回到候选集（可达，本轮第二重；第四轮 7.4 原样复活）

**若「被抛弃时间线的根一条都选不中」是一条恒成立的性质，那么把它撑起来的那些行就不能被删。** 它们恰好可以被删。

**可达历史**：

1. 实例 7 发布根 R500（txg 500）。实例 7 崩，实例 8 恢复，发布 R501、R502、R503。
2. 管理员回退到 R500：按 P2 写 (7, 500, W500) 与中间实例的 **(8, 0, 0)**；取新实例 9；
   第一个新根 R504（txg = 环里最大 503 + 1）。R501–R503 **仍在根环里**（回退不删槽，
   回退深度 ≤ 根环深度是第五版自己的射程句），自证校验和照旧通过。
3. 此时候选判据把 R501–R503 挡住：行 (8, 0, 0)，501 ≤ 0 为假。**到这一步第五版是对的。**
4. 实例 9 挂着但基本空闲（回退之后先跑一轮清扫再决定要不要继续，是管理员的常规动作）。
   清扫按 P4 的孤儿分支把实例 8 独占的落点抹头：写序实例 8 < 9 ✓，按 (8, 0, 0) 判未发布 ✓ ⇒ 清。
5. 整轮清扫完成（第三版给的量是 16 TiB 盘约 2.3 小时），「盘上不再有实例 8 超出上限的可读单元」成立、
   全部设备在线 ⇒ 按 P2 的回收条款**删掉行 (8, 0, 0)**。
6. 池空闲 ⇒ 没有新发布 ⇒ 根环没有轮转，R501–R503 还在环里。
7. 管理员做第二次回退。候选判据这次读到的是「实例表无 8 的行」⇒ **R501–R503 全部回到候选集**。

## 攻击面 5：分配记录不点删（P4，第五版对第四轮 5.1 / 5.2 的处置）

第五版逐字：「D3（空间分配）已定项 7 的分配记录条目在落点释放时**不删**，改写成『已释放 + 释放代』……
**条目留到该落点被重新分配时覆盖**」；
「**准入（合取，全部来自运行时结构）**：条目标已释放 ∧ 释放代 ≤ 环里最旧根的 checkpoint_txg ∧ 头可读；
孤儿（没有条目、也不在分配器在飞 overlay 里）：写序所属实例 < 当前实例 ∧ 按 P2 谓词未发布 ⇒ 清；
当前实例的单元一律不碰。**清扫水位只推进到「环里最旧根的 txg」。**」

### 5.1 「释放」的口径没写，而快照不在根环里，水位那道闸对它零保护（可达）

**若「清扫水位只推进到环里最旧根的 txg」是清扫不误伤活数据的理由，那么全部还引用旧块的根都得在根环里。** 快照不在。
P3 自己逐字把根集写成「树表里的可写头 ∪ **快照列表**」——快照是一份独立的表，不是根环的槽。

**可达历史**：

1. txg 80 建快照 S。
2. txg 90 可写头 COW 覆写落点 L 上的单元。按第五版逐字「分配记录条目在落点释放时……改写成『已释放 + 释放代』」，
   L 的条目变成（已释放，释放代 90）。
3. 时间推到 txg 148，环深 K 让环里最旧根是 txg 101。
4. 清扫扫到 L：条目标已释放 ✓、释放代 90 ≤ 101 ✓、头可读 ✓ ⇒ 三条合取全真 ⇒ **抹头**。
   「当前实例的单元一律不碰」救不了它：L 上那个单元是 txg 90 之前写的，写序所属实例可以早于当前实例。
5. 快照 S 仍然引用 L ⇒ 从 S 读那个 key ⇒ 头没了。

真正挡得住的是 deadlist（被快照引用的块不进空闲集、也就不该标已释放），
**而第五版 P4 从头到尾一个 deadlist 都没提**，反倒把「环里最旧根的 txg」写成清扫的射程理由。
⇒ 判定：按逐字可达；若实现意图是「被快照引用的落点不算释放」，那也要在 P4 里写死这一句——
现在写下来的那条理由结构上覆盖不到快照。

**最小改法**：把准入第一条改成「条目标已释放 **且不在任何快照的 deadlist 里**」，
并把清扫水位那句改成「min(环里最旧根的 txg, 最旧快照的 txg)」。

### 5.2 「当前实例的单元一律不碰」的射程只挂在孤儿那一支，而第五版恰好把一类落点挪进了另一支（说法问题，但要钉死）

第四轮 5.2 打的是「释放代寿命 17 毫秒、清扫周期 2.3 小时，差六个数量级」。
第五版改成不点删，寿命问题关上了，**同时把同一条线越到了另一侧**：
现在每一个曾被释放过的落点都**永久**带着一条「已释放 + 旧释放代」的条目，
从条目那一支看去，它永远满足前两条合取。
挡住误伤的只剩「头可读」与那句「当前实例的单元一律不碰」，
而后者按排版只跟在孤儿那一支后面；「不在分配器在飞 overlay 里」这道闸更是明写只在孤儿那一支。
⇒ 一个刚被当前 checkpoint 重新分配、单元已写、条目还没被发布覆盖的落点，
按条目那一支的三条合取逐字全真。
**最小改法**：把「不在在飞 overlay 里」与「写序所属实例 < 当前实例」提成两支共有的合取项，一句话的事。

### 5.3 E74（分配记录的条目数与整理开销） 的绝对值断言在新口径下是必然为假，不是「重跑看看」（可达，推翻条件写虚了）

第五版第五节末逐字把「E74（分配记录的条目数与整理开销）/ E97（记账与分配记录的条目编码）
重跑后分配记录的条目数越过它们自己的判据」列成推翻第五版的三个现象之一。
而 E74（分配记录的条目数与整理开销）判据 1 逐字是「**绝对值断言**：条目数必须**恰好等于已分配落点数**」，
第五版逐字又把口径改成「条目数上界由此从『已分配落点数』变成『**曾分配过的落点数**』」。
⇒ 这条断言在新口径下**按定义为假**，不需要跑。
把一个已知结论写成待观测的推翻条件，等于给第五版留了一条永远不会触发的自检。
**最小改法**：在代价表里直接写「E74（分配记录的条目数与整理开销） 判据 1 的绝对值断言改写成『条目数 == 曾分配过的落点数』，重跑取新的绝对值」，
把它从推翻条件里拿掉。

## 攻击面 6：第五节的判决（第五版整段重写）

第五版逐字：「**判决：取臂 A（写序上全部三类）。** 两条腿都是量出来的：
① 臂 B 让 extent 叶丢失时的数据重建退回 C113（扫描重建时多版单元的现行版本判定无输入）定案前的处境（数据孤儿无判据），臂 A 不会；

### 6.1 `wseq_meta_only` 不是臂 B，是「extent 叶恒丢」的臂 B——实验自己写了这句，判决没带上（可达，本攻击面最重）

**若 `wseq_meta_only` 是臂 B 的模型，模型里就该有 extent 树这条到达路径。** 没有。
现查 `research/e7-index-bench/src/bin/e104_current_version.rs:51-54`，`Key` 只有两支
（`Key::Data` 与 `Key::Cont`），`rebuild_root` 对数据单元一律走「扫盘 → 按 key 归并 → 择最大者」；
`:884` 逐字 `if arm.meta_only && matches!(u.key, Key::Data { .. }) { return u.birth <= cur_txg; }`
——臂 B 的数据单元被塞进**按 key 择版本**这条路，而臂 B 的定义逐字是
「数据 extent **顺着重建出来的 extent 树到达**」、第四版那一栏更逐字写着「**从不按 key 择版本**」。

`.claude/kb/experiments/104-扫描重建的现行版本判定.md` 自己已经写下了这句：

**它量的是 extent 叶丢失时数据单元靠自己的头能不能判，不是完整的臂 B**」。

⇒ 那组数（crash 6、crash_double 7、crash_clean 6、rollback 3、rollback_after_crash 6）

本身就是「臂 B 的水位机制被整条摘掉」的签名，而不是臂 B 的常态。

### 6.2 判决理由 ① 就是第四轮被撤的 ②，而处置表把「② 塌进 ①」记成「采纳」（可达）

第四轮 6.4 的结论逐字：「② 塌进 ①……叶双毁与数据单元双毁的影响期望**同量级**」，
第五版第一节处置表对应那一行逐字写着「② 塌进 ①……**采纳，量了再判**」。
而第五版量完之后给出的 ① 逐字是「臂 B 让 **extent 叶丢失时**的数据重建退回定案前的处境」——
**这就是 ②**，只是把「叶两副本都毁」换成了「叶丢失」。
第四轮 6.4 给的量级算术（叶数 ≈ 数据单元数 / 叶容量，受影响 extent 的期望 = 数据单元数 × p，

### 6.3 叶没丢时臂 B 的表现，E104（扫描重建的现行版本判定） 里没有任何一条臂能显示（可达，判据缺一半）

⇒ 判决的第一条腿实际形状是：「以概率 p（叶双毁）臂 B 退化，以概率 1 − p 两臂相同」，

### 6.4 「1.25–1.78×」是取样出来的：同一份输出里就有 1.000，解析上单次更新的下确界也是 1.000（可达）

**若「每次更新贵 1.25–1.78×」是 E105（extent 叶改码 3 的代价）的结论，那份输出里就不该有低于 1.25 的格。** 有，而且不止一格：

| 输出行（`research/results/e105-extent-leaf-packed-2026-09-05.out`） | b_over_a |
|---|---|
| `rec=wide n=10000 hdr=68 k=100` | **1.141** |
| `rec=wide n=10000 hdr=68 k=1000` | **1.000** |
| `rec=narrow n=10000 hdr=68 k=100` | **1.041** |
| `rec=narrow n=10000 hdr=68 k=1000` | **1.000** |

第五版第五节逐字只报了「批量 **1e6 上** 1.44×（k = 10）到 1.78×（k = 1000）」，
把 1e4 那一档的批量行整列略过；判决那一句更把限定去掉，写成「每次更新贵 1.25–1.78×」。
⇒ 判决引的区间不是量出来的区间，是**挑过的**区间。饱和处两侧字节数相等有结构性原因：
单元 32 KiB 恰是节点 16 KiB 的两倍、每容器记录数恰是叶扇出的两倍，全碰到时两侧的叶层字节完全相同。

更硬的一格是**单次更新**。按 E105（extent 叶改码 3 的代价） 自己的算术复算（判据 1 的口径不变，只把 N 扫成连续值）：

单次更新 b/a = (h_B + 1) / h_A，h_A = 码 2 叶形态树高、h_B = 码 3 叶形态树高
h_B = h_A     ⇒ 1 + 1/h_A（这就是取样点上的 1.5 / 1.333 / 1.25）
h_B = h_A − 1 ⇒ 恰好 1.000，且点查还少读一个节点

点查是 a_reads = 3 对 b_reads = 2、字节比 1.000；下一段在 n ≈ 7 529 537 起同样出现。

记录 52 那一档同形，第一段起点 n = 61 349。

⇒ 两件事：① E105（extent 叶改码 3 的代价） 的 `read_ratio_bounds` 断言「落在 1.25–2.0 之间」只在

一个尺寸、一个参数、一个负载算出来的倍数，不能叫『最坏情况』」）；

## 攻击面 7：分叉盘「第一版不可达」的推理

第五版逐字：「**分叉盘**：第一版 2 盘、掉一块盘只能只读挂载（D2（RAID 条带策略）已定项 9）、
只读不取号 ⇒ 分叉在第一版不可达。」

### 7.1 P2 自己的取号顺序把这条推理破掉：取号与写超级块排在「动任何单元」之前（可达）

**若「掉一块盘只能只读挂载 ⇒ 不取号」成立，那么发现写不了的那一刻必须早于取号。** 第五版把顺序写反了：
P2 逐字「每次可写挂载（含干净挂载、只读转可写）**取一次新号并先写全部可见超级块再动任何单元**」。
`w ≥ 2` 发不出写这件事，是在「动单元」那一步才暴露的；而号已经取了、已经写进**可见的那块盘**的超级块了。

**可达历史**：2 盘池，盘 B 离线。管理员做一次可写挂载尝试：
取号 N+1、写盘 A 的超级块（超级块每盘一份、按槽轮换更新，不受 `w ≥ 2` 约束）；
随后 D2（RAID 条带策略）已定项 6 的 `w = clamp(…) 再夹当时可写设备数 = 1 < 2` 让挂载退回只读。
盘上的结果是：**盘 A 的实例代号 N+1、盘 B 的实例代号 N，而没有任何单元被写。**
这一格恰好落进 P2 自己声明不防的「取号那一刻两路见证不完整可见」，
**只是它不是外部事件造成的，是取号顺序自己造出来的**。

单看这一步无害（没有单元）。但它把「掉盘 ⇒ 不取号」这句话变成假的，
而第五版的不可达论证整根架在那句话上。**推理要重写**：真正让第一版分叉不可达的是
「同一时刻只有一个可写挂载」，而那条前提全仓没有落点（现查 `.claude/kb/decisions/`、
`.claude/kb/invariants.md` 里没有任何一条关于设备独占打开或挂载互斥的条款）。

### 7.2 「第一版 2 盘」不是不变量：D2（RAID 条带策略） 已定项 3 / 4 允许在线加盘，≥ 3 盘那笔欠账带着日程（可达）

**若「第一版 2 盘」能撑住不可达，设备数就得在池的整个生命期里恒为 2。** 不恒：
D2（RAID 条带策略）已定项 3 逐字「设备集合变化之后走显式『几何再求值』事务，**不许强制重挂**」，
已定项 4 逐字「几何不合格拒绝加盘、排空后再换几何、加盘后跑一次后台可续做的重平衡」，
已定项 8 的组大小 g 初值就是 4。
⇒ 加一块盘是**在线事务**，不重挂、也就不重新取号、不重新判分叉。
第五版把 ≥ 3 盘的分叉判定立成「新欠账」，而按 D2（RAID 条带策略） 已定项 3 / 4，从 2 盘走到 3 盘不需要任何格式变更或重装。
⇒ 那笔欠账不是「将来某个版本的事」，是**这个第一版的池加一块盘之后当天就到期**。
第五版第四节代价表里「新欠账」那一行写的是「分叉盘判定与重同步（≥ 3 盘）」，
**没有写它的触发条件是一条已定的在线操作**。

### 7.3 两个并发可写挂载会拿到同一个实例代号，而 max 规则结构上分不出（可达，前提缺失）

**若实例代号能分辨时间线，两条并发时间线就不能拿到同一个号。** max 规则给不出这个保证：
新代号 = max(全部可见超级块的代号, 根环里全部根记录的实例代号) + 1。
两个挂载看到的是同一批超级块与同一个根环 ⇒ 算出同一个 max ⇒ **同一个 N+1**。
此后两条时间线上的单元写序都是 (N+1, ·)，谓词的三支
（`i < i_now` 查行、`i == i_now` 比 txg、`i > i_now` 判损坏）**一支都分不出它们**。
这一格与第四轮 4.3 打的「盘回归代号更大被 max 吸收」方向相反：那一格是号更大，
这一格是**号相等**，而相等在 max 规则下连一个可疑信号都不产生。

拦住它的只能是「同一时刻只有一个可写挂载」，也就是 7.1 末尾那条没有落点的前提。
**最小改法**：超级块加一位「已被可写挂载持有」的标记，与实例代号同一次写落盘
（P2 已经要求「先写全部可见超级块再动任何单元」，边际成本为零）；
挂载时发现标记已置且代号不是自己的 ⇒ 拒绝可写挂载。
这一条同时把 7.1 那个「取号已经烧掉、挂载又退回只读」的形态变成可判定的：
标记留在盘上，下次挂载看得出上一次没干净收尾。

## 攻击面 8：P8 的射程（新机制零证据）

第五版 P8 逐字：「E104（扫描重建的现行版本判定）：全规则臂 24 个种子全 0，
九条消融各按闭式非 0（第四轮新增 `wseq_meta_only`）。」

### 8.1 第五版最核心的两样新机制，E104（扫描重建的现行版本判定） 一格都没建（可达）

现查 `.claude/kb/experiments/104-扫描重建的现行版本判定.md` 的「它答不了的」，逐字：
「事务失败只有『崩溃抛弃』一种形态，没有单副本失败重试、**没有取号后写单元前的作废**」。
全文没有任何一处提到 kind 2 作废行。再现查源码，`e104_current_version.rs` 里没有作废行、
没有 (实例代号, 事务号) 二元组的行表、没有事务级失败这个事件。

⇒ 第五版新加的两样承重机制——**失败表 ③ 的作废行**与**根记录的最大已施加事务号**——
在 E104（扫描重建的现行版本判定） 里一条臂、一个世界都没有。
那句「全规则臂 24 个种子全 0」被放在 P8 里当第五版的实验支撑，
而它跑的是**没有这两样机制的那套规则**。
按 `.claude/singlefs-ai-sop/rules/show-me-test.md` 的「门禁能证明什么」那一节，
这一格属于「覆盖的不是出问题的那条路径」——而攻击面 1 给的可达历史正好落在那条路径上。

**最小改法**：E104（扫描重建的现行版本判定） 加一类世界「事务级失败 + 作废行」，并把攻击面 1.1 那条历史做成一个世界
（作废行随崩溃丢失 ⇒ 全规则臂必须报复活 ≥ 1）。
在那条世界跑出非 0 之前，P1 失败表 ③ 与 P2 的 kind 2 不能算「已验」。

## 一句话判决

**第五版不能按现在这样进正文。** 它自己写的三条推翻条件里，第一条这一轮中了两次：
攻击 4.1 是一条 P3 判错的可达历史（第四轮 7.4 从「回收掉候选判据的输入」这道门原样回来），
攻击 1.1 是一条 P1 / P2 判错的可达历史（作废行与它要证伪的那次崩溃同生共死，
而 (T, W) 这个结构只表达得了前缀、表达不了洞）。
第五节的判决两条腿也都要再动：`wseq_meta_only` 量的是「extent 叶恒丢」的臂 B（实验正文自己写了这句），
而 1.25–1.78× 是挑过的区间——同一份输出里就有 1.000，解析上约 13% 的规模区段两侧写代价相同、臂 B 还少读一个节点。
另有两处是新引入部分自己的硬伤：切分纪律让「多事务合写一个容器」成为常态，而那种单元的写序没有定义（2.2）；
「分叉在第一版不可达」的推理被 P2 自己的取号顺序、D2（RAID 条带策略）已定项 3 / 4 的在线加盘、
以及没有落点的挂载互斥前提各破一处（7.1 / 7.2 / 7.3）。
⇒ **建议出第六版**：改 ③ 的兜底载体、kind 0 行的回收条件、码 2 / 3 的写序定义、分叉盘那段推理与第五节的判决口径，
并把攻击 1.1 与 4.1 两条历史做成 E104（扫描重建的现行版本判定） 里必须报非 0 的世界，然后再打一轮。
