Consider a scenario where occupancy is 99% (102 free slots out of 10240). The format group arm with group size N=128 requires a contiguous block of 128 slots to rewrite any group. At 99% occupancy, the largest contiguous free space is likely less than 128 (e.g., multiple small free fragments totaling 102 slots but no single block of 128). Thus, the format group arm cannot rewrite any group with N=128 because no contiguous space exists. All dirty objects remain in place, resulting in runs=8192 (fully shredded). In contrast, policy compact uses the budget of 32 to rewrite 32 objects in key order, which can fit into the available small free spaces (e.g., multiple small fragments totaling combined to hold 32 contiguous slots). This would reduce runs significantly (e.g., to ~1000), while format group fails catastrophically. This shows format group's disadvantage at high occupancy where contiguous space is scarce.

Another counterexample: a skewedsk workload where a single hot key (key 500) is dirtied repeatedly in a contiguous block of clean keys (keys 0-999). Group size N=8. The group for key 500 (keys 500-507) has 7 clean neighbors. Rewriting the entire group moves all 8 keys to a new location, splitting the original contiguous block (0-999) into three parts: 0-499, 500-507 (new location), and 508-999. Runs increase by 2 (from 1 to 3). Policy compact rewrites only the dirty key 500, creating one additional run (total runs=2), which is better than format group's 3. Here, rewritingrewriting clean neighbors unnecessarily increases fragmentation.

For the separate question: a group identifier must be stored on disk if group membership is not derivable from the key's position. For example, if groups are dynamically formed based on access patterns (e.g., keys with similar hotness clustered together, regardless of key order), or if groups are non-contiguous in key space (e.g., keys grouped by a hash function), then each node must store its group ID to determine which group it belongs to. Fixed key-range groups (e.g., 0-7, 8-15) require no stored ID since the group can be computed from the key. But any dynamic or non-key-based grouping necessitates explicit storage of the group identifier in the node header.
