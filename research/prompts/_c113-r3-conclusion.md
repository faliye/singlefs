## 三、提案（第三版）

### P1 单元头带「写序」= (实例代号 4, 事务号 6)

**每个单元的类身份段加 10 字节写序 = 写出它的那个事务的 (实例代号, 事务号)。**
事务号就是 D23 已定项 7 已定要加进记录头的那个「事务号」字段：按实例计数、48 位、从 1 起；一个事务的全部记录都带它。
住类身份段不住共同前缀：码 1 与五元组、诞生代号同列（明文）；码 2 / 3 与诞生代号同待遇（加密开启后进密文）。

**取号纪律**：
1. 取号时刻 = 事务进入提交管道那一刻（并发路径上的序化点）；记录按事务号顺序追加；号永不回收。用户数据单元进入管道后就可以写（不必等固定点），树节点照旧在固定点收敛后写（D3 已定项 5 的形态不变）。
2. **取号之后不存在「中止」。** 失败按一张封闭的表处置：单个副本写失败 ⇒ 换落点重试，写序不变（写序住单元头，与落点无关）；不可恢复的失败（全部副本失败、内部不变量破）⇒ 实例结束：转只读，下次挂载走恢复，被丢弃的一定是事务号后缀（按取号顺序追加）⇒ 水位截得住。不写空记录。
3. **W1**：一个事务对一个逻辑 key 至多留一种净效果——单元、墓碑、或都没有；已写出但尚未点名的单元允许原地重写或不点名；写序相等时墓碑赢（相等只可能是同事务先写后删的残留）。同一发布内两个事务改同一 key 是允许的，写序不同即可择新（E104 same_txg 世界全规则臂 0）。

**10 字节买三件事**：同 key 已发布版本定序（诞生代号 + W1 够——`no_wseq` 臂只在同 txg 跨事务改同 key 时歧义）；分辨崩溃前后时间线（4 字节实例代号够——`inst_only` 臂在 crash_clean 世界 0）；在飞 txg 被部分重放时分开同实例同 txg 的已施加与被抛弃（**非要事务号不可**——`inst_only` 臂在 crash 世界复活 6 = 被抛弃单元数）。第三格的发生频率未测（第二版引的 E42 87.4% 是「一事务切 8 条、无边界字段」那条臂的数，不是崩溃点分布，已删）。

**与唯一先例的差异**：bcachefs 用两个字段（每节点重写序 `BTREE_NODE_SEQ` 定序、bset 的 `journal_seq` + 黑名单定已发布性）；本工程一个字段承担两件事，因为每次重写都是一个新事务、事务号本身就是每身份的重写序；代价是取号纪律成为写路径义务。未在本项目验证。

**重开两句已定**：D18 已定项 1（按其射程重开：写序买恢复口径）；D8 已定项 6「别的单元类都没有……不给容器单独加实例代号」——全部单元类一起加，前提不再成立。

### P2 实例表：码 3 打包记录单元；实例代号的取号规则

**实例表单元**：一片由根记录直接指向的码 3 打包记录单元，打包记录类型 4「实例表行」，记录宽 64：`实例代号 4 | 发布上限 txg 8 | 事务号上限 6 | 预留 46`；实例代号 0 的记录是「下一片指针」（59 字节位置指针住预留段）。一片装 (32768 − 103) / 64 = 510 行；根记录加一条 59 字节指针（127 → 186）。
- 为什么是码 3 不是码 2：它就是定长记录的数组，与 D8 已定项 6 把 inode 叶定成码 3 同型，自带载荷校验和，链指针被同一份校验和罩住，载荷格式落进 D15 冻结组件 ①。根指针本来就带位置条目的 32 位校验和（D19 已定项 4），所以这不是补完整性，是统一形态。
- **COW 重写**，挂根下；mkfs 写出一片空表（记录数 0），第一个事务的根指针不悬空。
- **态别**：它属于 D21「根」那一格——根记录 + 树表单元 + 实例表单元是根的间接层，权威态清单的措辞补这一句。两副本都不可读时：树表单元丢了池子挂不上；实例表丢了池子挂得上但谓词退化——只用「诞生代号 ≤ 挂载根 txg」那一支，同 (实例代号, 诞生代号) 上的多版记歧义、不择，重建停在级 1 并报告。

**行怎么写**：
- 崩溃恢复：给 [所选根的实例, 新实例) 每个实例写 (i, 在飞 txg, 重放施加的最大事务号)，一条记录都没施加的实例写 (i, 在飞 txg, 0)；
- 回退（P3 定义）：给旧根的实例写 (r_old, T_old, ∞)，给 (r_old, 新实例) 之间的每个实例写 (i, 0, 0)；
- 与恢复 / 回退后的第一个根同一次发布写出。
**回收**：一行可删当且仅当清扫（P4）确认盘上不再有该实例超出上限的可读单元（bcachefs 黑名单 gc 的同型）；zoned 第一版不回收。

**已发布谓词（全局）**：i_now = 挂载根的实例；单元写序 (i, n)、诞生代号 b：
- i < i_now：无行 ⇒ 已发布；有行 (i, T, W) ⇒ b ≤ T ∧ n ≤ W；
- i == i_now：b ≤ 挂载根的 txg；
- i > i_now：判损坏（取号规则保证不可达）。

**实例代号**：住超级块（E100 段四候选表里已有的 4 字节，P2 给它语义）；**新代号 = max(全部可见超级块的代号, 根环里全部根记录的实例代号, 实例表里最大的实例代号) + 1**——只看超级块会在「掉盘降级、盘失而复得」下回滚（D22 已定项 8 买下的「掉一块盘还能挂」正是那条历史）。每次挂载（含干净挂载）取一次新号并先写超级块再动任何单元；只读挂载不取号；从 1 起、0 无效；32 位按挂载次数算够用（D23 已定项 9 的场景点是取的不是量的，口径同）。加密开启后与 nonce 水位同受主密钥 MAC 覆盖；第一版不加密时只有非密钥校验和，与 `map_provenance` 同口径。

### P3 现行版本判定规则

输入：挂载根，根集 ℛ = 树表里的可写头 ∪ 快照列表（I-3.7 的结构字段表未定，这里按「快照根不带实例代号、只带 txg」处理，是对一处空白的假设），祖先表（P6），实例表，扫到的单元集，墓碑 / 退役记录。

**回退的定义**（仓里此前没有）：管理员选一个根环里的旧根 R_old 挂载 = 一次恢复——不施加 R_old 之后的任何 journal 记录，取新实例代号，写回退行（P2），发布第一个新根。回退之后 R_old 就是挂载根，被抛弃的时间线按行判未发布。旧根引用的块由 defer 窗口与 I-7.4 保护。

逻辑 key 与写者树：码 1 的 key = (对象 ID, 对象出生代, 锚点偏移)、写者树 = 五元组的树 ID；码 3 的 key = 四元组、写者树 = 出生树（P6 保证）。

```
Visible_R(u)  := 已发布(u) ∧ u.诞生代号 ≤ T_R ∧ ∃(a, c) ∈ anc(t_R): u.写者树 = a ∧ u.诞生代号 ≤ c
v*(R, k)      := Visible_R 且 key = k 的单元里写序最大者
Current_R(k)  := 若存在对 R 可见、指认 k、死亡写序 ≥ v*.写序 的墓碑记录 ⇒ 死；否则 v*
```

**三步求值**：① 对全部码 3 容器身份求 v*；② 从现行的类型 1 容器（同时装类型 1 与类型 3 记录）取出墓碑与退役记录，从现行的类型 4 容器取实例表行（第一片由根指针指认，不走 v*）；③ 数据 key 与类型 2 容器套用 kill / retire。类型 1 容器版本撕裂时它所属的事务未被施加（E77 施加前验证），真值里那些删除也没发生，落回上一版是对的；已发布之后的介质损坏是权威态损失，由 w = 2 兜，不由规则兜。两个现行类型 2 容器装着同一 inode 号记歧义。

**派生量**：分配记录 = 各根的 Current 落点 ∪ 重建过程新写出的索引节点落点 ∪ 固定结构（根环、journal、超级块区、树表单元、实例表单元及其链）；扫到的旧码 2 节点一律是垃圾。重建产物是新分配、要占空间，且 `map_provenance = rebuilt` 未晋升前只读（D18 已定项 5）。可写头 H 的 deadlist = 对 H 谱系上某快照现行、对 H 不现行的落点。

### P4 垃圾清扫

释放路径不加 I/O。清扫是与 D13 代际增量 scrub 不同的第二个后台 pass，全盘、低频、可续做。
- **准入（显式合取）**：分配记录说该落点空闲（含从未分配的孤儿）∧ 释放代 ≤ 当前 − K（根环旧根不引用，I-7.4）∧ 释放代 ≤ 重放窗口下界（D22 已定项 4）∧ 头可读。判据全部来自运行时结构，不用 P3。
- **重建过的镜像**：`map_provenance = rebuilt` 未晋升期间禁止清扫；晋升要级 2 见证者，今天不存在 ⇒ 重建过的镜像今天不会再清扫（分配记录是 P3 的产物，C12 的形状由此避开，代价是墓碑不回收）。
- **手段**：非 zoned 原地抹头（一个扇区）；**zoned 第一版不支持清扫**（D22 未定项 6 明写第一版若改跑 zoned 就判不了；D26 五个未定项里两个直接卡着），墓碑与实例表行在 zoned 上不回收。
- **清扫水位**只在整轮完成时推进，中途进度是运行时状态；清扫水位与「最近一次根销毁的代号」是两条记账统计量（D5 已定项 4 第 13 / 14 项，合并规则取最大值），不参与择版本。
- **代价**：每轮一遍全盘读（16 TiB 盘 2 GB/s 约 2.3 小时），频率是策略；D18 已定项 3 连锁表「scrub 从只读变成写」知情重开，射程是一个扇区、不造新块、不进 deadlist。

### P5 墓碑记录带死亡写序；容器退役记录；回收条件

类型 1 记录加 10 字节死亡写序（删除事务的写序）。类型 3「容器退役」记录 = (打包记录类型 2, 容器号 8, 出生代 8)，**不带写序**——身份不复用，退役不与任何东西比大小，对某个根可见与否由装着它的容器版本的诞生代号定；合并、叶删空、重生各写一条。
回收条件（类型 1 与 3 同）：D18 已定项 10 的条件（没有快照还引用它指认的死亡 / 没有根还引用退役容器任一版）∧ 清扫水位 ≥ max(死亡或退役代号, 最近一次根销毁的代号)。永不清扫时墓碑只增不减，以已承诺预留量（D3 已定项 2 / 4）的形式吃可用空间。

### P6 跨头首次 COW 让容器重生并退役旧身份；祖先表

## 五、被否形态与别家信号

同第二版第五节，补两条：「实例表住码 2」（只靠根指针的 32 位校验和，链上第二片的指认者住载荷，且四层与两个冻结组件都装不下它的载荷格式）；「中止写空记录」（提交标记齐 ⇒ 孤儿判已发布，不齐 ⇒ 已应答的后续事务被丢）。
别家信号照旧只当线索：bcachefs 黑名单是一组区间、住超级块、有 gc；btrfs generation 期望值住引用方；ZFS 没有扫描重建。没有现役实现给数据 extent 做扫描择版本，举证责任在本工程。

**什么现象会推翻第三版**：三方论证给出一条 P3 判错的可达历史；取号或实例代号规则在某条已定条款下写不出来；E104 按第三版纪律建模后全规则臂非 0。
