## 一、问题

英文名：crash_amplification_design_function_test

**主 agent 给的问题（逐字）**：三轮设计之后的崩溃放量新设计（`research/prompts/m3-prune-gpu-r3-main-verification.md` 第四节那张表）里每一件改法，在入库装置上、小范围的域里，是不是把它对应的「红的世界」从非 0 变成 0，且不引入新的漏或假红；每一行做与不做两臂都跑。

**读法写死**：

1. 被测对象是第三轮判决第四节那张表写的设计（下称「新设计」），不是 `crates/` 今天的实现：新设计的身份、属性、复用、反向检查、流水线、领块、标签类型、指纹在 `crates/` 里都没有（第三节 grep 零命中）。`crates/` 在这个实验里只当被观测的对象：在它的仓副本上施加真代码改动（下称「变体」），看新设计的各件对这些改动反应得对不对。
2. 每一行 F1–F13 的两臂：「做」= 新设计的那一件照第四节表的字面做；「不做」= 问题单「红的世界」一列写的那种做法。两臂之外的各件取第五节「各行的基线设定」那张表写死的值，两臂只差这一件。
3. 「从非 0 变成 0」拆成两个量、各判各的：不做臂在它的红的世界上报非 0（阳性对照，证明入库装置复现了那个世界）；做臂在同一个世界上报 0。
4. 「不引入新的漏或假红」拆成三个量：做臂在中性变体（只重编、只加一行注释）上多余的重录、重核与假红数；做臂在判别对照上仍然报得出该报的（没把检查关掉）；「全设计臂」（第四节表里各件都做）在全部变体上的漏数。
5. 小范围：每一格秒级到分钟级；单段超过 30 分钟的格停下报告，不自己缩域。
6. 「漏重录」的口径按「输入变了」算，不按判定算：一步被复用、而它的崩溃状态的输入（这一步之前的镜像、这一步带屏障与 FUA 的写表）与旧编译的不同，这一步与它的全部崩溃状态记作漏重录。状态数按 D13（验证路线） 已定项 4 的两态闭式算（`crates/singlefs-harness/src/segments.rs` 第 201–214 行 `closed_form_state_count` 那一个：1 + Σ(2^|段| − 1)），原地覆写的第三态不计。这是与第三轮攻方报告不同的口径（它按判定与身份在不在算、含撕裂态、只展开段长小于 16 的段），两边的数不比。
7. 「漏红」「过程变了」「判定变了」这类量要在崩溃状态上造镜像、跑池级 checker 与记录核对器，按 `.claude/rules/verification.md` 第 16 行与第 26 行归 checker 档；派发提示写了「不要 checker 档」。这些量写进第三段，第三段的判据在这里写死，开不开由主 agent 定（第五节末「分段」与第十一节）。

### 5.2 历史与探针

- **H-短**：mkfs → 取号 → 两次暖机 → 新池新建文件，照 `crates/singlefs-harness/src/scenario.rs` 的 `run_new_pool_file_creation` 与 `e142_parameters` 的参数，录制器开 `retain_contents`，在内存池上录。

- **步**：mkfs 是基线（步 base）；取号是步 0、两次暖机合成步 1、新池新建文件是步 2、之后每次发布一步。探针在每次调用前后记录录制流的长度，按它切步；scenario 的入口切不出步界时停机（第十一节 S-probe）。

### 5.4 新设计各件在装置里的写法（两臂共用的词）

### 5.6 流水线与领块模型（F10、F11）

- 库里每块四样：录入的数据（没有 / 半块 / 整块）、「已录入」标记、「已核对」标记（布尔，或记下核它的判法摘要）、结果（没有 / 数，外加累加计数）；领块记录（没有 / 哪张卡，带租期的另记租期到没到）。
- 录入进程按块号逐块写；核对进程每张卡按批领「已录入且未按当前判法核过」的块，算完写回。两个进程在任意两次库写之间都能被杀一次、从头重起，重起只看库。积压上限：已录入未核的块数到了上限，录入等着；「等着就放批」开着时，核对方手里批没满也先核。判法在运行中途可以换一次（摘要 D1 → D2）。
- 卡可以掉线（之后永不回来）；带租期的形态里，租期可以在任何时刻到期（持有的卡还活着也可以），到期后别的卡可以接这一块，原持有的卡照样可能把结果写回。
- 终局时门禁读一次：每块要么有按当前判法算的结果，要么报「本次未跑」。错误五种：`missing_result`（标了已核对、结果却没有）、`wrong_input`（结果拿半块或没有的数据算）、`double_tally`（结果按追加计、同一块计了两次）、`stale_after_change`（判法换了之后旧结果仍当已核对）、`stuck`（有块没核而两个进程都动不了，或块被掉线的卡领着不放；带「领着不放」的记作死块）。
- 最强形：录入一批原子写（数据与标记同一批）、核对一批原子写、标记记判法摘要、结果按块键覆盖、领块只在内存、两张卡、批 ≤ 积压上限或「等着就放批」开着、中途换一次判法。
- 五种弱形，各只改最强形的一样：标记先于数据写（`record_flag_before_data`）；已核对标记先于结果写（`checked_flag_before_result`）；先写结果后写标记且结果按追加计（`result_then_flag_with_appended_tally`）；已核对标记是布尔（`checked_flag_is_a_boolean`）；批大于积压上限且不放批（`batch_larger_than_backlog_cap_without_flush`）。
- F11 三形：落盘不带租期（领块记录进库、卡掉线后没人收回）；不落盘（领块只在内存，掉线的卡重起时丢掉）；落盘带租期（进库、带租期，语义见上）。三形都开「卡掉线」。
- 几何：块数 2 与 3；卡数 1 与 2（弱形原本取 1 张的也在 2 张上跑一遍）；积压上限 1 与 2；批 1 与 2。可达状态数超过 10⁷ 的格停下报告，不缩域。

### 5.7 F12、F13、W3、W5 的写法

- **F12**：两种类型形。弱形：复用键是只能从写表算出的新类型，标签不实现 `Hash`、`Eq`、`Ord`，但实现 `Display`。收严形：标签什么格式化与比较都不实现（没有 `Display`、`Debug`、`Clone`、`Hash`、`PartialEq`、`Ord`），只交给只写的覆盖报告。五种写法：①标签直接当库的键传进去；②标签放进 `HashMap` 当键；③拿标签造复用键；④拿标签的文字（`to_string()`）当内存里的键；⑤合法写法：把标签交给覆盖报告。每格一份 `.rs`，调用方所在 crate 带 `#![forbid(unsafe_code)]`，`rustc --emit=metadata` 编一次，记编得过 / 编不过与第一个错误码。
- **F13**：六种设置，都在带 `.git` 的仓副本上算（只读，不做 git 写）：S1 个人 `CARGO_HOME` 下的 `config.toml` 只写 `[term] color = "always"`；S2 副本放在一个自带 `.cargo/config.toml`（只写 `[net] offline = true`）的上层目录下；S3 副本的 `.cargo/config.toml` 把 gcc 13 的头文件路径换成 14；S4 `RUSTFLAGS="-C target-cpu=native"`；S5 `CARGO_PROFILE_RELEASE_OVERFLOW_CHECKS=true`；S6 副本放在另一层路径下、另设 `CARGO_TARGET_DIR` 与线程数。做臂的指纹：`admission.py` 今天收的源文件与 `Cargo.lock` 清单照收，另收 `rustc -vV`、目标三元组、生效的 rustflags（`RUSTFLAGS`、`CARGO_ENCODED_RUSTFLAGS`、各层配置的 `build.rustflags` 与 `target.<三元组>.rustflags`）、profile 设置（`CARGO_PROFILE_*` 与各层配置的 `[profile]` 表）、runner 与 wrapper 指的程序按内容；`[env]` 表与环境变量只在这条用例的依赖闭包（`cargo metadata --offline` 按用例的包与特性解）里有带 build 脚本的包时收；`[term]`、`[net]`、`[http]`、`[registry]`、`CARGO_HOME` 与仓在哪一律不收。**判「会不会改编出的代码」的对照**不用这张键表：同一份副本、同一个编译目录里先按默认设置编 `cargo build --release --offline -p singlefs-harness --lib -v`，再换上那一种设置编一次，cargo 对任何工作区包报 `Compiling` / `Dirty` 就记「要重编」，全是 `Fresh` 记「不重编」，编完换回默认再编一次；S6 换了编译目录，这个对照不适用，记「不适用」。
- **W3**：域是 `git rev-list --all` 的全部提交、全部路径。改名按 `git log --all -M --diff-filter=R --name-status`（默认相似度）。「旧名被占回」：一次改名 旧 → 新（提交 c）之后，任何更晚的提交里旧路径上又出现一份文件、而它不是从新路径改名回来的，记一次；分全部路径与「含 `#[test]` 的 `.rs`」两栏。逐提交唯一性：每个提交的树里，身份 `<代码文件名>::<#[test] 函数名>` 按两种「代码文件名」各算（文件名本身不带目录；仓内路径），数有重复身份的提交数与单个提交里最多几个重复。
- **W5**：节点清单现取：`.claude/gate.d/stage-inputs.tsv` 每一行 `crash-case:`（包取第三列 `test=` 的包）算一个崩溃枚举节点；`singlefs-harness`、`singlefs-checker`、`singlefs-core`、`singlefs-format` 各包的 `--lib` 各算一个、`tests/*.rs` 每份算一个测试节点。典型改动：`git log` 里最近 30 次改了 `crates/*/src/` 的提交（不到 30 次取全部），按改到哪几个包分类（core / checker / harness / checker-tier / format / 多包）。节点要重跑当且仅当它的依赖闭包（5.4 的按 crate 闭包）里有包的 `src/` 被这次提交改了，或这次提交改了它自己的目标文件。

## 八、轨迹与几何敏感性

### 8.1 轨迹

被谓词消费的量只有两处，报峰值、为正的状态数、终局值三样：

| 量 | 被哪个谓词消费 | 报什么 |
|---|---|---|
| 积压（已录入未核的块数） | 录入「到了积压上限就等」 | 每种形、每个几何点：可达状态里的峰值、积压 > 0 的可达状态数、终局里积压取到的值的集合；最强形的峰值超过积压上限就是 Q10-traj 那一行的翻面 |
| 被领着的块数（F11） | 核对方「只领没被领的块」 | 同样三样，另报终局里被掉线的卡领着的块数（= 死块） |
| 每一步的复用判定（第二段） | 「复用 / 重录」 | 不只报总数：每臂每变体逐步列出「复用 / 重录 / 真值是否变了」，漏在哪一步看得出 |

其余的量（摘要变没变、编不编得过、指纹同不同、重跑比例）不是任何停机、起跑、准入谓词的输入，不适用。
