## 三、格

### G1　logged_ops 意图记录的字段表（C364）
一条意图 = 树里一条普通 key 的 value（D26 已定项 2「零格式位」要这样读）。要装：种类（整理 / 销毁快照）、整理的 `R`（设备, 起始槽, 槽数）、`c0`（签发那一刻的分配代）、`segs0`（签发那一刻的全空聚簇段数，以值写）、续做点、暂停标志、销毁快照的 (头, lo, hi, P)。各答：key 怎么排（种类 + 签发 txg？按头？）、宽度、value 定宽还是按种类变宽（D8 已定项 11 种类到条目宽的表一树一宽）、`segs0` 三种口径取哪一种（C372（全空聚簇段数两份定义相反））、意图与最后一批同一次发布删（D8 已定项 5）、提示类意图的暂停与提前收怎么表达；m3-intent-r1 攻方 F1–F6 逐条在这版字段表上还成不成立。

### G2　选段与搬迁计划：纯函数、输入、输出
输入只从已发布状态读：分配记录树（每落点的分配代 / 释放代）、中央映射（key → 落点）、runs 与全空聚簇段数（记账树）、三条水位。输出：`R`（一个或几个聚簇段）与要搬的清单（映射 key, 源落点, 目的落点）。搬迁单位是整个对象重落一组（D26 已定项 12），第一版单盘每单元一份。选段判据候选：空槽最多的非全空段（greedy）、cost-benefit（F2FS 的 CB，线索）；`R` 的粒度 = 聚簇段（64 槽，`CLUSTER_SEGMENT_SLOTS`）。写成纯函数带 CPU 参照实现（GPU 口子，D24 已定项 2 第 3 条）。各答：函数签名与住哪个模块、单测怎么钉绝对值、与 D3 已定项 8 的落点政策（`R` 内不许分配、开放段不许当目的地）怎么对得上。

### G3　一批搬迁的事务形态
一批 = 读源单元 → 原内容（`birth` 不变）写新落点 → 中央映射那条条目的落点改成新的 → 分配记录源侧写释放代、目的侧写分配代 → 源落点进 defer；三笔写同一次发布（C197）；意图的目标态「`R` 内不存在分配代 ≤ `c0` 且未释放的落点」单调（D26 已定项 2）。各答：一批最多搬几个单元（受一次发布的记录上限与已承诺预留约束，D3 已定项 2、D16 已定项 1 环窗口）、搬迁那次发布是不是一个「文件版本」（`PublishPlan` 的 `file` 字段）还是新的发布形态（`DeletionStepOfThePublish` 之外第三个入口）、位置提示（指针里的位置条目，D19 已定项 4、8）搬后失效走映射回退读、要不要刷新（C417）；搬被快照共享的块：中央映射是唯一入口（D19 已定项 5）⇒ 只改映射那一条、不改任何引用方——在今天的代码里快照与活头读路径是否都经映射（`recovery.rs:448` 那条回退读是不是唯一的位置来源），能的话 C142 关、不能的话哪一处还按位置提示读。I-4.6、I-3.1、I-7.4 在每个中间态成立的理由；I-4.4 的判法（意图描述目标态、不描述增量）。

### G4　停机谓词、`N₀` 与三条水位的第一版取值
停机 `全空聚簇段数(现在) − segs0 ≥ 1`（D26 已定项 1）；`N₀` 取能让棘轮不发散的最小值（D26 已定项 3）；三条水位（全空聚簇段数、`F = runs / L`、不可回收字节）任一越线起跑。第一版各取什么值、做成挂载可调的旋钮（`system_configuration.rs` 的 `compaction_watermarks` 已有三格恒 0），E10 跑前登记要量哪几个量才能把它们定下来（这一格的产出就是 E10 的岔路单：每行候选、翻面观测、够判条件）；C373：停机判真时活意图删不删；C140：意图完成不等于空段被腾出，怎么判。

### G5　discard 什么时候发
候选：甲 落点被清扫确认可再分配之后由清扫整段发（`reclaim_released_up_to` 之后，照 F2FS / btrfs 线索「先可分配后 trim」）；乙 GC 产出全空聚簇段那次发布之后整段发；丙 第一版不发、只留块设备 trait 的口子。各答：块设备 trait 加什么方法、文件后端打洞、内存盘记事件、设备日志判器怎么判（Discard 事件今天被跳过）、崩溃点重放里 discard 算不算写（D13 已定项 4 的段模型）、发了 discard 的落点在 I-7.4（近 K 代块未被复用） 下怎么判。

### G6　崩溃流与必红世界
二·3 要两条流：GC 搬迁一条、搬被快照共享的块一条（后一条等快照落地）；接在哪条已有的流后面、每批写几个单元、对着每落点 64 次写、每流 2048 次写、展开深度 30 估态数；必红世界（源落点在映射发布之前就被释放，判器红）。只供测试的开关：批大小、强制选哪一段（`.claude/rules/fs-design.md` 五条硬要求第 2 条每条分支能被测试强制进入）。

### G7　「GC 是恒等变换」怎么证
二·4：搬完之后抽象文件系统状态逐字不变。在 Verus 上能证的是哪一截（计划函数的纯函数性质：输出清单里每条 key 的新落点不在 `R` 内、不与别的落点重叠、key 集合与输入的活集合相同）；模型对拍：随机历史穿插 GC，结果与不跑 GC 逐项相同，`HistoryOperation` 加哪一种。

### G8　调度：第一版谁触发 GC
挂着时没有调度器（`instance_table_sweep.rs:825`）。候选：甲 第一版只由会话显式触发（测试入口 + 用户可调的「现在整理」），每次调用跑到停机谓词为真或暂停；乙 挂载末尾（续做删除队列之后）跑一批；丙 后台线程。与删除续做、抬 F 的次序；提示类意图不挡挂载（m3-intent-r1 I3）。

### G9　「区域扫描」是什么
里程碑五要「整理器沿中央映射 key 序把 ≤ 4 KiB 的对象搬进容器」「全死的容器由区域扫描回收」。区域扫描 = G2 的选段函数对一个 `R` 逐落点读分配记录与映射、认出可搬与已死的那一步？给它一句定义、它的输入输出，列进 G2 的函数签名或另立一个。
