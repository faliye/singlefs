## 一、问题

**主 agent 给的问题（逐字）**：一次 fsync 从发出到返回等了多久，在甲（今天的形态，组提交）与 WAL 臂上随并发数 k 怎么走——一种读法：按一次 fsync 的挂钟等待时间（发出到返回），在被测进程里计时。

### 读法写死

- **W（一次 fsync 的等待）**：调用方线程在把 fsync 请求交出去之前一刻，取一次单调时钟，记为 `t_issue`；它被唤醒、看到自己那一批已经完成之后一刻，再取一次，记为 `t_return`。`W = t_return − t_issue`。两次都在同一个来宾进程里取，都用 Rust 的 `std::time::Instant`（CLOCK_MONOTONIC）。开环（第八节 G8）里 `t_issue` 取**排定的到达时刻**，不取实际发出的时刻：发晚了的那一段也算等待，不能被丢掉（开环测量里这个偏差叫「协同遗漏」）。
- **「返回」在哪一刻**：甲在这一批的根槽写完、并且紧跟的那次 `fdatasync` 返回之后（D16（发布语义）已定项 7「fsync 等根槽持久之后才返回」；`crates/` 里 FUA 就是「写完立刻 `sync_data`」，第三节）。WAL 臂在这一批的第二道屏障返回之后（E155 的臂定义：单元 → 屏障 → 记录 → 屏障，第二节末尾）。系统配置槽那一步排在返回之后、下一批开始之前。
- **k（并发 fsync 数）**：闭环里调用方线程的个数。每个调用方各有一个文件；fsync 一返回就立刻发下一次（零思考时间）。取样点 **k ∈ {1, 2, 4, 8, 16, 64, 256, 1024}**：16 以下逐个翻倍，这是组提交刚开始攒得起来的那一段；16 以上每档乘 4，一直取到 1024。D25（目标负载优先级）已定项 7 的下限是 16、不设上限，所以任何有限的上端都是取出来的，不是定下来的（第十节 F2 管这件事）。
- **到达过程（D25 没写，这里写死）**：主取**闭环、k 个调用方、零思考时间**。理由：D25 已定项 7 定的是「并发 fsync 的个数」，这是一个并发数，不是一个到达率。闭环里 k 就是字面上同时没返回的 fsync 个数，不用再从到达率反推。另登记一种到达过程重跑判决那几格：**开环泊松到达**（第八节 G8），到达率 λ 按第五节 5.5 的规则从同一轮的闭环吞吐算出来，取 0.7 与 0.3 两档。
- **WAL 臂**：wal_full-K10 与乙-M-K10 两条都留，全文说「WAL 臂」时指这两条，每条各自和甲比、各判各的（文件头第 5 行）。
- **组提交**：发布者线程空闲、而队列里有请求时，立刻把队列里的请求全部收成一批，不设攒批等待。甲的一批就是一次发布；WAL 臂的一批就是一次「单元 → 屏障 → 记录 → 屏障」。同时在飞的只有两批：一批在发布中，另一批开着收请求（D16 已定项 5：「在飞 checkpoint 深度 = 开放 + 发布中两个」）。**组提交关**：每批恰好 1 个请求，批与批串行，先到先服务。
- **两臂的「差距」读作比值**：`R(k) = 甲的 W 中位 ÷ WAL 臂的 W 中位`，同一格、同一轮。两臂之差 `D(k)`（毫秒）照报，但不判：两臂的等待都随 k 涨，比值不变时差值也会随 k 变大，所以差值分不出「组提交有没有摊薄等待」。这条读法交主 agent 认（报告里列为待认项，不阻塞开工）。
- **「越过一个跑前写死的倍数」**：倍数 **M = 2**。理由：闭环里一个调用方每秒能做的 fsync 次数就是 1/W，所以 W 的比值翻倍，就等于同样的并发数下甲的 fsync 速率只剩 WAL 臂的一半。这是按「吞吐掉一半」这条政策线定的，不是从哪条臂的定义推出来的。另外，1.25、1.5、3、5、10 五档照报，看每档在哪个 k 上被越过，但这五档不判。
- **「每个 k 报中位与离散」**：每轮报中位、p10、p90、p99、最大值与样本数；五轮合起来报「五个每轮中位的中位」，以及每轮中位的最小值与最大值。

## 计时不在转发输出的循环里打时间戳

## 五、臂、阳性对照、真实基线

### 5.1 装置写在哪、量延迟为什么真跑

**装置写在 `research/e7-index-bench/src/bin/e159_fsync_wait_group_commit.rs`（独立手写模型，不与 `crates/` 共用代码），不是入库装置。** 理由是第三节第一行：`crates/` 里没有组提交，这条岔路问的不是「`crates/` 今天这份代码的性质」。宿主侧的包装脚本写在 `research/scripts/e159-run.sh`，产物进 `research/results/e159-…`，变异表进 `research/mutations/e159_fsync_wait_group_commit.tsv`。

**量延迟用真跑，不用计数模型。** E155 的装置是纯计数模型，只算字节与写调用，不量时间。要从计数模型得到时间，就得另外假设一个设备模型：每次写多久、FLUSH 多久、盘内部能不能并行。而这个假设本身就会决定答案：甲比 WAL 臂多写的主要是很多个小单元，盘内部并行度一取，差距就定了。这正是 `evidence-discipline.md`「不许先有结论再建模型」要拦的那一步。真跑时让本机的 NVMe 自己决定每一批花多少时间，装置只负责三件事：把 E155 算出来的「这一批写什么」原样交给设备，把组提交做对，把时间计在被测进程里。

**写量模型照搬 E155，不重写**：从 `research/e7-index-bench/src/bin/e155_fourth_run_group_commit_concurrency.rs` 拷出常量、K1–K4、5.3 组公式、`solve_fixed_point_core`、`solve_jia_batch_publish`、`solve_write_ahead_log_batch_fsync`、`solve_write_ahead_log_batch_checkpoint`，以及它们依赖的函数。**函数体一个字不改**（第十一节 S2 用 diff 核）。这些函数算得对不对，归 E155 的锚点与变异表管；这一次钉的是「装置交给设备的写」和「模型给的写」相符、和来宾块层读数相符（第七节）。

**格子**：一格 = (臂, k, 组提交开 / 关, 到达过程, 几何取样点)；每格一个调用方集合、跑 11 秒。**主几何**照 E155 第 7 行主表：P = 10⁴ 个文件、族 F8A（一次 fsync 改一个文件相邻的 8 个数据单元，也就是 D25 已定项 1 那一档）、k 个文件在 key 上相邻（共享脊柱）、落点 seq、位置策略 L均、φ = 1、K3、g = 24、`physical_block_size` = 512，WAL 臂的中间版取 K10。选 P = 10⁴，是因为 k 最大取到 1024，而 E155 要求 P ≥ k。

### 5.2 臂

三条臂的名字与第一句定义照第二节 2.3 逐字；下面「怎么做」是这一次在时间这一维上补的，「做完会怎样」是待证的命题（第七节钉数、第九节变异）。

**甲（真实基线，`crates/` 今天的形态 + 组提交）**：「每次 fsync 是一次全量发布」；k > 1 时 E155 第 7 行的定义是：一批就是一次发布，写这一批 k 个 fsync 改动的并集、四样固定点、⌈点名项 / 67⌉ 条记录、根槽、每块盘一个超级块槽（第二节 2.3 第一块）。
- 怎么做：发布者线程把一批 b 个请求（b ≤ k）交给 `solve_jia_batch_publish(主几何, b, 共享)`，得到每种单元的期望个数，按 5.3 取整；然后照 `crates/` 的次序落盘：全部单元 → 屏障 → ⌈W/67⌉ 条记录（W = 这一批实际写出的单元数）→ 屏障 → 根槽 512 字节写 + `fdatasync`。之后放行这一批的调用方，再做系统配置槽（先读两个槽、再写一个），做完才收下一批。
- 做完会怎样：每批 2 次屏障 + 1 次 FUA（写 + `fdatasync`），也就是来宾块层每批 3 次 FLUSH（照 5.3 的回放盘口径）；每批读 2 次、每次 4096 字节；在飞的最多两批；k = 1、P = 1、F1 时写的种类、宽度、次数、次序与 `crates/` 一致（第十一节 S1）。

**wal_full-K10**：「同第 1 行 wal_full，另外一个 checkpoint 间隔里写了又被换掉的每个中间版也写一条已释放的分配记录」；第 1 行 wal_full 是「每次 fsync 写脏数据单元、脏叶与全部祖先、一条点名子树根的记录，不发根，根与固定点在 checkpoint 写」（第二节 2.3 第二块）。
- 怎么做：一批 b 个请求用 `solve_write_ahead_log_batch_fsync(主几何, 全量, b, 共享)`；单元 → 屏障 → 记录 → 屏障，然后放行。checkpoint 由**单独一个线程在后台做**，触发条件照 D16 已定项 2：`(now − 上次 checkpoint 的时刻 ≥ T_time) ∨ (上次切点以来追加的 journal 字节 ≥ 有效 T_dirty)`，`T_time` = 5 s、有效 `T_dirty` = 256 MiB（D16 已定项 5）。触发时在 journal 上切一刀：切点之前追加过记录的批次归这个间隔，数出间隔里的 fsync 数 N 和批数 N_b；然后调 `solve_write_ahead_log_batch_checkpoint(主几何, 全量, k̄ = max(1, round(N / N_b)), 共享, N_b, K10)`，按 5.3 取整。之后照甲那一次发布的形态落盘：单元 → 屏障 → 记录（拿 journal 锁，与批次的记录按先后排进环）→ 屏障 → 根槽写 + `fdatasync` → 系统配置槽（先读两个、再写一个）。checkpoint **不挡** fsync 批次：它们只共享设备、共享 journal 追加的次序。一个 checkpoint 还没做完、又到了下一次触发，就等它做完再切（在飞最多两个：开着的间隔 + 发布中的 checkpoint）。环里在飞的记录数到了上限（环 768 MiB ÷ 4096 ÷ F，F = 3，也就是 65 536 条），批次就等 checkpoint 做完（D23 已定项 18）。
- 做完会怎样：每批 2 次屏障、0 次 FUA；每个 checkpoint 2 次屏障、1 次 FUA、读 2 次；checkpoint 之间的间隔 ≥ `T_time`，除非是 `T_dirty` 先到；批次的 W 里不含 checkpoint 的时间，除非碰上环满（等环的次数照报，第六节 Q9）。
- 为什么后台做：这是支持 WAL 的人会认的样子（提交与 checkpoint 并行）。让 checkpoint 挡住批次，是对 WAL 更不利的读法，登记成第八节的反向取样点 G7。

**乙-M-K10**：「每次 fsync 写脏数据单元、脏叶与一条点名叶的记录……中间版照 K10 记」（第二节 2.3 第二块）。
- 怎么做：同 wal_full-K10，只是两个函数的臂参数换成「只写叶」；checkpoint 另外补写两棵用户树间隔并集上第 1 层起的祖先（E155 的函数已经算进去了）。
- 做完会怎样：刷写与 FUA 同 wal_full-K10；同一批的写字节不多于 wal_full-K10（第七节 B2 在一格上钉）。

### 5.3 一批怎么交给设备

- **回放哪块盘**：E155 的写量按两块盘镜像算（`D` = 2：单元、记录、系统配置槽两盘各一份，根槽只在一块盘）。本机只有一块 NVMe。主取**只回放一块盘，而且是带根槽的那块**：真机上两块盘各写同样的内容、并行地写，一次发布的挂钟取的是慢的那块，而带根槽的那块多一次 FUA，正好是慢的那块。于是回放的就是 E155 每种单元的个数（不乘 2）+ 记录 + 根槽 + 一个系统配置槽。把两块盘都放到同一块 NVMe 上，会让物理盘上的字节翻倍、FLUSH 也多一倍，而甲字节多，这样做对甲更不利；它作为反向取样点 G5 登记。
- **来宾里的设备**：`/dev/vda`（G5 时加 `/dev/vdb`），用 O_DIRECT 打开；缓冲按 4096 对齐，内容是固定种子生成的伪随机字节（不用全 0：盘即使会压缩或去重，也不会因此偏向哪一臂）。**区域**：`[0, 1 MiB)` 放 2 个系统配置槽和 24 个根槽位置（3 区 × 8 槽，`lib.rs:186`、`:204`），槽距 16 KiB；`[16 MiB, 784 MiB)` 是 journal 环（`lib.rs:159`、`:162`），记录按追加顺序写、写满回绕；`[1 GiB, 5 GiB)` 是单元区，32 KiB 单元与 16 KiB 节点各从一个顺序游标取落点，写满回绕。根槽按发布序号轮着用那 24 个位置。
- **测量之前整盘写一遍**：盘镜像用 `VM_DISK_PREALLOCATE=1` 预分配，来宾一启动先把整个 5 GiB 按 1 MiB O_DIRECT 顺序写满，再 `fdatasync` 一次，这一步单独计时并照报。理由：宿主 ext4 上预分配出来的区段是「未写过」的，第一次写要改元数据，宿主的 `fdatasync` 就要多提交一次日志，而谁先碰到新区段就由落点决定。写满一遍之后，所有写都是覆盖已初始化的块，宿主那一层就只剩一次 FLUSH。
- **同一阶段的写并发交出去**：一个阶段（全部单元，或全部记录）里的写同时交给 32 个 I/O 工作线程，每个线程一次一个 `pwrite`（`FileExt::write_at`）；全部完成之后才发屏障。屏障 = 回放盘上一次 `fdatasync`（`File::sync_data`）。32 这个队列深度两臂共用。`crates/` 今天是逐个同步写（第三节 `transaction.rs:3381-3387`），这个写法登记成反向取样点 G4（队列深度 1）。
- **取整**：E155 给的是期望值（小数）。每一批、每种单元按「整数部分 + 以小数部分为概率再加 1」取整，随机源是 splitmix64，种子 = (轮, 格, 臂) 的固定函数，照报。这样每格累计写出的单元数的期望与模型相等，第十一节 V9 核。
- **每种单元的期望个数从哪来**：E155 的函数交回的是每种单元的字节（两盘合计，按字节取整）；期望个数 = 这一种的字节 ÷ (单元宽 × 2)，小数精度到 1/16 384 个单元，够用。记录条数不用函数交回的期望，按这一批取整之后实际写出的单元、照各臂的点名规则现算：甲 ⌈W/67⌉，wal_full-K10 一批恒 1 条，乙-M-K10 ⌈实写脏叶数/67⌉，checkpoint ⌈这次写出单元数/67⌉；根槽、系统配置槽照 5.2 的「怎么做」。
- **批的形状怎么查**：甲与 WAL 臂一批的形状对 b = 1 … k 预先算好、缓存起来，这一格开跑之前算完，算的时间不计入任何 W。WAL checkpoint 的形状在 checkpoint 线程里触发时现算，算的时间计进 checkpoint 时长（不在批次的 W 里），另报。
- **已知与 `crates/` 不同的地方**（不当结果，第十一节 S1 不比这几样）：落点地址（装置用顺序游标，`crates/` 取最低空槽，见 `allocator.rs:1-11`）；每批的记录条数（装置按 ⌈W/67⌉，`crates/` 只有一条记录的路径）；共享脊柱下一批 b 个文件按一个 b·d 条的连续组算（实际 b 个文件是 k 个相邻文件的子集，中间可能有空）。前两样两臂一样，最后一样对甲与 wal_full 都略微少算（对乙-M 少算得更少）。

| AA 同臂对照（噪声地板） | 甲在同一轮里跑两格（放在随机次序里不同的位置） | 主几何、k = 16 与 k = 1024 | 两格 W 中位之比每一轮落在 **[0.8, 1.25]** | 这一轮的噪声已经接近最小的一档照报门槛 1.25，这一轮不进判据（V6） |

- PC2 选 F1 而不选主几何的 F8A：F1 一次 fsync 只写一个数据单元，一批里固定开销（屏障、记录、根槽）占大头，组提交省下固定开销的效应在这一格上是确定的。F8A 一批里数据写占的比重大，组提交能省多少本身就是这个实验要量的，拿它当对照就是自己证自己。
- PC3 的门槛 0.9 意思是「随便从两格各抽一个样本，九成的时候甲那个更长」，两个方向都认（A ≤ 0.1 就是 WAL 臂更长），不押方向（第四节）。
- 「所有臂一起错」由第七节钉绝对值的锚点挡：块层字节数与 FLUSH 数逐格等于程序计数，程序计数等于模型期望（取整误差之内），PC1 钉死计时通路的 2 ms。

### 5.5 网格、到达过程、一格怎么跑

- **一格的时间**：先用 0.5 s 在回放盘上做一个参照探针（4096 字节写 + `fdatasync`，取中位，用来看设备有没有漂），再跑这一格 11 s：前 1 s 预热，样本只收 `t_issue` 落在 [1 s, 11 s) 里的。WAL 臂的 checkpoint 计时器从这一格开始时起算，所以窗口里有 5 s、10 s 两次 checkpoint。格与格之间空 2 s。
- **主网格**（第一段）：3 条臂（甲与两条 WAL 臂，两条都留）× k ∈ {1, 2, 4, 8, 16, 64, 256, 1024} × 组提交开 × 闭环 × 主几何。
- **对照**：PC1 × 3 臂；PC2 × 3 臂 × {开, 关}；PC3 × 3 臂 × k = 16（k = 128 附带）；AA × 2 格。**锚点格**（只数不计时，每轮开头跑一次、每格 2 s）：各臂在 F1、P = 1、k = 1 上各一格（B4、S1）。
- **开环 G8（另一种到达过程）**：到达是泊松过程，率 `λ_k = f × X_min(k)`，f ∈ {0.7, 0.3}。`X_min(k)` = 同一轮主网格里、同一个 k 上各臂闭环吞吐（窗口里完成的 fsync 数 ÷ 10 s）的最小值；所以 G8 的格排在这一轮主网格之后。两臂拿同一个 λ，也就是同样的负载。f = 0.7 是「最慢那条臂吞吐的七成」，排队稳定但批攒得起来；f = 0.3 是轻载，批多半只有一个。k 取 {1, 16, 256, 1024}。发出的线程：一个 `M = min(4096, max(64, 8k))` 个调用方的池，按到达序号轮流取，睡到排定时刻前 200 µs 再忙等到点。池里全忙时这次到达就晚发，晚的那段计进 W（`t_issue` 取排定时刻）；晚了多少另报（p50、p99、最大）。调用方线程（闭环与开环）的栈都取 64 KiB。
- **随机次序**：每一轮里各格的先后按种子为轮号的随机排列（G8 各格在主网格之后另排），排列本身照报。设备漂移、SLC 缓存耗尽、温度都随时间走，打乱次序是为了不让它们总落在同一条臂上。
- **轮**：跑 5 轮，每轮一次虚机启动（`VM_CPUS=8`、`VM_MEM=4096`、`VM_DISK_MB=5120`、`VM_DISK_PREALLOCATE=1`、`VM_TIMEOUT=3600`，内核取 `bash research/scripts/vm-kernel.sh --release $(uname -r)` 给的那个）。计时有真 I/O 与并发，是有变化的观测，要说「越线」就得每一轮都越线，要说「不越线」也得每一轮都不越线，两边都不满足记「不稳定」（`test-discipline.md`「单次观测不算数」）。

### 5.6 在被测进程里计时、结果怎么出来

- 时间全在来宾那个进程里取（第一节 W 的定义）。每个样本另外记这一批的三个时刻：收批时刻 `t_start`、持久点时刻 `t_durable`（甲是根槽的 `fdatasync` 返回；WAL 臂是第二道屏障返回）、放行时刻 `t_release`。于是 `W = 排队（t_start − t_issue）+ 发布（t_durable − t_start）+ 放行到醒（t_return − t_durable）`，三段的中位照报。**包含自检**：每个样本必须满足 `t_issue ≤ t_start ≤ t_durable ≤ t_release ≤ t_return`，不满足的样本不进统计，另外计数（第十一节 V5）。
- 样本全部留在来宾内存里，一格跑完再算分位数，每格只打汇总行（字段见第六节），再加一行对数直方图（桶宽 2^(1/16)）。**不打每个样本、不在转发输出的循环里打时间戳**（`vm-harness.md`「计时不在转发输出的循环里打时间戳」，第二节抄）；PC3 的 A 用两格的全部样本在来宾里算。
- 每格前后读一次 `/sys/block/vdX/stat`，差值和程序计数一起打出来（第七节 B5）。
- 宿主那一侧由 `research/scripts/e159-run.sh` 包着 `vm-bench.sh`，每次虚机启动前后各记一次：`/sys/block/nvme0n1/stat`、`/sys/class/nvme/nvme0/hwmon1/temp1_input`、`/proc/loadavg`、`ps -eo pid,etimes,pcpu,args`。宿主这块盘在这一轮里被别人写了多少，就从这里算（第十一节 V7）。

## 六、报哪些量与各自的判据

**记号**：格 c、轮 r（1…5）。`m_{c,r}` = 这一格这一轮窗口内全部 W 的中位；`q99_{c,r}` = p99。`R_r(k) = m_{甲,k,r} ÷ m_{WAL,k,r}`、`R99_r(k) = q99_{甲,k,r} ÷ q99_{WAL,k,r}`（同一轮、同一个 k、同一种到达过程与几何）。每条留下来的 WAL 臂各算一串，各判各的。

**规则 R（给一串值打走势标签）**：一串值按轴排好，第 i 步 `δ_i = v_{i+1} ÷ v_i − 1`。最后 3 步每步 δ ≥ +5%，记「随轴扩大」；最后 3 步每步 δ ≤ −5%，记「随轴缩小」；最后一步 |δ| < 5%，记「收敛」；都不是，记「其它」，并报每一步的 δ。

**五轮怎么合**：每个判定先在每一轮上各判一次。五轮都判同一个结果，才报这个结果；不一致就报「不稳定」，并列出每一轮的结果。

每个量各占一行、各报各的判定；合取留给人做。门槛逐个和第五节的臂定义并排核过：没有一个能从臂的定义推出来（M = 2 与 1.5 是政策线，0.9、2、[1.8, 2.3]、[0.8, 1.25] 是测量有没有判别力的闸）。

## 八、轨迹与几何敏感性

### 8.1 轨迹（被判定消费的量，不只报期末值）

装置里有四处拿一个量当谓词的输入。每一处都报三样：**吃光初始供给之后的峰值、为正的次数、期末值**。只报了期末值的量，正文里不许写「从来」「恒」。

| 谓词 | 它消费的量 | 报什么 |
|---|---|---|
| 组提交「发布者空闲 ∧ 队列非空 ⇒ 收批」 | 收批那一刻的队列长度 | 峰值；队列长度 > 1 的批数（攒起来了）；这一格结束时队列里还剩几个 |
| WAL 臂 checkpoint 触发 `(now − 上次 ≥ T_time) ∨ (切点以来的 journal 字节 ≥ T_dirty)` | 切点以来的 journal 字节 | 峰值；每 100 ms 采样一次，为正的采样点数；期末值；每次触发由哪一半触发（Q9） |
| WAL 臂「环里在飞记录数到上限 ⇒ 批次等」 | 环里在飞记录数 | 峰值；到上限的次数；期末值 |
| 在飞深度「最多两个」 | 甲的在飞批数、WAL 臂的在飞 checkpoint 数 | 峰值；等于 2 的次数；期末值 |
| 开环「池里有空闲调用方 ⇒ 按时发出」 | 空闲调用方个数 | 最小值；为 0 的次数（这时会晚发）；期末值 |

### 8.2 几何敏感性

| 取样点 | 改什么 | 方向（跑前的推断，不是结论） | 段 |

| G8 开环泊松 | 到达过程换成开环，λ = 0.7 × X_min(k) 与 0.3 × X_min(k) 两档（第五节 5.5） | 批攒得比闭环零思考小，轻载那一档多半一批一个：组提交摊得少 | 第一段 |

    out = [max(1, math.ceil(n / leaf))]
    while out[-1] > 1:
        out.append(math.ceil(out[-1] / internal))
    while len(out) < minimum:
        out.append(1)
    return out

    cov, res = leaf, []
    for n in lay:
        res.append(min(n, 1 + (g - 1) / cov))
        cov *= internal
    return res
