| 工作做完、意图未删 | 意图还在 | 续做一遍发现无事可做，然后删掉意图 |

不可能出现「意图没了但目标状态没达成」——**删除意图必须与最后一批工作在同一个事务里提交**。

1. **意图声明目标状态，绝不声明增量。**「把文件 X 截到 N 字节」可以重复执行，「再删 1000 个 extent」不能。
2. **续做是每次恢复都跑的常规动作，不是修复手段**（否则会出现「平时不跑、真出事时才第一次跑」的代码路径）。
3. **中间状态必须每一个都是合法的文件系统状态**——「删了一半 extent 的文件」本身就得合法。
4. **一批里每个动作施加时先核它要删的东西还在**（随 D5（快照 / 空间记账机制） 已定项 12）——幂等的字面：一批按批开始时的状态为几个意图各算一份计划、施加时不复核，两个区间重叠的级联会把同一块放两次，统计量减两次、I-3.1（已分配统计对得上） 红。

**范围重建 vs 逐项修改：两条都要有，且要有显式判据**（`.claude/rules/fs-design.md`「不追求万能方案」）：

| 走法 | 代价 | 适用 |
|---|---|---|
| 逐项修改 | K × 随机访问 | 受影响的 key 稀疏散布 |
| 范围重建 | N × 顺序访问 | 受影响的 key 在 key 序上连续 |

**真正的开关不是 K/N，是「受影响的 key 连不连续」**：连续 ⇒ 范围重建可整节点丢弃或重写；不连续 ⇒ 只能逐项。**由此得到一条布局规则：让一起死的东西在 key 序上挨在一起。**

- dirent 按 `(parent_inode, name)` 编 key → 删整个目录是范围操作
- extent 按 `(inode, offset)` 编 key → 截断是范围操作
- 同一快照的 key 带同一 snapshot 前缀 → 删快照有机会变成范围操作

**这顺带从结构上解掉了 whiteout 膨胀**：范围删除直接丢弃整个节点，不用插 N 个墓碑。

### 5.1 删除一个文件的过程（各臂共用）

1. mkfs → 可写挂载（K 经开关链装上，5.4）→ 写第一个文件 N 个数据单元（`publish_first_file` + `publish_sequential_write`，式子那一判开着；写不进记「这一格写不进 N 单元的文件」，不进 Q1 判定）。**这一步起环窗口真扣**（D28 已定项 1 的「从第一个文件版本那次发布起计」），所以窄盘比原登记更早写不进（5.7）。
2. 关进程、重开可写挂载一次（让分配器装上从盘上读来的根环表）。
3. 按 5.3 把池压满。
4. 删。**A 臂（装置逐批驱动）**：`publish_unlink_intent`（意图）、再 `publish_unlink_step` 到 `deleted_inodes` 空，每步之间装置自己读分配器。**B 臂（会话）**：一次 `publish_user_change(UserChange::Unlink { inode: 1, write_time_seconds })`。两条臂的删除各批都不判式子那一判（core 内置，`transaction.rs:13454`）；装置断言删除路径上交回的每个拒绝的 `judged_short_by` 都不是 `FormulaAvailableAgainstDemand`，是就停 S9。
5. 每次删除发布之前读 reserve_t、RW_t、CR_t（按 1.1 的读法）、free_before_t、deferred_before_t、落点需求 D_t（`units_of_a_publish_to_land`），发布之后读 W_t（两盘）、free_after_t、deferred_after_t；A 臂逐次出 `E name=publish …` 行，B 臂每个发成的版出一行（只有 W_t、版序号，其余写 `unobservable`）。

### 5.2 臂

原 5.2 的 N-A、N-B、W-A、W-B 四条臂**定义不变**；核 core 之后，N 臂的账「待删占用 = 0、已承诺预留 = 0、环窗口 = 0」不再是 core 自己的账（core 现在记墓碑预付、扣环窗口），所以它只由 5.3 的压满目标构造：池被压到「不算环窗口、不算墓碑预付」的可用 ≤ 0，等于把原登记的构造原样搬来。**补两条臂**，它们才是 core 今天的准入：

| 臂 | 压满目标（压满那一刻的账） | 删除某一批被拒时 | 谁认这条臂 |
|---|---|---|---|
| **N-A**、**N-B** | 同原 5.2：目标是 `capacity − allocated − unreclaimable − mount_time_commitment − isolated − checkpoint 保留池份额` ∈ (−16384, 0]（装置按 `DeviceAdmissionTerms` 各项自己重加，不调 core 的合计），即池里只剩保留量那么多空闲 | A：直接交回拒绝；B：会话推抬 F 再判 | 同原 5.2 |
| **R-A**（出货准入、直发） | 目标是 core 的 `AdmissionReading::available_on_each_device()`（`admission.rs:800`）每盘 ∈ (−16384, 0]：环窗口与墓碑预付都照 core 现行的算，池里剩的空闲 ≈ 保留量 + RW + CR | A：直接交回拒绝 | D28 已定项 1 的人：环窗口是「删除各批新写的兜底」，把池压到出货准入的可用 ≤ 0 之后，删除各批新写的槽不超出剩下的空闲，所以不被落点那一判拒 |
| **R-B**（出货准入、经会话） | 同 R-A | B：会话推抬 F 再判，推满仍拒才算拒 | 同上，且认为删除各批和普通用户改动一样享有推抬 F 的重判 |

R 臂是**真实基线**（这个项目实际出货的准入）；W-A、W-B 留在第二段，意义同原 5.2（另记的量取量到的 W_max，不是 core 的 W 式子）。

「怎么做 → 做完会怎样」的核对：R 臂的定义只推出「池里剩的空闲 ≈ 保留量 + RW + CR」，推不出「删除不被拒」「W_t ≤ W 式子」——这两句正是 Q3 真式子与 Q2 真路径要量的，不写进臂的定义。

### 5.3 压满

在分配器拷贝上把每块盘没挡的空闲槽标成已分配（只动分配器，不写盘），方向 F-end（从单元区末尾往前标，原 5.3；F-start 在第二段），直到该臂的目标落进 (−16384, 0]。标完断言：两块盘各自的目标量都在区间里，且 N 臂与 R 臂在同一格上标掉的槽数之差，与该格的 RW + CR 份额之差不超过 1 槽（两边各停在 (−16384, 0] 区间里，各有不到 1 槽的余量；超过 1 槽就停 S3n：说明环窗口或预付没按读数扣）。

- **K = 144**（产品）与 **K = 1**（只供测试的最小批）：理由和报告方式同原 5.4——没有条款定 K，K 是没扫就不许写进结论的旋钮，两列分开报，K = 144 是主判列，K = 1 是敏感性。K 经 `mount_writable_with_test_only_switches_and_deletion_switches` 装上；每格开头断言分配器上的 `deletion_switches().batch_size.data_units_per_batch()` 等于该格的 K，否则停。

### 5.5 阳性对照（每条臂都跑；换掉原 PC-noreclaim）

原 PC-noreclaim 靠补丁里的回收关闭开关；core 没有这个开关，也不加。换成两种只动分配器拷贝的构造，**对四条臂（N-A、N-B、R-A、R-B）每一条都跑**，在两个几何上：P1(S = 16) 与 P4(S = 4)，K = 1，文件取该组梯子里 4 × 3S 那一点（该点的 dry run 若被拒，往下取梯子上更小的点直到 dry run 做完；一个点都做不完记 V1）：

- **PC-排空短缺**：dry run（该格的 A 臂正常跑一遍，取 t = 0 的落点需求 D_0 与其余各行）之后，在同一格的新拷贝上：先 `reclaim_released_up_to(最新根的 txg, ReclaimedReuse::Immediately)`（`allocator.rs:2696`）把 defer 里的槽全部收回空闲（只动内存里的分配器；PC 格不判 checker），再把盘 0 的空闲标到恰好 D_0 − 1 槽。**必拒的推导**：盘 0 此刻空闲 + 能被任何抬 F 放出的槽 = D_0 − 1 < 意图那次的落点需求 D_0（defer 已空，抬 F 的空发布每次占的槽不少于它换下的），所以 A 臂意图那次被落点那一判拒，B 臂会话交回 `NoSpaceEvenWithEverythingAFloorRaiseCouldRelease` 或 `NoSpaceAfterRaisingTheFloor`。前提「抬 F 放不出更多」用读数核：排空之后 `deferred_slots()` 与 `isolated` 项都为 0，不为 0 就记 `pc_not_constructible` 并算 V1。
- **PC-整体下移**（只对 A 臂，B 臂看不到逐批读数）：dry run 的每一批取 m = min_t (free_before_t[盘 0] − D_t[盘 0])，δ = max(0, m) + 1；在同一格新拷贝上把盘 0 多标 δ 个空闲槽。**必拒的推导**：删除各批和 dry run 同一串（装置确定性，原 V5），直到某批空闲不够；在取 m 的那一批 t* 上空闲 − δ < D_t*，所以至迟在 t* 被拒。断言被拒之前每一行的 free_before 恰好比 dry run 小 δ、W_t 相等（`pc_trace_matches`），不等就停 S10。

判定：四条臂 × 两个几何 × 两种构造（PC-整体下移只有两条 A 臂）= 12 格，每格都要出拒绝，种类对（A 臂：`judged_short_by` 为数据单元那一样或提交内生块那一样，即落点那一判；B 臂：上面两种会话拒绝之一），一格不出整轮作废（RV1）。B 臂的拒绝种类读法延伸原 U12 读法乙（拒绝出自会话那一支），在 `name=positive_control` 行打 `refusal=`。

### 5.9 每片峰值怎么量，量完怎么改内存表第 17 行

「片」= 装置一个梯子组（盘大小点 × S × K × 臂），是装置按内存上限定同时跑几片的单位（原修订 12；`PEAK_BYTES_OF_ONE_LARGE_SLICE` 注释）；大片 = P4 的组。服务的内存上限由第 17 行给，装置自己按 `E168_MEMORY_CAP` 与那两个常量排片，所以每件峰值和底座必须是量的数。

装置加两样（改装置的一部分，执行员写）：`segment1` 与 `positive-controls` 收一个 `--group <臂>-K<批大小>` 选项（只跑该几何里这一组），与 `--except-point <点名>` 选项（跑除该点外的全部几何）；进程结束前把 `/proc/self/status` 的 `VmHWM` 与 `VmRSS` 写进**标准错误**一行 `E168-memory label=<标签> vmhwm_bytes=<字节> vmrss_bytes=<字节>`（不进产物，不进 exact 比对；计时与计量都在被测进程自己里取，不在转发输出的循环里）。线程固定 `E168_THREADS=1`、`E168_LARGE_SLICE_THREADS=1`（量单片）。

def root_level(abs_slots, ndev=2):

    while ndev*-(-abs_slots//span(R-1))>FAN: R+=1
    return R

## 十四、并行与挂钟

独立单位：装置的单位是梯子组（盘大小点 × S × K × 臂），组与组互相独立，各自在自己线程上建池（线程局部状态），按片的次序整片打出（原修订 12）；几何（P0 / P1 / P2w / P4 各两个 S）之间也独立，可分成各自一条 `--geometry` 命令；5.9 的峰值测量 18 条命令彼此独立。
线程：31（取登记值 `.claude/heavy-thread-default`，装置读 `E168_THREADS`，没设取 `SINGLEFS_THREAD_CAP`，再没设取登记值）；P4 的大片按内存上限限并发，一次几片由装置按 `E168_MEMORY_CAP` 与 5.9 量出的每件峰值定。
串行：每个组内的删除发布一批接一批（后一批读前一批的结果）必须串行；阳性对照的 dry run 要先于下移 / 排空那一遍（后一遍用前一遍的 m 与 D_0）；第零段量完内存表第 17 行要先于第一段整段开跑（服务按那一行给内存上限）；其余（几何之间、组之间、峰值测量各条之间）都能并行。计时与内存读数都在被测进程自己里取（`VmHWM`），不靠转发输出的循环，没有因计时必须串行的步骤。
预计挂钟：态数 × 单态耗时（推的，没量过）：第一段删除发布约 35 万次（原补丁版整段 175835 次，实验页读数一节量的；臂多一倍）× 每次约 0.74 线程秒（原整段约 9 小时 × 4 线程 ÷ 175835，实验页「复跑」一节的 9 小时与线程数，推的）≈ 72 线程小时，除以平均在用约 20 核得约 3.6 小时，再加 P4 大片按内存上限排队，取 6 小时，范围 3 到 12 小时。各段：第零段约 2 到 3 小时（单测与变异证红约 1 小时，峰值测量 18 条并行，最长一条是 P4 的一个组，按原整段 9 小时里 P4 占大头、分到 16 个组估每组 0.5 到 1.5 小时）；第一段约 6 小时，范围 3 到 12 小时；第二段、第三段量到第一段的耗时之后再估。
预计在用核数：（推的）第零段峰值测量最多 10 条同时（每条一个线程，内存上限 50G 之内、每条约 4 GiB 的假设下），约 10 核；第一段小片 31 线程满开，P4 大片按内存限在 8 到 10 片，平均在用约 20 核，范围 8 到 31。
- 超过 2 小时的段（第一段）：**分片单元** = 一个组（`--geometry <几何名> --group <臂>-K<批大小>`，装置在 5.9 里加的选项）；**续跑入口**：装置再加 `--output-directory <目录>`，每个组跑完原子地写 `<目录>/<几何名>-<组名>.out` 与同名 `.done`，同一条命令重起时跳过已有 `.done` 的组、只补没做完的（被打断的组整组重做，组内不分段）；最后由执行员按几何、组的固定次序把各组产物拼成 `…-segment1-2026-11-10-r1.out`（拼法与逐字节相同判据同 E184 长跑拼产物，拼完补 `name=done emitted=` 行，照 `replay.sh` 的 `e168_wrap`）。组内不能再分段：一个组的 N 梯子一格接一格，后一格的 N 取决于前一格是否饱和（原 8.4）。K = 1 的 P4 大组是最长的单位，它的耗时没量过，量到之后在报告里写，若单组超过 2 小时再考虑按 N 点切片（那要改梯子的续加规则，属于改判据，不在这一次登记里做）。
