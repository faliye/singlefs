## 二、定案（第四版）

### P1 形态：inode 树 = 内部节点（码 2，派生态，不留缓冲区）+ 叶（码 3 打包记录单元，记录类型 2，权威态单元）；根恒为码 2

- **叶** = 一个 32 KiB 码 3 容器，装 233 条 140 字节记录（记录类型 2 由「保留」转「启用」；day-1 类型，不需要位）。
  叶自带类身份段、记录数、记录宽、载荷校验和；扫描路径上的载荷完整性证据（C104 对码 2 的洞）对它不存在。
- **内部节点** = 码 2 索引节点，派生态。**条目 = 分隔 key 8 + 身份引用 26 + 子指针 59 = 93 字节，扇出 175**（节点头 58 / 67 / 76 三档都是 175）。
  身份引用就是 D18 已定项 11 给「别的树引用容器」的那 26 字节（出生树 8 + 打包记录类型 2 + 容器号 8 + 容器出生代 8），不另发明一种。
  **类型段的值说明子节点是什么**：0 ⇒ 子节点是码 2 索引节点（容器号、出生代两段恒 0），2 ⇒ 子节点是码 3 容器。
  读者由此知道读一个槽还是两个槽，码 3 的 AAD 五段（标签由类型 ≠ 0 推出，其余四段照抄条目）全部来自查找路径（A6）——
  **不需要树的种类**。出生树逐条目携带，是因为克隆头（D6 已定项 1）共享 origin 的叶，同一个内部节点里会混着出生树不同的条目。
- **内部节点带 key 区间**（min / max 各 8，进 D18 已定项 7 的类身份段）。这是 D18 已定项 2 留给 inode 树的那一格，本项定「带」：
  理由与记账树同一条（F44，一个节点单独捡起来能自证覆盖段；key 是 inode 号不是文件名，敏感性论证够不到），代价是 0（三档头扇出都是 175，E103 单测钉住头 76）。
- **根恒为码 2 索引节点**，即使只有一片叶（第一个事务多写一个 16 KiB 节点）。理由 F33：树表指针不带类，根的类若随树长大而变，读者按 16 KiB 读 32 KiB 是静默误读。
  「先读 16 KiB 看偏移 6 再决定读不读第二个槽」这条替代路不取：它把每次叶读拆成两次 I/O，而且第一个槽读完还验不了单元。
- **容器索引就是这棵树的内部节点**，不另立树：物理指针只住内部节点；dirent 树引用的是 inode 号。更新一条记录 = COW 叶容器 + 全部祖先（D23 甲）。
- **内部节点不留消息缓冲区：inode 树的 ε = 0。这是对 D11 已定项 6「全部布局共用 ε = 0.65」的一次修订**，不再假装「不改」。
  理由不是性能：D11 已定项 4 让缓冲留在派生态的前提是消息能只从「单元 + 记账 + 墓碑单元」重算（F40），
  而 inode 属性更新在到达叶之前没有权威态载体，缓冲进派生态节点就撞 D21 硬约束 6。
  分支变量是「这棵树的叶是不是权威态单元」，按树恒定；过 `.claude/rules/fs-design.md` 五条硬要求：判据显式（叶的单元类）、
  测试能强制进入（建一棵 inode 树就在这条分支上）、单独验（E103 + 崩溃点重放各自）、可观测（节点布局）、操作中途不变。
  它落在 D15 第 4 层（派生态，不冻结），不是格式分支。D11 已定项 6 改写成「带缓冲的树共用 ε = 0.65；叶为权威态单元的树 ε = 0」，记历史条目。
- **态别按重算性判，不按「树」这个词判**。D21 补的那句改成：「态别按内容能不能只从权威态重算判：一棵树的内部节点可从它的叶重算 ⇒ 派生态；
  叶若装着算不回来的值 ⇒ 权威态。记账是这条判据的已定实例（离线可遍历重算，但被问到那一刻要有答案，故取权威态）」。
  v3 那句「态别的载体是单元类」会把码 2 的记账树判成派生态，与 D21 已定冲突，撤回。
- **内部节点丢了从叶重建**：收集记录类型 2 的容器，按 (出生树, 容器号, 容器出生代) 分组，同身份多版的择现行 = C113（本项不解，点名，并给它加一个实例，见 P5）；
  每叶 key 范围由记录算，内部节点的 key 区间由叶算。**记录数为 0 的类型 2 容器不落盘**（发布前必须合并掉）——否则空叶在重建时没有 key 范围。
  重建产物落 D18 已定项 5 的**级 1（只读挂载）**，级 2 的见证者今天不存在。
- **永久的字节**：记录格式（P6）、码 3 类身份段对类型 2 的用法、inode 树的 key 编码。**不动 D15 的四层**（把载荷记录格式塞进第 1 层会改那一层的定义与依赖理由）：
  本项定的记录格式**立成一个独立的已冻结组件**，C9 的 `spec_hash` 按组件记，冻结时刻是第一个写出类型 2 容器的镜像；
  类型 1（墓碑）的记录格式随 C84 各自独立，不因本项一起冻结。内部节点布局不永久（派生态整层退出冻结）。

### P2 不进本项的：树的种类、树 ID 的分配

- **树的种类不再是本项的前置**。第三轮找出它的三个消费者，三个都换了别的路：叶的类由条目的类型段给（P1）；AAD 期望值由条目给（P1）；
  nlink 那条不变量不在本项立（P7）。扫描重建靠码 3 头里的类型 2 + 出生树认领 inode 叶，也不需要它。
- **树 ID 的分配与编码规则**全仓无落点，卡第一个事务（三棵树都要 ID）。它今天只在 checks-owed 里以文字形态存在，31 号门禁看不到 ⇒
  **新开一条 D8 未定项 8「树 ID 的分配与编码」**，在那里判它改不改第一个事务的字节（改）。

### P3 装载纪律按记录类型分写（改 D18 已定项 11）

四条纪律里「② 一容器一个代际」与「快照发布前先关闭开放容器」**只对按代际回收的记录类型**（打包记录类型 1，墓碑）成立；
**记录类型 2 不适用**：inode 记录逐条死亡，容器由 B 树分裂 / 合并回收，一片叶活很多代、反复重写。按字面套用会禁止跨代际的叶合并、让树失去平衡能力。
D18 已定项 11 里「更新一个容器 = COW 它 + 改容器索引一条」**拆句不替换**：类型 1 照旧（容器索引独立存在，C103）；类型 2 = COW 它 + 改全部祖先。
C105 / C106 各拆成两支：类型 2 的容器数 = O(inode 数 / 233)，与活代际数无关；每次发布重写被碰到的叶，E103 第三臂量的正是它。

### P4 容器身份不需要分配器：容器号 = 触发分裂的那条新记录的 inode 号

- inode 号单调不复用（P5）⇒ **插入永远落在最右的叶** ⇒ 分裂只发生在最右叶，**分裂点取末尾**：左半保留全部原有记录与身份，右半从触发分裂的那条新记录起。
  右半容器号 = 那条新记录的 inode 号，出生代 = 本次发布的 checkpoint_txg。第一个容器的号 = 第一条记录的 inode 号（第一个事务里是 1）。
- **唯一性由构造保证**：每个容器号都是某一条记录首次插入时的 inode 号，而 inode 号在树内不复用 ⇒ 同一棵树里两个容器不会同号，
  同一次发布内「分裂 → 合并 → 再分裂」也造不出同身份两版（第三轮反推腿的反例靠「再次以同一个 key 分裂」，末尾分裂下那个 key 是新号，永不重复）。
- 合并：保留左半身份，右半退役走 COW 释放路径。合并时机是写路径策略（派生态，单测 / 模型对拍），不进格式。
- **两条不同的断言都写下来**：「容器被 COW 重写时身份不变」（D18 已定项 11 原句，内容同、位置变）与「分裂后左半身份不变」（本项新立，内容少了、身份不变）。
- D18 已定项 11 类身份段表偏移 53 那一行（F41「树内按类型单调分配」）**按记录类型分写**：类型 1 单调分配（C103 那套，回退不破身份）；类型 2 = 触发分裂的新记录 inode 号。
  C103 的检查列（「各 (树, 类型) 的最大容器号一致」）对类型 2 无对象，同样按类型限定。
- 可判的不变量（P7）：容器内每条记录的 inode 号 ≥ 容器号；沿叶序容器号严格递增，且左容器的最大 key < 右容器号。

### P5 inode 树的 key：`(inode)` 8 字节；inode 号单调不复用；水位是记账里的单调统计量

- key = inode 号；唯一性范围 (树 ID, inode)。**inode 号单调不复用**（F24 / F34 同一戒律）：`deleted_inodes` 后台回收窗口里复用会让新旧对象的 extent key 三段逐字相同。
  位宽 64、声明生命周期创建总数上界 2^63（F34 要求声明）。
- **下一个 inode 号是记账里的一条统计量**：key = (统计量「inode 号水位」, 树 ID, 设备段, 代)，**不带设备维**（D5 已定项 4 第 4 / 6 / 7 项的口径），value = 下一个可用号。
  **合并规则取最大值**（幂等、交换、结合）——合并结果不依赖 seq，不受 write buffer 排序丢时间序影响。
  **但条目照样带 seq**：D8 硬要求 3 逐字是格式要求（F43），一棵 write buffer 树一套条目格式，按统计量分两种布局是买不到失败模式改善的格式分支。
  这是 D5 已定项 3「后者胜」之外的第二种合并语义，只对单调统计量开放，写进 D5 已定项 4 的表（新第 12 项）与已定项 3；
  D5 已定项 4 的完备性口径照第 10 / 11 项的先例补一句「分配判定要它」。标签值随 C71（十一项今天都没分配）。
  E97 的 53% 按 2 项带树维算，第 12 项进来后带树维的是 3 项，上界 53% × 1.5 = 80%，仍在预算内；E97 未重跑，这句写进 D5。
- **克隆头**：新头的水位 = origin 那一刻的**运行时**水位（含还在 write buffer 里没落盘的那条），**建克隆那次发布必须为新树写出这条水位行**，
  否则新树的水位读出来是空，与 0 分不开。两个头此后各自分配，**号会相交**（都从同一个初值起）；唯一性靠 (树 ID, inode)，不靠号不相交。
  后果要写明：两个头共享 origin 的叶，各自 COW 之后是**同身份两版、同一个 key 装着不同对象**——判定归 C113（本项给它添的实例）；
  跨头首次 COW 时容器身份要不要重生（出生树改成新头）归 E90 第二笔（克隆祖先表，C110），本项不定。
  D5 没有「新建一棵树时它的记账行怎么初始化」这条，第 8 / 9 项也缺，本项把它列成 D5 的既有空白。
- **不变量**：水位 > 该树 inode 树内最大 key，> `deleted_inodes` 树内最大 key，> 该树全部墓碑记录的对象 ID（checker 遍历侧与运行时水位是两条独立路径）。
- 未发布的事务重发同一个号是安全的：水位与叶容器共用同一个发布屏障（未发布的不在根下，回到旧根看不见），未发布的事务等于没发生；
  若 write buffer 日后有独立于根的持久形态（D8 未定项 7），捡回来的水位只会更大，浪费号不复用号。

**预留 20 怎么来的，如实写**：预留宽度不承重——记录内任何赋义都是 incompat，宽度只决定那次要不要连记录宽一起改；
20 是 140 减去 120 个已定字节的余数，140 沿用 E98 / E103 / D18 已定项 11 三处已算过的几何。加宽记录能同时缩小爆炸半径（160 ⇒ 204 条），
这笔取舍归 C100，本项不拿「宁可写大」替它定。
**溢出路线按属性逐个判档，本项不预判**：无语义依赖的属性走新增 keyspace（D15 那一行给 compat），有依赖的走 flags 位 / 预留（incompat）；
属性 keyspace 今天没有落点（xattr 被推迟，D8:362），立成欠账，不写成「已有溢出路线」。
**记录宽必须等于登记表给类型 2 的宽（140）**，不等判损坏（写进 I-1.7，判定顺序在「类身份段」之后、「边界」之前插一步）；改宽是 incompat。
本项定的宽度全部登记 `format-const`：`INODE_REC = 140`、`INODE_INTERNAL_ENTRY = 93`、`INODE_LEAF_RECORDS = 233`。
