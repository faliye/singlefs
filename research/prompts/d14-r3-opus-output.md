# D14（双轨（大小文件 / 持久临时）） 未定项 2 第三轮——反推腿（Opus）报告

**立场**：假设候选甲（「第一版不做分配器提示，本项定否」）是错的，去找它错在哪。先攻装置，再攻条款。

**一句话**：甲的**方向站得住，四条支柱里三条站不住**。① 那个「99% 回落」是装置里一个从没被扫过的参数造出来的，
scratchpad 副本上把它换一个取值，同一条臂在 uniform 两格上回落变 0 而局部性一格不掉（实测，第二节）；
② 「没有消费者」半假——删目录腾出的段进「全空聚簇段数」，而那个量被两条用户定案读着；
③ 「家固定 = 创建时继承一次此后不改」这条判据一旦成立，甲自己写进条款的重开前置就永远满足不了，甲自相矛盾；

`.claude/kb/decisions/08-核心索引结构.md:207` 逐字「⚠️ 连带：第一版没有目录，而这个值按本项从父目录继承 ⇒ **没有父目录时取什么，也要一起定**。」
⇒ 按目录的提示在第一版**没有输入**，甲与乙在第一版写出的字节逐字节相同，E151 第四次跑的 54%–55% 对第一版不说话。

## 一、攻装置：五处，前三处让这次跑答不了它要答的那一问

### 1.1 t = 0 时五条臂逐格相同 ⇒ E122 的 `grouped` 不对应任何一条臂，它是**初始条件**

E122（按目录聚在一起买到什么） 的 `grouped` 逐字是「同一父目录下的对象在盘上连续」，
它的 `place` 把目录 d 的第 i 个文件放在 `unit = d * files_per_directory + i`
（现查 `research/e7-index-bench/src/bin/e122_directory_locality.rs:98-105`）。
E151 的 `Sim::new` 逐字注释是「初始布局：key k 住槽 k（顺序创建的形态），与 E93 逐字同一套」
（现查 `research/e7-index-bench/src/bin/e151_arrival_and_container_arms.rs:171`），
而目录 = `key / OBJECTS_PER_DIRECTORY`（同文件 410 行、445 行）⇒ **目录 d 初始占槽 32d..32d+31**。
两者是同一个排布。E122 的 `arrival` 在 `stride = 32` 时也是同一个排布（E122 正文与产物已记）。

在 scratchpad 副本上把 `directory_metrics` 的采样轮数扫成轨迹（改法见第二节抬头），t = 0 那三行逐字：

```text
0     uniform  first_fit  256       100         1          256
0     uniform  home_k32   256       100         1          256
0     uniform  hint       256       100         1          256
```

（列是 `t / load / arm / dir_runs / touch_mean / touch_max / chunks32`。）

⇒ **E122 量的那个状态，E151 按构造发给了每一条臂，包括减数臂。**
所以这次跑量的不是「按目录聚买到什么」，是「谁把一份白送的聚集守得住」。
E122 那一格的收益（`grouped` 16 段对 `arrival stride=1` 512 段，32 倍）在 E151 里恒等于 0，因为减数臂拿到的是同一份。

### 1.2 E122 的第二格收益（删目录腾整段）在老化下**每条臂都归零**，这次跑没有报出来

即**保住 256 里的 12 个，4.7%**。E151 正文报的 `single_directory_chunks_32` 11–12 对 0 看着是「11–12 比 0 好」，
放回初始值 256 才看得出两条臂都输光了。⇒ **E122 那两格收益，第四次跑实际上把第二格判成了 ≈ 0，而正文没这么写。**

### 1.3 `directory_runs_total` 量的量与它的名字不是一回事，而正文引的是弱的那个

E151 正文与背景材料把 `directory_runs_total` 叫「**目录遍历段数**」，
而装置里它逐字是「每个目录成员按槽排序后的连续段数之和」（`e151_arrival_and_container_arms.rs:463-464` 的文档注释与实现）——
是**槽相邻性**，不是段。段的那个量叫 `segments_touched_mean_percent`。两个量给出的倍数差一个数量级：

| 量 | first_fit | directory_home | 倍数 |
|---|---|---|---|
| `directory_runs_total`（正文叫「目录遍历段数」）| 8025 / 8028 / 7956 / 7960 | 4420 / 4406 / 4310 / 4315 | **1.8×** |
| `segments_touched_mean_percent`（真的段数 ×100）| 1986 / 1986 / 1972 / 1972 | 167 / 168 / 192 / 192 | **10.3×–11.9×** |

（四格顺序：uniform M=0 / uniform M=9 / runs8 M=0 / runs8 M=9，整行抄自
`research/results/e151-arrival-and-container-arms-2026-09-13-directory.out` 的 `name=directory` 行。）

⇒ 背景材料第一问那句「目录遍历段数是减数臂的 54%–55%」用的是 1.8 倍那一个。
**这一处对甲不利**：真按段粒度读，家固定的臂买到的是 10 倍不是 1.8 倍。
⚠️ 但它与 J1 抵消——10 倍的那个量今天没有消费者（第四节）。

### 1.4 H1′ 的坐实门槛就是被测臂的定义，它对这条臂没有判别力

`research/prompts/e151-r4-prereg.md` 里 H1′ 逐字：
「提示臂的 `segments_touched_max` ≤ 3（**家 + 溢出 + 至多一处回落**）且 `segments_touched_mean_percent` ≤ 300，而 `first_fit` 的最大值 ≥ 10」。
而同一份登记里那条臂逐字是「目录的「家」是**两个固定的段**——它初始所在的段……与一个溢出段」。
⇒ **「≤ 3」= 「2 个家段 + 1 次回落」= 把臂的定义换成判据写了一遍。**
轨迹产物显示 `touch_max` 从 t = 2 起就恒等于 2，2000 轮里一次没动过。
`.claude/singlefs-ai-sop/rules/test-discipline.md`「检查本身也可能是错的」逐字要求「写完一个检查就问：被测对象真坏了，它会不会红」——
H1′ 对 `directory_home` 答不上来。而产物里 `name=directory_answer` 那一行五个答案里
`home_stays_in_few_segments_in_every_cell=true` 是**唯一一个 true**，也就是说这一轮唯一的正面结论出自这条判据。

### 1.5 H1′ 与第二条臂是看了数之后补的——三步走完了，但补出来的那条判据是空的

`.claude/singlefs-ai-sop/rules/evidence-discipline.md`「臂的定义也在跑前写死之列——失败条款打中的时候怎么办」
给的合法出路是三步：**记一次输 / 只许收严 / 写明收严在哪**。逐条核 `research/prompts/e151-r4-prereg.md` 文末那段修订：

| 步 | 做没做 | 依据 |
|---|---|---|
| 记一次输 | **做了** | 逐字「`directory_hint` 那条臂的单测（uniform、300 轮、M = 0）给出 `segments_touched_max` 21 对 `first_fit` 27、`directory_runs_total` 7713 对 7969」 |
| 只许收严 | **形式上做了** | 逐字「H1 原样保留，两条臂各自判」——H1 没放宽，新臂照旧被 H1 判（结果 54%–55%，H1 既不坐实也不推翻） |
| 写明收严在哪 | **做了** | 逐字「它是「从 key 算出来、每次分配现算、没有盘上字段」的形态，比 `directory_hint` **多要求一样：家不随回落漂移**」 |

⇒ **不算「先看数再改判据」的那一型**，三步齐。但补出来的 H1′ 落在 1.4 那一格：它是一条对被测臂无判别力的判据，
而这一轮唯一的正面答案是它给的。⇒ 判词应当是「三步合规，判据无效」，不是「程序违规」。
⚠️ 顺带：装置里那条单测 `directory_home_pins_directories_to_few_segments_while_member_hint_drifts`
逐行钉着 `assert!(home.directory.segments_touched_max <= 3)` 与
`assert!(home.directory.directory_runs_total * 10 > first_fit.directory.directory_runs_total * 5, "槽相邻性谁都守不住…")`——
后一条把 **H1 的失败**钉成了回归断言。钉住负结果本身没问题，写清楚就行；这里指出来是因为它说明写装置的人跑之前就知道 H1 不会过。

### 1.6 两组负载各偏向哪边——这一格对甲不利，正文没写

- **runs8 偏向提示臂**：`dirty_set` 的 runs8 分支逐字 `let start = rng.below(object_count); for key in start..(start + 8)`
  （`e151_arrival_and_container_arms.rs:663-670`），而目录是 32 个连续 key ⇒ 一次请求的 8 个 key 有 **25/32 = 78%** 落在同一个目录里。
  这等于把「一个目录成批重写」直接喂给家固定的臂。结果也如此：runs8 上它的 key 序 runs 6555 对 7997（少 18%）、`chunks32` 12 对 0。
- **uniform 偏向减数臂**：每目录每轮期望 64 / 256 = **0.25** 次重写 ⇒ 提示每次只放得下一个对象，聚不成批。
  结果：key 序 runs 8063 对 8186（打平）、`chunks32` 0 对 0。

⇒ 两组负载是两个端点，而 D25（目标负载优先级） 的负载表里**没有目录交错度这一维**，也没有「一个目录成批重写」这一维。
⚠️ 所以「54%–55% 两组负载都成立」这句话的强度比看着低：两组负载在**目录**这一维上是同一个形态
（目录恒 32 个连续 key、初始连续、不增不删），差的只是重写是不是成串。

## 二、攻「代价」那一句：99% 是一个从没被扫过的参数造出来的

### 2.1 那个参数是什么

`home_segments_of_directory` 逐行（`e151_arrival_and_container_arms.rs:435-442`）：

```rust
    fn home_segments_of_directory(&self, directory: usize) -> [usize; 2] {
        let object_count = self.last_write.len();
        let home_segment = directory * OBJECTS_PER_DIRECTORY / self.slots_per_segment;
        let home_segment_count = object_count / self.slots_per_segment;
        let overflow_segment_count = (self.slot_count - object_count) / self.slots_per_segment;
        let overflow_segment = home_segment_count + home_segment * overflow_segment_count / home_segment_count;
        [home_segment, overflow_segment]
    }
```

`overflow_segment_count = (10240 − 8192) / 64 = 32` = **盘上全部空闲段**。
`home_segment * 32 / 128` 把 128 个家段摊到这 32 个段上、每段 4 个家段（8 个目录）
⇒ **第一轮的 64 次重写就把 32 个段全部碰过一遍**，`empty_segments` 第 2 轮归零（产物 `drained_at_seed0=2`）。
而 `allocate_bump` 要的是 `find_empty_segment`（`free_slots_per_segment == 64`）⇒ 提交内生块从此永远回落。

⇒ **99% 不是「家固定」这个政策的性质，是「溢出段 = 全部空闲段」这个取值的性质。**
E151 正文「它答不了的」第 7 条逐字写着「家固定那条把尾部全空段当溢出段，提交内生块因此几乎全回落——**是数不是取法**」——
这句话按下面的实测**不成立**：换一个取法，同一条臂在 uniform 两格上这个数就是 0。

### 2.4 溢出段来源的设计句与推导（J2 要的那一格）

**设计句**：家 = 创建时父目录的家段；溢出 = 尾部 `k` 个段，`k` 由挂载参数给，其余 `32 − k`（一般地
`(S − L)/G − k`）段**只给提交内生块的 bump 分配器**，前台提示不许碰；家与溢出都满才回落到 D3（空间分配） 已定项 8 第 1 条。

**要多大**：稳态下每个家段被挤出去的成员数 ≈ 1（家段初始正好满：64 槽住 2 个目录 × 32 个成员；
COW 重写先占新槽、旧槽本轮末才进 defer ⇒ 每个家段常驻 1 个成员在外）。128 个家段 ⇒ 约 128 个溢出槽 ⇒ **2 段**。
实测 uniform `overflow_slots = 300`（k ≥ 8 各档都是 300，已饱和到真实需求）⇒ **5 段够**，取 8 段有余量。
runs8 不一样：一次请求 8 个连续 key 同时挤出 7 个 ⇒ 实测需求 `overflow_slots = 978`（k = 32）
⇒ **≥ 16 段**，而 k = 16 时已经开始溢出（`hint_fb` 8451、`touch_max` 10）。

**守不守得住 ≤ 3 段**：

| 负载 | 能留给提交内生块的段数 | 那时 `touch_max` | 判 |
|---|---|---|---|
| uniform | 24（k = 8）| **2** | **守得住**，且 `dir_runs` 4435 对 k=32 的 4406，差 0.7% |
| uniform | 16（k = 16）| **2** | 守得住，`dir_runs` 4425 |
| runs8 | 16（k = 16）| **10** | **守不住**——越过 H1′ 自己写的推翻线「`segments_touched_max` > 5 ⇒ 家守不住」 |
| runs8 | 24（k = 8）| **24** | 守不住，`dir_runs` 6317（只剩 79% 的减数臂，收益基本没了）|
| runs8 | 0（k = 32，入库那一格）| 2 | 守得住，但提交内生块回落 17808 / 18000 |

剩下的留给提交内生块就不够 ⇒ 这不是取值问题，是这条政策在 runs8 上的结构性代价。

### 3.1 不落盘：父目录关系与 `locality_id` 是**同一种**落盘，那一句就是为这种情形写的

`.claude/kb/decisions/14-双轨大小文件-持久临时.md:300` 逐字：

```markdown

```

家固定的提示要回答「这个对象的家段是哪个」，输入是「它属于哪个目录」。盘上表达这件事的只有两处，两处都已经为别的理由付过：

| 盘上表达 | 为什么已经付过 | 出处 |
|---|---|---|
| dirent 树的 `parent, name` → inode | 命名 | `.claude/kb/decisions/08-核心索引结构.md:133` 逐字「命名走 dirent 树（`parent, name` → inode），改名就是删一条加一条，**O(1)**」 |
| inode 记录偏移 16 的 `locality_id` | 改过名的文件要能重新编 key | `.claude/kb/decisions/08-核心索引结构.md:203` 逐字「⇒ **inode 记录必须存一份 `locality_id`**，否则改名之后数据只能靠扫描才找得到」 |

⇒ 「加字节数是 0 而仍然落盘」逐字命中。**与 2026-09-09 判掉 `locality_id` 的是同一句、同一种落盘。**
⚠️ 一条替 乙 辩护的读法与它的下场：*创建* 时父目录是请求参数（`create(parent, name)`），不用读盘。

### 3.2 每次分配都可以重新判：家固定与它**不矛盾，但掏空它**

E151 装置里家是 `f(key)`（`home_segments_of_directory` 只读 key 与几何常量）⇒ 每次分配都真的在重算 ⇒ 字面上「可以重新判」成立。
`.claude/kb/decisions/14-双轨大小文件-持久临时.md:301` 逐字：

```markdown

```

真实系统里家不可能是 key 的纯函数（key = `(locality_id, inode, offset)`，inode 单调不复用，
一个目录的成员 inode 不连续），只能是 `hash(locality_id)` 之类——而 `locality_id` 逐字「创建时从父目录继承，**改名时故意不更新**」
（`.claude/kb/decisions/08-核心索引结构.md:130`）⇒ 重算永远得到同一个陈值 ⇒ **掏空**，与 2026-09-09 判 `locality_id` 时同一个词。

⇒ **甲的支柱 ③ 成立，而它成立得太多**：D14 自己 287 行逐字「**将来真要做时的机制约束**：只能取「创建时继承一次、此后不再改」——」，
而 301 行逐字说这个形态「**恰好破这一句**」。两句放在同一条未定项里 ⇒ **判据集与机制约束不能同时满足**。
甲把那句机制约束原样写进「将来重开的前置」，等于写下一条**永远满足不了**的重开条件。**甲自相矛盾，这一格必须改写。**

### 3.3 硬要求 5：宽口径下乙违反，而 J2 的解法让它违反得更多

D3（空间分配） 已定项 8 那一节逐字记着上一轮定死的口径：「① 硬要求 5 取**宽口径**（「操作中途」），
