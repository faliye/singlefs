1. For P329, an I/O error during the rows publish causes missing rows for instances between the chosen root's instance and the new instance. Since no row exists for these instances, F2 considers them published, but they were never actually written. For P330, rows written for instances between chosen root and new instance being reclaimed leads to missing rows, causing F2 to incorrectly mark those instances as published. For Q330, journal records from an abandoned timeline with higher checkpoints cause the new instance's checkpoint to be set too high, leading to units from the abandoned timeline being incorrectly published. For R, journal ring wraparound causing lost journal records during replay results in T_pub being set incorrectly, leading to code-2 or code-3 units being marked unpublished when they should be published.

2. R cannot mark a unit referenced by the mounted root as unpublished because the published status for i == i_now depends solely on the mounted root's checkpoint, not T_pub. P330(2) cannot mark a unit of an abandoned timeline as published because the (i,0,0) rows for abandoned instances would require b <= 0 for code-2/3 units, but checkpoints start at 1. W still matters for code-1 units because it allows publication when n <= W even if b > T_pub, and the atomic publish ensures W is correctly set.

3. P329 costs an extra row and chain rewrite at every mount (except first after format) and one more switch reserve share. P330 costs an extra row and chain rewrite at every mount. Q330 costs a scan for journal records to compute the max checkpoint. R costs an extra row rewrite at every mount during replay. The bytes of the first transaction on the first mount do not change for any package.

4. For P329, a check that all instances between the previous and new instance have rows after a switch and crash; runs in an image checker. For P330, a check that instances between chosen root and new instance have (i,0,0) rows; runs in an image checker. For Q330, a check that the new instance's checkpoint is at least the max of all journal records after recovery; runs in multi-mount crash-point replay. For R, a check that the chosen root's row T_pub equals the checkpoint after replay; runs in multi-mount crash-point replay.

5. No package contradicts the admission rule, warm-up rule, rollback rule, root tie-break, or rows uniqueness rule. P329 enforces the admission rule, P330 handles rollback correctly, Q330 ensures checkpoint consistency, and R properly sets T_pub. The recommended combination is all four packages together.
