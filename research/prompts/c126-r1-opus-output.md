# C126（切换预留的最坏量没有口径）第一轮 · 反推腿（Opus）

立场：假定倾向甲是错的，去找能推翻它的观测。下面只交攻击与结果，不复述材料、不投票。
每条都标了「核过的」（附录逐字或本轮现查）与「推的」（我自己的推导）。

## 〇 一句话

**甲在两种读法下都站不住，而且是同一句没定义的话把它劈成两半的。**
「号 ≤ W 的事务的分配已随记录施加进重建态」这句话是甲的地基，它不是定理，是 C284（施加一条记录在指针层上做什么没有定义）那笔欠账的正题。
按写下来的那种读法（恢复路径不调用分配器），**重做会把重建态仍在引用、而且已发布谓词明令要留的块当空闲分配出去并覆写**——判据 3-1 的第二个析取支被构造出来了；
按另一种读法（施加登记落点），同一条记录点名的那批码 2 元数据也一起被登记成已分配，而已发布谓词明令「恢复实例重写它们」⇒ **重做要的是一整份新鲜的固定点空间，也就是乙。**
两条路都不给甲。

## 一 攻击 1（判据 3-1，主命中）：一条具体的序列，重做覆写了重建态仍在引用的块

### 1.1 这条攻击踩的四条已定条款（都是核过的，整句抄）

① 恢复只施加谁的记录 —— 附录 `23-journal的角色与格式.md:1177-1202`：

> **恢复只施加 `(实例代号, checkpoint_txg)` 严格大于所选根的记录；
> 陈旧 tail 只是「从哪开始扫环」的优化，不再决定重放集合。**

② 分配记录条目什么时候生效 —— 附录 `03-空间分配.md:205-276`（D3 已定项 7）：

> 条目改写与产生这次释放的 COW 在同一次发布里原子生效——分配记录是根下的 COW 树（D22（单元原子性怎么合成） 已定项 3），条目与根同一次发布

③ 已发布谓词按单元类分 —— 附录 `18-块里携带什么信息.md:759-897`（D18 已定项 11）：

> 有行 (i, T_pub, W)：码 1 ⇒ b ≤ T_pub ∨ n ≤ W（在所选根里，或被重放施加……），码 2 / 3 ⇒ b ≤ T_pub（**所选根之后的固定点单元一律未发布，恢复实例重写它们**……）

④ 重放不调用分配器 —— 附录 `23-journal的角色与格式.md:2-20` 那张表逐字一行是「重放要不要分配器 | **要** | 不要 | **不要**」；
本轮现查 `.claude/kb/checks-owed.md:276` C284（施加一条记录在指针层上做什么没有定义）的「怎么还」一栏逐字：

> 可判形式照 D13（验证路线） 已定项 1 的 M2：部分施加的结果等于某个整数个已提交事务的结果，且**恢复路径不调用分配器**

同一行的「卡在哪」一栏逐字：

> 而「施加一条记录」在指针层上具体做什么——换哪个指针、祖先谁来 COW、**落点谁分配**——全仓没有定义。D23（journal 的角色与格式） 开篇「重放不要分配器」与「只施加一部分事务就要重新生成祖先」互相顶着

⇒ 材料第 1 问括号里那句「号 ≤ W 的事务的分配已随记录施加进重建态」**恰好是 C126 之外另一笔欠账的题目**，不是一条可以拿来当前提的已定条款。

### 1.4 另一种读法：把它修好就变成乙

如果规定「施加一条记录时把它点名的落点登记进分配器」，矛盾没了，代价当场回来（`probe/mut-replay_registers_alloc.out`，整行抄）：

```
CONTRADICTION (keep AND free)            : []  count=0
redo needs 10 slots, allocator hands out [1012, 1013, 1014, 1015, 1016, 1017, 1018, 1019, 1020, 1021]
redo slots taken beyond the failed checkpoint's own footprint: [1014, 1015, 1016, 1017, 1018, 1019, 1020, 1021]  count=8
MODEL A OK under the other reading: 0 contradictions, but 8 FRESH slots needed (exactly the metadata the published predicate orders the recovery instance to rewrite)
```

8 = 被已发布谓词判成未发布、必须由恢复实例重写的那批码 2 单元数。**这一格就是「一次固定点重做的最坏量」，也就是乙。**

⚠️ 注意这两种读法**不能按单元类各取一半**：一条属于事务 41 的记录同时点名它的数据单元（必须留）和它的祖先节点（必须重写），
而「施加」是对整条记录的动作。要让甲成立，得另写一条「施加时只登记码 1 不登记码 2」的规则——仓里一个字都没有，而且它会把 C284 的题面改大。

## 二 攻击 2（判据 3-1，加重形）：择根退一格时，材料那句定理按字面为假

材料第 1 问逐字写「失败那次 checkpoint 的固定点单元、号 > W 的事务写出的单元，**从没进过任何已发布的分配记录**」。
这句只在「所选根 = 最新发布过的根」时成立，而附录 `18-块里携带什么信息.md:759-897` 逐字：

> 恢复恒选最新可读且自证通过的根，**它可以不是最新发布过的根**（槽坏了就退一格，之后的记录接不上就一条都不施加、W = 0）

⚠️ **材料的 P3 把这半句删掉了**（见第八节）。把它放回来，序列变成：

| 步 | 发生什么 |
|---|---|
| 1 | 实例 7。txg 100 发布成功（区域 100 mod 3 = 1）。txg 101 **发布成功**（区域 2）：它分配了 dev0 槽 7000..7001 给事务 50 的数据单元，并把 dev0 槽 3000 的旧版本释放进 defer，释放代 101。这两笔都写进了 txg 101 那一版分配记录树 |
| 2 | txg 102 开放，事务 51 单元写失败，探针写成功 ⇒ 实例切换 |
| 3 | 切换的恢复择根：txg 101 那个根槽这一次读不出来（区域 2 所在盘上那个扇区坏了，可写设备数仍够、不转只读）⇒ **择到 txg 100** |
| 4 | jsn 连续 ⇒ 施加 (7, 101) 与 (7, 102) 的记录 ⇒ W = 50；写行 **(7, 100, 50)** |

后果三条，方向各不相同：

| # | 后果 | 依据 |
|---|---|---|
| ① | dev0 槽 7000..7001 **进过**一份已发布的分配记录树（txg 101 那一版），只是没被载入 ⇒ 材料那句定理按字面为假 | D3 已定项 7「条目与根同一次发布」（核过的） |
| ② | 重建态的分配记录树来自 txg 100 ⇒ 7000..7001 无条目 ⇒ 分配器判空闲；而已发布谓词 n = 50 ≤ W = 50 ⇒ 判已发布、清扫不许碰 ⇒ 与攻击 1 同一个矛盾，**但这次被覆写的是一次已经向用户返回过的 fsync 的数据** | D18 已定项 11（核过的） |
| ③ | dev0 槽 3000 的释放代 101 没有载入 ⇒ 它在重建态里仍算已分配 ⇒ **永久泄漏**，直到 checker 全盘遍历 | D3 已定项 7（核过的） |

还有一条顺带的：行 (7, 100, 50) 一写下去，根环里那个 txg = 101 的根按回退候选集判据「(i, T) 可选 ⟺ …… T ≤ Ti」变成 **101 > 100 ⇒ 不可选**（附录 `23-journal的角色与格式.md:1177-1202`，核过的），
而 I-7.4（近 K 代块未被复用）的「有效」正是按这个候选集判 ⇒ **一次瞬时读失败把一个成功发布过的根永久逐出候选集，它独占的块随即可被清扫抹头。**
这一条不改变空间账，但它说明 T_pub 取「所选根的 checkpoint_txg」在择根退格时会追认一段并没有被抛弃的时间线。落成新欠账（第九节）。

## 三 攻击 3（判据 3-2）：链的**每一片**都有一条链指针记录，甲的式子少算

附录 `18-块里携带什么信息.md:759-897` 逐字两句：

> - `kind` = 1 链指针记录（**恒为一片的最后一条**）：`kind 1 | 有无下一片 1 | 位置指针 59 …… | 预留 3`。

> 一片 ⌊(32768 − 135) / 64⌋ = 509 条记录（含链指针；135 是含 nonce / MAC 预留位的码 3 头，已定项 14）；mkfs 写出一片空表，记录数 1（唯一一条是「无下一片」的链指针记录）

⇒ 一片装 509 条记录，其中 1 条是链指针 ⇒ **一片只装得下 508 行**。
甲写的是 `⌈(rows0 + k + 1) / 509⌉`，那是「整条链只有一条链指针记录」的算法。
正确的是 `max(1, ⌈rows / 508⌉)`。

产物（整行抄，`probe/baseline.out`）：

```
records per page = (32768 - 135) // 64 = 509
first row count where the two disagree: r=1017 (jia=2 pages, literal=3 pages)
rows0=    0  jia=  12 blocks   literal=  12 blocks
rows0=  508  jia=  24 blocks   literal=  24 blocks
rows0= 1016  jia=  32 blocks   literal=  36 blocks
rows0= 4064  jia=  96 blocks   literal= 108 blocks
```

**甲在 rows0 + k ≥ 1017 时开始少算，rows0 = 4064 时少算 12 个 16 KiB 块（96 对 108）。**
自证这个差就是那条条款造成的：把链指针改成「整条链一条」，两个式子逐格相等（`probe/mut-chain_one_link.out`，整行抄）：

```
first row count where the two disagree: r=-1
rows0= 1016  jia=  32 blocks   literal=  32 blocks
rows0= 4064  jia=  96 blocks   literal=  96 blocks
```

⇒ **最小改法**：式子写成 `Σ_{k=1..N_switch} 副本数 × 32768 × max(1, ⌈(rows0 + k) / (每片行数)⌉)`，
每片行数 = ⌊(32768 − 135) / 行宽⌋ − 1，行宽从 `INSTANCE_ROW_BYTES` 读，不写死。

**Σ 而不是 max 这一格甲是对的**（推的，但机制清楚）：每次写行 COW 重写整条链，旧链要等新根发布才释放；
而连续切换正是因为上一次重做没发布成功才发生 ⇒ 最坏情形下 N_switch 份链同时躺在盘上。

## 四 攻击 4（判据 3-3）：12 这个数是对的，但它是一个分辨不出任何东西的取样点

`Σ_{k=1..3} 2 × 32768 × ⌈(0 + k + 1) / 509⌉ = 3 × 65536 = 196608 字节 = 12 个 16 KiB 块`——算术没错。

**问题是这一格对三个不同的常量全都不敏感**（`.claude/rules/mutation-sampling.md` 的第三类）：

| 换掉哪个常量 | rows0 = 0 那一格算出来 |
|---|---|
| 每片 509（甲）| 12 块 |
| 每片 508 行（攻击 3 的正确口径）| 12 块 |
| C304（实例表链指针记录装不下 83 宽的指针）之后行宽 88、每片 370 条 / 369 行 | 12 块 |

产物（整行抄，`probe/baseline.out`）：

```
C304 recompute: kind=1 record = 1+1+83+3 = 88 bytes > 64; if the row widens to 88, records/page = 370, rows/page = 369
  and at rows0=0 the widened row still gives 12 blocks -> third constant the sample point cannot see
```

⇒ 判据 3-3 按它自己的问法（「12 个 16 KiB 块算错」）没被打中，**但它验不了式子**。
要验式子，取样点必须落在 rows0 ≥ 1017（两个分母分岔）与行宽变更之后（C304）这两处。这一条同样管 C126 自己要的判别力自证（第七节）。

### 5.1 第 1、2 项今天没有上界 —— 失败条款第二条被触发

材料的 P10 把 D16 已定项 5 那句话抄到「每次切换都要熬完 T_retry 再把在飞 checkpoint 重做一遍」为止，
而附录 `16-发布语义.md:104-177` 那一句后半截逐字是：

> 每次都要熬完 T_retry 再把在飞 checkpoint 重做一遍（T_redo），**而重做期间开放的那个 checkpoint 发布不了、只能一直攒**（第八轮反推腿 5.1）

⇒ 「一次固定点重做的最坏量」与「号 > W 的数据单元重写」这两项的规模，不是由 T_dirty = 2 GiB 罩住的，
而是由「**切换期间前台还能写进来多少**」定的；在飞深度只有两个（开放 + 发布中），触发条件成立也只能空转，攒的量因此越过 T_dirty。
它要多少字节 = (T_retry + T_redo) × N_switch × 持续写带宽，而附录 `16-发布语义.md:104-177` 同一节逐字：

> ⚠️ **本机持续写带宽没有实测**（E58（校验和粒度的端到端代价） 那个 2045 MiB/s 是校验和实验里的顺序口径，
> 不是写带宽，不许拿来换算），所以「5 秒能写多少字节」现在也算不出来。

⇒ **这一项的上界所需要的那个量，仓里逐字写着算不出来。**
按材料自己的失败条款第二条：「若 3-4 补出的项没有上界（随盘上内容涨）⇒ C126 只能收窄成「链重写有口径、另一项仍欠」」——**触发。**

### 6.1 ④ 展开：甲把那条已经被判过一次的不可逆环重新造了一遍

> **回收**：行可删当且仅当整轮清扫对**池中每一个落点**都得出了判定（读成功并按行判、已抹头、已被覆盖）且其中没有该实例的未发布单元、**那次清扫里没有任何一次读失败**（读不到不等于不存在，扇区维），**且全部设备在线**（设备维），且根环里没有该实例发布的根。

1. 每次非干净结束 / 每次切换 ⇒ rows0 加一，**单调不减**；

## 八 判据 3-5（journal 环）：算术与判定
