Section 2. Definitions to check the facts above against. These are close paraphrases of decision and invariant text that already exists in the project; do not assume the paraphrase is perfectly complete, but treat every qualifier below (words like only, never, before, exactly once, narrow, greater than or equal to) as load-bearing and do not silently drop any of them when you use these definitions in your answers.

D1 (rollback floor and reclaiming, decision D16 item 1). Reclaimable means released and release generation is less than or equal to max(F_生效, the oldest still-valid root remaining in the root ring). F_生效 (effective rollback floor) is an 8-byte value carried inside every root record; under normal operation it never changes, and it is only ever raised when admission control finds there is not enough space. The ceiling that a raise is allowed to target is the minimum, across devices, of (the newest persisted valid root on that device), further minimized against (the checkpoint_txg of the 4th most recent non-empty valid root across the whole pool, falling back to the oldest valid root if fewer than 4 non-empty valid roots exist). A raise only takes effect once every surviving device carries a persisted root whose own floor field equals the new floor; the effective floor visible after a remount is computed as the minimum, across devices, of the maximum floor value carried by any readable root assigned to that device. The rollback candidate set requires a root to be valid per the instance table and to have checkpoint_txg greater than or equal to F_生效.

D2 (allocation record rewrite policy, decision D3 item 7). Placement granularity is 16384 bytes. When a placement is released, its allocation record is rewritten in place to released plus a release generation, rather than being deleted; the record is left in the tree until the placement is reallocated, at which point the same record is overwritten again with the new allocation's data.

D3 (accounting rows, decision D5 item 4). Fourteen accounting statistics are tracked in total. Each statistic only writes a row for a given key when it actually has a value; reading a key that has no row means that statistic was never maintained for that key, and must not be read as zero.

D4 (invariant I-2.1, checksum matches content, invariants.md line 107). Any block that is referenced must have its checksum match its content. As of 2026-09-17, a note attached to this same invariant states that referenced is now defined relative to the I-3.1 candidate set of roots (D5 below): units referenced only by roots that are below the current rollback floor may already have been reclaimed and reused, so this checksum check is not run against them at all. The same note explicitly requires, as a regression test, that reclaiming a slot without first raising the floor, while some root that still references that slot remains in the candidate set, must make this invariant go red.

D5 (invariant I-3.1, allocated statistics match, invariants.md line 120). Allocated space statistics must equal the sum obtained by actually walking every reference in the pool. A note attached to this same invariant (dated 2026-09-14 and 2026-09-17) states the walk takes the union of references contributed by every root in the rollback candidate set, meaning every root that is valid per the newest root's own instance table and whose checkpoint_txg is greater than or equal to the newest root's own carried rollback floor F. Units referenced only by roots on an abandoned timeline are isolated by the shadow ledger and are not counted; units referenced only by roots below F may already be reclaimed and reused and are likewise not counted.

D6 (invariant I-5.2, free statistics match, invariants.md line 167). Free space statistics must equal total space minus allocated space, and this equality must be demonstrated by two independently maintained counting paths, never by defining one in terms of the other.

D7 (step 5 status paragraph, milestone file 02-second-txn.md line 189, current as of 2026-09-17). This paragraph, describing the current state of the code, explicitly lists two open decision points at its end: first, how the checker should recognize a non-empty persisted valid root (today this is done by checking whether some journal record matching that root's instance and checkpoint_txg has a nonzero transaction field); second, whether it is consistent with the stated policy (that F normally never moves except when admission control is short) for a newly established instance's very first root to write a value of F_生效 that is lower than what an individual surviving device had already been carrying.

D8 (step 4 status paragraph and decision D23 item 14, milestone file 02-second-txn.md line 160 and decision file 23-journal的角色与格式.md line 1209). The shadow ledger's isolation rule, as implemented, isolates only slots that are referenced by some root whose (checkpoint_txg, instance) pair is greater than the rollback target R_old, and that R_old itself does not reference (this is called the narrow reading). Decision D23 item 14 explicitly states that this narrow reading was chosen, on 2026-09-16, over an alternative broad reading (isolating every slot ever referenced by any readable root anywhere in the ring); the recorded reason for rejecting the broad reading is that it would let raising the rollback floor reclaim nothing at all, given the first version's ring only holds 24 slots of history.
