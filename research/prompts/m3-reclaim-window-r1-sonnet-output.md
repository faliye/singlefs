## 零、结论先写

1. **W1**：今天的实现会留下窗口外的有效根。条件是一次发布崩在「记录已持久、根槽没持久」，写行那次发布的 txg 因此从洞的后面接着算，洞那一槽里留着上一圈的根。
   这一条有三处旁证：代码推得出（第一节）、仓里已有两份测试盘面（第一节，没跑）、端口里 48 个场景 48 个都有。
   E139 r1 的假候选与不可恢复，在今天的实现上我**推不出来**：回退候选集的锚是现行那一版的 txg，恢复先施加记录，洞里的旧根不进候选集。
   有一处例外：池级 checker 候选过滤的锚是镜像里最新的那条根；镜像丢了一块盘、洞之后只发了两次发布时，这个锚会低到让旧根进候选集（端口 800 个点里 16 个，连崩两次写行 11 个）。checker 对缺盘镜像有没有入口，我没读。
2. **W2**：46 / 3 不是装置参数写错造出来的，也改不掉：把装置上能对上条款的几处（②③④⑥）改成条款的样子，还剩 6 行假候选、3 行不可恢复。
   五处丙里只有「回退候选集的下界」(⑥) 单独造出假候选（46 行变 6 行），而且方向与实验页写的相反；②、④ 单独改一点影响都没有；⑦ 在这些世界里走不到；「生效」(③) 单独改反而让假候选更多。
   3 行不可恢复与五处丙都无关：它们来自「推进 txg 再发」(D23 第 399 行的目标形态) 加上同一块盘连续写失败，幸存盘最新根落后 13 到 14 个 txg，超过一圈（12）。
   把失败处置换成今天实现的「原样重发同一个 txg」，或恢复之后接着施加记录，46 / 3 都变成 0 / 0（后一个是按构造为零，不算独立证据）。
3. **W3**：窗口照留、退回环里最旧有效根、窗口的锚改成「每个区域最新有效根的最小者」，这三个在我量过的世界里分别是：
   窗口照留在 D23 目标形上出局（46 / 3），在今天实现的锚上没有反例；环里最旧有效根 0 / 0，代价是洞之后一圈之内一直扣着已释放的块，而且要连 checker 一起改；
   锚改成每区域最新根的最小者 0 / 0，稳态与窗口完全一样，只在洞之后的头两次发布里把门槛压低至多 3 个 txg。「窗口长度加定值」不够，「长度随洞数加长」还剩 1 行。细节在第三节。

## 一、W1：今天的实现会不会留下窗口之外的有效根

### 1.1 前提（我读过、现查过的）

- 输入文件的 sha256 与快照一致：`sha256sum crates/singlefs-core/src/allocator.rs crates/singlefs-core/src/mount.rs crates/singlefs-core/src/transaction.rs crates/singlefs-checker/src/walk.rs scripts/experiments/e139_tightened_floor.rs | diff - research/prompts/m3-reclaim-window-r1-snapshot/crates-sha256.txt` 只多出快照里别的四个文件的行（`.out`、`e139-r1-prereg.md`、两份窗口判决），前五行逐字相同；`.out` 与 `e139-r1-prereg.md` 的 sha256 也与快照第 6、7 行相同。
- `crates/` 里没有降级挂载：`grep -rn -i 'degraded\|降级' crates/singlefs-core/src/*.rs | wc -l` 输出 `0`。一块盘丢了，在实现里表现为 `PoolReader::read` 返回 `None`，那一盘的根环槽全读成 `Unreadable`（`crates/singlefs-core/src/recovery.rs:1244` 起的 `read_root_ring_slot`）。
- 窗口谓词：「写成 txg + 3S > N，N < 3S 时整个环都在窗口里、不减出负数」(`crates/singlefs-core/src/root_ring.rs:120`)。区域 = txg mod 3、区内槽 = (txg / 3) mod S，所以 txg 与 txg + 3S 同槽。

### 1.2 洞是怎么留下的（K1）

1. 新实例第一次发布的 txg 取环里根与记录两样的最大值再加一：「新实例的第一次发布的 checkpoint_txg = max(根环里全部根记录的 txg, 环里全部自证通过的记录的 checkpoint_txg) + 1」(`crates/singlefs-core/src/mount.rs:1225`)。
2. 一次发布的持久顺序是单元、记录、根槽（`transaction.rs` 里记录先写每一块盘）：「CommitStep::WriteJournalRecordToEveryDevice {」(`crates/singlefs-core/src/transaction.rs:1145`)。崩在记录之后、根槽之前，记录在、根不在。
3. 恢复由记录补出那一版：「施加一条记录 = 把所选根的这七个字段换成记录里的」(`.claude/kb/decisions/23-journal的角色与格式.md:451`)。于是那一版的 txg x 在记录里、不在根环里，下一次发布取 x + 1。
4. x 号槽里还是上一圈的根 x − 3S，它自证合法、按实例表有效。进程内回收门槛的锚是「这个进程记到的最新根」，挂载时是 x − 1，第一次记根（x + 1）之后锚到 x + 1，窗口 txg > x + 1 − 3S 把它排除在外。
   进程内记根的断言明说不许跳号：「失败的发布连这张表一起退回、重发用同一个 txg。跳号说明有一条根绕过了这几处」(`crates/singlefs-core/src/allocator.rs:1826`)，所以在一个进程里不会再出第二种洞。
5. 仓里已有这个盘面的两份测试，文档注释写得很清楚（我没编、没跑，只读）：
   「txg 7 的根一直留在 txg 31 那一槽里，是环里最旧的有效根，而 txg 8–11 已经离开根环」(`crates/singlefs-harness/tests/one_revolution_window_after_a_hole_in_the_root_ring.rs:7`)；
   「可写挂载（实例 2）恢复由记录施加出 txg 31 那一版，写行 txg 32、暖机 txg 33、34 盖掉 txg 8、9、10 的槽」(`crates/singlefs-harness/tests/one_revolution_window_after_a_hole_in_the_root_ring.rs:6`)；
   另一份 `rollback_target_outside_the_one_revolution_window_is_not_a_candidate.rs` 判回退到 txg 7 在任何写之前被拒。
6. 端口里的核对：`python3 probe_stale_root_exists.py` 输出 `scenarios 48 with a valid root outside the window after the mount 48` 与 `hole slot holds x-3S in 48 of 48`（模型目录 `out/probe_stale_root_exists.txt`）。
7. 实验页第 220、221 行说「同一个槽重写，不留洞，窗口恒等于整环」(`.claude/kb/experiments/139-按盘回退下界的收严形态.md:220`)、「今天的实现造不出这几行的洞」(`.claude/kb/experiments/139-按盘回退下界的收严形态.md:221`)。
   这两句只对「根槽写失败」这一种洞成立；崩溃之后由记录补出一版这一种洞，今天的实现造得出（上面 5、6）。执行员那句「今天的实现因此不留这种洞」推过了头。

### 1.3 五种形各留下什么

| 形 | 留下窗口外的有效根吗 | 依据 |
|---|---|---|
| K1：崩在记录之后、根槽之前，挂载由记录补出那一版 | **会**，一条（x − 3S，在 x 号槽里） | 1.2 的 1–6；端口 48 / 48 |
| 连崩两次写行：挂载 2 的写行也崩在根槽之前 | **会**，两条（x − 3S、x + 1 − 3S），门槛一次跳 3 个 txg | 同一条机制；端口 `k1_world.py --double 1`。零单元发布失败整个挂载返回错误、下一次挂载换实例代号：「零单元发布（`publish_without_units`）不经分配器、不冻结」(`crates/singlefs-core/src/transaction.rs:1166`)，所以洞在下一次挂载里接着算 |
| 挂载那一刻读不出的槽 | **不产生新的**。读不出的槽在进程内表里按它在窗口里能住的最大 txg 记；它真正住的若是窗口外的旧根，窗口外不进门槛 | `mount.rs:1680` 起的注释与 `allocator.rs:1863` 起的重读规则：「窗口外的不进窗口」。同一个槽以后读得出，也因为锚在现行那一版而不进回退候选集 |
| 被抛弃的根 | **不产生**：被抛弃的根按实例表就不是有效根，门槛不看它；它们占着自己那几个 txg 的槽，旧的有效根已经被盖掉。被抛弃的时间线里若又有一段没写根的 txg，就是 K1 | `allocator.rs:1052` 的 `AbandonedRoot => None`；隔离那一半归影子账，不在这一格 |
| 两块盘根环不齐 | 分两种。一块盘整个读不出：根环里没有新的窗口外根，但幸存盘上最新的根比最新发布的根低（区域归属 0 / 1 / 0，空洞再加 3）；端口里最多落后 5 个 txg（`out/probe_lag_max.txt`），远小于一圈 12。一块落后的盘又回来：`devices_without_the_selected_version`（`mount.rs:3805`）有一条逐盘判落后的路，我没读透，这一支**推不出** | 挂载那一刻的门槛锚在读得出的最新有效根（`mount.rs:1827`），比进程内的锚低，只会让门槛更低 |

### 1.4 各处判窗口的锚取什么（正推的关键）

洞里的旧根只有在「窗口的锚 < x」时才会落进窗口、成为候选；锚 ≥ x 时它被排除。今天各处的锚：

| 用到窗口的地方 | 锚 | 位置 |
|---|---|---|
| 挂载重建分配器的回收门槛 | 环里读得出的最新有效根 | 「N = 环里读得出的最新有效根的 txg（挂载重建分配器时取它、不取 first_txg − 1）」(`crates/singlefs-core/src/mount.rs:1827`) |
| 进程内回收门槛 | 这个进程记到的最新根；挂载时是 first_txg − 1 | 「窗口 = txg > N − 3S（3S 是环长）」(`crates/singlefs-core/src/allocator.rs:1039`)、`mount.rs:1948` |
| 抬 F 那一遍的门槛 | 现行那一版的 txg | 「let window_anchor = current.root.checkpoint_txg;」(`crates/singlefs-core/src/mount.rs:3030`) |
| **回退候选集** | **现行那一版的 txg** | 「锚 `window_anchor` = 现行那一版的 txg」(`crates/singlefs-core/src/mount.rs:5864`)，调用处 `mount.rs:6275-6282` 传 `current.root.checkpoint_txg` |
| 恢复择根 | 不看窗口 | 「三个区域全部槽逐个验自证校验和，取 `(checkpoint_txg, 实例代号)` 最大的」(`crates/singlefs-core/src/recovery.rs:1263`) |
| 池级 checker 的候选过滤、丁-defer | **镜像里最新那条根** | 「let newest_txg = roots[newest_index].2.checkpoint_txg;」(`crates/singlefs-checker/src/walk.rs:8014`)、「一圈窗口（D16（发布语义） 已定项 1）：N 取最新根（它按自己的实例表恒有效），3S 是根环槽数。」(`crates/singlefs-checker/src/walk.rs:8080`) |

回退候选集的锚是现行那一版，而现行那一版是恢复之后接着施加记录的结果，它的 txg 在可写挂载写完行那次发布之后不会低于任何一次已经消耗过的 txg，洞的 x 就在其中（写行之前，候选集与门槛的锚都还在洞前面，两边一致）。所以**在今天的回退路径上洞里的旧根永远不进候选集**。
记录写到每一块盘（`transaction.rs:1145` 起那一段），丢一块盘记录也还在；所以丢盘之后现行那一版仍是最新一版，不是幸存盘上最新的根。

回退路径还有最后一道关：目标引用的单元若仍分配、分配代与目标那一版账里的不同就拒：「Some(record) if record.generation != target_generation => {」(`crates/singlefs-core/src/mount.rs:6008`)；
已释放的进复活集、逐盘逐份验 CRC：「复活集里每个单元在每块盘上的那一份都要读得出、整单元 CRC-32C 与映射条目里的对得上」(`crates/singlefs-core/src/mount.rs:6038`)。所以就算候选集里混进一条单元已被复用的根，回退也是被拒，不会读出坏数据；但候选集本身就错了，checker 的 I-7.4 按候选集判，还是红。

### 1.5 E139 r1 的假候选与不可恢复，在这五形上

| | 今天实现的回退候选集（锚 = 现行那一版） | 池级 checker 的候选过滤（锚 = 镜像里最新根） | 恢复择根 |
|---|---|---|---|
| K1 | 推不出假候选（旧根 x − 3S 在 x ≤ 锚 的窗口外）；端口 800 个点 0 个 | 丢一块盘之后头两次发布里会：端口 800 个点 **16 个**（S = 4、16 各 8 个，都在洞之后第二次发布处） | 推不出不可恢复：择中的根被复用的点 0 / 800 |
| 连崩两次写行 | 同上，0 / 800 | **11 个**（S = 4 四个、S = 16 七个，都在第二次发布处） | 0 / 800 |
| 读不出的槽、被抛弃的根 | 不新增 | 不新增 | 不新增 |
| 两块盘不齐（丢一整块盘） | 同 K1 | 同 K1；checker 对缺盘镜像有没有入口**没读** | 择中的根要被复用，必须落到窗口外（落后 ≥ 3S）或被 F 越过：端口落后最多 5 < 12；F 的上限取「每块盘上最新的持久有效根」（`.claude/kb/decisions/16-发布语义.md:37` 第一句）不越过幸存盘最新根 |

不可恢复为什么推不出：门槛 = max(F_生效, 窗口里最旧有效根)，要越过择中的根 C，只有两条路：C 在窗口外，或 F_生效 > C。前者要求幸存盘最新根落后一整圈，今天的实现不推进 txg、一块盘的区域每三个 txg 必来一条，落后的来源只有区域归属与洞，端口里最大 5；后者被抬 F 的上限挡着。
E139 里那 3 行的机理见 2.4，它们靠的是「推进 txg 再发」，在今天的实现里没有对应物。

### 1.6 这一格的推翻条件

- 在真代码上构造出：K1 盘面加丢盘（或读坏最新根）之后，`roll_back_by_a_forward_publish` 放行了洞里的旧根，或 `choose_root` 择中的根的单元被复用。构造出一个就推翻「推不出」。
- 找到 `rollback_candidate` 的某条调用路径，锚取到比洞的 x 低的值（我只读了 `mount.rs:6275` 这一处调用）。
- checker 对缺盘镜像有入口并在合法镜像上判红：那就把上表右栏的 16 / 11 坐实成真误红；没有入口，则那两格只是「锚的定义不一致」，不是可达的红。
- 我这一格是读代码加端口，没有在真代码上量；判决里「W1 只抽了一次样」的写法适用于我这条腿。

## 三、W3：回收门槛取什么

### 3.1 先把「怎样的门槛才安全」推出来

回收的块是释放代 g ≤ 门槛 G 的已释放块。一个释放代为 g 的块被所有 txg < g 的根引用着，所以只要候选集里没有 txg < G 的根，回收就安全：**G 不能高于将来可能进候选集的任何一条根的 txg**。
候选集是锚 A 下窗口里的有效根。将来的锚 A 只会比现在低在「丢盘 / 根读不出」这类事件上：幸存盘最新的根不低于「每块盘最新根里最小的那个」，也不低于「每个区域最新根里最小的那个」（一块盘至少住一个区域）。
所以 **G 取窗口里最旧有效根时，窗口的锚只要取到这个最小值，就罩得住所有幸存盘子集下的候选集**；锚取现在的最新根则罩不住。D16 自己在正常卸载那一行写过同一个量：「丢一块盘时择的是剩下那块盘上最新的根」(`.claude/kb/decisions/16-发布语义.md:42` 同一句话的前半)。实现里这个量已经有：`newest_valid_root_txg_on_every_device`（「fn newest_valid_root_txg_on_every_device(」(`crates/singlefs-core/src/mount.rs:2475`)），挂载时只用它压卸载那一串的当场回收（`mount.rs:1871`）。
