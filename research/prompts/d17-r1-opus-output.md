### 1.1 mkfs 不写 journal 记录，这一条有条款，不只是装置

装置第 1598-1670 行整个 `fn mkfs` 里没有任何一次写落在 journal 区，而条款也这么说。D13（验证路线） 第 232-233 行逐字（整句抄）：

> **为什么是这个单元，不是更小的两块**：根槽的写者只有发布、mkfs 种子、实例切换/管理员回退三种，
> journal 环的写者只有发布与 tail 推进两种，**没有任何 btree 操作写它们**——状态变量集恰好被这个单元封闭，
> 一个不多一个不少。

「journal 环的写者只有发布与 tail 推进两种」⇒ **mkfs 种子不是 journal 环的写者** ⇒ mkfs 种根这条路径的步骤种类集合里没有「写记录」。

同一句还给出第二样东西：仓里已经把**根槽的写者枚举成三种**（发布 / mkfs 种子 / 实例切换与管理员回退）。一条已定项亲手把根槽的写者分成三类，而候选甲要把这三类算成同一个等价类。

## 二、第 1 问 / 判据 3-1：一对成员集合相同、段不同的序列

判据 3-1 的判红条件逐字是「有腿给出一对步骤序列：`CommitStep` 成员集合相等，而 P7 的崩溃状态集合（段的切法）不同」，触发观测是「两条具体的序列，各写出段」。下面给两条。

### 2.1 先给类型层的理由：集合丢掉的正是段需要的两样

D13（验证路线） 已定项 4 第 328-331 行逐字：

> **崩溃点重放要枚举的崩溃状态集合定义为**：屏障把录下来的写请求流切成段，一个崩溃状态是
> 「前若干段全部持久，当前段任意子集持久，之后各段全部没持久」；枚举的单位是**一次整写**。

「屏障把写请求流切成段」——段由**顺序**（屏障出现在第几次写之后）与**重数**（每段里有几次写）共同决定。集合两样都不保留：`{a, b}` 与 `{a, b}` 相等，无论 a 在 b 前还是后、无论 a 出现一次还是十次。

⇒ **「成员集合相等」在类型上就推不出「崩溃状态集合相等」**，这不需要反例，反例只是把它变成可核对的。

### 2.2 序列对：把两份镜像记录之间加一道排序点

两条序列都取今天这条线的第一个事务，唯一的差别是 journal 记录那两份镜像写之间有没有排序点。第二条不是我编的形态——它是 D17（实现分层与第三方管道） 已定项 1 第 142-146 行那三个合成手段里「双写」的执行形态：双写要买到东西，两份副本必须落在不同的段里，否则一次崩溃可以同时抹掉两份。

**序列甲（今天，E142（第一个事务的干跑） 主臂）**：

```

  ── FLUSH ──
段 2：W(rec @dev0), W(rec @dev1)               2 次写
  ── FLUSH ──
段 3：W_FUA(root @region1 slot0)               1 次写
段 4：W(sb @dev0), W(sb @dev1)                 2 次写
段序列 16+2+1+2 ⇒ 状态数 1+65535+3+1+3 = 65543（產物逐字 states=65543 closed_form=65543）
```

**序列乙（一条设备侧原子宽度达不到 512 的线，核心层按 D17（实现分层与第三方管道） 已定项 1 合成双写）**：

```

  ── FLUSH ──
段 2：W(rec @dev0)                             1 次写
  ── FLUSH ──
段 3：W(rec @dev1)                             1 次写
  ── FLUSH ──

段 5：W(sb @dev0), W(sb @dev1)                 2 次写

```

## 四、第 3 问 / 判据 3-3：合成会不会悄悄加步骤

判红条件逐字是「有腿证明 P2 的某个合成手段在 `CommitStep` 里必须是新成员」。三个手段逐个判。D17（实现分层与第三方管道） 已定项 1 第 142-146 行逐字给的合成手段是「达不到的由核心层合成（读回校验 / 双写 / 补一条日志）」。

| 合成手段 | 判 | 理由 |
|---|---|---|
| **读回校验** | **比「新成员」更糟：它落在 D13（验证路线） 已定项 4 的定义域之外** | 已定项 4 逐字「屏障把录下来的**写请求流**切成段」「枚举的单位是**一次整写**」——读不是写，录不进那条流，也没有「持久 / 没持久」这个二值。而读回校验在提交路径上买到的正是一个排序点：读回成功之后才发下一次写。段因此改变，而写请求流一个字节都没变 ⇒ **崩溃状态集合变了，成员集合没变，写清单也没变**。这一格连「加个成员」都接不住 |
| **双写** | **要新成员或者要新屏障，两条路都改集合或改段** | 若两份副本落在同一段，一次崩溃可以同时抹掉两份，双写什么也没买到；要买到就得在两份之间加排序点 ⇒ 段改变（第 2.2 节那对序列就是这个形状）。若把「双写」做成一个原子步骤，那它是一个新成员 |
| **补一条日志** | **是新成员，除非先承认「写 journal 记录」是成员** | 枚举里今天没有「写 journal 记录」这个成员（第 3.1 节）。补的这条日志要么落进一个不存在的成员，要么与被它保护的那次写落在不同段里（否则同样什么都没买到） |

**由此得到一条比 3-3 判红条件更硬的话**：取甲（失败模型轴恒为 1）不是把那根轴消掉了，是**把差额搬进第一根轴**——达不到单一失败模型的管道，它的差额以「合成步骤 + 新的排序点」的形式出现在提交协议里。而第一根轴的载体（`CommitStep` 枚举）今天不含任何合成步骤。

⇒ 「× 1」在形式上成立，实质上是把一个没人枚举的量乘进了 1。**这正是材料第 3 问自己担心的那一句**（逐字「若是，『× 1』仍成立，但步骤集合要把合成步骤写进去，否则第一条第三方管道出现时集合变了而枚举没变」）——我的判定是：担心成立，而且比它写的更宽，因为读回校验连「集合」这个形状都装不下。

## 七、最强的一条：这条枚举该被什么取代

### 7.1 判据该落在崩溃状态集合的**生成器**上，不落在步骤集合上，也不落在崩溃状态集合本身上

**凭哪些已定条款**：

1. D13（验证路线） 已定项 4 第 328-331 行逐字定义了崩溃状态集合，而它的全部输入是「屏障切出的段」与「每段里有哪几次整写」。
2. D12（目标介质） 债表第 2 条逐字「**每个提交协议结构等价类各跑一遍崩溃点重放**」——被这个数乘的对象就是「一遍崩溃点重放」，而一遍重放跑的就是一个崩溃状态集合。

⇒ 等价关系应当定义在「跑一遍」这件事上：**两条线同类 ⟺ 对最小封闭单元里的每一条写路径，两条线录出来的写请求流在「段边界的位置 + 每段内步骤种类的多重集」上同构。**

**为什么不直接说「崩溃状态集合的同构数」**：崩溃状态集合是 6.5 万级的对象（今天这条线 65543 个），拿集合本身做判据不可判定也不可门禁化；而它由段序列**完全生成**（D13（验证路线） 已定项 4 那条定义就是生成规则，E142（第一个事务的干跑） 產物逐字 `states=65543 closed_form=65543` 证明生成式与穷举相等）。⇒ 判据放在生成器上，既可判又与集合等价。

「最小封闭单元里的每一条写路径」这半句是必要的：D13（验证路线） 已定项 1 定的单元是「一次发布 + 一次崩溃 + 一次恢复」，而同一节第 232-233 行自己枚举了根槽的三种写者。**一条线的类身份要覆盖它全部的根槽写者，不能只覆盖发布。**

### 7.2 「每开一条线重算」的输入：两个候选都不可执行，可执行的是第三个

材料第 5 问问的是「判它 +1 用的观测是 P9 乙问的答案，还是只要 `CommitStep` 多了三个成员就够」。两个都不行：

| 候选输入 | 为什么不可执行 |
|---|---|
| P9 乙问的答案 | D22（单元原子性怎么合成）「未定项 6 的真正形状」一节第 938-953 行逐字「⇒ **这一项今天定不下来的原因不是证据不够，是它的前置是一张欠条。**」，那张欠条逐字是「zoned 那一类根会漂移，需要一套「**最新的根在哪**」的发现程序。」⇒ 拿它当重算的输入，等于把重算挂在一张从没兑现的欠条上 |
| 「`CommitStep` 多了三个成员」 | 枚举不是今天这条线的清单（第三节）。而且 zoned 那条线的成员集合今天**算不出来**：乙问未定 ⇒ zoned 上超级块槽与根环槽还是不是原地轮转未定 ⇒ zoned 线里「原地覆盖固定位置」这个成员在不在都未定。这就是为什么材料 P1 那一行只敢写「**至少**多出一个等价类」——「至少」两个字承担了全部内容，而条款要的是一个数 |

**可执行的第三个输入已经存在，而且是一条已定项要求的**。D17（实现分层与第三方管道） 已定项 5 第 126-129 行逐字：

> ⚠️ **录制钩子挂在块设备接口上，不是挂在操作 API 上**（正推腿指出）：一次「发布 / fsync」内部会发出
> 多次单元写、两道屏障与一次 FUA 写，钩子挂在 API 层就把那些中间崩溃点整个吞掉，
> 而 D13（验证路线）已定项 4 的枚举域正是那些原语。**实现要给出「一次 API 调用发了几个设备级操作」的读数**，
> harness 拿它比对录到的条数，对不上整轮作废——形态照 [vm-harness.md](../vm-harness.md) 那道完整性闸。

那份录制读数就是段序列的原始材料：它是机械产生的、每跑一次就有一份、不靠任何人记得申报——正是 D13（验证路线）「一」想要那道 grep 门禁买到的性质（逐字「**不靠人记得申报**」）的可执行形态。

⇒ **重算的输入应当写成：一条线开线时，跑一遍最小封闭单元的每条写路径，把录制流的段序列与已有各类的段序列比对；不同构即 +1，并把新的段序列登记进类清单。** 这条既是判据也是门禁，不需要先有 `CommitStep` 那个 `enum`。
