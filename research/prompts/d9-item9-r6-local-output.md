1. The container index is stored in a fixed location within the root ring. During lease signing, the system attempts to read the container index from this location. If the root ring container holding the container index is corrupted (e.g., due to a prior media fault), the lookup fails. The signer cannot verify the new conjunct, causing lease signing to abort. This breaks the requirement that lease signing must complete if slots meet all conjuncts. The smallest change is to store the container index location redundantly across multiple non-root-ring sectors (e.g., in the journal ring and a dedicated header), ensuring at least one copy is accessible during signing.

2. During unlock, the system begins returning lease slots to the free pool but crashes before completing. The next mount sees the lease slots still marked as reserved but not allocated. The space is not recoverable because the free pool update was incomplete, and the system lacks a transactional mechanism to detect and retry the operation. This violates the requirement that unused lease slots must return to the free pool at unlock. The smallest change is to log the free pool update as a transaction before modifying the lease state, ensuring crash recovery can replay the operation.

3. The rebuilt column is written into the lease area during the keyless mount. At unlock, a signature failure causes the move to be rejected. The rebuilt column remains in the lease area as invalid data with no distinguishing markers. Nothing can identify it as a rebuild because the system treats all lease area modifications equally during signature checks. This violates the requirement for rebuild-specific handling. The smallest change is to embed a unique rebuild flag in the lease area's metadata for rebuilt columns, allowing the system to recognize and process them differently during unlock.
