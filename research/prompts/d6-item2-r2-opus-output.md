## 一、打中①：理由一是循环论证 —— 「livelist 走 write buffer」是主 agent 自己加的

### 现查：那条硬要求的射程句逐字在哪一段、管的是哪些树

### ⇒ 假前提就在这里

> 走 write buffer，因而条目自带 `seq`。

## 二、打中②：就算硬要求 2 罩得到，它的机制在 livelist 上不成立

硬要求 2 不是凭空的，它整条的依据是 E14（I-3.1 的判别力：幂等完整值 vs 增量 Δ）。E14 自己的机制句逐字（`.claude/kb/experiments/14-I-3.1的判别力幂等完整值vs增量Δ.md`，「机制」一节）：

> - 幂等完整值形态：权威是内容（键 → 值）。账是它的缓存。
>   checker 遍历内容求和，与运行时那条「入缓冲时增量维护」的代码**不共享任何东西**——
>   两条路径独立，所以下刷侧的任何语义错都会让它们分叉。
> - 增量 Δ 形态：**账本身就是权威内容**，没有别的可遍历。
>   checker 唯一的重算办法是拿同一个累加函数重放同一份已持久化的 Δ 日志。
>   日志少了一条，两边都少那一条；符号反了，两边都反——**它在和自己比**。

**机制的成立条件逐字是「没有别的可遍历」。** livelist 不满足这个条件：

1. **D21（权威态与派生态的分界）`:22` 逐字**：「记账是同一条判据的已定实例：离线可由遍历重算，但被问到那一刻要有答案，故取权威态。」
   同一条判据施到 livelist 上：livelist 的内容 = 「头 H 自己出生、现在还活着的那批落点」= 遍历 H 那棵树、取 `birth > origin.txg` 的块。**这正是候选乙 的定义。**
2. **乙 就是那条独立重算路径。** D6（快照实现模型） 判据 2 逐字（`06-快照实现模型.md:111`）要的正是它：

**出处 `.claude/kb/decisions/06-快照实现模型.md:111`（整行抄）**

```markdown
| 2 | **决策路径增量 + 独立审计**：进入准入控制 / ENOSPC / defer 判定的记账量提交时增量维护、代价不随盘容量增长；且有一条**与运行时不共享判定代码**的独立重算路径 | D3（空间分配） 的准入控制；[checks-owed.md](../checks-owed.md) C12（增量语义共用） 与它在 bcachefs 已发生的同源失效 |
```

⇒ **一份 ALLOC/FREE 形态的 livelist 不会让任何 checker 失明**，因为 checker 手上有第二个权威（头自己的树），而 E14 那四格盲区的成因是「只有一个权威」。
⇒ 硬要求 2 在这棵树上**买不到它在记账树上买到的那个东西**，而 `.claude/rules/fs-design.md` 对格式分支的判据逐字是「看它能不能把『用错了』变成『挂不上』」——同一条精神：**买不到失败模式改善的约束，不值得付它的代价。**

⚠️ **这一条不否定「甲′ 也可以做成幂等完整值」**。它否定的是**理由一那条推导**：幂等完整值在这里若成立，得另找理由，不能靠硬要求 2。

## 三、打中③：理由二引的不是集合表示 —— E130 两条臂**都是**事件流

材料第 21-24 行：

> **理由二（实测）**：E130 量出 Δ 形态（`naive`）在 `n=65536 churn=16` 上条目数 `2162688` 而净活块只有 `65536` …… 恒 condense 形态同格逐字 `entries=65536 ... overestimate=1.0000`。
> **而「恒 condense 的 livelist」就是幂等完整值的集合表示。**

**最后那一句与装置的源码正面冲突。** 现查臂的定义（**材料的小节清单把它标了「抄」，而附录里没有它**，见第九节）：

**出处 `.claude/kb/experiments/130-每头一份livelist过不过有界销毁.md:35-41`（整段抄，未转述）**

```markdown
### 臂

| 代号 | 定义 |
|---|---|
| `naive` | 每次 ALLOC 追加一条、每次 FREE 追加一条，**从不 condense** |
| `condense` | 每次 ALLOC 追加一条、每次 FREE 追加一条，且结构条目数 > 2 × 净活块数时抵消一次，只留净 ALLOC |
| `no_structure` | 乙 的形态，**对照臂**（2026-09-10 已出局，放进来是给「甲多付了什么」一个减数）|
```

源码逐字（`research/e7-index-bench/src/bin/e130_livelist_bounded_destroy.rs:128-142`）：

```rust
fn condense(l: &Load) -> Reading {
    let raw = l.allocs() + l.frees();
    let net = l.allocs() - l.frees();
    let entries = condense_entries(raw, net);
    ...
        free_path_extra_bytes: LIVELIST_ENTRY_BYTES,
```

三件事当场坐实：

| 事实 | 依据 |
|---|---|
| `condense` 臂**每次 FREE 也追加一条** | `raw = l.allocs() + l.frees()` |
| `condense` 臂的释放路径**照样收 24 字节** | `free_path_extra_bytes: LIVELIST_ENTRY_BYTES`，产物逐行 `name=condense n=65536 churn=16 share=0.0 ... free_path_extra_bytes=24` |
| **没有任何一条臂**建的是「每次 FREE 当场删 key」 | 三条臂只有 `naive` / `condense` / `no_structure`；源码里 `幂等` 与 `集合表示` 各出现 **0 次** |

⇒ **`condense` 臂就是 D5（快照 / 空间记账机制）`:154-156` 写的那个 ZFS 形态**——「ALLOC/FREE 配对……可增量、可 condense」。
⇒ **E130 量到的 `entries=65536 / overestimate=1.0000` 是事件流 + 周期性抵消的读数，不是集合表示的读数。**
⇒ **理由二不支持 甲′，它支持的是主 agent 想否掉的那个形态。**

⚠️ 另有一处**用词漂移**：材料造了「**恒** condense」这个词，而装置的判据是 `if raw > CONDENSE_RATIO * net`（`CONDENSE_RATIO = 2`），**不是恒**。源码注释还专门写了它取不到 `(1, 2]` 那一段（`.claude/rules/mutation-sampling.md` 第三类）。「恒 condense」这三个字在 E130 全文与源码里各出现 **0 次**。

## 四、打中④：甲′ 不是 E130 验过的那个甲

D6（快照实现模型）`:160` 逐字：「**甲** 独立 livelist（ZFS 形态，**每头一份**）」。E130 的标题逐字也是「**每头一份** livelist」。

而 甲′ 是**一棵共享树，靠 key 里的树 ID 分头**。这不是同一个结构，两处可现查的证据：

1. `grep -n "tree_id" research/e7-index-bench/src/bin/e130_livelist_bounded_destroy.rs` → **0 命中**。条目宽的注释逐字（`:30-31`）：

```rust
/// 一条 livelist 条目：类型标签 2 + 物理指针 14（D19 已定项 4 的位置条目宽） + birth txg 8。
const LIVELIST_ENTRY_BYTES: u64 = 2 + 14 + 8;
```

**24 字节里没有树 ID，有 birth txg。** 甲′ 的 key 反过来：有树 ID 8，没有 birth txg。**两个条目一个字段都不重合地各改了一处。**

2. 由此，E130 报出去的每一个绝对值都换了口径：

| 产物里的数 | 它的算式 | 在 甲′ 下 |
|---|---|---|
| `worst_batch_bytes=221184` | `4096 × (30 + 24)`，24 = 条目宽 | 24 换成 甲′ 的条目宽（key 18 + value 至少 seq 4）⇒ **要重算** |
| `free_path_extra_bytes=24` | 同一个 24 | 同上，且 甲′ 释放路径写的是**墓碑**不是 FREE 记录 ⇒ **要重算** |
| C260（livelist 条目的预付没算进解开自己那个量） 的「每释放一个块多预付 24 字节」 | 同一个 24 | **同一笔账，另一个数** |

这正是 `.claude/rules/mutation-sampling.md` 第五类的形态：**同一个物理量两个口径，而它们在基线那一臂上恰好同值**——两条 livelist 臂的 24 相同，于是没人再去查换了结构之后还等不等于 24。

### ④ 的要害：E130 判据 2 的前提被 甲′ 击穿，而击穿方式与杀死乙 的那把刀是同一把

E130 判据 2 逐字（材料附录里有）：

> | 2. 批前预留算得出，且不读活树 | 单测 `livelist_pre_reserve_does_not_read_the_live_tree`：净活块数相同、活树规模差一倍的两格，**两条 livelist 臂的 `pre_reserve_bytes` 相等** |

在 甲（每头一份）下，「这个头有多少条目」是**结构自身的计数**——那份结构就是这个头的，条目数是它的属性。
在 甲′（一棵共享树）下，「头 H 有多少条目」**不是任何结构自身的计数**：它是一棵共享树上一个前缀区间的基数。要拿到它只有三条路，三条各自撞墙：

| 路 | 撞在哪（逐字） |
|---|---|
| 范围计数（数 `树 ID = H` 那一段） | 那是遍历，且发生在**写意图那一刻** —— 与 乙 出局的理由**逐字同形**：D6（快照实现模型）`:160`「乙 在写意图那一刻给不出这个数（那正是遍历还没做的事）」 |
| 新立一个带树维的统计量 | D6（快照实现模型）`:160` 逐字「能当上界用的每树字节总量是已定项 4 第 8 / 9 项，2026-09-06 已撤回、编号不回收」；同处逐字「**乙 的出路只有一条，且要另立**：恢复一个带树维的字节统计量等于重开 D5（快照 / 空间记账机制） 已定项 4 的那次撤回」 |
| 塞进树表条目 | 树表条目已定死 121 字节（D8（核心索引结构） 已定项 8），**预留 32 已被 C144（快照谱系的区间标号没有载体）(16) + C145（deadlist 在盘上没有落点)(8) 认购 24**，只剩 8 字节余量；同处逐字「已知欠账就已经超额认购 8 字节」是它上一次扩宽的理由 |

⇒ **主 agent 拿 E130 的判据 2 给 甲′ 背书，是把「每头一份」那个结构的性质搬给了一个没有那个性质的结构。**
⇒ 若走第二条路，甲′ 就要走 乙 被判出局时**唯一那条出路**，也就是重开一次 2026-09-06 的撤回。那样一来，**乙 出局的理由同时失效**——第一轮的判决要一起重开。

## 五、打中⑤：集合表示丢什么、谁在消费（材料判据 3）

### 丢的是 birth txg，也就是「同一个落点历任占用者」的分辨力

甲′ 的 key = `(头的树 ID 8, 设备身份 4, 16 KiB 槽号 6)`，`key 在 = 活着`。这个 key 里**没有一位表达 birth**。而 D5（快照 / 空间记账机制）`:154-156` 给 livelist 的形态逐字含「**按 birth txg 分组**」，销毁时要释放的逐字是「`birth > origin.txg` 的那批块」。

### 具体构造（带 txg、带落点、带崩溃点）

设备 `d = 1`，头 `H` 的树 ID = 7，origin 快照 `O.txg = 50`，`H.prev_snap_txg` 初值 50
（D5（快照 / 空间记账机制）`:150-151` 逐字：「新克隆的 `prev_snap_txg` **必须初始化为 origin 快照的 txg**——置 0 则克隆里删一个继承来的老块会算出「立即释放」，**数据丢失**」）。

| txg | 事件 | 事件流形态（E130 那个 24 字节条目） | 甲′ 集合表示 |
|---|---|---|---|
| 100 | H 在槽 `0x1000` 写出 B1 | `ALLOC(dev=1, slot=0x1000, birth=100)` | 插 key `(7,1,0x1000)` |
| 120 | **对 H 建快照 S1**（D16（发布语义） 新规则 1：快照点落在 checkpoint 边界）。`H.prev_snap_txg` 变 120 | 无 | 无 |

## 六、打中⑥：恒 condense 不是免费的 —— 「删 key」的物理形态是**追加一个墓碑**
