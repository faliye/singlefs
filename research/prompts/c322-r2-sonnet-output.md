### 2. 那个单元的写序实例代号是新号还是旧号

**新号**（本实例这次取号取到的那个），不是旧号。依据两条：一是 D18 已定项 11「与第一个新根同一次发布」——实例表行写的对象是**上一个**（被恢复 / 被切换走 / 被回退掉）的实例（[所选根的实例, 新实例) 这个区间），但**承载它的那个单元本身**是在新实例的上下文里被写出的，写序字段记的是「谁写的」不是「记的是谁」；二是第一轮反推腿的构造（`c322-r1-opus-output.md` 第 140 行）显式验证了这一点：「第二次挂载：恢复择 (1, 3)；取号 = max(超级块 1, 根环 1) + 1 = 2……接着第一次发布（txg 4）先写实例表单元（行 (1, 3, 0)）两份」——这里明写实例表单元的写序实例代号是 **2**（新取到的号），而它记录的行内容是关于旧实例 **1** 的。两者是不同的轴，不能混。

### 3. 孤儿翻成「已发布」之后，扫描重建或别的路径能不能观测到错

**谓词翻面本身已经是错，这一半不需要更多证据**。D18 已定项 11 的已发布谓词逐字（背景材料 1227 行，与 `.claude/kb/decisions/18-块里携带什么信息.md:879` 相同）：「i == i_now ⇒ b ≤ 挂载根的 txg；i > i_now ⇒ 判损坏」。撞号之前（挂载根仍是旧实例），那批孤儿的 i(2) > i_now(1)，判「损坏」；撞号之后（新实例复用了同一个号 2），i(2) == i_now(2) 且 b(4) ≤ 挂载根 txg，判「已发布」。同一批字节，谓词从「损坏」翻成「已发布」——这直接违反 I-1.2（块头写序已发布） 的设计初衷（第一轮反推腿的原话，`c322-r1-opus-output.md` 第 159 行：「I-1.2（块头写序已发布） 的扫描方向依据『判不成已发布者必是未发布的撕裂事务垃圾』在这批孤儿上反过来了」）。这一半不用再验，它是谓词定义的直接代入，不依赖任何未建模的假设。

**下游会不会读出错数据，是推理，第一轮自己标了「没建模」**（`c322-r1-opus-output.md` 第 160 行：「⚠️ 没建模的一半：把谓词翻面走到『扫描重建复活了一份错的版本』，要第二次尝试写出的内容与孤儿不同、身份相同……这一步是推理，模型只量了谓词翻面」）。作为辩方，我在这一半上找到的不是「第一轮推错了」，而是一条第一轮自己没有具体化、但能让这半推理站得更稳的路径，如实报出（不改变结论方向）：

C113（扫描重建时多版单元的现行版本判定无输入） 定案 P3（`.claude/kb/checks-owed.md:119`，背景材料附录 1394 行，逐字）：「判据是单元写序 (实例代号, 事务号) + 实例表的已发布谓词（按单元类分）+ 祖先表，不是记账」；D18 已定项 11 正文（同一段）：「扫描重建同时找到同一身份的多版容器时按 C113（扫描重建时多版单元的现行版本判定无输入） 定案的规则判……先按实例表的已发布谓词滤掉未发布的版本，再在对该根可见的候选里取该类的择新键最大者（定案 P3：码 1 取写序，**码 3 取 (诞生代号, 实例代号, 事务号) 三元**——诞生代号打头，因为同一实例连着两个 checkpoint 都不分配新事务号时两版写序逐字节相同；事务号留在末位做同一 checkpoint 内的平局破除）」。

## 二、K2：回退与屏障——甲″/乙′「取号之后先持久一道屏障」撞不撞 D23（journal 的角色与格式） 已定项 14「之前没有持久效果」

D23（journal 的角色与格式） 已定项 14（`.claude/kb/decisions/23-journal的角色与格式.md:1204-1241`，背景材料 815 行，逐字）：「回退与它的第一个新根同一次发布，之前没有持久效果，崩了就重做」。

**构造一个回退途中崩溃、超级块已带新号而回退没生效的状态**：
- 前态：当前挂载实例 = 1，当前根 = R_cur（某个正常运行时的根）。
- 管理员发起回退到 R_old。挂载计算新实例 = max(超级块 1, 根环 1) + 1 = 2。甲″/乙′：先把这两次超级块写（两盘）持久，接一道完成了的屏障（乙′是两道，逐盘各一道）。
- 屏障完成——**此刻两盘超级块都durable地带着实例代号 2**，而回退本身（写它自己的 COW 单元、实例表行 (r_old, T_old, 0)、journal 记录、新根 FUA）一个字节都还没写。
- 崩溃发生在这里。
- **持久写集合**：{超级块@盘 0（实例 2）, 超级块@盘 1（实例 2）}，回退的其余部分一个都没有。

**逐字对判**：「之前没有持久效果」——这里的「之前」指回退的第一个新根**之前**；「没有持久效果」照字面读，是「回退这件事在它自己的根发布之前不留下任何持久痕迹」。而「回退途中崩溃」那个构造状态里（超级块两盘都持久为实例 2、回退自身内容一字未写），超级块的实例代号已经从 1 变成 2 并且**持久**——这是一个持久痕迹，出现在回退的第一个新根**之前**。**按字面，甲″/乙′的屏障与这句话冲突。**

**撞了哪一边让步**：不是甲″/乙′让步（放弃屏障会直接回到 K1 的撞号），是 D23（journal 的角色与格式） 已定项 14 的**措辞**需要收窄，理由与它自己那一段紧接着已经写明的另一条例外同构——同一段原文（背景材料 849 行）紧跟着写：「⚠️ 回退例外里『之前没有持久效果』这一句按今天的条文不成立：回退那次发布先写它自己的 COW 单元……分配器从 R_old 的账重新载入……那些单元可以落在最新那个根引用的单元上；崩在记录之前，下一次恢复挂上那个根、读到被复用的单元……落 C314（回退可以复用被抛弃的根引用的单元）」。这条已经承认「之前没有持久效果」这句话不是逐字成立的、已经开了一个口子（C314，2026-09-13 已用影子账还清）。K2 找到的是**第二个**需要开口子的地方，同一种毛病：超级块的实例代号推进是「取号」这个独立步骤的持久效果，不是「回退」这个操作本身的效果——两者在物理盘上无法分开落笔，但在语义上可以分开记：取号推进的是「防止未来撞号」的账本，不是回退所选的那棵树；崩了之后，下一次挂载走的是**普通的「非干净结束之后的可写挂载」恢复路径**（读到的根仍是 R_cur，因为回退的根从没写出），管理员需要重新发起回退指令，实例号被跳过一格（不连续，但 D18 已定项 11 全篇没有要求实例号连续，只要求单调）。

**代价**：只是给 D23（journal 的角色与格式） 已定项 14 再加一句例外，形式与 C314 那句同构（「取号那次的超级块写与其后紧跟的屏障不算回退的持久效果」），不需要改甲″/乙′的屏障设计。

**这一条不偏向乙′**：乙′的写法是「盘 0 超级块 → 屏障 → 盘 1 超级块 → 屏障」，两次独立屏障都在回退自己的第一次发布**之前**完成，与甲″（一次屏障）在「超级块先于回退自身内容变成持久」这一点上**完全同构**——乙′不比甲″更早、也不比甲″更晚让超级块持久。⇒ K2 不满足背景材料反向接受条款「若 K2 证明甲″与已定项 14 不可调和而乙′可调和，取乙′」——两者同样需要那句例外，同样可调和，**不触发取乙′**。

## 四、K4：Q7 的 ①② 与第一轮甲的改写，在三类镜像上各判什么

**候选文本**：

- **Q7①**：盘上每个根记录、journal 记录、单元写序的实例代号 ≤ 各盘超级块实例代号的最大者。
- **Q7②**：各盘超级块实例代号不等时，较大者不出现在任何根、记录、单元写序里。
- **第一轮甲的改写**：本轮指定要读的三份材料（`c322-r2-background.md`、`c322-r1-main-verification.md`、`c322-r1-opus-output.md`）里没有它的完整逐字条文，只有碎片，如实标注、不拼一句假装整段引用——`c322-r1-main-verification.md` 第 26 行：「甲新 I-7.7 的『没有带最大实例代号的根或记录』」；第 38 行：「那个状态上……甲改过的 I-7.7 都判成立……两盘超级块都是实例 1，走『相等』那一支」（隐含它有一个按「相等」分支的结构）；`c322-r1-opus-output.md` 结论表 J3 一行：「甲改过的 I-7.7（保留 / 删掉『≥根环』那半句两种读法）都判成立」。三条碎片拼出的形状是「相等 ⇒ 成立；不等 ⇒ 查根环 / journal 里有没有带最大实例代号的根或记录」，但这是本轮从碎片重建的形状，不是某一处的逐字原文。

### 撞号镜像 {实例表单元@盘 0}（Z，第一轮反推腿构造，两盘超级块都是实例 1、盘上有一个写序实例代号 2 的孤儿单元）

- **Q7①**：孤儿单元写序实例代号 2 > max(超级块) = 1 ⇒ **判红**，抓住撞号。
- **Q7②**：前提「各盘超级块实例代号不等」在 Z 里是假（两盘都是 1、相等）⇒ 这一条**不适用、不触发**，等于放过 Z。
- **第一轮甲的改写**：走「相等」那一支 ⇒ **判成立**，同样放过 Z——这与第一轮判决三 J3-1 的结论一致（`c322-r1-main-verification.md` 第 38 行：「那个状态上今天的 I-7.7 与甲改过的 I-7.7 都判成立……甲的新条款放过一个真错」）。

⇒ **Q7② 与第一轮甲的改写是同一种形状**（都带一个「不等时才检查」的前提），在 Z 上**同样漏判**；只有 Q7① 独立于两盘超级块是否相等去检查每个写序，才抓得住 Z。这是本轮复核新加的一步——第一轮判决没有把 Q7① 与 Q7② 分开评过判别力，只笼统报了「①② 的形态采纳」（`c322-r1-main-verification.md` 第 45 行）。

### 取号没做完的合法状态 {只落盘 0} / {只落盘 1}（乙、甲″、甲下都可达，第一轮判决三「乙的『只落盘 0』仍可达」一节已确认）

取这一态：盘 0 超级块 = 新号（2），盘 1 超级块 = 旧号（1）；root 环、journal、单元全部还是旧号（1）——因为这一态发生在取号自己的两次写之间，后续任何写都还没被issue。

- **Q7①**：每个根 / 记录 / 单元写序实例代号（都是 1）≤ max(超级块) = 2 ⇒ **判绿**，不误报。
- **Q7②**：超级块不等（2 ≠ 1）⇒ 前提成立，检查「较大者（2）不出现在任何根 / 记录 / 单元写序里」——根 / 记录 / 单元里确实没有 2 ⇒ **判绿**，不误报。
- **第一轮甲的改写**：按「相等 ⇒ 成立；不等 ⇒ 查根环 / journal」这个从碎片重建的形状，不等 ⇒ 走第二支，检查根环 / journal 里有没有带实例代号 2 的根或记录——确实没有 ⇒ **判绿**，不误报。

⇒ **三条候选在这一态上都不误判**，与第一轮判决三「J3-2」一节的方向一致（第一轮那里测的是另一个具体状态：暖机第一条记录 w1 先于超级块两次取号写全部持久的极端情形，同样判「今天字面不红、甲改过的也不红」，本轮测的是最朴素的「取号只完成一半」态，结论方向相同：**合法态没有被误伤**）。

### 外盘替换

三条候选都不检查 fsid，在外盘替换上**一致失效**（两个池各自第一次挂载都取实例 1，恰好相等，三条候选都判「成立」），这与第一轮判决四第 5 条一致：该缺口已由 checker 逐盘比超级块 fsid 单独补上（Q6），不由这三条 I-7.7 候选中的任何一条负责，**三者不分辨臂**，本轮复核不再重复这一格。

⇒ **K4 结论**：最终采纳的 I-7.7 改写必须含 Q7① 这种「绝对上界」形态；单独用 Q7② 或第一轮甲的「相等 / 不等时查环与记录」形态都不够，会漏判撞号镜像 Z。Q7①+② 合起来（① 兜底、② 补一句「较大者不出现」作为更严的收紧）都不会误伤两个「取号没做完」的合法态。

## 七、总判断

三个反向接受条款逐条核过：K1 没有推翻第一轮判决第 1 条（甲仍出局）；K2 找到一条真实的文本冲突，但判它可调和、且甲″与乙′同样冲突（不偏向乙′）；K3 在三条已建模路径上确认甲″关得住撞号，没找到第四条路径。三条都不触发，落到 K6：**甲″比乙′更省，取甲″**。

连带三笔要写进条款、不分辨甲″与乙′本身的选择：① I-7.7（超级块实例代号不低于根环） 的最终改写要包含 Q7① 这种绝对上界检查，单独用「相等，或不等时查环与记录」（第一轮甲的原形）会漏判 K1 的撞号镜像；② D23（journal 的角色与格式） 已定项 14「之前没有持久效果」要再开一个口子——取号那次的超级块写与紧接的屏障不算回退的持久效果，形式与已有的 C314（回退可以复用被抛弃的根引用的单元） 例外同构；③ 世代号规则取 G1（全池最大 + 1），G2（D22（单元原子性怎么合成） 已定项 16 字面「逐盘 +1」）在甲 / 甲″下有 1/16 的历史会漏看一次取号，G1 在三条臂下都是 0；「全部超级块」两种读法与 G1/G2 的交叉验证本轮仍是缺口，只给出了不依赖实测的单调性论证，如实报告未补。
