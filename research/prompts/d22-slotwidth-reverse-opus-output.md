### 2. 「没有落点」核得住，但他的核法核不住；而且顺手核出 C82 自己漏了两格

结论对（我把范围放宽到 `io_min` / `映射单元` / `根环` / `根槽` / `根记录` 仍然零命中），
**但 `槽宽|E34` 这两个词撑不起这个结论**：这条张力在 checks-owed 里如果存在，
最可能的措辞是 `io_min` 或「映射单元」，而不是「槽宽」——事实上 C82 就是这么写的，
它命中 `io_min` 而不命中 `槽宽|E34`。他的 grep 恰好绕开了唯一可能装下它的那类措辞，**结论对是运气**。

放宽之后另有收获。提问者自己算过一次 C82：

> `io_min` = 32768、`physical_block_size` = 512 这一格**过得了那道闸**，而它把 `32768 / 512 = 64` 个槽放进同一个物理映射单元。

这个算术对，但它只走了一步。再走两步，**C82 那道闸自己漏了两格**：

| 格 | C82 的闸 `io_min ≤ 32768 且 32768 % io_min == 0` | 谁违规 |
|---|---|---|
| `io_min` = 4096、`physical_block_size` = 512 | `4096 ≤ 32768` ✓、`32768 % 4096 == 0` ✓ ⇒ **放行** | 512 字节的根槽写 < 4096 ⇒ **违反硬要求 1**。这台设备**不需要是阵列**：按 `core.c:2129` 的 `phys_bs = bs * (1 + npwg)` 与 `core.c:2141` 的 `min(phys_bs, atomic_bs)`，一块 NPWG 报 4096、NAWUPF 未声明的普通 NVMe 就是这个几何 |
| `io_min` = 32768、`physical_block_size` 任意 | `32768 ≤ 32768` ✓、`32768 % 32768 == 0` ✓ ⇒ **放行** | **元数据单元 16384** < 32768 ⇒ 违反硬要求 1。`18-块里携带什么信息.md:691` 逐字：「并存——元数据 16 KiB、数据 32 KiB（D4（校验和位置）已定项 1），所以步进取 16384。」 |

第二格是一条**已经发生的回扫漏项**：C82 的日期是 2026-09-02，它的 `32768` 取的是数据单元；
而两档单元的口径在同一天已经写进 D18（`18-块里携带什么信息.md:714` 逐字：
「⚠️ **步进口径曾定 32768、与元数据单元 16 KiB 对不拢，2026-09-02 已修正为 16384**」），
`02-RAID条带策略.md:327` 也在 2026-09-06 因为同一个理由改过字。**C82 的阈值没跟着回扫。**

⇒ 这两格把提问者的结论推得更远：**不只是「C82 落地也不能替这条张力收尾」，是 C82 那道闸本身就是按错的量写的。**
它跟的是「单元宽度」，而硬要求 1 跟的是「本设计发出的最小写宽度」，
而那个量今天是根槽宽 = `physical_block_size`，不是 32768。

### 3. 「判据缺口 + 证据缺口」这个拆法，两个方向都错了：丢了一半，又把一件事数成了两件

#### 丢掉的第三半：**代价缺口**

提问者自己整行抄了它，**两遍**，然后在第四节里没写。
背景材料第 80–82 行（抄自 `22-单元原子性怎么合成.md:265-267`）：

> 2. **代价没量。** 槽宽从 512 抬到 64 KiB 是 **128 倍**的根环占地，
>    而 D22（单元原子性怎么合成） 已定项 2 给槽宽的理由逐字是「大于它不多买安全性，只多花字节」——
>    **那句话写在没有 `io_min` 这一维的时候**。

背景材料第 136–138 行（抄自 `34-根环槽几何.md:155-157`）：

> ⚠️ 代价那一侧也没量：槽宽从 512 抬到 64 KiB 是 **128 倍**的根环占地，
> 而 D22（单元原子性怎么合成） 已定项 2 定槽宽时逐字写的理由是「大于它不多买安全性，只多花字节」——
> **那句话是在没有 `io_min` 这一维的前提下写的。**

代价缺口是独立的第三半，而且它是**唯一一个今天就能关掉的**——见第三节。
丢掉它，五个候选的选择就没有依据了：A/B/C/E 之间选哪个，取决于这件事是「欠一条检查」还是「欠一次取舍」，
而只有代价那一侧能回答它。

#### 他数成两件的那两件，其实是同一件

- 硬要求 1 与 2 的证伪条件，`02-RAID条带策略.md:30-31` 整行抄：
  > ⚠️ 本机无法用故障注入证伪（`dm-flakey` 造不出撕裂），按
  > `.claude/singlefs-ai-sop/rules/evidence-discipline.md` 记为**机制推导**，证伪等崩溃点重放 harness。
- E34 欠的那条机制，`34-根环槽几何.md:167-168` 整行抄：
  > ⚠️ 撕裂是构造出「数据落了、parity 没落」这个盘上状态，**不是真的断电**——
  > 状态等价，路径不等价。真断电要掉电注入硬件或 QEMU 级别的写序截断。

⇒ 「判据缺口」（硬要求 2 的措辞算不算数）与「证据缺口」（SSD 内部 RMW 注不进去）
**卡在同一个前置上**：崩溃点重放 / 掉电注入。它们不是两个可以分别推进的半边，是一个挡路条。
把它写成两半，会让人以为「先关判据那一半，证据那一半慢慢等」——**而判据那一半也在等同一个东西**。

真正能分开推进的那一半是他丢掉的第三半。

## 三、反过来最强的一条：它凭什么可能已经该定案，以及还差哪一步

先说结论：**「槽宽不改」今天定不了案，但挡它的不是证据，是它的依据已经被打穿了一半。**

### 它凭什么够

最强的形态是这样：D22 已定项 2 的槽宽定案给了一条依据，逐字是

> 大于它不多买安全性，只多花字节

这是一个合取：①「不多买安全性」；②「只多花字节」。
E34 的两半合起来，对①的处置是**收窄，不是恢复**——`34-根环槽几何.md:124-125` 整行抄：

> ⇒ **暴露面 ≠ 损失面。** 算术那一半的 16 是**上界**，真设备上这一类故障实现不到它。
> **这条直接减轻了改槽宽的理由**（见 D22（单元原子性怎么合成） 已定项 2 里那条张力）。

「减轻」不是「消掉」。而 E34 算术那一半在同一份实验里逐字是
`34-根环槽几何.md:55-56`：已定取法 **18 / 48** 格「一次写打掉 ≥ 2 个槽」，
建议取法 **0 / 48**。⇒ **① 已经不成立了**：抬槽宽确实买到了东西。

于是那条依据只剩②「只多花字节」。而 `.claude/rules/fs-design.md` 对「只多花字节」有明文，整行抄：

> **自描述数据宁可写大一点。** 遇到「这个字段能不能省掉 / 能不能压窄 / 能不能现算」这类权衡，
> 默认答案是**不省**——除非有实测证明省下来的那部分是瓶颈。

⇒ **默认值翻了。** 在这条规则下，承担举证责任的是「省」那一边，也就是今天的 `physical_block_size`。
D22 正文却把举证责任放在另一边（`22-单元原子性怎么合成.md:259` 逐字：
「**两件事先记清楚，免得被读成「槽宽要改」**」）。**这是我这条腿打中的第二处框架问题**：
不是「要不要改」欠三方论证，是「不改」这一侧今天已经没有一条站得住的依据了。

### 还差哪一步

四步，按能不能今天做完排：

| 差什么 | 今天做得了吗 | 依据 |
|---|---|---|
| **1. 代价那一侧一个数都没有** | **做得了，纯算术** | 见下 |
| **2. 三方论证的两条云端腿** | 做得了（这份答复是其中一条） | `34-根环槽几何.md:169` 逐字：「3. **两条云端腿仍然欠着**（`.claude/rules/three-way-inference.md` 要三条）。」而 `.claude/rules/three-way-inference.md` 逐字：「**凡是「推论」，都要走三方。** 推论指：设计判断、取舍结论、以及任何用来推翻或确立 `.claude/kb/decisions.md` 里某一条的依据。」「槽宽不改」正是「确立 decisions.md 里某一条」 |
| **3. SSD 内部 RMW 这条机制** | **做不了**，等崩溃点重放 / 掉电注入 | `34-根环槽几何.md:131-133` 逐字：「因此它证的是 **RAID5 写洞**这一条机制。E34（根环槽几何） 主张 1 的另一条机制——**SSD 内部对整个映射单元做 RMW**——**在 loop 上注入不了，仍然欠着**。两条机制的故障单元不同（前者按扇区行，后者按整个映射单元），**不许互相顶替**。」 |
| **4. 连带要改的三处，五个候选一个都没提** | 做得了 | 见下 |

#### 第 1 步我现在就做掉一半（主 agent 现算，不是实验，谁都可以复核）

R = 3（D22 已定项 2）、S 上界 16（D22 已定项 2 逐字「1..16 之间取值不碰任何一条边」）：

| 槽宽 | 根环总占地 = R × S × 槽宽 |
|---|---|
| 512 | `3 × 16 × 512` = **24 576 字节 = 24 KiB** |
| 65536 | `3 × 16 × 65536` = **3 145 728 字节 = 3 MiB** |

⇒ **「128 倍的根环占地」的绝对值是 24 KiB → 3 MiB，一次性、mkfs 时定死、不随池容量或负载增长。**
在一个以 32 KiB 为数据单元的池上，3 MiB 恰好是 **96 个数据单元**，增量是 **95.25 个**。
D22 与 E34 两处都只写了倍数没写绝对值，而这正是
`.claude/singlefs-ai-sop/rules/evidence-discipline.md` 点名的那个形态
（「我是不是**只在一个点**上取了值」「一个尺寸、一个参数、一个负载算出来的倍数，不能叫「最坏情况」」）。

**但代价不在占地上，在写带宽上，而两处都没写它。** 每次发布写一个槽，
`22-单元原子性怎么合成.md:312-313` 逐字：「每次 fsync 发一次根（D23（journal 的角色与格式） 已定项 1 轴一已定）⇒ 一圈时长 = 槽总数 ÷ fsync 率
⇒ 8 槽在本机（E44（序号位宽的本机实测与代价） 实测 2785 次/秒）是 **2.87 毫秒**」。
按 2785 次/秒：`512 × 2785` ≈ **1.36 MiB/s**，`65536 × 2785` ≈ **174 MiB/s**。
**这才是那个 128 倍会疼的地方，而 D22 与 E34 都没提到它。**

⚠️ **这个数的方向我没量，只给机制**（按 `.claude/rules/three-way-inference.md`，这是我这条腿的推论，判决归主 agent）：
在 `io_min` = 64 KiB 的设备上，发一个 512 字节的写，设备/阵列侧本来就要做一次 64 KiB 量级的读改写；
所以主机侧省下的 128 倍未必对应设备侧省下 128 倍，**符号未知**。
⇒ 代价那一侧要么补一个真设备上的写放大测量，要么就承认「128 倍」今天不能当拦阻理由用。

#### 第 4 步：改槽宽会连带动到三处，五个候选一处都没提

| 连带 | 逐字 |
|---|---|
| **对齐** | D22 已定项 2 的对齐行逐字：「每个槽的起始偏移是判定宽度的整数倍」。槽宽改了而对齐仍按 `physical_block_size` 算，槽照样跨两个 `io_min` 单元 ⇒ 对齐那一格要一起改 |
| **I-7.5（根槽按判定宽度对齐）** | `invariants.md:50` 逐字：「每个根槽的**起始偏移**是挂载时探测的 `physical_block_size` 的整数倍。」跟的是 pbs |
| **C47（根槽没按判定宽度对齐）** | `checks-owed.md:57` 逐字：「⚠️ **判定宽度在异构池里是一个集合不是一个数**：mkfs 要按池内 `max(physical_block_size)` 划，挂载时逐设备复算比对」。同样跟的是 pbs |
| **第一个事务的字节数** | `first-txn-layout.md:76` 逐字：「**66 048 字节**（映射树叶节点 1 + 内部 3 个 × 16384 + 一个根槽 512）」 |

⇒ 候选 A（「立成 D22 的一条新未定项」）**射程不够**：这不是 D22 一格的取值，
它同时动 D22 已定项 2 的两行、一条不变量、一条欠账、和第一个事务的字节表。

## 四、五个候选里哪一个是稻草人

**D。**「什么都不立：E34 真设备那一轮已经把损失面收窄，剩下的是已知残余风险，正文写着就够。」

   这是在说这个选项**不管用**，不是在说它多贵。**一个代价列写着「本选项无效」的候选，不是候选。**

2. **它在第零节就已经被判过一次了。** 背景材料第 12–16 行整行抄：
   > 这句话今天**没有任何落点**——它不是 D22 的未定项（D22 的未定项只有 6 与 9），
   > 也不是 checks-owed 里的一条 C 号（`grep -n "槽宽\|E34" .claude/kb/checks-owed.md` 零命中），
   > `first-txn-layout.md` 里根环那一行的状态是「已定」。
   > ⇒ 它只活在一段散文里，门禁阶段 31（每个未定项有没有判过改不改第一个事务的字节）
   > 与 60（未定项有没有被别处定了）都看不见它。

3. **D 根本不是「什么都不立」，它是现状。** `22-单元原子性怎么合成.md:271` 逐字
   「**槽宽这一格暂不改。**」，259 逐字「**两件事先记清楚，免得被读成「槽宽要改」**」——
