# E128 跑前写死的判据、阈值与作废条款（2026-09-10，写于任何一行测量代码之前）

**问的是**：D19（块指针的结构与宽度预算） 未定项 7 的候选甲把指针头部 31 → 47，
连带把 inode 树内部条目 93 → 109、记账树内部条目 81 → 97。
**在 16 KiB 节点上，这两组各多付多少一次点查的 CPU 时间？**

**为什么另立新号，不在 E20（指针变宽的 CPU 缓存代价） 上加臂**：E20 的判据 2026-08-29 写死、
产物已入库、`replay.sh` 已注册（与 E95（老化的节点布局臂） → E127（分裂合并之下组身份要不要存） 那次同一条理由）。

## 臂（六条，全部在 node_bytes = 16384 上）

| 臂 | entry_bytes | 是什么 |
|---|---|---|
| `inode_bing` | 93 | 丙 = 今天：分隔 key 8 + 身份引用 26 + 子指针 59 |
| `inode_jia` | 109 | 甲：子指针 59 → 75 |
| `ledger_bing` | 81 | 今天：分隔 key 22 + 子指针 59 |
| `ledger_jia` | 97 | 甲 |
| `xdev_67` | 67 | **跨装置对照**，E20 量过 |
| `xdev_111` | 111 | **跨装置对照**，E20 量过 |

节点头常量 `NODE_HDR = 64`，与 E20 同一个数，理由是它同时复现本工程两处已登记的扇出
（(16384−64)/93 = 175、(16384−64)/81 = 201），见下面的绝对值断言。

## 判据（跑前写死，跑完不许改；改了就是新实验，重跑）

1. **阳性对照，每条臂各跑一遍**：同一 entry_bytes 下 L1 档（2¹¹ key）与 DRAM 档（2²³ key）
   的 ns 比值 **≥ 2.0**。任一格不过 ⇒ **整轮作废**，退出码非 0。
2. **跨装置闸**（`.claude/singlefs-ai-sop/rules/show-me-test.md`「立在装置之间」）：
   `xdev_67` 与 `xdev_111` 在 node_bytes=16384 / keys=2²³ 上的 ns，
   与 E20 入库产物 `research/results/e20-sweep-2026-08-29.out` 的
   **466.99** 与 **547.50** 相差 **≤ 15%**。超出 ⇒ **整轮作废**。
   两个数逐字抄自那份产物，抄写见本文件末尾附录。
3. **绝对值断言**（防「所有臂一起错」，`test-discipline.md`）：
   槽数逐档钉死 93→175 / 109→149 / 81→201 / 97→168 / 67→243 / 111→147；
   2²³ key 上的树深逐档钉死 175→4 / 149→4 / 201→4 / 168→4 / 243→3 / 147→4。
4. **轮数**：这是有变化的观测（真实 CPU 计时），跑 5 轮，每轮取 3 次 min。
   要说「甲比丙慢」得 5 轮都慢，要说「不慢」得 5 轮都不慢；两边都不满足就写「不稳定」。

## 不设的阈值，以及为什么

**本实验不设「慢多少算可接受」的阈值。** 那个数属于判决，不属于实验——
设了它，实验就只会在「符合预期」时判通过（`test-discipline.md`
「实验的失败条款不许让结论不可证伪」）。

## 结果反过来我接不接受（写在跑之前）

- 若 `inode_jia` 比 `inode_bing` **快**，或两者差 **< 2%**：
  我会写下「**甲的这笔缓存代价在 16 KiB 节点上不成立**」，
  并据此把 D19（块指针的结构与宽度预算） 未定项 7 里那句
  「另加 E20（指针变宽的 CPU 缓存代价） 实测的缓存代价……**这一笔从没进过任何一条腿的材料**」
  改成「这一笔已量，量出来是零」。这是我接受的结果，不是要规避的结果。
- 若慢得很多（> 50%）：**也不等于甲出局**——甲被三处消费者要着，
  代价大只是把它推向「要不要换一条既满足消费者又不加宽的路」。

## 本实验测不了的（写在跑之前，防止事后把射程说宽）

- **只测点查，不测扫描 / 范围查询 / 写路径。**
- **只测 16 KiB 节点**（D8（核心索引结构） 已定项 2 钉死的那个数），不扫节点档。
- **不测树表**（121 → 137）：树表查找频次与 inode 树差几个数量级，
  且它的条目宽有两套口径没统一（C157（树表容量在两处按不同条目宽算））。
- **纯 CPU/内存模型，没有设备 I/O。**
