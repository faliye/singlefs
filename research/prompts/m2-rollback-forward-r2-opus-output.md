## 一、原型的最小规格（这条腿自己定的，不是条款，被攻过零轮）

改动全在 `prototype.patch`（冻结副本 `crates/singlefs-core/src/` 下 `mount.rs`、`allocator.rs`、`recovery.rs`、`rollback_witness.rs` 四处，外加新文件 `prototype_rbf2.rs` 由 `mount.rs` 末尾 `include!` 进来）。第一轮原型（`m2-rollback-forward-r1-opus-model/prototype.patch`）整份先打上，借它的复活函数与「不判上限」的抬 F；产品路径的行为只在四个开关打开时变，开关全关时与冻结副本同。

**P-MNT：挂着的时候向前发布的回退**（`prototype_rollback_in_mount`，正文第一节那一形）：

1. 候选：R_old 在环里（盘上现读）、txg ≥ max(盘上 F_生效, 现行那一版带的 F)、按现行那一版的实例表仍然有效。不看见证（这一形不写见证）。
2. 从盘上重建 R_old 那一版；八棵树的号与现行那一版不同就拒（第一版同一条血统里恒同）。
3. 「上一版」= 现行那一版，只把用户可见的那几样（数据单元、extent 树、inode 树的单元、映射 key、树表里 extent / inode 两条、inode 记录）换成 R_old 的；固定点（树表、记账树、映射树、分配记录树、实例表）照现行那一版，由这次发布照常 COW 重写。走 `publish_version`、`file: None`、实例表照抄、事务号照常加一、txg = 现行 + 1、不取号、不写行。
4. 分配器在拷贝上调整，发布成了才换上：
   - 复活：R_old 引用的用户可见单元，在现行那一版的账里已释放的，改回仍分配、分配代写回 R_old 那条记录的；
   - 释放：现行那一版引用、R_old 不引用的用户可见单元，释放代 = 这次的 txg；
   - 核（第一轮原型加的那一道，正文第一节「留着」）：R_old 那一版里仍分配的用户可见单元，在现行那一版的账里要有同槽、同跨度的记录；仍分配的要同分配代，已释放的要没被回收。
5. inode 号水位 = max(现行那一版的, 环里每一条读得出的根的)；树 ID 水位 = max(现行那一版的, 环里根与记录的)。
6. 臂：`Full`（上面全做）、`WithoutProtectionCheck`（去掉第 4 步的核）、`LiteralWholeTreeDiff`（发布之后另把「现行那一版账里分配着、R_old 那一版账里没有同槽同代」的全部落点释放——两棵分配记录树整棵求差的字面）、`WatermarkOfNewestOnly`（inode 号水位只取现行那一版的）、`WithoutTableValidityCheck`（候选不按实例表判，本报告没用到）。

**B1**（`prototype_unmount_b1`）：抬 F 到现行那一版的 txg，走今天的 `raise_rollback_floor` 那一整段（整串预演、扣住、推空发布到每块盘、放开）。两种读法：`literal`＝先按「每块盘上最新的持久有效根，各盘取小」判上限，超了拒；非 literal＝不判上限（第一轮原型的 B）。

**C419 的两种生效规则**：`recovery::PROTOTYPE_FLOOR_RULE_MAX` 关＝今天的「各幸存盘所带 F 最大值的最小值」（下文 `min_of_max`），开＝「各幸存盘所带 F 的最大值」（下文 `max`）。只改 `effective_rollback_floor` 一处；挂载重建分配器、候选集、原型的回退都读它。checker 不跟着改（它按最新根带的 F 判）。

**这条腿自己提的改法「扣到暖机覆盖」**（`recovery::PROTOTYPE_HOLD_UNTIL_COVERED`，下文 `max+hold`，只在我的模型上量过、被攻过零轮）：取最大值规则下挂载重建分配器时，释放代 ≤ max(最大值的最小值, 环里最旧有效根) 的照常回收；多出来的那一段（释放代落在两种规则之间）回收了先扣住（`ReclaimedReuse::HeldUntilFloorTakesEffect`，与抬 F 那一串同一个扣法），本实例的写行与暖机把根推到每块盘之后才放开。

**删掉见证与截断之后的代码读盘的样子**（`rollback_witness::PROTOTYPE_WITNESS_AND_TRUNCATION_DELETED`，G5 用）：见证的三个 `abandons` 恒假（择根、重放、影子账都不再按见证抛弃），`rollback_high_water_of_root` 恒 `None`（重放不遇回退行截断）。实例表行的解析不动（带 flags bit0 的行照读）。

**这份规格的已知毛病**：释放与复活只在用户可见单元上做（第 4 步），不是「两棵分配记录树整棵求差」的字面——字面那一臂见 X1；核是按账做的，已释放的记录里写的是释放代、不是分配代，核看不出「这个槽被复用过又释放了」（X2 的一半）。

几何：两块 4 GiB 内存稀疏盘、根环三个区域（归属 盘 0 / 盘 1 / 盘 0）、每区 8 槽；起点池只建一次（mkfs、暖机 txg 1、2，A =（实例 1, txg 3）），每段历史在内存里拷。多数历史的前缀是「重开 → 实例 2（写行 txg 4、暖机 txg 5）→ 覆盖写」。

### X1　「按两棵分配记录树求差来释放」照字面做，走普通发布路径时把新根还引用的固定点也释放了（打中，零故障，分辨臂）

2. 挂着回退到 A（txg 9）。臂 `Full` 与 `LiteralWholeTreeDiff` 的发布一字节不差，差别只在发布之后分配器里多释放的那一条：「现行那一版账里仍分配、A 那一版账里没有」而新根还引用着的落点，两臂都量到 1 条（`whole_tree_diff_referenced_by_the_new_root: 1`）：槽 50304、跨度 2、分配代 4（`g1_smoke` 那一行内存与盘上的账比出来的差 `AllocationRecord { device: DeviceIdentity(0), slot: SlotNumber(50304), span_slots: 2, generation: CheckpointTxg(4), is_released: false } vs … generation: CheckpointTxg(9), is_released: true`）。分配代 4 是实例 2 写行那一次；那一次写的跨度 2 的单元只有实例表单元（推的，按角色表），回退根照抄它（`InstanceTablePlan::Carry`）。A 那一版在实例 2 之前，它的账里没有这张表。
3. 接着覆盖写 40 次（10..49），环转过一圈。

每一步许可它的条款：第 2 步是第一轮判决 F1「释放的集合按两棵分配记录树求差」与正文第一节「释放：按最新那一版与 R_old 那一版两棵分配记录树求差」；「走正常事务路径」是正文第一节回退那一行。回收按 `16-发布语义.md:33` 整行 `| 可再分配 | 已释放 ∧ 释放代 ≤ max(F_生效, 环里最旧有效根) |`。

**共用问句**：回退根（以及之后每一条根）引用的实例表单元被复用，读不对——量过。

**四句**：

1. 分辨臂：分辨「整棵求差」与「只在用户可见单元上求差（= 现行那一版分配着的落点减去新根引用的落点）」这两种读法；同一段前缀、同一次回退，只差释放集合。
2. 被判系统看不看得到判别它的东西：看得到——两版的账都在内存里，新根引用哪些落点在发布之后就知道。
3. 满足的是判据字面的哪一句：共用问句「那一版引用的块有没有被复用」，与 I-7.4 字面（`invariants.md:54`，候选根引用的块未被重新分配）。
4. 改法在这几格上还中不中：`Full` 臂的释放集合（现行那一版引用、R_old 不引用的用户可见单元）量过不中；「以 R_old 为上一版发布」（第一轮原型 P-FWD 那一形，固定点全部换新）推的不中，但它带 H11 那条 I-3.9，没在这一形上量。条款要写明释放集合是「现行那一版的账里仍分配、而回退根不引用的落点」，不是两棵账的差。

### G1 没打中的：用户动作放开扫、逐点崩溃、整段子集崩溃

**用户动作放开扫**（`g1_sweep_user_steps`）：只固定前缀与第一次回退，之后的用户动作全放开。前缀两种（覆盖写 ×3；顺序写 3 单元 + 建 3 个 inode + 覆盖写）× 第一次回退的目标三种（候选里上一个状态 / 最旧的带文件的根 / 居中那一条）× 后缀 400 种（7 种动作——覆盖写、建 3 个 inode、顺序写、回退到上一个 / 最旧 / 居中、关掉重开——长度 0..3 全排列）= 每臂 2400 段历史。每段末尾：环里每条根走读 + 整版重建（共用问句）、对环里每条根把更新的根全改坏之后恢复落在哪（落点表）、候选根之间 inode 号有没有同号不同对象出生代、checker；每次回退之后内存里的现行版本与分配器和盘上重建的那一版逐项比（G2）。原样行：

## 八、这条腿自己的限度

- 原型是我自己定的最小规格（第一节），被攻过零轮；释放与复活只在用户可见单元上做、核只看账，这两处是读法，不是条款（X1、X2 各打中一处）。
- C419 的「最大值」只改了 `effective_rollback_floor` 一处；checker 仍按最新根带的 F 判候选集；挂载内回收（`record_root_written_by_this_process`，`crates/singlefs-core/src/allocator.rs:1318`）按挂载时算出的 F 立刻回收，「扣到暖机覆盖」只罩挂载那一刻的回收，挂载之内那一路没攻。
- G5 的「删掉」是开关模拟的（见证恒不抛弃、截断恒不起作用），不是真把代码删了；实例表行的解析没动。
- 故障只有根槽翻字节、从录制流取前缀当崩溃、把一块盘从池里拿掉三种；没有记录撕裂之外的单元坏（整段子集枚举里有）、没有瞬时读错（第一轮 H12 那一类没再造）。
- 几何只有两块 4 GiB 盘、每区 8 槽；负载只有一个文件对象（单单元覆盖写、3 单元顺序写）与建 inode；没有快照；准入紧张时的回退与卸载（预演拒、ENOSPC）没造；没有真并发、没有文件句柄。
- 整段子集崩溃只做了一条流（第二节写明为时长缩了什么）。
- X2 里「新根读不出」那 3 格要的前提是 F 已经回落（今天的规则）；在「最大值」下同一个核的漏洞要 X4 那一格（带 F 的根全坏）才走得到，那一格里我没造出「接受了读不对的回退」，只造出候选根坏。
