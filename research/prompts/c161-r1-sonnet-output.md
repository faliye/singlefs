# C161 第一轮·正推腿（Sonnet）报告

## 结论先行

三条臂里能站住的是 **丙（一棵树只准一级）**，但不是背景材料写的那个「事先的倾向」原样成立——
它要付两笔背景材料没有写全的代价：① 必须显式修订 D11（索引节点要不要留消息缓冲区）已定项 6（树轴），
给「走前端的树」加一条例外，否则丙与已定项 6 字面冲突（这正是任务书问题 3，答案是「冲突，且冲突真实」，
见下文第三节）；② 丙需要一条新的发布前置门（前端在发布完成前必须排空到叶），这条门今天不存在，
但它的形状与 D11（索引节点要不要留消息缓冲区）已定项 5（重建前排空）完全同构，不是凭空发明。

**甲（前端直落叶）在 U1 被我自己推出的一个具体场景打中，按反向接受条款出局**；
但把甲打补丁堵住那个场景之后，甲对「走前端的树」的行为与丙逐字相同——**补丁后的甲不是丙的另一个选项，
是丙本身**。这是本轮推导里第一个背景材料没有写出来的结论。

**乙（前端 flush 进根缓冲、逐层下推）比背景材料预设的还要脆**。背景材料自己的反向接受条款只预见了
「seq 跨发布判不出新旧」这一个失败点；我从机制上另外推出第二个、独立的失败点：
**乙的读算法信的是物理位置（树深），不是显式比较 seq**，而 D8（核心索引结构）已定项 7 正文里
早已明写「btree 层同 key 是『谁后写谁赢』，不是『谁 seq 大谁赢』⇒ 同一个 key 的跨批次插入顺序必须与 seq 同向……
并行 flush 下两个批次的物理落地先后不受 seq 约束」（`.claude/kb/decisions/08-核心索引结构.md:449`）。
这句话原本是对另一条决策（seq 住 key 还是住 value）里的「乙」（seq 住 value）写的警告，
两个「乙」是不同决策里的同名臂，但警告的**机制**对 C161 的乙同样成立：乙的下推规则「消息越靠根越新」
本质上是拿物理位置当 seq 的替身，而这句警告说的正是「物理位置不追踪 seq」。背景材料给乙开的反向接受修法
（「seq 改成全池单调」）只解决了「seq 本身能不能跨发布比较」这个问题，**不解决「读算法根本不比较 seq」这个问题**——
两个问题独立，修一个不会连带修好另一个。真要把乙修好，读算法要从「找到就停」改成「走完整条路径、
收集全部命中、按 seq 取最大」，这会把读放大从「提前终止」变成「恒等于树高」，代价比背景材料预估的大得多。

下面逐节展开：前提核对、三臂机制推导、四个专项问题、每臂的会红检查与判别力自证、什么观测会推翻这个结论。

## 二、机制推导：逐臂过 U1–U4

### 甲（前端 flush 直落叶）

**甲的定义本身有一处没堵死的缝**：「节点缓冲区只收不走前端的更新」这句话没有回答——
对一棵**同时**开了前端与 ε > 0 的树（记账树就是这样的树：D8（核心索引结构）把它分进前端，
D11（索引节点要不要留消息缓冲区）已定项 6 的树轴把它判「能」⇒ ε = 0.65），
**这棵树的节点缓冲区到底会不会真的收到消息**。两种读法：

- **读法 A（节点缓冲区确实会收到旁路写入）**：某些对这棵树的更新不走前端、直接走节点缓冲区（甲的字面允许这样）。
  这时构造反例很直接：txg=10 时一条旁路写入把 key K 的旧值塞进某个内部节点的缓冲区；txg=20 时前端把 K 的新值
  排序去重后 flush 直落叶。读的时候，标准 Bε-tree 读法是「沿根到叶查每一层缓冲区，找到就停」——
  **它会先在内部节点缓冲区里找到 txg=10 那条旧消息，命中即返回，根本不会往下走到叶去看 txg=20 的新值**。
  这正是反向接受条款里「同 key 在节点缓冲区的旧消息压过前端落叶的新值」那个触发观测，**甲在这个读法下出局**，
  而且不需要任何刻意构造的极端情形，只要旁路写入曾经发生过一次就会撞上。
  ⚠️ 更根本的问题是：这个读法之所以危险，是因为它破坏了 Bε-tree 消息缓冲机制赖以成立的那条隐藏不变量——
  「沿路径找到的第一条消息必然比叶里的值新」。这条不变量只有在**所有**写入都走同一条路径（同一套排队纪律）
  时才成立；甲允许两条路径（前端、旁路）各自独立写同一个 key，恰好撕掉了这条不变量。
- **读法 B（节点缓冲区对这三棵树永远不会收到东西，因为文档没有另开旁路写入的入口）**：
  那么「同一棵树上两级都可以开」这句话在这三棵树上是空话——ε = 0.65 对它们没有任何实际效果，
  已定项 6 树轴判它们「能 ⇒ 留缓冲」变成一句永远兑现不了的承诺。而这三棵树以外的树本来就不走前端，
  甲对它们的行为与丙完全一样。**读法 B 下，甲对三棵前端树的行为收敛成「前端 flush 直落叶、缓冲区恒空」——
  这就是丙对这三棵树的定义，逐字相同。**

⇒ **甲要么在 U1 出局（读法 A），要么在「走前端的树」上退化成丙（读法 B）**。它不是与丙独立的第三条路，
是「丙 + 一个要么不安全、要么不生效的额外自由度」。这不是背景材料反向接受条款直接写出的结论，
是我从「甲对同一棵树允许两条独立写路径」这个定义本身推出来的。

### 乙（前端 flush 进根缓冲、逐层下推）

乙的读算法定义是「按『前端 → 根缓冲 → … → 叶』从新到旧取第一条」——**这是一个纯位置算法**：
不比较任何显式的时间戳或序号，只信「离根越近就越新」这条结构性假设。这个假设在什么条件下成立？
只有当「消息只会从根往叶推、从不反向、且**同一个 key 的多条消息之间，推送顺序与它们的产生顺序严格同向**」
时才成立——因为一旦某条消息 A（较新）比消息 B（较旧）先被推下去、或者两条消息因为落在不同的并发 flush 批次
里而导致 **B 反而比 A 更晚才物理落地在更浅的层**，「离根近 = 新」这个替身就会撒谎。

背景材料给乙准备的反向接受条款只问了「seq 跨两级、跨发布判不出新旧」这一件事，修法是「seq 改成全池单调」。
但这条修法**只修好了 seq 这个字段本身的可比性，没有碰乙的读算法**——乙的读算法根本不读 seq，
它只看你是在哪一层找到的。真正让乙不安全的是 D8（核心索引结构）已定项 7 正文里已经写死的那句警告
（`.claude/kb/decisions/08-核心索引结构.md:449`）：

> 「btree 层同 key 是『谁后写谁赢』，不是『谁 seq 大谁赢』⇒ 同一个 key 的跨批次插入顺序必须与 seq 同向，
> 这条不许留成隐含假设（E17（write buffer 合并上限） 实测按叶分区可并行 6.26–6.38×，
> 并行 flush 下两个批次的物理落地先后不受 seq 约束）。」

这句话是对另一条决策里的「乙」（seq 该住 key 还是住 value，最终选了住 value 那个乙）写的，
但它陈述的机制事实——**并行 flush 下，物理落地顺序与逻辑写入顺序（seq）可以不同向**——对任何
「用物理位置判新旧」的机制都成立，与它原本挂在哪条决策无关。C161 的乙恰好就是「用物理位置判新旧」
的那种机制：它把「消息越靠根越新」当成定义。**只要 write buffer 的 flush 按叶分区并行执行
（这正是 E17（write buffer 合并上限） 测量 6.26–8× 加速比时的那个配置，也是这一轮论证的前提——
第一版禁止并行、这一版要开 ε > 0 正是为了撑住规模化之后的吞吐，并行 flush 不是一个可以回避的选项），
乙的「离根近 = 新」这条替身就可能撒谎**：批次 A（seq 较小，逻辑上更旧）因为线程调度先抢到锁，
比批次 B（seq 较大，逻辑上更新）更晚才把消息推送/插入到更浅的层，读到的人会认为 A 更新，读错。

⇒ **乙有两个独立的 U1 缺口，不是一个**：① 背景材料预见的「seq 跨两级/跨发布不可比」（对反向索引 / LRU 两棵树尤其致命，
它们的 key 布局至今全仓未定义，D8（核心索引结构）已定项 7 自己留的骑手要求「去重窗口同样被 `T_dirty` 界住」还没兑现）；
② 我推出的「读算法用位置代替 seq 比较，而位置在并行 flush 下不追踪 seq」。
**背景材料给出的修法（seq 改全池单调）只堵住①，堵不住②**——要堵②，读算法必须从「找到就停」改成
「走完整条路径、把每一层命中的消息都收集起来、显式比较 seq 取最大」，这个改动本身就取消了 Bε-tree
消息缓冲机制最核心的性能特性（提前终止），乙也就失去了它存在的理由。

### 丙（一棵树只准一级）

丙对 U1 的回答是结构性的，不是算法性的：因为一棵树要么走前端（ε 恒 0，不留任何节点缓冲区）、
要么走节点缓冲区（不走前端），**同一个 key 在「前端 / 叶」与「节点缓冲区」两个位置同时存在这件事
在丙的构造下永远不会发生**——不是靠读算法比出来的，是靠格式上根本不允许两条写路径同时指向同一棵树
排除掉的。丙对走前端的树（记账 / 反向索引 / LRU）的行为，逐字就是 D8（核心索引结构）已定项 10
第一版已经验证过的「记账直落记账树叶」那个机制，只是把它从「第一版全部树都这样」收窄成
「这三棵树永远这样，与前端有没有全局开关无关」；丙对其余树的行为，逐字就是 D11（索引节点要不要留消息缓冲区）
已定项 6 的树轴，没有新增机制。**丙不需要发明任何新的读算法**，这是它在 U1 上干净的根本原因。

**但这份干净是有代价的，代价就是任务书问题 3 问的那个冲突，而且冲突是真的**：
D11（索引节点要不要留消息缓冲区）已定项 6 的树轴逐字是「能 ⇒ 留缓冲、ε = 0.65；不能 ⇒ 内部节点不留消息缓冲区、ε = 0」
（`.claude/kb/decisions/11-索引节点要不要留消息缓冲区.md:242-260`），这是一个**无条件的映射**——
只要「待下刷的消息能不能只从权威态重算」这个谓词判「能」，ε 就必须是 0.65，没有给「这棵树同时走前端」
这件事留任何豁免。而记账树按 D21（权威态与派生态的分界）「离线可由遍历重算」判「能」，
是树轴自己举的正面例子。丙的规则「走前端的树 ε 恒 0」对记账树给出 ε = 0，**与已定项 6 对同一棵树给出的
ε = 0.65 字面矛盾**。这不是我需要构造反例才能发现的冲突，是把丙的定义与已定项 6 的定义并排一读就撞上的。

⇒ **丙要成立，必须显式修订 D11（索引节点要不要留消息缓冲区）已定项 6，加一条前端例外**：
「一棵树若已被 D8（核心索引结构）判定走 write buffer 前端，其 ε 恒为 0，不受树轴谓词支配」——
这是对一条**已定**分项的正面修改，不是补一条新分项就能绕开的；它落在 D15（格式冻结政策）第 4 层
（`.claude/kb/decisions/15-格式冻结政策.md:64`「第 4 层：索引节点内部布局（节点大小规则、bset 形态、
D11 的消息缓冲区）」），而第 4 层今天未冻结（前提七，已在第一节核实），所以修改本身不违反任何冻结约束，
但按 `.claude/singlefs-ai-sop/rules/kb-discipline.md` 与本项目的决策纪律，它需要一次正式的决策更新
（改正文 + 记一笔决策变更史），不能只在 C161 这条欠账行里悄悄说一句就算数。

**这条例外站不站得住，理由是什么**：前端与节点缓冲区想解决的是同一类问题——避免小更新直接命中随机的叶子位置。
前端已经用「批量攒、排序去重、批量插入」买到了这个好处；在同一棵树上再叠一层节点缓冲区，
买的是**同一个好处的第二份**，边际收益没有实测数字支持这一点（E56（消息缓冲的收益 vs ε） 的四组收益数据
全部来自「无 write buffer 前端」的基线，D11（索引节点要不要留消息缓冲区）「两条代价」一节自己写着
「E56 不是『无批量』基线」，E7（离线索引 harness） 同样写着「没有一个对照组带 write buffer 前端」）——
**丙这条修订买到的是「避免 U1 correctness 缺口」，付出的是「记账树拿不到 D11 已定项 2 测出的 2.91–5.03× 收益，
且这个损失的量至今没有实验量过」**。我判它值得付，因为 U1 是正确性问题（读到旧值），
错误的严重度与「少拿一份未量化的吞吐收益」不对称；但这笔损失应该被记成一条新的待验证欠账，
不能当作零代价接受。

| 甲（打补丁：禁止旁路写前端树） | 对前端树等价于丙 | 与丙同 | 与丙同 | 与丙同 |
| 乙 | **两个独立缺口**：①seq 跨级/跨发布不可比；②读算法用位置代替 seq，并行 flush 下位置不追踪 seq | 若要给出非扫描答案必须放弃「跨发布留存」这个卖点，退化成与丙同等的排空门；否则继承 C80 的未解缺口 | 最贵：seq 位宽/语义改动（第 3 层）+ 读算法改动（第 4 层，且取消提前终止） | 无直接冲突，但代价最大、收益最不确定 |
| 丙 | **干净**：结构性排除同 key 跨级共存 | 干净：前端树靠发布门，缓冲区树延用 D11 既有的「陈旧可检出」答案，两者都不需要扫描 | 需要一条新的发布前置门（协议步骤，不加字节） | **与 D11 已定项 6 字面冲突，须显式修订** |

## 三、U2：发布点排空到哪一层、崩溃后没排空的前端条目从哪来（问题 2 的正式回答）

C80（`.claude/kb/checks-owed.md:90`）与前提十已经确立两个硬事实：① 发布出去的根若不含同批事务的记账更新，
崩溃回到该根后账是旧的，I-3.1（已分配统计对得上）必红；② journal 记录施加时只换所选根的四个指针字段
（树表单元指针、中央映射树根指针、树 ID 水位、回退下界 F），**不携带任何树语义**——前端或缓冲区里
未落盘的内容，journal 从格式上就没打算替它兜底。这意味着：**任何一条臂，只要允许「已发布的根不完整反映
某个 key 的最新前端写入」，就必然要么违反 I-3.1，要么去发明一套 journal 没有的新恢复机制**。三条臂在这一步的
真实差别只有一件事：它们各自要不要允许这种情况发生。

**甲 / 丙对前端树（记账 / 反向索引 / LRU）给出同一个答案，且是非扫描的**：**排空到叶，且这是发布协议的前置条件**——
COW 重写、生成新根、写 journal 记录这几步之前，先无条件把该 checkpoint 窗口内三棵前端树的 write buffer 排空
（按 key 排序去重、批量插入到叶）。这一步与 D11（索引节点要不要留消息缓冲区）已定项 5「任何一次索引重建之前
各层缓冲必须先排空，由重建入口强制」（`.claude/kb/decisions/11-索引节点要不要留消息缓冲区.md:231`）是同一个纪律形状，
只是把触发点从「重建入口」换成「发布入口」。排空之后，前端在内存里已经清空，剩下要发布的就是普通的树状态，
走既有的 COW/根/journal 机制，**不需要 journal 携带任何前端内容，也不需要恢复时做任何扫描**：
崩溃发生在排空完成之前 ⇒ 那次发布根本没有产生新根，所选根仍是上一个已发布的根，前端内存态直接丢弃即可
（它对应的更新从未被承诺过持久）；崩溃发生在排空完成之后、根发布之前或之后 ⇒ 前端已空，剩下的就是标准的
根 + journal 前缀恢复，没有特殊情况。这个答案不靠事后扫一遍，是一个协议顺序问题，答案给得出。

**丙对非前端树（用 ε > 0 缓冲区的树）沿用 D11（索引节点要不要留消息缓冲区）已定项 3 / 4 已经接受的答案，
不是一个新问题**：节点缓冲区里未下刷的消息本来就被定义成「纯派生态」，可以「从权威态（单元 + 记账 + 墓碑单元）
重算」——损失它不等于损失数据，只是让树暂时「陈旧」，由已定项 3 的检出机制（单元自带写序 + 实例表 + 祖先表）
兜底。这个重算属于 `.claude/rules/fs-design.md:24`「checker / 审计」一档（**必须**遍历），不属于「运行时决策路径」
一档（不许遍历）——它不是每次分配决策都要问的问题，是一次性的一致性检出，与 I-3.1（已分配统计对得上） 本身
允许全盘遍历是同一个豁免。**这个答案在 C161 之前就已经被 D11（索引节点要不要留消息缓冲区）已定项 1 的定案接受了**，
C161 没有让它变得更糟，丙也没有替它解决——它维持现状。

**乙给不出干净答案，除非放弃自己的卖点**：乙允许前端内容直接进根缓冲区、跨发布留存不强制排空，
这是它相对甲 / 丙唯一的结构差异（否则就是丙）。但记账树的「能重算」这条判据本身是未实测的神谕
（`.claude/kb/decisions/11-索引节点要不要留消息缓冲区.md` 已定项 6 树轴原文：「记账树按 D21『离线可由遍历重算』
判能，但 E59（缓冲消息能不能只从单元重算） 那一列是神谕、未实测（C113（扫描重建时多版单元的现行版本判定无输入））」），
而记账是 I-3.1（已分配统计对得上） 直接盯着的那本账，C80 的红线正是为它画的。**若乙坚持不强制排空，
它就是在没有实测支持的前提下，把记账的崩溃一致性押在一个未经检验的重算机制上**——这正是 C80 今天仍然
「原样成立」的那个缺口，乙没有关上它，只是继承了它。若乙改为强制排空（与甲 / 丙一致），它就失去了
「允许跨发布留存」这个唯一还能与丙区分的优势，同时仍然背着 U1 的两个缺口——**没有任何理由再选乙**。

## 四、问题 1：seq 的第一版口径在两级并存时够不够判新旧

**不够，而且分两层不够**：

1. **口径本身的射程不够**：seq 按「(标签, 树, 设备, 代) 在一次发布里被写进树的第几次」定义，
   **在同一代（checkpoint）内部才有意义**，跨代（发布）不可比——但这对记账树本身不是问题，因为代本身
   就是记账 key 的一段（D5（快照 / 空间记账机制） 已定项 3），跨代的两条「同一统计量」在 key 层面就是不同的 key，
   不会走到需要比较 seq 的那一步。**真正没有射程的是反向索引与 LRU 两棵树**：D8（核心索引结构） 已定项 7
   自己留的骑手写着「反向索引与 LRU 的 key 布局全仓一个字都没有 ⇒ 它们定 key 时必须让去重窗口同样被 `T_dirty`
   界住（代进 key，或别的等效办法），否则 4 字节在那两棵树上没有依据」——这条骑手至今没有兑现，
   意味着这两棵树上「seq 够不够判新旧」这个问题今天连前提都不成立（key 布局本身未定义）。
2. **即使口径本身够用，乙的读算法也用不上它**：见第二节对乙的分析——乙的读算法比较的是物理位置，不是 seq 值。

**不够时要改成什么**：若继续走乙这条路，需要两处改动——① seq 的宽度与语义从「一次发布内的序数」
改成至少「跨发布可比」（背景材料建议的「全池单调」是一种，另一种是「实例内单调、覆盖 write buffer
在缓冲体系里最长可能滞留的窗口」），这个改动是对 D8（核心索引结构） 已定项 7 已定字段的修改，落在
D15（格式冻结政策） **第 3 层**（各 keyspace 的 key/value 编码，`.claude/kb/decisions/15-格式冻结政策.md:63`：
「第 3 层：各 keyspace 的 key 编码（D8 的 locality_id / inode / offset）」——write buffer 条目最终落进树的
key/value 编码，属于这一层）；② 读算法从「位置优先、找到就停」改成「显式比较 seq、走完整条路径」，
这个改动动的是索引节点如何组织和解释消息，落在 D15（格式冻结政策） **第 4 层**（索引节点内部布局，
`.claude/kb/decisions/15-格式冻结政策.md:64`）。**两层都要动，且都未冻结（前提七），格式上不违规，
但工程量与代价比背景材料原先设想的（只改 seq 位宽）大得多**——这正是我判乙不值得选的直接原因。
若走丙这条路（本轮推荐），seq 的第一版口径完全不需要改：丙下前端树永远不会有第二个位置持有同一个 key，
seq 只需要继续完成它原来的工作（front-end 内部一次 flush 批次的去重），不需要跨级可比。

## 五、问题 4：每条臂的会红检查与判别力自证

| 臂 | 会红检查 | 判别力自证 |
|---|---|---|
| 甲（未打补丁） | 造一份镜像：记账树某 key K 在叶里是前端已 flush 的新值（txg 较大），同一路径上某内部节点的缓冲区里留着一条更旧的旁路写入（txg 较小）；用标准「缓冲区优先、找到就停」的读算法读 K，断言读到的是叶里的新值 | 把两条消息的新旧对调（缓冲区放新的、叶放旧的），检查必须由红转绿；未打补丁的甲在两种构造下都读缓冲区那条，断言恒失败，证明它没有分辨力——这正是甲出局的证据本身 |
| 乙 | 造两个并行 flush 批次：批次 A（seq 较小）人为延迟其插入完成时间，批次 B（seq 较大）先完成并被推送到比 A 更浅的层；断言按「离根近即新」读出的是批次 B（seq 更大、逻辑更新）——如果两批次都写同一个 key、且调度让 A 反而落在更浅处，断言应失败 | 把两批次的调度顺序对调（正常序 vs 颠倒序），检查必须相应由绿转红、由红转绿；只有当读算法真的显式比较 seq（而非信任位置）时，两种调度下都应读到 seq 更大的那条，检查才能稳定为绿 |
| 丙 | 造一份镜像，模拟「发布协议在前端排空完成前就已经生成新根并写出 journal 记录」（即故意跳过排空这一步）；断言：任一已发布 checkpoint 对应的三棵前端树，其 write buffer 在该 txg 时点的内存快照必须为空——跳过排空后这条断言应失败，且 I-3.1（已分配统计对得上） 在崩溃点重放里对应那个发布点应判红 | 把排空调用从发布路径里摘掉（故障注入），同一检查必须由绿转红——与 C80（`.claude/kb/checks-owed.md:90`） 自己写的判别力自证要求「故障注入自证——把记账排空从发布路径摘掉，同一检查必须红」逐字一致，说明丙对 C80 给出的答案本身是可验的 |

## 六、问题 3 的直接结论（已在第二节丙的小节里展开，这里只收口）

**冲突是真的，不是读法问题。** D11（索引节点要不要留消息缓冲区） 已定项 6 的树轴给记账树的判定是
ε = 0.65（因为它判「能重算」），丙给记账树的判定是 ε = 0（因为它是前端树）——两条判定对同一棵树、
同一个字段给出不同的值，不是「可以并存的两种读法」，是字面矛盾。要接受丙，必须显式修订已定项 6，
加一条前端例外，并把这次修订记进当月的决策变更史；不能假装这条冲突不存在，也不能只在 C161 的欠账行里
含糊带过。这条例外本身的收益（避免 U1 缺口）大于它的已知代价（记账树拿不到已定项 2 测出的吞吐收益，
且这个代价的量未测），但代价没测是一个应该被记下来的欠账，不是可以忽略的零。

## 七、什么观测会推翻这份结论

- **若能证明「同一棵树，前端与节点缓冲区永远不会被要求同时开启」这句话在设计意图上就是假的**
  （比如将来出现一棵树，业务上必须既要前端的批量去重、又要节点缓冲区的下推收益，且两者的边际收益经实测
  确实是可加的、不是重叠的），丙的核心论据（前端已经买到了节点缓冲区想买的大部分好处）就会被推翻，
  这时候值得重新评估乙，并且要先把它的读算法改成显式比较 seq 的版本再评估，不能沿用「找到就停」那版。
- **若把乙的读算法改成「走完整路径、显式比较 seq」之后，实测读放大的代价小于预期**
  （比如树高本身很矮，走完整路径与提前终止差别不大），乙相对丙的劣势会显著缩小，那时候丙「必须修改已定条款」
  这个代价可能变得不划算，值得重新比较。这个实验目前没有任何数据，是一处明确的空白。
- **若 D11（索引节点要不要留消息缓冲区） 已定项 6 的树轴谓词「记账树能重算」被证明其实是假的**
  （E59（缓冲消息能不能只从单元重算） 的记账那一列至今是未实测的神谕，C113（扫描重建时多版单元的现行版本判定无输入）
  只是提供了机制候选，没有真正把它测过），那么记账树本来就该 ε = 0，丙与已定项 6 的冲突会自动消失——
  但这时候丙的胜出理由会从「避免了一个真实的字面冲突」退化成「侥幸没撞上」，论证的性质变了，需要重写。
- **若甲的旁路写入路径（读法 A）被证明在实践中根本不会被任何写者使用**（比如工程实现上只给前端树暴露
  一个写入口，物理上不存在第二条写路径），甲的 U1 缺口会变成一个不可达状态，此时甲与丙就是逐字相同的东西，
  谈不上谁推翻谁，只是名字选哪个的问题——我在第二节已经指出这一点，这里不是新结论，是提醒它仍然是判断丙
  的一个隐藏前提：丙要成立，也隐含地要求「前端树不存在第二条写路径」这件事被显式写下来，不能只靠约定。
