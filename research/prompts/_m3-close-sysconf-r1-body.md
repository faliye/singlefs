## 二、实现今天的样子（主 agent 的观测，2026-10-19，行号按树副本 `~/.local/share/singlefs/work/m3-close-sysconf-r1-tree`：此刻主工作区的 `crates/` 原样拷出，主工作区这几天还会打补丁，腿只读那份副本）

- **R2 判不出谓词**：在 `crates/singlefs-core/src/recovery.rs:4306` `system_configuration_witness_is_undecidable`，判法是「有槽设备报读错，且没有一块盘两槽都自证过」。
  - 可写挂载读阶段的见证读（`mount::newer_publish_witness`）与取号那一刻读见证值（`transaction::self_verified_system_configurations_of_every_device`）都按它判。
  - 撕裂的轮换（读得出、自证不过、设备没报错）不算判不出。
  - fsid 不符的槽不数进「报读错」，落在判得出那一边，没有用例（C707）。
- **取号**：在 `crates/singlefs-core/src/transaction.rs:931` `next_instance_generation_to_acquire`。式子是 max(每块盘两槽里全部自证过的槽的实例代号, 根环里全部根记录的实例代号) + 1，只读盘。
  - journal 环与单元写序不进这个 max。
  - C555 的调查补丁在式子里多读 journal 环一路：调查副本上 225 格 0 红，但只写了单元就崩的那几格照样撞号（`research/prompts/seed540096-investigation/report.md`）。
- **落后逐盘核**：在 `crates/singlefs-core/src/mount.rs:5938` `devices_behind_the_current_version`，与可写挂载取号之前的落后支共用判法 `what_a_device_behind_the_version_lacks`。
  - 「落后」与「缺所选那一版的单元，或它的根写在这块盘上而根环槽里不是它」两样同时出现就记下。
  - C593 的盘面（轮换没持久，加同盘一份单元坏）因此每次可写挂载都拒。
- **恢复报告**：`RecoveryReport.devices_without_a_mountable_system_configuration_slot` 点名两槽都不可择的盘（C463 已有那一半），没有自愈重写。
- **池级 checker 的反向链**：在 `crates/singlefs-checker/src/walk.rs:9043` `expected_back_chain_of`。
  - 计数器 − 1 那一条是别的实例的，就判这一条是本实例第一条、链应为 0。
  - 恢复只在同实例前一条在盘上时比链（`crates/singlefs-core/src/recovery.rs:4388` `judge_back_chain_against_the_previous_record_on_disk`）。
  - 前一槽躺着上一条时间线的残留记录时，两边判法不同（C569，推的，没造镜像量）。
- 里程碑四在同几份文件（`recovery.rs`、`mount.rs`、`transaction.rs`、`walk.rs`）里有没提交的改动。用户 2026-10-19 定「和里程碑4 没有关系 你们到时候一起提交的」，所以不算阻挡。
- 方案按 `crates/` 今天的实现来谈。

## 三、格

### S1　C596：R2 之后仍判不出的盘面怎么走出只读

盘面是：有槽读错，且没有一块盘两槽都自证过。今天之后每次可写挂载都拒，只读挂载不写盘，那一槽永远没有机会被重写。

候选至少列这几种，各自写清楚：怎么触发、谁有权触发、写哪几个槽、写之前要核什么才不会把确认过的写丢掉、出错时盘上留下什么。
- 管理员工具：离线定点重写系统配置槽。
- 只读挂载下的定点修复。
- 可写挂载在附加条件下放行：条件写全。
- 接受永远只读，写成已知代价。

每个候选另写两样：
- 能不能让「之后可写挂载做成，且确认过的写不丢」的用例成立。
- 与 D22 已定项 8「单故障承诺」、C583「双故障形不罩」的关系，以及与 C331 取甲那一判是否相容。

### S2　C593：落后且缺一份单元的盘

这种盘面是一次正常崩溃（最后一次轮换没持久）加同盘一份单元坏，今天永久拒可写。

候选：
- 改法丁：落后与否看这块盘上有没有那一版的末条记录（`yi-j-mount.diff`，被攻过零轮）。
- 维持拒。
- 别的形态。

对每个候选写：挂着之后的入口与会话每次改动（`mounted_session.rs` 里调 `devices_behind_the_current_version` 那一处）怎么跟着改；同池旧快照的盘经入口「洗白」那一形（C585）会不会重新打开。

### S3　C707：fsid 不符的槽落 R2 哪一边

fsid 不符的槽，指读得出、校验和过而 fsid 不同的槽。它算「读错」，还是算「自证不过」？

两边分别会改变哪些盘面的结局：撕裂、整盘换成别池的盘、只换一槽。和 S1 选的出路怎么配。

### S4　C463：一块盘两槽全废之后的自愈重写

自愈重写与取号重写是同一个写。要写清：
- 在哪一刻写：恢复里，还是可写挂载取号时。
- 写之前核什么。
- 写失败怎么报。
- 与 S1 的出路是不是同一个机制。

### S5　C555：两盘最新系统配置槽都坏时取号撞号

最小历史 4 步：
1. 覆盖写到 txg 7。
2. 可写挂载取号 2，只落前 23 条写。
3. 两盘最新系统配置槽各翻坏一个字节。
4. 再可写挂载，又取号 2。

候选二选一：
- **照 C583 先例写成「不罩」**：故障模型不收「两块盘最新槽在之后的写落盘之后都持续坏」。要写清这句射程与单故障承诺的关系。
- **改取号式子**：max 里再并进 journal 环、单元写序或别的来源。要写清只写了单元就崩的那几格怎么也不撞，以及多读一路的代价。

再找第三种。

### S6　C569：反向链遇上前一槽的残留记录

候选二选一：
- **收**：I-8.6 的「本实例第一条」改成不看前一槽上是谁、按计数器与实例表认，checker 跟着改。
- **不收**：I-8.6 射程写明这一格判违例是有意的。

两种各写一样：恢复与 checker 在每种盘面上判得一不一致。另写：这一格在今天的写路径上能不能造出来，造出来要几步。
