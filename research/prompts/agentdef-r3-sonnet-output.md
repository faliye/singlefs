### 1.3 上一条论证要自己打的补丁：规则原文「这一轮里新冒出来的」字面指的是「在第三轮才首次出现」

**如实标注**：`three-way-inference.md`「这一轮里新冒出来的零轮形态」那半句，字面上说的是「在第三轮本身才第一次被提出」的形态；而「复核改判」表这条收严**第一次出现是在第二轮**（`agentdef-r2-opus-output.md`，第二轮攻方腿报告），不是第三轮。用这句话直接扣它，字面上有一处松动。

但这处松动不改变 1.2 的结论，理由是**时序算术，不是读法之争**：agentdef 这条线到本轮（agentdef-r3）为止只剩这一轮；不论这条收严生于第二轮还是第三轮，它能拿到的「被别的腿攻过」的轮次**最多只有本轮这一轮**（因为线在本轮之后就停，`.claude/rules/three-way-inference.md`「第三轮之后停，不开第四轮」对这条线本身适用，不是只对「第三轮里新提的形态」适用）。而「三轮里多数打穿才算」这条判据要的是**三轮量级**的检验；一轮（不论那一轮是第二轮的延续还是第三轮本身）够不上这个量。⇒ 就算不援引「这一轮里新冒出来的」那半句的字面，仅凭「线到本轮为止、三轮的判据没有第四轮可用」这条更基础的算术，结论仍然是**它今天最多只能进交用户表标注轮次不足，不能被当成「留到某个未来开工时段」悬空处理**——1.2 节引的 c381 先例是「同一条线走到最后一轮时，如何处置一个新出现的零轮形态」，取的是这层算术上的可比性，不是逐字对应「第三轮才出现」这个前提。

### 3.2 处置本身：不用它推翻 C 格，这一步的推理站得住，但有一处没挑明的松动

判决的推理是：C 格的断言是「**今天**读 `decisions/06:42` 这一行原文，推不出门禁 94 号罩不罩得到它」——这是对**当前文本**的可读性做的判断，`git log -S` 能直接核（两处相关文字确实只在 `11a551b` 才出现），**不需要**借助「当时是不是真判错过」这件历史事实。⇒ 就算「06:42 曾判错」这件事本身无法坐实（只有自述），C 格本体（文本今天的可读性缺口）依然站得住——**这一步推理是对的**。

但有一处判决没挑明的松动，值得记进本轮辩护的限度：**C 格在第一轮的原始措辞**（`agentdef-r1-main-verification.md:26`）是「触发这次改动的那处判错…**规则措辞『对着载体今天的原文核一遍』治不了它自己的触发案例**」——这句话的修辞力量部分来自「**这条规则是被一次真实发生的判错事件催生、而它连自己被催生的那个案例都治不了**」这个历史叙事。如果「那次判错」从未真实发生（自述失实或记混），C 格「治不了自己的触发案例」这句仍然**字面成立**（因为「今天读原文推不出结论」这件事是真的），但它的**修辞框架**（这是一条规则在自己诞生的现场就失灵的证据）就站不住了——**没有「触发案例」这回事，就无所谓「治不了触发案例」**，能剩下的只是「这行文字今天读不出来」这个更弱的、纯架构性的批评（任何一行需要跨文件才能判断准确性的决策文本，都有这个问题，不特别指向这次改动）。

### 3.3 推翻 C 格（或至少推翻它「治得了/治不了触发案例」这句修辞）要补什么证据

**要推翻 C 格本体（今天读 `decisions/06:42` 推不出门禁 94 号覆盖与否）**：需要证明「阶段同步发生那一刻」读到的 06:42 文本本身包含了判断门禁 94 号覆盖范围所需的全部信息。⚠️ 现查今天原文（`sed -n '42p' .claude/kb/decisions/06-快照实现模型.md`）确实写了「94 号判两个 crate 的依赖闭包交集」这一句，但 `git log -S` 已经证实**这句正是 `11a551b`——也就是那次判定改判的同一次提交——才写进去的**；换句话说，今天这行文字之所以自解释，是因为它已经是**改判之后**的版本。这不能反过来证明「改判之前」的旧文本也是自解释的——`owed-batch1to3-sync.md:36`（本报告 3.1 节已引）明写旧文本是「**欠**：C12（增量语义共用）：② 的引用计数旁表与运行时共用增量语义时……」，一个字都没提门禁 94 号的射程。⇒ 这条线索**证不了**「C 格技术本体已经被修好」，只能证明「这一行**从这次改判起**，往后每次阶段同步重新扫到它时会更容易判」——这是 C468 那条「同步记录该带上原始候选表与判定报告」的收严要解决的东西（让后来者能分清「改判前」与「改判后」），不是 C 格本身的反例。

**要推翻/坐实「触发案例」这个修辞层**：需要下面任一件——
- （坐实方向）找到 `/tmp` 下当时那份中间态候选表或逐行判定报告的副本（若仍在某个会话的暂存目录或另一台机器上），或者找到当时那个子 agent 会话的完整记录（`agent-handover.py` 一类的交接摘要，如果当时留过），直接看到「那一刻」的判定确实是错的；
- （推翻方向）如果找不到任何这样的旁证，且当轮会话记录也查无实据，那么严格说「触发案例」这个历史事件目前**既不能坐实也不能证伪**，公允的处置是把 C 格里那句「它治不了自己的触发案例」降级成「它治不了『一行判断需要跨文件才能确认』这一类场景，`06:42` 是其中一个例子」——**这与判决自己在 C468 里已经写的态度一致**（「连事件本身都只有当事人的一面之词」），只是没有回头把这句降级也写回 C 格本身。

**结论**：判决「不拿 C468 推翻 C 格」这个处置本身**站得住**——C 格的核心技术论断不依赖那次判错是否真实发生。但判决对 C 格**修辞框架**（「治不了自己的触发案例」）与**技术本体**（「今天文本读不出来」）两者的边界没有分开处理，留下一处没被挑明的松动：C 格标签仍然是「坐实，而且最重」，而这份「最重」的分量有一部分来自一个此刻既不能坐实、也不能证伪的历史叙事。

什么现象会推翻这一条：找到 06:42 那次判错的原始副本或会话记录，证明它确有其事——C 格「触发案例」这层修辞被坐实，判决今天的处置反而应该更强而不是更弱；反过来，如果查出根本没有第三方能验证的原始记录留存于任何会话历史，那么下一次涉及 C 格的判决行文应把「治不了自己的触发案例」改写成「治不了『需要跨文件判断』这一类问题」，去掉对一个单方陈述历史事件的依赖。
