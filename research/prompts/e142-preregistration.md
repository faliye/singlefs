# E142 跑前登记：第一个事务的干跑

写于 2026-09-13 02:34 JST，装置写之前。

## 问的是

把 [first-txn-layout.md](../../.claude/kb/first-txn-layout.md) 那张字节表**原样写成字节**：mkfs + 一个小文件 + 一次发布，两块 512 槽的盘，
然后冷启动读回、按 D13（验证路线） 已定项 4 的层 0 崩溃状态集合逐个恢复。目的不是量性能，是让代码把「字节表里哪几格写不出来、
哪几条已定条款在字节层面互相顶着」逼出来——每一处装置不得不自己补的取法都要报成一行 `gap`。

## 被测对象的定义（逐字贴，装置照这几句写）

- D16（发布语义） 已定项 7：「**发布的持久顺序：单元/节点 → 屏障 → journal 记录 → 屏障 → 根槽（FUA）；恢复重放施加前必须逐项验证点名单元。**」
- D16（发布语义） 已定项 6：「**发布计数器：每次发布 checkpoint_txg + 1，fsync 触发的也是发布；同一个计数就是根槽轮转键、记账的代、重放水位。**」
- D13（验证路线） 已定项 4：「**崩溃点重放的崩溃状态集合怎么定义**……**屏障切段、段内任意整写子集；撕裂态并进「没持久」，没持久的位置放旧字节且真的生成镜像；镜像双写按设备各算一次。**」
- D23（journal 的角色与格式） 已定项 14：「**恢复只施加 `(实例代号, checkpoint_txg)` 严格大于所选根的记录；陈旧 tail 只是「从哪开始扫环」的优化，不再决定重放集合。**」
  与它的五条口径：「jsn 严格连续（断号即止）、**`(实例代号, checkpoint_txg)` 大于根的水位**、提交标记齐全的事务才施加（D23（journal 的角色与格式）已定项 7）、
  施加前逐项验证点名单元（D16（发布语义）已定项 7，E77（发布的持久顺序）证明承重）、**所选根的实例在实例表里有回退行时，该实例的记录只施加到回退行的 W 为止**」。
- D22（单元原子性怎么合成） 已定项 7 的根记录字段表（2026-09-13 起 250 字节，含回退下界 F 8），已定项 2 的根环参数（R = 3、跨区轮转、槽宽 = 探测到的 `physical_block_size`）。
- 判 oracle 用 E77（发布的持久顺序） 判据 1 的原句：「违例 = 根槽已持久而恢复 ≠ 新态或走读失败；或恢复出部分事务；或嫁接了校验失败的单元。根槽未持久时新旧两态都合法（fsync 没返回）。」
- 宽度与取值一律照 [first-txn-layout.md](../../.claude/kb/first-txn-layout.md) 零到七各节；表里标「预想」的照预想值取；表里给不出的，装置自己取一个并报 `gap`。

## 倾向与反过来

倾向：判据 1–5、7 全过，判据 6 的 `differing_states = 0`（第一版每次发布都写根，重放下界 = 根的水位 ⇒ 记录在根之下永远施加不到）；
`gap` 至少 10 行，其中最硬的三条预计是：码 2 头宽字节表算错（84 对 94）且不自描述 key 宽；映射树同树两种 key 宽（27 / 25）；
记录里没有新根，「施加」在指针层无定义（C284（施加一条记录在指针层上做什么没有定义））。
反过来：判据 4 违例 > 0 而装置无错 ⇒ 说明两道屏障 + FUA 在这组字节上罩不住某个状态，那是 D16（发布语义） 已定项 7 要重开的证据，不许改 oracle 去迁就。
判据 6 有差异 ⇒ journal 在第一个事务里确实承重，「redo 为空」那句要重看。

## 它答不了的

1. 层 0 是段内整写子集，撕裂不枚举（D13（验证路线） 已定项 4 的口径）；真实 FLUSH / FUA 是否生效归 C6（块层语义假设写错）。
2. 只有一次发布、一条记录：环回绕、多记录前缀、实例切换、回退行一个都碰不到。
3. 码 2 头宽、映射 key 补齐、根记录字段序、32 字节校验和算法、反向链首值都是装置自取的预想值；它们对不对由 `gap` 行交给决策，装置不判。
4. 「施加一条记录」装置只做验证不改状态，所以判据 6 的结论只对「施加 = 验证」这一读法成立。
5. 纯确定性（fsid、时间戳都是固定参数）：跑 N 遍一样，证据强度来自绝对值断言与变异表。
