## 二、逐格推导

### A1：码 1、码 3、D27 容器槽、权威树的码 2 节点（记账树）

**码 3（打包记录单元）**：类身份段表（已定项 11）：

> 「42 | 单元类型标签……43 | 出生树 ID | 8……61 | 容器出生代 | 8……73 | 诞生代号 | 8 | 只记这一次写……93 | 写序（实例代号 4 + 事务号低 48 位）| 10」——`.claude/kb/decisions/18-块里携带什么信息.md:752-876`

出生树（偏移 43）、诞生代号（偏移 73，"只记这一次写"正是候选要的按版本区分的出生 txg 语义，与 I-1.8 把它列进码 3 全序键第一位吻合）、实例代号（写序字段前 4 字节）都已经在，缺的同样只有出生序号 4 字节，与码 2 同一笔改动。这里要注意一个容易混淆的点：候选的 key 没有用到「容器号」「容器出生代」这两个已有字段。这不构成漏洞——出生序号的计数作用域是「(树, checkpoint 号, 实例代号)，内存里发、从 0 起，不分类」（背景材料第 20 行），也就是同一作用域里不同容器的写事件也会拿到不同的出生序号，所以 key 不需要额外携带容器号就能把同一作用域内的不同物理写区分开。

**D27 容器槽**：候选定义明写「D27 槽里的 key 另带（带自己的类标签，不假设复用五元组那 1 字节）」——即候选自己承诺槽要携带独立的一份 key。但 D27 已定项 3 原文：

也就是 D27 槽的具体字段表今天确实是格式级空白，这与⑨⑦「D27 的十三条已定项一条不重开」并不冲突——⑦ 说的是不需要重开已经定下的十三条（打包顺序、装载纪律等），槽自己的类身份段本来就是待定，候选没有假装它已经定了，E134 的 `slot_extra_over_five_tuple`/`slot_extra_over_e114_pack` 两栏也明写这是"增量"估算而非定案字段表。所以 A1 在 D27 槽这一类上不是"重建不出"，而是"这一类的字段表本身还没写"——这是已知的、候选自己承认的未定状态，不构成 A1 判据要求的"重建出的与引用侧的可能不同"那种反例。

**判决**：A1 没打穿。

### A2：第 4 格·共享与 reflink、第 5 格·搬迁不变

候选的 key 完全由"出生"属性构成（出生树、出生 txg、写序或实例代号+出生序号），不含任何与"谁在引用我""我现在在哪个物理位置"相关的量。

共享（reflink/快照）下多个引用者要凑出同一个 key：

> 「**自包不可变数据带唯一一条指向**：「我属于谁」——五元组……⚠️ **它指的是出生所有者，不是「当前所有引用者」**。」——`.claude/kb/decisions/01-数据可移动性-反向索引.md:82-107`（已定项 5）

单元的身份字段记的是出生时刻的属性，与后续有多少引用者、引用者是谁无关。候选把这条原则原样继承到自己的 key 上：出生树、出生 txg、写序/出生序号都在单元写出那一刻就确定，此后不因新增引用（reflink、快照）而改变。而候选把这些字段的一份副本放进每一个指向它的指针里（"指向码 1 的指针 +26""指向码 2/3 的指针 +24"），任何新建的引用（无论来自哪棵树、哪次 reflink）在构造指针时，只能是"复制"被引用单元已经确定的这些字段，而不是"重新计算"——这与 COW 指针一贯的构造方式（子节点先写好，父节点的指针内容就是抄那个子节点的身份）是同一件事，没有找到会让两个引用者凑出不同 key 的机制。

搬迁（后台整理换物理位置）：

> 「⚠️ **搬迁不改 `birth`（2026-09-06 收口）**：后台整理把一个单元从一个落点搬到另一个落点，**不是「发布一个新版本」**——逻辑内容一个字节没变，只是物理位置换了。按 D5（快照 / 空间记账机制） 给 `birth(b)` 的定义句「块被**发布**的那个 checkpoint 号」，搬迁不产生新的发布事件 ⇒ `birth` 原样跟着单元走。」——`.claude/kb/decisions/05-快照-空间记账机制.md:1-68`

这条讲的是"出生 txg"（birth）不因搬迁而变；同一逻辑，出生树、写序/出生序号也是写出那一刻的属性，物理搬迁不触碰它们。而搬迁需要更新的东西，D19 已定项 5 已经讲清楚：

> 「中央映射……**解引用与释放判定的唯一入口**。搬迁只改这里一条条目，**「谁引用我」根本不用知道**」——`.claude/kb/decisions/19-块指针的结构与宽度预算.md:42-161`（已定项 5）

也就是搬迁改的是映射条目的 VALUE（物理落点），不是 KEY；候选的 key 恰好完全不含物理位置信息，搬迁天然不需要改任何引用者手里的 key 副本。这与 A2 判据要求的"逐字节搬迁之后 key 变了、有引用者要改"直接相反。

**判决**：A2 没打穿。

### A3：类标签从哪来

逐条路径过一遍，每条路径进映射那一刻手里有什么、类标签从哪来：

**解引用**：D19 未定项 8 已经把这条路径的逐段来路写清楚了：

> 「**逐段来路，2026-09-10 现查**：① 单元类型标签由查找路径推得」——`.claude/kb/decisions/19-块指针的结构与宽度预算.md:42-161`（未定项 8）

extent 树只指向码 1 数据单元，inode 树内部节点条目自带"类型段"（"0 ⇒ 子节点是码 2 索引节点……2 ⇒ 子节点是码 3 容器"，`.claude/kb/decisions/08-核心索引结构.md:327-446` 已定项 6），所以对绝大多数指针，类标签是从"你正在走哪棵树的哪条边"这个静态信息就能确定的，零额外 I/O。

**D5 释放判定**：D5 的 O(1) 判定本身不需要类标签：

> 「判定(ptr): birth = ptr.birth // 指针内联字段，零次额外 I/O; p = head.prev_snap_txg // 活头头部一个标量，常驻内存」——`.claude/kb/decisions/05-快照-空间记账机制.md:171-190`

这一步只读 `ptr.birth` 和 `head.prev_snap_txg`，判定"立即释放"还是"进 deadlist"，全程不涉及类标签。真正要落到中央映射构造 key 的那一步，是"立即释放"或"deadlist 条目要记版本身份"之后、真正去解引用/释放的那个动作——而那个动作走的是"解引用"同一条路径，类标签依旧是查找路径给的。这与 A3 判据表里"那条路径是单一引用块上的 D5 释放判定时，它出局"的触发条件不符——这条路径本身不需要类标签，不构成"多一次查找"。

**deadlist/livelist 条目处理**：候选下 deadlist/livelist 条目本身就要记录版本身份（即候选的 key，含类标签），处理这些条目时类标签已经是条目自带的一个字段，不需要现查。

**搬迁**：搬迁前要先读被搬迁的单元本身（把它的字节整个复制到新位置），单元自己的头（偏移 6）就带着类标签，同样零额外查找。

**checker / 扫描重建**：checker 与扫描重建读的正是单元本身，偏移 6 就是类标签，天然自带。

**模型对拍**：对拍用的内存模型按定义直接维护候选的 key 结构（含类标签），不存在"查找"这个概念。

**判决**：A3 没有找到"要多读一次单元或多查一棵树才拿得到类标签"的路径，也没有触发"单一引用块上的 D5 释放判定"这一出局条件；A3 本身不构成候选出局的理由，只是记一笔（这也与判据表本身的表述一致："记『多一次查找』"是默认记账动作，不是判负动作，只有撞在 D5 释放判定那一条才判负）。

### A6：⑨ 里任何别的一句

逐句核对⑨的引用与源文件原文，找到的唯一一处出入是引用精度问题，不是内容错误：

⑨㈠ 原文：「它另在第 2 格记「多一次查找」：派生树的码 2 节点头里没有 key 区间（D18（块里携带什么信息） 已定项 2 只给记账树与 inode 树），而 **D8（核心索引结构） 逐字**「**分隔 key** = 该孩子创建时的最小 key」，搬迁从落点出发拿不到它，要回树里下探一次。」

现查源文件，"分隔 key = 该孩子创建时的最小 key" 这句话的原文出处：

> 「**分隔 key** = 该孩子创建时的最小 key，条目按分隔 key 单调递增，查找取最后一个分隔 key ≤ 目标 key 的条目。」——`.claude/kb/decisions/08-核心索引结构.md:327-446`（已定项 6，标题「inode 树的叶是码 3 打包记录单元」）

这句话是 D8 已定项 6 讨论 inode 树内部节点条目结构时给出的定义，不是 D8 全篇的通用陈述。⑨㈠ 把它笼统标成"D8 逐字"，在引用精度上把"分项级"（已定项 6，专讲 inode 树）收窄成了"决策级"（笼统的 D8）。这个出入不影响⑨㈠ 论证的实质方向——B 树的分隔 key 本来就是内部节点条目结构的通用概念，D8 已定项 6 恰好是仓里唯一显式写出这个定义的地方，用它来说明"没有 key 区间的派生树节点，分隔 key 信息不在自己头里，要靠树本身给"这个论点是成立的；但作为逐字引用，源头应标"D8 已定项 6"而非笼统的"D8"。

除此之外，逐句核对⑨㈡（出生落点+每槽版本号键出局的理由）、⑨㈢（按类复用写序键最弱读法在第 3 格输一次、以及收严办法）、⑨㈣（随机 16 字节标识键最弱读法在第 3 格输一次）、⑨㈦（候选集完整性不触发）里点名的条款与数字（D18 已定项 12、D23 已定项 14、I-1.2、D21 已定项 1 等），都能在附录原文里找到对应且逐字一致的支撑，没有发现第二处对不上或说宽的句子。

**判决**：A6 没有找到实质性的打穿点，有一处引用精度（分项级 vs 决策级）问题，记录在案但不改判⑨的结论。
