## 判决：三条腿打中的是同一个病根的三个面

**病根**：这一轮把 `.claude/rules/format-evolution.md`「决策正文只写现状，依据写成指针；决策与实验双向登记」一节的规则**抄了第二份进定义**，抄的时候漏了一半、歪了一处，而两份定义各抄一半又互设成对方的前置。

## 改法（四条，全部落在定义与规则上）

**一、定义不抄规则，只指过去。** 两份定义里这一轮新加的规则细节全部删掉，改成「开工先读那一整节」加本定义特有的分工。这同时修掉本地腿的七格与正推腿的「查法没给」（查法就在那一节靠前的「决策正文长什么样」里）。

**二、死结按「谁判关系」拆，不按「谁写文件」拆。** 判关系是主 agent 的活（它定案时本来就要判这个实验撑不撑这条分项）；`kb-scribe` 的定位是「照规格写，不补内容、不做判断」，它的写范围本来就含 `.claude/kb/**`（含实验页）。所以：**规格改了某条分项的依据段时，同一份规格要带上那个实验页「影响的决策」表里对应那几行的改动**；书记员照写两边，缺行就停下报告、不自己判关系。`main-agent.md` 的调度表那一行跟着写明这一点。

**三、「每条决策一行」改成「每条分项一行」，规则与定义一起改。** 规则第 39 行按 75 号的实际判法与仓里 123 个组合的实际形态改写：一条决策撑着几条分项就写几行，只作背景提到的才写决策级一行。

**四、待回填清单那一句按 75 号的实际判法写**：清单里的决策整段跳过双向检查，所以那时写决策级、不查依据段；等它瘦身完再补分项号与关系。

## 攻方腿自己提的改法：不采纳

攻方腿给了 A / B / C 三个改法，按 `.claude/rules/three-way-inference.md`「攻方腿自己提的收严，只在它自己的模型上量过，算『没被攻过』」——它们被攻过零轮，且 A 的做法（执行员 `grep` 全部决策文件枚举分项）把判关系的活压给了执行员，与上面第二条的分工相反。这一轮取主 agent 的改法，A / B / C 不采纳；攻方腿的四格命中全部采纳。
