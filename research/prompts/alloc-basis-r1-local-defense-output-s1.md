1. DOES NOT HOLD. The cross-reference table in F2 defines the outer formula's "allocated" term as exactly statistic item 1 ("allocated bytes") and "defer_pending_release" term as exactly statistic item 5 ("defer-queue pending-release bytes, keyed by release generation"). F13 states that statistic item 1 includes released-but-deferred slots (as "allocated_slots" counter is "still-allocated slots plus released-but-still-inside-the-defer-window slots"), and statistic item 5 is directly from the "deferred_slots" counter, which tracks only the deferred slots. F14 confirms this overlap with example numbers: allocated=23 slots includes 10 deferred slots, and defer=10 slots. Thus, subtracting both in F1's formula subtracts the same deferred bytes twice. Refuted if: statistic item 1 does not include released-but-deferred slots or statistic item 5 is not the deferred slots.

2. DOES NOT HOLD. F5 states that pushing empty publishes to raise F does not change user-visible state, so statistics (including those used in F1's outer formula) remain unchanged. F3 specifies the gates are in series: outer formula is checked first, and if it fails, the inner formula's raise-F logic is never reached. Since statistics do not change during empty publishes, the outer formula's Available remains insufficient after raising F, so the request is rejected immediately without retry. This violates F4's requirement 2 for bounded reclaim, as the request fails before any reclaim steps can occur. Refuted if: pushing empty publishes to raise F changes the statistics used in the outer formula.

3. DOES NOT HOLD. F13 explicitly states there is no code path that decrements the "allocated_slots" counter (and thus statistic item 1) due to ring rotation; it only increments on allocation and has no decrement mechanism. F10 defines I-3.1's union as all self-verifying roots unfiltered (reading i), so when a root is overwritten (e.g., root t-24 overwritten by publish t), it is no longer in the ring, causing the walked sum to drop, but the allocated statistic remains unchanged, violating I-3.1. For the separate part: yes, the time-lag problem equally affects reading (iii) when F_effective=0 and no rollback, because reading (iii) (valid per F7 and txg >= F_effective) still excludes overwritten roots from the union when they leave the ring (as they are no longer in the ring), but the allocated statistic does not decrement, so the mismatch occurs regardless of the root reading. Refuted if: there is a code path that decrements allocated_slots when a root is overwritten.

4. For Q4a and Q4b, there is no reading or definition under C (which uses reading i) that prevents the mismatch. Reading (iii) structurally avoids both problems: for Q4a, it excludes roots with txg < F_effective, so reused blocks cannot be referenced by such roots in the union; for Q4b, F7's instance-table predicate excludes abandoned roots, so they are not in the union. Reading (i) includes all self-verifying roots unfiltered (F13), causing the mismatch in both cases. This is not a shared gap; reading (i) has the issue while reading (iii) does not, and it is specific to the root reading choice, not inherent to union-based approaches. Refuted if: a definition exists that excludes invalid roots or roots with txg < F_effective from the I-3.1 union under reading (i).
