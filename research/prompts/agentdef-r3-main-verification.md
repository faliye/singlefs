## 三、H 格：本地腿的数我校正了一格，结论不变

本地腿两份干净样本一致：让一件真变了的事实产生零候选行，**只要一个动作**（把旧事实那一格写成以「新立：」开头），它在事实表里留痕（那个前缀看得见）、在候选表里**不留痕**（`build_candidates` 对这个前缀无条件 `continue`，`research/scripts/stale-candidates.py:270-271`），而且给不出判据（两份都答 `CANNOT-STATE-CRITERION`，理由是事实表的五列里没有基准那一版的原文）。

**「一个动作」这个数我现查之后校正成三个**，`--check-facts` 还有一道闸（`stale-candidates.py:317`、词表在 `:73`）：标「新立：」的行，检索词在基准那一版有命中、或新事实里出现「落地 / 实现 / 已有 / 跑完 / 还清 / 有了」任一个，当场判红。所以要过闸得同时做三件事：标「新立：」、选一个基准那一版零命中的检索词、新事实避开那六个词。

**这一格是我自己的材料缺口，不是本地腿的错**：我给它的事实表只写了候选表构建那一步的无条件跳过（FACT-9），没写 `--check-facts` 的这道闸，它据此答「1」是忠实的。形态同 `.claude/singlefs-ai-sop/rules/evidence-discipline.md`「喂给多方论证的背景材料，本身要先核」——材料里少一条，腿照样给出「一致」的答案。

**校正之后 H 格照旧成立**，而且工具作者自己那句话就把这三件事写全了（`stale-candidates.py:36`，整行抄）：

> 写表人给一件真变了的事实选一个基准里从没出现过的检索词、再标「新立：」，新事实里又避开落地 / 实现这类字，过得了闸，

三件事一件都不落在候选表里，而现有流程只强制「逐行全看」候选表那 138 行，事实表那 21 行没有任何一道闸要求主 agent 重读。
