## G2　判据复用：source 上游 lib.sh

### G2-1　LIB 路径按脚本自己的位置算，不按 ROOT 算——这个选择对不对

现查 `.claude/gate.d/95-fixture-claims.sh` 第 46-49 行：

```
set -uo pipefail
ROOT="${1:-$(cd "$(dirname "$0")/../.." && pwd)}"
cd "$ROOT" 2>/dev/null || exit 2
LIB="$(cd "$(dirname "$0")/../.." && pwd)/.claude/singlefs-ai-sop/scripts/lib.sh"
```

`ROOT` 可以由 `$1` 覆盖（被判的那个仓，样本沙箱跑时是一个临时目录）；`LIB` 只认 `$0` 的物理位置，
不看 `$1`。

**判定：一致，这个选择是对的，且被两条独立的调用路径逼着必须这么写**，现查两处调用点：

1. `stage-selftest.sh` 第 64-65 行（`.claude/singlefs-ai-sop/scripts/stage-selftest.sh`）：
   ```
   out="$(cd "$work" && env -u GATE_BASE -u GATE_STAGED_FROM bash "$stage" "$work" 2>&1)" || got=$?
   ```
   `$stage` 是真仓里 `.claude/gate.d/95-fixture-claims.sh` 的固定路径（`$0`），`$work` 是
   `mktemp -d` 建的沙箱（`$1`/`ROOT`）。沙箱里没有 `.claude/singlefs-ai-sop/` 副本——若 `LIB`
   按 `ROOT` 算，`source "$LIB"` 会找不到文件，`require_date_arithmetic` 之前就先炸。
   按 `$0` 算，`LIB` 落在真仓，`source` 成功。这正是背景材料第 30 行说的那句话，现查为真。

2. `.claude/singlefs-ai-sop/scripts/gate.sh` 第 78-81 行（`--staged` 分支）：
   ```
   if [[ -d "$src_root/.claude/$staged_family" && ! -d "$staged_tree/.claude/$staged_family" ]]; then
     mkdir -p "$staged_tree/.claude"; cp -r "$src_root/.claude/$staged_family" "$staged_tree/.claude/"
   fi
   ```
   `--staged` 建临时 worktree 时显式把 `.claude/singlefs-ai-sop/` 拷进去（因为它被
   `.gitignore` 第 6 行 `/.claude/singlefs-ai-sop/` 挡着，`git worktree add` 不会带它）。
   门禁随后用 `bash "$f" "$ROOT"`（`gate.sh` 第 424 行左右，`$ROOT` 此时是 worktree）跑
   `.claude/gate.d/*.sh`，`$0` 与 `$1` 都落在同一棵 worktree 里，`LIB` 按 `$0` 算同样能找到
   刚拷进去的那份副本。

两条路径分别覆盖了「样本沙箱没有 SOP 副本」与「`--staged` worktree 有 SOP 副本但是拷贝来的」
两种现场，`LIB` 按 `$0` 算在两边都对得上；反过来按 `ROOT` 算，第 1 条会找不到文件。
**推翻条件**：如果将来出现第三种调用方式，`$0` 所在目录与 `.claude/singlefs-ai-sop/` 的相对
位置不再是「上两级」，这个写法会找错文件——但现查全仓没有第三条调用路径。

### G2-2　子 shell 里的静默失效三条，现查踩中没踩中

`.claude/singlefs-ai-sop/rules/command-safety.md` 第 160 行「子 shell 里的赋值传不回父进程」：
该条管的是 `rc="$(run_one ...)"` 这种把子 shell 的内部赋值指望父进程读到的写法。
95-fixture-claims.sh 第 120-193 行那一段不这么用：子 shell的输出经 `> "$date_report" 2>&1`
整段写文件，不经任何 `$(...)` 赋值；子 shell 内部 `start_date="$(project_start_date ...)"`
这一行本身就在子 shell 里，读也在子 shell 里，不跨进程边界。**判定：一致，没有踩中这一条。**

第 182 行「进程边界上的三种静默失效」表列的三种，逐条核：

- 「`set -e` 下写 `里层; rc=$?`」——95-fixture-claims.sh 第 663 行写的是
  `) > "$date_report" 2>&1 || date_rc=$?`，即表格里给的正确写法
  `if 里层; then rc=0; else rc=$?; fi` 的等价形式（`||` 短路，只在左边非零时才执行赋值），
  不是那个反例形式。**一致，没有踩中。**
- 「`export X="$(cmd)"` / `local x="$(cmd)"`」——现查第 120-193 行没有一处 `local` 或
  `export` 包着命令替换（`grep -n "local \|export "` 命中 0 次）。**一致，没有踩中。**
- 「握手用的环境变量漏给子进程」——这一段没有起第三层进程，不适用。

### G2-3　require_date_arithmetic 在子 shell 里 die，报告文件有没有 COUNT，外层判什么

`.claude/singlefs-ai-sop/scripts/lib.sh` 第 49 行 `die() { bad "$1"; shift; ...; exit 1; }`，
`bad`/`howto` 都是 `printf`，不写文件、只写 stdout（会被子 shell 的 `2>&1` 重定向吸进
`$date_report`）。

**现场实测**（不改动仓库文件，在 `/tmp/claude-1000/c510-forward/g2-die-test/` 里复现）：
把 `PATH` 前置一个假的、不认 `-d` 的 `date`，直接跑真仓的 `.claude/gate.d/95-fixture-claims.sh`：

```
$ PATH="/tmp/claude-1000/c510-forward/g2-die-test/bin:$PATH" bash .claude/gate.d/95-fixture-claims.sh > /tmp/.../g2-full-out.txt 2>&1; echo "REAL_EXIT=$?"
REAL_EXIT=1
  ✗ 日期这一条没跑完，报告里没有计数行：
        ✗ 这台机器的 date 不认 -d，算不出日期下界
           → 怎么办： 日期检查要 GNU date（coreutils）：装上它，或把它放到 PATH 前面，再重跑。env.sh 也查这一项。
     → 怎么办：上面是子 shell 的原样输出；多半是 lib.sh 取不到或 git 列不出文件，按它说的修。
```

报告文件里**没有 COUNT**（`die` 在 `require_date_arithmetic` 那一行就把子 shell 带走，
后面 `printf 'COUNT\t...'` 那一行根本没跑到）。外层第 692-693 行的判据：

```
elif ! grep -q '^COUNT' "$date_report"; then
  date_rc=1
  echo "  ✗ 日期这一条没跑完，报告里没有计数行："
```

命中的正是这一支（不是 `^BAD(NAME|BODY)`，也不是 `^SKIP`），把 `die` 的原样输出整段
`sed 's/^/      /'` 缩进抄进汇总，同时给出通用 howto。**判定：一致，这不是静默失败**——
外层专门为「子 shell 里 die 了」这条路径写了分支，判红且带出路，直接引用了原始 die 信息，
不是「悄悄绿过去」。

### G2-4　上游改名或改边界口径，本仓这一条会怎样——已现场复现两种截然不同的结果

两个场景分开测，都不碰真仓文件，用 `/tmp/claude-1000/c510-forward/` 下的独立 scratch 仓：

**场景 A：只改边界口径（`DATE_GRACE_DAYS` 从 7 改成 0），不改名。**
现查 `.claude/singlefs-ai-sop/scripts/lib.sh` 第 568 行 `DATE_GRACE_DAYS=7`。在 scratch 仓里
把它改成 0，造一个「提交前 5 天」的日期（旧口径 7 天宽限内合法，新口径 0 天宽限内不合法），
跑 scratch 仓自己那份 95-fixture-claims.sh：

```
  ✗ 1 个文件名里的日期不可能是真的：
      records/2026-08-27-test.md：2026-08-27 早于这个仓第一个提交（2026-09-01）0 天以上
```

**判定：一致，这不是失效，是设计意图本身**——95-fixture-claims.sh 第 625 行注释写的就是
「两套装置算同一个量，就要落到同一个数」，边界口径变了、本仓这一条自动跟着变，
这正是「不另写一份」要的效果。

**场景 B：上游把 `date_out_of_range` 改名（不改签名、不改语义，只改名字），95 号自己没跟着改。**
在 scratch 仓里把 `lib.sh` 全文的 `date_out_of_range` 批量改成 `date_out_of_bounds_RENAMED`，
95-fixture-claims.sh 原样不动（它仍然调用旧名字），造一个带日期的文件名，跑：

```
  ✓ 日期都可能是真的（文件名：5 个文件里 1 条带日期；样本正文：1 份 .md 里 0 个日期；下界 2026-09-23 往前宽 7 天）
```

**报绿**。用一份不删报告文件的调试版脚本把 `$date_report` 的原始内容抄出来看：

```
.claude/gate.d/95-fixture-claims-debug.sh: line 140: date_out_of_range: command not found
COUNT	5	1	1	0	2026-09-23
```

`date_out_of_range` 在 `if why="$(date_out_of_range "$found" "$start_date")"; then` 这一行
（95-fixture-claims.sh 第 644 行）里调用，`if` 的条件位置不受 `set -e` 约束，未定义函数报
「command not found」、退出码 127，`if` 判定为假，等价于「这个日期在范围内」——因为
`scanned`/`dated`/`COUNT` 那几个计数器是在调用 `date_out_of_range` **之前**就已经累加好的
（第 639-641 行），所以就算这次调用彻底没跑，`COUNT` 那一行照样打印，外层落进
「有 COUNT ⇒ 判读」这一支，把 `command not found` 那一行原样丢在报告里但从没被任何
分支读过（`grep -qE '^BAD(NAME|BODY)'` 找不到 `BAD` 开头的行，`grep -q '^SKIP'` 也找不到）。

**这是一条具体、可复现的静默失效路径**：上游只要改名或删掉这个函数（不用改语义），
本仓这一条就会从「该判某个日期不合法」悄悄变成「什么都没判、但报告说都合法」。

**`.singlefs-ai-sop-version` 版本戳这道闸罩不罩得住它——罩不住，现查两点理由**：

1. 现查 `.claude/singlefs-ai-sop/scripts/gate.sh` 第 180-186 行，版本不一致时的处置是
   `bad "规范版本不一致…"` + `howto "先读一遍上游这几版改了什么…确认没有影响你这次改动，
   再跑 install.sh 更新版本戳"`——这是叫人**去读 CHANGELOG、自己判断有没有影响**，不是
   机械核对某个函数名还在不在。版本戳照常被抬升、这句 howto 照常被读过，`date_out_of_range`
   照样可以在无人注意的情况下被改名——机械上没有任何东西会去核对 95 号里写死的这个函数名
   在新版 `lib.sh` 里还存不存在。
2. 就算版本不一致时那一格真的判红，那是 `gate.sh` 里独立的「规范版本」阶段（第 166 行
   `head1 "规范版本"`），与「项目本地阶段」（95 号所在的第 392 行起那一段）是两个不同的
   `head1` 区块、各自独立记分；「规范版本」判红不会让 95 号这一条本身跟着判红——两者脱钩。

**推翻这条打中的现象**：如果日后 lib.sh 改成在函数不存在时主动 `set -o errexit` 之外再加一层
`command -v date_out_of_range >/dev/null || die ...` 的存在性自检，或者 95-fixture-claims.sh
把 `if why="$(date_out_of_range ...)"` 的调用移出「命令位置」的 `if` 条件（改成先判定函数
是否存在），这条打中就会被堵上；现查两处现在都没有这层自检。

### G4-2　gate-stage 一行说两件事，会不会让射程被读歪——**打中**，现查到一处具体的字面缩窄

现查 `.claude/gate.d/95-fixture-claims.sh` 第 2 行（这一行会被 `.claude/singlefs-ai-sop/scripts/gate.sh`

但这只覆盖了「查 C510 这一行」的路径，不覆盖「只读门禁汇总」的路径。

**推翻条件**：如果把第 2 行的 `gate-stage` 改成同时点出「全仓文件名」与「样本正文」两个
不同射程（比如「阶段头部声称的判别力样本必须真的存在；文件名（全仓）与样本正文里的日期
也不许是编的」），这条打中就被堵上；现查第 2 行今天没有这么写。
