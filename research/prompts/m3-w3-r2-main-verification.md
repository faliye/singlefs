### 攻方：修补本身与没被看过的地方
- **K2 造出来了崩溃恢复抛弃建 inode 的发布再建**：原型在冻结树副本自造流，层 0 全域枚举 P 的 65 548 个状态；A 历史 262 192 张镜像，131 072 张有合法的跨抛弃重发（E175 一次没有）；池级 checker 0 红，两个最强形 0 误报。
- **打中误报，病根在今天的条款**：管理员回退的水位取环里全部根的最大值，被崩溃恢复抛弃、读得出的高水位根也算进去（D23 已定项 14「水位」那一格），回退把水位抬过这条时间线没发过的号。原型 B 有 4 个状态造出这一形；以下几种读法在合法镜像上红：字面 C2a 配 I-9.30 ③、C3r 的「记录盖住水位」、谱系带回退之后的水位。模型同类 163 700 / 231 204 张，最短 `[create,crash-hide,rollback1]`；所有误报都在跳升之后，跳升只来自被抛弃的根。判：**这是条款的问题**，不是某个候选的。号只是被浪费、不重复，产品语义没错；但 W3 的任何历史核对都要么容许这一跳，要么把回退取水位改成只取没被抛弃的根（改 D23 已定项 14，零轮）。交用户（第四节 Y1）。
- 清扫删行、实例切换、A → B → A：两个最强形都没打中（模型 258 万次清扫、195 万次切换、58 万次回到先前 cur）。一次抽样。
- 攻方的最强形：C2aL（每次水位变了的发布都留台阶行，加 I-9.30 ①②③；谱系多带 cur 的水位、判「等于」）与 C3rL（C3rs 加谱系带 |log(cur)|，判「等于」），V1 臂都漏 0。代价（推的）：C2aL 台阶行 34 B / 次，≤ 462 行时 0 单元，超过后记账树长一层、每次发布 +1–2 单元，谱系 +8 B / 次回退，要给 I-3.13 与 D5 已定项 2 开例外；C3rL 每次建 inode 的发布 +2 单元、+4 写，P 那段崩溃状态 65 543 → 1 048 583。
