1. For A-R4: A non-front-end write to key X enters node buffer. Front-end flush for X writes to leaf and removes older messages on path (so node buffer's X is cleared). Another non-front-end write for X adds to node buffer. Read checks node buffer first, returns stale X (older than leaf's X). For K=2 accounting: checkpoint deletes generation 1, but fsync publishes before front-end flush for delete; crash leaves generation 1 present.  
For B-D: Root buffer has X with seq=1 (older), child buffer has X with seq=2 (newer). Pushing down replaces child's newer with root's older; read returns stale value. Across publishes: publish 1 writes X (seq=2 in child), publish 2 writes X (seq=1 but later position), pushing down replaces child's newer with root's older; read returns stale value.  
For B-mono: Root buffer has X with seq=5 (older), child buffer has X with seq=6 (newer). Pushing down replaces child's newer with root's older; read returns stale value.  
For C: No sequence causes stale read or accounting disagreement for front-end trees (e.g., accounting). Draining before publish ensures all updates are in leaves; no buffers for front-end trees avoids stale reads. Inode tree issues are separate but not relevant for accounting.  

2. A-R4: Node layout has node buffers only for non-front-end updates; seq remains 4 bytes in values for non-front-end. Tree axis: front-end trees (accounting, etc.) set to epsilon 0 (violates F5's "can" trees recommendation but practical); inode tree epsilon 0.65. Write amplification: lower for front-end trees (direct leaf writes), but path traversal during flush adds cost. Read amplification: higher (check front end, then node buffers, then leaves).  
B-D: Seq removed from values; no seq used. Tree axis: all trees use epsilon 0.65 (violates F5 for "can" trees). Write amplification: high (pushing down across levels). Read amplification: high (check root to leaf buffers).  
B-mono: Seq is global monotonic counter (4 bytes still sufficient for most cases); width unchanged. Tree axis: same as B-D. Write/Read amplification: similar to B-D.  
C: Node layout: front-end trees have no buffers (epsilon 0); inode tree has buffers. Seq used only in leaves for front-end trees (within same publish window). Tree axis: front-end trees (can) epsilon 0; inode tree (cannot) epsilon 0.65 (aligns with F5 if draining removes pending messages). Write amplification: low for front-end trees (direct leaf writes); higher for inode tree. Read amplification: low for front-end trees (direct leaf reads); higher for inode tree.
