## 二、攻 P2（全案最重的一步）

P2 的整句话是：C113 定案「把『观测 + 判定规则』升成了『**某个逻辑身份此刻的现行物理落点**』这个问题的可判定答案」。
我按反推问：**如果这句话是假的，我本该看到什么？** 答案是——
E104 里那个号称在比落点的度量，其实在副本世界里恒真；
以及，存在一条纯良性的运维历史，走完之后 I-6.10 必红。两样我都看到了。

### H1：C113 答的是版本，不是落点（源码级）

1. 加密开启，w = 2（`02-RAID条带策略.md:47` 第一版 2 盘；`:318` 逐字「位置条目每个副本一条」）。
2. 单元 U 的两份副本**逐字节相同**：`09-加密.md:278` 逐字「D2 已定『N 个副本是同一份密文写 N 遍、共用一个 nonce』」。
3. 扫描重建按 C113 P3 择新。两份的 (key, 写者树, 诞生代号, 写序) 逐字段相同 ⇒ **副本归并成一个候选**
   （`experiments/104-扫描重建的现行版本判定.md:43` 逐字：「同 key、写者树、诞生代号、写序的多份可读单元先归并成一个候选」）。
4. 问「这个身份此刻的现行物理落点是哪几个」。第 3 步已经把落点这一维折掉了。

**破的是**：P2 那句「升成了『某个逻辑身份此刻的现行物理落点』的可判定答案」。
规则升成的是**现行版本**的可判定答案；从版本到**落点集合**、再到「哪几个落点该出现在映射层里」，中间两步没有任何条款。

**我去看了 E104 的源码，它更糟——那一格是恒真的**（`research/e7-index-bench/src/bin/e104_current_version.rs`）：

| 行 | 逐字 | 后果 |
|---|---|---|
| `:400-410` | 「w 份副本逐字节相同…各占一个落点；**主落点 = 最小的那个**」，`locs.sort(); let primary = locs[0];` | 真值把「正确落点」**定义**成最小的那个 |
| `:1118-1123` | 遍历 `w.disk`（按落点升序的 `BTreeMap`），`if arm.merge_replicas && !seen_versions.insert((u.key, u.writer, u.birth, u.wseq)) { continue; }` | 归并保留**先遇到的**，也就是最小的那个 |
| `:1212-1213` | `match re.data.get(k) { … Some(p) if p != l => o.wrong += 1 … }` | 拿单个 `u64` 比 |

⇒ 重建代码和真值代码用的是**同一条「最小落点获胜」的隐含规则**，而那条规则**只存在于模型里**，
C113 定案 P3 一个字都没写它。所以 `wrong = 0` 在副本世界里说明不了任何事。
这正是 `.claude/singlefs-ai-sop/rules/test-discipline.md`「只让多条臂互相比，测不出所有臂一起错」那条的形态，
而且这里连臂都不用——是被测方与真值方一起错。
E104 自己在隔壁那一格已经诚实标过同样的病（`e104_current_version.rs:1130-1131` 逐字：
「⚠️ 模型按事务写容器…键末尾补一个写序当平局破除器，**那一维是模型的补丁不是规则的一部分**」），
落点这一维没标。

**最小改动**：
① C113 的输出口径改写成「现行版本 **+ 它的落点集合**」，并写明落点集合的正确性由谁保证；
② E104 加一个落点维的度量，并造一个「真值落点不是最小的那个」的世界（今天造不出来，因为模型没有搬运——见 H2）；
③ 在那之前，P2 只能写成「C113 给了**版本**的可判定答案」，落点那一步单列为**未答**。

### H2′：P3 第二条腿压着的那个前提，D9 已定项 7 内部就不自洽

- `09-加密.md:414` 逐字：「外加**预授权的可回收集合 E**（**已疏散的源头可并入 A**）」。
- `09-加密.md:427` 逐字：「(b) (A∪E) 与 {S 的单元 / 根环 / journal 环 / 准入预留 / 重放窗口内待重用} **交集为空**」，其中 S 是**上锁瞬间**的权威状态。

上锁那一刻，「已疏散的源头」还装着 S 的单元。于是：
- 若 E 在签发时就把这些落点列进去 ⇒ **(b) 当场为假**；

两读都不能让残留消失，所以 H2 在两读下都成立。这不是提案造出来的洞，但 **P3 的第二条腿整条压在上面**，提案要么引用它要么绕开它，不能当它不在。

### H3：这一层存在的**理由**在无密钥侧用不了（元数据那一半）

1. `09-加密.md:220-222` 逐字给出这一层的机制理由：「元数据块可以原样搬…但**父指针里的地址字段仍要改，而父节点的载荷是密文**」。⇒ 瓶颈是**元数据**，不是数据。
2. `invariants.md:187` 逐字（I-6.2 第二张白名单）：元数据类明文头「**仅此而已**（五元组 / key 区间等身份字段一律进密文）」；`18-块里携带什么信息.md:476-478` 同一句。
3. ⇒ 无密钥侧扫到一个码 2 / 码 3 单元时，读得到的只有共同前缀（magic / 格式版本 / flags 含类标签 / 声明长度 / 头校验和）+ nonce 代号 + MAC。**它读不出这个单元是谁。**
4. ⇒ 搬完之后，搬运工要更新映射层里「这个单元」那一条，而它**说不出那一条的键**。
5. 想让它说得出，只能把元数据的逻辑身份摆进明文。码 2 的身份是「树 ID + 层级 + **该树已定携带的 key 区间**」（`18-块里携带什么信息.md:427`）。
6. ⇒ 那就是把 btree 内部节点的**分隔 key** 摆进明文。`09-加密.md:234` 逐字：
   「**这个范围差异是已定项 5 成立的全部依据，守不住就等于走了 ZFS 那条路。**」

**破的是**：P2 的「派生态，重建源 = 单元自描述」对**元数据**成立。
单元自描述在元数据上是密文，无密钥读不到；而这一层的立身理由正是元数据。

**仓里已经独立记过同一件事**：`checks-owed.md:117`（C110）逐字
「I-1.2（块头写序已发布）在加密开启后对元数据类**判不了**（诞生代号在密文）」，处置是
「I-1.2 写明射程（**无密钥扫描只对数据单元类判**）」。

**最小改动（二选一，都要用户定案）**：
- 明写这一层**只覆盖码 1**，同时承认 `09-加密.md:220-222` 那条机制理由在这一层里**没有对应物**
  ⇒ 锁盘期搬不了元数据 ⇒ 给 `03-空间分配.md:8-10` 的自动整理硬承诺记一处例外与代价；

## 六、攻「这一层与明文反向索引是同一棵树还是两棵」

两种答法各撞什么：

### 同一棵树

- **撞 I-6.2。** 一棵树的内部节点是**码 2（索引节点）**，而码 2 的身份字段一律进密文（`invariants.md:187`、`18-块里携带什么信息.md:476-478`）
  ⇒ **一棵明文结构的索引节点住在密文里，无密钥走不动它。**
  要走得动，就得给它一个**新的单元类码**（明文索引节点）——那是 D18 已定项 11 登记表的变更（`18-…:144`）**加** D9 明文豁免清单的变更（`09-加密.md:7-9`）。P1 / P2 一个字没提。
- **撞态别。** 映射层（P2 判派生）与反向索引（`21-…:378` 方向已定权威）在同一棵树里，一棵树只能有一个态别。
  判权威 ⇒ P2 倒；判派生 ⇒ 与 D21 未定项 1 的方向对撞。

### 两棵树

- **撞的是同一条 I-6.2**（两棵树各自的内部节点仍是码 2）⇒ 新单元类那笔账**两种答法都要付**。
  ⇒ 它**不是**「一棵还是两棵」的分歧点，是这一项自己欠的一格。写下来免得下一轮把它当成二选一的代价去比。
- **多出来的那笔账在原子性，不在棵数。** 两棵树意味着无密钥侧要**跨两个结构维持一致**
  （搬一个块要同时改映射条目与反向索引条目），而无密钥侧**没有事务**——记账在密文、journal 在密文。
  ⇒ 两棵之间的原子性今天没有任何机制；一棵树能把它压成一次写。
  而 D22（单元原子性怎么合成）的机制在锁盘期成不成立，全仓没写。

**我的判断**：这一问在「**新单元类**」与「**无密钥侧的原子性**」这两笔账记下来之前**不该答**——
答了就是在两个都没定的量上做二选一。

## 七、替代方案 R：把明文层从「映射」改成「搬运记录」，逻辑身份一个字节都不进明文

| **R3 明文物理边（可选）** | 物理槽 → 物理槽，不含任何逻辑身份 | 条带成员表就是这个形状，见下 |

### 语义

- **权威的「逻辑身份 → 物理落点」留在密文指针里，一个字节都不挪出去。**
- 锁盘期的搬运**不改任何映射**，只追加一条 R1 记录；源不回收（本来就不能，`03-空间分配.md:22-23`）。
- 解锁时，密钥侧按序号顺序**逐条**回放：验目的地那个单元的头校验和与记录一致、**且解密后 MAC 通过**、
  且它的逻辑身份等于源落点在权威树里的那一条 ⇒ 把权威指针改成目的地，源进 deadlist。
  任一条对不上 ⇒ **那一条**不予采信（逐条，不是整批），源仍是权威。

### 它对着提案逐条买到什么

| 项 | 提案 | R |
|---|---|---|
| 码 2 / 3 能不能搬（H3） | 表达不了它们的键 | 能——记录里只有物理落点 |
| 分隔 key 泄漏（H3 第 6 步） | 要支持码 2 就得把 key 区间摆明文 ⇒ 走 ZFS 那条路 | **零**：明文侧不含任何逻辑身份，泄漏面比今天的已定**还小** |
| w 副本（Q1） | 一条条目一个落点 | 每副本一条记录 |
| 共享单元（Q3） | 重建给不出别名条目 ⇒ I-6.10 必红 | 不重建映射，不受影响 |
| 残留（H2） | 源与目的逐字段相同、归并成一个候选 ⇒ 永久钉住且 checker 恒红 | 记录显式说了谁是源 ⇒ 解锁即可回收 |
| 完整性（H5） | 两边都在明文，攻击者同时改 ⇒ 比对为空 | 目的地那一份**要过 MAC**（密钥侧回放时做）⇒ 伪造进不来；攻击者能做的只剩「让某条搬运不被采信」= 拒绝服务，而**源还在** |
| 条带成员表（P5） | 住不进（键式不对） | 住得进 R3（键本来就是物理的）⇒ 给 `02-…:400` 的边界 ③ 开出第三条出路 |

### 代价（照实写全）

1. **锁盘期不再有任何查找能力。** 将来若要支持「无密钥只读挂载」，这条路直接堵死。
   今天不支持（挂载需要密钥），但这是把一扇门**焊上**，不是暂时关上。
2. **回放要在解锁之后、允许写之前做完**，长度 = 搬运条数。上界 = R1 环容量，容量进 A 的签发范围
   ⇒ **锁盘期能搬多少，由上锁那一刻定死**（比今天的 A∪E 又多一条上限）。
3. **权威指针要在解锁时被逐条改写**，代价就是 E94 已经量过的 `ptr_rewrite` 那一档：
   `experiments/94-搬共享落点的触碰面.md:53` 逐字，K=16、u=1024、phys 批次：ptr 244 个 COW 节点 vs central 62，**3.9×**；
   `:56` 逐字「**根引用重写恒 = K + 1**：每搬一批，全部保留快照的根记录都要跟着换」；
   `:68` 逐字 deadlist「ptr_rewrite 下每批要逐条重写 11–36 条…central_map 下**恒零重写**」。
   ⚠️ 这笔账**提案的 P2 也要付**，而且提案没提：P2 判派生态，就等于说权威落点仍在密文指针里
   （`09-加密.md:439` 逐字「逐字节搬运不动它，**只脏一个派生索引**」），
   那么解锁后必须有人把那个「脏」擦掉，擦法就是 ptr_rewrite。**R 只是把这笔账写明白，不是新增的。**
4. **D18 已定项 3 的一条依据变弱。** 数据单元头五元组明文「不新增泄漏面」的理由之一逐字是
   「同一份信息已经因为另一条已定决策躺在明文里了…D9 已定项 5 已定『明文反向索引』」（`18-块里携带什么信息.md:261-263`）。
   R 把明文侧的逻辑身份清空之后，那条理由没了 ⇒ 五元组明文成了**唯一**的明文身份来源，要**重新给理由**（不是推翻，是重新论证）。
5. **反向索引那一格 R 没解。** 若反向索引仍要回答「这个单元被谁引用」且答案是逻辑身份，它还是要明文身份。
   R3 只给物理边，回答不了那一问。那一问的消费者（balance / 缩容 / 快照删除，`21-…:382-383`）**都有密钥**，
   所以原则上可以整体搬进密文侧——但那是把 D9 已定项 5 的「明文反向索引」也一并撤掉，
   **比提案的变更更大，必须单独走用户定案**，不能挂在这一项下面过。
6. **多一类明文单元**（R1 环的记录单元）要进 D18 已定项 11 的登记表与 D9 的明文豁免清单——
   与第六节说的「新单元类」是同一笔账，两个方案都要付。

### 什么现象会推翻 R

- 「无密钥只读挂载」被定为要支持的能力 ⇒ R 当场作废（代价 1 是硬的）。
- 量出解锁时的回放 + ptr_rewrite 代价越过某条准入线（E94 只有结构量，没有耗时；
  `experiments/94-….md:99` 自陈「计数模型：无真实 I/O」）⇒ 要回到 central_map 那一档，
  而那一档就是「映射层是权威态」，C34 收口成权威、I-6.10 不可能成立。
- 找到一条历史，其中 R1 记录本身被离线攻击者篡改而回放**不能逐条拒绝**——我没找到（回放的每一条都要过 MAC，
  攻击者伪不出通过 MAC 的目的地单元），但这只是我没找到，不是排除。
