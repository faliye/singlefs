# 三方论证的做法

判据在 `.claude/rules/three-way-inference.md` 与 `.claude/rules/implementation-workflow.md`；`.claude/skills/three-way/SKILL.md` 只放到那一步才用的做法，节名与那两份规则里的节名、条目名相同。

## 引 kb 里的条目要整行抄，不许摘句——三处都管

什么时候读它：写三方材料、生成小节清单与附录时。

- **别用手抄**：用 `scripts/kb/quote-kb.py` 按「文件:行区间 / 文件@标题 / 文件~正则」把条款整段抽出来，它写完回读产物、与源文件逐字节比对。它是直接跑的文本工具（`.claude/hooks/lib_project_code_runs.py` 的 `TEXT_TOOLS_RUN_DIRECTLY`）：主 agent 与子 agent 都在仓根直接起，不经统一任务服务；清单、正文与出口写草稿目录里的绝对路径。取法、退出码与自证在它的文件头。
- **用 `@标题` 取，不用 `:行区间` 取**。例外是分项索引表：`### 已定项` 是 `#### 已定项 N` 的父节时，`@标题` 会把名下分项全带进来、`quote-kb.py --checklist` 退 6；这时索引表在清单里标「不抄」并写明「用 --extra 按行区间取」，行区间从标题的下一行起、到第一个 `####` 之前，被父节带出的子节标「抄」、理由以「随」开头。非用行区间不可时，抄完看一眼被抄内容的最后一行（不是产物最后那行外层围栏）：以 `|---|` 收尾、或内层代码围栏没闭合，就是少了一行（欠账 C244（机械抽取选错行区间，产物本身没有断裂痕迹））。
- **材料要带一张小节清单**：写材料时，先把全部小节列成一张表，逐节标「抄 / 不抄 / 为什么不抄」，这张表本身进材料；射程是这一轮要引的每一个 kb 文件，不只被判那一项所在的文件；漏掉的那一节在材料里要留下一行「不抄，因为……」，而不是无声消失。清单用 `scripts/kb/kb-sections.py` 生成（开头那段正文与一级标题下的正文各单独占一行；顶上是一级标题的文件，`checks-owed.md`、`crates/singlefs-checker/invariants/README.md`、`layout/01-first-txn.md` 这类，一级标题同样要有自己的行，欠账 C273：小节清单不认一级标题，自证用 `KB_SECTIONS_NO_H1=1`），机器生成的清单整份进材料，不再过滤。
- **附录用 `scripts/kb/quote-kb.py --checklist` 抽**：取法从清单里标「抄」的行自动生成，不手写第二份：`scripts/agents/checklist-specs.py 清单.md --cited 正文.md --out 出口.md [--extra 文件:行区间 …]`，它生成取法后用参数列表直接调 `quote-kb.py --checklist`；参数、退出码与自证在两份脚本的文件头。清单标「不抄」的小节、标题行却出现在附录里同一个源文件的抄录块中（多半是 `--extra 文件:A-B` 整段带进来的）退 6（欠账 C320）；`@标题` 取法的节尾与 `kb-sections.py` 算的不等退 7；「不抄」的理由声称别处抄了并点名一节、附录里没有那一节退 8。`--cited 正文.md` 要求正文里提到的每个 D / E / C / I 编号所在的 kb 文件都有一张清单，缺一张退 5（欠账 C234 第 ① 条的检查）；它只抓正文里字面出现的编号。
- **正文没点名的枢纽条款**：写材料时把正文里每一句「已经如何」当成待查的引用，拿它的动词全仓 grep 一遍，命中的欠账行进 `--extra`，命中的条款进清单。
- **「不抄」的理由要能被核**：凡是标「不抄，因为它的正文在别处抄了」的行，写之前去数一眼那个小节在不在。
- **判据表也要照这条办**：写判据表之前，先把被判那一项的正文从头读一遍，把每一句「要连同 X 一起答」都摘成一格。

## 判决由主 agent 做，不由投票做

什么时候读它：腿要交命令给主 agent 跑时。

- 腿要跑的（模型、复跑命令、拷来改过的装置与要喂钩子的输入）写成 `task-server/task submit -- <命令>` 的整条写进报告「要主 agent 跑的命令」一节；要写文件的，`--cwd` 给腿自己的草稿目录，或输出写绝对路径。要腿接着读输出的，新派的那条腿的派发提示写一行「承接：<前一份报告的路径>」并指到输出路径。
- 判决要引的数照旧由主 agent 复跑，做法照「核查与判决由主 agent 做，不派子 agent 去核子 agent」第 3 步。

## 多轮：一次打穿不算数，三轮里多数打穿才算

### 用户叫停、不写判决的轮

什么时候读它：往 `research/prompts/abandoned-rounds.tsv` 写一行之前。

登记一行收开工快照：四列用制表符分隔（轮名、日期 YYYY-MM-DD、为什么撂下、去向），同一轮只登记一行，每一行都要出处，不按日期判。

- 出处写成 `records/<文件>.md 第 N 行〔<原话>〕` 或 `records/<文件>.md:N〔<原话>〕`：路径里不带 `..`，解到真路径后仍在 `records/` 之内，文件存在；〔〕里逐字照抄出处那一行里的一段原话，不含〔〕、制表符与换行。
- 出处那一行要有这一轮的轮名（前后不连着别的轮名字符）与「」括起来的用户那句话（去掉空白后至少 6 个字），除这一轮的轮名外不许有别的轮名。别的轮名指仓里认得的轮名全集（`research/prompts/` 下 `_<轮>-body.md`、`<轮>-snapshot/`、`<轮>-main-verification.md` 与登记表里的轮名）与形如 `<名>-r<数字>` 的写法。
- 定位：拿〔〕里的原话在那份文件里找。恰好命中一次的，命中的那一行就是出处，行号只当提示（对不上而原话找得到照收）；命中几处而行号提示正落在其中一处的，取提示那一行；原话找不到，而行号提示那一行有这一轮的名字，且〔〕与那一行去掉 `.claude/kb/term-renames.md` 登记的新旧名与日期、再去掉空白与逗号之后〔〕逐字落在那一行里的（那一行只经过术语改名、删日期），取提示那一行。其余不收：没带原话；找不到而提示那一行没有这一轮的名字；去掉新旧名与日期之后仍对不上（〔〕写的是转述或改了别的字）；命中几处而提示不在其中（把行号写成含这一轮名字的那一处，或多抄几个字）。
- 出处不许指这一轮自己的材料（`research/prompts/<轮>-*`、`_<轮>-*`）、规则与定义文件、仓外路径、别的轮的叫停原话。
- 派发闸 ⑥ 与门禁 doc-process-records 的 abandoned-rounds 格共用一份登记行判法（日期、同一轮重复、出处、旧行名单四样）；出处不合这几条的 ⑥ 不收，那一轮照旧算开着，拒绝说明写没收的原因。出处那一行是开轮行、引规则行、「先放一放」这类，或那句话是不是用户为这一轮说的，由主 agent 核。

### 核查与判决由主 agent 做，不派子 agent 去核子 agent

什么时候读它：腿交齐之后、写判决之前。

1. 交 `task-server/task submit --cwd <草稿目录> -- python3 <仓根>/scripts/agents/snapshot-tree.py <轮> --out <草稿目录>/<轮>-tree --repository <仓根>`（`<草稿目录>` 在工作根 `~/.local/share/singlefs/work/` 下），`task-server/task wait <号>` 读结局：它照 `research/prompts/<轮>-snapshot/` 里每一份 `*-sha256.txt`（`judged-sha256.txt`、`kb-sha256.txt`、`crates-sha256.txt`……）与对 HEAD（旧轮对暂存区）的 diff 倒推出开工快照那一刻的树、逐份核 sha256。再直接跑 `python3 scripts/agents/cite-check.py <全部腿报告> --root <草稿目录>/<轮>-tree --background <背景材料>`。两条命令原样写进判决；它判了的（对不上、指到标题行、写成背景材料的行号）照它的判定写；它列成「没判」的与认不出写法的引文逐处人工核；`snapshot-tree.py` 点名倒推不出、sha256 对不上的几份，判决里写明是哪几份，腿引到它们的行逐处人工核。
2. 腿引的每一行产物，在产物文件里逐字找。
3. 判决要引的模型数，腿自己量出的不直接引：主 agent 把腿的模型目录拷到工作根下的草稿目录，在副本里交腿报告里的命令（`task-server/task submit --cwd <副本> -- <命令>`，命令要写的文件写进副本或写绝对路径）、`task wait` 读结局，比 sha256、比输出与腿报告写的，不在腿的原目录里跑。复跑做完，副本里的仓副本当场删，编译目录经 `task-server/task clean <号>` 删；复跑的输出与模型目录拷贝留到这一题的下一轮判决写完、或这一题不再开下一轮时再删。
4. 核不动的（要虚机、要网络、服务到最大上限仍报错）在判决里写明是哪一条、为什么，不当核过。

### 判决从骨架起笔

什么时候读它：开工快照记好、要起判决文件时。

`python3 scripts/agents/verdict-skeleton.py <轮>` 排他新建 `research/prompts/<轮>-main-verification.md`（已在就拒；没有快照目录或清单也拒，先照「代码轮派腿之前记一份开工快照」补记）。骨架带「## 一、腿与核查」「## 二、判决」「## 三、改法」「## 交用户的」「## 这一轮被判过的文件」「## 回看决策」六节；被判过的文件一节按快照清单（`research/prompts/<轮>-snapshot/` 里的 `*sha256*.txt`，`kb-sha256.txt` 除外）每个路径预填一行「- 路径：（待填：判了它什么）」，写完换成这一轮判了它什么，不写「没判」「没攻」这类否定词（门禁 doc-process-records 只认这一节、不认写了否定词的行）。

## 云端腿的报告要分段落盘

什么时候读它：写派云端腿的提示、接一条失败或停下的腿时。

- 派发提示里照 `.claude/rules/three-way-inference.md`「云端腿的报告要分段落盘」那几条写明；草稿与临时文件的目录写成 `~/.local/share/singlefs/work/<腿名>/`，不放会话共用的暂存目录；引 kb 的那一句写成「引 kb 条款写 kb 文件名加那份文件自己的行号，行号去 kb 文件里现查，不从背景材料里数」；交回内容照 `.claude/agent-common.md`「报告」一节。
- 看到「超过输出上限」的失败，先 `ls` 产物，按分段写的提示重派，不续那条腿。
- **中途停下、被停或报错的腿**（续做闸 `.claude/hooks/continuation-guard.sh` 拒绝给最后一次任务通知是 failed 或 killed 的子 agent 续做）：先 `ls -la` 看它的报告与模型落了多少，报告完整就直接读、不用接着做。没做完的，交 `task-server/task submit --cwd <草稿目录> -- python3 <仓根>/scripts/agents/agent-handover.py --agent <它的 id> --out <草稿目录>/<交接摘要>.md`（`<草稿目录>` 在工作根下）、`task-server/task wait <号>` 等到结局：脚本从那条腿的会话记录里机械地抽出派发提示、续做消息、写过的文件与现状、跑过的命令与输出、它最后说的话。再派一条同立场的新腿，派发提示指到交接摘要与已落盘的产物：第一步核现场，已落盘的不重做，接着做完。交接摘要只给新腿读，主 agent 不读；接续非得经过主 agent 的上下文，就从头重派。
- **上下文多大不是停、不续的理由**：看门狗报「上下文过大」时，主 agent 看它是不是在原地打转或做派发之外的事，不是就接着跑。

## 代码轮派腿之前记一份开工快照

什么时候读它：派三方的腿之前，与腿交齐、写判决之前。

- 快照放这一轮的材料目录：目录、清单文件名与判决里指到它的那一行，形态在门禁 `.claude/gate.d/doc-process-records.sh` 文件头 code-round-snapshot 一格。
- **别的会话改了快照里的文件**：`sha256sum -c` 对不上的，倒推出快照时的原样再核——HEAD 之后没被这一轮碰过的取 HEAD，被别的会话定点替换过的把那几处替换反着做一遍，副本的 sha256 与快照相同才算数；倒推用的改动清单存进这一轮的证据，判决开头写明哪个文件、被改了几处、腿引的行落没落在那几处。倒推整棵树照「核查与判决由主 agent 做，不派子 agent 去核子 agent」第 1 步交 `snapshot-tree.py`。

## 代码轮正文的检查单

什么时候读它：写代码轮正文 `research/prompts/_<题>-code-r<数字>-body.md`，或当腿判它的检查单时。格名以 `.claude/rules/implementation-workflow.md`「代码轮正文的检查单」那一行为准。

每格一个标题「### 检查单：<格名>」，底下写这一轮对这一格的答案与证据（文件:行）；这一轮的改动里没有这一类的，写「本轮改动没有这一类」与查过的范围。

| 格名 | 正文里写什么 | 腿怎么判 |
|---|---|---|
| 走不到的理由二次查实 | 实现员报告「走不到的理由」一节（`scripts/gate/apply-writer-patch.py` 打补丁时核过列全）的每一处「文件:行 理由」原样列进来 | 每一处照调用点逐个追，判「走不到」成不成立；条款没定的错误成员判是不是在任何落盘动作之前返回、判定与后面的写读不读同一份输入；推不出的算打中 |
| 类型与名字 | 新加的类型、函数、变量、错误成员的名字，与每处 `expect` 依赖的不变量 | 同一个量不同语义不共用裸整数（newtype）、不缩写、不写 `_ =>`、`expect` 写清依赖哪条不变量，有一处不是就是打中 |
| 不兼容旧代码与旧格式 | 改动里认旧版本的分支、旧布局号与版本号常量、迁移路径、只为旧数据放宽的读法有没有（`.claude/agent-common.md`「写」一节「里程碑 17 收尾之前不兼容任何旧东西」） | 有一处就是打中 |
| 不新建判定库 | 改动里新的判定存放处（另一个目录、TSV、sqlite、另一份 RocksDB）有没有（`.claude/rules/verification.md`「判定库只有一份」） | 有一处就是打中 |
| 所有任务多机可用 | 新测试、自证、门禁、入口脚本读不读会改变判定结局的本机独有状态、写不写死主机名与地址（`.claude/rules/verification.md`「所有任务都要多机可用」） | 有一处就是打中 |
| 测试优先多线程 | 新测试与崩溃检测切片并行没有、线程数取登记值；不能并行的写明为什么（`.claude/rules/implementation-workflow.md`「测试与崩溃检测优先多线程」） | 该并行而没并行、线程数写死或覆盖，打中 |
| 带 --item 的命令与项 | 实现员报告里带 `--item` 的命令写全了没有（范围声明、`<根>`、每个新项），新项能被各条的 `--list-items` 列出 | 命令缺项或新项列不出，打中 |
| 新崩溃流多罩了什么 | 新加的崩溃点重放流或用例，比已有的流多罩了哪些崩溃状态、多跑了哪一步（重开、挂载、恢复）；与已有流相同的只加小用例钉住「相同」（`.claude/agents/implementation-writer.md`「做什么」第 7 步） | 写不出比已有的多罩了什么，打中 |
