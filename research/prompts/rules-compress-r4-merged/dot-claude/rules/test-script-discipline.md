# 测试用例与测试脚本的写法

管项目自己的验证代码：单元与集成测试、穷举与长时间随机的验证、真设备与外部工具的装置，以及入口脚本（把一批登记的项组织起来跑的脚本；必须带位置参数、对一张表或一份输入跑的工具与只读日志的辅助脚本不算）。它们同样受 `.claude/rules/show-me-test-by-review.md`「新增的测试必须先证明它会红」、`.claude/rules/test-discipline.md`、`.claude/singlefs-ai-sop/rules/show-me-test.md` 整份（含「门禁不许假装通过」「每一个弄坏开关都必须会红」）、`.claude/singlefs-ai-sop/rules/command-safety.md`、`.claude/singlefs-ai-sop/rules/preflight-discipline.md` 管。

## 用例原子化：每一条都能单独跑

**判据：点名单跑一条用例，与它在不指定范围那一趟里跑，判定相同。** 自证分了格、能点名单跑的，每一格同样守这一条。

- 一条用例一个场景。按参数循环、每一轮重建被测状态的，拆成一个带参数的函数加每个取值一条用例；确是一个场景的（同一份状态上按次序做几步），用例旁写一行注释说明为什么。
- 不依赖跑序，不读别的用例（自证里是别的格）留下的文件、全局变量、环境变量与临时目录：每条自己建、自己初始化、自己删（`.claude/singlefs-ai-sop/rules/command-safety.md`「测试镜像一律放临时目录」）。
- 随机输入带种子，红了打印种子，凭种子能单独复现那一条。
- 用例名写场景和预期（`.claude/singlefs-ai-sop/rules/code-discipline.md`「名字：光看名字，就说得出它是什么、做什么」），不带里程碑、步号、批次这类来历；来历进 commit message 或项目 kb。
- 红了只重跑红的：入口脚本从上一趟的输出里取出红的用例，给出只跑它们的命令；取出的条数与那一趟汇总报的失败数对不上，判红、不给命令，出路写「整份重跑一次」（`.claude/rules/command-safety-by-review.md`「结果抓取要有完整性闸」）。

## 入口脚本：不带参数就是不指定范围

| 参数 | 做什么 |
|---|---|
| 不带 | 不指定范围：全部项，照「判定可复用：按输入存，按前缀剪」只剪键相同、已判过的与等价的 |
| `--list-items` | 逐行列出可点名的项，不编译、不跑 |
| `--item <项>` | 指定范围：只跑点名的项，给几次取并集 |
| 项名写错、`--item` 后面缺项名 | 列出可点名的项，退 2 |

- 不指定范围与指定范围是同一套判法、同一份判定库，只差范围；只跑一部分状态或一部分种子的（抽样、缩域）不是不指定范围那一趟。
- 什么时候跑哪一种照 `.claude/rules/verification.md`「一个门禁：两种跑法」；对拍（加速路径与参照路径、多线程与单线程、优化前后、两套判法）同样照它跑。
- 门禁阶段不是入口脚本：`gate.sh` 不带参数起阶段；阶段里直接起测试框架或调入口脚本，不指定范围的不带选条参数，指定范围的显式写 `--item` 或测试框架自己的筛选参数。
- 不用测试框架自带的标记（`#[ignore]` 这类）分档：不带参数跑到的就是全部，脚本里不带 `--include-ignored`、`--ignored`。
- 规模变量（种子数、展开深度这类）被设过，这一趟的产物写出它的取值；缩过规模的那一趟不当门禁通过、不当正式产物。
- 整个脚本都离不开的工具、设备、硬件写成 `run-condition`（`.claude/singlefs-ai-sop/rules/preflight-discipline.md`），不满足退 78；只有个别项要的，那几项照 `.claude/singlefs-ai-sop/rules/show-me-test.md`「门禁不许假装通过」逐项报「本次未跑」，这一趟不说「全部通过」。
- 每项结束打一行：项名、退出码、判了多少、红了多少、复用了多少（没有判定复用这一层的项写「不复用」；有这一层、这一趟取不出数的写「取不出」，不并进总计，成功那句点名是哪几项；两种都不写 0）、用了几秒；末行是总计。收回的项数照 `.claude/singlefs-ai-sop/rules/command-safety.md`「并行不许把失败吃掉」核。
- 退出码含义固定：0 跑到的全绿（有项报了「本次未跑」也是 0）、1 有红、2 用法错、77 一项都没跑到、78 准入或运行条件不满足；别的拒绝形态另用退出码的，在文件头逐个列明。

## 测试脚本自己也要被测试证明有效

**判据：测试脚本与它用的判法都有一份自证；把它们改坏，自证会红**（`.claude/rules/test-discipline.md`「检查本身也可能是错的」用到项目的测试脚本上）。

- 写成能被测的形态：判法写成纯函数，项的驱动、设备、时钟、随机源都能从参数或环境变量换成假的，不写死路径与外部服务；换不掉的那一处在文件头写明。
- 自证用 `--selftest`、同包里的测试，或红绿用例（每条带一份写明期望退出码与输出的说明；写成样本目录的，要留的空目录放一个 `.keep`，门禁阶段「脚本执行位」判；写成单文件的，期望值写进文件头）。每一种判定（绿、红、本次未跑、用法错）至少喂一个答案已知的输入，判出来与答案相同；入口脚本的列项、点名、拒绝认不得的项名、失败计数、项数核对各走一遍。
- 每一处会判红的分支配一个弄坏开关或一条变异。开关在脚本文件头逐个列明：开关名、弄坏哪一处、打开后哪一项该红；只给自证用，平常跑时不认；逐个打开核红照 `.claude/singlefs-ai-sop/rules/show-me-test.md`「每一个弄坏开关都必须会红」。变异进入库的变异清单（`.claude/rules/show-me-test-by-review.md`「新增的测试必须先证明它会红」）。
- 失败句里不写失败行起头的那种形态（例「✗ <标签> <名>：」）：引样本原文时换写法，取格名的一方会把引文当成又一个红格。
- 自证接进门禁，改了测试脚本或判法就跑到；一律用假驱动，不起编译与重活；改了谁，主 agent 经任务服务交谁的 `--selftest`。

## 每个测试目标都在不指定范围那一趟里跑到

- 被测代码的每个测试目标（库、集成测试、可执行文件里的内联测试这类）都在不指定范围那一趟里跑到；哪一趟都跑不到的，入口脚本列项时点名报出来。
- 每一种判法的小输入用例、剪枝自证、多线程与单线程的对拍、优化前后的对拍、加速路径与参照路径的对拍、钉回来的红例，都能用指定范围单点跑；要特定硬件的那几条，在没有那种硬件的机器上报「本次未跑」。
- 挂编译开关（特性、`cfg` 这类）的测试，不指定范围那一趟至少编进来一次；某一类编进来 0 条，报「本次未跑」，不算跑过。

## 判定可复用：按输入存，按前缀剪

- 每一份判定按它依赖的全部输入算键存下：被测代码、判法代码、参数、工具链。键相同的直接复用，不设时限。
- 判定库不是这一趟的输出：输出照 `.claude/singlefs-ai-sop/rules/show-me-test.md`「门禁不许假装通过」每趟新写，复用来的判定与现判的分开报；判定库只有一份（`.claude/rules/verification.md`「判定库只有一份：全仓统一写进 prune-server 的那份 RocksDB」），不随这一趟的临时目录。
- 状态空间按共享前缀组织：几条流、几个项共有的前缀只判一次，后面的接着它判。
- 剪掉的只能是两种：键相同、已经判过的；与已判状态等价的（等价关系写成用例钉住）。按登记整批不判的一类不算剪枝：登记表一行一类、写明为什么不判，成功那句报跳过了多少，照「门禁不许假装通过」列出没判的是哪几类。
- 剪枝要自证：在小规模输入上关掉剪枝与复用跑一遍，判定与开着时逐项相同；剪枝自证能用指定范围单点跑。
- 复用也要自证：凡按判定入库、复用的脚本，自证里各有一格、三问都要过——同一份输入跑两趟，第二趟现判 0、复用数等于第一趟现判数；改一处不在任何判定闭包里的输入再跑，现判 0；改闭包里一个单元再跑，现判数恰好等于闭包含它的那几条、其余复用；少复用一条判红，多现判一条也判红。每一趟真跑再从判定库里随机抽几条键相同的已判项当哨兵，哨兵被现判的那一趟判红。
- 一块判完才落盘，写入是原子的；被打断后重跑同一条命令就是续跑，只补没判的。
- 成功那句报「现判 <个数>、复用 <个数>」。
- 整个脚本的输入没变就不重跑，写成 `admission: inputs-changed`（`.claude/singlefs-ai-sop/rules/preflight-discipline.md`）；判定一级的复用在脚本里做，两层都要。

## 编译与算法都要快

- 穷举、长时间随机、真设备这类用例用优化构建跑，溢出检查与断言照开（Rust：`opt-level = 3` 加 `overflow-checks = true`，`assert!` 一律留着）。只在调试构建里生效的断言（`debug_assert!` 这类）开不开，由项目量过代价之后定，关掉的在构建配置旁写明量到的代价。
- 一趟只编译一次：这一趟的几个项共用这一趟的一份构建。编译目录归这一趟：每一趟新建、跑完删（成功、失败、被打断都删），不跨趟、跨轮、跨会话、跨脚本共用，也不经链接或环境变量指到别处的编译目录。按键存结论的判定库与外部依赖的预编库不是编译目录，照留。
- 几份仓副本不共用一个编译目录，每份各给一个；往副本里拷源文件不保留修改时刻（不用 `rsync -a`、`cp -a`、`cp -p` 这类），或者拷完把内容变了的文件的修改时刻改到此刻。拿副本编的脚本（合入验证、二分、证红这类）在这一趟的编译输出里核改过的每个包都重编了（Rust：那个包有 `Compiling` 行），没有就判红。
- 热路径上不做与判定无关的事：格式化、逐条日志、反复分配。
- 进程内互相独立的单位按区间切片并行，并行度照 `.claude/rules/command-safety-by-review.md`「一个脚本里的检测项，能并行就并行」。合并要确定：计数按片的次序相加，「第一处」取序号最小的；多线程与单线程的对拍逐字相同，能用指定范围单点跑。不能并行的（共享状态、次序本身就是被测对象）在那条用例的注释里写明为什么。
- 自证同样并行：`.claude/hooks/selftest-registry.tsv` 登记成 selftest 的脚本，互不依赖的格与开关轮按每台默认重活线程数并行跑，成功句报并行度（「并行 N 路」）；整份不能并行的，在文件头写一行 `# selftest-serial: <为什么不能并行，至少 8 个字>`。门禁 code-tooling 的 selftest-parallelism 格判，存量登在只缩不涨的 `.claude/gate.d/selftest-parallelism-exempt.tsv`。
- 单项跑得超过项目定的进度间隔的（间隔在 `.claude/rules/implementation-workflow.md`「测试与崩溃检测优先多线程」），每过一个间隔至少打一行进度：每片报区间与已判的数。
- 优化不许换掉判据：优化前后在同一组输入上判定逐项相同，这组对拍能用指定范围单点跑。

## 用上现有的硬件加速

- 哪几类计算走加速硬件（GPU 这类）登记在项目的本地配置里，登记了的那几类只走加速路径；用哪几台机器、哪几张卡、各给多少额度由统一任务服务（`task-server/`）分，调用方不写、不挑。
- 配置开了的硬件或机器是整个脚本离不开的，写成 `run-condition: check`：用不上（设备不在、驱动不对、内核编不过、显存不够、第二台连不上）就退 78，出路写「修好设备，或改配置」；不悄悄退回 CPU 或单机，要退回就改配置或显式传参。
- 加速路径留一份 CPU 参照实现，两边在同一组输入上判定逐项相同，这组对拍能用指定范围单点跑。
- 加速路径同样先证明会红：往加速那一侧塞一个已知故障，对拍要红。

## 门禁出的红，钉成能单点复判的用例

- 门禁每出一个红，把触发它的输入钉成能用指定范围单点复判的一条用例或登记表里的一行；修好之后留作回归，不删。
- 钉之前能缩就把输入缩到仍然红的最小那一个，缩不了的写明为什么、原样钉。钉完核一次：在出红的那份代码上，钉住的用例同样红，红在同一条断言上。
- 钉表每钉一条登记一行：出红的那一行整行抄下、带产物文件名，以及改回哪一处（变异或那次提交）它就红。门禁产物里的每一个红在钉表里都找得到对应的那一行，才算关掉。

## 门禁管哪一半

还没有一条做成共享检查。能按字面判、项目可以在登记的门禁目录（默认 `.claude/gate.d/`）里接本地阶段判的：拿副本编的脚本核没核改过的包重编了、入口脚本的参数约定（`--list-items` 退 0 且不起编译和重活、项名写错退 2）、产物写没写这一趟缩没缩过规模、自证（三种形态之一）在不在、跑了是不是绿、文件头列明的每个弄坏开关打开之后自证红在点名的那一项、门禁产物里的红是不是都在钉表里、按参数循环的用例拆没拆开。

靠 review 的：自证覆没覆盖全每一种判定、用例是不是真的互不依赖、复用的键罩没罩全输入、剪枝的等价关系对不对、热路径上有没有与判定无关的事、该走加速硬件的计算登记全没有、每个测试目标都在不指定范围那一趟里跑到、那几类对拍与钉回的红例能不能用指定范围单点跑、钉住的用例与门禁的红是不是同一个缺陷、抽样与缩域有没有冒充不指定范围那一趟、提交那一趟是不是不指定范围。
