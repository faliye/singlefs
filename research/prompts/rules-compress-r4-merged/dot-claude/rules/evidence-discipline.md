# 所有结论要三次推导：正推 / 反推 / 校验

结论说出口之前三步都走完，每一步说清怎么做的；少一步就写成假设，不写成结论。

| 步 | 问什么 | 做不到就是没做 |
|---|---|---|
| **正推** | 从机制、代码或数据推到结论 | 说得出「哪条命令、哪几行代码、哪个数据文件」 |
| **反推** | 假设结论是错的，本该看到什么？真去看一眼 | 说得出一个具体的、这一轮做得到的观测，以及它确实没出现 |
| **校验** | 换一条独立的路子把同一个判断再做一遍 | 两条路子不共用同一段代码、同一次采样、同一个工具 |

## 校验路径本身也要证明它会红

往被测对象里塞一个本该被校验那条路子抓到的已知故障，看它抓没抓到；抓不到，之前所有「两条路子一致」的记录全部作废。

拿一个计数去印证一个拆法之前，先问计数器分不分得出拆开的那几类：分不出就只写「相容」、写明拆法来自哪里，并把另一个原始计数也对一遍。

## 喂给多方论证的背景材料，本身要先核

发给各方的「已知事实」里，每一条来自外部的事实（「某某实现是这样的」）问的人自己先现查；查不动的标「未核实」。

## 陈述外部状态之前，现查一次

说「外面现在是什么样」之前，当场跑一条命令确认。「外面」指不在这次对话里、可能在我不知道的时候被改过的一切；记忆、kb、上一轮对话、TODO 表都只是线索。不用现查的：这次对话里刚读过的文件、纯代码逻辑推导、算术。

| 要说的话 | 现查的命令 |
|---|---|
| 门禁现在过不过 | 引最近一次 `gate.sh --staged` 的汇总（带日期与那棵树的哈希）；那之后有改动就不说「过」，说「上次绿、之后改了哪些没跑」。不为说这一句重跑门禁 |
| 某个不变量实现了没 | 读 `crates/singlefs-checker/invariants` 下各类文件的「checker 状态」列，再 grep 实现它的检查的源码，确认它真的在 |
| 某个决策定了没 | 读 `.claude/kb/decisions.md` 的状态：已定 / 半定 / 待定 |
| 工具链与环境齐不齐 | 跑 `.claude/singlefs-ai-sop/scripts/env.sh` |
| 别家实现怎么做的 | 现查它的文档或源码，kb 里照 `.claude/singlefs-ai-sop/rules/kb-discipline.md`「2. 每条带出处与状态」标来源与「未在本项目验证」 |
| 被测对象或它的产物现在什么状态 | 现场跑项目的检查，不靠「上次跑过是好的」 |

- 改 kb 或 TODO 里任何一行状态，先跑那一行对应的命令。
- 说不出「我是靠哪条命令知道的」，那句话写成推测，不写成事实。
- 别人提出的事实性更正同样要核：不照单全收，也不急着反驳，核完把结果说清。

### 它定了没，和它到底怎么定义的，是两个问题

确认一条决策「已定」，不等于知道它定的是什么。拿一条决策去做任何推导（建模、写检查、推翻别的结论）之前，先把它的定义句原样贴进笔记或实验注释；贴不出来就别拿它推导。引用某条臂的数，同样连它的定义一起带上。

### 核了窄的那一句，说出口的却是宽的那一句

判据：说出口的那句话，主语和范围是不是就是刚才核的那一个。核的是「这条路不通」，只能说「这条路不通」，不能说「做不到」；核的是「这个文件里没写」，只能说「这个文件里没写」，不能说「全仓没有」。

- 把要说的宽话当成待证命题，问「要让它为真，需要排除掉哪些情况」，逐个排除；排不完就把话缩回真排完的范围。
- 判「一个对象有没有被条款罩着」之前，拿它的名字全仓搜一遍，看它有没有被归进某个已有的类。
- 截断过的输出也是窄的那一句（`grep … | head -12` 看到的是前 12 行）：要说「只有这几处」「命中的就是这些」，输出不许截断；嫌长先数（`grep -c`、`| wc -l`），数对上了再看内容。

### 检查还没出结局，不写成过了

- 交出去、还没跑完的检查（测试、门禁、复跑、自证），正文、记录与报告里只写「交了、等结局」，不写「绿」「过」「全抓」；结局出来、读过判定的那一行，再改成结论并引那一行。
- 几件检查写在同一句里的，没出结局的那一件单独拆出去写。
- 被取消、撞了资源上限或被打断的那一次运行，日志里已经打出的 ✓ 不算结局；结局以调度它的那一方给出的最终判定为准，引的时候引那一行。

## 原样保存的证据不许事后改

- 发给模型的提示、跑出来的原始输出、当时的日志，在这一轮里一个字都不改；改提示只能连同重跑一起改，要补说明另开一份文件。冻结的是内容，文件与目录的路径照 `.claude/rules/path-moves.md`「怎么做」改。
- 冻结只在这一轮内有效：这一轮提交之后，下一次提交把上一次留下的那批证据（提示、腿的报告、原始输出、留存产物）删掉，本次的照留；要查删掉的去版本库的历史里找。删之前查一遍被检查读的登记表（门禁登记表、钉表、变异清单这类）点名的路径：点到的不删，或者在同一次提交里改掉那几行登记。
- 旧证据是参考，不是依据：对早先的结论有疑问，重新验证（`.claude/singlefs-ai-sop/rules/kb-discipline.md`「2. 每条带出处与状态」里「所有旧数据都只是参考」），不去翻旧证据；要推翻早先的结论，照 `.claude/rules/three-way-inference.md` 重走一轮，不拿旧文件对质。
- 正文引产物的检查按「这次改动」判，不按全仓判：当天写进正文的数要和当天的产物逐字对得上，早先抄下的行当历史参考、不再判。
- 门禁绕开这批目录：`.claude/singlefs-ai-sop/scripts/doc-lint.sh` 从 `.claude/doc-lint-exclude` 读清单，一行一条，每条写明为什么；指向不存在的目录、或一个文件都没排到，判红。

## 进结论的每个数，先问它是量的还是拍的

- 进结论的速率、容量、比例，先问是量的还是拍的，拍的就去量。量不到的（比如企业盘的 fsync 率）写成条件式（「按 10⁵/秒是 89 年，那一档本机测不到，仍是假设」），不把假设写成上界。
- 转述给别的会话或别的 agent 的数，每个都标「量的」或「推的」，并写明是哪个量（哪个文件、哪份产物、源文件还是编出来的二进制）。收到的一方把它当线索：现查过才记进记录，没标的按「推的」办。

## 别的项目怎么做，是线索不是证据

外部实现只用在两处：提出假设、指出该测哪条路径。它不进正推、反推、校验里的任何一步，也不当校验路子；想拿它当证据，先在这个项目里跑出能观测的数据，引那个数据。

| 可以引 | 不可以引 |
|---|---|
| **事实**：能核实、能重跑的（「`XLOG_CONTINUE_TRANS` 这个常量存在」「某函数散在 22 个文件 93 处」） | **论证**：「因为 XFS 这么做，这么做是对的」 |
| **反证**：某个方案在现役实现里从来没出现过，是个需要解释的信号 | **正证**：方案在现役实现里出现过，不等于它适合这个项目 |
| **机制**：拆成机制，再论证机制在我们的前提下成立 | **搬运**：把结论连同它没写出来的前提一起搬过来 |

- 「没有任何现役实现走某条路」不证明这条路错，但举证责任在要走这条路的一边：得说清别人为什么不走。
- 引用别家实现时，同时写下它和这个项目的一处已知差异；写不出差异，这次引用就是搬运。来源与「未在本项目验证」照 `.claude/singlefs-ai-sop/rules/kb-discipline.md`「2. 每条带出处与状态」标。

## 假设要写得出能否掉它的观测

写下假设之后先问「什么现象会推翻它」，答不上来就别拿去建实验。排除一个假设，要么拿出能推翻它的观测，要么明说是推的；「我想不出别的解释」不算排除。

## 不许先有结论再建模型

写下结论之前答完这六问，答不上来就是还没做完：

| 问 | 说不出就是先有结论 |
|---|---|
| 这个模型是不是**先于**我的倾向就有了 | 说得出「建它的时候我还不知道会得出哪一边」 |
| 有没有给**另一边**也认真建一条臂 | 说得出对面那条臂最好该是什么样，以及量没量过 |
| 结果反过来**接不接受** | 跑之前就写下「要是量出相反的数，我会怎么改结论」 |
| 是不是**只在一个点**上取了值 | 一个尺寸、一个参数、一个负载算出来的倍数，不能叫「最坏情况」 |
| 给的区间，**同一份产物里有没有反例** | 说得出这个区间覆盖了产物里的全部取样点 |
| 这个数是不是**某个没扫过的参数**的函数 | 先问它是哪个参数的函数，再写进正文：说得出这条臂的代价与收益依赖装置里哪几个旋钮、每个都扫过 |

- 推翻一个旧结论时，要比确立时更严，不是更松。
- 稻草人对照臂：给对面那条路挑一个没人会真用的实现方式，拿它量出的差当那条路的代价。判据：对面那条臂的样子，支持那条路的人认不认。

### 臂的定义也在「跑前写死」之列——失败条款打中的时候怎么办

跑前写死的除了判据、阈值和作废条款，还有每条臂到底是什么。失败条款打中一条写得含糊的臂时，不许不记一次输就把臂「澄清」成强的那个读法再宣布它赢。合法出路三步，缺一步就算新实验、重跑：

| 步 | 做什么 |
|---|---|
| **记一次输** | 按最弱读法把失败条款的判决原样写下：这条臂在这一格上输给了谁 |
| **只许收严** | 新形态要被原来那套判据判得更严或相同，放宽一个字都不行 |
| **写明收严在哪** | 说得出新形态比旧形态多要求了什么；说不出就是放宽 |

- 臂的定义里同时写了「怎么做」和「做完会怎样」，先证明前一句推得出后一句；推不出就删掉「做完会怎样」，或把做法改成推得出它的那一种。
- **跑产物之前修订臂或判据，是合法的，但要留下记录**：单元测试跑完、产物一次没跑时补一条更强的臂或一条段粒度的判据，在跑前登记里写明改了什么、依据哪个单元测试读数、时点在产物之前；原判据原样保留，两条臂各自判。

### 判据自己也会写错：打中之后先判是哪一种

| 形态 | 长什么样 | 怎么办 |
|---|---|---|
| **打中不分辨臂** | 一格打中让每一条臂一起出局，病根在各臂共用的前提里 | 不拿它判臂：把共用前提另立一笔账先修，判臂只看分辨得出臂的那几格。写「全部出局则回落到某一条臂」这种条款时，同时写一格让所有臂一起出局时怎么记 |
| **判别子观测不到** | 判据要被判的系统区分两种情形，而系统做决定那一刻看得到的东西两种情形逐条相同 | 改判据，改完是新一轮 |
| **打中归错了判据** | 腿报「某条判据打中」，而发生的事按字面属于门槛不同的另一条判据 | 逐字核打中满足的是哪一条判据的哪一个分句 |
| **改法碰不到打中的格** | 跑前的反向接受条款写「打中就在两种改法之间选」，而其中一个改法在打中的格上照样中 | 写条款时每个改法写明修的是哪一格；打中之后先在打中的格上逐个核改法还中不中，还中的那个交出去时写明「对这几格不起作用」 |

打中之后先问四句：它分不分辨臂；系统当时看得到要被区分的东西吗；它满足的是判据字面的哪一个分句；跑前条款给的每个改法在打中的格上还中不中。四句都过，才按跑前条款判。

## 引产物就整行抄

引产物整行抄，带上文件名；概括只说自己算过的那一格。

### 重跑之后要回对正文，复跑绿不代表正文对

- 产物重跑一次，正文里引它的每个数逐个回对；复跑全绿不构成「正文的数是对的」。
- 能被一条命令数出来的声明（「<个数> 个单元测试」「<条数> 条变异」「产物 <行数> 行」）由一条命令来数。
- 数没错、限定词没了也是对不上：结论说「只有某条臂才买得到 / 某条臂独有 / 只有某条臂能」时，去产物里看那条臂之外每一条臂在每一个参数格上的值；正文那张表里没有那个参数的列，那句「只有」就不成立。

### 扫描出来的极值落在扫描区间的端点，就不是量到的数

报扫描出来的极值（「最小可行值」「最大安全值」）之前，看它是不是扫描区间的端点：是端点就写成「≤ 端点（扫描下沿，边界没量到）」，或把区间放宽重跑，直到极值落在区间里面。

### 产物归档之后，正文引它写成一行指针

- 产物归档出工作区之后，正文里那一行写成一行指针：`产物行见 git show <提交>:<路径> 第 N 行（name=<名>）`，一条指针指一行，不把几行并成一句。
- 指到的那一行以登记的产物行前缀起头（形态 `<前缀> name=<名>`），不以它起头的指针不算引产物。前缀登记在 `.claude/product-line-prefixes`，一行一个，`#` 后写它是哪一类产物的行。
- 判法：按指针 `git show` 取那一行，核它存在、且以登记表里某个前缀起头。这道检查接进 `.claude/gate.d/` 之前，记在 `.claude/kb/checks-owed.md`。

## 新立一条判据，记下要回扫的条目，随下一次阶段同步一批扫

立完判据先问它对已经在册的条目判什么，答不上来就是还没立完。

### 撤回一个数或一条结论，同样记进欠账表

- 被撤回或被改写的数值与条款同样回扫。回扫按批做：新立的判据、撤回的数各记一行进项目的欠账表，随下一次阶段同步一批扫，不为一条单派一次。
- 撤回之后问「全仓还有谁在用这个数」，答得出一份清单才算撤完；扫的范围是全仓。
- 扫出来的清单不一把全替换：把这句话里的旧值换成新值，还是真话的说的是现状，改；不是真话的说的是那一次发生的事，留着。
- 回扫按旧说法搜，不只按新名字搜：先写出「这件事做成之前仓里会怎么说它」（没有 <这件事>、<这件事> 还没、只有 <别的做法>、<个数> 条），拿这些说法全仓搜；这一阶段的 diff 里删掉或改写的现状句，也逐句搜别处还有没有。

### 撤回的理由失效，不等于被撤回的结论自动回来

要让被撤回的结论回来，得重新论证。发现撤回的理由失效时按顺序问三句，答不出就别往下走：

| 问 | 答得出的样子 |
|---|---|
| 今天顶在这一格上的依据是哪一条 | 说得出它住在哪个文件的哪一段 |
| 那条依据自己站不站得住 | 逐个支点查过，不只读它的结论句 |
| 要让被撤回的那条复活，重新论证做了没有 | 做了；不拿「理由塌了」代替 |
