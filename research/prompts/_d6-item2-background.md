### 由此触发的连锁：D5（快照 / 空间记账机制） 的 O(1) 性质失效

D5（快照 / 空间记账机制） 标题里那句「D6（快照实现模型）若取多可写头候选，O(1) 性质失效」**这次被触发了**。
⚠️ 但要读准：E18（D5 在多分叉 / 多可写头下是否报废） 已证**数据丢失方向结构性为零**（可证，不只是实测），
失效的是 **O(1) 性质，不是正确性**。

**具体反例**：主线 txg=10 建可写快照 X；在 X 里于 txg=30 写一个块（birth=30）；主线 txg=35 建快照 Y。
按 D5（快照 / 空间记账机制） 的条件 `30 ≤ 35 < death` → 判「Y 引用它」，
**而 Y 根本看不见它**（那个 key 挂在 X 的分支上）⇒ 过判 ⇒ 空间泄漏 + 归属错，
**而 I-3.1（已分配统计对得上） 全绿**（块仍被恰好一处引用，总账平）。

### 一条已验的优化，模型层证明能把 O(N) 拉回 O(分支数)

D5（快照 / 空间记账机制） 的「与上一个快照比 txg」本质是**链上的区间标号**；
树上的推广是**嵌套区间标号**（preorder / postorder），把「子树里还有没有活快照」
从遍历变成一次区间包含判定，再配一个**删除前沿**（每块记它在哪几个分支上被删了的极小反链，
在「继承没发生」的那一步提交时就地记下——记账是事务的副产品）。

**模型层已验（2026-09-03，E89（嵌套区间标号与删除前沿），三条判据全中）**：
候选臂全格子误放漏放恒 0（对着独立真值）；固定树上 extent ×32 时
付查找基线的反向查找 8→252 而候选恒 0，前沿上界跟分支数走（快照 16→128 时 5→22）；
Linear 拓扑下前沿 ≤ 1，恰好退化回 D5（快照 / 空间记账机制）的常数形态。
「树还是 DAG」由 D6（快照实现模型）已定项 1 解掉——每头一棵树、克隆自单一 origin、
无合并操作 ⇒ 谱系是树，不必碰 DAG 那档难度。

⚠️ **两条限度仍在**（[checks-owed.md](../checks-owed.md) C35（多可写头的 O(N) 没有优化过）记着）：
① 树增长时标号要 order-maintenance / list-labeling 增量维护，成熟解法存在但本工程未验，
E89（嵌套区间标号与删除前沿）建完树才编号，没碰这一层；
② 事务层与真实反向索引上的实装复验含崩溃点重放，一步没走。
前沿退化那条限度已量：最碎的删除档前沿最大 10、均值 0.967 条/extent，没超反链上界。
⇒ **两笔还清之前实现仍按乙（付查找）走**。

### 快照实现模型的戒律：九条判据（2026-08-26 三方论证）

**这九条从机制与方法论推得，不从任何决策的地位推得。**
不许用「本候选破掉 D5（快照 / 空间记账机制） 的前提 ⇒ 采纳它则 D5（快照 / 空间记账机制） 失效」去否候选——
那是条件句「D6（快照实现模型） → ¬D5（快照 / 空间记账机制）」，反着读就闭合成循环。

> **一个快照实现模型可以被采纳，当且仅当它同时满足这九条。**

| # | 条件 | 依据 |
|---|---|---|
| 1 | **单一谓词**：存在唯一一个「S 引用 b」的谓词，**同时**驱动读可见性与空间回收 | 两个分歧方向后果不对称：可见集合大于记账集合 ⇒ **数据丢失**；反向 ⇒ 泄漏 + 归属错，而 I-3.1（已分配统计对得上） 构造上看不见。D5（快照 / 空间记账机制） 的保守默认纪律**只兜住后者** |
| 2 | **决策路径增量 + 独立审计**：进入准入控制 / ENOSPC / defer 判定的记账量提交时增量维护、代价不随盘容量增长；且有一条**与运行时不共享判定代码**的独立重算路径 | D3（空间分配） 的准入控制；[checks-owed.md](../checks-owed.md) C12（增量语义共用） 与它在 bcachefs 已发生的同源失效 |
| 3 | **边界对齐 + 完整视图**：快照点落在 checkpoint 边界、钉在本 checkpoint 全部数据变更之后；不存在「部分可见」或「用户可见但未发布」的快照 | D16（发布语义） 新规则 1。`birth` 分辨率只到 checkpoint ⇒ 块无法表达「我生在快照点之前还是之后」，`birth == S.txg`（数据丢失）与 `death == S.txg`（泄漏）**同时失去确定答案** |
| 4 | **有界创建**：单个 checkpoint 内原子完成，代价不随规模增长，且**不触碰任何已发布块的字节** | D8（核心索引结构）「无界必分批」× D16（发布语义）「快照点不许跨 checkpoint 边界」互斥。第二条腿来自 D9（加密）：触碰已发布块要重加密 ⇒ 新 nonce + MAC 变 ⇒ 沿引用改写到根 |
| 5 | **有界销毁**：可分批、可续做，每批最坏空间需求有界且可在批前预留 | D3（空间分配）「释放空间不需要申请空间」。⚠️ D5（快照 / 空间记账机制） 在这一格是用「分叉点快照不许销毁」这条功能缺失回避掉的，不是满足 |
| 6 | **不开第二套事务层**：不引入绕过 journal 的发布路径，不给提交协议增加结构性步骤 | 崩溃点的定义域就是事务层状态机 ⇒ 两套是**叉积**；且 D16（发布语义） 把崩溃语义定义成「根 + journal 任意前缀」，两个 journal 之间没有全序 ⇒ 规范本身无定义 |
| 7 | **可扫描重建**：快照集合与可见性判定的输入，能在只有「所有块 + 其自描述头」的条件下重建 | D13（验证路线） 的扫描式 checker 与 I-6.1（nonce 不重用） 阶段 ② 都建立在它上面 |
| 8 | **小规模可判**：正确性差异能在层 0 冒烟档规模上**被强制触发**，且有直接构造该状态的测试开关 | `.claude/rules/fs-design.md` 硬要求 2「进不去就等于没测」 |
| 9 | **标识不回收 + 布局无关**：**已发布的**快照标识单调不回收，位宽写进格式并声明生命周期内创建总数上界 | ⚠️ **「已发布的」这四个字是 2026-09-06 用户定案加的**：理由句的动词是「变成可见」，而可见性作用在**树里的 key** 上；从没发布成的 checkpoint 留下的孤儿单元不在任何树里，判它们的两道闸（已发布谓词、择新键）与孤儿回收条件都不看树 ID。⇒ 未发布过的标识被重发不落在这条判据的射程里。回收一个快照 ID 会让盘上遗留的旧 key 在新快照里**变成可见**，与 C11（feature bit 跳号） 同型。布局无关那半来自 D12（目标介质） 与避坑第 13 条 |

#### 被**故意排除**在判据之外的六条（假戒律）

用它们否候选，等于用一条本来就可以改的决策去否掉一个可能更好的模型。

| 不许用 | 为什么 |
|---|---|
| 「永不事后遍历」 | 它只约束**运行时决策路径**，且已在三处豁免：I-3.1（已分配统计对得上） 全盘遍历、D8（核心索引结构） 的意图分批、D13（验证路线） 的代际增量 scrub |

#### 这套判据对候选的判别力

**九条里有判别力的是 1、4、5、8，其余五条两侧对称或两侧都满足。**

条件 1 上，「快照 ID 进 key 低位」**目前给不出 O(1) 局部可判定的归属谓词**：
「谁覆盖了我」不在块自己或它的直接父指针里，散落在整个数据树里同逻辑 key 的其它版本上；
要算归属必须按剥掉快照后缀的逻辑 key 分组、配合快照树的祖先关系全局重建。
那是一次全局重建，而 [invariants.md](../invariants.md) 明写只有 I-3.1（已分配统计对得上） 才准全盘遍历，
且该重建的算法骨架与遍历式方向高度雷同 ⇒ **两条本该独立的路径独立性打折**。

⚠️ **这是「戒律排除该候选的现有形态」，不是「D5（快照 / 空间记账机制） 排除它」。**
它若要成立，路径明确：**先给出一种让归属判据重新局部化的格式设计**（例如显式的反向覆盖记录），
并证明它能增量维护、能崩溃恢复。而那个反向记录在多可写头、多分叉下
**不是一个标量而是一个变长集合**，这一层从没人回答过。

### 已定项 1（2026-08-30，用户定案）：取每头一棵树

⚠️ **先修候选集：原来写的「① key 加一维快照」其实是两支，而仓里两处各说一种位置。**

| 出处 | 逐字 | 快照 ID 的位置 |
|---|---|---|
| D6（快照实现模型）候选① | 「bcachefs 的**快照 ID 进 key 低位**」 | 低位 |
| D8（核心索引结构） 已定项 5 的布局规则 | 「同一快照的 key 带同一 **snapshot 前缀** → 删快照有机会变成范围操作」 | **前缀** |

**位置相反，删一个头的代价整个不同**（全扫 vs 范围操作）。

**实测**（4 头 / 每头 1 万条 key / 4 KiB 节点 / 共享率 100‰；N=5 轮字节一致，9 条变异全抓）：

| 指标 | ①-低位 | ①-前缀 | ② 每头一棵树 |
|---|---|---|---|
| **删一个头触及** | **40 000** | **69** | **59** |
| 点查比几个 key 分量 | 7 | 4 | **3** |
| **点查走几次树下降** | **1** | **4** | **1** |
| **旁表条目** | **0** | **0** | **1 000** |
| key 总字节 | 1 120 000 | 1 120 000 | **960 000** |
| 固定元数据条数 | **3** | **3** | 12 |

⇒ **①-低位 出局**：它只在旁表与元数据两格优于 ②，而 ①-前缀 在那两格与它**完全相同**、
删头却从 40 000 塌到 69 ⇒ **被严格支配**。删头触及的最大比值 **5442×**。

⇒ **剩下的选择是一句话的取舍**：

| 臂 | 唯一的真代价 | 量 |
|---|---|---|
| **①-前缀** | 每次点查**多走 H−1 次树下降** | 4 头 4 次、8 头 8 次；**恒定倍数，压在读路径上** |
| **②** | **一张引用计数旁表 + 每头 3 条固定元数据** | 共享 100‰ / 每头 1 万条时 1 000 条；8 头 / 10 万条 / 500‰ 时 **50 000 条** |

⚠️ 旁表代价 E12（攒批的顺序追加 vs 不攒批的随机页读改写） 已量：**装得进缓存几乎免费，装不下时每次删除约 1 次设备 I/O**
⇒ **② 可不可接受取决于旁表装不装得下缓存**。
⚠️ **② 破 D5（快照 / 空间记账机制） 前提 3**（每块至多一个活引用）——旁表正是为此而要的。
⚠️ **①-前缀 的「H 次下降」是最朴素形态的上界**：跳表 / 位图 / 祖先集合缓存都可能把它压下去，E52（两种多可写头机制的运营代价）没建。
⚠️ E52（两种多可写头机制的运营代价） 是**计数模型不是实现**（文件操作 0 处）。

#### 定案：取 ②（每头一棵自己的树）

**用户定案原话：「如果一张引用计数旁表 + 每头 3 条固定元数据 我觉得没什么问题」。**

### 运行时判定是 O(1)，而且这个 O(1) 要证

```
判定(ptr):
    birth = ptr.birth              // 指针内联字段，零次额外 I/O
    p     = head.prev_snap_txg     // 活头头部一个标量，常驻内存
    if birth > p:  立即释放 → 进 defer 队列（不是直接进空闲表，见 D16 新规则 2）
    else:          追加进 head.deadlist
```

**归约证明**：设删除发生在 checkpoint `d`，P 为此刻最新的快照。
(⇐) 若 `birth ≤ P.txg`：P 已发布 ⇒ `P.txg < d = death` ⇒ `birth ≤ P.txg < death`，∃S 引用它。
(⇒) 若 ∃S：`birth ≤ S.txg < d`，则 S 在删除时已存在 ⇒ `S.txg ≤ P.txg` ⇒ `birth ≤ P.txg`。∎

**它只用了两件事**：txg 全序，以及**判定必须发生在死亡那一刻**。
⚠️ 哪一条破了 O(1) 就没了——D6（快照实现模型） 的候选破第一条，D8（核心索引结构） 的分批删除破第二条。

**销毁快照的代价是 O(deadlist 条目数 + 桶数)，不是 O(全盘)**，
前提是 deadlist **按 birth txg 分桶、桶边界 = 快照 txg**，否则销毁时的过滤退化成全表扫描。

#### 已定项 2（2026-08-30，用户定案 + E54（记账的「代」要保留几代） 实测）：要「代」，代取 checkpoint 号，只保留最近 K 代

**「代」取什么，以及旧代什么时候可以丢 —— 已定（2026-08-30，用户定案 + E54（记账的「代」要保留几代） 实测）：
要「代」；代取 checkpoint 号，并配一条增量丢弃规则，只保留最近 K 代。**

**先说这个「代」是什么**：D8（核心索引结构） 已定项 1 已定记账条目是**幂等完整值**——
一条记账记录写的是「某个统计量**此刻**的完整值」，不是「增加了多少」。
于是同一个统计量会被写很多次，**key 里必须有一段把这些次分开**，那一段就是「代」。

⚠️ **「代 = checkpoint 号」的口径已由 D16（发布语义）已定项 6 收口（2026-09-02）**：
每次发布（fsync 触发的也是发布）checkpoint_txg + 1 ⇒ **代按发布走，不按 5 秒窗口走**。
两条骑手条款直接砸在这里：代段宽度 **≥ 48 位**（2785 发布/秒下 32 位 17.8 天回绕，
E71（记账 key 的条目数与宽度）的宽度算术要按此重算）；
记账条目的**跨发布合并不再可行**（代进了 key）⇒ E54（记账的「代」要保留几代）
的每代「统计量数 × 2」次写是实付值，不是上界。

**它为什么必须存在**（用户定案「需要代」的机制理由）：**根可以回退，账必须跟着回退。**
D22（单元原子性怎么合成） 的根环保留最近若干代根，恢复时可能挂上上一代的根；
若账没有「代」这一维、只有一份就地覆盖的最新值，
**挂上旧根之后账是新的、树是旧的** ⇒ I-3.1（已分配统计对得上） 当场判红，
而那不是 bug，是设计漏了这一维。

**实测：甲加一条增量丢弃规则与丙在 60 个格上逐格相同**
⇒ **「代取什么」与「留几代」是两个正交问题**，不是一个二选一。

| | key 数（64 个统计量、100 万 checkpoint） | 对 checkpoint 数的斜率 |
|---|---|---|
| 不丢 | **64 000 000** | **= 统计量数** |
| 保留最近 K = 8 代 | **512** | **0** |

**丢弃满足 `.claude/rules/fs-design.md` 第一格**：要丢的那一代**算得出来**（当前代 − K），
**不用找** ⇒ 是点删不是扫描；触及的 key 数 = **统计量数**，
**与 checkpoint 数无关、与盘容量无关**。代价是每 checkpoint 的记账写次数从
`统计量数` 变成 `统计量数 × 2`（一写一删）。

|---|---|---|---|

#### 已定项 4（2026-09-01，用户定案）：准入不等式的权威形式

```
可用 = Σ设备( 容量 − 已分配 − 不可回收 − defer 待释放 ) − 待删占用 − 已承诺预留
```

**它是「任何增加空间占用的操作，进门前先算最坏情况下解开自己需要多少」（D3（空间分配） 第 3 条）的可执行形式。**
此前全仓没有一处把它写全——I-3.4（可用空间扣待删占用） 只说「可用空间统计已扣除待删占用」，
第 3 条只说「先算最坏情况」。

**六项逐项有出处，不是凑出来的**：

| 项 | 为什么在式子里 |
|---|---|
| 容量、**已分配** | I-3.1（已分配统计对得上） 的被审计对象 |
| **不可回收** | zoned 上一个活快照钉住的物理空间是 zone 粒度而引用的块数是块粒度，[invariants.md](../invariants.md) 逐字要求「另立一个不可回收量」 |
| **defer 待释放** | D16（发布语义）：checkpoint C 中产生的释放在 C 发布之前不得进入可分配集合 |
| **待删占用** | I-3.4（可用空间扣待删占用）；D5（快照 / 空间记账机制） 与 D8（核心索引结构） 分批删除定「待删除结构算作活引用」 |
| **已承诺预留** | D3（空间分配） 第 3 条；已定项 2 逐字「墓碑就是解开自己的一部分，计入那个量」 |

⚠️ **前三项按设备求和，后两项不按**——前三项是物理量（一块盘满了不能靠别的盘补），
后两项是全池的承诺量。**这个分界直接决定 D5（快照 / 空间记账机制） 已定项 4 里哪几个统计量要带设备维。**

⚠️ **它解锁了两样**：D5（快照 / 空间记账机制） 已定项 4（统计量有哪几个）的完备性现在可判了——
清单相对这个式子完备即可；[checks-owed.md](../checks-owed.md) C70（跨统计量的和没人盯） 的那条向量等式现在写得出来了。

⚠️ **式子的六项都是已发布统计量，准入却发生在窗口中间——在飞合成已由 E82（准入的在飞合成）
建模（2026-09-02）**：只读已发布值 ⇒ 同窗并发超卖（实测 80/120 格）；把窗口内释放记成可用
⇒ 20 格吃进 defer 该扣住的块（D16（发布语义）新规则 2 被静默绕过）；忘了把墓碑计入「解开自己」
⇒ 盘满后删除全数死锁。**正确形态已定案（2026-09-02），权威记录在 D3（空间分配）已定项 6**；
实现侧的测试开关（overlay 可强制清零，双向证）仍欠，见 [checks-owed.md](../checks-owed.md)
C87（准入读的合成值无定义）。


#### 已定项 5（2026-09-02，用户定案 + E81（提交的固定点））：提交内生块从聚簇段分配

**提交自身产生的块——分配记录树 / 记账树等结构的 COW 新节点——必须从 key 空间上
连续的聚簇段（bump 段）分配；用户数据块的落点不受此约束。**

**依据（E81（提交的固定点），计数模型）**：全部记账结构都是 COW 树
⇒ 给它们写节点又产生分配，固定点循环的放大由「提交内生块聚不聚簇」决定——
全散布时一次 12 单元的 fsync 拖出 **5909 个元数据块**（65 轮，journal 点名项 5921，
I-8.1（环几何够大）的「最坏事务占用」在该政策下没有可用上界）；
**只聚簇提交内生块就断链**（2 轮、28 块），用户数据全随机也不影响。

⚠️ **口径**：它是**分配器政策不是格式位**——聚簇段的位置与长度是运行时选择，
盘上没有任何字段声明它；违反它的实现写出的镜像完全合法，只是每次发布贵几百倍。
⇒ 拦它只能靠运行时读数：**提交路径记「本次发布的固定点收敛轮数」，超过声明上界判红**

#### 已定项 7（2026-09-03，用户定案 + E97（记账与分配记录的条目编码））：分配记录条目的盘上编码

**落点粒度取 16384 字节（一个 16 KiB 槽）；key = (设备身份 4 字节, 16 KiB 槽号 6 字节)；
一条记录记一个存储单元，另带一个跨度段；value = 分配代或释放代 8 字节，存完整 checkpoint 号。**
**落点释放时条目不删、不点删**（C113（扫描重建时多版单元的现行版本判定无输入） 定案 P4，2026-09-05）：改写成「已释放 + 释放代」——释放代仍写进那 8 字节，已释放标志位借跨度段的最高位，条目留到该落点被重新分配时覆盖。不点删的理由：树按落点排序、代住 value，按代点删要扫全树，而点删所需的按代清单正是崩溃会丢的那份内存态；条目改写与产生这次释放的 COW 在同一次发布里原子生效——分配记录是根下的 COW 树（D22（单元原子性怎么合成） 已定项 3），条目与根同一次发布，释放代 = 那次发布的 checkpoint_txg；崩溃丢掉的是没发布的那个 checkpoint，它里面的释放一条都不留痕、对应的旧版本仍被所选根引用。崩溃后 defer 队列的内存态丢失，接手的是「释放代 ≤ 环里最旧根 txg」这条闸（I-7.4（近 K 代块未被复用） 的注）。「释放」的口径 = 分配器把落点放进 defer 队列那一刻 = 没有任何根（含快照）引用它，被快照引用的落点按 D5（快照 / 空间记账机制） 的 deadlist 纪律进 deadlist 不进 defer、快照销毁时才释放 ⇒ 释放代晚于最后一个引用它的根被销毁的那次发布。清扫准入两支共有的合取 = 不在分配器在飞 overlay 里 ∧ 头可读；有条目的再要求已释放 ∧ 释放代 ≤ 根环最旧根的 checkpoint_txg（由释放的口径，此时环里没有根还引用它；单元属于哪个实例无关，当前实例自己释放的落点也要能清）；孤儿（没有条目）要求头里的写序实例 < 当前实例 ∧ 按实例表的已发布谓词判未发布（当前实例没有行，它的孤儿只能是在飞的写，交给 overlay 那一条）。条目数上界由此从「已分配落点数」变成「曾分配过、尚未被覆盖的落点数」，仍以容量 / 16 KiB 为界；E74（分配记录的条目数与整理开销） 判据 1「条目数恰好等于已分配落点数」在新口径下按定义为假，改成「条目数 == 曾分配过、尚未被覆盖的落点数」后与 E97（记账与分配记录的条目编码） 一起重跑取新的绝对值，今天未跑（C122（分配记录不点删之后的条目数口径））。
