#### 已定项 13：后台任务的计算放在哪、怎么开、什么节奏

**定案**：八条。

1. **计算放在哪**：默认 CPU。挂载参数 `background_compute`（取 `cpu` 或 `gpu`，默认 `cpu`；命令行有了之后写成 `--background-compute=gpu`）选 GPU。这一组挂载参数（第 1、2、3 条）只有一份，管全部后台任务，不按任务分设：开了 `gpu`，凡有 GPU 路径的后台任务（GC 搬迁、打包搬迁，以后接上 GPU 路径的别的后台任务）都走 GPU，没有 GPU 路径的照旧在 CPU 上算。它只活在内存里：不写进系统配置、不占 feature bit（D24（后台重活能不能卸给 GPU） 已定项 2 第 1 条），每次挂载各给各的。挂着的时候可以经已挂载会话的控制接口切换（一次切全部后台任务），从下一批开始生效；一批之内不换（`.claude/rules/fs-design.md`「分支变量不许在操作中途改变」）。GC 搬迁放上 GPU 的是三段：扫描里的校验和核对、区域扫描里的单元头解析与映射反查、选段打分；整理发布那一半照旧在 CPU 上。开了 `gpu` 就照开着跑，不按哪张卡、哪种提交间隔赚不赚自动切回 CPU；赔的卡与提交间隔写进文档与第 7 条的对照组。
2. **用哪几张卡**：挂载参数 `background_gpu_devices` 是一张卡的列表（可以点几张），点名了就只用点名的卡；不给就用本机全部独立显卡，集成显卡与软件 Vulkan 适配器不算「显卡」、不进「全部」。参与的卡都用，按挂载时在每张卡上量出的一次提交的主机 CPU 分活；按第 7 条量出来赔的卡照用，并报出来。
3. **显存上限**：挂载参数 `background_gpu_memory_limit` 是一个带单位的字节数列表，按次序一张卡一个，与参与的卡逐个对应（给了 `background_gpu_devices` 就对它的列表，没给就对第 2 条那份全部独立显卡的列表），不补齐：`background_gpu_devices` 点了三张卡，`background_gpu_memory_limit` 要么不给、要么正好给三个数，只给一个也报错；GPU 模式下全部后台任务在那张卡上合占的显存不超过它的那一个数：这个数是上限、不是预留，用得比它少没有关系（卡上此刻空闲的不到这个数也照常跑，只用空闲的那些），任何时刻都不许比它多，攒批、缓冲、暂存区一起算在里面。不给就不设上限，后台任务跑的时候卡上能用多少用多少。GPU 模式把连续几批的计算攒起来一次交给 GPU，攒多少受它管。装不下不拒绝：一批（连同攒批、缓冲、暂存区）在上限里装不下，就按上限自适应切成几片、缩小逐次交，挂着时单条装不下也切；挂载那一刻量代价（第 2 条）的那一段同样切片，代价取各片之和。参与的卡的上限连最小的一片都装不下，这张卡就不用（第 2 条「参与的卡都用」的例外）：照开设备、不分活、报出来，挂载不因此拒绝；挂着切换给了它装得下的上限，从下一批起照新上限重新量代价、分活。参与的卡因此一张都不剩时挂载照样不拒，后台任务照第 4 条进出错停着。
4. **配错时拒；GPU 用不上时重交、报警、停下，GC 按占用在 CPU 上补跑**：挂载或切换那一刻，`background_gpu_memory_limit` 给了而个数与参与的卡数不等、某一个数超过那张卡的显存总量、GPU 不在、驱动不对、点名的卡不存在，或 `background_gc_cpu_compensation_threshold` 超过 100（选 `cpu` 时也判），就拒绝挂载（或拒绝切换）并报错。挂着的时候一批等 GPU 超过挂载参数 `background_gpu_wait_limit`，放弃的那一批在同一张卡上重交，至多 3 次，都超时才报警、判那张卡用不了；重交只在挂着时的批里做，挂载那一刻量代价的提交超时不重交，算那张卡没开成。挂着的时候 GPU 出错（含重交 3 次都超时），正在算的那一批放弃（意图留在盘上，目标态单调，已定项 2），那个后台任务停下并报警。卸载时不等还在跑的提交，有这种提交的那张卡整张泄漏、不析构。停着的时候收到任何一次通过校验的切换请求（校验同挂载那一刻），当场解除停下，从下一批起用新设置；出错之前已经收到、还没生效的切换请求，在停下那一刻也算数，照它解除停下。GC 报警停着之后在每一批开头判一次占用：任一块盘「已分配 ÷ 容量」超过挂载参数 `background_gc_cpu_compensation_threshold`（默认 85%，取整百分点 0 到 100，可调），这一批在 CPU 上补跑；都不超过就照旧停着，补跑途中降到不超过，下一批起照旧停着。占用逐盘算，和水位按盘算、空间准入逐盘判是同一种口径。补跑只管 GC，打包搬迁停着时不补跑。这两个参数与第 1 到 3 条那一组一起给、一起校验，挂着随切换请求一起换、从下一批起生效；不给阈值的切换沿用原阈值。各参数的取值、默认与代码落点在 [mount-parameters.md](../mount-parameters.md)。除了 GC 的补跑与第 8 条（连续几轮状态不确定的条目按条交 CPU 判，后台任务照旧在 GPU 上跑），停着的后台任务不换到 CPU 上接着跑。
5. **什么时候起跑**：每次发布之后按已定项 1 的三水位查一次；另有定时兜底，每隔一段时间再查一次，间隔是挂载参数。两种模式起跑规则相同。
6. **起跑之后的节奏**：GC 不在用户改动的调用线程里跑（不在用户改动返回之前跑一批），挪出之后三样照旧有保证：一趟发布预算有上限、签下一条意图那一判跨趟留着、整理批不插进用户改动的抬 F 与再判之间。GC 占盘写带宽有一个上限（挂载参数）；前台有 fsync 在等时不发下一批，这一判别子要 GC 挪出调用线程之后才看得到。
7. **值不值按省下的 CPU 时间算**：GPU 模式的目的是少占主机 CPU 时间，数据量大时跑得更快只是副产物。收益是后台任务少占的主机 CPU 时间（CPU 模式下它的 CPU 时间减 GPU 模式下它的 CPU 时间，后者含准备数据、提交、等结果、两份结果的比对，以及第 8 条交 CPU 判的那几条），挂钟与 CPU 模式持平也做；D24（后台重活能不能卸给 GPU） 已定项 3 那条按挂钟比的判据不管这一项罩着的后台任务。实现之后跑一组对照：同一负载、同一池，CPU 模式与 GPU 模式各跑，报两边的 GC 挂钟、主机 CPU 时间、前台 fsync 延迟，并在几档盘容量上各跑一遍，看收益随容量怎么变。
8. **GPU 的结果怎么复核**：两份独立写的 GPU 核（不共用核函数）对同一批输入各算一次，逐条比两份的结果。两次相同的条目算确认，交 CPU：CPU 照发布路径逐条核计划与读盘核（`crates/singlefs-core/src/transaction.rs` 的 `relocation_checked_against_the_version`），再改位图，不另外抽样复核 GPU 的结果；两次不同的条目写明状态不确定，这一批不回收、不搬，留到下一轮重算。同一个条目连续 2 轮（N = 2）都不确定，交 CPU 那一份实现单独判一次，按 CPU 的判定处理；连续不确定的计数只放在内存里，重挂清零。每一批报确认、不确定、交 CPU 判的条目各多少，运行时看得出来。只有一张卡时两份核都在这张卡上跑，有几张卡时按第 2 条分活、两份核可以分开跑；不许要求多张卡，一张与几张都要能跑、判定相同。

GPU 路径与 CPU 路径是两份实现（D24（后台重活能不能卸给 GPU） 已定项 2 第 3 条）：运行时的复核照第 8 条由两份 GPU 核各算一次比对，CPU 那一份管连续不确定的条目，两份实现在测试里对拍。GPU 路径默认写成 WGSL、经 `wgpu` 起（checker 档的崩溃判器已经这样用，`Cargo.lock` 里是 `wgpu 30.0.1`，不用另装 CUDA 工具链）。产品的 GPU 代码住一个单开的包 `singlefs-background-gpu`：它依赖核心层，核心层不依赖它，挂载时由调用方把它的实现递进去；它与 checker 档的 GPU 判器不共用代码，门禁 checker-independence-and-sync 的 checker-implementation-disjoint 格判（用户 2026-10-26 定，七·2 第三轮判决 G7）。改新池新建文件的字节：否——八条全是挂载参数与后台行为，不写进盘。
