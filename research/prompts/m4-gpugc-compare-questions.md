# m4-gpugc-compare：七·5 GPU 与 CPU 两种模式 GC 对照组的问题单（2026-11-03）

出处：`.claude/kb/milestone/04-fourth-txn.md` 七·5 那一行（第 151 行）与里程碑四出口 12；压着的条款 `.claude/kb/decisions/26-后台整理与放置回收.md` D26（后台整理与放置回收） 已定项 13 第 7 条（第 251 行，收益按省下的主机 CPU 时间算）与第 2 条（第 246 行，多卡按卡的顺序填满、挂载时量的代价不记进性能）。这不是为岔路建的实验，照岔路单的格式写问题，不写倾向、不写已有的数。

| # | 问题 | 量什么（口径） | 够判条件 | 状态 |
|---|---|---|---|---|
| 1 | 同一负载、同一池，`background_compute=cpu` 与 `background_compute=gpu` 各跑一遍，GC 挂钟各多少 | 一次整理从起跑到最后一批发布完的挂钟；同一份起步镜像、同一串用户改动与同一组挂载参数，两种模式只差 `background_compute` | 两种模式在每一档盘容量上各有一组带重复次数与离散度的数 | 开着 |
| 2 | GC 占的主机 CPU 时间各多少，GPU 模式省下多少 | 后台整理那条线程（与它起的线程）用掉的主机 CPU 时间；GPU 模式含准备数据、提交、等结果、两份核结果的比对、交 CPU 判的那几条（第 7 条第 251 行列的那几样），不含挂载那一刻量代价的那一次 | 每一档容量上「CPU 模式减 GPU 模式」的差有数、有正负、有离散度 | 开着 |
| 3 | 前台 fsync 延迟两种模式各多少 | 整理在跑时，前台一串用户改动里每次 fsync 的延迟分布（中位、p99、最大） | 每一档容量上两种模式各有一份分布 | 开着 |
| 4 | 省下的 CPU 时间随盘容量怎么变 | 至少三档盘容量（取值由设计员定、写明理由），问题 2 的差在各档上的值 | 三档以上都有数，能说出随容量涨、平或降 | 开着 |
| 5 | 阳性对照：CPU 一侧故意把每个确认的条目再判一遍，省下的 CPU 时间必须变少 | 同问题 2 的口径，GPU 模式下加这一处故意的多判 | 多判之后省下的比不多判少，差有数 | 开着 |

装置要求（压着的约束，不是问题）：
- GPU 模式每张参与的卡显存上限给 1 GiB（`background_gpu_memory_limit`，用户 2026-11-01 定），与别的 GPU 活不混；一张卡与几张卡各跑一遍时，按卡的顺序填满（第 2 条）。
- 判定逐条与 CPU 参照相同才计一组数；两种模式读到的内容逐项相同。
- 经统一任务服务交，机器、线程、内存与卡由服务定，装置里不写；结果两台都读得到（判定进 prune-server 那一份库，产物放共享根）。
