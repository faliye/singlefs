# D2 未定项 12 第三版提案（第三轮的靶子）

**前两轮的处置**：第一版按用户口径「三轮中多数打穿」已经打穿两轮——
第一轮四条判据逐条被打穿（其中六条主 agent 现查坐实），第二轮在时间与并发面上又打穿七条。
第三版 = 第一版骨架 + 第二轮那七条的最小改动（R1–R5）+ 第一轮那两笔账。**不是新方案。**

## 骨架（两轮都没推翻的部分）

- **成员表是权威态**：按 D21（权威态与派生态的分界）自己的判据「丢了就丢数据 / 丢了只是慢」——
  丢了会让重建做不成、让分配器判不出钉住（E80（条带的部分释放）：单盘失效平均丢 9.8–13.0 个活单元，盘坏前零报错）。
  ⇒ 它必须住在**单元的载荷**里，不是索引，不是块头。
- **载体**：码 3 打包记录类型 5「条带成员记录」，一条记录记一个成员落点，带整条条带的成员表，
  住一棵池级单例 keyspace（比照 D5（快照 / 空间记账机制）已定项 4 的「树 ID 取 0 = 全池 / 无归属」与 D3（空间分配）的分配记录；
  D15（格式冻结政策）已定项 2 已定超级块树表是开放列表 ⇒ 新增 keyspace 是 compat，根记录固定字段不动）。
- **三条边界**（第一轮逼出来的，第三版接受）：不能住任何单元的**头**（D18（块里携带什么信息）已定项 3 禁放清单；
  且 D18（块里携带什么信息）已定项 6 / 已定项 9 让 parity 格放不下自己的头）；不能只住**指针 / 索引**；不能住**密文**。

## R1 整条链恒走 `w = 2` 镜像

**范围**：从根记录到容器的**整条链**（根记录 → 容器索引 → 容器）都恒走 `w = 2`。
三条独立理由：① `w = 2` 的条带一条记录都不写 ⇒ 依赖图无边，自举（第一轮命中 10、E106（条带成员表的载体）`first_stripe` 世界五种子全中）结构性消失；
② 写容器不再往任何格宽桶里加写入量 ⇒ 第二轮 D1 那个「`w` 的求值变成固定点」不存在（`.claude/rules/fs-design.md` 硬要求 5）；
③ 镜像两份字节相同（D9（加密））⇒ 扫描重建里不构成两个版本。
判据写死：**单元类 == 码 3 ∧ 打包记录类型 == 条带成员记录 ⇒ `w` 恒 2**，配只供测试的强制开关。
新增分配器不变量：**镜像的两份必须落在不同设备上**（做成会红的检查）。
代价：这张表占的空间翻倍（E106（条带成员表的载体） 自洽口径：1544 → 3088 ppm）。

## R2 记录不删，改写成「已退役 + 退役代」；钉住状态住进记录

与 D3（空间分配）已定项 7 的分配记录同形态同理由。记录仍 56 字节，从补齐里拿 5 字节：
格宽标志 1 + `w` 1 + 第几列 1 + 成员表 40 + 条带诞生代 8 + **状态 1**（bit0 已退役 / bit1 钉住 / bit2 修复中）+ **退役代 4**。

## R3 parity 格有分配记录条目

parity 格占一个落点，分配器要为它记账，否则下一次分配会把它分出去。
有条目之后清扫走「有条目」那一支，**不走孤儿支** ⇒ parity 无头这件事不再影响清扫
⇒ 第一版 P3 的清扫补丁整条撤掉，少一条格式级例外。
新增 checker 不变量：每个 parity 格的分配记录条目必须存在，且它的条带记录必须把它列在成员表最后一项。

## R4 发布顺序写死三段

① 一条条带的全部 `w` 个格写成功（含 parity）→ ② 才写这条条带的 `w` 条记录（容器 COW）→ ③ 才发布根。
挡的是「换落点重试造出同 checkpoint 内第二版容器、择新键逐字节相同」（第二轮 C1）。

## R5 记录搬迁的顺序写死

重平衡与修复搬一条条带：先写新记录 → 再改指针 → 最后把旧记录标退役。
中断时以**指针指向的那条**为准；checker 不变量：一个落点至多一条未退役记录。

## R6 修复的形态

D2（RAID 条带策略）已定项 11 规则 2 逐字「整批重落**一条**新条带」按字面不可执行
（`w = 4` 丢一列剩 3 个幸存者，新条带 `w = 3` 只装 2 个数据格）⇒ 改成「一条或多条」；
修复要写的条带表字节进准入预留。
