## 一、七个攻击面逐条

### 攻击面 1：末尾分裂 + 单调 inode 号

#### 1.1（对应问 a）1e6 顺序创建再随机删 90%：填充率的下界是 1/233，而「合并时机是写路径策略」这句盖不住它

一步一步走：

1. 顺序创建 1e6 个 inode。末尾分裂下每次分裂左半留满：`1000000 = 4291×233 + 197`
   ⇒ 4291 个满容器 + 1 个装 197 条。这与 E103（inode 打包路 ① 的更新代价） 的
   `b_containers = 4292`（产物第 9 行）一致。
2. 随机删 90%。每个容器期望剩 23.3 条；一个容器整个被删空的概率是 `0.1²³³ ≈ 0`
   ⇒ **基本没有容器会空掉，因此「空容器不落盘」那条纪律在这个负载上一次都不触发**。
3. 不合并时：4292 个容器装 10 万条记录，新建同样的树只要 `⌈100000/233⌉ = 430` 个
   ⇒ **9.98 倍空间放大**（4292 × 32768 × 2 = 281 MiB 对 28 MiB），内部层从 `[3, 1]` 变成 `[25, 1]`。
   点查读次数不变（两者树高都是 2），单次更新字节不变。
4. 顺序创建 + 单调号还有一层：**被分裂过的叶永远不会再被插入**（新号更大，只落最右叶）
   ⇒ 非最右叶只减不增，填充率**单调下降**，没有自愈。

P4（`_d8-item6-r4-conclusion.md:75`）逐字：

> 合并：保留左半身份，右半退役走 COW 释放路径。合并时机是写路径策略（派生态，单测 / 模型对拍），不进格式。

这句有两处盖不住：

**① 合并的方向不是策略，是格式级约束。** I-9.4（`:136`）逐字要求
「类型 2 容器内每条记录的 inode 号 ≥ 容器号」。设左容器 L 号 = a、右容器 R 号 = b（a < b）。

| 重平衡方式 | I-9.4 |
|---|---|
| 左吸收右（L 收走 R 全部记录，R 退役）| L 的记录全部 ≥ b > a ⇒ **成立** |
| 右吸收左（R 收走 L 的记录，L 退役）| R 里出现 < b 的记录 ⇒ **当场破** |
| 右从左借（L 把最大的几条挪给 R）| 同上，**当场破** |
| 左从右借（R 把最小的几条挪给 L）| L 的记录仍 ≥ a ⇒ 成立 |

⇒ **I-9.4 禁掉了 B 树里一半的标准重平衡动作**，这是格式（准确说是不变量）对写路径的硬约束，
不是「时机」。P4 只写了「保留左半身份」，没写「方向只能是左吸收右 / 左从右借」。

**② 填充率没有下界，而 233 这个数在两处被当成常数用。** C100（inode 容器丢失是永久损失而没有任何冗余条款覆盖它）
的爆炸半径 233、E103（inode 打包路 ① 的更新代价） 的 `b_containers = ⌈n/233⌉`，
都是**新建树**那一刻的值。上面第 3 步算出的 9.98 倍说明它们是最好情况，不是稳态。

判定：**打中（轻）**。改成什么：P4 那句改成「合并的**方向**进不变量（左吸收右 / 左从右借，
理由是 I-9.4），**时机**是写路径策略」；P9 的 E103 那一行补一句
「容器数 `⌈n/233⌉` 是新建树的值；删除后不合并时填充率无下界（1e6 删 90% 不合并 = 9.98 倍空间放大）」。

#### 1.2（对应问 e）「左容器最大 key < 右容器号」在合并后仍成立

按上面的左吸收右走一遍：合并前 L(号 a) → R(号 b) → S(号 c)，已知 L.max < b、R.max < c。

判定：**没打中**。I-9.4 在左吸收右下是封闭的——这也正是 1.1 那条「方向不是策略」的另一面。

（与 COW 重写不同：COW 不换身份，分裂是新建）」，并明写它与 P5 推给 E90 的那一问是两件事。

#### 1.6（对应问 d）内部节点分裂：末尾分裂成立，但分隔 key 的语义全仓没写

末尾分裂对内部节点成立，而且理由是同一条：新叶永远追加在父节点的最右端 ⇒ 父节点只会在右端溢出。
分裂出的右半是码 2，**没有身份**（D18（块里携带什么信息）`:568` 逐字，码 2 的类身份段是
「树 ID + 层级 + key 区间 + 诞生代号 + fsid」，没有容器号），所以 P4 那套身份规则在内部层没有对象。
父条目按 P1 写成「类型段 0、容器号与出生代两段恒 0、分隔 key = 右半第一个孩子的分隔 key」。

但走完之后有一处空的：**P1 从头到尾没有定义「分隔 key」指什么**（右子树的最小 key？左子树的最大 key？）。
内部节点布局落 D15（格式冻结政策） 第 4 层、派生态不冻结，所以它可以是代码选择；
可 I-9.2 / I-9.4 都不检查分隔 key，**写错了没有任何不变量会红**，而 I-9.1–I-9.4 又是 P7 立的全部。

判定：**打中（轻）**。改成什么：I-9 加一条「内部节点条目的分隔 key 单调递增，且第 i 条的分隔 key
≤ 第 i 个孩子的 key 区间下界、> 第 i−1 个孩子的 key 区间上界」——可判、便宜，且它是「内部节点带 key 区间」
这次新增字段唯一能买到的检查力。

### 攻击面 3：ε = 0 的分支变量

#### 3.1 分支变量用的正是第四版自己刚撤回的那个读法

P1（`:42`）逐字：

> 分支变量是「这棵树的叶是不是**权威态单元**」，按树恒定

P1（`:45-47`）逐字（同一段里）：

> **态别按重算性判，不按「树」这个词判**……v3 那句「态别的载体是单元类」会把码 2 的记账树判成派生态，与 D21（权威态与派生态的分界） 已定冲突，**撤回**。

「权威态单元」这五个字在仓里只有两种读法，第四版把其中一种在同一段里撤掉了：

| 读法 | 记账树的叶怎么判 | 与已定的关系 |
|---|---|---|
| 按**单元类**读（码 1 / 3 是单元，码 2 不是）| 记账树叶是码 2（D18（块里携带什么信息）`:577` 逐字「记账单元 → 2」）⇒ 不是权威态单元 ⇒ ε = 0.65 | **第四版自己撤回的读法** |
| 按 P1 新写的**重算性**读 | `.claude/kb/decisions/21-权威态与派生态的分界.md:394` 逐字「记账**已定**是权威态（「不是慢，是在被问到的那一刻没有答案」）」⇒ 记账树的叶是权威态 ⇒ **ε = 0** | 与 P1 括号里那句「今天只有 inode 树」直接矛盾 |

⇒ 分支变量在两种读法下给出相反的答案，而两种读法之一被同一段撤回了。
提案括号里逐字写的「（今天只有 inode 树）」（`:44`）在第二种读法下是假的。

#### 3.2 正确的分支变量是 D11（索引节点要不要留消息缓冲区） 已定项 4 自己那条谓词，而它对记账树给不出答案

P1 真正用的机制不是「叶的类」，是这句（`:40-41`）逐字：

> D11（索引节点要不要留消息缓冲区） 已定项 4 让缓冲留在派生态的前提是消息能只从「单元 + 记账 + 墓碑单元」重算（F40），而 inode 属性更新在到达叶之前没有权威态载体

⇒ 分支变量应当直接写成那条谓词：**「这棵树待下刷的消息，能不能只从权威态（单元 + 记账 + 墓碑单元）重算」**。
按它分：

| 树 | 判 | 依据 |
|---|---|---|
| extent / 反向索引 / dirent | 能 | E59（缓冲消息能不能只从单元重算） 的「单元 + 记账」一行三类全 0（D11（索引节点要不要留消息缓冲区）`:216`）|
| inode | **不能** | E98（inode 记录与 inode 树的几何） 判据 2：14 个字段里 11 个 |
| **记账** | **答不出来** | 重算源里就含「记账」，是循环；而 C113（扫描重建时多版单元的现行版本判定无输入）`.claude/kb/checks-owed.md:120` 逐字「E59（缓冲消息能不能只从单元重算） 源码里乙臂的「记账」是一个 `live: bool` **神谕**、不是机制」|

⇒ 换成正确的分支变量之后，**记账树那一格是开着的**，不是「共用 0.65」。
第四版把它按下去了，靠的是那个被撤回的读法。

判定：**打中**。改成什么：分支变量改写成 D11（索引节点要不要留消息缓冲区） 已定项 4 的谓词，
并显式写「记账树那一格本项不判：它的重算源含它自己，E59（缓冲消息能不能只从单元重算） 的那一列是神谕，
归 C113（扫描重建时多版单元的现行版本判定无输入）；本项只定 inode 树」。
这样既不动记账，也不再声称「今天只有 inode 树」。

#### 3.3 改写 D11（索引节点要不要留消息缓冲区） 已定项 6 的措辞会把它原本定的那件事删掉

`.claude/kb/decisions/11-索引节点要不要留消息缓冲区.md:136` 逐字（分项名）：

### 攻击面 4：取最大值合并 + 条目照样带 seq

#### 4.1 三条同 key 乱序到达，两种规则各算一遍：对单调统计量它们**等价**，唯一分歧就是回滚那一格

样本：同一个 key `(标签 12, 树 T, 设备段, 代 g)`，三条条目 (seq 7, 100)、(seq 9, 300)、(seq 8, 200)，
flush 排序后到达次序任取，设为 300 → 100 → 200。

| 规则 | 结果 | 依不依赖到达次序 |
|---|---|---|
| 取最大值 | max(300,100,200) = **300** | 不依赖 |
| 后者胜（按 seq） | seq 9 那条 = **300** | 不依赖 |
| 后者胜（按到达次序）| **200** | 依赖，错 |

⇒ 单调统计量上「取最大值」与「后者胜（按 seq）」**恒等**。P5（`:86`）逐字
「合并结果不依赖 seq，不受 write buffer 排序丢时间序影响」成立。

两者唯一分歧的那一格，正是 1.4 那扇门：txg 被重发、同一个 `代` 段里先后出现 500 与 200 两个值。
取最大值给 500（浪费号，安全），后者胜给 200（重发号，撞已存在的对象）。
⇒ **取最大值在这一格是严格更安全的那个**，P5 选对了。

但 P5（`:97`）给的理由不对：

> 未发布的事务重发同一个号是安全的：水位与叶容器共用同一个发布屏障（未发布的不在根下，回到旧根看不见），未发布的事务等于没发生

「回到旧根看不见」只对**常规挂载路径**成立。扫描重建路径看的是盘不是根
（D18（块里携带什么信息） 已定项 5 的三级降级），而 P1 的「内部节点丢了从叶重建」正是那条路径。
第三轮反推腿 1.3 用的就是这个观察（中间版已落盘），第四版在**容器身份**那一格采纳了它（改成末尾分裂），
**在水位这一格没有传导过去**。

判定：**打中（轻）**。改成什么：P5 末行改成
「取最大值在崩溃 + txg 重发那一格给出更大的水位（浪费号，不复用号），这是选它而不是『后者胜』的真正理由；
『未发布的等于没发生』只对常规挂载路径成立，扫描重建路径看的是盘（见 1.4）」。

#### 4.2 checker 拿着一棵 write buffer 树，怎么知道哪个标签用哪种规则：今天答不出来，而且这张表没有冻结层

P5（`:88`）逐字：

#### 5.2 建克隆那次发布崩在写水位行之前，重启后 clone 头是什么状态：提案的两道防线在这里各缺一半

|---|---|

## 四、如果只改三处

1. **1.4（崩溃 + txg 重发造出同身份两版）。** 它是唯一一处能让 P4 那句
   「唯一性由构造保证」整句作废的观测，而且撞号是确定性重放的结果，不是概率事件。
   仓里已经有现成的解（D16（发布语义） 骑手条款 1 的 32 位实例代号），
   要么把它接进容器身份（改字节，过 D15（格式冻结政策）），要么把那句普遍断言降成
   「一条已发布历史内成立」并把这条必然实例挂到 C113（扫描重建时多版单元的现行版本判定无输入） 上。

2. **2.4 + 5.1 + 7.3（自己的尺子只挥了一半）。** 第四版用
   `.claude/kb/invariants.md:6` 把 nlink 挡在门外，这是这一版最值得肯定的动作；
   可 I-9.1–I-9.4（门是「这棵树是 inode 树」）、I-9.5 / I-9.6（门是 `deleted_inodes` 树的形态）、
   I-9.11（右操作数在 K 代后被点删）三处的门同样没有输入。
   一份自己都不一致地执行的判据，下一个人会照着松的那一半用。
   出路二选一：本项顺手定树表条目带一段「树的种类」（顺带解掉 2.4 与 7.1），
   或者把这几条的状态列写成「输入不存在」并各立一条欠账。

3. **3.1 + 3.2 + 3.4（ε = 0 那一段的三处）。** 分支变量要改写成
   D11（索引节点要不要留消息缓冲区） 已定项 4 那条重算谓词（而不是「叶是不是权威态单元」），
   并显式承认记账树那一格开着；D11（索引节点要不要留消息缓冲区） 已定项 6 的改写要把
   「布局轴不分支」原样留住；「内部节点布局不永久」要把块头（D15（格式冻结政策） 第 1 层，冻结）
   与载荷布局（第 4 层，不冻结）拆开——不拆，新加的那 16 字节 key 区间会被下一个人当成随时可删的东西。

第四位是 **4.2（合并规则没有冻结层归属）**：P1 遇到同形问题时给出了一个干净的解法
（立成独立的已冻结组件，C9 按组件记），P5 遇到同形问题时把它留在了 kb 正文里。
照 P1 的先例办就行，改动很小。
