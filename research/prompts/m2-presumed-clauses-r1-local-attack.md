Part K3. Whether a clean-shutdown marker exists.

Candidate K3-1 (today's implementation): there is no on-disk clean-shutdown marker of any kind. Every mount, whether the previous session unmounted cleanly or crashed, runs the identical recovery path: full scan of the root ring, per-record verification, root selection, replay of the determined prefix. Verbatim from the current module header comment of the mount module: "The first version has no clean-shutdown marker; every reopen goes through recovery." Nothing in the mount path reads or writes any bit that records whether the previous shutdown was clean.

Candidate K3-2: an on-disk clean-shutdown marker exists. It is written durably at unmount time (after all other unmount work is complete) and read at the start of the next mount. If the marker is present and valid, the mount is permitted to treat the previous shutdown as clean and may skip or shortcut some part of the recovery path (which specific part is exactly what this candidate leaves open — your task in each row below is to say whether the clause in that row would have to answer differently depending on whether the marker is present and valid, or absent/invalid). If the marker is absent or invalid, the mount must run the same full recovery path as candidate K3-1.
