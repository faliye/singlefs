## 二、「逐行全看」与「各抽 ≥2 行」并存时，能不能合规地只做抽样那一半

**能。三种读法各自合规，而且三种在仓里留下的字节完全相同。**

**读法一：按共享规则读，抽样是必做项，全看是本地加的。** `.claude/singlefs-ai-sop/rules/show-me-test.md:188`（整行抄）：

> 　　它拦得住「抽样够了」「整组放行」，拦不住判错。核全之后还要在**全部判定种类**里抽查复判，抽中判错的那一段重做、再抽。

这句话里的「核全」指的是**机器核全**（同一条第 187 行说的是「每一项都有判定、判定是认得的那几种、理由里引了那一项的原话」，也就是 `stale-candidates.py --check-report` 退 0 那一步），不是人逐行看。⇒ 共享规则要求的人工动作只有一样：抽查复判。改法一之后，本地那句在文本上**完整包含**共享那句的要求，多出来的「逐行全看」是本地加的那一截，而那一截没有任何检查。做完抽样就停，共享规则一个字都没违。

**读法二：按工具自己的文件头读。** `research/scripts/stale-candidates.py:38`（整行抄）：

> 　逐行判的理由引了原话、判定也是五种之一，照样可以是没读懂就判的；靠主 agent 在全部判定里抽查复判。

这是那套工具作者写在「管不到的」一节里、今天仍在文件里的一句：这个缺口的**指定补法就是抽查复判**。照它办，做抽样就是照章办事。

**读法三：按「重判」这个词读。** 改法一写的是「另按判定种类各抽 ≥2 行**重判**」。「重判」预设了第一遍已经判过，可在这条链上第一遍是子 agent 判的、不是主 agent 判的；一个读的人完全可以把「全看」读成「把子 agent 那份报告从头到尾过一遍」（这确实是「逐行」、也确实是「全」），再对抽到的 8 行「重判」。这一读法下他做的事与我上面那张伪表**逐字节相同**。

改前本地那句写的是「不抽样、不按判定种类挑」。那句话有一个今天被当成缺点的性质：**做了抽样的人，在文本上是违规的**——E 格之所以能被第一轮打中，正是因为两句并排读得出互斥。改法一把互斥删掉之后：

再叠上第一轮 A 格量到的体量（123 个位置各 ±20 行 ≈ 载体全文的 95.3%，我这一轮没复量），少做那一边还省掉一整轮语料。

## 三、改法四的「出处」是什么形态，主 agent 判一行判定时拿得到吗

### 「出处」确实是候选表流程里的一个真列——但它装的不是改法四要的东西

⇒ **条款里「出处」的合法取值只有两种：H 编号，或提交。**「哪道门禁的哪一条判据」不在其中，`--check-facts` 也只核「每条 H 编号都要出现在某一行的「出处」列里」（文件头第 9 行），不核出处指到了什么。

- **0 行**的出处提到门禁。**0 行**的出处提到提交。
- **20 行**的出处开头是「本轮阶段同步派发提示做成的事第 N 项」——那份派发提示**从来没有入库**：`git log --all --format= --name-only --diff-filter=A -- "research/prompts/owed-batch1to3*"` 这一次只出四个文件（`-sync.md`、`-sync-facts-report.md`、两份 `-judge-*.md`），派发提示是主 agent 当时在会话里打的字，会话一关就没了。
- 唯一一行不指派发提示的是 F21，出处是 `H1`。

⇒ **改法四要求主 agent 对着的那个「出处」，在唯一一份跑过的真数据上是 0 命中；20/21 指向一件仓里不存在的东西。** 照它办，第一步就停在「去哪读」。

### 就算把出处补全，它的粒度也不对

出处住在**事实表**里，一条事实一个值；判定住在**候选表**里，一行候选一个值。量到的是 138 行候选 / 21 组，最大一组 F3 有 **19 行**。而 F3 这 19 行里的判定至少有三种：`.claude/kb/decisions/06-快照实现模型.md:42` 是「要改」，`.claude/kb/decisions/21-权威态与派生态的分界.md:249` 是「要人看」（两处都在 `git show 364d323^:research/prompts/owed-batch1to3-sync-judge-f1-f11.md` 的第 42、52 行）。
⇒ **一个对 19 行取同一个值的东西，判不了这 19 行里哪一行判错了。** 改法四把判别子从一个逐行取值的对象（载体原文）换成一个逐组取值的对象，在「分辨哪一行判错」这件事上是**判别力下降**，不是上升。

### 真正修掉 C 格的是改法四没量过的那一半：「新说法」

06:42 那一行在候选表里的五列，这一次原样取出来（`awk -F'\t' 'NR>1 && $1=="F3" && $4 ~ /06-快照实现模型.md:42/' /tmp/claude-1000/owed-sync/candidates.tsv`）：

**判别子逐字就在同一行的第三列里**：「按 **crate 粒度** 判 singlefs-checker 与 singlefs-core」。知道这一句，再看载体那一行说的是 core 内部两段代码，就够判出「94 号罩不到」。
⇒ 第一轮 C 格的结论「判别子在门禁 94 号的射程里，载体那一行一个字都看不出来」，**对「载体那一列」成立，对「候选表那一行」不成立**。改法四写的「新说法」这半句因此确实修得掉 C——但它修得掉的原因是**那半句要的东西本来就摆在复核者面前**，不需要任何新取数；而改法四花括注去定义、第一轮表格里标「量过」的那半句（出处），在真数据上是空的。

第一轮那一格标的是「**修掉**（量过：06:42 与两条「要人看」的判别子都在出处里，不在载体行里）」。**这个「量过」复不出来**：出处列 0 行提门禁，判别子不在出处里。

### 「载体原文只用来定位」这半句会打开一个新洞

载体是 `路径:行号`。第一轮自己量到 138 行里有 31 行今天与候选表快照对不上。把载体原文降级成「只用来定位」，就删掉了链条上唯一一次「读到的那一行是不是候选表说的那一行」的比对——行号漂了之后，出处照样能核，核的却是另一行。建议：无论采不采改法四，**「对着载体今天的原文核一遍」这半句要留着**。

**四句**：①分辨臂——分：它只打「出处」这条臂；改成「对着候选表同一行的『新事实』列核一遍」的臂不中（那一列今天就在）。②被判的系统当时看得到吗——看得到，而且这一格是可数的：事实表在盘上，出处列逐行数得出来。③满足的是哪个分句——满足的是改法四括注「出处是哪个提交、哪道门禁的哪一条判据」这个分句，不是「这条事实的新说法」那个分句（后者站得住）。④跑前条款给的每个改法还中不中——改法一、三在 C 格上照样中（都不碰判别子）；改法二只修半格，第一轮自己已经标了（06:42 那一行 63 字符、没被截断）。

## 四、四个改法两两之间的冲突

### 改法一 × 改法三：直接互相抵消

改法三（背景材料正文那一行逐字）：

> | 三 | 只把共享规则那句改成「核全之后还要抽查复判；项目可以收严成逐行全看」（归发版会话） —— 修 E |

「**收严成**」是替换，不是叠加：它给出的授权是「一个项目可以拿逐行全看**代替**抽查复判」。而改法一的 D、F 两格全部押在那张抽样表上（第一节量过）。⇒ **两个一起落地之后，任何人都可以指着共享规则那句说「本项目已收严成逐行全看，抽查那一步被代替了」，抽样表随之变成可选**——改法一唯一的产物、也就是它修 D 修 F 的全部凭据，被改法三的条文取消。

反过来也一样没用：**改法一落地之后，改法三要修的 E 已经不存在了**。E 格的机理是本地那句「不抽样、不按判定种类挑」与共享那句「还要在全部判定种类里抽查复判」字面互斥；改法一把「不抽样」删了，互斥当场消失。⇒ 在改法一之上，改法三**只剩副作用，没有作用**。

改法三还有两笔本轮新查到的代价：

- `CLAUDE.md:50`（整行抄）：

  > | 怎么改 | 共享规则只能在**上游**改。从本仓的会话改上游**只往文件里填内容**（规则正文、脚本逻辑、三语译文那几行）：不跑 `bump.sh`、不动 `VERSION`、不改 MANIFEST / SOURCE-MANIFEST 与译文首行的溯源哈希、不写带版本号的 CHANGELOG 条目、不提交，这些归做发版的会话；填之前先看上游三语仓 `git status`，有人在发版就等它提交完，填完告诉发版会话填了哪些文件哪几段。发版之后同步副本、跑 `bash .claude/singlefs-ai-sop/install.sh` 刷版本戳。**不许在 `.claude/singlefs-ai-sop/` 里就地改**——下次同步就没了，而且改它们等于改所有项目。上游的改动应当罕见：经常变说明规范本身没设计好；**作业在本仓，不在上游仓** |

  ⇒ 为了本项目一条调度表里的一行，去改一句「改它们等于改所有项目」的共享规则，且改的方向是**放宽**（新增一条许可），这一条自己写着「上游的改动应当罕见」。

### 改法二 × 改法四：互相取消

改法四写着「载体原文只用来定位」。若采，候选表第五列（原文）从判别子降级成定位辅助，**改法二修的那个 `[:500]` 截断就不再有任何后果**——改法二整条变成无用功。
反过来，若采改法二（把 `[:500]` 调大），候选表变大。这一次量的代价：

```

```

+19344 字符，占候选表 75589 字符的 **25.6%**。第一轮改法表里改法二在 A 格标的是「省 0 字符（量过）」——**符号反了**：它不是省 0，是多 19344，而 A 格问的正是装不装得下。

### 改法一 × 改法四：不冲突，但两个都落地时抽样表要跟着改口径

## 这条腿自己的限度

1. **n=1。** 全部数出自同一轮阶段同步（owed-batch1to3，2026-09-21）的事实表与候选表，而它们是**上一轮别的会话留在 `/tmp` 里的中间件**，不是这一轮跑出来的；`candidates.tsv` 的 sha256 与第一轮攻方记的相同，说明没被动过，但「没被动过」不等于「代表一般情形」。
2. **「06:42 曾被判错」这件事我没有直接证据。** 入库的逐行判定报告只有一个版本、那一行已是正确判定；我拿到的旁证是 `owed-batch1to3-sync.md:51`「抽样这一次漏掉了 06:42 那一处判错」与 `:36` 的「不删」两个字。⇒ 第一轮 C 格与这一轮 G 格都建在这条自述上；主 agent 要坐实，得去问当轮会话或承认这条无法复核（那本身就是 G 格）。
3. **那张伪「复判抽样」表是按第一轮攻方替改法一设想的四条判据造的**（`agentdef-r1-opus-output.md:159`），不是按一道真门禁造的——**没有任何门禁判过这张表**，因为改法一还没落地。它证明的是「这四条谓词挡不住机械抄」，不是「未来某道门禁一定挡不住」。谁写出一道能分辨它的门禁，第一节的结论就翻。
4. **没在副本上改过代码。** 改法二那个 `[:500]` 我只按今天的载体行长算了体量差（`cost.py`），**没把脚本改掉重跑一次候选表**；「+19344 字符」是按今天工作区那 41 行的长度算的，与当时那一版可能不同。
5. **没量 token，只量字符。** 第 25.6%、95.3% 这类比例都是字符比，不是 token 比。
6. **不判第一轮的六格 A–F 本身**（那是这一轮辩方腿的活），也不判改法一的抽样下限在极端分布下成不成立（那是本地攻方的活）。
