## 二、问法（五问，每问只有一种读法）

1. **判据可不可判。** P1 说「等价类由提交协议的步骤种类集合分」。给两条线各自的 `CommitStep` 成员集合，什么时候算同一个类：集合相等就够，还是还要屏障把步骤切成的段相同（P7 的崩溃状态集合由段决定）？举一对步骤种类集合相等、而 P7 的崩溃状态集合不同的序列——举得出，判据就要换。
2. **今天是不是恰好一个类。** 纯 SSD 线上今天已定条款写下的全部写路径：mkfs 种根（三个区域各写第 0 代根 + 两个超级块槽）、普通发布（P4 的 21 写）、空发布（P5 暖机）、实例切换（P6：写实例表行 = 码 3 单元 + 新根）、管理员回退（P6：回退行 + 新根）、超级块槽轮换、根环区域轮换。逐条数它们用到的步骤种类，是不是都落在同一个集合里。有一条用到集合之外的**结构性**步骤（不是参数），今天的数就不是 1。
3. **失败模型轴 = 1 之下，合成会不会悄悄加步骤。** P2 的合成手段是读回校验 / 双写 / 补一条日志。「补一条日志」「双写」是不是新的 `CommitStep` 成员？若是，「× 1」仍成立，但步骤集合要把合成步骤写进去，否则第一条第三方管道出现时集合变了而枚举没变。
4. **条款形态与门禁形态。** 候选条款：「等价类数 = 已开线的结构等价类数 × 失败模型数；结构等价类按 `CommitStep` 成员集合分；今天 1 × 1 = 1；每开一条线重算」。门禁形态两个候选：① 一个共享的 `CommitStep` 封闭枚举，每条线一个「用到的成员子集」断言，与 D13（验证路线）「一」的原形态同一个；② 每条线一个封闭枚举（写材料的人在 D17（实现分层与第三方管道） 未定项 2 里写的「每条线一个封闭枚举」）。② 与 P1「一个共享定义、改它的 diff 门禁 grep 得到」是不是矛盾的。
5. **「每开一条线重算」的输入是什么。** zoned 开线时至少 +1（P1 表里那一行），判它 +1 用的观测是 P9 乙问的答案，还是只要 `CommitStep` 多了 `AppendRootRecord` / `ZoneFinish` / `ZoneReset` 三个成员就够。条款要把重算的输入写死，不然「重算」没人会做。

## 五、倾向与「结果反过来我接不接受」

**倾向甲的理由**：P1 已经把判据写成「步骤种类集合」，P4 把今天唯一一条线的集合写成了字节，P2 把失败模型轴钉在 1；第 2 问的七条路径按写材料的人的读法都只用「写单元 / 屏障 / 写记录 / 根槽 FUA / 原地覆盖超级块槽」这几种步骤，空发布、切换、回退多的是**内容**（空记录、实例表行、回退行）不是**步骤种类**。
**反过来**：3-2 打中 ⇒ 接受丙并重数；3-1 打中 ⇒ 接受乙的方向，但这一轮不定数；3-4 打中 ⇒ 门禁取 ①、D17（实现分层与第三方管道） 未定项 2 里「每条线一个封闭枚举」那句撤回。
