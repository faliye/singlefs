

### 命题 1：块级重排无法欺骗 checker
- **攻不动**。  
  原因：checker 必须全盘遍历，且根据 B6 和提案 Q，checker 的真值来源密钥侧的权威树（如 btree 根），必须重建后对拍，不许把明文映射当真值读。权威树加密（A2），攻击者无密钥无法修改其密文（否则 MAC 失配）。对于对物理位置，checker 用权威树重建的预期逻辑身份作为 AAD 验证 MAC。若块被重排，预期逻辑身份与内容不匹配，MAC 失配，checker 报错。  
  要让它攻得动，格式里还须再松：**checker 不许把明文映射当真值读**（提案 Q 的核心要求）。若放开松此条，checker checker 直接使用明文映射层（如反明文反向索引）作为真值，则，攻击者可修改明文映射层：将物理位置 P2 映射为逻辑身份 L1（原本，文件 A 的块 X），然后 checker 验证 P2 时用 L1 作为 AAD，MAC 通过（因内容匹配 L1），欺骗 checker。

### 命题 2：块级重排无法导致提权
- **攻不动**。  
  原因：指针加密（A2），攻击者无密钥无法修改指针密文（否则 MAC 失配）。读取时，文件系统从指针取逻辑身份，用 AAD 验证 MAC。若块被重排，预期身份与内容不匹配，MAC 失配，读取失败。  
  要让它攻得动，格式里还须再松：**AAD 中包含树 ID / 对象 ID**。若拿掉树 ID / 对象 ID，攻击序列可如下：  
  1. 文件 A 的块 X（对象 ID A，逻辑偏移 0，birth txg 10，算法类型 AES-GCM，extent 偏移 0）位于物理位置 P1。  
  2. 文件 B 的块 Y（对象 ID B，逻辑偏移 0，birth txg 10，算法类型 AES-GCM，extent 偏移 0）位于物理位置 P2。  
  3. 攻击者将 X X 的密文复制到物理位置 P2，将块 Y 的密文复制到物理位置 P1（物理内容）。  
  4. 由于指针加密，攻击者无法修改文件 A 和文件 B 的指针（无密钥，修改指针密文会导致 MAC 失配）。  
  5. 当用户读取文件 B 的逻辑偏移 0 时，文件系统从指针获取逻辑身份（对象 ID B，偏移 0，birth txg 10 等），但 AAD 不包含对象 ID，仅用偏偏移 0、birth txg 10、算法类型、extent 偏移 0 作为 AAD。  
  6. MAC 验证通过（内容 X 匹配偏移、birth txg、算法类型等字段），文件 B 读到文件 A 的数据，提权。

### 命题 3：块级重排无法静默读出他人的旧数据
- **攻不动**。  
  原因：同命题 2，指针加密，修改，读身份与内容不匹配时 MAC 失配。整卷单密钥下，“他人的旧数据”说法成立：因所有数据用同一密钥，但逻辑隔离，“他人”指其他文件或历史版本（（例如 B5 生命周期靠 birth txg + deadlist，历史单向线性）。例如，文件 A 的旧版本数据对文件 B 的当前版本是“他人”。攻击者想静默读出不属于该逻辑位置的数据（如读文件 B 位置却文件文件 A 旧数据），但 MAC 验证失败。  
  要让它攻得动，格式里还须再松：**AAD 中包含 birth txg**。若拿掉 birth txg，攻击者可如下：  
  1. 文件 A 的旧版本块 X（对象 ID A，逻辑偏移 0，birth txg 5，算法类型 AES-GCM，extent 偏移 0）位于物理位置 P1。  
  2. 文件 A 的新版本块 Y（对象 ID A，逻辑偏移 0，birth txg 10，算法类型 AES-GCM，extent 偏移 0）位于物理位置 P2。  
  3. 攻击者将块 X 的密文复制到物理位置 P2。  
  4. 由于指针加密，攻击者无法修改文件 A 指针（无密钥，修改指针密文 MAC 失配）。  
  5. 用户读取文件 A 的版本的逻辑偏移 0 时，文件系统从指针获取逻辑身份（对象 ID A，偏移 0，birth txg 10 等），但 AAD 不包含 birth txg，仅用偏移 0、算法类型、extent 偏移 0 作为 AAD。  
  6. MAC 验证通过（内容 X 匹配偏移、算法类型、extent 偏移），静默读出旧数据（文件 A 的旧版本内容）。

### 额外两问
- **整卷单密钥下，“他人的旧数据”说法还成立吗？谁是“他人”？**  
  成立。因整卷单密钥，所有数据用同一密钥加密，但逻辑上（如不同 B1 权威态与派生态分离、B5 历史单向线性），“他人”指其他文件或历史版本的数据（例如文件 A 的旧数据对文件 B 的当前数据属“他人”）。威胁模型下，攻击者想读取不属于该逻辑位置的数据（如读文件 B 位置却得文件 A 的数据）。

- **提案 P 的 AAD 字段清单里，哪一个字段拿掉之后你立刻能构造出攻击？给出那条攻击。**  
  拿掉 **树 ID / 对象 ID** 后，能构造攻击（如命题 2 攻击序列）。  
  攻击序列：  
  1. 文件 A 的块 X（对象 ID A，逻辑偏移 0，birth txg 10，算法类型 AES-GCM，extent 偏移 0）位于物理位置 P1。  
  2. 文件 B 的块 Y（对象 ID B，逻辑偏移 0，birth txg 10，算法类型 AES-GCM，extent 偏移 0）位于物理位置 P2。  
  3. 攻击者将块 X 的密文复制到物理位置 P2，将块 Y 的密文复制到物理位置 P1（交换内容）。  
  4. 指针加密，攻击者无法修改文件 A 和文件 B 的指针（无密钥，修改密文 MAC 失配）。  
  5. 用户读取文件 B 的逻辑偏移 0 时，文件系统从指针取逻辑身份（对象 ID B，偏移 0，birth txg 10 等），但 AAD 不包含对象 ID，仅用偏移 0、birth txg 10、算法类型、extent 偏移 0 作为 AAD。  
  6. MAC 验证通过（内容 X 匹配偏移、birth txg、算法类型、extent 偏移），文件 B 读到文件 A 的数据，提权。  
  - 注：拿掉 birth txg 或 extent 偏移也可能导致攻击，但拿掉树 ID / 对象 ID 最最直接且通用；拿掉算法类型或 extent 偏移通常不直接导致数据混淆（因算法类型固定、extent 偏移用于 extent 管理）。
