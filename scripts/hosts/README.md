# scripts/hosts

内存与线程上限的兜底、第二台那几段、task-server 载入的判法（跑项目代码的长活归 task-server）。内存包装、`capped.sh`、`multi-host-run.sh --peer` 与清场包装 `scripts/crash/gpu-quiesce-run.sh` 只认服务起尝试时直接套的那一层（各认服务给的准入标记，读掉、不交给命令），任务里面的脚本再套一层当场拒，出路是删掉那一层，内存、线程、卡照读服务交的 `TASK_SERVER_MEMORY_CAP_BYTES`、`SINGLEFS_THREAD_CAP`、`GPU_CARDS_BY_PRIORITY`。排队、记账、挑机器、定额度与起任务只在仓根 `task-server/`，这里的脚本不再自己做这几样。两台跑同一份脚本与同一份多机配置：仓根的 `multi-host.env`（不进 git，模板 `multi-host.env.example`）是唯一的源，它在 NFS 共享根下，第二台照同一个绝对路径读同一份（第二台上不留常驻的那一份）。两台对称：哪一台是自己只照多机配置的 `HOSTS` 与这一台网卡上的地址认（`multi_host_addresses.py` 的 `resolve`，判法是配置判法的 `--emit-addresses`），不带认台的角色变量，同一份配置在两台上判的结局相同；卡的台标签写 `HOSTS` 里那一台的地址（`<地址>:<卡号>:<额度>`）；两台不同的三样（cargo 所在目录、本地盘上的编译根、slice 的总上限）写在多机配置的三个按台的键 `CARGO_BIN_DIRECTORY_BY_HOST`、`BUILD_ROOT_BY_HOST`、`SLICE_MEMORY_CAP_BY_HOST` 里（`<地址>=<值>` 空白分隔，每台恰好一项），要哪一台的按那一台的地址取（`peer-host-lib.sh` 文件头「按台的三个键」，python 一侧 `multi_host_addresses.py` 的 `by_host_values`）；差异只走参数。

| 文件 | 做什么 |
|---|---|
| `run-with-memory-cap.sh`、`memory_peaks_lib.py` | 内核层兜底两层：这一条命令自己的 scope 上限，与 slice `singlefs-heavy.slice` 的总上限（照多机配置 `SLICE_MEMORY_CAP_BY_HOST` 里这一台那一项）；不排队、不记账。task-server 起每一次尝试经它，只认服务直接起的那一层；实测峰值记在共享数据根下的 `memory-peaks.tsv`（`.claude/hooks/lib_work_root.py` 的 `shared_data_path`，两台读写同一份，每行记是哪一台量的，读的时候只认本台的行）；`memory_peaks_lib.py` 另量这台此刻的余量（slice 自己记着、哪个子 cgroup 里都没有的回收不掉的那一截，按 1 GiB 向上取整，文件头「余量」），task-server 照它定每台单条的上限 = 总上限 − 余量 |
| `capped.sh` | 给一条命令定线程上限；上限写 `default` 取每台默认重活线程数（task-server 给每一次尝试套 `capped.sh <N>`，提交的命令里不写它；只认服务套的那一层，任务里面再套当场拒） |
| `two-logs.sh`、`two_logs.py` | 日志出两份：`two-logs.sh [--quiet] <名> -- <命令…>` 照原样转打输出，同时写 `<名>.log`（全量）与 `<名>.problems.log`（只收错误与警告，行前带全量日志里的行号，末行写收了几行、全量几行），退出码是被包命令的；`--from-log <名>` 从已有的全量日志现筛。收哪些行：门禁的 `✗` 与它的 `→` 出路、`⚠`、本次未跑、逐格汇总，cargo / rustc 的 error 与 warning、libtest 的 FAILED 与 panicked、Traceback、非 0 退出码。入口脚本与门禁里的 `.log` 都经它写，一般只看 `.problems.log`；配套钩子 `.claude/hooks/two-logs-guard.sh` 拒绝手敲的 `> x.log`、`\| tee x.log` |
| `heavy-threads.sh`、`heavy_threads.py` | 每台默认重活线程数的两份取法（shell 的 `heavy_thread_default`、python 的 `default_heavy_threads`）：`SINGLEFS_THREAD_CAP` 设了照它，否则读 `.claude/heavy-thread-default` 的登记值，写坏或不在就拒 |
| `multi-host-run.sh`、`peer-host-lib.sh` | 把一条命令挪到第二台跑、两台共用的那几段：task-server 派第二台经 `multi-host-run.sh --peer`（在同一个绝对路径的共享树里跑；派不派第二台由 task-server 判；不带 `--peer` 是用法错、退 2，本机的任务由服务直接起内存包装；只收服务的尝试单元直接起的那一次，任务里面再带 `--peer` 两台都拒、退 255）；含第二台那条命令带过去的多机配置路径与清场握手 `peer_host_carried_environment` |
| `host-dispatch.py` | task-server 载入的判法库：各台此刻的余量（`probe_local`、`probe_peer`）、这台放不放得下（`judge_host`，预测由服务照它自己的记录填进 `Prediction`，余量由服务交那台此刻量的，量不到的不派、不退回固定的数）、多机配置里第二台的读法（`Peer`）；命令行派发删了，单独跑只认 `--selftest` |
| `gpu-card-health.py` | 显卡本身坏没坏：按多机配置两种显卡先后点名的卡查两台（台标签是这一台地址的在本机查、是另一台地址的经 ssh 查，在哪台跑查的都是同一组卡），逐卡判 nvidia-smi 读不出或少卡、温度功耗读成 `ERR!` 这类、`GPU Recovery Action` 不是 `None`、计算进程表里 pid 为 `[N/A]` 的行、这次开机后的致命类 Xid；逐卡一行 `GPU_CARD_HEALTH` 机读行与汇总，全好退 0、有坏卡退 1（出路是主 agent 弹窗请用户重置那张卡）、查不了退 78；清场包装 `scripts/crash/gpu-quiesce-run.sh` 清场之前调它，看门狗 `scripts/agents/agent-watch.py` 按 `watch.conf` 的 `gpu-health-every-minutes` 定时调它，task-server 分卡时读它的配置读法 |
| `compile-then-swap.py`、`source-stamp.py`、`target-prune.py`、`target-prune.conf` | 先编后换（经 `task-server/task submit -- python3 scripts/hosts/compile-then-swap.py …` 起）、换了源码没重编的拦法、清编译目录的旧产物 |
| `minimal-copy.py` | 建最小仓副本：拷贝范围取 `lib_repository_copy.py` 的闭包（`--with-gate-tables` 再声明 `.claude/gate.d`，`--with-test-inputs` 连测试读的仓根文件），拷前报大小、超阈值拒绝，拷过去的修改时刻是此刻 |
| `lib_repository_copy.py` | 拷仓副本的范围只在这一份：共用清单（`Cargo.toml`、`Cargo.lock`、`.cargo`、`crates/`）加闭包（path 依赖指到的目录、编译期 `include_str!` 读的、副本里起的二进制与脚本运行期读的仓根文件连同它们 source、起的；`test_inputs` 连测试代码），调用方多拷的经 `declared` 逐条写为什么；多机配置 `multi-host.env` 决不拷，副本里起命令的环境用 `environment_for_commands_in_the_copy`（`SINGLEFS_MULTI_HOST_CONFIG` 显式指到主工作区那一份）。调它的：`minimal-copy.py`、`compile-then-swap.py`、`scripts/gate/apply-writer-patch.py`、`scripts/gate/hook-swap.py`（只用环境）、`scripts/mutation/crates-mutation-rows.py`、`scripts/mutation/mutate.sh`（`link-into`）、`scripts/mutation/prove-red.sh`（只用环境）、E201 的 `full_table_run.py` 与 `current_tree_row_driver.py`、`scripts/experiment-apparatus/replay.sh`（E168 补丁树与 E171 s4 冻结树经 `minimal-copy.py` 拷，副本里起命令用 `configuration-path`）、`scripts/experiment-apparatus/e165-replay-mutation-kill-bounds.sh`（每个变体的副本）。`entries <仓根>` 打闭包与每一条为什么；`verify-copy -- <cargo build 参数>` 是真编核对（拷进不是 git 工作树的副本、真编、在副本里起登记的运行期脚本，经 `task-server/task submit` 交） |
| `work-directory-ownership.sh` | 工作根下每个目录的归属文件（会话号、建于、用途）：`claim` 写、`show` 读、`sweep [--dry-run]` 只删归属是本会话又没有进程开着的，别的会话的与没有归属文件的逐项列出交用户，删前逐项连大小写进 `<工作根>/sweep-<日期>.log` |
| `rocksdb-prebuilt.py` | librocksdb-sys 的 C++（`librocksdb.a`、`libsnappy.a`）每台主机只编一次，放 `~/.local/share/singlefs/rocksdb-prebuilt/` 按版本、rustc、C/C++ 编译器与指令集分目录；各编译目录经进程环境的 `ROCKSDB_LIB_DIR`、`ROCKSDB_STATIC`、`SNAPPY_LIB_DIR`、`SNAPPY_STATIC` 链它（不写进 cargo 配置：`[env]` 进变异的键）。`build` 持锁编一次、`install` 另写这台的三处环境来源、`check` 判这台、`audit-target <编译目录>` 判编译目录里现编过没有、同一把键下见过几种取值 |
| `cache-keepalive.sh`、`test-environment-check.py` | 子 agent 等长活时续提示缓存的计时器（agent 定义与共用约束都不再叫子 agent 起它）；测试环境的残留检查 |
| 仓根 `task-server/` | 一切跑项目代码的任务都经它起（`task-server/task submit -- <命令…>`、后台 `task-server/task wait <号>`）：排队、记账、挑机器、定内存额度、定线程、分卡都只在服务里；它起本机的每一次尝试经 `run-with-memory-cap.sh`（只剩两层兜底），派第二台经 `multi-host-run.sh --peer`；见 `task-server/README.md` |

审核回归测试：`python3 -B -m unittest discover -s scripts/hosts/tests -v`。使用临时目录检查清理的保留规则、备份隔离、Git 状态复查、会话路径边界，以及源码副本路径的校验；各入口原有的 `--selftest` 另行运行。
